0013 摘  要
0014 本报告围绕第二十一届全国大学生智能汽车竞赛“走马观碑”组车模的软件系统设计与实现展开。江西水利电力大学“我不会配环境队”以 LS2K0300 平台为核心，采用龙邱科技灵眼 Pro 摄像头、imu660RC 和 1024 线增量式编码器完成赛道环境感知与运动状态反馈。软件总体采用“灰度视觉循迹 + 红色目标预检测 + 轻量化神经网络分类 + 目标板状态机 + 双轮差速闭环控制”的分层架构。赛道部分通过灰度图像搜索左右边线，并采用多行加权方式计算车辆相对赛道中心的横向误差；目标识别部分先依据 YCRCB 色度特征在有效赛道区域内检测红色标志，仅当目标进入可分类距离后构造 50×50 ROI 并调用 NCNN 模型完成九个细分类识别，再映射为物资、交通工具和武器三类任务。控制部分根据目标类别和道路形态进入不同状态，结合 imu660RC 偏航变化与编码器累计距离完成预偏移、正式绕行、直行通过和退出恢复。该方案将传统图像算法、轻量化深度学习和实时运动控制结合起来，降低了无效推理开销，提高了车模在目标识别与分类绕行过程中的实时性和稳定性。

0064 第一章  引言
0065 1.1  系统概述
0066 本车面向第二十一届全国大学生智能汽车竞赛“走马观碑”组任务设计，以 LS2K0300 为车载计算与控制核心，使用灵眼 Pro 摄像头获取赛道和目标图像，结合 imu660RC、左右轮 1024 线增量式编码器及 DL1B TOF 测距模块获取姿态、速度、位移和前向距离信息。车辆采用左右轮差速驱动，并配置负压机构提升高速行驶时的附着能力。
0067 软件采用“循迹优先、按需识别”的处理方式：常规状态下以 160×120 灰度图完成左右边线搜索和中线误差计算；检测到有效红色标志后，再构造 50×50 分类 ROI 并调用 NCNN 模型。九个细分类最终映射为物资、交通工具和武器三类任务，由状态机分别执行右绕、直行和左绕。
0068 控制系统采用分层闭环结构：视觉位置外环根据赛道横向误差生成目标角速度，IMU 角速度内环计算差速修正量，左右轮增量式 PI 速度环完成电机输出。由此形成“感知—决策—控制”的统一链路，使普通循迹、目标识别和绕行动作能够在同一控制框架下切换。
0069 1.2  算法创新
0070 算法设计重点在于减少无效推理并提高分类输入的一致性。本方案将赛道约束、YCrCb 红色预检测、IPM 逆透视和轻量化分类网络串联，使神经网络仅在目标进入有效区域后工作，并尽量保证不同弯道和距离下的分类 ROI 具有一致的几何形态。
0071 1.2.1  赛道约束的红色预检测
0072 程序先完成灰度图左右边线提取，再把红色搜索限制在有效赛道区域内，而不是在整幅图像中无约束扫描。红色判断采用 YCrCb 色度特征，并结合连续红色段长度、命中行数、连续有效行数和面积范围进行筛选。这样可以把红色背景、零散噪声和赛道外干扰提前过滤掉，降低后续模型推理次数。
0073 1.2.2  IPM/逆透视 ROI 一致化
0074 检测到红色标志后，软件将 160×120 检测坐标映射回 320×240 原图，并利用图像坐标到 IPM 俯视坐标的单应矩阵估计目标在地面坐标中的方向。随后在红色标志前方构造分类区域，再通过逆透视关系和透视变换统一裁剪成 50×50 图像送入模型。该方法的效果是：即使目标出现在不同弯曲程度的赛道中，裁剪出的目标图像也会被校正到接近直道情况下的观察方式，使模型看到的目标位置、朝向和尺度分布保持一致。
0075 这种一致化裁剪显著降低了模型训练难度。模型不需要额外学习大量“同一目标在不同曲率弯道、不同倾斜角度、不同透视形变下仍属于同一类别”的复杂变化，而是更多聚焦于目标本身的纹理和轮廓差异。因此，在保证分类准确率稳定达到 98% 以上的前提下，网络可以使用更少参数和更低输入分辨率完成任务，当前部署模型仅 7371 个参数，能够很好地契合 NCNN 轻量化部署需求。
0076 1.2.3  锁存式任务决策
0077 红色首次出现时只触发预减速和等待分类，只有当目标进入设定距离并且分类置信度达到阈值后，才把九个细分类映射为物资、交通工具、武器三类动作。分类结果一旦生效便由状态机锁存，直至目标板处理完成，避免连续帧识别抖动造成动作反复切换。
0078 1.2.4  虚拟中线复用控制
0079 目标绕行并非直接给电机固定指令，而是通过虚拟中线把目标动作转化为循迹误差偏移，再复用视觉位置外环、IMU 角速度内环和左右轮速度环完成闭环控制。该处理保持了算法接口的一致性，使普通循迹、弯道、环岛和目标板绕行能够在同一控制框架下切换。
0080 1.3  硬件创新
0081 硬件设计以“车载识别与实时控制一体化”为目标。LS2K0300 同时承担图像处理、NCNN 推理和运动控制，主控 PCB 集成电源、传感器和驱动接口，使车模能够在脱离上位机的情况下完成感知、决策与执行。
0082 摄像头安装与软件算法协同设计：龙邱科技灵眼 Pro 同时承担赛道循迹、红色目标定位和分类 ROI 构造三项任务。工程将其配置为 320×240、120 fps、手动曝光，并采用 LQ_CAMERA_0CPU_MJPG 低 CPU 占用采集路径，底层实际设置为 MJPG FOURCC。该配置减少了图像采集对处理器的占用，使车载端能够把更多算力用于灰度边线提取、红色预检测和 NCNN 推理。
0083 运动反馈部分采用 imu660RC 与 1024 线增量式编码器互补。imu660RC 用于角速度闭环和目标绕行阶段的偏航变化判断，1024 线编码器用于左右轮速度闭环和目标板状态切换距离判断。相比只依赖视觉或只依赖开环时间控制的方案，该硬件反馈结构能够在光照变化、车身打滑和绕行姿态变化时提供更多保护条件。
0084 第二章  模型车总体设计方案
0085 2.1  设计思路与技术方案概要
0086 “走马观碑”任务同时要求车辆具备较高的赛道通过速度和可靠的目标识别能力。针对这一特点，本车采用 F 型差速车模作为机械基础，以自主设计主控与驱动电路完成硬件集成，并将传统视觉循迹、轻量化目标分类和分层闭环控制结合起来。设计原则是：常规循迹保证高频实时性，目标识别按需触发，识别结果通过状态机转换为连续动作，从而兼顾速度、识别准确性和运动稳定性。
0087 2.2  系统总体架构
0088 2.2.1  硬件系统架构
0089 本车硬件系统主要由车模机械结构、主控电路板、驱动电路、电源管理模块和传感器系统组成。各部分围绕车模高速循迹、目标识别和稳定运动控制进行协同设计，形成“能源供给—信息感知—主控计算—运动执行”的完整硬件链路。
0090 车模机械部分以F 型车模底盘为基础，保留左右驱动轮和基本传动结构，并在底盘上完成主控板、摄像头、IMU、编码器及负压装置的安装。左右驱动轮分别由有刷直流电机驱动，通过两侧电机转速差实现车辆直行、转向及轨迹修正。为提高高速行驶时的轮胎附着能力，车体增加由无刷电机驱动的负压机构并且装配摩擦系数更高的光头胎，通过产生附加下压力提高车轮法向载荷，从而增大可利用的轮胎附着力。
0091 电控部分以自主设计的主控 PCB为核心，LS2K0300主控模块通过插接方式安装在电路主板上。主板负责电源分配、传感器接口、电机控制接口以及各功能模块之间的信号连接。摄像头、imu660RC和左右轮编码器采集的数据汇入主控平台，由主控程序完成赛道识别、运动状态反馈和闭环控制运算。
0092 驱动系统分为有刷电机驱动和无刷电机驱动两部分。左右轮有刷电机由DRV8701驱动电路控制，主控系统根据视觉循迹误差、IMU角速度和编码器反馈计算左右轮目标速度，再通过PWM调节两侧电机输出，实现车模前进、减速和差速转向。负压机构采用 EMAX 2207 无刷电机，并由无刷电子调速器驱动，用于带动负压机构高速旋转，为车模提供附加下压力。
0093 整车采用3S锂电池供电。电池电压接入主控电路后，根据不同模块的工作电压进行分级转换：一路稳压至5 V，为5 V外设供电；另一路在5 V基础上进一步转换为3.3 V，为3.3 V传感器、数字接口及其他低压器件供电。分级供电既满足不同模块的电压需求，也便于对动力部分和控制部分进行统一电源管理。
0094 传感器系统主要包括龙邱科技灵眼 Pro 摄像头、imu660RC、左右轮1024 线增量式编码器以及DL1B TOF 测距模块。摄像头负责获取赛道与目标板图像，IMU提供车辆角速度等姿态信息，编码器测量左右轮速度和累计位移，DL1B TOF 测距模块用于获取车模正前方的距离信息，为坡道元素的识别与通过控制提供辅助依据。主控系统综合视觉、姿态、速度及距离信息对车辆运动进行闭环调节，为后续软件算法运行提供稳定的硬件基础。
0095 2.2.2  软件系统架构
0096 软件系统分为上位机训练端和车载实时端两部分。上位机训练端负责数据集整理、轻量化分类模型训练、模型精度评估以及 PyTorch 到 ONNX、NCNN 的转换；车载端运行在 LS2K0300 平台上，完成摄像头图像采集、灰度赛道识别、红色目标预检测、NCNN 分类、目标板任务决策和左右轮闭环控制。
0097 车载端采用模块化数据流：龙邱科技灵眼 Pro 摄像头提供原始 320×240 彩色图像，程序同步生成 160×120 灰度图用于循迹，生成 160×120 彩色图用于红色目标搜索，并在目标进入有效区域后回到原图构造 50×50 分类 ROI。识别结果经置信度筛选和类别映射后，不直接改变电机输出，而是进入目标板状态机，由状态机结合道路形态、imu660RC 偏航和 1024 线增量式编码器距离生成连续动作。
0098 系统总体流程：传感器采集 → 赛道/目标预处理 → NCNN 分类 → 状态机决策 → 差速闭环控制
0099 这种架构的核心特点是将高频控制与神经网络推理分层处理。常规赛道识别和电机控制保持稳定周期，神经网络只在必要时触发，既降低了车载端计算压力，也提高了复杂目标场景下的动作一致性。
0100 2.3  主要技术指标
0101 整车主要指标以“实时、轻量、可闭环”为原则。摄像头工作分辨率为 320×240，图像处理帧率 120 Hz；赛道和红色目标预检测主要在 160×120 图像上完成，目标分类输入统一为 50×50。车载控制周期为 5 ms，赛道信息检测频率约 103 Hz。
0102 轻量化分类模型共 7371 个参数，训练结果中细分类测试准确率为 99.90%，粗分类测试准确率为 99.96%。机械部分摄像头最终安装高度约 34 cm，负压系统可提供约 1.35 kgf 附加下压力。上述指标共同构成后续结构、电路和软件设计的约束条件。
0103 第三章  机械结构设计与安装
0104 3.1  车模机械改造
0105 图3.1 车模前视图
0106 图3.2 车模左视图
0107 图3.3 车模俯视图
0108 本车以 F 型差速车模为基础进行机械改造，重点解决重心分布、轮胎附着、摄像头视野以及电路模块安装维护四个问题。
0109 底盘保留左右独立驱动结构，主控 PCB、电池和驱动模块尽量低位集中布置；实车调试后进一步将重心适当后移，以改善高速弯道中后轮附着不足造成的甩尾和打滑。
0110 左右驱动轮由有刷直流电机独立驱动，通过左右轮速度差完成直行和转向。该结构省去了机械转向机构，也便于软件直接根据视觉误差和 IMU 反馈实施差速闭环控制。
0111 为提高高速状态下的抓地能力，底盘增加以 EMAX 2207 无刷电机为动力的负压机构。EMAX 2207 无刷电机高速旋转后带动负压装置工作，使车底局部气压降低，从而对车体产生附加向下作用力。若轮胎与赛道之间的摩擦系数为μ，车轮法向载荷为N，则轮胎可利用的最大附着力近似满足Fmax=μN。加入负压机构后，法向载荷可近似表示为N=mg+Fvac，因此在轮胎摩擦系数基本不变的条件下，负压产生的附加下压力能够提高车轮的纵向驱动能力和横向附着能力。
0112 负压机构布置兼顾附加下压力、重心和离地间隙。无刷电机及风道靠近后轮区域安装，使附加法向载荷更有利于后轮附着；负压装置底部与赛道保持合理间隙，在避免刮擦的同时降低漏气。
0113 3.1.1  无刷电机支架设计
0114 图3.4 无刷电机支架结构及参数
0115 为保证 EMAX 2207 负压无刷电机在车模高速运行过程中的安装刚度和位置稳定性，本车设计了专用无刷电机支架。支架通过安装孔与车模主板结构连接，在固定无刷电机的同时将负压机构产生的载荷传递至车体主体结构。支架采用长条形加强结构，并设置长圆孔及安装孔，在减小结构质量的同时兼顾安装位置调节、装配便利性和整体抗弯刚度。
0116 负压机构工作时，无刷电机高速旋转会产生持续振动和反作用力，因此支架除了承担电机自身质量外，还需保证电机与负压风道的相对位置稳定，避免工作过程中出现明显偏移。稳定的机械支撑能够维持负压装置与赛道之间的有效间隙，并降低振动向主控板和传感器传递所造成的影响。
0117 该支架采用铝合金材料制作，模型厚度约为3 mm，质量约为42.69 g。实际负压系统可为车模提供约1.35 kgf的附加下压力，因此支架需要在轻量化与结构强度之间取得平衡。当前结构在增加质量较小的前提下，为 EMAX 2207 无刷电机及负压机构提供了可靠的安装和受力基础。
0118 此外，机械安装过程中对电路板、主控模块、传感器和线束进行可靠固定，避免车模高速行驶和负压电机工作产生的振动导致接插件松动或传感器姿态变化，从而保证机械结构与控制算法参数之间的一致性。
0119 3.2  传感器安装设计
0120 3.2.1  灵眼 Pro 摄像头安装
0121 灵眼 Pro 摄像头安装于车模前部上方，距离车模底板约34 cm，并使镜头朝向车辆前方赛道。安装高度和俯视角需要同时兼顾近端赛道边界和远端前瞻范围：位置过低会使远端赛道可见范围不足，位置过高则会减小近端赛道在图像中的有效占比，并可能增加车体振动对图像稳定性的影响。
0122 本车摄像头同时承担赛道边线识别、红色目标检测和神经网络分类 ROI构造，因此完成标定后应保持摄像头相对车体的安装位置和角度稳定，避免机械位置变化导致IPM 参数及视觉阈值失配。
0123 3.2.2  imu660RC 安装
0124 imu660RC 安装在主控 PCB附近并尽量靠近车辆中心位置。其Z轴角速度用于方向控制内环，同时在目标板绕行阶段参与偏航角累计，因此安装时应保证传感器坐标轴与车体坐标方向一致，并采用可靠固定方式减小机械振动和安装松动造成的测量误差。
0125 将IMU靠近车辆旋转中心布置，可以减小局部结构运动对姿态测量的影响，使角速度反馈更加接近车体整体的转动状态。
0126 3.2.3  1024 线增量式编码器安装
0127 左右驱动轮分别配置1024 线增量式编码器，用于获取两侧车轮转速和累计运动距离。编码器与驱动轮之间保持可靠的机械连接，使车轮运动能够准确传递到编码器测量端。
0128 编码器数据一方面用于左右轮速度闭环，使实际轮速跟随软件给定值；另一方面用于目标板状态机中的距离判断。因此安装时应尽量减小联轴器间隙、松动和偏心，避免出现额外的脉冲测量误差。
0129 3.2.4  DL1B TOF 测距模块安装
0130 本车配置DL1B TOF 测距模块，用于坡道元素的距离感知与辅助控制。车模接近坡道时，前方坡面与传感器之间的距离会随车辆位置发生变化，主控程序可利用该距离信息辅助判断坡道元素，使车模在上坡和下坡过程中采用相应的运动控制策略，从而提高通过坡道时的稳定性。
0131 DL1B TOF 测距模块固定在摄像头支撑杆上，测距方向保持朝向车模正前方，安装高度约高于前轮最高点2 cm。该位置既能够使传感器有效获取车辆前方坡面的距离变化，又可避免前轮、底盘及其他机械结构进入测距方向而造成干扰。安装时保持传感器朝向稳定，并与摄像头支撑结构可靠固定，以减小车模高速运行和坡道冲击引起的姿态变化对测距结果的影响。
0132 3.3  系统电路板固定与连接
0133 主控 PCB安装于车模底盘中部，是整车电气系统的主要连接和承载平台。LS2K0300主控模块采用插接方式安装在主板上，便于系统调试、维护和主控模块更换。
0134 PCB 机械布置时尽量靠近车体中心并保持较低安装高度，电池、主控板和驱动模块在车体纵向方向上尽量均衡分布，以减小电控部分质量对整车重心和前后轮载荷分配的影响。
0135 主控 PCB通过接口分别连接灵眼 Pro 摄像头、imu660RC、左右轮编码器、DL1B TOF 测距模块、DRV8701有刷电机驱动以及无刷电子调速器。动力电机相关导线与传感器信号线在布置时尽量分开，以减小大电流快速变化对编码器、IMU、TOF测距模块和摄像头等信号的干扰。
0136 整车3S电池首先接入主控电路系统，控制和传感部分经稳压电路产生5 V和3.3 V电源后分别供给不同工作电压的模块。各功能模块共用统一参考地，并通过可靠连接器与PCB连接，在保证连接强度的同时便于后期拆装和故障排查。
0137 针对车模高速运动以及负压电机工作时可能产生的机械振动，主控板、插接模块和线束均进行固定，避免接插件松动、线缆脱落或传感器姿态发生变化，提高整车运行可靠性。
0138 3.4  机械结构参数
0139 改造后车模质量约 1255.8 g，长约 28 cm、宽约 30 cm、高约 34 cm，轴距约 16.5 cm、轮距约 15 cm。摄像头最终安装高度约 34 cm；无刷电机铝合金支架厚度约 3 mm、质量约 42.69 g；负压机构实测可提供约 1.35 kgf 附加下压力。主要机械参数在第七章统一汇总。
0140 第四章  电路设计
0141 4.1  电源管理电路
0142 主控板电源部分完成 3S 锂电池输入、动力电源引出、5 V 与 3.3 V 两级稳压以及 5 V 外设受控上电等功能。整车动力与控制电源由同一电池系统供给，但针对主控、传感器和外设的不同电压需求进行分级转换与滤波，电源原理图如图 4-1 所示。
0143 供电流程：3S 锂电池 → 主电源开关 → 5 V 降压 → 3.3 V 稳压 / 5 V 外设受控供电
0144 图4.1  主控板电源管理电路原理图
0145 4.1.1  电池输入与主电源开关
0146 整车 3S 锂电池通过 P1（XT60）接口接入主控板，正极形成 VCCBAT 电池母线，负极连接系统 GND。输入端采用 HY190P03D MOS 管 Q1 配合机械开关 S1 构成主电源通断控制，D1（BZT52C16）与 R2 对 MOS 管栅极相关节点进行电压约束和保护。电池母线同时通过 DCOUT1（XT30）接口引出，为需要直接使用电池电压的动力部分提供电源连接。该设计将整车总电源开关与动力电源接口集中在主板上，便于车辆上电、断电以及调试维护。
0147 4.1.2  5 V 降压电源
0148 控制与外设所需的 5 V 电源由 SCT2450 开关降压芯片 U5 产生。VCCBAT 经输入端电容组 C26、C24、C25 进行低频储能和高频去耦后送入降压级；U5 的开关节点配合 4.7 μH 电感 L2、SS54 肖特基二极管 D2 以及输出电容 C17、C22 构成降压滤波网络。反馈电阻网络连接至 FB 引脚，用于稳定输出电压，最终形成 VCC5V 电源轨。相较直接采用线性稳压器，从 3S 电池降压至 5 V 使用开关降压方式能够降低稳压器自身功耗，更适合为车载主控及多个外设持续供电。
0149 4.1.3  3.3 V 稳压电源
0150 3.3 V 电源由 RT9013-33GB 低压差线性稳压器 U2 在 VCC5V 基础上二次稳压得到。输入端配置 C1（10 μF）和 C2（100 nF），输出端配置 C3（10 μF）和 C4（100 nF），分别承担储能与高频去耦作用。输出电源标记为 VCC3V3，并通过 R1 与 LED3V3 构成 3.3 V 上电指示。该电源主要用于主控数字接口、IMU、编码器等 3.3 V 器件，为低压数字电路提供相对稳定的供电。
0151 4.1.4  5 V 外设上电时序
0152 为避免所有 5 V 外设在主电源接通瞬间同时启动，主板设置了独立的 5 V 外设受控供电支路。SY6280AAC 芯片 U6 的输入端接 VCC5V，输出端形成 VCC5V_EXT，EN 引脚由控制信号 CR 管理，R16 与 ISET 引脚构成电流设定网络。VCC5V_EXT 端还设置去耦电容和 LED 指示支路。通过该受控电源开关，可以在主控系统建立稳定供电后再接通外设电源，实现外设上电时序管理；第二张接口图中的 TOF 接口即使用 VCC5V_EXT 供电。
0153 4.2  传感器及外设接口电路
0154 主控板将车模所需的传感器、显示、人机交互和执行机构控制信号集中引出，形成统一的外设接口区域。接口电路如图 4-2 所示。该设计使传感器与驱动模块可以通过插接方式连接主板，便于整车装配、调试和模块更换。
0155 图4.2  传感器及外设接口电路原理图
0156 4.2.1  屏幕与姿态传感器接口
0157 屏幕接口 P7 提供 VCC3V3、GND 以及多路主控信号，用于连接调试显示模块，便于车辆调试阶段观察运行参数和传感器状态。姿态传感器接口 P4 同样采用 3.3 V 供电，并引出多路数字信号与主控相连，用于连接 imu660RC。IMU 的 Z 轴角速度数据在软件中参与方向角速度内环以及目标板绕行阶段的偏航判断，因此该接口既承担传感器供电，也承担实时姿态数据传输。
0158 4.2.2  DL1B TOF 测距接口
0159 TOF 接口 P3 为 6 针接口，其中电源端接受控的 VCC5V_EXT，并配置独立 GND，同时向主控引出四路信号线。该接口用于连接 DL1B TOF 测距模块。由于 TOF 模块用于坡道元素的距离感知，采用受控的外设 5 V 电源可以使其上电过程与主控系统保持协调。测距数据送入主控后，可作为坡道识别及上、下坡运动策略切换的辅助信息。
0160 4.2.3  左右编码器接口
0161 左右轮编码器分别通过 P2 和 P9 接入主板，接口均提供 VCC3V3 与 GND，并引出 A 相和 B/Dir 信号；Z 相在当前设计中未作为主要反馈信号使用。两侧 1024 线增量式编码器用于获取左右驱动轮的转速与累计位移。编码器反馈一方面构成左右轮增量式 PI 速度闭环，另一方面为目标板绕行、直行通过及退出恢复等状态提供距离判据。
0162 4.2.4  有刷电机与无刷电调控制接口
0163 主控板通过 H1 接口向左右有刷电机驱动板输出 PH 与 EN/PWM 控制信号，并通过 H2 接口向负压无刷电调输出调速控制信号。该处仅承担主控板与功率驱动模块之间的信号连接，具体 DRV8701E 全桥功率级和 EMAX 2207 三相无刷电调结构在 4.3 节中展开说明。
0164 4.2.5  按键与蜂鸣器接口
0165 主板配置多路按键/拨码输入，输入端采用 3.3 V 上拉电阻网络并连接至主控 GPIO，可用于模式选择、参数调试及运行控制。蜂鸣器采用 S8050 NPN 三极管 Q2 进行低端开关驱动，主控信号经 R31 接入基极，并设置 R34 下拉电阻保证上电时三极管处于确定状态。蜂鸣器支路由 3.3 V 供电，可用于上电提示、状态提示及故障报警。
0166 4.3  电机驱动电路
0167 本车电机驱动系统分为车轮有刷电机驱动和负压无刷电机驱动两部分。左右驱动轮采用两套独立的 DRV8701E 外置 MOSFET 全桥驱动，实现左右轮独立调速和差速转向；负压机构采用 EMAX 2207 无刷电机，由基于 Ai8051 主控、FD6288Q 三相栅极驱动器和六管三相逆变桥构成的无刷电调驱动。两类驱动分别承担车辆运动和负压吸附任务。
0168 4.3.1  DRV8701E 双路有刷电机驱动
0169 图4.3  DRV8701E 双路有刷电机驱动电路原理图
0170 车模左右驱动轮分别配置一套独立的有刷直流电机驱动电路，两路电路结构基本一致。每路以 DRV8701E 为栅极驱动核心，配合 4 只 TPH1R403NL N 沟道功率 MOSFET 构成完整 H 桥。DRV8701E 负责产生高、低侧 MOSFET 栅极驱动信号，H 桥通过改变电机两端电压极性实现正反转，并通过 PWM 调制改变电机平均端电压，从而完成调速。
0171 主控板向驱动板提供左右两组 PH 和 EN 控制信号。左电机使用 L_PH 与 L_EN，右电机使用 R_PH 与 R_EN，其中 PH 用于确定桥臂工作方向，EN 接收 PWM 调速信号。左右轮目标速度可以独立设定，因此软件方向控制产生的差速修正量能够分别叠加到左右轮目标速度，实现直线行驶、转向和轨迹修正。
0172 控制信号进入 DRV8701E 前经过 SN74HC125PWR 缓冲器。该器件对左右两路 PH、EN 信号进行缓冲和边沿整形，减小主控端直接驱动外部功率板带来的信号负担。两路驱动同时引出 NSLEEP 使能信号，用于统一控制驱动芯片的工作与休眠状态。
0173 DRV8701E 周围配置 VCP、CPH、CPL 等电荷泵相关电容，为高侧 N 沟道 MOSFET 提供所需的栅极驱动条件。驱动板动力输入端标注工作电压范围为 6～18 V，并配置 220 μF 母线电容用于吸收电机启动、换向和快速加减速过程中的瞬态电流，降低动力母线波动。左右电机分别通过独立 XT30 接口与驱动板连接，便于安装与维护。
0174 4.3.2  EMAX 2207 负压无刷电机电调驱动
0175 图4.4  EMAX 2207 负压无刷电机电调原理图
0176 负压机构采用 EMAX 2207 无刷电机作为动力源，并使用独立三相无刷电调进行驱动。电调由 Ai8051 主控、FD6288Q 三相栅极驱动器、六只 TPH2R703NL 功率 MOSFET、三相采样网络、电池输入滤波、电压采样及 PWM 输入接口等部分组成。主控板通过 PWM 输入接口向电调发送调速指令，电调再完成三相换相与功率放大。
0177 无刷电机功率级直接使用 3S 电池母线供电。由于电机高速换相时会产生较大的脉动电流，电池输入端并联多组 22 μF 电容形成集中储能与滤波网络，用于降低母线纹波和瞬态压降。电调同时设置由 3S 电池母线产生的 5 V 控制电源，为 Ai8051 等低压控制电路提供工作电源。
0178 Ai8051 根据运行控制产生三组互补 PWM 信号并送入 FD6288Q。FD6288Q 输出 HOA、HOB、HOC 与 LOA、LOB、LOC 六路高低侧栅极驱动信号，分别控制三相桥臂。功率逆变级由 6 只 TPH2R703NL N 沟道 MOSFET 构成，每相由一个高侧器件和一个低侧器件组成，三相桥臂中点分别形成 VSA、VSB、VSC，并连接无刷电机三相绕组。高侧驱动外围配置二极管和自举电容网络，为高侧 N 沟道 MOSFET 提供浮动栅极驱动电源。
0179 三相 VSA、VSB、VSC 节点分别经电阻分压和 RC 滤波形成 ABMF、BBMF、CBMF 三路采样信号并送回 Ai8051。该采样网络为无位置传感器换相提供三相反电动势信息，使控制器能够根据电机运行状态确定换相时机。
0180 电调还设置电池电压 ADC 采样电路，VBAT 经 47 kΩ 与 10 kΩ 电阻分压后送入 BATADC，并由 100 nF 电容滤波。其理想分压关系为 V_ADC = V_BAT × 10/(47+10) ≈ 0.175V_BAT，使 3S 电池母线电压能够转换到主控 ADC 可测量范围，用于运行状态监测。
0181 通过上述三相驱动结构，主控系统可经 PWM 输入调节 EMAX 2207 的运行状态与转速，使负压机构根据设定输出工作。无刷电机与机械负压风道共同产生附加下压力，为车模高速运行时提高轮胎法向载荷和可利用附着力。
0182 4.4  电气可靠性设计
0183 整车动力部分与传感器信号部分在布线和接口上尽量分离，大电流回路采用短路径和较大铜面积，传感器与数字电路配置就近去耦；主控板对 5 V 外设设置受控上电，减少上电瞬间的电源扰动。
0184 负压无刷电调属于整车主要发热单元。早期四层 PCB 在持续大电流工作时温升较快，后续改为六层 PCB，并在 MOSFET、母线和三相功率路径周围增加大面积铺铜及散热过孔。该改进能够满足约 90% PWM 占空比下的长时间运行，但极高占空比工况仍需注意温升。
0185 第五章  软件系统实现与核心算法
0186 5.1  软件问题结构与任务分解
0187 “走马观碑”组的核心任务不是单一循迹，而是在斑马线后完成发车，在 PVC 白色赛道和蓝色背景地面之间稳定识别赛道边界，并在赛道两边界中心附近连续遇到多个目标板时完成识别、决策和绕行。由此可将软件问题拆分为起步识别问题、白色赛道循迹问题、目标板识别问题和目标板动作执行问题四个层次。
0188 5.1.1  场景约束与主要难点
0189 首先，车辆从斑马线后方发车，近端图像中会同时出现高对比度横纹和赛道白边，若直接按普通白线搜索，容易把斑马线纹理误认为有效边界，因此软件需要在底部参考区域和远端参考列之间建立稳定的前瞻判断。其次，赛道为 PVC 白色边界、蓝色背景地面，颜色区分明显但反光和曝光变化会改变灰度阈值，循迹算法不能只依赖固定阈值，而要结合参考点、纵向对比度和连续边线约束。
0190 再次，目标板位于赛道两边界中心附近，且一圈中可能出现多个目标板。目标板识别必须满足两个条件：一是只在赛道有效区域内触发，避免蓝色背景或场外红色干扰造成误识别；二是每个目标板只触发一次动作，处理完成前不能被连续帧重复识别打断。最后，识别结果还要转化为车辆动作，物资、交通工具、武器分别对应右绕、直行和左绕，并且同一动作在直道、左弯、右弯上的轨迹并不相同。
0191 5.1.2  软件任务分解
0192 针对上述问题，软件任务被分解为五条处理链。第一条是发车与赛道感知链，利用摄像头图像完成底部参考点、参考列、左右边线和 remote_search_Line 的计算，为斑马线后的起步和普通循迹提供可见前瞻。第二条是目标触发链，在赛道边界约束下检测红色标志，并通过面积、连续行和位置条件筛掉无效红色。第三条是目标分类链，将红色标志附近的图像通过 IPM/逆透视裁剪成稳定的 50×50 输入，再交给 NCNN 轻量化模型分类。
0193 第四条是任务决策链，将九个细分类结果归并为物资、交通工具、武器三类任务，并用锁存式状态机保证一个目标板只对应一次动作。第五条是运动执行链，把普通循迹、目标板左右绕行和直行通过统一为虚拟中线跟踪问题，再由视觉外环、IMU 角速度内环和编码器速度环生成左右轮 PWM。这样，第五章后续各节均按照“任务难点—代码措施—控制效果”的顺序展开。
0194 5.1.3  问题与软件措施对应关系
0195 斑马线后发车对应的措施是：不在启动阶段依赖单点阈值，而通过 reference_point、reference_col 和 remote_search_Line 描述当前可见赛道范围，并用纵向灰度对比度 D 判断白色 PVC 赛道的连续性。白色赛道与蓝色背景循迹对应的措施是：在 160×120 灰度图中提取 left_edge_line、right_edge_line 和 mid_Line，再用多行加权误差 E=Σ[w_i·(C−M_i)]/Σw_i 作为控制输入。
0196 多个目标板识别对应的措施是：红色检测先被限制在左右边线之间和赛道中线附近，再通过 IPM 前向 ROI 保证弯道和直道中的目标输入形态一致；NCNN 输出经 0.65 置信度门限筛选后才进入状态机。目标板绕行对应的措施是：分类结果不直接作用到电机，而是先锁存为 LEFT、RIGHT 或 STRAIGHT，再结合 Curve_Flag、imu660RC 偏航角和 1024 线编码器距离执行 PRE、OUT、STRAIGHT 等阶段，保证连续目标板之间动作边界清晰。
0197 5.2  软件总体架构与数据流
0198 本车软件围绕“稳定循迹、可靠识别、平滑绕行”三个目标展开。系统采用上位机训练与车载端实时运行相结合的方式：上位机完成数据集整理、轻量化分类模型训练、精度评估和模型格式转换；LS2K0300 车载端负责摄像头采集、赛道边线识别、红色目标预检测、NCNN 推理、目标板状态机决策以及电机闭环控制。
0199 车载主流程可以概括为：龙邱科技灵眼 Pro 摄像头采集 320×240 彩色图像，缩放得到 160×120 图像并转换为灰度图；灰度图用于赛道边界和中线计算，彩色图用于红色目标检测，原始彩色图用于目标区域精确裁剪。分类结果不直接驱动电机，而是先转换为任务类别，再由状态机结合 imu660RC 偏航反馈和 1024 线增量式编码器距离生成绕行策略。
0200 该结构将高频控制和相对耗时的视觉推理解耦：常规循迹每帧执行，神经网络只在红色目标进入有效区域后触发，并设置置信度门限和推理冷却时间，避免无效推理和连续重复触发。
0201 软件数据流：320×240 图像 → 160×120 循迹/红色预检测 → 50×50 ROI → NCNN → 类别映射 → 状态机 → 电机控制
0202 5.2.1  主程序数据流
0203 主程序启动后依次完成龙邱科技灵眼 Pro 摄像头、NCNN 分类器、imu660RC、1024 线增量式编码器、PWM、电机驱动、TCP 图传和周期定时器初始化。每次获得新图像后，程序先调用 image_process() 提取左右边线，再调用 ClassifyRedTarget() 完成红色目标检测与必要的神经网络分类。随后通过 Ncnn_GetResult() 读取识别结果，并交给 TargetBoard_UpdateFromNcnn() 更新目标板状态。
0204 运动控制部分在图像处理后计算 Err_Sum()，得到当前帧的横向误差。若目标板状态机处于绕行阶段，TargetBoard_GetTargetMidline() 会把普通赛道中线替换为基于左右边线偏移得到的虚拟中线，从而使后续方向控制器仍沿同一接口工作。
0205 5.2.2  软件模块划分
0206 软件按功能划分为赛道识别模块、目标识别模块、目标板决策模块、方向与速度控制模块、传感器采集模块和调试通信模块。赛道识别模块维护 left_edge_line、right_edge_line、mid_Line、remote_search_Line 等全局赛道信息；目标识别模块输出 red_detected 与 class_id；目标板模块将 class_id 锁存为 LEFT、RIGHT 或 STRAIGHT 动作；控制模块根据视觉误差、imu660RC 角速度和编码器速度输出左右轮 PWM。
0207 5.3  传感器采集与实时任务划分
0208 5.3.1  摄像头与多分辨率处理
0209 视觉传感器采用龙邱科技灵眼 Pro。工程中通过 lq_camera_ex 将摄像头配置为 320×240、120 fps 和手动曝光，并选择 LQ_CAMERA_0CPU_MJPG 低 CPU 占用采集路径；底层设置 MJPG FOURCC，采集后再按任务需要生成彩色图、灰度图和缩放图。灵眼 Pro 具备较灵活的输出与采集方式，后续若切换 YUYV 等低开销格式，也可以沿用当前多分辨率处理链。
0210 软件将原图缩放为 160×120，用于循迹和红色目标快速检测；分类时再回到 320×240 原图进行透视裁剪，最终形成 50×50 网络输入。低分辨率处理保证实时性，高分辨率裁剪保证分类区域的细节，低 CPU 占用采集模式则为灰度循迹、红色检测和 NCNN 推理留出更多处理时间。
0211 5.3.2  IMU 与编码器信息
0212 IMU 采用 imu660RC，其 Z 轴角速度用于方向内环反馈，并在目标板预偏移阶段积分得到 Card_Angle，作为第一段绕行是否完成的判据。编码器采用 1024 线增量式编码器，左右轮编码器一方面为速度闭环提供实际速度，另一方面累计平均位移，用于目标板正式绕行、直行通过和退出低速保持等状态切换。视觉、IMU 与编码器共同构成位置、姿态和距离的互补反馈。
0213 为减小控制抖动，方向外环、角速度内环和速度环输出均加入一阶低通滤波。其通用形式为 u(k)=A·u*(k)+(1−A)·u(k−1)，其中方向外环和角速度内环 A=0.90，速度环 A=0.95。
0214 5.4  赛道识别与循迹误差计算
0215 5.4.1  参考列与左右边线搜索
0216 image_process() 对灰度图进行一帧初始化后，先计算参考点和参考列，再以最长白列及参考列作为边界搜索起点，由近端向远端跟踪左右赛道边线。程序记录每行的 left_edge_line 与 right_edge_line，同时统计单边丢线、双边丢线、边界起始点和连续性变化，为 PVC 白色赛道循迹、斑马线后起步、弯道判断、环岛和目标板绕行提供共享判据。
0217 参考点 reference_point 由图像底部参考区域的灰度均值得到，并据此计算白点判断阈值 white_max_point 与 white_min_point。随后程序在候选列上自下而上比较当前像素与上方像素的灰度差异，以判断该列能够连续观察到的最远赛道位置。纵向对比度定义为：
0218 D = 200 × [I(row,col) − I(row−Lineoffset,col)] / [I(row,col) + I(row−Lineoffset,col)]公式1
0219 式中，I(row,col) 为当前像素灰度值，Lineoffset 为纵向比较间隔。当 D 大于 reference_contrast_ratio，或搜索到达 STOPROW 时，将该行记录为 remote_distance[col]。所有候选列中最长白列对应的列号作为 reference_col，其远端行 remote_search_Line 用于表征本帧赛道的有效前瞻范围。
0220 红色目标检测也使用左右边线限制有效搜索区域。目标必须位于赛道边界之间，才允许进入后续几何分析和分类流程，从源头减少赛道外红色背景造成的误触发。
0221 5.4.2  加权中线误差
0222 常规循迹采用多行中线加权方式计算车辆横向误差。对于第 i 行，左右边线分别记为 L_i、R_i，中线位置为：
0223 M_i = (L_i + R_i) / 2公式2
0224 设图像中心横坐标为 C，第 i 行权重为 w_i，则综合循迹误差为：
0225 E = Σ[w_i(C − M_i)] / Σw_i公式3
0226 该误差直接反映车辆相对赛道中心的横向偏移。不同场景使用不同权重表，使近端与远端边线对控制量的贡献可根据道路状态进行调整。
0227 Weight、Island_Weight 和 Target_Weight 分别对应普通赛道、环岛和目标板绕行等场景。普通循迹时求和区间为 remote_search_Line 至图像底部；目标板红色预减速或分类绕行阶段使用 Target_Weight，并从图像底部累计到 remote_search_Line+20，弱化远端不稳定边线对绕行方向的影响。不同权重表改变远近图像行对误差的贡献，目标板状态机还可以通过虚拟中线叠加左右偏移，使普通循迹、特殊元素和目标绕行共用同一套误差接口。
0228 5.5  红色目标检测与 NCNN 分类
0229 5.5.1  YCrCb 红色预检测
0230 为了降低车载端神经网络推理负担，程序先利用颜色特征和空间连续性完成红色标志预检测。源码不直接在 RGB 空间判定红色，而是由 BGR 像素换算亮度 Y、红色色度 Cr 和蓝色色度 Cb：
0231 Y = (77R + 150G + 29B + 128) / 256公式4
0232 Cr = 183(R − Y) / 256 + 128公式5
0233 Cb = 144(B − Y) / 256 + 128公式6
0234 实际调试后采用的主要红色判据为：Y≥28、Cr≥150、Cb≤128、Cr−Cb≥48 且 Cr−Y≥14。多条件联合判断能够减小暗色区域、蓝色背景及高亮反光对红色检测的干扰。
0235 红色搜索并不遍历整幅图像，而是结合赛道远端位置和左右边线建立动态检测区域。纵向搜索范围为：
0236 row_start = max(kRedRowMin160, remote_search_Line + kRedLaneStartOffset160, STOPROW)公式7
0237 row_end = min(SEARCH_IMAGE_H − 1, image_h − 1, kRedRowMax160)公式8
0238 当前代码中 kRedRowMin160=18、kRedRowMax160=65、kRedLaneStartOffset160=−5。对每一行，横向搜索区域进一步限制在赛道中线附近：
0239 [x_0,x_1] = [max(L_i,M_i−b_i), min(R_i,M_i+b_i)]公式9
0240 其中 M_i=(L_i+R_i)/2，较远区域 b_i 取 40，近端区域取 20。这样可以将红色候选限制在有效赛道范围内，减少背景误检。
0241 检测时先自下而上寻找种子行，再沿红色区域向远端连续跟踪。设第 i 行检测到的连续红色段为 [a_i,b_i]，其长度为：
0242 n_i = b_i − a_i + 1公式10
0243 根据各行红色段可计算连通区域面积及质心：
0244 A = Σn_i公式11
0245 x_c = Σ[(a_i+b_i)n_i/2] / A公式12
0246 y_c = Σ(i·n_i) / A公式13
0247 实际判断还结合种子行连续长度、有效命中行数、连续命中行数以及赛道边界约束。只有满足这些条件的红色区域才进入后续几何分析。
0248 5.5.2  红色几何分析与 IPM 单应变换
0249 当红色中心达到设定的可分类距离后，程序才进入原图级几何分析和 NCNN 推理。首先将 160×120 检测图中的坐标映射回 320×240 原图：
0250 x_f = round(x_d · W_f / W_d)公式14
0251 y_f = round(y_d · H_f / H_d)公式15
0252 随后以映射后的红色中心构造局部搜索窗口，窗口尺寸取 s=max(56,2·max(w_bbox,h_bbox))，并在原图中重新生成红色 mask，通过四邻域连通搜索获得更完整的红色连通域。
0253 IPM 采用平面单应模型。设原图像素齐次坐标为 p=[x,y,1]^T，IPM 俯视坐标为 q=[X,Y,1]^T，则二者满足：
0254 q ≈ H_ipm · p公式16
0255 展开后可写为：
0256 X = (h00x + h01y + h02) / (h20x + h21y + h22)公式17
0257 Y = (h10x + h11y + h12) / (h20x + h21y + h22)公式18
0258 其中 H_ipm 为图像坐标到俯视坐标的单应矩阵，H_img=H_ipm⁻¹ 用于将 IPM 坐标重新投影回原图。两组矩阵均由专用标定软件根据最终摄像头安装姿态和赛道平面标定点求解得到，并固化在程序中使用。
0259 将红色连通域像素投影到 IPM 平面后，先计算质心：
0260 c = (1/N) Σq_i公式19
0261 再利用二阶矩估计红色标志的主方向，其中：
0262 cov_xx = Σ(X_i−X_c)²公式20
0263 cov_xy = Σ(X_i−X_c)(Y_i−Y_c)公式21
0264 cov_yy = Σ(Y_i−Y_c)²公式22
0265 θ = 0.5 · atan2(2cov_xy, cov_xx−cov_yy+10⁻⁹)公式23
0266 由此得到主轴方向 u=[cosθ,sinθ]^T 及其垂直方向 v=[−u_y,u_x]^T。程序还根据红色中心附近的赛道中线估计车辆前向方向，并通过点积符号修正 u、v 的方向，使横向轴与赛道横向一致，纵向轴始终指向目标前方。
0267 5.5.3  IPM 前向 ROI 与逆透视裁剪
0268 获得红色标志在 IPM 平面的四个包围点后，将各点相对质心 c 分别投影到横向主轴 u 和前向轴 v：
0269 α_i = (q_i − c) · u公式24
0270 β_i = (q_i − c) · v公式25
0271 由投影极值得到红色标志在俯视平面中的宽度和高度：
0272 W = max(4, α_max − α_min)公式26
0273 H = max(2, β_max − β_min)公式27
0274 分类 ROI 不直接覆盖红色标志本体，而是在其前方动态扩展。横向边距、前向间隔和裁剪高度分别为：
0275 p = max(0.22, 0·W)公式28
0276 g = max(0.10, 0.10H)公式29
0277 h = max(2.45H, 0.92W)公式30
0278 这种尺度自适应设计能够使远近不同的目标获得相对一致的分类区域。
0279 据此在 IPM 平面构造前向分类四边形：
0280 Q₁ = c + (α_min−p)u + (β_max+g+h)v公式31
0281 Q₂ = c + (α_max+p)u + (β_max+g+h)v公式32
0282 Q₃ = c + (α_max+p)u + (β_max+g)v公式33
0283 Q₄ = c + (α_min−p)u + (β_max+g)v公式34
0284 随后利用 H_img 将 Q₁～Q₄ 逆投影回 320×240 原图。由于 ROI 的“前方”由赛道实际前向方向定义，而不是固定的图像上下方向，因此车辆处于左弯、右弯或不同偏航姿态时，裁剪区域仍能保持与目标相近的地面相对位置。
0285 得到原图四边形后，程序利用透视变换将其归一化为 50×50 分类图像。目标点设置为 D₁=(0,0)、D₂=(49,0)、D₃=(49,49)、D₄=(0,49)，透视矩阵由 OpenCV 的 getPerspectiveTransform() 求得。输出关系可概括为：
0286 I_out(u,v) = I_full(T⁻¹[u,v,1]^T)公式35
0287 随后通过 warpPerspective() 完成双线性插值。该处理使不同弯道和透视条件下的目标在网络输入中具有更一致的位置、方向和尺度，从而降低分类网络需要学习的几何变化。
0288 如果 IPM 前向 ROI 构造失败，代码会退化为 build_marker_body_crop_quad()：以红色标志四角中心为基准，按标志宽高略微外扩后裁剪。这一退化分支保证异常帧不会直接中断流程，但正常情况下优先使用 IPM 前向 ROI，以获得更稳定的目标内容区域。
0289 5.5.4  轻量化分类网络与置信度筛选
0290 训练得到的 PyTorch 模型导出为 ONNX FP32 后，再转换为 NCNN FP32，车载端加载 hhh.ncnn.param 和 hhh.ncnn.bin。实际部署网络包含普通卷积、Depthwise Convolution、全局平均池化和全连接分类层，共 7371 个参数，输出 9 个细分类别。深度可分离卷积先在每个通道内做空间卷积，再用 1×1 卷积完成通道融合，相比同规模普通卷积可显著减少运算量。
0291 分类器将裁剪图像统一缩放为 50×50，完成 BGR→RGB 转换和归一化后送入 NCNN。网络输出 logits 经 Softmax 转换为类别概率。为提高数值稳定性，计算前先减去最大 logit：
0292 P_i = exp(z_i−z_max) / Σ_j exp(z_j−z_max)公式36
0293 程序取概率最大的类别作为预测结果，并设置最小有效置信度 0.65。低于该阈值的结果视为无效，不进入目标板状态机。
0294 九个细分类标签分别为 suppliers/jijiubao、suppliers/wangyuan、vehicle/jiuhu、vehicle/zhuangjia、weapon/buqiang、weapon/c4、weapon/shouliu、weapon/shouqiang 和 weapon/shuzhuang。车载端最终将其归并为物资、交通工具、武器三类任务，其中物资对应右绕，交通工具对应直行，武器对应左绕。
0295 5.6  任务决策与目标板状态机
0296 5.6.1  识别结果锁存
0297 目标板流程采用“红色先锁存、分类后执行”的策略。第一次检测到红色时，系统进入预减速和等待分类状态；当目标进入可分类距离并得到有效类别后，锁存本次类别和道路类型，后续连续帧的识别变化不再改变当前动作。若红色出现后长期没有有效分类，状态机会超时清除，并等待画面中的目标完全消失后才允许下一次触发。
0298 状态机输入不是直接使用九分类输出，而是先映射为三类任务变量：物资 target_material_now、交通工具 target_vehicle_now、武器 target_weapon_now。第一次检测到红色时置 target_process_lock_flag=1、target_red_lock_flag=1、target_red_slow_flag=1；只有在红色锁存后，分类结果才允许触发动作。若 target_red_wait_cnt 达到 100 仍无有效分类，则清除本轮状态并置 target_red_ignore_until_clear_flag，等待 red/class 全部消失后再允许下一次识别。
0299 5.6.2  多阶段绕行动作
0300 目标板核心状态包括 IDLE、LEFT_PRE、RIGHT_PRE、LEFT_OUT、RIGHT_OUT 和 STRAIGHT。物资类映射为 TARGET_CMD_RIGHT，进入 RIGHT_PRE；武器类映射为 TARGET_CMD_LEFT，进入 LEFT_PRE；交通工具类映射为 TARGET_CMD_STRAIGHT，直接进入 STRAIGHT。第一段 PRE 主要用于提前把车身转向绕行侧，第二段 OUT 再按编码器距离完成正式绕行。
0301 目标板绕行仍复用普通循迹误差接口，关键在于根据状态机生成“虚拟中线”。普通状态下：
0302 M_i = (L_i + R_i) / 2公式37
0303 左绕状态（LEFT_PRE、LEFT_OUT）采用：
0304 M_i* = clip(L_i − o, 0, W−1)公式38
0305 右绕状态（RIGHT_PRE、RIGHT_OUT）采用：
0306 M_i* = clip(R_i + o, 0, W−1)公式39
0307 其中 o 为阶段相关偏移量。直道第一、第二阶段分别取 7 和 3；弯道内绕分别取 7 和 0；弯道外绕分别取 7 和 3。这样可把绕行动作等效为“跟踪一条偏移后的中线”，后级控制器无需重新设计。
0308 第一阶段 PRE 的退出采用角度、编码器和计数三重保护。分类成功后，目标板专用偏航量清零，并根据 imu660RC 的 Z 轴角速度进行离散积分：
0309 CardAngleSpeed(k) = CardAngleSpeed(k−1) + gyro_z · GYRO_SENS · dt公式40
0310 Card_Angle(k) = −[K·CardAngleSpeed(k) + (1−K)·LastCardAngleSpeed]公式41
0311 其中 dt=0.005 s，GYRO_SENS=1/16.4。RIGHT_PRE 在 Card_Angle≥θ_pre 时切换，LEFT_PRE 在 Card_Angle≤−θ_pre 时切换，当前 θ_pre=15°。若角度尚未达到阈值，但编码器距离或状态计数超过保护值，也会强制进入 OUT 阶段。
0312 路况在有效分类成功后才锁存，来源为 Curve_Flag=Curve_Debug(red_bottom_row)。CURVE_LEFT 锁存为左弯，CURVE_RIGHT 锁存为右弯，未知或直道均按直道处理。随后根据“道路方向 + 动作方向”判断绕行类型：左弯左绕、右弯右绕为弯道内绕；左弯右绕、右弯左绕为弯道外绕；直道左右绕为普通绕行；车辆类为直行。第二段编码器阈值按类型分组，直道 OUT 为 4500，弯道内绕 OUT 为 1000，弯道外绕 OUT 为 8000，车辆直行为 500。
0313 弯道外绕额外加入外侧丢线修正。左弯右绕时监测 Right_Lost_Time，右弯左绕时监测 Left_Lost_Time；当外侧丢线数达到 65 时，状态机不改变 LEFT_OUT/RIGHT_OUT 主状态，也不清空编码器，而是临时令 TargetBoard_ErrProcess() 输出固定误差。左弯外绕固定误差为 +45，右弯外绕固定误差为 −45，并由 Card_Angle 达到约 5° 后退出该临时修正。
0314 5.7  运动闭环控制算法
0315 本车采用“视觉位置外环 + IMU 角速度内环 + 编码器速度内环”的三层串级闭环控制结构。其中视觉外环负责根据赛道中线误差生成期望转向趋势，IMU 角速度环抑制车身姿态变化带来的转向滞后，左右轮速度 PI 环根据 1024 线增量式编码器反馈实现差速驱动。该结构属于三层串级控制，但各环并非全部为标准 PID：视觉外环为 PD 加非线性比例项，角速度内环为 PD，速度环为增量式 PI。
0316 5.7.1  视觉位置外环
0317 视觉位置外环以加权横向误差 e 为输入，输出目标角速度 ω_ref。除常规比例、微分项外，程序增加了二次非线性比例项：
0318 ω_ref = K_p·e + K_p2·e|e| + K_d[e(k)−e(k−1)]公式42
0319 其中 K_p 决定基础纠偏强度，K_d 抑制误差快速变化引起的摆动，K_p2·e|e| 用于在大误差时增强转向能力。
0320 普通循迹时 K_p=130、K_d=50，K_p2 根据道路状态动态切换，环岛阶段可提高至 3.5。外环输出还经过一阶低通滤波：
0321 ω_ref(k) = 0.90·ω_raw(k) + 0.10·ω_ref(k−1)公式43
0322 因此小误差时系统保持较平稳的直线响应，而在大弯或偏差较大时能够迅速增加转向力度。
0323 5.7.2  IMU 角速度内环
0324 IMU 角速度内环以外环给出的目标角速度 ω_ref 为参考，以 imu660RC 的 Z 轴角速度 ω_g 为反馈。误差定义为：
0325 e_ω(k) = ω_g(k) − ω_ref(k)公式44
0326 微分项只对实际角速度变化求差：
0327 D(k) = ω_g(k) − ω_g(k−1)公式45
0328 控制输出为：
0329 u_ω = K_pω·e_ω + K_dω·D(k)公式46
0330 这种“微分先行”形式避免目标角速度突变直接造成 D 项冲击。
0331 普通循迹时 K_pω≈0.029，目标板绕行时提高到约 0.045，K_dω≈0.03。角速度环输出同样进行一阶低通：
0332 u_ω(k) = 0.90·u_raw(k) + 0.10·u_ω(k−1)公式47
0333 滤波后的 u_ω 作为左右轮目标速度的差速修正量。
0334 5.7.3  左右轮增量式 PI 速度环
0335 左右轮分别使用 1024 线编码器构成速度闭环。虽然程序函数名保留 speed_pid，但实际控制形式为增量式 PI：
0336 u(k) = u(k−1) + K_p[e_v(k)−e_v(k−1)] + K_i·e_v(k)公式48
0337 当前左右轮基础参数均为 K_p=30、K_i=5。控制输出经过低通滤波和 PWM 限幅后送入电机驱动。
0338 方向内环输出以相反符号叠加到左右轮目标速度，从而形成差速转向：
0339 v_L* = v_ref + u_ω公式49
0340 v_R* = v_ref − u_ω公式50
0341 左右轮速度误差分别为：
0342 e_L = v_L* − v_L，    e_R = v_R* − v_R公式51
0343 速度环原始输出再进行低通滤波：
0344 u_v(k) = 0.95·u_raw(k) + 0.05·u_v(k−1)公式52
0345 最后经 Motor_Limit() 限幅后输出 PWM。
0346 为使车辆速度与视觉前瞻能力匹配，程序根据 remote_search_Line 动态限制 PWM 上限。当前策略为：11～15 行取 9000，16～30 行取 8000，超过 48 行取 7500；31～48 行之间采用线性插值：
0347 limit = 8000 − [(remote_search_Line−31)/(48−31)]·(8000−7500)公式53
0348 因此当赛道远端信息不足时，系统会自动降低最大驱动力；前瞻充分时则允许更高输出，提高高速循迹的安全裕量。
0349 5.7.4  目标减速与退出恢复
0350 红色目标首次出现后，系统先进入低速准备状态，为分类和制动留出余量；分类绕行期间继续保持较低速度；绕行结束后再依据编码器累计距离维持一小段退出低速，随后恢复普通循迹速度。该策略避免“刚完成大角度绕行就立即加速”带来的横向振荡。
0351 5.8  模型训练与嵌入式部署
0352 5.8.1  训练流程
0353 run_all_50.ps1 将训练、评估和模型转换组织为一键流水线。当前配置使用 dataset2 数据集，输入尺寸 50×50，Batch Size 为 96，最大训练 45 轮，初始学习率 2×10⁻³，Weight Decay 为 2.1×10⁻⁴，随机种子为 42，网络宽度系数 width_mult=0.80。数据按 0.55、0.30、0.15 划分训练集、验证集和测试集，并设置 patience=3 的提前停止机制。
0354 训练脚本采用随机水平翻转、随机旋转和颜色扰动增强训练样本；验证和测试阶段仅进行尺寸统一与归一化。优化器使用 AdamW，学习率调度采用 CosineAnnealingLR。训练过程中保存验证集最佳模型，并输出 labels.txt、metrics.json 和 ONNX 模型。
0355 5.8.2  训练结果与部署文件
0356 当前 artifacts50/metrics.json 显示，最佳验证准确率为 99.87%，测试细分类准确率为 99.90%，测试粗分类准确率为 99.96%；随机抽取 45000 个样本复核时，细分类准确率为 99.94%，粗分类准确率为 99.95%。训练完成后模型导出为 tiny_classifier_fp32.onnx，并通过转换脚本生成 hhh.ncnn.param 与 hhh.ncnn.bin，连同 labels.txt 一起部署到车载端 /home/root/class/model 目录。
0357 嵌入式端使用 NCNN 推理框架加载模型，分类结果经标签前缀映射为三类任务。由于训练端、转换端和车载端都统一使用 50×50 输入和相同归一化参数，减少了模型迁移过程中输入尺度、颜色通道和标签顺序不一致造成的误差。
0358 5.9  软件设计小结
0359 综上，软件系统以低成本图像算法完成高频循迹和红色目标筛选，以轻量化神经网络完成目标细分类，以状态机把识别结果转换为连续、可控的运动动作。视觉、IMU 和编码器信息在不同层级形成互补，使车模在常规赛道、目标板和特殊路况下均能保持较稳定的闭环控制。

0387 板卡运行环境配置完成后，使用 MobaXterm 与 LS2K0300 建立终端连接。连接成功后进入车载程序所在目录，通过命令行启动程序，并观察终端输出信息。首次运行主要检查摄像头、imu660RC、左右轮编码器、DL1B TOF 测距模块、NCNN 模型以及电机控制相关模块是否能够正常初始化。
0388 当程序运行过程中出现异常时，根据终端输出定位问题，返回 VS Code 和 Ubuntu 环境修改程序或配置，再重新编译并上传至 LS2K0300。通过多次“修改—编译—上传—启动—检查”的迭代，最终完成车载程序运行环境的安装与验证。
0389 6.2.5  环境配置与安装流程总结
0390 本车开发环境的实际配置流程可概括为：参考逐飞科技 LS2K0300 教学资料，完成 Ubuntu 开发环境和工程依赖配置；配置 SSH 并使用 VS Code 远程连接 Ubuntu；完成工程首次编译；建立与 LS2K0300 板卡的网络连接并上传目标程序及模型文件；最后通过 MobaXterm 登录板卡并启动程序进行运行验证。
0391 通过参考成熟的平台开发教程进行环境搭建，可以减少 LS2K0300 初期开发过程中由工具链、系统依赖和远程连接配置不正确造成的问题，为后续车模软件开发、程序部署和实车调试提供稳定的基础环境。
0392 6.3  调试过程与问题分析
0393 6.3.1  机械调试
0394 车模早期机械调试主要集中在摄像头安装位置和整车重心分布两个方面。初期摄像头安装高度及俯视范围与视觉算法匹配不够理想，采集图像中近端和远端赛道比例不稳定，导致左右边线提取及目标区域识别效果较差。随着车速提高，视觉前瞻不足对方向控制的影响更加明显。
0395 针对该问题，通过多次改变摄像头高度和俯视范围进行实车对比，最终将摄像头安装高度调整为距车模底板约34 cm。调整后，图像能够同时保留较完整的近端赛道信息和足够的远端前瞻区域，赛道边界、红色标志及分类 ROI在图像中的位置更加稳定，视觉识别效果得到明显改善。摄像头机械位置确定后保持固定，以保证后续IPM标定参数与实际安装姿态一致。
0396 整车重心同样是高速调试中的关键机械因素。早期车体质量分布偏前，低速运行时影响不明显，但车速提高后，在弯道和快速方向修正过程中后轮容易产生横向滑移，表现为甩尾和打滑较严重。该现象会降低转向稳定性，也会使编码器测得的轮速与车体实际运动状态出现偏差。
0397 在保持负压机构基本结构不变的条件下，对电池、主控板及相关部件的位置重新布置，使整车重心适当后移，增加后部驱动轮的有效法向载荷。调整后，高速弯道中的后轮附着状态明显改善，甩尾和打滑现象减少，车模在普通循迹和目标板绕行过程中的轨迹更加稳定。经过摄像头位置与重心分布的联合优化，为后续软件控制参数整定提供了较稳定的机械基础。
0398 6.3.2  电路调试
0399 电路调试过程中，主要问题集中在Ai8051 无刷电调长时间大电流工作时的散热能力。早期电调采用四层 PCB设计，在一般负载下能够正常驱动EMAX 2207无刷电机，但负压系统以较高占空比持续运行时，MOSFET 及大电流走线温升较快，四层板的铜箔导热与热扩散能力不足，不利于负压系统长时间稳定工作。
0400 针对该问题，后续将Ai8051 无刷电调由四层 PCB改为六层 PCB，并重新优化功率级布局和散热结构。在MOSFET、电池母线及三相大电流路径周围采用大面积铺铜，降低导体电阻并扩大有效散热面积；同时在功率器件及大面积铜皮区域布置较多散热过孔，将表层热量快速传导至内部铜层和另一侧铜层，提高整板热扩散能力。
0401 经过六层板、大面积铺铜和散热过孔优化后，电调持续散热能力明显提升。实车测试中，改进后的电调能够支持EMAX 2207负压电机在约90% PWM 占空比条件下长时间进行大电流输出，满足车模高速运行过程中负压机构持续工作的需求。该调试过程表明，负压电调设计除考虑瞬时电流能力外，还需要综合考虑PCB层数、铜箔面积、大电流路径和散热过孔等热设计因素。
0402 6.3.3  软件调试
0403 软件调试主要围绕红色目标检测与分类参数、IPM 逆透视标定、分类 ROI 几何参数以及方向/速度闭环控制参数的确定展开。由于这些参数同时受到摄像头安装姿态、赛道光照、车辆速度和实际机械响应的影响，因此最终参数以实车运行效果为依据，通过反复采集图像、观察调试输出和实车测试逐步确定。
0404 6.3.3.1  红色目标检测与分类参数调试
0405 目标识别首先需要确定模型输入、颜色阈值、检测范围、连通域尺寸和分类置信度等参数。当前分类模型输入尺寸固定为50×50 像素，分类前对裁剪图像整体进行约1.2倍亮度增强，以提高不同光照条件下目标纹理的可辨识度；最低有效分类置信度设置为0.65，最大类别概率低于65%的结果不进入目标板状态机。
0406 红色目标在160×120 检测图中进行预检测。经实车反复测试，有效检测行范围最终主要限制在第24～65行，原始320×240 图像中的红色连通域面积约限制为120～640像素。普通检测带以赛道中线为中心，半宽约20像素，较远区域可扩展至约40像素，从而兼顾弯道目标覆盖范围与赛道外干扰抑制。红色区域还通过连续像素长度、有效行数和连续命中行数进行筛选，减少零散噪声触发。
0407 颜色判断采用YCrCb 特征。调试后主要阈值为Y≥28、Cr≥150、Cb≤128，同时要求Cr-Cb≥48、Cr-Y≥14。上述阈值通过不同光照和赛道位置下的实车图像逐步修正，在保证目标稳定检测的同时，降低白色PVC反光、蓝色背景及高亮区域被误判为红色的概率。
0408 6.3.3.2  IPM 逆透视参数标定
0409 目标ROI构造使用IPM（Inverse Perspective Mapping，逆透视映射）进行图像坐标与俯视平面坐标之间的变换。需要特别说明的是，程序中使用的图像到IPM单应矩阵及其逆矩阵并非根据经验手工填写，而是通过专用标定/标注软件，根据摄像头最终安装姿态和赛道平面标定点求解得到。
0410 标定时首先固定摄像头最终机械位置，并在实际赛道平面选取若干具有明确几何对应关系的标定点，在标定软件中分别标注其图像坐标与目标俯视平面坐标。软件依据这些对应点求解平面单应矩阵H_IPM，使图像点p_img与俯视坐标p_IPM满足 p_IPM ~ H_IPM·p_img；同时计算逆矩阵H_IMG，用于将IPM坐标重新投影回原始图像。
0411 由于单应矩阵与摄像头高度、俯视角和相对车体位置直接相关，因此机械调试将摄像头高度最终确定为约34 cm后，以该最终安装状态重新完成IPM标定。若摄像头位置变化而仍沿用旧矩阵，会造成目标方向估计和分类 ROI位置偏移。标定完成后，通过直道、左弯和右弯场景实际观察50×50推理裁剪图，确认目标位置、尺度和朝向在不同赛道曲率下保持较好一致性。
0412 6.3.3.3  分类 ROI 几何参数调试
0413 在IPM平面中确定红色标志位置和方向后，还需要调节分类区域相对于红色标志的前向间隔、横向扩展和裁剪高度。当前参数中，分类区域高度主要按红色标志高度约2.45倍扩展，并结合红色标志宽度约0.92倍设置最低高度约束；IPM坐标下设置约0.22的最小横向边距和约0.10的最小前向间隔。
0414 这些参数的整定目标不是追求固定几何比例，而是保证最终50×50输入能够稳定、完整地包含分类目标。调试阶段程序保留推理裁剪图像输出，通过检查实际送入NCNN模型的图像，逐步修正ROI偏移、目标截断和透视变形等问题。
0415 6.3.3.4  方向与速度闭环参数调试
0416 方向控制采用视觉位置外环与IMU角速度内环。视觉外环最终基础参数为Kp=130、Kd=50，非线性比例系数Kp2在普通状态下约为1.0，在环岛等大误差场景可提高至约3.5。调试过程中，Kp主要决定车辆偏离中线后的纠偏强度，过小会造成入弯响应迟缓，过大则容易在高速直道产生左右摆动；Kd用于抑制误差快速变化造成的转向振荡。
0417 IMU角速度内环普通循迹比例系数约为0.029，在目标板绕行状态下提高至约0.045，微分系数约为0.03。通过针对普通循迹和目标板绕行采用不同参数，使高速循迹保持较平稳的姿态响应，同时在绕行阶段获得更快的转向跟随能力。
0418 左右驱动轮速度环采用增量式PI控制，左右轮基础参数均为Kp=30、Ki=5。调试时先在较低速度下观察编码器反馈和PWM输出，再逐步提高目标速度，使比例项具有足够的响应速度，同时避免输出振荡；积分项用于消除长期轮速静差，并避免参数过大造成加减速过冲。最终由方向内环输出以相反符号叠加到左右轮目标速度，实现差速转向。
0419 整定顺序：固定机械结构 → IPM 标定 → 红色检测 → 分类 ROI → 速度环 → IMU 内环 → 视觉外环 → 高速实车验证
0420 6.3.3.5  参数整定流程
0421 整车软件参数按照由“几何标定—目标感知—分类输入—底层速度—姿态内环—视觉外环”的顺序逐步整定。首先固定机械结构和摄像头位置并完成IPM标定；随后调节红色检测阈值、面积和搜索范围；在目标稳定触发后再调整分类 ROI和置信度门限；最后依次完成编码器速度环、IMU角速度内环和视觉方向外环整定。
0422 采用分层、逐项的调试方式可以减少多个参数同时变化造成的相互干扰，使每次修改都能够较明确地对应到实际图像或车辆运动效果。最终参数在普通循迹、目标识别以及目标板绕行等场景中进行综合实车验证。
0423 6.4  测试结果
0424 实车测试表明，车辆能够完成常规赛道循迹、红色目标检测与分类、目标板左绕/直行/右绕以及坡道辅助判断等主要功能。赛道信息检测频率约 103 Hz，控制周期为 5 ms，图像处理帧率为 120 Hz；离线模型细分类测试准确率为 99.90%，粗分类测试准确率为 99.96%。
0425 机械调整后，34 cm 摄像头高度与后移重心改善了视觉前瞻和高速弯道稳定性；六层无刷电调在约 90% PWM 占空比下可持续工作。当前主要边界条件为偏暗环境下识别稳定性下降，以及负压电调在约 96% 以上 PWM 占空比时温升明显，相关问题在第八章进一步总结。

0508 第八章  结论
0509 8.1  工作总结
0510 本车完成了机械结构、电路系统、视觉识别和运动控制的一体化设计。整车以 LS2K0300 为核心，灵眼 Pro、imu660RC、1024 线增量式编码器和 DL1B TOF 分别提供视觉、姿态、轮速/位移和前向距离信息；F 型差速底盘配合 EMAX 2207 负压机构，提高了高速运行时的附着能力。
0511 电路系统采用 3S 锂电池供电，主控板完成 5 V/3.3 V 电源转换与接口集成；左右轮使用 DRV8701E 外置 MOSFET 全桥驱动，负压机构使用 Ai8051 + FD6288Q 三相无刷电调。电调由四层 PCB 优化为六层 PCB，并通过大面积铺铜和散热过孔提升持续大电流工况下的热可靠性。
0512 软件形成“赛道感知—红色预检测—IPM ROI—NCNN 分类—状态机—闭环控制”的处理链。九个细分类映射为三类任务，由锁存式状态机生成右绕、直行或左绕动作，再通过视觉位置外环、IMU 角速度内环和左右轮增量式 PI 速度环执行。
0513 模型由 PyTorch 训练后经 ONNX 转换为 NCNN 部署文件，可直接运行于 LS2K0300。综合测试表明，当前方案能够完成赛道循迹、目标识别与分类绕行、坡道辅助判断和高速差速控制等主要任务，整车设计达到了预期功能目标。
0514 8.2  存在的问题
0515 经过实车调试，当前系统仍存在一定的环境适应性和功率热设计限制。首先，目标识别对环境光照仍具有一定敏感性。虽然训练阶段采用了颜色扰动，车载端也设置了裁剪图像亮度增强和 YCrCb 红色检测条件，但在整体照度较低、目标表面细节和颜色对比度下降的环境中，摄像头采集图像的有效纹理信息减少，红色标志检测和后续分类的稳定性会有所下降。特别是在偏暗环境下，部分目标的分类置信度会降低，可能出现需要更靠近目标才能获得有效分类结果的情况。因此，离线数据集上的高准确率并不能完全代表所有现场光照条件下的实际识别效果。
0516 其次，负压无刷电调在极高输出状态下仍存在温升问题。六层 PCB、大面积铺铜和散热过孔已经明显改善了持续大电流工作能力，实车中约 90% PWM 占空比能够较长时间稳定运行；但当负压电调 PWM 占空比进一步提高至约 96% 以上时，功率 MOSFET、母线及相关大电流路径的发热明显增加，连续运行时电调温度上升较快。该现象说明当前电调的散热设计虽然能够满足正常比赛使用区间，但在接近满功率的极限工况下仍存在进一步优化空间。
0517 此外，车模高速性能受到视觉、机械附着和控制参数之间耦合关系的影响。摄像头位置、车体重心、负压大小以及方向和速度控制参数改变后，均可能影响高速弯道中的实际轨迹，因此整车性能仍依赖较充分的赛道实测与参数整定。
0518 8.3  改进方向与展望
0519 针对偏暗环境下识别稳定性下降的问题，后续可从图像采集、训练数据和算法自适应三个方面继续改进。首先可进一步优化摄像头曝光、增益和亮度补偿策略，使不同环境照度下的目标图像保持较稳定的灰度和颜色分布；其次在训练数据集中增加低照度、局部阴影、曝光不足及不同色温条件下的样本，并使用更有针对性的亮度、对比度和噪声增强，提高模型对现场光照变化的泛化能力；同时可以根据图像整体亮度动态调整红色检测阈值和分类前图像增强系数，降低固定参数在极端光照条件下的局限性。
0520 对于负压电调的温升问题，后续将重点提高功率级的导流与散热能力。可进一步优化 MOSFET 布局和三相大电流回路，缩短高电流路径并增加有效铜面积和散热过孔数量；在结构允许的情况下，可通过增加铜厚、改善电调周围空气流动或增加辅助散热结构降低器件结温。同时可在 Ai8051 电调中加入更完善的温度监测和功率限制策略，当温升超过设定范围时主动限制负压电机最大占空比，从而避免长时间接近满功率运行造成可靠性下降。
0521 在整车控制方面，后续还可进一步研究根据车速、弯道曲率和目标板状态动态调节负压强度及控制参数，使负压输出不再长期保持单一高功率，而是在直道、弯道和特殊元素之间按实际附着需求进行分配。结合现有视觉、IMU、编码器和 TOF 信息，可继续完善多传感器状态判断和自适应控制策略，在保证识别可靠性的同时进一步提高车模的运行速度、能量利用效率和整车稳定性。

0554 B.2  红色目标前向 ROI 构造核心子程序
0555 build_forward_roi_quad() 将红色标志四角点映射到 IPM 俯视坐标系，根据赛道前进方向和标志几何尺寸动态构造其前方分类区域，再通过逆单应矩阵投影回原图，为后续 50×50 透视裁剪提供四边形 ROI。
0556 bool build_forward_roi_quad(const LocalRedComponentInfo& component_info,
0557 const cv::Size& full_size,
0558 cv::Point2f roi_quad[4]) // 根据红色标志位置构造其前方分类ROI四边形
0559 {
0560 std::vector<cv::Point2f> marker_full; // 保存原图坐标系下红色标志的四个角点
0561 marker_full.reserve(4);
0562 for (int i = 0; i < 4; ++i)
0563 {
0564 marker_full.push_back(component_info.box_points_full[i]); // 读取红色连通域外接四边形角点
0565 }
0566 std::vector<cv::Point2f> marker_ipm; // 保存转换到IPM俯视坐标系后的角点
0567 if (!transform_points(marker_full, kImageToIpmHomography, marker_ipm) || marker_ipm.size() != 4)
0568 {
0569 return false; // 图像坐标到IPM坐标的变换失败
0570 }
0571 cv::Point2f ipm_center(0.0f, 0.0f); // 红色标志在IPM坐标中的中心点
0572 for (const cv::Point2f& point : marker_ipm)
0573 {
0574 ipm_center = point_add(ipm_center, point); // 累加四个角点坐标
0575 }
0576 ipm_center = point_scale(ipm_center, 0.25f); // 四个角点求平均得到中心坐标
0577 cv::Point2f forward_dir = estimate_forward_dir_ipm(component_info.refined_center_full, full_size);
0578 // 根据当前赛道中线信息估计IPM坐标系中的赛道前进方向
0579 cv::Point2f lane_lateral(-forward_dir.y, forward_dir.x); // 计算与赛道前进方向垂直的横向方向
0580 cv::Point2f major_dir = point_sub(marker_ipm[1], marker_ipm[0]); // 取红色标志上边作为横向主方向
0581 if (point_dot(major_dir, lane_lateral) < 0.0f)
0582 {
0583 major_dir = point_scale(major_dir, -1.0f); // 保证主方向与赛道横向方向保持一致
0584 }
0585 major_dir = normalize_or(major_dir, lane_lateral); // 对横向主方向进行单位化
0586 const cv::Point2f ipm_top_center = point_scale(point_add(marker_ipm[0], marker_ipm[1]), 0.5f);
0587 // 计算红色标志上边中心
0588 const cv::Point2f ipm_bottom_center = point_scale(point_add(marker_ipm[3], marker_ipm[2]), 0.5f);
0589 // 计算红色标志下边中心
0590 cv::Point2f minor_dir = point_sub(ipm_top_center, ipm_bottom_center); // 得到红色标志前后方向
0591 if (point_dot(minor_dir, forward_dir) < 0.0f)
0592 {
0593 minor_dir = point_scale(minor_dir, -1.0f); // 保证该方向指向赛道前方
0594 }
0595 minor_dir = normalize_or(minor_dir, forward_dir); // 单位化前向方向
0596 float min_major = std::numeric_limits<float>::max();
0597 float max_major = -std::numeric_limits<float>::max();
0598 float min_minor = std::numeric_limits<float>::max();
0599 float max_minor = -std::numeric_limits<float>::max();
0600 for (const cv::Point2f& point : marker_ipm)
0601 {
0602 const cv::Point2f rel = point_sub(point, ipm_center); // 计算角点相对中心的位置向量
0603 const float major_proj = point_dot(rel, major_dir); // 计算角点在横向主轴上的投影
0604 const float minor_proj = point_dot(rel, minor_dir); // 计算角点在前向轴上的投影
0605 min_major = std::min(min_major, major_proj);
0606 max_major = std::max(max_major, major_proj);
0607 min_minor = std::min(min_minor, minor_proj);
0608 max_minor = std::max(max_minor, minor_proj);
0609 }
0610 const float marker_width_ipm = std::max(4.0f, max_major - min_major); // 计算红色标志在IPM中的宽度
0611 const float marker_height_ipm = std::max(2.0f, max_minor - min_minor); // 计算红色标志在IPM中的高度
0612 const float crop_major_pad = std::max(kCropImageLateralPadMinIpm,
0613 marker_width_ipm * kCropImageWidthExpandRatio);
0614 // 根据标志宽度确定分类区域左右扩展量
0615 const float crop_gap_minor = std::max(kCropImageGapMinIpm,
0616 marker_height_ipm * kCropImageGapRatio);
0617 // 根据标志高度确定红色标志与分类区域之间的前向间隔
0618 const float crop_height_ipm = std::max(marker_height_ipm * kCropImageHeightByMarkerHeight,
0619 marker_width_ipm * kCropImageHeightByMarkerWidth);
0620 // 根据红色标志宽高动态计算分类区域高度
0621 const float crop_min_major = min_major - crop_major_pad; // ROI左侧边界
0622 const float crop_max_major = max_major + crop_major_pad; // ROI右侧边界
0623 const float crop_bottom_minor = max_minor + crop_gap_minor; // ROI靠近红色标志的一侧
0624 const float crop_top_minor = crop_bottom_minor + crop_height_ipm; // ROI远离红色标志的前方边界
0625 const cv::Point2f roi_quad_ipm[4] = {
0626 point_add(ipm_center, point_add(point_scale(major_dir, crop_min_major), point_scale(minor_dir, crop_top_minor))),
0627 point_add(ipm_center, point_add(point_scale(major_dir, crop_max_major), point_scale(minor_dir, crop_top_minor))),
0628 point_add(ipm_center, point_add(point_scale(major_dir, crop_max_major), point_scale(minor_dir, crop_bottom_minor))),
0629 point_add(ipm_center, point_add(point_scale(major_dir, crop_min_major), point_scale(minor_dir, crop_bottom_minor))),
0630 }; // 在IPM俯视平面中构造分类区域四个顶点
0631 for (int i = 0; i < 4; ++i)
0632 {
0633 if (!project_point(roi_quad_ipm[i], kIpmToImageHomography, roi_quad[i]))
0634 {
0635 return false; // 将ROI顶点投影回原始图像失败
0636 }
0637 }
0638 return true; // 前向分类ROI构造成功
0639 }
