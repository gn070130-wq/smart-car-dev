0053 第一章 引言
0054 1.1全国大学生智能汽车竞赛介绍
0055 全国大学生智能汽车竞赛是面向国内高校学子开展的高水平工程创新竞赛。赛事秉持 “立足培养、重在参与、鼓励探索、追求卓越” 理念，鼓励学生投身移动机器人研发实践。赛事面向全国全日制本、专科在校大学生，鼓励学生组队开展模型智能车研发，在整车搭建、系统调试的完整流程中开拓创新思路，锤炼动手实践能力，塑造良好的团队协作意识。竞赛交叉融合机械设计、电路开发、嵌入式软件、自动控制、机器视觉与人工智能等诸多学科知识。全面考验参赛队伍系统整合、算法优化与现场问题处置能力。参赛队伍除保障小车稳定运行、完成现场竞速与任务挑战外，还需要梳理研发思路。评审专家结合车辆运行表现、方案创新程度、技术实现难度、资料完整性等维度进行综合打分，评选各级别奖项。[1]
0056 历经二十余年发展，全国大学生智能汽车竞赛现已成功举办二十余届。赛事搭建起跨校技术交流平台，让广大工科学生得以同台竞技、互通经验，持续点燃青年学子对于智能驾驶与机器人技术的研究兴趣，推动高校工程实践教育不断创新。与此同时，竞赛持续挖掘具备工程实战能力的青年人才，为自动驾驶、智能硬件、智能交通等相关行业输送后备力量，助力国内智能移动机器人相关技术不断向前发展。
0057 1.2第二十一届走马观碑组规则介绍
0058 走马观碑组是第二十一届全国大学生智能汽车竞赛的核心室内视觉竞速组别，面向全国本科在校学生开放参赛，全程依托自主研发的三轮智能车完成全自动赛事任务，重点考察学生机器视觉识别与车体运动控制综合能力。[1]
0059 走马观碑组别以赛事场地为标准化室内赛道，涵盖直道、弯道、十字路口、环岛、坡道等多元路况，赛道区域划分清晰、路况复杂。赛道内随机布设多类目标识别板，分为武器、物资、交通工具三大类别，车辆需通过摄像头实时采集图像、运行自主编写的识别算法，精准判定目标类别并执行对应通行规则，分别完成左侧绕行、右侧绕行、直行通过的差异化行驶操作。
0060 比赛以全程行驶耗时为核心评分依据，结合违规情况叠加罚时核算最终成绩，识别错误、通行违规、环岛通行异常等均会对应加时，严重偏离赛道无法自主复位则判定赛事失败。参赛队伍可对标准车模进行合规改装，自主搭建外围硬件电路、调试嵌入式算法。该组别聚焦软硬件一体化开发，全方位锻炼学生图像处理、路径规划、闭环控制及工程问题排查能力，是视觉智能车基础研发实践的核心赛事组别。

0065 2.2整车结构设计
0066 根据第二十一届全国大学生智能汽车竞赛走马观碑组竞赛规范，本团队以赛事指定三轮智能车模为开发载体，整体底盘结构、轮距轴距均严格沿用原厂标准架构。车身主体采用轻量化高强度材料，配合高弹性防滑轮胎，有效提升整车行驶容错率与耐久性能。在整体布局设计上，团队秉持低重心、高对称、稳布局的设计思路，将龙芯主控模块、视觉采集摄像头、姿态检测单元等核心器件集中布置于车身中心区域，同时将电源模块低位内嵌安装，采用锁固式结构避免高速行驶、颠簸路段出现器件松动、位移等问题。针对比赛场景中高频出现的急弯、坡道、连续变道等复杂路况，我们对车辆负压吸附系统进行专项适配调校，通过优化风扇转速与风道结构，强化底盘负压吸附效果，显著削弱高速过弯产生的侧滑趋势，大幅提升车体贴地稳定性与转向跟随精度。经过系统性结构优化与布局迭代，整车具备优秀的直线匀速性能与弯道动态适应性，能够在多变赛道环境中保持稳定行驶，保障视觉识别与路径追踪的精准度，满足赛事高速、稳定、高精度的竞速要求。

0068 2.3编码器的选择
0069 编码器可以使电路更加完善，信号更加精确，编码器功耗低，重量轻，抗冲击抗震动，精度高，寿命长，非常实用，我们选择的是带方向编码器，在车模下方架编码器。
0070 带方向编码器（Incremental Encoder）是一种常见的编码器类型，用于测量位置和方向信息。它可以提供位置计数和旋转方向（正向或反向）的信号输出。带方向编码器通常由两个输出通道（一般称为A相和B相）组成。当旋转时，这两个通道会产生脉冲信号，并根据脉冲计数和相位关系来确定位置和旋转方向。

0072 2.4陀螺仪模块选择
0073 我们采用的是 ICM42688 六轴 IMU 模块，作为高性能运动传感单元，ICM42688 集成加速度计与陀螺仪，能够高精度采集角速度与线性加速度数据，实现车体姿态信息实时解算。该模块支持多轴同步采样，体积小巧、功耗控制优异，同时拥有低噪声、高测量灵敏度与出色的温度稳定性，能够在智能车高速行驶、震动干扰的赛场环境下持续输出稳定可靠的传感数据。[6]

0088 第三章 硬件电路设计
0089 3.1遵循的原则
0090 本项目在进行硬件设计时尽可能遵循以下原则：
0091 1、尽可能选择典型电路，并符合单片机常规用法。为硬件系统的标准化、模块化打下良好的基础。
0092 2、系统扩展与外围设备的配置水平应充分满足应用系统的功能要求，并留有适当余地，以便进行二次开发。
0093 3、硬件结构应结合应用软件方案一并考虑。硬件结构与软件方案会产生相互影响，考虑的原则是：软件能实现的功能尽可能由软件实现，以简化硬件结构。但必须注意，由软件实现的硬件功能，一般响应时间比硬件实现长，且占用CPU时间。
0094 4、系统中的相关器件要尽可能做到性能匹配可靠性及抗干扰设计是硬件设计必不可少的一部分，它包括芯片、器件选择、去耦滤波、印刷电路板布线、通道隔离等。
0095 5、单片机外围电路较多时，必须考虑其驱动能力。驱动能力不足时，系统工作不可靠，可通过增设线驱动器增强驱动能力或减少芯片功耗来降低总线负载。
0096 6、尽量朝“单片”方向设计硬件系统。系统器件越多，器件之间相互干扰也越强，功耗也增大，也不可避免地降低了系统的稳定性。随着单片机片内集成的功能越来越强，真正的片上系统SoC已经可以实现。
0097 7、电路设计需要尽可能简洁，尽量减少元器件使用数量，缩小电路板面积，使电路部分重量轻，易于安装。在设计完原理图后，注重PCB板的布局，优化电路的走线
0098 最好手动布线，整齐排列元器件，最终做到电路板的简洁。
0099 3.2 电源模块设计
0100 走马观碑赛道车模在运行过程中，各类外设需要不同的工作电压，常用的有 5V 和 3.3V。本车模采用 格式-2300mAh-45C-4S 锂电池作为主电源，标准电压为 16.8V，正常工作范围为 14.8V~16.8V，可直接为驱动电机供电。在主控板部分，为满足摄像头、无线通信模块及传感器等外设的用电需求，我们设计了基于 SCT2450STER 芯片的 DC/DC 降压电路，将电池高压稳定转换为 5V 输出。该降压模块支持宽输入电压范围，输出电流可达 5A，采用同步降压拓扑，内置低阻抗功率 MOSFET，具有高效率、低发热和优良的瞬态响应特性。电路中配备了输入/输出滤波电容（220µF、47µF 等）、电感（4.7µH）及肖特基二极管（SS54）以保证输出电压的稳定，同时利用分压电阻网络精确设定输出电压，为高速行驶时外设的稳定工作提供了可靠保障。
0101 图3.2.1  5V稳压电路
0102 使用AMS1117-3.3芯片固定输出电压为3.3V，为屏幕、姿态传感、蜂鸣器、按键等供电。AMS1117-3.3 是一款线性稳压器芯片，由 Richtek Technology（锐捷科技）生产。它是一种定电压降压稳压器，能够将输入电压稳定地转换为固定的输出电压。AMS1117-3.3 的 “3.3” 部分表示它的输出电压为 3.3V。根据这个芯片的型号，它提供的输出电压是固定的，即输出为 3.3V。这款芯片具有低压降、低噪声、高精度和高效率的特点。它适用于多种电子设备和电路中，如电源管理、嵌入式系统、消费电子产品等。AMS1117-3.3 的具体特性可能包括过压保护、过热保护、短路保护、低功耗待机模式等功能。

0117 3.7传感器硬件设计
0118 我们重点聚焦于四轮车模的关键传感器功能，包括姿态传感器、图像传感器以及用于测速闭环控制的编码器。对于姿态检测，我们采用了ICM42688传感器模块，安装于车体的一侧，用于精准捕捉和分析车辆的空间姿态。ICM42688是当前最新推出的一款姿态传感器，与传统的MPU6050和ICM20602相比，它具有更出色的数据稳定性。其IIC接口支持更高速的数据读取，提供了更及时的反馈，这对四轮车模在高速运动时的姿态调整至关重要。
0119 除了姿态传感器，测速闭环控制依赖高精度编码器，这些编码器确保了车模在各种速度下的平稳运行和良好的控制响应。图像传感器的引入则为车模提供了对周围环境的实时视觉感知，帮助实现路径规划及障碍物检测等功能。
0120 Simulink仿真模型用于分析三轮车模系统的动态行为和传感器数据处理。通过建立仿真模型，我们能够提前测试和优化传感器与控制系统的互动，确保在实际应用中实现稳定的操控和良好的性能表现。仿真模型提供了系统在不同操作条件下的表现预测，帮助识别潜在问题并作出相应的修正，确保车辆的安全可靠运行。
0121 图3.7.1  simulink仿真模型
0122 在这个系统中，电机的转速实际上可以通过PID控制器来管理，以保持车辆在不同速度条件下的稳定性。PID控制器可以调节电机的输出，使车辆在加速时不会超出预期速度，从而避免不必要的快速变化，这在路径跟随和驾驶稳定性中至关重要。
0123 最终，通过对系统的仿真模拟，我们可以预测并优化车辆在不同路况和操作条件下的响应。这种分析有助于提升整个系统的操控品质，确保车辆在不同场景中都能表现出色。图像传感器和位置编码器的反馈信号在这一过程中扮演了重要角色，提供了指引信息以便进一步调整和完善控制策略。

0126 第四章 软件设计及控制原理
0127 4.1 总述
0128 本车为基于龙芯 LoongArch Linux 开发板的三轮差速智能车。软件以相机视觉为主要导航信息，以 ICM42688 惯性测量单元、VL53L0X 距离传感器和左右轮编码器作为辅助反馈，通过轻量级多线程完成图像处理、赛道元素识别、路径决策和电机闭环控制。工程采用 C++11 编写，视觉处理依赖 OpenCV，目标分类使用 NCNN 推理框架，底层设备由相机、电机、液晶、按键和通信封装库统一管理。[4]
0129 系统的输入为 320×240、120 Hz 的彩色相机图像以及角速度、距离和编码器计数；主要输出为左右驱动电机 PWM 和无刷电机占空比。每帧视觉链路先生成左右赛道边界和跟踪中线，再通过纯跟踪算法计算航向角误差。控制链以航向角误差为外环输入，以陀螺仪角速度为中环反馈，以左右轮编码器速度为内环反馈，最终形成差速转向。十字、圆环、坡道、斑马线和目标板等特殊场景由独立状态机改变跟踪边、前瞻点、速度目标及中线偏移。
0130 4.2 程序整体设计框架
0131 软件按主程序层、任务层、核心算法层和硬件封装层组织。main.cc 仅负责设备初始化、周期线程启动和主取帧循环；app 目录保存视觉、电机、编码器、IMU、按键和菜单任务；line_track.h 与 cross.h 分别承载巡线、纯跟踪和赛道元素状态机；app_context 统一保存跨任务共享的设备对象与运行状态，app_config 则集中给出可调默认参数。该分层使控制逻辑与硬件访问相互隔离，也便于现场通过菜单或图传页面观察和调整参数。
0132 图4.2  软件总体架构与任务调度关系
0133 程序启动时依次检查相机、LCD、按键、电机、无刷电机、ToF 和 IMU。随后创建 1 ms 电机任务、4 ms IMU/ToF 任务、5 ms 编码器任务、1 ms 按键任务和 100 ms 菜单任务。主线程持续取帧并调用 photo_task；若相机连续 5 次取帧失败，则立即将两路驱动电机和无刷电机输出清零。图传服务工作在 8080 端口，可按需显示循迹、分类、灰度阈值、透视边线和红色掩膜，同时回传目标速度、实际速度、PWM、角速度、元素状态和分类结果。
0134 4.3 视觉预处理与赛道边界提取
0135 为兼顾感知范围与嵌入式实时性，程序保留一份 320×240 翻转原图供目标板裁剪，同时将图像缩放为 160×120 后执行主循迹算法。小图经 BGR 到灰度转换后，在图像高度约 70% 处选取起始行，并在其上下各 10 行区域内利用 Otsu 最大类间方差法获得黑白分割阈值。算法从图像中心分别向左、向右搜索白色赛道的边缘起点，再使用 15×15 自适应邻域和左右手迷宫规则沿边界向前爬线。为抑制误爬，若边界相对已达到的最高位置向车体方向回退超过 3 px，则在该处截断。[2]
0136 原图边界坐标通过离线生成的透视查找表映射到鸟瞰坐标系。查找表把相机去畸变和透视映射合并为常数时间的坐标访问，避免每个边界点重复执行矩阵乘法。变换后的左右边界先进行核长为 5 的三角滤波，再以 3 px 间隔进行等距采样，单侧最多保留 100 个有效点。等距点列既保证局部角度估计具有统一尺度，也使前瞻点可直接用索引表示。
0137 角点检测采用跨 8 个采样点的局部方向变化，并通过非极大值抑制保留突出的局部峰值。当角度突出量处于 70° 至 140° 时，将其判定为 L 型角点。该特征不直接决定车辆动作，而是作为十字、圆环等元素识别和边界截断的几何证据。完整视觉链如图4-2所示。

0139 4.4 中线生成与纯跟踪算法
0140 正常循迹时，程序分别将左边界沿右法向、右边界沿左法向偏移半个赛道宽度，得到两个候选中线。g_track_side 决定优先采用哪一侧边界；当首选边界点数不足且车辆不处于绕行丢线状态时，系统自动退化为另一侧边界。状态机还可通过 g_centerline_offset 改变法向偏移比例，从而在圆环入环、目标板绕行和恢复阶段主动移动参考轨迹。生成的中线再次等距采样，并以车体参考点 (g_cx, g_cy) 归一化起点，减小左右边界切换时的预瞄突变。[3]
0141 设前瞻点相对车体参考点的横向偏移为 Δx，纵向距离为 Δy，d²=Δx²+Δy²，鸟瞰域轴距参数为 L，则程序采用下式计算纯跟踪航向角误差：
0142 δ = −atan(2LΔx / d²) × 180 / π                                      (4-1)
0143 式中负号用于匹配图像横坐标与车辆转向方向：前瞻点位于车体右侧时输出负角，位于左侧时输出正角。普通道路默认前瞻点索引为 7，直道加速为 8，十字与红褐障碍为 12，圆环及 NCNN 绕行为 5，坡道为 3；若中线点数不足，则前瞻索引自动限制在有效范围内。当前代码保留了按实际轮速计算动态前瞻距离的函数，映射关系为“实际前进速度×0.014”，并限制在 12 至 42 px，但主视觉决策仍以按状态设定的固定索引为准。中线完全丢失时，普通状态保持上一次有效纯跟踪角；绕行状态则使用状态机给定的强制转向角，避免突然回正。
0144 4.5 三级闭环控制
0145 车辆转向采用角度环、角速度环和左右轮速度环组成的三级闭环，如图4-3所示。角度环每 10 ms 执行一次，将纯跟踪航向角误差转换为目标偏航角速度；角速度环每 5 ms 执行一次，以 ICM42688 的 z 轴角速度为反馈，输出左右轮目标速度差；同一 5 ms 周期内，编码器更新实际轮速，两个增量式速度控制器分别调整左右 PWM。电机任务本身以 1 ms 周期运行，以便完成启动计时、保护判定、蜂鸣器刷新和多速率控制调度。
0146 图4.5.1  三级闭环差速控制结构
0147 角度环和角速度环采用位置式 PID 结构。对离散时刻 k 的误差 e(k)，程序分别计算比例、积分和误差差分项，并对三项独立限幅：
0148 u(k) = satP[Kp e(k)] + satI[Ki Σe(k)] + satD[Kd(e(k)−e(k−1))]                                      (4-2)
0149 当前普通道路角度环实际使用 PD 参数 Kp=42.5、Ki=0、Kd=35；圆环角度环为 Kp=50.8、Kd=35；目标板绕行为 Kp=21、Kd=4；绕行三次后的加速角度环为 Kp=60、Kd=37。普通角速度环为 Kp=0.2，圆环角速度环为 Kp=0.18，绕行角速度环为 Kp=0.2，三者积分和微分项均关闭。控制器切换依据元素类型、圆环阶段及 NCNN 绕行状态，停车或模式复位时清除全部历史项，防止再次起步时带入旧误差。
0150 左右轮速度环采用增量式 PI。其单次输出增量为：
0151 Δu(k)=Kp[e(k)−e(k−1)]+Ki e(k)+Kd[e(k)−2e(k−1)+e(k−2)]                                      (4-3)
0152 两侧速度环的当前参数均为 Kp=40、Ki=20、Kd=0，单次增量限幅 8500。控制器输出累加到左右 PWM，并限制在 −9000 至 9000；启动斜坡期的负向下限收紧为 −2000。角速度环产生的差速量 Δv 经动态限幅后，与基础左右速度组合为 vL*=vL−Δv、vR*=vR+Δv，再交由速度环跟踪。该结构将路径几何误差、车体旋转响应和轮端执行误差分层处理。
0153 图4.5.2  串级与常规PID比较
0154 4.6 特殊赛道元素识别与处理
0155 十字和圆环均以 L 型角点为主要几何特征，并用多帧确认抑制偶然误检。十字判定包括近角点与同侧远角点同时出现，或左右近角点同时出现且横向间距小于 60 px；当前确认帧数为 4。进入 CROSS_BEGIN 后，算法从角点附近重新搜索远线，并把近、远边界生成的中线连接起来；当近处双边暂时消失时进入 CROSS_RUNNING，在固定远端区域继续搜索左右边界；连续 5 次恢复双边后退出十字。十字状态还设有超时跳转，防止识别失败时长期停留。
0156 圆环判定要求单侧近 L 角点、该侧无对应远角点、另一侧为长直边界，并且车辆已通过第一个十字。状态依次为 CIRCLE_BEGIN、CIRCLE_APPROACH、CIRCLE_RUNNING、CIRCLE_OUT 和 CIRCLE_END。BEGIN 阶段沿外侧直边前进，并结合编码器累计和内侧边界消失/重现判断入口；APPROACH 阶段沿入口弧线，通过 IMU 偏航积分超过正负 9000 且外侧边界点数大于 15 进入 RUNNING；RUNNING 阶段检测靠近车体的出环角点；OUT 阶段切换跟踪边，当角点消失、边线超过 30 点且恢复长直形态，连续 3 帧后进入 END 并恢复普通循迹。
0157 坡道由 VL53L0X 距离触发：测距处于 50 至 500 mm 并连续满足 6 帧时进入坡道状态，以目标速度 100 行驶，达到配置的编码器累计距离后退出且不再重复检测。斑马线只在发车 5000 ms 后启用，连续 3 帧确认后将运行标志清零并快速停车。红褐色路障检测沿左右鸟瞰边界逆变换到原图，在赛道内侧 8 px 位置检查灰度跳变和红色像素占比；至少 2 个点命中并连续 5 帧确认后，车辆切换到障碍对侧边界，绕行 500 ms 后恢复。各元素的状态关系见图4-4。

0159 4.7 识别与绕行
0160 目标板识别采用“几何与颜色定位、轻量分类、动作状态机”三级处理。算法沿逆透视后的道路中线向前搜索红色跳变，并以标准红色 H∈[0,12]∪[170,179] 和棕红色 H∈[8,22] 为主要色相范围，同时要求标准红色饱和度不低于 65、棕红色饱和度不低于 70、亮度不低于 35。候选框宽度至少为 4 px，中心与图像中心偏差不超过 30 px，候选中线索引不大于 40。程序再将红色底边投影到鸟瞰域，根据 45 cm/24 px 的标定比例估算到车头的平面距离；普通路面、十字和圆环的分类距离门限分别为 60、70 和 40 cm。
0161 满足距离门控后，程序在 320×240 原图中依据红色底边向上构造四边形，并透视展开为 64×64 三通道模型输入。NCNN 采用单线程 CPU 推理，输入由 BGR 转 RGB，并以均值 [123.675,116.28,103.53] 和归一化系数 [0.01712475,0.017507,0.01742919] 标准化。模型输出六类标签：binoculars、bomb、gun、medical、vehicle_black 和 vehicle_write。softmax 最高概率需不低于 0.50；系统收集最多 3 次有效识别结果并多数投票，若前两次结果相同则可提前锁定。gun、bomb 映射为左绕，binoculars、medical 映射为右绕，两类 vehicle 标签映射为直行。[5]
0162 动作状态机如图4-5所示。IDLE 检测到候选后进入 WAIT_TRIGGER，连续 2 帧满足几何和距离约束后进入 SLOW_CLASSIFY；投票得到有效命令后进入 LOCKED，并冻结高层元素切换。BYPASS 阶段按命令选择左或右边界，修改中线偏移和初始爬线位置，并以编码器累计判断是否越过目标；若所选边界丢失，则暂时施加 ±15° 至 ±30° 的强制转向角。随后 RECOVER 阶段等待左右边界或远线恢复且编码器达到恢复计数，最后在 DONE 中清理锁定标签、偏置角、编码器计数和冻结标志，返回普通循迹。普通道路、十字出口和圆环内使用相同主状态机，但分别采用独立的绕行距离、速度、中线偏移和丢线超时参数。

0164 4.8 调试接口、边界条件与本章小结
0165 为便于现场调试，系统通过 LCD 多级菜单和网页图传提供循迹、分类、阈值、透视与红色掩膜五种图像视图，并回传 PID 参数、纯跟踪角、角速度、轮速、PWM、边界点数、角点位置、元素状态、分类概率和各视觉阶段耗时。速度环、角速度环、普通角度环和圆环角度环参数可在运行时统一更新，更新后立即清除对应历史状态。图像调试在发车后默认关闭，以减少绘制和网络发送对视觉帧率的影响。

0358 * pid_positional_solve() — 位置式 PID 计算（每个控制周期调用一次）
0359 *
0360 * @param error  当前误差 = 目标值 - 实际值
0361 * @return       PID 输出（P/I/D 分项独立限幅后）
0362 *
0363 * 计算过程：
0364 *   D 项 = (error - prev_error) * low_pass + prev_D * (1 - low_pass)
0365 *   I 项 += error（积分限幅）
0366 *   输出 = kp * error + ki * I + kd * D

0368 static inline float pid_positional_solve(pid_positional_t *p, float error) {
0369 // D 项：(当前误差 - 上次误差) 做低通滤波
0370 p->out_d = (error - p->out_p);
0371 p->out_p = error;   // 保存本次误差供下次计算 D 项
0372 // I 项：累加误差，并限幅防止积分饱和
0373 p->out_i += error;
0374 if (p->ki != 0 && p->i_max > 0) {
0375 float ki_abs = p->ki > 0 ? p->ki : -p->ki;
0376 p->out_i = PID_CLAMP(p->out_i, -p->i_max / ki_abs, p->i_max / ki_abs);
0377 }
0378 float out_p = p->kp * p->out_p;
0379 float out_i = p->ki * p->out_i;
0380 float out_d = p->kd * p->out_d;
0381 if (p->p_max > 0)
0382 out_p = PID_CLAMP(out_p, -p->p_max, p->p_max);
0383 if (p->i_max > 0)
0384 out_i = PID_CLAMP(out_i, -p->i_max, p->i_max);
0385 if (p->d_max > 0)
0386 out_d = PID_CLAMP(out_d, -p->d_max, p->d_max);
0387 return out_p + out_i + out_d;

0741 {
0742 best_score = -1e30f;
0743 int best_idx = -1;
0744 for (int i = 0; i < out.w; ++i) {
0745 const float score = out[i];
0746 if (score > best_score) {
0747 best_score = score;
0748 best_idx = i;

0750 }
0751 return best_idx;

0753 std::vector<float> softmax_scores(const ncnn::Mat& out)
0754 {
0755 std::vector<float> probs;
0756 if (out.w <= 0) return probs;
0757 probs.resize(out.w);
0758 float max_logit = out[0];
0759 for (int i = 1; i < out.w; ++i) {
0760 if (out[i] > max_logit) {
0761 max_logit = out[i];
0762 }
0763 }
0764 float sum = 0.0f;
0765 for (int i = 0; i < out.w; ++i) {
0766 probs[i] = std::exp(out[i] - max_logit);
0767 sum += probs[i];
0768 }
0769 if (sum <= 0.0f) {
0770 probs.assign(out.w, 0.0f);
0771 return probs;
0772 }
0773 for (size_t i = 0; i < probs.size(); ++i) {
0774 probs[i] /= sum;
0775 }
0776 return probs;
0777 }
