0049 第一章 引言
0050 1.1全国大学生智能汽车竞赛介绍
0051 全国大学生智能汽车竞赛以“立足培养、重在参与、鼓励探索、追求卓越”为指导思想，是面向全国大学生的探索性工程实践赛事，现已举办二十一届。竞赛覆盖电子工程、自动控制、计算机、人工智能等多学科，由各高校学生组队参赛。队伍自主完成智能车的设计、制作与调试，展现车辆感知、决策、控制相关技术能力，以及对整车系统的综合运用水平。
0052 参赛队伍需遵循竞赛规范，开发各类功能模块，依托传感器与算法实现自主导航、环境感知、路径规划、目标识别等核心功能。第二十一届赛事更加突出自主可控与工程实践，主控平台大量采用国产龙芯处理器，设置燕过留痕、走马观碑等竞赛组别。其中“走马观碑”组要求赛车高速行进时识别赛道随机目标板并完成绕行；赛事新增硬件、软件盲盒任务，考验队伍临场设计调试能力。
0053 竞赛除技术实现外，还要求参赛团队完成项目演示与技术报告撰写，评委结合各项表现综合评审确定奖项。
0054 该赛事吸引了大量高校队伍参与，为大学生搭建起技术实践与交流平台，激发学生对智能车技术的研究热情，助力相关技术创新发展，同时锻炼学生创新思维、协作意识与工程实践素养，为智能汽车领域输送高素质人才。
0055 1.2第二十一届走马观碑组竞速规则介绍
0056 第二十一届全国大学生智能汽车竞赛走马观碑组在封闭室内赛道竞速，考核赛车高速状态下路径识别、目标板（“碑”）检测与自主绕行决策能力。赛车限定三轮结构，采用官方指定车模底盘，传动结构、轮距、轴距不得改动，允许结构加固与外观优化；主控使用国产龙芯2K0300/久久派开发板，以灵眼Pro摄像头为主感知设备，搭配龙邱LQ6050v3陀螺仪、LQ_1024线方向mini编码器，实现巡线、目标板识别、轮速闭环与差速转向控制。·
0057 竞速赛道包含直道、弯道、十字路口、环岛、坡道、砖红色路障。赛车行驶中识别随机摆放的目标板：识别“武器”向左绕行，识别“物资”向右绕行，识别“交通工具”直行，按完成用时排名。车辆脱轨、静止超时、严重碰撞标志物即判定失误。全程由车载系统自主控制，禁止人工干预、外部通信与预设路径，目标板位置每次发车前随机更换。
0058 第二章 系统结构设计方案
0059 2.1系统总体设计方案
0060 本届走马观碑组的核心任务是在保证竞速速度的同时，完成赛道巡线、目标板识别与自主绕行决策。因此，本车模方案以 F 车模三轮结构的高速稳定性为基础，围绕视觉识别、路径规划、左右轮差速度闭环和两轮差速转向控制进行设计；车模前轮为万向轮，主要起支撑和随动导向作用，两个后轮由主驱一体拓展板上的电机驱动电路控制并通过速度差实现转向。整车实际使用的板卡主要包括 2K0300 主板、主驱一体拓展板和无刷电调，其中 2K0300 主板承担图像处理、路径决策与运动控制任务，主驱一体拓展板完成电源分配、外设接口引出和后轮直流电机驱动，无刷电调用于负压风扇驱动控制。
0061 系统总体方案图
0062 2.2整车结构设计
0063 根据第二十一届全国大学生智能汽车竞赛“走马观碑组”的竞赛要求，我们采用官方指定 F 车模三轮结构平台为基础进行搭建，底盘结构、轮距与轴距保持规则允许范围内的原始规格，并围绕高速巡线和目标板绕行任务进行结构加固与重心优化。车体合理布置 2K0300 主板、主驱一体拓展板、无刷电调、灵眼 Pro 摄像头、LQ6050v3 陀螺仪模块、LQ_1024线方向mini编码器、3S 电池及双负压风扇等核心部件，使整车在直道加速、连续弯道、目标板绕行和坡道等场景下兼顾响应速度与姿态稳定性。其中，前轮采用万向轮结构，两个后轮由主驱一体拓展板上的电机驱动电路控制；控制器通过调节左右后轮电机 PWM 输出形成速度差，从而实现小车转向。双负压风扇通过无刷电调接入 3S 电池供电，形成下压力以增强轮胎贴地性，降低高速转向和避障绕行时的侧滑风险。
0064 龙芯车模
0065 2.3编码器的选择
0066 编码器用于获取驱动轮转速和运动方向信息，是左右轮差速度闭环与两轮差速转向控制的重要反馈来源。本车模采用 LQ_1024线方向mini编码器，对后轮运动状态进行检测。该编码器具有体积小、分辨率高、响应稳定等特点，能够为后轮电机转速控制、直线校正和绕行过程中的差速分配提供可靠数据。
0067 LQ_1024线方向mini编码器带有方向输出信号，控制器在采集编码器脉冲数量计算轮速的同时，可通过方向引脚的高低电平判断电机当前旋转方向，从而区分正转与反转。在本车模中，编码器反馈与后轮电机输出共同构成左右轮差速度闭环，使车辆能够在不同赛道元素下保持稳定速度，并通过两个后轮的速度差实现转向半径调整。
0068 LQ_1024线方向mini编码器
0069 2.4陀螺仪模块选择
0070 我们采用的是龙邱科技 LQ6050v3 陀螺仪模块，用于采集车模运行过程中的角速度和加速度信息。该模块体积小、安装方便，能够为车辆在高速转向、坡道通过和目标板绕行过程中的姿态变化提供实时反馈。在软件处理中，我们对模块输出的数据进行零偏校准、互补滤波和滑动滤波处理，降低振动和瞬时噪声对控制量的影响，从而为差速转向补偿、速度控制和状态判断提供稳定可靠的姿态参考。
0071 LQ6050v3陀螺仪模块
0072 2.5差速转向方案
0073 本车模采用前轮万向轮、后轮两轮差速的转向方案。前轮万向轮主要承担支撑和随动作用，不参与主动转向；两个后轮由主驱一体拓展板上的电机驱动电路控制，控制器根据赛道中心偏差、目标板绕行策略和车辆姿态反馈，调节两侧后轮电机 PWM 输出，通过后轮速度差实现车辆转向。该方案结构简单、响应直接，减少了机械转向机构带来的装配误差，并便于在直线、弯道和目标板绕行过程中通过软件策略动态调整转向强度。
0074 前轮万向轮与后轮差速转向结构
0075 2.6电机选择
0076 本车模驱动系统采用智能车竞赛官方指定直流电机，两个后轮由主驱一体拓展板上的电机驱动电路控制。该驱动方式能够同时完成车辆前进动力输出和转向控制：当前轮万向轮随动、两个后轮速度一致时，车辆保持直线行驶；当两个后轮形成速度差时，车辆产生转向趋势，从而实现两轮差速转向。配合编码器速度反馈和 PID 控制，后轮直流电机能够在直线加速、坡道通过、目标板绕行和赛道回正过程中保持稳定响应。

0078 2.7摄像头选择
0079 本车模视觉系统采用灵眼 Pro 摄像头作为主要图像感知设备，用于采集赛道边界、目标板和障碍物等视觉信息。灵眼 Pro 具备较高的图像采集稳定性和嵌入式应用适配性，能够在高速行驶过程中提供连续的图像输入。摄像头与龙芯2K0300 / 久久派开发板配合工作，为巡线、目标板识别、路径规划和绕行决策提供可靠的视觉基础。

0081 第三章 硬件电路设计
0082 3.1遵循的原则
0083 本项目在进行硬件设计时尽可能遵循以下原则：
0084 1、尽可能选择典型电路，并符合单片机常规用法。为硬件系统的标准化、模块化打下良好的基础。
0085 2、系统扩展与外围设备的配置水平应充分满足应用系统的功能要求，并留有适当余地，以便进行二次开发。
0086 3、硬件结构应结合应用软件方案一并考虑。硬件结构与软件方案会产生相互影响，考虑的原则是：软件能实现的功能尽可能由软件实现，以简化硬件结构。但必须注意，由软件实现的硬件功能，一般响应时间比硬件实现长，且占用CPU时间。
0087 4、系统中的相关器件要尽可能做到性能匹配可靠性及抗干扰设计是硬件设计必不可少的一部分，它包括芯片、器件选择、去耦滤波、印刷电路板布线、通道隔离等。
0088 5、单片机外围电路较多时，必须考虑其驱动能力。驱动能力不足时，系统工作不可靠，可通过增设线驱动器增强驱动能力或减少芯片功耗来降低总线负载。
0089 6、尽量朝“单片”方向设计硬件系统。系统器件越多，器件之间相互干扰也越强，功耗也增大，也不可避免地降低了系统的稳定性。随着单片机片内集成的功能越来越强，真正的片上系统SoC已经可以实现。
0090 7、电路设计需要尽可能简洁，尽量减少元器件使用数量，缩小电路板面积，使电路部分重量轻，易于安装。在设计完原理图后，注重PCB板的布局，优化电路的走线
0091 最好手动布线，整齐排列元器件，最终做到电路板的简洁。
0092 3.2 电源模块设计
0093 走马观碑组车模在运行过程中，各类模块需要不同的工作电压，主要包括电池电压、5V 和 3.3V。本车模采用 格氏ACE-2200mAh-50C-11.1V-3S1P 锂电池作为主电源，电池标称电压为 11.1V，满电电压约为 12.6V，可为后轮直流电机和双负压风扇提供主要能量来源。其中，两个负压风扇通过无刷电调由 3S 电池供电，以获得足够的风量和下压力；主驱一体拓展板上设计了基于 TPS54331D 芯片的 DC/DC 降压电路，将电池电压稳定转换为 5V 输出，用于为需要 5V 的外设模块供电。3.3V 电源部分未在主驱一体拓展板上单独设计稳压电路，而是直接从 2K0300 主板的 3.3V 输出端取电，为 LQ6050v3 陀螺仪模块、按键等低压外设提供工作电压。
0094 5V稳压电路
0095 主驱一体拓展板未单独设计 3.3V 稳压电路。车模中需要 3.3V 的低压外设直接从 2K0300 主板的 3.3V 电源输出端取电，再通过主驱一体拓展板引出至对应接口，为 LQ6050v3 陀螺仪模块、按键等模块提供工作电压。这种方式减少了主驱一体拓展板上的稳压器件数量，降低了板上电源设计复杂度和成本，同时利用 2K0300 主板已有的 3.3V 稳压输出保证低压外设供电稳定。
0096 3.3V电源取自2K0300主板
0097 3.3 主驱一体拓展板及其PCB
0098 根据设计要求，整车控制核心采用 2K0300 主板完成主要控制与运算任务。2K0300 主板负责运行视觉处理、路径判断、目标板识别以及运动控制等程序，其计算能力和接口资源能够满足走马观碑组的实时控制需求。本文所设计的 PCB 为主驱一体拓展板，承担 2K0300 主板的接口拓展、电源分配和后轮电机驱动功能，用于完成 5V 电源输出、后轮直流电机驱动、编码器信号接入、LQ6050v3 陀螺仪模块接口、LQ_1.8寸LCD 显示接口以及按键等外设连接。在系统连接关系上，灵眼 Pro 摄像头直接连接至 2K0300 主板，由主控平台完成图像采集与处理；主驱一体拓展板主要负责将2K0300主板的控制信号、电源信号和外设接口进行集中引出，并通过板载电机驱动电路控制两个后轮电机，实现两轮差速转向。无刷电调用于两个负压风扇的驱动控制，使负压风扇能够由 3S 电池提供高功率输出。三类板卡分工明确，便于整车装配、调试和维护。具体布局及连接示意图如下：

0100 3.4 驱动电机模块
0101 采用 DRV8701E 芯片驱动后轮直流电机。DRV8701E 是一款高电流 H 桥驱动器芯片，适用于直流电机驱动应用，可提供高电流、高效率和高性能的电机驱动解决方案。本车模的电机驱动电路集成在主驱一体拓展板上，通过 PWM 调节两个后轮电机输出，实现左右轮差速度闭环和两轮差速转向。该芯片支持较宽的电机电压范围，并具有热关断保护、电流限制保护等功能，可提升电机驱动系统在高速竞速和频繁差速调整过程中的可靠性。

0112 本文重点研究走马观碑组三轮车模的关键传感器：灵眼 Pro 摄像头、LQ6050v3陀螺仪模块，以及实现左右轮差速闭环控制的LQ_1024线方向mini编码器。灵眼 Pro摄像头采集赛道边界、目标板、障碍物等视觉信息，是“观碑”识别与绕行决策的核心输入。龙邱LQ6050v3陀螺仪负责采集角速度与加速度数据，辅助检测车模高速转向、坡道及绕行时的姿态变化；编码器反馈左右后轮的转速与转向信息，为差速闭环、差速分配提供数据支撑。
0113 左右轮差速闭环依靠LQ_1024线方向mini编码器的反馈，保障后轮可以稳定跟踪目标转速，为差速转向提供实时依据。摄像头与陀螺仪分别提供视觉感知和姿态反馈，完成路径规划、目标板绕行以及复杂赛道工况处理。
0114 控制参数依靠实车赛道调试、分阶段整定得到。控制方案采用无电流环的三串级PID：最内环为左右轮差速度环，以后轮电机转速作为反馈，调节后轮转速差，输出控制电机驱动板；中间为角速度环，读取陀螺仪输出的实际角速度，补偿差速转向带来的动态误差；最外环是方向环，以视觉解算的赛道中线偏差或绕行偏移量为反馈，输出期望角速度。

0121 4.3 PID控制算法
0122 我们针对三轮车模的两轮差速转向控制设计了三串级 PID 控制策略。控制系统由内到外依次为左右轮差速度环、角速度环和方向环。左右轮差速度环是最内环，其反馈值为编码器采集到的左右后轮电机转速，用于保证两个后轮能够按照给定的基础速度和差速量快速跟随目标；角速度环位于中间层，其反馈值为 LQ6050v3 陀螺仪测得的实际角速度，用于修正车辆转向过程中的角速度误差；方向环位于最外层，其反馈值为视觉算法得到的赛道中线偏差，并结合目标板绕行策略计算期望角速度，从而为角速度环提供目标值。
0123 在实际运行中，视觉算法首先根据赛道边界和目标板位置计算赛道中线偏差或绕行偏移量，方向环 PID 将该偏差转换为期望角速度；角速度环 PID 再结合陀螺仪测得的实际角速度，计算车辆需要的左右轮差速控制量；最内层左右轮差速度环根据左右电机转速反馈，将基础速度与差速量分配到两个后轮，并通过主驱一体拓展板上的电机驱动电路控制电机 PWM 输出。该控制结构没有电流环，电机电流不作为闭环反馈量，主要依靠编码器转速、陀螺仪角速度和视觉中线偏差完成分层控制。
0124 三串级 PID 控制系统如图所示，最内层左右轮差速度环负责后轮电机转速跟随与差速输出，中间角速度环负责抑制转向动态误差，最外层方向环负责路径跟踪与绕行决策。当视觉系统识别到目标板后，决策模块根据目标板类别生成左侧、右侧或中间通过策略，并将目标路径偏移量叠加到赛道中线偏差中送入方向环；方向环输出期望角速度，角速度环计算差速需求，左右轮差速度环最终通过主驱一体拓展板上的电机驱动电路完成左右后轮电机输出控制，从而实现稳定、连续的绕行动作。

0128 在基本图像处理完成后，就要从图像中提取出有效的赛道信息，也就是赛道边缘，以此来完成小车的行驶路径和特殊元素的识别。特殊元素的循迹思路如下：
0129 1.对于十字回环,由于只能搜到赛道一边的拐点，确定找点的初始位置，选择另一边进行补线处理，然后给左右面积乘以某个系数，同时根据矫正图像滤除十字回环拐角线，从而顺利连线；
0130 2.对于圆环，能够找到圆环的一边边界的列数会有较大的差异，从而补线让其进入圆环内；
0131 4.5八邻域跟踪算法
0132 在本项目中，我们主要采用八邻域跟踪算法实现巡线，八邻域跟踪算法基本思想是，遍历图像找到第一个非零像素点，那么这个点一定是边界点。设这个点为起始点x，按照0->1->2->3->4顺时针查找该点八邻域内遇到的第一个非零像素点x’（点x’也为边界点）。令x=x’，再进行邻域内的顺时针查找，查找的起点为刚刚x到x’过程中x’前一个零点。

0860 VisionTask.Overtake_RoadDir = 0;   // 直道
0861 }
0862 else if (image_seq_cnt == 2)
0863 {
0864 // overtake_then_cross = 1; // 第2个目标绕行后紧跟十字

0875 VisionTask.Overtake_RoadDir = 0;   // 直道

0877 }
0878 }
0879 // 绕行用 OvertakeHoldTicks()，不饶用延时慢慢恢复速度（每2帧+1，到55需50帧）
0880 uint8_t hold_ticks = VisionTask.Need_Overtake ? OvertakeHoldTicks() : 50;
0881 if (VisionTask.StateTick < hold_ticks)
0882 {
0883 VisionTask.StateTick++;
0884 return;
0885 }
0886 VisionTask.StateTick = 0;

0888 return;
0889 }
0890 case RedTask_Recover:
0891 {
0892 // 特殊写死恢复：绕行后紧跟十字，两段固定偏置 + 编码器距离恢复
0893 if (overtake_then_cross)
0894 {
0895 if (cross_recover_phase == 0)
0896 {
0897 // 首帧：锁定恢复方向（左绕→向右恢复，右绕→向左恢复），启动第一段(回中)
0898 cross_recover_sign = (VisionTask.Overtake_Dir == 1) ? 1 : -1;
0899 cross_recover_start_encoder = encoder_distance;
0900 cross_recover_phase = 1;
0901 cross_recover_bias = cross_recover_sign * CROSS_RECOVER_SEG1_BIAS;
0902 }
0903 else if (cross_recover_phase == 1)
0904 {
0905 // 第一段(回中)跑完 → 第二段(反方向回正车头)
0906 if ((encoder_distance - cross_recover_start_encoder) >= CROSS_RECOVER_SEG1_DIST)
0907 {
0908 cross_recover_start_encoder = encoder_distance;
0909 cross_recover_phase = 2;
0910 cross_recover_bias = -cross_recover_sign * CROSS_RECOVER_SEG2_BIAS;
0911 }
0912 }
0913 else // cross_recover_phase == 2
0914 {
0915 // 第二段(回正车头)跑完 → 恢复完成，清空回空闲
0916 if ((encoder_distance - cross_recover_start_encoder) >= CROSS_RECOVER_SEG2_DIST)
0917 {
0918 cross_recover_phase = 0;
0919 cross_recover_sign = 0;
0920 cross_recover_bias = 0.0f;
0921 overtake_then_cross = 0;
0922 VisionTask.TuXiang_ISNULL_Flag = 0;
0923 VisionTask.Need_Overtake = 0;
0924 VisionTask.Overtake_Dir = 0;
0925 VisionTask.ModelResult = Model_None;
0926 VisionTask.RedState = RedTask_Idle;
0927 return;
0928 }
0929 }
0930 return; // 恢复期间保持 RedTask_Recover，不清状态
0931 }
0932 // 原版：4帧保护，避免绕行刚结束立刻再次触发红色矩形框识别
0933 static int recover_cnt = 0;
0934 recover_cnt++;
0935 if (recover_cnt < 5)
0936 return;
0937 recover_cnt = 0;
0938 VisionTask.TuXiang_ISNULL_Flag = 0;
0939 VisionTask.Need_Overtake = 0;
0940 VisionTask.Overtake_Dir = 0;
0941 VisionTask.ModelResult = Model_None;
0942 VisionTask.RedState = RedTask_Idle;
0943 return;
0944 }
0945 case RedTask_Idle:
0946 default:
0947 break;
0948 }
