0016 摘   要
0017 本文介绍湖南科技大学走马观碑组智能车的总体设计与实现。赛车采用竞赛指定三轮车模，以龙芯2K0300处理器为核心控制器，灵眼PRO摄像头负责赛道图像和目标板图像采集。普通循迹部分沿用成熟的边线搜索、元素状态机和运动控制方案；目标识别部分基于OpenCV与NCNN实现。程序定位目标板区域并将ROI统一缩放至68×68，轻量级网络输出8个子类，随后映射为物资、车辆和武器三大类，并分别执行右绕、直行和左绕任务。编码器与IMU660RB提供速度和姿态反馈，左右驱动电机通过差速完成转向，并与负压系统协同完成整车控制。

0067 第一章 引言
0068 智能车系统把机械结构、嵌入式计算、视觉感知和运动控制集中在同一平台上。车辆需要在有限算力和复杂光照条件下持续获取赛道信息，并及时完成转向、调速和任务决策，因此各模块之间的配合比单独追求某一项性能更为重要。
0069 全国大学生智能汽车竞赛强调从方案设计、硬件制作到整车调试的完整工程过程。本队围绕走马观碑组任务，将系统划分为机械平台、硬件电路、图像与目标识别、运动控制四个部分，并以可靠完成任务为首要目标。
0070 本届走马观碑组要求车辆自主完成赛道行驶，并在目标区域识别不同类别的目标板。识别结果直接决定绕行方向，因而系统不仅要保持循迹稳定，还要保证目标区域内的图像质量、分类连续性以及轨迹切换的可靠性。
0071 针对上述要求，主控同时承担图像预处理、边线搜索、元素状态判断、神经网络推理和运动控制。程序采用分层状态机组织各项任务，普通循迹、环岛、十字和目标绕行使用相互独立的进入、保持与退出条件。
0072 整车研制按照“单模块验证—联合调试—任务整合”的顺序推进。巡线和赛道元素处理沿用上一届车模中已经稳定验证的算法框架，本届重点完成龙芯2K0300平台适配、68×68目标图像预处理、NCNN八分类模型部署以及三大类任务映射与绕行决策联动。
0073 智能车竞赛的设计过程不仅是单一算法的实现，还涉及机械装配、电源与驱动电路、图像处理、嵌入式推理和闭环控制等多方面内容。任何一个环节出现不稳定，都可能在高速运行时被放大，例如摄像头支架轻微振动会造成边线跳动，传动阻力不一致会造成左右轮速度偏差，识别结果偶发变化则会影响目标区域的路径选择。因此，本队在设计中优先保证各模块工作状态可重复，再逐步提高运行速度。
0074 本届赛车在继承上届巡线与赛道元素处理方法的基础上，对软硬件接口和任务流程进行了重新组织。普通赛道阶段以稳定提取左右边界和中线为主，目标区域阶段增加红色提示区域定位、目标板截取、八分类推理和三大类映射，最后由统一的状态机完成普通循迹与目标绕行之间的切换。整车调试以完整跑通比赛流程为基本要求，再针对弯道、环岛和目标区域分别优化参数。
0075 第二章 系统总体设计
0076 本章简要介绍智能车系统总体方案，后续章节分别说明机械结构、硬件电路、图像处理、目标识别、运动控制和整车调试。
0077 本队采用竞赛指定三轮车模，以龙芯2K0300作为主控制器。灵眼PRO摄像头负责采集赛道与目标板图像，编码器和IMU反馈车辆运动状态。程序依次完成赛道边线提取、十字与环岛处理、WPNIST目标分类和局部绕行轨迹生成，最终输出左右电机的目标速度和PWM控制量。系统结构如图2.1所示。
0078 图2.1 系统总体方框图
0079 根据总体方案，赛车由六个功能模块组成：龙芯主控模块、视觉传感器模块、电源模块、双电机驱动模块、速度与姿态检测模块以及辅助调试模块。各模块功能如下：
0080 1.龙芯主控模块：完成图像处理、目标分类、路径规划和车辆控制。
0081 2.视觉传感器模块：采集赛道边线、赛道元素、红色提示区域和目标板图像。
0082 3.电源模块：为主控、传感器、左右驱动电机和负压系统提供稳定电源。
0083 4.驱动模块：分别驱动左右电机，通过两轮差速完成速度与转向控制。
0084 5.检测模块：通过编码器和IMU反馈车速与姿态，供闭环控制使用。
0085 6.辅助调试模块：用于参数修改、图像观察、数据记录和故障定位。
0086 系统工作时，摄像头连续输出赛道和目标区域图像，龙芯2K0300完成图像预处理、边界搜索、元素判断和NCNN推理。编码器提供左右驱动轮速度反馈，IMU提供角速度与姿态变化信息，两类数据共同用于判断车辆运动状态。控制程序根据当前赛道状态计算基础速度和差速量，再生成左右轮目标速度，并通过双电机驱动与负压系统执行控制。
0087 各模块之间采用分层接口连接。图像处理层只输出边界、中线、元素状态和分类结果；决策层根据这些信息生成目标速度、目标路径及任务模式；控制层根据编码器和IMU反馈计算左右电机输出。这样既能减少不同算法之间的直接耦合，也便于在调试时单独替换某一模块。系统发生图像丢失、模型输出异常或传感器数据越界时，程序进入保护状态，限制速度并等待有效信息恢复。
0088 第三章 智能车机械结构调整与优化
0089 机械状态会直接影响图像稳定性、转向响应和可用速度。装配时重点控制车架刚度、传动阻力和各模块位置，使电路板与底盘可靠固定，同时为拆装维护留出空间。调试中先排除机械松动、齿轮过紧和轮胎状态不一致等问题，再进行软件参数整定。
0090 三轮车模结构紧凑，摄像头、核心板、驱动板、负压机构和电池集中安装在有限的底盘空间内。安装位置不仅影响整车重心，也会影响线束走向、散热和维修效率。本队装配时先确定摄像头和电池位置，再依次布置主控、驱动和辅助模块，使大电流线与图像、编码器等弱信号线分开，减少机械干涉和电气噪声。
0091 机械调整遵循由静态到动态的顺序。静态检查包括紧固件、支架刚度、齿轮间隙、轮胎同心度和电池固定；低速运行时检查直线偏移、转向回正和传动异响；提高速度后再观察摄像头振动、车尾摆动和轮胎侧滑。只有机械状态稳定后才固定控制参数，避免把机械问题错误地归因于软件。

0094 3.1 摄像头
0095 本队采用灵眼PRO摄像头，输出分辨率为320×240，帧率为120帧/s，主要用于赛道循迹、元素识别和目标板分类。
0096 摄像头安装位置兼顾赛道前瞻距离与目标板成像尺寸。实际安装高度为35 cm，俯仰角为60°，有效前瞻距离约为2.5 m。
0097 摄像头采用3D打印支架固定。曝光和增益参数在比赛场地光照条件下标定，曝光值设为80，自动增益设为80。
0098 摄像头支架需要同时满足刚度、重量和可调性要求。支架底部与车架采用螺栓连接，转折位置增加加强结构，并对线缆设置应力释放，防止车辆振动时接口受力。安装完成后分别检查直道、弯道和目标区画面，保证近端能够看到车辆前方赛道，远端保留足够前瞻，同时使目标板在截取区域内具有稳定尺寸。
0099 曝光和增益对二值化与目标分类均有直接影响。曝光过高时白色赛道容易饱和，红色提示区域边缘也会扩散；曝光过低则远端边界和目标图案细节不足。实际调试时先固定摄像头位置，再在不同光照条件下比较灰度分布、红色区域轮廓和分类置信度，选择兼顾赛道边界与目标板细节的参数。比赛前只进行小范围修正，避免临时改变参数导致整套阈值失配。

0101 3.2 编码器
0102 本队采用逐飞科技1024线编码器测量驱动轮转速。两路正交脉冲接入定时器计数接口，采样周期为5 ms，用于电机速度闭环和里程估计。安装时保证齿轮啮合顺畅，避免过紧或过松造成测量波动。
0103 编码器安装后首先检查A、B两相信号和计数方向，使车辆前进时速度反馈符号与控制程序约定一致。采样周期内的脉冲增量经过比例换算得到轮速，并采用短窗口滤波抑制单次计数跳变。低速阶段重点检查是否存在回差和丢脉冲，高速阶段则观察计数是否连续，防止连接松动造成速度环突然输出。
0104 速度反馈不仅用于保持设定车速，还参与弯道减速、目标区域限速和异常保护。当两侧反馈差值持续过大时，程序限制输出并记录当前状态，便于区分轮胎打滑、传动阻力和驱动电路问题。编码器齿轮长期运行后容易积尘，因此定期清理齿面并检查固定螺钉，保证测速状态具有重复性。

0106 3.3 IMU
0107 本队采用IMU660RB测量角速度和加速度，通过SPI与主控通信。IMU固定在车体中心附近，并在启动时完成零偏标定。
0108 IMU安装面尽量与车体底盘平行，并远离电机和大电流开关器件。车辆静止启动时连续采集若干组数据求取零偏，标定期间禁止推动车模；运行过程中对角速度进行低通滤波，用于判断车辆转弯趋势和环岛阶段。与单纯依赖图像相比，IMU在边界短时缺失时仍能提供连续的姿态变化信息。
0109 图像与IMU采用互补方式参与状态判断。普通循迹阶段以图像中线为主要依据，IMU用于抑制突发角速度和辅助检查转向是否符合预期；进入环岛或目标绕行后，程序结合角速度积分、边界恢复情况和行驶距离判断阶段切换。这样可以避免仅凭单帧图像过早退出元素状态。

0111 3.4 双驱动电机与差速转向
0112 三轮车模采用前随动轮和后部左右双驱动轮，车辆通过两侧轮速差完成转向。装配时重点保证两侧电机、齿轮和车轮状态一致，使相同PWM下的左右轮转速尽量接近。前随动轮转动应灵活且安装方向与车体中心线一致，避免机械偏置造成直线行驶时持续修正。
0113 控制程序把中线偏差转换为差速量：车辆需要左转时降低左轮目标速度并提高右轮目标速度，需要右转时执行相反分配。直道阶段减小差速以抑制摆动，弯道和绕行阶段根据偏差与曲率提高差速。左右轮分别采用编码器闭环，输出经过限幅和变化率限制，防止差速突变造成侧滑。
0114 3.5 负压系统的安装
0115 三轮车在较高速度通过弯道时容易出现侧滑，因此车体设置负压系统以提高轮胎对赛道的附着能力。两台2306无刷电机和风道安装在底盘中后部，进风口与赛道保持合适间隙，周围结构进行密封处理，减少漏气对负压效果的影响。安装时同时检查叶轮与外壳间隙，防止高速旋转时发生摩擦。
0116 两台负压无刷电机工作会带来振动和较大电流变化，因此采用独立驱动和牢固支撑。程序根据车辆启动、直道、弯道、环岛和目标区状态设置不同占空比，并对起转过程进行斜坡限制。调试中比较开启前后的弯道侧滑情况和电池压降，在保证稳定性的前提下避免持续满功率运行。

0118 3.6 电机的安装
0119 驱动电机安装时重点调整齿轮间隙与传动阻力。电机型号为380，传动比为50∶1。调试中以空载电流、运行异响和轮端阻力为依据确定合适的啮合位置，并定期清理传动机构。
0120 齿轮间隙过大时会产生明显回差，车辆加减速和换向时响应滞后；间隙过小时传动阻力和电机电流增大，还可能使齿轮快速磨损。调整时松开电机固定螺钉，使齿轮在轻微预紧状态下啮合，手动转动驱动轮检查一周内阻力是否均匀，再以低占空比空载运行，确认没有周期性异响。
0121 左右传动状态需要保持一致。将车轮悬空并给予相同控制量，比较两侧启动占空比、稳态转速和停止后的自由转动时间；若差异明显，优先检查齿轮、轴承和轮胎，而不是直接用软件增益补偿。正式测试前清理齿轮附近杂物并复查紧固件，避免长时间振动使电机位置变化。

0123 3.7 智能汽车的轮胎处理
0124 3.7.1 轮胎打磨
0125 原装胎面花纹较深且各轮一致性有限，因此先将轮胎装到轮毂上，借助低速旋转工具配合细砂纸均匀打磨。处理时只削低凸起花纹，不做成完全光面，以免胎面吸附灰尘后抓地力下降。每次调车前检查磨损和偏磨情况，状态异常时及时更换。
0126 3.7.2 轮胎软化处理
0127 打磨后的胎皮仍偏硬，采用轮胎软化剂进行保养。软化剂均匀涂覆后用保鲜膜包裹静置，使高速转弯时胎面能够产生适量形变并增大接地面积。正式测试前清理表面残留，避免软化剂影响赛道和轮胎摩擦状态。
0128 3.7.3 涂抹硅橡胶
0129 高速旋转会使胎皮与轮毂之间产生相对滑动，严重时可能脱圈。装配时在两者接触边缘薄涂硅橡胶加固，并在完全固化后再上车测试。日常检查若发现局部开裂或脱胶，则清洁接触面后补涂，防止轮胎状态变化影响控制参数。
0130 3.8 智能车重心位置的调整
0131 三轮车的动力电池安装在车体最后端，并尽量降低安装高度。该布置为主控板、驱动板和摄像头支架留出中部空间，同时使驱动轮获得较好的附着条件。调试中通过固定电池、降低上层器件高度和检查高速转弯姿态，避免尾部配重引起明显侧摆。
0132 整车重心调整以直线加速不抬头、差速转弯不过度、左右驱动轮具有足够附着力为原则。主控板和驱动板尽量贴近底盘布置，摄像头支架在满足视野的条件下减轻顶部重量，线束沿车架固定，避免运行时摆动。改变器件位置后重新检查左右轮静载、启动一致性和前随动轮方向，保证机械调整不会引入新的方向偏差。
0133 电池位于车体最后面后，后轴负载和驱动轮抓地力得到改善，但过度后移也可能增加车尾惯量。本队通过多次低速转向和高速连续弯测试确定固定位置，并使用限位结构约束电池横向移动。每次更换电池后检查魔术贴、挡块和接头，防止比赛过程中因电池窜动造成重心变化或瞬时断电。
0134 本队使用3S锂电池，标称电压11.1 V、容量2200 mAh、放电倍率110 C，共1块。电池横向放置在车体最后端，采用魔术贴与限位挡块双重固定，既便于快速拆装，也可防止加减速和转弯过程中发生窜动。电池安装如图3.8所示。

0160 第五章 智能汽车软件设计
0161 为使赛车稳定完成赛道循迹与目标任务，软件按赛道处理、目标识别和运动控制三个层次组织。巡线、十字和环岛处理采用上一届已经验证的算法框架；本届重点完成龙芯2K0300平台适配、68×68目标图像预处理、NCNN八子类推理、三大类映射以及目标绕行决策。
0162 软件设计的基本要求是每个图像周期内完成采集、处理、决策和控制更新，同时保证元素状态不会因单帧噪声反复切换。工程按功能划分为设备驱动、赛道图像处理、目标识别、状态决策、运动控制和调试通信等模块，各模块通过结构体和状态变量交换结果，避免在不同处理函数之间直接修改大量全局量。
0163 巡线和赛道元素部分延续上届经过实车验证的处理顺序，并根据三轮车的视野和控制特性重新标定阈值。目标识别部分独立运行，在满足目标区域触发条件时才执行NCNN推理，普通赛道阶段不重复占用推理计算资源。任务完成后清除分类锁定和绕行状态，使程序恢复常规循迹。
0164 5.1 程序主体流程
0165 程序启动后依次初始化摄像头、左右编码器、IMU、两路驱动电机、负压系统和调试接口，并加载NCNN模型参数与权重文件。初始化完成后进入主循环，持续完成赛道处理、目标识别、任务决策和差速运动控制。
0166 图5.1 程序流程图
0167 主循环首先获取赛道图像，完成预处理、边线提取、中线计算和十字、环岛等元素识别，再根据赛道曲率计算目标速度和转向偏差。
0168 进入目标区域后，程序定位红色提示区域并截取目标板ROI，再将目标图像统一缩放至68×68。经过通道转换和归一化处理后，图像被送入部署在龙芯2K0300上的NCNN轻量级分类网络。
0169 网络首先输出8个子类的分类结果，程序再按照比赛任务将其映射为武器、车辆和物资三大类：步枪、手榴弹、手枪和炸药包归为武器类，救护车和装甲车归为车辆类，急救包和望远镜归为物资类。三大类结果分别触发左绕、直行和右绕轨迹。程序流程如图5.1所示。
0170 主循环采用状态机组织运行顺序。初始化完成后首先进入普通循迹状态，持续更新边界、中线、车速和姿态；检测到十字、环岛或目标区域特征后，保存当前状态并进入相应处理分支。每个元素均设置进入、保持、退出和短时屏蔽条件，防止同一区域被重复识别。若图像处理失败，则短时间沿用上一帧有效结果并降低目标速度。
0171 图像、编码器和IMU数据按各自周期更新。图像线程负责生成赛道与目标识别结果，控制线程以固定周期读取最新有效数据并计算输出。对跨线程使用的状态设置明确的更新时间和有效标志，避免控制程序读取到一半更新的数据。调试信息采用较低频率输出，防止大量日志影响主循环实时性。
0172 5.2 图像处理
0173 5.2.1 赛道边沿及中线提取
0174 赛道边沿是循迹和元素判断的基础。程序先将灰度图二值化，再从图像底部种子点出发，采用四邻域迷宫巡线分别搜索左右边界；搜索过程中利用相邻行位置限制范围，从而降低孤立噪点造成的跳变。
0175 预处理依次完成灰度化、3×3中值滤波和Otsu自适应阈值分割，并对近端小面积断点进行连通修补。有效搜索区域覆盖车辆前方赛道，处理流程在一个图像周期内完成。
0176 赛道图像具有近大远小的透视特征，因此边界搜索由图像下方向上进行。程序先在近端行寻找稳定的左右起始点，再依据相邻行边界位置限定下一步搜索范围。四邻域迷宫巡线能够沿连续边缘逐点推进，在遇到局部噪点时仍保持搜索方向，直到两侧边界相遇、达到远端限制或有效点数不足。
0177 Otsu阈值用于适应场地整体亮度变化，同时对计算结果设置上下限，避免强反光或阴影使阈值突变。二值化后先去除孤立黑白点，再给图像边缘设置保护框。对于连续几行内的小断点，根据前后边界斜率进行补偿；大范围丢线则交由元素状态机处理，不使用普通补线强行延伸。
0178 图5.2 边沿提取算法
0179 当局部边界不连续时，程序依据断点前后的有效点和赛道宽度约束进行线性补线；若两侧同时缺失，则结合上一帧中线和远端重新搜索结果恢复参考路径。
0180 左右边界取中得到原始中线，再对连续有效点进行分段最小二乘拟合，并以滑动平均抑制个别异常点，得到用于转向控制的平滑参考路径。
0181 中线计算时不简单使用固定赛道宽度，而是优先采用同时有效的左右边界取中；只有单边有效时，才根据当前图像行对应的标准赛道宽度向另一侧偏移得到临时中线。补出的点设置较低权重，避免单侧边界误差直接放大到左右轮差速量。
0182 拟合后的中线还需要进行连续性检查。当相邻点横向变化超过允许范围时，程序回看附近有效点并剔除异常值。最终用于控制的不是单独一行，而是多个前瞻区域的加权结果，从而兼顾直道稳定性和弯道响应速度。
0183 图5.3 中线提取结果
0184 5.2.2 图像矫正
0185 摄像头倾斜安装会使图像中的距离和宽度随纵坐标变化。本队使用棋盘格完成相机标定，并根据安装高度和俯仰角建立逆透视映射表，将像素点转换到车体坐标系；运行时采用查表方式降低计算量。
0186 原始图像中远端赛道被压缩，同一实际宽度在不同图像行对应的像素数不同。如果直接使用像素斜率和宽度判断元素，阈值会随位置变化。标定时固定摄像头支架，采集不同位置的棋盘格图像求取内参与畸变参数，再根据赛道平面建立像素坐标到车体坐标的映射关系。
0187 逆透视结果主要用于赛道宽度、角点位置和绕行轨迹计算。为减小龙芯平台上的重复运算，程序提前生成查找表，运行时按像素索引读取映射坐标。超出有效区域的点直接标记为无效，并对映射后的边界进行一次平滑，避免查表取整产生锯齿。
0188 图5.4 图像校正前后对比
0189 5.2.3 偏差计算
0190 转向偏差由参考中线与车辆中心线计算得到。程序采用随速度和曲率变化的动态前瞻：直道提高远端点权重以减小摆动，弯道提高近端点权重以加快响应；最终偏差为多个前瞻点横向误差的加权和。
0191 固定前瞻在不同赛道上的效果差异较大：前瞻过远会使车辆提前转向，连续弯中容易压线；前瞻过近则直道修正频繁，高速时出现摆动。本队根据中线曲率、有效边界长度和当前速度选择近、中、远三组采样区域，并对各区域误差设置不同权重。
0192 当远端边界完整且曲率较小时，提高远端权重，使车辆提前感知缓弯并保持直道平稳；曲率增大或远端丢线时，逐步转向近端误差，保证车辆能够沿当前可见赛道通过。偏差结果经过限幅和一阶滤波后送入转向控制，元素状态下则使用对应的补线中线或规划路径替代普通中线。
0193 5.3 元素识别
0194 5.3.1 识别可用几何特征
0195 元素识别综合使用边界连续性、角点数量、赛道宽度、斜率变化和曲率趋势。各阈值按归一化图像尺寸设置，并由状态机连续三帧确认；退出阶段要求普通赛道特征连续恢复，避免单帧噪声造成重复触发。
0196 为防止误判，程序采用状态机和连续帧确认，并对同一元素设置进入、保持和退出条件。
0197 几何特征在单帧图像中可能同时满足多个元素条件，因此识别顺序和互斥关系需要明确。程序先判断当前是否已经处于某一元素状态，若已进入则只执行该元素的阶段判断；普通状态下再按照目标区域、环岛、十字等优先级检查候选特征。候选条件连续出现后才锁定，锁定期间其他元素不再抢占。
0198 角点由边界局部方向变化计算，赛道宽度由逆透视坐标得到，斜率与曲率则使用连续点拟合结果。每类特征均设置有效点数量和位置范围，避免图像边缘、阴影或局部反光形成的伪角点参与判断。调试时将关键点和状态编号叠加到图像上，结合实车录像逐帧检查进入与退出位置。
0199 5.3.2 十字识别
0200 十字区域通常表现为左右边界同时向外扩展、近端边界短时丢失并出现成对L角点。上述特征连续三帧成立后进入十字状态，优先利用远端有效边界确定出口方向；远端不可用时连接角点补出两侧边界并取中通过。
0201 进入十字后，普通边界搜索容易沿横向分支离开主赛道，因此程序不直接采用搜索到的全部边界。若远端仍有成对有效边界，则从近端断点向远端边界连接；若仅检测到一侧角点，则根据十字前保存的中线方向和标准赛道宽度补出另一侧。补线仅在十字状态内有效，防止影响普通弯道。
0202 车辆通过十字中心后，近端左右边界逐步恢复。程序要求边界宽度、连续点数和中线方向连续满足普通赛道条件，才退出十字状态；退出后的若干帧内屏蔽再次识别。这样能够减少车辆在十字后沿因残留角点重复进入状态。
0203 图5.5 十字识别
0204 5.3.3 环岛识别
0205 环岛识别划分为发现、入环、环内、出环和恢复五个阶段。入口阶段根据单侧边界连续弯折、另一侧边界暂时丢失以及赛道宽度突变触发状态机；随后结合角点位置和IMU航向变化，分阶段补出参考中线。
0206 车辆驶过出口后，程序同时检查左右边界是否重新稳定、赛道宽度是否回到普通范围以及航向变化是否完成。条件连续满足五帧后退出环岛状态，并设置短时屏蔽窗口防止重复进入。
0207 环岛入口与普通弯道的区别在于单侧边界形态和赛道宽度会持续变化。发现阶段只记录候选方向，不立即大幅补线；随着角点位置向近端移动，状态机进入入环阶段，利用圆环内侧边界和入口方向生成平滑参考线。车辆进入环内后，普通中线暂时失去意义，此时控制主要依据阶段补线和IMU角速度。
0208 出环阶段重点识别外侧边界重新出现以及内侧边界斜率突变。程序根据出口角点和上一阶段路径连接出环中线，并逐步把控制权交还普通边界。若只依赖单个角点，反光或断线容易导致提前出环，因此同时使用航向变化量、有效边界长度和赛道宽度作为确认条件。
0209 环岛方向、入口位置和退出位置在不同车速下会有偏差，因此调试时先降低速度验证状态顺序，再逐步提高入环和环内速度。每次测试记录状态编号、转向偏差和IMU角速度，通过比较多次运行结果调整阈值，保证同一环岛能够在不同电池电压下稳定通过。

0211 5.3.4 目标板识别
0212 本队目标识别程序基于OpenCV和NCNN实现。程序在红色提示区域附近截取目标板ROI，将其统一缩放至68×68，并完成通道转换和归一化处理后输入轻量级分类网络。网络输出8个子类，分别为步枪、急救包、救护车、手榴弹、手枪、望远镜、炸药包和装甲车。程序读取输出向量并确定置信度最高的子类，再将步枪、手榴弹、手枪和炸药包映射为武器类，将救护车和装甲车映射为车辆类，将急救包和望远镜映射为物资类。该方案采用“八分类识别—三大类任务映射”的两级结构，既保留了目标板细分类信息，又能直接生成比赛所需的左绕、直行和右绕指令。
0213 目标区域首先通过HSV颜色空间提取红色提示部分。程序对高、低两个红色色相区间分别阈值分割，再进行形态学闭运算以连接局部断裂区域。轮廓筛选时去除面积过小的反光点，并优先选择底边位置靠近车辆的有效轮廓。根据轮廓中心与底边位置向上截取目标板区域，同时进行边界限制，防止ROI超出原图。
0214 截取后的图像统一调整为68×68，并按照模型训练时的通道顺序完成BGR到RGB转换及均值、方差归一化。NCNN加载参数文件和权重文件后创建推理执行器，输入节点为in0，输出节点为out0。八维输出经过Softmax换算为置信度，最大值对应当前细分类结果。推理过程同时记录耗时，便于检查平台负载和模型运行是否稳定。
0215 为避免单帧误识别直接改变车辆轨迹，程序在目标区域内对分类结果进行连续确认。只有置信度达到要求且同一大类连续出现时才锁定任务；若细分类在同一大类内部变化，三大类映射结果仍保持不变。置信度不足或输出节点异常时，车辆保持目标区低速并继续采集，不使用无效结果。
0216 八个细分类的顺序与训练数据目录保持一致：步枪、急救包、救护车、手榴弹、手枪、望远镜、炸药包和装甲车。程序将索引0、3、4、6映射为武器类，将索引2、7映射为车辆类，其余索引映射为物资类。映射完成后只向决策层输出三大类任务编号，图像界面仍保留细分类名称和置信度用于调试。

0219 5.4.1 控制理论
0220 受电池电压、路面摩擦和车辆负载变化影响，电机采用编码器反馈的闭环控制方式，以提高不同工况下的速度稳定性。

0229 左右电机分别保存控制器状态，但使用相同的整定步骤。直道阶段目标速度较高，弯道、环岛和目标区根据曲率与状态降低速度；转向量较大时还会对左右轮目标速度进行差速修正，使外侧轮适当加速、内侧轮适当减速。负压系统的目标占空比与车辆状态同步更新。

0231 5.4.2 PID 参数的作用与整定
0232 PID参数按照先比例、后积分、再根据需要加入微分的顺序整定，并分别在直道加速、弯道减速和低速行驶工况下进行验证。
0233 （1）比例P：决定速度误差的基本响应强度。
0234 （2）积分I：用于消除稳态误差，并设置积分限幅防止饱和。
0235 （3）微分D：抑制误差快速变化引起的超调，实际使用时需配合滤波。
0236 最终参数以低速运行不振荡、加减速过程无明显超调、弯道速度能够稳定跟随为整定目标。调试时同步记录目标速度、编码器速度和PWM输出，用于检查响应滞后、积分饱和以及左右电机差异。
0237 比例系数过小时响应缓慢，过大时速度会在目标值附近持续振荡；积分系数主要消除摩擦和左右传动差异造成的静差，但累积过快会在加减速阶段形成明显超调；微分项对高频测量噪声敏感，因此只有在速度变化趋势需要提前抑制时少量使用，并配合滤波。
0238 参数整定从低占空比和低目标速度开始。先关闭积分与微分，只提高比例项直到响应速度满足要求且不持续振荡；再逐步增加积分消除稳态偏差；最后根据加速和减速曲线判断是否需要微分或前馈。左右轮分别整定后进行直线运行检查，必要时只做小范围差异补偿。
0239 参数整定原则如下：
0240 （1）先在低速条件下确认方向、编码器极性和输出限幅；
0241 （2）逐步提高比例增益，使响应足够快且不持续振荡；
0242 （3）加入少量积分消除静差，必要时加入微分抑制超调。
0243 整定完成后分别在直道、弯道、坡道和目标区进行重复测试。

0245 5.5 目标决策与绕行
0246 目标大类确定后，武器类生成左侧绕行轨迹，物资类生成右侧绕行轨迹，车辆类保持中线直行。分类映射在推理程序中固定完成：步枪、手榴弹、手枪和炸药包对应武器；救护车和装甲车对应车辆；急救包和望远镜对应物资。绕行路径由两段三次贝塞尔曲线连接，并与目标板保持安全间距；目标位于车后且普通赛道中线恢复后，车辆重新进入常规循迹。
0247 绕行决策不直接修改普通赛道边界，而是在车体坐标系中生成一段局部参考路径。程序根据目标板横向位置、预定绕行方向和安全间距确定贝塞尔曲线控制点，第一段引导车辆离开原中线并绕到目标侧方，第二段使车辆平滑回到赛道中心。两段曲线在连接处保持方向连续，减少左右轮差速量突然反向。
0248 目标区域内限制行驶速度，并根据路径曲率动态选择前瞻点。车辆尚未到达目标板时优先跟踪第一段路径，越过目标板后切换第二段；当目标位于车后、左右边界重新稳定且中线误差回到正常范围时，清除任务锁定并恢复普通循迹。若恢复条件不足，则继续沿局部路径低速行驶，避免过早切换导致压线。
0249 车辆类对应直行任务时仍保留目标区限速和分类锁定，只是不生成左右偏移路径。武器类和物资类分别采用相反的横向控制点，其他速度、退出和保护条件保持一致。通过统一的轨迹接口，三种任务只改变任务编号和控制点方向，不需要为每个细分类分别编写一套控制程序。

0279 本车以龙芯2K0300为核心，完成三轮车机械平台、摄像头与编码器/IMU、差速驱动和负压系统的集成；软件实现常规循迹、十字与环岛处理，以及68×68八分类结果向物资、车辆、武器三大类映射并执行相应路径。现阶段主要不足是光照突变和目标板倾斜时识别稳定性仍会下降，后续可通过补充样本、统一曝光和优化状态切换阈值进一步提高可靠性。

0470 static bool run_ncnn_inference(ncnn::Net &net,
0471 const Mat &target_image,
0472 int &sub_class,
0473 float &confidence,
0474 double &infer_time_ms)
0475 {
0476 ncnn::Mat input = ncnn::Mat::from_pixels_resize(
0477 target_image.data,
0478 ncnn::Mat::PIXEL_BGR2RGB,
0479 target_image.cols,
0480 target_image.rows,
0481 MODEL_INPUT_SIZE,
0482 MODEL_INPUT_SIZE);
0483 input.substract_mean_normalize(mean_vals, norm_vals);
0484 auto start_time = chrono::high_resolution_clock::now();

0486 extractor.input("in0", input);
0487 ncnn::Mat output;
0488 if (extractor.extract("out0", output) != 0 || output.empty())
0489 {
0490 return false;
0491 }
0492 auto end_time = chrono::high_resolution_clock::now();
0493 infer_time_ms = chrono::duration_cast<chrono::microseconds>(
0494 end_time - start_time).count() / 1000.0;
0495 const float *score = (const float *)output.data;
0496 float max_score = score[0];
0497 sub_class = 0;
0498 for (int i = 1; i < MODEL_OUTPUT_CLASS_NUM; ++i)
0499 {
0500 if (score[i] > max_score)
0501 {
0502 max_score = score[i];
0503 sub_class = i;
0504 }
0505 }
0506 float exp_sum = 0.0f;
0507 for (int i = 0; i < MODEL_OUTPUT_CLASS_NUM; ++i)
0508 {
0509 exp_sum += exp(score[i] - max_score);
0510 }
0511 confidence = 1.0f / exp_sum;
0512 return true;
0513 }
