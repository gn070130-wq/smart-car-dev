0044 全国大学生智能汽车竞赛由教育部高等学校自动化类专业教学指导委员会主办，是面向全国大学生的一种具有探索性工程实践活动，该竞赛以“立足培养、重在参与、鼓励探索、追求卓越”为指导思想，旨在促进高等学校素质教育，培养大学生的综合知识运用能力。
0045 竞赛内容涵盖广泛，涉及控制、模式识别、传感技术、电子、电气、计算机、机械、通信、汽车工程等多个学科领域。竞赛鼓励全国各高等学府的与以上领域相关专业的学子积极参与，以激发创新灵感，促进跨学科融合，为中国智能车技术的进步贡献一己之力。
0046 在本次竞赛中，我们采用大赛组委会指定的F车模完成规定任务，在经历了多次对整车机械结构的调整、软件调试、硬件电路优化后，得到了一套稳定的可以自动识别、搬运、返回完成比赛任务的智能车系统。
0047 本篇技术报告介绍智能视觉组智能车系统的软硬件结构和开发流程，将从智能车的机械结构、硬件电路、算法设计、模型训练等方面全面详细的介绍整个准备过程。
0048 本文的参考文献中，主要涉及数字电子、模拟电子的基础知识讲解，C/C++程序设计，电子电路设计，PCB制作和车模机械结构校调等方面的内容。
0049 第一章 系统设计方案
0050 在系统总体设计上，本方案采用“感知—决策—执行”的分层架构。感知层由摄像头模块、陀螺仪模块和编码器模块组成，分别获取赛道图像信息、车体姿态信息和车轮速度信息；决策层由2K0300核心板完成，运行图像处理、路径规划和运动控制算法，实时计算转向角和目标速度；执行层由有刷驱动模块和无刷驱动模块构成，根据核心板输出的PWM控制信号驱动电机转动，实现转向和速度调节。
0051 各模块之间通过拓展板引出的接口进行连接。核心板通过图像采集接口读取摄像头数据，通过SPI或IIC接口读取陀螺仪数据，通过编码器接口采集脉冲信号，同时输出多路PWM至驱动模块。编码器模块实时反馈车轮转速，与核心板内设定的目标速度进行比较，形成速度闭环控制，保证小车在直道和弯道中均能按照期望速度行驶。电源部分采用多级稳压电路，为各模块分别提供稳定的5V、3.3V等所需电压，减少电机驱动等大电流部分对传感器和核心板的干扰。
0052 在软件流程上，系统上电后首先完成外设初始化和参数配置，然后进入主循环。主循环中周期性采集图像和传感器数据，更新车辆状态，调用控制算法计算转向和速度控制量，并输出至执行机构。通过定时中断保证控制周期稳定，提高系统实时性。该总体设计方案兼顾了实时性、稳定性和可扩展性，为后续软硬件调试奠定了基础。
0053 机械结构设计与优化
0054 本届比赛龙芯组对摄像头、陀螺仪的选择没有过多限定，我们采用了规则指定车模博思威龙的F车模。本章将主要介绍本组在规则范围内对智能车车模的机械结构设计及调整方案。
0055 2.1 车模整体结构
0056 本届比赛龙芯组指定使用博思威龙F车模，这是一款高灵活性的三轮车，设计精密，抓地力强。对于车模结构调整，我们力求紧凑和低重心，以此来保证转向的稳定。车轮方面，我们选择使用摩擦力更大的硅胶胎。
0057 在此基础上，为进一步提高整车性能，我们对车模整体布局进行了优化。首先，在满足安装要求的前提下，尽量将电池、驱动板、核心板等质量较大的部件安装在底盘较低位置，使整车重心尽量贴近地面，减小高速过弯时的侧倾趋势。其次，调整左右两侧质量分布，保证车辆左右对称，避免因重心偏移造成直线行驶跑偏。再次，对前轮转向机构进行适当调节，保证左右转向力矩对称，转向灵活且回正顺畅。轮胎方面，选用硅胶胎后，我们还在赛前对胎面进行清洁处理，去除表面油污和脱模剂，以充分发挥其高摩擦系数优势；同时根据赛道材质和温度变化，适当调整轮胎胎压，使轮胎与地面保持最佳接触状态。

0059 2.2 各部件安装
0060 2.2.1 摄像头的安装
0061 我们选用了龙邱灵眼pro摄像头模块，通过碳素杆固定。碳素杆具有重量轻、刚度好的特点，可减小车辆行驶过程中摄像头抖动对图像质量的影响。
0062 为了获得稳定、有效的赛道图像，我们重点调整了摄像头的安装高度和俯仰角。摄像头安装高度经过多次试验确定，使图像中赛道近端和远端均能清晰成像，最远可看到两米以上的距离，为路径规划提供足够的预瞄信息。俯仰角调节使赛道在图像中占据合理的比例，避免因视野过低或过高导致赛道边界丢失。同时，在碳素杆与车体连接处增加减震胶垫，抑制电机运行和路面颠簸引起的振动，保证采集图像的稳定性。摄像头数据线采用软排线并适当固定，防止运动过程中晃动拉扯造成接触不良或信号干扰。
0063 2.2.2 陀螺仪的安装
0064 陀螺仪模块我们选用的是IMU660RB陀螺仪。由于F型车模的体积较小、空间紧凑，我们将陀螺仪放置在驱动板的旁边。
0065 为保证姿态测量的准确性，安装时我们注意以下几点：一是将陀螺仪模块固定平面与车体底盘保持平行，安装后通过静态标定消除零偏误差；二是在模块底部粘贴减振海绵或橡胶垫，降低电机运转和路面振动对陀螺仪数据的干扰；三是尽量远离大电流驱动走线和电机等强电磁干扰源，避免影响SPI/IIC通信质量。陀螺仪数据与摄像头图像融合后，可以辅助判断车体姿态变化，提高转向控制的稳定性和抗干扰能力。
0066 2.2.3 编码器的安装
0067 编码器我们选用的是逐飞科技的产品，直接安装在车模提供的安装位置上。该位置与电机传动齿轮配合良好，安装方便且结构可靠。
0068 安装时，我们确保编码器齿轮与驱动齿轮之间的啮合间隙适中。间隙过大会导致测量滞后和丢步，间隙过小则会增加传动阻力并加速齿轮磨损。通过反复调整固定螺钉，使齿轮啮合平顺、转动灵活。同时，检查编码器线束走线，避免与旋转部件干涉，并做好插头固定，防止长期运行后松动。编码器反馈的实时速度信号为速度闭环控制提供了可靠依据，使小车能够根据赛道情况快速调整行驶速度。
0069 2.2.4 负压的安装
0070 我们使用的是逐飞RS2205无刷电机，通过3D打印的负压支架固定负压风扇与保护壳。
0071 负压装置的作用是通过风扇高速旋转在车底形成负压区，增大车轮对地面的正压力，从而提升轮胎附着力，改善过弯时的稳定性和极限速度。在机械结构上，我们利用3D打印工艺制作了轻量化负压支架和保护壳，支架与车体连接牢固，避免高速行驶时产生松动或共振。保护壳既起到导流作用，又能防止赛道异物卷入风扇。通过调整负压风扇的安装高度和密封裙边与地面的间隙，使负压效果达到最佳。在调试中，根据弯道中车辆侧滑情况适当调节负压电机转速，平衡下压力与能耗之间的关系，保证车辆既有足够抓地力，又不会因下压力过大而增加行驶阻力。
0072 通过以上各部件的合理安装与优化，整车的机械结构在紧凑性、稳定性和可维护性方面均得到了较好保证，为后续的软硬件调试和实际运行奠定了良好基础。

0074 电路设计说明
0075 本组电路部分主要由电机驱动模块和主控电路板构成，其中主控电路包括了陀螺仪模块、无刷驱动模块、供电模块等。本章将对主要模块电路的设计方案进行具体阐述。
0076 3.1 主控电路板
0077 主控电路板根据本组需要用到的功能，引出了核心板的引脚，方便后期各模块功能集成。在电源管理方面，设计12V转5V的电源模块和变阻器，为主控板上各类元器件进行供电。稳压模块作为主控板上的重要组成部分，我们采取了模块化设计。
0078 5V稳压芯片我们选用了一款宽输入电压范围的同步降压转换芯片。该芯片具有以下特点：
0079 - 宽输入电压范围，支持高达3A的持续输出电流；
0080 - 集成低导通电阻的MOSFET，轻载时支持脉冲跳跃模式，提升效率；
0081 - 输出电压可调，初始精度较高；
0082 - 内部补偿可最大限度减少外部器件数量；
0083 - 固定开关频率，适用于小型滤波器尺寸；
0084 - 具备过流限制、过压保护和输入欠压保护；
0085 - 工作结温范围宽，满足车模工作环境要求。
0086 上述特性加上该芯片体积较小、集成度高，我们最终采用了此芯片。
0087 在具体电路设计上，12V电源经输入滤波电容后进入稳压芯片的输入引脚，输出端通过功率电感和输出电容构成LC滤波网络，得到稳定的5V电压。根据数据手册推荐，选取了合适的电感值和电容值，以确保输出纹波满足要求。芯片底部带有散热焊盘，PCB布局时通过过孔阵列将热量传导至地层，提升散热能力。同时，将输入电容尽量靠近芯片输入和地引脚放置，减小高频环路面积，降低开关噪声。在5V输出端串联可调变阻器，便于根据实际负载情况微调输出电压，并为后级电路提供一定的限流保护。
0088 模块化设计使得主控板上的电源部分与核心板、传感器接口相互独立，便于单独调试和更换。若电源模块出现故障，可快速定位并修复，不影响其他电路。主控板上还预留了多个扩展接口，包括摄像头接口、陀螺仪通信接口、编码器接口、无刷电机PWM接口以及串口调试接口等，方便后期功能扩展和软件调试。

0090 3.2 有刷电机驱动板
0091 我们采用一款专为有刷直流电机设计的栅极驱动芯片作为主驱动芯片，搭配信号隔离芯片和若干MOS管构成全桥驱动电路。
0092 该栅极驱动芯片内部集成电荷泵，可驱动高边N沟道MOSFET，支持PWM控制。与传统的分立元件驱动方案相比，该芯片具有更高的集成度和可靠性，能够提供足够的栅极驱动电流，使MOSFET快速开关，降低开关损耗。信号隔离芯片为多路三态缓冲器，在电路中起到信号隔离和电平转换的作用，将主控输出的PWM信号与驱动芯片隔离，防止电机驱动侧的大电流或干扰信号反灌到主控电路，提高系统稳定性。
0093 全桥电路由多枚MOS管组成，每半桥使用两枚MOS管并联，以降低导通电阻、提高电流承载能力。全桥结构可实现电机的正转、反转和制动控制。PWM信号经栅极驱动芯片放大后驱动MOS管栅极，通过调节PWM占空比控制电机端电压，从而调节电机转速。为减小上下桥臂同时导通造成的直通短路风险，栅极驱动芯片内部具有自适应死区控制功能，并在外部设置了必要的栅极电阻，抑制寄生振荡。
0094 电源输入端并联大容量电解电容和小容量陶瓷电容，滤除电机换向引起的电源纹波，保护前级电路。电机两端并联续流二极管（或利用MOS管体二极管），为电机感性负载提供续流回路。PCB布局上，将大电流走线加宽并覆锡，减小线路压降和发热；驱动芯片与MOS管尽量靠近放置，缩短栅极驱动回路长度，降低寄生电感，提高开关性能。

0096 3.3 无刷电机驱动
0097 我们采用一款高性能单片机作为无刷电机电子调速器（电调）的主控芯片，用于驱动负压风扇的无刷电机。
0098 该单片机具有较高的主频，内部集成多路PWM输出、ADC采样和硬件乘法器等资源，适合用于无刷电机的电子调速控制。本组利用该芯片制作单通道无刷电调。
0099 电调的工作原理为：上电后，单片机首先检测无刷电机转子初始位置，通过反电动势过零点检测方法实现无传感器换相。启动时采用开环强制定位和加速策略，待电机达到一定转速后切换至闭环运行。在运行过程中，单片机通过ADC实时采样三相绕组的反电动势信号，判断过零点并计算换相时刻，通过控制三相逆变桥的开关管依次导通，使电机持续旋转。电机转速通过调节PWM占空比实现，外接PWM信号作为调速指令，由单片机捕获并转换为相应的驱动PWM占空比。
0100 电调电路采用六枚MOSFET组成三相全桥逆变电路，每个桥臂由高边和低边MOS管组成。为简化驱动电路，选用了集成栅极驱动器的MOS管驱动芯片，单片机输出六路PWM信号控制驱动芯片，驱动芯片再驱动MOS管栅极。电源输入端设置防反接保护和滤波电容，三相输出端连接无刷电机。同时，板载LED指示灯用于显示电调工作状态，方便调试。
0101 在实际调试中，我们对无刷电调的启动参数、换相延时和PWM频率进行了优化，确保负压风扇在不同电压和负载条件下均能稳定启动和调速。负压风扇高速旋转时会产生较大的反电动势和电磁干扰，因此在电调电源输入端和信号线路上均增加了滤波和屏蔽措施，减小对主控电路和传感器的影响。
0102 通过上述硬件电路设计，本组实现了主控、驱动、供电等各模块的协调工作，为整车的稳定运行提供了可靠保障。

0104 程序与算法说明
0105 4.1 图像处理
0106 图像处理算法，主要用于赛道元素识别与处理。算法首先通过改进的大津法进行图像二值化，动态调整阈值以适应不同光照条件。接着，利用传统的扫线法提取赛道边线，通过中心扩展策略增强抗干扰性。在元素识别模块，算法基于边界的突变和宽度变化检测特殊赛道元素，如环岛、直道、障碍物和斑马线。针对边线丢失的情况，算法通过预测丢失边线的走向进行补偿。最后，算法计算前瞻控制误差并实现紧急制动功能，确保车辆在复杂赛道环境中的稳定与安全。整体而言，这套算法在准确性和实时性上都有不错的表现，但在极端场景下的鲁棒性仍有提升空间。
0107 4.2 PID调试
0108 PID控制部分在代码中通过Velocity_loop_PID_left和Velocity_loop_PID_right两个函数实现，采用增量式算法对左右电机进行独立控制。核心逻辑包括：通过编码器获取实际速度（speed_left/right），计算与目标速度（target_velocity）的误差，将误差经过比例、积分、微分三个环节的线性组合（Speed_Pl/Il/Dl参数）生成控制量。特别设计了输出限幅机制，防止PWM占空比超出安全范围。方向控制通过GPIO电平与PID输出正负联动，当输出为正时设置GPIO高电平驱动电机正转，负值则输出反向PWM并设置低电平实现反转。值得注意的是，积分项采用增量累加方式而非位置式存储，这种设计天然具备抗积分饱和特性，同时微分项采用(e(k)-2e(k-1)+e(k-2))的三阶差分形式，相比标准微分项能更好抑制高频噪声。
0109 阿克曼差速控制通过Ackerman_diff函数实现，其核心是根据转向角度动态调整左右轮目标速度。当检测到转向输入（Duty偏离steer_middle）时，系统首先将转向量转换为非线性补偿系数y，该系数通过二次函数计算得出，其中x由转向偏差与转向速度参数（Left_Speed/Right_Speed）共同决定。对于左转工况（Duty≥steer_middle），右轮目标速度获得正向补偿，左轮则相应降低；右转时补偿方向相反。特别设计x的最大阈值，防止过度转向导致的系统不稳定。当前实现中limit参数被置零，意味着差速补偿尚未启用限幅功能，这可能是为了保留转向系统的动态响应能力，但实际应用中可能需要结合车辆动力学特性进行参数优化。
0110 4.3 模型训练与绕行
0111 首先，对目标板的处理采用先定位、再裁剪、后绕行的思路，使用NCNN对数据集进行训练，得到轻量化模型，导入板卡中进行推理，再进行对应的绕行决策。具体实现过程如下：
0112 （1）数据集构建与预处理。针对实际应用场景采集大量包含目标物体的图像，使用标注工具对目标位置进行标注，生成包含目标类别和边界框信息的数据集。为提升模型泛化能力，对图像进行随机旋转、缩放、裁剪、亮度变化等数据增强操作，并将数据集划分为训练集和验证集。
0113 （2）模型训练与轻量化。选用适合嵌入式部署的轻量化目标检测网络，在PC端使用深度学习框架进行训练。训练过程中采用迁移学习策略，加载预训练权重加速收敛，并通过调整学习率、批大小等超参数优化模型性能。训练完成后，将模型导出为ONNX格式，再通过NCNN工具链转换为NCNN格式（.param和.bin文件），必要时进行INT8量化以减小模型体积和降低计算量。
0114 （3）板卡端推理。将转换后的NCNN模型文件部署到目标板卡上，调用NCNN推理框架加载模型。对摄像头采集的实时图像进行预处理，包括尺寸缩放、像素归一化等，然后输入网络进行前向计算，得到目标物体的位置、置信度和类别信息。为提高实时性，可对输入图像进行适当降采样，并结合多线程或硬件加速单元优化推理速度。
0115 （4）绕行决策。根据推理结果判断目标在图像中的位置和大小：控制设备向右绕行；向左绕行；与直行。同时结合连续多帧检测结果进行滤波，避免因单帧误检造成错误动作。通过在实际环境中反复调试，确定合理的置信度阈值和非极大值抑制参数，最终实现稳定可靠的自动绕行功能。
0116 开发工具、制作、安装、调试过程说明
0117 5.1 软件开发工具
0118 本项目软件开发主要基于 Linux 环境进行。使用 Linux 系统虚拟机搭建开发调试环境，可有效模拟目标设备的运行环境，避免宿主操作系统差异带来的兼容性问题。虚拟机中安装了交叉编译工具链、必要的依赖库及调试工具，通过命令行完成代码编译、链接与运行测试，便于快速定位和解决软件问题。
0119 同时，使用 MobaXterm 作为远程终端和文件传输工具。MobaXterm 集成了 SSH、SFTP、串口终端、X11 转发等多种功能，能够方便地连接虚拟机或目标板，完成代码上传、下载、日志查看以及串口调试等操作。在开发过程中，通过 MobaXterm 远程登录 Linux 虚拟机进行代码编译，并利用其文件传输功能将生成的可执行文件或固件下载到目标设备，显著提高了开发调试效率。
0120 5.2 硬件开发工具
0121 本项目选用嘉立创 EDA 专业版进行 PCB 设计。其集成式器件库支持符号、封装、3D 模型、参数一体化调用，设计时无需在商城与编辑器间切换，并显著提升元件库复用效率。在设计过程中，利用其原理图与 PCB 同步功能，可以快速完成布局布线；通过 3D 预览功能检查元器件与结构件之间的干涉情况；使用设计规则检查（DRC）及时发现电气间距不足、线宽不符合要求等问题，保证 PCB 设计的正确性。
0122 完成 PCB 设计后，嘉立创 EDA 专业版可直接导出 Gerber 文件、BOM 清单和坐标文件，用于后续 PCB 打样、元件采购及贴片加工，减少因格式转换带来的错误。
0123 5.3 制作过程
0124 PCB 设计完成后，将 Gerber 文件提交至 PCB 厂商进行打样。收到空板后，首先进行外观检查，确认板面无划伤、无短路、无断路、过孔导通良好等缺陷。然后根据 BOM 清单采购元器件，并对关键器件进行参数核对，确保元件型号、封装和参数与设计一致。
0125 焊接时，按照先电源后主控、先低矮元件后高元件的顺序进行。先焊接电源部分，上电测试各路电压正常后，再依次焊接主控芯片、外围电路及接插件。对于 QFN、0402 等小封装元件，可采用回流焊或手工热风枪焊接。焊接完成后，使用放大镜或显微镜检查焊点，清理残留助焊剂，确保无虚焊、连锡等问题。
0126 5.4 安装过程
0127 硬件安装方面，将焊接调试完成的 PCB 固定到外壳或支架上，连接电源线、信号线、天线及外部接口，确保接线正确、固定可靠。安装过程中注意防静电措施，避免对敏感元件造成损伤。
0128 软件安装方面，在 Linux 虚拟机中交叉编译生成目标板可执行文件或固件，通过 MobaXterm 的上传至目标板文件系统，或通过SSH等方式烧写。安装完成后，配置启动脚本、网络参数及设备树等，使系统能够开机自动运行所需应用程序，并保证各功能模块正常加载。
0129 5.5 调试过程
0130 硬件调试阶段，上电前使用万用表检查电源与地之间是否存在短路，确认无误后上电，测量各路电源电压是否正常，检查晶振是否正常起振，复位信号是否正常。通过示波器或逻辑分析仪观察关键信号波形，验证硬件电路的工作状态。
0131 软件调试阶段，通过串口终端查看系统启动日志，调试法定位软件问题。结合 MobaXterm 远程登录目标板，运行测试程序验证各功能模块是否达到预期效果。
0132 系统联调阶段，将软硬件进行联合调试，模拟实际工作环境进行功能测试、稳定性测试和长时间运行测试。对测试过程中出现的问题进行分析和修改，记录调试数据，直至系统满足设计要求。通过软硬件协同调试，确保整个系统运行稳定可靠。
0133 第六章 总结
0134 本文介绍了数字摄像头智能车的总体设计方案，从机械布局与架构设计、硬件系统设计和软件设计等几个部分详细介绍了我们设计小车的方案和一些创新。在基本的设计流程中，我们也进行了不断地尝试，并且取得了较理想的成果。车模的设计要综合考虑各个方面的问题和可能遇到的问题。在设计的时候要胆大心细，求实创新。
0135 在机械布局与架构方面，我们注重整车的重心分布与结构紧凑性，通过合理布置电池、主板、摄像头等部件，降低整车重心，提高高速行驶和过弯时的稳定性。在硬件系统设计中，对电源管理、电机驱动、图像采集等关键电路进行了针对性优化，保证系统在复杂工况下可靠运行。软件设计方面，采用先定位、再裁剪、后绕行的处理策略，利用NCNN部署轻量化目标检测模型，实现了对目标的实时检测与自主绕行决策。
0136 在整个设计制作过程中，我们经历了方案论证、原理图设计、PCB制作、软件编写到整车联调的全流程。调试阶段遇到了图像识别误检、电机控制响应滞后、电源干扰等问题，通过逐项排查、反复试验和软硬件协同优化，最终解决了这些问题。尤其是在模型轻量化和嵌入式推理方面，通过模型转换与量化，使板卡在有限算力下仍能保持较高的检测速度和精度，为系统实时性提供了保障。

0302 // 3×3 求逆 (伴随矩阵法); 奇异返回 false
0303 static inline bool PerspInvert(const PerspH& a, PerspH& o)
0304 {
0305 const double (*m)[3] = a.m;
0306 const double det = m[0][0] * (m[1][1]*m[2][2] - m[1][2]*m[2][1])
0307 - m[0][1] * (m[1][0]*m[2][2] - m[1][2]*m[2][0])
0308 + m[0][2] * (m[1][0]*m[2][1] - m[1][1]*m[2][0]);
0309 if (std::fabs(det) < 1e-18) return false;
0310 const double id = 1.0 / det;
0311 o.m[0][0] =  (m[1][1]*m[2][2] - m[1][2]*m[2][1]) * id;
0312 o.m[0][1] = -(m[0][1]*m[2][2] - m[0][2]*m[2][1]) * id;
0313 o.m[0][2] =  (m[0][1]*m[1][2] - m[0][2]*m[1][1]) * id;
0314 o.m[1][0] = -(m[1][0]*m[2][2] - m[1][2]*m[2][0]) * id;
0315 o.m[1][1] =  (m[0][0]*m[2][2] - m[0][2]*m[2][0]) * id;
0316 o.m[1][2] = -(m[0][0]*m[1][2] - m[0][2]*m[1][0]) * id;
0317 o.m[2][0] =  (m[1][0]*m[2][1] - m[1][1]*m[2][0]) * id;
0318 o.m[2][1] = -(m[0][0]*m[2][1] - m[0][1]*m[2][0]) * id;
0319 o.m[2][2] =  (m[0][0]*m[1][1] - m[0][1]*m[1][0]) * id;

0503 //  窗口式逆透视重采样 (推理路径专用, 不查 LUT)

0544 const int bot = (int)p10[ch] * (256 - wx) + (int)p11[ch] * wx;
0545 d[ch] = (unsigned char)((top * (256 - wy) + bot * wy) >> 16);

0577 const double off = short_e * 0.5 + crop_h * 0.5;   // 色块中心 → 裁剪框中心的距离
0578 double ccx = rcx + sx * off;
0579 double ccy = rcy + sy * off;
0580 // =====================================================================///////////////////////////////////
0581 //  ③ 反向保护: 裁剪框中心映回原图后, 必须在色块中心 *上方*
0582 bool flipped = false;
0583 {
0584 double s_rx, s_ry, s_cx, s_cy;
0585 if (PerspMapPt(H, rcx, rcy, s_rx, s_ry) &&
0586 PerspMapPt(H, ccx, ccy, s_cx, s_cy) &&
0587 s_cy > s_ry)                      // 裁剪中心在原图里更靠下 → 截反了
0588 {
0589 flipped = true;                   // 只置标志, 翻转统一在下面落地
0590 }
0591 }
0592 // ---- 调用方强制翻面 (在 ③ 之后生效) ----
0593 if (force_flip) flipped = !flipped;
0594 if (flipped) { sx = -sx; sy = -sy; }      // 注意: ③ 里没有立即改 sx,sy, 统一在此落地
0595 ccx = rcx + sx * off;
0596 ccy = rcy + sy * off;
0597 if (out_flip) *out_flip = flipped;
0598 const double hu  = (crop_w - 1) * 0.5;
0599 const double hv  = (crop_h - 1) * 0.5;
0600 // =====================================================================
0601 //  4 顶点 (IPM 绝对坐标)
0602 out_pts[0] = cv::Point2f((float)(ccx - lx*hu + sx*hv), (float)(ccy - ly*hu + sy*hv));
0603 out_pts[1] = cv::Point2f((float)(ccx + lx*hu + sx*hv), (float)(ccy + ly*hu + sy*hv));
0604 out_pts[2] = cv::Point2f((float)(ccx + lx*hu - sx*hv), (float)(ccy + ly*hu - sy*hv));
0605 out_pts[3] = cv::Point2f((float)(ccx - lx*hu - sx*hv), (float)(ccy - ly*hu - sy*hv));
0606 // =====================================================================
0607 //  ④ 越界前置判据: 4 顶点必须全部落在原图内, 且齐次分量 w 同号
0608 {
0609 const double SWm = (double)src.cols - 1.0 - (double)edge_margin;
0610 const double SHm = (double)src.rows - 1.0 - (double)edge_margin;
0611 const double lo  = (double)edge_margin;
0612 int wsign = 0;
0613 for (int k = 0; k < 4; k++) {
0614 const double w = H.m[2][0]*out_pts[k].x + H.m[2][1]*out_pts[k].y + H.m[2][2];
0615 if (w > -1e-12 && w < 1e-12) { if (out_oob) *out_oob = true; return 0.0f; }
0616 const int s = (w > 0.0) ? 1 : -1;
0617 if (wsign == 0) wsign = s;
0618 else if (s != wsign) { if (out_oob) *out_oob = true; return 0.0f; }  // 跨消失线
0619 const double X = (H.m[0][0]*out_pts[k].x + H.m[0][1]*out_pts[k].y + H.m[0][2]) / w;
0620 const double Y = (H.m[1][0]*out_pts[k].x + H.m[1][1]*out_pts[k].y + H.m[1][2]) / w;
0621 if (X < lo || Y < lo || X > SWm || Y > SHm) {
0622 if (out_oob) *out_oob = true;   // 探出视野 → 本帧不裁不推
0623 return 0.0f;                    // ★ 提前退出, 不做任何重采样
0624 }
0625 }
0626 }
0627 // ---- geom_only: 几何和越界都算完了, 到此为止 ----
0628 if (geom_only) return 1.0f;
0629 PerspH C;
0630 const double a00 = lx, a01 = -sx, a02 = ccx - lx*hu + sx*hv;
0631 const double a10 = ly, a11 = -sy, a12 = ccy - ly*hu + sy*hv;
0632 for (int r = 0; r < 3; r++) {
0633 C.m[r][0] = H.m[r][0]*a00 + H.m[r][1]*a10;
0634 C.m[r][1] = H.m[r][0]*a01 + H.m[r][1]*a11;
0635 C.m[r][2] = H.m[r][0]*a02 + H.m[r][1]*a12 + H.m[r][2];
0636 }
0637 if (dst.empty() || dst.rows != crop_h || dst.cols != crop_w || dst.type() != CV_8UC3)
0638 dst.create(crop_h, crop_w, CV_8UC3);
0639 const int SW = src.cols, SH = src.rows;
0640 const unsigned char* sp = src.ptr<unsigned char>(0);
0641 const size_t sstride = src.step;
0642 int valid = 0;
0643 for (int v = 0; v < crop_h; v++)
0644 {
0645 unsigned char* dp = dst.ptr<unsigned char>(v);
0646 const double dv = (double)v;
0647 double nx = C.m[0][1]*dv + C.m[0][2];
0648 double ny = C.m[1][1]*dv + C.m[1][2];
0649 double nw = C.m[2][1]*dv + C.m[2][2];
0650 for (int u = 0; u < crop_w; u++, nx += C.m[0][0], ny += C.m[1][0], nw += C.m[2][0])
0651 {
0652 unsigned char* d = dp + u * 3;
0653 if (nw > -1e-12 && nw < 1e-12) { d[0] = d[1] = d[2] = 0; continue; }
0654 const double fx = nx / nw, fy = ny / nw;
0655 if (fx < 0.0 || fy < 0.0 || fx > (double)(SW - 1) || fy > (double)(SH - 1)) {
0656 d[0] = d[1] = d[2] = 0; continue;
0657 }
0658 const int x0 = (int)fx, y0 = (int)fy;
0659 const int x1 = (x0 + 1 < SW) ? x0 + 1 : x0;
0660 const int y1 = (y0 + 1 < SH) ? y0 + 1 : y0;
0661 const int wx = (int)((fx - (double)x0) * 256.0);
0662 const int wy = (int)((fy - (double)y0) * 256.0);
0663 const unsigned char* p00 = sp + (size_t)y0*sstride + (size_t)x0*3;
0664 const unsigned char* p01 = sp + (size_t)y0*sstride + (size_t)x1*3;
0665 const unsigned char* p10 = sp + (size_t)y1*sstride + (size_t)x0*3;
0666 const unsigned char* p11 = sp + (size_t)y1*sstride + (size_t)x1*3;
0667 for (int ch = 0; ch < 3; ch++) {
0668 const int top = (int)p00[ch]*(256-wx) + (int)p01[ch]*wx;
0669 const int bot = (int)p10[ch]*(256-wx) + (int)p11[ch]*wx;
0670 d[ch] = (unsigned char)((top*(256-wy) + bot*wy) >> 16);
0671 }
0672 valid++;
0673 }
0674 }
0675 return (float)valid / (float)(crop_w * crop_h);
0676 }
0677 // =====================================================================
0678 //  裁剪朝向的第二道判据: 与 160 空间"向上正方形"的重合度
0679 struct IpmCropGuardInfo {
0680 float overlap_fwd  = -1.0f;   // 原朝向重合度 (<0 = 未能计算)
0681 float overlap_rev  = -1.0f;   // 翻面后重合度 (<0 = 没试/未能计算)
0682 float overlap_used = -1.0f;   // 最终采用方向的重合度
0683 bool  flip_applied = false;   // 最终朝向是否与 PickBoardSideNormal 原始选择相反
0684 bool  by_overlap   = false;   // 翻面是由本判据触发的 (区别于 ③ 反向保护)
0685 bool  both_bad     = false;   // 两个方向重合度都不达标 (轴向本身可疑)
0686 bool  sq_unavail   = false;   // 参考正方形建不出来 → 本判据整体弃权 (见 BuildUpSquare160)
0687 // ---- 像素计数 (判据的原始数据; 现场看这几个数最直观) ----
0688 //   不带 _rev 后缀的 = *最终采用方向* 的值; 带 _rev 的 = 反向那次试探的值
0689 int   px_crop_in   = 0;       // 裁剪框落在 160 画面内的像素数
0690 int   px_sq_in     = 0;       // 参考正方形落在 160 画面内的像素数
0691 int   px_int       = 0;       // 两者重合的像素数 (== 0 就是"一点都不重合")
0692 int   px_crop_in_rev = 0;
0693 int   px_sq_in_rev   = 0;
0694 int   px_int_rev     = 0;
0695 // ---- 参考正方形取源诊断 (换源前后对比用; 不参与任何判定) ----
0696 //   sq_tilt_deg / sq_side_ipm : 实际采用的源 (rr_ipm 映射回 160) 的长边倾角与长度
0697 //   sq_tilt_160 / sq_side_160 : 若仍用 160 原生 rr160 会得到的同两个量
0698 //   现场判读:
0699 //     · side_ipm 明显小于 side_160 → 160 那边被粘连拉长了 (换源正在起作用)
0700 //     · tilt_deg 显著大于 30°      → 撞上"rr_ipm 轴向翻转"这个已知代价
0701 float sq_tilt_deg  = -1.0f;
0702 float sq_side_ipm  = -1.0f;
0703 float sq_tilt_160  = -1.0f;
0704 float sq_side_160  = -1.0f;
0705 cv::Point2f sq160[4];         // 160 空间参考正方形 (ww 叠加用)
0706 cv::Point2f crop160[4];       // 最终裁剪框映回 160 (ww 叠加用)
0707 bool  pts160_valid = false;
0708 };
0709 // IPM 裁剪框 4 顶点 → 160 空间 (先用 H 映到 320, 再折半)
0710 //   任一顶点落在消失线上 → 返回 false (无法比较, 判据放弃)
0711 static inline bool IpmQuadTo160(const PerspH& H, const cv::Point2f in[4],
0712 cv::Point2f out[4])
0713 {
0714 for (int i = 0; i < 4; i++) {
0715 double sx, sy;
0716 if (!PerspMapPt(H, in[i].x, in[i].y, sx, sy)) return false;
0717 out[i] = cv::Point2f((float)(sx * 0.5), (float)(sy * 0.5));
0718 }
0719 return true;
0720 }
0721 // =====================================================================
0722 //  参考正方形 (从 IPM 色块映射回 160 构造) —— 判据的基准来源
0723 //
0724 //  【为什么不用 160 空间原生的 rr160】
0725 //    160 空间那遍检测要过三层裁剪 (4.2a 行密度断行 / 4.2b cut_ratio 距离修正 /
0726 //    4.2c 强制比例), 每层都在"削上沿"改写矩形。红条与目标板红内容粘连时长边会被
0727 //    连带拉长 —— 实测粘连使 160 空间长边偏大 55%~210%, 而参考正方形的边长 *就是*
0728 //    长边, 于是正方形整体过大, 拿它算重合度会误判。
0729 //
0730 //    IPM 二次识别侧的几何稳得多: 定值长度门 [IPM_STRIP_LEN_MIN, MAX] +
0731 //    fat-blob 底边救援 + RectForceRatio 强制比例, 三重约束且尺度已被地面归一。
0732 //    故改为: 取 IPM 里那个色块, 4 顶点用 H 映射回 160, 在 160 空间重新拟合矩形,
0733 //    再以它为基准向上截正方形。
0734 //
0735 //  【"向上"仍然是在 160 空间钉死的】
0736 //    映射完成后走的是同一个 BuildUpSquare160 —— 里面 `if (sy > 0) 取反` 把法向钉成
0737 //    指向图像上方 (y 减小)。所以方向判据没有变成"从 IPM 继承", 仍是 160 空间的
0738 //    几何事实。变的只是正方形的 *位置、尺寸、旋转角* 三项。
0739 //
0740 //  【已知代价 (换源的取舍, 记录在此备查)】
0741 //    若 rr_ipm 自身轴向翻了 90° (长边被 minAreaRect 挑成径向), 映射回 160 后长边
0742 //    方向也跟着错 —— 此时参考正方形会与裁剪框*同源同错*, 判据抓不到那一帧。
0743 //    数值实测: 轴向翻转帧映射后长边倾角 0.7~84.4°, 与正常帧 0.7~30.6° 重叠,
0744 //    无法用一道倾角门区分。倾角逼近竖直 (|sy| < BUILD_UP_SQ_SY_MIN) 的那部分会被
0745 //    BuildUpSquare160 自身的退化门拦下 → 判据弃权 (sq_unavail), 不会给错答案;
0746 //    中间那段 (倾角 30~85°) 则会静默失效。
0747 //    → 现场若看到 ov_fwd 高但橙框明显截反, 查 model_ipm_sq_tilt: 它显著大于 30°
0748 //      就是撞上了这个已知代价。
0749 //
0750 //  out_tilt_deg: 映射后长边与水平的夹角 (度, [0,90])。诊断用, 见上。
0751 // =====================================================================
0752 static inline bool BuildUpSquareFromIpm160(const PerspH& H,
0753 const cv::RotatedRect& rr_ipm,
0754 cv::Point2f out_pts[4],
0755 float* out_tilt_deg = nullptr)
0756 {
0757 if (out_tilt_deg) *out_tilt_deg = -1.0f;
0758 // IPM 色块 4 顶点 → 160 空间 (任一顶点落消失线 → 放弃)
0759 cv::Point2f ip[4]; rr_ipm.points(ip);
0760 cv::Point2f m160[4];
0761 if (!IpmQuadTo160(H, ip, m160)) return false;
0762 // 矩形的射影像是一般四边形, 用最小外接矩形拟合回 RotatedRect。
0763 //   与 photo.cpp 的 IPM_CROP_SRC==0 路径同款做法 (那边也是映射后 minAreaRect)。
0764 //   只有 4 个点, 开销可忽略。
0765 std::vector<cv::Point2f> vp(m160, m160 + 4);
0766 const cv::RotatedRect rr_m = cv::minAreaRect(vp);
0767 // 诊断: 映射后长边倾角 (用 RectMeasure 量顶点, 不读 rr_m.angle —— 后者被
0768 //   OpenCV 折进 [0,90), 长边短边可能互换)
0769 if (out_tilt_deg) {
0770 double lx, ly, le, se;
0771 if (RectMeasure(rr_m, lx, ly, le, se))
0772 *out_tilt_deg = (float)(std::atan2(std::fabs(ly), std::fabs(lx)) * 180.0 / M_PI);
0773 }
0774 // 之后与原路径逐字相同: 法向钉 sy<0, 以上沿为底向上截边长=长边的正方形
0775 return BuildUpSquare160(rr_m, out_pts);
0776 }
0777 // 返回值 / 参数语义同 PerspCropDirect, 额外:
0778 //   rr160        : 160 空间色块旋转矩形 (仅诊断对比用; 参考正方形已改由 rr_ipm 映射构造)
0779 //   overlap_min  : 重合度阈值; 实测重合度 <= 此值 → 试翻面 (默认 0 = 只在完全不重合时翻)
0780 //   gi           : 非空时输出诊断信息 (ww 面板/现场调参用)
0781 static inline float PerspCropDirectGuarded(const cv::Mat& src, const PerspH& H,
0782 const cv::RotatedRect& rr_ipm,
0783 const cv::RotatedRect& rr160,
0784 int crop_w, int crop_h,
0785 cv::Point2f out_pts[4], cv::Mat& dst,
0786 float edge_margin = 0.0f,
0787 bool* out_oob = nullptr,
0788 bool* out_flip = nullptr,
0789 float overlap_min = 0.0f,
0790 IpmCropGuardInfo* gi = nullptr)
0791 {
0792 IpmCropGuardInfo info;
0793 for (int i = 0; i < 4; i++)
0794 info.sq160[i] = info.crop160[i] = cv::Point2f(-1.0f, -1.0f);
0795 // ---- 参考正方形 (160 空间) ----
0796 cv::Point2f sq[4];
0797 const bool sq_ok = BuildUpSquareFromIpm160(H, rr_ipm, sq, &info.sq_tilt_deg);
0798 info.sq_unavail = !sq_ok;
0799 if (sq_ok) {
0800 for (int i = 0; i < 4; i++) info.sq160[i] = sq[i];
0801 // 边长 = 相邻两顶点距离 (BuildUpSquare160 的顶点序: [2][3]=底边, [0][1]=顶边)
0802 info.sq_side_ipm = (float)std::hypot((double)sq[2].x - sq[3].x,
0803 (double)sq[2].y - sq[3].y);
0804 }
0805 // 诊断: 同时量一次"若仍用 rr160 会得到什么倾角", 供现场对比换源前后的差异。
0806 //   只做测量, 不参与任何判定。
0807 {
0808 double lx0, ly0, le0, se0;
0809 if (RectMeasure(rr160, lx0, ly0, le0, se0)) {
0810 info.sq_tilt_160 = (float)(std::atan2(std::fabs(ly0), std::fabs(lx0)) * 180.0 / M_PI);
0811 info.sq_side_160 = (float)le0;
0812 }
0813 }
0814 // ---- 只算几何, 返回该朝向映回 160 后与正方形的重合度 (-1 = 算不了) ----
0815 cv::Point2f q_fwd[4], q_rev[4];
0816 bool oob_fwd = false, oob_rev = false, fl_fwd = false, fl_rev = false;
0817 cv::Mat dummy;
0818 auto measure = [&](bool force, cv::Point2f q[4], bool& oob_o, bool& fl_o) -> float {
0819 float pv = PerspCropDirect(src, H, rr_ipm, crop_w, crop_h, q, dummy,
0820 edge_margin, &oob_o, &fl_o, force, /*geom_only=*/true);
0821 if (pv <= 0.0f && !oob_o) return -1.0f;
0822 if (!sq_ok)               return -1.0f;
0823 cv::Point2f c160[4];
0824 if (!IpmQuadTo160(H, q, c160)) return -1.0f;
0825 // 数像素: 只在 160×120 画面内数, 图外部分自然不计
0826 //   → 参考正方形/裁剪框伸出画面时, 用它们"还在画面内"的那部分来比较
0827 int n_c = 0, n_s = 0;
0828 const int n_int = QuadOverlapPixels(c160, sq, IPM_GUARD_IMG_W, IPM_GUARD_IMG_H,
0829 n_c, n_s);
0830 // 记下画面内像素数 (诊断用: 一眼看出框剩多少在画面内)
0831 info.px_crop_in = n_c; info.px_sq_in = n_s; info.px_int = n_int;
0832 // 画面内剩得太少 → 判据不可信, 弃权。
0833 if (n_c < IPM_GUARD_PX_MIN || n_s < IPM_GUARD_PX_MIN) return -1.0f;
0834 return (float)n_int / (float)std::min(n_c, n_s);
0835 };
0836 info.overlap_fwd = measure(false, q_fwd, oob_fwd, fl_fwd);
0837 // ---- 正向重合度不达标 (或压根测不出) → 试另一侧 ----
0838 //   ★ 与旧版的区别: 旧版要求 overlap_fwd >= 0 才试翻面, 于是越界帧 (fwd 测不出)
0839 //     永远不翻。现在 fwd < 0 也试 —— 因为 fwd 测不出的最常见原因就是"框探出画面",
0840 //     而"截反了所以框探出画面"正是要救的情形。翻过去若能测出且达标, 就是它。
0841 const int px_c_fwd = info.px_crop_in, px_s_fwd = info.px_sq_in, px_i_fwd = info.px_int;
0842 bool use_rev = false;
0843 if (info.overlap_fwd < 0.0f || info.overlap_fwd <= overlap_min)
0844 {
0845 info.overlap_rev = measure(true, q_rev, oob_rev, fl_rev);
0846 info.px_crop_in_rev = info.px_crop_in;   // measure 内写的是"最近一次"的值
0847 info.px_sq_in_rev   = info.px_sq_in;
0848 info.px_int_rev     = info.px_int;
0849 // 恢复正向那次的诊断值 (info.px_* 语义 = 最终采用方向的, 下面按 use_rev 定)
0850 info.px_crop_in = px_c_fwd; info.px_sq_in = px_s_fwd; info.px_int = px_i_fwd;
0851 // 取重合度更大的一侧。反向测不出 (-1) 时这个比较自然不成立 → 维持正向。
0852 if (info.overlap_rev > info.overlap_fwd) {
0853 use_rev = true;
0854 info.by_overlap = true;
0855 info.px_crop_in = info.px_crop_in_rev;
0856 info.px_sq_in   = info.px_sq_in_rev;
0857 info.px_int     = info.px_int_rev;
0858 } else if (info.overlap_fwd >= 0.0f) {
0859 // 两侧都测出来了但都不达标 → 不是"选哪一侧"的问题, 轴向本身可疑
0860 //   (长边翻向 / 色块几何异常)。仍按原朝向走完, 但把 both_bad 打出来。
0861 info.both_bad = true;
0862 }
0863 // (fwd 与 rev 都测不出 → 什么都不置, 交给后面的 oob 逻辑跳过本帧)
0864 }
0865 // ---- 方向定了, 真正采样一次 ----
0866 bool oob = false, fl = false;
0867 float pv = PerspCropDirect(src, H, rr_ipm, crop_w, crop_h, out_pts, dst,
0868 edge_margin, &oob, &fl, use_rev, /*geom_only=*/false);
0869 if (out_oob)  *out_oob  = oob;
0870 if (out_flip) *out_flip = fl;
0871 info.flip_applied = fl;
0872 info.overlap_used = use_rev ? info.overlap_rev : info.overlap_fwd;
0873 if (IpmQuadTo160(H, out_pts, info.crop160)) info.pts160_valid = true;
0874 if (gi) *gi = info;
0875 return pv;
0876 }

0988 const int CVG = -852492, CVR = 1673527, SH = 20;

0991 for (int oy = 0; oy < DET_HEIGHT; oy++) {
0992 const int src_y = (UVC_HEIGHT - 2) - 2 * oy;          // 垂直翻转
0993 const uchar* srow = yuyv_320.ptr<uchar>(src_y);
0994 uchar* drow = bgr_160.ptr<uchar>(oy);
0995 for (int ox = 0; ox < DET_WIDTH; ox++) {
0996 const int src_x = (UVC_WIDTH - 2) - 2 * ox;       // 水平翻转
0997 const int base  = 2 * src_x;
0998 const int Y = srow[base];
0999 const int U = srow[base + 1];
1000 const int V = srow[base + 3];
1001 const int yy = (Y > 16 ? Y - 16 : 0) * CY;
1002 const int uu = U - 128, vv = V - 128;
1003 int b = (yy + CUB * uu + RND) >> SH;
1004 int g = (yy + CVG * vv + CUG * uu + RND) >> SH;
1005 int r = (yy + CVR * vv + RND) >> SH;
1006 drow[ox*3+0] = (uchar)(b < 0 ? 0 : (b > 255 ? 255 : b));
1007 drow[ox*3+1] = (uchar)(g < 0 ? 0 : (g > 255 ? 255 : g));
1008 drow[ox*3+2] = (uchar)(r < 0 ? 0 : (r > 255 ? 255 : r));
1009 }

1030 // ---------- 归一化旋转矩形 (与 model.cpp NormalizeRotatedRect 完全一致) ----------
1031 //   OpenCV RotatedRect 的 width/height 不一定 width 就是长边, angle 范围也不固定。
1032 //   统一成: out_long=长边, out_short=短边, out_angle∈[-45°,45°) (长边相对水平的夹角)。
1033 void NormalizeRotatedRect(const RotatedRect& rr,
1034 float& out_long, float& out_short, float& out_angle)
1035 {
1036 float w = rr.size.width, h = rr.size.height, ang = rr.angle;
1037 if (w >= h) { out_long = w; out_short = h; out_angle = ang; }
1038 else        { out_long = h; out_short = w; out_angle = ang + 90.0f; }
1039 while (out_angle >=  45.0f) out_angle -= 90.0f;
1040 while (out_angle <  -45.0f) out_angle += 90.0f;
1041 }
1042 // ---------- 边界裁剪 (与 model.cpp ClampRect 一致) ----------
1043 bool ClampRect(Rect& r, int W, int H) {
1044 if (r.width <= 0 || r.height <= 0) return false;
1045 if (r.x < 0) { r.width  += r.x; r.x = 0; }
1046 if (r.y < 0) { r.height += r.y; r.y = 0; }
1047 if (r.x + r.width  > W) r.width  = W - r.x;
1048 if (r.y + r.height > H) r.height = H - r.y;
1049 return (r.width > 0 && r.height > 0);
1050 }
1051 // ---------- 旋转裁剪 (与 model.cpp MakeCropPatch 几何完全一致) ----------
1052 //   动态裁剪框: crop_w/crop_h 由调用方按色块行号查表得到 (320 空间, 默认36×20, 不再×2)。
1053 //   裁出的任意长宽矩形返回后, 由调用方统一 resize 成 MODEL_INPUT_SIZE 方形。
1054 //   几何约定 (与跑车 model.cpp 逐像素一致, 不可改):
1055 //     CROP_W 沿色块长边方向, CROP_H 沿短边法向 (指向目标板, 即图像上方 sy<0)
1056 Mat MakeCropPatch(const Mat& bgr, const RotatedRect& rr,
1057 float short_edge, float ang_norm,
1058 int crop_w, int crop_h,
1059 Point2f out_pts[4])
1060 {
1061 const int CROP_W = (crop_w > 0) ? crop_w : MODEL_INPUT_SIZE;
1062 const int CROP_H = (crop_h > 0) ? crop_h : MODEL_INPUT_SIZE;
1063 const int W = bgr.cols, H = bgr.rows;
1064 float theta = ang_norm * (float)CV_PI / 180.0f;
1065 float lx = cosf(theta), ly = sinf(theta);      // 长边方向单位向量
1066 float sx = -ly,         sy = lx;               // 短边法向 (逆时针90°)
1067 if (sy > 0) { sx = -sx; sy = -sy; }            // 保证 sy<0 (指向图像上方)
1068 float half_s = short_edge * 0.5f;
1069 float cx = rr.center.x + sx * (half_s + CROP_H * 0.5f);
1070 float cy = rr.center.y + sy * (half_s + CROP_H * 0.5f);
1071 float hw = CROP_W * 0.5f, hh = CROP_H * 0.5f;
1072 out_pts[0] = Point2f(cx - lx*hw - sx*hh, cy - ly*hw - sy*hh);
1073 out_pts[1] = Point2f(cx + lx*hw - sx*hh, cy + ly*hw - sy*hh);
1074 out_pts[2] = Point2f(cx + lx*hw + sx*hh, cy + ly*hw + sy*hh);
1075 out_pts[3] = Point2f(cx - lx*hw + sx*hh, cy - ly*hw + sy*hh);
1076 if (fabsf(ang_norm) < 10.0f) {
1077 // 小角度快速路径: 直接 ROI, 不做仿射变换
1078 Rect r((int)round(cx - hw), (int)round(cy - hh), CROP_W, CROP_H);
1079 if (!ClampRect(r, W, H)) return Mat();
1080 Mat roi = bgr(r);
1081 if (roi.cols == CROP_W && roi.rows == CROP_H) return roi.clone();
1082 Mat out; resize(roi, out, Size(CROP_W, CROP_H)); return out;
1083 }
1084 // 大角度: warpAffine 反旋转, 让目标板正过来
1085 Mat M = getRotationMatrix2D(Point2f(cx, cy), ang_norm, 1.0);
1086 M.at<double>(0,2) += CROP_W * 0.5 - cx;
1087 M.at<double>(1,2) += CROP_H * 0.5 - cy;
1088 Mat out;
1089 warpAffine(bgr, out, M, Size(CROP_W, CROP_H), INTER_LINEAR, BORDER_REPLICATE);
1090 return out;
1091 }
