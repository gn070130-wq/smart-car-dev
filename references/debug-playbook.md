# 调试、日志与回放

## 建立可证伪的假设

从用户现象、失败位置、速度、目标类别、光照、电量、温度和最近改动入手。先复现或读取工程已有记录；没有日志时给出最少必要观测点，并继续检查不依赖实车的代码。不要要求用户一次上传全套材料才开始。

| 现象 | 分层排查路径 |
|---|---|
| 原图正常但小车偏 | 边界/中线→前瞻误差符号→轮速目标→实测速度→执行方向 |
| 直道蛇行 | 中线是否抖→图像年龄→方向目标是否抖→角速度是否跟随→PWM是否饱和 |
| 弯道外切 | 远端是否可见→参考线是否正确→减速时机→轮速饱和/打滑→内外环响应 |
| 环岛误入/提前出 | 角点与丢边→状态进入条件→IMU积分→里程→边界恢复确认 |
| 目标分类错 | 红色候选→ROI是否完整→训练预处理→标签顺序→模型输出→时间确认 |
| 类别正确仍撞板 | 检测/确认距离→路径坐标→所有轮迹→控制饱和→恢复时机 |
| 同一目标绕两次 | 事件ID、锁定重置、目标短漏检、冷却与重新布防 |
| PC准但板端不准 | 用同一ROI比较解码、BGR/RGB、归一化、算子、精度和输出解释 |
| 推理时卡顿 | 捕获队列、旧帧积压、重复分配、日志/图传阻塞、CPU与内环抢占 |
| 开风扇后异常 | 母线/逻辑电源、EMI、振动与曝光、CPU/接口错误；不先归咎PID |

## 最小有效日志

沿用现有日志格式；新增时可参考 `assets/telemetry-columns.csv`。每行代表什么任务的一次记录需先说明。CSV工具识别以下可选列：

| 列 | 约定 |
|---|---|
| `timestamp_ms` | 必填，单调时钟，当前记录时刻，毫秒 |
| `vision_timestamp_ms` | 可选，同一时钟域的视觉捕获时刻，毫秒 |
| `frame_id` | 可选，当前使用的视觉帧号，重复帧在高频控制中可能正常 |
| `state` | 可选，状态/模式，工具统计相邻记录变化次数 |
| `lateral_error` | 可选，当前路径误差；单位由项目声明 |
| `left_target_mps/right_target_mps` | 可选，左右轮目标线速度m/s |
| `left_speed_mps/right_speed_mps` | 可选，对应实测线速度m/s |
| `left_pwm/right_pwm` | 可选，PWM数值，其单位与 `--pwm-limit` 一致 |

实际调试还可记录 `yaw_target_rps/yaw_rps`、轮速/角速度任务执行时间、目标事件号、类别/置信度、ROI位置、保护原因、积分量、供电电压与温度。不要为日志阻塞控制线程；保存高频数据和低频显示可以采用不同路径。

视觉年龄最好从捕获算到控制消费，不能只从推理结束算。跨板时钟先同步或使用本地接收年龄，不直接相减。

```text
python "<skill>/scripts/analyze_telemetry.py" "run.csv" --expected-period-ms 5 --pwm-limit 4000
```

输出记录间隔的min/均值/p50/p95/p99/max、相对期望周期的间隔统计、时间逆序/重复计数、视觉年龄、误差RMS、左右目标跟随误差和命中已声明PWM限幅的比例。分位数用于描述这份日志，不能证明实时调度最坏界限。记录时间不是控制周期开始时间时，不用这些间隔判定内环周期。

缺失列或空值会报告可用样本数，跳过相应指标；非数值、NaN、Inf等无效数据不会被填零。若时钟逆序/重复或年龄为负，先检查时间基准，不能继续把错误统计解读为性能提升。

## 把调试分成可以定位的实验

视觉问题：同一失败帧对照原图、阈值图、边线、中线与ROI，比较调整前后的正确性和耗时。
分类问题：固定一组现场ROI，分别运行PC和板端预处理/推理，保留原始输出与标签。
控制问题：确认参考路径稳定后，对单环目标和反馈比较；不要在路径一直跳变时盲目加大内环增益。
状态机问题：用记录的观测序列回放进入/退出/超时/复位，重点覆盖短漏检、重复消息和目标离开视野但未通过。
通信问题：检查丢包、延迟、乱序、重传、对端重启与事件绑定，验证恢复路径。

报告里“单帧耗时”“相机90/120fps”“实时控制1/2/5ms”分别记录。端到端年龄、吞吐量和控制抖动至少区分，不把一次最佳耗时作为稳定运行能力。

## 给用户的结果

先说明故障定位及证据，再说明修改和验证。若证据只排除了部分原因，用“支持/不支持某假设”，不宣称根因已证实。调参建议写明条件、观测量和回退标准，不要求无关重构或重复已完成的验证。
