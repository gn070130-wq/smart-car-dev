# 真实算法与数据流

所有文件位置以manifest中的固定提交为准；行号可用符号索引核查。以下为代码静态阅读所得，速度、鲁棒性和实车效果未独立测量。

## 1 采集和映射

`camera.cpp::get_mmap_image`（L1163起）使用V4L2 DQBUF/QBUF，先把原始帧复制到固定 `g_yuyv` 缓冲。固定地址用于维持预计算映射表中像素指针的有效性，重构成每帧clone/换内存时必须重做表或改为偏移索引。

- 跑车主循环调用 `get_mmap_image(1)`：提取Y灰度、标准Otsu、二值化。模式4/5提供亮度减色度惩罚的白色得分，但主循环当前没有选择它，不能说当前跑车必用该算法。
- 彩色映射初始化前调用模式3。`ImagePerspective1_Color_Init`处理相机内参与畸变；`ImagePerspective2/3_Color_Init`继续处理IPM。映射结果保留YUYV宏像素位置及奇偶标记，避免每帧整图转BGR。
- `_big`查表尺寸是基础320×240网格的两倍，即640×480坐标网格；它映射回原图，不等于相机额外获得更多真实像素。
- 颜色由YUYV读取，共享U/V，按偶/奇像素选Y；ROI阶段才做BGR转换。处理时必须沿用相同色彩范围约定。

重构关注：指针表生命周期、空映射、帧宽高、bytesperline/bytesused、缓冲长度及相机配置变化。当前拷贝按 `width*height*2`，不能无条件用于带额外stride或其他格式的设备。

## 2 边界到中线

主循环顺序：

```text
line_init
→ find_edge_line
→ filter_lines(左右)
→ resample_track_line(左右, spacing=5)
→ 左右角点 / find_circle / patch_line
→ chose_line / chose_line_width
→ find_mid_line_from_left / right
→ resample_track_line(两条候选中线, spacing=5)
```

`line_init`在图像近端第239行搜索最长连续白段作为边界起点，并在绕行/丢路时限制搜索范围。这是“横向白段”，不要写成垂直最长白列。

`find_edge_line`交替调用 `line_grow_left/right` 沿边界推进，记录逐行宽度；左右相遇、达到图像边界、步数/误差约束时停止。输出用于后续平滑、重采样和角点判别。

`resample_track_line`将点列按弧长插值成近似等距点。多处 `lenth` 存储最远有效下标，不总是点数量：函数显式以 `lenth+1` 读取点数，空线可能设为-1。重构不能统一把它当 `vector.size()` 而忽略原来的下标语义。

法线中线：用边界点i±4估计切向，转90度并归一化，平移 `width` 生成候选中心；左右各有一条。`chose_line`依元素选参考边，`chose_line_width`改偏移宽度实现避让。当前代码有正常约50、绕行-20/120等像素数，属于本项目映射尺度，不是米制路宽或通用常量。

十字/环岛通过角点、补线、参考边、`circle_save`和保持/冷却协同。阅读每个case和调用位置，不把魔数状态直接映射成别队的六阶段编号。

## 3 前瞻到差速

`find_curve_from_left/right`根据 `far_num*speed_true/mid_speed` 选前瞻点，并受有效路径约束；几何计算返回相对预瞄的角度。`find_curve_all`根据普通路、丢边、绕行、坡道等选择双边融合或单边结果；将路径误差按 `speed_true/250` 缩放，再经 `gp_true` 得到 `expect_gyro`。

`control.cpp::error_compute`读取Z轴原始IMU值，计算 `(imu_gyro_z-expect_gyro)/100`，以 `kp/kd` 得到差速量。`main_run`分配 `left=expect_speed-dif`、`right=expect_speed+dif`。它是项目标定尺度下的“路径误差→目标原始角速度→差速”，不能直接解释为所有变量都是rad/s、m/s。

`get_expect_speed`依据路径末端切线延伸可见性、目标/绕行、坡道、环岛和有效长度选择速度档；启动阶段逐帧渐增。该函数虽然带 `Error` 参数，当前实现主要读全局路径/状态，不应只依参数名推断纯误差限速。

`pit_callback_speed`读取左右编码器，右侧取反，计算平均 `speed_true`，调用 `speed_control`。轮速控制用增量PID，累计输出并钳位到项目范围，最后依据符号写方向GPIO与PWM。`wp/wi/wd`没有显式dt，包含原工程离散周期尺度；调周期必须重新核对增益语义。

`kalman_filter_int`存在，但该跑车回调没有调用它；四元数更新在视觉主循环相应位置被注释。不要把备用函数写成已启用传感器融合。

## 4 目标精定位与ROI

当前跑车调用 `find_barrier_accurate`，不是旧版 `find_barrier`：

1. 沿未受圆环选边影响的候选中线找红色种子，HSV的H使用0—360度表达，S/V是相应浮点尺度；不要套OpenCV常见0—179阈值。
2. 由中线局部前向建立纵横方向，在局部区域缓存红色判定，寻找近侧边缘候选，要求连续红色像素支持。
3. 用确定性的间隔点对产生RANSAC式假设，依据方向、内点、跨度等选近侧长边，再对最佳内点 `fitLine` 精修。它不是随机抽样循环，也不是简单外接矩形。
4. 用近侧长边中点与朝远端的法线估计卡片中心；记录 `angle_barrier_save`，按屏幕上方为0、顺时针为正。
5. 在双倍坐标网格调用 `cut_image(y*2,x*2,75)`，按离散旋转表取75×75ROI并转BGR，空采样用灰色填充。
6. 在位置、完整度和状态条件满足时调用 `model_identify(square)`，返回类别编号。

75×75是该调用的几何裁剪尺寸，模型输入尺寸随后按JSON再次resize，不能因此声称实际部署网络一定是75×75输入。采样表固定75×75，若推广 `cut_image(length)` 必须同步检查表尺寸。

## 5 模型与任务语义

`model_load`从 `/home/root/models/<name>/<name>.json` 读取输入、输出、归一化和标签，加载同目录param/bin。`model_identify`持模型互斥锁，缩放、归一化、前向、校验输出维数，直接argmax；当前没有统一补Softmax或阈值拒识。

配置给了三类TinyRoadsign和六类ShuffleNetV2 0.5x示例，但主程序写死加载 `75ttv1`。当前提交没有提供这一配置和对应权重，也没有这两个示例的param/bin，不能由JSON名字重建网络结构或宣称整车可直接运行。

六类配置顺序：0枪、1爆炸物、2急救包、3望远镜、4装甲车、5救护车。跑车绕行逻辑以0/1左、2/3右、4/5直行处理，未通过配置 `action_names`统一转换。三类配置即使推理成功，原动作分支也不会自动适配它。

代码注释写BGR→RGB，但实际调用 `ncnn::Mat::PIXEL_BGR`；学习时以实际枚举和训练预处理共同核对，不能引用注释就宣称已经转换RGB。输出是否已归一化需要param/训练配置确认，`conf`命名不是概率校准证据。

## 6 绕行生命周期与进度

`barrier_save`负值表示搜索/候选/恢复等内部阶段，0—5代表锁定类别。`find_barrier_accurate`对0—5直接维持当前类别；本次阅读未在实际分类入口看到连续多帧投票或 `conf` 阈值门控，不能借用其他报告的确认机制描述它。

分类影响选边、法线偏移宽度、速度与保持量。`main_run`在保持量用完后把0—5转为-4恢复，再退出；4/5采用短保持和冷却。斜向目标还改变保持量，反映了几何姿态对绕行持续距离的修正思路。

重要尺度：`barrier_hold_way`及部分圆环计数每个视觉循环减 `speed_true/10`；砖、坡道、斑马线等另有按帧减/加的计数。前者并未乘实际视觉dt，也没有在5ms轮速线程积分，不能视作严格的物理里程计。移植到不同帧率或异步推理时需重建时间/距离语义。

## 7 保护和学习边界

丢路保护结合边界失败、近端白像素数与绕行状态；绕行中的部分条件会豁免普通丢路判定。斑马线累计圈数后延迟停车。退出路径清理定时器、方向GPIO、轮PWM和风扇。

这些是值得复用的局部机制，仍需结合下一份参考中的具体缺项及并发问题。不要复制大量全局变量与魔数后声称完成了可维护的重构。
