第一章 引言
全国大学生智能汽车竞赛是由教育部高等学校自动化类专业教学指导委员会与中国自动化学会联合主办的全国性学科竞赛，自创办以来已成功举办二十届。该竞赛以“立足培养、重在参与、鼓励探索、追求卓越”为指导思想，要求参赛队伍设计制作能够在特定赛道上自主行驶并具有优越性能的智能模型汽车，综合运用机械设计、电子线路、自动控制、计算机编程等多学科知识，完成具备环境感知、决策规划和运动控制能力的智能系统开发。竞赛连续多年位列全国高校学科竞赛排行榜前列，已成为国内智能科技领域最具代表性的大学生竞赛之一。
第二十一届全国大学生智能汽车竞赛共设11个竞速组别，按赛道类型分为缩微赛道、室内赛道和室外赛道三大类。其中，缩微赛道包括飞檐走壁、疯狂电路、蚂蚁搬家三个组别。疯狂电路组作为本届竞赛缩微赛道的重要组成部分，要求参赛队伍制作缩微轻量车模，利用光电传感器或摄像头传感器引导车模，在电路图赛道上运行，通过电路中所有的电路回路。赛道以电路导线为循迹路线，车模运行轨迹为电路示意图，其中包括若干节点和回路，节点之间的引线作为车模行进引导线，节点支路上存在若干电子元器件作为车模识别赛道的干扰图案。
与往届竞赛相比，疯狂电路组的赛题设置具有显著特点。首先，比赛采用分科目模式，从串联网络（科目一）到串并联网络（科目二），再到包含串联、并联、反馈等多种回路的复杂网络（科目三），电路复杂度从简单到复杂逐步过渡。其次，比赛成绩与车模重量密切相关，重量越轻越有利于提升操控响应速度和优化动态性能，这要求小车在极致的轻量化与强劲的性能之间寻求最佳平衡。第三，赛道紧凑且设有锥筒，对车模小型化设计及导航精度均提出了较高要求。在场地规格方面，疯狂电路组预赛场地为2.5m×2.5m，赛道长度约17米；决赛场地扩容至2.5m×4m，赛道长度增至约27米。决赛额外增加大量电路支路，对路径规划与元器件识别能力提出了更高要求。
此外，疯狂电路组还设置了盲盒任务环节。盲盒任务分为硬件盲盒与软件盲盒两类：硬件盲盒要求选手随机抽取实操题目、限时完成电路搭建调试；软件盲盒则要求队伍现场应对未知任务变更。盲盒任务的存在使得比赛不仅考验参赛队伍的日常技术储备，更考验临场应变与快速解决问题的能力。
面对上述赛题挑战，本队制定了明确的技术方案：在传感器方案上采用摄像头感知方案；在控制算法上围绕赛道识别与路径规划核心任务展开；在机械结构上以轻量化为导向进行车模设计与改造；在电路设计上力求紧凑可靠。本报告将从机械结构、电路系统、控制软件、开发调试等方面对本队的工作进行系统阐述。
本报告共分为八章。第二章介绍系统总体设计方案；第三章阐述机械结构集成与安装改造；第四章说明电路系统设计；第五章介绍控制软件设计；第六章描述开发工具与调试过程；第七章给出模型车主要技术参数；第八章进行总结与展望。附录部分附有电路板详细设计原理图与核心算法子程序。

第二章  系统总体设计方案
2.1 模型车设计制作主要思路
本队针对第二十一届全国大学生智能汽车竞赛疯狂电路组的赛题特点，确立了“轻量化为先、感知与控制在精度与速度之间寻求最优平衡”的总体设计理念。
疯狂电路组要求制作缩微轻量车模，利用光电传感器或摄像头传感器引导车模在电路图赛道上运行，尽量通过电路中所有电路回路。预赛场地为2.5m×2.5m、赛道约17米，决赛场地扩容至2.5m×4m、赛道拉长至27米，决赛额外增加大量电路支路。赛道以电路导线为循迹路线，引导线宽度为20mm±5mm，节点支路上存在若干电子元器件作为赛道识别的干扰图案。上述赛题特征对本队的设计提出了三方面核心要求：第一，车模重量与成绩强相关，需要在极致的轻量化与强劲的性能之间寻求最佳平衡；第二，赛道紧凑且设有锥筒，对车模小型化设计及导航精度均提出较高要求；第三，决赛赛道复杂度和元器件数量大幅增加，考验路径规划能力。
基于上述分析，本队从车模平台、传感器方案、控制策略和电路系统四个维度确立了以下设计思路。
（1）车模平台：轻量化与结构紧凑并重。 根据牛顿第二定律、惯性和离心力等理论，重量越轻，物体在受力时运动状态就越容易改变，合理的重量优化是提升车速上限的正向赋能。本队选用基于“N30pro”车模平台的缩微四轮有刷车模作为基础平台，在保留车模基础机械结构的前提下，通过精简非必要结构件、优化电路板布局、合理规划线束走线等方式进行轻量化改造，力求将整车质量控制在较低水平。同时，针对赛道紧凑、存在锥筒的特点，对车模外形尺寸进行小型化设计，确保车模在复杂电路回路中具备良好的通过性。
（2）传感器方案：摄像头感知。 疯狂电路组允许采用光电传感器或摄像头传感器引导车模。本队采用摄像头感知方案。摄像头负责赛道引导线的全局识别与路径规划，能够获取赛道拓扑结构的全局信息，为复杂电路回路中的路径决策提供依据，此外，规则并未限制摄像头必须是彩色或灰度，本队根据实际图像处理需求选择适配的摄像头型号（MT9V034）。
（3）控制策略：分层决策与实时响应相结合。 针对疯狂电路组赛道包含若干节点和回路的电路拓扑结构，本队采用分层控制策略。上层基于摄像头采集的赛道图像进行电路拓扑识别，判断当前所处的回路位置与可选的路径分支，完成全局路径规划。采用PID控制算法对舵机和驱动电机进行闭环控制，确保车模精确跟随引导线行驶。上下层之间通过中断机制实现信息交互，在保证路径规划合理性的同时确保控制的实时性。
（4）电路系统：集成化与抗干扰并重。 为配合轻量化目标，本队将主控电路、传感器接口电路、电机驱动电路、电源管理电路等进行轻量化设计，尽量减少电路板数量与板间连接器数量，降低整体重量。同时，针对赛道环境复杂、电机驱动可能产生干扰等问题，在电路设计中充分考虑电源隔离、信号滤波与去耦等措施，保障系统稳定运行。
综上，本队的设计思路可以概括为：以轻量化车模平台为基础，以摄像头感知为核心，以分层决策与实时控制为策略，以集成化抗干扰电路为保障，四者有机结合，共同构成满足疯狂电路组赛题要求的完整智能车系统。
2.2 实现技术方案概要
本方案实现了一套基于英飞凌 TC264D 双核 MCU 的智能车循迹与定点转向控制系统。整体思路是充分发挥双核优势，把"看"和"控制"分到两个核并行处理：CPU1 专门负责视觉，用 MT9V03X 灰度摄像头连续采集赛道图像，通过 DMA 直接搬进本地 DSRAM，然后跑 OTSU 自适应阈值做二值化，再从中提取出赛道中线位置；CPU0 则专注控制，拿到中线偏差后做差速巡线，同时管理转向状态机，在路口处借助 IMU660RB 陀螺仪完成定点转向，两个核通过一个帧完成标志做跨核同步，避免读到半帧数据。
视觉处理的核心思路是"前瞻"与"平滑"。摄像头每一帧先做 OTSU 自适应阈值分割，把赛道白线从背景里抠出来，再对每一行扫描左右边缘，取边缘中点作为该行中线。为了抗噪，一方面要求左右边缘同时存在才计入，另一方面对相邻行的中线跳变做限幅抑制。最关键的是中线加权时采用"远重近轻"的权重分布——图像顶部（远处）权重大、底部（近处）权重小，这样相当于让车"看得远、提前预判"，而不是只盯着脚下反应，从而在长直道上走得更稳、不容易左右摆动；最后再用指数平滑对中线做一阶滤波，进一步滤除抖动，输出一个稳定的中线位置给控制用。
巡线控制的思路是"单级纯 P 差速"。把图像中心（75）作为目标，用实测中线与它的偏差乘上一个比例系数，得到左右轮的差速修正量，再叠加到基础速度上：偏左就右轮快左轮慢、偏右则相反，底层再靠左右轮各自的速度 PID 闭环把目标速度转成 PWM 驱动电机。这里刻意不引入积分项，只用纯 P，是为了避免长直道上积分慢慢累积导致车身"越纠越偏、来回画蛇"的振荡；配合前面的前瞻加权，用较低的增益就能平稳地贴线行驶。基础速度用一个运行时可变的量，这样转弯前或预判窗口里可以临时降速，转弯完再恢复。
转向部分采用"预设任务规划表 + 状态机 + 串级 PID 定点转"的思路。整条赛道的走法被提前编成一张表，用数字表示每一步动作：2/3 是左/右转 90 度、纯数字表示直行多远的编码器脉冲、1 表示速度切换标记。车在直道上行驶时，只盯着"当前该遇到什么路口"去扫描图像边缘——左转就看左边两列有没有白色缺口、右转就看右边，检测到入口后进入转向状态机，先短暂接近，再执行转向。转向不靠盲开，而是用陀螺仪做双环串级闭环：外环角度环把"目标航向与实际航向的差"换算成期望角速度，内环角速度环再用实测角速度去逼近这个期望值，输出左右轮反向差速，让车原地转到目标角度；转向完成的判据是航向误差连续若干个周期都落在允许误差内，说明车身已经稳定到位，再切回直行。内轮在转向过程中只刹停不反转，避免打滑失控。
整个系统从启动到停机也有保护逻辑：上电后先用占空比斜坡缓慢加速，防止起步冲击；跑完规划表后逐渐降低占空比直至停车并关闭定时中断。总体上，这套方案把"看得稳、纠得缓、转得准"作为设计主线，用双核并行和分级 PID 来平衡实时性与控制精度。
第三章 机械结构集成与安装改造
本队选用逐飞科技推出的第21届缩微组N30Pro有刷四轮车模套件作为基础平台。该车模严格对齐第21届智能车竞赛缩微组别规则，是专为飞檐走壁组和疯狂电路组设计的竞赛车模。
3.1 成品车模选型与基础参数
整车质量：车模本体重量约46.7g。该重量级别在同类缩微车模中处于领先水平，有效降低了车模的转动惯量，提升了加速响应与制动性能。
动力系统：搭载高转速N30有刷电机进行动力输出，采用四轮独立驱动方案。有刷电机具有驱动简单方便、控制响应直接的特点。四轮轮毂电机方案实现了零传动损耗的直驱响应，消除了传统传动机构带来的能量损失与响应延迟。
底盘结构：底板采用轻量化碳纤维材质，在保证结构刚度的前提下大幅降低了整车质量。碳纤维材料的高比强度和抗疲劳特性，使车模在高速过弯和激烈驾驶条件下依然保持良好的结构稳定性。
该车模平台的适应性体现在以下方面：碳纤维底板为电路板和传感器支架提供了充足的安装空间与固定孔位；模块化的支架设计方便用户根据实际需求进行结构调整；四轮独立驱动的动力架构为差速转向和速度控制提供了灵活的硬件基础；轻量化的本体质量则为极致减重留下了充分的操作空间。
3.2 机械部分适配与改造
在N30Pro成品车模基础上，本队针对疯狂电路组的赛题特点进行了以下适配性改造：加装支架的设计与制作。 为安装摄像头和电路板，本队基于车模进行二次开发，设计并制作了专用的传感器支架。摄像头支架采用轻量化设计思路，通过合理的结构布局在保证刚性的前提下精确移除冗余材料。
3.3 传感器的设计安装
摄像头的安装。 摄像头安装于车模前部居中位置，通过打印件固定于碳纤维底板上。安装高度经反复测试确定为距离赛道平面适当高度，确保摄像头视野能够完整覆盖车模前方赛道区域。摄像头俯仰角度通过支架上的可调结构进行精确调节，使引导线在图像中处于合适的位置。
摄像头支架的固定采用螺栓连接为主、热熔胶加固为辅的双重固定策略。具体而言：支架底部打印件与碳纤维底板上的预留孔位进行刚性连接，确保支架在高速运行和剧烈震动条件下不发生整体位移。打印件与碳杆通过螺栓进行刚性连接，在螺栓紧固的基础上，在接触面的缝隙处以及螺栓头部点涂适量热熔胶，利用热熔胶固化后的填充与粘接作用进一步限制支架的微小颤动。热熔胶本身具有一定的弹性和阻尼特性，能够吸收高频震动能量，对摄像头的图像稳定性起到了积极作用。这种双重固定方式兼顾了连接的可靠性与抗振性，经赛道实测验证，在长时间连续运行后摄像头安装参数未发生可察觉的漂移。
3.4 系统电路板的固定以及连接
本队的电路系统由主控板、驱动板两块电路板组成。主控板通过打印件以及螺栓固定在车模上，驱动板通过轧带固定到车模上。电路板背面均贴满电工胶，保护了pcb以及焊点的可靠性，打印件可以根据电路板的实际尺寸和空位进行定制，无需二次修改电路板，安装精度高，而且打印件自身轻便，可以保证强度的前提下进一步降低重量。
N30Pro采用四轮独立有刷电机驱动方案，相较于传统单电机+传动机构方案，动力线束数量有所增加。全车线束按照功能分区进行规划：四路电机电源线采用适当线径，满足各轮驱动电机的大电流需求；信号线采用细径柔软导线，减少线束整体重量和弯折阻力。各线束沿车模底盘和上方走线，避免线束在运行过程中与车轮等运动部件发生干涉。
为了降低车的中心，板子中间采用了镂空，安装时将负压电机安装在此位置，可以降低板子的高度，从而降低车的中心，保证车在巡线时不会因为重心偏高而发生倾倒。

第四章 电路系统设计
电路系统是智能车硬件平台的核心组成部分，承担着信号采集、数据处理、功率驱动和能量管理等多重任务。疯狂电路组的赛题设置对电路设计提出了特殊要求：一方面，缩微车模的空间极为有限，要求电路板布局紧凑、高度集成；另一方面，四轮独立驱动的N30Pro车模需要四路电机驱动电路，对功率驱动部分的体积和散热提出了更高要求。基于上述考量，本队在电路设计中以“紧凑集成、稳定可靠、低功耗”为原则，构建了完整的多模块电路系统。
4.1 电路总体方案概述

4.3 电机驱动电路
N30Pro车模采用四轮独立有刷电机驱动方案，每个车轮由独立的N30有刷电机驱动。同时，为提升高速过弯时的抓地力与稳定性，本队在车模底部加装有刷负压风扇，通过产生向下吸附力抑制侧滑和甩尾。基于上述需求，本队设计了三路独立的H桥有刷电机驱动电路，其中两路用于驱动车轮电机，一路用于驱动有刷负压风扇。
（1）控制方案说明。 三路PWM信号的分配如下：第一路PWM控制左前轮电机，实现独立调速，与右前轮配合实现差速转向；第二路PWM控制右前轮电机，实现独立调速，与左前轮配合实现差速转向；第三路PWM控制有刷负压风扇，实现独立调速，调节风扇转速以控制下压力大小。。通过两路车轮PWM的占空比差异化分配，可实现车模的直行加速、减速制动以及差速转向：直行时两路占空比一致，转向时内外侧车轮依据转弯半径分配不同占空比，从而实现灵活的转向控制。第三路PWM独立调节负压风扇转速。
（2）驱动方案选型。 有刷电机的驱动需要实现正反转控制和PWM调速功能。本队选用德州仪器（TI）的DRV8701全桥栅极驱动器作为核心驱动芯片。DRV8701是一款采用4个外部N通道MOSFET的单路H桥栅极驱动器，主要用于驱动12V至24V双向有刷直流电机。该芯片具有宽工作电压范围（5.9V至45V），可充分适应12V锂电池供电环境；支持100% PWM占空比，可实现电机全速运行；具备可调节的栅极驱动电流（拉电流6mA至150mA、灌电流12.5mA至300mA），通过IDRIVE引脚上的单个外部电阻即可配置；支持PH/EN（DRV8701E）或PWM（DRV8701P）两种控制接口方式，方便与MCU连接；内置20V/V分流放大器，可实现可调节的电流控制；集成固定关断时间的PWM电流斩波调节功能，可限制电机启动时的浪涌电流；内置AVDD（4.8V，30mA）和DVDD（3.3V，30mA）双LDO稳压器，可为外部元器件供电；具备低功耗睡眠模式，静态电流仅9μA，通过将nSLEEP引脚置低即可进入；集成欠压闭锁（UVLO）、电荷泵欠压（CPUV）、过流保护（OCP）、前置驱动器故障（PDF）和热关断（TSD）等完善的保护功能，故障状态通过nFAULT引脚指示；采用24引脚VQFN超小封装，尺寸仅4.0mm×4.0mm×0.9mm，非常适合缩微车模的紧凑空间需求。
DRV8701作为栅极驱动器（预驱动器），需要搭配4个外部N沟道功率MOSFET组成完整的H桥。本队选用低导通电阻的N沟道MOSFET（如TPH1R403NL或同类产品），确保在大电流工况下功率损耗和发热量均在可控范围内。该方案在智能车竞赛中已有成熟应用，实测12V/10A工况下运行正常且发热很小。
（3）单路驱动电路设计。 每路DRV8701驱动电路由控制接口、功率级、电荷泵电路、电流检测、IDRIVE配置、保护与指示以及输出滤波等部分组成。控制接口方面，TC264输出的PWM信号和方向控制信号接入DRV8701，三路PWM输出引脚分别连接至各芯片对应控制引脚。芯片支持1.8V、3.3V和5V逻辑输入，可直接与TC264的3.3V电平对接，无需电平转换。功率级由4个外部N沟道MOSFET构成完整H桥，DRV8701以9.5V VGS栅极驱动电压来驱动高侧和低侧FET，确保功率MOSFET完全导通，芯片内部强制插入380ns死区时间，防止同一桥臂上下管同时导通造成直通短路。电荷泵电路方面，在VM与VCP之间连接16V/1μF陶瓷电容，在CPH与CPL之间连接0.1μF X7R电容，为高侧N沟道MOSFET提供栅极驱动电压。电流检测方面，在低侧FET源极与地之间接入检测电阻（SNS引脚），配合内置的20V/V分流放大器实现电流检测，可用于过流保护和电流闭环控制。IDRIVE配置方面，在IDRIVE引脚上连接单个外部电阻，配置栅极驱动电流等级，根据所选MOSFET的栅极电荷特性选择适当的驱动强度。
（4）三路驱动的整体布局。 三路DRV8701驱动电路集中布置在同一区域，共用VM电源输入和地线，但每路驱动的控制信号和输出通道相互独立。功率地线与信号地线采用单点接地方式分开布线，避免大电流回路对信号回路产生干扰。VM输入端并联大容量电解电容（如100μF~220μF），为三路负载（两路车轮电机加一路负压风扇）同时启动时的瞬时大电流提供能量缓冲。DRV8701底部设有散热焊盘，PCB设计时应保证该焊盘与地平面良好焊接，并布置足够的散热过孔以增强散热能力。

4.4 电源管理电路
电源管理电路是整个系统稳定运行的基础。本队采用12V（3S）锂电池供电，通过多级电压转换电路为各模块提供稳定电源。
锂电池（3S，11.1V）接入系统后，首先经电源输入保护电路，然后分流至各电压转换模块。电源分配方案如下：电池电压（11.1V~12.6V）直通至电机驱动电路，充分利用3S电池的高压优势为电机提供强劲动力；电池电压经DC-DC降压电路转换为5.0V，为串口、核心板等供电。5.0V再经LDO线性稳压器（1117）降压至3.3V，为摄像头供电。采用两级降压（DC-DC转5V，LDO转3.3V）的策略，兼顾了效率与低噪声：DC-DC负责大压差下的高效率转换，LDO则在后级提供纯净的模拟电源。
DC-DC降压电路（12V转5.0V）。 由于12V至5.0V的压差较大（约7V），若采用线性稳压方案将产生较大功耗和发热，因此选用高效率DC-DC降压芯片。本队采用德州仪器（TI）的TPS5430降压转换器。该芯片具有宽输入电压范围（5.5V至36V），可充分适应3S锂电池充满电12.6V至放电末端9.0V的宽电压变化范围，即使使用更高节数的电池组也留有充分裕量；连续输出电流高达3A（峰值4A），完全满足系统5V负载的需求；固定开关频率为500kHz，允许使用小型电感和陶瓷电容，有利于缩小电路板面积；集成100mΩ高侧N沟道MOSFET，转换效率高达95%；输出电压可调，最低可至1.22V；内置过流保护和热关断功能，具备完善的自我保护能力；采用8引脚SOIC PowerPAD™封装，底部带有散热焊盘，有利于在大电流工况下将热量传导至PCB铜箔。该芯片在智能车竞赛中已有成熟应用，被广泛用于为系统提供稳定可靠的5V电源。
TPS5430的降压电路设计要点如下：输入电容选用10μF陶瓷电容（X7R材质）并联0.1μF高频去耦电容，靠近芯片VIN引脚放置，滤除电源输入纹波；功率电感选用额定电流大于负载峰值电流（建议1.5倍裕量）的屏蔽电感，电感值根据500kHz开关频率计算，典型值为10μH~22μH；反馈电阻分压网络的取值根据芯片内部基准电压（1.221V）精确计算，选用1%精度电阻以确保输出电压精度；在BOOT引脚与PH引脚之间连接0.01μF电容，为高端MOSFET提供栅极驱动电压；ENA引脚为高电平有效使能端，可通过MCU的GPIO控制DC-DC的开关，也可悬空使其保持常开状态；芯片底部的PowerPAD™散热焊盘必须与PCB地平面良好焊接，并布置多个散热过孔以增强散热能力。
为防止电机驱动回路产生的大电流在接地阻抗上形成压降，进而通过公共地回路耦合至主控电路，导致MCU供电电压波动、ADC采样基准漂移甚至系统复位等严重问题，本队在电源分配网络中采用了星型单点接地策略，并对不同功能模块的供电进行了物理隔离。
具体而言，电池输入的12V电源地线作为整个系统的“星型中心”，分别通过两枚独立的0Ω电阻连接至功率地平面与信号地平面。其中，功率地为电机驱动电路（DRV8701及其外围MOSFET）的专用地回路，承载车轮电机与负压风扇工作时的数安培级脉冲电流；信号地则为主控MCU（TC264核心板）、摄像头、光电管阵列及其他数字/模拟信号处理电路提供参考地。两枚0Ω电阻的独立布置，确保了大电流在功率地路径上产生的压降不会沿公共地线传导至信号电路，从而避免了地电位偏移对敏感信号（摄像头图像数据）的干扰。
在电源隔离方面，本队对不同3.3V负载的供电来源进行了差异化设计。显示屏和六轴陀螺仪（imu660rb）的3.3V供电采用独立的AMS1117 LDO稳压器提供，而摄像头的3.3V供电则使用另一路独立的AMS1117。两组LDO的输入均取自DC-DC输出的5.0V总线，但其输出回路相互独立。这一设计的主要考量在于：显示屏在工作时会产生较为频繁的数字电平跳变，其电流波形中含有较丰富的高频分量；陀螺仪对电源噪声较为敏感，供电纹波直接影响其角速度/加速度输出的信噪比。将两者与摄像头的供电从源头加以隔离，可有效避免上述负载之间的噪声串扰，确保摄像头输出图像的稳定性和陀螺仪姿态解算的精度。
通过上述“分地”与“分电源”的双重隔离策略，本系统在电机大电流工作与传感器微弱信号采集并存的恶劣电磁环境下，仍能保持主控电路与信号采集链路的电源完整性，为控制算法的稳定运行提供了可靠的硬件基础。

第五章 控制软件设计
控制软件是整个智能车系统的“大脑”，负责把摄像头采集到的赛道图像实时转化为车模的行驶决策。针对疯狂电路组“导线循迹、节点转向”的赛题特征，本队设计了“双核分工、分层模块”的控制软件架构：CPU1 专职视觉，完成图像采集、OTSU 自适应阈值分割与赛道中线提取；CPU0 专职控制，完成电机闭环、视觉巡线与陀螺仪定点转向。本章从软件总体架构、图像预处理、赛道中线提取、巡线差速控制、路口检测与定点转向、系统启动保护与调试六个方面对控制软件设计进行详细介绍，并给出核心算法源码及说明。
5.1 软件总体架构与开发环境
本队控制软件基于逐飞科技 TC264 开源库开发，开发环境为 ADS v1.9.4，编程语言为 C，全部控制算法由本队自行设计实现。软件整体采用“双核分工”架构，充分发挥 TC264 双核 MCU 的并行处理能力：CPU1 作为视觉核心，负责摄像头图像采集、OTSU 自适应阈值分割、图像滤波与赛道中线提取；CPU0 作为控制核心，负责左右轮电机闭环控制、视觉巡线、路口检测与陀螺仪定点转向。两个核心之间通过帧处理完成标志 frame_processing_done 实现跨核同步：CPU1 每完成一帧图像处理（中线提取结束）后将标志置 1，CPU0 仅在标志为 1 时读取中线结果与二值图像，从而避免读取到正在更新的半帧数据，保证控制逻辑使用的图像信息始终完整一致。
从工程代码组织上，软件划分为用户层（user）、算法层（code）与驱动层（libraries）三层，各主要源文件的功能如下：
user/cpu0_main.c：CPU0 主函数，负责系统初始化、转向任务规划表执行、起步与停车控制，并定义 5ms 周期电机闭环中断与 1ms 周期调试串口上报中断；
user/cpu1_main.c：CPU1 主函数，负责双路摄像头初始化与图像处理主循环；
code/otsu1.c：大津法（OTSU）自适应阈值计算模块，输出逐帧分割阈值；
code/scan_photo.c：OTSU 二值化、路口单边缝隙检测与加权中线提取（Forward）；
code/zn_motor.c：电机底层 PWM 驱动、左右轮速度闭环 PID、陀螺仪串级角度 PID 转向控制、编码器测速与里程统计；
code/turning_mode.c：转向状态机与路口转向调度；
code/pid.c：位置式/增量式 PID 通用算法与斜坡函数；
user/isr.c：摄像头场中断、DMA 采集完成中断、串口中断等底层中断的统一挂载。
图像数据通过 DMA 直接写入 CPU1 本地 DSRAM，CPU0 与 CPU1 之间仅通过 final_mid_line、frame_processing_done 等少量共享变量交互，避免了整幅图像数据的跨核拷贝，降低了核间通信开销。实测在双核并行架构下，图像处理与电机控制互不阻塞，电机闭环控制周期稳定维持在 5ms，满足高速巡线的实时性要求。
5.2 图像采集与 OTSU 自适应阈值分割
摄像头采用逐飞科技 MT9V03X 灰度摄像头，配置输出分辨率为 188×120。考虑到赛道引导线主要位于画面中下区域，软件通过裁剪宏将有效处理区域固定为 150×60：CROP_ROW_OFFSET 取 0（保留画面顶部），CROP_COL_OFFSET 取（188-150）/2=19（水平居中裁剪）。裁剪窗口同时作为 OTSU 灰度统计窗口与二值化输出窗口，保证“统计区域”与“分割区域”严格一致，避免因统计窗口与分割窗口错位导致阈值整体偏移——若近景亮区参与统计而从不参与二值化，会抬高均值与阈值钳位区间，造成远景暗区赛道被误判。
大津法（OTSU）是经典的自适应阈值分割算法，其基本思想是遍历 0~255 灰度范围内的所有可能阈值，选择使分割后前景与背景两类像素类间方差最大的灰度值作为最优阈值。本队在 otsu1.c 中实现了带自适应滤波的 OTSU 算法，处理流程为：
（1）统计裁剪区域内全部像素的灰度直方图，并计算区域平均灰度 g_image_mean；
（2）确定区域内有效最小、最大灰度；若灰度对比度不足（小于随平均灰度自适应变化的阈值 10+mean/8），直接依据平均灰度将阈值强制置为 0 或 255，避免低对比度画面下类间方差法失效；
（3）正常情况从最小灰度遍历至最大灰度，按“类间方差最大”准则选出最优分割阈值；
（4）根据区域平均灰度对阈值进行钳位，将阈值限制在 [mean×3/5, mean×13/10] 区间（进一步限制在 [30, 252]），防止光照突变导致阈值大幅漂移；
（5）对逐帧阈值做一阶 IIR 低通滤波，滤波系数按阈值变化幅度自适应取值：变化超过 40 时取 0.6 快速跟随，超过 20 时取 0.4，平缓波动时取 0.25 强平滑，有效抑制帧间阈值抖动引起的二值图像闪烁。
otsu() 的核心计算代码见附录B中1部分。
得到阈值后，Otsu_image() 将裁剪区域像素逐一二值化：灰度小于等于阈值的像素置为 0（黑色背景），大于阈值的像素置为 255（白色引导线）。二值化完成后依次调用 image_filter() 进行简易形态学滤波、调用 Pixle_Filter() 进行四邻域椒盐噪声滤波，去除元器件阴影、反光等造成的孤立噪点。核心代码见附录B中2部分。
5.3 赛道中线提取算法（Forward）
二值化图像仅提供“白线/黑底”的像素级信息，还需进一步提取可供控制使用的赛道中线位置。本队 Forward() 函数采用“逐行扫描边缘 + 远重近轻加权 + 指数平滑”的方法，从二值图中提取全局中线 final_mid_line。具体流程为：自图像底部（车模近处）向顶部（远处）每隔 5 行采样一行，共采样 11 行；对每一行从左到右扫描像素跳变，检测到“黑→白”跳变点记为左边缘，检测到“白→黑”跳变点记为右边缘，取二者中点作为该行赛道中线。
为保证中线提取的鲁棒性，算法采取了四项抗干扰措施：
（1）只有左右边缘同时存在的行才作为有效样本计入，避免近处赛道过宽、只找到单边时产生错误中线；
（2）相邻有效行之间的中线跳变超过 ±35 像素时，认为该行被元器件或噪声干扰，强制沿用上一行的中线值；
（3）中线合成采用“远重近轻”的权重分布，权重表为 {1,1,1,3,5,5,6,8,10,10,8}，使远处（图像顶部）赛道信息占主导，让车模“看得远、提前预判”，在长直道上行驶更平稳；
（4）当有效权重和不足 20（有效样本过少）时保持上一次中线结果不变（“死守”策略），避免样本不足时中线剧烈跳变；正常时对加权结果做一阶指数平滑（新值占 0.8、旧值占 0.2），进一步滤除抖动。
Forward() 核心代码见附录B中3部分。
最终输出的 final_mid_line 即当前帧赛道中线在图像中的横坐标，其物理含义是赛道相对车模的横向位置，作为 5.4 节巡线差速控制的输入。
5.4 视觉巡线差速控制
本队巡线控制采用“中线偏差→差速量”的单级比例控制结构。控制核通过 CCU60_CH1 定时器以 5ms 周期进入电机闭环中断，中断中首先读取 IMU 陀螺仪数据更新航向角，读取左右轮编码器计数值作为速度反馈并累计总里程；随后根据当前行驶状态选择控制逻辑：转向执行时调用串级 PID 转向控制（见 5.5 节），正常巡线时执行视觉巡线差速控制。
巡线差速控制的计算过程为：以裁剪图像宽度中值 75 作为目标中线，以 final_mid_line 作为反馈值，由 line_pid 计算偏差修正量。line_pid 采用纯比例结构（kp=1.2，ki=kd=0，死区 1，输出限幅 ±1000），刻意不引入积分项，避免长直道上积分缓慢累积导致车身“越纠越偏、来回画蛇”的振荡。为消除起步低速时差速量过大的问题，差速量还按实测车速归一化：diff = adjust × v_avg / 350，其中 v_avg 为左右轮编码器反馈速度均值，350 为标定基准车速；车速越低差速量越小，从而保证低速起步时车身平稳。最后将差速量限幅在 ±基础速度内并叠加到基础速度上输出：diff 为正（车偏右）时右轮加速、左轮减速，使车模向左纠偏。5ms 中断中的巡线差速核心代码见附录B中4部分。
底层左右轮各自配有独立的速度闭环 PID（kp=2.8，ki=0.3，kd=0.2，积分限幅 ±4000，输出限幅 ±4000），由Motor_speed_set() 在 5ms 中断内完成位置式 PID 运算，将目标速度转换为 PWM 占空比与方向电平，经 DRV8701 驱动电路控制电机。双路速度环独立闭环保证左右轮实际转速精确跟随目标值，为上层差速控制提供可靠的执行基础。
5.5 路口检测与陀螺仪定点转向
疯狂电路组赛道由导线构成若干节点与回路，车模需要在预设路口完成 90° 转向。考虑到缩微赛道空间紧凑、元器件图案干扰多，本队放弃了对图像做完整拓扑识别再决策的复杂方案，采用“预设任务规划表 + 单边缝隙检测 + 陀螺仪串级 PID 定点转”的工程化方案：将整条赛道的走法预先编排为一张任务表，车模按表逐项执行。
任务规划表 turn_plan[] 以 uint32 数组形式存放在 cpu0_main.c 中，表中数字含义为：2 表示左转 90°，3 表示右转 90°，4/5 分别表示左/右转 90° 预检测标记，0/1 表示两级速度切换标记，其余数字表示直行段需要行驶的编码器脉冲距离。CPU0 主循环按索引逐项执行：直行段调用 Turning_Straight_Skip() 以左轮编码器累计脉冲差值判定是否走完指定距离；速度切换段直接修改基础速度；转向段先进行路口检测，检测到入口后进入转向状态机。任务表与路口扫描代码见附录B中5部分。
路口检测采用“单边缝隙检测”策略：当期望的转向方向已知时，只扫描对应一侧的边界列，检测是否出现“白色缝隙”（路口的进入通道）。Scan_Left_Turn() 检查图像最左侧两列（第 1、2 列），Scan_Right_Turn() 检查最右侧两列（第 147、148 列）。检测采用双列“与”逻辑——同一行两列必须同时为白色，并要求连续 5~11 行满足条件才确认路口，从而有效抑制元器件图案造成的误触发。
转向控制采用陀螺仪串级双环 PID 闭环。转向状态机包含三个状态：NO_TURN（正常巡线）、TURN_APPROACH（接近转向点）、TURN_EXECUTING（执行转向）。检测到路口后进入 TURN_APPROACH，车模保持原方向短暂行驶 1ms 后切换至 TURN_EXECUTING；执行阶段锁定目标航向角（理想航向 ±90°），以 5ms 周期执行串级控制：
（1）外环角度环：以目标航向角与 IMU 解算航向角 FJ_Angle 的差为误差，误差经归一化限制在 [-180°, 180°]，保证沿最短方向旋转，输出期望角速度；
（2）内环角速度环：以期望角速度与 IMU Z 轴实测角速度的差为误差，输出左右轮差速修正量；
（3）差速量按 1.5 倍增益叠加到基础速度上，形成左右轮反向差速实现原地转向；内轮目标速度一旦小于 0 即强制置 0（刹停不反转），防止低速时反转导致打滑失控。
外环角度环 kp=10、ki=0.05、输出限幅 ±1000（即期望角速度最大值），内环角速度环 kp=1.5、ki=0.05、输出限幅 ±1000。Motor_Cascade_Control() 核心代码见附录B中6部分。
转向完成判据：当角度误差绝对值小于 1° 且连续 3 个 5ms 周期（共 15ms）保持稳定，判定车身已到位，清除各 PID 积分量、退出转向状态并恢复巡线。为避免连续路口时重新检测带来的延时，转向执行过程中还会预先扫描规划表下一项（4/5）对应的入口，命中后将转向类型暂存于 pending_turn，当前转向一结束立即执行下一转向，实现“转弯中预判下一弯”。转向完成判据核心代码见附录B中7部分。
5.6 系统启动、保护与调试
启动保护：为避免上电瞬间大占空比造成的电流冲击，CPU0 主函数在初始化完成后先以固定间隔逐步提升电机 PWM 占空比（每 60ms 递增 1%，直至 55%），完成“软启动”后才开启 5ms 电机闭环定时器进入正常控制。同时，系统上电后等待 2s 让 IMU 稳定，并执行陀螺仪零偏校准（gyroOffsetInit），保证航向角解算基准准确。
终点停车：CPU0 主循环检测到规划表执行完毕后，先将左右轮目标速度清零，随后以每 60ms 递减 1% 的方式缓慢降低 PWM 占空比，占空比降为 0 时关闭 5ms 控制定时器，电机完全停止，实现平滑停车，避免急停导致车模倾覆。
调试手段：软件预留了 1ms 周期无线串口上报中断，可实时上报左右轮目标速度与实际速度，供速度环 PID 参数整定；CPU1 图像主循环在 IPS114 屏幕实时显示二值化处理结果、实际采集帧率（FPS）与 OTSU 阈值（TH），便于现场快速判断图像质量与阈值漂移情况。上述在线调试手段显著缩短了算法参数的整定周期。
第六章 结论与展望
本队针对第二十一届全国大学生智能汽车竞赛疯狂电路组的赛题要求，围绕“轻量化为先、感知与控制在精度与速度之间寻求最优平衡”的总体设计理念，完成了基于N30Pro有刷四轮车模平台的智能模型车系统设计、制作与调试工作。系统以英飞凌TC264单片机为核心控制器，采用摄像头与光电管相结合的异构传感器方案实现赛道感知，通过三路独立PWM控制实现两轮差速驱动与负压风扇调速，构建了涵盖机械结构、电路系统和控制软件的完整技术方案。
在机械结构方面，本队选用逐飞科技N30Pro有刷四轮车模套件作为基础平台，在保留核心结构件的前提下精简冗余部件以降低整车质量，通过定制化3D打印结构件完成摄像头支架和电路板固定支架的设计与制作。摄像头支架采用螺栓连接为主、热熔胶加固为辅的双重固定策略，有效抑制了高频震动对图像采集的干扰。
在电路系统方面，本队自行设计了外围接口电路板，以TPS5430为核心构建了12V转5.0V的DC-DC降压电路，为系统提供稳定可靠的5V电源；以DRV8701全桥栅极驱动器为核心设计了驱动电路，驱动能力满足两路车轮电机和一路负压风扇的负载需求；采用LDO将5.0V二次降压至3.3V，为TC264核心板及其他3.3V外设提供低噪声电源。
在控制软件方面，本队采用分层模块化架构，实现了图像采集与处理、光电管信号采集与滤波、赛道拓扑识别与路径规划、PID转向与速度闭环控制等核心功能模块。摄像头提供全局赛道拓扑信息，光电管提供局部循迹偏差信息，两者通过数据融合形成完整的环境感知结果，共同支撑车模在复杂电路回路中的稳定循迹行驶。
在系统设计与调试过程中，本队也发现了一些有待改进之处。
传感器融合策略有待深化。 目前摄像头与光电管的信息融合主要采用简单的切换或加权方式，尚未实现更深层次的融合。在赛道光照条件变化较大或图像中出现较多干扰图案时，单纯依赖摄像头或光电管均可能出现误判，影响循迹稳定性。未来可借鉴光电与IMU融合循迹的思路，在信号丢失时融合历史数据与惯性信息进行决策修正。
负压风扇控制策略较为粗放。 直接使用有刷电机作为负压，增加了整车的重量，相较于无刷电机方案，有刷电机在同等功率输出下重量更大、效率更低，对整车的轻量化目标产生了不利影响。与此同时，受限于缩微车模的电池容量和底盘离地间隙，风扇实际产生的下压力增量有限，在部分赛道工况下的系统收益未能充分抵消其重量代价。
路径规划算法有待完善。 针对疯狂电路组包含串联、并联、反馈等多种回路的复杂赛道拓扑，当前的路径规划算法在处理多分支节点时的决策鲁棒性仍有提升空间。在决赛场地赛道长度增至约27米、电路支路大量增加的情况下，路径规划的计算效率和准确性面临更大挑战。
系统集成度可进一步提高。 当前电路系统由多块电路板组成，通过3D打印支架固定于车模上，虽然满足了功能需求，但板间连接器数量和线束复杂度仍有优化空间。进一步将驱动电路、电源管理电路等整合至更少的电路板中，有助于减轻整车重量并提高电气可靠性。

                right_line[z] = x;                        // 白→黑跳变：右边缘
        }
        if (left_line[z] != 0 && right_line[z] != 0)      // 双边同时存在才计入
        {
            mid_line_buf[z] = (left_line[z] + right_line[z]) / 2;
            // 相邻行中线跳变限幅，超限沿用上一行值
            if (z > 0 && (mid_line_buf[z] - mid_line_buf[z-1] > 35

                mid_line_buf[z] = mid_line_buf[z-1];
            mid_line_sum     += mid_line_buf[z] * mid_wight[z];
            valid_weight_sum += mid_wight[z];
        }
        z++;
    }
    if (valid_weight_sum >= 20)      // 有效样本足够：加权平均 + EMA平滑
    {
        int weighted_mid = mid_line_sum / valid_weight_sum;
        final_mid_line = weighted_mid * 0.8f + last_mid_line * 0.2f;
    }
    else
        final_mid_line = last_mid_line;   // 样本太少：不更新，死守上次值
    last_mid_line = final_mid_line;
}

if (diff >  base) diff =  base;                     // 差速限幅
if (diff < -base) diff = -base;
// diff > 0 → 车偏右 → 需要左转 → 右轮快、左轮慢
Motor_speed_set(base + diff, base - diff);

uint8_t Scan_Left_Turn(void)              // 扫描左侧第1、2列检测白色缝隙
{
    int run = 0;                          // 连续满足条件的行数计数器
    for (int y = 5; y < MT9V03X_IMAGEend_H - 5; y++)
    {
        // 双列“与”逻辑：同一行两列必须同时为白色
        if (mt9v03XImageotsuend[y][1] == 255 && mt9v03XImageotsuend[y][2] == 255)
        {
            run++;
            if (run > 4 && run < 12) { road = ROAD_LEFT_TURN; return 2; }  // 连续5~11行
        }
        else run = 0;                     // 重置计数器
    }
    return 0;                             // 未检测到左转
}

void Motor_Cascade_Control(float angle_set, float angle_now, float gyro_now)
{
    float base_speed = g_base_speed;      // 原地转向基础行驶速度
    // 外环角度PID运算，输出期望目标角速度
    target_gyro = PID_Angle_CALC(&cascade_angle_pid, angle_now, angle_set);
    // 内环角速度PID，输入目标角速度与陀螺仪实测角速度
    cascade_gyro_pid.speed_set = target_gyro;
    cascade_gyro_pid.speed_now = gyro_now;
    speed_adjust = PID_Speed_CALC(&cascade_gyro_pid);
    if (speed_adjust >  base_speed) speed_adjust =  base_speed;   // 限幅
    if (speed_adjust < -base_speed) speed_adjust = -base_speed;
    if (speed_adjust > 0)           // 右转：左轮加速、右轮减速
    {
        left_target  = base_speed + 1.5f * speed_adjust;
        right_target = base_speed - 1.5f * speed_adjust;
        if (right_target < 0) right_target = 0;   // 内轮刹停不反转
    }
    else if (speed_adjust < 0)      // 左转
    {
        left_target  = base_speed + 1.5f * speed_adjust;
        right_target = base_speed - 1.5f * speed_adjust;
        if (left_target < 0) left_target = 0;     // 内轮刹停不反转
    }
    else
    {
        left_target  = base_speed;
        right_target = base_speed;
    }
    Motor_speed_set(right_target, left_target);
}
