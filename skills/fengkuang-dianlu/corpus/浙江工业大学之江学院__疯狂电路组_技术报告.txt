摘要
本文详细介绍了浙江工业大学之江学院三只懒猫队参加第二十一届全国大学生智能汽车竞赛（疯狂电路组）的智能车系统设计方案。
车模组装方面，精心安装了编码器、陀螺仪、摄像头、主驱一体控制板和电调驱动板，在优化重心前后位置的同时，同步降低了整体重心高度，增强车模的抓地能力和抗侧倾能力。
硬件设计方面，系统以英飞凌TC264为核心，采用MT9V034摄像头采集赛道信息、IMU660RB陀螺仪作为整车转向控制传感器、1024 线编码器作为速度检测与反馈的核心传感器。硬件电路采用模块化设计，设计了两块PCB，主控板负责信号处理与行进电机驱动，电调驱动板负责驱动负压风扇。
软件设计采用TC264双核协同架构。CPU1负责摄像头图像的分区阈值二值化和连通域滤波，CPU0负责赛道中线提取、L/R/S支路识别、T字及十字路口分类和路线策略决策。运动控制采用方向PD与左右轮速度PI构成的串级闭环，并结合编码器距离反馈和IMU航向信息，实现普通巡线、航向转弯和路口直行三种运行状态的切换。
【关键词】分区二值化；连通域滤波；路口识别

第一章 引言
随着科技的飞速演进，智能控制技术已深度融入各行各业。作为高新技术的集大成者，智能汽车融合了控制工程、模式识别、传感技术、电子电气及计算机机械等多学科知识，通过路径识别、速度采集与角度控制等核心模块，实现了自动驾驶与道路自动识别等功能，是现代电子产业的关键组成部分。为顺应这一发展趋势，我国教育部委托高等学校自动化专业教学指导委员会，每年定期举办全国大学生智能汽车竞赛。该赛事不仅为高校学子搭建了展示创新思维与实践能力的广阔舞台，更为我国智能车领域持续输送了大量高素质的后备人才，吸引了跨专业大学生的广泛参与。
本车以英飞凌32位微控制器TC264为核心控制单元，采用MT9V034摄像头采集赛道信息、IMU660RB陀螺仪作为整车转向控制传感器、1024 线编码器作为速度检测与反馈的核心传感器。
团队自主设计开发了主驱一体板等核心硬件电路，并探索了多种转向控制策略，从而保障了车模对赛道的精准识别与稳定运行。在研发过程中，团队深入剖析车模物理特性，对整体结构与控制系统进行了系统性设计，并基于实测数据进行了动态优化。在硬件层面，针对车模结构特点，对传感器布局及电路模块的安装位置进行了多轮迭代验证；在软件层面，采用经典PID控制算法，实现了转向与速度的高精度闭环控制。本报告将重点阐述车模组装、硬件设计、软件设计、开发工具与调试过程、车模的主要技术参数等。
第二章 车模组装
2.1 车模简介
智能车疯狂电路赛道今年不限制车模的选择，这为团队提供了更多的发挥空间。经过深思熟虑和多次测试，团队采用逐飞科技的N30四轮车模，碳纤维底板和轻量化设计是N30车模的一大亮点。碳纤维不仅轻盈坚固，而且具有极高的耐用性，能够在长时间的使用和高强度比赛中保持稳定性能。无论是面对复杂的赛道环境还是突发的碰撞情况，碳纤维底板都能提供可靠的保障。此外，低底盘设计是实现高速转向的关键。
该车模的车长130mm，宽170mm，最高处180mm，车模底盘高度经过精心调校，使其在高速行驶时能够保持较低的重心，从而提高转向的稳定性。在急转弯道或曲折赛道上，四轮车模低底盘的优势尤为明显，能够使车辆快速平稳地通过，减少侧倾和失控的风险。在今年的比赛中，这款车模将为团队带来出色的表现，助力我们队伍取得优异的成绩。
2.2 车模组装
2.2.1 主要思路
在本组缩微四轮车模的设计与调试过程中，动态稳定性与操控响应是重点优化的核心指标。在初始方案中，实际测试表明原有配置虽提升了静态稳定性，却导致车模加速性能不足。为此，进行了系统的重心优化实验，最终确定将整车重心前移2cm，有效改善了四轮车模在直线加速阶段的抓地力与响应速度。
进一步研究发现，当车模在赛道上高速行驶及过弯时，较高的重心位置容易引发明显的侧倾现象，严重影响循迹稳定性。因此，在优化重心前后位置的同时，同步降低了整体重心高度，以增强车模的抗侧倾能力。基于上述分析，车模组装主要围绕“低重心布局”和“前移重心优化”两大策略展开，最终实现了四轮车模行驶稳定性与动态性能的协同提升。
2.2.2 编码器安装
速度是衡量智能小车运行快慢的重要物理量，而编码器则是实现速度检测与反馈的核心传感器，其安装位置直接关系到测速的准确性。因为考虑到还需要进行断路区的惯性导航，所以最终选用了逐飞科技生产的 1024 线编码器，该型号体积小、重量低至1.5g、稳定性高，能够在各种运行工况下提供稳定的速度信号。为了保证测量的精准性，编码器必须与电机输出轴端齿轮实现可靠啮合，无论在高速还是低速情况下都不能出现松动或打滑。在实际安装中，将编码器固定在小车尾部，利用其自带的黑色安装板与车身进行紧固，使其与电机齿轮保持稳定啮合。这样既保证了速度测量的准确性，又确保了运行过程中的结构牢固性与可靠性。安装编码器后的车模如图2-1所示：

2.2.3 陀螺仪安装
   陀螺仪采用了逐飞科技生产的IMU660RB模块，其搭载的IMU为ST公司(意法半导体)生产的LSM6DSV。是一款高端、低噪声、低功耗的6轴小型IMU，配备了一个3轴数字加速度计和一个3轴数字陀螺仪。陀螺仪作为整车转向控制的核心传感器，其安装位置的选取直接影响系统的控制性能。为确保传感器能够精确反映车体俯仰角变化，同时避免因固定不牢导致的姿态解算误差，在安装方案上进行了多方面的考量。理想的安装位置需要满足两个关键要求：一是能够灵敏、准确地捕捉车体姿态变化，二是具备良好的机械稳定性以抑制振动干扰。经过反复测试验证，最终将陀螺仪安装在主板中心下侧的位置，传感器y轴旋转180°摆放通过与间距2.54mm排座连接实现了传感器在主板上的稳固安装，从而在测量精度和机械稳定性之间取得了最佳平衡；陀螺仪安装图如下图2-2所示：

2.2.4 摄像头安装
   在摄像头选型中，选择了逐飞科技的总钻风摄像头，其内部为MT9V034数字摄像头。MT9V034是安森美半导体出品的全局快门CIS，拥有卓越的画质和低照度的表现。在整车布局设计中，特别注重降低重心对车体稳定性的影响。经过多次配重测试和仿真分析，最终确定将视觉摄像头安装在车体几何前部位置。这一布局方案具有双重优势：一方面，中心位置能够确保视觉数据采集的实时性和准确性；另一方面，该安装位置使整车重心严格控制在设计允许范围内，能够平衡电池在中心后侧的重量，有效提升了车体在高速运动时的稳定性。实验数据表明，这种对称式布局设计使得车体在转向时表现出更好的性能。摄像头的安装图如下图2-3所示：

硬件设计
3.1 概述
硬件设计是智能车模高效运行的核心保障。一套优秀的硬件设计方案不仅需要确保车模在调试过程中的安全性和可靠性，更要充分释放其性能潜力。然而，高性能的实现并非硬件设计的唯一目标，还需综合考虑以下关键因素：首先，设计方案必须与车模机械结构实现完美适配；其次，要充分考虑调试人员的使用便利性。真正出色的硬件设计需要实现原理图设计、PCB布局与结构设计的有机统一，这三个要素相互协同才能打造出卓越的作品。

3.3 电调驱动板电路

软件设计
智能车软件主要由视觉处理、路口决策和运动控制三部分组成。摄像头通过DMA双缓冲方式采集赛道图像，CPU1对完整图像帧进行二值化和连通域滤波，并将处理结果发布给CPU0。CPU0完成赛道中线提取、路口特征识别和路线策略决策。底盘控制由5 ms定时中断驱动，根据车辆状态选取图像中线误差或IMU航向误差，并通过方向PD和轮速PI控制左右轮电机。

4.2 图像处理部分
4.2.1 图像预处理
智能车视觉系统需要在高速运行和环境光照变化条件下稳定输出赛道信息。当前软件采用TC264双核协同结构，将图像预处理与车辆决策分离：CPU1负责二值化和连通域滤波，CPU0只读取已经处理完成的图像帧，并执行中线提取、路口识别及路线决策。该结构降低了图像运算对5 ms实时控制中断的影响。
MT9V034摄像头输出188×120像素灰度图像，采集过程采用中断触发和DMA双缓冲方式。摄像头驱动在一帧采集完成后更新帧序号及就绪缓冲区，CPU1仅处理序号发生变化的完整新帧；处理完成后再发布结果缓冲区编号和结果序号。CPU0通过比较结果序号消费新帧，从而避免读取DMA正在写入的不完整图像。
图像预处理采用分区固定阈值二值化。考虑到镜头视野中央与两侧区域的亮度存在差异，程序将左右边缘各10列与中间区域分别设置阈值，当前中间阈值为108、边缘阈值为104，灰度值高于相应阈值的像素判定为白色。二值化后采用基于游程编码的连通域滤波，去除与主赛道区域分离的小面积噪声，提高后续扫线和支路检测的稳定性。

图4-2 二值化及连通域滤波后的图像
4.2.2 路径中线提取
赛道中线提取在二值图像的Y=109至Y=69区域内进行，行间隔为2，共扫描21行。每一行分别从图像左端和右端向内搜索白色赛道区域，并要求相邻位置同时出现白色像素，以降低孤立噪点造成的误判。当左右边界均有效且右边界位于左边界右侧时，取二者平均值作为该行的赛道中点。
程序首先对全部有效中点求平均值，再剔除与平均值相差超过18像素的跳变点。保留下来的中点一方面用于计算当前帧的平均中线，另一方面用于拟合主赛道直线，为路口虚拟交点计算提供几何基础。最终中线经过一阶滤波后与目标中点94作差，得到普通巡线方向误差；若本帧没有有效中点，则增加丢线计数并暂时回到安全中点。
4.2.3 路口识别与路线决策
路口识别分别检测左支路L、右支路R和前方直行支路S。左右支路检测在图像两侧各选取8个固定列，从上向下搜索第一段连续白带，记录白带中点及宽度。只有有效列数量达到设定阈值时才确认支路存在；其中宽度正常的检测点还用于支路线拟合，以减少局部宽白区域对几何计算的影响。
当前帧检测到的左右支路会进行短时锁存，使路口特征在个别帧受曝光或振动影响时不会立即丢失。检测到左支路或右支路后，程序以支路中点为参考向图像上方搜索S支路，并在中心行及上下相邻行检查连续白带宽度。三行均满足条件时确认前方存在直行通道，从而形成稳定的L、R、S特征组合。
程序根据L、R、S组合完成路口分类：L、R、S同时成立时判定为十字路口；其中任意两个同时成立时判定为T字路口；仅左侧或右侧支路成立时判定为普通单侧转弯。分类优先级按照十字路口、T字路口、单侧转弯依次处理，避免在复杂路口刚进入视野时因特征尚未完全出现而过早执行普通转弯。
为确定合适的动作位置，程序分别拟合主赛道直线和支路线，并计算两条直线的虚拟交点。虚拟交点的纵坐标反映路口在图像中的接近程度，当其达到当前距离档位对应的行阈值时允许执行动作。对于几何拟合暂时无效的帧，程序同时统计连续候选帧数，达到保底帧数后也可触发动作，形成位置判据优先、帧计数保底的双重机制。
对于T字和十字路口，程序读取当前路线策略表中的L、R或S指令。L、R指令将当前航向换算为相邻的90°目标航向，并切换到IMU转弯状态；S指令保持当前基准航向并切换到路口直行状态。动作执行期间设置锁定标志，防止同一路口被重复识别，动作退出后再清除L、R、S锁存并推进策略表下标。

图4-3 T字路口二值图像
针对连续路口和特殊赛段，程序还根据上一动作后的编码器累计距离调整虚拟交点阈值与候选帧数，使近距离连续转弯和远距离路口采用不同的触发提前量。个别指定路口可使用与主线平行的局部采样结果辅助判断，从而减小支路过短或宽白区域造成的位置偏差。
当路线策略动作达到设定下标，或真实左右转弯累计达到终止条件后，系统进入最终巡线阶段，并在继续行驶设定距离后启动软停车。该流程不断路重放或全白图像停车，而是由路线表、路口状态机、编码器距离和人工停车入口共同完成运行管理。



4.3控制部分
4.3.1 方向与速度串级控制
智能车底盘采用方向外环和左右轮速度内环构成的串级闭环。方向外环根据当前运行状态选取图像中线误差或IMU航向误差，并计算左右轮目标差速；速度内环读取编码器反馈，分别调节左右轮PWM输出。方向环主要决定车辆转向趋势，速度环用于抑制电机、电池电压及地面负载差异造成的轮速偏差。
数字反馈控制器的基本结构如图4-4所示。实际程序根据控制对象分别选用PD或PI形式，并在5 ms固定周期内完成采样、误差计算和输出更新。

结合智能车的实际控制需求，各校正环节在本系统中的作用如下。
比例环节直接放大当前偏差，使车辆在出现横向偏移、航向偏差或轮速误差时及时产生修正作用，是方向环和速度环快速响应的主要来源。
积分环节仅用于左右轮速度内环，通过累计目标轮速与编码器实际轮速之间的偏差减小稳态误差。程序对积分量设置上下限，防止启动、堵转或突发负载变化时产生积分饱和。
微分环节用于方向外环，根据当前误差与上一周期误差之差抑制方向变化过快和转向振荡。模式切换时会更新历史误差，避免进入新状态的第一拍产生过大的微分冲击。
因此，当前程序的实际控制结构不是三级位置式、增量式PID，而是方向PD与左右轮速度PI组成的两级串级控制。
（1）方向PD控制
方向控制误差由车辆状态决定。普通巡线状态使用图像模块输出的中线误差；IMU转弯状态使用目标航向与当前航向的最短角度差；路口直行状态前段使用航向误差，后段使用特殊巡线误差。方向差速量按u_d(k)=Kp·e(k)+Kd·[e(k)-e(k-1)]计算。
设当前模式基础速度为v_b，则左右轮目标速度分别为v_L*=v_b+u_d和v_R*=v_b-u_d。程序对目标速度和最大差速进行限幅，并为普通巡线、IMU转弯和路口直行设置不同的控制参数。丢线次数较多时会适当降低巡线基础速度，提高异常图像条件下的稳定性。
（2）左右轮速度PI控制
每个5 ms控制周期内，程序读取左右编码器增量并立即清零计数器。编码器方向通过符号宏统一，随后对相邻周期变化过大的读数进行限幅滤波，所得结果作为本周期左右轮实际速度。
速度误差分别定义为e_L(k)=v_L*-v_L(k)和e_R(k)=v_R*-v_R(k)，左右轮使用独立积分状态。速度PI输出如下：
u_L(k)=Kps·e_L(k)+Kis·Σe_L(k)
u_R(k)=Kps·e_R(k)+Kis·Σe_R(k)
式中，Kps和Kis分别为速度环比例与积分系数，u_L、u_R为左右轮PWM控制量。
速度环直接根据本周期误差及累计误差计算当前PWM控制量，属于离散PI控制，而不是报告原方案所述的增量式三级PID。左右轮积分分别保存，使两侧电机能够独立补偿机械和负载差异。
（3）限幅与平滑处理
为提高实际运行可靠性，控制器对编码器速度突变、方向差速、速度积分和最终PWM均设置限幅。单轮PWM相邻周期的变化量也受到限制，从而减小电机输出突变对车体姿态和图像稳定性的影响。
车辆正式发车后采用约200 ms的输出斜坡；IMU转弯退出后，方向差速在约100 ms内由较小倍率逐步恢复；收到停车请求时，左右轮和负压风机进入软停车过程。这些处理能够降低起步、状态切换和停车时的机械冲击。
控制参数采用工程整定方法。调试时先在低速下确定方向PD参数，使车辆能够稳定回到赛道中心，再调整速度PI以减小左右轮稳态误差，最后逐步提高基础速度并检查连续路口、转弯退出和丢线情况下的控制裕量。
4.3.2 5ms中断与状态机控制
整车实时控制由CCU60通道0产生的5 ms定时中断统一调度。进入中断后首先清除中断标志，更新蜂鸣器和负压风机软启动状态，读取IMU角速度并完成航向积分；随后根据停车标志和车辆状态选择相应控制误差，调用电机控制函数读取编码器、计算方向PD和速度PI，并输出左右轮PWM。
在普通巡线状态STATE_TRACKING下，控制器使用CPU0最近一次图像处理得到的中线误差驱动车辆。编码器平均速度同时换算为本周期行驶距离，用于累计起步识别屏蔽距离、相邻路口间距和最终停车距离。发车后的前8 cm只执行普通巡线，不进行L/R/S路口识别，以避免起步阶段图像波动造成误触发。
在IMU转弯状态STATE_IMU_TURNING下，程序不使用图像中线控制转向，而是计算目标航向与当前航向之间的误差，并将其送入转弯模式方向PD。目标航向以当前最接近的90°坐标方向为基准，左转增加90°、右转减少90°；当航向误差绝对值不大于8°时退出转弯状态，清除路口锁存并恢复普通巡线。
在路口直行状态STATE_CROSSING下，车辆前12 cm使用IMU航向误差保持直行，后8 cm使用图像中部指定行范围计算的特殊巡线误差进行修正。编码器累计距离达到20 cm后退出该状态。该分段策略既避免车辆刚进入T字或十字路口时因边线缺失发生偏转，又能在离开路口前利用重新出现的赛道线完成回正。
当路线策略完成、真实转弯次数达到终止条件、运行按键按下、WiFi收到停车命令或主循环超时时，系统设置停车请求并启动软停车。停车过程中5 ms中断继续逐步降低左右轮PWM和负压风机输出，同时记录控制波形，直至底盘输出完全关闭。
由此形成了图像帧处理与实时控制相互解耦的闭环结构：CPU1负责图像预处理，CPU0主循环负责中线和路口决策，5 ms中断负责IMU、编码器和电机闭环。该结构避免在中断中执行耗时的图像、WiFi或串口操作，保证底盘控制节拍稳定。

5.2 ADS与VOFA联合调试流程
本系统采用“ADS构建程序、VOFA在线调整、实车验证、参数固化”的联合调试方式。ADS负责生成并下载可运行程序，VOFA+负责车辆运行过程中的波形观测和参数调整，两者形成完整的控制参数整定闭环。
首先，在ADS中打开智能车工程，检查图像处理、运动控制、WiFi和VOFA等模块的配置，确认功能开关及通信参数符合当前调试任务。随后执行工程编译和链接，待控制台显示构建成功后，将生成的程序下载至TC264，并通过下载信息确认程序已经正确写入。
程序下载完成后，将调试计算机与智能车WiFi模块接入同一局域网。在VOFA+中建立TCP服务端，监听端口设置为8086，数据引擎选择JustFloat。智能车上电并连接成功后，VOFA+即可持续接收line_err和line_mid两路数据。调试开始前先观察静止状态下的波形是否连续、数值是否合理，以确认SPI、WiFi、TCP和数据解析链路均工作正常。
智能车运行后，根据line_err的峰值、过零次数和收敛速度判断方向控制效果，并结合line_mid相对目标中点94的偏移观察车辆回中过程。VOFA+可发送dkp、dkd、skp、tkp、ski、ikp、ikd和speed等文本命令，分别调整巡线方向PD、转弯方向PD、左右轮速度PI及基础速度；还可使用start和stop命令控制车辆启动与停止。调参时先在较低速度下整定方向环，再调整速度环，每次只改变少量参数并在相同赛道条件下重复试验。
在线修改的参数仅在本次运行期间保存在RAM中，智能车重新上电后会恢复程序默认值。获得稳定的参数组合后，将最终数值写回ADS工程中的默认配置，重新编译并下载程序，再进行完整赛道验证。通过上述流程，可利用VOFA+提高初步整定效率，同时由ADS完成可靠参数的最终固化。

第七章 结论
本文系统介绍了智能车系统的整体设计方案，主要包含车模组装、硬件设计和软件软件三个核心部分。
在车模组装方面，重点优化了车模的重心布局和传感器安装位置。通过降低重心和合理前移的设计，显著提升了车模的动态稳定性。同时针对陀螺仪和摄像头等关键传感器，都进行了专门的安装位置优化，确保其测量精度和可靠性。
硬件设计采用模块化思路，将控制系统分为主驱一体控制板和电调驱动板。电源系统经过精心设计，采用多级供电方案，既保证了各模块的稳定供电，又实现了紧凑的布局。驱动电路特别考虑了电流采样精度和抗干扰能力。
软件算法部分主要完成图像预处理、赛道中线提取、L/R/S支路识别、T字及十字路口分类和路线策略执行。系统利用TC264双核完成图像处理与车辆控制任务分工，并采用方向PD和左右轮速度PI构成闭环控制。结合IMU航向信息和编码器距离反馈，车辆能够在普通巡线、转弯和路口直行状态之间稳定切换。
整个系统在AURIX开发环境下完成软件开发和调试，充分利用了该平台的工具优势。通过机械、硬件和软件的协同优化，最终实现了一个性能稳定、响应灵敏的智能车系统。

void car_frame_proc(void)                                 // 每帧处理巡线和路口识别
{
    // Update base line tracking every frame, then check element recognition if unlocked.
    line_proc();
    if(post_turn_fast_filter_frames > 0U)// 每处理一个转弯后新帧消耗一次快速滤波
    {                                                                          
        post_turn_fast_filter_frames --;// 已完成一个alpha=1.0的新图像帧
        if(0U == post_turn_fast_filter_frames)                                 
        {                                                                      
            filter_alpha = FILTER_ALPHA_TRACK;// 第2帧后恢复用户普通滤波宏 
        }                                                                      
    }                                                                          
    car_wifi_marks_clear();// 每帧默认清除调试MID点,未进入识别则不显示旧点
    car_wifi_corner_marks_apply();// 非识别帧保持显示角落FLAG到动作结束
    if(STATE_CROSSING == Car_State)
    {
        car_cross_line_proc();//S直行期间额外计算70到50行的特殊巡线误差
    }
    if((STATE_TRACKING == Car_State) && (0U == act_lock) && (!finish_flag))
    {
        if(start_lrs_ignore)// 发车起步前8cm不处理L/R/S,防止全屏闪白误锁存
        {
            car_wifi_corner_hold_clear();// 起步屏蔽期间不显示误识别角落FLAG
            car_wifi_mid_hold_clear();// 起步屏蔽期间不显示误识别MID
            car_wifi_marks_clear();// 清掉本帧调试显示点
            return;// 只保留line_proc巡线结果,不进入L/R/S识别
        }
        if(!car_turn_img_hold_ready())//转弯后8cm内只保留巡线，不进图像识别
        {
            car_wifi_mid_hold_clear();// 保护段内不显示旧MID保持点
            return;//保护段内直接退出本帧识别流程
        }
        if(opamp_box_track_only)
        {
            car_wifi_mid_hold_clear();
            return;
        }
        car_check_turn();
    }
}
void motor_get_target_speed (motor_mode_e mode, float err, uint8 line_lost_count, int16 *left_target, int16 *right_target)   //PID控制代码
{
    motor_ctrl_t *cfg = &motor_ctrl[mode];
    float i_limit = 0.0f;
    float diff_f;
    int16 base_spd = cfg->base_spd;
    int16 min_spd = cfg->min_spd;
    int16 max_spd = cfg->max_spd;
    int16 max_diff = cfg->max_diff;
    if(MOTOR_MODE_TRACK == mode)
    {
        base_spd = motor_get_track_base(base_spd, line_lost_count);
    }
    if(min_spd < 0)
    {
        // 当前转弯也不允许反转，最小目标速度直接限制为 0。
        min_spd = 0;
    }
    if(min_spd > max_spd)
    {
        min_spd = max_spd;
    }
    if(motor_absf(cfg->ki) > 0.0001f)
    {
        i_limit = (float)max_diff / motor_absf(cfg->ki);// 积分限幅跟随起步差速限制
        cfg->i = motor_clamp_f32((cfg->i + err), -i_limit, i_limit);
    }
    else
    {
        cfg->i = 0.0f;
    }
    motor_direction_p_term = cfg->kp * err;
    motor_direction_d_term = cfg->kd * (err - cfg->last_err);
    diff_f = motor_direction_p_term + cfg->ki * cfg->i + motor_direction_d_term;
    cfg->last_err = err;
    diff_f = motor_clamp_f32(diff_f, -(float)max_diff, (float)max_diff);
    diff_f = motor_apply_post_turn_diff_ramp(mode, diff_f);

    //分配左右轮目标速度。
    *left_target = motor_clamp_i16((int16)((float)base_spd + diff_f), min_spd, max_spd);
    *right_target = motor_clamp_i16((int16)((float)base_spd - diff_f), min_spd, max_spd);
}
