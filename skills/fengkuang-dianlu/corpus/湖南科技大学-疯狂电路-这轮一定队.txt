第一章 引言
全国大学生智能汽车竞赛是以智能汽车为研究对象的创意性科技竞赛，是面向全国大学生的一种具有探索性工程实践活动，是教育部倡导的大学生科技竞赛之一。
竞赛以“立足培养，重在参与，鼓励探索，追求卓越”为指导思想，旨在促进高等学校素质教育，培养大学生的综合知识运用能力、基本工程实践能力和创新意识，激发大学生从事科学研究与探索的兴趣和潜能，倡导理论联系实际、求真务实的学风和团队协作的人文精神，为优秀人才的脱颖而出创造条件。
竞赛以竞速赛为基本竞赛形式，辅助以创意赛和技术方案赛等多种形式。竞速赛以统一规范的标准硬软件为技术平台，制作一部能够自主识别道路的模型汽车，按照规定路线行进，并符合预先公布的其他规则，以完成时间最短者为优胜。创意赛是在统一限定的基础平台上，充分发挥参赛队伍想象力，以创意任务为目标，完成研制作品；竞赛评判由专家组、现场观众等综合评定，目标是提高参赛队员创新能力，鼓励队员之间相互学习交流。
竞赛过程包括理论设计、实际制作、整车调试、现场比赛等环节，要求学生组成团队，协同工作，初步体会一个工程性的研究开发项目从设计到实现的全过程。竞赛融科学性、趣味性和观赏性为一体，是以迅猛发展、前景广阔的汽车电子为背景，涵盖自动控制、模式识别、传感技术、电子、电气、计算机、机械与汽车等多学科专业的创意性比赛。竞赛规则透明，评价标准客观，坚持公开、公平、公正的原则，保证竞赛向健康、普及、持续的方向发展。
全国大学生智能汽车竞赛组织运行模式贯彻“政府倡导、专家主办、学生主体、社会参与”的16字方针，充分调动各方面参与的积极性[1-3]。


第二章 系统整体设计
依据第二十一届全国大学生智能汽车竞赛疯狂电路组要求，本系统采用Infineon TC264作为核心控制器，整车由3S锂电池统一供电。系统主要由赛道信息采集、姿态检测、速度检测、电机驱动、涵道式负压控制以及人机交互等模块组成。总钻风摄像头用于采集赛道图像，LSM6DSRTR用于获取车体姿态信息，编码器用于检测车轮转速，为车辆控制提供实时反馈。
车辆运行过程中，TC264对摄像头、陀螺仪和编码器的数据进行综合处理，根据赛道偏差和车辆状态计算控制量，并通过DRV8701控制驱动电机，实现车模的启停、调速和运动控制。同时，TC264通过电调控制涵道式负压装置，提高车辆高速运行和转弯时的附着能力与稳定性。
系统还配有按键和显示屏，用于参数设置、模式切换和运行状态显示。整体形成“信息采集—控制计算—执行输出—反馈修正”的闭环控制结构，从而保证车模稳定运行。

第三章 自制车模机械结构设计与优化
3.1 自制车模总体结构方案
本车模采用自主设计的一体化结构方案，根据疯狂电路组比赛要求，对车体底盘、驱动机构、负压装置以及电路系统进行整体设计。整车在保证结构强度的基础上尽可能减小体积和重量，使车辆具有较低的重心和较小的转动惯量，从而提高高速运行和转弯过程中的稳定性。
车体两侧布置驱动电机及车轮，涵道式负压装置设置在车体中部，用于提高车辆与赛道之间的附着能力。主控、电机驱动、电源管理以及姿态传感器等电路均集成在一块主板上，其中LSM6DSRTR直接集成于主板，减少了独立模块和连接线束带来的空间占用及可靠性问题。3S电池根据整车重心位置进行布置，使车体前后重量分配更加合理。
总钻风摄像头安装于车模前部，用于获取前方赛道信息。显示屏和按键主要用于调试和参数设置，车辆正常运行时不随车安装，从而进一步降低整车重量并减少不必要的结构占用。整体设计以轻量化、一体化、低重心和高可靠性为主要目标，为后续整车高速稳定运行提供良好的机械基础。
3.2 底盘与车架结构设计
本车模基于龙邱科技疯狂电路Q车模改造，进行全自制化，优化部分机械结构，提升整体性能。具体改造如下：
3.2.1 底板材料与轻量化设计
车模底板采用1.5mm碳纤维板，在满足结构强度的前提下降低整体重量。底板设计中对非主要受力区域进行了大面积镂空处理，仅保留必要的连接边框、安装区域和加强结构，从而减少材料用量。
同时，通过增加斜拉杆和局部加强筋的方式代替单纯增加板厚，使底板在减重的同时保持足够的抗弯和抗扭能力。各部件安装位置也尽量共用底板本体，不额外增加过多支架和连接件，从而进一步降低整车重量，使结构更加紧凑。
碳纤维底板实物图见附录A，3D模型示例图见图3.1。

3.2.2 结构强度与装配方式
车模底板采用1.5 mm碳纤维板，在轻量化的同时具有较好的刚度。针对涵道风机工作时产生的振动，对风机安装区域进行了加宽，并在底板主要受力位置增加斜拉杆结构，使载荷能够更加均匀地传递，减小底板在高速运行及负压装置工作时产生的弯曲和扭转，提高整车结构稳定性。
装配方面，底板根据各部件安装位置预留固定孔，风机、驱动机构、电池及主板等部件通过螺钉或相应支架与底板连接。各部件位置在设计阶段统一规划，在保证连接牢固的同时尽量减少额外连接件，使整车结构更加紧凑，并方便后期拆装和维护。
底板周围设置多组预留安装孔，可根据实际调试需要调整部分部件的安装位置，同时减少后期重新加工底板的需求。
3.3 驱动与运动机构设计
车模驱动机构以轻量化、结构紧凑和响应迅速为主要设计目标，采用双电机独立驱动方案，并通过简单可靠的齿轮结构完成动力传递。左右驱动轮可根据车辆运行状态独立调节转速，通过两侧轮速差实现车辆转向。整体驱动结构尽量减少不必要的传动部件，在降低整车质量和机械损耗的同时，保证车辆具有良好的动力响应和运动灵活性。
3.3.1 驱动电机、车轮与传动结构
车模驱动部分采用龙邱科技030型直流电机，该电机体积小、质量轻，同时具有较好的动力输出和响应性能，能够满足轻量化车模的驱动需求。车轮轮毂由本队自主设计，在保证基本结构强度的前提下，对非关键受力区域进行了镂空处理，以降低旋转部件质量和整车负担。电机实物图片见图3.2。
传动结构采用较为直接的齿轮传动方式，由电机输出端齿轮带动车轮轮毂上的齿轮实现动力传递。整体结构简单紧凑，能够减少额外传动部件带来的重量和机械损耗，同时便于安装与维护。具体齿轮参数及轮毂尺寸根据整车实际调试情况进行匹配优化。传动结构3D示例图见图3.3。具体实物图见附录B。

3.3.2 转向与差速运动实现
车模采用左右驱动轮独立控制的差速转向方式，不额外设置机械转向机构。车辆直线行驶时，两侧驱动轮保持相近转速；进入弯道时，通过改变左右驱动电机的输出，使内外侧车轮形成一定的速度差，从而产生转向效果。
该方式省去了舵机、转向拉杆等机械结构，有利于减小整车尺寸和重量，同时使车体结构更加简单。实际运行过程中，主控根据赛道信息及车辆当前状态动态调整左右电机输出，实现直线、转弯及方向修正。具体差速控制量根据实际赛道测试进行调整，以兼顾车辆的转向响应与高速行驶稳定性。
3.4 传感器安装与空间布局
车模传感器根据其功能进行合理布置。编码器安装于轮毂后方，通过传动机构获取车轮转速信息；总钻风摄像头安装在底板最前端，以获得较大的前方视野和前瞻距离。整体布局兼顾检测效果、安装空间与整车重心，为后续传感器参数优化和车辆控制提供可靠基础。
3.4.1 摄像头安装高度与视场设计
总钻风摄像头安装于车模前端，安装高度约为15cm。摄像头的安装高度和俯仰角主要根据车模尺寸、赛道宽度及实际前瞻需求进行调整，使图像中能够保留足够的近端赛道信息，同时获得较大的前方视野。实际调试过程中，通过改变摄像头俯仰角对前瞻距离进行优化，在保证近处赛道边界识别稳定的同时，尽可能提高远处赛道信息的获取能力，为车辆提前判断弯道及进行方向控制提供依据。
具体安装角度和前瞻参数根据实际赛道测试效果进行调整，以兼顾识别稳定性与前瞻距离。具体实物图片见附录C。
3.4.2 编码器选型与安装
车模选用龙邱科技1024线Mini编码器进行速度检测，其质量约为1.5g，具有体积小、重量轻的特点，能够满足整车轻量化设计需求。编码器安装于轮毂后方，并通过传动结构获取车轮转动信息，将采集到的脉冲信号传输至MCU，用于计算车轮转速及车辆运行速度，为后续速度闭环控制提供反馈。编码器实物图见图3.4。轮毂编码器传动3D示意图见图3.5，实物图见附录D。

3.5 电池、电路板与线束固定
车模的电池安装于底板后侧，并采用魔术贴进行固定。该方式结构简单、重量较轻，同时便于电池的快速拆装和更换。电池位置结合整车空间与重心分布进行布置，在保证固定可靠的同时，尽量避免对其他部件安装造成干扰。电池固定部分实物图见附录E。
电路板通过自主设计的3D打印支架安装在侧板上，并采用M2纯钛螺丝进行固定。侧板内部嵌入滚花螺母，螺丝拧紧后能够形成较为可靠的咬合连接，使电路板在车辆高速运行及振动情况下仍能保持稳定。相比直接粘接，这种固定方式也更加方便后期拆卸、检查和维护。电路板固定实物图检测附录F。
在线束处理方面，对编码器等较细且容易松动的连接端口使用热熔胶进行辅助固定，减小车辆振动对接口接触可靠性的影响。电机线以及电调三相线则根据实际走线空间进行布置，尽量避免与车轮、齿轮等运动部件发生干扰。整体固定方案以结构简单、连接可靠和便于维护为主要考虑，在不过多增加额外重量的情况下保证整车电气连接的稳定性。

第四章 硬件电路系统设计
4.1 硬件系统总体方案
本车硬件系统以Infineon AURIX TC264为核心控制器，整车采用3S锂电池统一供电，并围绕赛道信息采集、车辆状态检测、驱动控制、负压控制以及调试交互等功能进行设计。为减小整车体积和质量，主控、电源管理、电机驱动以及姿态传感器等主要电路均集中设计在一块主板上，减少独立模块之间的连接线束，提高整车结构紧凑性和电气连接可靠性。
赛道信息主要由总钻风摄像头进行采集，图像数据送入TC264后用于后续赛道识别和路径判断。车辆姿态信息由集成在主板上的LSM6DSRTR六轴惯性传感器获取，编码器则负责采集车轮转速信息，两者共同为车辆运动状态判断和闭环控制提供反馈。驱动部分采用DRV8701电机驱动电路控制左右驱动电机，通过调节两侧电机输出实现车辆速度控制及差速转向。
除车辆行驶驱动外，系统还设置独立的涵道式负压机构，由TC264输出控制信号至电调，再由电调驱动涵道风机工作，以提高车辆运行时的附着能力。按键和显示屏主要用于程序调试、参数设置及状态观察，正常比赛运行时不作为随车必要部件安装，从而进一步减少整车负载。整体硬件方案在满足车辆基本控制需求的同时，兼顾了一体化、轻量化和连接可靠性。
按照系统功能，可将整车硬件划分为主控模块、电源模块、赛道信息采集模块、姿态与速度检测模块、电机驱动模块、负压控制模块以及调试交互模块。各部分均以TC264为信息处理和控制中心，完成传感器数据输入、控制计算以及执行机构输出。其中，3S 锂电池作为整车主要能源，经电源管理电路后为主控及各低压功能电路提供稳定供电，同时为驱动电机和涵道负压系统提供所需电能。总钻风摄像头将采集到的赛道图像信息传输至TC264；集成在主板上的LSM6DSRTR将车辆角速度和加速度信息送入主控；安装于轮毂传动位置的编码器将车轮转动产生的脉冲信号反馈至TC264，用于车辆速度计算。
TC264对摄像头、惯性传感器和编码器采集的信息进行综合处理后，根据当前车辆状态输出相应控制信号。驱动控制信号送入DRV8701，再由驱动电路控制左右两侧030电机，实现车辆前进、调速以及差速转向；负压控制信号则送入电调，通过改变电调输出控制涵道风机的工作状态。调试过程中，按键作为输入端用于参数选择与功能切换，显示屏作为输出端显示运行状态和调试信息。
因此，整车硬件信号关系可以概括为“传感器采集—TC264处理—执行机构输出—状态反馈”的控制结构。各功能电路围绕主控进行集中设计，使信号传输路径较为直接，同时减少了外部模块及连接线数量，为整车稳定运行提供硬件基础。
4.2 主驱电调一体板设计
为减小整车电路系统体积和重量，并降低模块间连接带来的故障风险，本车将主控、电机驱动、电调、电源管理及部分传感器电路集成在同一块PCB上，形成主驱电调一体化控制板。主控采用Infineon AURIX TC264，负责完成赛道信息处理、车辆状态采集、控制量计算以及各执行机构的协调控制。
车辆左右驱动电机分别由两路DRV8701驱动电路控制，配合外部功率器件实现电机的启停、调速及方向控制，从而完成车辆直线行驶和差速转向。与此同时，涵道式负压装置所需的无刷电调电路同样集成在主板上，由主控输出相应控制信号，通过电调驱动涵道风机工作，实现负压系统的调节。
在供电方面，整板由3S锂电池供电，并通过板载降压及稳压电路为TC264、传感器及外围电路提供所需的不同电压。关键电源节点配置滤波、去耦及保护器件，以减小电机和风机工作时产生的电源波动及电磁干扰对主控系统的影响。
此外，主板还集成了姿态传感器及摄像头、编码器、调试接口等相关电路，使车辆主要检测信号和执行控制信号能够直接在板内完成传输。通过这种高度一体化设计，可以有效减少外接模块和线束数量，使整车结构更加紧凑，同时有利于轻量化和后期安装调试。

第五章 软件控制系统设计
5.1 整体思路
疯狂电路车模的软件系统围绕赛道信息获取、路径判断和运动控制三个环节展开。程序采用双核协同方式，将图像处理与实时控制任务分开运行，并通过共享的道路状态和控制偏差完成信息交互，从而兼顾视觉计算效率与底层控制实时性。相关软件核心代码见附录G所示。
5.1.1 分层控制结构
执行层：完成驱动电机和负压风机的输出控制，并读取编码器等底层反馈信息。
控制层：根据车模与赛道中心的偏差调节左右轮速度，同时结合车体姿态信息改善转向过程的稳定性。
决策层：处理摄像头图像，提取赛道边界和行驶中心，并结合当前道路状态确定直行或转向策略。
5.1.2 多传感器信息融合
视觉摄像头用于获取赛道灰度图像，是道路识别和循迹控制的主要信息来源；IMU用于反映车体转动状态，辅助判断转向过程；编码器用于获取车轮运动信息，为速度闭环和行驶距离估计提供反馈。三类信息在不同环节相互补充，提高车模在复杂道路上的稳定性。
5.1.3 核心工作流程
车模核心工作流程如图5.1所示，主要过程如下：
（1）系统上电后完成摄像头、编码器、IMU、电机、负压风机和显示模块等初始化，并等待发车触发。
（2）满足发车条件后建立负压，车模采用平稳起步方式进入运行状态。
（3）运行过程中持续采集赛道图像和车体状态，对图像进行预处理并提取道路特征。
（4）根据当前道路形态和预定行驶方案作出方向决策，再由速度、方向控制器生成电机输出。
（5）上述过程循环执行，直至完成比赛任务或触发安全保护，随后停止驱动。

5.2 传感器数据处理
5.2.1 视觉图像处理
摄像头采集灰度图像后，程序先进行自适应二值化处理，使赛道区域与背景区域具有较明显的灰度差异。为适应现场光照变化，图像阈值会根据当前画面进行调整，避免固定阈值在阴影或强光环境下失效[4-5]。
在二值图像上由近及远搜索赛道边界，并根据左右边界计算中线。对多行中线信息进行加权与平滑处理后得到最终循迹偏差，既保留对前方道路趋势的响应，又减小局部噪声造成的控制抖动。
5.2.2 IMU 数据处理
IMU 输出车体角速度信息。程序对有效数据进行零偏校正和积分处理，获得车体转向过程中的偏航变化。该信息主要用于辅助转向控制和判断弯道动作是否完成，减少单独依赖视觉信息时可能出现的过转或不足。
5.2.3 编码器数据处理
左右轮编码器分别记录车轮运动脉冲，程序对采样结果进行简单滤波后作为速度反馈。除速度闭环外，编码器累计量还用于估计分段行驶距离，配合道路状态管理降低元器件和相邻路口对识别结果的干扰。
5.3 循迹与运动控制方案
5.3.1 视觉循迹
车模以图像中心附近的标定位置作为目标中线，将识别得到的赛道中线与目标位置比较，形成方向控制偏差。控制器根据偏差连续调整左右轮速度，使车模保持在有效道路范围内。
5.3.2 道路判断与路径选择
程序根据边界变化和道路连通特征区分普通直道、直角弯和多支路区域。对于存在多个可行方向的路口，车模按照赛前规划的行驶方案选择对应支路；完成一次道路动作后更新当前状态，继续识别下一个有效路口。
转弯阶段对目标中线进行适当修正，并结合车体偏航变化确定转弯结束时机。转弯完成后设置短暂的识别保护区间，避免同一路口或附近元器件被重复判断。
5.3.3 速度与方向控制
方向控制以视觉偏差为主，并引入IMU角速度信息抑制车体摆动。控制输出转换为左右轮的差速目标，使车模在不使用舵机的情况下完成转向。
左右轮分别采用速度闭环控制，根据编码器反馈修正电机输出。直道、弯道和复杂区域使用不同的速度策略，并在起步、入弯和出弯阶段平滑改变目标速度，以兼顾行驶速度与稳定性[6-7]。
5.3.4 发车与安全保护
发车流程采用状态机管理，可根据现场任务选择视觉目标或按键作为触发方式。触发后先建立负压，再进入车轮起步阶段，防止车体因瞬时输出产生较大扰动。
运行期间持续监测赛道图像、比赛时间和任务进度。当车模离开有效赛道、达到结束条件或触发其他保护状态时，程序立即停止驱动输出，保证车模运行安全。

第六章 开发工具
本车模从程序开发、电路设计到整车调试，需要多种软硬件开发工具相互配合。嵌入式程序主要采用英飞凌AURIX Development Studio进行编写、编译和调试；电路原理图及PCB使用嘉立创EDA专业版完成设计；整车调试阶段则配合VOFA+和逐飞科技串口助手，对运动控制数据和摄像头图像进行实时观察。上述工具共同构成了从硬件设计、程序开发到整车参数整定的完整开发环境。
6.1 嵌入式软件开发工具
本车模核心控制程序采用英飞凌AURIX Development Studio（ADS）进行开发。ADS面向AURIX系列微控制器，集成了工程管理、代码编辑、编译链接、程序下载以及在线调试等功能，能够满足TC264D控制程序的开发需求。
项目开发过程中，首先在ADS中建立TC264D工程，并根据整车硬件配置完成GPIO、PWM、定时器、串口以及相关外设驱动程序的编写。在此基础上进一步完成摄像头图像采集与处理、编码器测速、姿态数据读取、电机驱动、速度控制及车辆运动控制等程序。各功能按照一定的软件结构进行组织，便于后续功能修改和整车联合调试。
在程序调试阶段，可通过ADS的在线调试功能观察关键变量及程序运行状态，并结合断点、单步运行等方式定位程序运行中的异常。完成编译后，将生成的程序下载至TC264D主控芯片中，在车模上进行实际运行测试。通过多次修改、编译、下载和验证，逐步完成整车控制程序的完善。
6.2 PCB设计与制作工具
车模电路原理图及PCB采用嘉立创EDA专业版进行设计。该软件能够完成原理图绘制、器件封装管理、PCB布局布线以及电气规则和设计规则检查，并可与PCB制造流程直接衔接，便于完成设计文件输出和制板。
设计过程中，首先根据整车功能需求划分主控、电源、电机驱动、电调、传感器及外围接口等电路，并在原理图中完成各功能电路之间的连接。在确认基本电气关系后，根据自制车模底板尺寸、安装空间以及接口位置进行PCB外形和器件布局设计。
由于本车采用主驱电调一体化设计，PCB上同时包含主控、驱动和部分大电流电路，因此布局时需要兼顾电路板尺寸、器件安装位置和走线空间。主控及信号处理部分尽量集中布置，大电流驱动区域与弱信号区域合理分开，并根据不同电流需求调整相应走线方式，以减少驱动电路工作时对主控及传感器信号产生的影响。
PCB布局完成后，通过电气规则检查和设计规则检查排除明显的连接、间距及布线问题，之后生成生产文件并进行PCB制作。制板完成后进行元器件焊接和分模块测试，在各部分工作正常后再进行整车联合调试。
6.3 上位机调试工具
整车调试阶段主要使用VOFA+和逐飞科技串口助手两类上位机工具。由于车辆运行过程中，大量控制变量和图像信息无法直接通过肉眼观察，因此需要利用串口将单片机内部数据发送至计算机，并通过曲线或图像的形式进行可视化显示。其中VOFA+主要用于车辆速度、控制量等连续数据的观察，而逐飞科技串口助手主要用于摄像头图像及图像处理结果的显示。两种工具分别针对运动控制和视觉处理进行调试，可以较为直观地判断程序运行状态，从而提高整车参数调整和问题定位效率。
6.3.1 VOFA+
VOFA+主要用于车模速度环及运动控制参数调试。调试过程中，TC264D通过串口周期性发送目标速度、左右轮实际速度以及相关控制输出等数据，VOFA+将接收到的数据实时绘制为曲线。
通过同时观察目标速度与实际速度曲线，可以直观判断车辆加速过程中的响应速度、超调情况以及稳定后的速度偏差。当控制参数不合适时，曲线通常会出现响应过慢、波动较大或难以稳定等现象。根据这些现象对控制参数进行调整，再结合车辆实际运行效果进行多次测试，使左右轮速度控制逐渐稳定。
除了速度环调试外，在需要时也可将部分姿态数据、控制误差或电机输出量上传至VOFA+，辅助分析车辆在直线、加速和转弯过程中的状态变化。相比仅观察车辆实际运动情况，曲线能够更加直观地反映控制系统内部变化，有利于快速定位控制问题。
6.3.2 逐飞科技串口助手
逐飞科技串口助手主要用于摄像头图像上传及视觉算法调试。调试过程中，将总钻风摄像头采集到的原始图像或经过初步处理后的图像通过串口发送至上位机，在计算机端实时显示当前赛道成像情况。
通过观察上传图像，可以检查摄像头安装位置、俯仰角及当前光照条件对图像质量的影响，同时判断赛道边界、道路中心以及其他特征是否能够被稳定识别。当出现边界丢失、图像噪声较多或道路判断异常时，可结合图像显示结果检查对应的处理过程，并对摄像头参数或相关图像处理方法进行调整。
在整车调试过程中，逐飞科技串口助手主要解决“车辆看到了什么”的问题，而VOFA+则主要用于观察“车辆如何根据这些信息进行控制”。两者相互配合，可以同时从视觉感知和运动控制两个方面分析车模运行状态。
综上，本车开发过程中形成了“ADS程序开发—嘉立创EDA硬件设计—VOFA+控制调试—逐飞串口助手视觉验证”的开发流程。通过不同工具之间的配合，可以较为高效地完成程序编写、电路制作、功能验证及整车参数调整，为后续车辆稳定运行提供开发和调试基础。

第七章 结论
本项目围绕第二十一届全国大学生智能汽车竞赛疯狂电路组的任务要求，完成了轮式差速车模的软件设计与整车调试。系统以AURIX TC264D为控制核心，使用摄像头获取道路信息，结合IMU和编码器反馈，实现了赛道循迹、道路状态判断、行驶方向决策以及速度和方向闭环控制。
针对疯狂电路赛道光照变化明显、元器件分布密集和多支路道路容易误判等特点，车模采用自适应图像处理、状态化道路判断和预定路径选择相结合的方案，并在起步、转弯和复杂路段使用相应的速度策略。负压建立、平稳起步、出界检测和结束停车等保护流程，提高了车模连续运行的稳定性与安全性。
在调试过程中，使用ADS完成程序编译与在线调试，利用VOFA+观察速度环动态响应，并通过逐飞科技串口助手分析摄像头图像。曲线与图像两类调试手段相互配合，使控制问题和视觉问题能够分别定位，缩短了整车参数调整与故障排查时间。
目前系统已经能够完成预定的循迹和路径运行任务，但在复杂光照、赛道局部污染以及高速状态下仍存在进一步优化空间。后续可继续提高视觉算法对环境变化的适应能力，完善道路状态切换与异常恢复策略，并加强不同场地条件下的参数验证，从而提升车模的速度、稳定性和方案通用性。
通过本次智能车制作，参赛队员对嵌入式软件、图像处理、自动控制、电路设计和整车联调形成了更加完整的认识，也提高了工程问题分析、团队协作和方案迭代能力。

2.加权中线计算子程序
uint8 Find_line(void)
{
    uint32 mid_line_sum = 0;
    uint32 weight_total = 0;
    for (uint8 i = MT9V03X_H - 3; i > end_line; i--)
    {
        mid_line_sum += image_mid[i] * mid_weight[i];
        weight_total += mid_weight[i];
    }
    uint8 mid_line = (uint8)(mid_line_sum / weight_total);
    uint8 mid_out = (mid_last_line + 9 * mid_line) / 10;
    mid_last_line = mid_out;
    mid_err = Get_image_err(mid_out);
    return mid_out;
}

3.速度环控制子程序
float speed_pid_calc(int target, int input, Speed_Pid *pid)
{
    pid->error = (float)(target - input);
    pid->output += pid->ki * pid->error
                 + pid->kp * (pid->error - pid->last_error);
    pid->last_error = pid->error;
    pid->output = limit(pid->output, pwm_duty_max, pwm_duty_min);
    return pid->output;
}
