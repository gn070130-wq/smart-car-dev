第 1 章 引言
1.1 竞赛背景与项目概述
全国大学生智能汽车竞赛是面向全国大学生的综合性工程实践赛事，以自主行驶智能车模为载体，融合机械设计、嵌入式系统、自动控制、图像处理等多学科知识，重点考察学生的系统设计能力与工程创新能力。第二十一届赛事围绕车模自主巡线行驶核心任务，对参赛作品的机械可靠性、硬件集成度与算法稳定性提出了全面要求。
本参赛队以逐飞 N30Pro 车模为基础平台，通过差速动力方案、负压增稳设计与视觉巡线算法的结合，实现车模在赛道上的稳定、快速自主行驶。报告完整覆盖机械改造、硬件设计、算法实现与调试全流程，全面呈现参赛作品的技术细节与设计思路。
1.2 报告整体框架
本报告共设七章主体内容，辅以参考文献与附录材料。第二章介绍车模整体设计思路与系统架构；第三章阐述机械结构改造方案与元器件安装布局；第四章说明硬件电路的模块划分与设计思路；第五章讲解主控软件架构与核心控制算法；第六章记录开发制作流程与系统调试方法；第七章给出整车技术参数；最后总结设计成果，分析现存问题并提出改进方向。
第 2 章 车模整体方案设计
2.1 车模选型与设计目标
本次参赛选用逐飞 N30Pro 车模作为基础平台，该车模结构紧凑、机械强度高，适配差速驱动方案，能够满足高速巡线行驶的结构要求。设计核心目标为：实现赛道的精准识别与稳定行驶，通过机械优化与算法调校提升车模运行速度与过弯稳定性，同时保证系统集成度与运行可靠性。

图2.1 N30Pro车模装配体
2.2 系统总体架构
车模系统分为机械结构、硬件电路、软件算法三层架构：
机械层：以 N30Pro 车模底盘为基础，包含差速传动机构、负压风扇机构、传感器安装支架与减震结构，为整车提供机械支撑与运动执行能力。
硬件层：以 TC264D 主控芯片为核心，集成电源管理、电机驱动、传感器采集、人机交互等模块，实现信号采集、运算处理与动力输出的硬件闭环。
软件层：基于 AURIX Development Studio 开发环境，实现图像采集处理、赛道识别、姿态感知、运动控制等功能，是车模自主行驶的控制核心。
2.3 核心技术方案概要
动力系统采用左右双有刷电机差速控制方案，每侧有刷电机通过齿轮将动力传输至轮毂，齿轮传动比为 10:41；车模中心加装无刷负压风扇，通过增大下压力提升轮胎抓地力，保障高速行驶与过弯时的稳定性。
感知系统以逐飞总钻风摄像头为核心视觉传感器，通过采集赛道画面并进行图像分析完成比赛任务；辅以自制 AS5047P 编码器获取车轮转速信息，搭配 LSM6DSV16XTR 六轴陀螺仪采集车身姿态与转角数据，构成多传感器融合的感知体系。
控制算法采用扫线式赛道识别方案，根据图像识别结果判断赛道类型；直行路段执行直线行驶控制逻辑，转弯路段结合陀螺仪角度反馈实现闭环转向控制，达到预设角度后退出转弯状态，重新进行赛道扫描，形成 “识别 - 决策 - 控制 - 再识别” 的循环控制流程。

图2.3 N30Pro车模搭建实物














第 3 章 机械结构设计与安装
3.1 原车模基础与改造思路
逐飞 N30Pro 原车模具备完整的差速底盘与基础安装位，本次改造围绕减震优化、传感器适配、轻量化与结构可靠性四个方向展开。针对高速行驶下车身震动对摄像头成像与电路板可靠性的影响，重点优化了主板安装的减震结构；同时针对视觉传感器与编码器的安装需求，设计定制化固定结构，保证感知精度。
3.2 机械结构改造细节
3.2.1 减震结构优化
在原车模基础上延长上层固定柱，采用硅胶减震柱连接车模主体与全集成主板。该设计一方面可抵消车模高速行驶、过弯时产生的形变量，避免主板因受力发生弯曲损坏；另一方面硅胶材质可有效吸收机械震动，降低震动对摄像头画面稳定性与陀螺仪采集精度的干扰。

图3.2.1 车模与集成板通过硅胶柱连接

3.2.2 定制化结构件设计
使用 3D 建模软件自主设计并制作了车轮组件与摄像头固定件。摄像头固定件可精准调整总钻风摄像头的安装高度与俯仰角度，保证赛道画面采集的视野范围与清晰度；定制车轮与原车传动系统匹配，保障动力传递效率。

图3.2.2 自制摄像头支架与偏振滤光镜
3.3 传感器与电路板安装布局
3.3.1 传感器安装布局
总钻风摄像头：安装于车模前端上方固定支架处，镜头朝向赛道前方，保证足够的前瞻距离，为赛道识别预留反应时间。
AS5047P 编码器：自制编码器安装于车轮传动侧，与齿轮同轴布置，实时采集车轮转速数据，为速度闭环控制提供反馈。
LSM6DSV16XTR 陀螺仪：集成于主板中央位置，靠近车模重心处，保证车身姿态与角速度采集的准确性。
3.3.2 电路板安装与连接
全集成主板通过硅胶减震柱水平安装于车模上层空间，板上集成主控、驱动、电源与全部接口电路。板载 FPC 接口通过柔性排线连接前端摄像头；TFT 屏幕接口连接显示屏，用于实时显示运行参数；UART 串口、编码器接口、烧录接口均布置于主板侧边，便于调试与接线。

图3.3.2 全集成一体主板
3.4 机械连接与轻量化设计
整车大量采用铝制螺丝螺母进行结构连接，在保证连接强度与结构稳定性的同时，降低整车重量；同时铝制连接件防锈性好，拆装便捷，便于调试过程中的结构调整与硬件更换。





第 4 章 硬件电路系统设计
4.1 硬件系统总体架构
本次设计采用全集成单主板方案，将主控单元、电源模块、电机驱动、传感器接口、调试接口全部集成于一块 PCB 上，减少分体板间接线带来的故障点，提升系统集成度与可靠性。硬件系统以 TC264D 主控芯片为核心，向外延伸电源管理、动力驱动、感知采集、人机交互四类功能模块。


图4.1 PCB文件架构
4.2 核心功能模块设计
4.2.1 主控单元
主控采用英飞凌 TC264D 汽车级芯片，具备高性能多核处理能力，可同时满足图像处理、电机控制、传感器数据采集的运算需求，是整车的控制核心。
4.2.2 电源管理模块
板载 DC-DC 降压电路，将动力电池输入的电压转换为各模块所需的工作电压，为主控、传感器、电机驱动电路提供稳定供电，同时具备过流、过压保护功能，保障电路安全。
4.2.3 电机驱动模块
有刷电机驱动采用 DRV8701 双路 H 桥驱动芯片，分别控制左右两个有刷驱动电机，支持差速输出，实现车模的转向与加减速控制；无刷负压风扇驱动采用基于 STC32G 单片机的无刷电机驱动电路，控制中心负压风扇稳定运行，提供下压力。
4.2.4 传感器信号电路
板载陀螺仪 LSM6DSV16XTR 直接集成于主板，通过总线与主控通信；预留编码器接口，连接自制 AS5047P 编码器，采集转速脉冲信号；设计专用摄像头 FPC 接口，传输总钻风摄像头的图像数据。
4.3 接口与外设电路
主板集成丰富外设接口，包括 1.14 寸 TFT 屏幕接口、五向按键接口、UART 串口调试接口、TC264D 烧录接口、编码器接口。其中 TFT 屏幕与五向按键构成人机交互单元，可实时显示车速、赛道状态、陀螺仪角度等参数，通过按键可切换运行模式、调整控制参数；串口与烧录接口用于程序下载与在线调试。
完整电路板原理图详见附录 A。
第 5 章 软件系统与控制算法设计
5.1 软件开发环境与整体架构
软件开发基于 AURIX Development Studio（ADS）环境完成，采用 C 语言进行嵌入式程序编写。软件整体采用模块化设计，分为初始化模块、图像采集处理模块、传感器数据采集模块、运动控制模块、人机交互模块五大模块。
主程序运行流程为：系统上电后依次完成时钟、外设、传感器、电机驱动的初始化；进入主循环后，依次执行图像采集与赛道识别、陀螺仪与编码器数据读取、行驶状态决策、电机输出控制，同时通过屏幕与串口输出运行信息。
5.2 赛道识别扫线算法
赛道识别采用扫线算法作为核心视觉处理方案，算法流程如下：
摄像头采集一帧赛道图像后，对图像进行灰度化、二值化预处理，提取赛道边线特征；从图像底部向上逐行扫描，识别左右赛道边线的像素位置，计算赛道中心线；根据扫描得到的边线走势判断赛道类型：若连续多行中心线偏移量小于阈值，则判定为直道；若中心线出现持续单侧偏移，则判定为弯道。
该算法运算量小、实时性高，能够满足高速行驶下的赛道检测帧率要求，可稳定识别直道、弯道等基础赛道元素。

图5.1 部分扫线代码

5.3 行驶控制策略
5.3.1 直道控制
当算法判定当前赛道为直道时，执行直线行驶控制逻辑。以赛道中心线为基准，计算车模偏移量，通过差速调节修正行驶方向，使车模始终沿赛道中心线行驶；同时根据前瞻距离调整车速，直道阶段提升行驶速度。
5.3.2 弯道控制
当识别到弯道时，系统进入转弯控制流程。控制过程以 LSM6DSV16XTR 陀螺仪采集的车身转角数据为反馈：根据弯道曲率设定目标转角，通过左右电机差速输出实现转向；当陀螺仪检测到车身转过预设角度后，判定转弯完成，退出转弯控制环节，重新启动赛道扫描与识别，进入下一轮控制循环。
该控制方式将视觉识别与姿态反馈结合，避免弯道内视觉识别延迟带来的控制滞后，提升过弯的稳定性与响应速度。
5.4 核心代码设计说明
代码采用分层架构设计，底层为硬件驱动层，包含 GPIO、定时器、通信接口等外设驱动；中间层为算法层，包含图像处理、姿态解算、控制算法；应用层为业务逻辑层，实现整体行驶状态机调度。核心算法子程序代码详见附录 B。























第 6 章 系统制作与调试过程
6.1 开发工具与制作流程
开发过程使用的工具包括：
软件开发工具：AURIX Development Studio，用于主控程序的编写、编译与烧录；
机械设计工具：3D 建模软件，用于定制零件的结构设计；
辅助工具：3D 打印机、焊接工具、万用表等，用于硬件制作与测试。
整体制作流程为：3D 结构件设计与打印→PCB 电路板焊接与硬件测试→车模机械组装→软件烧录与系统联调。

图6.1 制作全集成PCB
6.2 车模组装与硬件调试
车模组装严格按照车模厂商提供的安装规范进行，依次完成底盘装配、传动机构安装、电机固定、主板与传感器安装、接线布线。组装完成后，先进行硬件通断测试与电压测试，确认电源电路无短路、各模块供电正常；再单独测试电机驱动、摄像头、陀螺仪、编码器等外设功能，验证硬件工作正常。
6.3 软件分段调试方法
软件调试采用分段赛道调试法：
搭建模拟测试赛道，将完整赛道拆解为直道、缓弯、急弯等多个独立路段；
针对单一路段单独调试对应控制参数，例如直道的速度参数、弯道的转角阈值与差速参数；
单段调试完成后，逐步拼接赛道进行联合调试，验证不同路段衔接处的控制逻辑切换是否流畅。
调试过程中使用手机作为录像工具，录制车模运行全过程，通过回放慢放观察车模行驶轨迹、姿态变化与问题出现的具体节点，精准定位代码逻辑或参数设置的缺陷，提升调试效率。
6.4 问题排查与优化过程
调试过程中针对高速行驶震动大、弯道识别不准等问题进行了优化：通过增加硅胶减震结构降低震动对图像的干扰；通过调整扫线算法的前瞻行数与二值化阈值，提升复杂光线下车道识别的稳定性；通过陀螺仪数据滤波处理，优化转角判断的精度，减少过弯冲出赛道的情况。

第 8 章 总结
本参赛作品基于逐飞 N30Pro 车模平台，完成了机械结构优化、全集成硬件电路设计与巡线控制算法开发，实现了车模的自主赛道巡线行驶。通过差速驱动 + 负压增稳的动力方案，提升了车模高速行驶的抓地力与稳定性；通过扫线算法结合陀螺仪反馈的控制策略，保证了赛道识别与转向控制的实时性。
目前车模可稳定完成直道、弯道等基础赛道元素的行驶，但在复杂赛道元素适配、极限速度优化等方面仍有提升空间。后续可进一步优化图像处理算法，增加更多赛道元素识别能力；同时通过机械轻量化调校与控制参数精细化整定，进一步提升车模的行驶速度与稳定性。

void speed_huan(int16 Target_Left,int16 Target_Right,int16 actual_Left,int16 actual_Right)
{
    int16 Error_Left=0;
    int16 Error_Right=0;
    
    // static变量：保存PID历史状态（需持续保留，仅初始化一次）
    static float result_Left=0, result_Right=0;       // 最终输出的PWM值（带方向）
    static int16 Error_Left_Last=0, Error_Right_Last=0; // 上一次误差（P/D环节用）右）
    
    // 1. 计算本次转速误差（期望转速 - 实际转速）
    Error_Left  = Target_Left - actual_Left;
    Error_Right = Target_Right - actual_Right;
    // ======================== 左电机PID计算 ========================
    
    // 2. 叠加PID增量到原有PWM值（核心：在原有占空比基础上调整）
   result_Left += speed_p_Left*(Error_Left-Error_Left_Last) + speed_i_Left * Error_Left;
   result_Right += speed_p_Right*(Error_Right-Error_Right_Last) + speed_i_Right * Error_Right;
   
   
    // 3. PWM输出限幅（防止超出电机驱动能力）
    if(result_Left > 9000) result_Left = 9000;
    if(result_Left < -9000) result_Left = -9000;
    if(result_Right > 9000) result_Right = 9000;
    if(result_Right < -9000) result_Right = -9000;

//    // 4. 更新PID历史状态（供下次计算使用）差
    Error_Left_Last = Error_Left;       // 上次误差 = 本次误差
    Error_Right_Last = Error_Right;

    
//    printf(":%f,%f\n",result_Left,result_Right);
   
    // 5. 硬件控制：设置PWM占空比 + 方向GPIO（核心逻辑不变）
    // 左电机：正负控制方向，绝对值控制占空比
    
    if(result_Left >= 0)        //左轮
    {
        pwm_set_duty(TCPWM_CH11_P05_2, (int)result_Left);
        gpio_set_level(P05_3, 0); // 正转方向电平
    }
    else
    {
        pwm_set_duty(TCPWM_CH11_P05_2, -(int)result_Left); // 取绝对值
        gpio_set_level(P05_3, 1); // 反转方向电平
    }
    // 右电机
    if(result_Right >= 0)
    {
      pwm_set_duty(TCPWM_CH09_P05_0, (int)result_Right);
        gpio_set_level(P05_1, 0); // 正转方向电平
    }
    else
    {
        pwm_set_duty(TCPWM_CH09_P05_0, -(int)result_Right); // 取绝对值
        gpio_set_level(P05_1, 1); // 反转方向电平
    }
}这个也是速度环

int16 Position(int16 Goal,int16 Actual)
{
  int16 xianfu = NOW_spped*75/100;//一般为速度的百分之70，太大会反转，不过有时转直角需要大一点
  
  static int16 Err = 0;
  static int16 Err_Low_Out = 0;
  static int16 Err_Low_Out_last = 0;
  static int16 result;
  double a = 0.8;//低通滤波系数
  double gyro_rate;//角速度
  
  gyro_rate = imu660ra_gyro_transition(imu660ra_gyro_z) ;
  
  Err = Goal - Actual;
  Err_Low_Out = (int16)(a*Err+(1-a)*Err_Low_Out_last);
  result = (int16)( (kp * Err_Low_Out) + kd * (Err_Low_Out - Err_Low_Out_last) - gkd*gyro_rate/ 10 );
  /*限幅*/
  if(result >= xianfu)
  {result = xianfu;}
  if(result <= -xianfu)
  {result = -xianfu;}
  Err_Low_Out_last = Err_Low_Out;
  return result;
}
