第一章 绪论
智能汽车融合了人工智能、自动控制、传感器技术与计算机视觉等多学科前沿成果，已成为交通智能化转型的核心方向。随着高级别辅助驾驶逐步落地，相关技术人才的培养需求也日益迫切。
全国大学生智能汽车竞赛是国内最具影响力的自动化类学科竞赛之一，自创办以来，始终以“立足培养、重在参与、鼓励探索、追求卓越”为宗旨。竞赛通过引导参赛者独立完成车模的机械搭建、电路设计、算法开发与系统调试，全面锻炼其工程实践与创新能力。二十年来，赛事在技术难度、平台多样性和参与规模上持续提升，成为检验高校工科教学成果的重要标尺。
为适应智能驾驶技术从场景模拟向特定工程问题解决转变的趋势，本届竞赛缩微组别特设“疯狂电路”赛道。该赛道要求车模沿电路图路线运行，并经过全部元器件，考察重点从单纯的循迹速度拓展至路径规划。车模需在缩微尺度下稳定识别电路节点并进行决策，这对传感器选型、图像处理及运动控制均提出了更高要求。
本报告围绕“疯狂电路”赛道任务，从设计方案、硬件设计、核心算法及调试优化等方面展开论述，总结参赛过程中的关键技术方案与实践经验。
第二章 系统设计方案
2.1 系统组成
智能车主要分为三部分：视觉检测系统、控制决策系统、动力系统。其中，视觉检测系统采用总钻风摄像头，控制决策系统采用TC264芯片，动力系统主要控制直流电机转速以及无刷负压。整体流程为：总钻风摄像头检测赛道路径与元器件等赛道信息，并将赛道信息发送给单片机，同时由编码器构成的反馈网络将智能车的运行状态发送给单片机，由单片机根据前方赛道信息与目前的电机运行状态进行处理与决策，并通过PWM信号控制直流电机进行相应操作，从而实现车体的转向控制和速度控制。
智能车的硬件电路由五部分组成：电源管理模块、MCU模块、无刷负压模块、有刷驱动模块、外设模块。
电源管理模块，给整个系统供电，确保系统安全稳定运行。
TC264芯片及其外围电路组成MCU模块，是整个智能车的“大脑”。
无刷负压模块拔高了整个智能车的上下限，对车模运行的稳定性具有巨大的提升。
有刷驱动模块采用DRV8701E制作双路有刷驱动，为直流电机运行提供条件。
外设模块中有摄像头接口连接总钻风摄像头获取赛道信息发送给单片机进行处理，是智能车的视觉部分。

第三章 机械结构设计与调整
今年我们参与的疯狂电路组别属于缩微赛道，最终成绩与整车重量挂钩，但缩微组别开放了车模自制，这为我们追求更低的重量和更好的结构提供了条件。
智能汽车竞赛的核心是控制策略和算法，但是机械结构的设计也是限制车模运行的一大瓶颈。因此，我们在自制车模时考虑各方面的影响，以便智能车具有更好地运行状态。
3.1 车板材料选择
我们选择碳纤维为智能车的车板材料，这种材料不仅轻盈坚固，而且具有极高的耐用性，能够在长时间的使用和高强度比赛中保持稳定性能。无论是面对复杂的赛道环境还是突发的碰撞情况，碳纤维底板都能提供可靠的保障。底板的高度也经过精心调校，使其在高速运行时也可以保持较低的中心，保证转向时的稳定。在进行结构设计时我们考虑到后面会加入负压来提高速度，所以在车板中预留好无刷电机的位置和风扇空间并设计了第二层碳板连接电路板和摄像头支架。
3.2 摄像头选择
在摄像头的选型过程中，我们综合考虑了分辨率、帧率、自动曝光、动态特性等关键参数。经过对比分析，我们最终选用了总钻风摄像头。该摄像头能够将采集到的图像灰度值以数组形式直接传输给单片机处理，省去了额外的图像采集卡；同时，该摄像头在动态性能方面表现优异，能够适应赛道光照变化。为了保证摄像头在循迹过程中图像稳定、不产生抖动，摄像头与底座的固定显得尤为关键，因此在安装前需要先确定合适的安装位置，并对摄像头的前瞻距离与视野宽度进行调整，以便获得更全面的赛道信息。
在摄像头的安装过程中，我们特别注意了摄像头底座连接的稳定性、摄像头的高度和摄像头与杆形成的夹角。这些都会影响到摄像头采集的图像。我们还编写好了程序，使得我们可以在显示屏上观察到摄像头采集的图像，方便调试。

3.3 编码器选择
速度是智能车竞赛成绩的重要评分标准，而编码器测试检测速度与反馈信号的核心传感器。考虑到性能以及重量，我们最终选择逐飞科技1024线增量式编码器Pro版，并将其实际安装在车模的尾部。这款编码器体积小、稳定性高、能在各种情况下稳定测速且重量约为1.5g。完全满足我们赛道的需求。为了保证测量的精准度，编码器的齿轮必需与直流电机输出端的齿轮实现可靠啮合，使得在运行过程中不会出现打滑等情况导致测量数据与实时数据不匹配。
第四章 硬件电路设计
为了保证电路板可以正常满足工作需求的同时具有较低的重量和方便连接，我们使用主驱一体集成板。这块板子主要分为五部分：电源管理、核心MCU、有刷双驱、无刷负压、外设接口及按键。
4.1 电源管理
电源开关部分使用AGM40P35A，作为一款P沟道MOS，具有极低的RDS。通过控制栅极电压，可以控制MOS的通断来给后级电路供电、断电。BZT52C16与电阻搭配可以构成一个防反接电路，若是发生电池电源接反等特殊情况时，不会烧坏后级元件与电池。同时AGM40P35A的栅极接住10k电阻到底，起到一个稳定的下拉作用，使得MOS的关断更稳定、更安全。
降压部分有两级：
一是使用TPS82130SILR降压芯片将12V降压到5V给后续的降压提供电源并给5V外设供电。该芯片带有功率电感、外置电路简单、整体回路所需PCB空间小，同时也能满足我们的需求，是制作降压电路的不错的选择。
二是使用两片RT9013-33GB芯片将5V降压至3.3V分别给TC264和其余3.3V外设供电，两路3.3V分别供电，增加安全性与可靠性。
同时，所有的降压电路均配有指示灯，方便我们观察供电的状态。

5.2 图像部分
5.2.1 图像采集与预处理
图像采集是整个视觉系统的第一步，也是决定后续处理质量的关键环节。本系统采用逐飞科技总钻风MT9V03X灰度摄像头作为视觉传感器，该摄像头具有分辨率高、图像清晰、帧率可调等优点。在实际使用中，考虑到图像处理速度以及车模运行速度，摄像头帧率设置为100FPS，在保证图像更新速度的同时，也为图像处理算法预留了充足的时间。
原始图像尺寸为188×120像素，虽然能够提供较为丰富的赛道信息，但若直接对其进行处理，将会消耗大量的计算资源，影响系统的实时性。因此，在图像处理流程的最前端，设计了图像复制与压缩两个预处理步骤。
图像复制环节的主要作用是去除摄像头镜头边缘的畸变区域并且避免图像撕裂。摄像头镜头在边缘位置通常存在一定程度的畸变，这些畸变区域中的像素信息并不可靠，若直接参与后续计算，可能会对边线检测和元素识别造成干扰。为此，在复制图像时舍去左右各4像素，仅保留中间180像素的有效区域，既去除了畸变影响，又减少了数据处理量。复制过程采用memcpy逐行批量操作，相较逐像素复制具有更高的效率。
图像压缩环节将188×120的图像进一步压缩为80×60，压缩比约为2:1。压缩采用等比例缩放策略，通过计算原图与压缩图的尺寸比例，对每个压缩像素点进行四舍五入取整映射。这一压缩策略虽然会损失部分图像细节，但对于智能车赛道识别任务而言，赛道本身具有明显的颜色特征和几何特征，压缩后的图像仍然能够保留完整的赛道走向和边界信息。更重要的是，压缩后图像的数据量仅为原始图像的25%，大幅降低了下游二值化、边线搜索等算法的计算负担，为高帧率处理奠定了基础。
在完成图像压缩后，系统还引入了伽马校正环节，用于调整图像的对比度特性。赛道环境中的光照条件复杂多变，实验室灯光、体育馆射灯、自然光等不同光源会导致图像整体偏亮或偏暗。伽马校正通过非线性变换调整图像的灰度分布，当伽马值小于1时，能够拉伸暗部区域的灰度级，使暗部细节更加清晰。本系统经过大量实验，将伽马值设置为0.4，在保留亮部信息的同时有效增强了暗部区域的对比度，使赛道与背景的区分更加明显。伽马校正采用查表法实现，预先计算好256个灰度级的映射表，实际校正时只需查表赋值，具有极高的执行效率。
5.2.2 二值化处理
二值化是将灰度图像转换为黑白图像的过程，是赛道识别中最核心的步骤之一。二值化效果的好坏直接决定了边线检测和元素识别的准确性。
本系统的二值化方案采用OTSU自适应阈值算法，该算法由日本学者大津展之于1979年提出，其核心思想是通过遍历所有可能的灰度阈值，计算该阈值下前景与背景的类间方差，选取使类间方差最大的灰度值作为最优阈值。相较于固定阈值法，OTSU算法无需人工预设阈值，能够根据图像内容自动计算出最佳分割阈值，具有良好的光照适应性。
在实际实现中，考虑到图像压缩后的尺寸已经较小，为充分保证阈值计算的准确性，系统使用压缩后图像的全部像素进行OTSU直方图统计。直方图统计完成后，通过前缀和技巧在O(256)的时间复杂度内完成类间方差计算，避免了嵌套循环带来的性能开销。同时，系统对OTSU的计算结果进行了可信度评估，当白点占比过低或类间差距过小时，认为OTSU结果不可靠，此时启用底部背景补偿策略：利用图像底部靠近车体的稳定区域统计背景灰度参考值，并根据底部区域的灰度标准差动态计算偏移量，生成修正后的阈值。
在阈值确定后，系统采用分区阈值策略对图像进行二值化。考虑到图像远中近不同区域的特性差异，分别为三个区域设定不同的阈值：远端区域阈值略高，以减少远处干扰像素的误判；中间区域采用标准阈值；近端区域阈值略低，以保证赛道边线的完整提取。这种分区策略能够在保证边线完整性的同时，有效抑制远端噪声的干扰。
二值化的执行过程是本系统的另一大优化亮点。传统逐像素二值化需要对每个像素执行阈值比较操作，在80×60的图像上需要执行4800次比较，且每次比较都伴随着分支判断，存在一定的性能损耗。本系统采用查表法结合32位批量处理的方案，首先为每个分区建立256长度的查找表，将灰度值到黑白值的映射预先存储。随后将图像指针转换为32位指针，一次读取4个连续的像素值，通过位运算并行提取每个像素的灰度值，查表后拼装为32位二值数据，一次性写回目标数组。这种方案将循环次数从4800次降低至1200次，配合查表法消除了分支判断，二值化效率相比逐像素方案有了质的提升。
5.2.3 边线检测与搜索
边线检测是从二值化图像中提取赛道边界的过程，也是后续赛道特征提取和元素识别的基础。本系统采用逐行边线追逐法，从图像底部向上逐行搜索左右边界。
图像底部行是距离车体最近的图像行，该区域的图像信息最为可靠，受远处光照干扰和透视畸变的影响最小。因此，边线搜索首先从第59行开始，在该行上从左右两侧向中间搜索连续白点，以确定底部行的左右边界位置。搜索策略采用连续两个白点作为判定依据，相比单个白点判定具有更高的可靠性，能够有效避免孤立噪声点的干扰。
在获得底部行的边界位置后，系统从第58行开始逐行向上搜索。对于每一行，搜索范围并非整个图像宽度，而是基于上一行边界位置在邻域内进行局部搜索，搜索范围为上一行边界位置±3像素。这种局部搜索策略充分利用了赛道边界在相邻行之间连续平滑变化的特性，在保证搜索准确性的同时，极大地缩小了搜索范围，提高了搜索效率。
在搜索过程中，系统通过识别跳变类型，将每行的边界状态分为三类：T类型表示正常跳变边线，即在该行的搜索范围内检测到了由黑到白或由白到黑的跳变，此时直接记录跳变位置作为该行的边界；W类型表示白边，即该行搜索范围内未检测到跳变且区域中心点为白色，此时标记为白边状态，边界位置取搜索区间的中点；H类型表示丢边，即搜索范围内未检测到跳变且中心点为黑色，此时标记为丢边状态，边界位置延续上一行的边界值。
对于检测到的W类型和H类型边线，系统会进一步进行重新确认处理。当检测到左边线为W或H时，系统会在整行从左往右重新搜索黑到白跳变，若仍然无法找到有效跳变，则根据最左侧点的颜色状态重新判定类型。右侧同理，从右往左重新搜索。这种二次确认机制有效提高了边线检测的准确性，避免因局部干扰导致的误判。
系统还引入了丢边计数机制，当连续丢边行数超过预设阈值时，根据丢边发生的行位置动态调整可视距离，提前终止搜索。这种机制一方面防止了在远处区域无效搜索浪费时间，另一方面也保证了可视距离的自适应调整，使系统在不同赛道环境下都能保持合理的视野范围。
5.2.4 赛道特征提取
在完成边线检测后，系统需要从边线数据中提取出用于控制决策的关键特征，包括可视距离、前瞻点和拐点位置等。
可视距离反映了车模在当前赛道条件下能够看到的有效赛道范围。系统从图像顶部向下搜索，找到第一个同时检测到左右边界的行，该行位置即为当前的可视距离。可视距离越长，说明前方视野越开阔，车模可以提前感知远处的赛道变化；可视距离越短，则说明前方存在弯道或元素，需要及时减速并调整控制策略。可视距离还用于计算白列高度，白列高度是动态前瞻控制的重要依据。
前瞻点是指用于计算图像偏差的参考行位置。传统固定前瞻策略在不同车速和赛道条件下难以兼顾响应速度和控制稳定性。本系统采用动态前瞻策略，根据白列高度实时调整前瞻点位置：白列高度较高时，说明当前处于直道或大曲率弯道，此时将前瞻点前移，使车模能够提前感知远处的赛道变化，提高直道行驶的稳定性；白列高度较低时，说明当前处于急弯或元素区域，此时将前瞻点后移，使控制更加关注近端赛道信息，提高弯道的通过性。动态前瞻的具体实现为前瞻点位置与白列高度呈负相关关系，白列每增加一定比例，前瞻点向前移动相应的行数，同时系统还对前瞻点设置了上下限幅，防止极端情况下的异常值。
拐点检测是赛道特征提取的另一项重要内容。拐点是指赛道边线状态发生变化的行位置，具体表现为从无边状态（W）恢复到正常边线状态（T）的位置。系统从上往下逐行扫描，首次检测到W→T跳变的行位置即为拐点，分别记录左拐点和右拐点位置。拐点信息对于直角转弯、十字路口等元素的识别和处理具有关键作用，也是分段补线策略的依据。
此外，系统还通过框检测技术提取图像特定区域的跳变特征。框检测是在图像中划定一个矩形区域，分别统计该区域上下左右四条边上的跳变次数和跳变类型，通过分析各边的跳变模式判断该区域是否存在特定的赛道元素。框检测的结果直接服务于元素识别模块。
5.2.5 赛道元素识别
赛道元素识别是本系统视觉处理的核心功能之一，其目标是从图像中检测出赛道上的各类特殊元素，包括左右直角、左右节点、T型节点和十字路口等。
元素识别的总体策略为“拐点定位+框检测确认”。首先通过拐点检测获得候选元素的位置信息，然后在候选位置附近执行框检测，根据框检测结果判定具体的元素类型。这种两阶段识别策略兼顾了效率和准确性，拐点检测筛选出可能存在元素的位置，框检测则对候选位置进行精确验证。
左直角的识别条件为：存在左拐点但不存在右拐点，且左拐点位置在预设的搜索范围内，同时左白色无边点存在而右白色无边点不存在，左右丢边点均存在，结合框检测结果判定是否为左直角。框检测的具体要求为上边界跳变次数为0、下边界跳变次数为2、左边界跳变次数为2、右边界跳变次数为0，这一模式与左直角的几何特征相匹配。
右直角的识别条件与左直角对称：存在右拐点但不存在左拐点，且右拐点位置在预设范围内，框检测要求为上边界跳变0次、下边界跳变2次、左边界跳变0次、右边界跳变2次。
左节点的识别不依赖拐点信息，而是直接进行框检测，当框检测结果显示上边界2次跳变、下边界2次跳变、左边界2次跳变、右边界0次跳变时，判定为左节点。左节点的典型特征是在左边界存在白黑交替的跳变模式，与二极管的几何形状相符。
右节点的识别与左节点对称，框检测模式为上边界2次、下边界2次、左边界0次、右边界2次。T型节点的识别模式为上边界0次、下边界2次、左边界2次、右边界2次，该模式对应T字路口在图像中的投影特征。十字路口的识别模式为四个边界均为2次跳变，呈完全对称的结构特征。
为避免元素被重复识别或误识别，系统为每种元素类型设计了独立的锁机制。当某类元素被识别后，对应的元素锁会锁定该类型，防止在短时间内再次触发相同的识别逻辑。元素锁在元素处理完成后或车模退出对应元素区域时解锁，保证每个元素只被处理一次。
5.2.6 元素处理与转向控制
元素识别完成后，系统需要根据元素类型执行相应的转向控制策略。元素处理的核心任务是根据元素类型和路径规划参数，计算车模的期望行驶轨迹，并将轨迹转化为具体的转向控制指令。
对于节点和十字类元素，系统首先需要精确定位元素的拐点位置。定位方法为在框检测区域的左右边界列上，从图像底部向上搜索黑白跳变点。具体而言，左边界搜索列位于框检测区域的左边界，右边界搜索列位于框检测区域的右边界。从第59行开始逐行向上检查，当检测到当前行为黑且上一行为白的跳变时，记录该行位置作为拐点。如果左右两侧均成功搜索到拐点，则取两者的平均值作为最终的拐点位置；如果某一侧未能搜索到，则使用默认值30。
在确定拐点位置后，系统采用分段补线策略对中线进行设定。拐点以上的行采用偏置模式：对于左转元素，将中线强制偏置到图像最左侧；对于右转元素，将中线强制偏置到图像最右侧。这种偏置策略能够使车模在进入元素之前提前转向，提高元素通过的流畅性。拐点以下的行则采用正常的中线计算模式，保证车模在元素出口处能够平稳过渡到正常赛道。
转向角度的实时跟踪采用陀螺仪积分的方式实现。系统在开始转向时记录当前时刻，通过积分陀螺仪的角速度信息实时计算已转过的角度，与目标角度进行比较得到角度偏差。当偏差小于预设阈值时，认为车模已完成转向动作，执行路径点切换和编码器清零操作，进入下一段行驶过程。
5.2.7 路径规划与全局导航
路径规划是本系统区别于传统智能车方案的核心亮点之一，它赋予了车模在复杂赛道中自主导航的能力，使其能够按照预设的全局路径完成整圈行驶。
（1）路径数据结构设计
系统设计了Pathtypedef结构体用于存储和管理路径信息，每个路径点包含四个核心要素：
目标角度：每个路径点的期望转向角度   
目标距离：到达该路径点所需行驶的距离   
速度决策距离：到达该路径点所需行驶的距离 
转向方向标志：L左转、R右转   
当前执行路径点索引   
路径总长度
该系统支持同时存储多套路径方案，分别对应不同的赛道布局，通过PathSwitch变量在赛前选择加载。路径参数在初始化时从预置数组中加载，预置数据根据赛道实际布局和车模性能标定得到。
（2）转向方向标志的深度应用
转向标志在系统中具有多重功能。它不仅指示了元素处理时的偏置方向，还与框检测结果协同判断当前所处的路径阶段。在实际运行中，当车模识别到元素并进入元素处理函数时，系统会检查当前路径点的转向标志：
‘L’标志触发左转处理：在拐点以上区域将中线强制偏置到图像最左侧，同时陀螺仪积分计算左转角度
‘R’标志触发右转处理：在拐点以上区域将中线强制偏置到图像最右侧，陀螺仪积分计算右转角度
这种设计使路径规划与元素识别紧密耦合，路径点不仅规定了“去哪里”，还规定了“怎么去”，实现了全局路径与局部控制的无缝衔接。
（3）多路径系统与赛道适配
系统支持两套独立的路径参数，分别对应预赛和国赛：
Path[0]：预赛路径
Path[1]：决赛路径
每套路径都包含完整的角度序列、距离序列、速度决策序列和转向标志序列，通过PathSwitch变量实现一键切换。这种设计使得车模能够在不修改代码的情况下快速适配不同赛道的路径规划需求，大大提高了系统的通用性和调试效率。
（4）编码器距离驱动的前进机制
路径点的切换由编码器距离驱动。系统在初始化时将第一个路径点的目标距离载入。随着车模运行，编码器不断累计行驶距离。当累计距离达到当前路径点的目标距离后，系统通过距离控制逻辑触发路径点切换
每个路径点完成转向后，系统会累加下一段的目标距离，形成连续的距离序列驱动车模前进。
（5）速度目标位置的路径耦合
路径结构中的memory_VEL_TAR_POS字段记录了各路径点对应的期望距离，与memory_target_distance协同工作。在速度决策模块中，系统根据当前距离与速度目标位置的差值判断车模处于赛道的哪个阶段，从而动态调整期望速度。这种设计使得车模能够在直道自动加速、在弯道和元素区域自动减速，实现了速度与路径的自适应匹配。
（6）强制直行模式的距离保护
在路径执行过程中，系统引入了强制直行模式作为安全保护机制。当车模已经识别到元素但尚未到达该元素的目标距离时，会进入强制执行模式，此时元素处理函数中的转向偏置被屏蔽，车模保持直行姿态。只有当编码器距离达到目标距离后，强制直行模式才解除，车模按照路径点的转向标志执行转向动作。
这一机制确保了每个转向动作都在精确的位置执行，避免了因提前转向或滞后转向导致的路径偏差，是路径规划精度的关键保障。
5.2.8 偏差计算与闭环控制
在完成边线检测、特征提取和元素处理后，系统需要将所有信息融合为最终的偏差值，用于控制系统的闭环反馈。偏差计算的核心思想是通过加权平均方法，将前瞻点附近的多行中线信息融合为一个稳定的偏差输出。
系统采用正态分布权重对前瞻点附近的20行中线值进行加权平均。权重分布呈中间高两端低的钟形曲线，前瞻点所在行的权重最高，随着行距增加权重逐渐降低。这种加权策略使偏差值主要反映前瞻点附近的赛道趋势，同时兼顾远端信息进行平滑滤波，在响应速度和稳定性之间取得了良好的平衡。
偏差计算的输入为每行计算得到的赛道中心位置。对于正常边线状态的行，中心位置为左右边界的均值；对于白边或丢边状态的行，中心位置已在前面的处理中被填充为合理值。在权重计算过程中，系统还排除了异常值的影响，当某行中线位置超出合理范围时，该行在加权平均中的权重被置零。
最终偏差输出加权平均后的图像中线位置，与图像中心位置的差值即为图像偏差img_err。该偏差值通过共享内存传递给控制核心，作为串级PID控制器的输入量。
5.2.9 停车保护机制
系统设计了双重停车保护机制，确保车模能够可靠地停在终点线。
第一重停车保护基于图像信息。当可视距离达到55行以上，且图像底部中间区域的三个关键点均为黑色时，判定为到达终点区域，启动停车计数。当连续检测到停车条件超过设定帧数后，置位停车标志stop_flag，触发停车动作。
第二重停车保护基于编码器距离。当车模累计行驶距离达到预设的总行程位置，且当前路径点索引已到达路径终点时，直接置位停车标志。这一机制作为图像停车的冗余保障，即使在光线极端恶劣导致图像识别失效的情况下，车模依然能够依靠距离信息完成停车。
5.3 控制部分
控制部分是连接视觉系统与动力系统的核心环节，本系统采用双核分工的组织方式：CPU1负责摄像头图像的采集与处理，将解算出的赛道中线偏差通过共享变量实时传递给控制核心；CPU0负责运动控制，以1ms周期的定时中断作为电机控制主循环，依次完成编码器读取、图像偏差解算、陀螺仪角速度采样与PID运算，最终输出左右电机的PWM占空比。同时CPU0还以10ms周期扫描按键状态，以20ms周期完成启动延时、负压调节以及堵转、翻车等安全状态检测，保证了控制的实时性与可靠性。
转向控制采用“图像偏差—角速度”串级PID结构。外环以图像偏差为输入，偏差先经过一阶低通滤波去除毛刺，再由带自适应比例系数的控制器映射为目标角速度：比例系数随偏差的平方增大而增大，使小偏差时转向平缓、大偏差时响应迅速，二次项进一步增强了急弯工况下的转向力度，微分项经过低通滤波以抑制噪声放大；内环以陀螺仪实测角速度与目标角速度的偏差构成角速度闭环，采用“微分先行”的PD结构，微分项只对陀螺仪测量值求差，避免了目标值突变引起的微分冲击，同时叠加目标角速度变化的前馈补偿，输出经限幅后作为差速转向的修正量。
期望速度由速度决策模块综合行驶里程与图像信息生成。系统将赛道各路段对应的速度目标位置预先标定并保存在路径结构体中，运行时根据编码器累计距离与目标位置的差值判断当前所处路段，分段确定最大期望速度，并对直角、节点等特殊路段单独设置较低的限速值；速度变化按照最大加速度限制分步逼近目标速度，避免急加速与急减速；此外期望速度还随图像偏差的增大而线性下降，实现“直道自动加速、弯道自动减速”的自适应调节。
速度环对左右轮分别进行闭环控制，采用增量式PID结合前馈补偿的方案。编码器计数先经过一阶低通滤波抑制高频噪声，速度误差通过增量式PID运算得到PWM增量，同时根据目标速度及其变化率计算速度前馈与加速度前馈，并叠加库仑摩擦前馈项以克服电机静摩擦带来的死区，三项前馈与PID输出相加后经限幅得到最终的PWM占空比，使车模在匀速与加减速过程中均能精确跟踪期望速度。
转向与速度的融合通过差速实现。转向环输出的修正量以相反的符号叠加到左右轮的速度误差上，即左轮期望速度减去修正量、右轮期望速度加上修正量，再分别送入左右轮速度环进行闭环控制，在保持平均车速基本不变的同时完成转向，使速度控制与转向控制相互解耦，便于两套参数独立整定。
系统利用编码器与陀螺仪实现航位推算。编码器脉冲按标定的比例换算为行驶距离，结合陀螺仪积分得到的偏航角，实时解算车模在场地坐标系中的位置坐标，该坐标通过调试串口上传至上位机用于轨迹回放与路径验证，并与预置路径的距离信息配合，作为路径点切换和停车判断的冗余依据。
为保证运行安全，系统设计了完整的启动流程与保护机制。上电后先进行陀螺仪零偏校准，取启动阶段多次采样值的平均作为偏航角零位，并对90°、180°等特征角度进行整化处理；按键确认发车后开启无刷负压，负压占空比按固定周期逐步缓升至限幅值，电机控制中断在按键使能后延时约1.6s再开启，为负压建立留出时间；运行过程中实时检测堵转状态与翻车状态，一旦触发立即同时关闭电机与负压；停车采用图像停车线与编码器总里程双重判断，确保车模准确停在终点区域。
第六章 系统开发环境
6.1 开发调试工具
使用的开发工具为AURIX Development Studio，该软件是一款专为英飞凌TriCore MCU系列设计的集成开发环境，它在Eclipse环境下支持使用C语言和英飞凌底层驱动库（iLLD）进行开发，并提供多核心在线调试功能。

6.2 人机交互工具
在调试过程中需要不断观察、改变参数，我们使用显示屏与按键配合完成此功能。
显示屏我们使用TFT显示屏，具有尺寸大、高分辨率等特点，符合我们的需求。
6.3 蓝牙及上位机调试
控制算法的调试是一个反复观察与修改的过程，仅靠显示屏上的数值难以观察参数的动态变化趋势。为此，我们采用蓝牙与上位机相结合的调试方案，在车模运行过程中实时传输并显示各项运行数据，实现了“边跑边看、边看边调”的高效调试流程。
系统将串口0配置为115200波特率的调试串口，主循环按照“数值1,数值2,……,数值n\n”的逗号分隔格式周期性输出十五路运行数据，包括左右轮编码器实测速度、左右轮目标速度、陀螺仪角速度、目标角速度、图像偏差、转向修正量、转向角度差、瞬时车速、行驶里程、里程计坐标以及期望速度等，上位机按帧解析后即可对全部数据进行实时观察，方便直观。
上位机选用逐飞科技出品的逐飞助手软件（Seekfree Assistant），其内置的虚拟示波器支持多通道波形同步显示，可以直观地对比期望值与实际值的跟随情况。调试转向环时，同时观察目标角速度与实际角速度两条波形，根据两者的跟随速度与超调情况调整外环比例系数；调试速度环时，对比左右轮目标速度与实际速度波形，观察稳态误差与振荡情况，配合调整比例、积分、微分及前馈系数，直至波形平稳、响应迅速。
为摆脱调试线对车模运动的束缚，实现整车运行过程中的实时监视，车模主板上预留了蓝牙串口模块接口。蓝牙模块采用沁恒CH9141芯片，支持蓝牙与串口之间的透明传输，模块与单片机调试串口连接后，在上位机侧插入蓝牙适配器完成配对，即可将调试数据以无线方式转发到上位机，通信波特率与有线调试保持一致。这样在车模高速通过弯道、节点等工况时也能连续记录数据，同时避免了调试线对车模姿态的干扰，提升了调试的安全性与数据完整性。
逐飞助手还提供摄像头图像显示功能，可以实时查看车模摄像头采集的原始灰度图像以及算法提取的赛道边线、中线，边线与中线以不同颜色叠加显示。图像处理中的丢边、补线错误、元素误判等问题均可以通过图像直观地发现，我们对图像处理算法的大量改进都是借助该功能完成的。
除数据观察外，逐飞助手还支持参数在线调节功能。工程中集成了逐飞助手通信库，单片机通过串口中断解析上位机下发的指令，实时修改转向环、速度环的PID参数，无需反复编译烧录即可完成多组参数的对比试验，显著缩短了调参周期。结合按键与显示屏，我们在赛前完成了多套参数组的标定，并可通过路径切换选择适用于不同赛道工况的参数组合。
通过“上位机波形观察、摄像头图像查看、参数在线调节、按键与显示屏交互”的组合调试手段，我们对转向环、速度环、负压控制等各部分进行了大量迭代优化，最终获得了稳定可靠的参数组合，为车模的高速稳定运行提供了保障。

// 函数简介     左轮PWM值增量式PID控制
//根据增量式离散PID公式
//pwm+=Kp[e（k）-e(k-1)]+Ki*e(k)+Kd[e(k)-2e(k-1)+e(k-2)]
//-------------------------------------------------------------------------------------------------------------------
void PID_speed_left(int *encoder, int *error, int *motor)
{
    static float e, e1, e2, e_filt, v_tar, v_tar_last, a_tar, a_tar_delay = 0;
    static int enc_pid_out = 0;
    float P = 0,I = 0,D = 0;
    float a = 0.2;
    static int count = 0;
    e = (float)(*error);
    e_filt = (1-a)*e + a*e1;
    P = PID_parameter.speed_L_KP*(e_filt - e1);
    I = PID_parameter.speed_L_KI*e_filt;
    D = PID_parameter.speed_L_KD*(e_filt - 2*e1 + e2);
    enc_pid_out += (int)(P+I+D);
    v_tar = *encoder + e;
    a_tar = (v_tar - v_tar_last)/Ts_sec;
    v_tar_last = v_tar;
    if(a_tar != 0 || count == 1)//冲击函数
    {
        count ++;
        if(count == 2){a_tar_delay = a_tar_delay*1.0;}
        else{a_tar_delay = a_tar;}
    }
    float sgn = (v_tar > 1.0f) ? 1.0f : (v_tar < -1.0f ? -1.0f : 0.0f);
    float FF  = K_a_ff_l * a_tar_delay + K_w_ff_l * v_tar + K_c_ff_l * sgn;
    if(count == 2){count = 0;a_tar_delay=0;}
    *motor = enc_pid_out + (int)FF;
    speed_limit(motor);
    e2 = e1;
    e1 = e_filt;
}

//-------------------------------------------------------------------
// 函数简介     图像误差低通滤波
// 参数说明     raw_error  原始图像误差
//-------------------------------------------------------------------
float process_camera_error(float raw_error)
{
    static float last_filtered = 0;
    float filtered;
    filtered = PID_parameter.err_filter_a * raw_error + (1.0f - PID_parameter.err_filter_a) * last_filtered;
    last_filtered = filtered;
    return filtered;
}
//-------------------------------------------------------------------
// 函数简介     串级PID外环 —— 图像误差映射为目标角速度
// 参数说明     error  滤波后的图像误差
//-------------------------------------------------------------------
float PID_camera(float error)
{
    float motor_kp, motor_kd;
    float out_p, out_d, out_kp2;
    float derivative, filtered_derivative;
    static float last_error_cam = 0;
    static float last_derivative_cam = 0;
    //自适应KP：误差平方修正
    motor_kp = error * error * PID_parameter.cam_KP_a + PID_parameter.cam_KP_b;
    motor_kd = PID_parameter.cam_KD;
    out_p   = motor_kp * error;
    out_kp2 = PID_parameter.cam_KP2 * error * fabsf(error);
    // D项低通滤波 —— 防噪声放大
    derivative = error - last_error_cam;
    filtered_derivative = derivative * 0.9f + 0.1f *last_derivative_cam;
    last_derivative_cam = filtered_derivative;
    out_d = motor_kd * filtered_derivative;
    last_error_cam = error;
    float out = out_p + out_d + out_kp2;
    if (out >  PID_parameter.cam_out_max) out =  PID_parameter.cam_out_max;
    if (out < -PID_parameter.cam_out_max) out = -PID_parameter.cam_out_max;
    return out;
}
//-------------------------------------------------------------------
// 函数简介     串级PID内环 —— 角速度闭环（纯PD，微分先行）
// 参数说明     target  外环给出的目标角速度（与陀螺仪同量纲，°/s）
//              gyro    陀螺仪实测角速度（°/s）
float PID_omega(float target, float gyro)
{
    static float gyro_d_filt = 0.0f;   // D项专用：陀螺仪低通滤波状态
    static float gyro_d_last = 0.0f;   // 上一拍滤波后的陀螺仪值
    static float a_tar_last = 0.0f;
    float e = gyro - target;           // 误差，符号与原实现一致（gyro - target）
    float out_p, out_d, out_ff;
    // 微分先行：D只对陀螺仪测量值求差（=角加速度阻尼），目标突变不产生微分冲击
    gyro_d_filt = PID_parameter.omega_d_filter * gyro + (1.0f - PID_parameter.omega_d_filter) * gyro_d_filt;
    out_p = PID_parameter.omega_KP * e;                              // 比例：纠正角速度偏差（刚度）
    out_d = PID_parameter.omega_KD * (gyro_d_filt - gyro_d_last);    // 阻尼：反对角加速度变化
    out_ff = -PID_parameter.omega_FF * (target - a_tar_last);                       // 前馈：omega_FF=0 时等效关闭
    a_tar_last = target;

    gyro_d_last = gyro_d_filt;
    return out_p + out_d + out_ff;
}

void PID_YAWRATE(int *gyro_rate, int *steer_out, int *target_rate)
{
    // 内环：纯PD跟踪目标角速度（微分先行，无积分），输出限幅保持不变
