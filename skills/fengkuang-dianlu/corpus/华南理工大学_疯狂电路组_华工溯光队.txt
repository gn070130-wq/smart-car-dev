摘  要
本技术报告围绕第二十一届全国大学生智能汽车竞赛疯狂电路组参赛任务，系统阐述了华南理工大学华工溯光队自主设计、制作微型智能车模的完整技术方案与开发过程。报告从机械结构、电路硬件、软件算法与系统调试四个层面展开：机械层面介绍了全差速转向车模的整体结构与传感器布局方案；电路层面介绍了主控与驱动一体化主板及可插拔调试小板的设计思路；软件层面介绍了以视觉循迹为核心的图像处理、路径识别与闭环控制技术链路，以及面向高效调试的人机交互与无线通信系统；最后汇总了车模的主要技术参数，并总结了开发调试过程中的典型问题与解决方案。本报告侧重于方案设计思路、技术路线选择与系统架构层面的阐述，力求为同类智能车模的设计提供有益参考。
关键词：智能汽车；全差速转向；视觉循迹；图像处理；PID控制；嵌入式系统


引  言
全国大学生智能汽车竞赛是由教育部高等学校自动化类专业教学指导委员会主办的全国性大学生科技竞赛，自创办以来已成功举办二十一届，现已成为我国自动化及相关领域最具影响力的大学生学科竞赛之一。竞赛以"立足培养、重在参与、鼓励探索、追求卓越"为指导思想，以智能汽车为研究对象，要求参赛学生自主完成方案设计、车模制作、算法开发与系统调试的全过程，旨在促进高等学校素质教育，培养大学生的综合知识运用能力、基本工程实践能力和创新意识。竞赛内容涵盖自动控制、模式识别、传感技术、电子电气、计算机、机械设计等多个学科领域，对参赛学生的知识融合能力和实践动手能力提出了较高要求。
第二十一届智能汽车竞赛疯狂电路组作为竞速类赛道的重要组成部分，要求参赛队伍在高度约束的物理尺度内，自主设计并制作能够自动识别赛道、自主决策行驶路径的微型智能车模。该组别赛道以电路图为蓝本，在蓝色底布上使用白色胶带（宽度约20mm）铺设电路导线与元器件图形，构成包含串联回路、并联支路和反馈回路在内的完整电路拓扑。元器件均封装在边长小于15cm的方框内，有源器件（三极管、晶闸管等）处形成T型分支路口。与传统的闭合环道竞速不同，该组别要求车模在理解电路拓扑的基础上，沿导线自主行驶并尽可能遍历所有回路，对路径规划能力和实时决策能力提出了较高要求。
华南理工大学"华工溯光队"由来自自动化科学与工程学院、机械与汽车工程学院等多个院系的本科生组成，队员各有所长、分工明确，分别承担机械结构设计、电路硬件搭建、软件算法开发和系统集成调试等工作。在备赛过程中，队伍遵循"需求分析—方案设计—样机搭建—联调测试—迭代优化"的工程化开发流程，充分发挥跨学科协作优势，进行了系统性的探索与实践，力求构建结构紧凑、运行稳定、便于快速迭代的智能车模系统。本技术报告即是对上述工作的全面总结和系统阐述。
本报告的结构安排如下：第一章介绍车模的机械结构总体方案与传感器布局；第二章阐述电路系统的设计思路与关键技术；第三章作为报告核心，系统论述软件系统的整体架构设计和各功能模块的实现方案；第四章介绍开发工具链和调试方法；第五章汇总车模的主要技术参数。此外，附录中附有部分功能模块的示意性源代码以及车模与电路板图片。

第一章  自制车模整体设计
1.1  车模机械结构总体方案
在疯狂电路组赛道环境中，赛道内侧锥桶距引导线仅12cm，车模需在极限空间内完成高速转向。综合考量转向半径、机械占用空间和动态响应等因素，本车模最终采用全差速转向架构，通过左右两侧驱动轮的独立速度控制实现转向，取消了传统舵机转向机构，结构更为紧凑。
车模的机械系统由以下几部分构成：底盘作为整车的核心基础结构，预留有负压风扇安装孔、摄像头座子安装孔以及电池安装区域。底盘下方贴合负压膜，形成密闭的负压腔体。侧板通过螺丝与底盘垂直连接，构成稳固的车体框架。侧板上安装有两个无刷电机作为驱动动力源，轮毂直接套设在无刷电机的输出轴上，胎皮套设在轮毂上，传动结构紧凑高效。为精确获取电机转速信息以进行速度闭环控制，在无刷电机尾端安装有磁编码器，配合径向磁铁实现非接触式转速测量，并通过主板集成的电机驱动电路进行数据处理与控制。
底盘采用轻质板材加工而成，作为整车核心承载结构。底盘盘面预留有负压风扇的安装通孔和摄像头座子的固定孔位，并规划了电池的专属放置区域。底盘下方粘贴有柔性负压膜，与赛道表面之间形成负压腔体。负压电机固定安装于底盘上方，其输出轴带动负压风扇高速旋转，抽吸负压腔体内的空气，在轮胎与赛道表面之间产生额外气动下压力，从而提升车辆的附着极限和过弯速度。底盘与侧板之间通过螺丝紧固，在保证结构强度的同时便于拆装维护。
车模的主板（PCB）直接安装固定于侧板上，省去了传统顶板结构，既简化了结构层次，又有效降低了整车质心高度，同时缩短了传感器与主控芯片之间的信号走线距离。主板预留电源接口与底盘电池槽中的锂电池连接，为全车各用电模块统一供电。此外，摄像头杆子穿过主板上的预留通孔，杆子上的固定件通过两个螺孔与主板锁紧连接，形成双重稳固结构，确保在高速行驶和剧烈转弯过程中摄像头不会发生晃动或移位。
摄像头支架固定于底盘前部的摄像头座子上，向上延伸使摄像头能够获得足够的高度以采集充分的赛道前视信息。摄像头杆子不仅承担图像采集功能，还通过其与主板之间的双孔连接结构，同时起到加固主板、增强车体整体刚度的作用，体现了结构复用和紧凑化设计的思想。
1.2  传感器布局与安装
车模搭载的传感器系统主要由视觉传感器、惯性测量单元和电机位置传感器三类组成，各传感器在车体上的安装位置根据其功能需求进行了针对性设计。
视觉传感器采用全局快门CMOS图像传感器，配合广角镜头使用，安装于车模前部上方。相比卷帘快门传感器在高速运动时产生的"果冻效应"（因逐行曝光时间差导致的图像扭曲），全局快门传感器在同一时刻对所有像素进行曝光，从根本上避免了运动畸变问题。广角镜头的大光圈设计保证了短曝光时间条件下的充分进光量，使得在高帧率运行时仍能获得亮度充足的图像。
惯性测量单元（IMU）以模块形式安装于主板。该传感器用于实时测量车体绕各轴的旋转角速度，经积分运算后可获取车模的姿态角信息，为视觉系统在复杂路段（如急弯路段）提供辅助的姿态参考数据。
电机位置传感器采用磁编码器方案，安装于左右驱动电机的尾端。该传感器通过检测安装于电机转轴末端的径向磁铁的旋转磁场变化，实时输出电机转子的角度信息，为主板集成电调的磁场定向控制（FOC）提供精确的换相依据。

第二章  电路设计
2.1  主板电路设计（主驱一体）
主板电路采用主控与电机驱动一体化（主驱一体）设计，将TC264主控芯片、无刷电机双驱电调、电源管理及外设接口全部集成于同一块PCB上，避免了传统分立方案中主板与驱动板之间的连接器损耗和信号走线延迟。主板承担以下核心功能：其一，运行视觉处理与运动控制算法并输出双路无刷电机FOC驱动信号；其二，为后级大功率负载（负压风扇等）提供可控的12V电源通路；其三，将锂电池电压转换为各逻辑电路模块所需的不同电压等级并滤波稳压；其四，提供各传感器模块之间的信号互连接口。
在实际调试过程中，我们发现电机在启动和变速瞬时的电流峰值远超常规机械开关的额定承受能力。即使开关标称电流远高于电机稳态工作电流，瞬时浪涌电流仍会导致触点烧蚀和开关永久失效。针对这一问题，本设计采用PMOS电子开关方案：由低压小电流的机械开关控制PMOS功率管的栅极电压，PMOS管作为主通路开关承载大电流。由于流经机械开关的仅为mA级别的栅极控制电流，远低于其额定值，开关的使用寿命和可靠性得到了根本性改善。
电源转换链路采用两级降压架构。第一级使用同步整流DCDC降压电路将12V电池电压转换为5V，实现高效率的降压升流转换。第二级根据各用电模块的需求，通过多个独立的低压差线性稳压器（LDO）将5V分别降至3.3V，为摄像头、陀螺仪、主控MCU、TFT屏幕等模块独立供电。独立LDO供电方案有效避免了各模块之间通过电源线路的串扰耦合。
在电磁兼容性方面，本设计采取了多项噪声抑制措施。PCB布局上将数字电路区域和模拟电路区域的地平面进行物理分割，仅在一点通过0Ω电阻桥接，并在此处并联磁珠，利用磁珠在高频下的高阻抗特性将数字电路产生的高频噪声以热能形式耗散，防止其通过地平面耦合至敏感的模拟电路区域。同时，为抑制DCDC开关电源的传导噪声，在电源输出通路中串联磁珠构成LC滤波网络，并在开关节点增加RC吸收电路以抑制开关管导通和关断瞬间产生的振铃。
集成无刷电机双驱电调
主板集成无刷双驱电调模块，采用磁场定向控制（FOC）原理驱动左右两路无刷电机。电调部分的核心控制芯片选用Infineon CYT2BL3，该芯片集成了ARM Cortex-M0+内核和丰富的电机控制外设资源，能够胜任FOC所需的Park/Clark坐标变换、SVPWM空间矢量调制和相电流采样等实时计算任务。双路电调共用一路供电输入，独立输出两路三相驱动信号至左右电机。
转子位置反馈采用高精度磁编码器方案。该编码器通过三轴霍尔传感器阵列检测径向磁铁的旋转磁场，提供数字量角度输出。编码器直接安装于电机转轴末端，通过数字接口与CYT2BL3通信，为FOC算法提供实时转子角度信息。
主控TC264与电调芯片CYT2BL3之间通过UART串口进行全双工数据通信。主控向电调下发包含左右轮目标速度的指令帧，电调向主控上报包含编码器里程数据的反馈帧，通信协议包含帧头同步、数据载荷和校验等标准字段。由于主控与电调位于同一PCB，通信链路极短且不受外部电磁干扰影响，数据传输的实时性和可靠性优于分立板间通信方案。
2.2  调试小板设计
为满足赛道边调试的实际需求，我们设计了可插拔的独立调试小板。该小板集成了TFT彩色显示屏、按键输入阵列和无线通信模块接口，通过FPC排线与主板连接，在调试时安装使用，正式竞速时可拆卸以减轻重量和降低功耗。FPC排线连接方案相比传统排针排母具有更小的空间占用、更高的引脚密度和更好的抗振动性能。
显示方面，采用SPI接口的TFT彩色液晶屏，分辨率为240×240像素或更高，可实时显示赛道图像、关键参数和运行状态信息。该屏幕工作电压低、功耗小，适合电池供电的移动平台使用。
按键输入方面，采用无声硅胶按键替代传统金属锅仔片开关，具有更长的按压寿命和更宽的工作温度范围。为在有限的GPIO引脚资源下获取尽可能多的按键输入，使用8-3线优先编码器芯片将8路按键输入编码为3位二进制信号，MCU仅需3个GPIO即可识别8个按键的状态，既节省了IO资源，又因编码器自带的优先级判定功能避免了多键同时按下时的信号冲突。

第三章  软件系统设计
3.1  系统软件架构概述
本车模的嵌入式软件系统基于Infineon AURIX TC264双核微控制器开发。TC264是Infineon面向汽车电子和工业控制领域推出的高性能MCU，采用TriCore处理器内核，具有两个独立的CPU核心。本系统充分利用双核硬件资源，将计算密集型的视觉处理任务与实时性要求较高的运动控制任务分别部署在不同的处理器内核上，通过共享内存机制实现跨核数据同步。
软件系统采用模块化设计思想，将整体功能分解为多个功能独立、接口清晰的软件模块。各模块之间遵循高内聚、低耦合的设计原则，通过定义良好的全局数据结构和标志位进行信息交换。这种架构有利于团队成员的并行开发、独立调试和后期维护。
从功能层面划分，系统可归纳为感知层、决策层和执行层三个层次。感知层包括图像采集与预处理模块、特征提取模块和姿态感知模块，负责从传感器原始数据中提取赛道几何信息和车体运动状态。决策层包括路径识别模块、偏差计算模块和控制决策模块，负责根据感知信息确定车模的目标行驶方向和速度。执行层包括PID控制模块、差速分配模块和电机通信模块，负责将决策层的指令转换为具体的电机控制信号。此外，还有参数管理、人机交互、无线通信等辅助性支撑模块。
系统上电后按照预定流程完成各模块的初始化配置，随后进入周期性的主控制循环。每个控制周期依次完成传感器数据采集、图像处理与赛道识别、偏差提取与路径判断、控制量计算与电机指令输出等步骤。系统的控制周期通过硬件定时器精确管理，确保各环节的执行在时间上的确定性。
在代码组织层面，系统利用编译器提供的段定位机制，将性能敏感的数据和代码放置在靠近处理器的快速存储器区域，将初始化仅执行一次的配置数据和调试信息放置在常规存储区域，在有限的片上存储资源条件下实现了存储访问效率的最大化。
3.2  图像预处理与透视校正
图像预处理是视觉感知链路的基础环节，其目标是将摄像头采集的原始图像转换为适合后续算法处理的标准格式，同时消除镜头畸变和透视效应对赛道几何关系的影响。
由于摄像头的安装位置和拍摄角度限制，原始图像中存在两类主要的几何失真。第一类是由广角镜头引入的桶形畸变——直线的赛道边线在图像边缘区域呈现为向外弯曲的弧线。第二类是由拍摄倾角引入的透视畸变——实际平行的赛道边线在图像中呈现为向远处汇聚的梯形，破坏了赛道平面的真实几何关系。
针对镜头畸变，系统在初始化阶段通过相机标定获取镜头的畸变参数，并对原始图像逐像素应用去畸变校正变换，将弯曲的边缘拉直。针对透视畸变，采用逆透视变换（IPM）技术，利用标定获得的单应性变换矩阵，将斜视图像映射为俯视（鸟瞰）视角图像。变换后，赛道上任意两点之间的像素距离与实际物理距离之间保持线性比例关系，为后续的横向偏差和前瞻距离计算提供了可靠的几何基础。
考虑到逐帧进行完整的透视变换运算计算量较大，系统在初始化阶段预先构建了一张像素地址映射表。该映射表为输出图像中的每一个像素位置记录了其在原始图像（或去畸变图像）中对应的源像素地址。运行过程中，通过查表即可直接获取任意输出像素的灰度值，避免了每帧重复执行浮点透视变换计算。对于映射后落在原始图像边界外的无效像素，映射表统一指向预设的填充值，确保后续处理逻辑的简洁性和鲁棒性。
经过"去畸变→逆透视变换"两级处理后得到的俯视图像，为后续的边缘检测、路径追踪和几何测量提供了统一的、可量化的参考平面，是整个视觉系统的数据基础。
3.3  图像分割与特征提取
在获得标准化的俯视图像之后，下一个关键步骤是将白色引导线与蓝色赛道背景进行有效区分。这一步本质上是图像二值化或边缘提取问题，其核心挑战在于不同赛道区域的光照条件可能存在显著差异——近端受车体遮挡影响可能偏暗，远端受环境光直射可能过曝，单一固定阈值难以在全图范围内取得一致的检测效果。
3.3.1  自适应阈值计算
为了适应赛道不同区域的光照变化，系统采用基于迭代统计的自适应阈值算法。该算法在工作区域内对像素灰度值进行统计分析，通过迭代优化的方式自动寻找最佳的分割阈值，使目标（白色引导线）与背景（蓝色赛道面）的类内灰度差异最小化。
算法通过对工作区域内像素灰度分布进行统计分析，自动确定前景与背景的最佳划分阈值。其核心思想是迭代地优化阈值估计，使两类像素的内部灰度一致性最大化。为避免逐像素全量计算带来的运算开销，算法在保证统计有效性的前提下合理选取采样点。经过有限次迭代收敛后，对结果施加安全边界约束，确保在极端光照条件下阈值不会偏离合理区间。
该算法在赛道图像这类双峰灰度分布明显的场景中，能以较小的计算代价获得较好的分割效果。计算区域的选取策略也有助于排除赛道边界外无关内容的干扰，提高统计结果的针对性和可靠性。
3.3.2  边缘检测方法
在完成阈值计算后，系统对图像进行边缘检测，定位白色引导线与蓝色背景之间的分界位置。本系统支持两种可灵活选择的边缘检测方法——基于灰度比较的比值法和基于梯度计算的Sobel法，两种方法各有优势，适用于不同场景。
比值法的基本思想是通过比较图像中相邻区域的灰度差异来判断边缘的存在和方向。该方法沿指定方向取采样点对，计算其灰度对比度，并与自适应阈值进行比较以判定边缘的存在性及极性。在每次判决之前进行有效性预检：确保采样位置合法性，排除灰度特征不满足条件的无效区域。垂直方向采用相同的原理，仅在比较方向上有所区别。比值法实现简洁、计算开销小，对光照渐变具有一定的鲁棒性。
Sobel梯度法使用经典的离散微分算子计算图像的梯度信息。在正式计算之前，首先进行亮度预检以排除阴影或无效区域。梯度幅值由两个方向的梯度分量合成，当幅值超过自适应判定阈值时确认检测到有效边缘。边缘的方向由占主导的梯度方向和符号确定，可将边缘分类为上、下、左、右四种类型。Sobel法引入了邻域信息，对孤立噪声点的抑制能力更强，但计算量相对较大。
两种检测方法通过编译时宏开关进行选择，方便根据实际赛道条件和调试需求快速切换方案。检测结果的格式统一，对上层算法透明。
3.4  赛道线追踪与路径识别
在完成边缘检测后，系统需要从分散的边缘点中提取出连续的赛道左右边线，并在此基础上识别赛道的拓扑结构（直道、弯道、T型分支路口等），为偏差计算和行驶决策提供依据。本系统采用基于图搜索思想的边线追踪算法来完成这一任务。
3.4.1  起始点定位
边线追踪的起点是赛道左右边线在图像近端的起始位置。起始点定位需要平衡搜索效率与可靠性——搜索范围过大则计算开销高，搜索范围过小则可能在弯道或分支处丢失起始点。系统在图像近端区域内进行起始点搜索，并对搜索到的候选起始点执行多项验证检查（包括间距合理性、灰度一致性等条件），过滤掉可能的伪起始点。当连续多次搜索失败时，系统判定当前视野内无有效赛道信息，触发相应的保护措施。
为确保起始点的可靠性，系统对搜索到的候选起始点执行多项验证检查，包括间距合理性、灰度一致性等条件，过滤掉可能的伪起始点。
3.4.2  边线追踪方法
从起始点出发，算法以迭代推进的方式沿赛道边线向图像远端逐像素追踪。追踪过程在左右两侧独立进行，每一步根据当前位置的局部图像特征（边缘检测结果）和已累积的追踪历史信息，按照预设的决策规则确定下一步的推进方向。当遇到无法继续推进的情况（如进入元器件区域、触碰图像边界或追踪步数达到安全上限）时，该侧追踪终止。
3.4.3  断线处理与特殊路段
在实际赛道环境中，由于弯道几何突变、光照不均匀或白色胶带局部反光等因素，某一侧边线的追踪可能出现过早终止。对此，追踪算法包含边线恢复机制——当一侧追踪提前终止而另一侧正常，且局部几何条件满足一定判据时，系统在终止点附近重新搜索该侧的起始点以恢复追踪，确保边线点集的完整性。
对于赛道中的元器件区域，由于元器件图形（如三极管符号、晶闸管符号等）相比普通导线更为复杂，边线追踪可能在此区域受到干扰。系统通过预设的元器件区域配置数据来识别这些位置，当追踪位置接近元器件区域边界时，自动调整追踪策略以确保边线点集的正确连接和整体连续性。
3.4.4  中线生成
左右边线追踪完成后，系统通过对两侧对应点取均值的方式生成赛道中线（中心线）点集。中线点集是后续计算横向偏差和分析赛道几何特征的主要输入数据。在某些特定的路段类型（如T型分支路口、单侧线丢失路段），中线的生成方式会切换为仅依赖单侧边线推算，以适应不同的导航需求。
3.5  偏差计算与赛道特征识别
视觉系统的最终输出是引导车模沿赛道中心行驶所需的转向指令，其基础是车模当前位置相对于赛道中心线的横向偏差。偏差计算的准确性直接影响循迹精度和行驶稳定性。
系统在中线点集中选取合适位置的参考点来计算横向偏差。参考点与车模正前方方向之间的横向像素偏离量，经透视变换的尺度因子转换为实际物理偏差，作为后续控制计算的输入。参考点位置的选取对循迹性能有直接影响——位置过近则响应滞后，位置过远则对近处赛道变化不敏感。合适的位置需要在赛道测试中综合赛道几何特征、行驶速度和机械特性等因素确定。
除横向偏差外，系统还对赛道中线的局部几何特征进行分析，以判断前方赛道的弯曲程度。这些几何信息可用于区分直道和弯道路段，并在不同类型的路段中采用差异化的控制策略。
3.6  闭环控制算法
闭环控制是连接视觉感知与执行机构的核心环节，其任务是将视觉系统输出的偏差信号转换为稳定、快速、准确的转向控制量。本系统采用位置式PID控制算法作为基础控制框架，并针对实际应用场景进行了多项工程优化。
3.6.1  位置式PID控制原理
PID控制算法由比例项（P）、积分项（I）和微分项（D）三部分组成。比例项根据当前偏差的大小产生控制输出，是最基本的控制分量，决定了系统的响应速度。积分项对历史偏差进行累积，能够消除系统在稳定状态下的残余静差，使车模最终精确收敛到赛道中心线。微分项根据偏差的变化率产生预测性的阻尼输出，能够抑制系统在接近目标值时的超调和振荡，提高控制品质。
在实际应用中，PID控制器的参数整定是一个系统性的调优过程。通常遵循"先P后D再I"的调试顺序：首先调整比例系数，使系统对偏差产生快速的纠正响应，同时观察是否出现明显的振荡；然后引入微分项以抑制振荡、提高系统阻尼；最后根据稳态精度的需求决定是否引入积分项。参数调整的工具包括阶跃响应分析、频域分析以及基于赛道实测的反复迭代优化。
3.6.2  积分分离策略
标准PID控制器的积分项在偏差较大时存在"积分饱和"风险——当车模因特殊原因（如初始放置偏离、赛道线误识别等）出现大幅偏差时，积分项会因长时间的大偏差累加而积累到很大的数值。当偏差恢复正常后，过大的积分项会持续输出较强的控制信号，导致系统在目标值附近来回振荡，甚至失稳。
针对这一问题，本系统在PID控制器中引入了一些工程优化措施：当偏差过大时对积分项进行必要的限制，避免积分过度累积；同时设置合理的积分上下限，防止极端工况下控制量超出安全范围。
为进一步增强积分项的鲁棒性，系统对积分累加值设置了限幅保护。即使积分功能处于启用状态，累加值也不会超过预设的上下限范围。这一设计构成了积分饱和的双重防护。
3.6.3  多级控制架构
完整的控制链路采用分层结构组织，将视觉感知、姿态控制和电机驱动等不同层面的问题解耦处理。各层之间的接口清晰、职责明确，可独立进行调试和参数整定，再将各层串联后在赛道上进行整体性能的微调。
3.7  差速转向
在全差速转向架构下，转向动作通过左右轮的转速差实现，而不再依赖专用的转向舵机。差速控制策略是实现平顺、高效转向的关键技术。
3.7.1  差速分配策略
差速控制的核心是在目标基础速度之上，根据期望的转向方向和力度，对左右两轮的转速进行差异化调整。本系统采用对称差速分配策略——需要减速的一侧在基础速度上下调一定比例，需要加速的一侧在基础速度上上调一定比例。
差速比例的确定综合考虑了视觉偏差量和车体当前运动状态等多个因素，通过合理的量纲转换和限幅保护，确保差速指令在各种行驶工况下均处于安全可控范围内。
此外，为了补偿转向过程中内外侧车轮负载差异导致的转速偏差，加速侧的比例系数略大于减速侧（构成不对称差速），使得在相同目标差速比下，提速轮的增量和减速轮的减量之和为正向净增，有助于在转向过程中维持或增大车速，充分利用动力。
此外，系统根据当前路段类型和剩余长度动态调整目标行驶速度。速度参数可在Flash中持久化存储并支持通过调试菜单实时修改，以适应不同的赛道布局和路面条件。
3.8  IMU姿态感知与辅助导航
陀螺仪作为视觉系统之外的辅助感知手段，为车模提供实时的偏航角（Yaw）和角速率信息。这些数据在以下场景中发挥关键作用：T型分支路口的转向完成判断、以及急弯路段中的姿态参考。本系统采用MEMS陀螺仪芯片，通过Z轴角速度的实时采集、滤波和积分获取车模偏航角。
3.8.1  陀螺仪零偏标定
MEMS陀螺仪在制造和使用过程中存在固有的零点偏移误差——即使在静止状态下，传感器也会输出非零的角速度读数。如果不对这一偏差进行标定和补偿，即使在完全平直的路面上行驶，积分得到的偏航角也会随时间持续漂移，最终导致方向判断完全失效。
为解决这一问题，系统在每次上电初始化时自动执行静态零偏标定。标定过程在车模完全静止的条件下进行，对连续多个周期的Z轴角速度采样值取平均，作为该次上电的零偏估计值。后续所有角速度读数在使用前均先扣除该零偏值。标定完成后有一个等待稳定期，以确保陀螺仪内部电路已进入稳态工作。标定期间车模必须保持静止，否则零偏中会混入实际运动成分。
3.8.2  角速度滤波与角度积分
原始角速度信号中包含来自车体振动和电机电磁干扰的高频噪声分量。如果直接对这些含噪信号进行积分，噪声的累积将导致角度估计值的漂移和抖动。系统采用数字低通滤波器对角速度信号进行平滑处理，在保留车模真实转向运动信号的前提下衰减高频噪声。滤波器的截止频率通过权衡响应速度和滤波效果确定。
偏航角的更新基于角速度的时间积分。为提高积分精度，采用梯形积分法替代简单的矩形积分——使用当前和上一次两个角速度样本的均值作为该时间区间内的代表性角速度，乘以时间间隔得到角度增量。这一方法在线性变化的假设下具有二阶精度，优于矩形积分的一阶精度。积分得到的偏航角通过模运算约束在[0°, 360°)范围内。
3.8.3  偏航角在转向控制中的应用
在转向过程中，陀螺仪提供的实时偏航角信息可用于判断车模是否已完成预期的转向动作。与纯视觉判断相比，结合惯性测量数据的综合判断方式具有更好的实时性和可靠性，尤其在连续弯道等复杂路段中表现更为稳定。
在T型分支路口的通过判断中，系统利用偏航角变化和行驶里程两个信息源来判定车模是否已完成转弯或直行通过。对于转弯型分支，将当前偏航角与目标偏航角之间的角度差异作为判断依据；对于直行型分支，以通过距离作为判断依据。考虑0°/360°的角度环绕问题，角度差的计算使用最小夹角算法，确保在角度值跨越0°边界时的正确性。
3.9  路径规划与决策
本组别赛道采用固定的拓扑布局，系统据此采用基于状态机的顺序导航方案：将赛道划分为若干顺序衔接的路段，车模按照预设顺序依次完成各路段行驶，从而有序遍历赛道中的各条回路，实现对整个电路拓扑的完整覆盖。
导航状态数据记录了各路段的行驶方向与先后顺序，作为路段切换与行驶控制的依据。当车模行经T型分支路口时，系统根据当前路段的状态信息确定转弯方向或直行通过，从而完成对各分支的遍历。该方案结构清晰、实现简单，能够可靠地完成对固定拓扑赛道的完整巡线。
系统支持预设多套导航方案，用户可根据实际赛道条件与调试情况，通过调试菜单在运行过程中实时切换，无需重新编译程序。这一设计为赛道边的快速方案对比与临场调整提供了便利。
在行驶过程中，路段自动切换逻辑持续监测车模的当前位置和行驶方向是否满足进入下一路段的条件。当条件满足时，自动更新路段索引，触发下一路段的控制参数加载。整个过程中的路段切换是完全自动化的，不需要额外的外部干预。
3.10  辅助控制与参数管理
除核心的循迹控制功能外，软件系统还包含若干辅助控制与系统管理模块，为车模的可靠运行和高效调试提供支撑。
3.10.1  下压力风机控制
为提升轮胎在高速弯道中的抓地力，车模安装有负压风扇以提供额外的气动下压力。风机的转速通过PWM信号控制，采用缓启动策略——PWM占空比从较小的起始值以固定速率逐步增大至目标值，避免阶跃变化对风机叶片和车体产生冲击。启动过程由一个三态状态机管理（空闲→过渡→稳定运行），电机启动逻辑与风机运行状态互锁，确保车模在获得充分下压力之后才开始行驶。
3.10.2  参数持久化存储
系统所有可调参数（包括PID系数、速度设定、图像阈值等）均支持在MCU内部非易失存储器中的持久化存储。参数的存储和读取采用统一的数据缓冲机制，支持多种数据类型（整型、浮点型、无符号整型等）。存储操作遵循先检查、后擦除、再写入的标准流程，并仅在用户明确发出保存指令时才执行写入操作，以保护Flash存储器的使用寿命。
系统预置了多套参数配置方案，涵盖了从保守到激进的多种参数组合。用户可根据赛道路面状况（摩擦力水平）、电池电压状态（影响电机响应速度）和比赛策略需求，一键切换整组参数。参数切换后配合保存功能，支持在赛道边的快速方案对比。
3.11  人机交互与调试系统
高效的调试手段是智能车竞赛取得好成绩的重要保障。本系统设计实现了一套完整的车载人机交互与远程调试系统，支持参数查看修改、运行状态监控和实时图像传输等功能。
3.11.1  菜单系统架构
车载调试菜单基于树形结构组织，采用兄弟-长子链表实现多级菜单层次。每个菜单节点可以是文件夹（目录）、数值绑定项（链接到某个全局变量）或函数回调项（触发特定功能）。菜单节点从预分配的静态内存池中获取存储空间，避免了嵌入式环境下的动态内存碎片问题。
菜单树的顶层包含多个功能文件夹，分别对应控制参数、惯性测量、图像处理、赛道配置、存储管理和图像传输等不同功能域。用户通过上下按键在文件夹内导航，左右按键实现进出文件夹和数值编辑，逻辑清晰、操作简便。为提高操作效率，同一层级菜单项构成循环链表，支持无限循环上下导航。
3.11.2  参数编辑功能
对于数值型参数，系统支持多档位步进值的实时增减编辑。步进值可通过按键循环切换，兼顾了精细微调和快速粗调的需求。所有编辑操作立即生效，用户可直接观察参数变化对车模行驶表现的影响。只读型参数仅显示当前值，不开放编辑，防止误操作。
3.11.3  图像与数据可视化
TFT屏幕上可实时显示当前帧的处理图像（支持多种显示模式切换，如二值图、透视校正图、原始灰度图等），并叠加显示参考线、检测到的赛道边线和关键计算点等视觉信息。屏幕的右侧区域分多页循环显示丰富的实时运行数据，包括赛道识别信息、控制参数信息和传感器原始数据等，调试人员可通过按键在不同信息页之间切换，从多个维度快速了解车模的运行状态。
3.11.4  无线通信与远程调试
系统支持通过无线串口模块（如蓝牙或2.4G透传模块）与PC端上位机建立双向通信链路。上位机软件可实时接收并显示车模传回的图像帧和运行数据，调试人员也可在上位机上发送控制指令（启动/停止车模、切换测试模式、复位传感器等）。这一功能在实际赛道测试中非常实用——调试人员无需靠近车模或连接有线调试器，即可在赛道旁的任意位置完成参数调整和数据观测，大大提升了调试工作的便利性和效率。
此外，系统还支持通过定时器中断驱动的蜂鸣器发出不同频率的提示音，用于向调试人员传递车模的当前状态信息（就绪、运行、故障等），实现不看屏幕即可获取基本状态反馈的功能。

第四章  开发工具与调试过程
4.1  开发环境
本项目的软件开发基于AURIX Development Studio集成开发环境，该环境基于Eclipse平台扩展而来，集成了编辑器、编译器、调试器和Flash烧录工具。编译工具链采用Tasking C/C++ Compiler，该编译器对TriCore架构具有深度优化能力，支持多核编程所需的段定位、内存分区和链接脚本定制等功能。代码编写以C语言为主，利用Infineon提供的iLLD底层驱动库快速构建外设初始化和管理功能。
在辅助工具方面，团队使用了以下软件资源：串口调试工具用于验证UART通信协议的正确性和数据完整性；数据可视化软件用于实时绘制传感器数据波形和PID控制量变化曲线，辅助控制参数整定；专门的上位机软件用于无线接收和显示摄像头图像帧；机械设计工具用于车模结构件的3D建模和装配验证；PCB设计工具用于电路板的原理图设计和布局布线。
4.2  调试流程与方法
车模的调试工作按照"传感器单体验证→执行器单体调试→子系统集成测试→整车赛道实测"的层次化流程推进。
传感器单体验证阶段，对各传感器单独进行数据采集和标定。陀螺仪在静态条件下进行零偏标定和噪声水平评估，摄像头在不同光照和距离条件下检验图像质量和透视变换矩阵标定精度，编码器通过手动旋转电机轴验证脉冲计数和里程转换系数的准确性。
执行器调试阶段，对主板集成的双路电调进行速度闭环测试。通过串口发送阶跃速度指令并采集编码器反馈数据，调优FOC参数和速度环PID参数，使电机在空载和有负载条件下均具有快速稳定的转速响应。负压风扇进行PWM驱动范围和推力特性的测试标定。
子系统集成阶段，在实验桌面上搭建简易赛道片段，将视觉系统和控制算法联合调试。通过观察传感器数据、中间处理结果（边缘检测效果、边线追踪轨迹）和控制输出，定位和解决视觉识别偏差或控制参数不当的问题。
赛道实测阶段，在标准赛道上进行全系统联调。根据赛道实际表现，通过车载菜单逐步调整PID参数、视觉处理阈值等关键变量。整个调试过程遵循"改参数→观察效果→记录比对→再调整"的迭代循环，每次只修改一个或少数几个参数以明确因果关系，逐步收敛到最优配置。
4.3  典型问题与解决方案
在开发和调试过程中，团队遇到了若干具有代表性的工程问题。以下选取几个典型案例进行简要回顾。
问题一：高速运动条件下卷帘快门摄像头产生的图像畸变。在车体高速旋转或横向运动时，卷帘快门的逐行曝光时序使得同一帧图像的不同行之间存在空间位移，导致原本平直的赛道边线在图像中扭曲变形，严重影响偏差计算精度。解决方案：更换为全局快门图像传感器，利用其所有像素同步曝光的特性从根本上消除了运动畸变问题，同时配合设置合理的短曝光时间以控制运动模糊量。
问题二：DCDC开关电源高频噪声对传感器信号的干扰。开关电源的开关频率及其谐波通过电源线和地平面的传导和辐射耦合至信号链路，导致ADC采样值和传感器数字输出出现明显的周期性波动。解决方案：在PCB布局阶段将数字区域和模拟区域的地平面物理分隔并在一点桥接；在DCDC输出端增加LC滤波网络；在开关管节点增加RC吸收电路以衰减开关振铃。
问题三：传统机械电源开关在大电流场景下的寿命问题。电机启动和变速瞬时的峰值电流远超开关的标称额定值，导致开关触点迅速烧蚀失效。解决方案：采用PMOS电子开关方案，实现以微安级别的控制电流切换数十安培级别的主电流通路，从根本上解决了机械开关烧蚀问题，且电子开关的响应速度远快于机械开关。
问题四：频繁"修改参数→重新编译→烧录→重启"的调试循环效率低下。解决方案：开发了基于车载屏幕和按键的交互式参数修改系统，实现参数的秒级实时修改和效果观察，将单次参数调试迭代时间从数分钟缩短到数秒。配合无线图像传输功能，调试人员可远离工作台在赛道边独立完成全部调参工作。
问题五：高速过弯时的轮胎侧滑（推头）问题。随着车速提高，弯道中轮胎与赛道面之间的侧向摩擦力成为限制转弯性能的瓶颈。解决方案：安装负压风扇以产生额外的气动下压力，增加轮胎与赛道面之间的正压力和最大静摩擦力，从而提升弯道极限速度。风机采用软启动策略避免对车体造成突然的冲击或振动。


结  论
本技术报告系统介绍了华南理工大学"华工溯光队"参加第二十一届全国大学生智能汽车竞赛疯狂电路组的设计方案和制作过程。报告涵盖车模的整体机械架构、电路硬件系统、嵌入式软件算法以及开发调试工具链四个方面，力求全面而概括地呈现队伍在备赛过程中积累的工程经验和技术思考。
在机械设计层面，全差速转向架构配合负压风扇气动下压力方案，在紧凑的外部尺寸约束内兼顾了转弯灵活性和高速行驶稳定性。在电路硬件层面，电子开关方案解决了传统机械开关的可靠性问题，多级隔离供电方案和地平面分割设计有效抑制了电磁噪声对敏感电路的干扰。在软件算法层面，我们构建了从图像透视校正、自适应阈值分割、边缘检测与路径追踪到分层级联PID控制的完整视觉感知与控制处理链路。车载交互式菜单系统和无线数据传输功能显著提升了赛道边调试的迭代效率。
展望未来，方案在以下方向存在进一步优化的空间：（一）图像处理算法在极端光照条件下的鲁棒性提升，可探索引入基于学习的特征提取方法来替代部分手工设计的规则；（二）多传感器融合姿态估计的精度提升，可引入互补滤波或卡尔曼滤波框架，将陀螺仪角速度与编码器里程数据进行融合，获得更准确的偏航角估计；（三）速度规划的在线优化，可引入模型预测控制等先进方法，在车体动力学约束下实现更智能的竞速策略。
通过此项目的训练，队员们在嵌入式系统设计、自动控制理论应用、图像处理算法实现和工程系统集成等方面获得了宝贵的实践经验。从方案选型、原型搭建到反复调试和性能优化，每一个环节都切实提升了同学们分析问题、解决问题的工程思维能力。这段经历将为队员们未来从事相关领域的深入研究和工程实践奠定坚实的基础。

A.3  图像去畸变处理示例
/**
 * 图像去畸变处理示例
 * 基于预标定畸变参数的像素坐标校正
 */
void undistort_image(uint8 *src, uint8 *dst, int width, int height)
{
    for(int y = 0; y < height; y++)
        for(int x = 0; x < width; x++)
        {
            /* 将像素坐标归一化到相机坐标系 */
            float nx = (x - cx) / fx;
            float ny = (y - cy) / fy;

            /* 计算径向距离 */
            float r2 = nx * nx + ny * ny;

            /* 应用径向畸变校正 */
            float factor = 1.0f + k1 * r2 + k2 * r2 * r2;
            float ux = nx * factor;
            float uy = ny * factor;

            /* 映射回像素坐标并取值 */
            int src_x = (int)(ux * fx + cx + 0.5f);
            int src_y = (int)(uy * fy + cy + 0.5f);
            dst[y * width + x] = get_pixel_safe(src, width, height, src_x, src_y);
        }
}

A.4  低通滤波器实现示例
/**
 * 一阶低通滤波器实现示例
 * 用于传感器信号的实时平滑处理
 */
typedef struct {
    float alpha;       /* 滤波系数 (0~1) */
    float output;      /* 当前滤波输出值 */
} LowPassFilter;

void lpf_init(LowPassFilter *f, float alpha)
{
    f->alpha = alpha;
    f->output = 0.0f;
}

float lpf_update(LowPassFilter *f, float input)
{
    f->output = f->alpha * input + (1.0f - f->alpha) * f->output;
    return f->output;
}

A.5  串口数据帧接收状态机示例
/**
 * 串口数据帧接收状态机示例
 * 展示基于帧头和校验的通信协议解析框架
 */
typedef enum { WAIT_HEADER, READ_DATA, CHECK_SUM } RxState;

int parse_frame(uint8 byte, FrameBuffer *frame)
{
    static RxState state = WAIT_HEADER;
    static uint8 data_idx = 0;
    static uint8 checksum = 0;

    switch(state)
    {
        case WAIT_HEADER:
            if(byte == FRAME_HEADER) {
                state = READ_DATA;
                data_idx = 0;
                checksum = byte;
            }
            break;

        case READ_DATA:
            frame->data[data_idx++] = byte;
            checksum += byte;
            if(data_idx >= FRAME_DATA_LEN) {
                state = CHECK_SUM;
            }
            break;

        case CHECK_SUM:
            state = WAIT_HEADER;
            if(byte == (checksum & 0xFF))
                return 1;  /* 帧接收成功 */
            break;
    }
    return 0;
}

A.6  Flash参数存储接口示例
/**
 * Flash参数存储接口示例
 * 展示非易失性参数保存的一般流程
 */
int save_parameters(void)
{
    /* 准备参数缓冲区 */
    ParamBuffer buffer;
    pack_parameters(&buffer);

    /* 检查目标扇区状态 */
    if(flash_sector_is_busy(TARGET_SECTOR))
        return -1;

    /* 擦除目标扇区 */
    flash_sector_erase(TARGET_SECTOR);

    /* 等待擦除完成 */
    while(flash_sector_is_busy(TARGET_SECTOR));

    /* 写入参数数据 */
    flash_write(TARGET_ADDRESS, (uint32*)&buffer, sizeof(buffer));

    /* 等待写入完成 */
    while(flash_sector_is_busy(TARGET_SECTOR));

    return 0;
}

A.10  图像自适应阈值与边缘检测
/**
 * 图像二值化阈值计算示例（示意性代码）
 * 采用经典的迭代均值法，仅展示算法基本思路
 */
uint8 auto_threshold(uint8 *img, uint16 w, uint16 h)
{
    uint32 sum = 0;
    uint16 cnt = 0;

    /* 统计整幅图像灰度均值，作为初始阈值 */
    for (uint16 i = 0; i < (uint32)w * h; i++)
    {
        sum += img[i];
        cnt++;
    }
    uint8 T = (uint8)(sum / cnt);

    /* 迭代细化阈值（示意性实现，略去边界处理） */
    for (int k = 0; k < 3; k++)
    {
        uint32 s1 = 0, s2 = 0;
        uint16 n1 = 0, n2 = 0;
        for (uint16 i = 0; i < (uint32)w * h; i++)
        {
            if (img[i] < T) { s1 += img[i]; n1++; }
            else            { s2 += img[i]; n2++; }
        }
        if (n1 == 0 || n2 == 0) break;
        T = (uint8)((s1 / n1 + s2 / n2) / 2);
    }
    return T;
}
