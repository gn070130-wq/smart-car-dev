摘 要
本文详细介绍了 “疯狂派队”在第二十一届全国大学生智能汽车竞赛竞速赛疯狂电路组中的系统方案。该智能车（自制）的硬件系统以32位的TC264D40F200微控制器作为核心控制单元，使用自行设计的主控制电路板、LSM6DSRTR陀螺仪以及相关功能电路板，通过摄像头采集赛道相关数据，编码器实时监测当前速度。同时利用PID程序算法，输出PWM波驱动电机，以完成智能汽车前进、转弯等过程。最终实现发车过后的系统自动依据路况变化进行闭环操作的功能。实际制作中也存在一系列问题，例如机械结构对智能汽车行驶路径的影响、PID参数对汽车行驶路径的影响等等。从结果而论，在制作智能汽车的过程中，进行了大量硬件与软件测试。实验结果表明，本组小车能在一些复杂支路行稳定循迹，该系统设计方案确实可行。

关键词：智能车；TC264D40F200；LSM6DSRTR；PWM ；PID ；机械结构

 引言
1.1 智能车大赛背景
为加强大学生实践、创新能力和团队精神的培养，促进高等教育教学改革，受教育部高等教育司委托(教高司函[2005]201号文)，由教育部高等自动化专业教学指导分委员会（以下简称自动化分教指委）主办全国大学生智能汽车竞赛。该竞赛以智能汽车为研究对象的创意性科技竞赛，是面向全国大学生的一种具有探索性工程实践活动，是教育部倡导的大学生科技竞赛之一。该竞赛以“立足培养，重在参与，鼓励探索，追求卓越”为指导思想，旨在促进高等学校素质教育，培养大学生的综合知识运用能力、基本工程实践能力和创新意识，激发大学生从事科学研究与探索的兴趣和潜能，倡导理论联系实际、求真务实的学风和团队协作的人文精神，为优秀人才的脱颖而出创造条件。该竞赛由竞赛秘书处为各参赛队提供/购置规定范围内的标准硬软件技术平台，竞赛过程包括理论设计、实际制作、整车调试、现场比赛等环节，要求学生组成团队，协同工作，初步体会一个工程性的研究开发项目从设计到实现的全过程。
该竞赛融科学性、趣味性和观赏性为一体，是以迅猛发展、前景广阔的汽车电子为背景，涵盖自动控制、模式识别、传感技术、电子、电气、计算机、机械与汽车等多学科专业的创意性比赛。该竞赛规则透明，评价标准客观，坚持公开、公平、公正的原则，保证竞赛向健康、普及，持续的方向发展。
2008年起该竞赛被教育部批准列入国家教学质量与教学改革工程资助项目中科技人文竞赛之一（教高函[2007]30号文）。全国大学生智能汽车竞赛原则上由全国有自动化专业的高等学校（包括港、澳地区的高校）参赛。竞赛首先在各个分赛区进行报名、预赛，各分赛区的优胜队将参加全国总决赛。
全国大学生智能汽车竞赛组织运行模式贯彻“政府倡导、专家主办、学生主体、社会参与”的16字方针，充分调动各方面参与的积极性。
全国大学生智能汽车竞赛一般在每年的10月份公布次年竞赛的题目和组织方式，并开始接受报名，次年的3月份进行相关技术培训，7月份进行分赛区竞赛，8月份进行全国总决赛。
竞速赛大类根据所使用的车模、微控制器、传感器、比赛任务以及参加学生的不同分为十一个不同的竞速组别。参赛队伍使用指定微控制器系列作为核心控制模块，通过增加道路传感器、电机驱动电路以及编写相应单片机软件，制作一部能够自主识别道路或者目标的模型汽车，按照规定路线或者任务行进，以完成综合时间最短者为优胜。本组参加了其中的疯狂电路组。

 机械结构调整及设计
智能车的核心是控制策略和算法，但是，机械结构也是限制赛车速度的巨大瓶颈，如果一辆赛车的程序架构很好，但是机械部分做得不好的话，其速度也会被大大的限制。即当车速较高的时候，车模有明显的甩尾和侧滑现象，此时对车的机械结构要求很高。除了对车身姿态的影响外，机械性能影响车的加减速响应速度，运行的对称性和稳定性等，因此，本组在不违反规则的情况下对小车进行了多方面的改造以使小车具有良好的运行性能。
2.1 整车布局
本组采用的是自制车模，对称性好，尺寸约为131mm*55mm*160mm，轮胎尺寸直径为22mm，通过对轮胎胎皮进行合适的自制处理，具有极好的减震性和耐磨性，也增强轮胎摩擦性，提高抓地性能。驱动电机采用N30强磁超高速直流电机，额定电压为11.1V，堵转力矩为200 gf·cm，堵转电流小于15A，空载电流为230mA，电机本体重量约11.7g。外形尺寸为：总长7.50mm、总高18.60mm、总宽11.80mm。智能车车模的外形大致如图1。

2.2 自制车模的整体机械机构
本组使用官方要求的自制车模完成车模的制作。该车模结构更加稳定。该四轮系统智能车机械结构主要由两个中置N30电机组成，该车模的机械结构特点是将驱动轮和转向轮合并，通过左右两侧轮差速实现转向控制。
1. 双电机四轮驱动与低重心布局
车模底盘采用双电机驱动四轮布局，相较于单电机方案，四轮独立驱动不仅提升了动力输出的冗余度，还能通过差速控制实现更敏捷的转向响应。在结构设计上，团队对传动系统进行了深度优化，将电机与减速齿轮组尽可能贴近底板安装，大幅降低了整车重心。根据牛顿第二定律与离心力理论，低重心设计有效减小了车模在高速过弯时的侧倾力矩，提升了操控稳定性，同时降低了对传感器前瞻距离的需求[4]。
2. 无刷负压吸附系统
为满足赛道紧凑、路肩密集带来的高过弯离心力挑战，车模引入了无刷负压系统。相较于传统有刷负压电机，本方案选用了轻量化无刷电机搭配定制尼龙离心风机，整套负压系统总重控制在10g以内。该结构不仅实现了小型化与低功耗，还通过外转子与风机同步转动的设计，利用气流辅助电机散热，避免了长时间满速运行导致的发热与风机脱落风险。同时，在底板进风口四周保留了完整的环形区域并粘贴环形双面胶，有效阻断了外围镂空部位的漏风路径，保障了强劲且稳定的下压力。
在调试该车模的时候本组总结出该车的一些控制特点：
前瞻性较好。负责驱动和转向的左右两侧轮在整个车模的中部，无论是使用摄像头或电感寻迹，传感器采集到的赛道信息都在两轮前方较远的距离，使得控制系统有良好的前瞻预测性。
综上，在搭建四轮车模的时候，需要在尽可能将中心位置靠近转向轴的同时，尽可能减轻车模的重量。

 硬件电路设计
硬件是智能车的基础。只有搭建一个稳定且安全的硬件环境才能车模的平稳行。为响应赛题对重量的严苛限制，本车模摒弃了传统的“主板+扩展板”分离式架构，采用了高度集成化的PCB设计。将MCU最小系统、电机驱动、电源管理、传感器接口等核心电路全部整合至一块主驱一体板中。这种集成化设计不仅大幅缩减了布线长度与接插件数量，更直接减少了约20%的硬件冗余重量，为整车轻量化提供了坚实基础。
3.1单片机系统设计
单片机最小系统是智能车控制的核心。在比赛规则中提供的几款英飞凌微控制器中，考虑到摄像头循迹需要的管脚较多，计算量较大等特点，选择TC264D40F200芯片[3]。

3.2电源模块设计
由于 5V 稳压电路输入取自动力电池 VCCBAT[2]，该电路为同步降压 DCDC 电路，如图 7。选用 TPS565201DDCR 作为稳压芯片，它是一款高功率密度全集成同步降压转换器，芯片特性如下：
输入电压范围：支持 4.5V~17V 宽压输入，适配车载电池电压波动，降低前端浪涌防护设计难度；
输出能力：持续输出电流最高 3.2A，可为主控、运放、传感器等全车 5V 设备稳定供电；
外围简洁：搭配 3.3μH 功率电感、陶瓷输入输出电容即可完成功率回路，片内集成上下桥 MOS，无需额外功率管；
反馈调压：通过 R31、R32 分压网络设置输出电压，精准稳定输出 VCC5V；
完善保护机制：内置过热关断、输出过压、输入欠压、逐周期限流保护，避免电压异常损坏后级弱电芯片；
小型化适配：器件体积小巧，搭配贴片阻容电感，便于 PCB 紧凑布局，适配智能车小型一体化驱动板。 电路输入端搭配多颗大容量滤波电容抑制电池侧纹波，输出端电容滤除开关噪声，保障 5V 电源纯净度，降低电机驱动带来的电磁干扰。

3.4姿态传感器电路
IMU660RB 集成三轴加速度计与三轴陀螺仪，可同步采集载体实时加速度、角速度运动原始信号；芯片内部自带硬件低通滤波，对原始传感信号完成初步降噪处理，输出稳定的数字运动数据，可直接通过通信接口传输至主控单片机读取。单片即可满足智能车姿态、倾角、航向数据采集需求，无需额外搭配多颗分立传感器。因此本组选用 IMU660RB 搭建姿态检测电路，通过寄存器配置可调滤波带宽与测量量程，精准输出车身俯仰、横滚、偏航姿态信息。

3.5负压模块设计
为满足赛道紧凑、路肩密集带来的高过弯离心力挑战，汽车在高速跑动的情况下会出现甩尾，我们在原有的主板模块上加入了无刷电调驱动模块，来帮助汽车实现强抓地力的目标。
1.主控：电路控制核心，输出三相 PWM 调制信号；采集电池电压、电机反电动势过零、外部控制 PWM 指令；完成串口调试通讯、运行 / 故障指示灯逻辑控制，实现无刷电机无感换相与扭矩转速闭环调控。
2.FD6288Q 栅极驱动电路：放大主控弱 PWM 信号驱动功率 MOS；自举电路实现上桥管驱动，搭配稳压二极管、限流电阻抑制电压尖峰，保护功率管。
3.三相 MOS 逆变桥：6 路 N 沟道 MOS 管组成全桥，将动力电池直流电压逆变为三相交流电，驱动无刷电机运转。
4.信号采集电路 
（1）电压检测：电阻分压采样电池电压，实现过 / 欠压保护；
（2）过零检测：采集电机端反电动势，判断转子位置，省去霍尔传感器；
（3）PWM 捕获：接收整车控制器下发的转速扭矩指令；
（4）调试串口 + 状态灯：支持程序烧录、故障诊断，直观反馈驱动板工	      作状态。
5.优点：电路可快速响应整车域控 PWM 指令，高精度调节电机转速与扭矩；无感换相方案简化底盘线束、减轻车重。

 软件设计及调试
4.1软件系统设计及实现
优秀的软件控制程序是智能车高速稳定完成比赛任务的基础。软件部分主要的任务是进行赛道的识别，速度的反馈控制，转向控制。
关于赛道的识别，采用摄像头进行赛道识别。
关于转向控制，采用PID控制。
关于速度反馈控制，使用编码器进行增量式PID控制。
4.2 总体设计
智能车采集信息的底层处理算法是整个上层控制策略的基础。摄像头的图像采集稳定性、图像预处理算法的有效性、以及路径特征识别的准确性，都直接决定着上层控制策略能否发挥作用。只有从摄像头获取的图像中准确地提取出赛道边界与中心引导线，智能车才能实现高速稳定行驶。本组采用摄像头作为核心赛道感知传感器，进行赛道图像的实时采集与识别处理。本届智能车竞赛中，车模完全采用图像循迹，图像循迹流程如下图13所示：

图 13摄像头寻迹流程图

本组智能车行驶的前提是获取准确的赛道信息输入，通过该输入量的获取，本组可以进行分析，得到小车行驶过程中所需的输出参数，从而为后续的路径优化做好准备。
为了防止因外部因素导致的图像噪声干扰，采用图像滤波算法对摄像头采集的图像进行处理。每5ms采集一帧图像，并对其应用中值滤波或均值滤波，以消除随机噪声，得到稳定、清晰的图像数据作为该控制周期的输入。巡线部分主要依靠赛道提取算法。
赛道提取算法是智能车至关重要的环节，小车之所以能沿赛道快速行驶，首先要从处理后的图像中提取出车身与赛道的横向偏移量，得到一个偏差值，然后将该偏差值送入控制器处理，最后控制器输出信号控制舵机和电机，以纠正车身姿态并调节行驶速度。
4.3 各环控制
4.3.1 速度控制
速度环的控制周期是5ms，每5ms进行一次控制，并进行平滑输出。通过PI控制车模速度，P为比例参数，I为积分参数，使得实际速度紧紧跟随目标速度，提高车模速度的稳定性。
4.3.2 转向控制
实现车模方向控制是保证车模沿着竞赛道路比赛的关键。由于采用摄像头作为赛道感知传感器，系统需从采集的图像中提取赛道中线，并计算车身与中线的横向偏差。转向环每5ms执行一次控制。获取图像偏差后，将其乘以一个比例系数，直接作为两轮差速的控制量，从而驱动电机实现转向。经实际验证，该简化方法响应迅速、控制稳定，能够有效保证车模沿赛道行驶。
4.4 PID控制
4.4.1 PID算法简介
PID控制即比例、积分、微分控制[1]，该方法在工程实际中应用相当广泛。PID控制算法具有结构简单、工作可靠、便于调整、性能稳定等优点。当被控对象的性能、结构等一系列参数无法得知，而且建模等控制方法亦无从下手时，本组便可以应用PID控制技术，但是，系统控制器的结构和参数必须依靠经验和现场调试来确定。当本组不完全了解一个系统和被控对象，或不能通过有效的测量手段来获得系统参数时，最适合用PID控制技术。PID控制，实际中也有PI和PD控制。PID控制器就是根据系统的误差，利用比例、积分、微分计算出控制量进行控制的。图14为PID控制系统原理图。


图 14 PID控制系统原理图

PID函数的一般形式为：U(s)=kp(1+1/(TI*s)+TD*s)；其中kp为比例系数，TI为积分时间，TD为微分时间常数。
比例控制是一种简单实用的控制方式。该方法的输出与输入误差成比例关系。比例系数越大，调节作用亦越大，减少误差的过程则越迅速，但是比例系数如果过大，则系统的稳定性会大大下降。 
对于积分控制，控制器的输出与系统的输入误差信号的积分成正比关系。积分项的引入是为了消除稳态误差，积分项对误差取决于时间的积分，随着时间的增加，积分项会增大。这样，即便误差很小，积分项也会随着时间的增加而加大，它推动控制器的输出增大使稳态误差进一步减小，直到等于零。 
微分控制中，控制方法的输出与输入误差的变化率成正比关系。智能车控制系统由于存在有较大惯性，其变化总是落后于误差的变化自动控制系统，在克服误差的调节过程中可能会出现振荡，严重时会导致不稳定。为了充分解决此问题，本组需要提前抑制误差的变化作用，即在误差接近零时，抑制误差的作用就应该是零。这就是说，在控制器中仅引入“比例”项往往是不够的，比例项的作用仅是放大误差的幅值，而目前需要增加的是“微分项”，它能预测误差变化的趋势，这样，具有比例+微分的控制器，就能够提前使抑制误差的控制作用等于零，甚至为负值，从而避免了被控量的严重超调。
4.4.2 PID参数整定
PID控制算法中PID参数的整定是控制系统设计的核心内容。该过程是根据被控过程的特性确定PID控制器的比例系数、积分时间和微分时间的大小。
PID控制器参数整定的方法很多，概括起来有两大类：一是理论计算整定。该方法需要依靠一定的数学模型，即通过一定的模型进行理论计算，最后确定控制器参数。但是，理论计算的方法所得到的数据常常是不能够直接运用到实际中的，其必须通过实际工程进行验证，并进行调整和进一步修改。二是工程经验整定。该方法主要依赖工程经验，直接在控制系统的试验中进行，且方法简单、易于掌握，在工程实际中被广泛采用。工程整定方法中的PID参数整定主要有临界比例法、衰减法、反应曲线法。三种方法各有其特点，每一种方法所得到的控制器参数，都需要在实际运行中进行最后调整与完善。此外，其共同点都是通过试验，然后按照工程经验公式对控制器参数进行整定。
进行 PID控制器参数的整定步骤一般如下：
（1）预选择一个足够短的采样周期让系统工作；
（2）仅加入比例控制环节，直到系统对输入的阶跃响应出现临界振荡，记下这时的比例放大系数和临界振荡周期；
（3）在一定的控制度下通过公式计算得到PID控制器的参数；
（4）根据实际运行情况对计算出的PID控制器的参数进行调整。
本系统的PID参数为通过上位机调试得来，具体调试方法为：先将PID参数设置为经典参数，然后通过上位机观察速度曲线，不断改变PID参数，直至观察速度曲线发现其加减速时间很短，超调量很少，则说明此时的PID参数已经基本比较合适，这样就确定出适合本系统的一组PID参数。
4.4.3 实际PID参数调试过程
实际调试PID过程需要结合虚拟示波器进行调试。在调试四轮车的速度环时需要将实际得到了速度和理论所给的速度同时发送至上位机上，观察实际波形和理论所给波形适当调节PID参数，达到系统响应快而不容易超调。调试转向环时，应当先确立转向外环参数，此时应当将小车速度环关闭而只打开转向环，并将小车放在赛道上用手左右推小车，如果感觉到有明显的阻尼，证明转向环过硬，而如果阻尼较小，则证明转向环过软。实际调试过程中要适当调节转向环参数，使得小车既可以过弯道时候打过来角，又不会出现通过大弯道甩尾的情况。
4.5速度反馈控制
测速就是对于编码器的使用，本车直接对编码器读取的速度进行控制。
本组使用的是增量PI 控制，采用变积分PI控制，其中I与速度偏差成反比。由于本车采用了内八斜电感，因此速度控制全权交由斜电感计算的偏差来控制速度，并用角速度加以限制，防止在左右连续弯道时冲出赛道。

//-------------------------------------------------------------------------------------------------------------------
//  函数名称：    float PID_Increase(PID*PID,float NowData,float Point)
//  函数功能：    增量式PID
//  输入参数：    PID(PID参数)，NowData(实际值)，Point(目标值)
//  输出参数：    float
//  备注信息：    无
//-------------------------------------------------------------------------------------------------------------------
//增量PID
float PID_Increase(PID *PID,float NowData,float Point)
{
    static float OutPut=0;
    float kkp=0,kki=0;
    PID->Error = Point - NowData;
    if(PID->Error>250) PID->Error=250;//防止翘头
    if(PID->Error<-250) PID->Error=-250;
    PID->Out_P=(PID->Error - PID->LastError);
    PID->Out_I=PID->Error;
    OutPut+=(kkp*PID->Out_P + kki*PID->Out_I );
    Limit_float(&OutPut,-pid_limit,pid_limit);
    return OutPut;
}

//////////堵转保护///////////
int duzhuan_timer=0;
bool locked_rotor=0;
void Duzhuan(void)
{
    if((motor_l.duty_speed>=6000||motor_l.duty_speed<=-6000||motor_r.duty_speed<=-6000||motor_r.duty_speed>=6000)&&(motor_l.encoder_speed<10||motor_r.encoder_speed<10))
    {
        duzhuan_timer++;
        if(duzhuan_timer>200) {locked_rotor=1;duzhuan_timer=0;}
    }
    else duzhuan_timer=0;
}

int delay_timer=0;
void Delay_run(void)
{
    delay_timer++;
    if(delay_timer>200*3) {run_flag=1;delay_timer=0;}
}
