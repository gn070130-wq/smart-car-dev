第一章引言
全国大学生智能汽车竞赛是由教育部高等学校自动化专业教学指导委员会主办。竞赛以“立足培养，重在参与，鼓励探索，追求卓越”为指导思想，旨在促进高等学校素质教育，培养大学生的综合知识运用能力、基本工程实践能力和创新意识。智能车竞赛涉及自动控制、模式识别、传感技术、汽车电子、电气、计算机、机械与能源等多个学科，为大学生提供了一个充分展示想象力和创造力的舞台，吸引着越来越多来自不同专业的大学生参与其中，激发了大学生从事科学研究与探索的兴趣和潜能，其倡导理论联系实际、求真务实的学风和团队协作的人文精神，为优秀人才的脱颖而出创造条件。
我们本次比赛参加的组别为疯狂电路组。车模采用左右驱动轮差速的方式完成转向，在本次备赛过程中，我们重点研究了赛道图像处理、特殊路口识别、转向控制、速度规划以及车辆高速运行稳定性等问题，并通过多轮测试不断优化整车性能。
系统以摄像头采集的赛道图像作为循迹和特殊元素识别依据，通过编码器完成左右驱动轮速度反馈，并结合陀螺仪角速度及相对航向角进行转向控制和场景退出判断。在此基础上，根据预先规划的比赛路径对不同赛段设置相应的运行速度，以兼顾车辆运行速度和稳定性。
本组采用缩微车模作为研究平台，以 Infineon™ TC264D 芯片作为主控制器 [1]。正文部分共分为七章。第一章为引言；第二章介绍系统总体方案；第三章介绍车模机械结构和主要部件的安装；第四章介绍系统主要硬件组成；第五章重点讨论图像处理、特殊元素识别、速度规划和闭环控制算法；第六章介绍本系统使用的开发环境以及实际调试方法；第七章对本次系统设计与实现进行总结。

第二章系统总体设计
本章主要介绍智能车系统的总体设计思路，并对系统中摄像头、编码器、陀螺仪、驱动电机和主控制器等部分的作用进行简要说明。在后续章节中，将分别对机械结构、硬件组成和软件控制方法进行进一步介绍。
2.1 系统总体方案的选定
在循迹传感器方面，选用 MT9V034 总钻风灰度摄像头[2]。MT9V034 采用全局快门方式，能够较好地避免车辆运动过程中因逐行曝光产生的图像畸变，适合高速运动条件下的赛道图像采集。车辆运行过程中，根据摄像头获得的赛道信息进行循迹、转向和停车等处理。速度反馈采用两个正交编码器，分别采集左右驱动轮的运动信息，为左右电机的闭环速度控制提供反馈。
2.2 系统总体方案的设计
智能汽车系统采用 Infineon TC264D 微控制器作为核心控制单元。MT9V034 灰度摄像头采集前方赛道图像，主控制器对图像进行逐行扫线、特殊元素检测以及中线误差计算，并根据计算结果控制左右驱动轮的速度差。两个正交编码器分别反馈左右驱动轮的实际运动状态，用于电机速度闭环控制。系统同时使用 IMU660RC 六轴惯性传感器采集车辆 Z 轴角速度，并通过角速度积分获得相对航向角，用于直角及 T 字路口转弯过程中的角度判断；Z 轴角速度还作为方向控制中的阻尼量，以改善车辆快速转向时的动态稳定性。
疯狂电路赛道中存在大量 90° 转向和连续路口。为了兼顾整车运行速度和转弯稳定性，系统根据预先规划的路线，在指定路径点完成后切换下一赛段的基础速度，使较长的直线路段采用较高速度，而转弯较为密集的区域采用相对较低的基础速度。车辆采用左右双电机差速转向，主控制器输出 PWM 和方向控制信号，由电机驱动电路控制左右驱动电机。此外，车模还配置负压装置，主程序按照车辆启动时序控制负压电机工作。

2.4 小结
本章介绍了系统的总体方案和各主要模块的作用。系统以 TC264D 作为主控制器，以灰度摄像头完成赛道信息采集，以编码器和陀螺仪提供运动状态反馈，并通过双电机差速完成车辆转向。后续章节将分别对机械结构、硬件组成及软件控制方法进行详细说明。

第三章机械结构设计及调整
智能车的控制策略和软件算法决定了车辆的基本运行方式，而机械结构同样会直接影响车辆能够达到的实际性能。当车速提高后，车辆在快速转向过程中更容易出现侧滑和姿态波动，因此需要合理安排摄像头、电池、主控板以及驱动电机等部件的位置，使整车具有较为合理的质量分布和稳定的机械结构。
3.1 整车布局
本系统采用缩微车模，左右两侧分别布置驱动电机，并通过左右轮速度差实现车模转向。整车布局综合考虑主控板、摄像头、编码器、电池和驱动电机的位置，在满足各模块安装要求的同时，使车身结构尽量紧凑，并保持较为合理的质量分布。摄像头安装在车模前上方，以获得满足循迹和特殊元素检测需要的前方赛道视野。

3.2 摄像头的安装
摄像头的安装高度和俯仰角会直接影响其能够观察到的赛道范围。为了保持安装结构稳定，本系统采用铝合金杆作为摄像头支撑杆。调整摄像头的安装高度和角度，使图像中能保留足够的赛道信息。镜头前加装偏振滤光片，以削弱赛道表面反光对灰度图像的影响，并使用热熔胶对摄像头安装结构进行加固。

图 3.3 : 摄像头固定示意图
3.3 车模底盘及电池安装
车模使用 300 mAh 电池供电，并将电池安装在智能车底盘中心位置。电池与主控板、驱动电机等部件共同进行布局，使整车结构保持紧凑，并避免较大的左右质量偏移，为车辆高速行驶和快速转向提供较为稳定的机械基础。

第四章硬件电路设计
硬件系统是车辆稳定运行的基础。本系统围绕 TC264D 主控制器搭建车模控制平台，并连接灰度摄像头、正交编码器、IMU660RC、液晶屏、按键、电机驱动以及负压装置等模块。硬件设计以满足各功能模块的连接和控制要求为主要目标，同时尽量保持主板结构简洁，便于安装和调试。
4.1 单片机系统设计
单片机系统是智能车控制的核心。考虑到灰度图像处理、特殊元素识别、双电机闭环控制以及多路外设接口等需求，本系统选择 Infineon TC264D 芯片作为主控制器，并使用核心板完成主控制器与车载主板的连接。TC264D 负责摄像头图像处理、路径状态管理、方向控制、速度控制以及车载人机交互等任务。
4.2 传感器的选择
4.2.1 编码器
车辆左右驱动轮分别配置正交编码器。主控制器周期性读取两个编码器的计数值，并将其作为左右轮实际速度的反馈量。编码器反馈与目标速度进行比较后进入左右电机速度控制器，从而形成独立的双轮速度闭环。
4.2.2 摄像头
摄像头是车辆获取赛道信息的主要传感器。本系统采用 MT9V034 总钻风灰度摄像头，实际处理图像分辨率为 188×120。主控制器直接读取灰度图像，通过阈值判断、逐行扫线和局部特征检测获得赛道中线、左右边界及上边界等信息，为普通循迹、直角识别和 T 字路口识别提供依据。
4.2.3 IMU660RC 六轴惯性传感器
本系统使用 IMU660RC 六轴惯性传感器[3]获取车辆绕 Z 轴方向的角速度。车辆启动后首先对陀螺仪进行零偏校准，随后对去除零偏后的 Z 轴角速度进行积分，得到车辆相对于启动后的航向角变化。相对航向角主要用于普通直角和左右 T 字路口的转角判断，而当前 Z 轴角速度则参与方向控制，用于抑制快速转向过程中的过度旋转和振荡。
4.3 主板
车载主板用于连接 TC264D 核心板以及各类传感器和执行器。主板包含屏幕与按键交互接口、摄像头接口、编码器接口、IMU 接口、电机控制接口以及其他车载外设接口。整体布局以满足实际接线和安装需求为主，并尽量减少车内连线的复杂程度，便于车辆调试和维护。


图 4.3 : 主板原理图
4.4 电机驱动电路
电机驱动电路负责将主控制器输出的控制信号转换为左右驱动电机所需的驱动输出。主控制器分别向左右电机提供方向控制信号和 PWM 信号，通过改变 PWM 输出控制电机驱动力，并利用方向信号控制电机旋转方向。左右驱动轮的编码器反馈分别进入速度闭环控制器，使两侧电机能够按照各自的目标速度运行，并通过左右目标速度差完成车辆差速转向。

4.5 负压装置
车模搭载负压装置，负压电机由主控制器通过独立 PWM 通道进行控制。车辆启动和停止过程中，主程序根据当前运行状态控制负压电机的工作时序，使负压装置与左右驱动电机按照设定顺序启动和停止。负压系统使用无刷电机及相应电调模块完成驱动，具体启动时序在第五章的软件控制部分中进行说明。

第五章软件控制设计
5.1 程序运行主要流程
系统上电后首先完成摄像头、液晶屏、IMU660RC、按键、正交编码器、左右电机 PWM 以及负压电机 PWM 等模块的初始化，随后进入主循环。主循环持续处理按键和菜单状态，并在摄像头完成一帧图像采集后执行赛道图像处理。车辆尚未启动时，图像处理仍持续运行，因此可以在发车前观察摄像头图像和赛道识别结果。
操作者通过菜单发出 START 请求后，程序复位本次发车所需的控制状态，并开始启动延时和陀螺仪零偏校准。IMU660RC 以固定周期读取 Z 轴角速度，发车后前约 1 s 的数据用于计算静止零偏。在 3 s 的车辆启动延时期间，负压装置先于驱动轮启动：START 后约 1.8 s 开启负压，达到 3 s 延时且陀螺仪校准完成后，才允许左右车轮进入闭环控制。该启动方式使陀螺仪校准、负压启动和驱动轮启动按照固定时序完成。
车辆运行过程中，摄像头图像处理持续更新方向误差和特殊场景状态； 5 ms 周期任务负责陀螺仪更新和方向差速目标计算，2 ms 周期任务读取左右编码器并执行电机速度闭环控制。车载菜单在车辆运行过程中仍可用于查看状态和切换摄像头显示。当程序满足主动终点停车条件或触发丢线保护后，左右驱动电机停止输出，同时负压装置停止运行。

5.2 图像处理
本系统使用灰度摄像头采集赛道图像，图像分辨率为 188×120。程序不再单独生成完整的二值化图像，而是在普通扫线和特殊元素检测过程中直接读取原始灰度值，并将像素灰度值与设定阈值进行比较。当像素灰度值大于或等于阈值时，将其判定为白色赛道区域；否则将其判定为黑色背景。
白色像素判断阈值以程序参数形式保存。普通扫线根据该阈值寻找各行中的白色赛道区域；直角和 T 字路口识别则在灰度阈值判断基础上，进一步结合局部灰度变化、白色区域连续宽度和连续高度等特征进行确认。通过多种局部条件共同判断，可以减少单个亮点、赛道反光或局部图像噪声造成的错误识别。

5.4 元素处理
5.4.1 直角
普通直角弯容易因赛道边界迅速离开摄像头视野而出现大范围丢线。本系统首先在图像指定区域内检测左右两侧的边界特征。当仅检测到单侧边界，并且上方边界未满足 T 字路口确认条件时，将当前场景识别为普通左直角或右直角。
进入普通直角场景后，系统锁定当前转向状态，同时记录进入场景时的相对航向角。随后对指定范围内的中线进行侧向覆盖，使方向环产生足够大的转向偏差。转弯过程中持续计算当前航向角与进入场景时航向角之间的差值，当累计转角达到设定条件后解除场景锁定，恢复普通扫线。
由于车辆刚看到 T 字路口时，完整的左右边界和上边界特征不一定会同时进入摄像头视野，因此系统在普通直角锁定后仍继续检测另一侧边界和上方边界。当补充特征满足要求，并且当前转角仍位于允许升级的范围内时，可将已经锁定的普通直角升级为 T 字路口。升级过程中沿用进入原普通直角场景时记录的角度基准，避免重新计算起始角度造成转角判断不连续。
5.4.2 补线
在直角和 T 字路口等特殊区域，原始扫线得到的中线可能出现缺失或方向不符合实际行驶需求，因此需要根据当前特殊场景对中线进行补偿。对于左转和右转场景，系统将指定范围内的中线覆盖到图像对应侧，使方向误差快速增大，从而驱动车辆完成急转。
对于直行 T 字路口，系统选取上边界中心点和下方中线点作为补线端点。两点可以确定一条直线，因此根据两个端点坐标计算中间各图像行对应的横坐标，并将结果写入中线数组，在原始赛道中线缺失区域形成一条连续的引导中线。补线结果可以直接参与后续加权方向误差计算。

5.4.3 T 字路口
系统通过预设的局部检测区域识别 T 字路口特征。当左右两侧边界同时满足确认条件，或者单侧边界与上方边界同时满足确认条件时，系统判定车辆进入 T 字路口。进入路口后锁定当前场景和本次路径事件，避免同一个路口在连续图像帧中被重复计数。
T 字路口的行驶方向由预先设置的路径序列确定，每一个路径事件对应左转、右转或直行三种状态之一。左转和右转状态采用侧向中线覆盖，使车辆快速产生相应方向的差速，并根据陀螺仪累计转角判断退出；直行状态采用两点连线方式补全中线，并在保持规定帧数后退出。当前场景结束后，系统恢复普通扫线，并在下一个 T 字路口读取路径序列中的下一项。

5.4.4 停车判定与保护
系统设置了被动丢线保护。程序在图像底部指定区域内按一定间隔采样白色赛道像素。当检测区域中仍能够找到有效白点时，认为车辆仍处于赛道范围内；若该区域连续多帧未检测到有效白色像素，则认为车辆可能已经严重偏离赛道，触发强制停车状态。采用连续多帧确认的方式，可以减少短时丢线和图像噪声造成的误停车。
除丢线保护外，系统还设置了正常比赛路线的主动停车逻辑。程序根据已经完成的路径事件和运行圈数判断是否到达预设终点条件，当满足主动停车条件时，在规定的路径事件完成并退出后置位停车状态。无论是主动停车还是被动保护停车，系统都会停止左右驱动电机输出，并停止负压装置运行。
5.5 启动与路径速度规划
5.5.1 启动时序与首次软启动
为避免车辆从静止状态直接进入较高目标速度，系统对第一次发车设置了速度软启动过程。完成启动延时并允许驱动轮运行后，实际使用的基础速度从较低的初始值开始，以固定周期逐步增加，直至达到当前赛段设置的基础目标速度。首次软启动完成后，软启动状态被锁存，不再对后续赛段的速度切换重复执行速度斜坡。
与车轮软启动同时，系统还对负压装置和陀螺仪设置独立启动时序。按下 START 后首先开始 IMU 零偏校准和整体启动计时；约 1.8 s 后开启负压装置，达到 3 s 延时并确认 IMU 校准完成后才允许驱动轮闭环控制开始运行。这样可以保证车辆正式起步之前完成必要的传感器初始化和执行机构启动过程。

5.5.2 路径点速度规划
疯狂电路的完整路线由大量直角和 T 字路口组成，不同路段允许的稳定运行速度存在明显差异。因此本系统并非始终使用同一基础速度，而是将速度规划与预先设置的 T 字路口路径序列相结合。程序对已经完成的 T 字路口路径事件进行编号，并在部分指定路径点退出后切换下一赛段的基础目标速度。
对于较长的直线路段，可以设置较高的基础速度，以缩短整体运行时间；对于连续急转或转弯间距较短的区域，则降低基础速度，为车辆转向和重新稳定留出足够时间。第一次发车的基础速度变化通过软启动逐步完成，而首次软启动结束后，路径点触发的基础速度调整采用直接切换方式，使车辆能够及时进入下一赛段要求的目标速度。
5.6 闭环控制算法
本系统采用方向环与左右轮速度环相结合的控制结构。摄像头计算得到的 error_x 进入方向控制器，方向控制器根据车辆偏离赛道中心的程度计算左右轮目标速度差；随后左右轮速度环分别根据各自编码器反馈调节电机 PWM，使左右驱动轮跟随对应的目标速度，从而形成“图像方向控制–-左右轮速度闭环”的串联控制结构。
5.6.1 增量式 PID 速度控制
左右轮速度控制采用增量式 PID[4]。设当前时刻速度误差为 e(k)，前两次误差分别为 e(k-1) 和 e(k-2)，则增量式 PID 的输出变化量可以表示为：
系统以固定周期读取两个正交编码器的计数，并分别计算左右轮的实际速度。将左右轮目标速度与实际速度进行比较后，分别计算两侧电机 PWM 的增量，并累加得到新的输出。左右轮采用相互独立的速度控制器，因此在车辆直行和差速转向时，两侧电机都能够跟随各自不断变化的目标速度。
5.6.2 方向环 PD 与差速控制
方向环采用 PD 控制，根据加权中线与图像中心之间的偏差 error_x 计算转向控制量。比例项用于根据当前方向偏差快速产生转向响应，微分项根据相邻计算周期中偏差的变化抑制过快的方向变化。同时，系统将 IMU660RC 采集的 Z 轴角速度引入方向控制输出，形成角速度阻尼项，以改善车辆急转过程中的动态稳定性。
方向环输出随后转换为左右轮目标速度差。当转向控制量增大时，一侧目标速度提高，另一侧目标速度降低，从而通过双电机差速完成车辆转向。程序同时对方向输出及左右轮允许差速进行限制，避免因瞬时图像误差过大而产生过强的差速指令。方向环负责给出车辆需要的转向趋势，左右轮增量式 PID 则负责使实际轮速跟随最终得到的左右目标速度。

第六章开发工具和调试过程说明
6.1 英飞凌 AURIX Development Studio
本系统采用英飞凌 AURIX Development Studio 作为软件开发工具。该开发环境面向 AURIX 系列微控制器，提供工程管理、C/C++ 程序编辑、TASKING 编译、程序下载和在线调试等功能。本系统使用 AURIX Development Studio 完成 TC264D 主控程序的编写、编译、烧录和调试。
6.2 车载状态显示与调试
主项目通过车载液晶屏和按键完成运行状态观察及部分人机交互。程序设置了图像中线误差、左右边界识别结果、T 字路口序号、当前特殊场景类型、陀螺仪相对航向角以及停车状态等调试变量，并可将相应信息显示在车载液晶屏上。发车前可以通过显示页面观察摄像头图像和赛道识别结果；车辆运行过程中，也可以通过按键切换摄像头图像显示状态，以便检查实际运行时的中线和特殊元素识别情况。
6.3 独立项目及上位机调试
为了连续观察速度控制过程中的动态波形，我们另外建立了独立调试工程，通过 WiFi-SPI 模块将车辆运行数据发送至上位机，并使用逐飞助手显示相关数据。调试过程中可以同时观察左右轮目标速度、实际速度和 PID 输出等波形，从而分析左右电机的响应速度、超调和稳定情况。
上位机调试主要用于整定左右电机速度环 PID 参数、差速控制参数，并观察负压装置开启后车辆速度响应的变化。通过实际波形反复调整参数后，再将验证后的控制参数应用于最终主项目。与仅通过车辆运行现象判断相比，上位机曲线能够更加直观地反映控制器的动态响应，有利于提高参数整定效率。

第七章结论
本文围绕第二十一届全国大学生智能汽车竞赛疯狂电路组的比赛要求，完成了缩微车模的机械安装、硬件搭建、赛道图像处理、特殊路口识别、车辆运动控制以及整车调试。系统以 TC264D 为主控制器，利用 MT9V034 灰度摄像头获取赛道图像，通过两个正交编码器构成左右轮速度反馈，并结合 IMU660RC 的 Z 轴角速度和相对航向角完成特殊转弯场景的角度判断与方向阻尼控制。
软件部分采用逐行扫线和多行加权方式计算方向误差，并针对普通直角和 T 字路口设计了场景锁定、中线补偿、普通直角升级 T 口以及对应的退出逻辑。在运动控制方面，系统采用方向 PD 与左右轮增量式 PID 相结合的控制结构，并根据预设路径点切换不同赛段的基础速度；首次发车加入软启动，同时配合负压装置的提前启动时序，以提高车辆起步和高速运行过程中的稳定性。
在调试过程中，除车载液晶屏状态显示外，还通过独立 WiFi-SPI 调试工程和逐飞助手观察左右轮速度及控制输出波形，对速度环 PID、差速参数和负压开启后的车辆响应进行整定。经过多轮赛道测试和参数调整，系统最终能够按照预设路线完成循迹、特殊路口处理、赛段变速以及终点停车等任务。

//============================================================
// 检测并确认T口上边界
//============================================================
static void detect_top_boundary_confirmed(int cx)
{
    // 局部变量：y_line 保存本帧上边界扫描行
    int y_line = get_rect_top_y(cube_probe_y);

    // 局部变量：d 为围绕中心x向左右扩展检测的偏移量
    int d;

    y_line = CLAMP(y_line, 1, IMG_H - 2);

    cube_top_scan_y = y_line;
    cube_top_center.row = y_line;

    for (d = 0; d <= g_rect_half_w; d += RECT_SCAN_STEP)
    {
        // 保存当前偏移下需要检测的候选x坐标
        int probes[2];

        // 当前有效候选x坐标数量
        int probe_cnt = 0;

        // probes数组遍历索引
        int i;

        probes[probe_cnt++] =
            CLAMP(cx - d, 2, IMG_W - 3);

        if (d != 0)
        {
            probes[probe_cnt++] =
                CLAMP(cx + d, 2, IMG_W - 3);
        }

        for (i = 0; i < probe_cnt; i++)
        {
            // 当前找到的上边界候选白段中心x
            int seg_center = -1;

            if (find_white_segment_on_row(
                    y_line,
                    probes[i],
                    &seg_center))
            {
                // 候选点向上的连续白高
                int white_up_h;

                // 候选点向下的连续白高
                int white_down_h;

                cube_top_candidate_hit = 1;
                cube_top_candidate_x = seg_center;

                // 测量候选点向上的连续白高
                white_up_h =
                    measure_continuous_white_height_col(
                        y_line,
                        seg_center);

                // 测量候选点向下的连续白高
                white_down_h =
                    measure_continuous_white_down_height_col(
                        y_line,
                        seg_center);

                cube_top_white_h = white_up_h;

                // 向上和向下的白高必须同时满足要求，
                // 才正式确认上边界命中
                if (white_up_h >=
                        g_top_confirm_white_h &&
                    white_down_h >=
                        g_top_confirm_white_down_h)
                {
                    cube_top_hit = 1;
                    cube_top_center.x = seg_center;
                    return;
                }
            }
        }
    }
}
