摘　　要

本报告介绍了疯狂电路队在第二十一届全国大学生智能汽车竞赛疯狂电路组别中的参赛智能车技术方案。整车以英飞凌 TC264 双核微控制器为核心，采用 MT9V034 全局快门摄像头采集赛道图像，配合 LSM6DSV16XTR 六轴姿态传感器估计车体姿态，由轻型 030 有刷强磁电机驱动，抽吸式负压提高运行速度上限。报告从总体方案、机械结构、硬件电路、软件算法、制作调试等方面进行了系统阐述，重点介绍了图像采集与预处理、赛道识别以及 PID 控制算法的设计与实现。经过整车联调，车模能够稳定完成赛道循迹，达到了预期的设计目标。

第一章 引言
1.1 研究背景与意义
全国大学生智能汽车竞赛是一项以"立足培养、重在参与，鼓励探索，追求卓越"为宗旨的全国性大学生科技竞赛，要求参赛队伍自主完成智能模型车的机械结构、硬件电路、控制算法的设计、制作与调试，使车模能够自动识别赛道并快速稳定地完成比赛[1]。智能车是机械、电子、传感器、嵌入式软件与自动控制等多学科知识的综合载体，对提高学生的工程实践能力、团队协作能力和创新意识具有重要意义。
本队以稳定、轻量、高速为设计目标，选用英飞凌 TC264 双核微控制器作为核心控制平台，采用 MT9V034 全局快门摄像头感知赛道图像，LSM6DSV16XTR 六轴姿态传感器估计车体姿态，使用轻型 030 有刷强磁电机驱动车模，并以 3S 11.1V 锂聚合物电池为系统供电。在带队教师的指导下，本队完成了从方案论证、机械装配、电路设计到软件调试的全过程，本文即对该过程进行系统总结。
1.2 国内外相关研究现状综述
（1）智能车感知技术。视觉传感器能够获取丰富的赛道信息，是智能车导航的主要手段。与卷帘快门传感器相比，MT9V034 等全局快门传感器可有效避免高速运动下的图像畸变与拖影，更适合高速行驶场景[7]。陀螺仪与加速度计等惯性传感器可用于估计车体姿态，为坡道、弯道等场景提供车体状态信息[8]。
（2）赛道识别与路径规划。常用方法包括灰度阈值分割、边缘检测、中线拟合等；近年来基于深度学习的方法也被引入竞赛，但对算力与实时性要求较高。考虑到嵌入式平台的实时性约束，本队采用基于图像特征提取的传统方法进行赛道识别[2]。
（3）运动控制算法。比例-积分-微分（PID）控制因其结构简单、鲁棒性好，在电机转速与转向控制中被广泛采用[4]；针对弯道变速、十字路口等场景，可结合动态参数调整策略进行改进。
（4）嵌入式控制平台。英飞凌 AURIX 系列微控制器凭借多核架构、丰富的外设与较高的运算能力，在智能车竞赛中得到广泛应用[6]，可在多核上并行处理图像与控制任务，满足高帧率、低延迟的控制需求。

图2.1 系统运行框图

第三章 车模机械结构设计
3.1 车模总体机械结构概述
车模以低重心、轻量化、结构可靠为总体设计目标，采用无刷离心风机的抽吸式负压方案。整车沿行进方向按"感知 → 驱动 → 供电"的顺序布置：前端安装摄像头以获取最大前瞻距离，中部布置主控与驱动机构，尾部或中部低处布置电池，使整车重心尽量靠后且贴近地面。车模整体结构如图3.1所示。

图3.1 车模底盘与传感器结构实物图
3.2 抽吸式负压系统
为提升车模高速运行的稳定性与速度上限，本车采用无刷抽吸式负压方案。其原理是利用风机在车底与赛道表面之间形成低压空腔，使车体获得额外的向下压力，从而增大轮胎正压力与侧向抓地力，提高弯道极限速度，并抑制高速行驶中的车身弹跳。
本系统主要由负压风机、无刷电调与负压密封膜三部分组成。负压风机选用 1103 无刷电机驱动的微型风机，具有体积小、重量轻、响应快的特点，适合在有限的底盘空间内提供稳定风压。电调以 STC32G12K128 微控制器为核心，配合 EG2134 三相无刷驱动芯片及功率 MOS 管构成三相逆变驱动电路，由主控输出 PWM 信号调节风机转速，实现负压大小的连续调节；电调内部包含过流保护与堵转保护，保证风机在负压背压升高时仍能可靠运行。
负压密封膜选用聚丙烯（PP）材质，该材料性价比高、韧性好、耐用性强且易于裁剪加工，能够贴合赛道表面形成合格的低压空腔，有效减少负压泄漏，使吸力分布均匀。实测表明，本方案形成的负压空腔密封性良好，吸力达到预期目标。抽吸式负压系统结构如图3.2所示。

图3.2 抽吸式负压系统实物图
在控制策略上，风机转速可根据车模速度与赛道元素动态调节：直线高速段保持较高吸力保证贴地，低速与入弯前根据需求调整，兼顾稳定性和电池续航。
3.3 底盘与车架改造
底盘在保证强度的前提下进行减重处理，去除不必要的材料并合理布置加强筋，避免高速行驶时发生扭转变形。针对赛道颠簸与急加速工况，对电路板安装位置增加减震措施，对传感器支架提高刚性，减少振动对图像与姿态数据的影响。底盘高度通过垫片等结构件进行调节，在通过性允许的范围内尽量降低底盘，以降低整车重心。底盘碳纤维板布局如图3.3所示。

图3.3 底盘碳纤维板布局示意图

3.4 转向机构设计
本车采用双电机独立驱动、差速转向方案：两个 030 有刷强磁电机分别驱动左右后轮，通过两侧轮速差实现转弯，结构简单、响应直接。侧板采用 6061 铝合金 CNC 精加工一体成型，兼顾结构强度与轻量化需求。侧板结构如图3.4所示。

图3.4 侧板结构示意图

3.5 驱动机构设计
驱动电机选用轻型 030 有刷强磁电机，具有体积小、重量轻、扭矩密度高的特点。电机通过减速齿轮组驱动双轮，减速比根据最高车速与加速性能要求综合确定。选用抓地力适当的光头胎，并保证左右轮一致性，减少跑偏。

3.6 传感器安装设计
摄像头 MT9V034 安装于车模前部，安装高度、俯仰角与前瞻距离经过反复试验确定，在保证足够前瞻的同时尽量降低重心、减小图像透视变形。姿态传感器 LSM6DSV16XTR集成在PCB上、而PCB靠近重心位置，与车体刚性固定，并使用垫片采取减震措施，以减小振动对姿态解算的干扰。
3.7 电路板与电池固定
电池（3S 180mAh）布置在车体低重心位置，采用支架加魔术贴固定，兼顾可靠性与快速拆装；主驱一体板固定牢靠，器件采用防松螺母设计，防止高速行驶中松动。

第四章 硬件电路设计
4.1 硬件电路总体架构
硬件系统以 TC264 主控板为核心，分为主控电路、电源电路、电机驱动电路、图像采集接口电路、姿态传感器接口电路和调试通信电路等模块。电路设计遵循"可靠、高效、简洁"的原则，将大电流回路与数字信号回路分离，各模块电源入口均设置滤波与去耦电容。
4.2 主控最小系统
TC264 最小系统包括电源、晶振、复位电路、滤波电容与程序下载调试接口。电源采用多路去耦电容组合，保证内核与 I/O 供电稳定；晶振电路靠近芯片引脚布局，走线尽量短；下载调试接口引出以实现进一步减重。TC264 最小系统如图4.1所示。

图4.1 TC264 最小系统
4.3 电源电路设计
整车由 3S 11.1V 锂聚合物电池供电。电机驱动直接使用电池电压；逻辑电路所需电压由稳压电路产生，主要包括 5V 与 3.3V 两路。开关电源采用RY9121E负责大电流转换，其ECOT控制方式带来非常快速的瞬态响应，同时使环路设计变得简单，输出稳压精度也很高，且仅需极少数常用的外部元件即可工作，整板LDO均为LP5907QMFX-3.3 ，LP5907-Q1 采用创新的设计技术，无需噪声旁路电容便可提供出色的噪声性能，并且支持远距离安置输出电容[5]。电源电路原理图如图4.2、图4.3所示。

4.4.1 负压风机无刷电调
负压风机采用独立无刷电调驱动。电调以 STC32G12K128 微控制器为核心，配合 EG2134 三相无刷驱动芯片与功率 MOS 管构成三相逆变电路，由 PWM 信号调节 1103 无刷电机转速，从而控制负压大小。电调具备过流保护与堵转保护功能，并预留与主控的通信接口，便于根据车速与赛道元素动态调整风机转速。

第五章 软件控制算法设计
5.1 软件开发环境与工程结构
软件开发环境采用英飞凌 AURIX Development Studio（或 IAR）[6]，使用 C 语言编写。工程按功能模块化组织，分为底层驱动（时钟、GPIO、ADC、PWM、DMA、串口、SPI/I2C）、传感器驱动（摄像头、姿态传感器）、图像处理、控制算法与应用主循环等模块，便于调试与维护[3]。
5.2 图像采集与预处理
摄像头图像通过场中断与像素中断（或 DMA）方式采集到内存，采集完成后先进行预处理：根据光照情况采用大津法或动态阈值计算二值化阈值，将灰度图转换为二值图；针对反光、噪点等干扰，采用形态学处理或邻域滤波滤除孤立白点，提高后续识别的稳定性。
5.3 赛道识别与路径生成
在二值图像基础上，采用八邻域爬线寻找赛道边界：对每一行，得到左右边界点；对异常行（找不到边界或边界突变过大）进行无效行处理，避免造成误识别。在有效行上取左右边界中点拟合成赛道中线，并根据近端与远端的边界信息计算车体相对赛道的横向偏差与方向偏差，作为控制输入。
针对T形路口，十字路口等特殊元素，分别设计识别与节点规划：识别路口延伸方向等处理。
5.4 姿态解算
LSM6DSV16XTR 以固定频率输出三轴加速度与三轴角速度，进行姿态解算[8]，估计车体yaw角。姿态信息一方面用于速度补偿，另一方面可辅助判断直角旋转角度，提高元素处理的可靠性。
5.5 运动控制算法
转向控制采用位置式 PD 算法，根据赛道偏差与偏差变化率计算目标转向量；速度控制采用增量式 PI 算法，通过编码器测速构成速度闭环。速度策略根据赛道元素动态调整：直道高速、弯道减速、入弯提前降速，避免"猛加猛减"。对于双电机差速方案，将转向量与速度量换算为左右轮目标转速，分别控制两个电机。
5.6 程序调度与控制周期
程序采用中断与主循环结合的方式运行：图像采集与速度采样在中断中完成，图像处理与控制算法在图像采集完成后执行，控制量在中断或定时器中输出，保证控制周期稳定。各任务优先级与执行时间经过优化，满足实时性要求。

第六章 系统制作与调试过程
6.1 开发工具与调试环境
开发工具包括 AURIX Development Studio（或 IAR）编译环境、程序下载调试器、示波器、万用表、逻辑分析仪以及自主开发的上位机调试软件。上位机通过串口或无线模块接收车模实时图像与参数，用于离线分析与在线调参。
6.2 机械部分装配与调试
机械装配按照"底盘 → 总钻风底座、电机、电池→  主驱一体板"的顺序进行，每完成一个部分即检查固定牢靠度与运动灵活性。重点调试内容包括：底盘高度与重心位置、电机与减速机构同轴度、左右轮一致性、摄像头角度与前瞻距离、传感器固定刚度等。
6.3 硬件电路调试
硬件调试按"电源 → 主控 → 外设"的顺序进行：先检查各电压输出是否正常、纹波是否满足要求；再下载最小程序验证主控运行；随后逐模块调试摄像头、姿态传感器、电机驱动与通信接口，确认信号波形与通信时序正常。
6.4 软件算法调试与参数整定
软件调试先进行模块级验证，再逐步联调。图像处理部分通过上位机观察二值化与扫线效果，调整阈值与滤波参数；控制部分先在直道上整定速度环与转向环参数，再针对弯道与特殊元素分别调整，最后通过记录赛道数据回放分析异常工况。
6.5 整车联调与赛道实测
整车联调以完整赛道为目标，逐步提高车速，记录各元素处的图像、姿态与控制量数据，反复优化参数。经过多轮测试，车模能够稳定完成赛道循迹，达到设计指标。

第八章 结论
本文系统介绍了疯狂电路队参赛智能车的设计方案与制作调试过程。整车以英飞凌 TC264 为控制核心，采用 MT9V034 摄像头与 LSM6DSV16XTR 姿态传感器构成感知系统，由 030 有刷强磁电机驱动，3S 电池供电。在机械方面，通过低重心、轻量化和传感器合理布局保证了高速稳定性；在软件方面，完成了图像预处理、赛道识别、姿态解算与 PID 控制算法的设计与实现。
经过整车联调与赛道实测，车模能够稳定完成赛道循迹任务，达到了预期的设计目标。但在以下方面仍有改进空间：一是整车重量与重心位置可进一步优化，提高极限速度下的稳定性；二是图像处理算法在极端光照下的鲁棒性有待增强；三是特殊赛道元素的识别策略可以更加细化，进一步提高通过成功率。后续将针对上述问题继续改进

uint8 cam_otsu_threshold(void)
{
    uint32 hist[256] = {0};
    uint32 total = CAM_IMAGE_BOTTOM_H * MT9V03X_1_W;
    uint32 sum_all = 0;
    uint32 w0 = 0, sum0 = 0;
    float max_variance = 0;
    uint16 i;
    uint8 j, threshold = 0;

    for (i = 0; i < CAM_IMAGE_BOTTOM_H; i++)
    {
        for (j = 0; j < MT9V03X_1_W; j++)
        {
            hist[cam_image_bottom[i][j]]++;
        }
    }

    for (i = 0; i < 256; i++)
    {
        sum_all += i * hist[i];
    }

    for (i = 0; i < 256; i++)
    {
        w0 += hist[i];
        if (w0 == 0) continue;

        uint32 w1 = total - w0;
        if (w1 == 0) break;

        sum0 += i * hist[i];
        float m0 = (float)sum0 / w0;
        float m1 = (float)(sum_all - sum0) / w1;
        float variance = (float)w0 * w1 * (m0 - m1) * (m0 - m1);

        if (variance > max_variance)
        {
            max_variance = variance;
            threshold = (uint8)i;
        }
    }

    if (threshold < CAM_OTSU_MIN) threshold = CAM_OTSU_MIN;
    if (threshold > CAM_OTSU_MAX) threshold = CAM_OTSU_MAX;

    return threshold;
}

void Speed_Decision(void)
{
    if(speed_decision_enable == 0)
    {
        speed = target_speed;
        return;
    }

    int seg_dist = encoder.target_distance;
    int base = target_speed;

    if(seg_dist > CM_TO_ENCODER(90))
    {
        if(encoder.disA >= seg_dist * 20 / 100 && encoder.disA < seg_dist * 75 / 100)
        {
            speed = base + 350;
        }
        else
        {
            speed = base;
        }
    }
    else
    {
        speed = base;
    }
    return;
