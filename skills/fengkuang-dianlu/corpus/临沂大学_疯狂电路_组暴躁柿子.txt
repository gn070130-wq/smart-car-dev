摘要
本文介绍了临沂大学的队员们在准备此次比赛中的成果。 本次比赛采用自制车模， 硬件平台采用TC387， 软件平台使用ADS。
文中介绍了本次我们的智能车控制系统软硬件结构和开发流程，整个智能车涉及车模机械调整， 传感器选择， 控制算法优化等许多方面。整辆车的工作原理是先将小车的控制周期中提取出相应的时间片，相应的时间片作为一次控制周期， 用来控制速度和转向，由MT9V034摄像头采集赛道信息至主板， 由久久派读取信号进行分析处理， 运用我们自己的软件程序对赛道信息进行提取并以此为根据控制舵机和电机。
在进行大量的实践之后，表明我们的系统设计方案完全是可行的。
【关键词】智能车，TC387，MT9V034摄像头


第一章 系统整体设计
1.1系统概述
光电（摄像头） 智能车系统的总体工作模式为： MT9V034摄像头采集赛道信息，输入到tc387，经过软件二值化后的得到巡线；通过编码器来检测车速，通过LSM6DSRTR加速度计陀螺仪采集车身姿态，驱动强磁电机采用PID控制，通过PWM控制驱动电路调整电机的功率；而车速的目标值由默认值和基于图像处理的优化策略进行综合控制。
该系统总共包括 6个子系统： 电源模块、 主控制器模块、 赛道采集模块、 电机控制模块、调试模块、姿态传感器模块。
1、主控制器模块
使用英飞凌 AURIX TC387 作为智能车底层实时域控主控制器，该芯片采用 32 位 TriCore 多核架构，4 颗运算核心主频 300 MHz，内置硬件浮点单元，搭载 10 MB 带 ECC 校验 Flash 与 1568 KB ECC 保护 SRAM，原生支持裸机程序或 AUTOSAR、FreeRTOS 实时操作系统，具备硬件锁步安全内核，中断响应速度快、时序确定性强，能够满足智能车多传感器实时采集、电机闭环运动控制、多节点总线协同等高实时性控制需求。
2、赛道采集模块
使用逐飞科技提供的MT9V034摄像头作为光电传感器进行赛道图像采集， 通过使用场中断触发主控制器开始图像采集、 像素中断控制采集速度。
3、姿态传感器模块
姿态传感器模块主要为速度传感器，使用普地提供的带方向编码器读取实时速度， 用于对于电机进行闭环控制。
4、电机控制模块
使用030强磁电机进行车模的速度控制。
5、调试模块
调试模块由IPS屏幕、 组合按键、tape-C串口组成。
6、电源模块
	电源模块分为四类：
第一类为12V电池电压，用于驱动电机。
第二类是5V电源，用于给核心板和电调MCU供电，并配有5V指示灯。
第三类为干净3.3V电压，供给对噪声非常敏感的姿态传感器和摄像头模块。
第四类为一般3.3V电压，供应给编码器，下载调试器，拨码开关，按键等各模块，并配3.3V指示灯。
第二章 机械系统设计与实现
智能车车模的机械结构设计是智能车制作过程中极具关键性的一环，它极大程度地影响着小车的行驶平稳性和精度。合理且合适的机械结构设计加上软件的算法控制能够使小车的运行状态得到最大的优化和提高。因此在实际设计中，学习和了解机械结构设计的基本知识同时，也要通过不断测试已做的机械设计的实际结果来不断调整优化机械结构来实现高效完美的小车机械结构。本章内容也将对车模类型、车模机械部分安装及改造、传感器的设计安装、系统电路板的固定及连接等进行介绍。
2.1 车模类型介绍
车模选择的自制车模，采用3D打印的方式，打印出车的底板、侧板、轮毂等小零件进行组装，车轮胎皮采用硅胶自制胎皮。
车模底板我们选择的是2mm厚的玻纤板，相比碳板，其有更好的绝缘性和刚性。
2.2 机械结构设计方案
车模允许自制，我们对比了两种方案，包括前置万向轮式的三轮差速车，双电机四轮差速车，最终发现对于今年的赛题组，三轮上限低，而双电机四轮差速几乎是最优结构，在转向和控制的方面表现最好，因此选用四轮差速。
2.3 摄像头安装
   对于前瞻的我们选用更细的毫米碳素杆进行搭建，在自制车模时就考虑到碳素杆如何又方便又稳固的搭建，最终我们自己设计了一种固定结构，并将其3D打印出来，将碳素杆固定至该结构件，结合胶枪进行牢固，这样我们就能够很好的控制电磁传感器的高度与角度。
2.4 编码器安装
编码器是用来对车速进行测算的仪器，目前很多学校使用的是通过光电编码的编码器，其精度较高、安装较为方便，但体积有点大。编码器的安装精度较高，要求编码器轴与赛车后轴同轴，且编码盘必须与赛车的中心线共线。 我们是直接装在车上，利用齿轮与差速器上的大齿轮相咬合。这种安装方法方便快捷，更能较准确的测出电机的转速。
2.5 负压的实现
负压风扇的加入，大大提高了车模的上限，车底盘中央靠前的地方放置风机扇叶，采用1103无刷电机，利用涵道效应来产生负压力。

3.6.硬件部分的总结
对于硬件部分，能够满足调车的需求是最基本的。对于我们注重的是稳定性和实用性。在我们的一年的锻炼和学习中，从一开始使用最稳定、常用的电源方案，分模块根据经典应用设计制作电路到逐渐有自己的想法。在创新的基础上，都要保证稳定性，足够稳定既包含电路板本身的性能稳定、也包含电路板的安装稳定。我们发现如果电路板在行驶的过程中固定不牢有松动，复位这种情况就很容易发生。复位很大一部分原因是电路板的元器件比如大的电容松动。硬件部分作为整个车的基础，通过原理图绘制 PCB，制板后上车验证，根据实际情况，调整方案，最后定型。
第四章 软件系统设计及实现
4.1 软件控制程序的整体思路 
软件编写的目的，是控制车模在既定规则前提下，以最快的速度，最多的超车次数，跑完整个赛道。不论上哪种方案，软件的总体框架总是相似的，我们追求的就是稳定至上，兼顾速度。软件上大类分为图像采集、图像处理识别、会车控制，速度控制以及速度反馈。 
4.2 主程序流程
采用初始化+主循环+中断架构。上电初始化时钟、GPIO、定时器、中断、外设和变量，就绪后进入主循环。主循环按时间片执行图像处理、姿态解算、速度计算、转向与速度控制、PWM更新、按键处理、IPS显示、激光逻辑和状态监测。中断处理摄像头帧同步、编码器脉冲、控制周期时基和串口通信。
4.3 摄像头图像处理算法
4.3.1 中心扫线
中心扫线是指每行图像的起始扫线都是从上一行图像的中线位置开始的，从白点向左向右扫到黑点及寻找到所需要的边界线，进而拟合出赛道中心线。
优点：对于环境光线依赖比较小，如由于光线不均匀造成的反光仅仅会影响反光存在的几行，而不会对整幅图像之后的边界线提取造成干扰；
缺点：比较消耗时序，需要遍历图像中大多数像素点才能够找到赛道的边界线，同时由于环岛等特殊元素的存在，使我们寻找的边界线与环岛的特征点有一定的差距，不利于元素的识别。
4.3.2 根据不同的赛道元素类型，指定每行的扫线起始点
“根据不同的赛道元素类型，指定每行的扫线起始点”是指在每行扫线的过程中，同时对元素类型进行区分，根据先前确定下来的赛道元素类型明确扫线的方向及起始点。
如在正常扫线可以将下一行的扫线起点指定为本行的左右边线，这种方式的扫线可以最大限度的简化程序执行流程，同时我们可以在扫线的应用“搜索”中“剪枝”的思想。
如在扫线的过程中判断是否已经扫到了赛道外，如果已经扫出赛道即停止扫线，体现了“可行性剪枝思想”；在对特殊元素的判断中，可以根据之前图像找到的特征点具体位置寻找这场图像的特征点，体现了“记忆化搜索思想”。
4.4 电机PID控制算法
PID控制器以其原理简单、适应性强、工作可靠、调整方便等优点而在实际工程中得到广泛的应用。其主要由比例单元（P）、积分单元（I）和微分单元（D）组成。当我们不完全了解一个系统和被控对象，或不能通过有效的测量手段来获得系统参数时，最适合用PID控制技术，实际中也有PI和PD控制。
PID 控制器是一种线性控制器，它根据给定值与实际输出值构成控制偏差，将偏差的比例(P)、积分(I)和微分(D)通过线性组合构成控制量，对被控对象进行控制。采用PID实现电机速度闭环：


比例环节：及时成比例地反映控制系统的偏差信号,偏差一旦产生,控制器立即产生控制作用,以减少偏差.
积分环节：主要用于消除静差,提高系统的无差度.积分作用的强弱取决于积分时间常数,越大,积分作用越弱,反之则越强.
微分环节：能反映偏差信号的变化趋势(变化速率),并能在该偏差信号变得太大之前,在系统中引入一个有效的早期修正信号,从而加快系统的动作速度,减小调节时间.
第五章 智能车调试说明
前面几章一直是在为系统制定方案以及方案的细化。但整个系统的完善主要还是在系统的现场调试。在细分的每个模块中，大部分都涉及有众多参数， 对这些参数的确定就需要软硬件联合调试。而这过程就需要一整套开发调试环境和工具。包括程序源代码的编辑以编译环境，参数调节与设定工具。 
5.1 上位机调试软件的介绍
上位机在工业控制当中又被称为HMI,就是一台计算机，它的作用是监控现场设备的运行状态，当现场设备出现问题在上位机上就能显示出各设备之间的状态（如正常、报警、故障等）。 
上位机的概念属于计算机集散控制系统的概念。在计算机集散控制系统中， 计算机分为各个级别，与现场设备发生直接关系的计算机属于下位机，用来控制下位机，或给下位机下达新任务的计算机是下位机的“上位机”。若集散控制系统较大，计算机的级别可能不止两级，此时上位机还可能有级别更高的上位机对其进行控制或指派任务。
使用 VOFA + 作为智能车系统调试上位工具，该软件是面向嵌入式开发的轻量化可视化调试平台，原生支持 Windows、Linux、macOS 多操作系统，搭载 FireWater、JustFloat、RawData 三类数据解析引擎，兼顾文本收发与高速浮点数据流解析，无需开发定制上位机程序，可高效接收主控通过串口、TCP/UDP 网口上传的实时数据，实现多通道波形绘制、状态观测与在线参数调节，充分满足智能车 PID 参数整定、传感器信号观测、运动状态监控、多节点数据遥测的调试需求。
软件集成丰富可视化组件资源，支持多路实时波形图、数据仪表盘、3D 姿态显示、滑动调参控件、指令发送模块；内置大容量波形缓存与 FFT 频谱分析功能，可长时间记录、回放运行数据；通信链路兼容有线串口、无线蓝牙、WiFi 透传等常见方案，适配龙芯 2K0300、TC387、STC32G 等各类智能车主控制器，能够直观展示循迹误差、电机 PWM 输出、陀螺仪姿态、速度反馈等关键信息，大幅降低智能车控制算法调试难度，提升参数优化效率。

5.2 上位机软件的使用和调试
 VOFA + 搭建波形观测平台完成智能车电机 PID 参数整定，该上位工具支持串口、网络等多种通信方式接收主控实时输出的目标值、实际反馈值、误差、P/I/D 输出量等浮点数据，通过可视化波形直观呈现控制动态响应过程，能够清晰观测超调量、调节时间、稳态误差、震荡现象，快速完成 PID 参数迭代优化，充分满足智能车电机闭环调速、位置闭环控制的调参需求。
工作流程：主控采集电机编码器速度 / 位置反馈，运行 PID 算法，周期性按照 VOFA + 约定协议打包目标值、反馈值、PID 输出等数据并上传；VOFA + 解析数据流并实时绘制多路波形。调试人员对照波形特征修改参数：波形出现持续震荡则减小比例系数 Kp；响应缓慢、上升时间过长可适度增大 Kp；存在明显稳态静差时增大积分系数 Ki；系统达到设定值后波动较大可引入微分系数 Kd 抑制震荡。同时 VOFA + 支持在线下发指令，可直接修改目标转速、在线更新 PID 参数，无需反复重新编译下载程序，大幅缩短电机闭环算法调试周期。
第六章 总结
本队设计制作了以英飞凌TC387为核心的智能模型汽车系统。机械方面使用自制车模，SolidWorks设计并3D打印。硬件方面设计高度集成主板PCB，整合电源、传感器接口和执行器接口，采用驱动030电机、1103无刷电机负压。软件方面实现灰度对比度搜索赛道提取、PID速度闭环、前瞻转向控制、陀螺仪姿态融合和负压动态调节。

    int row = 0;
    byte slope_index = 0;
    int max_row_length = 0;
    int current_row_length = 0;
    Find_Baseline_use();
    int start_point_col = Baseline_Findline_use();

    if (start_point_col < 2)
    {
        start_point_col = 2;
    }
    if (start_point_col > 184)
    {
        start_point_col = 184;
    }

    for (col = start_point_col; col < 184; col++)
    {
        if (BinPixels[0][col] == 0 && BinPixels[0][col - 1] == 0 && BinPixels[0][col - 2] != 0)
        {
            left_black_col[0] = (byte)(col - 2);
            break;
        }
        else
        {
            left_black_col[0] = 185;
        }
    }

    for (col = start_point_col; col > 2; col--)
    {
        if (BinPixels[0][col] == 0 && BinPixels[0][col + 1] == 0 && BinPixels[0][col + 2] != 0)
        {
            right_black_col[0] = (byte)(col + 2);
            break;
        }
        else
        {
            right_black_col[0] = 0;
        }
    }

    if (left_black_col[0] > 175)
    {
        left_black_col[0] = 175;
    }
    if (right_black_col[0] < 10)
    {
        right_black_col[0] = 10;
    }

    int start_col = right_black_col[0];
    int end_col = left_black_col[0];
    byte center_col = (byte)((start_col + end_col) / 2);

    for (byte i = 0; i < 26; i++)
    {
        for (byte j = 0; j < 70; j++)
        {
            reference_col[i][j] = 0;
        }
    }

    for (slope_index = slope_search_begin; slope_index < slope_search_end; slope_index++)
    {
        reference_col[slope_index][0] = center_col;
        if (BinPixels[0][reference_col[slope_index][0]] != 0)
        {
            for (row = 1; row < 70; row++)
            {
                if (slope_table[slope_index] != 0)
                {
                    col = (int)(((double)row / slope_table[slope_index] + (double)center_col) < 0 ? 0 : ((double)row / slope_table[slope_index] + (double)center_col));
                }
                if (slope_table[slope_index] == 0)
                {
                    col = center_col;
                }
                if (col > 185)
                {
                    col = 185;
                }
                if (col < 0)
                {
                    col = 0;
                }
                reference_col[slope_index][row] = (byte)col;

                if ((BinPixels[row][col] == 0 || row == 69 || col == 184 || col == 1))
                {
                    current_row_length = (int)(myabs(col - center_col) * myabs(col - center_col) + (double)row * (double)row * (double)300);
                    break;
                }
                else
                {
                    current_row_length = 0;
                }
            }

            if (current_row_length > max_row_length)
            {
                max_row_length = current_row_length;
                selected_slope_index = slope_index;
                max_valid_row = (byte)(row);
                current_row_length = 0;
            }
        }
    }

    int last_used_slope = current_used_slope;
    current_used_slope = selected_slope_index;

    if (myabs(last_used_slope - current_used_slope) >= 5 && (cross_flag_right == 2 || cross_flag_left == 2))
    {
        force_cross_slope = last_used_slope;
    }

    if (force_cross_slope != 0 && (cross_flag_right == 2 || cross_flag_left == 2))
    {
        selected_slope_index = force_cross_slope;
        last_used_slope = force_cross_slope;
        current_used_slope = force_cross_slope;
        force_cross_slope = 0;
    }
}

float calculate_steering_pid(int track_error, float error_derivative, float gyro_z_rate)
{
    float pid_result;
    steering_p_out = (-1) * Kp * track_error;
    steering_d_out = (-1) * Kd * error_derivative;
    steering_gyro_d_out = (-1) * GKD * gyro_z_rate / 100;
    pid_result = steering_p_out + steering_d_out + steering_gyro_d_out;
    if (pid_result > steering_output_limit) pid_result = steering_output_limit;
    if (pid_result < -steering_output_limit) pid_result = -steering_output_limit;

    return pid_result;
}
