摘 要

本文以第二十一届全国大学生智能车竞赛为背景，介绍了智能赛车控制系统的软硬件及机械结构和开发流程。该比赛采用C型车模，以英飞凌公司生产的 TC264 芯片作为核心控制器，以Orangepi 5作为AI计算卡，要求赛车在虚拟赛道上沿着蓝色指示标志以最快的速度完成比赛，同时躲开障碍，获取奖励。整个系统涉及车模机械结构调整、传感器电路设计及信号处理、控制算法和策略优化等多个方面。赛车通过语义分割与目标检测对元素进行识别，用 PD 方式对舵机转向进行控制。同时通过编码器获取车模运行速度，采用 PID 算法实现速度闭环控制。
关键词：TC264，Orangepi 5，语义分割，目标检测，图像处理，PID

Abstract
This paper, based on the 21st National University Student Intelligent Car Competition, presents the hardware and software architecture, mechanical structure, and development process of an intelligent racing car control system. The competition adopts a Type-C vehicle model, with the Infineon TC264 microcontroller serving as the main controller and the Orange Pi 5 as the AI computing platform. The racing car is required to follow blue directional markers on a virtual track, complete the course as quickly as possible, avoid obstacles, and collect reward items. The overall system involves multiple aspects, including mechanical structure adjustment, sensor circuit design and signal processing, control algorithm development, and strategy optimization. Semantic segmentation and object detection are employed to recognize track elements, while a PD controller is used for steering control. In addition, the vehicle speed is measured by encoders, and a PID algorithm is adopted to achieve closed-loop speed control.
Keywords: TC264,OrangePi 5; semantic segmentation; object detection; image processing; PID

2.2智能车整体参数调校
智能车的整体参数，包括车体重心、舵机电机放置位置、高度，传感器排布方式等，都对整个智能车系统的稳定运行起着至关重要的作用。小车的布局以精简、可靠、稳定为前提,通过对小车的布局，尽量保证小车左右平衡，以及寻找一个合适的重心，保证小车既能够可靠地抓牢地面，又能够对前轮舵机，后轮电机有较快的响应。
2.3舵机安装
舵机安装直接关系到是否能快速灵敏地转向进而影响小车机械上限，其安装方式有立式安装和卧式安装两种。卧式安装重心更低但不总是符合阿克曼转角原理；立式安装把舵机架高，它由舵机臂竖直平面的运动转化为拉杆水平方向的运动，减少了在同一平面上运动的死区，且更符合阿克曼转角原理。基于以上考虑及两种安装方式的车模实际性能比较，我们最终选择了立式安装。
2.4编码器安装
选用编码器进行速度的测量。本车模使用的是CSPES-500型光电编码器，该编码器集成度高，体积小，精度高，且可以直接安装到电机的尾部，与电机组成一个整体。编码器与电机之间通过焊接的方式进行固定。
2.5摄像头传感器安装
摄像头安装在车体前部，平衡了摄像头视线和车辆重心分布，使整辆车结构更加简洁且便于维修。 
摄像头处安装支架，以固定摄像头的角度和高度。摄像头碳素钢柱子会有一定幅度的摇晃，我们设计额外支架来固定。
2.6智能车机械参数调节
智能车机械参数调整主要涉及到车模底盘高度、车重心位置、齿轮咬合等。具体调整如下：
1.重心位置：重心位置同样影响小车性能。重心过前，增加转向阻力，引起转向迟滞，出现甩尾的情况。另外，如果车速度很快的情况下，上下坡道的时候会造成前轮首先着地，很可能造成意外事故。重心过后，则会使车前轮抓地不足，造成过弯非常不稳定，会出现以后轮为轴旋转的情况，也可能会出现加速过猛而翘头。影响重心的主要部件有板卡、风扇、电池和电机，实际调整以重心在电机处为准，保持各部分重量均衡。
2.齿轮咬合调整：调整齿轮咬合，以不松动，无卡滞，松紧合适为准。另外还要保证齿轮间咬合有足够的接触面积。



第三章 硬件电路设计说明
硬件系统是整个智能车系统可靠运行的基础，更是软件程序得以稳定运行的基础，硬件电路的好坏也是智能汽车性能好坏的关键因素。本智能车系统硬件电路设计以稳定可靠、高效利用为原则，在 PCB 板布局走线、元器件的选取、各模块电路板面积及功能实现上不断优化，力求在有限的已有条件和未知的比赛环境下做到最好。
系统硬件电路主要由两块自制 PCB 板以及一块Edgeboard运算卡构成。自制电路板包括主控板、电源驱动板。主控板上放置使用逐飞核心板，核心板采用英飞凌的 TC264 单片机。
3.1电源板电路设计
电源板负责整车电能输入、稳压转换、电源分配及电压检测，其原理图如图3.1所示。系统电源通过XT60接口接入，经电源开关后分别形成电机供电支路和控制板供电支路。两路电源均设置输入滤波电容和共模电感，可抑制电机换向以及开关电源工作时产生的高频干扰。控制板供电支路串联2 A保险丝，当后级发生短路或过流时能够及时切断电源，提高整车供电系统的安全性。
为满足不同负载的电压需求，电源板设计了多路降压电路。其中，TPS5430降压芯片将12 V电源转换为舵机电源和5 V电源，TPS565201降压芯片将BOARD_12V转换为BOARD_5V，分别为舵机、主控板及外围模块供电。各降压支路均配置输入、输出滤波电容，肖特基二极管与储能电感共同完成开关降压和续流，并通过反馈电阻网络稳定输出电压。各路输出设置LED指示灯，便于调试时快速判断电源状态。
电源板还设置了电池电压检测电路。12 V输入电压经200 kΩ和20 kΩ电阻分压后送入主控板ADC接口，并通过0.1 μF电容滤除采样噪声，主控程序可据此实时监测电池电压。电路中将功率地PGND与数字地BGND分区布置，并通过磁珠连接，以减小电机大电流回路对主控和传感器的干扰。

3.2驱动板电路设计
驱动板用于接收主控板输出的方向和PWM控制信号，并驱动两台直流电机，其原理图如图3.2所示。驱动板采用双路独立H桥结构，每一路均以DRV8701E栅极驱动芯片为核心，配合四只TPH1R403NL型N沟道MOS管构成完整桥式驱动电路。通过控制桥臂MOS管的导通组合，可以实现电机正转、反转、制动和停止等工作状态。
主控板输出的PH信号用于控制电机转动方向，EN信号输入PWM波以调节电机端平均电压，从而实现转速控制。两组控制信号首先经过SN74HC125缓冲器处理，以提高信号驱动能力并减小干扰。输入端配置下拉电阻，使系统上电或主控信号悬空时保持确定的低电平状态，避免电机误动作。
驱动电源输入端设置肖特基二极管和多级滤波电容，用于防止反接并吸收电机启动、制动及换向过程中产生的电压波动。板载3.3 V稳压电路为驱动芯片的数字部分供电，nSLEEP信号用于统一控制驱动器使能状态。驱动板还设置电源及使能指示灯、电机接线端子和主控信号接口，方便整车布线、状态观察和故障排查。

3.3主控板电路设计
主控板是智能车底层运动控制与外设管理的核心，其原理图如图3.3所示。主控芯片负责采集编码器、姿态传感器和按键等输入信息，接收上位计算平台发送的控制指令，并输出电机PWM、方向信号和舵机控制信号。主控板引出了较多通用输入输出端口，可满足比赛过程中不同传感器及执行机构的连接需求。
在供电部分，主控板将5 V电源通过ME6211C33稳压芯片转换为3.3 V，并分别形成核心电路电源和外部模块电源。各电源输入、输出端均设置去耦电容，以降低电源纹波和数字电路高速翻转产生的噪声；同时设置LED指示灯，便于观察各电源支路是否正常。核心电源与模块电源分开布置，可降低无线模块、显示模块等外设对主控芯片供电稳定性的影响。
主控板设置了编码器接口、姿态传感器接口、无线模块串口及SPI接口、显示屏接口、有刷电机控制接口和蜂鸣器驱动电路。编码器接口用于采集左右电机转速和方向信息，为闭环速度控制提供反馈；姿态传感器用于获取车体运动状态；无线串口可用于参数调试和运行数据传输。蜂鸣器采用三极管驱动，以避免主控引脚直接承担较大负载电流。
此外，主控板集成了以CH340G为核心的USB转TTL电路，并配置12 MHz晶振及串口接口，可用于程序下载、串口调试和状态信息输出。按键输入端设置上拉电阻，保证未按下时具有稳定电平。通过上述接口设计，主控板能够完成传感信息采集、执行机构控制、上位机通信及系统调试等任务。

第四章 智能车软件设计说明
4.1软件总体架构
软件系统分为AI端和MCU端。AI端运行图像采集、预处理、语义分割、目标检测、路径估计、任务状态机和通信线程；MCU端运行编码器采样、舵机PD控制、电机PID控制、通信协议解析、状态回传和故障保护。两端使用统一时间戳和帧序号关联感知结果与车辆状态，避免旧图像产生的控制指令覆盖新状态。
AI端采用生产者—消费者方式组织图像流。采集线程只保留最新帧，推理线程完成模型计算，控制线程读取最近一次有效结果。队列满时丢弃旧帧而不是积压，保证车辆控制面对的是当前场景。MCU端使用固定周期中断运行控制器，通信与日志任务放在较低优先级，确保控制周期不受打印和数据传输影响。

4.2图像采集与预处理
摄像头获取AR叠加后的前视图像。预处理首先裁剪车辆前方有效区域，去除车身、天空或场外区域，再根据模型输入尺寸进行缩放、颜色空间转换和归一化。为适应不同承办场地的背景、光照和曝光差异，训练与测试阶段均保留多种亮度、对比度、色偏、阴影和运动模糊样本。
图像处理避免仅依据蓝色阈值判断路径。离散蓝色方向标志与蓝色背景布可能具有接近的颜色分布，因此系统以模型输出为主，并综合目标形状、空间连续性、透视关系和历史轨迹进行筛选。摄像头曝光和白平衡在实车测试中尽量固定，减少自动曝光突变造成的模型输入漂移。
4.3数据集构建与模型训练
模型训练与评估采用赛事要求的PaddlePaddle工具链。数据集覆盖直道、弯道、岔路、不同距离的蓝色方向标志以及包含虚拟障碍和奖励目标的AR画面。采集时主动加入蓝色背景、反光、阴影、人员走动、局部遮挡和车辆振动等困难样本，并将模型容易误判的背景区域作为负样本回灌训练。数据按照采集场景划分训练集、验证集和测试集，避免同一连续视频的相邻帧同时进入不同集合而高估泛化能力。
语义分割标注用于描述可行驶方向标志或路径区域，目标检测标注用于描述障碍物、奖励目标及其他任务元素。训练过程中使用随机裁剪、尺度变化、颜色扰动、模糊和遮挡增强，并依据类别数量调整采样比例。模型选择以边缘端时延、显存占用和识别稳定性为共同指标，而不是只追求离线精度。
4.4语义分割与路径点提取	
语义分割网络输出路径相关区域的概率图。系统先进行置信度筛选与形态学去噪，再提取有效连通区域的中心点。针对方向标志离散分布的特点，路径点按图像纵向位置排序，并依据透视关系对近处点赋予更高控制权重；远处点用于提前判断曲率和分叉趋势。
单帧路径点经过稳健拟合得到参考轨迹。若局部标志被遮挡或模型短时漏检，系统利用前若干帧的轨迹和车辆运动趋势进行短时补偿；当有效点数量或平均置信度低于阈值时，系统不盲目外推，而是降低目标速度并扩大重新搜索范围。由拟合轨迹在预瞄位置处计算横向偏差e(k)和航向变化趋势，作为转向控制输入。
4.5目标检测与任务元素识别
目标检测网络识别AR画面中的障碍、奖励目标和任务提示。检测结果经过置信度门限和非极大值抑制后，与路径区域建立空间关系。障碍位于预测行驶走廊内时提高风险等级；奖励目标只有在不破坏安全边界且路径可达时才进入候选目标集合。连续多帧一致的结果用于触发任务状态，降低单帧误检造成的突然转向。
对于动态路牌、虚拟人物或车辆等任务元素，软件采用统一的类别、属性和动作接口。元素识别模块只输出类型、位置、置信度和必要属性，具体选路、避让或奖励目标处理由任务状态机决定，避免将识别代码与车辆控制逻辑直接耦合。区域赛V3.0已取消红绿灯任务，软件流程中不再保留红绿灯等待或碰撞计时分支。
4.6路径规划与动态速度策略
局部规划器根据路径点、目标位置和障碍区域生成短时参考轨迹。普通巡航时优先保持轨迹平滑和较小横向误差；接近分叉时依据方向标志或任务提示选择分支；检测到障碍时重新评估可行驶区域并选择减速停车或安全绕行；奖励目标只在额外路径代价和风险可接受时纳入轨迹。所有任务触发均来自当前视觉结果和状态估计，不使用固定时刻或固定坐标硬编码。
目标速度由基础速度、道路曲率、感知置信度和任务风险共同决定。直道且置信度较高时允许平滑加速；弯道、岔路、障碍附近或置信度下降时提前减速。速度命令经过上下限和加减速斜率约束后发送给TC264，从而减少AI结果轻微波动引起的纵向冲击。
4.7舵机PD控制
转向控制以路径横向偏差为主要反馈量，并引入差分项抑制快速变化。离散形式为：
δ(k) = Kp·e(k) + Kd·[e(k) - e(k-1)]
其中，δ(k)为舵机转向修正量，e(k)为当前帧的横向偏差，Kp决定跟踪力度，Kd用于增加阻尼。控制输出叠加舵机中位后进行左右限幅和变化率限制。参数整定从低速、小Kp开始，先消除持续偏差，再逐步增加Kd抑制蛇形振荡；不同速度区间可使用分段参数，以兼顾低速灵敏性与高速稳定性。
4.8电机速度PID控制
速度环以目标速度和编码器估计速度之差作为输入。为减小积分饱和和控制跳变，采用带输出限幅的离散PID，并在停车、通信失联或驱动禁用时清除积分状态。其基本形式为：
u(k) = Kp·ev(k) + Ki·Σev(k) + Kd·[ev(k) - ev(k-1)]
其中，ev(k)为速度误差，u(k)为电机PWM控制量。整定时先关闭积分和微分得到稳定的比例响应，再加入积分消除稳态误差，最后根据需要加入少量微分抑制突变。目标速度变化采用斜坡限制，使速度环无需追踪不连续的阶跃命令。
4.9任务状态机与安全策略
任务状态机包括初始化、第一圈巡航、第二或第三圈路牌识别、岔道选择、障碍避让、金币收集、低置信度搜索和故障停车等状态。第二圈和第三圈各出现一处动态路牌，其中一处指向直道、另一处指向岔道，先后顺序随机；系统依据当前视觉结果和圈次状态完成全程恰好一次岔道选择，禁止按固定圈次写死转向。
区域赛排序遵循“圈数优先、时间次之”，因此策略优先级依次为完成有效圈、正确识别路牌与岔道、安全避让、缩短物理用时、在风险可控时收集金币。碰撞一次罚20秒，相当于约7枚金币奖励；导航错误一次罚30秒，相当于10枚金币奖励。图像超时、通信异常或路径长时间丢失时，系统宁可降速恢复，也不以高风险动作换取少量金币。
4.10模型部署与运行优化
训练完成的模型在部署前统一输入尺寸、归一化方式和类别映射，并在Orange Pi 5上进行端到端一致性验证。运行优化优先减少不必要的图像复制和重复预处理，合理设置线程亲和性与缓存，并监控单帧时延、平均帧率和长时间运行温度。若使用量化或图优化，需要重新验证困难样本，确认加速没有显著降低小目标和远距离方向标志的识别稳定性。
日志系统记录图像时间戳、模型置信度、路径偏差、任务状态、目标速度、实际速度、舵机输出和故障码。调试时可按照同一时间轴回放AI结果与底层状态，定位问题究竟来自图像、模型、决策、通信还是执行机构。正式比赛模式关闭高开销可视化，只保留必要日志和故障信息。



第五章 系统联调与测试
5.1联调原则与流程
整车联调按照“单模块—分系统—低速闭环—完整任务”的顺序进行。首先在限流条件下检查电源与静态电流，再验证主控、编码器、舵机和电机驱动；随后检查Orange Pi 5图像链路、模型输出和串口协议；最后在低速下闭合转向与速度环，并逐步增加赛道元素和运行速度。每次只调整一类参数，并保存对应日志与模型版本，避免多因素同时变化导致问题无法复现。
5.2硬件与通信测试
硬件测试关注不同工况下各电源支路的电压稳定性、驱动器温升、舵机峰值负载、编码器计数连续性以及AI板卡长时间运行状态。电机快速启停和舵机大角度动作时重点观察主控是否复位、摄像头是否掉线、串口是否出现校验错误。发现干扰时依次检查供电余量、接地回路、线束走向、接口电平和滤波器件。
通信测试使用连续序号和校验字段统计丢帧、错帧和最大间隔，并主动断开AI端或暂停发送，确认TC264能够按预期降速停车。恢复通信后车辆保持安全等待，由明确的重新启动条件进入运行状态，避免连接瞬间直接恢复旧控制指令。
5.3感知模型测试
感知测试分别评估语义分割、目标检测和路径拟合。离线阶段记录分割交并比、目标检测精确率与召回率、困难样本误检类型以及端侧单帧时延；实车阶段重点观察不同背景布、光照、摄像头高度、车速和运动模糊下的连续稳定性。测试集必须包含蓝色背景和离散方向标志等易混淆场景。
对于单帧看似正确但时序抖动明显的问题，优先检查图像时间戳、帧队列和连续帧一致性，而不是单纯提高置信度门限。模型更新后采用固定回放集进行回归测试，确认新增困难样本没有造成其他类别性能明显退化。
5.4转向与速度控制调试
转向参数从低速直线开始标定舵机中位，随后在缓弯中增大比例系数，直至车辆能够及时跟随路径；若出现蛇形振荡，则增加差分阻尼、减小近场噪声或限制舵机变化率。高速参数在低速稳定后逐步放开，并同时检查机械间隙、前束和轮胎抓地，避免用控制参数补偿明显的机械问题。
速度环先在架空或安全直道上标定编码器方向和比例关系，再依次整定比例、积分和微分参数。测试加速、减速、弯道降速和紧急停车过程，观察超调、恢复时间和低速爬行。动态速度策略只在基础速度闭环稳定后启用。
5.5典型问题与改进措施
复杂背景下将蓝色背景误判为路径时，应增加背景负样本、颜色扰动和形状约束，并结合连续方向标志的几何关系筛选；离散标志之间出现路径断裂时，可通过多帧累积和稳健拟合补足短时缺口，但置信度过低时必须降速。
推理结果延迟或抖动时，应检查采集队列是否积压，并保证控制线程只读取最新有效结果；舵机在直线附近高频摆动时，可增加误差死区、差分滤波和输出变化率限制；电机动作引起图像或串口异常时，应加强动力与逻辑供电隔离、优化接地与线束，并在协议层使用校验和心跳保护。


第六章 总结与展望
本文围绕第二十一届全国大学生智能汽车竞赛人工智能模型组，完成了以C型阿克曼车模、TC264和Orange Pi 5为核心的虚实融合智能车方案设计。系统将AI视觉推理与实时运动控制分层实现，通过语义分割和目标检测理解离散方向标志及虚拟任务元素，利用路径拟合、任务状态机、舵机PD控制和编码器速度PID控制构成完整闭环，并在通信、电源和软件状态管理中加入失联降速与故障停车机制。
该方案的工程重点不是单一模型的离线精度，而是图像、模型、决策、通信和执行机构在真实车辆上的协同。通过困难样本回灌、连续帧一致性、动态速度策略和分阶段联调，可以针对蓝色背景干扰、方向标志离散、边缘推理延迟和车辆振动等问题持续优化。

class BirdEyeMapper:
    def prepare(self, frame_shape):
        height, width = frame_shape[:2]
        a = self.args

        source = np.float32([
            [a.src_bottom_left_x * width,  a.src_bottom_y * height],
            [a.src_bottom_right_x * width, a.src_bottom_y * height],
            [a.src_top_right_x * width,    a.src_top_y * height],
            [a.src_top_left_x * width,     a.src_top_y * height],
        ])
        destination = np.float32([
            [a.dst_left_x * self.width,  self.height - 1],
            [a.dst_right_x * self.width, self.height - 1],
            [a.dst_right_x * self.width, 0],
            [a.dst_left_x * self.width,  0],
        ])

        self.homography = cv2.getPerspectiveTransform(source, destination)

    def warp_mask(self, mask, frame_shape):
        self.prepare(frame_shape)
        return cv2.warpPerspective(
            mask, self.homography, (self.width, self.height),
            flags=cv2.INTER_NEAREST,
        )

    def project(self, point, frame_shape):
        self.prepare(frame_shape)
        result = cv2.perspectiveTransform(
            np.float32([[[point[0], point[1]]]]), self.homography
        )[0, 0]
        return float(result[0]), float(result[1])

def extract_paths(road_mask, args):
    height, width = road_mask.shape
    max_length = width * args.scan_max_length
    max_jump = width * args.scan_max_jump

    rows = []
    for y in range(
        int(height * args.scan_bottom_ratio),
        int(height * args.scan_top_ratio) - 1,
        -max(1, args.scan_step),
    ):
        segments = row_segments(road_mask[y], args.scan_min_segment_width)
        rows.append((y, row_candidates(segments, max_length)))

    branch_flags = clean_branch_flags(
        [len(c) >= 2 and c[-1] - c[0] >= args.branch_separation
         for _, c in rows],
        args.branch_min_rows,
        args.branch_max_gap_rows,
    )

    left_path, right_path = [], []
    previous_left = previous_right = None
    for (y, candidates), is_branch in zip(rows, branch_flags):
        if not candidates:
            previous_left = previous_right = None
            continue

        if is_branch and len(candidates) >= 2:
            left_x, right_x = candidates[0], candidates[-1]
            if previous_left is None or abs(left_x - previous_left) <= max_jump:
                left_path.append((int(round(left_x)), y))
                previous_left = left_x
            if previous_right is None or abs(right_x - previous_right) <= max_jump:
                right_path.append((int(round(right_x)), y))
                previous_right = right_x
        else:
            reference = previous_left if previous_left is not None else width * 0.5
            x = min(candidates, key=lambda value: abs(value - reference))
            if previous_left is None or abs(x - previous_left) <= max_jump:
                left_path.append((int(round(x)), y))
                previous_left = x
            previous_right = None

    return (
        snap_path(left_path, road_mask, args.path_smooth_window),
        snap_path(right_path, road_mask, args.path_smooth_window),
    )

def three_point_path_error(path, map_shape, args):
    height, width = map_shape[:2]
    center_x = width * 0.5
    half_width = max(1.0, width * 0.5)

    ratios = (
        args.error_y1_ratio,
        args.error_y2_ratio,
        args.error_y3_ratio,
    )
    weights = np.asarray([0.2, 0.5, 0.3], dtype=np.float32)

    sample_points, point_errors = [], []
    for ratio in ratios:
        target_y = int(round(height * ratio))
        point = sample_path_point(path, target_y)
        sample_points.append(point)
        point_errors.append(clamp(
            (float(point[0]) - center_x) / half_width, -1.0, 1.0
        ))

    d1, d2, d3 = point_errors
    error = clamp(weights[0] * d1 + weights[1] * d2 + weights[2] * d3,
                  -1.0, 1.0)
return float(error), sample_points[1], sample_points, point_errors
