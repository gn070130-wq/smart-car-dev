第一章 引言
1.1 赛事背景
随着信息科学技术的迅速发展，电子技术，人工智能技术在汽车行业运用越来越广泛，如此一来，智能化的汽车领域就显得尤为重要了。智能化已经被作为衡量电子产业的重要标准。智能化的汽车也会在未来的市场占据主导地位。受教育部高等教育司委托，高等学校自动化专业教学指导分委员会主办全国大学生智能汽车竞赛，以迅猛发展的汽车电子为背景，涵盖了控制、模式识别、传感技术、电子、电气、计算机、机械等多个学科交叉的科技创意性比赛。参赛选手须使用竞赛秘书处统一指定并负责采购竞赛车模，自行采用指定的微控制器作为核心控制单元，自主构思控制方案及系统设计，包括传感器信号采集处理、控制算法及执行、动力电机驱动、转向舵机控制等，完成智能汽车工程制作及调试，于指定日期与地点参加场地比赛。参赛队伍之名次由赛车现场成功完成赛道比赛时间为主，技术方案及制作工程质量评分为辅来决定。
本篇技术报告所阐述内容主要包括了人工智能模型组的硬件系统、机械系统、软件系统等。具体表现在电路的创新设计，算法的独特控制，在竞赛准备的过程中，培养了我们对电路设计，程序设计编程，系统的调试等方方面面的能力，让我们的知识融会贯通，并且运用到了实际中，提升了我们的创新能力，对我们今后的学习及工作有莫大的积极影响。
第二章 硬件设计
2.1电源管理
电源输出的首要指标是可靠性，整个硬件系统的工作完全由电源供电的可靠性决定，电源供电不稳定会引起损耗、单片机复位、传感器损毁等严重问题，香橙派承载着AR渲染、模型推理、运动决策等重要的功能，因此香橙派的供电格外重要，既要保证输出电压稳定，又要保证输出电流足够大，因此需要选择合适的元器件集成。

2.4.2定位模块
人工智能模型组正式规则下来后，查阅网上资料，全局定位主流方案有两种:(1)雷达SLAM建图，小车上需放置雷达;(2)全局摄像头+TAG码方案。
考虑到团队已有资产，雷达太贵且场地需要围挡、全局摄像头调试场地层高限制，加之需要一个额外的板卡处理数据，还有明显的延时，我们另辟蹊径，选择自制基于STM32F103C8T6+PAW3395鼠标模块+JY62定位模块。
鼠标模块传输原始XY坐标，IMU计算偏航角，两者数据结合解算出全局坐标，串口有线传输至上位机，可做到无延时、高响应。
整个定位模块成本在200以内，相比于主流方案动辄几千的条件下，此模块极具便携性与高性价比。但同时此模块具有一定的累计误差(需要调整好鼠标模块离地高度)，且对地面平整性要求比较高，团队调试的时候选择在教学楼内的瓷砖地，误差控制在3cm/m，整个备赛期间定位模块性能优异。效果如下所示：

第三章 车模结构设计
3.1I车模参数介绍
使用官方I车模作为车型，车模具有出色的对称性，便于安装舵机，且具备快速灵敏、高精度、快速响应、强劲动力、卓越抓地力、充足刚性和恰到好处的重心等多重优势。整车尺寸为316*190*110mm（不含摄像头碳纤杆），轮胎尺寸为26*62mm，经过适当打磨处理，车模的轮胎具备良好的减震性，从而提供更强的摩擦力。车模采用后轮单驱方式提供动力，而前轮的舵机则用于转向控制。驱动电机选用RS-555，额定电压为12V，额定转速为12000rpm，重量为60g。舵机方面，选用了 CS-3120 型号，供电电压为5.0V 时，额定扭矩可达15kg·cm；而在6.8V 供电时，额定扭矩则可增至17kg·cm。此外，舵机的动作速度为每60°动作0.14 ± 0.02秒。

3.2.2转向舵机安装
为了在保证主板安装便利的同时提升车模的转向性能，我们进行了对舵机安装结构的调整。为了加速转向机构的响应速度，必须在优化舵机的安装位置以及力矩延长杆的长度上下功夫。然而，功率与速度和力矩的乘积有关，过于追求速度可能会导致力矩的损失，而力矩过小则可能造成转向不灵敏。因此，在设计过程中，必须综合考虑转向机构的响应速度与舵机力矩之间的平衡，以获得最佳的转向效果。
在经过反复的尝试以后，我们选择了维持I车模推荐的舵机安装方式不变，即立式安装的方式，以获得最优的转向性能。

第四章 软件方案

4.1简介
本系统采用上位机（RK3588S）与下位机（TC264）协同的分层框架，通过串口实现控制指令与状态反馈的双向传输。上位机作为系统的感知与决策核心，基于PaddlePaddle 深度学习框架完成视频流采集、图像预处理及推理任务分发，分别通过目标检测与语义分割并行处理决策任务与巡线任务，经功能池中的路牌识别、行人避让、轨迹规划等模块综合仲裁后，生成舵机转角与电机速度控制量并打包下发；下位机则负责控制指令的实时接收与解算，直接驱动舵机和电机执行动作，同时通过自制定位模块采集位姿信息，经全局坐标解算与滤波后回传至上位机，形成"感知—决策—控制—反馈"的完整闭环。
4.2上位机部分
上位机采用的是双模型异步推理，主进程控制决策的架构，以 RK3588S 为计算核心，基于 Paddle 框架训练语义分割与目标检测模型，训练语义分割、目标检测两个模型用于赛道巡线、任务处理，并部署在rknntoolkit2环境上成功进行实时推理，经 ONNX 转换为 INT8 量化 RKNN 模型，通过 NPU 硬件加速实现实时推理。语义分割负责提取可行驶区域与赛道中线，目标检测负责识别路牌、行人、车辆等目标，二者形成功能互补的感知层。
4.2.1数据集采集
数据集采集阶段，我们通过运行自动化数据收集脚本，配合人工遥控小车在赛道上行驶，同步完成图像数据的采集工作。采集过程中，操作者可通过访问本地网页实时观看 AR 渲染后的图像画面，采集的图像数据将同时服务于语义分割与目标检测两个模型的训练，其中语义分割数据需包含赛道边界及可行驶区域的像素级标注，目标检测数据则需覆盖路牌、行人、故障车等目标的边界框标注，为后续模型训练提供充足且多样的样本基础。
4.2.2模型训练、转化、量化
模型训练、转化与量化阶段，首先基于 Paddle 深度学习框架，在百度智能云 AI Studio 平台上完成语义分割与目标检测模型的训练。具体而言，我们拉取 PaddleYOLO 开源仓库并配置训练环境，由于 RK3588S 的 NPU 对 RKNN 模型具有原生硬件加速支持，因此在训练前即需针对部署端进行前置适配，包括配置模型激活函数与检测头形式、设定 ONNX 导出时的输入格式，以确保后续转换的模型算子均落在 RK3588S 支持的 OP 范围内，从而最大化推理加速性能。
准备好训练的数据集，将其分割为训练集和验证集并做好数据集的格式转换。参照Paddle给出的模型性能测评，选择合适的模型。建议在训练模型时最好加上预训练权重，否则模型难以收敛。我们选择的语义分割模型为ppyoloe_seg，目标检测模型为yoloe，这两者模型的配置文件、数据集格式、输出格式会有所不同
训练时建议加载预训练权重以加速收敛，随后运行 tools/train.py 启动训练，待 loss 收敛至 1% 以下即可提前结束，亦可等待完整训练周期。训练完成后，通过 tools/infer.py 进行推理验证，确认效果符合预期后导出为 ONNX 格式。模型量化与转换环节使用 RKNN Toolkit2 完成，建议在本地 WSL 环境中单独配置转换环境以避免依赖冲突；鉴于 RK3588S NPU 对 INT8 量化模型的支持最佳，转换过程中加入 INT8 量化配置，并在量化校准阶段引入原始图像数据，以保证量化后模型的推理精度满足赛道任务要求。
4.2.3模型部署
模型部署阶段，要根据模型的输入输出形式要有针对性的来写前处理和后处理代码，必须与rknn模型的输入输出匹配对齐。一般前处理有色域的转化，图像均值、方差的变换；后处理一般会有nms，dfl等对anchor的处理算法，这里可以借鉴rknn_model_zoo的后处理算法。若在验证rknn模型时报错或者warning可以检查一下输入头和检测头，是否有误。
4.2.4程序架构
在运行主程序之前，要先做好AR图像渲染和AR模型定位数据的获取，这里AR图像渲染官方已经为我们封装为./setupui可执行程序，我们需要写好定位模块与AR模型定位的数据传输接口就行该程序为start.py
下面来介绍主程序
infer_main.py为主文件，ctrl.py为功能文件，infer_wrap.py为推理文件，rknnpool.py为进程池文件，func.py为前处理后处理文件
infer_wrap.py、rknnpool.py、func.py为实现rknnlitetoolite2环境下的模型推理文件，最后将语义分割、目标检测统一封装为Infer类，采用多进程、共享内存、零拷贝形式，进行双模型的异步推理，infer_main.py、ctrl.py为逻辑策略的主文件，是整个系统的大脑，ctrl.py服务于infer_main.py里面封装了预瞄距离，前馈补偿，中线选取等功能函数。下面是最重要的infer_main.py文件，读取AR视频流，获取推理结果进行控制状态逻辑决策：
主控进程每次迭代首先尝试从结果队列中拉取最新的检测框和分割掩码。若队列为空，即推理尚未完成，则使用上一帧的缓存数据进行决策，以确保控制指令连续输出，避免小车因等待推理结果而出现卡顿。在场景理解与路径规划方面，系统根据检测到的路牌类型执行路牌决策逻辑，判断当前任务模式。针对运动行人和行进路线上的其他运动车，通过比较双帧预测框与目标框的差异，用状态机分别执行独立的避让策略以确保安全距离。路径规划采用动态窗口法结合贝塞尔曲线拟合出可行驶路径的中心线。对于路牌理解，系统异步三次并发调用文心大模型 API 进行语义理解，该调用过程需要阻塞主控循环，等待模型做出决策。
针对小车的阿克曼运动学结构，系统采用纯跟踪算法进行控制量解算。在预瞄点选取环节，进行前馈补偿预测，以应对推理延迟。从而在前方拟合路径上选取最合适的预瞄点，并动态调整前视距离。获取预瞄点后，使用纯跟踪算法计算出所需的舵机转角。同时，根据不同任务场景，如直道巡航、弯道跟车或紧急避障，分配不同的电机转速。将转角指令、速度指令以及各项避障策略进行综合仲裁，例如避障优先级高于循迹，生成最终的控制指令。最终决策得出的舵机转角与电机速度数据，通过串口协议打包，下发至下位机执行，驱动阿克曼底盘完成相应的运动。
4.2.5任务模块
任务模块主要应对行人横穿、故障车阻挡及路牌语义理解三类核心任务场景。针对行人场景，系统采用双帧连续检测获取行人在图像坐标系中的位置信息，结合小车当前运动状态建立碰撞预测数学模型，通过分析行人运动趋势与小车行驶轨迹的时空交集，判断是否存在碰撞风险，并设置 stop_flag 标志位控制小车的紧急制动与恢复启动，确保在行人穿越赛道时能够及时停车避让。针对故障车场景，系统采用语义分割与目标检测融合感知的方案，一方面利用分割掩码提取可行驶区域并拟合出赛道中线轨迹，另一方面通过目标检测获取故障车底部中心坐标，将两者在图像坐标系下进行位置比较与逻辑判断，当判定故障车完全或部分阻挡行驶路径时，触发绕行或停车策略。针对路牌场景，由于路牌文字内容复杂且语义多样，传统规则方法难以准确解析，因此系统采用异步三次并发调用文心大模型 API 的方式进行语义推理，三次调用并行执行以降低单次推理延迟对主控循环的影响，随后对三次返回的决策结果采用权重累加机制进行融合仲裁，综合判断路牌指示含义并输出最终的小车运动决策，从而在保证实时性的同时提升复杂语义场景下的决策准确率与鲁棒性。
4.3下位机部分
下位机主控选用英飞凌 AURIX TC264 微控制器，该芯片基于 TriCore 双核架构，主频 200 MHz，算力足以同时承担串口通信、电机舵机 PWM 控制及定位解算等任务；其丰富的片上外设也便于直接接入编码器、IMU 等传感器，简化了硬件设计。同时，逐飞科技围绕该芯片提供了成熟的底层库与智能车开发套件。
4.3.1舵机控制
舵机控制由下位机 TC264 负责执行，系统通过串口接收来自上位机综合决策后的目标转角指令，经数据解算后转换为 PWM 占空比信号驱动舵机。TC264 输出高精度 PWM，通过调节占空比实现舵机角度的精确控制；控制指令在定时中断中以固定周期更新，确保舵机响应的实时性与一致性，从而快速跟踪上位机规划出的行驶方向。

4.3.2电机PID速度环
电机速度控制采用位置式 PID 闭环算法，由下位机 TC264 在定时中断中周期执行。系统通过编码器实时采集电机实际转速，与上位机经串口下发的目标速度作差得到当前偏差，经比例、积分、微分运算后直接输出 PWM 占空比值驱动电机；其中比例环节用于提升响应速度，积分环节累积历史偏差以消除稳态误差，微分环节则根据偏差变化趋势抑制超调与振荡。为防止积分饱和并保证执行机构安全，程序对积分项进行限幅处理，同时对最终 PWM 输出设置上下边界；若发生异常或通信中断，控制器可立即将输出清零，避免位置式 PID 因历史积分累积产生失控风险。速度环以固定频率运行，确保控制的实时性与稳定性，使智能车在不同负载和路面条件下均能保持车速恒定，精准跟踪上位机规划的速度指令。

4.3.3无线串口+VOFA调参
电机 PID 参数整定采用无线串口模块配合 VOFA+ 上位机软件完成。下位机 TC264 在定时中断中将目标速度、实际速度及 PWM 输出值通过无线串口实时发送至 PC 端，VOFA+ 以波形方式动态绘制速度响应曲线，使调节过程直观可视；调试时先通过无线串口在线修改比例系数观察响应速度，再逐步加入积分项消除稳态误差，最后引入微分项抑制振荡，各参数调整后的系统响应均可即时在波形界面中对比验证。相比传统有线串口，无线传输方式避免了频繁插拔数据线的麻烦，便于在赛道旁实时观测车辆运行数据；VOFA+ 的多通道波形显示与数据记录功能则大幅提升了 PID 整定效率，使电机速度环能够在短时间内收敛至理想的控制效果。

第五章 总结
5.1工作总结
本技术报告系统阐述了"模完不是丸魔"队伍参加全国大学生智能汽车竞赛人工智能模型组的完整技术方案。从硬件电路设计、车模机械结构优化到上下位机协同软件架构，团队完成了一个具备感知、决策、控制闭环能力的智能车系统研制。
在硬件层面，团队自主设计了以SCT2450为核心的BUCK降压电路与RT9013-33GB LDO稳压电路，为香橙派5及各类外设提供了稳定可靠的电源保障；电机驱动部分采用DRV8701ERGER栅极驱动器配合TPH1R403NL MOSFET构建H桥，实现了对有刷电机的高效驱动；尤为突出的是，团队针对全局定位需求，创新性地提出了基于STM32F103C8T6+PAW3395鼠标模块+JY62 IMU的低成本定位方案，在保证无延时、高响应的同时，将成本控制在200元以内，为竞赛定位方案提供了一条高性价比的技术路线。
在机械结构方面，团队在I车模基础上进行了精细化布局，通过3D打印技术快速迭代了电池架、摄像头固定架、定位模块外壳等异形结构件，并采用硅胶倒模自制轮胎以提升抓地性能，在保证结构强度与装配便利性的同时实现了整车重心的合理分布。
在软件层面，系统采用上位机（RK3588S）与下位机（TC264）协同的分层架构。上位机基于PaddlePaddle框架，通过语义分割与目标检测双模型异步推理，结合AR渲染与纯跟踪算法，实现了赛道巡线、路牌识别、行人避让及故障车绕行等复杂任务；针对路牌语义理解难题，团队创新性地引入文心大模型API进行异步并发语义推理，显著提升了复杂场景下的决策鲁棒性。下位机则负责舵机PWM控制与电机PID速度闭环，通过无线串口配合VOFA+完成参数整定，确保了控制指令的实时响应与执行精度。
整个系统经过数月的调试与优化，在教学楼瓷砖地环境下实现了约3cm/m的定位精度，能够稳定完成赛事要求的各项任务，达到了预期的设计目标。

5.2不足之处
尽管本系统在功能实现与性能指标上取得了一定成果，但在深入测试与比赛实践中仍暴露出以下不足：
自制定位模块虽然具备成本低、响应快的优势，但PAW3395鼠标传感器本质上属于相对位移测量器件，长时间运行后存在一定的累积误差，且对地面平整度与纹理特征要求较高。在赛道接缝、反光或灰尘较多的区域，鼠标数据可能出现跳变，导致全局坐标解算偏差增大，目前仍需依赖定期复位或特定地标校正来抑制误差发散。
路牌语义理解采用异步三次并发调用文心大模型API的策略，虽然通过并发与权重融合机制在一定程度上缓解了延迟问题，但API调用过程仍需阻塞主控循环等待返回结果。在网络波动或大模型服务端响应变慢时，可能造成控制指令输出的短暂停顿，对高速行驶场景下的实时性构成潜在风险。
在RK3588S NPU上部署的双模型异步推理架构，在常规场景下能够满足实时性需求，但当场景中同时出现大量目标（如多行人、多路牌、故障车叠加）且光照条件复杂时，语义分割与目标检测的推理延迟会有所增加，极端情况下可能影响控制频率的稳定性。
