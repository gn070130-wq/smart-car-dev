摘  要
本文介绍哈尔滨工程大学济海追风5队为第二十一届全国大学生智能汽车竞赛人工智能模型组设计的智能模型车。车辆以改制C1车模为基础，采用RK3588车载计算平台与TC264下位机协同工作的分层结构。赛事定位与三维场景系统根据车辆位姿生成虚实融合视觉环境，车载计算平台采用实例分割、Paddle目标检测和PaddleOCR获取道路、任务目标及路牌文字信息，并通过API调用文心大模型完成路牌语义理解与导航决策。TC264结合编码器与惯性传感器信息完成转向和速度闭环控制。本文对竞赛任务、总体方案、机械结构、硬件电路、视觉处理、多级信息连接、PID控制及系统调试方法进行说明。

第一章 引言
1.1 竞赛背景与任务概述
全国大学生智能汽车竞赛以自主智能车辆为载体，综合考查参赛队在机械结构、电子系统、智能感知、运动控制和整车调试等方面的工程实践能力。人工智能模型组在实体模型车与三维虚拟场景相结合的环境中开展比赛，模型车需依靠车载系统自主感知赛道及任务元素并完成行驶。
根据第二十一届全国大学生智能汽车竞赛人工智能模型组任务要求，模型车需要连续完成三圈有效行驶，并在运行过程中完成人与车辆避让、金币收集以及动态路牌导航。本队以稳定完成有效圈为基础，在此基础上兼顾任务执行的可靠性与比赛用时，主要任务及对应系统响应如表1.1所示。

第二章 系统总体方案
2.1 设计目标
系统设计以稳定完成有效圈和各项任务为主要目标，在满足车身尺寸与摄像头安装要求的基础上，实现三维场景视觉感知、路牌语义理解、路线生成、多级信息连接和车辆闭环控制。计算量较大的视觉推理与语义处理运行于RK3588平台，执行器控制和传感器采集由TC264完成。
2.2 系统组成
系统由赛事环境、车载智能感知、运动控制和执行反馈四部分组成。官方定位与三维场景系统提供车辆位姿和虚实融合视觉环境；OV13855与RK3588完成道路分割、目标检测、文字识别和任务决策；TC264、编码器和IMU完成底层状态采集与闭环控制；舵机和左右驱动电机完成车辆运动。

图2.1 模型车系统信息闭环
2.3 系统层级与功能划分
系统分为赛事环境层、车载感知决策层和运动控制层，各层依次传递场景、路线及控制信息，分别承担环境生成、视觉决策和车辆控制功能。
赛事环境层由官方定位、三维场景生成和裁判系统组成。定位与场景系统生成车辆当前视角图像，为车载程序提供道路和任务环境；裁判系统独立记录比赛事件。
RK3588位于感知决策层，完成道路实例分割、Paddle目标检测、PaddleOCR文字识别和文心大模型API语义处理，形成路线及任务信息。TC264位于运动控制层，结合编码器和IMU反馈完成转向与速度闭环，并驱动舵机和电机执行车辆运动。
2.4 信息闭环
车辆运动后，官方定位系统更新车辆位姿，三维场景系统据此生成当前视角下的道路及任务元素。RK3588从场景图像中提取道路、目标和路牌信息，形成路线及任务结果，经多级接口传递至运动控制层；TC264结合编码器和IMU反馈控制舵机与电机，使车辆沿目标路线运动并再次触发位姿与场景更新，从而形成完整环境闭环。裁判系统独立记录隐藏穿越面、碰撞、金币和导航事件，不作为车辆实时控制反馈。


第三章 机械结构与传感器安装
3.1 车模总体结构
本组别采用自制车模形式。团队对比了常见的C1与I车模结构后，选择以博思威龙C1车模为基础进行改进。车模重新设计碳纤维底板，使控制板、计算平台、电池和执行机构能够按照实际车辆的结构关系进行布置。改制过程中重点考虑结构强度、重心位置、散热、线束固定和维护便利性。
为安装官方定位模块，前桥舵机固定支架重新设计并预留安装孔位；用于固定电路板和RK3588开发板的专用支架同样根据车内空间设计。两类支架均采用PPA-CF材料3D打印制作，在保证刚度的同时便于快速拆装。
图3.1 模型车总体结构
3.2 转向、驱动与轮胎
车模采用前桥舵机转向，BLS3325舵机通过转向连杆驱动前轮。安装时保证舵机中位与前轮机械中位一致，并通过前轮前束和连杆长度调整减小左右转向差异。车辆后轴采用双轴设计，两台RS380电机分别驱动左右轮，便于结合左右轮速度反馈实现速度闭环和转向差速补偿。
轮胎采用光头胎，以获得较大的接地面积和抓地能力。车体装配后需要检查左右轮转动阻力、后轴同轴度、轮胎接触状态以及底盘离地间隙，避免机械差异被误认为控制参数问题。
3.3 摄像头与定位模块安装
OV13855摄像头水平平视前方，摄像头上边沿距地面138 mm。相对于车身中心，摄像头X轴偏移为0，Z轴偏移为12 cm，安装角度符合赛事要求。系统坐标轴中，X轴对应车身宽度方向，Y轴对应车身高度方向，Z轴对应车身长度方向。摄像头居中安装有利于减小虚拟场景叠加误差。
定位模块通过舵机前桥支架上的预留孔位固定。模型车长、宽、高参数已经包含定位模块固定器，模块安装后仍能保证支架无松动，并避免其干扰转向机构。

第四章 硬件系统设计
4.1 硬件总体架构
硬件系统由智能计算平台、下位机控制板、执行机构、传感器、电源和人机交互模块组成。RK3588开发板作为智能计算平台；TC264主控制板连接编码器、IMU、显示屏、电机驱动和舵机，完成车辆状态采集与控制输出。
4.2 主控制器与智能计算平台
主控制板MCU采用逐飞科技TC264核心板，配置两路正交编码器输入接口、IPS200显示屏接口、IMU660RA六轴传感器接口、电机驱动信号输出接口和舵机控制接口。RK3588开发板承担道路分割、Paddle目标检测、PaddleOCR、路牌语义处理和路线生成，并通过多级接口将感知与决策结果传递至TC264控制层。
4.3 驱动、转向与传感器
车模使用2台博思威龙原配RS380电机，采用DRV8701双驱模块驱动，电机PWM频率为17 kHz。BLS3325舵机作为前桥转向舵机，供电电压为6.6 V。左右轮分别安装正交编码器，用于获得轮速反馈；IMU660RA采集加速度和角速度信息，为姿态估计和位置计算提供输入。IPS200显示屏与4个按键用于状态显示和参数设定。

4.4 电源系统
车模使用格氏3S、5300mAh电池作为能源。电池分别向主控制板、电机驱动板和RK3588供电板提供输入。主控制板上的两块SCT2450STER分别产生6.6 V舵机电源和5 V系统电源，5 V再经RT9013稳压得到3.3 V，为传感器及其他外设供电。RK3588供电板采用TPS56637输出5 V，为开发板和摄像头提供稳定电源。

第五章 软件系统与控制算法
5.1 软件总体结构
软件系统由三维场景图像输入、道路实例分割、Paddle目标检测、PaddleOCR、文心大模型API调用、路线与任务决策、多级信息连接以及TC264闭环控制组成。RK3588负责视觉和语义处理，TC264负责传感器读取、转向控制和左右轮速度闭环。

图5.1 软件系统基本流程
5.2 视觉感知方法
5.2.1 图像输入与预处理
三维场景系统根据官方定位信息生成车辆当前视角下的虚实融合图像。视觉程序读取图像后完成尺寸调整、颜色格式转换和归一化等预处理，并将数据分别送入道路分割、目标检测和文字识别模块。
5.2.2 道路实例分割
道路感知采用轻量级实例分割模型，将道路区域从场景图像中分离。训练数据使用Labelme进行多边形标注，模型经训练和转换后部署于RK3588。分割结果经过必要的几何处理形成供路线计算使用的道路区域。
5.2.3 Paddle目标检测
任务目标识别采用Paddle目标检测模型，对路牌、金币、车辆和行人等目标进行检测。程序根据目标类别、位置及道路关系生成后续任务所需的信息。模型训练、导出和板端部署均基于PaddlePaddle相关工具完成。
5.2.4 道路信息提取
视觉程序根据道路分割结果提取道路边界和中心路线，并结合当前场景对直道、弯道及岔路进行处理。对于局部缺失或短时波动，系统利用连续信息保持路线输出稳定。具体判定阈值和路线修正参数由实车试验确定。
5.3 路牌语义理解与任务决策
检测到路牌后，系统截取相应图像区域并使用PaddleOCR获得文字识别结果。程序将识别文字与必要的场景信息组织为请求，通过API调用文心大模型完成语义理解，并将返回结果转换为直道或岔道选择。为避免单帧误识别直接影响车辆，路牌结果需经过基本有效性检查后进入导航状态。
行人、车辆和金币由Paddle目标检测模块提供类别与位置信息，决策模块根据目标与当前路线的关系进行避让或收集处理。任务结果与基础路线统一形成车辆需要跟随的目标路线；任务结束后系统恢复普通道路跟随。

6.2 制作与安装
机械部分按照建模、加工、试装和修正的顺序完成。碳纤维底板用于承载主要装置，PPA-CF支架用于固定定位模块、电路板和RK3588开发板。电气部分分别完成主控制板、电机驱动板和计算平台供电板的连接，并对动力线、信号线和连接器进行固定。
6.3 调试方法
系统调试按照由单模块到整车、由低风险到完整任务的顺序进行。首先检查电源电压、执行器方向、编码器符号和舵机中值；随后验证实例分割推理、道路中心输出和任务目标识别；上下位机联调时使用固定图像或记录数据检查控制信息是否一致；最后进行架空、低速单功能和连续三圈测试。
6.4 典型问题与处理
调试过程中重点关注道路中心跳变、任务目标偶然误识别、重复命令、左右轮输出不一致以及机械安装松动等问题。视觉侧通过连续帧判断和有效区域约束提高输出稳定性；控制侧通过状态释放、历史量重置和输出限幅减小任务切换冲击；机械侧通过紧固和线束整理减少振动造成的异常。

void dir_servo()
{
    pid_servo.err2 = SERVO_CENTER_VALUE - pid_servo.speed_current;
    pid_servo.duty = pid_servo.kp * pid_servo.err2
                   + pid_servo.kd * (pid_servo.err2 - pid_servo.err1);
    pid_servo.err1 = pid_servo.err2;
    if(pid_servo.duty >= SERVO_DUTY_LIMIT){
        pid_servo.duty = SERVO_DUTY_LIMIT;
    }
    if(pid_servo.duty <= -SERVO_DUTY_LIMIT){
        pid_servo.duty = -SERVO_DUTY_LIMIT;
    }
}
