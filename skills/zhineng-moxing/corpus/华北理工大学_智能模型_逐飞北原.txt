  摘  要
本报告介绍了一支参加第二十一届全国大学生智能汽车竞赛人工智能模型组的参赛队伍所研制的智能车系统。针对竞赛“虚实融合驾驶环境、纯视觉感知”的赛题要求，本车采用“上位机视觉感知 + 下位机运动控制”的分布式架构：上位机基于瑞芯微 RK3588S（SRK3588S 开发板）完成高清图像采集、IPM 逆透视与 HSV 赛道循迹、YOLO 目标检测、OCR 识别与语义决策，并通过 6 TOPS 的 NPU 与 RKNN 推理框架实现实时推理；下位机基于英飞凌 AURIX TC264 双核微控制器，完成电机速度闭环、舵机方向控制与姿态解算。动力部分采用两片 BTN7971B 组成全桥驱动直流电机，转向采用 BDS300 数字舵机，姿态测量采用逐飞科技 IMU660RA 六轴惯性单元，电源由 TPS5450 降压芯片分级供电。经长期调试，本车能够稳定完成安全避让、语义导航、红绿灯与限速响应、金币收集等竞赛任务，运行平稳、响应迅速。
关键词：人工智能模型组；虚实融合；YOLO 目标检测；RK3588S；TC264；RKNN


第一章 概述
1.1 竞赛背景
全国大学生智能汽车竞赛是由教育部高等学校自动化类专业教学指导委员会主办的一项面向全国高校大学生的科技竞赛活动，以“立足培养、重在参与、鼓励探索、追求卓越”为指导思想，旨在培养大学生的综合知识运用能力、工程实践能力与创新精神。竞赛迄今已举办二十一届，覆盖自动控制、模式识别、传感技术、电子、电气、计算机、机械等多个学科，是电子信息类专业中影响广泛的学科竞赛之一。
人工智能模型组是竞赛中面向人工智能技术应用的前沿组别。该组别不再以传统的“循迹竞速”为核心，而是强调智能车在真实物理赛道与虚拟增强现实（AR）叠加的“虚实融合驾驶环境”中，依靠纯视觉感知完成目标检测、语义理解、决策规划等一系列高难度任务，对参赛队伍在深度学习、嵌入式系统、自动控制等方面的综合能力提出了更高要求。
1.2 赛题概述
人工智能模型组采用“虚实融合驾驶环境”方案：赛车在真实赛道上行驶，同时由竞赛方提供的增强现实（AR）系统在赛道中叠加虚拟的行人、路牌、红绿灯、限速标志、金币等目标。赛车需在纯视觉（不使用其他外部环境传感器）的条件下完成三圈任务，核心任务包括：
安全避让（“鬼探头”）：第一圈虚拟行人会随机出现并突然横穿道路，赛车需实时感知其位置与速度，平稳避让或紧急制动，碰撞一次罚时 20 s。
语义导航：第二圈路口出现包含文字、图标、箭头的路牌（内容随机），赛车需通过 OCR 识别文字并借助大模型进行语义理解，选择正确分支，选错一次罚时 30 s。
速度规划：第三圈出现时长不定的虚拟红绿灯与限速标志，赛车需遵守限速，并决策是加速通过绿灯还是平稳停车。
金币收集：三圈中散落虚拟金币，每收集一枚在总时间上扣减 5 s。
竞赛官方指定目标检测、OCR、强化学习采用飞桨（PaddlePaddle）框架，语义理解与智能体采用文心大模型，边缘部署平台为 RK3588。本车据此选择 RK3588S 作为上位机推理平台，并采用 YOLO 系列目标检测算法完成赛道元素识别。
1.3 本车总体方案
结合赛题要求，本车采用“双处理器 + 视觉感知 + 闭环控制”的总体方案。上位机 RK3588S 负责图像采集、目标检测、OCR 识别、语义决策与轨迹/速度规划，并将决策结果以指令形式通过串口下发给下位机；下位机 TC264 负责接收指令并完成电机速度闭环、舵机方向控制、姿态解算等实时运动控制任务。整车主控板、驱动板与电源板均为自行设计制作，符合竞赛规则。
第二章 系统总体方案设计
2.1 总体架构
系统采用主从分布式架构，由上位机（视觉与决策层）与下位机（运动控制层）两级组成。上位机完成计算密集的视觉感知与决策，下位机完成时间关键的运动闭环控制，二者通过高速串口交换数据，既保证了深度学习推理所需的算力，又保证了控制回路的实时性与确定性。

2.2 系统框图

图 流程图
系统的功能可划分为感知层、决策层、执行层与供能层四个层次。感知层由摄像头与 IMU660RA、编码器组成，分别提供环境图像、车身姿态与轮速信息；决策层由 RK3588S 承担视觉识别与语义决策，由 TC264 承担控制律解算；执行层由 BTN7971B 全桥驱动电机、BDS300 舵机实现转向；供能层由锂电池经 TPS5450 与 LDO 分级稳压，为各模块提供稳定电源。
2.3 通信方案
上位机与下位机之间采用 UART 串口通信。上位机周期性地将决策结果——目标速度与横向偏差（循迹误差）等控制量——按自定义协议打包下发，停车、避让、加速等行为通过调整速度与偏差量实现；下位机将实际速度、当前姿态、状态字等信息回传。协议采用帧头 + 长度 + 命令 + 数据 + 校验 + 帧尾的结构，保证通信的可靠性与可扩展性。上位机内部各功能模块（采集、推理、决策、通信）通过多线程/消息队列解耦，保证推理不阻塞通信。
2.4 任务流程
车辆上电后，上位机加载 RKNN 模型与网络服务，下位机完成外设初始化与自检。发车后，上位机持续采集图像，通过 HSV 循迹提取赛道路径，并以 YOLO 模型检测赛道元素（行人、车辆、金币、交通灯、路牌），结合 OCR 与语义理解判断当前任务，由决策模块生成目标速度与横向偏差（循迹误差）并经串口下发；下位机据此闭环控制电机与舵机，同时利用 IMU660RA 与编码器反馈保持车身姿态与速度稳定。三圈任务依次执行，系统在语义导航、速度规划、避让与收集之间动态切换。
第三章 机械结构设计
3.1 车模与总体布局
竞赛允许在指定范围内自由选择底盘，整车尺寸须满足高 ≤ 15 cm、长 ≤ 35 cm、宽 ≤ 22 cm 且无外壳的要求。本车选用阿克曼转向结构的车模底盘，前后轮布局兼顾转向灵活性与直线行驶稳定性。整车质量分布遵循“重心低、前轻后重适度”的原则：电池置于底盘中部偏后以压低重心，上位机板平放固定，驱动板与主控板分别布置在两侧，既利于散热又便于检修。

图一 整车图
3.2 传感器安装
摄像头通过可调角度的支架安装于车头前方高处，俯仰角与安装高度经过反复标定，使赛道前方 0.3～3.0 m 范围内的虚拟元素均处于有效视野内，并兼顾近处与远处的检测需求。IMU660RA 陀螺仪安装于车身几何中心附近，其 X/Y/Z 轴与车身坐标系对齐，安装时保证平面水平、避免与电机等强振动源直接刚性连接，以减少振动噪声对姿态解算的影响。编码器安装于驱动电机轴端或传动齿轮处，用于实时测量轮速，为速度闭环提供反馈。
3.3 转向机构
转向由 BDS300 数字舵机通过转向拉杆带动前轮实现。舵机输出臂与转向节之间采用可调拉杆连接，通过调整拉杆长度与舵机中位，保证方向盘居中时前轮回正。舵机采用独立 7.4 V 稳压供电，输出轴与转向连杆的连接处加装缓冲，避免剧烈转向时机械冲击损坏舵机齿轮。

第四章 硬件电路设计
4.1 电源系统
电源系统是整车稳定运行的基础。本车采用3S航模电池作为总电源，经分级稳压为各模块供电。由于舵机、电机在启动与堵转时会产生较大电流冲击与电压波动，电源设计遵循“动力电与逻辑电分离、大功率负载独立供电”的原则，具体拓扑如下：

图二 12V转5V
TPS5450 是 TI 公司的高效降压型 DC-DC 转换器，输入电压范围 5.5～36 V，可提供 5 A 连续输出电流，开关频率固定为 500 kHz，效率可达 90% 以上，采用带散热焊盘的 SOIC-8 封装。其宽输入范围与高输出能力能够覆盖锂电池满电至欠压的整个放电区间，并为上位机（峰值约 4 A）提供充足裕量。输出端并联大容量电解电容与高频陶瓷电容，抑制开关纹波；输入输出分别加入防反接与过压保护。
3.3 V 支路采用低压差线性稳压器由 5 V 降压得到，为IMU660RA、编码器及 BTN7971B 的逻辑侧供电。由于这些负载电流小、对纹波敏感，采用 LDO 可提供更洁净的电源，降低对 ADC 采样与姿态测量的干扰。
4.2 电机驱动电路
电机驱动采用两片英飞凌 BTN7971B（NovalithIC 半桥）组成 H 全桥，驱动单个直流电机。BTN7971B 内部集成了 P 沟道高侧 MOS 管与 N 沟道低侧 MOS 管及其驱动电路，无需电荷泵，工作电压 4.5～28 V，连续输出电流可达 44 A，峰值 50 A 以上，导通电阻典型值仅 16 mΩ，支持最高 25 kHz 的 PWM 频率，并集成主动续流、过流限流、过温关断、欠压/过压锁定等保护功能。

图三 电机驱动原理图
每片 BTN7971B 构成半个桥臂，两片的 OUT 端分别连接电机两端，共用 VS 与 GND。正向旋转时第一片 IN1 置高（上管导通）、第二片 IN2 置低（下管导通），电流由 VS 经电机流向 GND；反向旋转时交换两片 IN 状态即可改变电流方向。PWM 施加于 IN 端以调节占空比，从而实现电机调速。IS 引脚提供与负载电流成比例（约 1/19500）的电流采样信号，既可用于电流闭环控制，也可作为故障诊断标志。控制逻辑经光耦或电平匹配后由 TC264 的 PWM 口驱动，动力地与逻辑地采用单点接地，抑制干扰。
4.3 舵机驱动
转向采用 BDS300 数字舵机，通过 50 Hz（周期 20 ms）PWM 信号控制，其中 0.5～2.5 ms 的脉宽对应0°～180° 的转角，1.5 ms 对应中位 90°。舵机内部具备闭环位置反馈，只需给定脉宽即可锁定目标转角。为保证转向精度，PWM 由 TC264 的 GTM 模块产生，脉宽分辨率可达微秒级。舵机采用独立 6 V 稳压供电，信号线经限流保护后接入主控，避免舵机堵转时的电流冲击影响其他模块。

图四 舵机降压
4.4 姿态传感器
姿态测量采用逐飞科技 IMU660RA 六轴惯性测量单元，内部集成三轴陀螺仪与三轴加速度计，通过 SPI 接口与主控通信。陀螺仪量程可配置至 ±2000°/s，加速度计量程可配置至 ±16 g，输出速率最高约 1.6 kHz。本车将其用于车身横滚、俯仰及航向角的解算，为转向、入弯出弯判断与侧倾补偿提供姿态反馈。
4.5 上位机平台
上位机采用瑞芯微 RK3588S 开发板（SRK3588S）。RK3588S 采用 8 nm 工艺，CPU 为 4×Cortex-A76（最高 2.4 GHz）+ 4×Cortex-A55（最高 1.8 GHz）的 big.LITTLE 八核架构，GPU 为 Mali-G610 MP4，并集成 6 TOPS（INT8）的三核 NPU，支持 INT4/INT8/INT16 及 FP16 等混合精度，可通过 RKNN 工具链高效运行深度学习模型。该平台板载 LPDDR4/LPDDR5 内存与 MIPI CSI 摄像头接口，满足高清图像采集与实时推理需求。
第五章 软件设计
5.1 上位机软件
上位机软件（allcarbiggo1 工程）运行于 RK3588S 的 Linux 系统上，采用 C++17 编写，依赖 OpenCV、RKNN API 与串口库，通过 CMake 组织构建。其技术路线为“摄像头采集 → IPM/HSV 路径提取 → RKNN 目标检测 → 任务状态机 → 控制量仲裁 → UART 下发”。软件采用多线程并发架构：主线程负责启动与任务编排，ThreadManager 将采集、循迹处理与可选视频流输出划分为独立线程，UART 模块独立维护接收与发送线程，RKNN 推理池使用三个工作线程并分别绑定 NPU Core 0/1/2，使耗时的推理、图像处理与网络展示互不阻塞控制环。各处理阶段的数据链路如下表：

全部参数由 config.json 集中管理，覆盖硬件通信、性能调优、IPM、循迹、检测、避让、金币、红绿灯、路牌与 OCR 等配置，并在读取后实施范围约束（如将置信度限制在 0～1），实现“配置外置 + 钳位校验”，便于在不重新编译的情况下完成赛道调参。
5.2 视觉感知与赛道循迹
上位机初始化时加载逆透视（IPM）矩阵，并在处理中使用变换后的赛道视图。IPM 的作用是减弱透视造成的距离尺度差异，使边界跟踪与前瞻点计算在更接近平面坐标的图像域中完成。赛道循迹由 HsvLineTracker 模块实现：从配置读取 HSV 颜色阈值、边界缺失容忍、前瞻范围、指数平滑系数与舵机 PD 参数，输出基础横向误差以及中心路径、左右扫描点、调试图等中间信息；这些路径信息继续被避障、金币与路线选择等模块复用，避免各模块重复估计赛道几何。转向控制中，误差经比例与微分项处理后映射到 PWM 范围，并具备丢线时误差保持与限速/平滑处理，以容忍瞬时图像退化。
5.3 目标检测与路牌识别
目标检测由 Detector 与 RknnPool 配合完成：Detector 将模型路径传入推理池，推理池负责模型加载、输入尺寸查询、BGR 图像预处理、RKNN 执行与 YOLO 后处理，并提供预热与最新结果缓存。配置中的检测跳帧间隔（det_skip_interval）可降低检测频率，在感知新鲜度与 CPU/NPU 负载之间调节。检测框通常结合类别、面积、置信度、图像位置与赛道中心线相对位置共同过滤：行人与车辆采用独立的面积、置信度与区域阈值，金币还需满足绿色边界/中心线相关条件。
路牌识别由 BoardRouteSelector 完成：检测到合格路牌后执行减速、对齐、停车与后台识别流程，调用 OCR 模型进行多帧投票，并为路线决策配置独立工作线程、超时、失效容忍、二次触发冷却与路线保持时间。语义理解可接入可选的大模型（LLM）服务端点，解析路牌文字与箭头后选择正确分支。
5.4 任务决策与行为仲裁
赛道元素由独立任务模块处理：CarAvoid 依据目标相对绿色边界与中心线的位置，将行人划分为左、中、右区域，中央区域满足阈值时停车，左右区域达到条件时向相反侧偏移，并在目标消失或偏移到位后按设定步长回正；TrafficLight 维护等待/通行状态机，支持黄灯等待、锁定与丢失帧容忍；金币模块选择合格金币侧并生成受限、平滑的横向牵引，遇障碍时自动抑制。
主循环并非简单地将检测框直接映射为转向量，而是先产生基础循迹结果，再逐层叠加高优先级行为：路牌对齐与停车、近距离行人/车辆避让、红绿灯限行、路线选择与金币牵引具有不同优先级，其中金币被安排为较低优先级，在人员、车辆或路线切换出现时被抑制。对控制量的变化采用平滑步进，为行人避让、车辆绕行、金币偏置、丢线恢复与路线对齐分别设置每帧最大变化量，将策略切换转化为渐变的误差目标，降低执行端因突变控制命令产生振荡的风险。
5.5 下位机软件
下位机软件运行于 TC264 上，采用前后台 + 定时中断的结构。主循环负责通信解析、任务调度与状态监测，定时中断中以固定周期执行运动控制闭环：读取编码器与 IMU660RA 数据、运行速度环与方向环控制律、更新电机与舵机 PWM。下位机软件主要包括：
通信模块：串口接收上位机指令并解析，回传状态；
速度闭环：基于编码器测速的 PID 控制，输出电机 PWM 占空比；
方向控制：基于横向偏差（循迹误差）的舵机 PWM 输出；
姿态解算：对 IMU660RA 数据做互补/卡尔曼滤波，得到车身姿态角；
故障保护：过流、过温、通信超时等异常时的安全停车处理。
第六章 模型部分
6.1 数据集构建
针对赛题需要识别的元素（行人、车辆、金币、交通灯、路牌等），队伍采集并标注了大量赛道图像。为提高模型在虚实融合环境下的泛化能力，数据集融合了真实赛道图像与 AR 叠加后的图像，并通过随机亮度、对比度、裁剪、翻转等数据增强扩充样本，覆盖不同光照、角度与距离下的目标形态。标注采用矩形框形式，标注完成后按比例划分训练集、验证集与测试集。
6.2 模型选型
目标检测采用 YOLO 系列单阶段检测算法。YOLO 系列将目标检测建模为端到端的回归问题，在检测速度与精度之间取得良好平衡，非常适合嵌入式边缘部署。结合 RK3588S 的 6 TOPS NPU 算力与实时性要求，本车在 YOLOv5/v8 等轻量级骨干网络上进行权衡选型，并采用飞桨（PaddleDetection）框架进行训练，以符合竞赛指定框架要求。
6.3 模型训练
训练在 GPU 服务器上完成。采用预训练权重进行迁移学习，使用带动量的随机梯度下降（SGD）或 Adam优化器，配合余弦退火学习率调度；损失函数包含边界框回归损失、置信度损失与分类损失。训练过程中通过验证集监测 mAP（平均精度均值）与损失曲线，结合数据增强与正负样本均衡策略调优，最终在测试集上取得满足竞赛要求的检测精度与召回率。
6.4 量化与部署
训练完成的模型导出为 ONNX 后，使用瑞芯微 RKNN-Toolkit2 工具链进行 INT8 量化，将模型转换为 .rknn 格式，并通过量化校准集降低量化带来的精度损失。部署时，上位机通过 RKNPU2 运行时调用 NPU 完成推理，显著降低 CPU 占用与功耗。在 640×640 输入分辨率下，YOLO 系列轻量模型在 RK3588S NPU 上可实现每秒数十帧的推理速度，端到端延迟约 30～40 ms，满足实时控制需求。量化前后通过对比测试集 mAP，确保精度损失在可接受范围内。
工程侧通过 RknnPool 推理池管理三个 RKNN 上下文，并分别绑定 NPU Core 0/1/2，实现多核并发推理；配合检测跳帧间隔（det_skip_interval）与最新结果缓存，可在感知新鲜度与 CPU/NPU 负载之间灵活调节。
第七章 下位机控制算法
7.1 主要控制算法
7.1.1 电机速度闭环
电机速度闭环采用 PID 控制，以编码器测得的实际轮速为反馈，目标速度由上（位机）决策给出。为避免积分饱和并便于工程实现，采用增量式 PID 算法，其离散形式为：
Δu(k) = Kp·[e(k) − e(k−1)] + Ki·e(k) + Kd·[e(k) − 2e(k−1) + e(k−2)]
其中 e(k) 为第 k 次采样的速度误差，Kp、Ki、Kd 分别为比例、积分、微分系数。比例项决定响应速度，积分项消除稳态误差，微分项抑制超调与振荡。为减小电机抖动，PWM 频率设为 15～20 kHz（在 BTN7971B 支持的 25 kHz 以内），并加入死区补偿，使车在目标速度附近保持平滑。
7.1.2 舵机方向控制
方向控制采用位置式 PID。上位机通过 HSV 循迹与任务决策生成横向偏差（循迹误差）并经串口下发，下位机接收偏差并结合车身姿态角进行修正，经 PID 与标定映射为舵机 PWM 脉宽，实现转向闭环。转向环节引入前馈项与限幅，避免大误差时舵机打满导致机械冲击，同时保证小误差时的响应灵敏度。偏差与脉宽之间通过标定建立线性映射，中位与两端极限值在调试阶段精确标定。
7.1.3 姿态解算
车身姿态通过 IMU660RA 的数据解算。陀螺仪角速度积分可快速响应动态变化但存在漂移，加速度计可提供长期稳定的重力参考但受振动影响。本车采用互补滤波融合二者，其递推形式为：
angle = α·(angle + ω·Δt) + (1 − α)·angle_acc
其中 ω 为陀螺仪角速度，angle_acc 为由加速度计计算的角度，α 为融合系数。通过合理选取 α，可兼顾动态响应与静态稳定性。解算得到的横滚角、俯仰角与航向角用于侧倾补偿、入弯出弯判断以及转向环的前馈修正，提高复杂路况下的行驶稳定性。
7.2 决策与任务执行
决策模块根据视觉检测结果完成各任务的状态机调度：
安全避让：检测到虚拟行人横穿时，结合其位置与速度计算避让方向与幅度，通过减速 + 微调转向实现平稳避让，必要时机采取紧急制动。
语义导航：识别路牌文字与箭头后，调用大模型进行语义理解，选择正确分支并规划转向。
红绿灯与限速：根据红绿灯状态决策加速通过或平稳停车，实时监测车速确保不超过限速值。
金币收集：将检测到的金币位置纳入路径规划，在保证安全的前提下尽可能收集金币以获得时间奖励。





第八章 系统调试
系统调试遵循“分模块调试、逐步集成”的原则。硬件层面，先分别调试电源、主控最小系统、电机驱动、舵机与姿态传感器，验证各路电压、PWM 波形与通信链路；软件层面，先完成编码器测速、PID 参数整定、姿态解算等底层功能，再联调上位机检测与下位机执行。
模型层面，通过反复采集赛道实景数据迭代训练，重点解决小目标漏检、强光/阴影下的误检等问题；量化部署后对比 RKNN 与原始模型精度，选取精度损失最小的量化方案。联调阶段针对“鬼探头”避让的时机、语义导航的识别准确率、红绿灯停车线距离等关键点反复标定，最终实现整车的稳定、快速、可靠运行。
第九章 总结与展望
本车围绕人工智能模型组赛题，设计了“RK3588S 视觉感知 + TC264 运动控制”的分布式系统，完成了 YOLO 目标检测、语义决策、速度与方向闭环控制等关键功能，能够稳定完成安全避让、语义导航、红绿灯与限速响应、金币收集等任务。通过本次竞赛，队伍在深度学习、嵌入式系统、自动控制与机械设计等方面的综合能力得到了全面锻炼。
展望后续工作，可进一步从以下几方面优化：一是采用更高效的目标检测与跟踪算法，降低误检率并提升小目标检测能力；二是引入强化学习与智能体技术，提升复杂场景下的自主决策水平；三是优化机械结构与重心分布，进一步提高行驶速度与稳定性。

// 中心线(IPM)加水平偏置 warped_offset_px 后逐点映射回原始图像
std::vector<cv::Point> mapOffsetCenterlineToRaw(const std::vector<cv::Point>& warped_center_path, int warped_offset_px, int frame_width, int frame_height)
{
    std::vector<cv::Point> raw_path;
    if (warped_center_path.empty() || frame_width <= 0 || frame_height <= 0) return raw_path;
    raw_path.reserve(warped_center_path.size());
    for (const auto& point : warped_center_path) {
        const cv::Point2d raw_point = ARRenderer::mapPointFromWarped(
            cv::Point2d((double)(point.x + warped_offset_px), (double)point.y), frame_width, frame_height);
        if (std::isfinite(raw_point.x) && std::isfinite(raw_point.y))
            raw_path.emplace_back((int)std::lround(raw_point.x), (int)std::lround(raw_point.y));
    }
    return raw_path;
}
// 用绿色边界(中心线 ± green_half_width_px)判断金币框在中心线左/右，并给出底边中心相对中心线的原始误差
bool classifyGoldByGreenBoundaries(const Box& box, const std::vector<cv::Point>& normal_center_path, int green_half_width_px, double outside_margin_px, int frame_width, int frame_height, GoldTrackSide* side, double* signed_centerline_error)
{
    if (side == nullptr || signed_centerline_error == nullptr) return false;
    *side = GoldTrackSide::NONE; *signed_centerline_error = 0.0;
    const std::vector<cv::Point> raw_left_boundary  = mapOffsetCenterlineToRaw(normal_center_path, -std::max(0, green_half_width_px), frame_width, frame_height);
    const std::vector<cv::Point> raw_right_boundary = mapOffsetCenterlineToRaw(normal_center_path,  std::max(0, green_half_width_px), frame_width, frame_height);
    if (raw_left_boundary.empty() || raw_right_boundary.empty()) return false;
    const double foot_x = 0.5 * (double)(box.x1 + box.x2);
    const int foot_y = std::clamp((int)std::lround(std::max(box.y1, box.y2)), 0, std::max(0, frame_height - 1));
    double left_x = 0.0, right_x = 0.0;
    if (!interpolatePathXAtY(raw_left_boundary, foot_y, &left_x) || !interpolatePathXAtY(raw_right_boundary, foot_y, &right_x)) return false;
    if (left_x > right_x) std::swap(left_x, right_x);
    const double margin = std::max(0.0, outside_margin_px);
    if (foot_x < left_x - margin || foot_x > right_x + margin) return false;   // 金币底边不在绿色带内
    double centerline_error = 0.0;
    if (!boxFootRelativeToNormalCenterlineInOriginalImage(box, normal_center_path, frame_width, frame_height, &centerline_error)) return false;
    *signed_centerline_error = centerline_error;
    *side = centerline_error < 0.0 ? GoldTrackSide::LEFT : GoldTrackSide::RIGHT;
    return true;
}
// 目标框底边中心相对正常中心线的原始图像水平误差（IPM 同 y 处插值后映射回源图）
bool boxFootRelativeToNormalCenterlineInOriginalImage(const Box& box, const std::vector<cv::Point>& normal_center_path, int frame_width, int frame_height, double* signed_error)
{
    if (signed_error == nullptr || normal_center_path.empty() || frame_width <= 0 || frame_height <= 0) return false;
    const cv::Point2d raw_foot_center(0.5 * (double)(box.x1 + box.x2), (double)box.y2);
    const cv::Point2d warped_foot_center = ARRenderer::mapPointToWarped(raw_foot_center, frame_width, frame_height);
    if (!std::isfinite(warped_foot_center.x) || !std::isfinite(warped_foot_center.y)) return false;
    std::vector<cv::Point> sorted_path = normal_center_path;
    std::sort(sorted_path.begin(), sorted_path.end(), [](const cv::Point& a, const cv::Point& b){ return a.y != b.y ? a.y > b.y : a.x < b.x; });
    double centerline_x = 0.0;
    if (!interpolatePathXAtY(sorted_path, (int)std::lround(warped_foot_center.y), &centerline_x)) return false;
    const cv::Point2d raw_centerline_point = ARRenderer::mapPointFromWarped(cv::Point2d(centerline_x, warped_foot_center.y), frame_width, frame_height);
    if (!std::isfinite(raw_centerline_point.x)) return false;
    *signed_error = raw_foot_center.x - raw_centerline_point.x;   // 正=中心线右侧
    return true;
}

// 目标框中心相对中心线的原始图像水平误差（路牌对齐用，远处目标锚定最近路径点）
bool boxCenterRelativeToNormalCenterlineInOriginalImage(const Box& box, const std::vector<cv::Point>& normal_center_path, int frame_width, int frame_height, double* signed_error)
{
    if (signed_error == nullptr || normal_center_path.empty() || frame_width <= 0 || frame_height <= 0) return false;
    const cv::Point2d raw_box_center(0.5 * (double)(box.x1 + box.x2), 0.5 * (double)(box.y1 + box.y2));
    const cv::Point2d warped_box_center = ARRenderer::mapPointToWarped(raw_box_center, frame_width, frame_height);
    if (!std::isfinite(warped_box_center.x) || !std::isfinite(warped_box_center.y)) return false;
    std::vector<cv::Point> sorted_path = normal_center_path;
    std::sort(sorted_path.begin(), sorted_path.end(), [](const cv::Point& a, const cv::Point& b){ return a.y != b.y ? a.y > b.y : a.x < b.x; });
    double centerline_x = 0.0;
    if (!interpolatePathXAtY(sorted_path, (int)std::lround(warped_box_center.y), &centerline_x)) {
        // 远处路牌映射到可见路径上方时，锚定最近路径点
        const auto nearest = std::min_element(sorted_path.begin(), sorted_path.end(), [&](const cv::Point& a, const cv::Point& b){
            return std::abs(a.y - warped_box_center.y) < std::abs(b.y - warped_box_center.y); });
        if (nearest == sorted_path.end()) return false;
        centerline_x = (double)nearest->x;
    }
    const cv::Point2d raw_centerline_point = ARRenderer::mapPointFromWarped(cv::Point2d(centerline_x, warped_box_center.y), frame_width, frame_height);
    if (!std::isfinite(raw_centerline_point.x)) return false;
    *signed_error = raw_box_center.x - raw_centerline_point.x;
    return true;
}

// 中心线插值：命中精确 y 直接返回，否则在覆盖段内线性插值
bool interpolatePathXAtY(const std::vector<cv::Point>& sorted_points, int target_y, double* out_x)
{
    if (out_x == nullptr || sorted_points.empty()) return false;
    for (const auto& point : sorted_points)
        if (point.y == target_y) { *out_x = (double)point.x; return true; }
    if (sorted_points.size() < 2U) return false;
    for (std::size_t i = 0; i + 1U < sorted_points.size(); ++i) {
        const cv::Point& p0 = sorted_points[i];
        const cv::Point& p1 = sorted_points[i + 1U];
        if (target_y < std::min(p0.y, p1.y) || target_y > std::max(p0.y, p1.y)) continue;
        const int delta_y = p1.y - p0.y;
        if (delta_y == 0) { *out_x = 0.5 * (double)(p0.x + p1.x); return true; }
        const double ratio = (double)(target_y - p0.y) / (double)delta_y;
        *out_x = (double)p0.x + ratio * (double)(p1.x - p0.x);
        return true;
    }
    return false;
}

// 解析循迹误差采样带：把配置 y 范围夹取到图像内并规范为 [top, bottom]
bool resolveTrackingErrorSampleBand(int image_height, int start_y_cfg, int end_y_cfg, int* sample_top_y, int* sample_bottom_y)
{
    if (sample_top_y == nullptr || sample_bottom_y == nullptr || image_height <= 0) return false;
    const int max_valid_y = std::max(0, image_height - 1);
    const int start_y = std::clamp(start_y_cfg, 0, max_valid_y);
    const int end_y   = std::clamp(end_y_cfg, 0, max_valid_y);
    *sample_top_y    = std::min(start_y, end_y);
    *sample_bottom_y = std::max(start_y, end_y);
    return true;
}

// 丢线兜底误差：取历史误差方向，幅度至少为 width * 0.25
double computeFallbackTrackingError(int image_width, double fallback_error)
{
    const double safe_fallback = std::isfinite(fallback_error) ? fallback_error : 0.0;
    if (std::abs(safe_fallback) <= 1e-6) return 0.0;
    const int safe_width = image_width > 0 ? image_width : kDefaultTrackingImageWidth;
    const double recovery_magnitude = std::max(std::abs(safe_fallback), (double)safe_width * kLaneLossRecoveryMinErrorWidthRatio);
    return (safe_fallback >= 0.0 ? 1.0 : -1.0) * recovery_magnitude;
}

// 基础加权循迹误差：采样带内对 (path_x - 320) 按深度线性加权求平均
double computeCommandTrackingError(const std::vector<cv::Point>& path_points, int image_width, int image_height, int start_y_cfg, int end_y_cfg, double fallback_error)
{
    if (path_points.empty()) return computeFallbackTrackingError(image_width, fallback_error);
    int sample_top_y = 0, sample_bottom_y = -1;
    if (!resolveTrackingErrorSampleBand(image_height, start_y_cfg, end_y_cfg, &sample_top_y, &sample_bottom_y))
        return computeFallbackTrackingError(image_width, fallback_error);
    std::vector<cv::Point> sorted_points = path_points;
    std::sort(sorted_points.begin(), sorted_points.end(), [](const cv::Point& a, const cv::Point& b){ return a.y != b.y ? a.y > b.y : a.x < b.x; });
    double weighted_error_sum = 0.0, weight_sum = 0.0;
    for (int y = sample_top_y; y <= sample_bottom_y; ++y) {
        double path_x = 0.0;
        if (!interpolatePathXAtY(sorted_points, y, &path_x)) continue;
        const double weight = 1.0 + (double)(y - sample_top_y);   // 越靠下(近)权重越大
        weighted_error_sum += weight * (path_x - kSerialTrackingReferenceX);
        weight_sum += weight;
    }
    if (weight_sum > 1e-6) return weighted_error_sum / weight_sum;
    return computeFallbackTrackingError(image_width, fallback_error);
}

void Servo_Ctrl(uint16 pwm)
{
    uint16 input;
    if(SERVO_PWMMAX < pwm)
    {
        input = SERVO_PWMMAX;
    }else if (SERVO_PWMMIN > pwm)
    {
        input = SERVO_PWMMIN;
    }else
    {
        input = pwm;
    }
    pwm_set_duty(Servo_pwm,input);
}

float PID_Normal(pid_param_servo*PID,float NowData,float Point)
{
    PID->Error=Point - NowData;
    PID->Out_D=(PID->Error - PID->Out_P)*PID->LowPass+PID->Out_D*(1-PID->LowPass);
    PID->Out_P=PID->Error;
    return (PID->Kp*PID->Out_P+PID->Kd*PID->Out_D);
}
