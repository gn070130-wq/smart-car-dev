摘要
本文面向第二十一届全国大学生智能汽车竞赛人工智能模型组，阐述了一
辆自动驾驶智能车在机械结构、硬件电路、软件算法与全局定位四个方面的完
整设计与实现。系统采用"上位机—下位机"分层架构：上位机基于香橙派
RK3588S 平台，依托其 NPU 运行 PP-YOLOE+ 目标检测、U-Net 语义分割与
PaddleOCR 文字识别等视觉模型，并结合自研 sideline 巡线算法与双轨制决策
架构，实现赛道环境的实时感知与避障、拾取、路牌识别等自主决策；下位机
基于英飞凌 TC264D 单片机，通过定时器中断与带前馈、抗饱和的差速 PID 控
制，实现电机与舵机的底层驱动。机械方面，基于新 C 型车模，通过底盘重心
优化、硅胶胎选型、舵机立式安装与前轮定位调节，提升了高速工况下的循迹
稳定性与过弯极限。硬件方面，设计了多路独立稳压电源与双 DRV8701E 电机
驱动电路，保证了系统供电的可靠性与驱动的精准性。此外，系统通过 AprilTag
全局定位模块实现车辆位姿解算，为比赛提供统一判定依据。经实际场地测试，
整车在复杂赛道环境下实现了稳定、可靠的自主行驶。

引言
全国大学生智能汽车竞赛是由教育部高等学校自动化类专业教学指导委员
会主办的全国性学科竞赛，以"立足培养、重在参与、鼓励探索、追求卓越"为指
导思想。竞赛要求参赛队伍自主设计并制作能够沿规定赛道自主行驶的智能车，
综合考察参赛队伍在嵌入式系统、自动控制、模式识别、传感器技术与机械设
计等多个学科方向的知识运用与工程实践能力。
人工智能模型组是本届竞赛面向人工智能技术应用设置的重要组别。与传
统组别不同，该组别要求参赛队伍综合运用深度学习、计算机视觉与嵌入式人
工智能等技术，构建具备环境感知、自主决策与运动控制能力的智能车系统。
比赛赛道设置了障碍车、行人、金币、路牌、门、限速牌、路障、交通灯等多
种元素，车辆在自主行驶过程中需要准确识别并合理处置这些元素，这对感知
算法的鲁棒性、决策逻辑的合理性以及整个系统的实时性都提出了较高要求。
本课题的任务是设计并实现一辆满足人工智能模型组比赛要求的自动驾驶
智能车。为此，系统采用"上位机—下位机"分层架构：上位机基于RK3588S 嵌
入式平台完成目标检测、道路分割与路牌识别等视觉感知任务，以及避障、拾
取、方向选择等融合决策与运动控制；下位机基于TC264D 单片机负责电机与
舵机的底层驱动及传感器采集；全局定位模块通过AprilTag 视觉基准解算车辆
位姿。整个系统需满足感知、决策、控制全链路的实时性要求，并在复杂赛道
环境下稳定可靠运行。系统方案的具体设计将在后续章节中详细阐述。

第一章 机械结构设计
智能车系统的性能上限由控制算法与机械结构的协同水平共同决定。当车速
提升至较高区间时，车模的甩尾、侧滑等现象将急剧放大，此时机械结构的合
理性直接制约着整车的极限速度与循迹稳定性。本团队基于新 C 型车模平台，
在严格遵守竞赛规则的前提下，从动力系统、转向机构、轮系定位、轮胎选型
及重心配置等多个维度进行了系统性优化，力求在加减速响应、弯道通过性和
直线稳定性之间取得最佳平衡。
1.1 整车基本参数与布局思路
本系统选用新 C 型车模作为基础平台。该车模采用双直流电机驱动后轮、
舵机驱动梯形转向机构完成前轮转向的布局方案，整体结构对称性良好，为后
续精密调校提供了有利条件。车体外形尺寸约为 250mm×184mm×125mm（长×宽
×高），整车质量较轻，且竞赛无相关重量要求。
驱动系统采用 RS380 型直流有刷电机。该电机使用电压范围为 DC3-9V，额
定电压 7.2V，空载转速 16200r/min，空载电流 0.5A。在最大效率工况下，转速
为 14060r/min，电流 3.29A，输出功率约 16W，输出转矩 10.9mN·m，约 111g·cm；
堵转状态下转矩可达 82.3mN·m，约 840g·cm，堵转电流 21.6A。该电机具有较
为宽泛的电压适应范围和较高的功率密度，能够满足高速竞赛工况下的动力需
求。电机如图 1.1 所示。

1.3 底盘高度与通过性平衡
底盘离地间隙直接影响整车的重心高度，而重心高度又决定了车辆在高速
转弯时的抗侧倾能力。理论分析和实践经验均表明，在确保车模底盘能够顺利
通过赛道灯盘及坡道障碍物的前提下，底盘越低、重心越低，车辆的抗侧翻能
力和弯道稳定性就越强。
对于 C 型车模而言，底盘高度可通过改变前轮轮轴中心与底盘之间的相对
高度来实现。具体做法是在前轮固定座与底盘连接处增加调整垫圈，通过垫圈
数量控制离地间隙。垫圈通常有 1mm 和 2mm 两种规格可供选择。本团队在满足
赛道元素通过性的前提下，通过阶梯式调节测试，将底盘离地间隙设置在 9~12mm
范围内，使整车重心有效下移，改善了高速过弯时的姿态稳定性。
此外，底盘高度的调节还需兼顾前后轮的平衡。过度降低前部离地间隙可
能导致前轮悬挂行程不足，影响转向时的轮胎接地状态；而过度降低后部则可
能改变驱动轮的抓地力分布。本团队通过前后轮分别调节的方式，使底盘在降
低重心的同时保持了前后轴的载荷分配合理。底盘高度如图 1.3 所示：

1.4 轮胎选型与处理
轮胎是车模与赛道直接接触的唯一部件，其性能直接影响抓地力、过弯极
限和整体操控性。智能车竞赛中常用的轮胎主要有三种：普通橡胶胎、硅胶胎
和光头胎。
原厂配备的普通橡胶轮胎在高速工况下容易打滑，抓地力不足。光头胎是
通过将普通轮胎的花纹磨去后得到的，抓地力优于普通胎，但制作周期较长且
一致性难以保证。硅胶胎是以硅胶为主要材料制成的轮胎，具有硬度低、弹性
好、化学稳定性强等特点。在室内光滑赛道（如塑料板或 PVC 赛道）上，硅胶
胎的过弯抓地力表现突出，胎面与赛道贴合度高。
本团队经过对比测试，最终选用硅胶胎作为前后轮的解决方案。硅胶胎的
优势主要体现在以下几个方面：首先，其柔软材质能够更好地填充赛道表面的
微观凹凸，提供更大的接触面积和摩擦力；其次，硅胶胎在弯道中能够提供更
强的侧向附着力，显著抑制高速过弯时的侧滑现象；最后，硅胶胎的化学稳定
性使其性能受温湿度变化影响较小，具有较好的一致性。
需要说明的是，硅胶胎在使用中需注意的问题：前后轮全部使用硅胶胎时，
抓地力过强可能导致车辆在急弯中翻车。我们在调试中通过适当调整前后轮胎

1.5 转向舵机安装与传动优化
转向系统的响应延迟是制约整车控制带宽的重要因素之一。本系统选用的
BDS300 型数字舵机具有较好的响应速度和扭矩输出能力，但安装方式与连杆布
置同样对转向时效性产生显著影响。
理论分析表明，在舵机输出角速度一定的前提下，转向连杆与舵机输出轴
连接点距轴心距离越大，转向轮获得的线速度越高，转向响应也就越迅速。这
相当于通过增大等效驱动臂长来提升运动传递效率。
舵机的安装方式主要有卧式、扣式和立式三种。卧式安装舵机平放于底板
上，质心较低，但舵盘不在底盘中心轴上，左右拉杆长度不一致，导致转向力
量不对称，后期调试难度较高。扣式安装结构稳固、质心较低，左右转向对称，
但整体占底盘面积较大且安装复杂。立式安装转向对称、占用空间小、响应速
度快、安装方便。
经对比实验验证，立式安装方案在空间利用率和力矩传递效率方面均优于
其他方案。采用立式安装时，转向连杆的摆动平面与转向轮运动平面基本重合，
减少了不必要的运动分解，使舵机能将更多输出功率转化为有效的转向力矩。
此外，安装过程中严格保证左右连杆长度一致、安装位置对称，确保舵机在左
右两个转向方向的等效臂长相等，从而使左右转向响应速度一致。

1.6 前轮定位参数调节
前轮定位是影响车辆直线行驶稳定性和弯道操控性的关键因素。本智能车
采用四轮触地方式，后轮为同轴刚性连接，其方向与车体纵向中心线保持平行，
因此整车的转向特性与直线稳定性主要依靠前轮定位参数进行调节。前轮调试
主要涉及前轮外倾和前轮前束两个核心参数。
前轮外倾：前轮外倾角是指从车辆正前方观察时，车轮顶端相对于竖直平
面向外倾斜的角度。前轮外倾的主要作用是抵消车辆重力使车轮向内倾斜的趋
势，减小车模机件的磨损与负重，使转向更加灵活。在实际调试中，前轮外倾
角的大小需要根据车模的载重和行驶工况自行调整。前轮外倾角偏大时，转向
反应较快，适合弯道较多的赛道；前轮外倾角偏小时，直线行驶稳定性更好。
本团队根据赛道特点，即类似于操场的赛道，选择了前轮外倾的调试方向，通

过调节转向拉杆的长度来改变外倾角的大小。经多轮场地测试，最终确定的外
倾角设置使车辆在弯道中的抓地性能表现最佳，转向响应迅速且可控。
前轮前束：前轮前束指从车辆正上方观察时，两前轮前端之间的水平距离
与后端之间的水平距离之差。若前端距离小于后端距离，称为正前束。
前轮前束的作用在于：由于前轮外倾使车轮滚动类似圆锥滚动，产生车轮
向外张开的趋势，但因舵机拉杆的约束，车轮无法向外滚开，从而增加了轮胎
外侧的磨损。合理的前束设置可以抵消车轮外倾带来的副作用，减少轮胎的异
常磨损，并改善直线行驶的稳定性。
本车模的前束值通过调节转向横拉杆的有效长度来实现。经实际测试，正
前束设定使车辆直线循迹性能最佳，轮胎磨损也较为均匀。需要说明的是，前
束值的选取与前轮外倾角密切相关，两者需协同调节才能达到最佳效果。前轮

3.2.1 目标检测
目标检测负责识别赛道上的离散目标（障碍车、行人、金币、路牌、门、
起终点标牌、限速牌、路障、交通灯等），为决策层提供"什么目标、在哪里、
置信度多高"的结构化信息。
模型选型：采用 PP-YOLOE+S。选择它的核心考量有二：一是精度与速度
的平衡，能 在嵌入式平台满足实时性；二是它对 NPU 量化的友好性
——PP-YOLOE+ 采用无锚 （anchor-free）设计，省去了锚框的预定义与匹配，
后处理链路更简洁，配合 INT8 量 化后能以较高帧率在 NPU 上运行。
预处理：输入640×640。①用letterbox（等比缩放+黑边填充）替代直接拉
伸，防目标变形；②保留uint8 不归一化，直接送入NPU 整数运算，省去浮点
开销。
输出结构：网络输出9 路特征（3FPN分支×3 类）。训练用DFL 将坐标建
模为17 个候选位置的离散分布；导出时将DFL 的softmax 解码移至后处理，并
新增score_sum 通道用于候选框预过滤。这样NPU只做规整卷积，解码交CPU，
分工清晰；score_sum 可在NMS 前低成本筛掉大量无效候选。

3.2.2 语义分割
语义分割负责把道路区域从图像中逐像素分离出来，输出道路掩码，是巡
线算法的输入。
模型选型：采用轻量级 U-Net。U-Net 是经典的编码器-解码器分割网络，
其核心特征是编码器与解码器之间的跳跃连接——高层语义信息负责"判断这是
什么"，低层细节 信息负责"边界在哪里"，二者逐层融合，恰好契合道路这类"
形状规整、边界清晰、语义简单"的目标。
后处理：推理输出逐像素的类别概率，经阈值二值化得到道路掩码，再通
过连通域分 析过滤面积过小的噪声区域，最终得到干净的道路掩码。
IPM 预处理：推理前对图像做逆透视变换，把道路掩码统一变换到鸟瞰视
角。该处理的原因与巡线算法一致——使几何关系在变换空间中保持一致，为
后续提取边线与中线提供几何一致的输入。值得说明的是，这一变换与巡线阶
段共用了同一套透视矩阵，保证了两者坐标系的严格对齐。

3.3.2 金币拾取
金币拾取采用"看到即拾取"的策略，核心思想是把金币的横向位置转化为巡
线偏移，让车辆主动偏向金币一侧行驶完成拾取，全程无需停车。
带符号距离计算：检测到金币后，系统将金币坐标经逆透视变换投影到鸟
瞰空间，计算金币相对于道路中线的带符号横向距离。鸟瞰空间中距离有统一
的物理尺度，带符号距离的符号表示金币位于道路中线的哪一侧，其大小直接
决定巡线偏移量。
双金币跟踪：系统支持同时跟踪多枚金币。所有检测到的金币按沿道路的
弧长排序，优先拾取最近的一枚；当相邻位置出现第二枚金币时，系统在两者
之间做跟踪偏向，避免在近距离金币间频繁切换目标。切换判定采用距离差阈
值：距离差超过阈值时保持旧目标，否则偏向新目标，从而在"尽量多拾取"与"
目标稳定"之间取得平衡。
近处减速：接近金币时，系统根据金币的弧长距离与切换跨度查表确定减
速幅度，自动降低车速以保证拾取成功率；退出减速后速度再平滑恢复，避免
车速突变。
3.3.3 行人避障
行人是安全优先级最高的元素。与静止的障碍车不同，行人可能移动、行
为具有不确定性，简单的绕行策略难以保证安全，需要一套"接近—观察—停车
—等待通过—恢复"的完整流程。
状态机沿Idle→Prepare→Danger→Stop→Go→Pass 主链推进，各阶段
的设计动机如下：
Idle：无行人，正常巡线；
Prepare：检测到行人后，先切至侧边线准备，但不改变速度。该设计的目
的是 提前预留横向避让空间，无需临场大幅转向；
Danger：进入危险距离后以蠕行速度缓慢接近，并逐帧判定行人是否阻挡路
径。蠕行的目的，是在保持接近的同时保留随时停车的能力；
Stop：行人阻挡路径时停车等待，通过停走控制维持安全车距；
Go：行人安全穿越或消失后加速通过；

安全窗口停走控制：Stop 阶段并不固定停车，而是设定一个距离窗口，行
人距离超过窗口上界时前进逼近，低于下界时后退保持，落入窗口内才完全停
车。其目的是应对行人的移动，使车辆自动维持安全车距，而非固定停车；
同侧/对侧穿越判定：判断能否安全通过时，根据行人在避让侧还是对侧采
用不同阈值。避让侧是车辆已经偏向的一侧、行人离车更近，危险程度更高，
阈值更严格；对侧相对安全，阈值宽松。
3.3.4 障碍车避障
障碍车避障面临的核心矛盾是： 既不能过早绕行，也不能过晚绕行 。过
早绕行时障碍 车可能还在远处、其占据道路的位置尚未稳定，方向判断容易出
错；过晚绕行则距离 太近、来不及避让。为此系统设计了"分层观察 + 投票决
策"的三阶段状态机。
三层距离嵌套：准备/起始/深入三个距离阈值，由远及近对应观察、锁定方
向、深入避障。远距降速观察积累信息，近距可靠后才执行绕行。
投票机制：观察阶段逐帧对偏左/偏右投票（+1/-1），进入避障时按净票数
锁定方向，时间维度多数表决抑制单帧抖动。
方向判定（质心法）：扩大检测框，算框内道路像素质心，以"接地点→质
心"向量与正前方的夹角判左右。利用道路被占后的剩余分布，不依赖车体形状，
鲁棒性强。
HSV剔除与道路补全：HSV提取剔除黄色车体（先闭运算连通车窗再取最
大区域），避免误判为道路；再提取周围道路轮廓连线填充补全，既消干扰又
保连通性。
双防抖与最短持续：出现/消失均多帧防抖；消失防抖初始"未消失"防启动
误报；进入避障后须持续最短时长才允许退出，防检测闪烁导致过早退出。
通过与鬼探头防护：消失防抖确认障碍车离开后偏移平滑回中；维护"已通
过"标识（定时过期），防障碍车短暂离开后重现的鬼探头场景。

3.3.5 路牌规划
路牌识别用于判断岔路口的行驶方向。其难点在于：路牌文字需要近距离
清晰成像才能被OCR稳定识别，而车辆高速接近时难以获得稳定的识别窗口。
系统的解决思路是"渐进式接近 + 停车识别"。
面积作为距离代理：单目相机无法直接测量距离，但同一物体在画面中的
面积与距离 成反比,路牌面积越大，说明车辆越近。系统以路牌检测框的面积作
为距离的代 理，据此分阶段控制车辆接近。
渐进式接近：检测到路牌后，依据面积阈值分三阶段推进——先完全停车
等待固定延时，再以低速蠕行接近，最后在面积达到识别阈值时停车进入识别
流程。这一"先停稳、再慢近、后停识"的渐进式设计，确保了识别时车辆静止、
图像清晰、采样充分。
停车识别与面积保持车距 ：停车识别阶段采用面积保持车距的停走控制,
路牌面积过小时前进逼近，过大时后退保持，落入安全窗口内则完全停车。这
与行人避障的停走控制思路一致，都是自动维持一个合适的"观察距离"。
OCR 与方向判断：停车后裁剪路牌区域图像，送入 OCR 引擎识别文字，
随后调用大模型接口，结合系统提示词判断真实行驶方向。识别结果写入共享
状态，供决策读取并据此设定行驶方向。

车辆在不同车速下的动态特性差异显著，固定一组 PD 参数难以在全速度

保守）。为避免频繁切换档位导致参数抖动，仅在档位真正变化时才更新参数。
3.4.3 曲率补偿与平滑调速
曲率补偿：针对弯道，系统在巡线阶段估计道路曲率，取边线首尾各若干
点计算方向向量，以两方向向量的夹角作为弯曲程度的度量，再乘以曲率补偿
系数得到偏移补偿量。该补偿量叠加到基础偏移上，使车辆在弯道内侧主动内
切，改善过弯轨迹。曲率补偿量经一阶低通滤波抑制帧间抖动。
平滑调速：速度调节支持平滑过渡。目标速度变化时，系统在指定时长内
对速度做线性插值，从当前速度逐步过渡到目标速度，避免速度突变导致的打
滑与车体俯仰。平滑过渡过程中若再次收到新的速度指令，则覆盖当前过渡，
重新开始。

3.5.3 上位机通信桥
上位机通信层封装为通信桥，对上层屏蔽底层传输细节，支持 UART 与

3.5.4 下位机解析
下位机采用状态机解析器逐字节解析帧，状态机包含五个状态：
等待帧头 → 读取长度 → 接收数据 → 校验 → 等待帧尾
解析器按字节流推进：首先等待帧头 0xAA，收到后记录长度并进入数据接
收状态；数据接收完成后读取校验和并核对，校验通过则等待帧尾 0x55；收到
帧尾即完成一帧的解析，取出数据区交由指令解析器执行。任一状态异常即复
位回等待帧头状态，实现自动重新同步。

第四章 全局定位模块
全局定位模块独立于车载系统运行，通过俯视全局摄像头识别铺设于场地
内的AprilTag 视觉基准标签，解算车辆在世界坐标系下的位姿，为监控与裁判
系统提供定位数据。本章介绍检测、位姿解算、滤波、加速与网络发送等各环
节。
4.1 AprilTag 检测
定位基于AprilTag视觉基准系统。AprilTag 是一种类似二维码的视觉标签，
其编码结 构允许从图像中快速、鲁棒地检测并唯一标识每个标签。系统预先在
场地内铺设若干 参考点标签与一个车辆标签，参考点标签用于建立图像坐标到
世界坐标的映射，车辆标签用于确定车辆位置。
检测过程包含多级处理：先对灰度图做降采样以加速，再通过高斯滤波与
边缘检测提取候选四边形，随后对每个候选区域解码，计算其与已知标签的汉
明距离并过滤超出阈值的误检，最终依据置信度阈值输出可靠的检测结果。检
测支持多线程并行，以提升大图上的处理速度。
4.2 位姿解算
位姿解算的目标是利用已知世界坐标的参考点标签，将图像坐标映射到世
界坐标，进而求得车辆位置与朝向。解算策略根据检测到的参考点数量自适应
选择：
恰好3 个参考点：采用仿射变换（getAffineTransform ）建立图像坐标到世
界坐标的线性映射。仿射变换保持平行性，由三对对应点即可唯一确定；
多于3 个参考点：采用RANSAC鲁棒估计算法求解单应矩阵。RANSAC 通
过随机采样一致集迭代求解，能够有效抑制个别误检参考点对结果的影响，在
参考点较多时显著提升鲁棒性。
得到映射后，将车辆标签的四角坐标变换到世界坐标系，取四角坐标的平
均作为车辆的位置；同时利用四角之间的几何关系计算车辆朝向——以两对角

4.3 其余处理
4.3.1 卡尔曼滤波
检测得到的 AprilTag 位姿存在帧间抖动——标签检测的亚像素误差、光照
变化等都会 引入噪声，直接输出会显得不稳定。为平滑定位结果、抑制检测噪
声，系统选启用卡尔曼滤波器对位姿进行滤波。
滤波器通过过程噪声协方差（q）与测量噪声协方差（r）配置平滑程度与响
应速度：过程噪声越大，滤波器越信任测量、响应越灵敏；测量噪声越大，滤
波器越平滑。两者构成一对折中——过大的过程噪声会导致滤波失去平滑作用，
过大的测量噪声则会使定位滞后于真实运动。此外还支持配置预测时间步长，
以适应不同的检测帧率。该模块可选启停，在定位精度要求高但检测噪声较大
的场景下开启。
4.3.2 ROI 裁剪加速
全局摄像头视野较大，若每帧对全图做 AprilTag 检测，耗时较长、帧率受
限。系统在 连续稳定检测到车辆后，将检测范围 裁剪至车辆附近的 ROI 区
域 ，仅对ROI内的图像做检测，并将检测坐标映射回原图坐标系，从而大幅提
升检测帧率。
裁剪模式下，参考点标签使用缓存结果——因为参考点通常分布在 ROI 之
外，裁剪后无法直接检测，若每帧重新计算会导致位姿跳变。系统在进入裁剪
前缓存参考点坐标，裁剪期间沿用缓存，保证位姿稳定。当车辆丢失或收到重
新检测指令时，恢复全图检测并重新计算裁剪区域。

与仿射/RANSAC 位姿解算，实现了车辆位姿的实时估计。

决策架构与多元素状态机，将目标检测与语义分割并行处理，并通过双体系正

时性需求，采用模型量化、多核推理池、线程亲和等一系列优化手段，实现了
感知、决策、控制全链路的实时运行。

自适应控制参数整定方法，进一步提升系统的环境适应能力与工程化水平。

```cpp
double computeSteeringPD(double error)
{
const auto now = std::chrono::steady_clock::now();
double filteredError =
steeringPD.errorFilter.filter(std::atan(error));
steeringPD.error = filteredError;
if (!steeringPD.hasLastTime) {
steeringPD.derivative = 0.0;
steeringPD.hasLastTime = true;
} else {
double dt = std::chrono::duration<double>(now -
steeringPD.lastTime).count();
dt = std::clamp(dt, 0.001, 0.1); // 时间间隔限幅，抑制
帧率波动
steeringPD.derivative = (steeringPD.error -
steeringPD.lastError) / dt;
}
steeringPD.lastError = steeringPD.error;
steeringPD.lastTime = now;
double output = steeringPD.kp * steeringPD.error
+ steeringPD.kp2 * steeringPD.error *
std::abs(steeringPD.error)
+ steeringPD.kd * steeringPD.derivative;
if (output >= 0.535) output = 0.535; // 输出钳位 ±0.535
rad
else if (output <= -0.535) output = -0.535;
return output;
}
```

A.2 sideline 法线偏移生成中线（sideline.cpp）
该函数实现 2.3 节所述的法线偏移，以差分半窗口估计切线方向，沿切线法线

```cpp
bool applyOffsetPx(std::vector<cv::Point2f>& dst,
const std::vector<cv::Point2f>& line, float
offsetPx)
{
if (line.size() < 2 || std::abs(offsetPx) <= 1e-6f) return
false;
const int n = (int)line.size();
const int halfWin = std::clamp(g_config.diff_half_window, 1,
n / 2);
dst.resize(n);
for (int i = 0; i < n; ++i) {
const int lo = std::max(0, i - halfWin);
const int hi = std::min(n - 1, i + halfWin);
cv::Point2f t = line[hi] - line[lo]; // 切线方向
const float len = std::sqrt(t.x * t.x + t.y * t.y);
if (len < 1e-6f) { dst[i] = line[i]; continue; }
t.x /= len; t.y /= len;
const cv::Point2f nLeft(t.y, -t.x); // 切线法线
const cv::Point2f normal = (offsetPx > 0.0f)
? cv::Point2f(-nLeft.x, -nLeft.y) : nLeft;
dst[i] = line[i] + std::abs(offsetPx) * normal;
}
return true;
}
```
