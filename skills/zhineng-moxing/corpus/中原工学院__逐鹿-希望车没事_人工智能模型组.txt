摘 要
本文给出智能模型组模型车的总体方案与软件实现。系统由 RK3588 级 Linux 上位机和 Infineon AURIX TC264 下位机构成。上位机从 /shm_ar_video 共享内存读取最新图像，以本地训练的 PPLiteSeg 道路分割模型提取可行驶区域和赛道中心线，并按赛段切换两套 PP-YOLOE 目标检测 RKNN 模型；第二赛段结合 PP-OCRv5 本地文字识别与文心大模型语义判断解析指示信息。检测线程采用最新帧覆盖策略，避免排队导致延迟累积。行为状态机依据车辆、行人、金色目标、门、指示牌和停止标志等事件选择速度、路径偏置和停车动作。上位机将左右轮速度、舵机目标及事件标志通过串口发送给 TC264，由下位机完成传感器采样与实时执行。
本报告依据less_gold 上位机源码与 orangepi_down/TC264 工程进行代码级分析。PPLiteSeg 语义分割模型由本队在本地完成训练，但当时未保存完整训练日志与训练曲线，因此本文不把无法复核的训练轮次、损失曲线和精度指标作为既成结论。
关键词：智能模型车；PPLiteSeg；PP-YOLOE；RKNN；PP-OCRv5；文心大模型；TC264

第一章  引言
1.1 项目背景
本项目面向第二十一届全国大学生智能汽车竞赛智能模型组，目标是设计一套能够自主感知赛道、估计运动状态、生成控制指令并可靠执行的模型车系统。根据技术报告细则，报告覆盖机械改造、传感器安装、电路、控制软件、开发调试过程、主要技术参数、电路原理图和核心算法程序等内容。
1.2 技术路线
系统采用 RK3588 级 Linux 上位机与 Infineon AURIX TC264 下位机协同架构。最新版上位机通过共享内存读取相机最新帧，在 RKNN Runtime 上并行组织 PPLiteSeg 道路分割、第一赛段 PP-YOLOE 检测、第二赛段 PP-YOLOE 检测和 PP-OCRv5 文字识别；由赛段/事件状态机将 car、human、gold、door、guideboard、stop 等感知结果转换为赛道中心误差、目标速度和控制标志。TC264 负责串口解析、编码器采样及舵机、电机实时执行。
系统采用“最新帧优先”的异步检测策略，目标检测线程只消费最新输入，避免图像队列堆积；道路分割与主循环保持闭环节拍。转向控制按速度档选择增益，转向量较大时依据四次多项式调整左右轮差速。该架构把 NPU 推理与场景决策放在上位机，把确定性较强的执行与传感器采样保留在 MCU。
1.3 报告组织
第二章说明机械结构、车模实物、传感器与计算平台；第三章说明电路原理图和上下位机通信；第四章给出多模型感知、道路中心线、状态机与控制算法；第五章说明软件结构与关键任务；第六章总结开发和调试流程；第七章给出实验与参数；第八章总结问题及改进方向。核心算法程序置于附录A，整车参数在第二章和第七章正文中。

第三章  电路与上下位机通信设计
3.1 电气系统组成
整车电气系统按功能划分为电源与保护、双路电机驱动、控制核心与外围接口四部分，电路原理图覆盖除 RK3588 级上位机与摄像头以外的全部自制底板电路。底板以 TC264 核心板为实时控制中心，核心板经排母与底板互联；底板上集成双路直流电机 H 桥驱动与电机端子、舵机供电接口、USB 转 TTL 调试电路、IMU660RC/编码器/显示屏/蜂鸣器接口，以及由电池输入、防反接、瞬态保护和多级二次电源构成的完整供电网络。自制接口板、电源板和电机驱动板均按详细原理图设计，供电拓扑与接口定义分别见表 3-1 和表 3-2。
供电链路自 XT30 电源插头 CN1接入电池电压，经 SS12D10G5 拨动开关 U11 与 HY19P03D P 沟道 MOSFET（Q2/Q3）组成的防反接电路后形成 VCCBAT 主电源轨；该轨并联 C35、C44（各 470 μF）等大容量滤波电容，并布置 SMBJ15CA、P6SMB6.8CA 瞬态抑制二极管和 BZT52C16 齐纳二极管，用于浪涌吸收、过压钳位与反压保护。VCCBAT 分三路变换：U5（LM73606QURNPRQ1，3.5–36 V 输入、6 A 同步降压）经 6.8 μH 电感 L1 输出 VCC5V（反馈分压 R4=30 kΩ、R3=7.5 kΩ），为 TC264 核心板、板卡、编码器、USB 转串口和 3.3 V 稳压器RT9013供电；U2（TPS5450，12 V 输入、5A 降压）经 4.7 μH 电感 L2 输出 VCC6V，反馈电阻 R10=2.26 kΩ、R11≈2.2 kΩ，输出为 6.79 V，供舵机使用；3.3 V 线性稳压器 RT9013由 VCC5V 产生 VCC3V，供 IMU、显示屏、缓冲器与逻辑电路使用。各路输出均配置 47–220 μF 输出电容与 100 nF 高频去耦电容；电源地按 PGND（功率地）、AGND（模拟地）、DGND（数字地）分区，经 0 Ω 电阻（R21、R25）单点相连，减小功率回路对敏感模拟信号的干扰[3]。各路稳压规格见表 3-1。

第四章  人工智能感知、路径与控制算法
4.1 多模型融合总体方案
上位机采用三类视觉模型与分层决策融合：PPLiteSeg 道路语义分割模型生成道路类别图；first.rknn 与 second.rknn 是按赛段拆分类别的 PP-YOLOE 检测模型；PP-OCRv5_rec.rknn 负责指示牌文字识别，识别文本再送入文心大模型进行语义判断。模型均通过 RKNN Runtime 在 RK3588 级 NPU 平台部署。PPLiteSeg 模型由本队在本地训练并转换为 road_seg_rk3588.rknn。


通用检测阈值 config.score 为 0.60，并在赛段配置中对 gold、human、car、door、guideboard、stop 等类别设置 0.65～0.70 的事件阈值。后处理支持按类别进行面积、长宽比和最大目标数约束，并执行分类别 NMS，减少异常大框、细长框及重复框对状态机的干扰。
PP-YOLOE 属于单阶段、无锚框目标检测器[6]。本项目利用其一次前向推理同时输出类别与边界框，再转换为 RKNN 供 NPU 执行。报告提交前还需补充实际采用的 PP-YOLOE 规模（S/M/L/X或自定义）、输入分辨率、预训练权重、训练轮数、数据增强、优化器、量化方式及转换链路；这些信息无法仅由运行源码可靠还原。
4.2 共享内存图像输入与低延迟调度
ArShmReader 连接 /shm_ar_video，共享内存映射后读取最新 BGR/RGB/Raw 帧。读取逻辑检查帧头一致性、宽高与缓冲区大小，并按配置进行垂直翻转。与旧版直接 V4L2 采集相比，共享内存将相机/AR视频生产者与识别进程解耦，便于独立重启和多进程复用。
目标检测在独立线程中运行。主循环仅覆盖一个“最新待检测帧”，检测线程被条件变量唤醒后根据 current_circle 选择 first 或 second 模型，完成推理后在互斥锁保护下更新最新结果。该策略不保存历史排队帧，在推理速度低于视频输入速率时仍优先保持结果新鲜度。分割模型在主循环中运行并参与赛道线提取，OCR另有工作线程，三类任务通过共享状态和赛段状态机汇合。
4.3 PPLiteSeg 道路分割与中心线
SegInferWrap 对输入图像缩放并转换为 RGB，调用 RKNN 推理后自动兼容 NCHW logits、NHWC logits 或二维类别图输出。对 logits 输出逐像素取最大类别，对类别图直接读取类别索引，再使用最近邻插值恢复到原图尺寸，避免类别编号被线性插值污染[9]。分割前景随后进入图像遍历与赛道边界处理，得到左右边界及中线误差 mid_err。
训练可追溯性方面，现存工程能够确认分割模型为本地训练并已转换为 RKNN，但原训练日志、损失曲线及完整超参数未留存。为保证技术报告可复核，训练集规模、训练轮数和 mIoU 等指标均不作推断，后续应使用固定测试集重新评估道路 IoU、边界误差和板端推理时间，并保留配置、模型哈希和测试日志。
转向误差不是单点中心差，而是由 find_mid_line_weight(speed) 依据不同前视行加权计算。速度升高时应增加远处边界权重，弯道或目标事件出现时再叠加偏置。对 gold 事件，代码按 gold_x_ratio=0.9 将中线误差与目标横向位置融合，使车辆在保持道路约束的同时靠近目标。
4.4 双赛段 PP-YOLOE 检测与行为状态机
第一赛段 PP-YOLOE 模型检测 car、gold、human、door。第一赛段状态机根据目标框位置、尺寸、道路左右边界和历史计数判断绕行侧、行人危险停车、车辆遮挡与目标接近；第二赛段 PP-YOLOE 模型检测 guideboard、gold、door、stop，并在 new_circle_start==2 后切换模型和对应状态机。不同赛段采用不同类别定义，避免单模型类别过多造成部署负担与误判传播。

4.5 OCR的应用
第二赛段先利用目标检测框裁剪 guideboard 区域，PP-OCRv5 本地识别模型完成图像归一化、RKNN 推理和 CTC 解码[7]，再通过关键词与句式规则判断“直行受阻”“右侧不可通行”“左右路况对比”等方向语义。根据队伍补充说明，复杂语义识别还会调用文心大模型，对 OCR 文本或裁剪图进行语义判定。OCR任务以互斥锁、条件变量和原子标志组织，防止主控制循环被长时调用直接阻塞。
4.6 舵机、速度与差速控制
上位机根据速度档选择舵机控制增益。其形式可概括为 u_s=u_0+Kp(v)e+Kp2(v)e|e|+Kd(v)[e(k)−e(k−1)]，具体实现以 my_servo_pid.cpp 为准。其为 150、180、210、240、270 及支路速度分别配置参数，更适合处理速度变化引起的车辆响应差异。
send_UART() 以舵机相对中值 x 判断是否进入差速区。当 |x|≥chasu_siqu 时，使用 Matlab 拟合所得四次多项式 y=f(x) 调整左右轮目标速度，再将方向位、左右轮速度、舵机目标和 flag 打包发送。control() 按 track_type 选择 normal_speed、speed_no_firstcirlce、guide_speed、car_to_human_speed 等速度或直接停车，实现感知—行为—执行闭环。
4.7 下位机姿态与速度闭环
TC264 上电进行参数与状态初始化。PID.c 对速度误差进行比例、积分和微分计算，并对积分项限幅。其编码器和下位机闭环用于速度反馈、异常诊断及短时状态估计，进而对小车进行实时控制。

float LPF_Update(LowPassFilter *filter, float input)
{
    if (!filter->initialized) {
        filter->prev_output = input;
        filter->initialized = 1;
        return input;
    }
    float output = filter->alpha * input
                 + (1.0f - filter->alpha) * filter->prev_output;
    filter->prev_output = output;
    return output;
}
A.2 PID 积分限幅（下位机 PID.c）
void PID_run(void)
{
    LastErr = Err;
    Err = result_r_num - target_speed;
    P_out = P * Err;
    Integral += I * Err;
    if (Integral > Max_Integral) Integral = Max_Integral;
    else if (Integral < Min_Integral) Integral = Min_Integral;
    D_out = D * (Err - LastErr);
    Output = P_out + Integral + D_out;
}
