第一章  引言
1.1 赛项背景与任务特点
全国大学生智能汽车竞赛面向智能感知、自动控制、嵌入式系统与人工智能等技术方向，要求参赛队围绕统一或指定车模完成从机械结构、电子系统到算法软件的完整工程实现。本届人工智能模型相关赛项采用虚实融合驾驶环境：车辆在真实物理赛道内运动，增强现实画面中叠加虚拟行人、车辆、道路标志、金币及其他任务对象，车辆需要完成感知、理解、决策和执行。
从赛道任务设置看，比赛不仅考查车辆能否稳定沿赛道行驶，还要求车辆在三圈全赛道范围内持续识别并避让随机出现的行人与车辆；第二圈和第三圈还会出现包含文字、箭头或图标信息的路牌，车辆需要识别路牌含义，并据此判断是否进入岔路口以及应选择的行驶分支。系统因此必须同时具备基础循迹的实时性、动态障碍物识别与避让的鲁棒性、路牌语义理解的正确性以及底层运动控制的确定性。
本队模型车采用C型车模作为机械基础平台，以TC264核心板作为下位机实时控制核心，使用香橙派边缘计算板作为上位机，负责图像处理、人工智能模型推理和高层任务决策；左右后轮采用双RS380直流电机独立驱动，电机驱动采用基于DRV8701的双路驱动板，转向采用BDS300舵机与阿克曼转向机构。系统通过摄像头获取外界赛道信息，通过编码器和陀螺仪获取车辆自身运动状态，形成“视觉感知—任务决策—实时控制—状态反馈”的闭环架构。
1.2 模型车设计目标
围绕竞赛任务和工程可靠性要求，整车设计确定了以下目标：首先，在机械方面通过碳纤维平板底盘、纵向中轴对称布局和三层立体结构降低重心并提高模块维护效率；其次，在电子方面采用上下位机分工结构，将计算量较大的视觉与语义任务交由香橙派处理，将高实时性的PWM输出、轮速闭环和舵机控制交由TC264执行；再次，在算法方面坚持安全任务优先，将行人与车辆避让置于普通循迹、岔路导航和收益型任务之前；最后，通过模块化软件和强弱电分离布线提高整车调试效率和赛场运行稳定性。
1.3 技术路线与报告结构
本报告首先给出整车系统总体架构和信息流；随后分别介绍机械结构、电路硬件和软件算法；之后对制作、安装和调试过程进行总结，并集中列出模型车主要技术参数；最后给出结论、现存问题以及后续改进方向。附录部分给出硬件连接原理说明以及核心算法源代码。

2.1 总体架构
整车采用“上位机智能计算 + 下位机实时控制”的分层架构。香橙派上位机直接接收车载摄像头图像，完成赛道基础特征提取、目标检测、OCR、视觉语义理解和任务状态机决策，并将期望车速、转向目标、制动指令及任务状态通过串口发送至TC264。TC264根据上位机目标以及编码器、陀螺仪等自身状态反馈，完成左右电机独立速度闭环、舵机PWM输出和故障保护。双驱系统尚未加入转弯电子差速，左右轮转弯时仍以统一基准目标速度为主。
图2.1  智能车系统总体架构
2.2 感知—决策—执行信息链
系统控制链按照“数据采集、特征提取、任务识别、策略规划、指令下发、底层执行、状态反馈”的顺序运行。上位机视觉线程保持连续图像输入，并在每帧内更新车道、目标物和交通语义；高层决策模块结合当前圈次、赛道状态和安全约束选择目标速度与路线；下位机以更高频率运行速度控制与转向控制，避免由于大模型或视觉推理时延直接影响电机控制稳定性。
图2.2  软件感知—决策—执行闭环
2.3 视觉任务感知与定位状态反馈边界
按照赛项视觉任务要求，车载摄像头承担虚拟行人、车辆、路牌、金币及赛道视觉信息的识别。左右编码器用于测量车轮转速，陀螺仪用于获取车辆自身姿态变化，两者属于车辆内部状态反馈。车上同时安装圆柱形雷达与赛事定位模块，用于车辆定位、赛场交互或辅助状态信息获取；上述模块不替代摄像头完成行人、车辆和路牌的语义识别。
2.4 系统安全与模块化设计
软件将安全相关任务设置为最高优先级：当全赛道范围内检测到行人或车辆存在碰撞风险时，避让或制动指令覆盖普通循迹、岔路导航和金币收集等指令；第二圈和第三圈检测到路牌时，系统在进入路口前完成语义解析，并根据结果判断是否进入岔路以及选择对应分支。当上位机与下位机通信超时、摄像头数据异常或任务识别置信度不足时，TC264进入降速或停车状态。硬件上采用模块化接插件、强弱电分离和关键插头防脱处理，使单个模块能够快速更换并降低赛场维护时间。

3.2 底盘轻量化与低重心设计
底盘采用平板式结构，主体使用碳纤维材料。在保证扭转刚度和板卡安装强度的前提下，碳纤维底盘能够减小非必要结构质量，使整车在加速、制动和快速转向时具有更小的惯性。整车布局遵循纵向中轴对称原则，电池、驱动板等大质量部件尽可能贴近底盘安装，以降低整车重心，减小高速过弯时的侧倾趋势和轮胎载荷变化。
3.3 双电机驱动与阿克曼转向
动力系统采用双电机后轮独立驱动，左右后轮分别由一台RS380直流电机驱动。双电机结构使左右驱动通道能够分别完成轮速闭环和输出补偿，便于修正两台电机、轮胎负载及机械阻力之间的不一致。程序尚未加入基于转弯曲率的电子差速控制，转弯时左右轮主要使用统一的基准目标速度，差速转弯作为后续可优化的方向。

3.4 三层模块化布置
传感器与控制模块采用“板卡+主板+定位模块”的三层立体结构。下层布置驱动板卡和电池，利用大质量部件稳定配重并降低重心；中层安装TC264主板、陀螺仪和散热风扇，风扇形成主动散热风道，陀螺仪与主板刚性固定以减小相对振动；上层用于圆柱形雷达与赛事定位模块安装，设置限位卡槽与锁紧结构，兼顾无遮挡、快速拆装和赛前检修需求。

3.5 摄像头、雷达及定位模块与线束固定
摄像头固定于车辆纵向中心轴，采用平视安装方式，并保留俯仰角微调能力。中心轴安装能够使左右视野近似对称，便于图像坐标与车辆横向偏差建立稳定映射。圆柱形雷达与赛事定位模块安装于上层卡槽，通过限位与锁紧结构固定，避免高速运行时发生平移或旋转，并保证定位与辅助状态获取所需的安装视野。
整车线束沿底盘两侧分别布置：动力线集中在一侧，摄像头、编码器、陀螺仪及串口等信号线布置在另一侧，尽量减小大电流开关对弱信号的电磁耦合。所有板卡接插件使用热熔胶或机械卡扣辅助防脱，舵机线缆预留转向运动余量并增加耐磨保护，避免反复弯折造成内部断芯。

4.1 TC264下位机接口设计
下位机采用TC264核心板及自制接口主板。根据主板原理图，主板围绕TC264核心板引出了电机控制、编码器、姿态传感器、屏幕、蜂鸣器、无线/串口及扩展IO等接口，并集成电池输入、5 V、3.3 V、舵机电源和板卡电源等供电支路。TC264主要承担实时性要求较高的舵机PWM、电机驱动控制、编码器采样、姿态数据读取和上下位机串口通信。核心板本体采用标准TC264模块，报告重点说明本队自制接口主板与外围电路。
4.2 电源与供电架构
主板电源由VCCBAT输入后分为多路供电。原理图中采用SP1N28STER开关稳压器构成5 V支路、舵机电源支路和板卡供电支路，并通过TPRT9013-25GB进一步得到3.3 V逻辑电源；各稳压支路布置SS54肖特基二极管、电感及输入/输出滤波电容。电机功率地PGND与逻辑地GND通过0 Ω电阻在指定位置汇接，既保证共同参考电位，又尽量避免大电流回流直接耦合到弱信号地。
依据TC264接口主板与DRV8701双驱板原理图，可对两块自制PCB的电容标称值进行统计：TC264主板约为1189.9141 μF，DRV8701双驱板约为247.4 μF，两块自制PCB合计约1437.3141 μF（约1.437 mF）。该数值按原理图中已标注并装配的电容求和，未包含香橙派、摄像头等商业模块内部不可见电容。整车正常运行电路功耗采用完整比赛工况下的电池端实测值。
4.3 DRV8701双路电机驱动
左右RS380电机由自制DRV8701双路直流电机驱动板独立控制。驱动板原理图中左右两路分别采用DRV8701E（U6、U29）作为栅极驱动核心，并各配合四只外置N沟道MOSFET构成全桥功率级。两路电机通过XT30接口独立输出，主电源同样采用XT30接口输入。控制侧以PH/EN信号实现方向与PWM调速，并通过SN74HC125DBR四路缓冲器对PH_1、EN_1、PH_2、EN_2进行缓冲；板上LR8341A-T44为逻辑部分提供3.3 V电源，NSLEEP用于统一使能。
图4.1  DRV8701单路电机驱动功能原理图
双路驱动使左右轮能够分别进行速度闭环，可补偿两台电机与机械传动之间的不一致。控制程序尚未启用基于转向曲率的电子差速，弯道中左右轮主要沿用统一基准目标速度。驱动板直接布置在电机附近以缩短大电流功率线路，降低压降与电磁辐射。DRV8701双驱板与TC264接口主板的完整EDA原理图见附录A。
4.4 编码器、陀螺仪与舵机接口
左右驱动轮分别配置1024线迷你编码器。编码器工作电压为3.3～5 V，工作电流约13.6 mA，高电平输出约3.3 V。正交编码器A/B相可以用于判定旋转方向并统计脉冲；若采用4倍频解码，理论上每转可获得更高的计数分辨率，实际计数规则以程序配置为准。
图4.2  1024线迷你编码器基础参数
陀螺仪安装在中层主板附近，主要用于获取车辆横摆角速度或姿态变化，为高速转向稳定性判断提供辅助信息。BDS300舵机由TC264输出周期PWM控制，程序中分别标定机械中位、左极限和右极限，避免舵机指令超出机械行程。
4.5 上下位机通信及抗干扰设计
香橙派与TC264采用串口通信。上位机周期发送期望速度、舵机目标/转向量、任务状态和控制标志；下位机回传左右轮实际速度、故障状态及必要的姿态数据。通信协议采用固定帧头、长度、数据区和校验字段，接收端在校验失败时丢弃该帧，并维护通信超时计数。
抗干扰方面，串口线、编码器线与摄像头信号线避开电机功率线，长线采用绞合或屏蔽方式；各模块供电端就近去耦，连接器进行应力释放与防脱固定；软件中对异常脉冲、突变速度和通信丢包进行限幅或滤波，避免单次干扰直接转化为大幅控制输出。

5.2 基于检测箭头的车道中线拟合与循迹
上位机基础循迹不直接依赖固定灰度阈值，而是从目标检测线程输出的“arrow”类别检测框中提取道路引导箭头中心点。程序首先过滤置信度低于0.30的检测框，并跳过画面最下方、车辆已经压近的最近箭头；随后在画面宽度50%、高度90%处设置固定车头锚点，使拟合曲线的近端始终与车辆当前位置一致。
为抑制岔路口或离群箭头造成的错误转向，程序采用“带车头锚点约束的RANSAC”筛选主路点集：候选直线必须同时经过或接近车头锚点，箭头中心点相对候选直线的横向偏差小于图像宽度的12%时视为内点。筛选后，若仅有1个有效箭头，则用“箭头+锚点”进行一次曲线拟合；有效箭头达到3个及以上时优先采用二次多项式x=f(y)拟合，失败则退化为一次拟合。
拟合得到的中线从画面中部/最远有效点开始，以4像素行步长向车辆近端采样，并将最后一个中线点强制固定到车头锚点。对有效中线区间（图像高度50%～90%）采用带峰值偏移的Hann窗进行加权，峰值向远场方向偏移0.25，使中远场趋势获得更高权重。由加权中心得到平均横向偏差后，再在图像高度约62%处取前视点计算航向偏差，并按0.75（横向）与0.90（航向）的权重融合，用于增强大弯道的提前转向能力。
主循环对融合偏差进行两级平滑：先将单帧偏差变化限制在±0.15以内，再使用系数α=0.25的指数滑动平均（EMA）抑制单帧抖动。发送到TC264前设置0.03的小死区，并以1.80倍增益放大有效转向量，最终限制在[-1,1]范围。识别短时失效时不立即保持最后一次大舵量，而是将历史偏差按0.92系数逐步衰减回中，从而提高检测瞬时丢失时的安全性。

5.3 目标检测与视觉语义理解
上位机程序通过独立NPU线程执行目标检测，并将检测对象以类别、置信度和目标框形式写入共享结果缓冲区。工程加载的模型文件为X_SmartV2.0.rknn，使用RKNN接口在NPU核心上运行；主线程只读取最新检测结果，检测结果超过150 ms未更新即判定为过期并清除，避免旧检测框持续影响控制。比赛任务中的行人、车辆、路牌与金币等对象均可沿用相同的检测结果接口进入任务层。
视觉大模型与语义导航属于国赛任务层的重要组成部分。工程在检测与循线链路之上，将图标/箭头检测和文心大模型返回结果规整为LEFT、RIGHT、STRAIGHT、STOP等有限动作，再由安全约束层下发到底层。
5.4 任务状态机与智能体决策
高层任务采用状态机与智能体策略结合的方式。状态机维护当前圈次、行人/车辆避让状态、路牌识别结果、岔路口决策、已收集金币、通信状态等离散信息；Agent根据感知结果、比赛规则和当前状态选择行为，但所有行为必须通过安全约束层。任务优先级设计为：紧急避障 &gt; 路牌与岔路决策 &gt; 正常循迹 &gt; 金币收益优化。
全程安全避让：三圈全赛道持续检测行人和车辆，结合目标位置、尺度变化与车辆自身速度评估碰撞风险，必要时提前减速、制动或在可行空间内平滑绕行。
第二圈路牌与岔路决策：识别路牌中的文字、箭头和图标，通过语义理解得到导航含义，并在接近路口前判断是否需要进入岔路；若需要进入，则进一步确定正确分支方向并锁定决策。
第三圈路牌与岔路决策：继续处理随机变化的路牌信息，根据识别结果判断是否进入岔路口以及对应的分支方向，并与全程行人/车辆避让同时运行，避免临近路口因重复识别造成指令抖动。
全域金币任务：仅在不破坏行人/车辆安全避让、岔路导航和有效圈路径的前提下评估绕行收益。

5.7 实时调度与故障降级
上位机采用异步数据流避免模型推理阻塞视频采集：AR画面由共享内存shm_ar_video读取，双缓冲帧队列通过frame_counter和条件变量通知NPU线程；目标检测结果通过互斥锁保护的DisplayBuffer异步返回。程序支持有显示/无显示两种模式，并计算画面刷新FPS。串口默认设备为/dev/ttyACM1，也可由命令行覆盖；当检测短时失效时，循线偏差逐步回中而不是保持旧的大转向量。TC264端设置独立通信超时与停车保护，避免上位机异常传播到功率执行层。
当通信在规定时间内未更新、摄像头图像无效、模型置信度持续过低或编码器反馈异常时，系统进入降级策略：首先降低速度并保持最近可信车道方向；若异常持续，则逐步制动停车。该机制使高层AI模块即使出现瞬时延迟，也不会直接造成底层电机输出失控。

6.1 机械装配与配重
整车制作首先完成碳纤维底盘开孔和各层支柱定位，再依次安装转向机构、双电机、驱动板、电池、TC264主板、散热风扇、香橙派、摄像头、圆柱形雷达和赛事定位模块。装配过程中重点保证前轮转向无明显机械卡滞、左右拉杆长度一致、舵机中位对应前轮直行，并通过移动电池和板卡位置使整车左右配重尽量对称。
6.2 电气联调
电气调试遵循“先低压逻辑、后功率驱动；先单模块、后整车联动”的顺序。首先独立验证TC264供电、串口、编码器和舵机；其次在车轮架空条件下测试左右DRV8701驱动通道、电机方向和编码器符号；最后接入香橙派和摄像头进行整车联调。任何发现的电机方向与编码器符号不一致问题，优先通过统一软件方向定义解决，避免后续PID出现正反馈。
6.3 控制参数整定
控制参数整定主要分为速度环和转向环两个阶段。速度环首先关闭转向影响，在直线架空和低速落地条件下分别调节左右轮Kp、Ki、Kd，使阶跃响应不过度振荡且稳态误差较小；随后在直线赛道上标定舵机中位和中线误差比例，再进入弯道，通过降低基准速度、增加前视信息和限制舵机变化率观察车身轨迹。系统尚未加入差速转弯，因此不进行电子差速增益整定。
6.4 视觉与任务联调
视觉调试首先固定摄像头安装姿态，并验证AR共享内存视频流、目标检测线程和循线主线程之间的时间同步。基础循迹阶段重点检查arrow检测置信度、最近箭头剔除、车头锚点位置及RANSAC主路筛选效果；随后通过直道、连续弯道和岔路场景逐步整定相关循迹参数。任务联调阶段重点在三圈全赛道验证行人和车辆检测/避让的连续性，并在第二圈、第三圈反复测试随机路牌识别、语义解析以及“是否进入岔路口”的决策稳定性。目标检测结果在实际叠加场景中检查漏检、误检和延迟，并验证150 ms结果TTL是否能够及时清除陈旧检测。
6.5 典型问题及改进
整车联调中重点关注左右电机输出不一致、编码器方向定义错误、转向机构机械虚位、箭头漏检/岔路误入、单帧偏差突变、串口偶发丢帧以及上位机推理延迟波动。机械与底层控制问题分别采用独立轮速闭环、统一方向符号和转向拉杆消隙处理；视觉循线则通过最低置信度筛选、跳过最近箭头、带锚点RANSAC排除支路、单帧±0.15限幅和EMA平滑降低误转向；检测结果设置TTL并采用异步NPU线程，通信侧配合帧校验、超时及TC264安全降级，避免陈旧视觉结果或上位机卡顿持续驱动车辆。
此外，竞赛任务具有随机性，单次成功不能代表算法可靠。调试后期应使用完整三圈连续运行作为主要验收方式，记录每圈耗时、任务成功率、速度波动和异常日志，并以“连续完成率”而非单圈最快速度作为优先优化指标。

本模型车围绕全国大学生智能汽车竞赛的智能驾驶任务完成了从机械结构、电子硬件到视觉感知和运动控制的软件架构设计。机械方面以C型车模为基础，采用碳纤维底盘、低重心配重和三层模块化结构；驱动方面采用双RS380电机独立后轮驱动与阿克曼前轮转向，通过DRV8701双路驱动和左右轮独立速度闭环提高驱动一致性。双驱控制尚未加入转弯电子差速，弯道主要依靠舵机转向与统一基准轮速完成；控制系统采用香橙派与TC264分层架构，使复杂视觉/AI推理与高实时性电机控制相互解耦。
在已完成并随报告提供的基础循迹算法中，上位机从目标检测结果提取arrow中心点，采用车头锚点约束的RANSAC筛选主路点集，并通过一次/二次多项式拟合、Hann加权横向偏差、前视航向补偿及EMA平滑生成转向偏差；检测模型在香橙派NPU侧以RKNN形式异步部署。底层由TC264执行电机、舵机及安全控制，形成上位机感知与下位机实时执行的闭环。
后续优化将重点围绕三方面展开：第一，在保证稳定循迹的基础上进一步优化双驱控制，并根据实车弯道表现评估是否加入电子差速转弯；第二，对行人、车辆与路牌识别结果建立置信度融合和时间连续性判断，降低单帧误识别，并重点提升第二、第三圈岔路决策的稳定性；第三，将强化学习或策略优化限定在安全约束之上，用于路线和金币收益决策，而全程行人/车辆避让与底层急停保护保持确定性控制。通过上述改进，可进一步提升模型车在复杂虚实融合赛道中的连续完赛能力和综合成绩。

以下节选包括转向偏差发送增益、主循环中的循迹结果更新、单帧变化限幅、EMA平滑以及串口下发流程。
static float make_control_offset(float smooth_offset) {
    // 小死区：直道附近的微小抖动不驱动舵机。
    static const float OFFSET_SEND_DEADZONE = 0.03f;
    // 大弯增益：视觉平均偏差偏小，发送前放大，让舵机更敢打。
    static const float OFFSET_SEND_GAIN = 1.80f;
 
    if (std::abs(smooth_offset) &lt; OFFSET_SEND_DEADZONE) {
        return 0.0f;
    }
 
    float control = smooth_offset * OFFSET_SEND_GAIN;
    return std::max(-1.0f, std::min(1.0f, control));
}
    static const float OFFSET_SMOOTH_ALPHA  = 0.25f;
    // 单帧 offset 最大允许变化量，超过则截断（限制突变速率）
    static const float OFFSET_MAX_DELTA     = 0.15f;
    static float g_smooth_offset = 0.0f;
    static bool  g_smooth_init   = false;
 
    // ==========================================================
    // 主循环：最新 SHM 帧做底图，检测/分割结果只做异步叠加
    // ==========================================================
    printf(&quot;[Main] Entering main loop. Waiting for SHM frames...\n&quot;);
 
    while (g_main_running.load() &amp;&amp; !stop_flag.load()) {
        cv::Mat frame;
        if (!stream.read(frame)) {
            std::this_thread::sleep_for(std::chrono::milliseconds(1));
            continue;
        }
 
        if (debug_frame_count % 100 == 0) {
            printf(&quot;[Main] Heartbeat: SHM Read OK, Frame ID: %lu\n&quot;, stream.last_fid);
        }
 
        // 写入共享帧缓冲区：模型线程通过 frame_counter 判断新帧，避免 read_idx 0/1 绕回导致漏帧。
        uint64_t frame_ts_us = now_us();
        {
            std::lock_guard&lt;std::mutex&gt; lk(frame_buf.cv_mutex);
            frame.copyTo(frame_buf.frames[write_idx]);
            frame_buf.read_idx.store(write_idx);
            frame_buf.frame_timestamp_us.store(frame_ts_us);
            frame_buf.frame_counter.fetch_add(1);
            frame_buf.has_new_frame.store(true);
        }
        frame_buf.cv_new_frame.notify_all();
 
        if (debug_frame_count % 100 == 0) {
            printf(&quot;[Main] Signal Sent: notify_all() called\n&quot;);
        }
 
        write_idx = 1 - write_idx;
        debug_frame_count++;

        if (disp_buf.yolo_updated.exchange(false)) {

            last_yolo_ts_us = disp_buf.yolo_res.timestamp_us;
 
            // 每50帧打印一次检测到的目标标签，用于确认 arrow 是否被检测到
            static int det_print_cnt = 0;
            if (++det_print_cnt % 50 == 0) {
                printf(&quot;[Det] objects=%d: &quot;, (int)last_yolo_objects.size());
                for (const auto&amp; o : last_yolo_objects)
                    printf(&quot;%s(%.2f) &quot;, o.label.c_str(), o.prob);
                printf(&quot;\n&quot;);
            }
 
            // 用最新 arrow 框计算道路中线和偏差
            last_lane_result = compute_lane_follow(last_yolo_objects, frame.cols, frame.rows);
            if (det_print_cnt % 50 == 0) {
                printf(&quot;[Lane] valid=%d arrows=%d mean=%.3f head=%.3f offset=%.3f send=%.3f\n&quot;,
                       last_lane_result.valid,
                       last_lane_result.num_arrows,
                       last_lane_result.lateral_mean_offset,
                       last_lane_result.heading_offset,
                       last_lane_result.lateral_offset,
                       make_control_offset(last_lane_result.lateral_offset));
            }
 
            if (last_lane_result.valid) {
                float raw = last_lane_result.lateral_offset;
 
                // 速率限制：单帧变化超过阈值则截断，防止岔路口突变
                if (g_smooth_init) {
                    float delta = raw - g_smooth_offset;
                    if (delta &gt;  OFFSET_MAX_DELTA) raw = g_smooth_offset + OFFSET_MAX_DELTA;
                    if (delta &lt; -OFFSET_MAX_DELTA) raw = g_smooth_offset - OFFSET_MAX_DELTA;
                }
 
                // EMA 低通滤波
                g_smooth_offset = g_smooth_init
                    ? OFFSET_SMOOTH_ALPHA * raw + (1.0f - OFFSET_SMOOTH_ALPHA) * g_smooth_offset
                    : raw;
                g_smooth_init = true;
 
                float control_offset = make_control_offset(g_smooth_offset);
 
                // 可视化保留平滑值；串口发送使用放大后的控制值。
                last_lane_result.lateral_offset = g_smooth_offset;
                float clamped = std::max(-1.0f, std::min(1.0f, control_offset));
                last_lane_result.servo_pwm = SERVO_CENTER_PWM + (int)(clamped * SERVO_STEER_GAIN);
                last_lane_result.servo_pwm = std::max(SERVO_MIN_PWM,
                                             std::min(SERVO_MAX_PWM, last_lane_result.servo_pwm));
 
                g_shared_lane_offset.store(control_offset);
                g_offset_valid.store(true);
 
                // 串口发送给下位机
                if (uart_ok)
                    lane_uart.sendOffset(control_offset);
            } else if (g_smooth_init) {
                // 无检测时缓慢向中心衰减，不立即归零
                g_smooth_offset *= 0.92f;
                if (std::abs(g_smooth_offset) &lt; 0.01f) {
                    g_smooth_offset = 0.0f;
                }
 
                float control_offset = make_control_offset(g_smooth_offset);
                last_lane_result.lateral_offset = g_smooth_offset;
                float clamped = std::max(-1.0f, std::min(1.0f, control_offset));
                last_lane_result.servo_pwm = SERVO_CENTER_PWM + (int)(clamped * SERVO_STEER_GAIN);
                last_lane_result.servo_pwm = std::max(SERVO_MIN_PWM,
                                             std::min(SERVO_MAX_PWM, last_lane_result.servo_pwm));
 
                g_shared_lane_offset.store(control_offset);
                g_offset_valid.store(false);

                if (uart_ok)

B.2 lane_follow.cc 道路中线计算主干（节选）
以下节选为道路中线计算主函数，包含arrow中心点提取、车头锚点约束、RANSAC筛选、多项式拟合、Hann加权以及前视航向融合等稳定循迹主干。
LaneFollowResult compute_lane_follow(
    const std::vector&lt;YoloObject&gt;&amp; objects,
    int frame_w, int frame_h)
{
    LaneFollowResult result;
 
    // Step 1：提取全部 arrow 中心点
    std::vector&lt;cv::Point2f&gt; centers;
    centers.reserve(objects.size());
 
    for (const auto&amp; obj : objects) {
        if (label_lower(obj.label) != ARROW_LABEL) continue;
        if (obj.prob &lt; ARROW_MIN_CONF) continue;
        float cx = obj.rect.x + obj.rect.width  * 0.5f;
        float cy = obj.rect.y + obj.rect.height * 0.5f;
        centers.push_back(cv::Point2f(cx, cy));
    }
 
    result.num_arrows = (int)centers.size();
    if (centers.empty()) return result;
 
    // Step 2：跳过最下面那个（y 最大 = 车正压着的位置，无方向参考价值）
    auto max_it = std::max_element(centers.begin(), centers.end(),
                                   [](const cv::Point2f&amp; a, const cv::Point2f&amp; b){
                                       return a.y &lt; b.y;
                                   });
    result.skipped_pt  = *max_it;
    result.has_skipped = true;
    centers.erase(max_it);
 
    // 有效区上下边界
    float y_wb_f = frame_h * (1.0f - ROW_EXCLUDE_BOTTOM);
    int   y_wb_i = (int)y_wb_f;
 
    // Step 3：锚点固定在车头附近。
    // 它既用于 RANSAC 过滤岔路，也参与多项式拟合，防止中线近端起点漂移。
    cv::Point2f anchor(frame_w * LANE_ANCHOR_X_RATIO,
                       frame_h * LANE_ANCHOR_Y_RATIO);
    result.anchor_pt = anchor;
 
    // Step 4：带锚点约束的 RANSAC（过滤岔路箭头）
    float threshold = frame_w * RANSAC_INLIER_RATIO;
    std::vector&lt;cv::Point2f&gt; inliers = ransac_with_anchor(anchor, centers, threshold);
 
    for (const auto&amp; c : centers) {
        bool found = false;
        for (const auto&amp; p : inliers) {
            if (std::abs(c.x - p.x) &lt; 0.5f &amp;&amp; std::abs(c.y - p.y) &lt; 0.5f) {
                found = true; break;
            }
        }
        if (!found) result.excluded_pts.push_back(c);
    }
 
    // Step 5：分离箭头点和锚点
    std::sort(inliers.begin(), inliers.end(),
              [](const cv::Point2f&amp; a, const cv::Point2f&amp; b){ return a.y &lt; b.y; });
    result.fit_pts = inliers;
 
    std::vector&lt;cv::Point2f&gt; arrow_pts;
    for (const auto&amp; p : inliers) {
        bool is_anchor = (std::abs(p.x - anchor.x) &lt; 1.0f &amp;&amp;
                          std::abs(p.y - anchor.y) &lt; 1.0f);
        if (!is_anchor) arrow_pts.push_back(p);
    }
    if (arrow_pts.empty()) return result;
 
    // Step 6：多项式拟合 —— 箭头点 + 固定锚点
    std::vector&lt;cv::Point2f&gt; fit_set = arrow_pts;
    for (int k = 0; k &lt; LANE_ANCHOR_FIT_WEIGHT; ++k) {
        fit_set.push_back(anchor);
    }
    std::sort(fit_set.begin(), fit_set.end(),
              [](const cv::Point2f&amp; a, const cv::Point2f&amp; b){ return a.y &lt; b.y; });
 
    int n_arrow_fit = (int)arrow_pts.size();
    if (n_arrow_fit == 1) {
        // 只有一个箭头时，用“箭头 + 固定车头点”拟合直线，比常数 x 更适合弯道。
        result.poly_degree = 1;
        result.poly_coeff = poly_fit(fit_set, 1);
        if (result.poly_coeff.empty()) return result;
    } else {
        int degree = (n_arrow_fit &gt;= 3) ? 2 : 1;
        result.poly_coeff = poly_fit(fit_set, degree);
        if (result.poly_coeff.empty() &amp;&amp; degree == 2) {
            degree = 1;
            result.poly_coeff = poly_fit(fit_set, degree);
        }
        if (result.poly_coeff.empty()) return result;
        result.poly_degree = degree;
    }
 
    // Step 7：从最远箭头（或画面中部）到有效区底边按行采样中线
    //   不再延伸到画面最底部，避免锚点以下的无约束外推
    int y_start = std::max(frame_h / 2, (int)fit_set.front().y);
    result.centerline_pts.reserve((y_wb_i - y_start) / LANE_ROW_STEP + 2);
 
    for (int y = y_start; y &lt;= y_wb_i; y += LANE_ROW_STEP) {
        double x = (result.poly_degree == 0)
                   ? result.poly_coeff[0]
                   : poly_eval(result.poly_coeff, (double)y);
        if (x &lt; 0 || x &gt;= frame_w) continue;
        result.centerline_pts.push_back(cv::Point2f((float)x, (float)y));
    }
 
    // 强制中线近端固定在车头锚点，画面上最后一段不会再左右漂。
    if (!result.centerline_pts.empty()) {
        result.centerline_pts.back() = anchor;
    }
 
    if (result.centerline_pts.size() &lt; 2) return result;
 
    // Step 8：Hann 窗加权求中线平均 x
    //   有效区：[y_weight_top, y_weight_bottom]，两端排除
    //   权重：w(y) = 0.5*(1+cos(π*t))，t∈[-1,1]，中间最大两端为 0
    static const double PI = 3.14159265358979323846;
    float y_wt = frame_h * ROW_EXCLUDE_TOP;
    float y_wb = frame_h * (1.0f - ROW_EXCLUDE_BOTTOM);
    float y_mid      = (y_wt + y_wb) * 0.5f;
    float half_range = (y_wb - y_wt) * 0.5f;
 
    result.y_weight_top    = y_wt;
    result.y_weight_bottom = y_wb;
 
    double sum_wx = 0.0, sum_w = 0.0;
    for (const auto&amp; pt : result.centerline_pts) {
        float y = pt.y;
        if (y &lt; y_wt || y &gt; y_wb) continue;
 
        double t = (double)(y - y_mid) / half_range;          // t ∈ [-1, 1]
        double t_biased = t + (double)WEIGHT_PEAK_BIAS;        // 峰往上移（上部权值略高）
        if (t_biased &lt; -1.0 || t_biased &gt; 1.0) continue;      // 偏移后超出有效区则跳过
 
        double w = 0.5 * (1.0 + std::cos(PI * t_biased));     // 偏移 Hann 窗
 
        sum_wx += w * pt.x;
        sum_w  += w;
    }
    if (sum_w &lt; 1e-9) return result;
 
    result.weighted_cx    = (float)(sum_wx / sum_w);
    float center_x        = frame_w * 0.5f;
    result.lateral_mean_offset = (result.weighted_cx - center_x) / center_x;
 
    // Step 8.5：大弯前视方向补偿
    // 平均横向偏差只表示“中线整体偏左/右”，在大弯上经常偏小；
    // 前视方向表示“从车头看过去，中线往哪边拐”，用于提前加舵。
    float lookahead_y = frame_h * LANE_HEADING_LOOKAHEAD_Y_RATIO;
    lookahead_y = std::max((float)y_start, std::min(lookahead_y, y_wb_f));
 
    double lookahead_x = (result.poly_degree == 0)
                         ? result.poly_coeff[0]
                         : poly_eval(result.poly_coeff, (double)lookahead_y);
    if (lookahead_x &lt; 0.0) lookahead_x = 0.0;
    if (lookahead_x &gt; frame_w - 1.0) lookahead_x = frame_w - 1.0;
 
    result.heading_offset = (float)((lookahead_x - anchor.x) / center_x);
 
    float combined_offset =
        result.lateral_mean_offset * LANE_LATERAL_WEIGHT +
        result.heading_offset      * LANE_HEADING_WEIGHT;
 
    result.lateral_offset = std::max(-1.0f, std::min(1.0f, combined_offset));
 
 
    // Step 9：舵机 PWM
    float clamped = std::max(-1.0f, std::min(1.0f, result.lateral_offset));
    result.servo_pwm = SERVO_CENTER_PWM + (int)(clamped * SERVO_STEER_GAIN);
    result.servo_pwm = std::max(SERVO_MIN_PWM, std::min(SERVO_MAX_PWM, result.servo_pwm));
 
    result.valid = true;
    return result;
}
