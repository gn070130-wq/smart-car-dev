一、智能车大赛背景
全国大学生智能汽车竞赛是一项面向全国高校大学生的科技创新与工程实践竞赛，旨在通过智能汽车系统的设计、制作、调试与竞速比拼，培养学生在嵌入式系统、自动控制、传感器技术、机器视觉、人工智能和机械电子等领域的综合能力。随着智能驾驶、自动驾驶和智能交通技术的快速发展，智能汽车已成为人工智能与实体经济深度融合的重要载体。该竞赛以实际工程问题为导向，要求参赛队伍完成方案设计、硬件搭建、软件编程、算法优化和现场测试，是提升学生创新意识、实践能力、团队协作能力和解决复杂工程问题能力的重要平台。
二、智能模型组比赛规则
智能模型组将数字技术与自动控制有机结合，智能车需要使用增强现实的摄像头，在虚拟的赛道中完成任务。总共有三圈任务，每一圈都是对现实生活中常见现象的模拟。第一圈需要智能车躲避停靠在路旁的车辆以及虚拟行人，第二圈需要识别路牌并能按要求循迹，第三圈在识别路牌的基础上尽可能的收集金币。
三、本文结构
本文将从硬件电路、机械结构、软件代码三个维度，介绍小车的技术细节，带领读者体验我们队智能模型车的完整设计过程。



第二章 车模整体设计思路
我们的智能模型小车主打稳定以及智能识别，对主控板、驱动板以及结构进行了多次调整，利用后轮电机控制小车运动，前轮舵机控制转向，板卡以及摄像头负责获取信息并处理，在数字化的赛道中完成任务。
电路设计使用嘉立创EDA，电路板由嘉立创工厂生产和贴片，机械结构零件由拓竹的3D打印机打印，材料为PETG。通过改良车身结构，调整小车重心使其在运动途中更为平缓稳定，设计不同的打印件来满足多样需求。
控制算法将与板卡结合，通过收集板卡传到下位机的数据来进行相应的判断与控制操作，采用PID对小车在赛道上的偏移进行纠正。








第三章 硬件设计
根据百度智能模型组公布的比赛规则，车模自制这一规则让我们的车模设计方面自由度很高，但同时考验我们对车模以及赛规的理解与适配程度。一个车模的设计，很大程度上影响了车辆运行的姿态以及稳定性。本届智能模型比赛内容考验车辆的精确控制以及最佳路径规划，需要车辆在快速反应的同时保证结构的稳定，因此对结构设计有着很高的要求。本章将介绍根据实际情况对车模机械做出的改进内容和相应电路结构介绍。
3.1 车模选择
由于车模自制，我们对车模有更灵活的选择。我们考虑过采用以往模型组的I车模，但鉴于I车模单电机、靠差速器转向、可用区域面积小，我们最终采用传统的C车模作为比赛模型。C车模作为智能车竞赛的老牌车模，有着空间大、电机方便更换、易组装等优势，C车模尺寸大小280mm*180mm*80mm，符合赛规要求。转向采用阿克曼结构，既符合赛规要求，又能满足车辆对于转向的需要。
车辆组装完成后，尺寸数据为288mm*183mm*155mm，符合赛规要求。
3.2 电机选择
因为智能模型是从虚拟赛道中收集信息，需要考虑帧率与速度之间的协调，速度太快会导致上位机与下位机通信断层，最终影响车辆行驶；速度太慢会导致效率降低。有刷电机的速度能够满足我们的需要并且有一定裕量，故障率相对较低，综合考虑，我们放弃了更高速的无刷，采用更加稳定的有刷电机。
在有刷电机当中，RC380相比于RS380，在相同的占空比下，有着更快的速度优势，它的上限也更高。但是在我们组装过程中发现，两个RC380电机的转轴会靠在一起，这导致在车辆运行过程中，两个电机之间会有不可忽视的摩擦，可能会伤害电机，影响工作性能，干扰车辆行驶。所以我们采用转轴稍微短一点的RS380。RS380电机是C车模的原装电机，适配好，固定强度高，与RC380电机相差不大。
3.3 编码器选择
在编码器的选择上，我们采用的是逐飞科技带方向编码器，采用脉冲+独立方向电平（PUL+DIR）输出模式，典型规格1024线，主要用于智能车电机转速与转角反馈。判向逻辑简单、开发调试便捷，配合主控实现速度PID闭环控制。
3.4 主控板设计
3.4.1 第一版
我们所使用的最小系统板是TC377，所以主控板的设计是围绕TC377展开的。考虑到板卡对供电电压和电流的要求，我们选择SCT2450STER作为输出5V的稳压芯片。SCT2450STER芯片的输出电压电流为5V4A，满足板卡需求。因为板卡需要Type-C供电，所以在电压输出位置增加了一个Type-A母口为其提供工作电压，图3.1为SCT2450STER原理图。
输出3.3V采用的是AMS1117-3.3稳压芯片，体积小、用料少、焊接简单，是非常常见的LDO型稳压芯片，图3.2为AMS1117-3.3原理图。
输出6V采用的是LM2596S-ADJ稳压芯片，该芯片属于DCDC，散热效果好、设计方便，占用面积虽然比SCT2450STER大一些，但是由于主控板空间充足，因此可以使用。图3.3为LM2596S-ADJ原理图。
此外，我们增加了一些常用接口以及交互设计，如按键、拨码开关、编码器接口等。图3.4为第一版实物图。

3.4.2 第二版
第二版是在第一版的基础上，更换了12V降6V的DCDC稳压芯片TPS5430QDDARQ1，该芯片体积更小、占用面积更小，可以有效地缩小主控板面积。图3.5为TPS5430QDDARQ1原理图。
此外，由于板卡每次断电重启需要耗费一些开机时间，所以，为了方便电源的控制，第二版增加了一个专门控制TC377的供电开关，这个开关不会影响板卡的供电，但是可以使TC377停止工作。但是由于实际过程中存在明显的漏电现象，导致这个开关形同虚设，最终没能起到作用。
添加了主控板的正确标识以及二维码，更改了电源开关的位置。图3.6为主控板第二版。
3.5 驱动板设计
驱动板负责控制MOS管的开启与关断，将输入的PWM转变成输出电压，进而控制电机转动。
3.5.1 第一版
驱动板包括隔离部分，我采用的是SN74HC125PWR，该芯片体积小、外部电路少并且支持多输入，图3.7为该芯片的原理图。




驱动芯片选取的是DRV8701ERGER，DRV8701ERGER是TI推出的单H桥外置MOS栅极预驱芯片，支持5.9V～45V电源输入，适配12V、24V有刷直流电机，采用PH/EN控制接口，可直接兼容1.8V/3.3V/5V主控电平；芯片具备5档可调栅极驱动强度、内置20倍增益电流采样运放与硬件限流，集成4.8V、3.3V两路30mA辅助LDO，支持低功耗休眠模式。
MOS管选取的是TPH1R403NL，TPH1R403NL是东芝的N沟道增强型功率MOS管，耐压30V，连续电流60A，10V栅压下最大导通电阻仅1.4mΩ，栅电荷小、开关速度快，适合配合DRV8701这类栅极预驱芯片搭建H桥。图3.8为驱动部分主要原理图。
在测试过程当中，我们发现其中一个DRV8701的NSLEEP端没有唤醒，导致该芯片处于休眠状态。我们采用飞线的解决方式，将正常工作的DRV8701的NSLEEP端与不正常的一端连接起来，最终实现了芯片的唤醒，工作状态正常。之后驱动板迭代时由于物料短缺，我将该驱动板上的MOS管拆除，所以实物图上该区域没有器件。图3.9为驱动板第一版实物图。
3.5.2 第二版
汲取第一版出现的问题，第二版及之后的版本当中，添加了为NSLEEP提供开启电压的钳位电路部分，二极管选择BZT52C3V3，理论输出为3.3V，足够使DRV8701正常工作，图3.10为钳位电路原理图。


除此之外，第二版修改了部分元器件的排版，将第一版的XT30接口替换成开窗，方便外部直接接线，适配更多情况。图3.11为第二版实物图。

3.5.3 第三版
第三版相较于前两版，没有器件上的改动，修改了器件的布局，添加了正确的标识以及二维码。图3.12为第三版实物图。
3.5.4 第四版
在第三版使用过程当中，我们更换过电机，但是由于缺少更换电机的注意事项，导致更换后两电机引脚接触，通电后将驱动板电源输入部分烧毁，MOS管击穿，修理过后，虽然能够正确输出电压，但稳定性明显降低，因此重新设计布局并制作第四版。
在使用过程中，第一版的稳定性是最高的，全程无损无异常。因此，第四版仿照第三版的布局，并且添加钳位电路，尽可能的缩小驱动板所占面积，最终完成第四版的制作与测试。图3.13为第四版3D图。




3.5.5 第五版
第四版驱动板输出电压正确无误，但是在实际使用过程当中会逐渐拖慢电机速度，并且拖慢程度并不相同，从编码器获取到的数据来看，差速已经严重影响了车辆的正常行驶。在难以从器件层面解决问题的情况下，我们认为是驱动板结构存在问题，解决办法是重新绘制并制作第五版。
第五版相对于其他版本，在结构上有了更大的变化。将隔离芯片放在驱动板中心位置，左右驱动分开，降低干扰。同时，选用四层板，使GND平面更完整、回流效率增大、信号干扰更低。
更换为第五版之后，差速影响几乎可以忽略不计，稳定性有很大提升，图3.14为驱动板第五版。
3.6 电池
我们选用的是格氏ACE G-Tech系列3S1P锂聚合物动力电池，标称电压11.1V、容量2200mAh，持续放电倍率30C，具备大电流输出能力，满电电压12.6V，自带平衡充接口。图3.15为电池图片。

3.8 板卡供电模块
我们之前给板卡供电的方案是选择用主控板上的5V稳压芯片，但是出现过板卡断电重启的情况。由于主控板上的5V供电都由这个芯片产出，所以我们怀疑是由于供电部分过多导致不稳定，因此我绘制并制作了独立的板卡供电模块。该模块是以12V降5V的DCDC稳压芯片TPS54560BDDAR为核心，采用电流模式控制，输入电压4.5V‑60V，最大输出电流5A，输出电压可调。开关频率支持100kHz至2.5MHz配置，具备Eco‑mode轻载高效模式，集成软启动、过流、欠压、过热保护，依靠外围电感、电容搭建降压电源，可为板卡提供稳定供电。图3.16和3.17为原理图和实物图。











第四章 软件设计
代码设计是智能车竞赛中不可或缺的一环。我们设计的智能车系统采用 板卡自带的增强现实摄像头进行虚拟赛道识别，识别之后需要处理并将数据输送到下位机，下位机进行运动控制，完成一系列任务。
在板卡收集信息这一过程需要视觉处理信息，并将需要的坐标发送给下位机。下位机与板卡同步并将坐标数据进行整理规划，控制占空比使车辆能够以更高效、更准确的姿态完成动作。
4.1 图像采集处理
4.1.1 原始图像
本组别原始图像属于虚实融合AR叠加图像，由物理场地实景+实时渲染的虚拟交通元素复合而成，并非纯实景或纯仿真图。图像底层是室内真实平面赛道底色，上层动态叠加虚拟行人、文字路牌、金币等3D渲染物体，虚拟元素的位置、姿态随车模位姿实时同步更新，存在透视形变、远近尺度变化。图像同时包含实景纹理噪声、光照波动、边缘混叠、虚实物体边界融合等干扰；目标尺度动态变化，路牌文字存在角度倾斜、透视畸变，易出现局部模糊；画面帧率、曝光受车载摄像头硬件与场地环境影响，存在运动模糊、高光、阴影干扰。图像数据直接送入RK3588S边缘端，用于目标检测与OCR识别，对模型抗干扰、多尺度检测、倾斜文字识别能力有明确要求。
4.1.2 图像处理
我们采用轻量化YOLOv8n模型完成虚拟行人、路牌、金币的多类别目标检测。首先采集虚实融合AR图像构建数据集并标注目标，通过数据增强提升模型抗光照与虚实边界噪声的能力；在深度学习框架完成训练后导出ONNX模型，借助RKNN Toolkit进行INT8量化，部署于RK3588S的NPU加速推理。推理输出结果经置信度过滤与NMS非极大值抑制消除重复框，再将检测框像素坐标转换为车辆局部坐标系下的距离与角度；路牌区域裁剪后送入OCR识别文字，最终将结构化目标信息下发决策层，为避让行人、语义导航、收集金币任务提供感知输入。
4.1.3 信息传递
上位机RK3588S与下位机之间采用USB转TTL进行通信，采用自定义二进制帧协议传输结构化数据，不传输原始图像。通信帧由帧头、数据长度、功能码、有效载荷、CRC16校验和帧尾构成，依靠帧头完成帧同步，通过CRC校验识别干扰造成的错误数据包并丢弃，上位机向下发送期望运动参数与任务标志。软件采用多线程解耦，分离AI推理任务与实时控制指令下发，下位机配置指令看门狗，长时间未收到有效指令时自动进入安全降级模式，保障虚实融合赛道自动驾驶的实时性与抗干扰能力。
4.2 PID控制算法
PID即比例-积分-微分（Proportional-Integral-Derivative）控制算法，是一种闭环反馈控制算法，通过误差信号的比例、积分、微分三项加权求和得到控制输出，无需建立精确被控对象数学模型，结构简单、鲁棒性强，广泛用于电机调速、转向控制等场景。
比例项P是基于当前误差直接输出控制量，快速缩小偏差。P值越大响应越快，但过大容易引发振荡、超调。积分项I是对误差进行累积，消除稳态静差。积分作用过强会增加超调，常配合积分限幅、防积分饱和策略。微分项D是对误差变化率进行抑制，预判误差趋势、阻尼振荡，抑制转速抖动、抑制冲击。
离散数字PID常用增量式或位置式实现。位置式直接输出最终控制量，适合电机PWM输出；增量式输出控制量变化值，抗积分饱和、启停冲击更小。

4.3 PID参数整定
PID参数整定通过调试比例、积分、微分系数，使闭环系统获得良好动态与稳态性能。我们常采用试凑法，先单独调节比例系数使系统产生临界振荡，再引入积分项消除稳态误差，最后加入微分项抑制振荡；整定完成后配合积分限幅、输出限幅等保护逻辑，在保证响应速度的同时避免超调、抖动与控制饱和。

在控制策略上，我们采用PID控制算法来实现车模的速度和转向精准控制。PID控制算法作为一种经典且广泛应用的反馈控制算法，具有结构简单、参数易于调整、稳定性好等显著优势。在速度控制环节，通过安装在电机上的编码器实时采集车模的实际速度信息，并将其反馈给控制系统。控制系统将实际速度与预设的目标速度进行对比，计算出速度偏差值。然后，根据PID算法的比例、积分和微分系数对偏差值进行处理，生成相应的控制信号，调整电机的驱动功率，从而实现车模速度的精确调节，确保车模能够按照预定的速度稳定行驶。
在结构设计过程中，我们坚持合理简洁的原则，对车模的各个部件进行了精心布局和优化设计。首先，我们将车模的重心尽可能地降低并调整到合适的位置，减少车模在高速行驶和转弯时的侧倾和晃动，提高行驶的平稳性和安全性。其次，我们制作的3D打印件能够有效地固定一些区域，更好地优化了整体结构，增强稳定性、降低干扰。
此外，所有电路板均由团队成员自主设计并焊接，这体现了我们的技术实力和创新能力。在供电电路方面，采用了高效的电源管理芯片和合理的电路布局，确保为车模的各个部件提供稳定、可靠的电源供应，同时降低了电源损耗，提高了能源利用效率。控制电路则是智能车的“大脑”，它接收采集电路传来的数据，并根据预设的控制算法生成相应的控制信号，驱动电机和舵机等执行部件工作。通过自主设计与焊接电路板，我们实现了供电、通信、控制等各项任务的有机整合，提高了车模的整体性能和可靠性。
尽管我们在车模的设计和制作过程中付出了诸多努力，但车模的结构仍存在较大的优化空间。例如，在车模的机械传动部分，目前采用的传动方式在传动效率和精度方面还有待提高。传动过程中的摩擦和间隙可能会导致动力损失和运动不准确，影响车模的加速性能和转向精度。而且，车模的车身材料选择和加工工艺也可以进一步优化。当前使用的车身材料在强度和重量之间未能达到最佳平衡，一定程度上限制了车模的性能提升。而且，3D打印件的精度不够高，导致车身部件之间的装配存在一定误差，影响了车模的整体美观度和稳定性。针对这些问题，我们将在后续的研究和改进中，探索更先进的传动技术和材料，不断提升车模的结构性能。

## 4. 电机方向与 PWM 输出

文件：`code/contral.h`、`code/contral.c`，函数：`motor_init()`、`PWM_motor()`。

当前方向电平：左电机正转 `1`、右电机正转 `0`。`PWM_motor()` 使用带符号的 PWM 参数：正数表示正转，负数表示反转；占空比取绝对值并限制在最大值内。

```c
void PWM_motor(float motor_1, float motor_2)
{
    uint32 duty_l = motor_limit_duty(motor_1);
    uint32 duty_r = motor_limit_duty(motor_2);

    gpio_set_level(DIR_L,
        motor_1 >= 0 ? MOTOR_L_FORWARD_LEVEL : MOTOR_L_BACKWARD_LEVEL);
    pwm_set_duty(PWM_L, duty_l);

    gpio_set_level(DIR_R,
        motor_2 >= 0 ? MOTOR_R_FORWARD_LEVEL : MOTOR_R_BACKWARD_LEVEL);
    pwm_set_duty(PWM_R, duty_r);
}
```

## 5. 循迹误差与舵机 PD

文件：`code/detect.c`、`code/PID.c`，函数：`Err_Get()`、`Servo_PD()`。

调用关系：UART 完整帧更新 `Target_Y` → `Err_Get()` 计算 `err` → `Servo_PD()` 输出舵机角度 → `pwm_set_duty(pwm_servo, ...)`。

```c
float Err_Get(void)
{
    err = 75 * (320 - (float)Target_Y) / 320 + 1;
    return err;
}

float Servo_PD(PID *pid, float err)
{
    pid->pid_err = err;
    pid->pid_out = mid_value
        + pid->pid_Kp * pid->pid_err
        + pid->pid_Kd * (pid->pid_err - pid->pid_err_last);
    pid->pid_err_last = pid->pid_err;
    if(pid->pid_out < pid->pid_end_min) pid->pid_out = pid->pid_end_min;
    if(pid->pid_out > pid->pid_end_max) pid->pid_out = pid->pid_end_max;
    return pid->pid_out;
}
```

当前舵机参数在 `CarCascadePID_Init()` 中设置：`Kp=0.910`、`Kd=2.50`，输出范围 `615~765`，舵机中值 `mid_value=690`。

## 6. 电机速度 PID 与左右差速补偿

```c
float PID_pwm_l = PID_Incremental(&car_pid.motor_l,
```

## 7. UART 帧协议和数据解析

文件：`code/uart.h`、`code/uart.c`，函数：`uart_rx_init()`、`uart_callback()`。

协议常量：波特率 `115200`，帧头 `0xAA`，帧尾 `0x55`，完整帧长度 `56` 字节。有效数据为 54 字节，解析为 27 个大端 `uint16_t`。最后三个数据字分别为 `RoadSign_Flag`、`RoadSign_X`、`RoadSign_Y`；根据车辆/小车识别结果动态选择 `Target_Y` 的前瞻索引。

```c
if(uart_byte_number == 0 && dat != FRAME_HEADER)
    return;                         // 帧头错误，重新等待

if(uart_byte_number == UART_RECEIVE_LEN)
{
    if(uart_rx_buf[UART_RECEIVE_LEN - 1] != FRAME_TAIL)
        return;                     // 帧尾错误，丢弃本帧

    memcpy(data, &uart_rx_buf[1], DATA_LEN);
    for(i = 0; i < DATA_WORD_LEN; i++)
        uart_data_word[i] = ((uint16_t)data[i * 2] << 8)
                          | data[i * 2 + 1];

    RoadSign_Flag = uart_data_word[DATA_WORD_LEN - 3];
    RoadSign_X    = uart_data_word[DATA_WORD_LEN - 2];
    RoadSign_Y    = uart_data_word[DATA_WORD_LEN - 1];
    Target_Y      = uart_data_word[forward_looking_walk];
    uart_online_flag = 1;
    uart_lost_count = 0;
}
```

## 8. UART 失联保护和重连

关键变量：`uart_online_flag`、`uart_lost_count`、`uart_lost_right_turn_active`。当前头文件中 `UART_LOST_MAX_COUNT=75`，2 ms 计数约 150 ms 未收到完整合法帧即进入保护。

文件：`user/isr.c` 的 `cc60_pit_ch0_isr()`。

```c
if(uart_lost_count < UART_LOST_MAX_COUNT)
    uart_lost_count++;

if(uart_online_flag && uart_lost_count >= UART_LOST_MAX_COUNT
   && !roadsign_stop_latched && !roadsign_right_turn_active
   && !uart_lost_right_turn_active)
{
    uart_online_flag = 0;
    uart_lost_right_turn_active = 1;
}

if(uart_lost_right_turn_active)
{
    pwm_set_duty(pwm_servo, 615);   // 失联阶段舵机向右寻线

```

收到第一帧合法 UART 数据时，`uart_callback()` 仍可识别 `uart_lost_right_turn_active`，先清除舵机误差历史并回中到 `mid_value=690`，随后清除失联标志、在线计数归零。5 ms 电机中断在失联右转期间输出 `PWM_motor(1100, 1100)`。

## 9. 路牌状态机、停车和转弯

文件：`code/uart.c`，函数：`uart_roadsign_handle()`、`roadsign_right_turn_update()`、`emergency_stop_enter()`。

主要模式：`MOTOR_MODE_NORMAL` 正常、`MOTOR_MODE_STOP` 停车、`MOTOR_MODE_AVOID` 避障/右转、`MOTOR_MODE_FAST` 快速。等待路牌进入停车锁存后，电机保持 STOP、舵机回中；只有现有允许的左转/右转流程能解除锁存。

```c
if(roadsign_stop_latched && RoadSign_Flag == ROADSIGN_RIGHT)
{
    roadsign_right_turn_active = 1;
    roadsign_right_turn_count = 0;
    roadsign_right_turn_output();
    return;
}

if(roadsign_stop_latched && RoadSign_Flag != ROADSIGN_LEFT)
{
    roadsign_motor_mode = MOTOR_MODE_STOP;
    pwm_set_duty(pwm_servo, mid_value);
    return;
}
```

右转由 `ROADSIGN_RIGHT_TURN_TICKS` 计时，计时期间持续输出 `right_value=645`，结束后切换 `MOTOR_MODE_FAST`。当前左转分支会清除停车并写入 `mid_value`，没有实际输出 `left_value=735`；因此“变量/路牌状态为左转”不等于“舵机物理输出左转”，这是整理时必须注意的现状。

## 10. 分段式急停制动

文件：`code/uart.c`，函数：`emergency_stop_enter()`、`emergency_stop_update_5ms()`、`emergency_stop_release()`。

流程：2 ms 路牌逻辑只负责进入 STOP 和置位 `emergency_stop_pending`；5 ms 电机中断负责一次性清 PID，并按左右轮各自编码器速度计算反向制动 PWM；两轮都进入零速死区后输出 `PWM_motor(0,0)`。

```c
static float emergency_stop_pwm(int16 speed)
{
    int16 speed_abs = speed >= 0 ? speed : -speed;
    int16 brake_pwm;
    if(speed_abs > STOP_BRAKE_SWITCH_SPEED)
        brake_pwm = STOP_BRAKE_FAST_PWM;
    else if(speed_abs > STOP_BRAKE_ZERO_SPEED)
        brake_pwm = STOP_BRAKE_SLOW_PWM;
    else
        return 0.0f;
    return speed > 0 ? -(float)brake_pwm : (float)brake_pwm;
}

void emergency_stop_update_5ms(void)
{
    float stop_pwm_l = emergency_stop_pwm(Encoder_speed_l);
    float stop_pwm_r = emergency_stop_pwm(Encoder_speed_r);
    if(abs(Encoder_speed_l) <= STOP_BRAKE_ZERO_SPEED &&
       abs(Encoder_speed_r) <= STOP_BRAKE_ZERO_SPEED)
    {
        PWM_motor(0, 0);
        motor_pid_reset();
        return;
    }
    PWM_motor(stop_pwm_l, stop_pwm_r);
}
```

## 11. 总体调用链（可作为 Word 小结）

`core0_main()` 完成初始化；`uart_callback()` 在串口中断中校验 0xAA/0x55 并发布视觉、路牌数据；`cc60_pit_ch0_isr()` 每 2 ms 处理失联保护、路牌状态和舵机循迹；`cc60_pit_ch1_isr()` 每 5 ms 读取编码器、执行 STOP/失联/正常模式优先级判断，再调用增量式速度 PID 和 `PWM_motor()`；所有最终电机动作都以 `PWM_motor()` 的左右带符号 PWM 为准。

## 12. 整理结论

本工程的实时控制核心不是 `while(TRUE)` 主循环，而是两个 CCU60 PIT 中断。UART 数据决定 `Target_Y`、`RoadSign_Flag` 和在线状态；2 ms 中断决定舵机、停车和路牌动作；5 ms 中断决定编码器闭环和电机输出。最近版本的主要改动方向是降低基础循迹速度、统一基础 PWM，并利用左右独立速度 PID 抵消电机性能差异。源码整理未修改项目文件，也未宣称重新编译；当前目录中可见已有 ADS 生成的 ELF/HEX/MAP 构建产物。
