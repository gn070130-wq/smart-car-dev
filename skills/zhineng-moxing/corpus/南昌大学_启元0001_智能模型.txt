第一章 引言
智能车是一种高新技术密集型的新型汽车，它涵盖的范围广泛，包括模式识别、传感器技术、自动化控制实现、电力电子技术、计算机技术等多个领域。在国际上已经形成智能汽车研究、设计、开发、竞赛的热潮。
全国大学生智能汽车竞赛与教育部已经举办的四大竞赛一样，都是为了提高大学生的动手能力和创新能力，具有重大的现实意义。与其他大赛不同的是，这个大赛的综合性很强，是以迅猛发展的汽车电子为背景，涵盖了控制、模式识别、传感、电子、电气、计算机和机械等多个学科交叉的科技创意性比赛，这对进一步培养本科生获取知识、应用知识的能力及创新意识，培养硕士生从事科学、技术研究能力，培养博士生知识、技术创新能力具有重要意义。
  全国大学生智能汽车竞赛是以“立足培养、重在参与、鼓励探索、追求卓越”为宗旨，鼓励创新的一项科技竞赛活动。基于组委会提供的统一智能车平台，在混合场景中完成一系列感知、理解、决策与执行任务，全面展现多模态视觉、强化学习与智能体规划等先进人工智能技术的实际应用能力。竞赛本要求指定的X车模，但最终由于各种原因，最终放弃了成品车模，从而使用任意阿克曼结构车模即可。最终我们使用了C车模。使用英飞凌的TC264微控制器作为下位机核心控制模块。硬件架构以RK3588边缘计算板为上位机，负责视觉感知、深度学习模型部署与任务决策；英飞凌TC264单片机作为下位机承担底层运动控制。硬件层面通过 UART-TTL 串口互连，统一参考地消除电平偏移，上位机下发运动控制指令，下位机执行 PID 调节驱动执行机构，同时反馈车辆运行状态，实现上下机数据交互。最终用单片机的PWM信号控制电机转速，使车模在虚拟赛道的状态下稳定运行赛道。近一年来的经历，培养了我们电路设计、软件编程、系统调试等方面的能力，锻炼了我们知识融合、实践动手的能力，对今后的学习工作都有着重大的实际意义。
  本技术报告主要包括机械结构设计、电路设计、软件控制设计等，尽可能详细地阐述了我们在调试过程中的设计思路。在智能车的制作与调试中，我们付出了辛勤的努力，这份报告凝聚着我们的智慧。

2.2 赛道定位及系统框架设计
人工智能模型组面向未来智能驾驶系统的关键能力培养，以现实赛道为基础，使用人工智能模型组指定的全新车模，通过虚拟对象叠加构建 虚实融合驾驶环境（Mixed Reality Driving Environment）。参赛者需基于组委会提供的统一智能车平台，在混合场景中完成一系列感知、理解、决策与执行任务，全面展现多模态视觉、强化学习与智能体规划等先进人工智能技术的实际应用能力。
人工智能模型组的赛道特色如下：
虚拟与现实深度融合的任务环境。车辆在真实物理赛道内行驶，同时系统会实时叠加虚拟行人、虚拟道路标识、虚拟障碍物、虚拟目标物（如金币、特效奖励、任务道具）等信息。增强现实系统由百度提供。
复合型人工智能技术的系统化应用。赛道要求选手充分和综合使用目标检测、多模态识别、视觉大模型、强化学习、智能体策略规划等丰富的AI技术，构建完整的“AI 驱动型自主智能车”能力体系，成为全国大学生智能汽车竞赛里“最聪明”和“最漂亮”的车。
本系统针对赛事五大核心场景，搭建轻量化、模块化的AI智能驾驶分层框架，全程摒弃固定时序、固定位置硬编码规则，依靠人工智能模型实时推理实现自主行驶。系统以机器视觉、多模态大模型与强化学习为核心技术支撑，适配鬼探头避让、路牌识别、智能泊车、红绿灯限速通行、全局金币巡航全场景任务，整体分为感知、决策、规划、控制、训练优化五大层级，各模块解耦协同，兼顾行驶安全性、场景适应性与全局任务收益。
系统感知层为环境输入核心，负责全赛道动态信息实时解析，适配所有赛事场景需求。针对鬼探头场景，可实时检测随机出现的行人位置与运动趋势，动态研判碰撞风险；针对分叉路口场景，融合OCR与文心多模态大模型，完成文字、图标类虚拟路牌的语义解析与方向识别；针对自主泊车场景，依托AprilTag辅助视觉感知，精准识别垂直、平行两类停车位；同时可实时感知红绿灯状态、区间限速数值与赛道金币分布，为上层决策提供精准、全面的环境数据支撑。决策、规划与控制层构成系统执行主体，依托感知数据完成AI端到端推理。决策层根据不同场景输出智能策略，实现突发行人避让、路口选路、泊车姿态调节、红绿灯节奏通行及安全巡航下的金币最优收集；规划层基于决策结果动态生成避障、转向、泊车、巡航的平滑轨迹；控制层将轨迹指令转化为车速、转向、制动等底层执行动作，保障车辆稳定合规行驶。
模型训练与优化层为系统智能化运行提供核心支撑，依托官方仿真平台与基础Demo迭代优化算法。通过多模态模型训练提升复杂路牌识别精度，基于强化学习持续优化泊车策略与轨迹精度，针对随机化赛事场景优化模型泛化能力，同时迭代全局平衡算法，实现行车安全与金币收集收益最大化。整套框架贴合赛事评分标准，以AI算法原生驱动替代传统硬编码逻辑，全场景模块化适配赛事考核内容，具备良好的场景适应性与综合性能，可高效完成全部线下赛任务。





第三章 机械结构设计
模型车的机械结构和组装形式是整个车身的基础。机械结构决定了智能车的上限速度,而软件算法的优化就是使车速不断接近这个上限速度，一辆软件十分优秀的小车，需要有精细的机械结构才能够不影响整体性能的发挥，由此可以看出机械结构的重要性。
基本优化方案:
(1)使用轻便的碳纤杆作为摄像头杆的材料。的安装支架采用3D打印的结构，可以方便调节摄像头角度向前方。
(2)车身的主板利用3D打印件置于在车辆尾部，并利用打印件的设计的特点将电池卡住，并且电池便于拆卸，方便取下充电。 
(3)打印件的固定孔与车模的螺孔相配合，并可以用螺丝固定打印件，通过斜放电池有利于降低车模的重心。
(4)整套打印件采用分体模块化思路，各支架相互独立装配，依托纵向空间搭建多层立体硬件布局，充分释放底盘有限安装面积。
(5)依托分层打印支架实现机械层面强弱电分区隔离，车尾区域集中放置电机驱动、动力电池等强功率器件。
(7)驱动板和转压板置于主板上方，用排针与排母连接，缩小板子体积，节省空间。
(8)替换更加柔软的硅胶胎，使得车模拐弯更加顺滑。差速的调整模型车的差速对转弯时的影响很大,可通过添加润滑油的手段,改进差速装置，提高差速的效果，从而提高了小车的转向性能。
3.1车身打印件的设计
本次智能车基于C原车底盘轮廓完成全套 3D 打印功能结构件正向定制开发，设计包含RK3588承载基座、视觉摄像头铰接支架、多路金属传感器立式支撑柱、线束限位托架、转接板固定支座等多种模块化构件。建模阶段充分匹配原车底盘安装点位，精准规避转向机构、避震、车轮运动干涉区域，所有构件预留标准沉头螺丝孔、定位基准面以及连续式线缆避让槽。结构上采用轻量化拓扑优化设计，在非受力区域镂空减重，关键承载位置增设内置加强筋，在控制整车重量、降低行驶负荷的同时保证结构刚度，能够承受高速过弯、赛道颠簸带来的持续冲击。整套打印件采用分体模块化思路，各支架相互独立装配，依托纵向空间搭建多层立体硬件布局，充分释放底盘有限安装面积。分体式设计便于单独拆装、更换损坏支架，在赛场调试阶段可快速调整传感器高度与安装位置，无需拆解整车；配套的线束限位结构可以约束线缆走向，防止车辆行驶中线缆缠绕转向机构、车轮，从机械层面规避线束拉扯磨损、短路等故障，显著提升整车装配规整度与运行可靠性。

3.2光头胎和硅胶胎的选用
我们在车上使用过光头胎以及硅胶胎。光头胎是由C车模原装的轮胎，磨光车轮上的纹路，并进过特殊的处理，使车模在赛道行驶的摩擦力更大，这样的好处是提高了车模速度上限，在弯弯绕绕的赛道上拐弯性能更好，避免了打滑问题带来的问题。
同时我们还选用过硅胶胎，硅胶胎是我们自制的，我们买来了材料自制过很多种不同成分比例的胎。这种胎的摩擦力更大，不过摩擦力过大会导致电机时常堵转发热，需要好的参数才可以减缓其带来的影响。
光头胎和硅胶胎各有优势，在比赛中，我们可以根据现场实际情况更换光头胎与硅胶胎，以满足不同情况下的不同需求。

3.3强弱电空间隔离、通用化模块化拓展架构
依托分层打印支架实现机械层面强弱电分区隔离，车尾区域集中放置电机驱动、动力电池等强功率器件，车身中部区域安放图像采集、主控等弱电信号电路板。通过物理支架形成空间隔断，使动力大电流线路与传感器信号线分区域走线，从机械布局源头降低动力回路产生的电磁噪声干扰图像、传感器信号，辅助提升整套智能车控制系统抗干扰性能。
整套机械支架系统采用标准化安装孔位设计，具备良好通用拓展能力。现有安装底座可直接兼容尺寸相近的板卡、主控板，各类传感器支架预留拓展安装点位，后续可快速新增激光雷达、额外摄像头等感知器件。整套机械结构无需大规模重新建模打印，仅更换局部支架即可适配硬件方案迭代，能够跟随人工智能模型算法升级灵活调整车载感知硬件配置，机械架构拥有较强的兼容能力与调试容错空间

3.4电路板的安装
整车电路板采用分层分区、强弱电分离的机械安装方案，充分兼顾散热、抗振、电磁兼容与调试便利性。
底层主控驱动板贴近底盘中轴线布置，有效缩短动力电池至驱动电路之间的大电流导线长度，减少线路压降与功率损耗。
人工智能板卡通过加高 3D 打印支架抬升，与下层电路板形成独立通风夹层，配合算力板自带散热风扇形成竖向对流风道，避免驱动模块与算力板热量互相堆积，缓解长时间运行下的芯片过热降频问题。
全部电路板通过尼龙铜柱悬浮式安装，隔离路面传递至底盘的高频振动，缓冲车辆加减速、冲击带来的机械应力，保护板载芯片、焊点与排线接头，降低颠簸环境下脱焊、接触不良风险。
布局上实现功能分区，车尾集中布置电机驱动等强电模块，车身中部布置主控、图像采集等弱电信号板卡，强电线路与信号线路依靠机械支架结构实现物理分隔。
所有板卡接口统一朝向车身外侧，预留充足空间方便排线插拔、线路测量与程序调试；排线沿着打印件预设通道有序固定，避免线缆大面积交叉重叠，降低电磁串扰，保障视觉图像、传感器采样信号稳定传输，为人工智能感知算法提供稳定硬件基础。

第四章 电路设计
4.1设计综述
电路设计共分为以下四个主要模块：
1.上位机板卡RK3588
2.主板MCU、供电模块以及外设接口
3.电源转压模块
4.电机驱动模块
4.2板卡、主板MCU及供电模块
本系统上层 AI 算力平台采用瑞芯微 RK3588 嵌入式开发板。RK3588 搭载八核处理器（4×Cortex-A76+4×Cortex-A55），内置独立 NPU，提供最高 6TOPS INT8 人工智能推理算力，支持主流深度学习模型转换与本地部署；具备多路 MIPI 摄像头接口、千兆以太网、USB 高速接口，运行 Linux 系统，适合视觉感知、多模态模型运算等高算力任务。
在整车异构架构中，RK3588 作为感知与高层决策单元，独立承担五大赛事场景的 AI 算法任务：虚拟行人目标检测、路牌 OCR 与多模态大模型语义解析、AprilTag 视觉识别、红绿灯状态检测、金币目标感知、强化学习推理与全局路径策略规划。完成环境感知与智能决策后，通过以太网将目标车速、转向指令下发至底层英飞凌 TC264 主控执行实时运动控制，形成 “RK3588 高层 AI 决策 + TC264 底层实时控制” 的分层异构体系。
简而言之：RK3588 为上层 AI 算力板卡，自带 6TOPS NPU 加速单元，负责视觉感知、深度学习推理、多模态语义理解、强化学习运算与全局行驶策略决策，完成环境分析后向 TC264 下发控制指令，实现智能感知与实时运动控制解耦。
我们采用的主控型号是是TC264核心板，本车底层运动控制主控采用英飞凌AURIX TC264汽车级32位多核MCU。TC264搭载双核TriCore处理器，最高主频可达200 MHz，具备硬件浮点运算与DSP加速能力，同时满足ISO 26262汽车功能安全标准，拥有极高的实时性与运行稳定性，适合智能车高动态、高实时性的运动控制场景。
芯片内置大容量Flash与SRAM资源，集成GTM高级定时器、高精度ADC、正交编码器接口、CAN FD、以太网、UART等丰富外设，能够高效完成电机PWM驱动、车速闭环控制、传感器数据采集以及与上层AI算力板的高速通信。
在本系统架构中，TC264主要承担底层执行层任务，负责接收上层多模态识别、强化学习泊车、全局巡航决策下发的控制指令，完成车速跟踪、转向控制、紧急制动、平顺调速等实时运动闭环，保障车辆在鬼探头避让、红绿灯区间限速、自主泊车、路口择路与金币巡航等场景下的行驶稳定性与控制精度。

4.5电机驱动模块
我们的电机驱动模块是IR2184作为驱动芯片的双路H桥驱动电路，IR2184是一款高电压、高速的功率MOSFET和IGBT驱动器，具有独立的高侧和低侧参考输出通道。IR2184通过HO控制上桥MOS管关断、通过LO控制下桥MOS关断，并且在芯片内部设有死区时间，防止同一路的上下桥MOS管同时导通，IR2184可以控制MOS管的导通，控制输入电机电压的有效值，以实现通过PWM信号控制电机转速的效果。
IR2184作为一款专业半桥驱动芯片，在全桥直流电机驱动方案中展现出多重优势。其高度集成的设计同时支持高侧和低侧MOSFET驱动，仅需搭配自举电容即可实现高侧供电，大幅简化了电路结构并降低系统成本。该芯片具备10-20V的宽工作电压范围，可适配多种电源方案，并能驱动600V以上的高压MOSFET，满足不同功率等级的电机控制需求。其±2A的强大驱动电流确保MOSFET快速开关，结合内置的死区时间控制，有效防止桥臂直通风险，显著提升系统可靠性。芯片输入兼容3.3V/5V逻辑电平，可直接连接各类微控制器，为电机提供精准的PWM调速、正反转控制和动态制动功能。尽管性能出色，IR2184方案仍存在若干需要注意的限制。其高侧驱动依赖自举电容供电的特性导致在持续高占空比（如100%）运行时可能出现电容电荷耗尽的问题，限制了其在需要长时间全功率输出场合的应用。系统设计时需精心选择快速恢复二极管和自举电容参数，否则可能影响高频工作时的稳定性此外，相比一些高度集成的智能驱动芯片，该方案需要更多的外围元件，在空间受限的超紧凑型应用中可能不具备优势。对于超大电流或超高集成度需求的应用场景，可能需要考虑采用集成式H桥驱动或智能功率模块等替代方案。但是运用在智能车上还是很符合要求的。

  steer_heading_ = pid_heading_.compute(heading_error_, 0.0, dt);

  double delta = -(steer_heading_ + steer_lateral_);

  delta = std::max(-config_.max_steer, std::min(delta, config_.max_steer));
  return delta;

参数整定方法： 
PID 控制器参数选择的方法很多，例如试凑法、临界比例度法、扩充临界比例度法等。我们一般选择相对操作简单的试凑法。
一般试凑法确定参数的步骤如下： 
(1)确定比例系数Kp 
确定比例系数 Kp 时，首先去掉 PID 的积分项和微分项，可以令 Ti=0、 Td=0， 使之成为纯比例调节。输入设定为系统允许输出最大值的60％～70％， 比例系数 Kp 由0开始逐渐增大，直至系统出现振荡；再反过来，从此时的比例系数Kp逐渐减小，直至系统振荡消失。记录此时的比例系数Kp，设定 PID 的比例系数Kp为当前值60％～70％。 
(2)确定积分时间常数 Ti 
比例系数 Kp 确定之后，设定一个较大的积分时间常数 Ti，然后逐渐减小 Ti， 直至系统出现振荡，然后再反过来，逐渐增大 Ti，直至系统振荡消失。记录 此时的 Ti，设定 PID 的积分时间常数 Ti 为当前值的150％～180％。 
(3)确定微分时间常数 Td 
微分时间常数 Td 一般不用设定，为 0 即可，此时 PID 调节转换为 PI 调节。如果需要设定，则与确定 Kp 的方法相同，取不振荡时其值的 30％。 
(4)系统空载、带载联调对 PID 参数进行微调，直到满足性能要求。

    机械结构的开发环境我们主要使用的Solidworks。首先先对自己所需的结构件进行简单的分析，考虑结构件的强度要求、结构要求、功能要求，然后再根据自己的分析用Solidworks进行建模。建模完成后在对其安装在车模上，看是否符合自己的要求，如果不符合则进行改进。最终用3D打印机将所需结构件打印出来，然后组装车模，在调试过程中用砂纸、锉刀等工具对其精修，使得其符合自己的要求。
6.2电路开发环境与电路板调试过程
电路开发环境我们使用的是嘉立创EDA专业版。在电路原理图设计工作之前，主板部分参考了逐飞科技开源的TC264学习板中的技术方案，同时结合经验，实现RK3588与下位机的连接，驱动方案使用了成熟的H桥驱动，并使用立创商城中提供的成熟的封装来降低硬件设计的风险。在电路的焊接与组装过程中，遵循由低到高、由内到外、焊一部分测一部分的组装思路。
其中在元器件选型过程中，需要注意产品质量，IR2184作为驱动芯片，是控制MOS管导通的关键。因此，在选择时要避免选到劣质芯片。在我们做车初期，由于选到劣质驱动芯片，在核心板输出PWM波给到驱动芯片后，它甚至给到核心板一个反作用导致烧毁核心板。所以质量好的芯片是很重要的。

    const std::vector<std::pair<double, double>>& centerline,
    double L_near, double L_far,
    PreviewPoint& near_pt, PreviewPoint& far_pt) {
  if (centerline.empty()) return false;

  // 引导线按 Y 升序排列（Y 小=远处、图像上方，Y 大=近处、图像下方）
  // 车在鸟瞰图底部中心 (320, 479)
  // 前向距离 = 车体到路径点的欧氏距离（非纯 Y 差）
  static constexpr double kCarX = 320.0;  // birdseye_center_x
  static constexpr double kCarY = 479.0;  // birdseye_height - 1

  bool found_near = false;
  bool found_far = false;

  // 从靠近车的尾部（Y大）往前（Y小）扫描，按欧氏距离选取预瞄点
  // 扫描方向：近→远，确保 near_pt 是最近满足 L_near 的点，far_pt 是最近满足 L_far 的点
  for (size_t i = 0; i < centerline.size(); ++i) {
    double px = centerline[i].first;
    double py = centerline[i].second;
    double forward_dist = std::hypot(px - kCarX, kCarY - py);
    if (forward_dist < 0.0) continue;   // 车后方，跳过

    if (!found_near && forward_dist >= L_near) {
      near_pt.x = px;
      near_pt.y = py;
      found_near = true;
    }
    if (found_near && !found_far && forward_dist >= L_far) {
      far_pt.x = px;
      far_pt.y = py;
      found_far = true;
      break;
    }
  }

  // 边界处理：找不到时取最远端点
  if (!found_near) {
    near_pt.x = centerline.back().first;
    near_pt.y = centerline.back().second;
    found_near = true;
  }
  if (!found_far) {
    far_pt.x = centerline.back().first;
    far_pt.y = centerline.back().second;
    found_far = true;
  }

  return found_near && found_far;
}

double StanleyController::computeSteering(
    const std::vector<std::pair<double, double>>& centerline,
    double speed, double dt) {
  // Step 1: 取预瞄点
  PreviewPoint near_pt, far_pt;
  if (!getPreviewPoints(centerline, config_.L_near, config_.L_far,
                         near_pt, far_pt)) {
    // 引导线无效，保持方向
    return 0.0;
  }
  near_pt_ = near_pt;
  far_pt_ = far_pt;

  // Step 2: 计算偏差
  // 横向偏差 e = 近预瞄点 X - 鸟瞰图中心 X（右正左负）
  static constexpr double kCarX = 320.0;  // birdseye_center_x = width/2
  lateral_error_ = near_pt.x - kCarX;

  // 航向偏差 θ_e（角度制 -180°~180°）
  //   近→远方向与"画面向上"的夹角，顺时针为正
  double dx = far_pt.x - near_pt.x;
  double dy = near_pt.y - far_pt.y;  // 近处y大 > 远处y小 → dy > 0
  heading_error_ = std::atan2(dx, dy) * 180.0 / M_PI;

  // Step 3: 合成转向角（双PID方案）
  //   δ = PID_heading(θ_e) + PID_lateral(e)
  steer_heading_ = pid_heading_.compute(heading_error_, 0.0, dt);
  steer_lateral_ = pid_lateral_.compute(lateral_error_, 0.0, dt);

  double delta = -(steer_heading_ + steer_lateral_);

  // Step 4: 限幅
  delta = std::max(-config_.max_steer, std::min(delta, config_.max_steer));

  return delta;
}

void StanleyController::reset() {
  pid_heading_.reset();
  pid_lateral_.reset();
  lateral_error_ = 0.0;
  heading_error_ = 0.0;
}

void StanleyController::updateConfig(const StanleyConfig& config) {
  config_ = config;
  pid_heading_.updateGains(config.heading_kp, config.heading_ki, config.heading_kd);
  pid_lateral_.updateGains(config.lateral_kp, config.lateral_ki, config.lateral_kd);
}
