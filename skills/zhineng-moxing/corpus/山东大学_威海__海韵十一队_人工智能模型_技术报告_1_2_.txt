一、车模整体设计
1.1C车模基础结构概述
C车模为第二十一届全国大学生智能汽车竞赛人工智能模型组指定车模，车体预装双驱动电机、轮胎、传动齿轮、底盘固件等全套核心部件，整车布局对称、结构紧凑，适配竞赛赛道行驶需求。
该车模底盘采用高强度玻纤板打造，刚性充足且轻量化。原厂车模尺寸为290*184*196mm，为适配设备安装、优化整车性能，我们自主设计并3D打印全新车壳，改装后整车尺寸不变，结构更加规整。
C车模采用双电机后轮差速驱动方案，前轮为随动结构，依靠后轮转速差完成转向，转向灵活、机动性强。车模搭载RS-380直流驱动电机，动力输出稳定，可满足赛道行驶工况；搭配高精度数字舵机，响应迅速、控制精准，有效保障小车行驶轨迹的稳定性。
1.2传感器配置
在传感器的选用上，我们配备了 1 个摄像头，用于信息采集，进而完成ov13855摄像头寻迹任务与 AI元素任务。这款摄像头具有诸多优势：一是图像流畅性高，即便车模处于高速状态，也能流畅获取有效的赛道信息，实现高速稳定寻迹；二是高分辨率且无畸变，能够真实还原赛道信息，便于后期处理赛道信息。
同时，本车搭载IMU660RA九轴惯性测量单元，集成三轴陀螺仪、加速度计与磁力计，适配智能车高速、颠簸的竞赛行驶工况。该传感器温漂小、长期稳定性高，有效降低姿态积分误差，保障航向检测精准。其测量量程大，可适应急加速、高速转向等极限场景，不易数据饱和。支持高速通信接口，抗干扰能力强，结合多源数据融合修正漂移，可为小车姿态纠偏、稳定控车提供高精度数据支撑。

1.3电池选择与使用
电池方面，我们选用了 1 个 3S 11.1V 2200mAh 30C 锂聚合物电池。它的优点众多：其一，电池容量较大，能够满足高强度的调车以及板卡供电需求；其二，体积小巧，尺寸为 20mm33mm105mm，占用车模空间少，便于车模布局；其三，重量相对较轻，有利于车模轻量化，提升车模速度；其四，电压适宜，可满足电机与板卡的供电需求；其五，放电倍率大，可达 30C，完全能满足电机的瞬时大电流需求；其六，支持较大的充电电流，可达 3A，充电时间短，效率高。
在电池充电时，我们使用 IMAX B6AC 80W 平衡充电器。该充电器能够实现锂电池组的平衡充电，有助于保护电池、维持电池容量，相对增加电池的使用次数，而且功能强大，具备快充、储存充、放电等功能。
1.4轮胎与四轮定位情况
本次使用C车模原厂标准竞赛轮胎，尺寸合规、圆度均匀，严格遵循赛规要求，未使用粘性涂层等违规改装。为优化行驶性能，通过细砂纸轻微打磨轮胎表面，去除表层光滑氧化层，有效提升轮胎与赛道的摩擦力，减少高速直行与弯道行驶时的打滑现象，保障车速与轨迹稳定性。
四轮定位方面，对整车轮距、同轴平行度进行校准调试。前轮采用小幅前束调校，抵消行驶偏移误差，提升直行稳定性，降低轮胎异常磨损；后轮严格保持水平平行，保证双差速驱动动力输出对称。同时校正四轮垂直度，杜绝偏磨、卡滞问题，让小车加减速、过弯动作更顺滑，适配高速竞赛工况。
1.5 差速器与减速器特点
C车模采用轮边独立减速结构，无传统中央差速器，依靠双电机转速差实现电子差速转向，结构简洁紧凑、传动损耗低。配套微型齿轮减速器减速比匹配合理，可降低电机高转速、放大输出扭矩，有效提升小车起步、爬坡与过弯的动力稳定性，适配赛道复杂工况。
该减速传动结构齿轮精度高、咬合顺滑，运行噪音小、抗震动能力强，高速行驶不易丢步。电子差速方案响应速度远优于机械差速器，可实时动态调节左右轮转速，大幅减小转弯滑移与轮胎磨损，让小车过弯轨迹更平滑、容错性更高。
1.6 车模结构优化措施
本车搭载上位机、下位机、传感器、编码器等多组电路模块，原车模无专用电路板安装结构，存在线路杂乱、模块固定不牢、重心分散、设备易受震动偏移等问题。为改善整车结构布局，提升设备运行稳定性，本次自主设计并3D打印定制电路板安装支架。支架贴合车模底盘结构尺寸，适配各类电路板规整安装，可集中固定所有车载电路模块，有效梳理整车布线，避免线路缠绕、接触干扰等问题。同时优化了整车配重分布，降低行驶颠簸带来的设备松动、传感器偏移风险，大幅提升智能车高速行驶、过弯工况下的整体稳定性与设备可靠性。

三、AI在智能车比赛中的调试与应用
本项目的软件系统采用“上位机视觉感知与决策 + 下位机实时运动控制”的分层架构。上位机以香橙派 Orange Pi RK3588/香橙派 RK3588 为核心，负责摄像头视频流接收、RKNN 神经网络推理、车道线提取、障碍物识别、状态机决策以及方向和速度指令生成；下位机采用英飞凌 TC264，负责电机、舵机及相关传感器的实时控制。
系统的软件数据链路可以概括为：视频采集 → RKNN 目标检测 → HSV 车道线检测 → IPM 逆透视与中心线提取 → 金币/车辆/行人/标志牌等目标解析 → 多策略方向融合 → 速度决策 → UDP/串口通信 → TC264 执行。
为了便于比赛调试和后续维护，本软件框架按照图片所示的报告结构进行整理，主要分为 AI 模型调试与应用、香橙派 RK3588 视觉算法部署、控制原理与策略三个部分。

3.1任务介绍
本项目的 AI 部分主要用于解决智能车比赛中的环境感知问题。由于传统纯图像处理方法难以稳定区分车辆、锥桶/金币、行人和标志牌，因此采用 YOLO 类单阶段目标检测网络对比赛场景中的关键目标进行识别，并将识别结果与传统视觉车道线算法融合。
模型检测类别包括 gold、car、person 和 noleft。其中，gold 用于赛道障碍物绕行决策；car 用于动态车辆避让；person 用于触发制动状态机；noleft 用于识别标志牌并触发内外圈扫描模式以及控制参数切换。
模型输入统一调整为 640×640 RGB 图像。推理结果输出目标框、类别和置信度，并在主控制循环中进一步进行尺寸、位置和置信度过滤，避免低质量检测结果直接影响车辆控制。

3.2数据的采集标注
AI 模型的数据来源于智能车实际比赛环境和调试过程中的视觉图像。数据采集应覆盖不同光照、不同车速、不同车辆位置以及目标远近变化，以降低模型对单一场景的过拟合。
数据标注重点围绕四类目标展开：gold、car、person 和 noleft。标注时需要保证目标框完整覆盖目标主体，并尽可能覆盖目标在近距离、远距离、部分遮挡等情况下的形态变化。
采集典型赛道环境：直道、弯道、内圈、外圈以及标志牌区域。
增加动态车辆和行人的样本，覆盖不同距离及不同侧向位置。
对 gold 等小目标进行充分采样，避免由于目标尺寸较小导致漏检。
对 noleft 标志牌进行不同角度和距离的数据扩充，提高状态机触发的稳定性。
数据标注完成后，对训练集、验证集进行合理划分，并在训练过程中重点关注小目标检测精度、漏检率和误检率。实际比赛中，模型性能不能只用 mAP 衡量，还应结合检测延迟以及控制系统对检测结果的容错能力进行综合评价。

3.3模型的训练部署
训练完成后的目标检测模型需要转换为适合 RK3588 NPU 推理的 RKNN 模型。本项目使用 rknn_lt.rknn 作为部署模型，在 香橙派 RK3588 上通过 RKNN Runtime 完成推理。
模型部署后的处理流程为：读取摄像头当前帧 → resize 到模型输入尺寸 640×640 → RGB 格式转换 → RKNN 推理 → 后处理得到 boxes、classes、scores → 根据置信度和位置条件筛选有效目标 → 将目标结果传递给车道线、避障、制动和状态机模块。
模型推理线程与主控制循环需要尽量减少不必要的阻塞。对于需要高频发送的控制指令，软件采用独立通信线程和队列进行缓冲，使视觉推理和通信过程相互解耦。


四、在香橙派RK3588 上部署视觉识别算法
4.1香橙派rk3588 简介
本项目的上位机采用香橙派 Orange Pi RK3588 平台。RK3588 集成 ARM 多核 CPU 和 NPU，可同时承担图像预处理、传统视觉算法、神经网络推理和通信任务。与仅依赖 CPU 的方案相比，利用 RKNN 将目标检测模型部署到 RK3588 NPU，可以降低推理对 CPU 的占用，为车道线处理和控制决策保留更多计算资源。
在软件层面，香橙派 RK3588 是整个系统的视觉与决策中枢：一方面接收摄像头和 YAW 传感器数据；另一方面将融合后的方向、速度和参数通过 UDP 或串口发送给 TC264。


4.2视觉处理流程
视觉处理采用“AI 目标检测 + 传统视觉车道线检测”的双通道结构。AI 通道负责识别语义目标，传统视觉通道负责提取蓝色车道线并计算道路方向，最终通过方向融合模块形成统一控制量。
完整处理流程如下：
第一步：通过 HTTP 获取 AR 网络摄像头视频帧，原始分辨率为 640×480。
第二步：将图像 resize 为 640×640，并送入 RKNN 模型进行目标检测。
第三步：解析 gold、car、person、noleft 四类目标，得到目标框中心坐标、类别和置信度。
第四步：对图像进行 HSV 颜色分割，提取蓝/青色车道线像素。
第五步：根据当前扫描模式 inner/outer 选择车道线扫描侧，并利用 car 检测框过滤车辆区域内的干扰像素。
第六步：按照从图像底部到上部的高度分组策略提取车道线代表点，并通过 IPM 逆透视映射将单侧车道线转换为道路中心线偏移。
第七步：分别计算 dir_road、dir_gold 和 dir_car，并按照权重进行方向融合。
第八步：结合行人制动、标志牌状态、车辆避让和基础速度等条件生成最终速度与方向指令。
第九步：通过 UDP 高频发送控制量，通过串口队列发送 PID 和其他参数。
车道线方向计算采用前瞻加权方式。以 Y_QIANZHAN=280 为参考位置，距离该参考位置越远的点权重越低，从而降低远处噪声对当前转向的影响。道路方向输出由 STEER_K 与加权平均偏移量共同决定，并根据 inner/outer 模式叠加相应修正量。

4.3香橙派rk3588 板卡的网络连接配置
香橙派 RK3588 同时承担视频接收、YAW 数据接收以及控制指令发送任务，因此网络配置需要保证与摄像头、TC264 和 YAW 传感器处于可通信状态。

UDP 控制报文采用 JSON 格式：timestamp 表示发送时刻，dir 表示融合后的方向控制量，speed 表示速度指令。串口参数采用自定义字符帧格式，以 A～I 作为字段边界，实现速度、舵机 PID 和左右电机 PID 参数的顺序下发。
串口发送采用独立线程配合 queue.Queue 缓冲，主控制循环只负责产生参数，不直接等待串口发送完成，从而降低串口阻塞对视觉控制周期的影响。      4.4香橙派rk3588远程连接调试软件：Visual Studio Code
开发调试阶段可使用 Visual Studio Code 通过 SSH 远程连接 香橙派 RK3588，在 PC 端直接编辑和运行上位机程序。该方式能够避免在板端频繁操作文件，提高代码调试效率。
实际调试时建议按照“网络连通性 → Python 环境 → RKNN Runtime → 摄像头视频流 → YAW 数据 → 模型推理 → 车道线 → 控制输出”的顺序逐层验证。不要在底层通信或视觉输入尚未正常时直接调试复杂控制策略，否则故障定位会比较困难。

五、控制原理与策略介绍
5.1PID  
5.1.1原理
本项目采用上位机进行视觉决策、下位机 TC264 进行实时闭环控制的结构。上位机输出方向和速度目标，下位机根据目标值与车辆实际状态计算舵机和左右电机的控制量。PID 参数通过串口动态下发，便于比赛现场根据不同赛道阶段进行调节。
舵机控制主要使用比例与微分环节，即通过 KP_SERVO_DYNAMIC 和 KD_SERVO 对方向误差及其变化趋势进行调节。低速阶段采用较小的舵机比例增益，高速阶段适当提高比例增益并提高微分抑制能力，以兼顾转向响应速度和车辆稳定性。
电机左右轮分别配置 Kp、Ki 参数，通过 TC264 完成电机速度闭环。上位机通过 A～I 字符帧将速度、舵机参数以及左右电机 PID 参数一次性下发。





5.2控制策略
5.2.1整体部分
最终方向控制量采用多源信息融合：
dir_output = K_ROAD × dir_road + K_GOLD × dir_gold + k_car_active × dir_car
当前 K_ROAD=2.5，K_GOLD 在不同圈段可配置，最终方向输出限幅在 -4.0～4.0。通过这种方式，道路中心线提供基础循迹方向，gold 提供障碍物绕行方向，car 提供动态车辆避让方向。
当车道线完全丢失时，系统进入丢线保护策略，当前实现将 dir_output 设置为 4.0，以执行预设的最大右转安全动作。该策略属于故障保护逻辑，应在实车调试中根据赛道实际安全性继续验证。

5.2.2 车道线与道路中心控制
HSV 车道线检测使用 H=95～110、S=150～255、V=170～255 的阈值范围提取蓝/青色区域。根据当前 SCAN_MODE 选择扫描侧：outer 模式主要从右侧扫描，inner 模式主要从左侧扫描。
扫描点按照图像高度进行分组，GROUP_MIN=40、GROUP_MAX=30，并从每组中选择具有代表性的像素进行平均。之后通过 IPM_K 与 IPM_B 完成逆透视映射，将单侧边线转换为道路中心线偏移。
道路方向量 dir_road 由 STEER_K 与加权平均偏移共同决定，并在 outer 模式增加 OUTER_MODIFY=0.15，在 inner 模式增加 INNER_MODIFY=0.0。
5.2.3 Gold 障碍物绕行策略
对于每一个 gold 目标，系统综合考虑其相对中心线的位置、距离以及与车辆目标的冲突关系。目标评分由中心线偏离分和距离分组成，并乘以车辆避让系数。
其中，距离评分采用 score_jvli=(y-210)/430，目标越靠近车辆，优先级越高；中心线偏离项用于判断目标位于车辆行驶路径附近的程度；若 gold 与较近 car 存在同侧冲突，则降低或禁止该 gold 被选中。最终选取得分最高的目标计算 dir_gold，并参与方向融合。
这种方法的核心思想不是简单地选择“最近的目标”，而是在目标距离、车辆行驶路径和动态车辆冲突之间进行联合决策，从而减少多目标环境下的错误绕行。

5.2.4 Car 动态车辆避让策略
车辆避让首先根据 car 中心点相对于车道中心线的位置判断车辆位于左侧还是右侧，而不是直接使用图像几何中心作为判断基准。为了抑制单帧检测抖动，系统维护长度为 7 帧的 car_side_window，其中 -1 表示左侧、1 表示右侧、0 表示无车，并通过多数投票确定当前车辆侧向。
方向补偿采用不对称限幅：车辆位于左侧时，delta 在 [-CAR_DOWN_LIMIT, +CAR_UP_LIMIT] 范围内；车辆位于右侧时，delta 在 [-CAR_UP_LIMIT, +CAR_DOWN_LIMIT] 范围内。这样可以根据实际赛道的避让习惯设置左右不同的转向力度。
无车辆时，last_dir_car 以 CAR_zero_LIMIT=0.1 的步长逐渐衰减至 0，避免车辆突然消失导致方向量瞬间跳变。同时通过 last_k_car_active 持久化上一次使用的 K_CAR_LEFT 或 K_CAR_RIGHT，使车辆短暂丢检时仍能保持合理的避让权重。
5.2.5 Person 行人制动策略
行人属于高优先级安全目标。系统设置警戒区域四边形 (0,480)、(200,270)、(440,270)、(640,480)，并以 y>270 作为进入制动触发区域的重要判断条件。
当 person 进入触发区且当前已经过解锁时间，状态机由状态 0 切换到状态 1，激活 shache_active 并触发急刹。急刹阶段采用 speed=-speed×K_SHACHE 的反冲制动方式，持续约 0.1 s；在非急刹阶段，状态 1 下速度设置为 0。
当行人连续 2 帧离开蓝区/红区或完全丢失 2 帧后，系统解除制动状态。解锁后方向保持 1 s，并在 1.5 s 内禁止再次触发，同时提供约 0.16 s 的速度 boost，随后恢复正常控制。
5.2.6 标志牌与赛道状态机
noleft 标志牌用于改变车辆的赛道扫描模式和控制参数。检测到置信度不低于 0.45 且满足尺寸、位置约束的标志牌后，状态由 STATE_NO_SIGN 转换为 STATE_SIGN_FOUND，并要求持续约 0.02 s 进行确认，降低单帧误检造成误触发的风险。
首次确认标志牌后，将 sign_count_state 设置为 1，并强制 SCAN_MODE=inner 持续 18 s。之后每隔 1 s 检查 sign_count_state，若其大于 0 则进入 STATE_AFTER_SIGN。
控制参数随状态切换：标志牌前的低速段使用 KP_SERVO_DYNAMIC=0.11、KD_SERVO=35；标志牌后的高速段使用 KP_SERVO_DYNAMIC=0.20、KD_SERVO=40。若处于标志牌触发的 inner 强制期，左侧车辆避让系数可强制设为 0，避免内圈策略与车辆避让策略产生方向冲突。
5.2.7 速度控制策略
基础速度当前统一设置为 V_BASE=2.0。系统根据行人状态、急刹状态、解锁状态以及 boost 状态对基础速度进行覆盖或修正。

5.2.8 控制融合与安全机制
系统控制决策具有明确的优先级：安全相关的行人制动优先于普通循迹；车辆避让和 gold 绕行对道路中心循迹进行补偿；标志牌状态机负责改变扫描侧和控制参数。各模块最终不直接操作底层执行器，而是统一生成方向和速度变量，再通过通信模块发送给 TC264。
为了提高系统稳定性，软件采用滑动窗口、持续时间确认、渐进归零、参数持久化、输出限幅和丢线保护等措施。其核心目标是将视觉检测产生的离散、抖动信息转换为连续、可执行的车辆控制指令。

六、结论
我们小车以完全模型组 C 车模作为基础，利用RK3588作为图像处理硬件，英飞凌 TC264 芯片作为小车控制核心，舵机、电机、编码器等作为反馈和执行器件，辅以长时间的软硬件联合调试（PID 等调参），实现了小车的高速运行，并且获得了综合奖励时间省赛负秒的好成绩。
智能车的整体设计与调试是一项集机械结构、硬件电路、嵌入式开发与人工智能算法于一体的综合性工程。在本次车模研发过程中，我们围绕车辆行驶稳定性、控制精准度、硬件可靠性与场景适应性等核心目标，对C车模机械结构校准、PCB电路设计、供电系统优化、车载设备布局与整车走线方案进行多次迭代调试。针对赛事复杂赛道工况，我们不断排查硬件干扰、优化3D打印结构布局、完善SY8205降压供电电路与传感器适配方案，逐步解决车辆打滑、供电波动、姿态偏移、布线杂乱等各类问题，最终完成了一套结构规整、供电稳定、运行可靠、适配多任务AI识别场景的智能车硬件系统。
在软件与算法开发层面，我们立足竞赛实际需求，基于飞桨框架完成AI模型的训练与优化，结合上下位机串口通信逻辑，搭建了完整的图像识别、姿态解算与整车闭环控制系统。通过大量赛道实车测试、参数迭代调试与鲁棒性验证，不断修正控制算法逻辑、优化车速与转向控制策略，针对性解决赛场光线变化、赛道干扰、高速过弯失稳等不确定问题。同时依托实测数据波形分析、代码结构梳理与功能模块优化，持续提升小车自主循迹、智能识别与动态行驶的综合性能，让整车控制逻辑更加严谨高效、适配性更强。
全国大学生智能汽车竞赛不仅是技术能力的比拼，更是团队协作与创新思维的综合历练。整车软硬件的完美适配、算法与机械结构的协同优化，离不开团队各成员的分工协作、高效沟通与互帮互补。备赛过程中，我们相互探讨技术难点、共享调试经验、共克研发难题，在磨合中提升技术能力，在实践中积累竞赛经验。同时感谢大赛组委会搭建的优质竞赛平台，感谢各大厂商与高校团队的技术分享与经验交流，为我们的学习与成长提供了极大助力。最后，祝愿全国大学生智能汽车竞赛蓬勃发展、薪火相传，愿所有参赛学子不负耕耘、不负热爱，在科创道路上稳步前行、收获成长与突破
