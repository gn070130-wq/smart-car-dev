第一章 引言
1.1 全国大学生智能汽车竞赛背景
全国大学生智能汽车竞赛是一项极具挑战性与创新价值的国家级学科竞赛，以智能车为载体，深度融合机械设计、电子电路、自动控制、计算机视觉、人工智能等多学科知识，旨在培养大学生的工程实践能力、创新思维和团队协作精神。竞赛由教育部高等学校自动化类专业教学指导委员会发起，全国大学生智能汽车竞赛秘书处统筹，各高校轮流协办，每年吸引来自全国数百所高校的数千支队伍参与。赛题设置紧密结合国家智能交通与自动驾驶战略，共有飞檐走壁、疯狂电路、蚂蚁搬家、飞跃雷区、走马观碑、雁过留痕、智能视觉、智能模型、卡丁快跑、轮腿穿越、单车定向等11个可选组别。参赛队伍需在数月内完成智能车的硬件设计（包括车体结构、传感器选型、主控平台搭建）、软件算法开发（路径识别、控制策略、决策规划）以及系统优化（实时性、抗干扰性），最终通过校内选拔、分区赛和全国总决赛的层层比拼，角逐国家级奖项。竞赛不仅考验学生的理论功底，更强调从设计到调试的全流程工程能力，许多团队通过开源社区共享代码、技术报告，形成良好的学术交流氛围。全国大学生智能汽车竞赛已成为高校培养智能交通领域创新人才的重要平台，既是对学生综合能力的全面锻炼，也是推动产学研深度融合的生动实践，为未来智能汽车产业输送了大量高素质人才。
1.2 方案总体介绍
	按照竞赛规则规定，我们采用RK3588为上位机，恩智浦公司生产的微控制器RT1064为下位机，摄像头实时采集赛道物理场景，通过主办方提供的AR空间配准框架，将虚拟3D赛道模型与实车视频流进行坐标映射与融合，生成叠加虚拟元素的增强现实视频流，作为车辆自主行驶的视觉引导依据，主控输出PWM波控制电机的转速和舵机的打角。

图2.1 车辆外形图
2.2 车模重心
车模的重心对赛车的转向及稳定性有较大影响，因此需要将重心的高度及先后位置进行合理的调整。重心越低，车辆在高速转弯时侧倾角越小，轮胎抓地力分布更均匀，减少侧滑风险，提高稳定性，因此在电池、电路板、摄像头、舵机和电机的安装过程中应使得重心尽量放低。根据车辆运动学理论，车身重心前移，前轴载荷增加，前轮抓地力增强，但转弯易出现转向不足（推头），后轮可能因载荷不足而滑移，影响转向灵活性；重心后移，增强高速稳定性，后轮抓地力也会增加，但易导致转向过度（甩尾）。但综合起来看，重心应靠近后轴一点。
2.3 舵机安装
智能车舵机的安装位置需综合考虑转向效率、结构稳定性、空间利用率及动态响应，其核心原则是缩短传动路径、降低重心、减少非必要负载。本设计将舵机竖直放置在车头中央，车头空间通常较充裕，可使结构更加紧凑；舵机输出轴直接连接转向拉杆，减少中间传动环节，降低机械损耗与间隙；力矩传递路径短，转向指令执行延迟低，适合高速赛道或需要快速避障的场景。
2.4 摄像头的固定 
摄像头的安装至关重要，摄像头的安装位置及高度会影响一辆车的性能好坏，可以说是整车的眼睛。遵循主办方关于摄像头的安装规范，我们将摄像头安装于车模中心线位置，保证左右视野对称。在高度标定中，我们对比了不同高度下的成像质量：受平视姿态限制，过高的安装位置会使远处赛道像素占比过低，易受光线波动影响而丢失边缘信息；而过低则导致弯道内侧视野盲区增大。经多轮场地测试，最终将高度定为13cm，该值在规则上限之内，兼顾了前瞻有效距离与图像稳定性。固定方式上，选用专用支架、固定座及碳纤材料，通过刚性锁紧结构将摄像头稳固于车体，确保高速行驶及转向冲击下姿态保持不变。

3.3 电机驱动电路设计 
一个好的驱动模块对竞速比赛来说是至关重要的，好的加速与制动能力对小车速度的提高有很大帮助。控制直流电机运行的方法是施加一个 PWM方波，其占空比对应于所需速度。电机起到一个低通滤波器作用，将 PWM 信号转换为有效直流电平。可通过微处理器输出PWM 驱动信号，在实际应用中的 PWM 频率是可变的，应对其进行优化，以防止电机颤抖，发出耳朵听得到的噪声。
常用的电机驱动有两种方式：一种是集成电机驱动芯片；另一种是采用N沟 道 MOSFET和专用栅极驱动芯片设计。集成电机驱动芯片将功率MOSFET、栅极驱动电路、保护功能（如过流、过压、欠压、过热保护）等集成在单一芯片中，其电路设计简单，但集成芯片内部的每个 MOSFET 导通电阻在 120 毫欧以上，大大增加了电枢回路总电阻，此时直流电动机转速降落较大，驱动电路效率较低，电机性能不能充分发挥。分立的 N 沟道 MOSFET 具有极低的导通电阻，大大减小了电枢回路总电阻，专门设计的栅极驱动电路可以提高 MOSFET的开关速度，使 PWM 控制方式的调制频率可以得到提高，减少电枢电流脉动。
选择 MOSFET应考虑其耐压和导通内。在耐压值选择是需留出一定的余量，导通内阻则是越低越好。于是我们最终选择了TPH1R403NL，漏源电压30伏、导通内阻3.3毫欧、连续漏极电流110安。如图3.3所示。

第四章 软件方案               
4.1 全局定位与虚实坐标配准
为实现虚拟3D赛道模型与真实物理场景的精确叠加与空间对齐，系统引入基于全局视觉的定位与坐标配准机制。本系统采用AprilTag视觉基准标签作为空间定位标识，在车模顶部安装TAG码，在赛道四角分别布置四个参考标签（ID=15、16、17、18），其对应的场地物理坐标分别为（5.0, 4.0）、（0.0, 4.0）、（0.0, 0.0）、（5.0, 0.0），单位为米。赛道上方部署全局摄像头，实时采集场地全局图像，通过AprilTag检测算法解算各标签在图像坐标系下的像素级角点位置。在系统初始化阶段，需完成图像像素坐标系与场地物理坐标系之间的单应性矩阵（Homography Matrix）标定。当四个参考标签均被成功检测后，系统提取各标签的四个角点像素坐标，与其已知的场地物理坐标建立对应关系，采用RANSAC算法求解单应性矩阵H，实现从图像平面到场地平面的透视变换映射。标定完成后，系统进入运行阶段，参考标签的像素位置将被冻结作为坐标基准，不再参与后续更新，以消除动态检测噪声对标定稳定性的影响。
在运行阶段，系统对车模顶部TAG码进行实时检测与跟踪。为提升跟踪鲁棒性，系统采用区域预测策略，基于上一帧有效检测位置划定感兴趣区域（ROI）进行局部搜索，降低全图检测的计算开销并提高检测成功率。检测到ID=1标签后，提取其中心点像素坐标，通过已标定的单应性矩阵H进行透视变换，将其映射至场地物理坐标系，得到车辆在场地中的实时位置（x, y）。同时，利用标签的水平和垂直边缘方向解算车辆朝向角θ。
为抑制检测噪声对定位输出的影响，系统设计了多级滤波与状态管理机制。位置信息经滑动平均滤波器滑处理，角度信息通过扩展卡尔曼滤波器EKF进行融合估计，提升角度输出的连续性与稳定性。此外，系统引入速度状态估计与状态机管理机制，通过相邻帧间位置变化量计算车辆运动速度，当速度低于设定阈值且持续一定帧数后，判定车辆进入静止状态，锁定当前位姿输出；当速度超过阈值后切换至运动状态，实时输出更新后的位姿信息。该机制有效消除了车辆静止时因微小抖动导致的定位漂移，保障了输出位姿的稳定性与一致性。
定位数据经处理后，通过UDP通信协议传输至主办方虚实融合系统。板卡系统接收定位数据后，依据车辆当前位姿实时渲染虚拟3D赛道模型，生成包含虚拟赛道元素与真实物理场景的增强现实视景。
该全局定位与坐标配准机制，有效支撑了虚实融合场景下车辆绝对位姿的高频获取，为闭环决策控制提供了稳定、连续的空间参考基准，使得车辆在后续感知—决策—控制链路中所依赖的“虚拟赛道”具备一致的空间坐标基础，实现了虚实空间的精确对齐与动态配准。
4.2 感知类视觉任务
4.2.1 数据集的采集
针对目标检测、语义分割和字符识别三大任务分别进行数据图片采集与标注。在目标检测方面，对金币、行人、障碍车等进行采集，使用txt格式标注边界框（Bounding Box）；在语义分割方面，对可行驶区域、车道线及特定背景等进行采集，使用掩码（Mask）图像或多边形JSON格式进行像素级标注；在字符识别方面，对路牌文本区域进行采集，使用包含文本框坐标及转录内容的txt或lmdb格式进行标注。本系统各任务模型的数据集数量均在3000张左右。
4.2.2 模型训练及编译
模型训练环境配置需在本地安装Python 3.10、pip工具、git工具以及CUDA 12.1 GPU版本。采用百度飞桨（PaddlePaddle）生态框架，需在Windows本地安装PaddleDetection（目标检测）、PaddleSeg（语义分割）和PaddleOCR（字符识别）三大套件。放入准备好的各任务数据集，选择合适比例划分训练集和验证集，配置数据集读取路径和模型训练参数，分别启动PP-YOLOE（目标检测）、PP-LiteSeg（语义分割）和PP-OCRv4（字符识别）等轻量级模型的训练。配置VisualDL实现训练数据可视化，实时跟踪损失率（Loss）、平均精度均值（mAP）、平均交并比（mIoU）及识别准确率（Accuracy）等重要参数变化，方便后期调整学习策略，提高模型质量。
在本地Windows环境训练好的模型，需迁移至 Ubuntu 20.04系统的虚拟机中进行后续的转换、量化与测试。在该Ubuntu 20.04环境下，使用RKNN-Toolkit2工具链将模型转换为适配NPU的rknn格式，并开展模型量化（如INT8量化）以及精度、推理性能的模拟测试。测试验证达标后，将量化后的rknn模型部署至RK3588板卡。本项目在板卡端采用 gcc/g++ + cmake + rknpu2库 进行C++推理工程的编译，以实现目标检测、语义分割与字符识别三个模型在边缘端的高效协同部署与推理。
4.3 控制系统整体处理流程
本车视觉感知系统以ov13855摄像头为图像采集前端，硬件帧率配置为60帧/秒，原始图像分辨率设定为640×480。感知软件栈需同步完成实例分割、目标检测与OCR识别三项视觉任务，为兼顾推理精度与系统吞吐量，单帧图像从采集到全部视觉任务推理结束的总处理时延需约束在33ms以内，以满足感知—决策—控制全链路的实时性指标。
图像数据流进入应用层后，系统对当前帧原始图像执行零拷贝分叉操作，生成三路共享底层内存的副本，分别馈送至三条并行处理的视觉推理任务流。该设计依托RK3588片内三核心NPU的异构并行架构，结合多线程异步推理机制，有效隐藏各任务间的串行等待开销，实现多视觉任务的深度并行化处理。
（1）赛道感知任务流
该任务流首先对输入副本执行逆透视变换，将前视图像重投影至鸟瞰视图空间，以消除透视畸变对车道线几何参数估计的干扰。随后，基于paddle-seg实例分割模型实现端到端的像素级语义解析，输出车道线掩膜与可行驶区域分类结果，为下游路径规划模块提供结构化的赛道几何表征。如图4.1.1，图4.1.2，图4.1.3所示：

4.4.1增量式PID

增量式PID（Proportional-Integral-Derivative）控制器是一种常用于闭环控制系统的算法，它通过计算偏差值的比例、积分和微分来调整控制输出，以达到控制目标的稳定性和准确性。在车模实际控制中，增量式PID每次输出都是对上一次输出的增量，响应速度快；误动作时影响小，必要时可用逻辑判断的方法去掉出错数据；自动切换时冲击小，便于实现无扰动切换，因此适合进行车模电机闭环控制。增量式PID根据公式可以很好地看出，一旦确定了 Kp、Ki 、Kd，只要使用前后三次测量值的偏差， 即可由公式求出控制增量。而得出的控制量Δu(k)对应的是近几次位置误差的增量，而不是对应与实际位置的偏差，没有误差累加。也就是说，增量式PID中不需要累加。控制增量Δu(k)的确定仅与最近3次的采样值有关，容易通过加权处理获得比较好的控制效果，并且在系统发生问题时，增量式不会严重影响系统的工作。

位置式PID是对当前系统的实际位置与预期位置之间的偏差进行PID控制，最终输出预期位置。因为有误差积分 ∑e(i)，一直累加，也就是当前的输出u(k)与过去的所有状态都有关系，用到了误差的累加值；（误差e会有误差累加），输出的u(k)对应的是执行机构预期的实际位置，，一旦控制输出出错(控制对象的当前的状态值出现问题 )，u(k)的大幅变化会引起系统的大幅变化。并且位置式PID在积分项达到饱和时,误差仍然会在积分作用下继续累积，一旦误差开始反向变化，系统需要一定时间从饱和区退出，所以在u(k)达到最大和最小时，要停止积分作用，并且要有积分限幅和输出限幅。因此在实际应用，一般直接使用PD控制，而位置式 PID 适用于执行机构不带积分部件的对象，如舵机。

int main(int argc, char** argv)
{
    signal(SIGPIPE, SIG_IGN);
    signal(SIGINT, signal_handler);
    XInitThreads();

    // ---- 1. SHM 初始化 ----
    SHMStream stream("shm_ar_video");
    if (!stream.open()) {
        printf("ERROR: Cannot connect to AR Engine SHM.\n");
        return -1;
    }

    // ---- 2. 等待第一帧 ----
    cv::Mat test_frame;
    while (g_main_running.load()) {
        if (stream.read(test_frame) && !test_frame.empty()) {
            printf("SUCCESS: Received first valid frame (%dx%d)\n",
                   test_frame.cols, test_frame.rows);
            break;
        }
        usleep(10000);
    }

    // ---- 3. IPM 初始化（与 main.cc 完全相同的参数） ----
    IPMConfig    ipm_cfg = makeDefaultIPMConfig();
    IPMProcessor ipm(ipm_cfg);

    // 先做一次变换，获取 BEV 输出尺寸（由 ipm_cfg.output_size 决定，此处为 640x480）
    cv::Mat bev_test;
    ipm.transform(test_frame, bev_test);
    if (bev_test.empty()) {
        printf("ERROR: IPM transform failed on first frame.\n");
        return -1;
    }
    printf("[IPM] BEV output size: %dx%d\n", bev_test.cols, bev_test.rows);

    // ---- 4. 视频写入器（使用 BEV 尺寸，而非原图尺寸） ----
    // 支持命令行指定文件名：./video_three bev_output.avi
    std::string video_filename = (argc > 1) ? argv[1] : "bev_output.avi";

    cv::VideoWriter video_writer;
    video_writer.open(
        video_filename,
        cv::VideoWriter::fourcc('X', 'V', 'I', 'D'),
        25.0,
        bev_test.size()   // ★ 使用 BEV 尺寸
    );

    if (!video_writer.isOpened()) {
        printf("WARNING: Failed to open video writer. Will display only.\n");
    } else {
        printf("SUCCESS: BEV video will be saved to [%s]\n", video_filename.c_str());
    }

    // ---- 5. 预览窗口 ----
    cv::namedWindow("BEV Record", cv::WINDOW_NORMAL);
    cv::resizeWindow("BEV Record", bev_test.cols, bev_test.rows);

    // ---- 6. 主循环 ----
    printf("[Main] Recording BEV... Press ESC or Ctrl+C to stop.\n");

    int   total_frames  = 0;
    int   fps_counter   = 0;
    auto  fps_start     = std::chrono::steady_clock::now();
    float current_fps   = 0.0f;

    while (g_main_running.load()) {
        // --- 读取原图 ---
        cv::Mat raw_frame;
        if (!stream.read(raw_frame)) {
            usleep(1000);
            continue;
        }

        // --- ★ 透视变换到鸟瞰图 ---
        cv::Mat bev_frame;
        ipm.transform(raw_frame, bev_frame);

        if (bev_frame.empty()) {
            printf("WARNING: BEV frame empty, skipping.\n");
            continue;
        }

        // --- 写入视频 ---
        if (video_writer.isOpened()) {
            video_writer.write(bev_frame);
        }

        // --- FPS 统计 ---
        fps_counter++;
        total_frames++;
        auto now = std::chrono::steady_clock::now();
        float elapsed_s = std::chrono::duration<float>(now - fps_start).count();
        if (elapsed_s >= 1.0f) {
            current_fps = fps_counter / elapsed_s;
            printf("[BEV Record] FPS: %.1f | Total: %d frames\n",
                   current_fps, total_frames);
            fps_counter = 0;
            fps_start   = now;
        }

        // --- 预览显示（可注释掉以节省 CPU） ---
        cv::imshow("BEV Record", bev_frame);
        int key = cv::waitKey(1);
        if (key == 27) {
            printf("[Main] ESC pressed. Stopping...\n");
            break;
        }
    }

    // ---- 7. 退出清理 ----
    printf("\nCleaning up...\n");
    if (video_writer.isOpened()) {
        video_writer.release();
        printf("BEV video saved: %s  (total %d frames)\n",
               video_filename.c_str(), total_frames);
    }
    cv::destroyAllWindows();
    printf("Done.\n");
    return 0;
}
