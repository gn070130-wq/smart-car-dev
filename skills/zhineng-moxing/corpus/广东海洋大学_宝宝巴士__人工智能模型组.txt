第一章　引言
1.1 竞赛背景与人工智能模型组简介
全国大学生智能汽车竞赛以"立足培养、突出实践、鼓励探索、追求卓越"为宗旨，是面向全国大学生的重要科技竞赛。随着人工智能技术的快速发展，竞赛设立了人工智能模型组别，鼓励参赛队伍将深度学习方法引入智能车的感知与决策环节，探索"传统控制 + 深度学习"融合的技术路线。
人工智能模型组的赛道任务包含赛道巡线、标志牌识别、动态障碍物（车、人）避让等多种场景，单一感知手段难以同时满足语义理解与几何精度的双重要求。本队在此背景下提出"异构计算分工 + 多级感知融合"的技术方案：以神经网络目标检测提供语义级感知，以传统视觉算法提供几何级巡线信息，以多模态大语言模型完成标志牌文字的语义推理，三级感知结果统一汇入决策层融合输出。
1.2 设计制作过程综述
本队自2025年9月组队以来，围绕"识得准、避得开、跑得稳"的目标，依次完成了方案论证、车模机械改造、硬件电路设计、检测模型训练与NPU部署、巡线算法开发、大模型接口集成与上下位机联调等阶段工作。视觉感知程序累计迭代10个大版本（至 v10.7），整车测试里程超过5公里。开发过程中经历了"双NPU模型核心冲突"等典型嵌入式工程问题，最终形成"NPU专跑检测、CPU专跑巡线"的异构计算架构（详见5.1节与7.4节）。
1.3 报告内容安排
本报告第二章介绍系统总体方案与感知技术路线论证；第三、四章介绍机械结构与硬件电路设计；第五章为本报告核心，详细阐述基于异构计算的环境感知与决策系统，包括PP-YOLOE+目标检测、传统视觉巡线、多模态大模型标志牌识别、动态障碍物应对与速度决策融合；第六章介绍下位机控制软件设计；第七章介绍制作调试过程与算法版本迭代；第八章给出主要技术参数；第九章为结论。核心算法源程序见附录B。

第二章　智能模型车总体设计方案
2.1 系统总体架构
本模型车采用"上位机感知决策 + 下位机实时控制"的分层架构，全系统数据流如下：
摄像头视频流（HTTP MJPEG，局域网无线传输）
        │  采集线程（最新帧缓冲，丢旧帧保实时）
        ▼
 香橙派 RK3588 感知决策主循环（每帧）
   ├─① YOLO目标检测（PP-YOLOE+，NPU推理，9类目标）
   ├─② 标志牌语义识别（YOLO触发 + 多模态大模型API）
   ├─③ CV巡线（HSV颜色提取→车道拟合→贝塞尔转向曲线，纯CPU）
   ├─④ 动态障碍物决策（Car避让状态机 / People方向预判）
   ├─⑤ 速度决策合成（多条件逐级叠加）
   └─⑥ 转向PD计算 → 串口20Hz下发转向角与目标速度
        │  UART /dev/ttyS4 @115200，文本帧协议
        ▼
 下位机 TC264（双核MCU，逐飞开源库）
   ├─ 串口指令字符级状态机解析（逐字节、无动态内存）
   ├─ 舵机角度执行（50Hz PWM、机械滞回消除、限幅）
   ├─ 电机PWM输出
   └─ 调试命令通道（Q查轮速 / D查计数）
该架构的核心特点是异构计算分工：
• NPU（6 TOPS）专用于神经网络推理：PP-YOLOE+检测模型独占NPU计算核心，保证推理帧率稳定；
• CPU专用于传统视觉与决策：巡线、避障决策、速度合成、转向PD均在CPU侧运行，与NPU推理流水线并行，算力零竞争；
• 感知与控制解耦：上位机以20Hz周期输出最终转向角与目标速度，下位机专注指令解析、舵机标定映射与电机输出的确定性执行，算法迭代不影响控制底层稳定性。
2.2 感知技术路线选择与论证
在感知方案上，本队先后试验并对比了三条路线：
1. 纯传统视觉：对光照、赛道材质敏感，无法识别标志牌文字、车辆、行人等语义目标，任务上限低；
2. 双神经网络模型（分割 + 检测）：早期版本采用 PP-LiteSeg 赛道分割 + YOLO 检测双模型方案，但在 RK3588 平台上两模型竞争同一NPU核心，运行中间歇性出现 "failed to submit" 提交失败错误，推理时序不可靠（问题定位过程见7.4节）；
3. YOLO检测 + 传统CV巡线混合：检测模型独占NPU，巡线改用HSV颜色提取与几何拟合，CPU与NPU各司其职。
本队最终选择路线3，并进一步引入多模态大语言模型完成标志牌文字理解，形成"神经网络检测（语义级）+ 传统视觉巡线（几何级）+ 大模型推理（认知级）"的三级感知体系。实践表明该方案在RK3588平台上帧率稳定、无NPU资源冲突，且各级算法可独立调试替换，工程可控性最好。
2.3 主要性能指标
• 巡线最高稳定车速：1.0m/s
• 感知决策循环频率：20 Hz（串口下发周期50ms）
• YOLO检测类别数：9类（sign/car/people/door/stopspot/coin/LSZ/road/stoplight）
• 标志牌识别方式：文心 ERNIE-4.5-VL 多模态大模型（云端API）
• 丢道自恢复：连续3帧丢道触发保护性转向，成功率90%
• 整车静态电流：< 200mA，动态峰值电流 <0.5A

第三章　机械结构设计与改造
3.1 车模底盘改造
车模采用竞赛指定C车模底盘。主要改造包括：
• 拆除原车模多余结构件以减重；
• 更换前轮定位参数：主销后倾角为3°，前轮前束为–0.3°，提高直线行驶稳定性与入弯响应；
• 电机齿轮与差速齿轮啮合间隙调整至0.15 mm，兼顾传动效率与噪声；
• 加装差速器限滑垫片方案，改善弯道内外轮速差。
3.2 摄像头安装与前瞻设计
摄像头支架采用3D打印材料，摄像头安装高度5 cm，前瞻距离75cm。图像经车载摄像头→无线视频流/AR眼镜链路接入香橙派（链路细节见5.2节）。支架与主板采用刚性连接，抑制车体震动引起的图像抖动。
3.3 重心优化与固定方式
电池与香橙派置于车体中部处，TC264主板以及驱动板布置于电池下方，整车重心高度降至5cm，前后配重比约4:5，有效抑制加速/制动时的俯仰与侧倾。所有模块采用铜柱+尼龙扎带+热熔胶以及3d打印结构固定，便于拆装且无松动风险。

第四章　硬件电路设计
4.1 电源降压与接口模块
驱动板电源从XT60接口接入3S 11.1V 3000mAh锂电池，前端设有船型电源开关、熔断保险及SMBJ12A瞬态抑制二极管，实现反接与浪涌初级保护。板上同时引出电机使能开关、信号接口、舵机接口、电源指示灯与电机输出接线端子。
电池正极VCC分为三路：
• 动力路：直接为左、右DRV8701ERGET全桥栅极驱动器及TPH1R403NL功率MOSFET供电。VCC母线并联C27/C28（各220μF）等大容量电解电容及多颗100nF/10μF陶瓷电容，抑制电机换向纹波与急加减速时的电压跌落；
• 逻辑5V路：采用SCT2450CSTER同步降压芯片（输入4.5~42V，最大5A）将电池电压降至PWR_5V，为香橙派、逻辑缓冲器SN74HC125PWR及TC264部分外设供电，输出端配置47μF+220μF滤波；
• 舵机可调路：采用TPS54531DDAR可调同步降压芯片，通过R8/R10反馈网络将输出稳定在约6V（VADJ，可按舵机规格微调），独立为舵机供电，避免舵机大电流拉低逻辑电源。
上、下位机共地，串口通信线直接连接TC264的3.3V UART与香橙派GPIO，电平兼容，无需额外转换。
图 2. 电源降压电路

4.2 TC264主控板电路
TC264主控板以LQ-TC264-5YSVC核心板插座为中心，集成电源管理、调试/烧录、人机交互及各类外设接口。主板从驱动板引入PWR_5V，经船型电源开关后分为两路3.3V LDO：OUT3V3（ME6211C33M5G-N）供外设与接口，INSIDE3V3（ME6211C33M5G-N）供核心板内部逻辑，两路独立以降低相互干扰。板上设有电源指示灯与CH340N USB转TTL电路（Type-C接口），便于程序下载与串口日志调试。
接口资源按功能分区布置：
• 主驱接口（CN2，6芯）：连接驱动板，传输 L_EN、L_PH、R_EN、R_PH、NSLEEP、GND 信号；
• 编码器接口（CN4，6芯）：+5V/GND 供电，四路信号引脚分别接左、右编码器 A/B 相；
• 串口接口（CN3）：P00.0/P00.1 接 CH340N USB转TTL，作为程序下载与日志调试口；与香橙派通信使用 UART1（P02.2/P02.3），由核心板对应引脚直接引出；
图3. TC26.主控板电路
4.3 电机驱动与舵机供电模块
电机驱动采用两片TI DRV8701ERGET单H桥智能栅极驱动器，分别驱动左、右轮。每片DRV8701外接四颗东芝N沟道MOSFET TPH1R403NL（VDS=30V、ID=150A、RDS(on)≈1.4mΩ@VGS=10V）构成全桥，VM端接电池VCC。DRV8701配置为PH/EN模式：TC264输出PWM至EN引脚控制电机转速/制动，GPIO控制PH引脚决定转向；nSLEEP引脚由主板统一控制，低电平时驱动器进入低功耗睡眠、H桥高阻，作为使能/急停开关。
由于TC264为3.3V IO，DRV8701逻辑输入虽兼容1.8V/3.3V/5V，但为增强抗干扰能力与电流驱动能力，L_EN/L_PH、R_EN/R_PH、NSLEEP等控制线均经过SN74HC125PWR三态缓冲器后再接入DRV8701，缓冲器使能端下拉常开。主板与驱动板通过6芯信号接口连接（L_EN、L_PH、R_EN、R_PH、NSLEEP、GND），驱动板输出端接左、右电机M+/M-接线端子。驱动板与主板分离布局，功率地（电池地/电机地）与信号地单点汇接，PWM频率设置为17kHz（超声频段，避免可听噪声）。
舵机接口由VADJ（≈6V）供电、GND回地，PWM控制信号直接由TC264对应引脚输出。

4.4 上位机香橙派核心板接口电路
香橙派（RK3588，6TOPS NPU）通过UART（/dev/ttyS4，GPIO复用）与TC264通信。为消除启动时序问题（香橙派启动约3s），TC264上电后进入等待状态，收到上位机有效指令帧后方使能电机。香橙派单独配置5V/5A供电线径。

4.5上下位机通信电路
采用UART TTL直连（3.3V电平一致，无需电平转换），下位机使用UART1（引脚P02_2/P02_3），波特率115200，8N1。上位机以20Hz周期发送文本指令帧，帧格式与解析机制见6.4节；下位机解析含格式校验与执行限幅，任何非法字符自动复位解析器，不会错位执行。改进项：增加通信超时安全停车保护，见第九章改进方向。

第五章　基于异构计算的环境感知与决策系统设计
本章为整车核心技术，内容对应本队视觉感知程序（v10.7）。系统运行于香橙派 RK3588，形成"YOLO检测（NPU）+ CV巡线（CPU）+ 大模型标志牌识别（云端API）"三级感知与统一决策融合架构。
5.1 感知决策系统总体架构
系统主循环按帧处理图像，各功能模块组织如下：
图像帧
 ├─① YOLO检测线程：PP-YOLOE+（RKNN INT8）→ 9类目标框
 ├─② 标志牌处理：检测到sign → 触发大模型API识别牌面文字
 ├─③ CV巡线模块：颜色提取→车道聚类→拟合→IPM→贝塞尔曲线→turn角
 ├─④ 避障决策模块：Car避让状态机 / People方向预判
 ├─⑤ 速度合成：基础速度 + 多条件修正量逐级叠加
 └─⑥ 输出：转向PD计算 → 串口下发 "@turn:xx-speed:xx!"
架构演进的关键工程决策：早期方案采用 PP-LiteSeg（巡线分割）+ YOLO（检测）双神经网络模型。实测中发现两模型在 RK3588 的 rknn 运行时下竞争同一NPU核心，推理间歇性报 failed to submit 错误，导致检测帧率不稳、时序抖动。经排查确认是NPU核心资源冲突后，本队做出架构回退决策：巡线全部改用传统CV实现（CPU），YOLO检测独占NPU。调整后NPU推理稳定，问题彻底消除。这一"按平台资源约束反推算法选型"的过程是本队最重要的工程经验之一。
5.2 图像采集与多线程流水线
• 视频链路：图像以 HTTP MJPEG 流（局域网无线）接入香橙派，链路断开时自动以1s间隔重连，保证长时间运行鲁棒性；
• 最新帧机制：采集线程将帧放入 queue(maxsize=1) 缓冲，处理线程始终取最新帧、自动丢弃积压旧帧，从机制上消除了处理延迟累积，保证决策基于最新画面；
• 流水线并行：采集、NPU推理、CPU巡线与决策在不同线程并行，充分利用RK3588八核CPU与NPU的异构算力。

5.4 基于传统视觉的巡线算法
巡线模块运行于CPU，处理流水线共8步：
（1）HSV颜色阈值提取。赛道边线为特定颜色，在HSV空间以（H:100~124, S:100~250, V:125~255）阈值分割并做形态学开运算去噪，得到车道掩码。
（2）触底约束过滤。对掩码做连通域分析，只保留纵向延伸至画面下方35%区域的连通域，滤除远处干扰色块与空中相似颜色物体。
（3）直方图双车道聚类。对掩码像素做x轴方向直方图统计，双峰分布对应左右两条车道线，据此将像素聚类为左右两组。该步同时可识别分流（fork，远端出现双峰）与合流（merge，近端出现双峰）路况，为特殊元素处理提供判断依据。
（4）二次多项式拟合。对每组车道像素（≥40点方拟合）做二次多项式拟合，得到平滑车道曲线，抑制逐像素噪声。
（5）IPM逆透视变换。利用标定好的单应矩阵将前视图变换为鸟瞰图（BEV），消除透视畸变对几何量测的影响。
（6）像素-世界坐标变换与分区间曲率估计。按30m×7m场地标定将像素坐标映射到世界坐标，采用三点外接圆法逐点计算曲率，分 Mid（0~20m）/ Far（20~40m） 两区间统计，并做中值滤波滑窗去抖，得到远近两段赛道的曲率先验。
（7）贝塞尔转向曲线生成。本算法的转向核心：从车头底部中心出发，到车道曲线上按曲率自适应选取的目标点（曲率越大、车道线越接近水平时取点越远），生成三次贝塞尔"转向曲线"。该曲线天然保证起点航向为车体正前方、切向连续光滑，避免了直接跟踪车道线造成的转向量阶跃。
（8）转向角计算。对贝塞尔曲线下半段做y加权平均航向角（近处权重更大），输出最终转向角 turn。
丢道保护（fallback）：巡线失败连续3帧后，执行强制右转55°并降速的确定性保护动作，直至重新捕获车道线；车辆避让期间丢道只计数不触发，避免误动作。
5.5 基于多模态大模型的标志牌语义识别
标志牌任务要求理解牌面文字含义（如"左路"/"右路"），传统检测或分类模型难以胜任。本队采用"YOLO触发 + 云端多模态大模型识别"的混合方案，这是本队方案中"人工智能"特征最突出的部分：
（1）触发条件（防误触发设计）。YOLO检测到sign目标且同时满足：面积 > 14000px²、框中心不在画面边缘5%区域内、连续多帧确认。三重条件联合过滤远处误检与擦边误检。
（2）识别流程。触发后：模型车倒车3s获得更好拍摄距离 → 停车（最长等待10s）；裁剪标志牌区域图像，JPEG编码后经API调用文心 ERNIE-4.5-VL 多模态大模型；提示词约束模型在"应该走左路 / 应该走右路"中二选一并给出分析，本地解析返回文本获得结论。
（3）执行策略。判定为右路 → 强制右车道行驶12s；判定为左路 → 保持左车道。
（4）交替识别状态机（省时设计）。观察到规则任务中标志牌指示通常左右交替，设计如下状态机：第1次sign调用API识别；第2次sign跳过API、直接取反上次方向（不停车、不倒车，节省约10s）；第3次回到API识别，如此交替。若API解析失败，则取消取反武装，回退为每次均调API的安全模式——任何优化路径都有失败降级出口。
（5）防重复触发：识别触发设15s冷却，识别完成后额外抑制5s。
5.6 动态障碍物应对策略
5.6.1 Car避让：左右分治策略
以未平移的原始车道中心线为参照判定前车位于车道左侧还是右侧——之所以强调"未平移"，是因为避让动作会平移车道线，若用平移后的线做左右判定，会形成"平移→判定更偏→继续平移"的正反馈，这是一个隐蔽但关键的工程设计细节。
Car在车道右侧 → 转角偏置避让：
• 触发面积阈值2500px²（左侧2000px²），按像素距离÷4.3折算为左打角度偏置，上限-60°；
• 消失后三阶段"欠账补偿"状态机：hold（延续阶段，偏置按0.14系数逐帧衰减，保持避让惯性）→ compensate（回正阶段，按避让期累计的"转向欠账"以4.0比例生成右转补偿量，0.8系数逐帧释放）→ cancel（巡线转向角<28°判定已回正，立即撤销补偿）。该状态机使车辆避让后精确回到车道中央而非缓慢漂移回去；
• 避让期间抑制sign识别3s，防止误触发标志牌流程。
Car在车道左侧 → 车道线整体右移：
• 不叠加转向偏置，而是将巡线目标车道线整体向右平移（平移量÷0.5放大，上限190px），由巡线闭环自然引导车体右移，转向过程更平滑；
• 目标消失后保持0.75s（一阶低通平滑逼近），再在0.5s内线性释放，杜绝方向盘阶跃；
• 平移激活期间降速2.3档。

第六章　下位机控制软件设计
6.1 软件总体框架
下位机软件基于逐飞科技TC264开源库（Seekfree TC264 Opensource Library，AURIX Development Studio开发环境）构建，按驱动对象划分为四个用户模块：
• my_uart：串口初始化与指令逐字节状态机解析（6.4节）；
• my_servo：舵机PWM标定与角度执行（6.2节）；
• my_motor：电机PWM输出（6.3节）；
• my_encoder：双编码器正交解码测速与RPM换算。
系统初始化后，CPU0主循环专注串口指令的解析与执行；CPU1当前保留扩展（可用于陀螺仪数据处理、特殊元素状态机等后续功能）。上位机完成感知、决策与转向PD计算并下发最终指令，下位机专注确定性执行，二者职责清晰。
6.2 转向执行与舵机标定
转向PD闭环运行于上位机（Kp=1.0、Kd=0.8、死区15°、限幅±65°，避障偏置直接叠加于PD输出，见附录B.5），下位机负责舵机的标定、映射与精确执行：
• 占空比标定：舵机采用50Hz PWM（ATOM2通道），命令角0°对应2500μs（右满）、180°对应500μs（左满），按线性公式换算占空比；
• 有效机械区间映射：实测该舵机有效转角对应命令角75~125，程序将0~180°全量程线性压缩映射至该有效区间，既避免无效打角浪费控制量，又防止机械过冲；
• 上电机械滞回消除：初始化时先打左满位置、延时200ms后再回到中位——保证每次上电舵机都从同一方向逼近中位，消除齿轮传动滞回引起的中位漂移；
• 中位微调：中位标定为71°（含向左1°机械偏差补偿）；上位机±90°命令角按 71 − angle 映射为舵机命令角并限幅0~180°后执行。
6.3 电机驱动
双电机采用17kHz PWM（超声频段，无可听噪声）+方向GPIO驱动H桥。上位机速度指令（−100~100）线性映射为PWM占空比（×50）。
6.4 上下位机通信协议与指令解析
协议格式：文本帧 @turn:数值（可支持小数）-speed:数值（可支持小数）!，20Hz（50ms周期），115200波特率。转向角范围±90°（90=左满、0=回中、−90=右满），速度范围±100。
字符级有限状态机解析器：不依赖sscanf与动态内存，逐字节状态转移：
'@' → 't' → 'u' → 'r' → 'n' → ':' → [负号][整数][.小数]（转向角）
  → '-' → 's' → 'p' → 'e' → 'e' → 'd' → ':' → [负号][整数][.小数]（速度）
  → '!' 帧完成：符号还原 → 限幅（±90° / ±100）→ 映射执行
任意非法字符 → 状态机立即复位，丢弃半帧
该设计的优点：①逐字节解析无需整帧缓冲，RAM开销极小；②任何干扰字节只会导致当前帧复位，不会错位执行；③小数按位权逐位累加，不调用浮点库函数，执行时间确定。
调试与遥测通道：单字符命令Q查询左右轮速（RPM）、D查询编码器原始计数，可由串口助手直接发送；下位机对指令字节原样回显并打印解析结果，配合上位机日志实现全链路可观测，显著加快联调排障速度。

7.3 算法版本迭代历程

• v1~v3（双模型期）：PP-LiteSeg分割巡线 + YOLO检测双NPU模型，功能验证通过，但运行中间歇性出现NPU failed to submit 错误；
• v4~v6（架构回退）：定位为双模型NPU核心资源冲突，巡线改为HSV颜色提取 + 几何拟合的纯CPU方案，冲突彻底消除，帧率稳定；
• v7~v8（避障精细化）：引入Car避让欠账补偿状态机（hold→compensate→cancel）与车道线平移避让，解决避让后回不正、避让抖动问题；左右判定改用未平移原始中心线，消除正反馈；
• v9（大模型接入）：接入ERNIE-4.5-VL标志牌识别，设计交替识别状态机与API失败降级；
• v10~v10.7（提速与打磨）：People方向预判替代简单停车；速度决策改为逐级叠加规则合成；增加各类冷却窗口与丢道兜底，长时间压测稳定性显著提升。
7.4 典型问题与解决方案
1. 问题：双神经网络模型在RK3588上运行时间歇性报 failed to submit，检测帧率抖动严重。
   定位：单独运行任一模型均正常，双模型同时推理必现，确认是rknn运行时内两模型竞争同一NPU核心导致任务提交失败。
   解决：架构级回退——巡线弃用分割模型，改用传统CV（CPU实现），YOLO独占NPU。调整后问题零复现。启示：嵌入式AI部署中，算法选型必须服从平台资源约束。
2. 问题：Car避让（早期转角偏置方案）结束后车辆回不到车道中央，且多次避让后越偏越远。
   定位：避让平移车道线后，用平移后的线判定障碍物左右位置，形成"平移→更偏→继续平移"正反馈。
   解决：左右判定一律采用未平移的原始中心线；引入欠账补偿状态机量化回正量，避让结束精确回中。
3. 问题：行人刚出现即急停，人已走远仍在停，浪费时间且速度不平顺。
   解决：改为移动方向预判——只对"正在挡向本车路线"的行人停车，对远离者反而加速通过；停止窗口设0.5~2s上下限与5s冷却。
4. 问题：标志牌远距离误触发大模型识别，倒车动作打断正常巡线。
   解决：面积>14000px² + 脱离画面边缘5% + 连续帧确认三重条件；触发冷却15s、识别后抑制5s。
5. 问题：阴天光照下HSV蓝色阈值提取的车道掩码断裂。
   解决：实际调参过程，放宽V通道下限/自适应阈值。

第九章　结论
本队围绕人工智能模型组别要求，完成了"香橙派异构感知决策 + TC264实时控制"分层架构智能模型车的设计与制作。主要成果：

3. 系统贯彻"感知可错、决策不崩"的确定性安全设计：连续帧确认、面积分档、冷却窗口、丢道兜底，全部误判路径均有兜底；

存在不足与改进方向：串口文本协议尚无校验和、下位机通信超时保护尚未启用，强电磁干扰环境下可靠性有待验证，计划增加帧校验与超时安全停车；HSV巡线对极端光照的适应性依赖手工阈值，后续可引入自适应阈值或轻量颜色分割网络作为备通道；大模型识别依赖无线网络，断网时只能降级，可探索小参数量本地VLM部署方案。

def steering_pd(turn, turn_last, car_bias=0.0):
    KP, KD, DEAD, LIM = 1.0, 0.8, 15, 65
    e = 0 if abs(turn) < DEAD else turn      # 死区回正
    out = KP * e + KD * (turn - turn_last)   # 微分阻尼
    out = clamp(out, -LIM, LIM)
    return clamp(out + car_bias, -LIM, LIM)  # 避让偏置叠加进PD输出

B.6 下位机：串口指令字符级状态机解析器（C语言，节选）
/* 逐字节解析 "@turn:xx-speed:yy!"，任何非法字符立即复位状态机 */
void my_uart_process_receive(void)
{
    static uint8 state = 0;
    static float servo_angle = 0.0f, motor_speed = 0.0f;
    static uint8 servo_neg = 0, motor_neg = 0;
    static uint8 servo_dot = 0, motor_dot = 0;
    static uint16 servo_div = 1, motor_div = 1;
    uint8 ch;
 
    if(!uart_query_byte(UART_1, &ch)) return;
 
    if(ch == '@') {                        /* 帧头：复位全部解析状态 */
        state = 1; servo_angle = motor_speed = 0;
        servo_neg = motor_neg = servo_dot = motor_dot = 0;
        servo_div = motor_div = 1;
    }
    /* 状态按 't'→'u'→'r'→'n'→':' 及 '-'→"speed:" 逐字节推进；
       数字位按位权逐位累加：
         整数位  angle = angle*10 + (ch-'0')
         小数位  div *= 10;  angle += (ch-'0')/div          */
    else if(ch == '!') {                   /* 帧尾：符号还原+限幅+执行 */
        if(servo_neg) servo_angle = -servo_angle;
        if(servo_angle >  90) servo_angle =  90;
        if(servo_angle < -90) servo_angle = -90;
        int16 t = (int16)(71 - servo_angle);   /* 映射为舵机命令角 */
        my_servo_set_angle((uint8)limit(t, 0, 180));
 
        if(motor_neg) motor_speed = -motor_speed;
        int16 spd = (int16)(limit(motor_speed, -100, 100) * 50);
        my_motor_set_base_speed(spd);          /* 更新差速补偿输出 */
        state = 0;
    }
    else if(ch == 'Q') { /* 调试命令：上报左右轮速RPM */ }
    else if(ch == 'D') { /* 调试命令：上报编码器原始计数 */ }
    else state = advance_state(state, ch);     /* 其余字符按状态机推进 */
}
B.7 下位机：舵机标定与机械滞回消除（C语言，节选）
#define SERVO_0_DUTY        1250   /* 命令角0°  → 2500μs（右满） */
#define SERVO_180_DUTY       250   /* 命令角180°→ 500μs（左满） */
#define SERVO_MIN_EFFECTIVE   75   /* 实测有效机械区间下限 */
#define SERVO_MAX_EFFECTIVE  125   /* 实测有效机械区间上限 */
 
void my_servo_init(void)
{
    pwm_init(SERVO_PWM_CHANNEL, 50 /*Hz*/, 0);
    my_servo_set_angle(180);        /* 先打左满 */
    system_delay_ms(200);           /* 等待到位 */
    my_servo_set_angle(71);         /* 同方向回中位（含1°微调），消除滞回 */
}
 
void my_servo_set_angle(uint8 angle)
{
    /* 全量程0~180°线性压缩映射至有效机械区间75~125 */
    uint8 mapped = SERVO_MIN_EFFECTIVE
                 + (uint32)angle * (SERVO_MAX_EFFECTIVE - SERVO_MIN_EFFECTIVE)
                 / SERVO_MAX_ANGLE;
    uint32 duty = SERVO_0_DUTY
                - (uint32)mapped * (SERVO_0_DUTY - SERVO_180_DUTY)
                / SERVO_MAX_ANGLE;
    pwm_set_duty(SERVO_PWM_CHANNEL, duty);
}
