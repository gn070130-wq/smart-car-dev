引言
全国大学生智能汽车竞赛以“立足培养、重在参与、鼓励探索、追求卓越”为宗旨，是一项鼓励创新的科技竞赛活动。智能车设计内容涵盖了控制、模型识别、传感技术、汽车电子、电气、计算机、机械、能源等多个学科的知识，对学 生的知识融合和实践动手能力的培养，具有良好的推动作用。
本竞赛以“立足培养，重在参与，鼓励探索，追求卓越”为指导思想，旨在促进高等学校素质教育，培养大学生的综合知识运用能力、基本工程实践能力和创新意识，激发大学生从事科学研究与探索的兴趣和潜能,倡导理论联系实际、求真务实的学风和团队协作的人文精神，为优秀人才的脱颖而出创造条件。
比赛要求在大赛组委会统一提供的竞赛车模结构—阿克曼基础上，自主构思控制方案及系统设计。本系统采用上位机与下位机协同工作的双机架构：上位机使用Orange Pi 5 Pro（RK3588S）运行ROS2 Humble机器人中间件，负责视觉感知、AI推理与行为决策；下位机使用NXP RT1064（Cortex-M7，600MHz）微控制器，负责电机控制、舵机控制、传感器数据采集与航迹推算定位。上下位机之间通过UART串口进行固定包长协议通信。系统集成了PP-YOLOE+深度学习模型进行实时目标检测，并结合百度文心大模型实现岔路口路牌识别与决策，最终实现了一套能够自主识别赛道、避障、收金币、通过岔路口的智能车控制系统。
备赛期间，我们学习了ROS2机器人中间件的使用、基于RK3588S NPU的深度学习模型部署、行为树（BehaviorTree.CPP）控制框架、NXP RT1064微控制器的底层驱动开发、PID控制算法、卡尔曼滤波、惯导定位、百度文心大模型API调用、UART串口通信协议设计等方面的知识。在对机械结构进行了调整的基础上，我们对小车软件进行反复调试与优化，在发现问题后努力解决问题，进一步优化智能小车的机械、软件和算法方案，最终形成了现在的稳定快速的智能小车。几个月来的经历，培养了我们嵌入式系统设计、AI模型部署、控制算法开发、系统集成调试等方面的能力，锻炼了我们知识融合、实践动手的能力，对今后的学习工作都有着重大的实际意义。








系统总体设计
1.1系统概述

本系统采用"上位机+下位机"的双机协同架构，如图1.1所示。上位机为Orange Pi 5 Pro（RK3588S，6 TOPS NPU），运行Ubuntu系统与ROS2 Humble机器人中间件，集成了摄像头驱动、PP-YOLOE+深度学习目标检测、AR增强现实渲染、行为树决策控制、百度文心大模型岔口决策等功能模块。下位机为NXP RT1064微控制器（Cortex-M7，600MHz），基于逐飞开源库（SeekFree v3.7.2）开发，运行裸机固件程序，负责电机转速PID闭环控制、舵机角度控制、ICM20602 IMU陀螺仪数据采集与航向角解算、编码器速度测量与卡尔曼滤波、航迹推算定位等底层实时控制任务。上下位机之间通过无线UART串口（115200bps）进行数据交换，采用12字节定长帧协议，帧头0xFE、帧尾0xEF，上位机向下位机发送目标速度与转向角度指令，下位机向上位机回传位置信息。

我们选择了去年完全模型组官方指定的i车模。本智能车基于 CICR-I 型号 I 模型车基础套装进行硬件改装设计，车辆采用舵机控制阿克曼转向方案，动力系统选用单电机后置驱动布局；搭载 12V、额定转速 12000rpm 直流高速电机，理论最高行驶速度可达 10m/s。底盘采用碳纤维材质打造，有效实现整车轻量化。加装摄像头碳纤维支架时长宽高为 316mm×190mm×120mm；经过主控驱动一体化电路板、视觉模块、电源、陀螺仪等器件装配调试后，改造完成的整车总重量约 1.45kg，轻量化的车身设计能够有效降低惯性，提升车辆加减速响应与赛道转向操控性能。

第三章 硬件系统设计及实现
3.1 硬件设计方案
本智能车主控驱动一体化电路板以高效稳定、轻量化集成、抗干扰能力强为设计核心准则，全程围绕竞赛车载使用场景开展硬件布局规划。轻量化层面，摒弃传统主控、驱动分板架构，采用主控驱动一体化设计，缩减两块电路板堆叠体积与整车配重，精简外接排线数量，降低布线杂乱带来的调试难度与线路故障概率；可靠性作为硬件设计首要原则，针对电机大电流驱动带来的电磁干扰问题进行专项优化，区分大功率动力回路与微弱数字信号回路，电源输入端增设大容量储能电容与滤波电容组，数字信号通路搭配缓冲芯片实现电平隔离与噪声滤除，同时规划合理的地层分割、电源走线宽度，削弱电机启停、PWM 高速切换产生的电磁串扰；简洁性体现在功能高度集成，将电源转换、电机驱动、信号缓冲、外设接口全部整合至单块 PCB，元器件排布紧凑规整，便于整车底盘装配、检修与后期参数调试。
3.2 电路设计方案
本系统采用MIMXRT1064 主控 + 电机驱动一体化单板架构，电路集成多路稳压电源、信号缓冲、功率驱动、外设通信四大模块，摒弃传统分板设计，从硬件层面削弱强弱电之间的电磁干扰。整车供电输入为 12电压，通过 RT8289GSP同步降压芯片输出 5V/5A 电源给上位机供电，通过两个TPS54331DDAR 降压芯片分别12V 转 5V 为编码器、无线串口等供电，12V 转 5V 专为舵机供电，5V 电压经稳压电路与 BZT52C16 稳压管降压生成 3.3V，供给陀螺仪、蜂鸣器、按键、状态指示灯等低压外设；各电源支路搭配 220μF、47μF 电解电容与 100nF、470pF 瓷片电容组合滤波，配合分压采样电阻稳定输出电压。
功率驱动部分增设专用缓冲电路，RT1064 输出的 PWM 调速、方向控制信号先经过缓冲芯片隔离整形，再输入全桥电机驱动回路，板载编码器采集接口用于实时采集电机转速；电路板集成标准化排针接口，包含舵机接口、陀螺仪通信端子、无线串口、屏幕接口、调试按键与状态指示灯，预留 AI 模块通信引脚，可完成图像传输、速度闭环控制、整车调试等全部功能。硬件绘制全程使用嘉立创 EDA 完成原理图绘制与 PCB 布局，强弱电区域分区布线，有效抑制电机启停产生的噪声干扰，保障智能车长时间稳定运行。

第四章 软件控制算法
本系统的软件控制算法分为上位机视觉感知与行为决策算法和下位机底层实时控制算法两大部分。上位机负责摄像头图像采集、深度学习目标检测、行为树决策控制与岔路口云AI识别；下位机负责电机转速PID闭环控制、舵机角度控制和航迹推算定位。上下位机通过UART串口协议协同工作，共同实现智能车的自主导航。
4.1 上位机视觉感知与目标检测
上位机视觉感知系统基于Orange Pi 5 Pro的RK3588S NPU（6 TOPS算力）实现。摄像头以640×480分辨率、30fps帧率采集RGB图像，通过共享内存（POSIX shm）传递给AI推理模块。推理模块使用PP-YOLOE+深度学习模型，该模型经过INT8量化后转换为RKNN格式，部署在RK3588S的三核NPU上。系统采用多核并行推理策略（rknnPoolExecutor），将连续帧以轮询方式分配到NPU Core 0/1/2上，充分利用三核NPU的并行算力，实现30~60fps的实时目标检测。
检测目标类型包括：赛道引导线（stra）、障碍物（car/person）、金币（gold/coin）、路牌（paizi）等。模型输出的边界框经过NMS（非极大值抑制）后处理和置信度过滤（阈值0.5），最终以ROS2自定义消息（XcarTargetList）发布到/xcar/target_info话题，供下游行为树控制节点使用。
模型后处理在func.py中实现，包含以下关键步骤：（1）BGR到RGB色彩空间转换与640×640尺寸缩放；（2）均值/方差归一化与NCHW通道重排；（3）NPU推理输出后根据输出张量形状自动路由到DFL解码分支或平坦解码分支；（4）逐类NMS去重与二次置信度过滤。该实现完全基于NumPy，不依赖PyTorch等深度学习框架，适合边缘端轻量化部署。
4.2 行为树决策控制
上位机的行为决策基于BehaviorTree.CPP（v4）行为树框架实现。行为树以30Hz频率tick运行，每帧从/xcar/target_info话题获取检测结果，经过坐标缩放（640×480→320×320模型空间）后存入共享状态黑板（Blackboard），由各行为节点读取并执行相应的控制策略。行为树结构为：Sequence{Parallel{LineTrack, Fallback{ObstacleAvoid, CoinGet}}, Controller}。
4.2.1 巡线算法（LineTrack）
巡线节点从检测结果中提取赛道引导线（stra类）的像素坐标，采用加权评分机制筛选最佳跟踪点。对于每个候选线点(x, y)，计算评分：score = |y - forward_view_y| + x_penalty × |x - ref_mid_x|，其中forward_view_y=160（图像近端），ref_mid_x=100（偏左参考点，适用于双线场景）。选择评分最低的点作为跟踪目标，通过相机视场角（FOV=120°）将像素偏差转换为转向角度：angle = (x - 160) / 320 × 120（度）。
当检测到岔路口（x方向散布超过30px且路牌在0.5s内出现）时，系统触发岔口模式：首先通过/xcar/fork_trigger话题发送路牌检测框坐标（640×480空间），触发百度文心多模态大模型（ernie-4.5-turbo-vl）对路牌进行识别。系统从共享内存中读取AR渲染后的视频帧，裁剪路牌区域，以base64编码发送至文心API，使用低温（temperature=0.1）确保输出稳定，由API返回LEFT/RIGHT/UNKNOWN决策。根据决策结果，巡线算法仅保留选择侧的点（如LEFT仅保留x<160的点），并通过转向缩放和强制转向窗口（1.0s内维持60°×2=120°的转向角）确保完成转弯。
4.2.2 避障算法（ObstacleAvoid）
避障节点基于障碍物（car/person类）与赛道引导线的相对位置关系进行触发判断。当car类障碍物的中心Y坐标与最近线点的Y坐标差小于100px（即障碍物接近行驶路径），或person类障碍物的此差值小于40px（人员类更危险，仅在非常接近时触发）时，启动避障。避障方向为障碍物所在位置的反方向：障碍物在右侧则向左转30°，障碍物在左侧则向右转30°。避障偏移量叠加在线巡结果上，持续100ms后自动清除。在避障期间，收金币行为被阻塞（优先级低于避障）。
4.2.3 收金币算法（CoinGet）
收金币节点对检测到的金币目标逐帧计算吸引力权重：weight = area_ratio × (coin_y / IMG_HEIGHT) × COIN_WEIGHT_SCALE（限制在[0, 1.0]区间），金币面积越大且越靠近图像底部时权重越大。金币的像素偏差同样通过FOV公式转换为转向角度。当金币角度偏差超过40°时忽略该金币，防止车辆冲出赛道追逐偏远的金币。

4.2.4 多任务融合控制（Controller）
Controller节点融合巡线、避障、收金币三个子任务的输出，使用加权平均公式：final_angle = (line_angle + obs_weight × obs_angle + coin_weight × coin_angle) / (1 + obs_weight + coin_weight)。融合后的角度经过舵机保护限幅（±75°）和5°死区滤波后，与目标速度（默认0.2m/s，岔口转弯时降为0.12m/s）一同通过12字节定长帧协议经UART发送至RT1064下位机执行。当赛道丢失超过0.5s时触发紧急停止；当赛道短暂丢失（但检测数据保持新鲜）时以45°右转寻找赛道。

4.3 下位机底层实时控制
下位机基于NXP RT1064（Cortex-M7，600MHz）微控制器，使用逐飞科技开源库（SeekFree v3.7.2）开发，所有控制逻辑在定时器中断服务程序（ISR）中执行，确保实时性。控制任务分为四个时间片：2ms捕获线程（编码器速度计算+IMU陀螺仪航向角积分）、5ms电机内环（PID计算+PWM输出）、20ms定位更新（航迹推算+位置回传）和20ms底盘外环（接收上位机指令+设定参考值）。
电机控制采用增量式PID控制器，Kp=400，Ki=15000，Kd=0，最大输出6000（PWM满量程），采样周期5ms（200Hz控制频率）。编码器为512线正交编码器，经4倍频解码和2.7:1减速比后，通过1D卡尔曼滤波器（参数：Q=0.01，R=0.1）对原始编码器计数值进行滤波，再转换为实际速度（m/s）。舵机控制使用50Hz PWM（中点750，量程±250对应±90°），角度限幅±80°。
IMU模块使用ICM20602六轴传感器（SPI接口），上电时进行200次陀螺仪Z轴零偏校准（附加0.012°/s修正量），每2ms读取陀螺仪Z轴数据并累积积分得到航向角，通过0.25°/s死区滤波器抑制静止漂移。
航迹推算定位模块每20ms执行一次：根据当前速度v和航向角yaw，在世界坐标系中更新位置：x += v×cos(yaw)×dt，y += v×sin(yaw)×dt。定位结果通过UART以16字节帧（帧头0xFE，命令0xA1，3个float X/Y/Yaw，帧尾0xEF）回传给上位机，供AR渲染引擎和裁判系统记录使用。

第五章 开发工具、制作、安装、调试过程说明

// ========== 上位机: 行为树巡线算法 (car_control.cpp 节选) ==========
// LineTrack::tick() - 加权评分选择最佳跟踪点
NodeStatus LineTrack::tick() {
    // 获取检测结果中的线点
    auto line_points = shared_state_->line_points;
    if (line_points.empty()) return NodeStatus::FAILURE;

    // 加权评分: 综合考虑纵向距离和横向偏移
    float best_score = 1e9;
    cv::Point2f best_point;
    const float forward_view_y = 160.0f;  // 近端预瞄点
    const float ref_mid_x = 100.0f;       // 偏左参考点(双线场景)

    for (const auto& pt : line_points) {
        float y_diff = std::abs(pt.y - forward_view_y);
        float x_penalty = 0.5f * std::abs(pt.x - ref_mid_x);
        float score = y_diff + x_penalty;
        if (score < best_score) {
            best_score = score;
            best_point = pt;
        }
    }

    // 像素偏差转角度 (FOV=120°, 图像宽度=320)
    float angle = (best_point.x - 160.0f) / 320.0f * 120.0f;
    shared_state_->line_angle = angle;
    return NodeStatus::SUCCESS;
}

// ========== 上位机: 多任务融合控制 (car_control.cpp 节选) ==========
// Controller::tick() - 加权角度融合
NodeStatus Controller::tick() {
    auto& s = *shared_state_;
    float line_angle = s.line_angle;
    float obs_angle = s.obstacle_angle;
    float obs_weight = s.obstacle_active ? 1.0f : 0.0f;
    float coin_angle = s.coin_angle;
    float coin_weight = s.coin_weight;

    // 加权平均融合
    float final_angle = (line_angle +
        obs_weight * obs_angle +
        coin_weight * coin_angle) /
        (1.0f + obs_weight + coin_weight);

    // 舵机保护限幅 ±75°
    final_angle = std::clamp(final_angle, -75.0f, 75.0f);

    // 5°死区
    if (std::abs(final_angle) < 5.0f) final_angle = 0.0f;

    // 岔口转弯减速
    float velocity = 0.2f;
    if (s.fork_state.is_active) velocity = 0.12f;

    // 通过UART发送给RT1064下位机
    send_package(final_angle, velocity);
    return NodeStatus::SUCCESS;
}

// ========== 上位机: 文心大模型岔口决策 (fork_decision_node.py 节选) ==========
def analyze_fork_image(image_bgr, paizi_box):
    """裁剪路牌区域并调用文心API进行方向决策"""
    x1, y1, x2, y2 = [int(v) for v in paizi_box]
    cropped = image_bgr[y1:y2, x1:x2]  # 裁剪路牌区域

    # Base64编码

    _, buffer = cv2.imencode(".jpg", cropped)
    img_b64 = base64.b64encode(buffer).decode()

    # 调用百度文心多模态大模型
    response = client.chat.completions.create(
        model="ernie-4.5-turbo-vl",
        messages=[{
            "role": "user",
            "content": [
                {"type": "image_url",
                 "image_url": {"url": f"data:image/jpeg;base64,{img_b64}"}},
                {"type": "text", "text": FORK_PROMPT},
            ]
        }],
        temperature=0.1,
        max_tokens=10,
    )
    return response.choices[0].message.content  # LEFT / RIGHT / UNKNOWN

// ========== 下位机: PID速度控制与卡尔曼滤波 (dc_motor.c 节选) ==========
// 2ms周期: 编码器读取 + 1D卡尔曼滤波 + 速度计算
void Motor_UpdateSpeed(motor_t *motor) {
    // 读取并清零编码器计数值(4倍频)
    int32_t raw_counts = encoder_get_count(motor->encoder);
    encoder_clear_count(motor->encoder);

    // 1D卡尔曼滤波, 参数: Q=0.01, R=0.1
    float filtered_counts = KF1_Calculate(

        &motor->kf, (float)raw_counts);


    // 速度计算: v = (counts * pi * D) / (dt * PPR * 4 * ratio)

    motor->velocity = (filtered_counts * PI * WHEEL_DIAMETER) /
        (CAPTURE_CONTROL_TIME * ENCODER_PPR * 4 * REDUCTION_RATIO);

}

// 5ms周期: 增量式PID计算 + PWM输出
void Motor_ControlLoop(motor_t *motor) {

    float error = motor->speed_ref - motor->velocity;

    // 增量式PID: Δu = Kp*(e_k - e_{k-1}) + Ki*Ts*e_k
    float p_term = MOTOR_KP * (error - motor->last_error);
    float i_term = MOTOR_KI * MOTOR_CONTROL_TIME * error;
    motor->pid_out += (p_term + i_term);


    // 输出限幅
    motor->pid_out = CLAMP(motor->pid_out,

        -MOTOR_MAX_OUTPUT, MOTOR_MAX_OUTPUT);


    // 设置PWM: 符号控制方向, 幅值控制占空比
    int16_t pwm_val = (int16_t)motor->pid_out;
    gpio_write(motor->dir_pin, pwm_val >= 0 ? 0 : 1);
    pwm_set_duty(motor->pwm, (uint16_t)abs(pwm_val));

    motor->last_error = error;
}

// ========== 下位机: IMU航向角解算 (imu.c 节选) ==========
void IMU_UpdateYaw(imu_t *imu) {

    // 读取陀螺仪Z轴角速度
    float gyro_z = icm20602_read_gyro_z();


    // 减去零偏并死区滤波(0.25°/s)

    float rate = gyro_z - imu->gyro_offset_z;
    if (fabs(rate) < 0.25f) rate = 0.0f;


    // 欧拉积分: yaw += omega * dt
    imu->yaw_deg += rate * CAPTURE_CONTROL_TIME;
}


// ========== 下位机: 航迹推算定位 (localization.c 节选) ==========
void Loc_Update(localizer_t *loc, float velocity, float yaw_rad) {
    // 世界坐标系下位置更新 (20ms周期)
    loc->x += velocity * cosf(yaw_rad) * LOCALIZATION_CONTROL_TIME;

    loc->y += velocity * sinf(yaw_rad) * LOCALIZATION_CONTROL_TIME;
    loc->yaw = yaw_rad;
}


// ========== 通信协议: UART定长帧 (vision.c / fixed_packet.hpp 节选) ==========
// 上位机→下位机 12字节帧:
// [0xFE] [cmd] [float velocity] [float angle] [reserved] [0xEF]
// 下位机→上位机 16字节帧:

// [0xFE] [0xA1] [float x] [float y] [float yaw] [0x0A] [0xEF]

// 帧解析状态机
void vision_data_handler(uint8_t byte) {

    switch (state) {
    case STATE_WAIT_HEAD:
        if (byte == 0xFE) state = STATE_RECV_DATA;
        break;

    case STATE_RECV_DATA:
        buffer[idx++] = byte;

        if (idx == 11) {
            if (byte == 0xEF) {

                // 解析速度与角度
                memcpy(&speed_ref, &buffer[2], 4);
                memcpy(&angle_ref, &buffer[6], 4);
            }
            state = STATE_WAIT_HEAD;
            idx = 0;
        }
        break;
    }
}
