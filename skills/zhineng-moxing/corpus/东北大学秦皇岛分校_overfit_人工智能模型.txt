引  言
全国大学生智能汽车竞赛自2006年创办以来，已成功举办二十届，是国内最具影响力的大学生科技创新赛事之一。竞赛始终秉持"立足培养、重在参与、鼓励探索、追求卓越"的指导思想，鼓励参赛学生综合运用控制理论、信号处理、计算机视觉、嵌入式系统等多学科知识，完成具有挑战性的工程实践任务。
随着人工智能与自动驾驶技术的迅猛发展，竞赛组委会在第二十一届赛事中首次设立了"人工智能模型"组别。该组别要求参赛队伍以RK3588为核心计算芯片及板卡，部署自行训练的AI模型，完成对赛道元素的检测、识别与理解，并据此实现车辆的自主导航与决策控制。这一组别着眼于考察参赛队伍在模型设计、训练、部署与推理优化等方面的综合能力。
本文详细介绍了本团队参赛作品的整体设计方案。此智能车设计方案以RK3588为核心计算芯片及板卡，部署自行训练的AI模型，实现从底层道路分割到高层语义理解的完整感知链路，能够应对岔路导航、红绿灯识别、障碍物避让、行人判断等多种特殊场景，能够较好的完成赛规要求的运行任务。

第一章  系统整体设计概述
1.1  系统概述
本智能车系统以"采集-感知-决策-执行"为技术主线，构建了一条完整的自动驾驶数据处理链路。系统从摄像头获取实时图像数据后，依次经过预处理、AI模型推理，再经过决策控制综合感知结果生成运动指令，最终通过串行通信接口下发至底层MCU，驱动电机和舵机实现自主行驶。
1.2  硬件平台
本系统以RK3588为核心计算平台，主要硬件组成如下：
（1）主计算单元：RK3588采用ARM big.LITTLE大小核架构（4×A76大核 + 4×A55小核），集成神经网络处理单元（NPU），可提供充足的推理算力，支持INT8/FP16等多精度推理。主控平台运行Linux操作系统，负责全部AI模型推理和控制逻辑的执行。
（2）图像传感器：采用USB接口的CMOS摄像头模组，具备高动态范围和自动曝光控制能力。摄像头采集的原始图像通过共享内存（SHM）机制与主控程序进行零拷贝数据传输。图像分辨率为640×480。
（3）底层运动控制器：独立MCU负责电机和舵机的实时闭环控制，接收主控单元通过UART串口发送的速度和转角指令，同时采集编码器速度反馈和姿态传感器数据。MCU与主控之间采用自定义串口通信协议。
（4）电源系统：采用11.1V锂电池供电，通过多级DC-DC变换电路为不同电压需求的模块提供稳定电源。主控单元和MCU系统采用独立的电源回路，并通过共模滤波和地线分割抑制噪声串扰。
（5）通信模块：配备WiFi模块用于调试阶段的视频推流和远程监控，正式比赛时可通过配置文件关闭无线通信功能。
1.3  软件架构总览
系统软件整体上分为四个功能层次：采集层、感知层、控制层和输出层。各层之间通过全局共享数据结构实现高效的数据传递，遵循生产者-消费者模式。

采集层负责从摄像头获取原始图像数据，通过共享内存机制实现高效的帧数据传输。感知层包含目标检测模型、语义分割模型和OCR识别模块，分别在独立线程中运行，对每一帧图像进行分析，提取赛道元素和道路区域信息。控制层是系统的决策中枢，综合感知层的输出结果，经过巡线、轨迹规划、场景处理和速度决策等运算，生成运动控制指令。输出层负责将控制指令通过串口发送给底层MCU，并同时提供MJPEG视频流用于实时调试监控。
第二章  车模机械结构设计
2.1  车模整体介绍
本作品使用C车车模作为基础平台。车模采用后轮驱动、前轮转向的经典布局，具有良好的对称性和操控稳定性。车模底盘尺寸约为316mm×190mm×110mm，轮胎尺寸约为26mm×62mm。采用380直流驱动电机（额定电压7.2V）和BDS300舵机（工作电压7.4V）。
针对人工智能模型组比赛的实际需求，我们进行了以下适应性改造：更换底盘以实现更灵活转向，后轮差速器上加装编码器以实现精确的速度闭环控制。
2.2  传感器安装与布局
本车模搭载的主要传感器包括：（1）CMOS摄像头×1，安装于车模前部上方，通过法兰座及碳杆固定，安装高度约15cm，俯仰角约15°，提供前方道路的完整视野。（2）编码器×2，分别安装于左右后轮，检测车轮转速，为速度闭环控制提供反馈。（3）六轴IMU姿态传感器×1，安装于车模主板，用于检测车体的横滚角、俯仰角和偏航角速率。
传感器布局遵循以下原则：摄像头置于车辆中轴线上以获得对称的前向视野；IMU传感器尽可能靠近车辆质心安装以减小杆臂效应带来的测量误差；编码器安装确保与车轮转轴的同轴度，避免偏心导致的转速测量波动。
2.3  电路板固定与连接
车模搭载的主要电路板包括RK3588核心板及底板、MCU控制电路板和电机驱动板。各电路板通过铜柱固定在车模PETG层板上，板间通过排线、杜邦线和焊接导线连接。全部连接线缆采用扎带或热缩管固定，防止车辆运动过程中的松动和缠绕。
第三章  硬件电路设计
硬件电路是实现系统各项功能的基础支撑。本系统的电路设计遵循模块化、可靠高效的原则，主要包括电源管理系统、MCU控制电路、电机驱动电路以及通信与传感器接口电路四个部分。
3.1  电源管理系统
电源管理系统负责将11.1V锂电池的输出电压转换为各模块所需的不同电压等级，并确保各电压轨的稳定性和隔离性。系统主要包含以下电压轨：12V直通输出（经防反接保护和共模滤波后直接为主控板和驱动板供电）、5V/3A稳压输出（基于DC-DC降压芯片，为MCU和传感器供电）、7.4V稳压输出（为舵机提供可调工作电压）、3.3V稳压输出（基于LDO，为数字逻辑电路供电）。
电源设计中的关键保护措施包括：输入端串联MOS管实现防反接保护；各电压轨输出端并联多颗不同容值的电容（电解电容+陶瓷电容），兼顾低频和高频滤波效果；大功率回路与信号回路采用分割地平面设计，通过单点连接减少相互串扰。
3.2  电机驱动电路
电机驱动电路负责将MCU输出的低压PWM控制信号转换为驱动电机所需的大电流功率输出。驱动电机采用H桥电路拓扑，由半桥栅极驱动芯片（DRV8701）和N沟道功率MOSFET组成。H桥支持正反转控制和PWM调速。舵机直接从7.4V电源轨取电，MCU的PWM信号经过电平转换后直接驱动电机。
驱动电路设计中采取了以下保护措施：栅极驱动芯片内置死区控制和欠压锁定功能，防止上下桥臂直通短路；电源输入端并联大容量电解电容，吸收电机换向时的电流尖峰；功率MOSFET选取低导通电阻型号以降低导通损耗和发热。
3.3  通信与传感器接口
通信与传感器接口电路包括：编码器信号接口（5V供电、AB双相脉冲输出，配置上拉电阻和RC滤波）、IMU姿态传感器I2C接口（3.3V电平，配置上拉电阻）、WiFi模块接口（USB 2.0接口标准）、主控与MCU之间的UART通信接口（3.3V TTL电平，配置瞬态抑制二极管ESD保护）。
第四章  上位机感知系统
4.1  上位机架构设计
感知系统采用多线程流水线架构，将图像采集、AI模型推理和数据传递等任务分配到独立线程中并行执行，以提升系统的整体吞吐量和实时响应能力。以下简要介绍线程模型、CPU资源调度策略和同步机制。
4.1.1  线程模型
系统在启动阶段创建六个核心工作线程：采集线程、目标检测线程、语义分割线程、OCR识别线程、核心控制线程。
4.1.2  CPU资源调度
比赛规定的板卡RK3588拥有4×A76大核 + 4×A55小核与NPU核心，算力较为充足。因此，系统采用多线程架构，按照不同的需求将线程绑定至不同的核中，多线程同时运行，可以很好的满足多个模型共同执行推理任务以及控制的需要。
4.2  感知子系统设计
感知子系统基于标准视觉逻辑框架构建，将常规道路与特殊场景元素统一集成到同一视觉逻辑架构中。系统由三个核心感知模块组成：目标检测模块、语义分割模块和OCR语义导航模块。
4.2.1  目标检测模块
目标检测模块负责在图像中检测并分类比赛规则中定义的全部11类交通标志和赛道元素（包括标志牌、金币、行人、车辆等）。模块将当前帧图像送入NPU进行深度学习推理，输出结构化的目标列表，每个目标包含类别ID、置信度和归一化边界框坐标。检测结果通过全局共享数据结构传递给下游的控制线程。
4.2.2  语义分割模块
语义分割模块提供像素级的道路区域识别能力，对输入图像进行逐像素的二分类，输出与输入图像同尺寸的二值掩码。该掩码为下游巡线提取和轨迹规划提供基础数据。
4.2.3  OCR语义导航模块
当目标检测模块在赛道前方发现岔路标志时，OCR语义导航模块被触发。控制线程触发识别请求后立即返回继续执行控制循环，OCR线程在后台完成文字/语义识别后回传方向结果。
4.2.4  特殊场景处理
比赛中的多种特殊场景元素，如岔路、障碍物、行人等，由元素处理模块进行统一管理。系统根据检测类别自动路由到对应的处理逻辑，每种场景配置独立的内部状态机，能够在多帧之间追踪场景的。
4.3  部署的模型
4.3.1  目标检测模型
官方提供的yoloe目标检测模型并不能很好的满足比赛对推理速度与实时性的需要。因此，在经过对多种模型的测试后，目标检测最终采用picodet模型。模型输入分辨率为416×416，经NPU推理加速后，推理速度较高。
4.3.2  语义分割模型
语义分割延用了官方提供的ppliteseg模型例程。输出逐像素的二分类掩码，为巡线提取提供基础数据。
4.3.3  API调用模型
在岔路导航等需要高层语义理解的场景中，系统通过API调用的方式接入ernie-4.5-turbo-32k大语言模型。该模型负责理解岔路标志图像的语义含义，回传导航决策。
第五章  控制系统与调试方案
5.1  控制流水线概述
控制与决策子系统运行于核心控制线程，是系统的决策中枢。它综合来自目标检测和语义分割两个感知模块的实时输出，经过多阶段串行处理后生成电机目标速度和舵机转角的控制指令，通过UART串口发送至底层MCU。
控制流水线按顺序包含以下主要处理阶段：
帧数据聚合阶段：从全局共享结构中同步获取最新帧图像、检测结果列表和分割掩码。
道路信息提取阶段：基于分割掩码，使用形态学操作提取车道边界和中线信息。
轨迹规划阶段：通过逆透视变换（IPM）将图像坐标映射到鸟瞰图坐标，进行等距采样和曲线拟合，生成平滑的期望行驶轨迹。
特殊场景处理阶段：根据检测结果判断当前场景类型，将控制路由到对应的处理模块。
偏差计算阶段：计算车辆当前位置与期望轨迹之间的横向偏差和角度偏差，处理丢线等异常情况。
速度决策阶段：综合场景类型、偏差大小、前方目标密度等因素，确定目标速度。
指令下发阶段：将速度和转角指令按协议编码后通过UART发送至MCU。
5.2  巡线与轨迹规划
巡线与轨迹规划模块负责从感知结果中提取可行驶路径。系统支持多种巡线方式，可根据场景自动切换。在常规赛道路段，主要基于语义分割输出的道路掩码，通过形态学操作提取车道中线。
为消除单目摄像头透视效应带来的距离失真，模块使用逆透视变换（IPM）将前视图像坐标映射为鸟瞰图坐标。在鸟瞰图坐标系中，沿车道中线进行等距采样获得离散轨迹点，再进行曲线拟合生成平滑的连续期望轨迹。
5.3  速度决策与控制
速度决策模块根据当前场景类型和车辆状态确定目标速度。系统采用分层速度策略，为不同场景预定义不同的基础目标速度：直道巡航速度最高，弯道次之，特殊场景进一步降速，STOP标志和红灯区域目标速度为零。速度切换采用平滑过渡机制，通过增量式PID控制器逐步调整PWM输出。
在密集目标区域，速度决策模块综合目标数量和最近目标距离，计算减速系数进行预防性减速。针对行人场景，系统通过模糊推理控制器综合行人距离、运动趋势和当前车速等因素，生成平滑的减速曲线，在确保安全的同时降低对行驶流畅性的影响。
第六章  下位机控制系统设计
下位机作为智能车“执行层”的核心，负责将上位机（RK3588）通过串口下发的速度与转角指令转化为电机和舵机的实时控制量，同时向上位机反馈编码器速度与姿态信息。本章详细介绍下位机的硬件平台与软件架构、上下位机通信协议，以及电机、舵机底层控制算法和姿态解算、惯导回放、参数调试等功能的实现。
6.1  下位机平台与软件架构
下位机采用英飞凌 AURIX TC264D 双核微控制器作为底层运动控制器，基于逐飞科技（SEEKFREE）提供的 TC264 开源库进行开发，集成开发环境为 AURIX Development Studio（ADS v1.10.2）。TC264D 拥有两个 TriCore CPU 核（CPU0 与 CPU1），本系统中由 CPU0 承担全部实时控制任务，CPU1 作为预留核仅完成看门狗关闭与中断使能等基础初始化。

下位机与上位机之间通过 UART 串口通信，共使用三路串口：UART_0作为调试串口，用于 PC 端在线调参与日志输出；UART_3作为与上位机主控的主通信接口，传输控制指令；UART_1用于扩展与参数整定指令的接收。

为增强通信鲁棒性，中断服务程序中加入了串口卡死检测机制：若一帧数据在 50ms 内未能完整接收（超过 10 个 5ms 周期仍处于接收中状态），则强制复位接收状态机，避免单字节丢失导致的通信死锁。
6.3  舵机转向控制
舵机转向控制是下位机最核心的控制任务，在每个 5ms 中断周期内执行一次。系统采用“增益调度 PID + 陀螺仪前馈 + 延迟预测”的复合控制策略，目标转角由上位机下发的角度偏差与偏差修正量加权合成。
传统固定参数 PID 难以同时兼顾直道稳定性与弯道响应速度，为此系统设计了增益调度机制替代模糊控制。控制器的比例增益 Kp 和微分增益 Kd 根据当前角度误差的绝对值在设定区间内线性插值：在直道小误差工况下采用低 Kp、高 Kd，抑制转向震荡；在弯道大误差工况下切换为高 Kp、低 Kd，加快转向响应。积分增益 Ki 则随误差增大而减小，防止大误差工况下积分饱和。
针对从视觉感知到舵机执行之间的系统延迟，控制算法利用陀螺仪角速度对误差进行前向外推，预测延迟时间之后的真实误差。
6.4  电机速度闭环控制
电机控制负责将目标速度转换为驱动后轮直流电机的 PWM 信号，同样在 5ms 中断周期内执行。
速度反馈来自安装于左右后轮的两个正交编码器（1024 线），通过定时器编码器接口采集脉冲数，结合车轮直径（64mm）和采样周期（5ms）换算出实际轮速。速度环采用位置式 PID 控制器，并加入输出斜率限制实现软启动，避免急加速对传动系统的冲击。
左右轮速度差通过独立的差速 PID 进行校正，将左右轮实际速度差调节至零，抑制直行跑偏。此外，为消除舵机转向时内外侧车轮的线速度差，系统实现了阿克曼转向速度补偿。
6.5  姿态解算
下位机集成 IMU660RA 六轴惯性测量单元，用于车体姿态解算与航迹推算。上电初始化阶段，系统对陀螺仪零偏进行校准。
姿态解算采用 Madgwick 四元数互补滤波算法，在 10ms 周期内融合陀螺仪角速度与加速度计测量值，解算出车体的横滚角、俯仰角和偏航角。相比单陀螺仪积分，四元数滤波能有效抑制积分漂移；相比纯加速度计解算，又能保持动态响应性能。
在姿态解算基础上，系统实现航迹推算功能：以四元数解算出的偏航角为航向，将编码器测得的车轮线速度投影到世界坐标系，对速度积分得到车体位置。航迹推算结果一方面用于惯性导航回放，另一方面通过串口回传给上位机用于调试。
6.6  人机交互与参数调试
为便于现场调试，下位机板载 OLED 显示屏（IPS200，SPI 接口）和四个独立按键，实现了层级式菜单系统。菜单采用树形结构组织，可现场调整速度环 PID、差速 PID、舵机增益调度参数、基准速度以及舵机零位偏移等关键参数，无需重新编译固件。
系统内置 8 组预设配置，覆盖不同赛道工况下的参数组合，调试时可通过菜单一键加载切换，避免逐项手动调参。此外还提供舵机零位自动整定功能：车辆运行时每 1 秒检测偏航角漂移，按漂移量自适应调整舵机零位偏移，直至漂移收敛到阈值以内。
为进一步提升调参效率，系统实现了基于 ASCII 文本协议的参数整定接口。上位机或 PC 端可通过串口下发指令，在线修改舵机增益调度参数，并对每个参数施加范围限幅保护；下位机回读当前参数。该接口将参数整定过程标准化，便于与自动化调参工具对接。
编写了一些便于调试的小工具，例如轨迹记录软件、蓝牙遥控软件等。可提高调试效率，增强可视化体验。

B.1  pid控制函数
float Unclipped_Positional_PID(pid_value *pid, float SetValue, float ActualValue, float Max_I)
{
    pid->Ek = SetValue - ActualValue;
    pid->Ek_total += pid->Ek;
    pid->Ek_total = fmaxf(fminf(pid->Ek_total, Max_I), -Max_I);
    float derivative = pid->Ek - pid->Ek1;
    pid->OUT = (pid->Kp * pid->Ek)
             + (pid->Ki * pid->Ek_total)
             + (pid->Kd * derivative);
    pid->Ek1 = pid->Ek;
    return pid->OUT;
}


float IncrementalPID_Update(IncrementalPID *pid, float tar_speed, float cur_speed) {

    pid->error[0] = tar_speed - cur_speed;

    float delta_pwm = pid->Kp * (pid->error[0] - pid->error[1])
                    + pid->Ki * pid->error[0]
                    + pid->Kd * (pid->error[0] - 2 * pid->error[1] + pid->error[2]);

    if (delta_pwm > pid->max_delta_pwm) delta_pwm = pid->max_delta_pwm;
    else if (delta_pwm < -pid->max_delta_pwm) delta_pwm = -pid->max_delta_pwm;


    pid->error[2] = pid->error[1];
    pid->error[1] = pid->error[0];

    return delta_pwm;
}

B.2  舵机类模糊控制自动调参
static void sched_gain_update(pid_value *pid, float e)
{
    float abs_e = fabsf(e);
    float t;

    if (abs_e <= sched_e_low) {
        t = 0.0f;
    } else if (abs_e >= sched_e_high) {
        t = 1.0f;
    } else {
        t = (abs_e - sched_e_low) / (sched_e_high - sched_e_low);
    }

    pid->Kp = sched_kp_low  + (sched_kp_high - sched_kp_low) * t; //大误差升p
    pid->Kd = sched_kd_low + (sched_kd_high  - sched_kd_low) * t;  // 大误差→升Kd
    pid->Ki = sched_ki_high + (sched_ki_low  - sched_ki_high) * t;  // 大误差→降Ki
    sched_cur_max_I = sched_i_max_high + (sched_i_max_low - sched_i_max_high) * t;
}

B.3  电机控制函数
float* motor_ctrl(float target_speed,float uart_speed_p,float angle){
    static float debug[4];
    static float speed_out = 0.0f;          // speed loop ramped output (positional + soft start)
    float left_speed = 0;
    float right_speed = 0;
    float actual_avg_speed, actual_diff_speed;
    float diff_out = 0, pwm_l = 0, pwm_r = 0, target_out = 0, ramp = 0;

    if(angle > 1000.0f)target_speed = 0.0f;

    // 每拍统一读速度(会清编码器, 避免停车期间累积假速度)
    left_speed  = get_currentspeed(1);
    right_speed = - get_currentspeed(0);
    actual_avg_speed = ((left_speed + right_speed) / 2.0f) * 100.0f;   // cm/s
    actual_diff_speed = (left_speed - right_speed) * 100.0f;

    // ===== 目标速度为0: 直接停车 =====
    if(fabs(target_speed * uart_speed_p) < 0.01f && fabs(actual_avg_speed) < 0.1f){
        pwm_set_duty(MOTOR_PWM_PIN_L, 0);
        pwm_set_duty(MOTOR_PWM_PIN_R, 0);
        speed_out = 0.0f;
        debug[0] = left_speed;
        debug[1] = right_speed;
        debug[2] = 0;
        debug[3] = 0;
        return debug;
        }
    // ===== 正常行驶 =====

    else{
        float target  = target_speed * uart_speed_p * 100.0f;   // cm/s
        target_out = Unclipped_Positional_PID(&motor_pid, target, actual_avg_speed, 1000.0f);   // positional speed loop
        if(fabs(target) < 0.01f){
            // 停车过程(目标为0但车还在动): 不做斜坡限制, PID输出直接生效, 快速刹车
            speed_out = target_out;
        }
        else{
            // 启动/正常行驶: 斜坡限制(软启动), speed_out每拍最多变化OUTPUT_RAMP_STEP
            ramp = target_out - speed_out;
            if(ramp >  OUTPUT_RAMP_STEP) ramp =  OUTPUT_RAMP_STEP;
            if(ramp < -OUTPUT_RAMP_STEP) ramp = -OUTPUT_RAMP_STEP;
            speed_out += ramp;
        }
        diff_out = Unclipped_Positional_PID(&diff_pid, 0.0f, actual_diff_speed, 0.0f);
    }

    speed_out = (speed_out > PWM_MAX) ? PWM_MAX : (speed_out < -PWM_MAX ? -PWM_MAX : speed_out);

    // ===== 合并输出 +  方向 + PWM =====
    pwm_l = speed_out + diff_out;
    pwm_r = speed_out - diff_out;

    pwm_l = (pwm_l > PWM_MAX) ? PWM_MAX : (pwm_l < -PWM_MAX ? -PWM_MAX : pwm_l);
    pwm_r = (pwm_r > PWM_MAX) ? PWM_MAX : (pwm_r < -PWM_MAX ? -PWM_MAX : pwm_r);
    if(fabs(pwm_l) < PWM_DEADZONE)pwm_l = 0.0f;
    if(fabs(pwm_r) < PWM_DEADZONE)pwm_r = 0.0f;
    uint8 dir_l = 0;
    uint8 dir_r = 1;
    if(pwm_l < 0 ){
        dir_l = 1;
        pwm_l = -pwm_l;
    }

    if(pwm_r < 0){
        dir_r = 0;
        pwm_r = -pwm_r;
    }

    gpio_set_level(MOTOR_DIR_PIN_L,dir_l);
    gpio_set_level(MOTOR_DIR_PIN_R,dir_r);
    pwm_set_duty(MOTOR_PWM_PIN_L, (uint32)pwm_l);
    pwm_set_duty(MOTOR_PWM_PIN_R, (uint32)pwm_r);

    debug[0] = left_speed;
    debug[1] = right_speed;
    debug[2] = pwm_l;
    debug[3] = pwm_r;
    return debug;
}
