摘要
本文详细介绍了湖南科技大学“逐龙飞邱”队在全国大学生智能汽车竞赛单车定向组中的系统设计与实现方案。本系统基于N1自行车模型，以英飞凌TC264微控制器为核心控制单元，搭载IMU660RB姿态传感器进行实时状态检测。在姿态解算方面，采用四元数互补滤波算法，有效消除积分漂移并提高动态响应精度。控制系统以三环串级PID（平衡环、速度环、转向环）为基础，结合Pure Pursuit（纯追踪）算法实现高精度的轨迹跟随。动力系统采用CYT2BL3作为FOC无刷电机驱动，提供平滑且强劲的动力输出。针对复杂多变的赛道环境（包含20米往返速度测试、圆内八字慢速绕桩、以及含锥桶、草地、坡道的复杂路径），本系统采用静态数组预设与Flash手推录入相结合的路径规划策略，赋予了单车优秀的自主导航能力、环境适应性和抗干扰性。实验证明，该单车系统运行稳定，动态性能优越，能够圆满完成各科目挑战。

关键词：自平衡自行车；惯性导航；串级PID；四元数姿态解算；Pure Pursuit

第一章 引言
1.1 竞赛背景与组别介绍
全国大学生智能汽车竞赛是一项旨在培养大学生综合知识运用能力、基本工程实践能力和创新意识的科技创意性比赛。本次比赛中，单车定向组提出了极高的控制挑战。该组别要求车模在没有传统四轮车辆侧向稳定性的前提下，仅依靠动量轮或转向控制实现自平衡，并完成复杂的导航任务。
具体而言，比赛分为三大科目：科目一为20米往返测试，主要考察单车在直线行驶状态下的极致速度与基本平衡能力；科目二要求在半径2米的圆内完成八字绕桩，重点考核单车在极慢速状态下的动态稳定性和精确转向控制；科目三则是最贴近实际应用场景的综合测试，包含20米往返并途经锥桶、草地、坡道等复杂路径，全面评估单车的速度、导航精度以及对各种路面干扰的抗干扰能力。

本系统的总体方案围绕“感知、决策、执行”三大环节展开。传感器负责采集环境与车体状态信息，主控单元进行数据融合与控制解算，驱动与执行机构完成最终的动作输出。系统整体架构如下框图所示：

第二章 机械结构设计
2.1 N1车模底盘分析
N1自行车模型作为官方指定车模，具有轻量化、结构紧凑的特点。然而，其原生结构在高速行驶及复杂路面下的表现不尽如人意。主要存在重心分布不合理、部分塑料件刚性不足、轮胎抓地力随路面变化剧烈等问题。为了满足各科目严苛的性能要求，必须对底盘及相关机械结构进行系统性的分析与重构。
2.2 重心设计策略
单车的平衡控制本质上是一个倒立摆问题。根据倒立摆的物理模型，其运动微分方程在小角度近似下可表示为：
d2θ = fracglθ
其中，d2θ 为角加速度，g 为重力加速度，l 为等效重心高度，θ 为倾角。
由公式可知，重心高度 l 越大，单车倾倒时的角加速度 d2θ 越小，意味着车体倒下的趋势更平缓，留给控制系统的调节时间越充裕。因此，我们采取了“重心上移”的设计策略，通过在车体顶部合理添加配重块，人为提高了系统的整体重心，显著降低了平衡控制的难度，提升了稳定性。
2.3 前轮转向机构优化
自行车前轮的自稳定特性很大程度上取决于前叉的几何参数，尤其是拖曳距（Trail）。拖曳距的计算公式为：
Trail = fracR cos(α)sin(α) - d
其中，R 为车轮半径，α 为头管角（Head Tube Angle），d 为前叉偏移量。
为了增加车辆行驶过程中的直线稳定性和恢复力矩，我们对前轮转向机构进行了优化。我们将前叉安装在最前端的空位处，通过这种方式增大了头管角 α 并有效增长了拖曳距，使单车在高速冲刺（科目一）和复杂路面（科目三）下具备更好的航向保持能力。

2.4 后轮电机固定板定制
原厂提供的后轮电机固定板为塑料材质，在频繁加减速和受力扭转时容易发生形变，导致动力损耗和控制滞后。为此，我们定制了高强度的碳纤维板替代原有塑料件，大幅提升了结构刚性和动力传导效率。

3.2 主控制板设计
3.2.1 主控芯片选型与电路设计
在单车定向组中，复杂的姿态解算算法（如卡尔曼滤波）和无刷电机高频控制对主控芯片的算力提出了极高要求。我们对比了常用的基于ARM Cortex-M4架构的芯片与英飞凌TC264。TC264拥有两个主频高达300MHz的TriCore内核，内置浮点运算单元(FPU)，在数学矩阵运算和实时控制任务响应上具有显著优势，因此最终选定TC264作为系统大脑。
电源管理是硬件系统的基础。单车采用两节3.7V串联的锂电池（额定7.4V，满电约8.4V）供电。为主控板上不同的数字逻辑和模拟器件提供稳定的电压，系统设计了多级降压电路：利用高效开关稳压芯片将7.4V降压至5V为主外设供电，再由LDO线性稳压器从5V降至3.3V为TC264及关键传感器供电。此方案兼顾了电源转换效率与输出电压的低纹波特性。
3.2.2 PCB对称布局与布线
单车的物理平衡对其动态控制至关重要。若PCB左右重量分布不均，将导致控制算法需输出额外的静态平衡扭矩。因此，在嘉立创EDA中进行PCB设计时，严格遵循了“左右对称，重心居中”的原则。
主控芯片布置在电路板中轴线上，大质量元件（如电解电容、连接器）沿中轴线对称分布。布线时采用模拟地与数字地单点接地的方案，减少大电流回路对传感器微弱信号的干扰。

3.3 无刷电机驱动板设计
3.3.1 驱动方案选择与CYT2BL3应用
无刷直流电机（BLDC）的驱动常采用六步换相控制或磁场定向控制（FOC）。六步换相控制实现简单，但在低速时扭矩脉动大；FOC控制可以实现电机电流的连续平滑控制，运行噪音低、效率高。由于单车需要在极低速甚至零速下保持平衡，FOC驱动方案是必然选择。
本系统选用英飞凌CYT2BL3作为专用驱动芯片，其内部集成了高性能的栅极驱动器和相电流采样运放，能够精准驱动外部MOSFET桥臂。
3.3.2 FOC控制核心算法原理
FOC控制的核心在于将三相静止坐标系下的交流电流，转换为两相旋转坐标系下的直流分量，从而实现类似直流电机的独立力矩控制。其关键数学变换如下：
Clark变换：将三相定子坐标系（A, B, C）转换为两相正交静止坐标系（α, beta）：
beginbmatrix i_α i_beta endbmatrix = frac23 beginbmatrix 1 & -frac12 & -frac12 0 & fracsqrt32 & -fracsqrt32 endbmatrix beginbmatrix i_a i_b i_c endbmatrix
Park变换：结合转子电角度 θ，将静止正交坐标系（α, beta）转换为随转子旋转的坐标系（d, q）：
beginbmatrix i_d i_q endbmatrix = beginbmatrix cosθ & sinθ -sinθ & cosθ endbmatrix beginbmatrix i_α i_beta endbmatrix
在实现中，我们将交轴电流 i_q 作为目标转矩控制量，直轴电流 i_d 设定为0，由CYT2BL3完成SVPWM波形的生成。实测显示，闭环响应时间小于2ms，满足竞赛对电机动态响应的要求。
3.4 传感器模块设计
3.4.1 姿态传感器
单车控制系统的反馈输入主要依赖于实时精确的姿态数据。系统选用了逐飞科技的IMU660RB传感器模块，其内部核心集成芯片为ST的LSM6DSRTR六轴传感器。
对比常规的MPU6050，LSM6DSRTR支持更高的输出数据速率（ODR）且内置硬件有限状态机，可显著降低主控的读取开销。其加速度计量程配置为±4g，陀螺仪量程配置为±2000dps，能够敏锐捕捉车体微小的倾角变化。通信接口采用硬件SPI，最高时钟可达10MHz，确保数据采集延迟小于0.5ms。


图3.4 六轴姿态传感器模块

3.4.2 磁编码器
为获取车轮的精准转速及转子位置（供FOC使用），我们在PCB上直接集成了磁编码器。磁编码器芯片布置于电机转轴正上方，配合安装在转轴端部的径向充磁磁铁，通过读取磁场强度的变化来解算绝对角度。该方案避免了传统光电编码器易受灰尘干扰的缺点，在复杂赛道环境下展现出极高的可靠性，角度分辨率高达14-bit。
3.5 执行器模块设计
3.5.1 后轮无刷电机
动力输出方面采用外转子三相无刷电机（带霍尔传感器）。电机外径47.50mm，转子直径35.60mm，高度27mm。较大外径的外转子电机提供了更强的低速转矩，有利于单车的起步与低速平衡。内置的霍尔传感器不仅为电机启动提供了初始相位信息，还与磁编码器数据互为校验，提高了系统的冗余度。

图3.5 后轮无刷电机

3.5.2 转向数字舵机
前轮转向控制选用了BDS300数字舵机。其物理尺寸为40×20×38mm，重量约55g，适配单车的机械结构。
工作在7.4V电压下，该舵机具有最高10kg·cm的堵转扭力和0.13s/60^°的高速响应能力。相较于普通模拟舵机，数字舵机的控制死区更小，能够精准执行主控计算出的PD转向补偿量。实际测试中，在连续急弯赛道上，舵机响应无明显滞后。

3.7 人机交互模块设计
良好的人机交互界面(HMI)有助于脱机运行时的状态确认。显示部分采用IPS200彩屏，通过SPI接口驱动。相较于传统OLED屏，IPS屏幕在户外强光下具有更广的视角和更高的对比度，用于显示当前电池电压、系统运行状态及选定赛道参数。
此外，主控板预留了5个独立按键及1个有源蜂鸣器。按键配合屏幕菜单实现了脱机参数修改、程序状态切换等功能；蜂鸣器则在系统初始化完成、低压报警或发生倾倒故障时提供声学反馈，确保系统运行的安全性与直观性。

第四章 软件系统设计
软件系统是智能汽车的大脑，直接决定了单车的平衡稳定性、路径跟踪的精准性以及应对各种赛道元素的鲁棒性。本章将详细阐述基于英飞凌TC264微控制器的软件系统设计，涵盖总体架构、多任务调度、核心算法（姿态解算、串级PID控制、Pure Pursuit纯追踪导航）及各赛道科目的路径规划策略等。软件系统以严谨的控制理论为基础，通过大量数据的测试与优化，实现了单车的高速稳定运行。
4.1 软件总体架构与调度机制
4.1.1 软件开发环境与模块划分
本系统采用英飞凌32位多核微控制器TC264作为主控芯片，软件开发基于ADS（AURIX Development Studio）集成开发环境进行。TC264具备强大的浮点运算能力和丰富的外设资源，非常适合处理高频的姿态解算与多任务控制。为了提高代码的可读性、可移植性与可维护性，软件系统采用模块化设计思想。系统主要包含硬件驱动层、数据处理层、核心算法层以及应用逻辑层。


图4.1 软件开发环境与模块划分示意图
4.1.2 多任务调度机制
控制系统的稳定性高度依赖于控制周期的精确性与任务执行的确定性。系统利用TC264内部的CCU6定时器，构建了基于定时中断的严格多任务调度框架。不同的控制环路与功能模块根据其对响应速度的要求，被分配到不同周期的中断任务中。

4.2 四元数姿态解算算法
姿态解算是平衡控制的基础。单车的姿态主要由IMU（惯性测量单元）获取的三轴角速度与三轴加速度融合得出。系统在 balance_control.c 中的 quaternion_module_calculate 函数内实现基于四元数的姿态解算，解算周期严格设定为1ms。
4.2.1 传感器数据预处理
陀螺仪采集的角速度数据首先被转换为标准单位弧度每秒（rad/s）。为了减小截断误差并提高精度，转换公式采用：
ω_x = fracfracGYRO_DATA_X10 × 10GYRO_TRANSITION_FACTOR × 0.01745329
对于加速度计数据，系统首先对其进行归一化处理，随后采用一阶低通滤波降低高频机械振动带来的噪声。低通滤波的系数 α 采用动态调整策略：当检测到车体处于静止或微动状态时，α = 0.8 以增强滤波效果；当车体处于剧烈运动状态时，α = 0.5 以减小延迟，保证系统动态响应。
a_filtered = α × a_filtered + (1 - α) × a_raw
4.2.2 误差计算与PI校正
系统利用四元数 q = [q_0, q_1, q_2, q_3]^T 将重力向量从导航坐标系投影到机体坐标系，得到理论重力分量 [g_x, g_y, g_z]：
g_x = 2(q_1 q_3 - q_0 q_2)
g_y = 2(q_0 q_1 + q_2 q_3)
g_z = q_0^2 - q_1^2 - q_2^2 + q_3^2
随后，计算加速度计实际测量向量与理论重力向量的叉积，得到姿态误差 [e_x, e_y, e_z]。例如X轴误差为：
e_x = a_y g_z - a_z g_y
误差项通过PI控制器校正陀螺仪的角速度测量值。为了加快开机收敛速度并保证稳态精度，PI控制器的参数被设计为动态可变：系统启动前0.1秒内，K_p = 10.0 实现快速收敛；进入正常运行后，静止状态下 K_p = 0.4，运动状态下 K_p = 0.32；积分增益 K_i = 0.015，并设置积分限幅为1.0。此外，引入动态积分增益机制，当误差较大时，积分增益按0.1倍率衰减，防止积分饱和。
4.2.3 四元数更新与欧拉角转换
利用校正后的角速度 [ω_x, ω_y, ω_z]，通过一阶龙格-库塔法求解四元数微分方程更新四元数，例如 q_0 的更新公式为：
q_0 = q_0 + frac12 (-q_1 ω_x - q_2 ω_y - q_3 ω_z) dt
最后对更新后的四元数进行归一化，并利用旋转矩阵转换关系计算出当前车体的横滚角（Roll）和俯仰角（Pitch），为后续的角度环控制提供精确的反馈量。
4.3 三环串级PID控制系统
针对单车模型复杂的动力学特性，系统设计了基于角速度环、角度环和导航环的三环串级PID控制架构。三个控制环路自内向外依次嵌套，外环的输出作为内环的输入，以此实现极佳的抗干扰能力和路径跟踪效果。


图4.2 三环串级PID控制系统示意图

4.3.1 角速度环（内环）
角速度环是维持单车平衡的最内侧核心，其执行周期为1ms。角速度环采用位置式PID控制，输入为角度环给定的目标角速度与陀螺仪实际输出的角速度之差。为保证系统高频响应无超调，取消了积分作用，参数设定为 P = 0.005, I = 0, D = 0.001。
为了保护舵机并减少高频抖动，角速度环输出的PWM控制量进行了平滑滤波处理，且舵机PWM的实际更新周期设定为3ms。平滑公式为：
Servo_pwm = 0.45 × Servo_last + 0.55 × Target_pwm
4.3.2 角度环（中环）
角度环用于控制单车的实际侧倾角跟踪目标侧倾角，周期为5ms。输入为导航环输出的目标侧倾角（由航向误差决定）与姿态解算得出的实际侧倾角。角度环同样采用位置式PID，其中比例参数起主导作用，参数配置为 P = 260, I = 0, D = 0.30。微分项的引入有效抑制了车体在恢复直立过程中的超调震荡，其输出直接作为角速度环的目标输入。
4.3.3 导航环（外环）
导航环控制车体沿既定路径行驶，周期为15ms。导航环利用Pure Pursuit算法计算出的航向误差（Error）及角速度（Yaw Rate），采用PD控制律输出目标侧倾角：
Output = K_p × Error_deg - K_d × YawRate
其中，比例系数 K_p = 0.30。为了保证单车在急转弯或大误差情况下不至于因目标倾角过大而发生侧滑跌倒，系统对导航环的输出进行了严格的物理限幅，将目标侧倾角限制在 LEAN_ANGLE_LIMIT = 6 度以内。
4.4 惯性导航与Pure Pursuit算法
4.4.1 航位推算里程计
系统在 nav.c 中实现了基于编码器和陀螺仪航向的航位推算（Dead Reckoning）算法。通过融合后轮编码器得到的微小移动距离 Delta dist 和IMU解算得到的偏航角 Yaw，系统不断累加更新车体在全局平面坐标系下的位置 [X, Y]。
首先将角度转化为弧度，并取反以匹配坐标系方向：
Yaw_current = - Yaw × fracpi180
接着在每次控制周期内分解位移：
X_current = X_current + Delta dist × sin(Yaw_current)
Y_current = Y_current + Delta dist × cos(Yaw_current)
4.4.2 Pure Pursuit 纯追踪算法
为实现高精度的轨迹跟踪，本系统采用了改进的Pure Pursuit（纯追踪）算法。算法的核心在于通过动态前瞻距离在参考路径上寻找目标点，并计算出所需的转向控制量。
1. 动态前瞻距离计算
传统纯追踪算法的前瞻距离固定，难以兼顾高速直道稳定性与低速弯道敏捷性。系统设计了基于车速的动态前瞻距离公式：
L = L_base + |v| × 0.25
其中，基础前瞻距离 L_base = 0.97 m，并施加物理约束 L in [0.65, 1.50] m。高速时前瞻距离变大，防止控制振荡；低速时前瞻距离缩小，提高过弯精度。
2. 目标点搜索与航向计算
算法在已知路径点集中，从当前推进进度点向后遍历，寻找第一个距离车体当前位置大于等于前瞻距离 L 的点作为目标点。若车体与当前推进进度点的距离小于设定阈值（Range），则推进进度索引自动递增。
找到目标点后，计算目标点相对车体的偏差量 (dx, dy)，进而得出目标航向角：
TargetYaw = atan2(dx, dy)
3. 误差处理与平滑滤波
计算出的目标航向角与当前航向角作差得出航向误差，并通过 wrap_pi 函数将其映射至 [-pi, pi] 区间。为避免目标点切换瞬间带来的剧烈扰动，航向误差引入了一阶低通平滑处理：
Error_smooth = (1 - α) × Error_smooth + α × Error_current
其中，平滑系数 α = 0.09，平滑后的误差作为外环PD控制器的直接输入。

为了应对竞赛规定的不同科目和复杂的赛道元素，系统针对路径的获取和分段控制设计了灵活的策略。
4.5.1 静态路径规划（针对科目一、科目三）
对于路径固定的科目，系统采用静态路径点数组 s_static_track_path 预先定义了由9个关键节点构成的路径走向。为了使单车在不同赛道元素下均能处于最佳运动状态，系统引入了分段参数表机制 s_static_segments。不同路段可以独立配置目标速度、PID参数以及前瞻距离参数。

4.6 电机驱动与通信机制
4.6.1 电机闭环控制
单车的纵向速度由独立于主控的电机驱动板实现闭环控制。主控芯片TC264通过UART串口向电机驱动专用芯片CYT2BL3下发目标速度指令。电机控制采用增量式PID控制算法，不仅避免了积分饱和，还能使驱动平滑过渡，减小电机瞬间电流冲击。其控制参数整定为：P = 0.70, I = 0.15, D = 0.10。
4.6.2 蓝牙远程通信
为了方便调试及特定科目要求，系统集成了HC05蓝牙模块进行无线遥控。遥控数据通过中断实时接收，系统解析指令后，通过设定全局变量 global_angle_error，将遥控指令转换为车体的目标倾角误差，从而实现通过倾角变化控制车辆转向与微调的高级操控模式。
4.7 安全保护及状态检测机制
为了防止车辆在异常状态下发生电机过载损坏或对场地人员造成安全隐患，系统建立了一套以100ms为周期的状态监测环，实现全方位的安全保护机制。
最核心的机制是跌倒保护：当由姿态解算得到的俯仰角（Pitch）绝对值超过 20^°，且该状态持续时间超过设定的安全阈值时，系统判定车体已失去平衡或跌倒。此时系统将立即切断控制使能标志位，清零目标速度，强制关闭电机输出与舵机PWM，并触发蜂鸣器发出持续警报。此机制极大地保护了电机堵转带来的烧毁风险，是系统长时间稳定运行的坚实保障。

第五章 系统调试与测试
在全国大学生智能汽车竞赛中，系统调试与测试是确保单车在复杂工况下稳定运行的核心环节。本团队结合软件算法与硬件架构，构建了完整的调试工具链，并针对多项关键参数与实际科目要求进行了深度优化。
5.1 开发调试工具链
针对单车定向组的多主控架构设计，本团队搭建了一套高效、直观的开发调试工具链。为保证开发效率与底层控制的精准性，我们采用了两套独立的IDE环境进行交叉开发。
提出问题：如何实现双核异构平台的代码开发与数据的高速、可视化反馈？
方案比较：传统的串口打印输出速率低且无法直观展示波形；而采用成熟的上位机配合高速通信接口能显著提升调试效率。
具体实现：
在代码开发层面，TC264主控芯片的底层驱动与控制算法采用 AURIX Development Studio (ADS) 编写，该环境对 Infineon 芯片支持完善，编译效率高；CYT2BL3 协处理器则采用 IAR Embedded Workbench 进行开发，以保证图像及部分通信处理的实时性。硬件 PCB 设计完全采用嘉立创 EDA 专业版完成，保证了信号完整性。
在数据回传与可视化方面，系统采用 WiFi-SPI 高速通信模块将传感器数据（如陀螺仪数据、编码器脉冲）以及控制系统内部状态（PID输出值、姿态角）实时打包发送至上位机。上位机软件采用“逐飞助手”与 VOFA+ 进行配合，其中 VOFA+ 用于实时绘制各变量的三维曲线波形。
效果验证：
通过该工具链，数据回传频率可稳定在 200Hz 以上，波形显示延迟小于 10ms。这使得开发人员能以极高的精度观察到系统受到微小扰动时的响应状态，为后续参数整定奠定了坚实的基础。

5.2 陀螺仪零偏校准
惯性测量单元（IMU660RB）在出厂及实际组装后往往存在固有的零点漂移误差。由于单车平衡极度依赖于角速度的积分与姿态的解算，微小的零偏会在短时间内导致严重的姿态角发散。
提出问题：如何消除陀螺仪静态零偏，防止积分漂移引起的系统发散？
具体实现：
系统在上电初始化阶段引入了动态静止零偏校准机制。在上电后的前 2000ms 内，单车必须保持静止。程序以 1kHz 的频率采集陀螺仪三轴数据 ω_x, raw，ω_y, raw，ω_z, raw。通过累加取平均值，计算出当前的零偏补偿量 ω_offset。
ω_offset = frac1N Σ_i=1^N ω_raw(i)
其中 N = 2000 为采样点数。校准完成后，在实际运行过程中，每次读取的陀螺仪数据都会减去该补偿量：
ω_real = ω_raw - ω_offset
效果验证：
实验测试表明，经过该零偏校准流程后，单车静置 10 分钟内解算出的俯仰角（Pitch）和横滚角（Roll）漂移量降低至 0.1^° 以内，极大提高了四元数互补滤波解算的稳定性。
5.3 PID参数整定
单车控制系统采用三环串级 PID 结构，包含内环（角速度环）、中环（角度环）和外环（导航环）。为保证系统稳定性，参数整定必须遵循“由内向外”的原则。
具体实现：
角速度环（内环）：首先关闭角度环与导航环，单独测试角速度环。逐渐增大比例系数 K_p, ω，观察驱动电机的响应速度。利用 VOFA+ 上位机观察响应曲线，当施加阶跃扰动时，若系统响应迅速且超调量控制在 5% 以内，加入适量积分系数 K_i, ω 消除稳态误差。当前系统内环参数整定为 K_p = 12.5，K_i = 0.8，K_d = 2.1。
角度环（中环）：在角速度环闭环运行稳定的前提下，引入角度环。角度环主要起粗调作用。逐步调节角度环的 K_p, θ，使得车模能够在一定角度倾斜时迅速产生反向恢复力矩。
导航环（外环）：导航环接收 Pure Pursuit 算法输出的期望曲率或转角，输出期望姿态角。该环路参数调节最为复杂。利用 WiFi 实时传输航向角偏差，不断迭代 K_p, nav 和 K_d, nav。
效果验证：
经过分层调试，单车在直道行驶时的横向偏差被控制在 ± 5cm 以内；在弯道及掉头动作时，系统均能平滑过渡，无剧烈振荡。
5.4 各科目调试经验
定向组比赛涵盖多种工况，单一的控制参数难以满足全过程需求。本团队针对不同科目实施了精细化调试策略。
科目一：直线高速和掉头
在长直道阶段，系统采用一组较为激进的导航参数，确保速度最大化（平均速度可达 2.8m/s）；当触发掉头标志位时，系统根据分段参数表迅速切换至大阻尼参数组，防止因侧向加速度过大导致侧翻。
科目二：低速平衡与精确跟踪
该科目要求车辆按照规定轨迹精确行进。我们采用手推录入的方式采集标准路径数据。调试过程主要围绕前瞻距离（Lookahead Distance, L_d）和到达半径展开。
L_d = k_v · v + L_d, min
经过多次验证，当前瞻距离随车速动态调整（k_v=0.4），并在弯道处缩小到达半径判定阈值时，系统轨迹贴合度最佳。
科目三：不同路面参数切换
针对摩擦系数变化（如平滑PVC至粗糙路面），系统开发了路面识别与抗干扰独立调参功能。通过监测驱动轮扭矩输出（电流反馈）突变，自动切换到底层电机的增益参数，显著提升了抗干扰能力。


第六章 结论
6.1 参赛总结
备战全国大学生智能汽车竞赛是一次对团队技术实力与协作能力的综合考验。在数月的研发周期中，湖南科技大学逐龙飞邱队分工明确，在底层驱动、硬件设计、控制算法以及上位机开发等多方面进行了深入的探索与技术积累。
期间，我们遇到了众多技术难关。例如初期解算姿态时常出现万向节死锁问题，我们通过引入四元数互补滤波替代欧拉角成功解决；中低速转向时平衡控制不稳定，我们通过建立动力学模型并细化三环串级PID得以克服。团队成员在面对挫折时迎难而上，展现了出色的工程实践能力与问题解决能力。
6.2 创新点
本项目的核心创新点主要体现在以下几个维度：
算法架构：引入了带有自适应校正系数的四元数互补滤波算法，结合三环串级 PID 及 Pure Pursuit 轨迹跟踪算法，实现了极高精度的导航与平衡解耦。
控制策略：设计了分段参数表机制，结合手推录入与算法计算的双路径源方案，使单车能根据不同路段特征动态切换控制参数，灵活应对多种复杂工况。
机械与硬件结构：全车 PCB 采用嘉立创 EDA 设计，实现了严格的质量对称；独创性地采用了碳纤维固定板，通过优化电池与主板位置实现重心上移，增加了等效摆长，使系统拥有更大的调节时间窗口与更好的抗扰动性能。
6.3 未来改进
受限于开发周期与硬件成本，本系统仍存在进一步提升的空间。未来可从以下方面展开优化：
多传感器融合：引入 GPS 与 UWB 室内定位系统，配合扩展卡尔曼滤波（EKF）进行全局坐标精准定位，弥补纯惯性导航累计误差。
先进控制算法：尝试将模型预测控制（MPC）引入平衡与导航系统，利用单车动力学模型在预测时域内进行滚动优化，以期获得更优的瞬态性能。
视觉与轻量化：升级视觉识别网络模型，提升对环境特征的抗噪能力；进一步采用航空铝材或3D打印件对车模骨架进行拓扑优化，降低整车重量，提升极限机动性。

C.3 Pure Pursuit 导航控制核心代码
float Nav_UpdateControl(void)
{
    advance_progress_index(s_active_route);
    profile = update_active_segment();
    lookahead = calc_lookahead(profile);
    lookahead_index = find_lookahead_index(s_active_route, lookahead);

    dx = s_active_route->points[lookahead_index].x - current_x;
    dy = s_active_route->points[lookahead_index].y - current_y;
    target_yaw = atan2f(dx, dy);
    yaw_error = wrap_pi(target_yaw - current_yaw);

    s_smooth_yaw_error = (1.0f - alpha) * s_smooth_yaw_error +
                         alpha * yaw_error;
    yaw_error_deg = s_smooth_yaw_error / DEG_TO_RAD;
    roll_balance_cascade.yaw_cycle.out =
        roll_balance_cascade.yaw_cycle.p * yaw_error_deg -
        yaw_kd * calc_yaw_rate_deg_s();

    return limit_float(roll_balance_cascade.yaw_cycle.out,
                       -roll_balance_cascade.yaw_cycle.out_max,
                        roll_balance_cascade.yaw_cycle.out_max);
}
C.4 PID 控制器核心代码
void pid_control(pid_cycle_struct *pid_cycle, float target, float real)
{
    float error = target - real;
    pid_cycle->i_value += error * pid_cycle->i_value_pro;
    pid_cycle->i_value = func_limit_ab(pid_cycle->i_value,
                                      -pid_cycle->i_value_max,
                                       pid_cycle->i_value_max);

    float diff = error - pid_cycle->p_value_last;
    pid_cycle->out = pid_cycle->p * error +
                     pid_cycle->i * pid_cycle->i_value +
                     pid_cycle->d * diff;
    pid_cycle->out = func_limit_ab(pid_cycle->out,
                                  -pid_cycle->out_max,
                                   pid_cycle->out_max);
    pid_cycle->p_value_last = error;
}
