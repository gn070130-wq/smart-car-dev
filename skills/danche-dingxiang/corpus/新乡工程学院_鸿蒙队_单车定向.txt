第一章 引言
1.1概述
全国大学生智能汽车竞赛是教育部倡导的大学生科技竞赛之一，以“立足培养，重在参与，鼓励探索，追求卓越”为指导思想，旨在培养大学生的综合知识运用能力和工程实践能力。在单车定向组中，比赛规则要求模型车在不依赖地面引导线的前提下，利用惯性测量单元（IMU）及其他传感器，自主识别车身姿态并精准导航至指定目标点。这一命题对车体的机械稳定性、硬件系统抗干扰性以及微控制器的实时计算能力提出了极高要求。目前，针对轮式机器人的姿态解算主要有卡尔曼滤波和互补滤波两种主流算法。卡尔曼滤波精度较高但计算量大，对单片机算力要求较高；互补滤波实现简单、响应快速。本车采用IMU660RC陀螺仪作为唯一环境感知传感器，通过互补滤波算法在TC264微控制器上实时解算车身俯仰、横滚与航向角。
1.2系统整体设计
本车选用英飞凌TC264微控制器作为整车的大脑，该系统架构分为“主控层”与“执行层”。主控层负责高频率采集IMU660RC姿态数据，通过互补滤波与串级PID算法计算出车体的俯仰、横滚姿态偏差及航向偏差；执行层则通过TC264的通用定时器模块（GTM）输出高精度的PWM信号，一路经CYT2BL3无刷主控驱动BDS3620无刷电机产生行进动力，利用磁编码器AS5600读取无刷电机速度形成闭环控制，另一路驱动BDS300舵机实现航向矫正。整车配备3S1650mAh动力锂电池，通过高可靠性降压网络分级稳压。系统整体规划了合理的强弱电隔离与传感器防震安装方案，确保在高速行驶中的稳定性和安全性。
1.3本报告结构
本报告共分为七章：
第一章概述了比赛背景与整体方案；
第二章详细解析了逐飞N1车模的机械结构改造与传感器安装；
第三章为核心硬件电路设计与电源管理方案详解；

第二章 机械结构设计与调整
2.1机械结构总体设计
2.1.1车模选择
依据竞赛规则，单车定向组选用逐飞科技N1单车车模。改造后整车长275mm，宽160mm,高140mm,重量696g，该车模具有轻量化、低重心、轴距紧凑等优点，非常适合高机动性的定向任务，且车模原厂预留了充足的安装孔位，为后续改装提供了极大便利。
2.1.2车模整体布局
车模主体由后轮驱动系统、前轮转向系统、主干支架及电子设备舱组成。为了便于模块化设计与维护，我们将系统划分为：前部转向舵机支架、中部主控与电源分层舱、后部无刷电机。整车采用平铺式布局，重点解决左右侧配重不平衡的问题。
2.2 N1车模改装与加固设计
2.2.1驱动电机与转向舵机的安装
BDS3620无刷电机作为动力源，固定于车模后轮轴旁。电机输出轴与驱动板连接形成闭环反馈，保证了车速控制的高动态响应。
前轮转向采用BDS300舵机，舵机安装支架经过二次刚性加固，消除舵机在高速扫角时产生的微幅抖动，大幅提升了定向的精准度。
2.2.2核心传感器IMU660RC的刚性固定
IMU660RC陀螺仪对车体振动较为敏感。在设计中，我们采用螺丝与高强度塑料柱将陀螺仪模块刚性安装在车体纵向中轴线的正上方（靠近重心位置）。纯铜柱结构保证了陀螺仪与车架之间的物理连接刚性强、无虚位，避免了因固定件松动导致的姿态数据异常波动，确保了偏航角测量的稳定性与可靠性。
2.2.3系统电路板的固定与连接
车模上的主控电路板、无刷驱动板以及各类传感器模块，均采用了螺丝与铜柱组合的刚性固定方式。核心主控板利用M3螺丝与铜柱固定在车体中央支架的指定孔位，这种固定方式提供了稳固的机械支撑和良好的电气绝缘性。即使在车辆高速行驶产生剧烈震动时，电路板也不会发生位移或松动，确保了系统运行的长期稳定性。同时，主控板与驱动板采用上下分层布局，便于后期的硬件维护与排线整理。
2.2.4 电池与整车线路的布置
3S 1650mAh锂电池虽然容量适中，但其重量较大。我们采用竖向居中的方式将其固定在车模中轴线的正下方。电池仓内以扎带紧固，防止车辆在急加速或紧急制动时电池发生位移，避免改变重心位置。所有弱电信号线（如IMU通信线）与强电动力线（电机三相线、电池主线）严格遵守“强弱分离、互相垂直”的布线原则，避免强电脉冲对传感器微弱信号产生电磁耦合干扰。

第三章 硬件设计
硬件系统是整个智能车的心脏和骨骼，决定了控制周期的上限和稳定性。本车队的硬件设计严格遵循“高可靠性、电源纯净、强弱电隔离、可维护性强”四大原则，共设计主控板、无刷驱动板和磁编码器控制板共三块核心PCB，并在PCB设计中着重考虑了电磁兼容性（EMC）。
3.1硬件架构与主控选型
主控制器（Master）：英飞凌TC264微控制器，双核TriCore架构，主频高达200MHz。其强大的算力用于高频采集IMU660RC数据，并通过GTM模块输出高精度PWM波。从控制器（Slave）：CYT2BL3CAAQ0AZSGS无刷驱动专用主控，负责接收TC264的指令并自行完成电机换向控制，减轻主控计算负担。
3.2电源管理模块设计
供电质量直接影响陀螺仪数据的准确性和主控运行的稳定性。因为3S锂电池充满电压高达12.6V，而不同模块所需电压不同，我们设计了严谨的三级降压稳压系统，整车功耗在6-7W左右，电容总容量1664UF。
12V转5V（主控核心供电）：选用了TPS5430高效降压型DC-DC转换器。相较于LDO，TPS5430具有3A的大电流输出能力和高达95%的转换效率，能有效将12V电池电压降至稳定5V，为主控TC264及其外围电路提供纯净能源。设计时，我们特别注意在TPS5430的输入端并联了大容量钽电容和陶瓷电容，以吸收电机突然启动带来的电压浪涌。如图3.2.1所示。

第四章 软件系统设计及实现
4.1软件系统总体设计
本车软件运行在英飞凌 TC264D 平台上，基于逐飞 TC264 开源库完成底层外设驱动调用。软件整体采用“主循环 + 定时中断控制环”的实时控制结构：主循环负责按键事件、显示与低优先级任务；定时器中断负责 IMU 更新、平衡 PID、航向控制和赛道动作时序，保证控制周期稳定。
系统主要由以下模块组成：
主程序初始化：时钟、调试串口、GPIO、PWM、FOC 电机、IMU、PID、定时器和屏幕初始化
中断调度：通过PIT定时中断实现1ms计时、2/5/10/20ms控制环调用
平衡控制：航向环、角度环、角速度环等串级PID控制
IMU姿态处理：IMU初始化、零偏校准、姿态角归一化、异常尖峰剔除
电机控制：通过UART控制无刷FOC驱动器，设置速度/占空比
舵机控制：PWM 输出舵机角度，并进行左右极限保护
按键交互：按键短按/长按状态机，完成启动、复位、模式切换等操作
低优先级任务调度：基于uwtick的简单周期任务调度器，可用于无线调试等非关键任务
PID通用驱动：封装位置式PID、增量式PID、输出限幅和参数设置接口
软件设计思路是将实时性要求最高的平衡控制放在固定周期定时中断中执行，而把显示、按键响应、调试通信等非实时任务放在主循环或普通调度器中，避免非关键任务影响车体平衡。
4.2软件主要理论
4.2.1平衡控制机理
两轮平衡自行车在行驶时依靠前轮转向产生横向加速度，使车体倾角回到平衡位置。软件中将控制问题分为两层目标：
1. 路径/航向目标：根据赛题路线，将期望航向角target_yaw按时间或距离规划出来。
2. 车体平衡目标：根据当前航向误差产生期望倾角，再通过舵机转向让车辆恢复或维持该倾角。
由于自行车本体具有强耦合、非线性、响应快的特点，代码采用串级控制结构，将一个复杂控制问题分解成多个简单闭环：

4.2.2航向目标平滑理论
赛题路线中航向角经常发生阶跃变化。若直接将 target_yaw 突然从一个角度切换到另一个角度，航向环会产生较大误差，导致舵机瞬间大幅打角，车体抖动甚至失稳。

4.3关键算法说明
4.3.1 IMU姿态解算与数据处理
IMU使用IMU660RC四元数模式，初始化时配置为IMU660RC_QUARTERNION_480HZ。软件上电后执行如下流程：
循环调用imu660rc_init()，直到IMU初始化成功；
2. 校准期间关闭IMU外部中断，避免ISR与主程序同时访问SPI；
3. 调用imu660rc_bias_calibrate(2000)完成零偏校准；
4. 记录当前imu660rc_yaw作为yaw_offset，实现开机航向归零；
5. 周期性调用imu_proc()更新pitch、roll、yaw和三轴角速度。

该算法保证所有航向角和航向误差都位于 [-180°, 180°]，便于PID控制。
2. pitch异常尖峰剔除
代码设置PITCH_SPIKE_THRESH = 30.0f。若当前raw_pitch与上一次有效值差值超过30°，认为是异常尖峰，直接使用上一次有效值替代。这样可过滤IMU偶发跳变，防止舵机因为错误姿态值突然大幅动作。
科目二的角度环还进一步对补偿机械零点后的pitch_balance做简单低通处理：小幅变化使用0.5 * old + 0.5 * new平滑，大幅变化则直接更新，兼顾平滑性和响应速度。
4.3.2 定时航向规划
1ms中断累加uwtick，按下启动按键后按时间段修改target_yaw。其中科目二主要航向动作如下：
uwtick>=700     target_yaw = 79       初始转向进入路线          
uwtick>=3640    target_yaw -= 0.02     缓慢改变航向，形成平滑过渡
············
uwtick>=28000   target_yaw = 125      末段航向    
该算法本质是基于时间轴的开环路径规划：车辆以近似恒定速度前进，软件根据经过时间推算当前位置，并切换对应赛段的目标航向。航向控制仍由闭环PID根据IMU的yaw实时修正，因此属于“时间规划+姿态闭环”的混合控制方式。
4.3.3 平衡控制
科目二采用两级串级PID控制“航向环-角度环”，科目一和科目三采用三级串级PID控制“航向环-角度环-角速度环”。
控制过程：
航向环
将target_yaw平滑为target_yaw_smooth，再计算yaw - target_yaw_smooth。PID输出target_angle，即期望车体倾角。大角度转弯时若航向误差超过80°，代码会禁用并清除积分，避免掉头过程中积分饱和。
角度环
先进行机械零点补偿：
pitch_balance = pitch - balance_zero_angle
其中balance_zero_angle = -4.20。随后角度PID根据target_angle - pitch_balance输出target_gyro_rate。
角速度环
角速度环以gyro_y_rate为反馈，将target_gyro_rate转换为最终舵机PWM偏移：
servo_output = PID(target_gyro_rate, gyro_y_rate)
servo_set(mid + servo_output)
三级串级结构使 `ke3` 在更高速度和更复杂动作下仍能保持较快响应。2ms 内环负责快速抑制角速度变化，10ms 中环保证倾角稳定，20ms 外环完成路线跟踪。

5.1 软件开发环境 
本项目的软件开发基于两套独立的集成开发环境（IDE），分别对应项目中使用的两款不同架构的微控制器：英飞凌AURIX™ TC264（TriCore™内核）与英飞凌CYT2BL3（Arm® Cortex®-M4F内核）。两部分的程序开发均在对应的IDE下进行，包括源程序的编写、编译、链接，并最终生成各自目标平台的可执行文件。
5.1.1 TC264开发环境——AURIX™ Development Studio
TC264端程序的开发在AURIX™ Development Studio（简称ADS）下完成。ADS是英飞凌公司于2019年底推出的免费的集成开发环境，专门面向基于TriCore™内核的AURIX™系列MCU。ADS提供了一个完整的开发工作流，其核心组件包括Eclipse IDE框架、专为TriCore™优化的C编译器、支持多核调试的调试器，以及英飞凌底层驱动库。尤其重要的是，该环境对于代码编辑、编译构建以及在线调试等全部开发环节，均未设置时间限制或代码大小限制，为复杂嵌入式应用的全功能开发提供了充足的自由度。在本项目中，利用ADS环境完成了TC264的源程序编写、工程配置、编译链接及通过调试器进行的多核程序下载与验证。
5.1.2 CYT2BL3开发环境——IAR Embedded Workbench for Arm
CYT2BL3端程序的开发则在IAR Embedded Workbench for Arm（简称IAR EW for Arm）环境下进行，版本为V9.40.1。该环境是专为Arm内核MCU设计的专业嵌入式开发工具，集成了高度优化的IAR C/C++编译器、链接器以及强大的C-SPY调试器。它提供了对CYT2BL3芯片的完整支持，包括器件头文件、启动代码及外设寄存器定义。在本项目中，借助IAR EW for Arm完成了CYT2BL3侧所有应用代码的编辑、工程管理、编译链接，并生成用于Flash烧录的可执行映像文件。
5.2 上位机
为便于系统调试与数据监控，本项目使用了逐飞助手（V2.0.0）上位机软件。
逐飞助手主要用于电机控制、传感器数据及PID参数等实时变量的波形显示与在线调节，其界面直观、通信协议兼容性强，有效支撑了控制算法的参数整定过程。

第七章 总结
7.1不足与改进
在整个设计、制作与调试过程中，我们虽然成功实现了基于IMU的定向巡航，但依然存在部分待优化的方面：
陀螺仪漂移问题：在室内赛道或路面不平整时，陀螺仪仍会出现微小累计漂移。未来我们计划在机械结构上进一步优化刚性固定底座，减少车架共振传导，并在软件算法中引入零偏自校准机制，以抑制长期的积分漂移。
极限速度下的姿态控制：在直线极速通过时，BDS300舵机受到路面震动的影响，存在微小的回中偏差。后续计划对舵机连杆使用更高精度的轴承结构，并在舵机控制算法中加入死区非线性补偿特性。
环境适应能力：目前完全依赖IMU，无法感知外部环境干扰。在下一代方案中，有望引入单目摄像头进行特征点辅助校准，利用视觉信息校正陀螺仪的积分漂移。

void balance_init(void)
{
   pid_init(&steering_pid,     0.38f, 0.0f, 0.06f, 0.0f,  15.0f);
   pid_init(&angle_pid,        14.0f, 0.0f, 80.0f, 0.0f, 3000.0f);
   pid_init(&gyro_pid,         2.5f, 0.0f, 0.0f, 0.0f, 1500.0f);
    pid_app_limit_integral(&angle_pid, -100.0f, 100.0f);
}

void balance_steering_loop(void)
{
    float target_yaw_error = normalize_angle(target_yaw - target_yaw_smooth);
    if(target_yaw_error > HEADING_STEP)
    {
        target_yaw_smooth = normalize_angle(target_yaw_smooth + HEADING_STEP);
    }
    else if(target_yaw_error < -HEADING_STEP)
    {
        target_yaw_smooth = normalize_angle(target_yaw_smooth - HEADING_STEP);
    }
    else
    {
        target_yaw_smooth = target_yaw;
    }
    float yaw_error = normalize_angle(yaw - target_yaw_smooth);
    if(fabsf(yaw_error) > STEERING_INTEGRAL_ANGLE)
    {
        steering_pid.integral = 0.0f;
        steering_pid.i_out = 0.0f;
        float steering_ki = steering_pid.ki;
        steering_pid.ki = 0.0f;
        target_angle = pid_calculate_by_error(&steering_pid, yaw_error);
        steering_pid.ki = steering_ki;
        steering_pid.integral = 0.0f;
        steering_pid.i_out = 0.0f;
    }
    else
    {
        target_angle = pid_calculate_by_error(&steering_pid, yaw_error);
    }
    uint32_t steering_limit_time = (uint32_t)(steering_limit_distance / USER_PARAM_sudu);
    if(uwtick < steering_limit_time)
    {
        target_angle = pid_constrain(target_angle, -10.0f, 10.0f);
    }
}

void balance_angle_loop(void)
{
    pitch_balance = pitch - balance_zero_angle;
    pid_set_target(&angle_pid, target_angle);
    target_gyro_rate = pid_calculate_positional(&angle_pid, pitch_balance);
}

void balance_gyro_loop(void)
{
    pid_set_target(&gyro_pid, target_gyro_rate);
    servo_output = pid_calculate_positional(&gyro_pid, gyro_y_rate);
    servo_set((uint32_t)(mid + (int32_t)servo_output));
}

typedef struct {
    void (*task_func)(void);
    uint32_t rate_ms;
    uint32_t last_run;
} task_t;

static task_t scheduler_task[] =
{
         {WIFI_test,130,0},
};

void scheduler_init(void)
{
    // 计算任务数组的元素个数，并将结果存储在 task_num 中
    task_num = sizeof(scheduler_task) / sizeof(task_t);
}

void scheduler_run(void)
{
    for (uint8_t i = 0; i < task_num; i++)
    {
        uint32_t now_time = uwtick;
        if(now_time>=scheduler_task[i].rate_ms+scheduler_task[i].last_run)
        {
            scheduler_task[i].last_run = now_time;
            scheduler_task[i].task_func();
        }
    }
}

void servo_set(uint32_t duty)
{
    if(duty <= l_max)
        duty = l_max;
    if(duty >= r_max)
        duty = r_max;
    pwm_set_duty(ATOM1_CH1_P33_9, duty);
}
