摘  要
本设计针对第二十一届全国大学生智能汽车竞赛单车定向组的比赛要求，以逐飞科技N1型电动单车为基础平台，设计并制作了一辆能够在室外操场赛道自主行驶的自平衡智能模型车。车模以英飞凌AURIX系列32位微控制器为主控核心，搭载IMU963RA六轴惯性测量单元、TLE5012BE1000磁编码器和GPS模块，采用无刷电机驱动后轮、舵机控制前轮转向的动力布局。
在控制算法方面，本设计采用串级PID控制结构实现自平衡控制——外环角度PI环根据倾角偏差生成目标角速度，内环角速度PD环驱动舵机输出转向力矩，依靠转向耦合产生的向心力维持车体直立平衡，无需动量轮辅助。速度控制采用增量式PID算法，通过UART串口将目标速度指令发送至无刷驱动板，由驱动板执行FOC磁场定向控制。导航方面采用GPS与航位推算融合的室外定位方案，结合纯追踪算法实现路径跟踪，并针对坡道、草地、锥桶绕桩等复杂路段设计了自适应控制策略。
经整车调试与场地测试，模型车能够稳定完成往返直线竞速、八字慢速和复杂路段（坡道、草地、绕桩）三个省赛科目，自平衡控制响应迅速、路径跟踪精度良好，达到了预期的设计目标。本设计在机械结构优化、多传感器融合导航和分路段自适应控制等方面进行了有益的探索，为自平衡单车在室外复杂环境下的自主导航提供了可行的技术方案。

第一章  引言
1.1  课题背景与意义
本节概述全国大学生智能汽车竞赛的背景，以及单车定向组的比赛任务与技术挑战。说明本设计的研究意义和应用价值。
单车定向组要求制作一辆电动单车，在室外操场赛道完成往返直线竞速、八字慢速、复杂路段（坡道、草地、锥桶绕桩）以及电磁门导航等科目。车模不允许使用负压或惯量方式维持平衡，完全依靠转向轮耦合实现动态平衡，对控制算法提出了较高要求。
1.2  国内外研究现状
自平衡自行车的动力学模型最早可追溯至 Whipple 提出的自行车经典动力学模型 ，该模型揭示了自行车通过转向耦合产生离心力以维持平衡的内在机理。在此基础上，国内外学者针对自平衡自行车的控制策略开展了大量研究。Getachew 等人对自主自行车的 PID、LQR 和模糊控制三种策略进行了对比分析，结果表明 LQR 在状态空间建模精确的前提下具有更优的动态响应和抗扰能力，但 PID 控制器因其结构简单、参数整定方便而在工程实践中应用更为广泛。针对智能车竞赛场景下的自平衡循迹自行车，Lee 等人  采用串级 PID 分层控制结构，以转向舵机产生的向心力作为控制力，外环角度环生成目标角速度、内环角速度环驱动执行器，实现了直立平衡与路径跟踪的协同控制。Thwin 等人则将 LQR 算法应用于两轮自平衡机器人系统，通过 Riccati 方程求解最优反馈增益矩阵，在倾角与角速度的综合代价最小化意义下实现了直立稳定。在姿态解算方面，互补滤波与卡尔曼滤波是处理 IMU 数据的两种主流方法，前者以计算量小见长，后者在噪声统计特性已知时具有更优的估计精度 。
在室外导航与多传感器融合方面，GPS 提供的绝对定位存在更新频率低、易受遮挡干扰等固有缺陷，而 IMU 与轮式里程计虽能提供高频相对位姿估计，但存在随时间累积的漂移误差。因此，基于扩展卡尔曼滤波（EKF）或无迹卡尔曼滤波（UKF）的多传感器融合方案成为室外移动机器人定位的主流技术路线 。针对室内外无缝切换场景，有研究提出了分层 EKF 架构：全局 EKF 优先融合 GPS 测量以抑制漂移，局部 EKF 通过 IMU 与里程计维持高频相对定位，二者根据 GPS 噪声协方差的变化进行自适应权重分配。在 ROS 生态中，robot_localization 软件包实现了 EKF 与 UKF 两种融合算法，能够将 IMU、里程计、GPS 等多源数据统一融合为稳定的位姿估计，已被广泛应用于室外无人车导航系统。

第二章  模型车整体设计方案
2.1  设计思路与技术路线
本设计以第二十一届全国大学生智能汽车竞赛单车定向组的比赛规则为依据，围绕“室外自主行驶、自平衡稳定、多科目适应”三个核心目标开展设计。单车定向组要求模型车在不使用动量轮、负压等辅助平衡手段的前提下，完全依靠转向轮耦合实现动态平衡，并在室外操场赛道完成往返直线竞速、八字慢速、复杂路段（坡道、草地、锥桶绕桩）等科目。
基于上述要求，本设计确立了“机械轻量化、控制分层化、导航多源融合”的总体技术路线：
（1）平台选型：采用逐飞科技N1型电动单车作为基础车模。该车模采用无刷电机直接驱动后轮、舵机控制前轮转向的结构，前叉与垂直面呈30°夹角，具有良好的操控特性和动态平衡潜力。原车模已集成基本车架和传动机构，在此基础上进行机械改造和电子系统加装。
（2）主控方案：选用英飞凌AURIX系列32位汽车级微控制器作为主控核心。该系列MCU基于TriCore架构，具有高性能计算能力、丰富的外设接口和较高的可靠性，能够满足500Hz自平衡控制、100Hz速度控制和10Hz导航计算的多任务实时调度需求。
（3）感知方案：采用IMU963RA六轴惯性测量单元（三轴加速度计+三轴陀螺仪）获取车体姿态和角速度，TLE5012BE1000磁编码器测量后轮转速实现车速反馈和里程推算，GPS模块提供室外绝对位置信息。三种传感器数据通过融合算法互补，实现高精度的车模位姿估计。
（4）控制方案：采用分层控制架构——最内层为500Hz自平衡串级PID控制（角度环+角速度环），中间层为100Hz速度闭环控制和方向控制，最外层为10Hz路径规划与导航决策。各层之间通过清晰的接口传递目标量，保证控制的实时性和稳定性。
（5）驱动方案：无刷电机驱动采用独立的CYT2BL23CAQX双核心微控制器执行FOC磁场定向控制，主控板仅通过UART串口发送目标速度指令，减轻主控计算负担。舵机由主控板直接输出PWM信号驱动。
2.2  系统总体架构
模型车系统由机械结构、硬件电路和控制软件三大部分组成，各模块之间的关系如图2.1所示。
机械结构部分包括N1车模本体、配重块、防倾倒杆、防撞架以及各传感器和电路板的安装支架，是整个系统的物理载体。硬件电路部分以英飞凌AURIX主控板为核心，外围包括电源管理电路、无刷电机驱动板、IMU姿态传感器、磁编码器、GPS模块、舵机驱动电路以及OLED显示和按键人机交互接口。
控制软件部分运行于主控MCU之上，采用前后台系统架构：后台主循环按固定频率执行传感器数据读取、姿态解算、导航计算和控制算法；前台中断服务程序负责定时调度、串口数据接收和PWM输出。软件按功能划分为硬件驱动层、传感器模块、控制算法模块、通信模块和应用层五个层次，各层之间通过标准接口交互，降低耦合度。
系统的工作流程为：IMU以500Hz频率采集加速度和角速度数据，经互补滤波解算出车体倾角和角速度，送入自平衡串级PID控制器，输出舵机PWM信号维持车体直立；磁编码器以100Hz频率测量后轮转速，经速度PID控制器输出目标速度指令，通过UART发送给无刷驱动板执行FOC驱动；GPS以1Hz频率输出位置信息，与编码器里程计和IMU航向融合后得到车模实时位姿，经纯追踪算法计算期望转向角，送入方向控制环作为自平衡的角度参考。

2.3  各科目实现方案概要
单车定向组省赛阶段包含往返直线竞速、八字慢速和复杂路段三个科目，各科目对车模的速度、平衡稳定性和路径跟踪能力有不同侧重，本设计针对各科目特点制定了相应的实现方案。
2.3.1  往返直线竞速科目
往返直线竞速科目要求车模在直道上完成起点到终点的高速行驶，并在终点处自主掉头返回起点。该科目重点考察车模的高速平衡稳定性和直线保持能力。
实现方案：采用高速模式，目标速度设定为车模稳定行驶的最大速度（约2.5~3.0m/s）。自平衡控制参数针对高速工况优化——适当增大角速度环比例系数以提高响应速度，增大微分系数以抑制高速振荡。直线保持通过舵机中位补偿和方向环微调实现，利用IMU航向角与目标航向的偏差进行小角度修正，避免高速行驶时跑偏。终点掉头采用预设的转向角度和时间控制，在到达终点位置（由编码器里程计判断）后执行固定角度的转向动作，完成180°掉头后切换为返程高速模式。
2.3.2  八字慢速科目
八字慢速科目要求车模沿八字圆环路径以低速行驶，重点考察车模的低速平衡能力和路径跟踪精度。低速行驶时自平衡系统的向心力不足，车体容易出现振荡甚至倾倒，对控制算法提出了更高要求。
实现方案：采用惯性导航方式实现八字路径跟踪。赛前在场地中采集八字路径的特征点坐标，经B样条插值拟合出光滑连续的参考路径。行驶过程中，通过IMU963RA解算航向角和姿态数据，通过磁编码器解算速度和行驶距离，结合航位推算得到车模实时位置。纯追踪算法根据当前位置和参考路径计算期望转向角，送入方向控制环。
该科目采用低速模式，目标速度限制在0.5~1.0m/s，前视距离L_d取较小值（0.3~0.5m）以提高路径跟踪精度。同时增大平衡控制的阻尼系数（Kd_ω），抑制低速时车体的振荡倾向。在路径的圆环交接处适当降低速度，保证转向过渡平稳。
2.3.3  复杂路段科目
复杂路段科目在往返赛道上设置坡道、草地和锥桶绕桩三种元素，要求车模依次通过，重点考察车模对不同路面和障碍的适应能力。
实现方案：整体采用GPS与惯性导航融合的导航方式。赛前利用GPS采集赛道关键节点坐标，经算法拟合出光滑路径，行驶中结合磁编码器速度和IMU航向进行航位推算，GPS有效时校正累积误差。
锥桶绕桩区域采用特殊处理：进入绕桩区域后将转向角限幅从正常的45°收窄至30°，避免大角度转向导致车身姿态剧烈波动甚至倾倒。绕桩路径采用正弦轨迹参数化生成，根据锥桶间距和行驶速度设定正弦波的振幅和频率，使车模平稳连续绕桩。
坡道处理利用IMU测量的俯仰角判断上下坡状态：当检测到俯仰角超过阈值（约5°）且持续一定时间时判定为进入坡道。上坡时适当增加目标速度以克服重力分量，下坡时减小目标速度并利用电机再生制动控制车速，防止车速过快失控。
草地路段由于路面摩擦系数低、颠簸大，容易出现车轮打滑和车体振动。进入草地后降低目标速度至1.0m/s以下，同时增大速度环的积分限幅以应对打滑导致的速度波动，并加强IMU数据的滤波以抑制路面颠簸引起的噪声。复杂路段末端的回头弯由高速模式切换为低速模式，提前减速以保证过弯稳定性。各路段的切换基于GPS位置与预设区域边界的比较来实现。


第三章  机械结构设计与改造
3.1  车模本体与改造
本设计以逐飞科技N1型电动单车为基础车模。原车模采用铝合金车架，无刷电机直接驱动后轮，舵机通过连杆控制前轮转向，前叉与垂直面呈30°夹角，轴距约18cm，整车重量约1.2kg。原车模结构紧凑、操控灵活，但在自平衡控制和室外复杂路况行驶方面仍需进行针对性改造。
在原车模基础上，本设计主要进行了以下机械改造：
（1）配重优化：在后轮右侧增加两个钢制配重块，在车模底部增加一个配重块。配重块的作用是降低整车重心高度并调整重心横向位置，使车模重心尽可能位于几何中心正下方。较低的重心有利于提高自平衡的稳定性，减小倾覆力矩；重心横向对中则保证左右转向时平衡特性对称。配重块通过3D打印定制的固定座安装，总配重质量约500g，改造后整车重量约1.56kg。
（2）防倾倒杆：在车模几何中心位置横向加装一根防倾倒杆，杆长约19cm，两端安装橡胶缓冲头。防倾倒杆的作用是在车模倾角过大即将倾倒时提供机械限位，保护车体和电子元件不受损坏。杆的长度经过设计，在正常行驶倾角范围内不接触地面，仅在倾角超过安全阈值（约30°）时起支撑作用。防倾倒杆采用碳纤维管材，在保证强度的同时尽可能减轻重量。
（3）防撞架：在车头前方加装碳纤维防撞架，通过铜柱固定于前叉上方。防撞架的作用是在车模碰撞障碍物或掉头失误时吸收冲击能量，保护车头部位的GPS天线和舵机等关键部件。防撞架采用镂空设计，在保证防护能力的同时不增加过多重量和空气阻力。
（4）轮胎处理：原车模轮胎宽度符合比赛规则要求（不超过1.6cm）。为提高室外操场跑道（塑胶/沥青路面）的抓地力，对轮胎表面进行了轻微打磨处理，增加胎面粗糙度。同时检查轮胎动平衡，确保高速旋转时不产生明显振动。
3.2  传感器安装设计
传感器的安装位置和固定方式直接影响测量精度和系统稳定性。本设计对GPS模块、IMU和磁编码器三种传感器的安装进行了精心设计。
3.2.1  GPS模块安装
GPS模块由增益天线和接收模块两部分组成。增益天线安装于车模最高处（防撞架上方），以获得最大的天空视野，减少车体金属结构对卫星信号的遮挡。GPS接收模块安装于增益天线的正下方，通过短同轴电缆连接，尽可能缩短天线与模块之间的信号线长度，减少信号衰减和外界干扰。
在保证卫星信号接收质量的前提下，尽量降低GPS增益天线的安装高度以降低整车重心。天线通过3D打印支架固定，支架高度经过反复测试确定，在信号接收质量和重心高度之间取得平衡。GPS模块与主控板之间通过UART串口通信，使用杜邦线连接，走线沿车架内侧布置，避免与动力线并行。
3.2.2  IMU安装
IMU963RA六轴惯性测量单元安装于车模几何中心位置。该位置是车体转动的中心，在此处安装IMU可以最准确地测量车体的倾角和角速度，减少因偏心旋转引起的加速度耦合干扰。如果IMU偏离几何中心，车模转向时产生的向心加速度会叠加到加速度计的输出中，影响倾角解算精度。
IMU模块通过双面胶和铜柱双重固定于主控板上方的定制安装座上，确保与车体刚性连接，避免振动导致的相对位移。安装时注意IMU的坐标轴方向与车体坐标系一致——x轴指向车模前进方向，y轴指向左侧，z轴指向上方，以减少坐标转换的复杂性。IMU与主控板之间采用SPI通信方式，使用排线连接，数据传输速率高、抗干扰能力强。
3.2.3  磁编码器安装
TLE5012BE1000磁编码器安装于无刷电机尾部，通过检测电机轴末端同轴固定的环形磁铁的磁极变化来获取转子位置和转速。该编码器采用巨磁阻（GMR）技术，分辨率为15位（每转32768线），具有抗灰尘、抗振动、安装方便等优点，适合室外复杂环境。
安装时将环形磁铁通过紧配合固定在电机尾部伸出轴上，确保与电机转子同轴旋转。编码器PCB板固定于电机端盖上，与环形磁铁保持规定的气隙（约0.5~2mm），气隙大小直接影响测量精度，安装时需仔细调整。编码器与主控板之间通过SPI接口通信，读取角度值后经差分计算得到转速。
3.3  电路板固定与连接
本设计的电路板主要包括主控板和无刷驱动板两块，此外还有GPS模块和IMU模块两块独立的传感器小板。各电路板的固定位置和连接方式如下。
主控板安装于车模后方2/3处，利用铜柱和定制玻纤板将主板固定在车模主体上。选择该位置是因为它靠近车模重心，且有足够的空间安装主板和连接线缆。主控板通过4根铜柱固定于玻纤板上，玻纤板再固定于车架，形成稳定的双层安装结构，既保证了散热空间，又便于检修。
无刷驱动板固定于车身尾部伸出的玻纤板上（与固定主控板的是同一块玻纤板的延伸部分）。驱动板靠近无刷电机，可以缩短三相动力线的长度，减少电磁干扰和线路损耗。驱动板与电机之间通过大电流硅胶线连接，线径满足峰值电流要求。
各模块之间的通信连接根据数据量和实时性要求选择不同的接口：
（1）IMU963RA与主控板之间通信数据量大（加速度、角速度各三轴，500Hz频率），采用SPI通信方式，利用8Pin排线连接，传输速率可达10Mbps以上，满足高速数据采集需求。
（2）无刷驱动板与主控板之间通信数据量少（仅目标速度指令和状态反馈），采用通用异步串口（UART）通信，利用XH2.54端子线连接，波特率115200bps，简单可靠。
（3）GPS模块与主控板之间采用UART串口通信，利用杜邦线连接，波特率9600bps，接收NMEA-0183标准数据。
所有信号线在走线时尽量远离电机三相动力线和电池电源线，必要时采用屏蔽线，以减少电磁干扰。接插件均采用带锁扣或端子固定的类型，防止车模行驶振动导致接触不良。
3.4  动力与传动系统
模型车的动力与传动系统包括驱动电机、后轮、舵机、转向机构和前叉结构五个部分。
驱动电机采用原车模配套的外转子无刷直流电机，电机直接与后轮结合——后轮固定于驱动电机的转子上，电机定子固定于车架。这种直驱结构取消了减速齿轮和传动带，极大地节约了空间、减轻了车身重量，同时消除了齿轮间隙和传动损耗，提高了传动效率和控制精度。电机额定电压12V，最大功率约150W，能够提供充足的加速和爬坡动力。
后轮采用橡胶轮胎，轮径约1.3cm，胎宽符合比赛规则（不超过1.6cm）。轮胎通过锁紧螺母固定于电机转子上，更换方便。
转向舵机固定于车模前部，采用原车模配套的金属齿轮数字舵机，扭矩约12kg·cm，响应速度快、定位精度高。舵机利用原装舵盘连接一个定制法兰盘，法兰盘固定于前叉轴上，舵机转动时通过法兰盘带动前叉和前轮偏转，实现转向控制。舵机由主控板输出50Hz PWM信号驱动，脉宽范围500~2500μs对应转角-90°~+90°。
前叉与垂直面呈30°夹角（即前叉倾角为30°），该设计有利于提升车模的操控性和自平衡特性。较大的前叉倾角使转向时前轮的轨迹更平滑，减小了转向时的车体扰动；同时前叉后倾角提供了一定的直行回正力矩，有利于车模在直线行驶时保持方向稳定。前叉采用铝合金材质，强度高、重量轻，能够承受转向和颠簸路面的冲击。
整个动力与传动系统在安装完成后进行了转动灵活性检查和转向角度校准，确保舵机中位时前轮正对前方，左右最大转角对称，无机械卡滞。

4.1  电源系统设计

5.2  姿态解算
姿态解算是自平衡控制的基础，其精度和响应速度直接决定车模的平衡性能。本设计采用IMU963RA六轴惯性测量单元采集车体的加速度与角速度数据，通过互补滤波算法融合加速度计和陀螺仪的输出，解算出车体的实时倾角与角速度。
5.2.1  IMU963RA传感器简介
IMU963RA是一款集成了三轴加速度计和三轴陀螺仪的六轴惯性测量模块，支持SPI通信接口，加速度计量程为±16g，陀螺仪量程为±2000°/s，输出数据速率最高可达1kHz。本设计中将IMU963RA安装于车模几何中心位置，以减小车体振动和偏心旋转对测量结果的影响。主控通过SPI总线以500Hz的频率读取加速度和角速度原始数据。
5.2.2  加速度计倾角计算
加速度计通过测量重力加速度在各轴上的分量来计算车体静态倾角。在车体静止或匀速运动时，利用反正切函数可求得倾角：
θ_acc = arctan(a_x / sqrt(a_y² + a_z²))        公式2
其中a_x、a_y、a_z分别为三轴加速度计的输出。加速度计的优点是无累积漂移，但缺点是对车体运动加速度敏感，在车模加速、转弯或经过颠簸路面时，运动加速度会叠加在重力加速度上，导致倾角计算产生较大误差。
5.2.3  陀螺仪角速度积分
陀螺仪直接测量车体绕各轴的转动角速度，对倾角进行积分即可得到角度变化：
θ_gyro(k) = θ_gyro(k-1) + ω × Δt        公式3
其中ω为陀螺仪输出的角速度，Δt为采样周期。陀螺仪响应速度快、不受运动加速度干扰，但存在零偏漂移，长时间积分会导致角度误差不断累积。
5.2.4  互补滤波融合
为综合加速度计和陀螺仪各自的优势，本设计采用一阶互补滤波算法进行姿态解算：
θ(k) = α × θ_acc(k) + (1 - α) × (θ(k-1) + ω × Δt)        公式4
其中α为滤波系数，取值范围为0~1。α越大，越信任加速度计的静态角度，抗漂移能力越强，但响应变慢；α越小，越信任陀螺仪的积分结果，响应速度快但易受漂移影响。经实验调试，本设计取α=0.02，在500Hz采样率下兼顾了响应速度与抗漂移能力。陀螺仪零偏在车模启动时进行静态校准，取启动后500组数据的平均值作为零偏补偿值。
此外，对陀螺仪输出的角速度信号进行滑动平均滤波，窗口大小为5，以抑制高频噪声对平衡控制的干扰。
5.3  GPS定位与导航
GPS模块为车模提供室外绝对位置信息，是复杂路段科目中路径导航的核心传感器。GPS天线安装于车模最高处以获得最佳卫星信号接收效果，GPS模块安装于天线正下方以缩短信号线长度。模块通过UART串口与主控通信，输出标准NMEA-0183协议数据。
5.3.1  GPS数据解析
GPS模块默认输出频率为1Hz，波特率9600bps。主控在串口中断中逐字节接收NMEA语句，以"$"符识别帧起始，以"\r\n"识别帧结束，完成接收后在主循环中进行字段分割与校验和验证。主要解析$GNGGA和$GNRMC两类语句：
$GNGGA语句包含UTC时间、纬度、经度、定位质量指示符、使用卫星数、水平精度因子HDOP和海拔高度等信息。当定位质量指示符为1（GPS单点定位）或2（差分定位）、且卫星数≥4、HDOP<2.0时，认为本次定位有效。
$GNRMC语句包含定位状态、经纬度、地面速度（节）和航向角（度）等信息，用于获取车模的运动速度和航向。解析得到的经纬度、航向、速度等数据存入全局结构体，供导航算法调用。
5.3.2  坐标转换
GPS输出的经纬度为WGS-84大地坐标系下的球面坐标，需转换为以赛道起点为原点的局部平面直角坐标系才能用于路径规划。本设计采用等距方位投影（局部切平面）方法，以赛道起点（lat₀, lon₀）为切平面原点：
x = R × (lat - lat₀) × π / 180        公式5
y = R × cos(lat₀) × (lon - lon₀) × π / 180        公式6
其中R为地球平均半径（6371000m），x为北向位移，y为东向位移。该方法在操场级别的小范围内（<1km）投影误差可忽略，且计算量极小，适合嵌入式平台实时运算。转换后的局部坐标系中，x轴指向正北，y轴指向正东，航向角定义为从正北顺时针旋转的角度。
5.3.3  路径规划与航点导航
复杂路段科目采用航点导航方式。赛前通过实地GPS采集赛道关键节点的经纬度，转换为局部平面坐标后形成有序航点序列P={p₁, p₂, ..., pₙ}。直道段航点间距为2~5m，弯道、坡道入口和绕桩区域航点加密至0.5~1m，确保路径覆盖所有关键转向点。
导航过程中采用前视距离法选取目标航点：沿路径方向查找距离车模当前位置最近、且累计路径距离超过前视阈值L_d的航点作为跟踪目标。前视距离随车速动态调整，低速时取较短前视距离以保证转向精度，高速时取较长前视距离以避免频繁转向引起振荡。
5.3.4  纯追踪导航算法
路径跟踪采用纯追踪算法（Pure Pursuit）。以车模后轴中心为参考点，以前视距离L_d为半径作圆弧经过目标航点，根据几何关系计算期望前轮转角：
δ = arctan(2L × sinα / L_d)        公式7
其中L为车模轴距，α为车模航向与目标航点方向之间的夹角。目标航向角由当前位置指向目标航点的向量方向确定：
ψ_target = arctan2(y_target - y_now, x_target - x_now)        公式8
航向偏差α=ψ_target−ψ_now需归一化到[-π, π]区间。纯追踪算法输出的期望转角δ经限幅和速率限制后送入方向控制环，与自平衡控制协同工作。
5.4  传感器数据融合
单一传感器各有局限性：GPS更新频率低（1Hz）且存在跳变，IMU姿态解算存在漂移，编码器里程计随行驶距离累积误差。本设计采用多传感器融合策略，结合各传感器的优势，获得稳定可靠的车模位姿估计。
5.4.1  航位推算
在两次GPS更新之间，利用编码器测量的车速和IMU测量的航向角进行航位推算（Dead Reckoning）：
x(k) = x(k-1) + v × cosψ × Δt        公式9
y(k) = y(k-1) + v × sinψ × Δt        公式10
其中v为编码器解算的车速，ψ为IMU融合得到的航向角。航位推算提供高频（100Hz）的相对位置更新，但误差随时间累积。
5.4.2  GPS与航位推算融合
当GPS定位有效时，以GPS位置作为绝对参考，对航位推算的累积误差进行校正。融合采用加权平均方式：
x_fused = w_gps × x_gps + w_dr × x_dr        公式11
权重根据GPS的HDOP值和卫星数动态调整：HDOP越小、卫星数越多，GPS权重越大；GPS信号差时增大航位推算权重。当GPS定位无效（卫星数<4或HDOP>3.0）或检测到位置跳变（相邻帧位移>5m）时，完全切换为航位推算模式，待GPS恢复有效后再进行校正。
5.4.3  车速解算
车速由TLE5012BE1000磁编码器测量。该编码器安装于无刷电机尾部，通过检测电机轴上环形磁铁的磁极变化来获取转子位置，分辨率为15位（32768线/转）。主控以固定时间间隔读取编码器计数值，结合车轮周长和减速比计算车速：
v = (Δcount / N) × 2πr × f_sample        公式12
其中Δcount为采样周期内的编码器增量，N为编码器每转线数，r为车轮半径，f_sample为采样频率。磁编码器相比传统光电编码器具有抗灰尘、抗振动、安装方便等优点，适合室外复杂环境。


第六章  微处理器控制软件与算法
6.1  软件总体架构
本设计的控制软件基于英飞凌AURIX系列微控制器开发，采用前后台系统架构：后台为无限循环的主程序，负责传感器数据读取、姿态解算、导航计算和控制算法执行；前台为中断服务程序，负责定时调度、串口数据接收和PWM输出。
系统采用定时器中断实现固定频率的任务调度：1kHz定时器中断作为系统时基，在中断中置位任务标志位，主循环根据标志位执行对应频率的任务。各任务的执行频率如下：
（1）IMU读取与姿态解算：500Hz，保证自平衡控制的实时性；
（2）自平衡控制（角度环+角速度环）：500Hz，与IMU同步执行；
（3）编码器读取与速度计算：100Hz；
（4）速度闭环控制：100Hz；
（5）GPS数据解析与导航计算：10Hz（GPS数据有效时）；
（6）方向控制与航位推算：100Hz；
（7）OLED显示与按键处理：10Hz。
高优先级的平衡控制任务在定时器中断中直接执行，确保控制周期的确定性和实时性；低优先级的导航和显示任务在主循环中执行，避免占用过多中断时间。各任务之间通过全局结构体共享数据，采用临界区保护防止数据竞争。

6.2  自平衡控制算法
单车定向组不允许使用动量轮维持平衡，车模完全依靠转向轮耦合倾角与转向力矩来实现动态平衡。其基本原理是：当车体向左倾斜时，控制舵机向左转向，使车模做向左的曲率运动，产生向右的向心力，从而将车体拉回直立状态；反之亦然。
本设计采用串级PID控制结构：外环为角度PI环，根据倾角偏差计算目标角速度；内环为角速度PD环，根据角速度偏差驱动舵机输出。串级结构相比单环PID具有更好的抗扰能力和动态响应。
6.2.1  角度环控制
角度环以车体期望倾角θ_ref与实际倾角θ的偏差作为输入，经PI控制器输出目标角速度ω_target：
e_θ = θ_ref - θ        公式13
ω_target = Kp_θ × e_θ + Ki_θ × Σe_θ × Δt        公式14
其中Kp_θ为角度环比例系数，Ki_θ为角度环积分系数。期望倾角θ_ref在静止直立时为0；在加速或爬坡时，根据目标速度和坡道俯仰角设置适当的前倾角度，以提供加速所需的向心力分量。积分项设置了抗饱和限幅，当输出超过限幅值时停止积分累积，防止积分饱和导致超调。
6.2.2  角速度环控制
角速度环以目标角速度ω_target与实际角速度ω的偏差作为输入，经PD控制器输出舵机控制量u_steer：
e_ω = ω_target - ω        公式15
u_steer = Kp_ω × e_ω + Kd_ω × (e_ω - e_ω_last) / Δt        公式16
其中Kp_ω为角速度环比例系数，Kd_ω为角速度环微分系数。角速度环采用PD控制而非PID，是因为积分项会引入相位滞后，不利于平衡系统的快速响应。微分环节提供阻尼作用，抑制车体振荡。舵机控制量u_steer经PWM输出驱动舵机转动，PWM频率为50Hz，脉宽范围500~2500μs对应舵机转角-90°~+90°。
平衡控制的参数整定遵循“先内环后外环”的原则：先固定角度环输出为零，单独调试角速度环，使车体在手动倾斜后能快速回正且不振荡；然后接入角度环，从小到大逐步增大Kp_θ，直至车模能稳定直立，最后加入Ki_θ消除静态倾角偏差。
6.3  速度控制算法
速度控制的目标是使车模实际速度跟踪目标速度。本设计采用增量式PID控制器，以目标速度v_ref与实际速度v的偏差作为输入，输出电机扭矩增量Δu：
e_v(k) = v_ref - v(k)        公式17
Δu(k) = Kp_v × [e_v(k) - e_v(k-1)] + Ki_v × e_v(k) + Kd_v × [e_v(k) - 2e_v(k-1) + e_v(k-2)]        公式18
增量式PID的输出为控制量的增量，累计后得到实际输出u(k)=u(k-1)+Δu(k)。相比位置式PID，增量式PID具有误动作影响小、切换平滑、易于手动/自动切换等优点。
速度指令通过UART串口发送给无刷驱动板（CYT2BL23CAQX），由驱动板执行FOC（磁场定向控制）算法驱动无刷电机。无刷驱动板以10kHz的PWM频率执行电流环，以1kHz的频率执行速度环，主控仅需发送目标速度指令，从而减轻主控的计算负担。
目标速度根据当前所在路段类型动态规划：直道段取较高速度，弯道段根据曲率大小降速，坡道和草地段取保守速度。曲率κ由路径相邻航点的航向差计算，最大侧向加速度限制为a_lat,max，由此确定弯道最大速度：
v_max_corner = sqrt(a_lat,max / κ)        公式19
6.4  方向与路径控制
方向控制的目标是使车模沿规划路径行驶，同时不破坏自平衡的稳定性。方向控制环输出期望转向角，作为自平衡控制的角度参考输入，形成“导航外环→平衡内环”的串级结构。
6.4.1  八字慢速控制
八字慢速科目要求车模沿八字圆环路径低速行驶。该科目对车模的低速平衡能力和路径跟踪精度要求较高。本设计采用惯性导航方式实现八字路径跟踪：
赛前在场地中采集八字路径的特征点坐标，经B样条插值拟合出光滑连续的参考路径。行驶过程中，通过IMU963RA解算航向角和姿态数据，通过磁编码器解算速度和行驶距离，结合航位推算得到车模实时位置。纯追踪算法根据当前位置和参考路径计算期望转向角，送入方向控制环。
八字科目采用低速模式，目标速度限制在0.5~1.0m/s，前视距离L_d取较小值（0.3~0.5m）以提高路径跟踪精度。同时增大平衡控制的阻尼系数（Kd_ω），抑制低速时车体的振荡倾向。
6.4.2  绕桩与复杂路段控制
复杂路段科目包含坡道、草地和锥桶绕桩三种元素，需要针对不同路段采用不同的控制策略。
锥桶绕桩区域采用特殊处理：进入绕桩区域后，将转向角限幅从正常的45°收窄至30°，避免大角度转向导致车身姿态剧烈波动甚至倾倒。绕桩路径采用正弦轨迹参数化生成，根据锥桶间距和行驶速度设定正弦波的振幅和频率，使车模平稳地连续绕桩。
坡道处理利用IMU测量的俯仰角判断上下坡状态：当检测到俯仰角超过阈值（如5°）且持续一定时间时，判定为进入坡道。上坡时适当增加目标速度以克服重力分量，下坡时减小目标速度并利用电机再生制动控制车速，防止车速过快失控。
草地路段由于路面摩擦系数低、颠簸大，容易出现车轮打滑和车体振动。进入草地后降低目标速度至1.0m/s以下，同时增大速度环的积分限幅以应对打滑导致的速度波动，并加强IMU数据的滤波以抑制路面颠簸引起的噪声。
复杂路段末端的回头弯由高速模式切换为低速模式，提前减速以保证过弯稳定性。各路段的切换基于GPS位置与预设区域边界的比较来实现。
6.5  代码设计介绍
控制软件采用模块化设计思想，将代码按功能划分为以下模块：
（1）硬件驱动层：包括GPIO、UART、SPI、定时器、PWM、ADC等外设驱动函数，为上层提供统一的硬件访问接口；
（2）传感器模块：包括IMU963RA驱动、TLE5012磁编码器驱动、GPS数据解析、姿态解算等函数；
（3）控制算法模块：包括自平衡串级PID、速度增量式PID、方向控制、纯追踪导航等函数；
（4）通信模块：包括与无刷驱动板的UART通信协议、上位机调试数据输出等；
（5）应用层：包括任务调度、科目状态机、参数管理等。
各模块之间通过清晰的接口函数和数据结构体进行交互，降低耦合度，便于调试和维护。关键控制参数（如PID系数、前视距离、速度阈值等）集中定义在参数头文件中，方便调参和版本管理。核心算法子程序见附录B，完整源代码见附录C。

7.2  制作过程
模型车的制作过程主要包括机械加工、电路板制作与焊接、整车组装三个阶段。
7.2.1  机械加工
在逐飞N1车模基础上进行机械改造。首先根据设计需求在车模后轮右侧和底部安装配重块，配重块采用钢制材料，通过3D打印定制固定座安装于车架指定位置。几何中心处横向加装防倾倒杆，杆长约____cm，两端安装橡胶缓冲头。车头前方加装防撞架，采用碳纤维板材切割成型，通过铜柱固定于前叉上方。
传感器安装支架采用3D打印（PLA材料）制作，包括GPS天线支架、IMU固定座和舵机法兰盘连接件。打印层高0.2mm，填充密度20%，在保证强度的同时控制重量。所有支架安装后进行重心测量，确保车模重心位于几何中心附近且高度尽可能低。
7.2.2  电路板制作与焊接
主控板和无刷驱动板均采用嘉立创EDA进行原理图设计和PCB布局，完成后提交嘉立创进行PCB打样。主控板为两层板，无刷驱动板为四层板。
焊接流程遵循“先小后大、先低后高”的原则：先焊接0402/0603封装的电阻、电容等贴片元件，再焊接SOP/QFN封装的芯片，最后焊接电解电容、接插件等较大元件。QFN封装的英飞凌AURIX主控芯片采用热风枪焊接，焊接后通过显微镜检查引脚连锡情况。无刷驱动板的大电流回路（电池接口、MOS管、三相输出）采用加厚焊锡处理，降低导通电阻和发热。
焊接完成后进行目视检查和万用表通断测试，确认电源与地之间无短路，各电源网络阻值正常。
7.2.3  整车组装
整车组装按以下顺序进行：（1）将主控板通过铜柱固定于车模后方2/3处的定制玻纤板上；（2）将无刷驱动板固定于车身尾部伸出的玻纤板上；（3）安装IMU模块于车模几何中心，连接SPI排线；（4）安装GPS天线和模块于车模最高处，连接UART杜邦线；（5）安装磁编码器于无刷电机尾部，对准环形磁铁；（6）连接舵机、电机、电池等动力线缆；（7）安装配重块、防倾倒杆和防撞架。
组装完成后进行整车检查：确认所有接插件插紧无松动，线缆走向合理不与运动部件干涉，电池固定牢固，车模静止时重心平稳。
7.3  调试过程
7.3.1  硬件调试
硬件调试首先进行电源测试：不接主控芯片，仅焊接电源部分，通电后用万用表测量各电压输出（12V、5V、3.3V）是否正常，纹波大小是否在允许范围内。确认电源无误后再焊接主控和其他芯片。
其次进行电机驱动测试：将无刷驱动板连接电机和电源，通过串口发送测试指令，验证三相输出波形和电机转向是否正确。测试FOC电流环和速度环的基本功能，确认电机能平稳启动和调速。
然后进行传感器测试：通过SPI读取IMU的加速度和角速度原始数据，验证各轴输出范围和零偏；通过UART接收GPS的NMEA语句，验证定位有效性和数据更新率；读取磁编码器数值，验证转动方向和计数精度。
最后进行舵机测试：发送不同脉宽的PWM信号，验证舵机转角范围、响应速度和中位准确性，调整舵机臂使车模直行时舵机处于中位。
7.3.2  软件调试
软件调试采用模块化方式，逐个模块验证：
（1）姿态解算调试：将IMU数据通过串口输出到上位机（VOFA+），观察互补滤波后的倾角曲线。手动倾斜车模，验证倾角跟随是否准确、有无明显漂移。调整滤波系数α，在响应速度和稳定性之间取得平衡。
（2）平衡控制调试：先仅运行角速度环（PD），将车模用支架悬空，手动转动车体观察舵机是否反向修正。然后落地调试角度环（PI），从小到大逐步增大Kp_θ，直至车模能在扶持下稳定站立，再加入Ki_θ消除静态倾角。
（3）速度控制调试：设定固定目标速度，观察实际速度曲线是否平稳跟踪目标，调整增量式PID参数使超调量小、响应快。
（4）导航调试：在场地中采集航点，观察车模是否能沿规划路径行驶，调整前视距离L_d和转向PID参数，减小路径跟踪误差。
7.3.3  整车调试
整车调试在室外操场进行，按科目逐个验证：
（1）直线往返竞速：先低速行驶验证直线保持能力，再逐步提高速度。重点调整速度环参数和直行舵机中位补偿，确保往返行驶不跑偏。
（2）八字慢速：以0.5m/s低速沿八字路径行驶，验证低速平衡稳定性和路径跟踪精度。增大角速度环微分系数抑制低速振荡，缩短前视距离提高跟踪精度。
（3）复杂路段：依次通过坡道、草地和绕桩区域。坡道调试重点在于上下坡速度自适应；草地调试重点在于防滑和抗振；绕桩调试重点在于转角限幅和正弦轨迹参数匹配。
每个科目反复测试不少于20次，记录每次的完成时间和失败原因，逐步优化参数。最终车模能稳定完成全部三个省赛科目。
7.4  遇到的主要问题与解决方法
在整个制作调试过程中，遇到了以下几个关键问题：
（1）问题一：车模静止直立时存在高频小幅振荡。原因分析：舵机响应延迟较大，角速度环微分系数过高导致系统不稳定。解决方法：更换响应速度更快的金属齿轮数字舵机，降低Kd_ω系数，同时对陀螺仪信号增加滑动平均滤波，最终振荡消除。
（2）问题二：加速时车模容易向后倾倒。原因分析：加速时车体需要前倾提供加速度分量，但角度环的期望倾角固定为0，导致加速时向心力不足。解决方法：在速度环输出与期望倾角之间引入前馈项，根据目标加速度动态设置期望前倾角度，加速时自动前倾，减速时自动后倾。
（3）问题三：GPS定位漂移导致导航路径偏差。原因分析：操场周边建筑物和树木引起多路径效应，GPS单点定位精度约2~5m，无法满足精确导航需求。解决方法：增加航位推算频率至100Hz，在两次GPS更新之间用IMU+编码器推算位置，GPS有效时用加权融合校正累积误差，同时增大GPS异常跳变检测阈值，剔除异常定位点。
（4）问题四：草地路段车轮打滑导致速度失控。原因分析：草地摩擦系数低，电机输出扭矩过大时车轮空转。解决方法：在草地区域降低目标速度和加速度限值，同时在速度环中增加积分抗饱和处理，打滑时限制积分累积，恢复接触后快速恢复控制。
（5）问题五：无刷驱动板与主控通信偶发丢包。原因分析：UART通信线较长且靠近电机动力线，受到电磁干扰。解决方法：将UART信号线更换为带屏蔽的双绞线，远离电机三相线走线，通信协议增加帧头帧尾和校验和，丢包时重发上一帧有效指令。

结 论
1.工作总结
本设计围绕第二十一届全国大学生智能汽车竞赛单车定向组的比赛要求，完成了一辆基于逐飞N1车模的自平衡电动单车的设计与制作。车模以英飞凌AURIX系列微控制器为主控核心，搭载IMU963RA六轴惯性测量单元、TLE5012BE1000磁编码器和GPS模块，实现了自平衡控制、速度闭环、路径导航和多传感器融合等功能。
在机械结构方面，在原车模基础上增加了配重块、防倾倒杆和防撞架，优化了车身重心分布和操控稳定性。传感器布局经过精心设计：GPS天线置于车模最高处以保证信号质量，IMU安装于几何中心以精确测量姿态，磁编码器同轴安装于电机尾部以提高测速精度。
在电路设计方面，完成了主控板和无刷驱动板的设计与制作。电源系统采用12V锂电池供电，经SCT2450STER同步降压至5V为主控和舵机供电，经RT9013-33GB LDO稳压至3.3V为IMU等低压器件供电，舵机电源独立供电以避免干扰。无刷驱动板采用CYT2BL23CAQX+FD6288Q方案，实现FOC驱动。
在控制算法方面，采用串级PID实现自平衡控制（外环角度PI+内环角速度PD），采用增量式PID实现速度闭环，采用纯追踪算法实现路径跟踪，采用互补滤波实现姿态解算，采用GPS与航位推算融合实现室外定位导航。车模能够完成往返直线竞速、八字慢速、复杂路段（坡道、草地、绕桩）等科目的行驶任务。
2.创新点总结
（1）机械结构创新：在车模几何中心横向增加防倾倒杆，在不违反比赛规则的前提下提高了车模的抗倾倒能力；通过后轮右侧和底部的配重块优化了重心位置，改善了平衡控制的动态特性。
（2）多传感器融合导航：将GPS绝对定位与IMU+编码器航位推算相结合，采用基于HDOP和卫星数的动态权重融合策略，在GPS信号短暂丢失时仍能保持一定时间的准确导航，提高了室外复杂环境下的定位鲁棒性。
（3）分路段自适应控制：针对坡道、草地、绕桩等不同路段特征，设计了基于IMU俯仰角的坡道识别与自适应速度控制、基于区域划分的绕桩转角限幅策略，实现了复杂路段的平稳通过。
（4）软硬件协同设计：将FOC算法下放至无刷驱动板的CYT2BL23CAQX执行，主控仅发送速度指令，减轻了主控的计算负担，保证了500Hz平衡控制的实时性。
3.存在的问题与改进方向
尽管本设计完成了基本功能，但在调试和测试过程中也发现了一些有待改进的问题：
（1）自平衡控制在低速和静止状态下仍存在小幅振荡。分析原因主要是舵机的死区和响应延迟影响了角速度环的控制效果。后续可考虑更换响应更快的数字舵机，或在控制算法中引入舵机死区补偿和前馈控制。
（2）GPS定位精度受环境影响较大。在操场周边有建筑物或树木遮挡时，GPS多路径效应导致定位漂移，影响导航精度。后续可引入RTK差分GPS或视觉里程计来提高定位精度，也可优化融合算法中的GPS异常检测与剔除机制。
（3）草地路段的通过稳定性有待提高。草地路面颠簸大、摩擦系数低，车模容易出现打滑和振动。后续可考虑增加悬架结构以吸收颠簸，或在控制算法中引入基于IMU振动检测的路面识别与自适应参数调整。
（4）电磁门导航科目尚未实现。由于时间和传感器选型限制，本设计未搭载电磁传感器，国赛科目四（电磁门导航）暂未完成。后续可增加电磁线圈传感器，研究电磁信号检测与定向通过算法。
（5）参数整定依赖经验。目前PID参数和导航参数主要通过手动调试确定，耗时较长且难以达到最优。后续可研究基于模型的参数整定方法或自适应控制算法，实现参数的自动优化。
4.展望
全国大学生智能汽车竞赛为大学生提供了一个将控制理论、电子技术、机械设计和嵌入式系统等多学科知识综合应用的实践平台。通过本次单车定向组的设计与制作，团队成员深入理解了自平衡控制、多传感器融合和室外导航等关键技术，积累了宝贵的工程实践经验。
未来，自平衡单车技术在个人短途交通、物流配送、园区巡检等领域具有广阔的应用前景。随着MEMS传感器精度的不断提高和微控制器计算能力的持续增强，自平衡单车的稳定性、智能化程度和环境适应能力将不断提升。后续工作可在以下方向继续深入：一是研究LQR、MPC等现代控制算法在自平衡单车上的应用，进一步提升平衡性能；二是引入视觉传感器实现更丰富的环境感知和自主导航；三是探索车联网和多车协同技术，拓展自平衡单车的应用场景。

B.1  自平衡串级PID控制
/* 自平衡控制：外环角度PI + 内环角速度PD，500Hz执行 */
typedef struct {
    float kp;          /* 比例系数 */
    float ki;          /* 积分系数 */
    float kd;          /* 微分系数 */
    float err;         /* 当前误差 */
    float err_last;    /* 上一次误差 */
    float integral;    /* 积分累积 */
    float out;         /* 输出 */
    float out_max;     /* 输出限幅 */
} PID_t;

static PID_t angle_pid  = {.kp = 80.0f, .ki = 5.0f,  .out_max = 300.0f};
static PID_t gyro_pid   = {.kp = 1.2f,  .kd = 0.05f, .out_max = 500.0f};

/* 角度环PI：输入倾角，输出目标角速度 */
float angle_loop(float angle_ref, float angle_fb)
{
    angle_pid.err = angle_ref - angle_fb;
    angle_pid.integral += angle_pid.err;
    /* 积分抗饱和 */
    if (angle_pid.integral >  50.0f) angle_pid.integral =  50.0f;
    if (angle_pid.integral < -50.0f) angle_pid.integral = -50.0f;
    angle_pid.out = angle_pid.kp * angle_pid.err
                 + angle_pid.ki * angle_pid.integral;
    /* 输出限幅 */
    if (angle_pid.out >  angle_pid.out_max) angle_pid.out =  angle_pid.out_max;
    if (angle_pid.out < -angle_pid.out_max) angle_pid.out = -angle_pid.out_max;
    return angle_pid.out;
}

/* 角速度环PD：输入目标角速度和反馈角速度，输出舵机PWM */
float gyro_loop(float gyro_ref, float gyro_fb)
{
    gyro_pid.err = gyro_ref - gyro_fb;
    gyro_pid.out = gyro_pid.kp * gyro_pid.err
                 + gyro_pid.kd * (gyro_pid.err - gyro_pid.err_last);
    gyro_pid.err_last = gyro_pid.err;
    if (gyro_pid.out >  gyro_pid.out_max) gyro_pid.out =  gyro_pid.out_max;
    if (gyro_pid.out < -gyro_pid.out_max) gyro_pid.out = -gyro_pid.out_max;
    return gyro_pid.out;
}

/* 500Hz定时器中断中调用 */
void balance_control_isr(void)
{
    float gyro_target = angle_loop(angle_ref, car.angle);
    float steer_pwm   = gyro_loop(gyro_target, car.gyro);
    servo_set_pwm(STEER_CENTER + (int16_t)steer_pwm);
}
B.2  互补滤波姿态解算
/* 互补滤波：融合加速度计倾角和陀螺仪积分，500Hz执行 */
#define ALPHA       0.02f   /* 加速度计权重 */
#define DT          0.002f  /* 采样周期 2ms */

static float gyro_bias = 0.0f;  /* 陀螺仪零偏 */
static float angle     = 0.0f;  /* 融合后倾角 */

/* 启动时静态校准陀螺仪零偏，取500个样本平均 */
void imu_calibrate(void)
{
    float sum = 0.0f;
    for (int i = 0; i < 500; i++) {
        sum += imu_read_gyro_x();
        delay_ms(2);
    }
    gyro_bias = sum / 500.0f;
}

/* 加速度计计算静态倾角 */
float acc_to_angle(float ax, float ay, float az)
{
    return atan2f(ax, sqrtf(ay * ay + az * az));
}

/* 互补滤波主函数 */
float complementary_filter(float ax, float ay, float az, float gx)
{
    float angle_acc = acc_to_angle(ax, ay, az);
    float gyro_cal  = gx - gyro_bias;   /* 零偏补偿 */
    /* 一阶互补滤波 */
    angle = ALPHA * angle_acc
          + (1.0f - ALPHA) * (angle + gyro_cal * DT);
    return angle;
}
B.3  增量式速度PID控制
/* 增量式PID速度控制，100Hz执行，输出发送给无刷驱动板 */
static PID_t speed_pid = {.kp = 0.5f, .ki = 0.02f, .kd = 0.01f, .out_max = 1000.0f};
static float speed_out = 0.0f;

float speed_inc_pid(float v_ref, float v_fb)
{
    static float e0 = 0, e1 = 0, e2 = 0;
    e2 = e1; e1 = e0;
    e0 = v_ref - v_fb;
    float du = speed_pid.kp * (e0 - e1)
            + speed_pid.ki * e0
            + speed_pid.kd * (e0 - 2*e1 + e2);
    speed_out += du;
    if (speed_out >  speed_pid.out_max) speed_out =  speed_pid.out_max;
    if (speed_out < -speed_pid.out_max) speed_out = -speed_pid.out_max;
    return speed_out;
}
B.4  纯追踪导航算法
/* 纯追踪路径跟踪，100Hz执行 */
#define WHEELBASE   0.18f   /* 车模轴距 m */
#define LD_MIN      0.3f    /* 最小前视距离 m */
#define LD_KV       0.15f   /* 前视距离速度系数 */

typedef struct { float x; float y; } Point_t;
static Point_t waypoints[64];  /* 航点数组 */
static int wp_count = 0;       /* 航点总数 */
static int wp_index = 0;       /* 当前航点索引 */

/* 选取目标航点：前视距离法 */
int select_waypoint(float car_x, float car_y, float speed)
{
    float ld = LD_MIN + LD_KV * speed;
    float acc_dist = 0.0f;
    int idx = wp_index;
    while (idx < wp_count - 1) {
        float dx = waypoints[idx+1].x - waypoints[idx].x;
        float dy = waypoints[idx+1].y - waypoints[idx].y;
        acc_dist += sqrtf(dx*dx + dy*dy);
        if (acc_dist >= ld) break;
        idx++;
    }
    return idx;
}

/* 纯追踪计算期望转向角 */
float pure_pursuit(float car_x, float car_y, float heading, float speed)
{
    int idx = select_waypoint(car_x, car_y, speed);
    wp_index = idx;
    float tx = waypoints[idx].x - car_x;
    float ty = waypoints[idx].y - car_y;
    /* 目标航向角 */
    float psi_target = atan2f(ty, tx);
    /* 航向偏差归一化到[-pi, pi] */
    float alpha = psi_target - heading;
    while (alpha >  PI) alpha -= 2*PI;
    while (alpha < -PI) alpha += 2*PI;
    /* 纯追踪公式 */
    float ld = LD_MIN + LD_KV * speed;
    float delta = atan2f(2 * WHEELBASE * sinf(alpha), ld);
    return delta;
}
B.5  GPS NMEA数据解析
/* GPS NMEA-0183语句解析，$GNGGA和$GNRMC */
typedef struct {
    float lat;       /* 纬度 度 */
    float lon;       /* 经度 度 */
    float speed;     /* 速度 m/s */
    float heading;   /* 航向角 度 */
    uint8_t sat_num; /* 卫星数 */
    float hdop;      /* 水平精度因子 */
    uint8_t valid;   /* 定位有效标志 */
} GPS_t;
static GPS_t gps_data;

/* 校验和验证：$与*之间所有字符异或 */
uint8_t nmea_checksum(char *str)
{
    uint8_t sum = 0;
    while (*str && *str != '*') { sum ^= *str++; }
    return sum;
}

/* 解析$GNGGA：经纬度、卫星数、HDOP */
void parse_gngga(char *buf)
{
    if (nmea_checksum(buf+1) != strtol(strchr(buf,'*')+1, NULL, 16)) return;
    char *p = strtok(buf, ",");
    int field = 0;
    while (p) {
        if (field == 2) gps_data.lat = nmea_to_deg(p);  /* 度分转度 */
        if (field == 4) gps_data.lon = nmea_to_deg(p);
        if (field == 6) gps_data.valid = (atoi(p) > 0);
        if (field == 7) gps_data.sat_num = atoi(p);
        if (field == 8) gps_data.hdop = atof(p);
        p = strtok(NULL, ",");
        field++;
    }
}

volatile uint32_t tick_1ms = 0;  /* 1kHz系统时基 */

int core0_main(void)
{
    /* 外设初始化 */
    imu_init();
    gps_init();
    encoder_init();
    servo_init();
    motor_comm_init();
    balance_init();
    speed_ctrl_init();
    navigation_init();
    state_machine_init();

    /* 陀螺仪零偏校准 */
    imu_calibrate();

    /* 启动1kHz定时器中断 */
    timer_init();

    while (1) {
        /* 100Hz任务：速度控制、导航、航位推算 */
        if (tick_1ms % 10 == 0) {
            car.speed = encoder_get_speed();
            speed_ctrl_update(car.target_speed, car.speed);
            navigation_update();
        }
        /* 10Hz任务：GPS解析、状态机、显示 */
        if (tick_1ms % 100 == 0) {
            gps_parse();
            state_machine_run();
            oled_update();
        }
    }
}

/* 1kHz定时器中断：500Hz平衡控制 */
void timer_isr(void)
{
    tick_1ms++;
    if (tick_1ms % 2 == 0 {
        imu_read(&car.ax, &car.ay, &car.az, &car.gx);
        car.angle = complementary_filter(car.ax, car.ay, car.az, car.gx);
        balance_control_isr();  /* 角度环+角速度环 */
    }
}
