第一章　引言
1.1　项目背景
全国大学生智能汽车竞赛要求参赛队围绕指定车模完成机械、电路、传感器和控制软件的系统设计，并通过可重复的工程调试使车辆在赛道环境中稳定运行。技术报告既是设计结果的说明，也是对制作、安装、标定和验证过程的记录。本文依据第二十一届竞赛技术报告要求组织内容，并将原理图、PCB图和核心程序列入附录。[1]
本车控制系统以英飞凌AURIX TC264D微控制器为核心。软件采用5 ms周期中断作为主控制时基，完成惯性数据读取、姿态估计、转向与速度控制；路径里程更新和前瞻计算按10 ms节拍运行。硬件将主控、电源、通信、调试接口及功率驱动集中在一块四层主驱板上，以缩短连接并便于整车维护。
1.2　模型车设计制作的主要思路
模型车的主要设计思路是把“稳定的基础闭环”和“可切换的赛道任务”分开实现。底层首先保证传感器数据、姿态估计、舵机输出和后轮驱动链路可靠；上层再通过路径记录、里程推算、最近点搜索和前瞻控制生成目标量。这样既便于单独调试每个环节，也能在更换路径或工况时复用同一套基础驱动。
为避免参数变化造成突发输出，程序在启停、模式切换和目标变化处加入状态复位、低通滤波、软启动、输出限幅及变化率限制。调试参数可通过菜单、Flash和遥测链路管理。代码中保留了Kalman、EKF和ESO等可选试验模块，但本报告只对当前主要使用的Mahony姿态估计、增量/位置式控制和惯性路径跟踪作概要介绍。
1.3　技术方案概要
图1.1　智能车主驱控制系统总体结构
如图1.1所示，系统从ICM42688惯性传感器、前轮正交编码器以及PWM输入获得状态信息，经TC264D完成姿态与里程估计、路径任务管理和控制计算，最终以300 Hz PWM驱动转向舵机，并通过UART向后轮驱动器发送速度或占空比命令。屏幕、Flash与调试遥测用于参数配置和状态观察。当前主程序中的GNSS硬件初始化处于注释状态，因此不把GNSS列为现阶段主要赛道信息源。

第二章　总体方案与机械系统
2.1　整车总体布置
整车布置遵循重心集中、惯性器件稳定、动力与信号分区、连接可维护的原则。主驱板位于车体中部的刚性安装面，电池和大电流线束靠近功率输入侧，惯性器件尽量接近车体纵向中心并与车身坐标轴平行。PCB板尺寸为91 mm×60 mm，四角圆角并设有固定位置，孔距为82.5 mm×52 mm，支柱高度为22mm。
图2.1　整车布置图片
2.2　机械部分安装及改造
机械改造以不改变车模基本驱动形式为前提，重点处理主驱板安装面、线束通道、传感器支架和防松结构。金属固定件用热熔胶或胶带隔离，避免与PCB焊点、功率器件和测试点接触；板下留出绝缘距离，使用尼龙支柱做绝缘处理。电池、主驱板和线束的质量分布左右基本对称，避免增加不必要的偏载。
车架、轮胎、转向机构和传动部分的实际改造内容：轮胎涂上胶水防止脱落，尾部使用加固件防止车身变形。
主驱板支柱材料、数量、高度及安装孔位：固定板孔距为82.5 mm×52 mm，三根绝缘尼龙柱高度为22mm。
整车防护的安装方式：硬质海绵条配合可拆卸魔术贴，防止车身撞击。
2.3　传感器设计安装
ICM42688为六轴惯性器件，安装质量直接影响姿态计算。器件与车体用AB胶稳固连接，位于车体纵向中心并与车身坐标轴平行，避开电机、齿轮和松动结构引起的高频振动，同时明确X、Y、Z轴与车体前向、横向、竖向的对应关系。上电后车辆应保持静止完成零偏和初始姿态估计；器件下方选用薄而稳定的3D打印件以便减振，避免形成低频摆动。[3]
后轮磁编码器 TLE5012BE1000 通过CYT2BL3 SCB3 SPI 接口接入 P6.0/P6.1/P6.2，P6.3 为 SPI 片选控制引脚。单片机通过 SPI 总线读取编码器寄存器数据，解析得到转动方向与脉冲增量。编码器支架应无相对滑动，信号线与电机相线分开走线。代码中的换算系数需要依据实际轮径、传动关系和标定距离复核，标定结果应记录原始脉冲、标准距离和重复测量误差。
表2.1　传感器安装与标定要点
2.4　系统电路板固定及连接
主驱板连接包括电池输入、舵机、后轮驱动、编码器、遥控、屏幕、蓝牙/调试和下载接口。大电流电源与电机连接应使用足够截面积的导线并做应力释放，低电平传感器线束尽量短且远离MOS开关节点。
电路板与车架之间应保持绝缘，固定螺钉不得压到走线和焊盘。线束在转向极限、悬架运动和电池拆装时均不应被拉紧。建议在电池输入、舵机、编码器和下载接口附近设置明显标签，并为关键线束留出可快速更换的余量。
2.5　安全性与可维护性
软件设置了启停状态复位、姿态范围判断、目标软启动、输出限幅和终点停车锁存等保护。机械上设置可靠的总电源开关，并在调试时采用架空车轮、限制占空比和逐级升压的方法。任何传感器方向、舵机方向或电机方向变化后，都必须重新进行低功率验证。

3.2　电源输入与电压变换
电源部分以电池输入为源，分别形成7.4 V、5 V和3.3 V等电压域。各级变换周围布置输入/输出电容、续流或保护器件，并区分功率地与信号地的回流路径。上电调试应先断开舵机和电机负载，逐级确认空载电压、纹波和器件温升，再接入负载测试。

	C_total = Σ C_i ≈ 1833.90μF	（公式1）
3.3　主控、时钟与调试接口
核心控制器为Infineon AURIX TC264D，板上配置时钟、复位、供电去耦和调试接口。主控的SPI、UART、PWM、编码器和捕获通道连接到传感器及执行器。本报告对与整车相关的接口和供电关系作出概要说明。[2]
调试接口用于程序下载和在线观察，复位与电源监测用于提高启动可靠性。布线时，时钟和高速数字信号尽量短而连续，去耦电容靠近电源引脚，模拟参考和电压监测信号避开功率开关区域。
3.4　传感器、通信与人机接口
ICM42688通过SPI0连接，MOSI、MISO、CS和SCK分别使用P20.14、P20.12、P20.13和P20.11，软件配置通信速率为10 MHz。屏幕、蓝牙、按键与指示灯用于显示、参数设置和状态提示。
后轮驱动采用UART通信，核心控制器为CYT2BL3。后轮磁编码器 TLE5012BE1000 通过CYT2BL3 SCB3 SPI 接口接入 P6.0/P6.1/P6.2，P6.3 为 SPI 片选控制引脚。当前驱动控制模块配置为UART1、460800 bit/s。通信帧包含命令、数据和校验，既可发送直接占空比，也可发送速度闭环参数及目标速度。连接时需确认主控与驱动板的收发方向、电平和公共地。
3.5　电机预驱与功率级
P5以FD6288Q作为预驱并连接MOS功率级，输入侧配有多级电容和保护器件。功率级的设计重点是栅极驱动回路短、功率回路面积小、散热路径明确，并避免开关电流经过敏感信号地。报告只对功能分区作说明，具体器件连接、阻容值和网络名称以附录A原理图为准。

第四章　控制软件设计
4.1　软件总体结构
软件运行在TC264D平台，工程由用户入口、中断服务、器件驱动、姿态估计、控制器、惯性导航、菜单/Flash和调试通信等模块组成。主程序完成时钟、调试口、IMU、编码器、屏幕、后轮驱动、PWM和周期中断初始化，实时控制主要在5ms中断中执行。
图4.1　5ms控制周期与多速率任务调度
基础控制周期为5ms，即200 Hz。惯性里程更新与路径处理按10 ms，即100 Hz运行。驱动器通信、遥测和菜单显示采用分频或事件触发方式，避免把所有任务集中到同一时刻。ICM42688器件ODR为1000 Hz，而主控实际读取和使用频率为200 Hz，两者不能混为同一技术指标。
	Δt = 1 / f_s = 1 / 200 = 0.005 s	（公式2）
4.2　初始化与运行模式
上电后程序先读取已保存路径索引和Mahony参数，再按当前路径选择IMU量程。通用配置为陀螺仪±2000 °/s、加速度计±8 g、ODR 1000 Hz；当路径索引为1时，软件改用陀螺仪±250 °/s和加速度计±2 g，以提高该工况的小量程分辨能力。两种配置均使用1000 Hz器件输出数据率。
IMU初始化成功后，程序丢弃50个样本并对150个静态加速度样本求平均，由此估计初始横滚和俯仰角。Mahony算法以200 Hz初始化，默认Kp为1.5、Ki为0.005；Flash中保存的分路径参数可覆盖默认值。随后初始化前轮编码器、TFT屏幕、后轮驱动通信、300 Hz转向PWM和两路PWM捕获。
4.3　数据采集与预处理
ICM42688一次读取三轴加速度和三轴角速度原始值，并按量程灵敏度换算为物理量。程序减去陀螺仪静态零偏，对速度反馈和部分控制信号进行低通滤波。车辆转弯时，横向加速度会影响姿态估计，软件根据速度与航向角速度估算向心加速度并进行可选补偿。
编码器速度既可直接用于速度环，也可按导航节拍积分为里程。惯性导航支持后轮速度或前轮编码器作为里程来源，使用前应统一单位、方向和比例。两路PWM输入先测量占空比，再做中值和有效范围判断，以避免输入抖动造成目标突变。
4.4　Mahony姿态估计
Mahony算法以陀螺仪积分获得快速姿态变化，并利用归一化重力方向修正长期漂移。程序以四元数表示姿态，计算估计重力与实测加速度之间的误差，经比例和积分反馈修正角速度，再更新四元数并换算横滚、俯仰和航向角。该方法计算量较小，适合200 Hz实时运行。[4]
姿态算法的实际效果不仅取决于Kp、Ki，还受传感器安装方向、零偏、振动、加速度干扰和采样周期影响。因此调试时先验证静态角度和慢速倾斜，再在架空和低速条件下观察动态响应，最后进入赛道。
4.5　转向、平衡与速度控制
控制层包含增量式PI/PID和位置式PD。角度外环根据目标横滚角与估计横滚角的偏差生成角速度目标，角速度内环再计算转向PWM；速度环根据目标速度与编码器反馈调整后轮命令。不同路径、直道/弯道和坡道可以使用不同参数组，但控制器接口和限幅逻辑保持一致。
	Δu(k) = K_p[e(k)-e(k-1)] + K_i e(k)	（公式3）
程序在控制输出后执行PWM滤波、变化率限制和上下限约束，舵机输出固定在安全占空比范围内。速度目标经过软启动和最大值限制；模式切换、起步和停车时清除历史误差，减少旧状态对新工况的影响。
4.6　惯性路径记录与前瞻控制
惯性导航最多管理3条路径，每条路径最多1000个二维点。记录模式以累计距离为依据，默认每10 cm保存一个点，并可附加直道、弯道、坡道或锥桶等标记。运行时程序根据速度与航向角更新二维位置，搜索当前最近路径点，再在路径前方选择满足前瞻距离的目标点。
	x_k=x_{k-1}+v_kΔt cosψ_k，　y_k=y_{k-1}+v_kΔt sinψ_k	（公式4）
前瞻距离可随速度和工况调整。路径点标记用于切换直道、弯道、坡道和锥桶区域的目标速度及控制参数；终点附近可触发停车锁存。该方法依赖里程比例和航向估计，赛前需要用同一路径多次记录与复现，检查累计误差和终点一致性。
4.7　保护、调试与参数管理
软件包含启动边沿复位、横滚角范围判断、跌倒保护、目标软启动、输出限幅、变化率限制、通信校验和终点停车等措施。调试遥测记录姿态、角速度、目标横滚、舵机PWM、前后轮速度、路径索引和剩余点数，便于对比实际响应。参数可通过菜单和调试命令调整，并按路径保存到Flash。

5.2　电路板制作与上电检查
PCB焊接后先进行目视和显微检查，确认芯片方向、焊桥、虚焊、连接器方向及功率器件散热焊盘。不上电时测量电池输入、各电源轨对地阻值；首次上电使用限流电源，依次检查7.4 V、5 V和3.3 V节点。电压正常后再连接下载器、屏幕、传感器、舵机和驱动负载。
5.3　上电检查
检查电源输入极性、保险/保护器件及总开关状态。
确认3.3 V、5 V和7.4 V空载及带载电压，记录纹波与温升。
检查调试口、复位、时钟和主控下载是否稳定。

5.4　整车安装与接线

第七章　结论与改进方向
7.1　工作总结
本模型车完成了以TC264D为核心的主驱控制系统设计。四层主驱板集成多电压电源、主控与调试接口、通信与人机接口、编码器输入及电机预驱/功率级；固件建立5 ms实时控制时基，实现ICM42688数据采集、Mahony姿态估计、前轮编码器反馈、转向与速度闭环、惯性路径记录和前瞻控制，并提供软启动、限幅、保护、参数保存和遥测功能。
7.2　存在的问题
惯性路径方案会受到陀螺零偏、编码器比例误差和轮胎滑移的累积影响；车辆振动和转弯向心加速度也会影响姿态估计。代码中参数与模式较多，若缺少统一的试验记录，容易出现参数组混用。
7.3　进一步改进方向
后续应首先完成整车机械和电气参数实测，建立可复现的标定表与赛道试验记录；其次优化IMU安装、供电纹波和功率回流，减少振动及开关噪声；再次整理参数版本和路径数据，形成从低速验证到比赛参数的分级配置。

  64  void Mahony_Update(Mahony_Handle_t *handle, float gx, float gy, float gz, float ax, float ay, float az) {
  65      float recipNorm;
  66      float halfvx, halfvy, halfvz;
  67      float halfex, halfey, halfez;
  68      float qa, qb, qc;
  69      float dt = 1.0f / handle->sampleFreq;
  70      float gy_deg = gy;
  71      float gz_deg = gz;
  72      float roll_rad;
  73      float pitch_rad;
  74      float cos_pitch;
  75      float psi_dot_deg;
  76  
  77      gx *= 0.0174532925f;
  78      gy *= 0.0174532925f;
  79      gz *= 0.0174532925f;
  80      if (!((ax == 0.0f) && (ay == 0.0f) && (az == 0.0f))) {
  81          recipNorm = invSqrt(ax * ax + ay * ay + az * az);
  82          ax *= recipNorm;
  83          ay *= recipNorm;
  84          az *= recipNorm;
  85  
  86          halfvx = handle->q1 * handle->q3 - handle->q0 * handle->q2;
  87          halfvy = handle->q0 * handle->q1 + handle->q2 * handle->q3;
  88          halfvz = handle->q0 * handle->q0 - 0.5f + handle->q3 * handle->q3;
  89  
  90          // error = a x v
  91          halfex = (ay * halfvz - az * halfvy);
  92          halfey = (az * halfvx - ax * halfvz);
  93          halfez = (ax * halfvy - ay * halfvx);
  94  
  95          if (handle->Ki > 0.0f) {
  96              handle->integralFBx += handle->Ki * halfex * dt;
  97              handle->integralFBy += handle->Ki * halfey * dt;
  98              handle->integralFBz += handle->Ki * halfez * dt;
  99              gx += handle->integralFBx;
 100              gy += handle->integralFBy;
 101              gz += handle->integralFBz;
 102          } else {
 103              handle->integralFBx = 0.0f;
 104              handle->integralFBy = 0.0f;
 105              handle->integralFBz = 0.0f;
 106          }
 107  
 108          gx += handle->Kp * halfex;
 109          gy += handle->Kp * halfey;
 110          gz += handle->Kp * halfez;
 111      }
 112  
 113      gx *= (0.5f * dt);
 114      gy *= (0.5f * dt);
 115      gz *= (0.5f * dt);
 116  
 117      qa = handle->q0;
 118      qb = handle->q1;
 119      qc = handle->q2;
 120  
 121      handle->q0 += (-qb * gx - qc * gy - handle->q3 * gz);
 122      handle->q1 += (qa * gx + qc * gz - handle->q3 * gy);
 123      handle->q2 += (qa * gy - qb * gz + handle->q3 * gx);
 124      handle->q3 += (qa * gz + qb * gy - qc * gx);
 126      recipNorm = invSqrt(handle->q0 * handle->q0 + handle->q1 * handle->q1 + handle->q2 * handle->q2 + handle->q3 * handle->q3);
 127      handle->q0 *= recipNorm;
 128      handle->q1 *= recipNorm;
 129      handle->q2 *= recipNorm;
 130      handle->q3 *= recipNorm;
 131  
 132      // Roll (x-axis rotation)
 133      // Pitch (y-axis rotation)
 134      // Yaw (z-axis rotation)
 135      handle->pitch = asin(2.0f * (handle->q0 * handle->q2 - handle->q1 * handle->q3)) * 57.29578f;
 136      handle->roll  = atan2(2.0f * (handle->q0 * handle->q1 + handle->q2 * handle->q3), handle->q0 * handle->q0 - handle->q1 * handle->q1 - handle->q2 * handle->q2 + handle->q3 * handle->q3) * 57.29578f;
 137      handle->yaw   = atan2(2.0f * (handle->q1 * handle->q2 + handle->q0 * handle->q3), handle->q0 * handle->q0 + handle->q1 * handle->q1 - handle->q2 * handle->q2 - handle->q3 * handle->q3) * 57.29578f;
 138  
 139      roll_rad = handle->roll * 0.0174532925f;
 140      pitch_rad = handle->pitch * 0.0174532925f;
 141      cos_pitch = cosf(pitch_rad);
 142      if (fabsf(cos_pitch) < 0.1f) {
 143          cos_pitch = (cos_pitch >= 0.0f) ? 0.1f : -0.1f;
 144      }
 145  
 146      psi_dot_deg = (gy_deg * sinf(roll_rad) + gz_deg * cosf(roll_rad)) / cos_pitch;
 147      handle->nav_yaw_rate_lpf = NAV_YAW_LPF_ALPHA * psi_dot_deg + (1.0f - NAV_YAW_LPF_ALPHA) * handle->nav_yaw_rate_lpf;
 148      handle->nav_yaw = wrap_angle_deg(handle->nav_yaw + handle->nav_yaw_rate_lpf * dt);
 149  }
