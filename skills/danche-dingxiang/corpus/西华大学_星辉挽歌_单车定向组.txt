摘  要
本文以第二十一届全国大学生智能汽车竞赛为依托，研究对象为单车定向组别中的N1型车模，围绕其整车控制系统的硬件架构与软件逻辑展开论述。全文系统阐述了从方案设计到实物搭建的完整过程，核心内容如下：在技术路线方面，系统采用惯性导航作为主要循迹手段。主控平台选用英飞凌TC264D微控制器，配合CYT2BL3单片机实现单路无刷电机的驱动管理；姿态感知方面搭载IMU660RA六轴传感器，实时解算车体当前方位角与横滚角，为运动控制提供精确的姿态基准。控制策略上，采用三串级PID算法对舵机转向角进行闭环调节，通过多级串联的控制结构实现车速与转向的协同配合，确保整车在行驶过程中具备良好的动态响应与路径跟踪能力。人机交互层面，系统配备TFT显示屏幕及按键输入模块，构建了直观的操作界面，可实时呈现偏航角、横滚角等关键运行参数，方便操作者随时掌握车体工作状态。硬件设计中，重点完成了车体模块的空间布局优化、防撞结构改进、机械连接件调校以及电路原理图绘制等工作。软件方面则涵盖了传感数据采集、信息融合处理到控制量输出的全链路实现，并引入多种优化算法对车体姿态进行闭环校正，最终保证各项性能指标满足赛题要求，顺利完成既定任务。  
关键词：智能车，硬件设计，软件系统，TC264D，INS，PID

Abstract
This paper is based on the 21st National College Student Intelligent Car Competition, focusing on the N1-type car model used in the single‑vehicle directional group. It discusses the hardware architecture and software logic of the vehicle’s integrated control system. The entire process from scheme design to physical implementation is systematically elaborated. In terms of technical approach, the system adopts inertial navigation as the primary tracking method. The main control platform is an Infineon TC264D microcontroller, assisted by a CYT2BL3 MCU for driving the single brushless DC motor. For attitude perception, an IMU660RA six‑axis sensor is mounted to provide real‑time estimates of the vehicle’s heading angle and roll angle, serving as an accurate attitude reference for motion control. The control strategy employs a three‑cascade PID algorithm to regulate the steering servo angle in a closed‑loop manner. Through this multi‑stage cascaded structure, speed and steering are coordinated to ensure good dynamic response and path‑tracking capability during operation. At the human‑machine interface level, a TFT display and key input module are equipped to build an intuitive operation panel, which displays critical parameters such as yaw angle and roll angle in real time, allowing the operator to monitor the vehicle’s status conveniently. In hardware design, efforts focus on spatial layout optimization of the car body modules, improvement of anti‑collision structures, adjustment of mechanical connectors, and schematic circuit design. In software, the complete data chain from sensor data acquisition and information fusion to control output is implemented, with multiple optimization algorithms introduced for closed‑loop attitude correction. Ultimately, all performance indicators meet the competition requirements and the assigned tasks are successfully accomplished.
Keywords: intelligent vehicle, hardware design, software system, TC264D, INS, PID

第二章  系统总体设计
2.1 系统总体方案的设计
智能车的整体实现依赖于多个功能单元与结构层次的协同运转，其构建内容涵盖软硬件协同设计、电气系统搭建以及车体结构规划等多个维度。本文重点阐述车辆机械架构的具体实现与模块化布置方案，同时涉及电路原理图的构思过程与PCB制板实践，以及基于TC264D主控芯片的算法逻辑设计与软件编码实现。在以上基础上，文章系统梳理了整个系统架构的总体方案规划、迭代优化策略以及联调联试阶段的完整流程。
2.1.1 方案总体设计背景
第二十一届全国大学生智能车竞赛设置多项室外场地科目，对参赛车模的平衡维持能力与自主路径跟踪性能提出了较高要求。本设计选取N1型电动单车模型作为载体，以TC264D芯片作为运算核心，完全依托前轮舵机转向机构来完成车体动态平衡的维持。系统获取姿态与空间方位的手段依赖于惯性导航模块，通过六轴姿态传感器进行数据融合与解算[1]，实时输出横滚角与航向角信息，整个过程不接入GPS或视觉传感器，从而有效屏蔽了外部光照变化及信号遮挡带来的干扰因素。针对惯导系统存在的累积漂移问题，采用了中值滤波结合动态加速度补偿策略进行误差抑制。在控制架构方面，运用串级PID结构对方向环与平衡环实施协同闭环调控，确保车模在直线路段、弯道区域及不平整路面条件下均能维持稳定的行驶姿态。面向赛道中多样化的地形元素，经过对滤波参数与控制周期的反复整定与验证，有效增强了系统对不同工况的适应能力，提高了各项任务的顺利完成率。
2.1.2 总体方案流程框图
综合考虑赛道的户外环境特性、光照变化对视觉方案的干扰以及控制精度的实际需求，本系统最终选用“惯性导航（INS）+六轴姿态传感器”作为核心循迹方案，不依赖GPS等外部信号，完全依靠车体自身传感实现自主导航与路径跟踪。

系统以TC264D为控制核心，车体人机交互由TFT屏幕和多个按键开关组成，结合IMU660RA六轴姿态传感器模块，通过惯导解算实时获取车模的位置、航向角及姿态信息，在准备阶段标定起点及目标点方位，传递至主控进行数据保存与处理。主控通过串级PID控制架构实现多闭环调节：姿态解算输出的横滚角（Roll）经串级PID驱动舵机打角，形成车体平衡主环；惯导解算的实时航向角与目标方位角的偏差，经方向环PID进一步修正舵机目标转角，实现循迹方向的闭环；速度环根据当前车速与目标速度的偏差，通过PID调节电机转速，实现速度的控制；三个控制环协同工作，最终实现车模在不同赛道元素下的高精度循迹行进。TFT屏幕可实时显示姿态角及编码器积分等信息，方便现场调试与参数整定。我们的总体设计框图如下：

第三章  车辆机械结构设计
在智能车设计中，车辆自身的机械结构对整体系统起着决定性作用，因为它是系统的基础框架与物理载体。因此，搭建一套完整且合理的车体机械结构就显得十分关键。在本章中，我们将详细阐述本组智能车机械结构的设计方案。讨论的重点将集中在与机械结构相关的若干环节，包括N1型车模的机械装配、各功能模块的集成安装、系统电路板的可靠固定与连接，以及防护装置的设计与布设。
3.1  N1型车模机械部分安装
我们使用的N1型车模全身由金属制成耐撞耐摔，车模长29.7cm，宽5cm，高7cm。后轮我们使用N1型车模自带BDS3620直流无刷电机[2]，电压范围在7.4V-12V，空载转速可达到6000rpm，堵转电流12A,其较大扭矩提供强劲动力。舵机型号为BDS300，使用电压范围为7.4V，工作频率为50~300Hz，不同电压下响应速度（速度/60°）：0.15s/6.0V、0.14s/6.6V、0.13s/7.4V，用此来控制车辆转向。
电机通过固定板固定在车身，舵机通过六角圆盘与前轮相连，其余模块我们使用自制3D打印件作为总安装载体，安装一个打印件在车顶部方便拿取。







图3.1  N1型车模整体安装

3.2 各个模块的安装
3.2.1 姿态传感器模块的安装
姿态传感器模块较为灵敏对摆放位置有要求，靠前靠后，太高太低，偏左偏右均有影响。
我们认为，作为平衡的核心模块，姿态传感器模块的安装位置直接影响其误差大小。于是我们根据车模上预留的一些孔位将其安置于车身略靠前，高度在中间，处于车模中轴线的位置，最大程度上让其准确检测车身姿态，减小误差。
然而，通过多次测试，我们发现使用热熔胶或胶带固定会脱落，为解决这个问题利用车模上的预留孔重新设计模块使用螺母、螺栓将其固定在车模上，并取得了显著的效果。

第四章 硬件电路设计
4.1 硬件电路系统设计方案
硬件电路是车辆的基础，配合算法和模块构成骨架。只有稳定的硬件环境，车辆才能平稳行驶。因此，在系统设计中参考多种方案，绘制实用的电子电路。我们以实用和稳定为设计原则，在满足模块要求的情况下，实现易更换易拆卸。电路模块分为三部分：TC264D核心板、主板电路、驱动板电路。核心板是系统的大脑，处理整合信息，控制电机和舵机运动。为确保核心板正常工作且信号稳定，我们分开设计主板上的控制电路和电源电路，减小干扰，使控制更精确。主板大致分为核心板接口底座、屏幕接口、电机驱动接口、舵机接口、姿态传感器接口、无线通信接口和电源接口等。
4.2 TC264D核心板介绍 
TC264D核心板采用BTB封装，具备双核架构，主频均为200MHz[3]。芯片ROM和RAM都享有ECC保护，供电电压可为5V或3V。TC264D微控制器在信息处理方面更为敏捷便利，内置ROM和RAM，并有众多I/O端口，可与外部总线连接。在应对复杂的控制需求时，其结构简明，便于调试，代码易于理解。

第五章  软件算法方案和相关代码的设计介绍
控制程序是设计者意图在车模平台上的具体映射，其代码结构需具备系统性、模块化和高可靠性，核心目标在于充分释放硬件电路与机械结构的全部潜能，使车模能以最稳健的状态完成全程比赛。简而言之，就是通过规范化的软件设计，将人的策略稳定地转化为车模的优异表现。
5.1 系统底层初始化
系统启动时，首先完成所有外设及软件参数的统一初始化，涵盖屏幕、舵机、按键等基础模块，以及对无刷电机驱动进行配置，并通过串口与驱动单元建立通信协议，确保控制指令正常下发。
软件参数从Flash中读取并赋给对应变量，使每次上电后的运行状态与上次存入flash的结果保持一致。除系统级初始化外，发车之前还需执行陀螺仪计算所得姿态角的零位校正，以消除零漂影响，获得准确的姿态角数据。
整体初始化流程兼顾了外设配置、参数持久化、传感器校准和运行状态刷新，为后续控制算法的稳定执行奠定基础。


图5.1 系统初始化

5.2 平衡与转向控制
对于纯舵机平衡、后轮驱动的两轮电单车系统，车模不存在动量轮等附加力矩执行机构，其自衡与转向力矩完全依赖前轮转向角与地面接触产生的侧向力。因此，直立平衡与路径循迹与舵机高度耦合。在直立控制中，传感器数据处理尤为关键。系统采用六轴惯性测量单元（IMU660RA）采集姿态信息，对其积分可间接获得横滚角变化量，然而积分漂移问题使得长期结果不可靠，仅在短期内有效。加速度计在静止时仅受重力作用，通过两轴反正切运算可获得真实横滚角，但行驶振动会引入干扰，导致角度不准确。因此，需将两者数据进行融合，以获取可靠的角度估计[6]。
	控制系统结构上采用“转向环-角度环-角速度环”三串级位置式PID控制架构[7]。三环自外向内协同工作：最外层转向环根据赛道偏差计算出车模所需的期望倾角；中层角度环跟踪该期望倾角并解算出期望侧倾角速度；最内层角速度环抑制车身角速度扰动，最终输出为舵机 PWM 控制量。调试时遵循“由内向外、逐环收敛”原则：
1.角速度环，该环核心作用是提高系统动态响应并增强姿态阻尼。单独调试内环时，给定比例系数P，手持车模快速左右晃动并观察前轮动作：车身向右侧快速晃动时，前轮应迅速向右偏转以做同向补偿；若前轮反向偏转，则说明反馈极性错误，需对角速度误差或输出符号取反纠正。
2.角度环，该环负责维持车体静态平衡与倾角跟踪。单独调试角度环时，加入比例控制，使车模处于静止倾斜状态，观察前轮偏角：车身向一侧倾斜时，前轮应维持朝向倾斜侧的静态偏角，且偏角大小与倾斜程度成正比。
3.转向环，负责根据赛道信息产生转向指令。两轮单车的转向动力学具有典型的非最小相位特性（即逆操舵特性）：当车速较高时，车模转弯必须通过侧倾产生向心力。转向环检测到赛道偏差后，若需向右转向，系统不能直接右打舵，而是先微幅向左“逆打舵”，使车轮接地点左移，利用重力力矩诱发车体向右侧倾；待车体达到期望倾角后，舵机迅速顺势右拐，平衡重力力矩与转
弯离心力，完成压弯与循迹。 
初步调参完成后，可进一步优化PID参数以提升系统稳定性。其中，三个环均采用PD控制。调试过程中，可通过无线串口将数据实时发送至上位机显示，便于观测和分析响应曲线，提升调试效率。调试时应先屏蔽转向环，仅使平衡环（角度环+角速度环）生效，待直立稳定后再逐步加入转向环。
关于循迹控制，由于单车无论是直立还是循迹，最终输出都体现在舵机的同一路控制量上，因此两者相互耦合，任一环节出现问题都会破坏整车稳定性。另外在科目二低速任务中，车速极低，转向必须兼顾大曲率转向机动与微小扰动下的快速支点平移。此时，角速度内环的微分阻尼作用会严重抑制舵机的快速大角度偏转，造成姿态响应相位严重滞后。为此，系统在该模式下主动切除角速度内环，重构为“转向环 - 角度环”的双串级架构，并使用陀螺仪z轴角速度代替转向环D项，角度环加入I项控制，以提高车模稳定性。
5.3 惯性导航
在智能车竞赛中，惯性导航系统需要根据赛道场景的不同采取差异化的路径记录与定位策略，因此我们针对科目二与科目三分别设计了惯导方案。
科目二为绕锥桶等对定位精度要求极高的特殊路段，GPS因固有精度限制和多路径效应完全无法满足需求。为此，系统采用手推式路径标定方法：沿目标路径手动推行车辆，编码器实时累计行进距离，每当行进距离达到预设的单位长度（如每30cm），系统便记录下当前时刻陀螺仪解算出的航向角，并将其作为一个路径特征点存入Flash。推行完毕后，整条路径由一系列等距分布的方向信息构成。正式运行时，车模按顺序依次跟踪各特征点的方向指令，实现精准绕桶行驶。该方式操作简便、标定效率高，尤其适用于连续曲线路径的快速预设。
科目三赛道距离较长、路径复杂度提升，单纯依靠预设方向点难以满足全程定位需求，因此系统切换至基于XY坐标的航位推算定位方案[8]。该算法深度融合编码器与IMU数据：编码器提供高精度的车轮转速，换算得到车辆位移增量（ΔS）；IMU（陀螺仪）以高频方式提供实时的航向角变化量（Δθ）。在

6.1 烧录及编写代码工具（AURIX Development Studio）
英飞凌推出的AURIX Development Studio（简称ADS），是一套专为AURIX系列多核微控制器打造的嵌入式软件开发平台[5]。作为一个功能完整的集成开发环境，ADS将代码编辑、编译构建、调试追踪和仿真运行等环节整合在同一框架内[10]，显著简化了从工程创建到固件部署的整体流程。
在编码阶段，ADS提供对C和C++的原生支持，并辅以语法高亮、智能补全和交互式调试等辅助功能，帮助开发人员提升编码效率与程序质量。当程序进入调试环节时，开发者可以实时操控目标芯片的运行状态，自由设置断点、监测变量变化、查看寄存器现场，从而深入追踪程序行为，快速定位逻辑或时序问题。
仿真与虚拟化能力则允许开发人员在无需真实硬件的情况下，通过模拟器提前验证系统行为和接口逻辑，为后续的硬件联调做好准备。在性能调优方面，ADS内置了多种分析工具，可用于捕捉执行热点和资源占用情况，辅助开发者识别并消除性能瓶颈，使应用运行更加高效。
编译完成后，开发者可借助ADS将生成的固件直接烧录至AURIX芯片中进行实机验证，确保软件在实际工况下的功能正确与长期稳定。此外，英飞凌还配套提供了详尽的用户文档、技术指导和培训资源，为开发者在使用ADS过程中遇到的各类问题提供支撑，保障项目顺利推进。

float get_inertia_points_azimuth (double inertia_x_1, double inertia_y_1, double inertia_x_2, double inertia_y_2)
{
    float azimuth=0;
    double x_x_dif=0;
    double y_y_dif=0;
    x_x_dif=inertia_x_2-inertia_x_1;
    y_y_dif=inertia_y_2-inertia_y_1;
    azimuth=((atan2(x_x_dif,y_y_dif)*M_180_D_PI));//以y正半轴为0度，顺时
    if (azimuth < 0) {
        azimuth += 360; // 确保范围在 0 到 360 度
    }
    return azimuth;
}
float get_inertia_points_distance (double inertia_x_1, double inertia_y_1, double inertia_x_2, double inertia_y_2)
{
    float distance=0;
    double x_x_dif=0;
    double y_y_dif=0;
    x_x_dif=inertia_x_2-inertia_x_1;
    y_y_dif=inertia_y_2-inertia_y_1;
    distance=sqrt((x_x_dif*x_x_dif+y_y_dif*y_y_dif));
    return distance;
}

 // 函数简介     Balance_Lookup —— 在PID表中查找speed<=target且最接近的条目
static Speed_PID_Entry* Balance_Lookup(int16 target)
{
    uint8 i;  // 循环索引

    // 地板: 目标速度小于表最小值, 返回表头作为地板值
    // 加速方向: 如TURN=15重启→Lookup(25)→返回30→跳到30速度+正确PID
    // 减速方向: 如decel到30→Lookup(20)→返回30→调用方DECEL地板检测转入ELEMENT_READY
    if (target < PID_Table[0].speed)                // target < 30
    { table_idx = 0; return &PID_Table[0]; }        // 缓存指向表头, 返回地板块

    // 目标速度 >= 缓存位置的speed: 从缓存位置向前搜索(加速方向)
    if (target >= PID_Table[table_idx].speed)
    {
        i = table_idx;                               // 从缓存位置开始
        while (i+1 < PID_TABLE_SIZE                      // 未越界
            && PID_Table[i+1].speed <= target)       // 下一个条目speed仍<=target
            i++;                                     // 向前移动
    }
    // 目标速度 < 缓存位置的speed: 从缓存位置向后搜索(减速方向)
    else
    {
        i = table_idx;                               // 从缓存位置开始
        while (i > 0                                 // 未到表头
            && PID_Table[i].speed > target)          // 当前条目speed仍>target
            i--;                                     // 向后移动
    }
    table_idx = i;                                   // 更新缓存位置供下次使用
    return &PID_Table[i];                            // 返回查找到的条目指针
}
// 函数简介     Balance_Locate_Index —— 初始定位缓存索引
static void Balance_Locate_Index(int16 speed)
{
    table_idx = 0;                                   // 从表头开始
    while (table_idx+1 < PID_TABLE_SIZE                  // 未越界
        && PID_Table[table_idx+1].speed <= speed)    // 下一个条目speed仍<=目标
        table_idx++;                                 // 向后移动到最佳位置
}
// 函数简介     Balance_Count_Segments —— 统计实际表内速度段数
static int16 Balance_Count_Segments(int16 from, int16 to_limit, int8 direction)
{
    int16 seg = 0;                                   // 段数计数器, 初始0
    int16 v = from;                                  // 当前速度, 从起点开始

    // 循环直到越过to_limit: 加速方向v<to_limit继续, 减速方向v>to_limit继续
    while ((direction>0 && v<to_limit) || (direction<0 && v>to_limit))
    {
        int16 target = v + direction * SUB1_SPEED_STEP;  // 下一个目标速度(=当前+方向×步长)

        // 全表扫描: 找speed<=target且差值最小的条目
        Speed_PID_Entry* best = NULL;                // 最佳匹配条目指针, 初始空
        int16 best_diff = 32767;                     // 最佳匹配差值, 初始极大
        uint8 i;
        for (i=0; i<PID_TABLE_SIZE; i++)                 // 遍历全表
        {
            int16 d = target - PID_Table[i].speed;   // 差值(越大说明条目speed越小)
            if (d >= 0 && d < best_diff)             // 条目speed<=target 且 差值更小(更接近)
            { best_diff = d; best = &PID_Table[i]; } // 更新最佳匹配
        }
        if (best==NULL || best->speed==v) break;     // 无匹配或速度未变化, 停止
        v = best->speed;                             // 更新当前速度为匹配条目的速度
        seg++;                                       // 段数+1
    }
    return seg;                                      // 返回实际段数
}
