第一章  引言
1.1 项目背景
本车以两轮直立/转向耦合车模为对象，面向第21届全国大学生智能汽车竞赛科目二和科目三任务。车体在低速和转弯过程中具有明显的横滚不稳定性，转向既承担航向调整任务，又是维持横向动态平衡的主要执行手段；与此同时，无刷电机速度、坡道姿态、航向累积误差和无线调试链路共同影响完赛可靠性。串级控制器采用位置式或增量式 PID，参数与限幅均以当前工程为准[8]。
车模动力由本队自制无刷驱动板控制，板级设计见第四章。
1.2 设计目标与技术路线
建立统一的姿态、航向、速度和里程数据链，使科目二与科目三共享底层驱动和安全机制。
科目二使用六段状态表按等待计数、转向方向、目标航向和步进间隔生成航向指令，再由方向环映射为目标横滚，并通过横滚角 PI 与角速度阻尼执行。
科目三使用轨迹状态机给出航向目标，通过航向环、横滚角环和横滚角速度环三串级控制转向，并以独立速度环完成坡道速度调节。
把倒地检测、速度反馈超时、启动确认、软启动和输出限幅置于控制链路中，降低调试及比赛过程中的失控风险。
使用无线串口和 WiFi SPI 输出位置、姿态、目标量、控制输出与状态编号，使关键运行数据可以离车观测。

第二章  系统总体设计
2.1 方案概要
系统按“感知层-状态层-决策层-控制层-执行层-调试层”划分。IMU660RC 和磁编码器构成感知层；姿态解算、航向归一化和里程推算构成状态层；科目二、科目三分段航向状态机构成决策层；串级 PID 和速度环构成控制层；舵机与无刷驱动构成执行层；无线串口和 WiFi SPI 构成调试层。科目差异集中在目标航向序列和控制编排，底层硬件接口与安全机制保持一致。

2.3 双核分工与数据发布
TC264D 的 CPU0 执行初始化、实时控制中断和安全状态机；CPU1 在后台周期输出 trajectory_printf() 与 wifi_printf()。控制侧通过调试快照发布共享数据，避免在高优先级中断中直接进行耗时格式化和网络连接。WiFi 初始化采用有限重试，连接失败后返回，不阻塞主控制循环。

第三章  机械结构与安装
3.1 底盘与总体布置
车模为前轮转向、后轮无刷驱动的两轮结构。电池布置在底盘中下部，主控与电源/接口主板位于底盘中部，转向舵机与连杆位于前部，驱动与磁编码器靠近后轮。该布局缩短了动力线和编码器线，同时保留了主板上方的检修空间。

3.2 双层加高板与重心修正
核心板与主板采用铜柱构成双层加高结构。下层承担供电、接口和大电流连接，上层放置核心板及通信模块；分层后便于拆装和探针测量，也避免信号线直接跨越运动机构。由于板卡和线束集中会造成左右配重差，底盘增设铁片进行静态平衡修正。铁片应使用螺钉或可靠机械夹持固定，边缘倒角并与裸露焊点保持绝缘距离。

3.4 线束、固定与维护
动力线与传感器/通信线分束布置，交叉时尽量正交，减小开关电流对 SPI、UART 和 IMU 的耦合。

第五章  控制软件与核心算法
5.1 软件架构与状态估计
初始化顺序为：时钟与调试口、IMU660RC、串级控制参数、舵机 PWM、速度控制、里程计、驱动 UART、陀螺仪/航向零漂校准、无线接口。运行中将航向归一化到 ±180°，使用角度差函数处理跨界；磁编码器转速帧经 odometry_on_speed_frame() 更新，里程计按 0.064 m 轮径、转速和航向积分得到 x、y 与累计里程。科目二当前控制不使用几何曲率或前轮转角换算，航向目标由分段状态表直接生成。
5.2 PID 与抗饱和
位置式 PID 的离散表达式为：u(k)=Kp·e(k)+Ki·I(k)+Kd·[e(k)-e(k-1)]，其中 I(k) 经过上限约束。当未限幅输出已沿误差方向继续进入饱和区时，控制器恢复上一积分值，抑制积分累积。输出再按 out_max 对称限幅。代码同时提供增量式 PID，用于速度等适合逐次修正的环节。

5.3 科目二：分段航向与两层平衡控制

图5.1  科目二分段航向与平衡控制链
科目二当前工程使用 zhuan_two_segments[] 保存六段任务，每段由等待计数、左右转方向、目标航向和步进间隔构成。zhuan_two() 以 2 ms 周期运行；等待计数结束后，目标航向按每次 1°逐步变化，目标与当前指令的差值小于等于 0.8°时直接对齐并切换下一段。当前目标航向序列为 100°、5°、-100°、-97°、130°和 180°，均来自实际启用的数组。
航向误差每 4 ms 进入方向 PID，输出为目标横滚角并限幅 ±8°。方向控制只有在车速高于 20、横滚姿态稳定且连续满足使能条件时逐步开放；横滚绝对值由 6°增加到 12°时，方向权重连续衰减。横滚角 PI 每 5 ms 更新，1 ms 基准周期内根据横滚角差分得到角速度阻尼，并叠加横滚耦合项后输出舵机命令。舵机使用 P33.9、100 Hz PWM，中位 96.5；横滚达到 18°时清空控制状态并回中。

5.4 科目三：航向-横滚角-横滚角速度三串级

图5.2  科目三三串级控制与速度环
科目三以 1 ms 为控制基准。横滚角速度内环每 1 ms 运行，横滚角环每 5 ms 运行，航向环每 20 ms 运行，对应 1000、200 和 50 Hz；里程与路线状态机每 2 ms 更新，速度环每 20 ms 运行。当前 SUBJECT_3_ROUTE_MODE=2，执行 zhuanwna_three_3()：先绕桩，再直行并完成标定为 206°的左转，最后进入直行阶段。目标航向仍按每次 1°变化，0.8°以内直接到达。
航向环输出的目标横滚在平地限幅 12°，当俯仰绝对值由 6°增至 18°时逐步收紧到 8°，且单次变化限制为 1°。下坡时横滚角环 Kp 由 8.0 逐步降至 7.0；横滚误差大于 8°暂停积分，小于 4°恢复积分。倒地超过 60°立即关闭电机、舵机回中并锁存，扶正至 10°以内并再次按 KEY0 后，才复位轨迹、PID、航向初值和软启动。
表5.2  科目三串级 PID 参数

速度环与转向三串级并行。平地基准目标为 550 rpm、前馈 1000；上坡目标最高 620 rpm、前馈最高 1150，下坡目标最低 300 rpm、前馈最低 500。速度反馈连续 3 帧后才允许闭环，100 ms 未收到新帧则清空状态并重新软启动。电机目标和前馈均按周期限速变化，舵机同步采用软启动比例与输出斜率限制，避免执行量突变。
5.5 FOC 原理与驱动协同
FOC 驱动通过磁编码器获得转子电角度，将相电流经 Clarke 变换映射到 αβ 静止坐标系，再经 Park 变换得到 d/q 旋转坐标分量。d 轴用于磁链调节，q 轴对应转矩；电流调节器输出经反变换和 SVPWM 生成三相占空比[9]。上位 TC264D 不直接执行高频电流环，而通过 UART 下发速度/驱动指令并接收转速反馈，实现“上位运动控制-下位功率控制”的分层。
5.6 无线数据与轨迹诊断
CPU1 约每 10 ms 调用轨迹打印和 WiFi 打印。无线串口用于观察车辆位置、里程和运行状态，WiFi SPI 建立 TCP 链路传输姿态、目标航向、目标横滚、PID 输出、转速与状态编号。调试时应控制字段数量和发送频率，避免占用过多总线或 CPU 时间；比赛模式下可降低日志频率或关闭不必要字段。

2. 板卡安装：用铜柱完成主板/核心板双层加高，布置绝缘垫片，固定铁片与电池。
3. 电气检查：不接电机时限流上电，测量母线、5 V、3.3 V；检查插头极性和公共地。
4. 传感器标定：固定车体，校准陀螺仪与航向零漂，确认 roll/pitch/yaw 轴向和符号。
5. 执行器测试：舵机回中，低幅左右扫动；电机离地低速运行，确认相序、编码器方向与速度帧。
6. 闭环分级：先角速度内环，再横滚角环，再航向/方向外环，最后加入速度和路径任务。
7. 任务整合：科目二逐段核对六段目标航向、等待计数和步进间隔；科目三验证路线模式 2，再联调坡道速度、倒地锁存与按键复位。
6.3 PID 调试方法
串级系统从内向外调试。内环先关闭积分，增加比例直至响应足够快但不持续振荡，再加入少量微分改善阻尼；角度环在内环稳定后逐步增加比例，积分只用于修正重心和坡道引起的静差，并结合抗饱和；航向/方向环最后调节，其输出限幅应首先由车辆可承受横滚角确定。每次只改变一组参数，并记录目标、反馈、输出、饱和标志和车辆状态。
6.4 分段航向与坡道调试
科目二先在低速核对六段目标航向的正负号、转向方向和切换顺序，再检查 2 ms 状态计时与 0.8°直达条件。
科目二转向过早或过迟时优先调整对应段的 wait_count；转向过快或过慢时调整 step_count，并同时观察方向环输出和 ±8°横滚限幅。
科目三按路线模式 2 分段验证绕桩、直行和 206°左转；用目标航向、航向误差与状态编号判断切换时机。
坡道调试记录俯仰角、坡度状态、目标转速、实测转速和电机输出，避免仅凭体感修改前馈。

7.2 阶段性赛道测试结果
在当前车辆装配、程序和场地条件下，科目二与科目三各连续试跑 10 次。原始记录采用成功次数区间，因此报告保留区间表达，不将其改写为单一精确值。科目二成功 4–5 次，阶段成功率为 40%–50%；科目三成功 5–6 次，阶段成功率为 50%–60%。
科目二失败主要表现为车模出界和反复压线，说明分段等待计数、目标航向以及方向环输出与实际场地边界仍需联合标定。科目三失败主要发生在急转和下坡阶段：急转时横滚变化过快导致车模摔倒；下坡时平衡未能稳定恢复，车模同样发生摔倒。后续应逐次记录失败阶段、目标航向、横滚角、俯仰角和舵机输出，用同一套场地条件复测。
7.3 工作总结
本设计完成了两轮车模机械、电气、感知、执行、控制与调试链路的集成。科目二通过六段目标航向状态机、方向环、横滚角 PI 和角速度阻尼协调转向与动态平衡；科目三通过航向-横滚角-横滚角速度三串级与独立速度环，实现路线模式 2、坡道速度调节和快速转向平衡。启动互锁、输出软启动、倒地锁存、按键复位和速度反馈超时处理共同限制异常状态下的执行输出。
7.4 存在问题
整车质量和外形尺寸已经完成测量；尚未完成的是整车全部电容汇总、平均/峰值运行功耗、最低稳定工作电压以及传感器绝对精度标定。电机和 IMU 的理论功率只能用于器件选型与供电边界分析，不能替代整车输入端实测。
磁编码器速度与 IMU 航向积分仍可能受轮胎打滑、磁距和零漂影响，位置估计长期误差需要标定。
科目二六段目标航向、等待计数和步进间隔针对当前车辆与场地标定；赛道表面、轮胎和重心变化后需要逐段复核。
7.5 改进方向
后续可增加电流与母线电压遥测，建立功耗和热负荷记录；使用编码器/IMU 融合改善航向与位置估计；把分段航向、车速、坡度和可用横滚角统一纳入参数管理；建立参数版本、台架数据和赛道回放工具，使每次修改可以定量比较。对于安全性，应增加硬件急停、欠压/过流事件记录和上电自检。

void pid_control(pid_cycle_struct *pid_cycle, float target, float real)
{
    float proportion_value;
    float integral_value;
    float differential_value;
    float output_unlimited;
 
    proportion_value = target - real;
    integral_value = pid_cycle->i_value + proportion_value
            * pid_cycle->i_value_pro;
    integral_value = func_limit_ab(integral_value,
            -pid_cycle->i_value_max, pid_cycle->i_value_max);
 
    differential_value = proportion_value - pid_cycle->p_value_last;
    output_unlimited = pid_cycle->p * proportion_value
            + pid_cycle->i * integral_value
            + pid_cycle->d * differential_value;
 
    if(((output_unlimited > pid_cycle->out_max)
            && (pid_cycle->i * proportion_value > 0.0f))
            || ((output_unlimited < -pid_cycle->out_max)
            && (pid_cycle->i * proportion_value < 0.0f)))
    {
        integral_value = pid_cycle->i_value;
        output_unlimited = pid_cycle->p * proportion_value
                + pid_cycle->i * integral_value
                + pid_cycle->d * differential_value;
    }
 
    pid_cycle->i_value = integral_value;
    pid_cycle->out = output_unlimited;
    pid_cycle->out = func_limit_ab(pid_cycle->out,
            -pid_cycle->out_max, pid_cycle->out_max);
    pid_cycle->p_value_last = proportion_value;
}

static const zhuan_two_segment_t zhuan_two_segments[] =
{
    {872U, TURN_DIR_RIGHT,  100.0f,  8.0f},
    {198U, TURN_DIR_LEFT,     5.0f, 16.0f},
    { 52U, TURN_DIR_LEFT,  -100.0f,  6.0f},
    {794U, TURN_DIR_RIGHT,  -97.0f, 14.0f},
    {470U, TURN_DIR_LEFT,   130.0f, 14.0f},
    {272U, TURN_DIR_RIGHT,  180.0f,  8.0f},
};
 
void zhuan_two(void)
{
    const zhuan_two_segment_t *segment;
    if(++turn_task_div < TURN_TASK_DIV) { return; }
    turn_task_div = 0U;
    if(direct_turn_state >= ZHUAN_TWO_SEGMENT_COUNT) { return; }
    segment = &zhuan_two_segments[direct_turn_state];
    if(++direct_turn_delay < segment->wait_count) { return; }
    if(TURN_DIR_LEFT == segment->dir)
        zhuan_wan_left(segment->target_yaw, segment->step_count);
    else
        zhuan_wan_right(segment->target_yaw, segment->step_count);
    if(turn_target_reached(segment->target_yaw))
    {
        direct_turn_delay = 0U;
        direct_turn_state++;
    }
}

{
    uint8 retry;
 
    for(retry = 0; retry < WIFI_INIT_RETRY_MAX; retry++)
    {
        if(0 == wifi_spi_init(WIFI_SSID_TEST, WIFI_PASSWORD_TEST))
        {
                if(0 == WIFI_SPI_AUTO_CONNECT)
            {
                if(0 != wifi_spi_socket_connect("TCP", TCP_TARGET_IP, TCP_TARGET_PORT, WIFI_LOCAL_PORT))
                {
                    printf("\r\n connect tcp failed. \r\n");
                    system_delay_ms(100);
                    continue;
                }
            }

            return 1;

    }
