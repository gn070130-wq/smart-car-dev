摘  要
针对单车定向赛题中单轨车模姿态与转向强耦合、运行速度跨度大以及室外定位误差易累积等问题，本文设计了一套以英飞凌 AURIX SAK-TC264D-40F200N 微控制器为核心的自平衡单车控制系统。系统采用惯性测量单元获取三轴角速度和加速度，结合静态零偏标定、标量卡尔曼滤波、低通滤波、基于四元数的非线性互补姿态解算以及横向加速度补偿，获得车体横滚角、俯仰角和连续航向角。控制软件针对高速和低速两类工作状态分别设计控制结构：高速状态采用航向角、偏航角速度、横滚角和横滚角速度逐级约束的串级控制，并叠加由速度与转弯角速度计算的理论倾角前馈；低速状态采用航向误差直接生成目标横滚角、横滚角反馈与角速度阻尼共同驱动舵机的简化控制结构。后轮速度由编码器反馈、前馈量和 PID 调节共同闭环控制。导航部分以惯性航向与轮速里程计进行平面航迹递推，支持等距离轨迹记录、Flash 分区保存、最近点搜索、速度相关前瞻以及二次 Bézier 平滑；在无需外部定位的场景中，系统也可依据路程、姿态和航向状态执行程序化决策。本文给出了整车方案、主板电路、实时软件架构、姿态解算、高低速控制、惯性导航和调试方法，并附主板原理图与核心算法子程序。
关键词：自平衡单车；TC264；姿态解算；串级控制；惯性导航；程序决策

第1章  引言
1.1 竞赛背景与设计目标
全国大学生智能汽车竞赛要求参赛队伍围绕模型车机械结构、电子线路、传感器、执行机构和决策算法完成自主设计。第二十一届比赛规则明确单车定向组采用英飞凌 AURIX 平台，并要求单车仅依靠转向舵机完成动态平衡与方向控制。[1]
单轨车模不能像四轮车模一样依靠静态支撑保持直立。车体横滚姿态、前轮转角、运行速度和转弯曲率之间存在显著耦合：舵机转向既用于改变行驶方向，也用于产生恢复横滚姿态所需的横向加速度。设计目标因此不是单独完成“平衡”“转向”和“导航”三个互不相关的功能，而是在统一实时控制框架内协调姿态、航向和速度。
结合实际软件实现，本文将运行状态抽象为高速和低速两类。高速状态强调转弯前馈、偏航角速度闭环和多环串级的动态响应；低速状态强调航向误差到目标横滚角的直接映射以及角速度阻尼，以降低速度不足时多级环路相互放大的风险。路线执行统一采用惯性导航或程序决策，不按具体比赛科目分别建立算法章节。
1.2 系统设计约束
系统设计遵循以下边界：主控制器采用允许的 Infineon AURIX TC264；平衡手段仅为前轮转向舵机，不设置反作用轮、惯性轮、吸附装置或其他辅助支撑；主板及接口板为自主设计；比赛运行不依赖 RTK 高精度定位；导航主链路以惯性航向和轮速里程为基础。成品 PCB 顶层覆铜面仍需在实物检查时确认学校名称、队伍名称和制作年份清晰可见。

第2章  系统总体方案与机械设计
2.1 总体组成
整车由单车机械本体、后轮驱动电机、前轮转向舵机、TC264 主控制板、惯性测量单元、外置电机驱动器、编码器、参数显示与人机交互模块以及调试通信模块组成。主控制器以固定周期采集姿态与运动信息，生成舵机角度和目标电机占空比；导航层向控制层提供目标航向和目标速度，控制层不直接区分路线来源。

2.2 单车平衡与转向机理
当车体向一侧倾斜时，控制器驱动前轮向同侧转动，使车体运动轨迹产生曲率。车体随之获得横向加速度，其等效恢复力矩抵消继续倾倒的趋势。若需要改变行驶方向，控制器先形成目标横滚角，再由平衡环驱动舵机建立相应曲率。因此，单车的目标转向方向与舵机瞬时纠偏方向并非始终一一对应，舵机指令必须由姿态闭环统一生成。
	φ* ≈ arctan(v·ωz / g)	(2-1)
式中，φ* 为稳定转弯对应的目标横滚角，v 为纵向速度，ωz 为偏航角速度，g 为重力加速度。软件中根据坐标系和舵机正方向加入符号约定，并对计算结果进行限幅、斜率限制和低通滤波。
2.3 机械安装原则
主板、惯性测量单元和电池的安装应兼顾重心、刚度、散热和维护性。IMU 应采用刚性连接并尽量靠近车体主体，安装坐标轴需与软件定义一致；舵机连杆应避免明显回差和干涉；电机动力线与传感器信号线应分束布置；大质量器件应可靠固定，防止坡面或草地振动引入额外姿态扰动。

第3章  硬件系统设计
3.1 主控制器与最小系统
主控制板采用 Infineon AURIX SAK-TC264D-40F200N 裸片方案。TC264 具有多核 TriCore 架构、丰富的定时器、SPI、UART 和通用 I/O 资源，可满足 250 Hz 姿态控制、串口电机通信、Flash 存储和人机交互的并行需求。主板设置 20 MHz 外部晶振、上电复位、调试接口、必要的去耦和核心电源回路。
CPU 核心电压由 AP2003 配合 4.7 μH 电感和 22 μF 滤波电容构成的降压回路提供，逻辑与模拟电源按照芯片手册要求布置去耦。调试连接器附近设置稳压二极管和瞬态抑制器件，以降低插拔与静电放电对主控的影响。

图3-1 主控制板正反面
3.2 电源系统
主板电源采用分级稳压结构。两个 SCT2450 同步降压回路分别为舵机侧和 5 V 负载提供大电流电源，其外围采用 SS54、4.7 μH 电感和输入输出滤波电容；两个 RT9013-33 低压差稳压器分别生成 3.3 V 外设电源和 3.3 V 核心相关电源。分轨供电可减少舵机电流突变对 IMU、Flash 和主控制器的干扰。

3.3 传感器与存储接口
IMU 通过独立 SPI 接口与主控制器连接，提供三轴加速度和三轴角速度。电机驱动器通过高速 UART 返回转速和编码器计数，并接收占空比控制帧。W25Q64JV 串行 Flash 用于保存多组 PID 参数、轨迹点和运行配置。主板还预留 GNSS 串口、TFT、无线串口、五向按键、WS2812 灯和状态指示灯接口。当前比赛运行链路以惯性导航或程序决策为主，GNSS 驱动与接口作为扩展和对比验证手段，不参与默认实时控制主链路。

3.4 舵机与电机接口
转向舵机由 GTM/ATOM PWM 通道驱动，程序默认 PWM 频率为 300 Hz，以中心占空计数 5600 为机械中位，将目标舵机角限制在 ±60° 以内并叠加输出低通。电机驱动器采用 0xA5 帧头的串口协议，主控周期性发送目标占空比并请求速度、编码器信息。轮径在源码中配置为 6.4 cm，里程计算对 15 bit 编码器计数回绕进行处理。

4.1 软件模块划分
软件采用驱动层、数据与参数层、控制层、导航决策层和人机交互层分层组织。全局运行状态集中保存在system_data 模块中，控制参数支持编译默认值和 Flash 配置两种来源。控制层只读取标准化的姿态、速度、航向目标和模式标志，降低导航策略变化对底层稳定控制的影响。
表4-1 主要自编软件模块

4.2 初始化流程
CPU0 上电后依次完成时钟、调试串口或遥控输入、W25Q64、系统参数、TFT 菜单、舵机、电机、IMU、控制器、任务管理和导航模块初始化。IMU 初始化阶段首先等待静态窗口，再采集 1000 组陀螺仪数据估计零偏；控制参数可在菜单中检查或切换配置。完成准备后启动 4 ms 周期中断，主循环以约 10 ms 节拍执行程序决策和非硬实时通信。
4.3 实时调度
姿态解算、舵机控制和惯性导航在 4 ms 中断内执行，构成 250 Hz 快速闭环。速度环以 4 ms 累加计时，当前实现达到阈值后按 12 ms 步长运行，等效频率约 83.3 Hz。程序决策在主循环中以约 10 ms 周期执行；无线日志默认 20 ms 发送一次。各环节使用固定采样时间计算 PID 和积分量，避免主循环通信造成控制周期漂移。

第5章  惯性测量与姿态解算
5.1 坐标系与原始数据
软件将车体坐标系定义为 X 轴向前、Y 轴向右、Z 轴向下。根据传感器实际安装方向，驱动层对原始轴向进行映射，使横滚角速度、俯仰角速度和偏航角速度的符号与控制器约定一致。姿态输出包括横滚角 roll、俯仰角 pitch、包络航向角 yaw 以及用于避免 ±180° 跳变的连续航向 yaw_accumulated。
5.2 静态标定与前级滤波
启动时先判断车体是否保持静止，随后以约 2.5 ms 间隔采集 1000 组角速度，对三轴陀螺仪零偏取均值。运行中，加速度各轴先经过标量卡尔曼滤波，源码默认过程噪声 Q=0.01、测量噪声 R=0.10；角速度采用一阶低通滤波，默认新数据权重由系数 0.65 控制。该处理降低机械振动和电机噪声进入姿态环的幅度。
	x̂k = x̂k-1 + Kk(zk - x̂k-1)	(5-1)
	Kk = Pk- / (Pk- + R)	(5-2)
5.3 四元数互补姿态解算
姿态解算采用基于四元数的非线性互补滤波。陀螺仪给出短时动态，归一化加速度在可信时提供重力方向修正。该方法避免欧拉角积分在大姿态下的奇异性，并允许通过比例—积分误差反馈估计慢变零偏。[4]
	e = â × ĝ(q)	(5-3)
	ωc = ωm - b + Kp·e	(5-4)
	q̇ = 1/2 · q ⊗ [0, ωc]	(5-5)
	ḃ = -Ki·e	(5-6)
式中，â 为归一化加速度方向，ĝ(q) 为由当前四元数估计的重力方向，e 为二者叉乘误差，ωm 为测得角速度，b 为在线零偏项。源码默认 Kp=2.75、Ki=0.027；四元数积分后立即归一化，再转换为横滚、俯仰和航向。
5.4 动态可信度与横向加速度补偿
单车转弯时，加速度计同时测得重力和向心加速度。若直接把合加速度当作重力方向，姿态解算会把正常转弯误判为横滚误差。软件依据当前速度和偏航角速度估算横向加速度 ay≈v·ωz，并在加速度归一化前进行补偿。同时根据加速度模长偏离 1g 的程度、短时变化量和横向加速度大小计算可信度权重；动态越强，重力修正权重越低。
	ay,comp = ay,meas - v·ωz / g	(5-7)
积分零偏只在车体相对静止且加速度可信时更新；在剧烈运动阶段，积分项逐步泄漏而不继续累积。这样可以兼顾静态收敛和动态抗干扰。由于默认运行未引入磁力计或外部绝对航向，连续航向仍会随陀螺仪零偏缓慢漂移，导航层通过短程运行、轨迹重放和程序状态约束降低该误差的影响。
5.5 输出滤波与异常处理
控制层对横滚角、横滚角速度、偏航角速度和航向误差分别使用一阶低通。航向角本身不跨越 ±180°直接滤波，而是先计算 wrap 后的最短航向误差，再对误差滤波，以避免边界处出现接近 360°的伪跳变。姿态数据异常或横滚超过保护阈值时，控制器停止速度输出并将舵机回中。

第6章  高速与低速平衡转向控制
6.1 控制模式划分
控制模式由上层运行状态选择，但导航层接口保持一致：均向平衡控制器给出目标航向和目标速度。高速模式利用速度较高、可产生稳定横向加速度的特点，采用多级串级控制与理论倾角前馈；低速模式减少环路级数，由航向误差直接产生目标横滚角，并在舵机输出端叠加角速度阻尼。两种模式共享姿态解算、舵机限幅、倒地保护和参数管理。

6.2 高速模式的航向外环
目标航向与连续航向计算最短角误差，经死区和低通后送入航向 PID，输出目标偏航角速度。航向环每 8 ms更新一次，其余 4 ms 周期保持上次输出。目标偏航角速度限制在 ±25°/s，并经过最大 80°/s² 的斜率限制和低通滤波，防止导航目标突变直接激励舵机。
	ωz* = sat{Cyaw(eψ)},  eψ = wrap(ψ* - ψ)	(6-1)
6.3 高速模式的转弯—横滚环
转弯环同时使用模型前馈与偏航角速度反馈。根据当前速度和目标偏航角速度计算理论横滚角前馈，偏航角速度 PID 对模型误差和外部扰动进行补偿，两者相加后形成目标横滚角，并受最大目标横滚角约束。
	φ* = sat[-arctan(v·ωz*/g) + Cturn(ωz* - ωz)]	(6-2)
这种结构在高速转向前就给出合理倾角，减少仅靠反馈造成的相位滞后；当轮胎侧偏、路面摩擦或模型参数发生变化时，偏航角速度反馈对前馈误差进行修正。
6.4 高速模式的姿态串级
目标横滚角与实测横滚角进入角度外环，输出目标横滚角速度；目标角速度与陀螺仪横滚角速度进入内环，输出舵机角度。内环直接抑制快速倾倒，外环消除稳态横滚偏差。最终舵机指令还经过输出低通和机械角度限幅。
	p* = Cangle(φ* - φ)	(6-3)
	δ = LPF{Cgyro(p* - p)}	(6-4)
6.5 低速控制
低速状态下，理论转弯倾角随速度平方快速减小，舵机死区、机械回差和地面扰动所占比例上升。软件不再完整串联偏航角速度环和横滚角速度 PID，而是由航向误差 PID 直接生成目标横滚角。目标横滚角经低通后，角度控制量与横滚角速度阻尼共同形成舵机指令，并根据实际速度使用低速增益补偿。
	φ*low = sat{Cyaw,low(eψ)}	(6-5)
	δlow = Kφ(φ*low - φ) - Kp·p	(6-6)
航向误差设有低速死区，目标横滚角受统一上限约束。低速模式仍保留偏航角速度测量和可选修正，但默认不把转弯角速度传给速度增益模块，避免低速转向时速度被过度抬升。
6.6 倒地检测与恢复
高速和低速模式均以 |roll|>40° 作为倒地保护条件。触发后清除 PID 积分和滤波状态，关闭速度运行标志，持续将舵机置于中位；若处于轨迹记录状态，先保存已记录轨迹。车体重新扶正并恢复控制时，速度斜坡从当前状态重新同步，避免突然给出大占空比。

第7章  速度检测与闭环控制
7.1 速度与里程计算
外置电机驱动器通过 UART 返回电机转速和编码器累计计数。主控根据轮径 6.4 cm 将转速换算为车体线速度，并对速度测量使用一阶低通。编码器为 15 bit 环形计数，软件在相邻采样间判断回绕并计算增量，再乘以单脉冲对应路程得到累计距离。
	v = πD·n / 60	(7-1)
	s(k) = s(k-1) + ΔN·ks	(7-2)
7.2 前馈与 PID 复合控制
速度控制采用目标速度前馈与 PID 修正相加。前馈按单位速度对应占空比估算基本驱动力，PID 补偿电池电压、路面阻力和载荷变化。速度环固定使用 12 ms 采样时间，输出限制在电机协议允许范围内。
	u = sat(Kff·v* + Cspeed(v* - v))	(7-3)
源码默认 Kff=11 duty/(cm/s)，速度 PID 默认 P=8.8、I=15.0、D=0.02。目标速度变化受 800 cm/s² 斜率限制，速度测量默认低通系数为 0.80。上述值仅为编译回退参数，实际比赛使用的 Flash 配置应在最终提交前核对。
7.3 转向与姿态速度补偿
单车转向时后轮阻力增大，速度下降又会削弱恢复横滚姿态的横向加速度。高速模式中，速度目标可根据目标偏航角速度和横滚角绝对值增加：偏航角速度超过死区后按比例补偿，横滚角越大也适度提高目标速度；补偿总量限制为 20 cm/s，最终目标速度上限为 600 cm/s。低速模式关闭该转向增速通道。
7.4 坡面速度辅助
程序可根据俯仰角低通值识别平地、上坡、下坡和落地恢复状态，并分别限制目标速度、积分量与偏航角速度。该状态机属于通用的路面程序决策，不与具体比赛科目绑定。默认俯仰零偏为 -4.5°；上坡进入、下坡进入、下坡退出和恢复均设置持续确认时间，避免短时振动反复切换状态。

第8章  惯性导航与程序决策
8.1 导航方式
实际运行统一采用两种路线生成方式：一是惯性导航，通过轮速和连续航向递推位置并跟踪预先记录的轨迹；二是程序决策，根据累计路程、航向误差、俯仰状态和阶段条件直接设定目标航向与目标速度。两种方式均使用同一平衡与速度控制接口，因此控制层不需要了解目标来自哪一类路线。
8.2 惯性坐标递推
以启动位置为原点，利用线速度 v 和连续航向 ψ 在 4 ms 周期内进行平面积分。为补偿控制响应和车辆前部执行点与后轮里程参考点的差异，程序还计算沿当前航向前推 20 cm 的预测点，用于最近点搜索。
	xk = xk-1 + v·cosψ·Δt	(8-1)
	yk = yk-1 + v·sinψ·Δt	(8-2)
	pahead = [xk, yk] + 0.20[cosψ, sinψ]	(8-3)
8.3 轨迹记录与 Flash 保存
记录模式按累计路程采样，每前进 2 cm 保存一个平面坐标点；相邻采样跨度过大时进行插值，避免轨迹点出现断层。每条路径最多保存 10240 个点，多套路径在 W25Q64 中分区存储。倒地、人工停止或记录结束时将有效点数和数据写入 Flash，并在加载时检查边界。
8.4 最近点、前瞻与 Bézier 平滑
重放时，程序在上一次最近点附近的前向窗口中搜索与预测点距离最小的轨迹点，避免全表扫描。前瞻点索引随速度增加：高速采用较大的基础前瞻和速度增益，低速采用更短前瞻以提高小半径跟踪能力。随后从相邻三个轨迹点构造二次 Bézier 曲线，在 t=0.2 处取平滑目标点。
	B(t) = (1-t)²P0 + 2(1-t)tP1 + t²P2	(8-4)
	ψ* = atan2(By-y, Bx-x)	(8-5)
目标航向每次更新最大变化 1.2°，再送入高/低速航向控制器。速度相关前瞻在高速时降低转向抖动和过度追踪，在低速时保留足够曲率分辨率。
8.5 程序决策
程序决策采用状态机组织，状态转换条件可由累计距离、目标航向误差、姿态角持续时间、稳定计数和外部启动信号组合构成。每个状态只输出目标航向、目标速度、控制模式和参数配置编号，不直接写舵机或电机占空比。这样可将路线逻辑与稳定控制解耦，并允许同一段路径在高速或低速模式下复用。

9.3 参数整定原则
调参时保持一次只改变一个环节：先确保 IMU 符号、舵机方向和中位正确，再提高角速度阻尼；随后调整横滚角外环消除慢性偏差；航向和转弯环最后加入。若舵机高频抖动，应优先检查传感器噪声、机械回差和滤波，而不是继续减小所有增益。高速参数和低速参数分配置保存，切换时清理相关积分和滤波状态。
9.4 安全保护

第11章  结论与改进方向
11.1 设计总结
本文围绕单车定向组的动态平衡、速度控制和路线执行需求，完成了基于 TC264 裸片主板的系统方案整理。硬件形成核心电源、多路稳压、IMU、Flash、电机、舵机、显示与调试接口；软件采用 4 ms 实时中断组织姿态、平衡和惯导，在高低速状态下分别使用多级串级控制和简化横滚控制，并以速度闭环维持纵向运动。导航层支持惯性轨迹记录/重放以及基于路程、姿态和航向的程序决策。
11.2 现有方案的局限
纯惯性航向会受到陀螺仪零偏影响，轮速里程也会在草地、坡面或急转时因打滑累积误差；高速与低速模式切换依赖规则和参数配置，若切换点设置不当可能产生目标横滚或舵机输出突变；前馈模型采用简化的稳态转弯关系，未显式包含轮胎侧偏、舵机动力学和车体质量分布。
11.3 后续改进方向
后续可在不改变主控制接口的前提下，引入基于静止段和已知路径几何的航向漂移校正、轮速打滑检测、高低速控制器的无扰切换、速度相关的模型参数辨识以及轨迹曲率前馈。若使用 GNSS 扩展，应仅作为低频绝对位置校正，并设置数据质量和超时判定，保持惯导在信号遮挡时能够独立运行。

static void imu_solve_step(imu_context_t *ctx,                            float ax, float ay, float az,                            float gx_deg, float gy_deg, float gz_deg,                            float dt) {     float gx = DEG_TO_RAD(gx_deg);     float gy = DEG_TO_RAD(gy_deg);     float gz = DEG_TO_RAD(gz_deg);      /* Lateral-acceleration compensation for a turning bicycle. */     float v = driver_motor_get_speed_cm_s() * 0.01f;     float yaw_rate = DEG_TO_RAD(gz_deg);     ay -= (v * yaw_rate) / GRAVITY_MPS2;      float norm = inv_sqrt(ax*ax + ay*ay + az*az);     ax *= norm; ay *= norm; az *= norm;      /* Estimated gravity from quaternion. */     float vx = 2.0f * (ctx->q1*ctx->q3 - ctx->q0*ctx->q2);     float vy = 2.0f * (ctx->q0*ctx->q1 + ctx->q2*ctx->q3);     float vz = ctx->q0*ctx->q0 - ctx->q1*ctx->q1              - ctx->q2*ctx->q2 + ctx->q3*ctx->q3;      float ex = ay*vz - az*vy;     float ey = az*vx - ax*vz;     float ez = ax*vy - ay*vx;     float trust = imu_accel_confidence(ax, ay, az, v, yaw_rate);      ctx->ex_int = imu_integral_step(ctx->ex_int, trust*ex, dt, trust > 0.6f);     ctx->ey_int = imu_integral_step(ctx->ey_int, trust*ey, dt, trust > 0.6f);     ctx->ez_int = imu_integral_step(ctx->ez_int, trust*ez, dt, trust > 0.6f);      gx += IMU_KP*trust*ex + IMU_KI*ctx->ex_int;     gy += IMU_KP*trust*ey + IMU_KI*ctx->ey_int;     gz += IMU_KP*trust*ez + IMU_KI*ctx->ez_int;      quaternion_integrate_and_normalize(ctx, gx, gy, gz, dt);     quaternion_to_euler(ctx, &g_data.attitude); }

void ctrl_balance_high_speed_core(float dt) {     float yaw = wrap_deg(g_imu_control.yaw_accumulated);     float yaw_err = limit_yaw_error(g_data.cmd_yaw_deg - yaw);      float yaw_rate_ref = pid_calculate(&g_params.yaw_pid,                                        lpf(yaw_err), 0.0f, 0.008f);     yaw_rate_ref = clamp(yaw_rate_ref,                          -g_params.yaw_to_rate_max_dps,                           g_params.yaw_to_rate_max_dps);     yaw_rate_ref = slew_and_lpf(yaw_rate_ref, dt);      float v = driver_motor_get_speed_cm_s() * 0.01f;     float omega = DEG_TO_RAD(yaw_rate_ref);     float roll_ff = -RAD_TO_DEG(atanf(v * omega / GRAVITY_MPS2));     float roll_fb = pid_calculate(&g_params.turn_pid,                                   yaw_rate_ref, g_data.imu_data.gyro_z, dt);     float roll_ref = clamp(g_params.zero_roll_angle + roll_ff + roll_fb,                            -g_params.max_target_roll_deg,                             g_params.max_target_roll_deg);      float roll_rate_ref = pid_calculate(&g_params.angle_pid,                                         roll_ref, g_data.attitude.roll, dt);     float servo = pid_calculate(&g_params.gyro_pid,                                 roll_rate_ref, g_data.imu_data.gyro_x, dt);     driver_servo_set_angle(lpf_and_limit_servo(servo)); }

void ctrl_balance_low_speed_core(float dt) {     float yaw = wrap_deg(g_imu_control.yaw_accumulated);     float yaw_err = limit_yaw_error(g_data.cmd_yaw_deg - yaw);      float roll_ref = pid_calculate(&g_params.yaw_pid,                                    0.0f, lpf(yaw_err), LOW_YAW_DT_S);     roll_ref = clamp(roll_ref,                      -g_params.max_target_roll_deg,                       g_params.max_target_roll_deg);     roll_ref = lpf_target_roll(roll_ref);      float angle_out = pid_calculate(&g_params.angle_pid,                                     roll_ref, g_data.attitude.roll, dt);     float damping = g_params.gyro_pid.kp * lpf(g_data.imu_data.gyro_x);     float gain = low_speed_servo_gain(driver_motor_get_speed_cm_s());      driver_servo_set_angle(clamp(gain * (angle_out - damping),                                  -SERVO_MAX_DEG, SERVO_MAX_DEG)); }

void driver_motor_speed_loop_step(void) {     float target = g_data.cmd_speed_cm_s;     target = speed_target_slew(target, MOTOR_SPEED_LOOP_DT_S);      if (!g_flags.low_speed_mode) {         float boost_turn = 0.60f * maxf(fabsf(g_data.turn_rate_ref_dps)-5.0f, 0.0f);         float boost_roll = 1.50f * fabsf(g_data.attitude.roll);         target += clamp(boost_turn + boost_roll, 0.0f, 20.0f);     }     target = ramp_state_speed_limit(target);     target = clamp(target, 0.0f, 600.0f);      float measured = lpf_speed(driver_motor_get_speed_cm_s());     float feedforward = 11.0f * target;     float feedback = pid_calculate(&g_params.speed_pid,                                    target, measured, MOTOR_SPEED_LOOP_DT_S);     float duty = clamp(feedforward + feedback, -10000.0f, 10000.0f);      if (!g_flags.speed_run_enable || g_data.balance_fallen)         duty = 0.0f;     driver_motor_set_duty((int16_t)duty, (int16_t)duty); }

void ctrl_nav_step(void) {     float v = driver_motor_get_speed_cm_s() * 0.01f;     float yaw = DEG_TO_RAD(g_imu_control.yaw_accumulated);     nav.x += v * cosf(yaw) * NAV_DT_S;     nav.y += v * sinf(yaw) * NAV_DT_S;      if (g_flags.enable_record_model) {         if (distance_since_last_point() >= 0.02f)             record_interpolated_path_points(nav.x, nav.y);         return;     }      float ahead_x = nav.x + 0.20f * cosf(yaw);     float ahead_y = nav.y + 0.20f * sinf(yaw);     uint16_t nearest = search_forward_nearest(ahead_x, ahead_y);     uint16_t lookahead = nearest + speed_dependent_lookahead(v);      point_t p0 = path[lookahead - 1U];     point_t p1 = path[lookahead];     point_t p2 = path[lookahead + 1U];     point_t target = quadratic_bezier(p0, p1, p2, 0.2f);      float yaw_target = RAD_TO_DEG(atan2f(target.y-nav.y,                                          target.x-nav.x));     nav_set_yaw_target_limited(yaw_target);   /* <= 1.2 deg/update */ }
