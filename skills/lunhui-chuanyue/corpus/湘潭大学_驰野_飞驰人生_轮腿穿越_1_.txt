1.引言
		全国大学生智能汽车竞赛是一项以“立足培养、重在参与、鼓励探索、追求卓越”为指导思想，面向全国大学生开展的具有探索性的工程实践活动。在竞赛中，我们基于博斯威龙V车模，使用英飞凌CYT4BB7芯片作为主控，英飞凌CYT2BL3作为无刷电机驱动芯片，集成为一体电路板紧凑安装在车模上。在机械方面使用3D打印件对于电路板和核心外设进行连接和支撑。接下来从车模设计思路入手，分别从机械制作、电路硬件设计和控制算法软件层面介绍该车模。

模型车设计制作的主要思路以及实现的技术方案概要说明
2.1车模设计制作的主要思路
首先，为了符合赛题要求，我们基于博斯威龙车模进行赛题针对性设计，采用了逐飞科技双频GPS模块和高强增益天线，用于获取车模实时得到GPS位置信息；单独采用GPS推算容易受天气等因素导致不定的漂移，所以我们融合进惯性导航信息，采用基于LSM6DSRTR的陀螺仪模块和自制的磁编进行惯导坐标获取；对于赛道PVC部分和三级台阶的识别采用了逐飞科技的总钻风在灰度画面中进行差比和算法提取边界。接着在总体结构上，我们使用3D打印件将各部分进行连接使得车模重心合理。
2.2 车模实现的技术方案
电路板固定采用3D打印件；无刷电机驱动采用CYT2BL3芯片；磁编码器采用TLE5012BE3005芯片。
		



模型车机械部分
3.1车模安装与支撑电路板的模块
为了使得车模整体安装合理，我们设计了与电路板相匹配的3D打印件，将电路板严丝合缝的安装在打印件上；同时我们为防范雨天等极端情况，我们对于电路板和整车系统进行了防水处理，使用防水胶涂抹在电路板的整体上面，不露出一点可导致短路的电路部分。

3.2 传感器的设计安装
摄像头用于识别图像信息和进行跳跃时间的确定，因此摄像头的稳定安装是识别稳定的基础，我们同样采用合适的3D打印件将摄像头安装在主板电路板上方，同时使用大量热熔胶对于连接处进行固定处理，并对于摄像头进行保护在碳杆顶部安装防撞保护件；GPS天线对于信号强度以及电磁干扰要求比较严苛，所以我们将GPS高强增益天线正好安装在顶部的摄像头防撞件上方。


电路模块设计说明
CYT4核心板拓展板
我们的车模基于CYT4BB7核心板进行开发，为了将其引脚功能与外设相连接，我们设计了CYT4核心板的拓展板，上面集成了各种车模需要用到的外设与电源部分。
图4.1.1 外设部分1原理图
如图4.1.1，这是外设其中一部分的原理图，我们采用了遥控器对车模进行控制，极大方便了车模的调试，因此需要一个SBUS转UART的功能口对遥控信号进行处理；为了在室外的夜晚等昏暗环境下突出车模，便于跟踪，我们加上了基于WS2812的灯板，采用SPI通信，同时5V供电，可以发出不同明亮的灯光；在这基础上，为了便于惯导的定位，还加入了GPS模块作为辅助，使用了一组串口引出；再者就是无线串口与蜂鸣器，前者极大方便了车模与其他设备进行通信，便于调试；后者可发出声响进行关键部分的辅助判断；最后就是电压测量功能，通过对电池12V进行分压进入单片机，观察小量从而反射出电池电压这个大量是否过低，及时更换电池以避免过放等损坏电池。


图4.1.2 外设部分2原理图
接下来是外设第二部分的原理图，我们采用了逐飞的CYT4BB7核心板进行直接插拔，在核心板出问题时可以快速更换而不是连带整个主板都要更换；摄像头模块高效助力科目三，便于三级台阶、坡道行进间的稳定，采用了FPC软排线进行连接；按键使用了五向按键，占地面积小，同时体感反射强，对屏幕上菜单进行操作方便高效；屏幕采用了逐飞的IPS200，尺寸大、显示清晰，极大提升了调试时的效率。最后便是舵机，四个舵机支撑车模的平衡与跳跃，每个舵机使用了7V左右的电压供电与一个PWM口进行驱动。
图4.1.3 舵机、摄像头电源部分原理图
接下来是舵机的电源部分原理图，我们采用MP2329CGG芯片作为舵机电源芯片，因为其具备一下优点：1.最大电流达到了6A，对于这种舵机而言绰绰有余；2.PCB占地空间极小，很方便于整体的PCB布局，通过改变外部电阻，我们可以把他的输出电压调整到7V左右，这是这款舵机的舒适电压，驱动车模强而有劲。对于摄像头，专门使用了LP5907这款5V转3.3V的ldo进行供电，相比于常见的RT9013，它用只有一半的电流能力换取了更低的纹波和更稳定干净的电压，利于摄像头高效运行。
图4.1.4 电源部分原理图
这是其他电源部分的原理图，在12V电池进来时，采用了常见的PMOS防反接装置，避免反接导致后级电路全部烧毁。12V转5V用了MPS公司集成的MPM3620这款电源芯片，内部直接集成了电感，极大减小了占用PCB的空间，同时过电流能力也绰绰有余。最后就是常见的RT9013，把5V转为3.3V的ldo，用于其他需要3.3V外设的供电。
图4.1.5 CYT2BL3驱动部分原理图
接下来是车模无刷驱动的原理图部分，采用了CYT2BL3作为无刷驱动的主控，通过串口与CYT4进行通信，再采用了两个FD6288T作为H桥驱动芯片，相比于FD6288Q的封装，焊接上更为容易，避免出现虚焊带来的驱动问题，保证了无刷驱动的高效运行。
图4.1.6 CYT2BL3驱动部分原理图
磁编码器电路板
磁编码器作为MCU知晓车模运动状态的重要工具，使用了TLE5012BE3这款芯片，采用SPI通信，外部电阻电容数量少，搭配RT9013这款ldo使得磁编码器模块拥有了更宽的输入电压，适配于更多的使用环境。

5. 微处理器控制软件主要理论、算法说明及代码设计介绍
5.1 控制软件总体方案
本车软件以“实时中断闭环 + 主循环决策”的结构组织。主循环在 main_cm7_0.c 中周期调用 GPS_MainTask、Nav_Mode_switch 和 Image_process，负责 GPS 数据维护、导航状态机推进以及视觉元素识别；PIT 中断在 cm7_0_isr.c 中完成 IMU 姿态更新、轮速采样、INS 里程积分、GPS/IMU 融合更新和电机输出，保证底层控制不被图像或屏幕任务阻塞。
工程代码按职责划分为导航、定位融合、图像识别、腿部控制、电机驱动、PID/滤波、屏幕菜单和灯效提示等模块。导航模块提供定位：GPS+INS 融合；科目选择由 Subject 枚举管理，元素状态由 Element_state 管理，使路径策略、速度策略和腿部动作能够在统一状态机内切换。

5.2 导航与路径规划算法
导航状态机以 PATH_READY、PATH_RUNNING、PATH_COMPLETED 和 PATH_STOP 为核心状态。发车时调用 Point_library_init 装载当前科目原始点，再由 Trajectory_Segmentation 生成实际跟踪轨迹。运行阶段先根据 nav_mode 选择当前位置来源，再计算预瞄距离、目标航向、速度输出和到点判定。
科目一采用锥桶 S 形曲线方案。代码将当前位置和原始导航点组成 path 序列，从 first_cone_index 之后进入锥桶区，先在相邻锥桶点之间构造正弦峰值点，然后执行到点导航。
科目二采用“分段轨迹行驶 + 原始点旋转”的策略。车辆行驶时仍跟踪 trajectory_points，但到点判定锁定到当前原始点，进入阈值后再执行原地旋转或直接切换。临近目标点时距离环限幅降低冲点风险，最后两个点改为直接跟踪以提升收尾效率。
科目三采用“轨迹跟踪 + 元素段覆盖”的策略。普通段使用Stanley 跟踪；当 current_nav_index 进入预设元素段后，状态机切换为台阶、单边桥、颠簸、草地等元素模式，并调整速度上限、GPS 融合权重、视觉闭环和转向内环 PID 参数。元素退出后统一恢复参数，避免上一段状态残留到下一段。
5.3 速度链路与姿态闭环
速度链路从无刷电调回传开始。Bldc.c 的 Get_speed 对左右轮回传速度做三点中值滤波和 EMA 低通，得到 Left_Speed、Right_Speed 和 AVG_Speed；导航层根据当前科目、当前原始段、前方转角和到点距离计算 Position_Distance_OUT；Timer.c 在 10ms 周期内用 Speed_Ring 对目标速度和 AVG_Speed 做闭环，输出 SPEED_OUT。
姿态链路采用多级闭环。1ms 周期根据角速度环得到 GYRO_OUT，5ms 周期由角度环将 SPEED_OUT 转换为目标俯仰控制量，电机输出阶段再叠加 Position_Yaw_OUT2 形成左右轮差速。保护模式、导航结束或平衡关闭时会清零速度、角度、转向和距离环输出，防止电机继续带力。
5.4 GPS、INS 与视觉融合
GPS.c 负责 GNSS 数据解析、发车原点捕获和科目航点库管理。GPS 点按科目分组存储，GPS_GetSubjectIdx 和 gps_subject_offset 使三个科目可以共用 GPS_PointLibrary；导航开始时根据发车原点把经纬度转换为局部厘米坐标，并记录 launch_yaw_ref_deg 作为航向零点。
INS 部分基于左右轮速度和 Yaw_Use 进行差速车位置积分。GPS_IMU_INS_Task 在 GPS+IMU 模式下使用 GPS 速度和航向参考更新融合状态；nav_apply_ins_gps_correction 则在 GPS 有效时把 INS 坐标按权重拉回 GPS 坐标。
视觉模块 Image_process 主要服务科目三元素。图像处理从摄像头帧中提取边线、中线；单边桥和台阶视觉模式下，导航层使用 Image_midline_error 或修正后的桥面中心误差调用 nav_fast_output_request_image_fixed，让转向跟随视觉中心而不是单纯跟随 GPS/INS 路径。
5.5 腿部机构与特殊元素控制
腿部控制由 Leg_control.c 统一管理。Leg_Control 每 20ms 调用，先处理自动跳跃，再根据 Element_state 切换腿部目标姿态。Normal、Single_bridge、Three_steps、Three_steps_vision、Bumpy_road 和 Grass 等状态具有不同的四腿基准角度与修正量。
台阶元素采用自动跳跃序列。进入 Three_steps 后，Leg_Jump_Control 触发 Jump_State 状态机，按伸腿、缩腿、缓冲伸腿和恢复阶段改变左右腿目标高度，并在跳跃过程中暂停 Roll 自稳，防止姿态环与跳跃动作互相干扰。
单边桥元素采用视觉确认与 Roll 自稳结合。进入桥面后切换 Element_state 为 Single_bridge，打开 Roll_enable，并临时替换转向内环参数以增强桥面跟踪稳定性。颠簸路段则提高转向和角度环增益，并带有卡住计数与短时脱困逻辑。
5.6 代码可靠性与现场调试设计
代码中大量关键参数被集中到 Nav.c、ScreenMenu.c 和 Menu_Flash.c 管理，包括三科目速度、到点阈值、GPS/INS 融合权重、元素速度、视觉开关和 PID 参数。屏幕菜单可在现场直接修改参数，Flash 负责掉电保存，避免每次调车都重新编译下载。
实时可靠性方面，底层输出使用 nav_fast_output_command 作为主循环到中断的命令缓冲，并在写入时关闭全局中断，减少半更新数据被控制环读取的风险；导航停止、保护模式、平衡关闭和路径完成都会调用统一清零逻辑，恢复 PID、腿部状态、灯效和元素状态。
调试观测方面，工程提供 telemetry_viewer.py、plot_nav_trajectory.py、nav_centripetal_test.py 等离线工具，用于查看导航点、轨迹拟合、实时位置和预瞄点。车载端通过 TFT 页面显示 INS、GPS、融合坐标、导航索引、速度和元素状态，便于赛场快速定位问题。

/* -------------------- PID计算 -------------------- */
/**
  * @brief  位置式PID
  * @param  pid PID结构体指针,目标值,当前值
  * @retval PID输出
*/
float Pos_PID (PID_Struct *pid,float Target,float Now)
{
  uint8_t integral_enabled = 0;

  // 更新测量值历史
  pid->Measure[2] = pid->Measure[1];
  pid->Measure[1] = pid->Measure[0];
  pid->Measure[0] = Now;           // 当前测量值

    // 更新误差历史
    pid->Bias[2] = pid->Bias[1];  // 上上次误差 = 上次误差
    pid->Bias[1] = pid->Bias[0];  // 上次误差 = 当前误差
    pid->Bias[0] = Target - Now;  // 当前误差

  integral_enabled = (pid->Integral_Separation <= 0.0f) ||
                     (fabs(pid->Bias[0]) <= pid->Integral_Separation);
        
    // PID计算
    pid->Pout = pid->Kp * pid->Bias[0];
  if(integral_enabled)
  {
    pid->Iout += pid->Ki * pid->Bias[0];
  }
  else
  {
    pid->Iout = 0;
  }
  // 计算D项
  if (pid->Diff_On_Measure)  pid->Dout = -pid->Kd * (pid->Measure[0] - pid->Measure[1]); // 微分先行
  else
      pid->Dout = pid->Kd * (pid->Bias[0] - pid->Bias[1]);// 误差微分
    
    // 积分限幅
    if(pid->Iout > pid->Max_Iout){pid->Iout = pid->Max_Iout;}
    if(pid->Iout < pid->Min_Iout){pid->Iout = pid->Min_Iout;}
    
    // 输出合成
    pid->Out_Put = pid->Pout + pid->Iout + pid->Dout;
    
    // 死区
    if(fabs(pid->Bias[0]) < pid->Blind_Spot){pid->Out_Put = 0;}
    
    // 输出限幅
    // 注意 Min_out = -Max_out 默认
    if (pid != &Speed_Ring)
    {
        pid->Min_out = -fabs(pid->Max_out);
    }

    if(pid->Out_Put > pid->Max_out){pid->Out_Put = pid->Max_out;}
    if(pid->Out_Put < pid->Min_out){pid->Out_Put = pid->Min_out;}
    
    // 返回输出
    return (float)pid->Out_Put;
}

float pid_out = 0.0f; // 增量PID输出
float pid_Dmax = 5.0f; // 增量PID输出限幅
/**
  * @brief  增量式PID
  * @param  pid PID结构体指针,目标值,当前值
  * @retval PID输出
*/
float Inc_PID (PID_Struct *pid, float Target, float Now)
{
    // 更新误差历史
    pid->Bias[2] = pid->Bias[1];  // 上上次误差 = 上次误差
    pid->Bias[1] = pid->Bias[0];  // 上次误差 = 当前误差
    pid->Bias[0] = Target - Now;  // 当前误差
    
    // 增量PID计算
    pid->Pout = pid->Kp * (pid->Bias[0] - pid->Bias[1]);
    pid->Iout = pid->Ki * pid->Bias[0];
    pid->Dout = pid->Kd * (pid->Bias[0] - 2 * pid->Bias[1] + pid->Bias[2]);

    pid_out = pid->Pout + pid->Iout + pid->Dout;

    if(pid_out >= pid_Dmax){pid_out = pid_Dmax;}
    if(pid_out <= -pid_Dmax){pid_out = -pid_Dmax;}

    // 累加输出
    pid->Out_Put += pid_out;
    
    // 死区
    if(fabs(pid->Bias[0]) < pid->Blind_Spot){pid->Out_Put = 0;}
    
    // 输出限幅
    // 注意 Min_out = -Max_out 默认
    if (pid != &Speed_Ring)
    {
        pid->Min_out = -fabs(pid->Max_out);
    }

    if(pid->Out_Put > pid->Max_out){pid->Out_Put = pid->Max_out;}
    if(pid->Out_Put < pid->Min_out){pid->Out_Put = pid->Min_out;}
    
    // 返回输出
    return (float)pid->Out_Put;
}

{

    if (b > c) { b = c; }
    if (a > b) { b = a; }

static uint8_t final_stop_yaw_damping_active(void)

  return (Mode == Auto &&
          Path_state == PATH_COMPLETED &&
          speed_abs > FINAL_STOP_YAW_DAMP_SPEED_MIN) ? 1U : 0U;
}

//设置电机占空比
void Set_Motor_duty(float left_duty,float right_duty)
{
  if(nav_disable_yaw_diff &&
     !final_stop_yaw_damping_active() &&
     !((left_duty == 0.0f) && (right_duty == 0.0f)) &&
     !(Mode == Remote && Mode_state.Wheel_control == 1))
  {
    float common_duty = 0.5f * (left_duty + right_duty);
    float sync_out = (float)(Left_Speed - Right_Speed) * 0.12f;

    if(sync_out > 350.0f) sync_out = 350.0f;
    if(sync_out < -350.0f) sync_out = -350.0f;

    left_duty = common_duty - sync_out;
    right_duty = common_duty + sync_out;
  }

  // 输出限幅
  if(left_duty >= DUTY_MAX) left_duty = DUTY_MAX; 
  if(right_duty >= DUTY_MAX) right_duty = DUTY_MAX;
  
  if(left_duty <= -DUTY_MAX) left_duty = -DUTY_MAX;
  if(right_duty <= -DUTY_MAX) right_duty = -DUTY_MAX;
  
  // 设置电机占空比
  motor_set_duty_in_progress = 1;
  small_driver_set_duty(-(int16)left_duty,(int16)right_duty);
  motor_set_duty_in_progress = 0;
}
