摘  要
本文介绍西安邮电大学轮腿穿越组智能车的系统设计与实现。整车以英飞凌 TRAVEO™ T2G CYT4BB 双核 Cortex-M7 微控制器为核心，采用双轮驱动、四舵机并联轮腿机构，搭载 IMU660RB 惯性传感器、GPS模块、MT9V03X 灰度摄像头及轮速反馈。系统以 2 ms、5 ms、10 ms 多速率周期任务分别完成姿态采样与底层控制、姿态解算与组合导航、按键及安全管理；以角度—角速度—速度串级 PID 实现动态平衡，以轮腿逆运动学、腿长/车身姿态调节和分阶段跳跃控制适应台阶、单边桥、颠簸路肩等障碍；以轨迹复现、GNSS航向校正、惯导定位和视觉道路检测完成路径跟踪。软件设置停车、运行、菜单、轨迹采集、遥控与失控保护等工作模式，并在输出端设置限幅、状态清理和舵机保护。本文按照第二十一届竞赛技术报告细则，对机械与传感器布局、硬件连接、软件算法、开发调试流程和主要技术参数进行说明，并在附录给出电路资料说明及核心算法源代码。
关键词：轮腿；动态平衡；组合导航；轨迹复现；视觉循迹；多速率控制
Abstract
This report presents the design and implementation of a wheel-legged autonomous vehicle for the 21st National Undergraduate Intelligent Car Competition. The system is built around an Infineon TRAVEO™ T2G CYT4BB dual Cortex-M7 microcontroller. A two-wheel drive base and four-servo parallel wheel-leg mechanism are integrated with an IMU660RB inertial sensor, a GPS receiver, an MT9V03X grayscale camera, and wheel-speed feedback. Multi-rate tasks at 2 ms, 5 ms, and 10 ms execute attitude sampling and low-level control, attitude estimation and navigation, and human-machine/safety management, respectively. Cascaded PID loops regulate body balance, wheel-leg inverse kinematics adjusts the chassis posture, and a staged jump controller handles stairs, a single-side bridge, bumpy terrain, and ramps. Recorded-route replay, GNSS/inertial positioning, and visual road detection provide navigation and tracking. The report describes the mechanical structure, hardware interconnection, control software, debugging procedure, and key technical parameters, with circuit-document references and core source code included in the appendices.
Keywords: wheel-legged robot; dynamic balance; integrated navigation; route replay; visual tracking; multi-rate control

第一章 引言
1.1 竞赛任务与设计目标
轮腿穿越组要求模型车在室外场地自主完成规定路线，并根据科目处理掉头、锥桶/路径点、排雷点以及台阶、单边桥、颠簸路段等典型障碍。相较于平整赛道循迹，轮腿车既要保持高速行驶时的动态平衡，又要在路面高程和附着条件突变时快速调整腿长、车身姿态与速度，同时还要应对室外光照变化和 GNSS 短时漂移。
本车的设计目标是：以统一的状态机组织不同科目，以高频姿态闭环保证底盘稳定，以轨迹复现和多传感器定位保证路线跟踪，以轮腿机构的主动调节提高障碍通过能力，并通过保护模式、输出限幅与参数分区降低现场调试风险。
1.2 总体技术方案
系统由机械执行、感知定位、嵌入式控制和人机调试四部分组成。机械端采用左右驱动轮与四舵机轮腿机构；感知端由 IMU660RB、GPS、MT9V03X 和电机轮速反馈组成；控制端由 CYT4BB7 完成姿态解算、轨迹跟踪、状态判断和执行器输出；调试端采用 TFT 显示、按键与拨码、蜂鸣器、调试串口及无线接收模块。

第二章 机械结构与传感器安装
2.1 轮腿底盘方案
车体采用两侧独立驱动轮承担前进、制动和转向，左右两侧各由前、后两个舵机驱动并联轮腿。代码中的几何参数 L1=6.0、L2=9.0、L3=9.0、L4=6.0、L5=3.7（单位按建模标定值）构成轮腿逆解模型。四舵机安装零位分别设置 +5°、-9°、-5°、+4°补偿，以抵消装配误差。轮腿通过改变末端目标坐标 (X,Y) 调节车体高度、俯仰补偿与跨障姿态。
底盘布置遵循低重心、左右质量对称、传感器刚性连接和线束不干涉的原则。电池与主控板固定在车体中部；驱动与大电流线束远离 IMU 和 GNSS 天线；舵机线束预留全行程余量并做拉力释放。所有紧固件在赛前复核，轮腿连杆转动副应消除明显间隙但不得卡滞。
2.2 轮腿运动学与执行机构
逆运动学函数以目标点 C(X,Y) 为输入，根据两组连杆长度和余弦定理求解前、后舵机角。为防止计算越界，程序对 X、Y 和舵机角分别限幅，并对四个舵机施加独立零位补偿。正常行驶时，左右轮腿采用同一基础高度；车身滚转或障碍状态出现时，在左右目标高度上叠加差动量。跳跃状态按收腿、准备起跳、执行伸展、恢复平衡四阶段改变腿长，同时临时调整控制器增益。
2.3 传感器安装
IMU660RB 必须与车体刚性连接，安装轴向与软件坐标定义一致，远离大电流回路和强振动源。开机静止 500 ms 后执行陀螺零偏采集，随后进入姿态解算。GNSS布置在车体上方前部无遮挡位置，避免被金属结构或电池遮挡，主要用于起点对准、全局路径点和累计漂移校正。MT9V03X 灰度摄像头固定在车体上方中心位置，视场覆盖近场道路边界；安装角度须在轮腿最高与最低位置均不被车体遮挡。电机反馈由驱动通信获取左右轮速，用于速度闭环、里程计和障碍距离判断。

主控板、驱动接口板和配电模块采用绝缘垫柱固定，板底焊点与金属件保持安全距离。电源线和电机线采用足够线径并缩短回路，信号线分束走线；摄像头、IMU、GNSS 与无线模块的接口均设置防反插标识。连接器在振动环境下使用锁扣或扎带固定，线束转折处避免反复弯折。

第三章 硬件系统设计
3.1 控制器与系统架构
控制器采用 CYT4BB7平台，系统时钟配置为 250 MHz，工程基于逐飞 CYT4BB 7开源库和官方 SDK，使用 IAR Embedded Workbench 9.40.1工程组织。主程序完成显示、按键、蜂鸣器、GNSS、无线接收、IMU、姿态解算、舵机、小驱板通信、Flash 和摄像头初始化。程序预留双 Cortex-M7 工程结构，当前核心控制流程在 CM7_0 上执行。

4.2 姿态解算与动态平衡
开机时累计 IMU 静止数据获得三轴陀螺零偏，运行时将原始加速度和角速度换算为物理量并滤波，姿态模块输出滚转、俯仰和航向角。底层控制以串级结构为主：外层角度环根据目标姿态产生角速度目标，内层角速度环产生左右电机公共力矩；航向角环和航向角速度环产生差动力矩；腿部倾斜速度环和腿部姿态环用于改变平衡零点及车体高度。
u_balance = Kpθ(θ*−θ)+Kiθ∫eθdt+Kdθdeθ/dt
uL = sL·u_balance + u_yaw，uR = sR·u_balance + u_yaw
控制输出在进入驱动前进行上下限约束，PID 状态在模式切换与跳跃恢复时执行清理，避免 NaN、积分残留或突变指令。当前代码中不同科目保存两套控制参数，允许按路况切换角度、角速度、航向和腿长控制器。
4.3 轨迹复现与组合定位
轨迹采集模式按固定里程间隔记录航向角并写入 Flash；运行时根据累计里程读取当前和前瞻轨迹点，得到前馈航向角。导航 PID 以横向误差 e_y 为输入生成航向补偿量，与记录航向叠加后形成目标航向。代码将每 5 cm 记录一次轨迹，Read_MaxSize 为 20000，可覆盖较长室外路线。
INS 模块根据车身航向和左右轮平均里程进行平面航位推算，并支持用 GNSS 经纬度建立起点/目标点方向和距离。科目函数优先使用 INS 路径，GNSS 用于起点校准、全局参考与特殊路段后的航向修正。

4.4 视觉道路检测
MT9V03X 图像处理流程包括自适应或固定阈值二值化、图像压缩、左右边界搜索、中线生成、加权偏差计算和丢线恢复。程序可选择中线、左边线或右边线跟踪；当中心采样列全部变黑、常规边界搜索失败时，根据分块白点分布判断道路位于车辆哪一侧并输出恢复方向。道路宽度与图像特征同时用于台阶、单边桥、颠簸和坡道等状态判断。
4.5 科目与障碍状态机
Custom_Tracking 根据 subject 选择科目一、二或三的 INS 跟踪函数。路径点数组中的元素类型编码用于触发不同动作：1 为掉头，2 为终点，3/4 为锥桶或中段标志，5 为排雷点，6 为台阶，7 为单边桥，8 为颠簸路，10 为坡道，11/12 为减速与恢复点。车辆在接近障碍时切换目标速度，进入障碍后调用对应 Judgment 函数，完成后设置 finish 标志，避免重复触发。

4.6 跳跃与轮腿协同控制
跳跃控制采用时间分段状态表。以当前定版配置为例，0～100 ms 保持起跳前状态，100～230 ms 收腿并改变腿长，230～330 ms 执行缓冲，随后恢复控制器。进入跳跃时保存腿角、腿速、车速、车身角度和角速度控制器参数，临时降低或关闭部分环节；退出时恢复原参数并清理控制器历史量。
4.7 模式管理与安全保护
车辆具有 Stop、Run、Jump、Spin、Controller、Menu、Collect、Remote 等模式。拨码开关决定菜单、运行、停车和遥控入口；终点标志使车辆自动停车；Controller 模式将速度目标清零以支持接管保护；Menu 和 Collect 模式禁止电机输出。舵机保护函数将四舵机收至安全角度。速度、角度、角速度和舵机目标均设置限幅，并对异常浮点数执行清理。

第五章 开发、制作与调试过程
5.1 开发工具
嵌入式工程使用 IAR Embedded Workbench 9.40.1，底层基于英飞凌官方 SDK 和逐飞 CYT4BB 开源库。代码按 Camera、IMU、GPS、INS、Navigation、Tracking、My_Car、PID、FCleg、Jump 等模块组织。TFT 用于现场显示模式、距离、目标航向和姿态量；调试串口及无线链路用于传输波形与参数。机械零件使用常规 CAD/3D 打印或机加工流程完成，电路资料建议统一使用 Altium Designer/EDA 管理。

  图5.1.1 IAR Embedded Workbench 9.40.1界面
5.2 制作与标定流程
制作顺序为：底盘和轮腿装配→舵机零位与连杆几何标定→电源和线束检查→主控/传感器安装→单模块初始化测试→静态姿态标定→悬空电机方向与反馈极性确认→低速平衡→路线采集与复现→障碍分项调试→全程联调。任何结构改动后均重新检查重心、舵机零位、IMU 方向和轮速比例。
5.3 分层调试方法
第一阶段观察原始 IMU、GNSS、图像和轮速，确认单位、极性和刷新频率；第二阶段支起车体，以小输出验证左右电机和四舵机方向；第三阶段锁定低速目标，按“角速度内环—角度外环—速度环—航向环—腿部控制”顺序整定；第四阶段采集直线和曲线路径，调整前瞻距离与横向误差补偿；第五阶段逐个调试台阶、单边桥、颠簸路和坡道，并记录进入速度、触发距离、姿态峰值和恢复时间；最后进行电量、光照、温度和多轮重复性测试。
5.4 版本管理与复现实验
项目使用 Git 保存迭代记录，建立“代码提交—参数备份—车体结构—电池状态—场地条件—结果”的对应关系，禁止只修改板端参数而不记录。
第六章 主要技术参数
细则要求给出整车重量、尺寸、功耗、电容总容量、传感器和伺服电机数量以及赛道信息检测精度/频率。代码可以确认控制周期、传感器型号和执行器数量，但无法替代对实车、电路板和电源的测量。为保证报告真实性，下表将无法从工程核实的数据保留为待实测项。

第七章 结论与展望
本车围绕室外轮腿穿越任务，完成了以 CYT4BB 为核心的多传感器轮腿控制系统。系统将高频动态平衡、轮腿逆运动学、轨迹复现、GNSS/INS 定位、视觉道路检测和多障碍状态机整合到统一软件架构中，并通过多速率调度、输出限幅、参数保存恢复与模式保护提高实时性和安全性。项目代码模块边界清晰，具备按科目切换速度和控制参数、保存与复现路线、处理台阶/单边桥/颠簸路肩的能力。

A.2 轮腿逆运动学（FCleg.c 摘录）
void Inverse_solution(wheel_param_ *p, float X, float Y) {
    X = func_limit_ab(X, -16.7f, 16.7f);
    Y = func_limit_ab(Y, 0.0f, 13.0f);
    float CX=X, CY=Y+3.0f, AX=-p->L5/2.0f, EX=p->L5/2.0f;
    float AC=hypotf(CX-AX,CY), EC=hypotf(CX-EX,CY), CO=hypotf(CX,CY);
    float a=acosf((p->L1*p->L1+CO*CO-p->L2*p->L2)/(2*p->L1*CO));
    float b=acosf((p->L5*p->L5*0.25f+AC*AC-CO*CO)/(AC*p->L5));
    p->phi1 = func_limit_ab((a+b)*180.0f/PI, 90, 260);
    /* 另一侧同理求 phi4，并换算为四舵机 PWM */
}
