简  介
本设计以第二十一届全国大学生智能汽车竞赛轮腿穿越组任务为背景，采用 CYT4BB7 微控制器作为核心控制单元，设计并开发了一款基于 V 型车模的轮腿式越野机器人。在感知与导航方面，系统利用激光测距传感器精准识别台阶等复杂地形，并融合陀螺仪与磁编码器数据，实现实时的测速与高精度的惯性导航。在运动控制方面，系统引入 PID 控制算法对车速及腿部高度进行动态解算与调节，实现了对车辆运动状态、速度及航向的精确闭环控制。此外，为进一步提升系统运行的机动性与稳定性，团队借助遥控器、独立按键及 TFT1.8 寸液晶屏等辅助交互模块，进行了充分的软硬件联调与优化。最终实车测试表明，该系统设计方案合理、运行稳定，各项性能均切实可行。
关键词：CYT4BB7，惯导，PID，陀螺仪

第一章  系统总体设计
1.1机械设计概述
我们采用了V车模并加以改装，通过使用英飞凌公司CYT4BB7芯片为核心控制器，增加imu660rc陀螺仪，制作出利用惯导来自主运行的汽车模型。由于车模为平衡车，在高速运行时，对车模的稳定性以及灵活性有很高的要求，所以机械结构的要求很高。
1.2硬件设计概述
硬件电路是小车平稳运行的基础，在尝试多种硬件电路后，确定了一套可靠的设计方案，满足性能需求。将电路设计得尽量简洁，缩减电路板面积，减轻电路重量，减轻整车重量，降低车模重心。
1.3软件设计概述
完整的软件控制是小车运行的核心。通过陀螺仪读取加速度与角速度，通过姿态解算获取车身当前姿态角，通过角速度、角度、速度进行平衡的控制。通过处理陀螺仪与磁编码器数据，计算出自身坐标，并根据目标点坐标，计算获得准确的行进路线。根据获取的路线对小车的转向和速度进行控制。

第二章  智能车机械结构设计
智能车的运动控制高度依赖其初始的机械底盘。我们在构思软件算法前，首要任务是摸清车模的机械特性并建立可靠的数学模型。进而，依据实际的赛题需求对车体结构进行定制化改装，并在下地调试过程中反复测试与完善。本章将详细梳理本届赛车的机械结构组成及改造调整策略。 
2.1 整体结构
本项目以逐飞科技V车模作为基础平台，动力系统搭载BDS3620无刷电机。为适应不同摩擦系数的赛道材质，轮胎特选用逐飞科技R车模后轮。同时，整车进行了严格的轻量化设计，从而有效降低负载，确保BDS300舵机能够输出充足力矩，完美实现车辆的跳跃功能。
2.2 车模的整体安装
 2.2.1 电路板的安装 
为兼顾车模的行驶速度与稳定性，整车硬件布局遵循“低重心、居中对称”的原则，所有电路板均尽量沿中轴线布置。具体安装方案如下：主板与舵机驱动板并排安装在舵机上方，通过自制3D打印件进行紧固；考虑到走线便利性，无刷电机驱动板需与电机及磁编码器相连，因此将其布置在舵机前侧，同样采用3D打印件固定并加装了专属保护壳。为确保数据采集的精准度，磁编码器安装于无刷电机尾部[1]。此外，为满足车辆跳跃时的机械位移需求，无刷电机三相线及磁编通讯线均预留了充足的冗余长度。整体装配如下图1、2、3所示。

 2.2.2 电池的安装
	考虑到电池是全车的主要配重件，为进一步减轻整车重量，我们在权衡后选用了小容量电池。虽然双无刷电机与四舵机组合的耗电量较大，但比赛排队发车的赛制提供了充足的换电时间，弥补了续航短板。在安装方案上，我们在舵机下方设计了3D打印安装板，并采用两条魔术贴进行固定。此方案不仅便于电池的快速拆装，还能确保电池位置牢固，避免因激烈运动导致重心偏移，从而对车辆的机械零点造成影响。此外，电池的安装位置经过精确调整，使其重心尽量与车模整体重心保持在同一垂线上，进一步保障了行驶的稳定性。


第三章  硬件系统设计及实现
	为提高硬件系统的可维护性，并满足赛场上备用板快速更换的需求，本车模的硬件系统采用了模块化设计，将整体功能合理解耦至五块电路板中。各模块分工明确：主控板作为系统核心，负责采集多传感器数据，解算出最优的电机目标转速与舵机控制信号并下发指令；舵机驱动板专职执行舵机动作控制[2]；无刷驱动板负责驱动无刷电机运转，同时实时采集电机转速数据，并通过串口回传至主控板；磁编码器板则用于精准采集电机转子的磁极位置方向。
3.1主控板
	本系统全部硬件由3S（12V）锂电池统一供电。针对主控板上各模块的不同工作电压需求，我们设计了多路稳压电路。考虑到摄像头模块工作电流较大，为防止其拉低电压或产生电源噪声干扰主控运行，特为其独立分配了一路降压芯片。因此，本系统的电源拓扑共包含三个降压电路：一路12V转5V主供电电路，以及两路相互独立的5V转3.3V电路（分别供摄像头与其他逻辑器件使用），以此满足全车的供电需求与稳定性要求。
	12V转5V的主供电网络核心采用了SCT2450同步降压转换芯片。该芯片支持宽电压输入范围，并具备高达5A的连续输出电流能力，具有转换效率高、内阻低及发热量小等优异特性。由于本车模采用12V的3S锂电池供电，且5V总线不仅需要为两路后级3.3V稳压电路供电，还可能承载部分传感器的峰值功耗，因此对电源的带载能力和动态响应要求极高。SCT2450的引入不仅保障了12V至5V的高效降压转化，更为整个主控系统提供了充裕的功率余量与稳定的电压基准，有效避免了由于瞬间大电流负载导致的系统复位或数据异常。该部分电源模块的具体原理图如下图4所示。

图 4电源模块原理图
	5V转3.3V的后级稳压电路选用了RT9013-33低压差线性稳压芯片（LDO）。相较于开关电源，LDO具有输出纹波极小、噪声低以及高电源抑制比（PSRR）等显著优势[3]。由于本系统中的主控MCU、各类高精度传感器以及摄像头模块对电源的纯净度要求极高，任何微小的电压波动都可能导致ADC采样误差或图像噪点。RT9013-33不仅能提供高达500mA的稳定输出电流，其快速的瞬态响应特性还能有效滤除5V总线上的高频杂波。通过该芯片构建的两路独立3.3V供电网络，彻底阻断了不同模块间的电源串扰，为核心数字与图像器件提供了极为纯净、平稳的工作电压。该稳压模块的详细设计原理图如下图5所示。

图 5稳压模块原理图
	为避免大电流负载下直接使用机械开关造成的触点打火与过载损坏，电源入口采用了基于 P 沟道 MOSFET（HY19P03）的固态电子开关设计。该电路通过微型拨动开关控制 MOSFET 栅极电平，使机械开关仅承受微安级的控制电流，真正的大电流则流经低内阻的 MOSFET 主通道，显著降低了开关压降与发热损耗。此外，外围接入的 16V 稳压二极管与下拉电阻构建了完善的栅极过压保护机制，有效防止了电源浪涌与反电动势击穿管子，保障了系统上电瞬间与高负荷运行下的电气安全性。该部分电路的具体原理图如下图6所示。

3.2 舵机驱动板
舵机驱动板的输入电源直接引自主控板的 12V 主供电母线。由于本系统所用舵机的标准额定工作电压为 7.4V，必须在驱动板上进行降压处理。经前期极限工况实测，单个舵机在瞬间发力或堵转时的峰值电流可高达 2A。若四个舵机采用单一芯片进行集中降压，极易因瞬态总电流过大（达 8A）导致芯片过热保护或输出电压严重跌落。为此，本设计采用了高可靠性的“分布式供电”方案，在驱动板上并联配置了四颗 SCT2450STER 同步降压芯片，为四个舵机提供“一对一”的独立 7.4V 稳压电源。该方案不仅确保了每个舵机都能获得充沛的瞬态功率支持，还实现了各路电源的相互隔离，彻底避免了多舵机联动时的电源耦合干扰。在信号控制方面，四路 PWM 控制信号则直接由主控板引出并接入对应舵机，以保证控制指令的低延迟传输。该舵机驱动板的具体原理图如下图7所示。

3.3 无刷双驱板
本车模的动力核心采用了自主设计的双路无刷电机驱动板，其硬件架构主要由电源管理、输入滤波、预驱动及逆变桥四大核心模块组成。 在供电端，为避免主路高压直接干扰逻辑电路，板载了两颗 RY9121E 降压芯片，分别独立生成 5V 与 3.3V 逻辑电压。同时，电源输入端并联了大规模的 MLCC 贴片电容阵列，并辅以 TVS 瞬态抑制二极管（SMAJ16A/CA），以强力吸收无刷电机急刹车或频繁换向时产生的巨大反电动势与电压尖峰。 
在驱动级，系统选用了两颗专用的三相栅极预驱芯片 FD6288Q，配合自举电容电路，为后级提供稳定的高低边驱动信号。功率输出端则选用了导通内阻极低的 TPN2R703NL 贴片 MOSFET 构建双三相逆变桥，该管子出色的电流承载能力与极低的热损耗，能够完美满足 BDS3620 无刷电机在跳跃与平衡控制时的瞬间大电流爆发需求。此外，板载引出的 UART 串口通过串联 100Ω 电阻进行阻抗匹配与保护，负责将采集到的电机转速等状态数据高速回传至主控板。无刷电机驱动板的具体原理图如下图8所示。

3.4 磁编
为实现无刷电机转子磁极位置的高精度采集，本系统独立设计了基于英飞凌 TLE5012B 巨磁阻（GMR）传感器芯片的磁编码器模块。在电源端，由于磁传感器对供电纹波极为敏感，模块输入端串联了 1N5819WS 肖特基二极管以实现防反接保护，并后接 RT9013-33 低压差线性稳压器（LDO），将外部输入的 5V 电压降至纯净的 3.3V，配合多级滤波电容，为传感器提供高稳定的工作电压[5]。在通信接口方面，TLE5012B 采用半双工 SSC（兼容 SPI）通信协议，电路中巧妙地通过 470Ω 电阻将单片机的 MISO 与 MOSI 信号线桥接，实现了标准 4 线 SPI 到传感器单根双向 DATA 线的电平转换与阻抗匹配；同时在时钟（SCK）与片选（CS）信号线上串联 100Ω 电阻，有效抑制了高频信号的反射与振铃现象，确保了电机高速运转下位置数据回传的精准与可靠。该磁编码器模块的具体原理图如下图9所示。

第四章  软件系统设计及实现
如果说精密的机械结构与可靠的硬件电路构成了车模坚实的物理基石，那么高效的软件控制算法则是驱动整个系统精准运行的“核心大脑”。本章将重点围绕车模的软件架构、控制逻辑及核心算法展开详细阐述。
4.1 原始数据采集
在底层传感器驱动开发中，为保障数据读取的实时性与稳定性，本系统充分利用了逐飞科技针对该平台优化的底层驱动库。该库提供了高效且可靠的数据采集方案，因此，无论是IMU660RC陀螺仪原始姿态数据的快速读取，还是无刷电机磁编码器高频数据的采集与解析，本系统均直接基于逐飞库提供的API接口实现。这不仅大幅提升了软件开发效率，更夯实了底层数据的可靠性。
4.2 姿态解算与数据融合算法
IMU660RC 惯性测量单元直接采集输出的原始数据为三轴加速度与三轴角速度[6]。然而，在车模的动态平衡与姿态控制中，系统真正需要的是直观且无万向节死锁（Gimbal Lock）问题的欧拉角（Roll, Pitch, Yaw）作为闭环反馈的基准参考量。由于无刷电机在高速运转时会产生强烈的机械高频震动，且陀螺仪自身存在固有的低频积分漂移，如果仅对原始数据进行简单积分，会导致姿态角迅速发散。为此，本系统自主设计了一套结合动态 PI 调节与高精度时间戳的 Mahony 互补滤波算法，对原始数据进行了多层级的深度处理，具体流程如下：
4.2.1 原始数据预处理与差异化滤波 
在数据进入解算核心之前，系统首先对陀螺仪进行了静态零偏校准与死区滤除，以剔除静止状态下的传感器底噪。同时，针对加速度计和陀螺仪不同的频率响应特性，系统引入了定制化的一阶低通滤波（LPF）。考虑到加速度计对底盘的高频机械震动极其敏感，我们对其采用了较为激进的滤波系数（取 0.5），以牺牲极小响应速度的代价换取数据的平滑；而对于自身高频响应较好且不易受高频震动干扰的陀螺仪，则采用了较为温和的滤波系数（取 0.9）。这种差异化的预处理方案，在信号源头极大削弱了电机震动带来的共模干扰。
4.2.2 基于 DWT 的高精度积分时间计算 
姿态解算的本质是对角速度进行积分，而积分时间间隔（dt）的精度直接决定了四元数更新的准确性。传统方法通常采用固定的定时器周期（如 5ms）作为 dt，但在实际运行中，由于 RTOS 任务调度或中断嵌套，实际执行周期会产生微小抖动。为彻底消除这一误差，本算法底层调用了 ARM 内核的 DWT（数据观察点和跟踪）周期计数器。通过捕获 CPU 运行的时钟周期差值，实现了纳秒级别的极高精度时间戳计算，并在此基础上加入了合理的阈值限幅保护，确保了算法在任何极端工况下都不会发生积分爆炸。
4.2.3 带有防干扰机制的动态 PI 互补滤波 
在核心的姿态融合阶段，算法通过提取当前四元数中的重力方向向量，将其与加速度计测量的实际向量进行叉积运算，计算出当前的姿态误差。值得一提的是，本系统在此环节引入了动态 PI 调节机制：程序会实时监控加速度计的模长（norm_acc），当检测到模长偏离正常的重力加速度区间（即不在 3500 至 4500 之间）时，系统判定车模正处于剧烈颠簸或急加减速的强干扰状态。此时，算法会智能地将比例系数（KP）与积分系数（KI）瞬间置零，暂时切断加速度计对陀螺仪的修正权重，纯粹依靠陀螺仪短时间内的优异积分特性来维持姿态[7]。待车身震荡结束后再恢复 PI 调节。这一设计完美解决了高动态工况下姿态被瞬间“拉偏”的致命问题，并辅以严格的积分限幅，防止了误差的过度累积。
4.2.4 欧拉角转换与姿态输出 
经过上述带有动态反馈修正的陀螺仪数据，最终被用于四元数的微分方程更新。更新后的四元数在完成严谨的归一化处理后，通过标准旋转矩阵公式被精确转化为车模当前的横滚角（Roll）、俯仰角（Pitch）与偏航角（Yaw）[8]。这一系列深度解算，最终为整车的串级 PID 控制与航向规划提供了极高置信度、零延迟的姿态状态反馈。
4.3 三闭环串级控制算法设计
针对V型平衡车模固有的高度非线性与欠驱动特性，本系统在运动控制架构上构建了以角速度环为内环、角度环为中环、速度环为外环的三闭环串级控制系统。该架构在时域上严格解耦，控制频率由外向内逐级提升，巧妙实现了对无刷电机与跳跃舵机机构的协同控制。
作为系统的最外层，速度环运行在 100Hz 的控制频率下，承担着宏观位置约束与重心调度的关键任务。该环路以左右轮磁编码器采集并解算出的平均车速作为状态反馈，目标给定值在原地驻留状态下设定为零。区别于传统直立车的直接转矩叠加，本系统速度环的控制输出直接作用于底盘的 BDS300 舵机。通过驱动舵机动态调节机械结构，系统能够实时改变车模的重心位置与“机械零点”，从宏观运动学层面有效抑制车模的稳态位移偏差，从根本上消除了“溜车”趋势。
角度环作为控制系统的中环，运行频率提升至 200Hz，在整个架构中起着承上启下的核心作用。其输入反馈量为经 Mahony 互补滤波算法高精度解算出的真实俯仰角（Pitch），基准目标值设定为车模标定后的静态机械零点（约 1.5°~2.5°）。角度环经 PID 运算后的输出并不直接驱动底层硬件，而是作为内层角速度环的动态目标给定值。这一机制不仅能够维持车身宏观上的竖直稳定，还能柔和平滑地补偿外侧速度环因频繁调节重心而引入的低频角度偏移。
位于控制架构最内层的角速度环，是实现车模动态自平衡的绝对核心防线。为追求极致的控制带宽与瞬态响应，该环路运行在高达 1kHz 的硬件中断级频率下。它直接跨过姿态解算延时，抽取 IMU 硬件输出的 Y 轴原始角速度数据作为高频反馈，其目标值严格跟踪角度环的实时输出指令。依托极高的执行频率，角速度环的最终 PID 计算结果被直接转化为底层 BDS3620 无刷电机的 PWM 占空比指令，使系统能够对路面微小扰动、机械高频震荡及姿态的瞬时变化做出极速的扭矩响应，从而保障车模在复杂工况下的绝对动态平衡。
4.4	 惯性导航和航位推算法
在实现车模自主路径规划与精准定位的过程中，由于系统不依赖外部绝对定位设备，本车模引入了基于多传感器融合的惯性导航技术，并以航位推算法（Dead Reckoning）作为核心的局部定位框架[9]。该算法通过深度融合底盘双侧磁编码器的里程计数据与 IMU 传感器的高精度航向信息，摆脱了对外部环境的依赖，实现了车模在全局二维坐标系下的自主连续位姿估计。
航位推算的核心解算逻辑建立在极短时间窗口内的微分运动学模型之上。在每一个高频控制中断周期内，系统首先读取左右无刷电机的磁编码器脉冲增量，计算出车模在该极短周期内的微小行驶步长；同时，提取由 Mahony 互补滤波算法实时解算出的高置信度偏航角（Yaw）作为当前车模的绝对航向。随后，算法利用三角函数法则，将这一微小步长正交分解为全局坐标系下的横向位移增量与纵向位移增量。最后，将这些微小坐标增量在全局坐标系中进行高频的离散化累加积分，从而持续追踪并描绘出车模实时的运行轨迹与空间坐标。
尽管航位推算法具有响应速度快、短时定位精度高的显著优势，但作为一种纯积分型算法，其不可避免地面临累积漂移误差与车轮打滑导致的里程计失真问题。为此，本系统在导航底层进行了针对性的深度优化：一方面，依托底层调用的 DWT 纳秒级高精度时间戳，确保了速度积分与位移推算周期的绝对精准，从根本上压制了系统离散化过程带来的截断误差；另一方面，结合速度环的闭环平滑控制机制，严格约束了电机瞬态输出的峰值加速度，极大削弱了车轮在极速启停或剧烈跳跃落地时的地面滑移率。通过算法层面的精密补偿与控制机理的协同，本系统有效抑制了惯性导航的长期发散，为后续的复杂路径追踪与目标点精准停靠提供了极其可靠的定位基准。
4.5全局路径规划与点位追踪策略
	在赛事实际执行中，本系统的自主导航任务被合理划分为预采集与实时追踪两个阶段。在正式发车前的准备阶段，系统首先进入航线预采集模式。操作人员通过牵引车模遍历赛道，系统底层依托高精度的航位推算算法，精确记录下赛道各关键节点（如起跑线、弯道切点、任务点等）在全局二维平面内的绝对坐标（X, Y）。这些离散的坐标节点按照特定的逻辑顺序依次存入主控存储器中，构建出一张高保真的全局拓扑地图，为后续的自主行驶提供了绝对可靠的期望路径基准。
在车辆正式发车并进入自主运行状态后，系统将无缝切入高频实时的闭环点位追踪模式。在每一个导航调度周期内，主控算法会实时提取由惯性导航解算出的当前自身坐标，并将其与当前待追踪的目标点坐标进行几何解算。系统一方面利用欧氏距离公式，计算出车辆当前位置与目标点之间的直线绝对距离，并将该距离映射为纵向速度环的目标输入，从而实现直线加速与逼近目标点时的自适应平滑减速；另一方面，算法利用反三角函数（atan2）实时解算出目标点相对于当前坐标的绝对期望方位角，将其与 IMU 当前输出的偏航角（Yaw）作差，得出横向航向偏差。该航向偏差被直接输入至偏航控制环，驱动车模动态修正行驶朝向。通过距离与角度的双维实时闭环，系统完美实现了由点及线的轨迹跟踪，确保车模能够以最优路径、最高效率穿越复杂赛段。
4.6系统开发与调试工具
在底层软件构建方面，主控芯片 CYT4BB7 与驱动板芯片 CYT2BL3 均依托 IAR Embedded Workbench 集成开发环境进行程序编译与在线调试。为进一步提升代码编写与工程管理的效率，日常开发环节深度整合了 Visual Studio Code (VS Code) 及其 IAR 扩展插件，构建了现代化的跨平台协同编码工作流。在控制算法的联调与参数整定阶段，系统配合使用逐飞串口助手与 VOFA+ 数据可视化上位机。通过将底层姿态与速度数据高频回传至上位机，实现了控制波形的实时绘制与 PID 参数的动态观测，极大提高了系统闭环调试的精准度与效率。

        float vy = 2.0f * (q0*q1 + q2*q3);
        float vz = q0*q0 - q1*q1 - q2*q2 + q3*q3;

        /* 3. 计算误差（叉积） */
        float ex = (ay*vz - az*vy);
        float ey = (az*vx - ax*vz);
        /* 4. 积分误差（带限幅） */
        integralFBx += dynamic_KI * ex * dt;
        integralFBy += dynamic_KI * ey * dt;
        if (norm_acc > 4500||norm_acc < 3500)
        { /* 如果加速度计数据异常，说明车身在剧烈振动，此时暂时不要参考加速度计的方向判断，P 和 I 参数暂停，等振动过去后再恢复 */
            dynamic_KP = 0.0f;  /* 完全不参考加速度计，关闭 P 反馈 */
            dynamic_KI = 0.0f;  /* 关闭 I 积分，防止短时的大量累积把陀螺仪漂移拉偏 */
        }
        /* 积分限幅 */
        if (integralFBx > INTEGRAL_LIMIT) integralFBx = INTEGRAL_LIMIT;
        if (integralFBx < -INTEGRAL_LIMIT) integralFBx = -INTEGRAL_LIMIT;
        if (integralFBy > INTEGRAL_LIMIT) integralFBy = INTEGRAL_LIMIT;
        if (integralFBy < -INTEGRAL_LIMIT) integralFBy = -INTEGRAL_LIMIT;
        if (integralFBz > INTEGRAL_LIMIT) integralFBz = INTEGRAL_LIMIT;
        if (integralFBz < -INTEGRAL_LIMIT) integralFBz = -INTEGRAL_LIMIT;

        /* 5. 应用比例和积分反馈到陀螺仪数据 */
        gx += dynamic_KP * ex + integralFBx;
        gy += dynamic_KP * ey + integralFBy;
    }

    /* Mahony互补滤波算法核心 ================================ */

    /* 使用修正后的陀螺仪数据进行四元数积分更新 */
    attitude.q0 += (-q1*gx - q2*gy - q3*gz) * 0.5f * dt;
    attitude.q1 += ( q0*gx - q3*gy + q2*gz) * 0.5f * dt;
    attitude.q2 += ( q3*gx + q0*gy - q1*gz) * 0.5f * dt;
    attitude.q3 += (-q2*gx + q1*gy + q0*gz) * 0.5f * dt;

    /* 四元数归一化 */
    float norm = sqrtf(attitude.q0*attitude.q0 + attitude.q1*attitude.q1 +
                      attitude.q2*attitude.q2 + attitude.q3*attitude.q3);
    if(norm > 0.0f)
    {
        norm = 1.0f / norm;
        attitude.q0 *= norm;
        attitude.q1 *= norm;
        attitude.q2 *= norm;
        attitude.q3 *= norm;
    }
    /* 转换为欧拉角 */
    attitude.roll = atan2f(2*(attitude.q0*attitude.q1 + attitude.q2*attitude.q3),
                          1 - 2*(attitude.q1*attitude.q1 + attitude.q2*attitude.q2)) * RAD_TO_DEG;
    attitude.pitch = asinf(2*(attitude.q0*attitude.q2 - attitude.q3*attitude.q1)) * RAD_TO_DEG;
attitude.yaw = -atan2f(2*(attitude.q0*attitude.q3 + attitude.q1*attitude.q2),
                          1 - 2*(attitude.q2*attitude.q2 + attitude.q3*attitude.q3)) * RAD_TO_DEG;
}
