摘 要
本文以第二十一届全国大学生智能汽车竞赛轮腿穿越组为背景，设计了基于英飞凌TRAVEO系列CYT4BB7芯片的轮腿车模系统。系统采用高精度差分GPS、IMU六轴姿态传感器、视觉传感器及关节电机编码器获取赛道与车身状态信息，通过多传感器融合算法与自主路径规划，实现行进绕桩、定点排雷及复杂路段穿越等多科目任务。在姿态控制方面，利用IMU实时解算车身姿态，结合关节电机力矩控制与PID算法，实现轮腿系统的动态平衡与速度闭环控制。为提高越障能力与行驶稳定性，系统集成了无线调试模块、TFT显示屏及人机交互按键，支持运行数据实时监测与控制参数在线调整。整个系统涵盖轮腿机械结构优化、硬件电路设计、FOC驱动、运动学解算及系统联调等关键技术环节，经实际车模测试验证了方案的可行性。

关键词：轮腿穿越；CYT4BB7芯片；姿态控制；路径规划

引 言
全国大学生智能汽车竞赛创办于2006年，是教育部倡导的全国大学生学科竞赛之一，其宗旨是培养大学生的工程实践能力、创新能力和团队合作意识。竞赛内容以设计和制造智能车辆为核心，学生需使用微控制器作为核心控制模块，结合传感器、驱动电路以及算法，完成车辆自主运行在未知复杂赛道上的任务。竞赛包含多个技术组别，如光电组、电磁组、摄像头组、轮腿组及创意组等。参赛选手需要运用电子技术、计算机编程、控制理论和机械结构设计等多学科知识，开发具有高灵活性和可靠性的智能车辆。毛群等[1]指出，智能车竞赛作为实践教学的重要载体，有效推动了电子技术课程的改革与创新；姚光顺等[2]进一步探索了竞赛与计算机硬件类课程的赛教融合模式，验证了以赛促学的教学效果。
全国大学生智能汽车竞赛过程包括理论设计、实际制作、整车调试、现场比赛等环节，要求学生组成团队，协同工作，初步体会一个工程性的研究开发项目从设计到实现的全过程。竞赛融科学性、趣味性和观赏性为一体，是以迅猛发展、前景广阔的汽车电子为背景，涵盖自动控制、模式识别、电子、电气、计算机、机械与汽车等多学科专业的创意性比赛。本竞赛规则透明，评价标准客观，坚持公开、公平、公正的原则，保证竞赛向健康、普及、持续的方向发展。
本届竞赛轮腿穿越组的赛题对车模的越障能力和自主导航提出了较高要求。赛道包含三个科目：科目一为锥桶绕桩与掉头，科目二为多点旋转与掉头，科目三为单边桥、颠簸路段、台阶、斜坡、草坪及掉头等复杂地形组合。针对上述赛题，本团队选用博思电子V型轮腿车模作为基础平台，以英飞凌CYT4BB双核ARMCortex-M7微控制器作为主控芯片，250MHz主频为高频实时控制提供充足算力。在传感器选型上，本车模搭载IMU660RC六轴陀螺仪实时解算车体姿态，TAU1201GNSS模块获取经纬度定位信息，电机内置磁编码器反馈车轮实时转速，配合MT9V03X灰度摄像头预留视觉检测接口。在控制算法上，采用一阶互补滤波算法融合陀螺仪与加速度计数据，构建三级PID串级控制架构（角速度环、角度环、速度环）实现轮腿系统的动态直立平衡与精确转向控制。在导航策略上，系统支持GPS经纬度循迹、INS 惯导航向序列导航及EKF扩展卡尔曼滤波组合导航三种模式，分别适配不同科目对定位精度和环境适应性的差异化需求。在电路设计上，整车采用主控板、无刷驱动板、舵机电源板及磁编码器板的四板分立架构，各模块独立供电，通过接口互联，兼顾调试便利性与系统可靠性。
在制作过程中，团队首先分析了轮腿车模的机械结构，合理布局电池、电路板和传感器安装位置，使整车重心尽量集中在轮轴正上方 ，降低平衡控制难度。随后完成四块电路板的原理图设计、PCB布局与焊接调试，对电源纹波、信号完整性和驱动效率进行了测试。在软件方面，基于IAREWARM平台编写嵌入式控制程序，在TFT180屏幕上搭建两级菜单系统支持现场快速调参，并通过VOFA+上位机实时遥测关键控制变量。经反复场地测试与参数迭代，车模最终在三个科目中稳定完成全部任务。
在文献调研方面，团队参考了多方面的研究成果。针对轮腿机器人的平衡控制，刘佳明等[3]在基于GPS/ICM路径规划的智能循迹小车研究中，验证了GPS与惯性测量单元组合导航在室外移动机器人中的可行性。在PID控制算法方面，位置式PID与增量式PID的组合应用在嵌入式实时控制系统中已得到广泛验证[4]。在传感器融合方面，扩展卡尔曼滤波（EKF）在GPS/INS松耦合组合导航中的应用已被大量文献证明能有效提升复杂环境下的定位精度和抗干扰能力。针对轮腿车模的特殊运动学特性，团队在现有研究的基础上，结合一阶互补滤波实现了姿态角的快速解算，并通过三级PID级联结构将平衡控制、速度控制和转向控制解耦为独立回路，降低了参数整定的复杂度。在导航层面，三分支架构（GPS/INS/EKF）参考了多传感器冗余融合思想，通过多模式互为备份提升了系统鲁棒性。此外，团队还参考了英飞凌TRAVEO™ T2G系列芯片的技术手册[5]及逐飞科技各传感器的数据手册，为软硬件设计提供了底层依据。
本文将对智能车总体设计和各部分详细设计进行一一介绍。引言部分概述了智能汽车的制作情况进行及对相关联的文献进行综述,并阐明技术报告内容框架安排；第二章阐述了轮腿车模系统总体设计方案，包括软件系统框架和硬件电路设计概述；第三章介绍了轮腿车模的机械结构设计，涵盖底盘布局、各模块安装固定方式及重心优化策略；第四章对硬件电路设计进行了详细说明，包括各电路模块电路原理与器件选型；第五章描述了软件系统设计及核心算法分析，包括三级PID级联控制、三种导航模式、速度决策与动态参数调整；第六章介绍了软件调试工具与人机交互界面；最后一章列写了车模的主要参数，并对本报告进行了总结。


第二章 系统总体方案设计
2.1系统总体设计框架
轮腿穿越组智能车硬件系统主要由电源系统、检测系统、控制决策系统和动力系统四部分组成。其中电源系统，使用电池供电给主板，主板再通过降压模块提供合适的电压给外设。检测系统由GPS和总钻风摄像头构成，通过检测系统获取赛道信息，将赛道信息发送给单片机。同时，磁编码器和IMU660RC六轴加速度计陀螺仪构成的反馈通道将车体的行驶速度信息传送给主控单片机。控制决策系统以CYT4BB7作为主控芯片，根据所取得的赛道信息和车体当前的速度信息，由主控单片机做出决策，并通过PWM信号控制无刷电机进行相应动作。动力系统主要用于控制BDS3620无刷电机的转速，根据接收到的PWM信号实现车体的转向控制和速度控制。轮腿车系统设计框图如图2.1所示。

2.2 硬件电路设计概述
智能车的硬件电路主要包括CYT4BB7双核主控芯片及其外围电路、电源模块、IMU姿态传感器模块、GPS信号采集模块、摄像头模块、编码器模块、屏幕模块、电机驱动模块、遥控接收模块及辅助调试模块等。
（1）CYT4BB7主控芯片及其外围电路是系统的核心部分。CYT4BB7为Infineon（英飞凌）公司推出的双核ARMCortex-M7微控制器，主频250MHz，内部集成两个CM7内核。使用CM7_0作为主控核，负责传感器数据采集、PID级联控制、GPS/INS/EKF导航算法、TFT菜单交互及VOFA+遥测输出。CYT4BB7外设资源丰富，集成多路UART、SPI、GPIO、PIT定时器、DMA及Flash控制器，满足本系统对多传感器通信和高频实时控制的需求。
（2）电源模块对系统的各个模块分级供电，保障整个系统稳定运行。电池电压经降压模块分别提供5V和3.3V，其中5V供给电机驱动和无线串口，3.3V供给主控芯片和传感器外设。
（3）IMU姿态传感器模块采用逐飞科技IMU660RC六轴惯性测量单元，通过SPI接口与主控通信，运行于480Hz四元数输出模式。该模块集成三轴陀螺仪和三轴加速度计，作为轮腿平衡车姿态控制的核心传感器，实时输出俯仰角、横滚角和航向角的角速度及加速度数据，供一阶互补滤波算法解算车体姿态。
（4）GPS信号采集模块采用TAU1201 GNSS模块，通过UART串口输出NMEA-0183标准协议数据。主控解析GGA和RMC语句获取经纬度、卫星颗数、定位质量等信息，用于GPS导航模式下的路径点采集和方位角/距离计算。GPS天线安装于车体顶部以减少遮挡干扰。
（5）编码器模块集成于电机内部，通过电机驱动板的UART通信将左右轮的实时速度数据反馈至主控。主控以20ms为周期读取编码器速度值，经低通滤波后作为速度环PID的实际速度输入，实现闭环速度控制。
（6）屏幕模块采用TFT180彩色液晶屏，通过SPI接口驱动。该屏幕作为人机交互的核心输出设备，用于显示两级菜单系统（10个主菜单及对应子菜单）、GPS经纬度与卫星状态、IMU姿态角、PID参数、行驶距离与时间、科目速度设定、FLASH存储状态等运行信息，同时支持GPS路径点的地图化轨迹绘制。
（7）电机驱动模块基于三相全桥逆变电路拓扑结构，由6个功率MOS管构成。系统通过控制MOS管的导通时序来改变三相绕组的换相逻辑，从而实现电机的正反转控制；通过PWM调节施加在电机两端的有效电压，实现对电机转速的控制。
（8）舵机电源与信号接口采用4路独立Buck降压电路，通过独立通道设计物理隔离各路负载，杜绝了舵机堵转引起的电压跌落与系统干扰。电路集成大容量储能电容与软启动网络，并具备防反接与一键断电保护功能，确保了复杂工况下供电系统的稳定性与安全性。
（9）辅助调试模块主要由贴片按键、TFT液晶显示屏、蜂鸣器及拨动开关等核心元器件构成，旨在为系统的参数配置与状态监测提供便捷的人机交互接口。


第三章 机械结构设计
第二十一届全国大学生智能汽车竞赛轮腿穿越组采用博思电子数码科技有限公司的V型平衡轮腿车模。车长189mm，宽177mm，最高处192mm，轮腿关键结构件采用开模注塑一体化成型，一致性强、精度高、强度足；车模底盘采用高强度碳纤板；整车零件连接均使用轴承连接，共18个轴承保障车模运行、运动更加顺畅、灵活，结构更加稳定，使用寿命更长。相比较于自制车模，V车模的工艺体系更加完善且省去机械结构设计的时间，将更多精力放在软件调试上。
3.1 轮腿车模结构
重心的位置是轮腿平衡车设计中至关重要的因素，直接影响车辆的平衡性能和运行稳定性。当重心过于偏前时，车辆在通过科目三坡道腾空时容易向前倾倒，难以在落地后恢复平衡姿态。反之，若重心过于靠后，加速时车身会后仰过度，提升平衡环的纠正负担，甚至造成翘头失控。此外，重心位置的变化还会影响车辆在单边桥抬腿、颠簸路段及斜坡等科目任务中的表现。因此，在进行轮腿车结构设计时，必须合理布局电池、电路板、GPS模块和IMU等器件的安装位置，使整车重心尽量集中在轮轴正上方且高度适当。通过精确的重心调整，能够在保持自平衡稳定性的前提下优化车辆的动态响应性能，确保在不同行驶工况下都能维持稳定的运行状态。轮腿车的结构如图3.1所示。

3.2 电机驱动板的安装
本设计采用无刷电机驱动器，通过UART串口与主控通信，接收转速及转向指令驱动两个无刷电机。无刷驱动板安装于车体尾部，与主控板分离布置，避免驱动模块的大电流和高频开关噪声干扰主控电路及传感器信号。驱动板与主控板之间通过杜邦线连接信号线和供电线，信号线沿底盘一侧走线并用扎带固定，电机三相输出线就近连接至左右无刷电机端子。驱动板供电由主板上的电源模块独立引出，以减少电机瞬时大电流对主控供电的冲击。无刷驱动板的安装位置如图3.2所示。

3.3 电路板及电池的安装与固定
轮腿车的电路板与电池安装布局直接决定整车的重心分布、空间利用率及运行可靠性，是整车结构设计的关键环节。通过合理设计电路板和电池的安装位置，确保车辆的重心分布合理，从而实现稳定的运行和操控性。电路板与电池的安装位置经合理规划，在保证装配可靠性的同时，最大程度减少对轮腿车内部空间的占用，为轮腿机械结构留出充足的运动裕量。采用合适的固定机构，保护电路板和电池免受外界环境的干扰和损害。电路板安装在轮腿车中后部，以优化重心位置、保证行驶稳定性。同时对电路板涂上三防漆做好防水措施。采用轻质高强度的碳纤维板作为底板支撑结构，既可有效承托电路板，又不增加过多附加重量。电路板与碳纤维底板之间通过尼龙隔离柱固定，尼龙柱可阻隔振动传递，减小路面颠簸对电路的干扰。轮腿车电路板的安装如图3.3所示。

3.4 姿态传感器的固定
陀螺仪作为整车平衡控制的核心传感器，其安装位置的选取直接影响系统的控制性能。为确保传感器能够精确反映车体俯仰角、翻滚角和偏航角的变化，同时避免因固定不牢导致的姿态解算误差，团队在安装方案上进行了多方面考量。理想的安装位置需要满足两个关键要求：一是能够灵敏、准确地捕捉车体姿态变化，二是具备良好的机械稳定性以抑制振动干扰。经过反复测试验证，最终将陀螺仪安装在舵机电源板的后方，该位置既靠近车体质心，能够真实反映整车运动状态。姿态传感器的固定如图3.5所示。

3.6 GPS天线的固定
GPS天线受遮挡物和电磁干扰影响较大，安装时需综合考虑信号接收与结构稳定性两个因素。本设计将GPS模块安装于主板的另一端——即核心板安装位置的对侧，位于车体稍靠后位置。由于主板上其他元器件会对GPS信号产生遮挡，需对模块进行架高处理，使其高于周边器件，以减少电路板本身的信号遮挡；然而架高结构在车体行驶过程中易因晃动导致信号不稳。因此，本设计采用3D打印底座作为GPS的支撑结构，将GPS模块粘合固定于底座上方，再通过铜柱将底座与主板连接，形成稳固的架高结构，既保证了GPS天线足够的信号接收高度，又大幅提升了行驶中抗晃动的结构稳定性。GPS模块通过排针与主板连接，供电和串口信号线就近引出。GPS天线的固定如图3.7所示。

第四章 硬件系统设计及实现
4.1 硬件方案设计
硬件是智能车平稳运行的基础，只有一个良好、稳定的硬件环境才能保证车模在赛道上平稳快速地行驶。本系统硬件设计本着“可靠、高效、简洁”的原则，在满足各功能需求的前提下，尽量减少元器件数量，缩小电路板面积，降低车模重心。
本系统硬件电路按功能分为四个模块：主控板、舵机电源板、无刷驱动模块和磁编码器板。各模块分立设计，独立供电，通过接口互联，便于调试与维护。整车硬件系统采用模块化设计架构。主控板以CYT4BB7最小系统板为核心，负责传感器数据采集、赛道识别、平衡控制算法及指令输出；舵机电源板采用SCT2450 DC-DC降压芯片为舵机提供独立供电；无刷驱动模块以CYT2BL3为驱动主控，配合JSM6288Q1预驱芯片和TPN2R703NL MOSFET实现双路三相无刷电机FOC驱动；磁编码器板采用TLE5012B磁角度传感器，为FOC算法提供高精度转子位置反馈。

第五章 软件系统设计及实现
稳健的软件程序是智能车高速平稳完成各科目任务的基础。本设计采用双核ARM Cortex-M7架构，以IMU660RC陀螺仪、TAU1201GPS模块及电机磁编码器作为传感器输入，通过三级PID级联控制实现轮腿平衡车的直立、转向和速度闭环，并支持GPS、INS惯导、EKF组合导航三种模式适配不同科目要求。
5.1 软件系统设计
轮腿车系统启动后首先进行系统初始化，配置时钟与外设（GPIO、UART、I2C、编码器、IMU、TFT屏等），调用Pid_Init()设置角速度环、角度环、速度环的级联PID参数，随后进入while(true)主循环。系统通过PIT定时器触发三级周期任务：1ms中断触发角速度内环，利用陀螺仪获取当前角速度，经PID计算后输出up_duty_out与diversion_duty_out驱动电机；同时检测翻滚角超过70°时触发急停保护。5ms中断触发角度中环，分别对俯仰角（pitch_angle_out）、翻滚角（roll_angle_out）、偏航角（yaw_angle_out）进行PID计算，其输出作为角速度环的期望值送入1ms内环。20ms中断触发速度外环，通过磁编码器读取实际车速经低通滤波后，结合GPS或INS速度决策与动态调节，将输出作为角度环的期望输入，构成速度→角度→角速度的三级级联闭环。同时，系统通过菜单交互处理进行参数配置：按键1切换页面（0~6），不同页面下按键2/3分别设置启动标志、调整目标速度、切换IMU使能、设定路径点参数等，并实时在TFT屏显示当前状态。主循环中持续解析GPS数据，根据run_flag状态机调度导航模式（Mode1 GPS跟随/Mode2 INS导航/Mode3 EKF导航），走完最后一个路径点后执行停车操作，整个流程结束。轮腿车软件程序流程如图5.1所示。

5.2 陀螺仪算法
本设计采用IMU660RC陀螺仪，初始化时配置为四元数模式（IMU660RC_QUATERNION_480HZ）。四元数是由1个实部和3个虚部组成的数学量（形式：q=q0+q1i+q2j+q3k），在陀螺仪中主要用于姿态解算——将陀螺仪输出的角速度积分得到旋转角度，最终表示载体的三维姿态（俯仰角、横滚角、航向角）。IMU660RC硬件内部以480Hz频率完成四元数融合运算，直接输出yaw、pitch、roll三个欧拉角，供平衡控制中pitch/roll的PID级联使用。低通滤波是一种信号处理方法，其核心是保留低频信号（有用信号）、衰减高频信号（噪声）。陀螺仪输出的航向角信号中，高频噪声（如机械振动、电路干扰）会影响导航精度，低通滤波可平滑数据。本设计对航向角采用一阶EMA低通滤波，并通过±180°unwrap处理角度跳变，平滑后的航向角供INS/EKF导航的转向控制使用。陀螺仪算法流程如图5.2所示。

5.3 导航算法
系统支持三种导航模式，通过全局变量Mode切换：
（1）Mode 1—GPS经纬度导航。采点阶段赛道手动踩点，通过按键触发踩点，将GPS经纬度以“整数部分+小数部分”拆分后存入Flash。导航阶段实时计算当前位置到目标路径点的距离和方位角，方位角与IMU航向角做差得到转向误差量，送入角度环控制转向。当距离小于切点阈值时自动切换到下一路径点，三个科目各有独立的阈值设置，科目一锥桶段使用0.7m、普通段使用1.7m，科目二到达路径点后触发720°原地旋转。
（2）Mode 2—INS惯导航向序列导航。不依赖GPS信号，而是记录车体在每个路径点的航向角序列。采点阶段以0.1m里程间隔自动触发，将经EMA低通滤波后的航向角依次存入航向数组。导航阶段根据累计行驶里程在相邻航向点之间进行三点二次插值，得到当前期望航向角，插值前对所有点做±180°解缠绕处理以防止角度边界穿越。该模式不受卫星信号质量影响，特别适用于科目二的多点旋转和科目三的复杂地形。当里程累加达到0.1m时路径点索引递增，超出采集点总数后自动切换为停车状态。
（3）Mode 3—EKF组合导航。采用3状态松耦合架构，状态向量为, 其中，为平面坐标，为航向角。预测步骤以约200Hz频率利用里程计距离和陀螺仪航向变化进行状态外推，更新步骤以约10Hz频率在GPS有效时通过卡尔曼增益修正状态。导航启动时将经纬度序列转换为以当前GPS位置为原点的平面坐标并初始化EKF状态，跟车算法综合航向误差和横向偏差合成转向控制量，使车辆既保持正确航向又紧贴路径行驶。
5.4 速度决策与动态参数调整
（1）速度决策。系统根据不同科目和当前路径段自动调整目标速度，GPS模式按路径点索引、INS/EKF模式按里程索引与预配置的特殊路段进行比较，匹配到特殊路段时切换到对应限速值（如科目三的单边桥限速60、台阶限速100）。速度采用斜坡式渐变（每周期±20~100），避免阶跃变化导致车体失衡。
（2）动态PID参数调整。进入单边桥路段时自动切换到专用PID参数组（pitch_kp=1.409、yaw_kp=9.601、roll_kp=0.050），离开后从备份中恢复默认值。这种双参数组机制使车体在普通路段和特殊路段均能保持最优控制效果。

5.5 控制算法
PID控制主要是对系统偏差进行比例、积分、微分三种操作并线性组合成控制量，以减小系统误差，提高系统响应速度和响应效果。经典PID控制又分为位置式PID和增量式PID[5]。PID控制系统框图如图5.3所示。


图5.3 PID控制系统框图

（1）位置式PID
位置式算法直接计算控制量的绝对值（如PWM占空比），输出可直接作用到电机上，无需累加历史值，仅依赖当前偏差和上一次偏差（微分项），计算量小，适合对实时性要求高的场景。本系统中1ms触发的角速度环和5ms触发的角度环（pitch/yaw）均采用位置式PID，能快速响应偏差变化。其中角速度环和角度环未引入积分项（Ki=0），即位置式PD控制，可避免积分项累积导致的控制量饱和问题，在角度、角速度等短时间动态调节场景中稳定性更优。

（2）增量式PID
增量式PID的输出是控制量的变化量而非绝对值，需要与上一次的控制量累加后才作为最终输出。本系统中翻滚角（roll）的角度环采用增量式PID（5ms周期），通过限制单次增量的最大值，可有效避免控制量的突然大幅变化，减少单边桥抬腿瞬间的电机冲击，提高系统稳定性。并且增量式包含积分项，通过累计当前偏差的积分作用，可逐步消除系统静差。进入单边桥区间时，增量式PID的历史数据被手动清零，使控制从零状态开始，防止前一阶段的积分累积影响抬腿响应。相比位置式PD，增量式PID更适合需要平滑过渡的翻滚控制场景。
（3）速度控制闭环
本设计引入了速度控制闭环（速度环），其主要目标是使车辆的实际行驶速度与期望速度相匹配，恒速稳定行驶。由于系统中采用两个独立电机驱动后轮，因此还需要考虑过弯时的差速问题。系统中的速度环程序给定的期望速度直接等于实际运行的期望速度，并根据不同科目和路径段进行动态调整。由于电机的闭环控制属于大惯性系统控制，且系统的主要任务是循迹，因此速度环对控制质量的要求不是特别高。本设计采用位置式PID算法进行控制，每20ms执行一次。车体速度通过左右电机编码器速度的均值经一阶低通滤波获得（滤波系数0.7/0.3），行驶距离按速度与周期时间累积计算。由于轮腿车使用电池供电，速度环的控制应相对平稳，因此需要对参数进行适当调整。开环与闭环对比流程如图5.4所示。

7.2 结论
本次轮腿穿越组智能车的设计与制作，经历了从机械结构分析、硬件电路设计、软件算法开发到整车联调的完整工程流程。在机械层面，团队基于博思电子V型轮腿车模，合理布局电池、电路板及各传感器模块，使整车重心集中在轮轴正上方，降低了平衡控制的难度；在硬件层面，完成了主控板、无刷驱动板、舵机电源板及磁编码器板四块电路板的分立设计，各模块独立供电，兼顾了调试便利性与系统可靠性；在软件层面，基于IAREWARM开发平台编写了完整的嵌入式控制程序，实现了三级PID级联平衡控制、GPS/INS/EKF三种导航模式、按路段动态速度决策与参数调整等核心功能。经实测，车模搭载IMU660RC六轴陀螺仪（480Hz姿态更新）、TAU1201GNSS模块、双磁编码器及MT9V03X灰度摄像头，控制周期1ms，姿态解算周期5ms，速度闭环周期20ms，能够在三个科目的复杂地形中稳定完成锥桶绕桩、多点旋转、单边桥、颠簸路段、斜坡等多个任务，达到了预期的技术指标。
在设计与调试过程中，团队遇到并重点解决了以下关键问题。
第一，GPS定位精度不足与信号漂移问题。GPS模块在室外环境下存在多点漂移和单点定位精度有限的问题，导致纯GPS导航在复杂路段出现轨迹偏移。针对这一问题，团队在GPS导航模式中引入了发车时的方位角偏移对齐机制和切点距离阈值自适应策略，同时开发了不依赖卫星信号的INS惯导航向序列导航模式，以及融合GPS与IMU的EKF组合导航模式，通过多模式互为备份的方式显著提升了导航的鲁棒性和定位精度。这一实践让团队深刻认识到，在室外轮腿导航中，单一传感器难以满足复杂环境的精度需求，多传感器融合与多模式冗余是提升系统可靠性的关键手段。
第二，单边桥路段的平衡控制难题。单边桥要求车模一侧车轮抬高过桥，横滚角发生剧烈变化，常规PID参数难以兼顾普通路段和单边桥路段的控制需求。团队通过引入机械零点三档动态切换机制和单边桥专用PID参数组，并在进入单边桥区间时手动清零增量式PID的历史数据，有效避免了积分累积导致的控制震荡。这一问题的解决使团队认识到，对于轮腿平衡车这类强非线性系统，单一控制参数难以覆盖全部工况，按工况分段调参和状态重置是提升复杂地形适应性的有效方法。
第三，旋转打滑导致的里程累计误差。在科目二的多点旋转任务中，车模执行720°原地旋转时轮子打滑，导致里程计累计的距离产生较大误差，影响后续路径点的切换精度。团队通过在旋转期间清零里程、旋转完成后引入1秒冷却期并继续累加距离以捕获惯性漂移的方式，有效抑制了打滑误差的累积。这一过程使团队认识到，轮式里程计在打滑工况下的可靠性有限，需要通过状态机控制和时序设计来规避而非依赖里程计本身。
然而，本系统仍存在一些有待进一步改进的问题。首先，摄像头视觉识别模块目前仅完成硬件预留，MT9V03X的图像处理和赛道元素识别算法尚未完整实现，后续可结合台阶等元素的视觉检测进一步提升导航的精确性和鲁棒性。此外，EKF组合导航的噪声参数目前依赖人工经验整定，后续可引入自适应噪声估计方法，进一步提升不同环境下的定位性能。
纵观整个设计过程，智能车的制作不仅考验了团队的实际操作能力和问题解决能力，也让团队更深刻地理解了理论知识的工程应用。在困难和挫折面前，团队始终保持坚定信念，勇往直前。虽然相较于其他高校，团队的进展或许较为缓慢，但团队成员一直追求着稳定的质量和可靠的结果。
最后，衷心感谢智能车竞赛提供的宝贵实践机会，也感谢指导老师和学校领导的支持与鼓励，正是这些支撑着团队克服困难，取得了如今的成果。

void Task_1ms_cycle(){ // 1ms周期一次运算
    task_count++;
    Beep_sleep(); // 蜂鸣器睡眠函数
    if (rotat_flag){
        if (rotat_time == 0){ // 旋转首周期：记录起始角度
            rotat_accumulated_angle = 0;
            rotat_last_yaw = imu660rc_yaw;
        }
        rotat_time++;
        float yaw_delta = imu660rc_yaw - rotat_last_yaw;
        if (yaw_delta > 180) yaw_delta -= 360;
        if (yaw_delta < -180) yaw_delta += 360;
        rotat_accumulated_angle += yaw_delta;
        rotat_last_yaw = imu660rc_yaw;
        if ((rotat_phase == 0 && rotat_accumulated_angle <= -720) ||
            (rotat_phase == 1 && rotat_accumulated_angle >= 720)){
            rotat_time = 0;
            rotat_flag = 0;
            rotat_phase = !rotat_phase; // 交替方向，下个点位反向转
            rotat_cooldown = 50; // 防止回正打滑累加距离
            next_point += 1;
        }
    }
    up_duty_out = -LocPID_Calculation(&pitch_cascade.av_cycle, pitch_angle_out, *pitch_cascade.cascade_value.gyro_raw_data); // 直立环输出
    if (rotat_flag == 0){
        if (run_flag == 1)
            diversion_duty_out = -LocPID_Calculation(&yaw_cascade.av_cycle, remote_diversion_duty, gyro_value_z);
        else
            diversion_duty_out = -LocPID_Calculation(&yaw_cascade.av_cycle, yaw_angle_out, gyro_value_z);
    }
    else{
        diversion_duty_out = -LocPID_Calculation(&yaw_cascade.av_cycle, (rotat_phase == 0) ? -(int16)rotat_speed : (int16)rotat_speed, gyro_value_z);
    }
    if (task_count % 5 == 0){
        pitch_angle_out = LocPID_Calculation(&pitch_cascade.angle_cycle, 0, pitch_cascade.cascade_value.filtering_angle); // 转向环外环的输出
        static uint8 last_single_bridge_flag = 0;
        if (last_single_bridge_flag == 0 && single_bridge_flag == 1){
            roll_cascade.angle_cycle.incremental_data[0] = 0;
            roll_cascade.angle_cycle.incremental_data[1] = 0;
            roll_cascade.angle_cycle.out = 0;
            roll_cascade.angle_cycle.i_value = 0;
        }
        last_single_bridge_flag = single_bridge_flag;
        if (Task >= 3){
            if (single_bridge_flag == 1){
                roll_angle_out = -IncPID_Calculation(&roll_cascade.angle_cycle, 0, roll_cascade.cascade_value.filtering_angle);
                pitch_cascade.cascade_value.mechanical_zero = pitch_mz_raised;
                roll_cascade.cascade_value.mechanical_zero = roll_mz_raised;
            }
            else{
                pitch_cascade.cascade_value.mechanical_zero = pitch_mz_level;
                roll_cascade.cascade_value.mechanical_zero = roll_mz_level;
            }
        }
        else{
            pitch_cascade.cascade_value.mechanical_zero = pitch_mz_lowered;
            roll_cascade.cascade_value.mechanical_zero = roll_mz_lowered;
        }
        if (Mode == 1){
            yaw_angle_out = LocPID_Calculation(&yaw_cascade.angle_cycle, Angle_error, 0);
        }
        else if (Mode == 2 || Mode == 3) {
            yaw_angle_out = LocPID_Calculation(&yaw_cascade.angle_cycle, Ins_error, 0);
        }
        if (task_count % 20 == 0) {
            if (run_flag == 0)  target_speed = 0; // 非遥控才归零
            else if (run_flag == 2){
                if (Mode == 1) Gps_speed_decision();
                    else if (Mode == 2) Ins_speed_decision();
                else if (Mode == 3) Ins_speed_decision();
                }
                Dynamic_adjustment();
            }
            static float car_speed_f = 0;
            car_speed = (motor_value.receive_left_speed_data - motor_value.receive_right_speed_data) / 2;
            car_speed_f = car_speed_f * 0.7f + (float)car_speed * 0.3f;
            car_speed = (int16)car_speed_f;
            if (rotat_flag == 0){
                if (rotat_cooldown == 0){
                    car_distance += car_speed * 0.02 * 0.00478;
                    pitch_speed_out = LocPID_Calculation(&pitch_cascade.speed_cycle, target_speed, car_speed);
                }
                else{
                    rotat_cooldown--;
                    car_distance += car_speed * 0.02 * 0.00478;
                    pitch_speed_out = LocPID_Calculation(&pitch_cascade.speed_cycle, 0, car_speed);
                }
            }
            else{
                pitch_speed_out = LocPID_Calculation(&pitch_cascade.speed_cycle, 0, car_speed);
            }
        }
    }
    Motor_control();
    Steer_control();
}
