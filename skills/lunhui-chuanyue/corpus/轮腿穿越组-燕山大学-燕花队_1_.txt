概述
本队伍参加第二十一届全国大学生智能汽车竞赛轮腿穿越组比赛。车模采用逐飞科技轮腿 V 车模平台，主控芯片为 Infineon CYT4BB（Cortex-M7 双核，主频 250 MHz）。
该车模为两轮动态平衡腿式结构，比赛任务为：在包含普通路面与颠簸路段、单边桥、台阶跳跃、固定速度直行、720° 转圈等特殊元素的赛道上完成自主循迹行驶。车模需要在无外部辅助的条件下完成自立平衡，并依靠惯性导航与摄像头视觉相结合的方式完成路线跟踪与特殊路段动作。
针对上述任务，本队以双核 MCU 为主控，将实时控制与图像处理分核并行执行；采用姿态融合与串级 PID 控制实现动态平衡；采用惯性导航与视觉感知相结合的方案完成路线跟踪与特殊路段自主通过。

总体技术方案
设计目标
根据竞赛规则，本车模需完成以下任务目标：
上电自检后自主起立并保持动态平衡，静止与行驶状态下均不倾倒；
按照比赛前记录的路线完成自主导航行驶，普通路段具备一定的巡航速度与跟踪精度；
自动识别并依次通过颠簸路段、单边桥、台阶跳跃、固定速度直行等特殊路段，并在指定位置完成 720° 转圈动作；
具备遥控接管、参数在线调整与路线数据掉电保存能力，满足比赛现场快速调试需求。
系统总体框图
系统由传感、控制、执行、人机交互四部分构成：
传感部分：六轴 IMU（含磁力计）、单色灰度摄像头、GNSS 定位模块、TOF 激光测距模块；
控制部分：CYT4BB 双核 MCU，主控核完成姿态解算与运动控制，视觉核完成图像处理；
执行部分：2 路无刷电机（驱动轮）、4 路舵机（腿部关节）；
人机交互：TFT 显示屏、五按键、无线串口、六通道遥控器。

关键技术方案
传感器选型：姿态检测选用六轴 IMU，满足姿态解算的带宽与噪声要求；路线感知以惯性导航为主、摄像头视觉为辅，GNSS 与 TOF 模块提供辅助信息；各传感器安装位置兼顾重心集中与视野需求（详见第三章）。
控制算法：平衡控制采用串级 PID 结构，叠加速度环产生俯仰补偿；转向采用航向反馈控制；特殊路段采用状态机统一管理，各路段控制策略见第五章。
双核方案：图像处理运算量较大且与实时控制无强耦合，故将其分配至视觉核并行执行，通过共享内存交换结果，保证主控核控制周期的稳定。
电源方案：整车采用 3S 锂电池供电（11.4~12.6 V）。电池输入主板后经 680 μF 电容滤波，并由开关分三路：一路经 TPS54302 BUCK 降压至 5 V、再经 RT9013 LDO 降至 3.3 V，供主控与大部分外设使用；一路经 SCT2450 BUCK 降压至约 7 V 供舵机使用；一路经 XT30 端子供给电机驱动板，驱动板再经 RY9121 BUCK 与 RT9013 LDO 产生 5 V / 3.3 V 为驱动控制电路供电。
机械结构设计与安装
车模整体组成与安装
舵机、电机采用逐飞科技轮腿V 车模方案，左右分别使用大、小腿将舵机与电机相连，电机处用单独连接件连接轮胎；舵机用前后两个L型结构统一固定在底部碳板上，组成下部分车模主体。为室外调车未避免阳光直射后加剧发热，对于一些结构进行上漆或选白色耗材打印，制成白色。

碳板底部用是3D打印件的电池仓，用于3S电池的固定，顶部放置舵机后有孔位连接一个3D打印的白色连接结构件。连接件上预留了足够的孔洞方便各类线穿过与PCB电路板的固定。
电路板分为前后两片，前端为电路主板，后端为电机驱动板。主板上则设计好了孔位固定碳杆，进而完成摄像头与GPS的固定。轮胎直径9cm的L车模轮胎，同时K-704NB硅密封胶封胎增加轮腿弹性。
从控制角度对机械结构提出的要求：整车重心高度与腿部姿态直接决定平衡控制的俯仰裕度，机械装配时需保证左右腿对称性，避免横滚静偏差。
传感器安装
本方案主要使用的模块包括：陀螺仪、摄像头、TOF测距、TFT屏幕、GPS定位。
摄像头安装于固定在主板的碳杆高处，以提供位于中心且无遮挡的视角。
陀螺仪安装于小车中心位置，实际位于主板背面中心，同时主板挖槽用铜柱固定防止抖动等位移产生读数偏移。
TOF测距安装于电池壳正面，置于较低位置方便扫描正面障碍距离。
TFT屏幕安装于主板右侧上方无遮挡方便使用。
GPS安装于屏幕上方，外套白色打印件；天线则固定于碳杆中段。
电路板固定与连接
电路板上挖槽区域预留了固定孔，可穿过铜柱，主板与驱动板皆设计了4个固定孔。电路板固定于3D打印的连接板上，连接板再通过铜柱与车主体相固定。两板在同一平面，底部通过打印件连接的简单结构连接的方式，避免了传统轮腿车模上端主板，主板地面堆叠舵机板的方案，有效降低了车模重心。主板中央挖槽区域，通过法兰盘结构将碳杆与主板固定在一起，以提供安装GPS和摄像头的位置。
电路设计
4.1 电源电路
主板电路：主板输入设计使用3S电池，提供11.4～12.6V电压。12V流入后经过680uF的滤波电容在主板通过开关分成三路，第一路是先使用TPS54302的BUCK电路降压至5V，再通过RT9013的LDO电路降压至3V3；第二路是使用SCT2450的BUVK电路降压至7V左右供给舵机使用；第三路是通过XT30端子供给电机驱动板使用。
FOC无刷驱动：驱动板通过 XT30 从主板取 VBAT（11.4~12.6V），输入两颗 470μF 电解电容 + 100nF 陶瓷电容滤波。RY9121 同步降压至 5V再经 RT9013的LDO 降 3.3V 给CYT2芯片。
4.2 电机驱动电路
两片 FD6288T 三相栅极驱动器 + N-MOS 三相全桥，两路独立控制左右电机。每路 6 路 PWM（3 上 + 3 下），共 12 路，每相 4.7μF 自举电容 + 快恢复二极管，栅极串 10Ω 电阻。MOS 体二极管续流，MR30 接口输出，PCB 左右对称布局。
主控板通过高速串口以数字指令方式向驱动板下发左右电机目标占空比，并接收左右电机速度反馈，驱动板内部完成换相与保护，速度反馈同时用于速度控制与车模里程计算。
4.3 传感器接口电路
主板上使用的MCU为组委会允许的CYT4主控核心板，直接使用排母连接至主板。
传感器接口均设计于主板上，TOF激光测距模块使用1*6PIN的XH座用线连接，固定于电车仓前端防止车模运动时脱落 ，其余模块均使用排母连接。TOF与陀螺仪接口设计在主板背面，其余传感器接口均位于主板正面。陀螺仪为保证稳定性，在主板设计了铜柱孔固定。
系统串口资源分配如下：串口 0 为调试串口；串口 1 为无线串口；串口 2 接 GNSS 模块；串口 4 接电机驱动板。摄像头经数字接口传输图像数据；TOF 模块经 I2C 接口连接；遥控器接收机信号经 GPIO 中断捕获。

4.4 电路板设计要点
主板设计时将舵机板与主控板合二为一，采用紧凑布局以降低车模重心并腾出安装空间。元件布局遵循 "同电源聚集、近信号引脚" 原则：3.3V 供电的陀螺仪、TOF、无线串口等模块集中于核心板上侧与右侧，5V 供电的摄像头、GPS、屏幕等集中于下侧，同时各模块尽量靠近 CYT4 核心板对应引脚，缩短信号线以减少串扰。供电走线上，3.3V 采用 "上行 — 右绕 — 环供" 的半环形布线，5V 则下行集中供电，避免不同电源轨交叉。
本板为四层设计，自上而下为顶层、电源层、GND 层、底层。独立电源层大幅提升了过流能力，解决了以往调试中因走线铜厚不足、电源转电机驱动路径大电流而烧板的问题；完整 GND 平面也为信号提供低阻抗回流路径。抗干扰方面，板上多处 Buck 电路的功率电感下方均设禁止铺铜区，避免交变磁场感应涡流干扰邻近传感器，关键去耦电容紧贴芯片引脚放置。
软件算法设计
软件总体架构
软件系统基于 IAR Embedded Workbench 开发环境与逐飞科技开源库开发。主控核负责传感器数据读取、姿态解算、平衡与转向控制、导航决策等实时任务；视觉核负责摄像头图像采集与处理。两核通过共享内存交换数据，主控核周期性读取视觉处理结果用于控制决策，避免了大量数据通信对实时控制的影响。
任务调度采用定时器中断与主循环结合的方式：姿态解算、电机控制等高实时性任务在定时中断中以固定周期执行；屏幕显示、参数存储、测距等耗时操作在主循环中执行，保证控制周期的稳定。
程序按功能划分为姿态与平衡控制、转向与速度控制、导航决策、图像处理、电机通信、遥控器处理、菜单显示与数据存储等模块，各模块之间接口清晰，便于分别调试与参数整定。
系统支持路线记录与自主运行两种工作模式：比赛前完成路线信息记录并保存，运行时依据传感器信息自主完成路线跟踪与特殊路段通过。具体工作流程与实现细节此处不再展开。
传感器数据处理
IMU 数据在使用前进行预处理：上电静止阶段自动采样校准陀螺仪零偏；运行过程中对加速度数据进行滤波，抑制噪声与振动干扰，并根据车模运动状态调整处理策略。
姿态解算采用基于四元数的姿态融合算法，综合陀螺仪与加速度计信息得到车模姿态角，供平衡控制与导航使用。算法中的滤波与校正参数在调试中反复整定。
遥控器信号通过定时器捕获方式测量各通道脉宽，经滤波处理后用于速度调节、方向修正与安全接管等操作。
赛道识别算法
摄像头图像经二值化等预处理后提取赛道边线与中线，作为视觉路段的转向依据。二值化阈值可根据光照条件自适应调整，并配合自动曝光，保证不同环境下的图像质量。
普通路段的车模位置由惯导推算获得，即根据电机速度反馈与 IMU 航向信息对车模位置进行积分解算，用于路径跟踪与里程判断。
特殊路段的识别与定位结合了摄像头、TOF 测距等多种传感器的信息，并辅以一定的路段先验信息进行综合判断。具体检测方法与触发条件经现场调试确定，此处从略。
运动控制算法
平衡控制采用串级 PID 结构，内环为角速度环、外环为姿态角环，并叠加速度环产生俯仰补偿。各控制环均采取限幅与抗积分饱和处理，参数按照先内环、后外环、再速度环的顺序整定。
速度控制根据目标速度与实际速度的偏差调整车身姿态补偿量，使车模在加减速过程中通过重心变化保持平衡。
转向控制根据目标航向与实际航向的偏差生成差速输出，并叠加角速度阻尼项抑制转向超调与振荡；视觉路段与惯导路段采用各自的转向计算方式。
特殊路段采用有限状态机统一管理：进入特殊路段后，按路段类型切换相应的速度策略、舵机姿态与转向控制方式，满足退出条件后恢复常规控制。各路段的具体控制策略、动作时序与参数经大量实验调试确定，属于本队调试成果，此处不再详述。
核心代码设计
与电机驱动板采用固定格式数据帧通信，帧中包含帧头、数据与校验信息，校验正确方更新数据，保证通信可靠性；电机速度反馈同时用于速度控制与里程计算。
路线数据与控制参数保存于片上 Flash，两条比赛路线独立存储，路线数据与其绑定参数一同加载，避免相互影响；Flash 读写安排在主循环中执行，避免阻塞控制中断。
系统配备五按键树形菜单，支持参数在线修改、路线管理与状态显示；同时对车身姿态与运行状态进行监测，出现异常时自动切断电机输出并进入保护状态。串级 PID 控制器的示意代码见附录 B。
开发调试过程
开发工具与环境
主控芯片：Infineon CYT4BB（Cortex-M7 双核，250 MHz）；
开发环境：IAR Embedded Workbench 9.40.1；
编程语言：C 语言；
底层支持：逐飞科技开源库；
调试手段：TFT 屏显示、无线串口上位机、调试串口、六通道遥控器。
硬件开发工具主要使用：嘉立创EDA、SOLIDWORKS 2025、Bambu Studio。
制作与安装过程
装配过程：
首先需要安装好V车模的结构，固定好舵机、碳板、大小腿、电机、车轮等。
将电池壳安装上，此时未安装连接板等结构，空间大方便电池壳安装。
安装连接板，将舵机等线理清穿过连接板的预留孔位，同步用法兰结构将碳杆固定在主板上。
将GPS等碳杆上的结构安装好，之后将主板与驱动板安装在连接板上完成安装。
软件工程组织过程：先基于开源库搭建工程框架，完成串口、定时器、IMU、摄像头等外设驱动验证；随后按模块迭代开发姿态解算、平衡控制与导航等模块；每完成一个模块即通过菜单参数化并在实车上验证，最后进行整车联调。
调试方法与记录
软件调试按照“单模块验证、静态调参、低速联调、完整路线测试”的顺序进行：
模块级验证：分别确认 IMU 姿态角、TOF 距离、GNSS 数据、摄像头图像和电机速度反馈是否正常；
平衡调试：在车模静止和低速状态下调整姿态解算及平衡 PID 参数，使车模保持基本稳定；
视觉调试：调整摄像头阈值与中线提取参数，确认不同光照条件下能够得到连续有效的赛道信息；
导航调试：先完成路线记录与检查，再以较低速度运行，逐项验证路径跟踪与特殊路段通过情况；
整车测试：进行完整路线测试，对速度、预瞄参数、特殊路段持续时间和舵机姿态进行综合调整。
调试过程中通过 TFT 屏幕、无线串口和调试串口观察姿态角、速度、里程与运行状态等信息，并根据测试结果迭代参数。最终将稳定参数和路线数据保存到 Flash，形成比赛使用的软件配置。

结论
本报告介绍了本队参加第二十一届全国大学生智能汽车竞赛车模的制作方案。车模以 CYT4BB 双核微控制器为核心，机械、电路与软件协同设计，实现了两轮腿式车模的动态平衡、惯导航线行驶与特殊路段自主通过。
整车制作过程整体情况与技术特点概括如下：
采用双核分工结构，主控核负责车辆控制、视觉核负责图像处理，通过共享内存交换数据，提高了系统实时性；
采用姿态融合与串级控制结构，提高了车模运动过程中的平衡能力；
采用惯性导航与视觉感知相结合的路线跟踪方案，将普通路段和特殊路段统一组织管理；
采用状态机统一管理各类特殊动作，便于调试和参数修改；
采用菜单和 Flash 存储机制保存路线及控制参数，减少了现场重复配置工作。
存在的问题与改进方向：目前软件在复杂光照适应性、高速特殊路段控制等方面仍有优化空间；惯导航向存在随时间累积的漂移，需依赖辅助信息校正；部分特殊路段触发条件对环境较为敏感，鲁棒性有待提高。后续可进一步完善状态同步、异常处理和路线数据校验，提高系统在不同赛道条件下的稳定性和容错能力。
调试过程中遇到的重要问题及解决经验：其一，速度环与平衡环耦合引起的振荡，通过分周期解耦运行与分阶段积分策略解决；其二，特殊路段切换时舵机突变造成的机械冲击，通过舵机目标值渐变逼近解决；其三，起转打滑问题，通过转向输出渐增与独立限幅解决。上述经验表明，对平衡类车模而言，各控制环路间的解耦与切换过程的平滑处理，与控制算法本身的精度同等重要。

B.1 串级 PID 控制器（角速度环）

typedef struct {
    float kp, ki, kd;
    float integral, last_error;
    float out_max;        /* 输出限幅 */
    float integral_max;   /* 积分限幅 */
} pid_t;

float pid_update(pid_t *pid, float setpoint, float measurement)
{
    float error = setpoint - measurement;
    pid->integral += error;
    /* 积分限幅，防止积分饱和 */
    if (pid->integral >  pid->integral_max) pid->integral =  pid->integral_max;
    if (pid->integral < -pid->integral_max) pid->integral = -pid->integral_max;
    float output = pid->kp * error
                 + pid->ki * pid->integral
                 + pid->kd * (error - pid->last_error);
    pid->last_error = error;
    /* 输出限幅 */
    if (output >  pid->out_max) output =  pid->out_max;
    if (output < -pid->out_max) output = -pid->out_max;
    return output;
}
