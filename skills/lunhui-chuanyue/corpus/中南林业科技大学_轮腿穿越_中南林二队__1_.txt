摘 要
本文围绕第二十一届全国大学生智能汽车竞赛轮腿穿越组车模系统展开，介绍了整车机械结构、硬件电路、软件算法和现场调试过程。系统采用博思威龙V轮腿车模平台，以CYT4BB7为主控核心，结合MT9V03X摄像头、IMU660RC、GPS模块和TLE5012B磁编码器完成环境感知、姿态解算和路径跟踪；执行系统由两路BDS3620无刷电机和四路BDS300舵机构成。软件部分采用图像处理、惯性导航、GPS融合导航和多级PID控制相结合的方式，实现绕桩、定点排雷、单边桥、颠簸路段和三级台阶等元素处理。华南区赛中，本车模三个科目均可完整跑完，总成绩75s，位列第四名，其中科目一11s、科目二27s、科目三37s，科目三全元素通过且无罚时。针对全国总决赛去除科目一、并将科目二与科目三融合为带雷区综合科目的赛道变化，团队正在继续提高各元素通过速度和室外视觉鲁棒性。

第一章 引言
1.1 概述
全国大学生智能汽车竞赛以“立足培养，重在参与，鼓励探索，追求卓越”为指导思想，融合了机械设计、模式识别、电子技术、传感技术、计算机科学、自动控制与汽车工程等多个学科的知识，充分体现了当代大学生综合运用所学知识并勇于探索创新的精神风貌。该赛事由教育部高等教育司委托有关专业教学指导委员会主办，是全国性、多学科交叉、兼具趣味性与创新性的科技竞赛，旨在强化大学生的工程实践能力与团队协作精神，推动高等教育人才培养模式的改革。竞赛始终坚持公开、公平、公正的原则，规则透明、评价客观，为各参赛队伍营造了健康有序的竞争环境。
学校历来重视大学生创新实践能力的培养，积极鼓励并组织学生参与高水平学科竞赛。本团队代表中南林业科技大学参加了第二十一届全国大学生智能汽车竞赛轮腿穿越组别的比赛，并根据竞赛规则，在规定的车模平台上对机械结构、硬件电路与控制系统进行了系统的设计与优化，赛前进行了充分准备。
在总体技术方案上，我们选用高性能微控制器作为核心控制单元，自主设计并搭建了涵盖传感器信号采集、电机驱动、电源管理与控制算法的完整系统。车模上配置了摄像头、惯性测量单元等多种传感器，用于实时感知赛道环境与车身姿态，为智能车的高速稳定运行提供可靠的数据支撑。
控制软件以PID控制算法为基础，结合轮腿穿越组别的运行特点，针对速度控制、转向控制以及特殊赛道元素通过策略进行了专项设计与反复调优。经过大量的场地测试与参数整定，车模在稳定性和动态响应之间取得了良好的平衡。
本报告详细记录了中南林业科技大学轮腿穿越组智能车系统的设计开发全过程，内容涵盖机械结构设计与改造、硬件电路设计、控制算法研究、软件实现以及现场调试等方面，并对制作过程中遇到的关键问题与解决思路进行了归纳总结，以期为后续参赛队伍提供参考。
1.2 竞赛科目与规则分析
第二十一届全国大学生智能汽车竞赛轮腿穿越组别共设置三个比赛科目，分别为行进绕桩、定点排雷和颠簸路段，旨在全面考察轮腿车模的行进特性、定位特性以及车身姿态控制与跳跃能力。三个科目均要求车模在自主导航与控制下完成相应任务，比赛成绩由完成时间与违规罚时共同决定。下面对三个科目的规则要点分别进行说明。
1.2.1 行进绕桩
行进绕桩科目主要考察车模平台的行进特性。车模需通过GPS、IMU或者其他导航方式，在规定的场地内完成直行和绕桩科目。比赛过程中，车模出发后先直行到掉头区，然后在返回的路径中通过由锥桶给定的间隙完成绕桩穿越。
设赛道中共有N个锥桶，则对应存在N-1个间隙，车模需要依次完成N-1次穿越过程。需要说明的是，锥桶的排列不限定在一条直线上，两个锥桶之间的最小距离为1.5米，这对车模的路径规划与转向控制精度提出了较高要求。
1.2.2 定点排雷
定点排雷科目主要考察车模的定位特性以及定点旋转功能。场地内预先铺设若干雷区，雷区通过宽度为10厘米的白色胶带粘贴成边长为100厘米的方框，可铺设于蓝色背景布板、KT板或红色操场赛道上。
比赛时车模通过雷区的顺序没有规定，车模在雷区内旋转的方向同样没有规定，但至少需要原地旋转两周；旋转过程中，车模车轮不允许冲出白色边框。比赛计时从发车区开始，车模完成雷区任务后经掉头区返回发车区，计时结束。该科目对车模的厘米级定位精度与原地旋转时的姿态稳定性提出了严格要求。
1.2.3 颠簸路段
颠簸路段科目主要考察轮腿车模的车身姿态控制以及跳跃功能。场地内设置了交错单边桥、颠簸路段、草地、三级台阶坡道等元素，车模从出发区出发，依次通过上述路段元素并在掉头区返回，通过顺序可自行选择。其中，三级台阶坡道元素需要正反两个方向各通过一次。
交错单边桥由若干左右交错摆放的三角楔形路障构成，楔形路障高度小于5厘米、颜色为黑色，间隔限定在10厘米至25厘米之间，用于考察轮腿车模在运动过程中通过腿关节运动保持平衡的能力，遗漏单边桥将按每个10秒进行罚时，且通过时不允许跳跃。颠簸路段由室内赛道路肩铺设，路肩高度2厘米、宽度2.5厘米，相邻间隔约10厘米，整个路段宽度约1米、长度不小于1米；草地路段通过人工草坪增加车模运行阻力；三级台阶坡道中，中间台阶表面为蓝色，便于车模识别台阶边缘，车模需先通过台阶上到坡道，再从坡道一侧返回并跳跃下台阶。
根据全国总决赛场地调整，轮腿穿越项目去除了原科目一，并将原科目二定点排雷与原科目三颠簸路段融合为带雷区的综合科目。相比华南区赛，总决赛对车模在复杂元素之间连续切换的稳定性提出了更高要求，尤其需要在完成排雷、单边桥、草地、颠簸路段和三级台阶等元素后保持导航坐标连续和视觉识别可靠。
1.3 主要技术难点分析
综合上述三个比赛科目的要求，本车模在方案设计与实现过程中面临以下主要技术难点：
（1）轮腿平衡控制难度大。轮腿车模在行驶过程中需要实时调节腿部关节与车轮转速以维持车身平衡，在交错单边桥、颠簸路段与三级台阶等复杂路况下，平衡控制的鲁棒性尤为关键，对控制算法的实时性与抗扰动能力要求很高。
（2）定位与导航精度要求高。行进绕桩要求车模在GPS信号可能存在遮挡的场地内实现米级甚至厘米级定位，并规划出满足锥桶间隙约束的绕行路径，需要将GPS与IMU等传感器数据进行有效融合。
（3）特殊元素的识别与通过策略复杂。雷区识别、台阶边缘检测与跳跃时机的把握，均需要视觉或激光传感器与运动控制的紧密配合，算法复杂度与实现难度较大。
（4）机械结构与硬件系统的可靠性要求高。轮腿机构在反复冲击与跳跃过程中承受较大载荷，传感器的安装布局、电路板与电源系统的稳定可靠是完成比赛的重要前提。

第二章 总体设计方案
2.1 设计思路与需求分析
根据轮腿穿越组三个比赛科目的任务特点，本车模在总体设计上遵循“主控分工、模块独立、稳定可靠、便于调试”的设计思路。整车采用双微控制器方案：以英飞凌TRAVEO™ T2G系列CYT4BB7作为整车主控，负责图像处理、姿态解算、路径规划与决策控制等核心任务；以英飞凌TRAVEO™ T2G系列CYT2BL3作为无刷电机双驱控制芯片，专门完成两路无刷电机的FOC磁场定向控制，从而将电机实时控制任务从主控中解耦，降低主控负载，提高控制实时性。
从比赛科目需求出发，本车模需要具备以下能力：一是稳定可靠的轮腿平衡能力，要求驱动系统具备大扭矩输出与快速响应能力，以适应交错单边桥、颠簸路段和三级台阶等复杂路况；二是高精度的定位与导航能力，要求在GPS信号存在波动的场地内，依靠GPS与IMU融合实现米级定位与精确的原地旋转；三是准确的环境感知能力，需要识别锥桶、雷区边界、台阶边缘等赛道元素；四是良好的可调试性与可维护性，便于在赛前进行参数整定与问题排查。
基于上述需求，本团队对各功能模块进行了选型：动力部分选用BDS3620无刷电机提供强劲动力，该电机采用12槽14极结构，转速常数为500KV，扭矩为0.12N·m，支持7.4V~12.4V宽电压供电；选用BDS300舵机控制轮腿关节，其堵转扭矩为10kg·cm，在7.4V供电下转动60°仅需约0.13s，响应迅速；感知部分选用逐飞科技总钻风MT9V03X灰度摄像头、IMU660RC六轴姿态传感器以及GPS卫星定位模块；人机交互部分选用逐飞科技IPS200液晶屏幕。各模块均选用竞赛常用成熟方案，资料齐全、稳定性高，有利于缩短开发周期。
2.2 系统总体架构
本车模系统按功能划分为感知层、决策层、驱动层与执行层四个层次。感知层由总钻风MT9V03X摄像头、IMU660RC六轴姿态传感器和GPS定位模块构成，分别负责赛道元素图像信息、车模姿态信息与全局位置信息的采集；决策层由主控CYT4BB7完成，负责传感器数据处理、姿态解算、路径规划与任务决策；驱动层由CYT2BL3双驱芯片及其外围功率电路构成，输出三相驱动信号驱动两路无刷电机，同时主控直接输出PWM信号控制BDS300舵机；执行层包括BDS3620无刷电机与轮腿舵机机构，最终实现车模的运动与姿态控制。
在数据流方面，摄像头通过DVP并行接口将灰度图像送入主控，IMU660RC通过SPI接口向主控提供三轴加速度与三轴角速度数据，GPS模块通过串口输出定位信息；主控通过PWM信号控制舵机，并通过通信接口向CYT2BL3发送电机转速与力矩指令，CYT2BL3采用FOC算法产生互补PWM驱动两路无刷电机；IPS200屏幕通过SPI接口实时显示车模运行参数，便于调试与状态监控。系统电源由电池经稳压电路为各模块供电，保证整机稳定运行。
2.3 传感器选型与布局
摄像头选用逐飞科技总钻风MT9V03X灰度摄像头，其基于MT9V034图像传感器设计，采用全局快门，最高帧率可达数百帧，能够有效避免车模高速运动时的图像果冻效应，且支持自动曝光，可在不同光照环境下稳定成像。摄像头安装于车模前部支架上，俯仰角可调，用于识别行进绕桩中的锥桶、定点排雷中的雷区边界以及颠簸路段中的单边桥与台阶边缘。
姿态传感器选用逐飞科技IMU660RC六轴模块，内部集成三轴加速度计与三轴陀螺仪，加速度量程最大可达±16g，角速度量程最大可达±4000dps，满足车模剧烈姿态变化下的测量需求，支持SPI与IIC接口。模块安装于车模重心附近的底盘上，以减小安装误差与振动对姿态解算的影响。GPS模块选用逐飞科技GPS卫星定位模块，为车模提供全局位置坐标，用于行进绕桩的路径规划与定点排雷的定点控制，模块安装于车模顶部，保证天线对天空的视野。
人机交互部分选用逐飞科技IPS200液晶屏幕，分辨率高、刷新快，通过SPI接口与主控通信，用于实时显示车速、姿态角、GPS坐标、任务状态等调试信息。传感器布局遵循“重心集中、安装牢固、便于走线”的原则，在保证功能的前提下尽量降低车模重心，提高轮腿车模的运动稳定性。
测速编码器选用自制磁编码器，采用英飞凌TLE5012B E1000角度传感器芯片，通过检测与车轮电机同步旋转的永磁体磁场方向来解算转角，具有分辨率高、体积小、抗污染能力强等优点。磁编码器安装于车轮电机输出轴附近，用于实时测量轮速，为轮腿平衡控制与速度闭环提供反馈信号。
2.4 小结
本章围绕轮腿穿越组三个比赛科目对车模提出的要求，给出了本车模的总体设计方案。整车采用CYT4BB7主控加CYT2BL3无刷双驱芯片的双控制器架构，感知、决策、驱动、执行各层职责清晰，传感器选型与布局能够满足环境感知、姿态测量与全局定位的需求，为后续机械结构、硬件电路与软件算法的详细设计奠定了基础。
第三章 机械结构设计与改造
3.1 轮腿车模平台介绍
本车模以博思威龙V车模为整车平台。该平台专为轮腿穿越组别设计，车身主体采用铝合金与碳纤维混合结构，具备较高的结构强度与较低的整备质量，并自带双轮腿机构。整车质量为1.5kg，外形尺寸为长16cm、宽22cm、高28cm，结构紧凑、重心较低，有利于车模在高速行驶与复杂路况下的稳定性。
3.2 轮腿机构与平衡结构设计
轮腿机构沿用V车模自带的双轮腿结构。每个轮腿由一个BDS3620无刷电机驱动车轮，并通过两个BDS300舵机控制腿部关节的运动，整车共使用4个BDS300舵机，构成四路舵机驱动系统。轮腿机构在平地行驶时保持车身直立，在遇到交错单边桥、台阶等障碍时，通过舵机改变腿形实现跨越与跳跃动作。为提升平衡性能，舵机选用金属齿轮结构并对称布置，保证左右轮腿运动特性一致，同时配合无刷电机的大扭矩输出，为车身姿态调节提供充足的动力。
3.3 传感器安装设计
摄像头安装采用碳杆架高方案：通过碳纤维杆将总钻风MT9V03X摄像头架高至车模前方上部，以获得更开阔的视野，并采用自制3D打印底座将摄像头可靠固定，配合可调俯仰角结构，便于针对不同赛道元素调整视角。磁编码器安装于车轮电机输出轴处，与电机同轴连接，实时采集轮速信息。IMU660RC六轴姿态传感器安装于车模重心附近的底盘中央，通过减振处理减小高频振动对姿态测量的影响。GPS模块安装于车模顶部开阔位置，保证天线接收质量。

3.4 电路板固定与连接
系统各电路板采用铜柱固定于V车模原有的预留安装孔上。主控核心板、无刷电机驱动板与电源板分别通过铜柱与螺母牢靠固定，既保证了电路板与车体之间的电气绝缘，又便于拆卸调试与维修。各模块之间采用排针、排线与接插件连接，并对线束进行整理与捆扎，避免在运动过程中因振动导致接触不良或信号干扰。
3.5 小结
本章介绍了本车模的机械结构设计与改造情况。整车以博思威龙V车模为平台，沿用其自带的双轮腿机构，配合四路BDS300舵机实现轮腿姿态控制；摄像头通过碳杆架高并采用3D打印底座固定，编码器、IMU、GPS等传感器均按功能需求合理布局；电路板利用铜柱固定于车模预留孔位。整机结构紧凑、安装可靠，为后续硬件电路与软件算法的实现提供了稳定的载体。
第四章 硬件电路设计
4.1 硬件电路总体架构
除CYT4BB7核心板采用成品核心板外，整车自制PCB共5块，包括主板、四路舵机驱动板、双路无刷电机驱动板以及左右两块磁编码器板。主板以CYT4BB7核心板为控制中心，负责传感器接口、调试通信、电源分配和低压外设管理；舵机驱动板为四路BDS300舵机提供独立稳压输出；无刷驱动板以CYT2BL3控制芯片配合双路三相栅极驱动和MOS桥，实现左右BDS3620无刷电机的独立控制；两块磁编码器板安装在左右轮测速位置，用于将轮端转角/速度信息反馈至控制系统。
从原理图和PCB图可以看出，本车硬件设计采用“控制信号与大电流负载分板处理”的思路。主板和舵机驱动板的学校、队伍等标识位于顶层丝印，无刷双驱板的相关标识位于底层丝印；磁编码器板同属自制PCB，板面标识与最终实物资料后续补充确认。各类电路共地连接，使主控PWM、编码器、UART和传感器信号能够在统一参考电位下工作。

4.3 电机驱动电路设计
双路无刷电机驱动原理图如图4-2和图4-3所示。控制部分选用CYT2BL3作为无刷驱动控制芯片，芯片外围包含3.3V电源去耦、16MHz晶振、SWD下载调试接口、复位/模式按键、状态指示灯、UART接口以及两路编码器接口。两路编码器接口以ECD1和ECD2形式引出，用于采集左右驱动轮的转速和位置信息，为速度闭环与惯性里程计提供反馈。
功率驱动部分采用两片FD6288Q三相栅极驱动芯片，分别对应左右两路无刷电机。每一路驱动芯片接收三相上下桥PWM控制信号，并通过HO/LO输出驱动六个MOSFET构成三相桥。MOS管栅极串联小阻值电阻，用于抑制开关振荡；自举二极管和自举电容为高边驱动提供所需电压。三相输出端通过VSA、VSB、VSC等焊盘连接电机相线。
电源与保护部分采用VBAT作为动力母线，并在输入端布置TVS/二极管保护和大量并联去耦电容阵列，以降低无刷电机快速换相时产生的母线纹波。板上还设置RY9121E降压电路产生5V和3.3V低压电源，供驱动芯片、编码器和通信接口使用。由于母线电容数量和等效容量需以最终BOM为准，本报告只说明其滤波和抗冲击作用，不填写未经确认的总容量。

4.4 四路舵机驱动设计
四路舵机驱动原理图如图4-4所示。舵机板输入端由DCOUT接口和电源开关引入电池电压，随后分成四路结构相同的降压支路。每一路均以SCT2450为核心，配合4.7uH电感、SS54肖特基二极管、输入/输出滤波电容和反馈分压电阻，形成独立的舵机供电电源，输出网络分别命名为VCCServo1至VCCServo4。
四路舵机接口CH1至CH4均采用三线制连接方式，包括控制信号、电源和地。与单一大电流舵机电源相比，四路独立降压可以减小某一路舵机大动作时对其他舵机的压降影响，有利于轮腿机构在台阶、颠簸和单边桥等冲击工况下保持响应一致。每路输出端设置LED状态指示，便于调试时快速判断对应供电支路是否正常。
该板主要服务于四个BDS300舵机。实际安装时，舵机信号线由主控PWM输出控制，电源线由舵机驱动板提供，所有控制地保持共地。这样既能保证控制信号有统一参考点，又能把舵机瞬态电流从主板低压电源中分离出来，提升系统稳定性。

4.5 传感器电路设计
传感器接口主要集中在主板上。摄像头接口连接MT9V03X模块，用于图像采集和图传调试；GPS接口引出电源、地和串口信号，用于接收定位信息；SPI接口和屏幕接口用于连接显示与调试模块；无刷驱动板预留编码器接口，并与左右两块自制磁编码器板连接，用于获取轮端速度和角度反馈。
传感器电路设计的重点是供电稳定、接口清晰和线束可靠。摄像头、GPS和显示模块均属于低压数字外设，因此主板上为其布置了3.3V/5V稳压与滤波支路；编码器靠近电机布置，可减少轮速信号长距离传输带来的干扰。调试时，逐飞无线图传用于观察摄像头图像和二值化效果，2.4G串口则用于把姿态、导航误差和关键状态上传到逐飞助手或VOFA上位机。
4.6 电源电路设计
整车采用3S锂电池供电，单块电池充电限制电压为12.6V，额定电压为11.1V，容量为1650mAh，额定能量为18.315Wh，比赛和调试共准备5块电池。主板负责提供控制与传感器所需的5V、3.3V和摄像头电源；舵机板将电池电压分别降压为四路舵机电源；无刷驱动板直接使用VBAT作为电机功率母线，并通过独立降压电路生成驱动与逻辑电源。这样的分层方式可以避免电机和舵机的大电流波动直接影响主控和传感器。
按当前原理图估算，整车主要储能与滤波电容总容量约为3.2mF。其中四路舵机驱动板每路含输入、输出滤波电容，四路合计约1.49mF；无刷双驱板动力母线由多颗22uF电容并联构成，母线去耦约1.14mF；其余容量来自主板、无刷驱动低压电源和各芯片局部去耦。该数值为根据原理图的近似估算，最终容量以BOM和实际焊接版本为准。
功耗方面，主控、传感器和调试模块功耗较小，主要负载来自两路无刷电机和四路舵机。结合电机、舵机数量及比赛工况估算，整车运行平均功耗约70W至90W，台阶、起跳或急加速等瞬态工况下峰值功耗可达约180W。按单块18.315Wh电池估算，连续调试时间约为10至15分钟，能够满足单次比赛流程需求。
4.7 小结
本章根据主板、四路舵机驱动板、双路无刷电机驱动板原理图及部分PCB图，对车模硬件电路进行了分析。主板负责低压供电、传感器接口和调试扩展；舵机板通过四路独立降压提高轮腿舵机供电稳定性；无刷驱动板以CYT2BL3和FD6288Q为核心实现左右电机三相驱动；左右磁编码器板完成轮速反馈。整体硬件结构与软件中的双核调度、导航控制和轮腿姿态控制相对应，满足轮腿穿越组多执行器、多传感器并行工作的需求。
第五章 软件算法设计
5.1 软件总体框架
本车模软件以 CYT4BB7 双核资源为基础进行任务划分。CM7_0 侧主要承担系统初始化、菜单参数管理、姿态闭环、导航控制和执行器输出；CM7_1 侧主要承担 MT9V03X 摄像头图像处理，并通过共享数组 m7_1_data 向控制侧传递图像偏差、跳跃识别、单边桥识别等状态量。该结构使图像处理与控制中断相互解耦，减少单帧图像处理对底层平衡控制的影响。
系统上电后首先调用 Init() 完成显示、IMU、无刷驱动、舵机、GNSS、滤波器、元素管理、PID 组和定时器等初始化。随后主循环负责按键检测和菜单显示，实时性较高的控制逻辑放入定时中断执行。图像核心在 mt9v03x_finish_flag 置位后调用 camera_deal_mode()，完成赛道识别和特殊元素辅助识别。

5.2 轮腿平衡控制算法
轮腿车模的稳定行驶依赖姿态闭环、速度闭环和轮腿舵机协同控制。程序在 1 ms 定时任务中读取 IMU 数据并更新姿态角，在固定周期内更新编码器速度，再根据当前车身高度、赛道元素和运行模式选择普通、中位或高位平衡控制。
平衡控制采用多级 PID 结构：速度环根据目标速度与编码器反馈形成期望姿态量，角度环根据 Roll 偏差产生角速度目标，角速度环进一步生成左右轮差速 PWM。舵机侧通过 steer_control() 对四个轮腿舵机进行同步修正，并利用 Pitch_steer() 在颠簸、台阶等场景下补偿俯仰姿态。
为提高可靠性，程序设置了起跳、落地、单边桥、排雷旋转等不同工况下的控制分支，并在车身姿态超限时关闭动力输出。文中不列出具体 PID 参数，仅说明其层级关系，如图5-2所示。

5.3 导航与定位算法
导航部分以路径点为核心组织运行过程。调试阶段可通过按键采集路径点并绑定元素信息；运行阶段根据当前位置、目标路径点和元素状态计算航向偏差 INS_error，再交由底层转向控制函数形成左右轮输出。
程序保留了 GPS 与惯性导航两种工作模式。普通循迹以惯性里程计和路径跟踪为主，遇到需要空间位置约束更强的元素时，可临时切入 GPS 模式，并在退出后同步坐标与目标点进度，保证控制过程连续。
5.3.1 GPS/IMU数据融合
IMU 姿态解算由 imu_2.c 等模块完成，程序读取陀螺仪和加速度计数据后进行姿态更新，得到 Roll、Pitch、Yaw 以及连续偏航角 yaw_continuous_。连续偏航角主要服务于自转和循迹衔接，避免角度跨越 ±180° 时出现突变。
惯性定位部分使用编码器速度与航向角进行里程计积分，更新统一的车辆坐标 g_nav_car_x、g_nav_car_y。GNSS 数据经过解析后用于打点、坐标参考或特定阶段的导航补偿。两类数据在模式切换时进行坐标同步，减少 GPS 与惯性里程计之间的跳变。
5.3.2 路径规划与锥桶绕行
路径规划采用“采点-拟合-跟踪”的方式实现。调试时记录原始路径点 POINT，并根据需要生成平滑路径 PATH；运行时搜索车辆附近路径点并选取前视目标，通过类似 Pure Pursuit 的方法得到航向偏差。前视距离会随速度和路径弯曲程度调整，以兼顾直线速度和弯道稳定性。
锥桶绕行和其他固定元素不在程序中写成独立的复杂地图，而是通过路径点、绑定点和元素表进行管理。这样可以根据实际场地快速调整触发位置，同时避免在主循环中堆叠过多特殊判断。具体点位编号与判定距离属于现场调试参数，正文不展开。
5.4 特殊元素处理算法
特殊元素由 element_list 统一管理。程序在目标点切换时调用 element_trigger_check() 检查是否进入元素区域，再由 update_current_element() 和 element_control() 设置对应的 subject_three_flag、GPS_MODE、蜂鸣器提示或专用控制标志。元素完成后调用 element_exit_process() 恢复普通循迹状态。

5.4.1 行进绕桩穿越
行进绕桩阶段主要依靠路径点跟踪完成方向规划，底层仍使用速度闭环、姿态闭环和转向闭环输出左右轮差速。程序根据当前路径段距离和弯曲程度调整目标速度，在接近目标点或弯曲较大时降低速度，在相对稳定的路段提高速度。
图像处理结果 image_error_1 可作为摄像头循迹模式下的横向偏差输入。当 camera_run_flag 进入对应状态后，camera_run_contral() 将图像误差转换为转向修正量，辅助车模沿视觉中线运行。
5.4.2 定点排雷旋转
定点排雷通过元素表中的雷区类型触发。进入该元素后，程序切换到排雷控制分支，并利用连续偏航角进行原地旋转角度判断。旋转过程中通过专用转向 PID 控制角速度，完成指定动作后清除旋转标志、重置相关积分项，并恢复后续导航。
该部分的关键在于“进入、旋转、完成、复位”四个状态的衔接。由于具体转角阈值、延时和速度参数直接影响比赛效果，正文只描述控制流程，不列出完整触发条件。
5.4.3 单边桥识别
单边桥处理结合路径点触发和图像识别。进入单边桥附近后，控制侧设置单边桥标志，图像侧根据赛道宽度变化和边线状态判断是否需要进行中线修正。Bridge_Judge_And_Modify() 用于在桥面半宽视野下重建可用中线，避免车模因单侧边线缺失而偏离。
退出阶段通过固定区域的图像特征进行确认，并设置锁存和清零逻辑，防止刚离开桥面时反复触发。报告中不展示具体 ROI 范围和阈值，仅保留识别思路与模块名称。
5.4.4 颠簸路段与台阶跳跃
台阶与颠簸路段采用视觉状态机与轮腿动作配合完成。图像侧通过 Camera_Jump_Warning_Boundary_Task() 识别台阶前方的黑白交界和阶段变化，并以 jump_sign 形式传递给控制核心；控制侧根据该信号调用 control_jump()，驱动四个轮腿舵机完成起跳、收腿和复位动作。
颠簸路段中，程序使用 Pitch_steer() 对俯仰角进行补偿，并在速度控制中加入限幅和工况判断，以减小落地冲击和姿态波动。三级台阶、单边桥退出和颠簸离开均设置了防重复触发逻辑，避免单帧图像误判造成连续动作。
5.5 小结
本章根据 华南区赛工程代码，对车模软件算法进行了概括说明。系统采用双核分工结构，将图像处理、姿态解算、路径跟踪、元素触发和执行器控制分层实现；底层以多级 PID 保证轮腿车模稳定，导航层以 GPS/INS 模式切换和路径点跟踪完成比赛路径控制，元素层针对单边桥、台阶、颠簸和排雷等任务设置专用状态。
考虑到比赛程序包含大量现场调试参数，本章仅保留模块关系、主调用链和核心控制思想，未公开完整阈值、点位和参数表。这样既能说明软件设计依据，也能避免关键策略被直接复现。
第六章 开发工具与调试过程
6.1 开发环境与工具
团队工作按照机械结构、电路设计、软件算法和现场调试四部分展开。机械部分负责轮腿机构安装、摄像头支架和线束固定；电路部分负责主板、舵机驱动板和无刷双驱板设计与焊接；软件部分负责姿态解算、导航融合、视觉识别和元素策略；现场调试部分负责参数整定、场地采点和多时段测试验证。

调试过程中使用逐飞科技无线图传辅助图像调试，并通过逐飞 2.4G 串口模块连接逐飞助手上位机与 VOFA 上位机，实时观察路径点、航向偏差、车身姿态、元素状态和图像处理变量。IPS200 显示屏与菜单系统用于现场修改阈值、速度和元素相关参数，Flash 参数保存用于固化调试后的常用设置。

6.2 制作与安装
整车安装按照“机械结构固定、传感器定位、电路连接、执行器校准”的顺序进行。主控板和无刷驱动板固定在车模预留位置，摄像头通过支架安装在车体前上方，IMU 尽量靠近车体质心并保证安装方向一致，GPS 模块布置在相对开阔位置以降低遮挡影响。
安装完成后首先进行静态检查，包括电源极性、接口连接、舵机初始位置、无刷电机方向、编码器反馈方向和摄像头图像方向。确认无异常后，再分别测试 IMU、GNSS、摄像头、舵机和电机驱动，避免多个问题叠加后难以定位。
舵机安装是轮腿车模调试的重点之一。四路舵机在程序中有低位、中位和高位等不同姿态基准，安装时需要保证左右轮腿的机械零位尽量一致，再通过程序中的基准值微调，使车模在静止和低速状态下能够保持基本平衡。
6.3 现场调试
整车调试周期从2025年11月赛题公布开始，一直持续到2026年8月。调试顺序由底层到上层逐步推进：首先完成陀螺仪与姿态角解算，随后调试轮腿平衡、变腿动作和舵机基准，再进行导航循迹、摄像头视觉识别和特殊元素策略。这样的顺序可以先保证车辆“站得稳、跑得直”，再逐步提高元素通过能力。
现场调试采用由低风险到高风险的顺序推进。首先完成供电、传感器和执行器单项验证，然后在低速条件下调平衡和速度闭环，随后加入导航、图像循迹和特殊元素处理，最后进行连续跑车测试。调试流程如图6-1所示。

平衡调试阶段主要观察 Roll、Pitch、编码器速度和左右轮 PWM 输出，先保证车模能够稳定站立并低速行驶，再逐步提高目标速度。导航调试阶段通过采集路径点和绑定元素点位，检查 tarpoint、INS_error、GPS_MODE 等状态是否按预期切换。
图像调试阶段重点观察 MT9V03X 图像质量、二值化结果、左右边线和中线。室外环境下光照变化大，实测大津法二值化效果不稳定，容易受强光、阴影和地面反光影响。后续调试中改为固定阈值配合曝光度调整，使赛道边界更加稳定，并通过无线图传观察图像处理效果。
6.4 调试中遇到的问题及解决
科目二定点排雷调试中，车模完成原地转圈后容易出现惯性导航路径漂移，导致后续循迹方向与实际路径不一致。针对这一问题，程序优化了陀螺仪姿态解算与连续偏航角处理方法，并在特定阶段进行偏航角复位和同步，使转圈动作结束后能够更平稳地衔接惯性导航路径。
室外图像调试中，大津法阈值会随背景亮度和阴影变化产生较大波动，导致二值化后的白线边界不稳定。解决时采用固定阈值作为主要二值化方式，并结合摄像头曝光度调整，使图像亮暗分布更适合赛道识别；同时利用无线图传和上位机观察图像效果，减少单纯依靠经验调参带来的误差。
科目三在通过单边桥、台阶和颠簸等元素后，若直接依赖 GPS 导航进行后续循迹，实测稳定性较差，容易出现目标点切换不顺或路径偏移。为此，程序采用惯性导航与 GPS 融合的方式：普通路段主要依赖惯性里程计和路径跟踪，关键阶段通过 GPS 辅助定位和点位同步，从而提高元素通过后的循迹连续性。
单边桥调试中，摄像头视野内会出现半宽赛道或单侧边线缺失。程序在图像处理模块中增加了桥面状态下的中线修正思路，通过桥面识别标志切换处理方式，使控制侧仍能获得可用的图像偏差。具体 ROI 范围、阈值和连续帧判定属于现场调试参数，报告中不作展开。
调试过程中难度最高的是科目三相关元素，包括三级台阶跳跃、单边桥识别通过以及颠簸路段的稳定通行。为验证视觉鲁棒性，团队在不同时间段、不同室外光照条件下反复测试科目三图像阈值和边线识别效果；同时针对科目一不同赛道长度与不同锥桶摆放、科目二不同赛道长度与不同雷区摆放进行重复测试，以检查导航打点、元素触发和路径衔接的稳定性。
6.5 小结
本章介绍了车模的软件开发环境、安装检查流程和现场调试方法。整车调试按照单模块验证、低速闭环、导航联调、元素分项测试和连续跑车的顺序进行，逐步排除供电、传感器、执行器、算法和机械装配中的问题。
通过多轮调试，车模能够完成基础平衡、路径跟踪、摄像头辅助循迹以及单边桥、定点排雷、颠簸路段和台阶跳跃等特殊元素处理。华南区赛实车验证表明，科目一和科目二运行较为稳定，科目三能够全元素通过且无罚时，但在室外光照变化较大时三级台阶识别仍存在一定波动，整体速度仍有提升空间。后续将结合全国总决赛综合科目场地变化，继续优化视觉识别、元素触发和通过速度。

7.1 车模基本参数
本车模以博思威龙 V 轮腿车模为基础平台，整车总质量约 1.5 kg，外形尺寸约为 16 cm × 22 cm × 28 cm。整车采用双轮腿结构，左右轮由 BDS3620 无刷电机驱动，轮腿姿态由 4 个 BDS300 舵机完成调节。

第八章 结论
8.1 工作总结
本报告围绕轮腿穿越组智能车的机械结构、硬件电路、软件算法和现场调试过程进行了说明。整车以博思威龙V轮腿车模为平台，采用CYT4BB7主控、CYT2BL3无刷双驱、MT9V03X摄像头、IMU660RC、GPS模块和磁编码器等器件，形成了较完整的感知、导航、控制和执行系统。
在华南区赛中，车模三个科目均可完整跑完，总成绩为75s，位列第四名。其中科目一用时11s，科目二用时27s，科目三用时37s。科目一和科目二运行稳定，科目三完成了单边桥、草地、颠簸路段、三级台阶等全元素通过，并且无罚时，说明整车机械结构、导航算法和视觉识别策略具备较好的综合可用性。
从实际比赛和调试结果看，本车模已经具备完成轮腿穿越组主要任务的能力。系统在惯性导航路径跟踪、GPS融合导航、摄像头视觉辅助和轮腿姿态控制方面形成了较稳定的工作流程，为后续全国总决赛调试提供了基础。
8.2 存在问题与改进方向
当前系统仍存在三方面不足。第一，科目三整体速度偏慢，部分元素通过策略偏保守，尤其是三级台阶和颠簸路段仍需要在稳定性和速度之间继续权衡。第二，室外光照变化较大时，摄像头对台阶边界和赛道边线的识别稳定性会下降，需要继续优化曝光、阈值和ROI区域选择。第三，综合科目中多个元素连续出现时，导航坐标、元素触发和车身姿态之间的衔接仍有进一步提升空间。
针对全国总决赛赛道变化，比赛场地去除了科目一，并将科目二与科目三融合为带雷区的综合科目。后续调试重点将从单独科目稳定完成转向综合场地连续通过：一方面提高单边桥、草地、颠簸路段和三级台阶等元素的通过速度；另一方面加强排雷旋转后惯性导航与GPS融合导航的坐标同步，减少元素切换后的路径漂移。
后续还将继续开展不同时间段和不同光照条件下的视觉鲁棒性测试，并针对不同赛道长度、锥桶摆放、雷区位置和综合元素顺序进行多场景验证。通过进一步优化参数整定、速度规划和元素触发策略，提升车模在全国总决赛复杂赛道中的稳定性和竞争力。

static int Image_Select_Threshold(void)
{
    if(Image_threshold_mode == IMAGE_THRESHOLD_MODE_OTSU)
    {
        Threshold = otsuThreshold(&mt9v03x_image[MT9V03X_H / 2][0],
                                  MT9V03X_W, MT9V03X_H / 2, 255);
        // 阈值限幅与低通滤波，避免亮度突变造成图像抖动
    }
    else
    {
        // 室外强光环境下采用固定阈值，并配合摄像头曝光调整
        Threshold = (uint8)Image_Limit_Threshold(Binarization_thresholds);
    }
    Image_current_threshold = Threshold;
    Image_scan_threshold = Threshold;
    return Threshold;
}

float Image_Deal(void)
{
    Image_Select_Threshold();
    Image_Binary(mt9v03x_image[0], Deal_Image_Binary[0]);
    if(!Image_Frame_Is_Usable())
        return 0.0f;

    Image_Find_Line_Fast_Binary(Deal_Image_Binary[0]);
    // 近处中线用于横向误差，远近中线差用于方向修正
    image_error_1 = k_lateral * lateral_error + k_heading * heading_error;
    return image_error_1;
}
