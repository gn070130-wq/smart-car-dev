第一章 引言

4.1主控的硬件设计
可靠是系统设计的第一要求，我们对电路设计的所有环节都尽心了如下的改进和设计。如图所示。

图4.1主板设计图

电源系统的稳压性能、纹波噪声的去除、功率的充足提供的可靠性等；主控系统的电路优化,减少电路元件的体积和用量, 减少不稳定因素；电源系统的性能可靠性，为整车的性能提升提供充足的保证；做好各部分的接地、屏蔽、滤波等工作,使本系统工作的可靠性达到了设计要求；传感器的性能稳定，保证整车数据流的准确可靠。 部分原理图设计如图4.2所示。

5V电源模块采用 SCT2450 芯片，对于 SCT2450这款 DC-DC降压芯片，将其用于 12V转 5V的应用是一个非常经典和合适的选择。选用 SCT2450的核心原因是它完美契合12V转5V的需求，提供宽输入电压范围 (4.5-60V)确保12V输入的稳定裕量，同步整流架构实现高效率(>90%)，显著降低发热并提升功率密度，同时其4.5A 持续输出能力满足多数中高功率需求，集成度高简化设计(省去外部肖特基二极管，内部补偿)，并具备完善的过流、过热、欠压保护以及低静态功耗，在国产芯中具有出色的性价比，是高效、可靠、易用且经济的理想选择。
3.3V电源模块和摄像头电源模块采用 RT9013-33GB，此芯片是一款高性能、低压差线性稳压器，专为将5V稳定转换为3.3V 而设计(后缀33GB表示固定 3.3V输出)。RT9013-33GB 是高效低压差(LDO)稳压器，以180mV@300mA的超低压差实现5V至 3.3V稳定转换(最小输入电压仅3.48V),大幅降低功耗与发热;其1.5A 高电流输出、士2%精度 (3.3V士66mV)及>60dB@1kHz的纹波抑制能力，可为 MCU、传感器、射频模块等噪声敏感负载提供纯净电压；集成过流与过热保护，采用 SOT-23-5小封装，是紧凑型设计中兼顾性能、可靠性与成本的高性价比选择。
此外为了尽量减轻整车重量，降低模型车的重心位置，应使电路设计尽量简洁，尽量减少元器件使用数量，缩小电路板面积，使电路部分重量轻，易于安装。我们在对智能车系统进行分析后可以通过以下几点来进行对系统简洁处理智能车机械结构的简化，这需要我们设计出更加精巧、灵活的机械构件提高智能车的精度，提高智能车的制作工艺，简化智能车的机械复杂程度。在对智能车硬件电路系统进行了详细分析后，通过认真筛选所用器件、简化电路合理设计元件排列、电路走线，最终的硬件电路板采用贴片封装形式，使本系统硬件电路部分轻量化和机械强度部分的指标达到设计要求。
一个好的设计应该是能给人以美感的。除了满足基本的设计要求之外我们还对元器件的摆放位置做了大量的尝试，使得整个电路较为美观。

第五章 控制软件设计
控制程序是人的思想在车模体现，程序要体系化，模块化，稳定化，目标是硬件电路和机械性能发挥到最大，让车模用最快的速度完成比赛。
5.1 PID 控制算法介绍
PID控制因结构简单、稳定可靠、调整方便，在工业控制中应用最广，尤其适用于系统参数未知或无法精确建模的场合。PID由比例(P)、积分(I)、微分(D)三部分组成：比例用于快速响应偏差，积分消除稳态误差，微分预测趋势并加快调节。
数字PID常用两种实现方式：
位置式PID：直接输出控制量，适合位置控制，但受累积误差影响大，且故障时冲击大。
增量式PID：只输出增量，误动作影响小、切换平稳，但存在积分截断和静差问题。
本设计采用位置式PID，对所有控制环统一实现，输出均带积分限幅与输出限幅。PID参数整定（KP、KI、KD）可用理论计算或工程整定。由于智能车系统机电耦合且结构常改，我们采用工程整定，并尝试动态调整PID参数以适应赛道环境。
最终实际使用PID三环控制如下：
速度环（PID）：输入为目标速度（roll_speed_pid.target_speed，可通过菜单设置多档目标速度 target_speed0～target_speed5）与实际速度（car.Sports.actual_speed，由磁编码器测得）；输出为速度环控制量（roll_speed_pid.out），叠加到角度环作为期望倾角，实现前后轮力矩分配。
转向环（PID）：输入为航向偏差（GPS.error，由目标方位角与当前航向作差得到；元素内也可切换为摄像头中线偏差 Track_Error）；输出为差速控制量（GPS_gyro_pid.out），经左右轮差速叠加到电机输出。
平衡环（姿态PID）：输入为车体倾角（IMU_Data.roll）与角速度（imu660rc_gyro_x）；输出为直立控制量（roll_gyro_pid.out），作为左右轮基础占空比，保持车辆直立。
5.2 视觉处理方法
5.2.1 总体处理流程
室外环境下的视觉任务可划分为“采集—预处理—提取—识别—控制—调试”六个环节：摄像头采集灰度图像，经压缩与二值化得到二值图像；在此基础上逐行扫描提取赛道边界与中线；针对不同元素进行特征识别并触发相应动作；排雷任务在原始分辨率上单独完成目标框检测与对准；全部中间结果叠加显示，便于现场标定与调试。整体流程层次分明，各环节解耦，便于参数整定与问题定位。
5.2.2 图像采集与预处理
摄像头输出固定分辨率的灰度图像，曝光时间可在菜单中调整，以适应不同光照条件。由于原始图像数据量较大，直接处理占用计算资源多，因此先对图像进行压缩降采样，缩小到适合算法处理与屏幕显示的尺寸；随后采用固定阈值二值化，将灰度图转换为黑白二值图：白色表示赛道、桥面、台阶面等目标区域，黑色表示背景，阈值根据现场光照标定。对于排雷这类需要保留小目标细节的任务，在原始分辨率图像上独立完成二值化与识别，避免降采样造成细节丢失。
5.2.3 赛道边界与中线提取
二值化完成后，自下而上逐行扫描图像，统计每一行的白色像素数量与最长连续白色段，据此判断该行是否处于白色目标区域内。在此基础上搜索图像中面积最大的连续白色区域，将其定位为当前关注元素所在区域，并划定感兴趣区间，排除背景干扰。在感兴趣区域内，由底部种子点向上逐行扫描，求取每一行白色区域的重心作为该行中线点，将各行中线点相连即得到赛道或元素的中线。中线相对图像中心的横向偏差即为转向控制量，经 PID 调节后转换为左右轮差速，实现循迹。同时记录白黑交界边缘所在行，用于判断元素边界位置与动作触发时机。
5.2.4 元素识别与越障触发
针对不同元素采用针对性识别策略：
三级台阶：通过连续白色区域识别台阶面，首跳前过滤较矮的横向白带，避免将地面白线误判为台阶；根据图像底部是否大面积变白判断车体是否已驶上台阶；当台阶边缘到达图像中特定位置时触发跳跃动作，配合四轮腿舵机的时序展开完成越障。
单边桥：提取桥面白色区域并计算其中线，输出桥面横向偏差实现桥上循迹，上下桥前后自动切换控制参数，保证过桥平稳。
逆三级台阶：利用白色区域与边缘信息判断下台阶时机，结合车体姿态完成平稳越障。
5.2.5 定点排雷视觉
排雷目标在图像中呈现为规则边框。算法对原图二值化后，检测目标框的入口拐角与侧边直线等特征，对边界点进行直线拟合，得到框的左右边界与侧边线；利用边界线与侧边线的中垂线交点求取框中心位置，以框中心相对车体底部的距离作为是否到达可旋转位置的判据，并通过多帧连续确认提高可靠性。框中心横向偏差直接参与转向控制，使车体行驶中自动对准框中心，到位后进入定点旋转完成排雷。
5.2.6 图像显示与调试
二值化结果、中线、元素区域、框中心等中间信息均叠加显示在屏幕上，便于实时观察算法运行状态；通过菜单可调整曝光时间与二值化阈值，显著缩短现场标定与调试周期。
5.3 GPS导航算法
5.3.1 总体设计思路
室外场地范围大、路径复杂，仅靠摄像头难以获得全局位置信息。本设计引入 双频GPS卫星定位模块和高增益天线实现航点级全局导航，并与视觉局部识别、姿态稳定控制融合：双频GPS卫星定位模块负责“车在哪里、去往哪个
航点、朝哪个方向走”的全局判断，姿态传感器与摄像头负责“车身是否平衡、当前元素是什么、如何通过”的局部执行。两者经统一控制调度融合，实现长距离循迹与复杂元素穿越。

5.3.2 GPS数据接收与解析
双频GPS卫星定位模块通过串口输出定位数据，接收中断按协议解析出经纬度等信息，解析完成后置位数据更新标志；主循环检测到标志后读取最新定位进行导航解算，保证定位数据的实时性与完整性。
5.3.3 航点导航与控制闭环
路径由最多 30 个航点组成，每个航点可独立配置到达判定距离、元素类型、速度档位等属性，相邻航点构成一个航段。导航过程中实时计算车体当前位置与目标航点的方位角和距离，距离小于设定阈值时判定到达并切换至下一航点。发车瞬间记录车体初始航向作为偏移量，将地理方位角转换到车体系下的相对方位角，再与当前航向作差得到航向偏差。航向偏差经外环 PID 运算得到期望转向角速度，内环角速度环对陀螺仪 Z 轴角速度低通滤波后跟踪该期望值，最终转换为左右轮差速，实现平滑转向循迹。
5.3.4 去零漂校准
GPS数据存在静态漂移，直接使用采集坐标会引入系统性误差。发车前在 0 号航点进行静止校准：以当前接收坐标与已存 0 号航点的差值作为整体偏移量，对所有航点统一平移，消除零漂影响；校准结果通过蜂鸣器提示，保证每次发车坐标基准一致。
5.3.5 元素区段管理与速度规划
相邻航点之间的路径被划分为普通航段与元素区段，元素区段的起点与终点即切点。车体到达元素起点时切换至对应元素控制模式（台阶、单边桥、逆台阶、颠簸路段、定点排雷、自旋、转弯等）；进入转弯或自旋前，根据剩余距离按比例提前减速，保证入弯速度可控；元素结束后恢复巡航速度，继续 GPS 循迹。每个航段可独立配置速度档位，实现“直道加速、弯道与元素减速”的分段速度规划。

5.3.6 航向保持与多源融合
在颠簸路段、视觉丢线或盲区等无法依赖摄像头的情况下，采用 GPS 航向保持：锁定进入元素前的航向，使车体沿固定方向直线穿越。元素内部转向控制可在摄像头误差、锁定航向、GPS 路径三种信源间切换，切换条件由元素状态机统一管理，实现视觉与 GPS 的互补。整个控制过程由固定周期的控制任务统一调度：姿态内环始终运行以保证两轮自平衡，元素/GPS 外环按当前模式选择投入，最终叠加为左右电机差速输出。

开发工具
6.1 开发工具介绍
本车模的程序开发在 IAR Embedded Workbench for ARM（IAR EW）集成开发环境下完成。IAR EW 功能完善、编译效率高，提供了包括 C 编译器、汇编器、链接器以及功能强大的在线仿真调试器在内的完整开发工具链，并通过统一的集成界面将工程管理、编译、下载与调试组合在一起，便于快速开发与问题定位。工程基于逐飞科技提供的 CYT4BB 开源库搭建，采用 C 语言编写，主控芯片为英飞凌 CYT4BB 双核 Cortex-M7 处理器，程序编译、在线仿真与现场调参均在此环境下完成。
调试手段主要依赖三类工具。其一为 IPS 屏幕菜单，发车前通过按键进入菜单，可实时修改 PID 参数、GPS 航点与到点距离、摄像头曝光与二值化阈值等，参数掉电保存，无需重新编译下载；其二为无线调试模块，通过无线串口连接上位机（逐飞助手），可观察状态量、下发与修改参数，便于小车行驶过程中的远程调试；其三为串口监视，将关键数据经串口发送至上位机，配合 VOFA 等波形工具实时观察数据变化趋势，辅助算法分析与参数整定。
6.2 调试过程
调试遵循“设置参数、行驶观察、分析现象、修改参数、再次验证”的闭环流程。让小车行驶并观察姿态、循迹与各元素通过情况，根据现象现场修改参数并反复验证，直到各路段表现稳定。调试顺序为先平衡、再速度、后转向与元素参数。
关键参数说明
主要可调参数按功能分为以下四类，均可在屏幕菜单中调整：
平衡参数：直立角速度环（菜单 Gyro Loop）调节 roll_gyro_pid 的 kp、ki、kd，决定抗扰动能力与动态响应；直立角度环（菜单 Angle Loop）调节 roll_angle_pid 的 kp、ki、kd 以及 mechanical_zero（机械零点），决定回复刚度并补偿安装误差。
速度参数：直立速度环（菜单 Speed Loop）调节 roll_speed_pid 的 kp、ki、kd，以及多档目标速度 target_speed0～target_speed5。

循迹参数：GPS 航向环（菜单 Turn Angle）调节 GPS_pid 的 kp、ki、kd，根据航向偏差输出期望转向角速度；GPS 角速度环（菜单 Turn Gyro）调节 GPS_gyro_pid 的 kp、ki、kd，跟踪期望转向角速度。
EKF 参数：航向由四元数扩展卡尔曼滤波（EKF）解算，其中过程噪声与量测噪声决定航向估计的跟踪速度与平滑程度。

7.1.1 位置式 PID 计算
void Positional_PID(pid_param *pid, float target, float real)
{
    float proportion_value;
    float differential_value;
 
    proportion_value = target - real;
    pid->integrator += (proportion_value * pid->i_value_pro);
    pid->integrator = func_limit_ab(pid->integrator, -pid->i_max, pid->i_max);
    differential_value = proportion_value - pid->e_1;
 
    pid->out = (pid->kp * proportion_value + pid->ki * pid->integrator + pid->kd * differential_value);
    pid->out = func_limit_ab(pid->out, -pid->out_max, pid->out_max);
    pid->e_1 = proportion_value;
}

7.3 GPS 导航算法
7.3.1 航点循迹主流程
void Follow_Track(void)          // 导航循迹函数
{
#if BRIDGE_FORCE_TUNE || STEP_FORCE_TUNE || KM2_FORCE_TUNE || BUMP_FORCE_TUNE || RAMP_FORCE_TUNE || YAW_HOLD_FORCE_TUNE
    /* 室内FORCE调参：跳过航点循迹，避免无点/结束旗把速度清零 */
    return;
#endif
    if (GPS.GL_NUM < 2)
    {
        GPS.start_flag = 0;
        GPS.finish_flag = 1;
        roll_speed_pid.target_speed = 0;
        car.flag.GPS_go_flag = 0;
        return;
    }
    // 旋转中或未开始则不处理GPS
    if ((car.flag.rotate_flag != 0 && car.flag.rotate_flag != 2) || car.flag.GPS_go_flag == 0)
    {
        return;
    }
    /* ramp(逆三级台阶)元素内允许 GPS 循迹回退 */
    GPS.T_latitude  = gnss.latitude;
    GPS.T_longitude = gnss.longitude;
    if (GPS.T_Points_NUM < GPS.GL_NUM)
    {
        double target_lat = GPS.run_latitude[GPS.T_Points_NUM];
        double target_lon = GPS.run_longitude[GPS.T_Points_NUM];
 
        GPS.azimuth = get_two_points_azimuth(GPS.T_latitude, GPS.T_longitude, target_lat, target_lon);
        GPS.dis      = get_two_points_distance(GPS.T_latitude, GPS.T_longitude, 
target_lat, target_lon);
 
        GPS_Rotate_Approach_Update();
        GPS_Turn_Approach_Update();
        point_QH();
 
        if (GPS.T_Points_NUM == 1 && GPS.start_flag == 0)
        {
            double target_lat_1 = GPS.run_latitude[1];
            double target_lon_1 = GPS.run_longitude[1];
 
            GPS.Angle_Z_azimuth_error = get_two_points_azimuth(GPS.T_latitude, GPS.T_longitude, target_lat_1, target_lon_1);
 
            // 抓取起飞时的车头朝向角
            GPS.yaw_offset = ekf_yaw;
 
            GPS.start_flag = 1;
        }
 
        if (GPS.start_flag)
        {
            GPS.azimuth -= GPS.Angle_Z_azimuth_error;
            /* 地理方位顺时针，与EKF航向系镜像：只改相对方位，不动极性 */
            GPS.azimuth = -GPS.azimuth;
        }
 
        Navigation_retroaction();
    }
    else
    {
        GPS.start_flag = 0;
    }
}
7.3.2 航向偏差计算
void Navigation_retroaction(void)
{
    double temp_yaw = ekf_yaw - GPS.yaw_offset;
 
    while (temp_yaw > 180.0)  temp_yaw -= 360.0;
    while (temp_yaw <= -180.0) temp_yaw += 360.0;
 
    GPS.current_yaw = temp_yaw;

   double target_azimuth = GPS.azimuth;
 
    if (target_azimuth > 180.0)
    {
        target_azimuth -= 360.0;
    }
    GPS.error = normalize_angle_360_180(target_azimuth - GPS.current_yaw);
}
