第一章 引言
本文介绍了南京信息工程大学“死腿快跑”队伍参加全国大学生智能汽车竞
赛轮腿穿越组的工作成果。本车以英飞凌 CYT4BB7（CYT4BB 系列，双核
Cortex-M7）微控制器为核心，在逐飞科技 CYT4BB 开源库基础上进行二次开
发，采用两轮无刷电机差速驱动与四路舵机轮腿机构，融合 MT9V03X 灰度摄
像头、IMU963RA 九轴惯性传感器、DL1B 激光测距模块，完成循迹、航点导
航、跳跃越障、上下台阶、单边桥通行等综合科目。报告主要从系统方案、机
械结构、电路设计和软件控制等方面，对本车设计与调试过程进行说明和总结。

第二章 方案设计
本章介绍轮腿智能车的设计思路与总体方案。系统主要由机械结构、传感
模块、控制模块和程序算法四部分构成。
2.1 系统的主要设计方案
本车以英飞凌 CYT4BB7 双核微控制器作为主控，主频配置为 250MHz，
使用 IAREmbeddedWorkbench9.40.1 开发环境，在逐飞科技 CYT4BB 开源库
的基础上进行二次开发。车辆采用两轮差速 + 四腿的轮腿结构：两路无刷电机
通过串口驱动板实现差速行驶和前后俯仰自平衡，四条腿由四路舵机驱动，通
过足端逆运动学解算实现抬腿、跳跃、越障以及单边桥上的左右横滚补偿。传
感方面，MT9V03X 灰度摄像头用于采集赛道线与场景信息，IMU963RA 提供
三轴角速度、加速度和磁力数据用于姿态解算与航向估计，DL1B 激光测距用
于障碍与台阶检测。TFT180 液晶屏与五向按键构成调试交互界面，蜂鸣器用于
状态提示。

第三章 轮腿车机械结构与调整优化
轮腿车的所有控制都建立在机械结构之上。本章介绍车体机械建模、轮腿
机构与重心调整，以及传感器安装方案。
3.1 轮腿车车体机械建模
本车采用两轮差速底盘与四条舵机腿相结合的轮腿结构。轮子半径为 42
cm，两轮间距约 18cm；四条腿分别由左前、左后、右前、右后四路舵机驱动，
基础足端高度设为 38mm、基础足端水平偏移设为 19mm。通过足端坐标到舵
机角度的逆运动学解算，可以独立控制每条腿的抬升与伸缩，实现跳跃、越障
和单边桥等动作。

3.2 轮腿机构与重心调整
3.2.1 足端运动学解算
程序通过 foot_real_xy_to_servo_angle() 将左右足端的 XY 坐标解算为前
后舵机的目标角度。速度环的输出被映射为足端 X 方向的偏移量，使车身在加
速时向前倾、减速时向后仰，同时根据俯仰角偏离平衡零点的程度对前倾量进
行衰减，保证加减速过程中的稳定性。
3.2.2 重心与平衡零点调整
自平衡控制以俯仰角（pitch）作为被控量，平衡零点按不同科目动态切换：
正常行驶约为 -0.82°，跳跃时约为 -1.6°，单边桥时约为 -1.13°，颠簸路段约为
-0.94°。通过调整腿的基础高度、足端水平偏移和横滚角零点，改变整车重心位
置，从而兼顾速度与越障稳定性。

3.3 编码器与测距传感器安装
两路无刷电机内置编码器，编码器、转速和力矩数据通过 UART4 串口回
传，用于速度闭环与里程累加。DL1B 激光测距模块安装于车体前部，用于检
测颠簸路段、台阶和单边桥等前方障碍与地形特征。
3.4 车体重心与电路板安装
主板、电池和舵机的安装位置综合考虑整车重心，尽量降低重心高度并保
持左右对称。电池安装位置与腿部机构的运动范围相互避让，避免在抬腿、跳
跃时产生机械干涉，提高行驶和越障过程的稳定性。

第四章 电路设计说明
4.1 电源管理模块
电源是整车稳定运行的基础。系统电池经稳压电路后分别为主控、传感器、
舵机和电机驱动系统供电，电源方案按负载类型分区供电，以减小舵机大电流
对主控和传感器模拟信号的干扰。

IMU963RA 提供三轴角速度、加速度和磁力数据；GNSS 通过 UART2 串口输
出定位信息；DL1B 输出前方距离信息。各传感器接口与主控连接如图4.1 所

第五章 智能车控制软件设计说明
5.1 软件设计总体框架
系统上电后由 CM7_0 核执行 clock_init() 完成 250 MHz 时钟与系统初
始化，随后调用 All_init() 完成各外设初始化，进入主循环执行菜单处理、导航
模式切换、图像处理、航点导航、距离检测、目标速度与目标转向计算等任务。
CM7_1 核当前作为预留辅助核心，双核通过共享 RAM 中的 shared_data 结构
体（地址 0x28001000）以及 Bin_Image、mt9v03x_image 两个图像缓存区交换
数据。1ms 的 PIT 中断内执行 IMU 解算、速度更新和平衡控制，10.2ms 的
PIT 中断内执行编码器里程累加。
5.2 传感器信息采集及处理
5.2.1 摄像头采集与图像处理
MT9V03X 采集 188×120 灰度图像后，通过 Otsu/自适应阈值进行二值化，
随后进行边线提取、透视变换、等距采样和角点检测，识别台阶、桥面等场景，
并利用纯跟踪算法计算 pure_angle 用于巡线转向控制。
5.2.2 IMU 姿态解算
IMU963RA 输出三轴角速度和加速度，先经过零偏标定、低通滤波与加速
度卡尔曼滤波，再采用 Mahony/互补滤波算法解算四元数，得到 roll、pitch、
yaw 姿态角。姿态数据同时用于平衡控制、转向控制和航向推算。
5.2.3 激光测距与障碍台阶检测
DL1B 激光测距数据经中值滤波和有效性判断后用于颠簸路段、台阶和单
边桥等元素的进入/退出判定。结合里程距离阈值，实现特殊元素的自动切换与
完成标记。
5.2.4 GNSS 定位与组合导航
TAU1201GNSS 解析经纬度后转换为平面坐标，并与基于 IMU 航向和编
码器里程的航位推算结果进行卡尔曼滤波融合，得到更平滑的融合位置与航向，
用于户外航点导航。

5.2.5 路径规划与航点导航
系统维护一个 checkpoint 航点列表，每个航点包含目标坐标、类型（旋转
点、终点、掉头点、转弯点、元素点）等信息。根据编码器里程和 IMU 航向实
时更新车辆 XY 位置，计算到下一航点的方位角和距离，并在转弯处使用贝塞
尔曲线进行平滑过渡。路径点可保存至内部 Flash 并回放。
5.3 速度控制部分
系统根据科目和当前特殊元素动态设置目标速度：跳跃阶段约 360，旋转
群约 60，颠簸路段约 210（支持倒车脱困），单边桥按配置速度运行，正常路
段在 360～700 之间切换。速度环将目标速度与实际平均速度的误差经 PID 计
算后映射为足端水平偏移，实现车身前倾加速、后仰减速。
5.4 PID 算法介绍
在现代自动控制技术中应用最广泛的调节方式是PID 调控方式，该控制原
理如下图5.1 所示。在本课题中智能车的转向、速度都不同程度的引用PID 算法

参数调整过程，但是可行性算高。相比较其他控制方式占很大优势。

PID 算法中各个参数的作用如下：
比例调节（Kp）：对偏差的快速调整，智能车测量得实际值与设定允许值
产生偏比例控制立即对此时刻误差发生控制，根据偏差的大小直接按比例的输
出相应的控制。朝着偏差减少方向变化。由此可见偏差调整的快慢取决于Kp 比
例值得大小，Kp值越大系统调整速度就越快，但是容易导致系统过调，使得系
统震荡，稳定性下降。比例值过小，使得系统震荡减小，但是偏差调节变慢，
不利于一些追求速度的系统。
积分调节（Ki）：对系统的历史偏差积分计算，当系统一直存在偏差时，
积分调节将对系统进行调整，调整直到没有误差才会停止。积分调节的强度取
决于积分时间Ti,，Ti越小，积分调整强度越大，反之越小。
微分调节（Kd）：微分是反映一个系统的偏差变化率，表明偏差的变化趋
势，由此可见它是能超前比例和和积分调节，但是微分是反映变化率，当偏差
没有发生变化时，微分作用也不存在，所以不可单独使用，必须结合使用。
数字PID控制算法通常分为位置式PID控制算法和增量式PID控制算法。
1、位置式PID
位置式 PID 中，由于计算机输出的 u(k)直接去控制执行机构(如阀
门)u(k)的值和执行机构的位置(如阀门开度)是一一对应的，所以通常
称公式2 为位置式PID 控制算法。

位置式PID 控制算法的缺点是：
由于全量输出，所以每次输出均与过去的状态有关，计算时要对过去
e(k)进行累加，计算机工作量大；而且因为计算机输出的u(k)对应的是
执行机构的实际位置，如计算机出现故障，u(k)的大幅度变化，会引
起执行机构位置的大幅度变化，这种情况往往是生产实践中不允许的，
在某些场合，还可能造成严重的生产事故。因而产生了增量式PID 控
制的控制算法，所谓增量式PID 是指数字控制器的输出只是控制量的
增量 ( )u k 。

void Bezier_change_for_turn(float bezier_t)
{
bezier_turn_point.turn_target_x=(1-bezier_t)*(1-bezier_t)*bezier_turn_point.x1+2*(1-bezier_t)*bezier
_t*bezier_turn_point.x2+bezier_t*bezier_t*bezier_turn_point.x3;
bezier_turn_point.turn_target_y=(1-bezier_t)*(1-bezier_t)*bezier_turn_point.y1+2*(1-bezier_t)*bezier
_t*bezier_turn_point.y2+bezier_t*bezier_t*bezier_turn_point.y3;
}
float get_bezier_t(void)
{
float vx = bezier_turn_point.x3 - bezier_turn_point.x1;
float vy = bezier_turn_point.y3 - bezier_turn_point.y1;
float wx = internal_data_now.x_pos - bezier_turn_point.x1;
float wy = internal_data_now.y_pos - bezier_turn_point.y1;
float len2 = vx * vx + vy * vy;
if(len2 < 1.0f)
{
return 0.0f;
}
float t = (wx * vx + wy * vy) / len2;
if(t < 0.0f) t = 0.0f;
XVI
if(t > 1.0f) t = 1.0f;
return t;
}
void load_bezier_turn_point(int index, float turn_radius)
{
bezier_turn_point.x1 = internal_data_now.x_pos;
bezier_turn_point.y1 = internal_data_now.y_pos;
bezier_turn_point.x2 = check_point[index].x;
bezier_turn_point.y2 = check_point[index].y;

check_point[index].y);
bezier_turn_point.x3 = check_point[index].x + turn_radius * sinf(yaw);
bezier_turn_point.y3 = check_point[index].y + turn_radius * cosf(yaw);
}
