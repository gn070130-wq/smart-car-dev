摘  要
本设计以第二十一届全国大学生智能汽车竞赛轮腿穿越组赛题要求为背景，结合3D打印技术、PCB制板技术等制作一辆以英飞凌TRAVEO单片机为核心控制单元的双足轮腿车模。车模融合轮式高效行驶与腿式主动越障能力，以逐飞总钻风摄像头视觉识别与逐飞IMU660RC六轴惯性传感器为核心感知手段，通过惯性导航实现车身姿态实时解算、航位推算与平衡控制；驱动采用DBS3620无刷电机搭配自制电机驱动板，转向与轮腿关节采用逐飞BDS300舵机。在轮腿协同控制策略下，车模完成室外操场赛道的全部比赛科目：科目一行进绕桩（直行至掉头区后穿越锥桶间隙返回）、科目二定点排雷（依据惯导与视觉定位依次进入雷区并自旋两周）、科目三颠簸路段（通过交错单边桥、颠簸路肩、草地及三级台阶坡道等复杂地形）。该轮腿车模系统展现了良好的运动稳定性、地形适应性与任务智能化水平，可为轮腿混合移动机器人及户外自主导航系统的后续研究提供参考经验。

第一章  引言
1.1 智能车大赛介绍
全国大学生智能汽车竞赛受教育部高等教育司委托，由教育部高等自动化专业教学指导分委员会主办。该竞赛以智能汽车为研究对象，是面向全国大学生的创意性科技竞赛与探索性工程实践活动，是教育部倡导的大学生科技竞赛之一，旨在加强大学生实践、创新能力和团队精神的培养，促进高等教育教学改革。
该竞赛以"立足培养，重在参与，鼓励探索，追求卓越"为指导思想，旨在促进高等学校素质教育，培养大学生的综合知识运用能力、基本工程实践能力和创新意识，激发大学生从事科学研究与探索的兴趣和潜能，倡导理论联系实际、求真务实的学风和团队协作的人文精神，为优秀人才的脱颖而出创造条件。
竞赛过程包括理论设计、实际制作、整车调试、现场比赛等环节，要求学生组成团队协同工作，初步体会一个工程性研究开发项目从设计到实现的全过程。该竞赛融科学性、趣味性和观赏性为一体，以汽车电子为背景，涵盖自动控制、模式识别、传感技术、电子、电气、计算机、机械与汽车等多学科专业。
1.2 第二十一届轮腿穿越组规则介绍
第二十一届全国大学生智能汽车竞赛新增轮腿穿越组，比赛环境为室外操场赛道。要求制作一辆双足轮腿车模，自制车轮直径小于等于12厘米，完成室外全部或部分比赛科目。微控制器采用英飞凌TRAVEO平台，传感器包括摄像头和IMU惯性测量单元，每支队伍四人参赛。
比赛科目包括以下三个部分：
（1）科目1：行进绕桩
该科目考察车模平台行进特性。要求车模通过IMU惯导、视觉识别或其他导航方式，在规定场地内完成直行和绕桩科目。车模出发后先直行到掉头区，然后在返回路径中穿越锥桶给定的间隙。有N个锥桶就有N-1个间隙，需要完成N-1次穿越过程；锥桶排列不一定在一条直线上，两个锥桶之间的最小距离为1.5米。
（2）科目2：定点排雷
该科目考察车模定位特性以及定点旋转功能。场地内预先铺设若干雷区，通过白色胶带粘贴成边长为100厘米的方框，白色胶带宽度为10厘米。车模通过雷区的顺序没有规定，在雷区内旋转的方向没有规定，但至少旋转两周。车模在雷区旋转过程中，不允许车轮冲出白色边框。
（3）科目3：颠簸路段
该科目考察轮腿车模车身姿态控制以及跳跃功能。比赛场地内设置交错单边桥、颠簸路段、草地、三级台阶坡道等元素。车模从出发区出发，依次通过上述路段元素，并在掉头区返回；通过颠簸赛道元素的顺序可以自行选择，其中三级台阶坡道元素需要正反两个方向各通过一次。
1.3 报告内容
本报告围绕第二十一届全国大学生智能汽车竞赛轮腿穿越组的双足轮腿车模设计制作过程展开，系统介绍车模的机械结构设计、硬件电路设计、软件算法方案以及调试过程。具体包括：第二章介绍车模整体机械结构与轮腿机构设计；第三章介绍电源、驱动、传感器等硬件电路设计；第四章详细阐述IMU姿态解算、惯性导航、PID控制、轮腿协同控制及三个科目的实现策略；第五章介绍开发环境与调试工具；第六章对整车设计进行总结与展望。
第二章  机械结构设计
智能车的核心是控制策略和算法，但机械结构也是限制车模运动性能的关键瓶颈。轮腿穿越组相较于传统组别，对机械结构提出了更高的要求——车模不仅需要在平地上高速行驶，还需要具备跨越台阶、通过颠簸路面的能力。优秀的机械结构可以保证轮腿协同运动的顺畅性，确保重心分布合理，为平衡控制和越障动作提供可靠的物理基础。
2.1 整体结构
本设计采用双足轮腿结构，车模整体由左右两个对称的轮腿单元组成。每个轮腿单元包含一个驱动轮和一个腿关节，腿关节由舵机驱动，可实现腿部的屈伸动作，用于调整车身高度和跨越障碍。车身中部安装主控板、电源模块和传感器，整体采用对称布局，确保重心位于车体中轴线上。
电池布置于车身下部，降低整车重心，提高行驶稳定性。主控板和驱动板分层布置于车身中部，便于接线和散热。逐飞总钻风摄像头安装于车身前部上方，视野覆盖车前区域；IMU惯性传感器安装于车身重心位置，以获取最准确的姿态数据。
（1）电池处于车身下部，降低重心，提高行驶稳定性。
（2）硬件采用居中对称分布，确保重心贴近中线。
（3）摄像头与IMU位置经过优化，保证感知精度。
2.2 舵机与电机选型
舵机和电机是轮腿车模的核心执行器，其性能直接影响车模的运动表现。
（1）电机选型
驱动轮采用DBS3620无刷电机。该电机为外转子无刷电机，额定扭矩0.12N·m，转速常数500KV（12V时空载转速6000rpm），电压范围7.4V~12.4V，堵转电流12A，空载电流0.4A，电机槽数12槽、极数14极，重量约77.4g。该电机具有扭矩密度高、响应快、效率高的特点，能够为车模提供充足的驱动力，满足室外操场赛道的高速行驶和越障需求。电机本身不带驱动板，由本设计自制的三相无刷电机驱动板进行驱动控制。
（2）舵机选型
腿关节和转向采用逐飞科技BDS300舵机。该舵机为数字舵机，扭矩大、精度高、响应速度快，能够快速响应控制指令，实现腿关节的精确屈伸和车身姿态调整。舵机工作电压范围宽，适配车模电源系统，在大负载下仍能保持稳定输出。

第三章  硬件电路设计
本车模的全部硬件电路均为自主设计，包括主控板、电机驱动板、电源管理、传感器接口和调试接口等。通过Altium Designer进行原理图设计和PCB布线，采用制板厂打样焊接完成。自主设计的硬件电路能够根据轮腿车模的实际需求进行针对性优化，提高系统集成度和可靠性。
3.1 电源模块设计
电源模块为系统其他各个模块提供所需要的电源，是智能车的命脉。电源模块的可靠性决定了车模的其他部分能否正常发挥作用，电源的不稳定将导致单片机复位、传感器不能正常工作等严重问题，因此稳定可靠的电源模块对车模尤为重要。
本设计采用1250mAh、3C放电倍率的锂电池作为动力源，满电电压约12.4V，可直接给无刷电机供电。系统需要多种电压等级，分别通过不同的稳压电路为各模块供电。
（1）电池采用1250mAh锂电池，3C放电倍率，满电电压12.4V，直接给DBS3620无刷电机供电。
（2）舵机电源：采用SP1N28STER同步降压芯片，将12V电池电压降压为6V，为4个BDS300数字舵机供电。舵机在大负载瞬间电流较大，因此在输入端和输出端都并联了大容量电解电容进行滤波。
（3）5V电源：用于摄像头、无线串口等模块供电。
（4）3.3V电源：采用开关稳压芯片输出3.3V，给单片机、IPS屏幕以及IMU惯性传感器等数字电路供电。
舵机电源部分是整个电源系统中设计的重点。由于BDS300数字舵机在动作瞬间会产生较大的电流冲击，如果电源纹波过大，会导致主控板复位或传感器数据异常。因此我们在舵机电源输入端设计了防反接保护和大容量滤波电路，在输出端也设计了LC滤波电路，确保舵机供电稳定。
如图3.1所示，舵机电源输入端采用SS14肖特基二极管作为防反接保护，防止电池正负极接反时损坏后级电路。二极管后并联两个220uF电解电容，用于滤除电池端的电压波动和电机产生的高频干扰。

图3.1 舵机电源输入滤波与防反接电路
如图3.2所示，舵机电源降压电路采用SP1N28STER同步降压芯片，输入电压12V，输出电压通过反馈电阻分压设定为6V。芯片内置MOS管，转换效率高，最大输出电流可达5A，完全满足4个舵机同时工作的需求。输出端采用4.7uH功率电感配合47uF和220uF电容进行LC滤波，输出电压纹波小。反馈电路中使用50K电位器可以微调输出电压，确保4个舵机都能工作在最佳电压。电路还配有LED电源指示灯，便于直观判断舵机电源是否正常。

图3.2 舵机电源降压电路（SP1N28STER）
如图3.3所示，5V电源采用LM2940低压差线性稳压芯片，输入12V，输出5V。LM2940是一款固定输出的LDO稳压器，具有输出电流大、纹波小、静态电流低的特点，适合为摄像头和无线串口等对电源噪声敏感的器件供电。输入端和输出端各并联22uF电解电容和104（0.1uF）陶瓷电容，分别用于滤除低频和高频干扰。

图3.3 5V电源电路原理图（LM2940）
如图3.4所示，3.3V电源采用低压差线性稳压芯片，输入5V，输出3.3V。芯片带有使能引脚（EN），可由主控芯片控制电源开关。输入端并联104陶瓷电容，输出端并联104陶瓷电容和10uF电解电容，确保3.3V数字电源的稳定。3.3V电源主要为CYT4BB单片机、IPS屏幕、IMU660RC惯性传感器等数字电路供电。

3.2 主控与驱动电路设计
主控电路以英飞凌TRAVEO系列单片机为核心，集成最小系统电路（包括晶振电路、复位电路、下载调试接口）、电源管理电路、传感器接口（SPI/I2C/UART）、电机驱动接口和舵机驱动接口。主控板负责采集传感器数据、运行控制算法、输出PWM控制信号。
电机驱动电路为自主设计的三相无刷电机驱动板，采用MOSFET构成三相全桥逆变电路，通过主控板输出的PWM信号控制电机的转速和转向。驱动板集成了电流采样电路，用于电机电流闭环控制和过流保护。舵机驱动采用逐飞BDS300舵机，通过PWM信号控制角度。主控板上集成了多路PWM输出通道，可同时控制两个驱动电机和多个舵机。
电机转速和位置反馈采用TLE5012BE磁编码器。该芯片是一款高精度360度角度传感器，通过SPI接口与驱动板单片机通信，采样率高、抗干扰能力强，能够实时检测电机转子的角度和转速，为电机闭环控制和航位推算提供准确的反馈数据。磁编码器电路包括RT9013-33稳压芯片（将5V转为3.3V为磁编码器供电）、SPI接口串联电阻（用于信号匹配和限流）和去耦滤波电容，通过6P ZH1.5MM连接器与驱动板连接。
3.3 调试电路设计
调试电路在车模调试过程中是必不可少的，可以直观显示智能车的参数和状态，并且方便修改参数。调试电路包括五轴按键、无线串口和IPS屏幕三个部分。
（1）五轴按键：用于菜单导航、参数调整和模式切换，操作便捷，节省空间。
（2）无线串口：通过2.4G无线模块与上位机通信，实现数据实时回传和参数在线修改，便于调试时观察PID参数、姿态角、速度等关键数据。
（3）IPS屏幕：实时显示车模运行状态、传感器数据和菜单界面，比赛时也可用于快速修改参数。
3.4 电路原理图与PCB设计
本车模的硬件电路分为主控板和电机驱动板两块PCB，均为自主设计。主控板集成了核心MCU、电源管理、传感器接口、舵机接口和调试电路；电机驱动板集成了驱动MCU、三相无刷电机驱动电路和电源降压电路。两块板之间通过UART串口通信，主控板发送速度和方向指令，驱动板接收后执行电机控制。

第四章  软件方案
软件系统是轮腿车模的大脑，负责传感器数据采集、姿态解算、惯性导航、路径规划、运动控制和科目任务执行。本章将详细介绍IMU姿态采集与解算、惯性导航与航位推算、赛道路径规划、PID控制算法、轮腿平衡与越障控制以及三个科目的具体实现策略。
4.1 IMU姿态采集与解算
IMU（惯性测量单元）是轮腿车模平衡控制和惯性导航的核心传感器。本设计采用逐飞IMU660RC六轴惯性传感器，集成三轴陀螺仪和三轴加速度计，通过SPI接口与主控板通信，采样频率为1kHz。
陀螺仪测量的是角速度，需要通过积分得到角度，但积分过程中会产生累积误差和零偏漂移；加速度计测量的是重力加速度，可以通过反正切函数计算出静态倾角，但在运动状态下会受到车体加速度的干扰。因此本设计采用四元数扩展卡尔曼滤波（EKF）算法，融合陀螺仪和加速度计的数据，得到准确的姿态角（俯仰角、横滚角、偏航角）。
四元数EKF算法以四元数表示姿态，通过陀螺仪数据进行状态预测，通过加速度计数据进行观测更新，能够有效抑制陀螺仪的零偏漂移和加速度计的运动干扰。算法初始化参数为：过程噪声协方差6、测量噪声协方差200000、陀螺仪置信度0.997、加速度计置信度0.002。
系统上电后首先进行陀螺仪零偏校准，采集2000次静止状态下的陀螺仪数据，计算平均值作为零偏补偿值，校准过程中若检测到运动则重新采集。校准完成后，利用加速度计计算初始姿态角，初始化四元数，避免上电时姿态收敛过程对偏航角的干扰。
4.2 IMU惯性导航与航位推算
由于轮腿穿越组比赛在室外操场进行，且本设计不使用GPS，采用纯IMU惯性导航结合视觉校正的方案实现车模定位。
惯性导航的基本原理是：通过加速度计测量车体加速度，对加速度进行一次积分得到速度，对速度进行二次积分得到位移；通过陀螺仪测量角速度，对角速度积分得到角度和航向。航位推算（Dead Reckoning）是一种基于已知初始位置和运动估计的定位方法，结合车轮编码器的速度信息和IMU的航向信息，可以推算出车模的实时位置。
由于纯惯性导航存在累积误差，需要通过视觉识别进行周期性校正。当摄像头识别到已知地标（如雷区方框、锥桶排列）时，根据视觉定位结果修正惯性导航的累积误差，实现长时间稳定定位。
4.3 赛道路径规划
路径规划是车模自主导航的关键环节。根据比赛科目要求，车模需要在不同场景下选择最优路径。本设计采用预瞄点算法，在当前位置前方设定一个预瞄点，根据预瞄点的位置计算转向角度，实现平滑转向。
（1）科目一绕桩：基于视觉识别锥桶位置，规划蛇形穿越路径，确保每次都从锥桶间隙通过。
（2）科目二排雷：基于惯导定位和视觉识别雷区方框，规划依次进入各个雷区的路径，在雷区内完成自旋两周。
（3）科目三颠簸路段：根据赛道元素布局，规划通过顺序，在台阶处触发跳跃动作，在单边桥处保持直线行驶。
4.4 PID运动控制算法
PID控制可以说是整个智能车软件里最基础、但也是最让人头疼的部分了。说它基础，是因为原理就三个参数——比例、积分、微分，课本上都讲过；说它头疼，是因为真到了实车调试的时候，才发现理论和实践差距有多大。我们一开始以为把三个参数凑一凑车就能跑起来，结果第一次上车的时候车直接往后仰着翻了，才意识到轮腿车的平衡控制远比想象中复杂。
轮腿车跟传统的两轮平衡车不一样，它多了腿关节这个自由度，车身高度可以变，重心也会跟着变，这就导致平衡控制的难度大大增加。我们试过只用一个角度环来控制，结果车要么抖得厉害，要么响应太慢根本站不住。后来参考了逐飞的例程和一些平衡车的资料，才慢慢摸索出多环串级的控制思路——用内环保证响应速度，外环保证控制精度，一层层嵌套起来。
经过反复调试和优化，我们最终的控制系统采用多环串级控制策略，其中最核心的是以下4个PID控制环：平衡角度环、平衡角速度环、速度环和转向环。此外还有横滚角补偿环、偏航角环、自旋环等辅助控制环，用于特定场景下的姿态修正和任务执行。下面重点介绍4个核心PID环的作用和调试体会。
（1）平衡角度P环：这是最核心的一个环，根据IMU解算出来的俯仰角和目标角度的偏差，直接计算电机应该输出多大的扭矩。我们一开始用的是PID，但后来发现积分项在平衡控制里容易导致超调和振荡，就把积分去掉了，只用P控制。这个P参数的整定特别关键，太小了车站不起来，太大了车会前后抖，我们是一点点往上加，加到刚好不抖再往回退一点。
（2）平衡角速度PD环：这是角度环里面的内环，直接用陀螺仪测的角速度做反馈。角速度的响应比角度快得多，加了这个内环之后，车的抗干扰能力明显增强了，用手推一下车能很快恢复平衡。我们调试的时候发现，D参数对抑制抖动很有效，但太大了又会引入噪声，所以要配合低通滤波一起用。
（3）速度PID环：光有角度环和角速度环还不够，车虽然能站住，但会越跑越快停不下来。速度环的作用就是通过编码器反馈的实际速度，来调整目标平衡角度——想加速就让车身往前倾一点，想减速就让车身往后仰一点。这个环我们用了完整的PID，积分项用来消除稳态误差，让车能稳定在目标速度上。
（4）转向P环：用来控制车的转向角度。我们用的是差速转向，通过左右轮速度差来实现转弯。这个P环的参数也很关键，太小了转弯不灵活，太大了又会转过头。我们是在绕桩科目里反复调试这个参数的。除了以上4个核心环之外，横滚角PI环用于过单边桥时的左右平衡，偏航角环用于航向保持，自旋PID环用于科目二的定点自旋，这些辅助环在特定场景下发挥作用。
4.4.1 位置式PID
位置式PID的输出是控制量的绝对值，跟过去所有的误差都有关系。这种算法的好处是控制精度高，能消除稳态误差，但缺点是计算量相对大一些，而且一旦出错影响范围也大。我们在舵机角度控制、转向控制、位置控制这些对位置精度要求高的场合用的是位置式PID。它的离散表达式如公式1所示。
u(k) = Kp×e(k) + Ki×Σe(i) + Kd×(e(k)-e(k-1))    （公式1）
公式里Kp是比例系数，直接决定响应的快慢；Ki是积分系数，用来消除稳态误差，但太大了会导致超调和积分饱和；Kd是微分系数，用来预测误差变化趋势，抑制超调。我们调试的时候一般先调Kp，再调Ki，最后调Kd，这个顺序比较稳妥。
4.4.2 增量式PID
增量式PID的输出是控制量的增量，只跟最近几次的误差有关。这种算法的好处是计算量小，误动作的影响也小，而且不容易产生积分饱和。我们在电机速度控制这些场合用的是增量式PID。它的离散表达式如公式2所示。
Δu(k) = Kp×(e(k)-e(k-1)) + Ki×e(k) + Kd×(e(k)-2e(k-1)+e(k-2))    （公式2）
增量式PID还有一个好处就是切换手动/自动的时候冲击比较小，因为输出是慢慢累加的。不过它也有缺点，就是对积分项的截断误差比较敏感，而且不能直接得到控制量的绝对值，需要累加才行。我们在实际使用中，电机的PWM输出就是用增量式PID算出来的增量一点点累加得到的。
4.4.3 PID参数整定
PID参数整定真的是整个调试过程中最费时间的部分了，我们前前后后调了差不多一个星期才调出比较满意的参数。一开始我们照着课本上的临界比例度法来调，先把Ki和Kd设为0，慢慢增大Kp直到系统出现等幅振荡，然后根据经验公式算Ki和Kd的初值。但实车跟理论仿真差太多了，算出来的参数上车根本不能用，还是得靠试凑法一点点调。
我们总结出来的调试经验是这样的：首先调平衡角度环，这是基础，必须先让车能稳稳站住。调的时候把车拿在手里，看电机的响应，P太小了车会软绵绵的没力气，P太大了车会前后高频抖动。找到刚好不抖的那个点，再稍微往小调一点留些余量。角度环调好之后，再调速度环，让车能稳定在某个速度上行驶，不会越跑越快或者越跑越慢。最后才调位置环、转向环这些外环。
调试的时候我们用了逐飞的无线串口模块，把姿态角、速度、PWM输出这些数据实时回传到电脑上，用VOFA软件画曲线。看曲线调参数比凭感觉调效率高太多了，能清楚地看到超调量、响应时间、稳态误差这些指标。比如超调大了就减小Kp或者增大Kd，响应慢了就增大Kp，稳态误差大了就加一点Ki。
除了无线串口，我们还在车模上装了IPS屏幕和五轴按键，可以不用接电脑直接在车上改参数。这个在室外调试的时候特别方便，蹲在车旁边就能调，不用来回跑电脑。我们把常用的PID参数都做成了菜单，通过按键选择和修改，改完直接生效，调试效率提高了不少。
另外还有一点很重要，就是参数整定的时候一定要在实际的比赛场地上调。我们一开始在实验室的地砖上调得好好的，一到操场的塑胶跑道上就不行了，因为地面摩擦力不一样，电机的负载特性也变了。后来我们专门去操场调了好几次，才最终确定了比赛用的参数。
总的来说，PID参数整定没有什么捷径，就是耐心调、反复试，多观察数据曲线，多总结经验。每个车的机械结构、重量分布、电机特性都不一样，别人的参数只能做参考，最终还是得靠自己调出适合自己车的参数。
4.5 轮腿平衡与越障控制
轮腿车模的平衡控制类似于两轮平衡车，但增加了腿关节的自由度，控制更为复杂。本设计采用多环串级控制策略，结合逆运动学求解，实现车模的平衡、速度、转向和越障控制。
（1）平衡控制：采用串级PID控制，内环为角速度环（陀螺仪PD），外环为角度环（平衡角度P）。根据IMU解算的俯仰角，计算电机需要输出的扭矩，使车模保持直立。
（2）速度控制：在平衡控制的基础上加入速度环（编码器PD+速度PID），通过调整平衡角度来控制车速。需要加速时车身适当前倾，需要减速时车身后仰。速度采用梯形加减速控制，限制加速度变化率，保证行驶平稳。
（3）转向控制：通过左右轮差速实现转向，同时配合舵机调整腿关节角度，使转向更平稳。偏航P环控制转向角度，横滚角PI环维持车身左右平衡。
（4）逆运动学求解：根据目标车身高度和姿态角，通过逆运动学计算左右腿关节的舵机角度，实现车身高度的精确控制和姿态调整。
（5）越障控制：当检测到前方有台阶或障碍时触发越障动作。腿关节伸展抬高车身，同时电机输出足够扭矩使车轮爬上台阶。下台阶时腿关节缓慢收缩，配合电机减速实现平稳落地。
（6）跳跃控制：在需要跳跃下台阶时，先通过腿关节快速收缩储存能量，然后瞬间伸展使车模获得向上的速度，实现跳跃。落地时通过加速度模长检测判断落地状态。
电机驱动采用串口通信方式，主控板通过UART向自制电机驱动板发送控制指令，驱动板接收后输出三相PWM信号控制无刷电机。这种方式简化了主控板与驱动板之间的接线，提高了系统可靠性。
4.6 科目任务实现策略
4.6.1 行进绕桩科目
（1）出发后直行至掉头区，通过惯导记录行驶距离。
（2）在掉头区完成180度转向。
（3）返回过程中通过视觉识别锥桶位置，规划蛇形路径。
（4）每次穿越锥桶间隙时，通过视觉和惯导确认位置，确保不遗漏、不碰撞。
4.6.2 定点排雷科目
（1）通过惯导和视觉识别定位第一个雷区。
（2）进入雷区方框中心位置。
（3）在雷区内自旋至少两周，通过IMU偏航角控制旋转角度。
（4）旋转过程中实时检测车轮位置，确保不冲出白线。
（5）依次完成所有雷区。
4.6.3 颠簸路段科目
（1）交错单边桥：保持直线行驶，通过IMU横滚角检测车身倾斜，调整左右轮速度保持平衡，不允许跳跃通过。
（2）颠簸路段：降低车速，腿关节适当伸展增加缓冲，保持车身稳定。
（3）草地：增加电机输出扭矩，克服草地阻力。
（4）三级台阶坡道：上台阶时腿关节伸展配合电机扭矩逐级爬升；下台阶时采用跳跃方式，腿关节先收缩后快速伸展实现跳跃下落。正反方向各通过一次。
4.7 辅助调试程序设计
辅助调试程序用于车模开发调试阶段，提高调试效率。主要功能包括：
（1）参数实时显示：通过IPS屏幕显示姿态角、速度、PID参数等关键数据。
（2）参数在线修改：通过五轴按键或无线串口修改PID参数、阈值等，无需重新烧录程序。
（3）数据记录与回传：通过无线串口将运行数据回传到上位机，用于分析和优化。
（4）模式切换：支持平衡模式、调试模式、比赛模式等多种模式切换。
第五章  系统开发环境与车模调试
5.1 开发环境介绍
本设计采用英飞凌TRAVEO系列单片机，开发环境使用英飞凌官方提供的集成开发环境。软件开发采用C语言编写，通过J-Link仿真器进行程序下载和在线调试。
开发流程包括：工程创建、代码编写、编译链接、下载调试。在调试过程中，通过仿真器可以实时查看变量值、设置断点、单步执行，便于定位和解决问题。
5.2 人机交互工具
为了提高调试效率，本设计配备了完善的人机交互工具，包括IPS屏幕、五轴按键和无线串口。
（1）IPS屏幕：实时显示车模运行状态，包括姿态角、速度、电池电压、当前模式等信息，同时提供菜单界面用于参数设置。
（2）五轴按键：支持上下左右中五个方向操作，用于菜单导航、参数增减、模式切换等，操作便捷。
（3）无线串口：通过2.4G无线模块与上位机通信，实现数据实时回传和参数在线修改。上位机软件可以绘制姿态角、速度等数据的实时曲线，便于分析系统动态特性。
在调试过程中，先通过无线串口观察数据曲线，调整PID参数使系统稳定；然后通过IPS屏幕和五轴按键在车模上快速微调参数；最后进行实际跑车测试，验证控制效果。
第六章  总结
6.1 车模总结
本设计针对第二十一届全国大学生智能汽车竞赛轮腿穿越组的赛题要求，设计并制作了一辆双足轮腿车模。车模以英飞凌TRAVEO单片机为核心控制单元，采用逐飞IMU660RC六轴惯性传感器实现姿态解算和惯性导航，配备逐飞总钻风摄像头进行视觉识别，驱动采用DBS3620无刷电机搭配自制电机驱动板，转向与轮腿关节采用逐飞BDS300舵机。
在机械结构方面，采用双足轮腿对称布局，通过3D打印制作轮腿连接件，实现了腿部屈伸和越障功能。在硬件方面，设计了多路稳压电源、电机驱动、传感器接口和调试电路，保证系统稳定可靠。在软件方面，实现了IMU姿态解算、惯性导航、PID串级控制、轮腿平衡与越障控制以及三个比赛科目的任务策略。
经过调试，车模能够在平地上稳定行驶，具备一定的越障能力，可以完成行进绕桩、定点排雷和颠簸路段等比赛科目。
6.2 工作综述
在本次智能车竞赛的准备过程中，团队成员分工协作，完成了从方案设计、机械加工、硬件制板到软件编程、整车调试的全部工作。通过这次比赛，我们深入学习了自动控制、传感器融合、惯性导航、机械设计等多学科知识，提高了工程实践能力和团队协作能力。
同时，我们也认识到车模仍存在一些不足之处：惯性导航的累积误差仍需进一步优化，轮腿越障的稳定性有待提高，视觉识别的准确率和速度还可以提升。在后续的工作中，我们将针对这些问题进行改进，进一步提升车模的性能。

附录A：主要程序源代码
本附录列出轮腿车模平衡控制的核心源代码，注释已翻译为中文。代码包含角度环、角速度环、速度环三个核心PID控制环的实现和参数初始化，是车模平衡站立和运动控制的核心算法。
// ====== 全局变量定义 ======
int16 motor_pwm = 0;       // 电机PWM输出
int16 balance_pwm = 0;     // 平衡PWM输出
float Exceptspeed = 180.0; // 期望速度

// PID结构体（定义在pid.h中）
closed_loop_struct balance_angle_p;        // 角度环（俯仰）
closed_loop_struct balance_gyro_weizhi_pd; // 角速度环（位置式）
closed_loop_struct balance_velocity_pid;   // 速度环

/*------------------------------------------------------------------
  @brief     角度环（位置式P控制）——平衡控制外环
  @param     realangle    实际俯仰角
  @param     Expectangle  期望俯仰角
  @return    角度环输出（作为角速度环的期望输入）
------------------------------------------------------------------*/
float balance_angle_P(float realangle, float Expectangle)
{
    float angle_banlance_error;
    balance_angle_p.error = Expectangle - realangle;
    balance_angle_p.i_integral += balance_angle_p.error;
    // 积分限幅，防止积分饱和
    if(balance_angle_p.i_integral < -100)  balance_angle_p.i_integral = -100;
    else if(balance_angle_p.i_integral > 100) balance_angle_p.i_integral = 100;
    // PID计算：P项 + I项 + D项
    angle_banlance_error = balance_angle_p.kp * balance_angle_p.error
                         + balance_angle_p.ki * balance_angle_p.i_integral
                         + balance_angle_p.kd * (balance_angle_p.error - balance_angle_p.last_error);
    balance_angle_p.last_error = balance_angle_p.error;
    return angle_banlance_error;
}

/*------------------------------------------------------------------
  @brief     角速度环（位置式PD控制）——平衡控制内环
  @param     gyro                 实际角速度
  @param     angle_banlance_error 角度环输出（期望角速度）
------------------------------------------------------------------*/
void balance_gyro_weizhi_PD(float gyro, float angle_banlance_error)
{
    balance_gyro_weizhi_pd.error = gyro - angle_banlance_error;
    // PD计算：P项 + D项（微分项抑制抖动）
    balance_pwm = balance_gyro_weizhi_pd.kp * balance_gyro_weizhi_pd.error
                + balance_gyro_weizhi_pd.kd * (balance_gyro_weizhi_pd.error - balance_gyro_weizhi_pd.last_error);
    balance_gyro_weizhi_pd.last_error = balance_gyro_weizhi_pd.error;
    motor_control(balance_pwm);  // 输出PWM到电机驱动板
}

/*------------------------------------------------------------------
  @brief     速度环（位置式PID控制）——通过调整期望俯仰角控速
  @param     encoder  实际编码器速度
  @param     exspeed  期望速度
  @return    速度环输出（叠加到期望俯仰角）
------------------------------------------------------------------*/
float balance_velocity_PID(float encoder, float exspeed)
{
    float vertical_banlance_error;
    balance_velocity_pid.error = exspeed - encoder;
    balance_velocity_pid.i_integral += balance_velocity_pid.error;
    if(balance_velocity_pid.i_integral < -5)  balance_velocity_pid.i_integral = -5;
    else if(balance_velocity_pid.i_integral > 5) balance_velocity_pid.i_integral = 5;
    vertical_banlance_error = balance_velocity_pid.kp * balance_velocity_pid.error
                            + balance_velocity_pid.ki * balance_velocity_pid.i_integral
                            + balance_velocity_pid.kd * (balance_velocity_pid.error - balance_velocity_pid.last_error);
    balance_velocity_pid.last_error = balance_velocity_pid.error;
    return vertical_banlance_error;
}

/*------------------------------------------------------------------
  @brief     核心PID环参数初始化
------------------------------------------------------------------*/
void pid_all_init(void)
{
    // 角度环：P=20, I=0, D=10
    balance_angle_p.kp = 20.0f;  balance_angle_p.ki = 0.0f;  balance_angle_p.kd = 10.0f;
    balance_angle_p.i_integral = 0.0f;  balance_angle_p.last_error = 0.0f;  balance_angle_p.error = 0.0f;
    // 角速度环（位置式）：P=15, I=0, D=10
    balance_gyro_weizhi_pd.kp = 15.0f;  balance_gyro_weizhi_pd.ki = 0.0f;  balance_gyro_weizhi_pd.kd = 10.0f;
    balance_gyro_weizhi_pd.i_integral = 0.0f;  balance_gyro_weizhi_pd.last_error = 0.0f;  balance_gyro_weizhi_pd.error = 0.0f;
    // 速度环：P=0.05, I=0, D=0
    balance_velocity_pid.kp = 0.05f;  balance_velocity_pid.ki = 0.0f;  balance_velocity_pid.kd = 0.0f;
    balance_velocity_pid.i_integral = 0.0f;  balance_velocity_pid.last_error = 0.0f;  balance_velocity_pid.error = 0.0f;
}
