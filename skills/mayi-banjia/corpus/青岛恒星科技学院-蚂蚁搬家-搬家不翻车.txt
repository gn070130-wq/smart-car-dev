第一章 引言
本章旨在简要介绍全国大学生智能汽车竞赛的背景、宗旨及整体概况，并阐述本次参赛任务与制作要求，为后续章节中技术方案、设计思路及调试过程的深入说明奠定理论与工程基础。
1.1 竞赛简介
全国大学生智能汽车竞赛以“立足培养，重在参与，鼓励探索，追求卓越”为指导思想，致力于推动高等学校素质教育的发展，提升大学生综合知识运用能力、工程实践能力与创新意识。该竞赛旨在激发大学生从事科学研究与技术探索的兴趣与潜能，倡导理论与实践相结合、求真务实的学术作风以及团队协作精神，从而为高水平技术人才的培养提供良好条件。
竞赛由秘书处统一设计并规范标准化的软硬件技术平台，涵盖理论设计、整车制造、系统调试与现场竞赛等环节。参赛队伍须由学生自主组成，协同完成从系统设计到实物实现的完整工程流程。竞赛结合科学性、趣味性与观赏性，以汽车电子快速发展的背景为依托，融合自动控制、模式识别、传感技术、电子工程、电气工程、计算机科学、机械工程与汽车工程等多学科内容，具有高度的综合性与创新性。赛事规则透明，评价标准客观，始终坚持“公开、公平、公正”的原则，力求在健康、普及与可持续的方向上稳步发展。
1.2 搬运任务要求
本次比赛选用逐飞 RT1021_BTB 核心板（144pin，MicroPython）作为主控平台，控制两辆三电机全向底盘车模，通过OpenART 摄像头完成目标物品识别、赛道特征检测与双车协同搬运，并以完成规定搬运任务的用时作为主要评价指标。
整车设计需满足以下要求：
电路板设计：必须由参赛团队自主设计和制作，包含电源单元、处理单元、电机控制单元与人机交互单元；不得使用成品模块，并须在电路板铜层刻印学校名称及队伍名称，电路板附有二维码。
机械结构调校：根据赛道特性与车辆运行状态对车模重心偏移调整，增加其稳定性。
软件系统：团队需自主开发车辆控制程序，实现物品及赛道检测、路径规划与运动控制。
整车组装：各部件需经过精确测量后安装，保证左右对称性与重量分布均衡，避免运行偏差。
本次智能车设计与制作涉及机械结构优化、电路板研发与控制软件设计三大核心任务，三者的协同优化直接决定了整车性能与比赛成绩。
1.3 设计思路及技术方案概要

图1-1 设计方案图
1.3.1.视觉识别
对赛道中物品的识别采用TFLite YOLO模型。识别box/ball/bear三类物品；
（1）隔帧推理（默认每3帧一次）提升帧率，检测结果缓存复用；
（2）目标锁定跟踪：按类别顺序锁定目标，支持目标短暂丢失重拾与死区判定；
（3）线检测：识别停止线（触发stop）与后板线（触发back）；
（4）支持通过串口指令切换推送目标（球/沙包/熊）。
1.3.2程序控制
运动控制：
（1）三电机全向底盘：支持全向平移与原地旋转（120°布置解算）；
（2）IMU660RX 陀螺仪+卡尔曼滤波估计航向，静止时自动校正零漂；
（3）串级控制：速度环PID（变速积分+静摩擦补偿）+航向环+角速度环；
（4）编码器反馈，5ms定时器中断执行，主循环100ms任务调度
任务状态机：
物品对准后直接推送；
（1）车头方向与目标板边不匹配时绕物品旋转；
（2）推送完成后自动掉头并继续下一目标；
（3）目标丢失超时回idle、通信超时进入emergency、拨码开关急停。
1.3.3机械结构​
在机械结构方面，团队对现有车模进行了针对性改装，以满足智能汽车在速度与稳定性上的需求：
（1）推杆优化：斜向分力可以 “兜住” 物品，物品不容易从两车中间滑跑；允许两车位置存在一定的对齐误差，容错更高。
（2）底盘及传动结构设计：采用三电机全向轮底盘，车模体积较小，可实现前后运动、横向平移与原地旋转，便于双车协同过程中的快速姿态调整。
（3）底盘及传动结构设计：采用全向轮，车模体积小，转向灵活，稳定
（4）车身重心调整：将电池和pcb后置，使得车模整体重心偏后，保证了车辆在完成搬运任务的稳定性。
1.3.4电路设计​
在电路系统方面，项目团队自主设计了六层PCB主控板，实现了电源模块、电机驱动模块与多传感器接口的高度集成，显著减少了布线复杂度与空间占用。
实际测试中，电路部分的优化进展如下：
已解决问题：陀螺仪放置位置偏移，重新设计后保持在车模中心位置。
待改进问题：缺少开关防打火电路，上电瞬间大冲击电流直接灌入后端，电解电容、电源芯片、单片机、电机驱动芯片易受浪涌冲击损坏。
综上所述，电路部分的性能已能满足当前阶段需求，但仍需提高抗干扰能力以适应更复杂的赛道环境。

第二章 设计方案
2.1 车模的结构
参赛车模采用镂空三角形结构稳定轻量化，碳纤维材料在保证轻量化的同时有较强的支撑性。车轮采用全向轮，转向更灵活。
驱动电机为N20减速电机，最高转速约2000 r/min，搭配逐飞公司生产的 1024线增量式编码器，用于测速与速度闭环控制。编码器可输出双相脉冲信号，经主控正交解码后获得旋转方向与脉冲计数信息，为三轮速度反馈提供依据。全向车模示意图如图2-1所示。

图2-1 全向车模示意图
主车采用双摄像头方案：OpenART Plus 主摄像头用于 YOLO 物品识别，OpenART mini 副摄像头用于黄色停止线等赛道特征检测，从而将目标识别与停车判断分离，提高系统鲁棒性，如图2-2所示。从车摄像头用于获取主车相关引导信息并配合跟随控制，如图2-3所示。
     
图2-2 主车摄像头                 图2-3  从车摄像头 
2.2 推杆结构
主车推杆与车体中轴线呈一定斜角，安装位置偏向车体一侧，如图2-4所示；从车推杆采用相对配合的布置形式，如图2-5所示。主车斜杆与从车横杆共同形成非对称夹持构型：横杆提供主要前向推力，斜杆提供侧向约束，使目标物在双车之间不易侧向滑出。该结构允许一定的双车对接误差，可降低协同定位与同步控制的压力。
2.3 传感器安装
IMU660RX陀螺仪安装在车模中心附近，使其测量坐标系与车体坐标系尽可能一致，可减小安装偏置对航向估计与闭环控制的影响，如图2-6所示。摄像头目标坐标则结合其安装位置、视场及图像中心进行误差换算后用于运动控制。

第四章 算法设计
基于NXP RT1021 MicroPython与OpenART视觉模块的智能搬运小车项目（主车+从车），实现目标物品的识别、对准、推送以及停止线检测等任务。
4.1 项目简介
主车：OpenART Plus 主摄像头（YOLO 目标识别）+ OpenART mini 副摄像头（黄线/停止线检测）+RT1021主控，三电机全向底盘。
从车：RT1021 主控，三电机全向底盘，与主车协同搬运。
视觉模型识别三类物品：box（沙包）、ball（球）、bear（熊），按配置顺序完成对准与推送。
4.2 系统架构
4.3 核心功能
4.3.1视觉识别
使用 TFLite YOLO 模型（yolo3_iou_smartcar_final_with_post_processing. tflite）识别box/ball/bear三类物品；
隔帧推理（默认每3帧一次）提升帧率，检测结果缓存复用；
目标锁定跟踪：按类别顺序锁定目标，支持目标短暂丢失重拾与死区判定；
线检测：识别停止线（触发 stop）与后板线（触发 back）；
支持通过串口指令 push_enter 切换推送目标（球/沙包/熊）。
4.3.2停止线检测
对摄像头图像进行颜色阈值二值化后，使用 find_line_segments 提取候选线段，并在图像下半区域筛选长度、水平跨度及纵向偏差满足阈值的横向线段作为停止线候选；
停止线连续3帧满足条件后确认触发，并设置5 s启动保护与约300 ms状态保持时间，以降低起步阶段和瞬时噪声造成的误触发；
通过固定曝光等方式减小运动拖影和环境亮度波动对赛道特征提取的影响；具体曝光参数应结合现场光照进行标定。
4.3.3运动控制
三电机全向底盘：支持全向平移与原地旋转（120° 布置解算）；
IMU660RX 陀螺仪 + 卡尔曼滤波估计航向，静止时自动校正零偏；
串级控制：速度环 PID（变速积分 + 静摩擦补偿）+ 航向环 + 角速度环；
编码器反馈，5ms 定时器中断执行，主循环 100ms 任务调度。
4.3.4状态机
init → forward → shuipingr → follow → push / orbit_item → diaotou → forward → follow ...
包含init、idle、forward、shuipingr、shuipingl、follow、emergency、diaotou、back、huijia、push、orbit、orbit_item 等状态，支持：
物品对准后直接推送；
车头方向与目标板边不匹配时绕物品旋转（orbit_item）；
推送完成后自动掉头（diaotou）并继续下一目标；
目标丢失超时回 idle、通信超时进入 emergency、拨码开关急停。



第五章 开发与调试
5.1 Micropython开发环境的安装
本系统未采用传统嵌入式裸机开发模式，而是基于 MicroPython 嵌入式开发环境进行程序开发与调试。开发过程中完成适配 RT1021 主控的固件烧录、串口连接、脚本下载与运行调试，并结合 OpenART 视觉模块完成相关程序部署。该方式便于快速迭代控制逻辑与视觉算法，同时保留串口输出用于在线调试和状态观察。
5.2 静摩擦补偿调试
针对车辆起步、掉头复位后 PID 输出不足以及电机受静摩擦影响出现堵转的问题，在速度环中加入可开关的静摩擦补偿：当控制器存在明确速度需求但输出不足以克服起步阻力时，叠加最小启动占空比；同时采用积分限幅抑制积分饱和，并在目标速度为零时禁止补偿，避免车辆静止时蠕行。相关补偿阈值与最小占空比结合实车和赛道摩擦条件进行标定。
5.3 航向环、角速度环调试
航向环与角速度环采用独立控制开关，以区分常规行驶和绕物体运动两类工况。常规行驶时以航向闭环为主；绕目标物体时根据需要启用角速度内环，避免两个控制环在不适用工况下同时强制修正而产生相互干扰。该调整保持原有串级控制框架，不改变从车通信、视觉识别及电机速度环等模块。

6.4 电路功耗
整车功耗可分为逻辑与传感器供电功耗、以及电机驱动功耗。电机由电池端VCCBAT直接供电；TPS564201DDCR将电池电压降至5 V，为摄像头和主控等外设供电。按5 V侧总负载电流约1.2 A、转换效率约90%估算，5 V支路电池侧输入功率约为6.7 W，其中DC-DC转换损耗约0.67 W。RT9013-33GU5由5 V进一步产生3.3 V，在3.3 V负载电流约0.35 A时，其压差损耗约0.60 W。电机重载搬运时，整车总功耗主要由电机决定，原测试估算约为27～47 W；该数据会随电池电压、负载和占空比变化。

第七章 结论

本报告从机械结构、电路系统、视觉识别、状态机及运动控制等方面对系统进行了说明。整体方案以三电机全向底盘为运动平台，通过主车双摄像头完成目标识别与赛道特征检测，并结合编码器、IMU及速度/航向闭环控制实现车辆运动与双车协同搬运。

LEFT_ROI = (0, 60, 60, 60)      # 左端 60px 宽
RIGHT_ROI = (100, 60, 60, 60)   # 右端 60px 宽

# ---------- 黄线段长度/形状过滤（防噪点误判）----------
BLOB_PIXELS_THRESHOLD = 6       # find_blobs 合并前的最小色块（先保留小碎片再过滤）
MIN_LINE_LEN = 20               # 黄线段最小横向长度(px)，滤掉小噪点
MIN_LINE_H = 2                  # 最小厚度(px)，滤掉 1px 细噪条
MIN_LINE_PIXELS = 40            # 每侧最少黄色像素总数

# ---------- 停车判断参数 ----------

STOP_HOLD_MS = 300              # 确认后保持停车状态的时间
START_PROTECT_MS = 5000         # 启动保护，避免起步误触发
stop_confirm = 0
stop_hold_until = 0
start_time = time.ticks_ms()

# ---------- LED 爆闪参数 ----------

last_blink_time = 0
led_on_state = False
white = LED(4)

# ---------- 判断一侧是否出现"合格的黄线段" ----------
def side_has_line(blobs):
    for blob in blobs:
        if (blob.w() >= MIN_LINE_LEN and
                blob.h() >= MIN_LINE_H and
                blob.pixels() >= MIN_LINE_PIXELS):
            return True
    return False

# ---------- 主循环 ----------
while True:

    img = sensor.snapshot()

    # 左右两端各找黄色色块，中间被物品挡住也不影响
    left_blobs = img.find_blobs([yellow_threshold], roi=LEFT_ROI,
                                pixels_threshold=BLOB_PIXELS_THRESHOLD, merge=True)
    right_blobs = img.find_blobs([yellow_threshold], roi=RIGHT_ROI,
                                 pixels_threshold=BLOB_PIXELS_THRESHOLD, merge=True)

    # 两侧都要求出现一定长度/厚度的黄线段，噪点不算
    left_ok = side_has_line(left_blobs)
    right_ok = side_has_line(right_blobs)
    is_stop_line = left_ok and right_ok

        stop_confirm = 0
