摘要
针对蚂蚁搬家组双车协同搬运、目标搜索、路径移动及复杂环境适应等任务需求，本文设计了一套以主从协同控制和多传感器信息处理为核心的智能搬运车软件系统。系统由主车、从车及视觉感知单元组成，通过分层控制方式完成环境感知、运动状态估计、车辆运动控制、任务决策和双车协同。
主车主要承担视觉任务语义接收、任务状态管理、运动指令生成以及从车协同信息组织。底层采用三轮全向运动模型，通过轮速闭环、二维速度控制和航向控制实现平面运动。为改善轮胎打滑、车体冲击等情况下的速度反馈，系统综合编码器和IMU信息，在两个平面方向建立独立卡尔曼状态估计器，并根据传感器一致性动态调整观测可信度。
从车根据主车无线指令在跟随、惯性导航、近距离夹持、出线和回库等模式之间切换。近距离协同时，从车进一步利用双磁传感器获得相对位置变化信息，形成横纵方向局部闭环。主车利用状态机管理搜索、跟踪、搬运出场、转向调整及最终回库过程，并在关键协同节点通过事件通知与从车同步。

第一章 引言
1.1 研究背景
全国大学生智能汽车竞赛技术报告用于总结参赛车模的技术方案、设计思路、制作调试过程及相关技术研究内容，基本部分需要覆盖总体方案、机械与传感器安装、电路、控制软件、开发调试以及主要技术参数等内容。[1]
蚂蚁搬家组与传统单车循迹任务相比，更强调二维场地中的自主运动、双车动作协调以及不同任务阶段之间的稳定切换。主车需要依据视觉信息完成目标搜索与任务决策，从车则需要根据主车状态完成跟随、导航和近距离夹持，两车在搬运过程中还必须保持相对位置关系。
单一传感器难以覆盖全部运动工况。编码器能够直接反映车轮运动，但在打滑时会与车体真实速度产生偏差；IMU能够快速感知车体加速度和姿态变化，却容易受到零偏和碰撞冲击影响。卡尔曼滤波能够通过预测与观测修正综合不同信息源，因此适合用于编码器与惯性信息的互补估计。[2][7]
1.2 系统设计目标
（1）建立稳定的三轮全向运动控制系统，实现车辆横向、纵向和旋转运动。
（2）利用编码器与IMU信息进行二维速度估计，提高运动反馈在打滑及冲击条件下的稳定性。
（3）实现OpenART视觉单元与主控制器之间的非阻塞信息交互，并根据视觉任务状态执行相应动作。
（4）建立主车与从车之间的无线协同机制，使从车能够在跟随、惯导、夹持、出线和回库等模式间切换。
（5）将较大范围路径运动与近距离相对位置调整分离处理，提高双车协同的可调试性和环境适应能力。
1.3 本文主要内容
第二章介绍系统总体方案及主从车功能分配；第三章介绍机械结构、传感器安装和电路设计；第四章介绍底层全向运动控制、编码器与IMU融合以及惯性导航；第五章介绍视觉系统总体方案、图像采集与预处理、目标识别定位和视觉任务信息输出；第六章介绍视觉通信与任务状态机、主从通信、磁场相对位置控制与自动回库；第七章总结开发调试过程；第八章给出模型车主要技术参数；第九章对系统进行总结并提出改进方向。

第二章 系统总体设计
2.1 系统组成与功能分配
整个智能搬运系统由主车、从车和视觉感知单元共同组成。主车承担任务语义接收、任务状态管理、运动指令生成以及从车协同信息组织；从车根据主车无线指令选择跟随、惯性导航或磁场局部闭环等控制方式；视觉单元负责输出目标运动方向、当前业务状态及场地相关信息。

2.2 系统任务流程
系统上电后首先完成传感器初始化和零偏校准，随后按照当前场地状态进入比赛区域。正常搬运循环依次经历搜索目标、目标跟踪、双车接近、协同夹持、搬运出场、转向与重新对齐等阶段。完成全部目标后，主车切换至最终回库状态，从车同步进入对应回库路线。
（1）初始化与零偏校准。
（2）进入比赛区域并建立场地边与航向上下文。
（3）视觉搜索并跟踪待搬运目标。
（4）主从车靠近并进入夹持状态。
（5）两车协同将目标搬运至指定边界。
（6）完成出线、转向和重新对齐，进入下一轮任务。
（7）完成全部搬运后执行自动回库并停车。
2.3 系统软件分层
软件按照实时性和业务职责分为基础数据层、运动控制层、状态估计与导航层、任务控制层以及双车协同层。底层控制只接收统一的世界坐标速度和目标航向，上层任务程序不直接操作三个电机，从而使视觉任务逻辑、路径规划与底盘控制保持相对独立。

第四章 软件系统与运动状态估计
4.1 多周期软件架构
主、从车软件采用定时控制与主循环业务处理相结合的结构。高频任务用于陀螺仪积分和姿态连续更新，固定控制周期内依次完成姿态解析、轮速控制、二维运动控制、多传感器融合以及导航坐标更新；任务状态切换和部分低实时性逻辑则放在主循环或业务层执行。 主控软件运行于MicroPython嵌入式环境，相关运行时与处理器外设资料可参考MicroPython文档及NXP i.MX RT1020系列参考手册。[3][6]

第五章 视觉系统设计
本章介绍视觉感知单元的总体方案、图像采集与预处理、目标识别与定位方法，以及视觉任务信息向主控制器的输出方式。视觉单元负责场景感知、目标判定和运动建议生成；主控制器负责航向保持、路径导航和电机执行。两端通过串口协议协同，形成从环境感知到车辆运动执行的完整链路。
5.1 视觉系统总体方案
视觉处理平台采用OpenART嵌入式视觉模组，运行OpenMV风格的MicroPython视觉程序。摄像头输出RGB565彩色图像，常用分辨率为QVGA（320×240）。为适应比赛现场光照条件，系统在启动阶段完成曝光锁定，并关闭自动增益与自动白平衡，使后续颜色分割阈值在运行过程中保持相对稳定。
摄像头安装于主车前方，视场覆盖场地中前方区域，用于目标搜索、跟踪、边界识别与局部避障观测。视觉软件按任务状态组织处理流程，主要状态包括基础搜索、分类确认、目标跟踪、带货出场、协同转向以及最终回库。单帧处理流程可概括为：采集当前图像；按当前任务状态执行对应感知算法；计算目标横向偏差与距离趋势量；生成包含任务状态、二维运动指令和场地边上下文的运动命令；经串口发送至主控制器，同时接收状态切换、边界障碍上下文等控制信息。
在有限算力条件下，系统采用“颜色区域检测为主、轻量神经网络分类确认”的方案。目标位置与运动建议量由颜色连通区域及其几何特征给出，目标类别则由轻量分类网络在感兴趣区域上完成确认。该分工有利于提高处理帧率、保留阈值级现场可调性，并增强行为的可预测性。
5.2 图像采集与预处理
图像采集使用固定像素格式与分辨率。启动时先对传感器进行稳定，再根据画面有效区域亮度完成曝光锁定；主循环中按固定流程抓取当前帧。图像顶部一定比例区域不参与自动识别，以削弱车体结构、远处无关景物等干扰对检测结果的影响。
颜色分析在LAB颜色空间阈值下进行区域提取。针对不同对象分别设置阈值：蓝色族用于沙包等偏蓝目标，非蓝色族用于网球、玩偶等目标，黄色用于场地边线胶带，砖块色用于局部障碍，深绿色用于回库库位。目标主链路仅保留蓝与非蓝两类阈值，其余阈值独立维护，以降低交叉干扰与调参成本。


预处理不以重型全图滤波为主，而是采用连通区域提取配合几何门控：依据像素面积、宽高比、填充率和贴边情况剔除不可靠候选；存在多个候选时，优先选择更靠近车体（检测框底边更靠下）且更接近图像中心的目标。跟踪阶段在上一帧区域附近扩大搜索窗，并对目标中心与脚点坐标进行平滑，以抑制抖动。
局部避障相关处理在前方感兴趣区域内对障碍色连通块进行左、中、右通道划分，并结合脚点纵坐标判断挡路程度，为入场与出场阶段的局部绕行提供观测依据。
5.3 目标识别与定位
待搬运目标主要包括网球、玩偶和沙包。粗检阶段按颜色族提取候选区域，并计算目标中心相对图像中心的横向偏差，以及检测框底边纵坐标（脚点）。脚点用于反映目标相对远近趋势：在针孔近似下，目标越近则脚点通常越靠图像下方。当目标进入近场且满足连续帧稳定条件后，系统进入分类确认：在候选区域裁剪补丁图像，由轻量分类网络输出类别及置信度。有效类别映射为网球、玩偶和沙包；障碍类仅用于排除，不作为搬运目标下发。
分类确认后进入颜色族稳态跟踪，持续更新横向偏差与脚点，并据此生成接近目标的二维运动建议。当脚点进入近距区间且横向误差足够小、连续满足门控条件时，判定接近完成，由上层任务进入后续转向与搬运流程。
场地黄胶带通过高长宽比连通区域检测，以其底边纵坐标表征出界进度。砖块障碍不估计全局地图坐标，而在局部车道内判断占用与距离档位。回库阶段检测绿色库位，先完成横向对齐，再进行纵向接近，连续满足停止条件后给出入库完成标志。
上述识别结果与位置量定义在图像像素坐标系及协议速度指令域，而非直接给出米制世界坐标。横向对准可采用约十余像素量级的死区与触发门限（可按现场标定调整）；分类置信度门槛约为0.75；运动命令上行频率约数十赫兹量级。相关性能评价指标包括识别准确率、板端帧率以及像素量与车体距离的标定关系。
5.4 视觉任务信息输出
视觉端与主控制器通过串口通信，波特率为115200。通信帧包含帧头、长度、消息类型、有效载荷和CRC16校验。视觉上行主消息为运动命令，将任务状态、目标类别、横向与纵向建议速度、有效标志以及来源边与目标边等上下文打包发送；主控制器下行则下发状态切换、边界障碍上下文、搬运进度和心跳等信息。
任务状态字段与主车业务状态对应，包括基础搜索、分类确认、目标跟踪、带货出场、协同转向以及最终回库等。二维运动指令中，横向分量由目标中心横向偏差映射并限幅得到，纵向分量由脚点分段映射，或由出场速度、避障档位等策略给定。分类确认阶段以保持为主，横向与纵向建议速度置零，等待类别结果用于后续任务决策。
有效标志包括命令有效、视觉源有效、安全或保持、已应用局部避障、对齐完成以及入库完成等，供主车决定是否消费当前指令、推进阶段或选择回库路线。场地边信息以离散边编号表示（底边、左边、上边、右边）。障碍方位由主车按边配置后同步至视觉端，视觉据此选择入场与出场默认绕行方向。障碍布局采用参数化描述，现场调整边侧参数即可适配不同障碍布置，无需改动识别逻辑。
避障信息不单独占用第二类上报包，而是折叠进同一运动命令。入场视觉避障在基础搜索状态下完成，不切换至出场状态；出场状态下结合黄胶带与局部障碍改写横向、纵向速度，并置位避障标志。主控制器在对应状态窗口消费视觉建议速度，同时保留航向控制、路径导航与电机执行职责，从而使感知判定与运动执行的责任边界保持清晰。

第六章 双车协同与任务决策
6.1 视觉通信与任务状态机
OpenART视觉侧与主车RT控制端通过串口交换任务状态和运动指令。通信帧包含帧头、长度、消息类型、有效载荷和CRC16校验，RT端采用非阻塞方式解析数据，并设置心跳机制维持链路状态。
主车业务层将正常搬运流程划分为基础运动、搜索、目标跟踪、搬运出场、转向与重新对齐以及最终回库等主要状态。状态4内部进一步使用小状态机处理弧形转向、等待、重新获取目标、对齐和180°转向，从而将复杂动作拆分为多个明确阶段。

6.2 主从通信与跟随控制
主车与从车通过NRF24L01无线通信交换当前从车运行模式、目标速度和目标航向。主车在生成从车速度时，部分场景会将视觉目标速度与主车实际测得速度按一定比例组合，使从车指令更接近主车真实运动状态，降低主车加减速、负载和控制滞后带来的相对位置误差。 无线收发器的工作特性与数据链路配置参考器件产品规范。[5]
从车收到数据后根据状态码选择控制模式。普通跟随阶段将主车速度信息与磁场局部修正量组合；预设路线阶段关闭磁场环并启动路径点惯导；夹持阶段以磁场局部闭环为主；出线和最终回库阶段则调用对应的预设路径。
6.3 磁场相对位置控制
从车使用两路磁传感器读取局部磁场，并通过差分方式降低共模环境磁场影响。程序对磁场方向和强度分别进行零点修正、限幅和低通处理，形成横向与纵向相对偏差信息，再通过两个闭环控制器得到局部位置修正速度。磁传感器的零点与比例参数依据实车安装位置完成标定。[4]
夹持阶段采用分段控制思想：当纵向距离仍较大时优先前后接近；进入适当范围后同时调整横向和纵向偏差；对于误差较大和误差较小的区域采用不同控制比例，以兼顾接近速度与局部稳定性。
6.4 复杂环境适应与自动回库
复杂环境适应主要体现在三个层面。第一，底层速度融合根据编码器与IMU一致性处理打滑、冲击与静止漂移；第二，视觉运动指令中保留避障标志，主车可根据局部环境修正平移方向，并将实际运动信息同步给从车；第三，固定路线导航保存不同场地边的路径配置，在进入、出线、调头和回库阶段根据当前边界上下文选择相应路径。
系统对已完成搬运任务数量进行累计。当达到设定总任务数后，不再进入下一轮搜索，而是在当前搬运与转向完成后切换到最终回库状态。回库过程结合固定路径导航和视觉接管，主、从车分别执行对应路线，最终返回停车区域。

7.2 分阶段调试方法
整车制作按机械安装、电路焊接与线束连接、传感器固定、上电检查和软件分阶段调试的顺序进行；安装完成后先核对接口方向与供电，再进入单模块和整车联调。
（1）首先完成编码器方向、电机方向、IMU轴向和三轮全向运动关系校验。
（2）完成单车轮速闭环、二维速度控制和航向控制，验证世界坐标速度接口。
（3）加入编码器与IMU融合，观察平稳运动、快速启动、打滑、冲击和停车过程中的速度反馈。
（4）加入OpenART串口通信和主车状态机，逐步验证搜索、跟踪、搬运出场与调头。
（5）加入主从无线通信和磁场相对位置闭环，完成双车跟随、靠近、夹持和协同搬运联调。
（6）在完整场地中连续运行全部任务，并根据失败场景调整状态切换和路径参数。
7.3 主要问题与解决方法
7.3.1 轮胎打滑造成速度估计偏差
车辆快速加速或带载搬运时，编码器速度可能高于车体实际速度。系统利用编码器变化与IMU加速度之间的一致性判断疑似打滑，并在异常方向提高编码器观测噪声，避免错误轮速直接主导速度反馈。
7.3.2 碰撞造成惯性加速度突变
车辆与目标接触或经过不平整区域时，IMU可能产生短时大幅加速度。程序通过限幅、滤波及编码器一致性判断识别冲击，并适当衰减该次惯性预测量。
7.3.3 主从车产生相对位置偏差
主车与从车的电机响应、负载和控制滞后存在差异。系统在普通跟随阶段结合主车实际速度信息，在近距离阶段切换至磁场相对位置反馈，从不同层级减小累计相对误差。
7.3.4 任务状态切换保留旧控制量
复杂状态切换时若上一阶段的速度或航向缓存未清理，容易产生瞬时错误动作。主车业务层在进入关键状态时重新锁存目标航向，并在离开转向状态后主动清理相关运行时变量；无有效指令时默认保持安全停车。

第九章 结论与展望
本文针对蚂蚁搬家组双车协同任务，完成了一套以多传感器信息处理和主从协同控制为核心的软件方案。系统通过模块化结构将三轮全向运动控制、姿态处理、二维速度估计、路径导航、视觉任务状态以及双车协同分离，实现了从环境任务信息到两辆车辆运动执行的完整控制链路。
在运动状态估计方面，编码器和IMU在两个平面方向进行卡尔曼融合，并通过数据一致性检测处理轮胎打滑和瞬时冲击，静止状态下进一步施加零速度约束。该方法使融合速度能够作为二维速度闭环反馈，在正常运动和部分异常工况之间动态调整不同传感器的作用。
在任务控制方面，主车利用OpenART任务状态组织基础运动、搜索、目标跟踪、搬运出场、转向对齐以及最终回库。主车通过无线链路将运行模式、运动速度和航向发送给从车；从车在较大范围运动阶段采用速度跟随或路径点导航，在近距离夹持阶段利用双磁传感器进行局部相对位置闭环，从而形成多种感知方式在不同距离范围内的互补。
目前系统仍存在进一步优化空间。路径导航依赖轮速与航向积分，长距离运动存在累计误差；磁场局部闭环的控制参数与安装结构相关，需要在最终机械状态下重新标定；任务状态较多，后续仍可继续简化业务接口并增加更系统的异常恢复策略。

def predict(self, acceleration):
    self.velocity += (acceleration - self.bias) * 0.01
    p01 = self.p01
    p11 = self.p11
    self.p00 += -0.02 * p01 + 0.0001 * p11 + 12.0
    self.p01 = p01 - 0.01 * p11
    self.p11 = p11 + 0.2

def update_velocity(self, measured_velocity, noise):
    s = self.p00 + noise
    k0 = self.p00 / s
    k1 = self.p01 / s
    innovation = measured_velocity - self.velocity
    self.velocity += k0 * innovation
    self.bias += k1 * innovation
