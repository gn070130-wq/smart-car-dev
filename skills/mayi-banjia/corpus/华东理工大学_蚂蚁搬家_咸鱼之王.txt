第一章　引言
1.1　智能汽车制作概述
本组别为微缩组别蚂蚁搬家赛道。比赛要求：两辆MicroPython小车搬运网球/沙袋/泰迪熊至场外指定方位（决赛需分类），辅助车不碰物品；预赛无障碍，决赛有坡道和砖块（≤3块）；车模需返回发车区，时间短者胜；车模重量与成绩挂钩，车模越轻，罚时越少。
基本设计思路：完成比赛任务要求，找到速度与车模质量的最佳平衡点。为实现小车灵活转向，我们采用三轮全向轮车模方案。在车身结构，车模材料，电路板，电池等部件上减轻重量。两车搬运采用“对牛”方案，即两车前后夹住物体搬运出界，两车间采用WIFI模块通信。物体分类，障碍物及边界识别等采用摄像头识别。
技术路线规划：首先完成大体方案敲定；确定方案后同步开启车模设计和电路板原理图PCB设计；车模组装完成后开始软件调试，电机选型，搬运方案验证。
1.2　报告内容框架
本报告将从系统总体设计、机械结构设计、硬件电路设计、软件算法设计和系统调试这五个方面系统阐述。
第二章　系统总体设计
2.1　设计思路
我们的赛题任务要求将不同种类的物体推至不同的方向，因此对车模灵活性有较高要求。在设计方案之初我们有两种车模方案，四轮麦轮全向车模和三轮全向轮车模。综合考量结构复杂程度和重量，我们选择三轮全向轮车模方案。
我们的比赛成绩与重量挂钩，因此我们车模的设计思路便是在保证速度的前提下尽可能地减轻重量。在车身减重方面，我们在车身结构，车模材料，电路板，电池等部件上减轻重量。车身结构方面，删去不必要的结构，仅保留能支持整车结构的最小强度件；车模材料方面，整车结构全部采用3D打印物料，连接件全部使用尼龙件（尼龙螺柱，尼龙螺丝，尼龙螺母等）；电路板方面，仅保留所需要功能，主驱同板，最小化电路板尺寸（5cm*5cm，0.8mm板厚），空板重量控制在4.9g；电池方面，选择850mAh 3S锂电池，电池容量满足基本任务需求。
2.2　技术方案
2.2.1　方案选择依据
蚂蚁搬家组别目前有两种主流搬运方案，一种是“对牛”，即两车前后夹住物体搬运出界，另一种是逐飞方案，从车跟随主车，两车呈V型将物体一起推出界。但由于逐飞方案推出时间较晚，对牛方案在前期验证过程中也调试的较为顺利，故最终敲定使用“对牛”方案。
2.2.2　系统架构
本系统以 RT1021 MicroPython 核心板作为唯一主控单元，构成感知-决策-执行闭环的嵌入式实时控制架构。主控通过 PWM 信号驱动三路 DRV8701 栅极驱动器（12V 供电）控制三个直流电机，同时采集同轴编码器（3V3）的脉冲反馈实现速度与位置闭环；姿态感知方面，核心板经 SPI 总线高速读取 IMU963 九轴姿态数据，用于车体平衡与航向解算。环境感知与显示共享一组 I²C 总线：TOF 红外测距模块实时输出距离数据，IPS200 屏幕同步显示运行状态与关键参数。通信链路由三路 UART 承担，分别对接无线转串口模块（5V，用于双车协同）、OpenArt Plus 视觉模块（用于物体与障碍识别）及上位机（用于调试与数据回传），实现多源信息融合与远程监控。此外，通用 IO 口连接拨码开关、时序电路与蜂鸣器，完成车模方案选择、起跑信号触发及状态提示等人机交互功能。各功能模块按总线类型分工明确，PWM 专供电机驱动、SPI 用于高速姿态采集、I²C 负责测距与显示、UART 承载多路通信、IO 处理离散控制，总线资源无冲突，系统具备良好的实时性与可扩展性。

第四章　硬件电路设计
4.1　电路总体设计
4.1.1 电源管理模块
	电源管理模块负责将 3S 锂电池（11.1 V/12.6 V）的电压分为两路，一路提供给电机，一路转换为系统所需的5 V（外设）、3.3 V（MCU与传感器）两级电压，并具备时序上电、过压保护、欠压监测功能。电源管理部分由以下子电路组成：
（1）：地隔离
电机驱动会产生大量噪声，通过一个0ohm的电阻把"大电流、强噪声"的功率回路和"低电平、高敏感"的信号回路在地参考上分开，避免电机开关噪声顺着共地路径灌进 MCU 和传感器。

（2）12V→5V 降压电路（DCDC）
采用TI的TPS62135RGXR同步降压型DCDC芯片，最大输出电流4A，效率高、纹波低。如图3所示，输入端经 SS54 肖特基二极管防反接，U8为1μH功率电感，与芯片内部开关构成Buck拓扑；R30（510kΩ）与R32（82kΩ）构成输出电压反馈分压，将输出电压设置为5 V（Vref=0.8V）。

（3）5V→3.3V降压电路（LDO）
采用RT9013-33GB低压差LDO，最大输出 500 mA，具备低噪声、高 PSRR 特性，专为MCU、传感器等模拟/数字混合电路供电。如图4所示，Vin端加10μF+100nF输入滤波；Vout端加10μF+100nF输出滤波，确保3V3母线噪声在50mVpp以内。

(4)双路电子开关（电源时序控制）
采用MPS MP5090GQHT-Z（U5）双通道负载开关，EN1/EN2由MCU CR引脚控制（MCU在5V上电后CR输出高电平），可实现5V_CR（受控 5V）、3V3_CR（受控3.3V）的分时序上电，避免大电流负载同时启动造成母线跌落。

(5)电源开关
电源开关由 P-MOSFET AGM60P100A（Q21）+ 拨片开关MSK12C02（SW2）+ 防反TVS BZT52C16（D1）+ R7（10 kΩ）下拉组成，波动开关将栅极拉低，Q21导通将12V母线接通；TVS用于吸收感性负载关断时的电压尖峰。

(6)电源指示灯
12V、5V、3V3、CR 四路LED指示，分别串联R33、R34、R35、R36（10kΩ）限流电阻至GND，方便调试时观察各级母线状态。

(7)电池电压测量
由R28（10 kΩ）+ R29（1 kΩ）构成分压网络，将12V电池电压按约11:1比例衰减送入MCU ADC引脚BAT_ADC；BAV99（D2）双向钳位二极管将ADC引脚电压限制3v3内；C6（100 nF）滤除高频干扰。MCU 可据此实现低压报警、自动停机等功能。

4.1.2 MCU核心板接口模块
主控采用基于NXP RT1021的MicroPython核心板（U15，型号 RT1021_BTB_CoreBoard，板对板连接器型号 HC-PM254-5.0H-2x8PS），主频500MHz，自带MicroPython固件，便于快速开发。核心板通过 50-pin BTB（板对板）连接器与底板对接，将 MCU 引出的电源（5V）、控制信号（CR）、3路电机PWM/DIR、6 路编码器输入、2路I2C（屏幕、TOF）、1路SPI（IMU963）、3路UART（无线转串口、OpenArt Plus摄像头、上位机）、ADC（BAT_ADC）、普通GPIO（按键、拨码、蜂鸣器、屏幕控制）等资源全部引出到主板。

4.1.3 电机驱动模块 
三路电机驱动采用完全对称的设计结构，每一路由栅极驱动芯片DRV8701 + 2颗漏源相连的双N-MOSFET AGM304MBQ组成H桥。满足性能的同时缩小体积。

4.1.4 电路功耗
车模整体工作功耗在10-20W之间，电路板使用两颗220uF固态电容一共440uF。

第五章　软件算法设计
5.1　控制理论
5.1.1　控制系统总体框架
本车控制软件以 NXP i.MX RT1021 微处理器（Cortex-M7，500 MHz）为核心，基于逐飞科技 MicroPython 固件开发，软件需要完成"自主定位—目标搜索—目标识别—搬运推送—双车协同—回归停靠"的完整任务流程。针对这一复杂任务，软件采用分层递阶控制的整体策略，自顶向下划分为四个层次：
1. 任务决策层：以有限状态机（FSM）为骨架，共定义 23 个任务状态（主流程实际使用 17 个，其余为调试与预留状态），负责根据传感器信息、定位结果与队友车辆状态进行任务调度与状态切换，是整车的"大脑"；
2. 环级控制层：采用串级 PID 结构，由外向内依次为距离环（点到点定位）、角度环（航向跟踪）、角速度环（陀螺仪反馈）和轮速环（三电机分别闭环），实现"位置→姿态→速度→力矩"的逐级精确控制；
3. 运动学解算层：根据三全向轮底盘逆运动学模型，把合速度指令（平移速度、平移方向、旋转速度）解算为三个轮子的目标转速；
4. 执行层：以 13 kHz PWM 驱动三路直流电机，通过 575 线正交编码器构成速度闭环反馈。
在控制方式上，本车采用开环规划与闭环校正相结合的策略：起停与加速阶段使用 Sigmoid 速度曲线进行开环平滑规划，避免速度阶跃引起的打滑与冲击；行驶与接近目标阶段切换为闭环控制，由传感器反馈实时修正。
坐标系定义。 全场建立全局直角坐标系，单位 cm；车体航向角 ψ 由九轴姿态解算获得，取值范围 0°~360°，定义车头朝向 +Y 轴方向时为 90°；上电起点坐标为 (46, −20)。全部状态机中的目标点、边界判断与坐标修正均在此坐标系下进行。
控制周期选择。 控制周期是影响系统性能的关键参数：过短则中断负载过重、MicroPython 解释执行开销导致周期抖动；过长则相位滞后大、带宽不足。经实测，姿态解算（Mahony 九轴）与控制环计算在 RT1021 上的最坏执行时间约 1.5 ms，故将控制中断周期定为 4 ms（250 Hz），既保证足够的控制带宽，又留有充裕的时间余量；编码器采集与里程计更新对实时性要求较低，定为 40 ms（25 Hz），该周期内编码器脉冲计数上限（±80）足以覆盖全速运行范围。
5.1.2　串级控制理论
对于航向控制这类"姿态→转速"双积分对象，单环 PID 难以兼顾响应速度与稳定性：比例系数增大可加快响应，但会放大角度噪声（陀螺仪噪声经微分放大）引起转向抖动。本系统采用串级控制结构（图5-2）：外环为角度环，以目标航向与实际航向的偏差为输入，输出期望角速度；内环为角速度环，以期望角速度与陀螺仪实测角速度之差为输入，输出转向指令。

串级结构的优势在于：车身扰动（如地面不平引起的角速度突变）在内环即被抑制，无需等角度偏差显现后才响应，等效于大幅提高了外环的抗干扰能力；同时内环将控制对象改造为近似的"角速度伺服系统"，外环只需面对一阶对象，参数整定大为简化。内环响应频率应显著高于外环（工程上一般取 5~10 倍），本系统内环与外环采用相同的 PD 参数并直接以内环输出限幅（±300）约束转向速度，实测航向阶跃响应无超调、到位后无摆动。
同理，目标接近控制也采用了"横向居中环 + 纵向定距环"的双环结构，两环分别以视觉像素偏差和 TOF 距离偏差为输入，输出经矢量合成后送入底盘，实现了接近过程中的空间解耦控制。
5.1.3　滤波算法
竞赛现场存在场地反光、电机振动、无线干扰等多种噪声源。传感器原始数据若直接进入控制环，噪声将被微分项放大，导致执行机构抖动、能耗增大甚至失稳。本系统综合运用了以下滤波方法：
（1）一阶低通滤波。 用于目标横向坐标的平滑以及开发早期 IMU 数据的预处理。其差分方程为：
公式3：y(k) = α·y(k−1) + (1−α)·x(k)
其中 α 为滤波系数。α 越大，滤波越强但相位滞后越大；α 越小则跟踪越快。本系统对 IMU 六轴数据取 α=0.3，在抑制高频振动的同时保持较小的相位滞后；对视觉目标坐标取 0.7/0.3 的加权比（即 α=0.7），重点抑制单帧误检引起的车辆横向抖动——因为目标坐标噪声主要来自帧间跳变，而非连续高频干扰，需要更强的平滑。
（2）算术平均滤波。 用于电池电压监测：ADC 连续采集 10 次电压数据取平均后与阈值比较，有效抑制了电源纹波与 ADC 量化噪声造成的误报警。
（3）卡尔曼滤波。 用于水平位置—速度的最优估计。系统将位置与速度建模为二维状态向量 X=[x, v]ᵀ，以编码器里程计作为位置观测、加速度计积分作为速度观测，按以下五条递推公式计算：
公式4：状态预测　X(k|k−1) = F·X(k−1)
公式5：协方差预测　P(k|k−1) = F·P(k−1)·Fᵀ + Q
公式6：卡尔曼增益　K(k) = P(k|k−1)·Hᵀ·(H·P(k|k−1)·Hᵀ + R)⁻¹
公式7：状态更新　X(k) = X(k|k−1) + K(k)·(Z(k) − H·X(k|k−1))
公式8：协方差更新　P(k) = (I − K(k)·H)·P(k|k−1)
其中状态转移矩阵 F=[[1, dt], [0, 1]]（匀速运动模型），观测矩阵 H 为单位阵。过程噪声 Q=diag(0.001, 0.01) 反映模型不确定性（速度噪声大于位置噪声），观测噪声 R=diag(0.0001, 1.0) 反映传感器特性——位置观测噪声取小值表示更信任编码器，速度观测噪声取大值反映加速度积分的不确定性。滤波器在预测—更新两步递推中按噪声协方差自适应加权，兼顾了里程计的长时稳定与惯性导航的短时响应，抑制了加速度二次积分随时间发散的问题。
（4）互补滤波（Mahony 算法）。 用于九轴姿态解算。其理论基础是传感器的频域互补特性：陀螺仪动态响应好、短时精度高，但积分存在长期漂移；加速度计与磁力计长期稳定（绝对基准），但易受振动和磁场干扰、动态精度差。将两者分别在低频段与高频段取信，即可在全频段获得理想估计。Mahony 算法以加速度计与磁力计观测误差经 PI 反馈校正陀螺仪漂移，再以校正后的角速度更新四元数，实质上是"积分陀螺仪 + 低频误差反馈"的互补滤波结构，计算量远小于卡尔曼滤波，适合在 MicroPython 解释执行环境下实时运行（详见 5.2.2 节）。
5.2　核心算法
5.2.1　PID 控制算法
PID 控制是环级控制层的基础，其连续形式为：
公式1：u(t) = Kp·e(t) + Ki·∫e(t)dt + Kd·de(t)/dt
式中 e(t) 为期望值与实测值之差；比例项即时响应误差、积分项消除稳态误差、微分项预报误差趋势并抑制超调。在微处理器中实现时将其离散化为位置式 PID：
公式2：u(k) = Kp·e(k) + Ki·Σe(j) + Kd·[e(k) − e(k−1)]
其中采样周期即控制周期 4 ms，Σ 为误差累加（积分项），e(k)−e(k−1) 为误差增量（微分项）。工程实现中针对两类饱和问题进行了处理：
积分饱和：任务切换或目标点突变时误差长时间同号，积分项累积过大，引起大超调与长时间震荡。软件中对积分项设置 ±inte_limit 限幅，并在状态切换、到达目标点、推送结束等时机主动清零积分项与微分项历史值（inlast/integral），避免上一状态的控制量污染下一状态；
输出饱和：当输出超出电机量程（±5500）时钳位，防止执行机构过载，也避免了饱和期间积分继续累积（配合限幅后系统实际具备一定的积分抗饱和能力）。

各环设计要点如下：
轮速环是全部控制的基础。三个电机因减速比、摩擦特性的个体差异必须分别闭环。调试中先以纯比例环节建立基本跟随能力，再引入微分抑制超调，最后以小量积分消除静差；积分限幅 10000 保证稳态误差快速收敛又不会失控；
角度环与角速度环构成串级（见 5.1.2）。角度环输出经限幅 ±250 后作为角速度环的期望值，角速度环以陀螺仪 X 轴角速度为反馈。角度误差计算中处理了 ±180° 跳变（误差先归一化到 [−180°, 180°] 再计算），保证车辆始终沿最短路径转向，不会出现"绕远路转大圈"的现象；
距离环以剩余距离为误差、输出行驶速度，天然实现"远端快速、近端减速"的软着陆效果：距离远时速度受限幅 70 顶满，接近目标时速度随距离线性下降，避免了定点急停造成的惯量冲击与打滑。到达判定距离 ≤1 cm 时输出到位标志；
TOF 定距环与居中环用于目标接近，均为小增益比例（微分）环节并设严格输出限幅，保证接近目标时动作柔和，避免碰撞与目标物被撞飞。
5.2.2　基于 Mahony 互补滤波的九轴姿态解算
姿态解算是航向控制与惯性导航的基础。本系统采用逐飞 IMU963RX 九轴传感器（三轴加速度计 + 三轴陀螺仪 + 三轴磁力计），运行 Mahony 互补滤波算法，在 4 ms 控制中断中完成一次完整解算，步骤如下：
（1）数据预处理与标定。 上电静置时采样三轴陀螺仪输出取均值得到零漂（本车标定值为 gx=0.696、gy=−6.353、gz=−4.341），运行时原始值减去零漂并按灵敏度系数 14.3 LSB/(°/s) 换算为弧度制角速度；加速度计与磁力计数据分别进行模长归一化，消除量纲影响。采样周期 dt 由定时器时标实测获得（对异常值限幅在 0.02 s 内，缺省取 0.004 s），避免中断延迟引入积分误差。
（2）参考矢量估计。 由当前四元数 q=(q0, q1, q2, q3) 计算出重力方向在机体系中的估计值 (vx, vy, vz)；由归一化磁场数据结合四元数先计算地磁水平分量 (bx, bz)，再反推出机体系中的地磁参考矢量 (wx, wy, wz)。
（3）误差计算与 PI 校正。 将加速度计实测值与重力估计值叉乘得到姿态误差，磁力计实测值与地磁参考叉乘得到航向误差：
公式9：e_acc = a_meas × v_est，e_mag = m_meas × w_est
叉乘结果的方向与幅值反映了估计姿态与真实姿态的偏差。按磁力计权重 MAG_K=0.8 融合两类误差后（e = e_acc + 0.8·e_mag），经 PI 环节校正陀螺仪：
公式10：g = g_raw + Kp·e + Ki·∫e·dt
其中 Kp=1.5、Ki=0.0005。积分项持续补偿陀螺仪零漂的缓慢变化（温漂），使系统对零漂标定误差具有自适应能力。
（4）四元数更新。 以校正后的角速度求解四元数微分方程并作一阶数值积分，随后对四元数归一化，抑制数值误差累积：
公式11：dq/dt = ½·Ω(ω)·q
（5）欧拉角输出。 由四元数换算欧拉角供控制系统使用：
公式12：
roll = atan2[2(q0q1+q2q3), 1−2(q1²+q2²)]·180/π
pitch = asin[2(q0q2−q3q1)]·180/π
yaw = atan2[2(q0q3+q1q2), 1−2(q2²+q3²)]·180/π
其中 yaw 归一化到 0°~360° 区间，与全局坐标系的航向定义一致。
磁力计的融合使 yaw 角具备绝对航向基准，长时间运行不漂移，这是纯陀螺仪积分方案无法实现的；加速度计校正则保证了动态过程中横滚、俯仰角的准确。实际测试中，车辆连续行驶 3 分钟后航向误差小于 2°，完全满足任务要求。
5.2.3　三全向轮运动学解算
本车底盘采用三全向轮结构，三个轮子沿圆周 120° 均布，轮缘小滚子使轮子具有横向滑动能力。全向底盘的运动由平移速度 v、平移方向角 θ 与旋转角速度 ω 三个自由度合成。
（1）逆运动学——指令解算。 控制层给出合速度指令 (v, θ, ω) 后，需要解算为三个轮子的目标转速。每个轮子的线速度等于平移速度在其轴线法向上的投影与旋转速度的叠加：
公式13：V_i = v·cos(θ_i − θ) + ω，i = 1, 2, 3
其中 θ_i 为第 i 个轮子轴线相对参考方向的角度。软件中 speed_get() 函数按此模型实现（三个轮子分别对应 0°、−60°、+60° 布局），并对 ω 做 ±180° 归一化处理。该函数同时承担限幅与符号定义职责。这一解算模型使车辆可以在不改变航向的情况下沿任意方向平移（如推送目标物时以 90° 方向侧移），也能在保持位置的同时原地旋转（搜索扫描），为全部任务动作提供了运动学基础。
（2）正运动学——里程计解算。 编码器里程计是逆过程的运用：40 ms 采集周期内得到三路编码器脉冲增量后，按安装角加权求和得到车体系位移矢量，再依据 yaw 角旋转投影到全局坐标系：
公式14：
ΔX = [n_md·cos(ψ−90°) + n_ul·cos(ψ+150°) + n_ur·cos(ψ+30°)] / K
ΔY = [n_md·sin(ψ−90°) + n_ul·sin(ψ+150°) + n_ur·sin(ψ+30°)] / K
其中 ψ 为当前 yaw 角，n_i 为本周期脉冲增量，K 为标定系数（27 脉冲/cm）。由于三个轮子受电机接线方向、编码器极性的影响，实际安装角存在符号差异，公式中的角度数值以实测校准结果为准

5.2.4　惯性导航与多传感器定位
本车以编码器里程计为主、惯性导航为辅实现全场定位。
（1）编码器里程计。 在 40 ms 定时中断中读取三路 575 线正交编码器脉冲增量，经限幅（±80）剔除干扰毛刺后，按公式14解算位移并累加得到全局坐标 (X, Y)。针对误差来源采取了以下措施：
打滑补偿：推送目标物时驱动轮打滑，轮速虚高而位移不足。系统在推送工况下分方向动态修正标定系数（直线推送时 X/Y 方向分别取 27/35 或 36/27 脉冲/cm），使坐标估计与真实位移吻合；
跳变保护：当单次脉冲增量异常（|Δ|>1000）时判定为采集故障，重置累计器并放弃本周期积分，防止坐标突变引发任务误判；
边界刷新：检测到场地黄色边界线时，以黄区的精确几何参数强制刷新坐标，消除多轮任务间的累计误差（详见 5.2.6 节）。
（2）加速度计惯性导航。 将加速度计数据经坐标系旋转与重力补偿投影到水平面后，采用梯形积分法先积出速度、再积出位置。由于加速度二次积分误差随时间平方增长，单独使用会在数秒内发散，故设计了 5.1.3 节所述的二维卡尔曼滤波器，以"编码器提供位置、加速度计提供速度"的方式融合两路信息。
实际调试表明，在场地平整、轮压稳定的竞赛条件下，配合上述补偿策略后纯编码器里程计即可满足任务所需的定位精度，故决赛代码以编码器里程计为主要定位手段，卡尔曼融合框架保留为冗余方案，用于冲击、碰撞等特殊工况下的位置修正。

5.3.2　双中断任务调度
系统采用双定时器中断架构，按实时性要求划分任务：
PIT2 控制中断（4 ms）：依次执行九轴姿态解算（Mahony）→ 状态机控制量计算（move_speed/move_angle/turn_speed）→ 全向轮逆运动学解算（speed_get）→ 三路速度环 PID → 电机 PWM 输出。这是实时性要求最高的闭环控制链路，由硬件定时器保证周期严格恒定；
PIT1 采集中断（40 ms）：编码器数据读取与限幅 → 里程计解算与坐标累加。周期较长但足以覆盖全速运行范围的脉冲计数；
主循环：承担 LCD 多行显示（坐标、航向、状态编号、传感器原始数据等 15 行）、串口协议解析、电池监测、状态切换判定等非实时任务，并在每轮循环末尾调用 gc.collect() 回收内存。
传感器采集由 ticker 硬件的 capture_list 机制自动完成（PIT2 关联 IMU 与 TOF，PIT1 关联三路编码器），中断回调中仅执行必要的计算，进一步降低了中断开销。分层调度使 CPU 负载均衡，避免了长任务挤占控制周期的问题；实测中断处理时间稳定在 1.5 ms 以内，留有 60% 以上的周期余量。

5.3.3　关键模块实现思路
（1）PIDController 类。 封装 kp/ki/kd、积分限幅、输出限幅等属性，提供两个接口：compute() 为通用位置式 PID，用于轮速环、距离环、TOF 环与居中环；compute_theita() 专用于角度环，内部先对角度误差做 ±180° 归一化，再经角度环 PID 生成期望角速度，最后调用角速度环 PID 以陀螺仪角速度为反馈完成串级计算。状态切换时由上层主动清零积分与微分历史，保证状态切换后的控制量平滑过渡，杜绝"上一个状态的输出突跳"。
（2）状态机实现。 使用字典将状态名映射为整数索引（state_index），配合目标类别索引（obj_index：方块 0、熊 1、球 2、空 3），使状态转移代码可读性强、便于扩展。每个状态的入口动作（清零 PID、复位标志位、初始化计数器）集中编写在转移处，保证状态间边界清晰。
（3）通信协议处理。 串口接收采用"先查长度再定长读取"的方式（any() 查询 + read(5) 定长读取），辅以帧长校验与无效值（899）过滤：帧长不等于 5 的残缺帧直接丢弃，未检测到目标时不更新坐标。接收逻辑只在对应状态的主循环分支中执行，避免无效数据污染其他状态。
（4）初始化序列。 上电后按序完成：GPIO（LED、蜂鸣器、拨码开关）→ 编码器 → 双串口（视觉 115200、无线 460800）→ 三电机 → IMU → 电池 ADC → LCD（含片选复位时序）→ TOF → 定时器启动。陀螺仪零漂标定值与全部 PID 参数以常量形式固化在程序中，上电即进入可运行状态。
5.3.4　可靠性设计
异常保护：拨码开关随时可终止程序运行，防止调试时失控；
电池监测：ADC 经 11 倍分压电路采集电池电压，换算公式 V = N·11/19520，连续 10 次均值滤波后与 11.297 V 阈值比较，欠压时蜂鸣器与 LED 报警，提醒更换电池；
内存管理：全部滤波状态、PID 状态、坐标变量等采用预分配的全局变量，杜绝中断内动态分配内存；主循环定期执行垃圾回收，长时间运行无内存异常；
数据限幅：编码器脉冲（±80）、控制输出（各环限幅）、积分项均设限幅，任何单点故障都不会造成满功率失控输出；
无效值过滤：TOF 的 8192、视觉坐标的 899 等传感器无效标志被统一过滤，保证控制环输入始终有效。

6.2　制作与安装
整车采用三层结构设计：底层安装电池与三路电机驱动板，中层为主控核心板与编码器接口，顶层安装 IMU、OpenART mini 视觉模块、线性 CCD 与 TOF 测距模块。制作安装过程与关键注意事项如下：
（1）底盘与动力系统装配。 三个全向轮按 120° 均布安装，轮轴指向车体中心；电机与轮子同轴直连，编码器安装于电机尾部。装配完成后逐轮通电检查旋转方向，通过电机初始化参数（invert）与编码器极性参数（True/False）统一方向定义，确保公式13、公式14中的符号体系一致——这是运动学解算正确的前提，任何一路方向错误都会导致全向运动互相"打架"。
（2）电路安装。 主控核心板固定于中层，电源经稳压模块给主控供电；ADC 通过 11 倍分压电阻网络采集电池电压，分压电阻选用 1% 精度并经实测标定比例系数（对应换算公式中的 19520 系数）；全部接口线缆按长度裁剪并做绝缘处理。
（3）传感器安装。 IMU 安装于车体旋转中心正上方，轴线与车体系严格对齐——远离旋转中心会引入杠杆臂效应，旋转时离心加速度叠加到加速度计输出上，直接破坏姿态解算精度；安装面粘贴减振棉抑制电机振动。OpenART mini 与线性 CCD 安装于车体前上方，俯仰角可调，安装高度与角度经反复试验确定：过高易丢失近距离目标，过低则视野受限。TOF 模块水平安装于目标物高度，避开反光金属件干扰光路。
（4）整车走线与安全措施。 所有线缆扎带固定，防止运动中的剐蹭导致接触不良；保留拨码开关作为紧急停止装置；蜂鸣器与 LED 用于欠压报警。整车重心压低，保证急停与转向时的稳定性。
6.3　调试过程
调试遵循"先底层后上层、先单环后整体"的原则分阶段进行，全部调试数据通过车载 LCD 与无线虚拟示波器实时观察。
6.3.1　底层驱动调试
逐项验证各外设的驱动与电气连接：电机 PWM 输出与占空比线性度、编码器计数方向与分辨率（575 线 ×4 倍频）、IMU 九轴数据刷新率、TOF 量程与精度、无线串口收发误码率、LCD 显示。底层验证通过后才开始搭建上层控制，避免"上层问题与底层问题纠缠"的调试困境。
6.3.2　传感器标定
（1）陀螺仪零漂标定。 车体静置，连续采样三轴陀螺仪输出取均值，得到零漂 (0.696, −6.353, −4.341)，写入程序作固定补偿。调试中发现零漂还会随温度缓慢变化，Mahony 算法中的积分反馈项（Ki=0.0005）可在运行中进一步自适应补偿残余零漂。
（2）编码器—位移标定。 让车辆直线行驶已知距离（1 m），记录脉冲总数，反推标定系数 K≈27 脉冲/cm。在推送任务测试中发现轮子打滑导致实际位移偏小，又针对推送工况分方向标定（Y 方向 35 脉冲/cm、X 方向 36 脉冲/cm），使坐标估计与真实位置吻合。标定过程反复多次取均值，并在预赛、决赛场地分别复测。
6.3.3　PID 参数整定
按"先内环后外环、先比例后积分再微分"的顺序整定，全程用虚拟示波器观察响应曲线：
轮速环：先令 Kp 逐渐增大至阶跃响应出现轻微振荡，记录临界值；再引入 Kd 抑制超调，最后加入小量 Ki 消除静差并设置积分限幅 10000。最终 Kp=103.2、Ki=5.8、Kd=1.45，阶跃响应快速且无超调，稳态误差趋零；
角度环：最初采用单环 PD 整定，发现大角度误差下转向过冲、小角度误差下响应迟钝，遂改为串级结构——外环 Kp=0.85、Kd=0.025 生成期望角速度（限幅 ±250），内环以陀螺仪角速度闭环（限幅 ±300）。改造后转向过程平顺，到位后无摆动，原地旋转扫描时航向跟随误差小于 2°；
距离环与接近环：距离环采用 PD（Kp=1.0、Kd=0.0002、限幅 70）实现"远端快速、近端减速"；TOF 定距环与居中环仅用比例（微分）环节并设输出限幅（±100），保证接近目标时动作柔和。整定中发现居中环增益过大会引起车辆横向来回摆动，最终取 Kp=0.235，摆动幅度控制在 ±2 cm 内。
6.3.4　功能调试
（1）状态机逐状态验证。 每实现一个状态，先将其设为初始状态单独验证（如 test 状态即为此用途），验证通过后再联入整体流程。状态机完整联调后，在场地上一遍遍跑完整任务流程，记录每个状态的耗时与切换原因，针对性优化：如缓启动时间由 1 s 逐步缩短至 0.4 s，在"起步不打滑"与"任务总时长"之间取得平衡。
（2）视觉识别联调。 与 OpenART mini 联调时首先验证串口帧格式（表5-3），逐帧核对坐标与类别编码；随后在场地不同光照、不同距离下测试识别稳定性，据此引入三帧投票确认与坐标低通滤波。目标锁定阈值（|x−160|≤25、TOF<120 mm、持续 55 周期）经过多次调整：过严导致锁定困难、任务卡死，过松导致误触发提前进入推送。
（3）双车联调。 两车在无线环境下反复测试协同时序：发送坐标帧→队友回报 '1'→本车启动二次推送。调试中曾出现帧丢失导致双方互相等待的死锁，加入双发冗余与固定帧长校验后死锁概率降为零；同时保留超时保护逻辑，确保极端情况下任务仍能继续。
6.3.5　典型问题与解决
调试过程中记录的主要问题及解决措施如下：
1. 原地旋转时里程计漂移。现象：车辆原地旋转一圈后坐标偏离达数厘米。原因：三全向轮轮径与安装角存在制造误差，旋转时各轮合成位移不为零。解决：对旋转工况单独标定修正；并在每轮任务结束后用黄区几何信息强制刷新坐标，将累计误差限制在一轮任务内；
2. 推送时坐标估计偏小。现象：推送目标物后坐标显示未到位而实际已到位。原因：驱动轮打滑，轮速虚高而位移不足。解决：分工况标定脉冲/厘米系数（35/36 脉冲/cm），并在推送结束后按目标类别补偿坐标（+30/+15/−30 cm）；
3. 目标误识别。现象：OpenART mini 单帧识别结果不稳定，连续帧间类别跳变，曾导致推送策略错误。解决：引入三帧一致投票确认机制与坐标低通滤波（0.7/0.3），误识别率大幅下降；
4. 无线通信丢包。现象：双车协同等待时队友车偶发收不到同步帧，任务卡死。解决：发送端同帧双发冗余，接收端固定帧长校验；并保留超时保护，超时后按默认策略继续执行；
5. TOF 受环境干扰。现象：强反光地面与金属目标物造成 TOF 数据偶发跳变（返回无效值 8192）。解决：无效值过滤置零、距离缩放系数限幅，并联合横向坐标进行多条件锁定判定，单传感器异常不再导致任务中断；
6. 电池电压跌落影响性能。现象：多轮任务后电机输出力矩下降、速度环跟踪变差。原因：电池内阻增大、电压跌落。解决：加入欠压监测与报警（11.297 V 阈值），赛前统一充电并规定换电流程；
7. MicroPython 内存碎片。现象：长时间运行偶发内存不足、代码执行卡顿。解决：传感器与滤波数据全部使用预分配全局变量，中断内禁止动态分配；主循环定期 gc.collect()，连续运行 10 分钟以上无内存异常；
8. 起步打滑与推球失控。现象：全速起步瞬间车轮打滑，球被撞飞偏离方向。解决：起步与推送阶段改用 Sigmoid 速度曲线（总时长 0.4 s）平滑加速，推球时同时锁定航向（车身 180°、推送方向 90°），推送成功率显著提高。

    halfT = 0.5 * dt
    q0 = Q_info.q0
    q1 = Q_info.q1
    q2 = Q_info.q2
    q3 = Q_info.q3

    # 归一化加速度
    norm = fast_sqrt(ax*ax + ay*ay + az*az)
    ax *= norm
    ay *= norm
    az *= norm

    # 重力方向估计
    vx = 2 * (q1*q3 - q0*q2)
    vy = 2 * (q0*q1 + q2*q3)
    vz = (q0*q0 - q1*q1 - q2*q2 + q3*q3)

    # 误差计算
    ex = ay * vz - az * vy
    ey = az * vx - ax * vz
    ez = ax * vy - ay * vx

    # 积分限幅
    I_ex += ex * dt
    I_ey += ey * dt
    I_ez += ez * dt
    I_ex = max(-5.0, min(5.0, I_ex))
    I_ey = max(-5.0, min(5.0, I_ey))
    I_ez = max(-5.0, min(5.0, I_ez))

    # PI校正陀螺仪
    gx += param_Kp * ex + param_Ki * I_ex
    gy += param_Kp * ey + param_Ki * I_ey
    gz += param_Kp * ez + param_Ki * I_ez

    # 四元数微分更新
    dq0 = (-q1*gx - q2*gy - q3*gz) * halfT
    dq1 = ( q0*gx + q2*gz - q3*gy) * halfT
    dq2 = ( q0*gy - q1*gz + q3*gx) * halfT
    dq3 = ( q0*gz + q1*gy - q2*gx) * halfT

    # 二阶修正
    delta_2 = (2*halfT*gx)**2 + (2*halfT*gy)**2 + (2*halfT*gz)**2
    q0 = (1 - delta_2/8) * q0 + dq0
    q1 = (1 - delta_2/8) * q1 + dq1
    q2 = (1 - delta_2/8) * q2 + dq2
    q3 = (1 - delta_2/8) * q3 + dq3

    # 四元数归一化
    norm = fast_sqrt(q0*q0 + q1*q1 + q2*q2 + q3*q3)
    Q_info.q0 = q0 * norm
    Q_info.q1 = q1 * norm
    Q_info.q2 = q2 * norm
    Q_info.q3 = q3 * norm

def altitude_calc():
    global eulerAngle
    global init_angle
    global ax_f, ay_f, az_f, gx_f, gy_f, gz_f
    global alt_count,alt_sum
    # 1. 读取 LSM6DSR 数据
    imu_data = imu.get()
    ax = imu_data[0]
    ay = imu_data[1]
    az = imu_data[2]
    gx = imu_data[3]
    gy = imu_data[4]
    gz = imu_data[5]
    
        
    
    # 2. 低通滤波
    imu_update_acc(ax, ay, az, gx, gy, gz)
    
#     alt_count+=1
#     alt_sum += gyro_data[1]
#     if alt_count == 1000:
#         print(alt_sum/1000)
      
    # 3. 减去陀螺仪零偏 + 单位转换
    gx_f = -(gyro_data[0] - gyro_x_offset) /14.3 * PI / 180.0
    gy_f = -(gyro_data[1] - gyro_y_offset) /14.3 * PI / 180.0
    gz_f = -(gyro_data[2] - gyro_z_offset) /14.3 * PI / 180.0
    ax_f = -acc_data[0]
    ay_f = -acc_data[1]
    az_f = -acc_data[2]


    # 4. AHRS 解算
    ICM_AHRSupdate(gx_f, gy_f, gz_f, ax_f, ay_f, az_f)
    q0 = Q_info.q0
    q1 = Q_info.q1
    q2 = Q_info.q2
    q3 = Q_info.q3

    # 5. 四元数转欧拉角
    eulerAngle.pitch = math.asin(-2 * q1 * q3 + 2 * q0 * q2) * 180.0 / PI
    eulerAngle.roll  = math.atan2(2 * q2 * q3 + 2 * q0 * q1, -2*q1*q1 -2*q2*q2 +1) * 180.0 / PI
    eulerAngle.yaw   = math.atan2(2 * q1 * q2 + 2 * q0 * q3, -2*q2*q2 -2*q3*q3 +1) * 180.0 / PI
    eulerAngle.yaw = eulerAngle.yaw + init_angle
    # Yaw 范围限定 0到360
    if eulerAngle.yaw > 360:
        eulerAngle.yaw -= 360
    if eulerAngle.yaw < 0:
        eulerAngle.yaw += 360

    # 大角度保护（防止翻车跳变）
    if abs(eulerAngle.pitch) > 70.0:
        eulerAngle.roll = eulerAngle.last_roll
        eulerAngle.yaw  = eulerAngle.last_yaw

    # 转圈计数
    if (eulerAngle.yaw - eulerAngle.last_yaw) < -350:
        eulerAngle.Dirchange += 1
    elif (eulerAngle.yaw - eulerAngle.last_yaw) > 350:
        eulerAngle.Dirchange -= 1

    eulerAngle.last_roll = eulerAngle.roll
    eulerAngle.last_yaw  = eulerAngle.yaw
    #print(str(eulerAngle.yaw)+"\r\n")
