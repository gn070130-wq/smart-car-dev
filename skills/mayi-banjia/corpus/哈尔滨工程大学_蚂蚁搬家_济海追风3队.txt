第一章 引言
1.1竞赛背景与任务概述
全国大学生智能汽车竞赛是一项面向全国大学生的综合性工程实践赛事，旨在培养参赛者在机械结构、电子系统、智能感知与运动控制等方面的综合能力。第二十一届竞赛增设的蚂蚁搬家组要求参赛队伍制作两辆搬运车模，协同完成物品搬运任务。搬运物品需由两辆或以上车模共同推动，物品在搬运过程中不得离开地面。两辆搬运车模之间允许通过无线通信进行信息交互，但不允许存在物理连接。
1.2 模型车总体设计思路
本队采用主从双车方案，车模以自制Y型车模为基础进行改制。主车与从车均使用PCB板作为主控载体，将NXP RT1021微控制器、IMU660RB六轴姿态传感器、电机驱动电路等集成于一体。两车各搭载一枚Open Art摄像头，主车摄像头朝前用于赛道与物品识别，从车摄像头朝前用于识别主车尾部的红外LED灯板，通过双灯点检测方案解算横向偏移、纵向距离和角度偏移，实现稳定跟随。主从车之间通过逐飞无线串口模块V2.4进行状态信息交互。物品识别采用Open Art训练的模型对网球、玩具沙袋和泰迪熊进行分类识别，双车协同完成搬运任务。
1.3 本文主要内容
全文共八章。第一章介绍竞赛背景与总体设计思路；第二章说明系统总体方案；第三章、第四章分别介绍机械结构与硬件系统设计；第五章说明软件系统与控制算法；第六章给出系统调试过程；第七章汇总模型车主要技术参数；第八章总结设计收获。附录给出电路板实物图和程序源代码节选。


第二章 系统总体方案
2.1 设计目标
系统设计以稳定完成蚂蚁搬家组搬运任务为首要目标。两辆搬运车模需在3.2米×2.4米的矩形场地内，将位于场地中央的三类物品（网球、玩具沙袋、泰迪熊）协同搬运至场地四周目标区域。预赛阶段只需将物品推至黄色边界线外即为成功，决赛阶段需按类别分类放置至指定区域。
两车之间不允许有物理连接，但允许通过无线通信进行信息交互。系统需在满足车身尺寸（含推杆不超过30cm）和重量要求的前提下，实现领航车路径规划、跟随车红外信标识别、双车协同搬运与物品分类的完
2.2 系统组成
系统由两辆搬运车模、感知与决策模块、运动控制模块和通信模块四部分组成。领航车与跟随车均以自制Y型车模为载体，搭载NXP RT1021微控制器（符合竞赛MicroPython编程要求），通过PCB主板集成IMU660RB六轴姿态传感器、电机驱动电路等核心组件。两车各配备一枚Open Art摄像头（符合竞赛图像处理平台要求）进行视觉感知，领航车摄像头朝前用于赛道与物品识别，跟随车摄像头朝前用于识别领航车侧端安装的红外LED灯板。
两车之间通过逐飞无线串口模块V2.4进行状态信息交互，领航车将自身车速、转向状态和任务阶段等信息发送给跟随车。执行层面采用GA12-N20减速马达编码器作为动力单元，该电机自带霍尔编码器，可提供实时轮速反馈。车模采用三轮全向底盘结构，全车共三台GA12-N20电机，通过三个轮子的协同转动实现前后移动、横向平移与原地旋转，为搬运任务提供灵活的运动能力。
2.3 系统层级与功能划分
系统分为感知层、决策层和执行层三个层级。
感知层由两车的Open Art摄像头、IMU660RB姿态传感器和GA12-N20电机内置的霍尔编码器组成。领航车摄像头获取前方赛道与物品图像，跟随车摄像头获取领航车侧端红外灯板图像，姿态传感器提供车辆姿态信息，霍尔编码器反馈各轮实时转速。
决策层运行于NXP RT1021微控制器（MicroPython环境）。领航车侧完成物品目标检测（网球、沙袋、泰迪熊三类）、赛道元素识别和路径规划；跟随车侧完成红外灯板双灯点检测，通过解算两灯点连线的中点横向偏移、灯点间距（纵向距离）和连线角度偏移，得到领航车相对于自身的位姿信息。双车决策结果通过无线串口模块交互，协同生成行驶与搬运指令。
执行层由三台GA12-N20减速马达（每车三台，两车共六台）和推杆组成。车辆采用全向运动方案，三个电机独立驱动，通过调节各轮转速与转向的组合实现全向移动，无需舵机转向结构。全向底盘支持横向平移与原地旋转，便于在搬运物品时精准调整车身姿态。推杆用于推动搬运物品（长度≤10cm，高度≤5cm）。
2.4 信息闭环
系统工作流程形成完整闭环：领航车摄像头采集前方图像→感知层识别赛道与物品→决策层生成路径与搬运策略→执行层驱动三台电机协同运动→跟随车摄像头采集领航车侧端红外灯板图像→解算相对位姿→跟随车调整三轮回转组合以保持稳定跟随。领航车同时通过无线模块将自身状态（车速、转向、任务阶段）发送给跟随车，辅助跟随车决策。
搬运任务触发时，领航车识别物品位置后引导跟随车靠近，双车协同推动物品至目标区域，完成后继续赛道行驶。两车之间通过无线通信保持状态同步，但不依赖无线信号进行实时控制，各车独立基于自身传感器完成基本行驶与跟随行为。GA12-N20电机内置的霍尔编码器为速度环PID控制提供实时反馈，确保三轮转速协同精度。
2.5 本章小结
本章给出了蚂蚁搬家组搬运车模的系统总体方案。系统以领航-跟随双车协同模式为核心，以NXP RT1021+OpenMV Art为感知与决策平台，通过红外灯板双灯点检测实现跟随车对领航车的稳定跟随，通过三轮全向底盘与GA12-N20减速马达编码器实现灵活运动与速度闭环控制，通过无线串口模块实现双车状态交互，最终形成感知→决策→执行→反馈的完整信息闭环。后续各章将分别从机械结构、硬件电路和软件算法三个方面对系统进行详细说明。


第三章 机械结构与传感器安装
3.1 车模总体结构
车模采用PCB主驱一体板兼作车身底板的结构设计，根据整车外形和各功能模块的安装位置对PCB轮廓进行设计，使其同时承担电路载体和机械底盘的作用。与传统独立底板上叠加多块电路板的结构相比，该方案省去了额外的底板、电路板支架和部分连接线束，能够大幅减轻整车重量，并提高空间利用率。
整车仅使用一块主驱一体板，电机驱动、电源管理、传感器及外设接口均集中布置在底板区域，使主要部件靠近车体底部，降低了整车重心，提高了车辆行驶和搬运过程中的稳定性。PCB上预留电机支架、OpenArt Plus摄像头支架及其他结构件的安装孔位，便于各部件准确定位和快速装配，同时减少额外转接结构对车体重量和尺寸的影响。

3.2 驱动与全向轮结构
每辆车采用三台GA12-N20一体式编码减速电机，没有采用任何其他伺服电机，并分别安装全向轮，构成三轮全向移动底盘。三组电机和全向轮按照车体结构均匀布置，由板载DRV8874驱动电路进行独立控制。通过调节三台电机的旋转方向和转速比例，车辆能够实现前后移动、横向移动、斜向移动、原地旋转以及移动过程中同步调整车身方向。
全向轮轮缘由多个可自由转动的小滚轮组成，能够在提供主驱动力的同时允许车辆沿侧向运动，因此不需要设置传统舵机转向机构。三轮全向驱动方式具有转向半径小、运动方向灵活等特点，便于智能车在有限空间内完成位置调整、对准及协同搬运任务。装配时需要保证三组电机的安装角度、全向轮高度和轮面接触状态一致，避免机械误差影响车辆运动方向和控制精度。
3.3 摄像头安装
主车与从车均安装OpenArt Plus摄像头，用于采集目标及周围环境图像，其检测图像的分辨率为120*160，运行时动态帧率稳定值为11。摄像头通过PCB底板上预留的支架安装孔进行固定，以减少车辆运动过程中摄像头的晃动。主车摄像头上边沿距地面19.5 cm，从车摄像头上边沿距地面14.2 cm。安装时应保证摄像头朝向与车体坐标系一致，并根据实际识别范围调整摄像头俯仰角度。

第四章 硬件系统设计
4.1 硬件总体架构
硬件系统由主控制板、执行机构、传感器、视觉识别模块、红外灯板、电源和人机交互模块组成。RT1021核心板作为整车主控制器，连接三路GA12-N20一体式编码减速电机、板载IMU660RB六轴惯性传感器、0.96英寸OLED显示屏、OpenArt Plus摄像头和红外灯板，完成车辆状态采集、图像识别、运动控制、任务执行及运行参数显示。红外灯板用于为摄像头提供辅助照明，减小环境光线变化对图像采集和目标识别的影响。
4.2 主控制器
主控制板MCU采用逐飞科技RT1021核心板，配置三路GA12-N20一体式编码减速电机接口、0.96英寸OLED显示屏接口、板载IMU660RB六轴惯性传感器接口以及OpenArt Plus摄像头接口。RT1021核心板负责采集三路电机编码器、IMU和摄像头数据，根据车辆运动状态及视觉识别结果完成任务决策和运动控制，并向电机驱动模块输出控制信号。OLED显示屏用于显示电机转速、传感器数据、运行模式及系统参数，便于整车调试和状态监测。
4.3 驱动、转向与传感器
每台车使用3台GA12-N20一体式编码减速电机，采用板载DRV8874三驱模块进行驱动，实现各电机的独立调速、正反转和制动控制。三台电机分别通过一体式编码器获取转速和运行方向反馈，为车辆运动控制和位置计算提供输入。板载IMU660RB六轴惯性传感器采集三轴加速度和三轴角速度信息，用于车辆姿态估计和运动状态判断。0.96英寸OLED显示屏用于系统状态显示和参数设定，OpenArt Plus摄像头配合红外灯板完成目标图像采集与识别。

4.4 电源系统
车模使用3S、300 mAh锂电池作为整车能源，电池直接为主驱一体板提供输入。主驱一体板上的SCT2450STER降压芯片产生5 V系统电源，并分为两路向不同模块供电。其中一路5 V电源经过SY6820上电时序控制开关，为无线通信模块、OpenArt Plus摄像头和红外灯板等外设供电，通过控制外设上电顺序减小启动瞬间的电流冲击；另一路5 V电源经过RT9013稳压芯片转换为3.3 V，为按键、编码器接口和OLED显示屏等模块提供稳定电源。该供电结构将大功率外设与低压数字模块分开供电，有利于减小电机及外设启停对控制系统的干扰，提高整车供电的稳定性。
4.5 电路板设计
整车采用主控与电机驱动一体化设计，将RT1021核心板接口、DRV8874电机驱动电路、电源转换电路、传感器接口、OLED显示屏接口、摄像头接口及无线通信接口集成在主驱一体板上。与主控制板、电机驱动板和电源板分开布置的方案相比，主驱一体化设计能够减少电路板数量和板间连接线，降低整车重量及空间占用，同时缩短电源与控制信号传输路径。该设计还可减少连接器松动和线束接触不良等问题，提高整车装配效率、结构紧凑性与运行可靠性。

第五章 软件系统与控制算法
5.1 软件总体结构
软件系统分为从车跟随控制与主车任务调度两部分，均运行于MicroPython环境。从车负责接收Open Art摄像头对红外灯板的识别结果（横向偏移、纵向距离、角度偏移），通过PID控制器计算三台电机的速度指令，实现稳定跟随。主车负责赛道行驶、物品识别与搬运任务调度，同时通过无线串口模块向从车发送自身运动状态及任务指令。两车软件独立运行，通过逐飞无线串口模块V2.4进行信息交互。

从车程序采用10ms定时器中断作为控制核心，包含编码器采集、IMU角度积分、运动学逆解和电机PID速度闭环等模块。主车程序采用状态机架构，将完整比赛流程划分为初始化、目标搜索、目标跟踪、绕行对准、冲刺前进、返航等多个阶段，各阶段之间通过视觉识别结果和计时器进行跳转。
5.2 从车跟随控制算法
5.2.1 总体控制框架
从车通过Open Art摄像头识别主车尾部的红外灯板，获取三个误差量：

：两灯点连线中点与图像中心的横向偏移，用于控制侧向纠偏；

：两灯点之间的像素距离，反映主从车纵向间距，用于控制前后速度；

：两灯点连线与水平方向的夹角，用于控制航向角跟随。

三个误差量经一阶低通滤波后，分别送入三个独立的PID控制器，输出对应方向的速度分量，再经运动学逆解分配至三台电机。

第六章 开发工具与系统调试
6.1 主要开发工具
本系统软件开发使用Thonny IDE（MicroPython程序）、VS Code（上位机调试）、OpenMV IDE（视觉模型部署）和逐飞助手（串口监视与PID调参）。机械结构使用SolidWorks设计，包括电机连接件、推杆和尾部保护轮等定制零件。
6.2 制作与安装
机械部分按建模、加工、试装、修正的顺序完成。电机连接件和推杆采用3D打印加工，推杆尺寸符合规则要求（长度≤10cm，高度≤5cm）。尾部保护轮用于防止两车碰撞时卡死，确保接触后能相对滑动或分离。装配后检查活动部件灵活性与紧固件防松。

电气部分按先电源后信号、先主控后外设的顺序连接。完成动力线、编码器信号线和UART通信线布线，使用扎带和热缩管固定线束。
6.3 调试方法
调试按模块→联调→整车的顺序进行。模块调试检测电源、电机方向、编码器和IMU校准；视觉调试在OpenMV IDE中完成图像采集与模型推理验证；通信调试验证无线串口和UART收发；联调测试在跑道上进行全链路双车跟随试验；整车测试完成低速单圈、连续三圈和搬运任务全流程。
6.4 典型问题与处理
光线变化导致黄线识别不稳定，通过自适应阈值分割加灰度拉伸和中值滤波解决。物体误识别因训练数据缺乏阴影样本，通过补充多样化数据加多帧投票确认解决。无线通信丢包因同频干扰，通过更换频道加通信监控与安全保护解决。从车跟随振荡因PID微分增益偏大，通过优化参数加动态增益调度解决。
6.5 参数整定过程
PID参数整定采用工程整定法，按先比例后微分再积分的顺序逐步确定。速度环参数通过架空电机观察编码器反馈进行整定；视觉环参数通过逐飞助手实时记录误差信号与控制输出波形进行整定，在各参数组合下观察响应速度和超调量，最终选取使系统兼具快速性与稳定性的折中值。视觉滤波系数则通过对比不同取值下的跟随效果确定，在噪声抑制与响应延迟之间取得平衡。

本章介绍了开发工具、制作安装、调试方法、典型问题及PID整定过程。通过逐级调试解决了光线变化、误识别、通信干扰和跟随振荡等问题，系统最终能够稳定完成双车跟随与搬运任务。

B．2上层PID控制器
class PID_Controller:
    def __init__(self, kp, ki, kd, output_max, deadzone=0):
        self.kp = kp
        self.ki = ki
        self.kd = kd
        self.max = output_max
        self.deadzone = deadzone
        self.integral = 0.0
        self.last_err = 0.0
        self.output = 0.0

    def reset(self):
        self.integral = 0.0
        self.last_err = 0.0
        self.output = 0.0

    def calculate(self, target, measure):
        err = target - measure
        if err > 180:
            err -= 360
        if err < -180:
            err += 360
        if abs(err) < self.deadzone:
            err = 0

        self.integral += err
        integral_limit = self.max * 0.8
        if self.integral > integral_limit:
            self.integral = integral_limit
        elif self.integral < -integral_limit:
            self.integral = -integral_limit

        P = self.kp * err
        I = self.ki * self.integral
        D = self.kd * (err - self.last_err)
        output = P + I + D

        limit = self.max
        if output > limit:
            output = limit
        elif output < -limit:
            output = -limit

        self.last_err = err
        self.output = output
        return output
