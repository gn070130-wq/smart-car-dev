 IV 
摘要 
本文详细介绍了安徽理工大学“爱吃烧烤不炸板”在第二十一届全国大学生
智能汽车竞赛 "蚂蚁搬家" 双车协同搬运任务的系统方案。系统由主车与从车
两辆麦克纳姆轮四轮全向小车组成，采用两块 NXP i.MX RT1021 作为底盘主控
制器、两块 OpenArt（i.MX RT1064）作为视觉处理器，共四块控制板协同工作。 
主车负责全局任务决策：通过 OpenArt 搭载的 YOLO 目标检测模型识别场地内
的待搬运物体（球 / 沙包 / 熊），利用黄色边界线检测与逆透视变换测距实
现目标定位与边界识别；基于 IMU 六轴 Mahony 姿态融合与四路编码器里程计
完成麦轮底盘的世界坐标定位与黄线位置校准，并通过 22 状态的有限状态机
完成完整任务链。从车依据主车下发指令协同运动，并利用侧视 OpenArt 的红
外四灯板检测与二次曲面标定实现与主车的相对位置闭环（并排推物）。 系统
采用航向外环 + 麦轮逆解 + 四轮增量式速度内环的级联控制结构，所有运动
输出统一经过安全仲裁器（急停、拨码退出、通信超时停车、PWM 限幅、斜坡
限制）后才写入电机，实现了双车在受限场地内的稳定、安全、协同搬运。经
四设备冷启动、三链路通信联调及双车完整任务实车验证，本方案可行且稳定。  
 
关键词：麦克纳姆轮；双车协同；YOLO 目标检测；Mahony 姿态解算；有限
状态机；增量式 PID。

第一章 系统总体设计 
本系统采用 “主车指挥 + 从车协同” 的双车架构，四块独立控制板构成完整
的通信与数据流体系，各模块职责与数据流向如下： 主车 OpenArt（主视觉）
负责环境感知，将物体坐标、黄线状态、线角、角落等信息通过$V 协议发送给
主车 RT1021；主车 RT1021 作为全局决策核心，运行任务状态机、世界坐标定
位与主车底盘控制算法，解析数据后通过协议向从车 RT1021 下发运行指令与
状态；从车 RT1021 接收主车指令，结合从车侧视 OpenArt 上传的$L 灯板检测
数据，实现跟随运动与并排推物协同。 其中主车 RT1021 承担全局任务状态机、
世界坐标定位、主车底盘闭环、视觉数据解析与从车指令下发的核心职责；从
车 RT1021 负责解析主车指令与侧视视觉数据，实现跟随、并排推物与自身安
全管控，不独立决策任务路线；主车 OpenArt 完成 YOLO 物体识别、黄线 / 角
点检测、逆透视测距功能；从车侧视 OpenArt 完成红外四灯板检测与透视标定
功能。 比赛场地为 240 cm × 320 cm 的矩形区域，四周设黄色边界线，包含
车库与多件待搬运物体。整车通过麦克纳姆轮实现前进、横移与原地转向的全
向运动，适配狭窄场地内的灵活作业需求。

第二章 机械结构调整及优化 
2.1 降低整体重心 
 机械结构优化围绕提升系统稳定性展开，核心方向包括降低整车重心，将电
池与主控板尽量靠近支撑中心布置，减少外力干扰下的倾倒力矩，提升动态行
驶与推物过程的稳定性；调整摄像头支架的安装高度与俯仰角，保证逆透视测
距的标定精度与检测范围；固定红外灯板的安装位置与侧视摄像头的安装角度，
保障相对位置检测的一致性；优化整车布局使重量均匀分布，提升四轮抓地一
致性与里程计精度。

第四章 软件算法系统设计 
4.1 二次曲面标定与等效距离换算 
受镜头透视效应、侧视安装倾角与光学畸变的共同影响，红外灯板在图像中
的像素坐标与两车实际物理距离之间存在显著的非线性耦合关系，仅依靠线性
单应矩阵进行坐标映射，难以满足近距离并排推物场景下的高精度跟随需求。
为此系统采用二元二次曲面标定法构建像素空间到物理空间的非线性映射模型，
通过引入畸变补偿项提升相对位置解算精度，为双车协同闭环提供可靠的视觉
反馈。该模型以红外灯板中心的图像横、纵坐标作为输入变量，在一阶线性单
应映射的基础上，引入二次项与交叉耦合项对透视畸变进行补偿，构建包含常
数项、一次项、交叉耦合项、二次项的二元二次多项式映射模型。模型分别针
对前向相对距离与侧向相对距离拟合两组独立的曲面参数，完整覆盖有效检测
范围内的非线性畸变特性，相比纯线性映射可有效抵消边缘区域的透视失真，
提升全区间的检测一致性。标定工作在标准场地下完成：将主车侧的红外灯板
固定在标定工装之上，在从车侧视摄像头的视野范围内依次布置 19 个标准标
定位置，全面覆盖前后方向、侧向方向的全部有效工作区间；逐点记录灯板中
心的像素坐标，同时高精度测量两车对应的实际物理距离，形成标定样本数据
集。 最终通过最小二乘拟合算法求解曲面模型的全部系数，分别得到前向距离、
侧向距离对应的两组标定曲面参数，并将参数固化于视觉程序中，实现检测过
程中的实时坐标解算。经标定精度验证，系统划定灯板像素坐标的有效工作区
间，该区间完整覆盖双车协同作业的常规相对位置范围。仅当灯板中心像素落
在有效区间内时，系统才输出高精度的曲面解算结果；当灯板位置超出有效区
间时，为避免外推计算带来的精度恶化，系统采用保守容错策略：若判定两车
侧向距离过近，则输出极限侧向等效值，触发底盘控制端的远离防撞逻辑；若
判定两车侧向距离过远，则输出极限侧向等效值，触发底盘控制端的靠近找回
逻辑。 通过边界区间的趋势化保守输出，保证检测失效边缘仍能输出符合安全
逻辑的控制指令，避免双车发生碰撞或跟丢目标。

4.2 麦轮底盘三级级联 PID 
麦克纳姆轮四轮全向底盘存在多轮运动耦合、摩擦非线性、姿态扰动强等特
性，单一闭环结构难以同时兼顾全向运动的控制精度、动态响应与运行稳定性，
无法满足双车协同搬运对走位精度、行驶平顺性的严苛要求。为此系统采用三
级级联 PID 控制架构，以分层解耦的设计思路，将车体姿态控制、运动学分配
与轮速跟踪拆解为独立闭环，逐级收敛控制误差，是整个系统运动执行的核心
基石，直接决定导航、避障、协同推物等所有上层功能的落地效果。 
4.3 IMU 六轴互补滤波姿态解算算法 
车体航向与姿态是全向运动控制、全局坐标定位、双车航向协同的核心基准，
姿态解算的精度与稳定性直接决定了导航与控制的性能上限。惯性测量单元中，
陀螺仪与加速度计各自存在固有性能局限：陀螺仪短期动态响应快、角度分辨
率高，但通过积分计算角度时会随时间累积零偏误差，静止与低速场景下航向
易持续漂移；加速度计可通过重力向量解算静态姿态，但车辆加减速、转向产
生的线加速度会与重力加速度叠加，导致动态场景下姿态解算严重失真。单一
传感器无法同时满足静态精度与动态响应的双重要求，为此系统采用基于 
Mahony 架构的六轴互补滤波算法，以四元数为姿态载体融合两类传感器的优势，
实现全工况下稳定、精准的车体姿态解算。

第五章 开发工具、平台调试说明 
5.1 开发工具 
底盘主控 RT1021 的开发采用 MicroPython 固件，使用 Thonny 软件通过 
Type-C 虚拟串口进行烧录与调试。Thonny 为轻量级 Python IDE，适配嵌入式 
MicroPython 开发场景，支持代码编辑、单步执行、断点调试与串口日志查看，
界面简洁，跨平台兼容，适合硬件控制类程序开发调试。 视觉模块 OpenArt 的
开发使用 OpenMV IDE，为  OpenMV 系列硬件的官方配套开发工具，深度适配 
OpenArt 硬件，支持 USB 一键烧录程序、自动适配驱动，内置 MicroPython 语
法补全；核心功能为实时图像预览，可直接查看摄像头画面与算法运行效果，
支持断点调试与串口日志输出，是视觉算法调试的核心工具。 工程管理采用 VS 
Code 配合 Git 版本控制，电脑端运行 unittest 单元测试覆盖协议、导航、状态
机、安全等模块，共 66 项测试用例；配套部署脚本自动生成四设备部署包与
校验清单，保障部署一致性。 
5.2 调试工具 
逐飞科技提供的逐飞助手为我们进行图像调试和控制调试提供了巨大便利。逐
飞助手是逐飞科技推出的免费嵌入式开发上位机软件，主打智能车竞赛等嵌入
式场景的调试需求，功能聚焦且实用。核心模块包括：串口助手（支持 TCP/UDP 
协议，可 HEX 显示、保存数据）、虚拟示波器（8 通道波形同步观测，便于
分析硬件时序）、摄像头图像显示（实时呈现图像，查看像素值、保存视频）。
此外，支持深浅主题切换，内置调参工具与虚拟手柄，可辅助参数调整和远程
控制，且持续更新迭代以完善功能，是嵌入式开发尤其是智能车调试的常用工
具。
