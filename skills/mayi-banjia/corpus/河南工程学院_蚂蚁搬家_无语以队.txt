摘  要
本文介绍了河南工程学院代表队参加第二十一届全国大学生智能汽车竞赛蚂蚁搬家组的智能车系统设计方案。按照竞赛规则，本队制作了两辆自制搬运车模（步兵），以恩智浦 NXP RT1021 为核心、运行 MicroPython 固件的逐飞 MicroPython-BTB 核心板作为主控制器，采用 Python 语言完成全部控制程序编写。车模采用三轮全向底盘，以三路直流减速电机配合三路 AT8236 电机驱动芯片和三路正交编码器实现各轮独立驱动与速度闭环，推杆固定于车头完成物品搬运。
针对蚂蚁搬家组对车模定位精度和地面适应性的要求，本设计以 PAW3395 光流传感器为速度观测核心，融合三路编码器与六轴姿态传感器（IMU）构成车模位置与航向参考系统：光流提供不打滑的真实地面位移，编码器在光流失效时兜底，IMU 提供航向基准；软件上通过光流表面质量（SQUAL）置信度门控实现多源信息的自适应加权融合，解决了省赛现场部分场地表面光流不可靠导致定位漂移的问题。两辆搬运车通过无线串口模块交换状态信息，以主从状态机协同完成“巡航、接近、对准、协同推送、返回”的完整搬运流程。
经实际测试，车模运行稳定，能够在 3.2m×2.4m 场地内完成对搬运物品的协同搬运任务，验证了本方案的可行性与可靠性。整车外形尺寸（含推杆）为长 25cm、宽 20cm、高 28cm，两车平均重量约 268g，其余详细参数见附录 B。
关键词：MicroPython；RT1021；三轮全向；光流定位；传感器融合；双车协同

第一章 引言
1.1 智能车竞赛简介
全国大学生智能汽车竞赛是以智能汽车为研究对象的创意性科技竞赛，是面向全国大学生的一种具有探索性工程实践活动，是教育部倡导的大学生科技竞赛之一。竞赛以“立足培养，重在参与，鼓励探索，追求卓越”为指导思想，旨在促进高等学校素质教育，培养大学生的综合知识运用能力、基本工程实践能力和创新意识，激发大学生从事科学研究与探索的兴趣和潜能，倡导理论联系实际、求真务实的学风和团队协作的人文精神。
竞赛以竞速赛为基本竞赛形式，辅助以创意赛和技术方案赛等多种形式。竞赛过程包括理论设计、实际制作、整车调试、现场比赛等环节，要求学生组成团队、协同工作，初步体会一个工程性的研究开发项目从设计到实现的全过程。竞赛融科学性、趣味性和观赏性为一体，涵盖自动控制、模式识别、传感技术、电子、电气、计算机、机械与汽车等多学科专业，规则透明、评价标准客观，坚持公开、公平、公正的原则。
1.2 蚂蚁搬家组规则与任务
蚂蚁搬家组是第二十一届全国大学生智能汽车竞赛新增的微缩赛道组别。参赛队伍需要制作两辆搬运车模（步兵）和最多两台辅助车模（工兵）或导引信标，在 3.2m×2.4m 的矩形场地内完成物品搬运任务。搬运物品包括浅绿色标准网球、红色/蓝色玩具沙袋以及棕色/白色泰迪熊三类，初始放置于场地中心 1m×1m 的区域内，物品之间保持不小于 10cm 的间距。预赛阶段只需将目标搬运出场地黄色边界线即可，决赛阶段则需要按物品种类分别搬运到场地四周对应的目标区域。
规则对车模和器材有严格限定：搬运车模主控必须使用基于恩智浦 NXP 控制器的 MicroPython 核心板，并且只能使用 Python 语言编写应用程序，不允许使用 C 语言或在线调试器下载调试；用于成绩计算的两辆搬运车模重量取平均值；车模制作完成之后，包括推杆在内，外形尺寸必须小于 30cm；搬运物品的推杆水平方向尺寸不超过 10cm、垂直方向尺寸不超过 5cm，推杆必须是直的且只允许有一个；辅助车模的控制器允许使用 STC 单片机，高度不超过 50cm、边长不超过 30cm×30cm，且不允许触碰搬运物品。
因此，本队的设计重点在于：轻量化自制车模、双车协同策略、以及稳定可靠的定位与运动控制系统。本文第三章、第四章、第五章将分别对机械结构、电路系统和软件控制设计进行详细介绍。

第二章 系统整体设计
2.1 设计目标与总体方案
蚂蚁搬家组的任务特点是低速、精确、协同：两辆搬运车需要把物品从场地中心推送到场地四周，过程中不允许单车完成搬运，因此两车之间的位置关系和同步性至关重要。结合规则对车模重量、尺寸和主控平台的限制，本队确定了“轻量化自制三轮全向底盘 + RT1021 MicroPython 主控 + 多源融合定位 + 无线双车协同”的总体技术方案。
系统由主控模块、电源模块、电机驱动模块、速度姿态检测模块和无线通讯模块组成。主控模块采用恩智浦 RT1021 MicroPython-BTB 核心板，负责传感器数据采集、定位融合解算、运动学解算与双车协同决策；电源模块由 XT60 电池接口、5V 与 6.5V 两路降压电路和 3.3V 稳压电路构成；电机驱动模块采用三片 AT8236 驱动三路直流减速电机；速度姿态检测模块由三路正交编码器、六轴姿态传感器和 PAW3395 光流传感器组成；无线通讯模块实现两辆搬运车之间的状态交换。系统总体框图如图 2.1 所示。

图 2.1 系统总体框图
2.2 底盘方案选型
蚂蚁搬家组车模需要频繁在物品之间横移对准、推送物品后迅速撤离，对底盘灵活性要求较高。常见方案包括两轮差速底盘、四轮底盘和三轮全向底盘。两轮差速底盘结构简单、控制成熟，但转向需要圆弧半径，在狭小的中心物品区调整姿态不够灵活；四轮底盘重量和复杂度较高，不利于轻量化计分。
综合考虑后，本队选择三轮全向底盘方案：三个全向轮成 120° 均匀布置，每个轮子由一路直流减速电机独立驱动并配备一路正交编码器，车模可以实现任意方向的平移与原地旋转，在推送物品时无需大幅转向即可对准目标，显著提高了搬运效率。三轮结构也比四轮方案更轻，符合规则对搬运车模计重计分的要求。
2.3 定位方案选型与融合设计
定位系统是蚂蚁搬家车模完成搬运任务的基础。场地内没有可用于视觉参照的固定标记（本车未采用含 MCU 的图像处理平台），因此定位只能依靠车载传感器推算。可供选择的有轮式编码器、光流传感器和惯性测量单元（IMU）三类：编码器通过轮子转角推算位移，结构简单，但推送重物时轮子打滑会造成显著误差；光流传感器通过拍摄地面图像跟踪表面特征，测量的是车体相对地面的真实位移，不受打滑影响，但对地面纹理、反光和光照条件敏感；IMU 的陀螺仪可以稳定提供航向角，但积分漂移无法长时间独立定位。
本队最初以 PAW3395 光流传感器作为位置推算的主要来源。在省赛河北工程大学场地测试时发现，部分地面表面光流可靠性下降，出现定位数据“时有时无”的问题，直接影响了搬运精度。为此，本设计最终确定“光流 + 编码器 + IMU”多源融合方案：以编码器速度环输出作为基础运动学推算，光流提供无打滑的真实地面位移修正，IMU 提供航向基准，三者通过置信度加权融合得到车模在场地坐标系下的位置与航向。软件中以光流表面质量寄存器 SQUAL 作为置信度指标，当 SQUAL 低于阈值时自动降低光流权重，由编码器与 IMU 兜底，从而保证任意场地表面下定位系统都不会完全失效。融合算法的具体实现在 5.3 节详细说明。
2.4 双车协同方案
规则要求搬运过程必须由两辆搬运车共同完成，两车之间不允许物理连接，因此需要无线通讯实现状态同步。本队在两辆搬运车上各安装一套无线串口模块，通过主板上的 8 位拨码开关设置车号与角色（主车/从车），主车负责搬运任务的统筹调度，从车根据主车广播的位置与状态执行跟随、对准和协同推送动作。为避免通讯异常导致任务失败，双车均采用独立的本地状态机，任何一辆车都可以在通讯中断时按照预设的保守策略自行完成撤离与复位。双车协同的状态机设计详见 5.5 节。

第三章 机械结构设计与优化
3.1 车模整体结构
搬运车模为全自制结构，以 PCB 电路板作为主体承力底板，三个全向轮通过电机支架固定于底板，主控核心板、电池、光流传感器、灯板等模块直接安装于底板上方。整车外形尺寸（含推杆）为长 25cm、宽 20cm、高 28cm，满足规则小于 30cm 的要求。整车结构如图 3.1 所示，主车与副车各视图照片见附录 C。

第四章 电路系统设计
4.1 硬件设计整体方案
整车电路由一块四页原理图的主板和一块三路 LED 灯板组成。主板第 1 页为 RT1021 核心板接口与传感器接口，第 2 页为电源电路，第 3 页为信号与交互电路（无线串口、拨码开关、屏幕接口、按键），第 4 页为三路 AT8236 电机驱动电路。所有电路均使用嘉立创 EDA 专业版完成原理图与 PCB 设计，主板 PCB 丝印层标记有学校名称、队伍名称与制作日期。
4.2 主控模块
主控采用逐飞科技与恩智浦联合设计的 RT1021 MicroPython-BTB 核心板，核心为恩智浦 i.MX RT1021 跨界微控制器，主频高达 500MHz，板载 QFlash，已预烧录官方 MicroPython 固件。核心板通过 BTB 连接器与主板相连，IO 资源分配如下：三路编码器接口（GH1.25-6P，A/B/Z/Dir）、姿态传感器接口（2.54-8P）、TFT 屏幕 SPI 接口（MISO/MOSI/NSS/SCK）、无线串口 UART 接口、8 位拨码开关与 4 个独立按键。编码器、姿态传感器、TFT 屏幕、无线串口与灯板均采用逐飞科技产品，与 MicroPython 固件中的 seekfree 驱动模块直接适配。核心板原理图如图 4.1 所示。

图 4.1 主控模块原理图
4.3 电源模块
电源模块以 XT60 接口接入 3S 450mAh 锂电池，经过拨动开关与 HY19P03D PMOS 反接保护电路后，分为三路输出：
（1）SCT2450 同步降压电路将电池电压降压至 5V（VCC5V），为电机驱动逻辑、无线模块、屏幕和按键等供电，输出端配置 47μF 与 100nF 滤波电容；
（2）TPS54302 降压电路输出 6.5V（VCC6V5），为逐飞灯板供电；
（3）TPRT9013-33 低压差稳压器将 5V 转换为 3.3V（VCC3V3），为核心板与传感器供电。
全板电容总容量约 645μF，其中 220μF 母线电容用于抑制电机换向引起的电压波动，其余为各级电源输入输出滤波电容与芯片去耦电容。电源电路如图 4.2 所示。

5.1 整体思路

5.2 MicroPython 开发框架
官方固件封装了常用的硬件接口：machine 类提供 Pin、ADC、UART、PWM 等基础外设；NXP 提供的 smartcar 类提供编码器（encoder）与定时器（ticker）模块；逐飞科技提供的 seekfree 类提供 IMU660/963RA、电机控制、按键、无线串口与屏幕等模块。本车在 ticker 回调中以 5ms（200Hz）的固定周期完成传感器采样与运动控制，主循环负责任务状态机与通讯处理，保证实时任务与决策任务分离。
5.3 定位与传感器融合
定位融合是本车软件的核心。编码器通道通过累计三路轮子转角，结合轮径与底盘几何参数推算车体系速度，经航向角旋转到场地坐标系后积分得到位置估计；PAW3395 光流通过 SPI 突发读取帧间位移增量，累计得到无打滑的地面位移；IMU 陀螺仪积分提供航向角，并在静止时进行零偏校正。
融合采用置信度加权结构：光流置信度由其表面质量寄存器 SQUAL 决定，SQUAL 高于阈值时以光流位移为主修正编码器打滑误差，SQUAL 连续低于阈值时自动将光流权重置零，系统退化为编码器 + IMU 推算；同时利用编码器短时位移对光流输出做一致性校验，剔除光流跳变毛刺。具体实现为：设权重 w 由 SQUAL 决定（SQUAL≥30 时 w=1，连续低于阈值 5 次以上 w=0），车体系位移 b = w·Δ光流 + (1−w)·Δ编码器，场地系坐标由 b 绕 IMU 航向角旋转后逐周期累加得到。融合后的位置与航向作为运动控制的位置环反馈量。省赛现场调试表明，该融合结构在光流“时有时无”的地面上仍能保持定位不发散，保证搬运任务正常完成。
5.4 运动控制
底盘为三轮全向结构，通过逆运动学矩阵将场地坐标系下的目标速度向量（Vx、Vy、ω）映射为三个全向轮的轮速指令，每个轮子由独立的速度环（PID）控制。速度环反馈来自对应编码器，位置环与航向环反馈来自定位融合输出。速度环参数在空载与推送负载两种工况下分别整定：先调比例项使轮速响应无明显振荡，再加入积分项消除稳态误差；推送物品过程中，负载变化引起轮子打滑，速度环输出会自动增大，配合光流修正可保持实际运动与指令一致。
5.5 双车协同与状态机
双车采用分层状态机实现协同。主车状态包括巡航搜索、接近目标、保持待命、同步推送、任务完成与复位；从车状态包括后方跟随、绕行到位、视觉/位置对准、推杆就绪、协同推送与撤离复位。两车通过无线串口按固定周期交换车号、位置、状态与指令，主车广播目标位置与推送时机，从车根据自身状态机响应。状态机切换如图 5.2 所示。

7.2 工作总结
本文从机械、电路、软件三个方面介绍了本队参加蚂蚁搬家组的双车协同搬运系统设计。系统以 RT1021 MicroPython 核心板为决策核心，三轮全向底盘配合三路编码器实现精确的轮速闭环；定位系统采用光流 + 编码器 + IMU 多源融合，通过 SQUAL 置信度门控解决了光流对地面表面敏感的问题；双车通过无线串口与分层状态机完成协同搬运。整车设计在保证功能完整性的前提下尽量轻量化，满足规则对搬运车模尺寸与计重的要求。
7.3 存在问题与改进方向

A-1 主程序与任务状态机（main.py）
主程序完成各模块初始化，注册 5ms 控制周期定时回调，并在主循环中轮询按键、刷新屏幕。控制回调内部按“采样—融合—控制—协同”的顺序执行，保证实时任务与决策任务分离。
# main.py —— 蚂蚁搬家搬运车主程序（示意代码）
import time
from smartcar import ticker
from seekfree import KEY_HANDLER
import sensor, fusion, motion, state, comm, ui
 
running = False
 
def on_tick():
    """控制周期回调（5ms）：采样 -> 融合 -> 控制 -> 协同"""
    if not running:
        return
    dx, dy, squal = sensor.flow.read()          # 光流位移增量与表面质量
    vx, vy, wz = motion.odom()                  # 三路编码器合成速度
    yaw = sensor.imu.yaw                        # IMU 航向
    pos = fusion.update(dx, dy, squal, vx, vy, yaw)
    motion.control(pos, state.target())         # 位置/航向闭环
    state.update(pos, yaw)                      # 任务状态机
    comm.broadcast(state.packet())              # 无线广播状态
 
ticker.register(5, on_tick)
 
def main():
    global running
    sensor.init()
    fusion.reset(0.0, 0.0, 0.0)
    motion.init()
    state.init()
    comm.init(car_id=ui.read_dip())             # 拨码开关设定车号
    running = True
    while True:
        ui.refresh(state.name, fusion.pos, sensor.flow.squal)
        if KEY_HANDLER.get_event() == KEY_HANDLER.KEY_1:
            state.next()
        time.sleep_ms(10)
 
main()
A-2 传感器驱动（sensor.py）
封装三路正交编码器、六轴姿态传感器与 PAW3395 光流传感器。光流为无 MCU 裸芯片，由主控通过 SPI 突发读取帧间位移增量与表面质量 SQUAL。
# sensor.py —— 编码器 / IMU / PAW3395 光流驱动封装（示意代码）
from machine import Pin, SPI
from smartcar import encoder
from seekfree import IMU660RA
 
class Encoder:
    """逐飞正交编码器：返回增量计数值"""
    def __init__(self, idx):
        self._dev = encoder(idx)
    def count(self):
        return self._dev.get_count()
 
class PAW3395:
    """PAW3395 光流传感器（SPI 直读，无板载 MCU）"""
    REG_PRODUCT = 0x00     # 产品号寄存器
    REG_BURST   = 0x02     # Motion 起始地址，突发读取 12 字节
    def __init__(self, spi, cs_pin):
        self._spi = spi
        self._cs = Pin(cs_pin, Pin.OUT, value=1)
        pid = self._read_reg(self.REG_PRODUCT)
        if pid != 0x39:    # PAW3395 产品号校验
            raise ValueError('PAW3395 not found: 0x%02X' % pid)
    def _read_reg(self, reg):
        self._cs(0)
        self._spi.write(bytes([reg & 0x7F]))
        val = self._spi.read(1)[0]
        self._cs(1)
        return val
    def read(self):
        """返回 (delta_x, delta_y, squal) 带符号位移与表面质量"""
        self._cs(0)
        self._spi.write(bytes([self.REG_BURST | 0x80]))
        buf = self._spi.read(12)
        self._cs(1)
        dx   = int.from_bytes(buf[1:3], 'little', signed=True)
        dy   = int.from_bytes(buf[3:5], 'little', signed=True)
        squal = buf[5]
        return dx, dy, squal
A-3 光流 + 编码器 + IMU 融合定位（fusion.py）
以 SQUAL 作为光流置信度指标：SQUAL 高于阈值时以光流位移为主修正编码器打滑误差，连续低于阈值时自动将光流降权，由编码器与 IMU 兜底，保证任意地面表面下定位不发散。
# fusion.py —— 多源融合定位（示意代码）
import math
 
SQUAL_OK  = 30     # 光流表面质量阈值
LOW_LIMIT = 5      # 连续低质量计数上限
DT        = 0.005  # 控制周期（s）
 
class Fusion:
    def __init__(self):
        self.x, self.y, self.yaw = 0.0, 0.0, 0.0
        self.low_cnt = 0
 
    def reset(self, x, y, yaw):
        self.x, self.y, self.yaw = x, y, yaw
 
    def update(self, flow_dx, flow_dy, squal, vx, vy, yaw):
        """flow_*: 光流增量(mm)；vx/vy: 编码器速度(mm/s)；yaw: IMU 航向(rad)"""
        if squal >= SQUAL_OK:
            self.low_cnt = 0
            w = 1.0
        else:
            self.low_cnt += 1
            w = 0.0 if self.low_cnt > LOW_LIMIT else 0.3
 
        # 光流增量与编码器积分增量加权（车体系）
        bx = w * flow_dx + (1 - w) * (vx * DT)
        by = w * flow_dy + (1 - w) * (vy * DT)
 
        # 旋转到场地坐标系
        c, s = math.cos(yaw), math.sin(yaw)
        self.x += bx * c - by * s
        self.y += bx * s + by * c
        self.yaw = yaw
        return self.x, self.y, self.yaw
A-4 三轮全向运动学与轮速闭环（motion.py）
通过逆运动学矩阵将场地坐标系速度向量映射为三路轮速指令，每个轮子由编码器反馈的 PID 速度环闭环控制。
# motion.py —— 三轮全向运动学与轮速闭环（示意代码）
import math
 
BASE_R = 62.0           # 轮心到底盘中心距离（mm）
SQ3 = math.sqrt(3) / 2.0
 
def ik(vx, vy, wz):
    """底盘速度向量 -> 三路轮速（符号按实际安装方向调整）"""
    return (
        vy + BASE_R * wz,
        -SQ3 * vx - 0.5 * vy + BASE_R * wz,
         SQ3 * vx - 0.5 * vy + BASE_R * wz,
    )
 
class PID:
    def __init__(self, kp, ki):
        self.kp, self.ki = kp, ki
        self.err = 0.0
    def update(self, ref, fb):
        e = ref - fb
        self.err += e
        return self.kp * e + self.ki * self.err
 
w_pid = [PID(0.8, 0.02), PID(0.8, 0.02), PID(0.8, 0.02)]
 
def control(pos, target):
    """位置误差经 P 控制生成场地系速度，再经运动学映射与速度环输出"""

    vy = clamp((target[1] - pos[1]) * 0.5, -300, 300)
    wz = clamp((target[2] - pos[2]) * 0.4, -1.2, 1.2)
    w1, w2, w3 = ik(vx, vy, wz)

        w_pid[0].update(w1, w_speed[0]),
        w_pid[1].update(w2, w_speed[1]),
        w_pid[2].update(w3, w_speed[2]),
