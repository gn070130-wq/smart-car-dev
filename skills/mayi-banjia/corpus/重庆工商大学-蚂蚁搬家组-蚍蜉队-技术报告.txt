第一章　引言
1.1　项目概述
本报告面向第二十一届全国大学生智能汽车竞赛蚂蚁搬家组，介绍重庆工商大学蚍蜉队双车协同搬运系统的机械结构、视觉感知、底盘运动控制、双车通信、任务状态机以及调试方法。两台车采用相同的三轮全向机械底盘和N20减速电机，主车负责识别与任务决策，从车依据主车运动信息和自身相对视觉信息完成协同跟随。
系统软件由四份Python程序构成：主车底盘程序、从车底盘程序、主车OpenART Plus视觉程序以及从车视觉程序。主车视觉同时完成球、沙包、泰迪熊、砖块等目标的TFLite检测和黄色场地边界的LAB阈值检测，并将识别结果通过串口送入底盘控制；从车视觉使用双光斑几何中心建立与主车的相对位置观测。
1.2　赛题约束
蚂蚁搬家组要求两辆搬运车协同完成目标物搬运。比赛场地为3.2 m×2.4 m，场地边界采用5 cm宽黄色胶带；被搬运物放置于中央约1 m见方区域。搬运物包括标准网球、玩具沙袋和泰迪熊，比赛过程中每次只允许搬运一件物品。两辆搬运车完成任务后均需返回发车区。[2]
搬运车允许安装1根直推杆，水平长度不超过10 cm、垂直高度不超过5 cm；包括推杆在内的整车外形尺寸需小于30 cm。本队按照该约束设计82 mm长、42 mm高的直推杆，并将主、从车最大外形控制在268 mm×218 mm×246 mm。[2]
1.3　总体设计思路
针对蚂蚁搬家任务中“双车需要同时运动、相互保持空间关系、又要完成目标搜索与搬运”的特点，系统采用“主车规划、从车跟随、视觉校正、编码器闭环”的分层结构。主车先通过视觉选择当前任务目标，再采用像素误差到里程计位移的映射进行粗定位和精定位；完成对准后进入搬运动作。主车把实测底盘速度和偏航角组成无线数据帧发送给从车。从车在普通平移阶段直接跟随主车速度并叠加视觉补偿，在主车旋转时切换至刚性编队模型，以车辆间偏置计算所需的附加平移速度。
控制系统不把视觉输出直接等同于电机PWM，而是在视觉、任务与底层速度环之间保留状态转换、死区、滤波、限幅和超时保护。这样既能降低目标检测抖动造成的高频运动，也能在通信丢失或视觉暂时失效时快速停车或进入恢复逻辑。
1.4　报告内容安排
第二章介绍机械结构；第三章说明硬件接口；第四章给出运动学、视觉定位、任务状态机和双车编队算法；第五章总结制作与调试过程；第六章汇总技术参数和测试记录；第七章给出结论。四份程序的关键代码片段列于附录B，完整工程源文件另行归档；系统电路详细设计图列于附录A。

2.5　传感器与电路板安装
三路编码器与三只驱动轮一一对应，用于5 ms周期的轮速采样和里程计积分。IMU应安装在车体刚性区域并尽量靠近车体中心，以减小机械振动和偏置误差。主车摄像头需要获得搬运目标和黄色边界的稳定视野；从车摄像头应固定在能够持续观察主车双光斑标记的位置，并保证光斑在主要运动范围内不易离开320×240像素视场。

第三章　电路与硬件系统设计
3.1　底盘控制与接口
根据主驱一体板V1.0原理图，两车底盘均以RT1021_BTB_CoreBoard核心板为控制核心，三路直流电机驱动全部采用DRV8874PWPR。三路控制信号与底盘程序保持一致：电机1使用PWM_C30/DIR_C31，电机2使用PWM_C28/DIR_C29，电机3使用PWM_D4/DIR_D5，PWM频率为20 kHz，软件输出限幅为±8000。DRV8874的VM端直接接VCCBAT，OUT1/OUT2分别引出为AO1/AO2、BO1/BO2、CO1/CO2，并配置VCP、CPH/CPL电荷泵电容以及nSLEEP、nFAULT、VREF、IPROPI等外围网络。

图3.1　主、从车底盘控制平台电气接口原理框图

图3.2　三路DRV8874电机驱动与N20电机/编码器接口原理图
3.2　编码器与IMU反馈
三路N20电机均通过6针接口CN1～CN3接入主驱一体板。CN1依次引出AO1、VCC3V3、C0、C1、GND、AO2；CN2依次引出BO1、VCC3V3、C2、C3、GND、BO2；CN3依次引出CO1、VCC3V3、D13、D14、GND、CO2。因此三路编码器与程序中的C1/C0、C2/C3、D13/D14一一对应。编码器由5 ms定时任务统一采样，每次采样将计数换算为速度量，经三点中值滤波后再以0.3系数进行一阶低通。IMU660RX通过板载“姿态传感器接口”连接，程序以120 Hz姿态输出读取偏航角，用于航向闭环和世界坐标系里程计积分。
程序中每轮编码计数为203，软件有效轮径取35 mm，因此每个编码计数对应的理论弧长为π×35/203 mm；为补偿实际轮径和安装误差，世界坐标积分分别乘以X方向1.045、Y方向1.05的标定系数。
3.3　主车视觉单元
主车使用OpenART Plus摄像头，图像格式为RGB565，分辨率为QVGA。为降低颜色识别随环境变化而漂移，程序固定曝光、增益与白平衡，其中曝光时间设置为800 μs。TFLite模型识别球、沙包、泰迪熊和砖块，类别ID分别为0、1、2、3，置信度阈值为0.60；黄色边界作为类别4，由LAB阈值(79,98,-32,-10,35,94)检测。主驱一体板P2页预留独立UART接口H1，提供VCC5V_EXT、GND及D23/D22信号，摄像头与底盘的逻辑通信由底盘UART7和视觉端UART12完成。[4]
视觉输出通过UART12以460800 bit/s发送，单目标格式为“[类别ID,中心X,中心Y,宽度]”，同一帧多个目标用分号分隔。对同类别目标，程序依据空间距离在跨帧滤波槽中进行匹配，中心坐标和宽度采用2/3系数的一阶滤波，减少模型框跳动。

图3.3　主车视觉检测与输出流程
3.4　从车视觉单元
从车摄像头同样工作在QVGA RGB565模式，通过LAB阈值(77,100,-15,12,-6,13)搜索两个光斑。程序采用pixels_threshold=50、area_threshold=50且不合并相邻色块，从全部候选中选取像素面积最大的两个色块，再按X坐标区分左右。两光斑中心的平均值作为相对视觉中心(c_x,c_y)，横向间距作为width，并以“[c_x,c_y,width]”格式通过115200 bit/s串口发送。从车与主车使用相同主驱一体板，因此摄像头同样可由板载VCC5V_EXT和UART接口供电、通信。
3.5　双车无线通信
主车与从车之间使用460800 bit/s无线串口。主驱一体板P2页设置“无线模块-串口”接口P12，并由VCC5V_EXT供电。主车每个控制周期发送11字节固定帧：前两字节0xAA、0x55作为帧头，随后依次为int16格式的vx、vy、wz和yaw共8字节，末字节为对前10字节计算的CRC8，生成多项式为0x07。固定帧长、帧头同步和CRC校验用于抑制无线链路丢字节或干扰造成的错误速度指令。

3.6　供电与电气参数说明
单车电源由P1 XT30接口输入，形成VCCBAT动力母线。输入端设置BZT52C16稳压/钳位器件D1、10 kΩ下拉R1、电源开关S1及HY19P03 MOS管Q1，构成电源接入与开关保护。VCCBAT一路直接供给三路DRV8874的VM端；另一路经SCT2450降压芯片U3、4.7 μH/5 A功率电感L2和SS54肖特基二极管形成VCC5V。VCC5V再由RT9013-33 U4生成VCC3V3，同时通过SY6280 U6受控输出VCC5V_EXT，为视觉、无线及外设接口供电。P2页还设置电池电压采样网络：VCCBAT经R30=10 kΩ、R31=1 kΩ分压，并由C24=100 nF滤波后送入B27，可用于软件监测电池电压。板上同时预留屏幕、姿态传感器、ToF、UART、红外灯板、拨码开关、按键和蜂鸣器接口。

第四章　控制软件与核心算法
4.1　软件任务调度
底盘控制采用非阻塞主循环配合5 ms编码器定时任务。编码器采样、轮速滤波和底层速度闭环在固定周期执行；摄像头串口解析、无线帧处理、任务状态机和垃圾回收在主循环中按事件或时间条件运行。主车在摄像头握手完成后自动进入任务状态机，并在每个控制周期向从车发送实测运动信息。
4.2　三轮全向运动学模型
定义车体前向速度为vx，横向速度为vy，绕垂直轴角速度为ωz。根据程序中的三轮几何关系，三只轮的目标速度m1、m2、m3由下式计算：
m1 = (√3/2)vx + 0.5vy − ωz	(公式1)
m2 = (√3/2)vx − 0.5vy + ωz	(公式2)
m3 = vy + ωz	(公式3)

图4.1　三轮全向底盘速度分解示意
上述运动学使主车能够横移搜索目标，也使从车能够在跟随主车前进速度的同时独立加入横向视觉修正。对于原地或组合旋转，ωz直接改变三轮目标速度的差动分量。
核心算法子程序（逆运动学）如下：
def chassis(vx, vy, wz):
    m1=(sqrt(3)/2)*vx + 0.5*vy - wz
    m2=(sqrt(3)/2)*vx - 0.5*vy + wz
    m3=vy + wz
    return int(m1), int(m2), int(m3)
4.3　轮速闭环、滤波与里程计
三路轮速均采用增量式PID，参数Kp=0.70、Ki=0.074、Kd=0.03，输出限幅为8000。为避免目标速度突变后积累的控制量造成瞬间冲击，当任一轮新旧目标差超过设定阈值时清空对应PID状态。速度误差绝对值小于20时按零误差处理，从而降低静止附近的抖动。
Δu(k)=Kp[e(k)−e(k−1)]+Ki·e(k)+Kd[e(k)−2e(k−1)+e(k−2)]	(公式4)
主车里程计先由三轮行程换算车体坐标位移，再用IMU偏航角进行二维坐标旋转。程序在前向和横向两个方向分别使用1.045和1.05的增益补偿。该里程计既用于按距离完成出库、推送、后退和返航，也用于把视觉像素误差转换为短距离位移后执行闭环定位。
4.4　IMU航向控制
主、从车均根据IMU偏航角计算最短角度误差，并使用位置式PD维持目标航向。主车航向控制参数为Kp=6.5、Ki=0、Kd=3.5，常规输出限幅500；从车同类控制器输出限幅600。绝对转向采用远近两档角速度：普通旋转速度230，在剩余角度小于15°时降为110，并要求连续若干控制周期进入容差后再切换状态。进入视觉对准或搬运前，角度容差收紧到2°并延长稳定确认时间。
4.5　主车目标识别与视觉定位
主车视觉检测一帧可能包含多个对象。底盘解析后首先根据当前任务阶段确定期望类别，再用“中心Y×20+检测框宽度”的评分优先选择更靠近车体且尺寸更大的候选。选定目标后锁定类别，避免在跟踪过程中跳到其他物体。目标中心再经过系数0.45的一阶滤波形成track_cx、track_cy。
定位采用“粗定位—视觉复核—精定位”的两阶段方法。程序设定目标像素位置CENTER_X=254、CENTER_Y=142；当误差较大时使用三次多项式把二维像素误差直接映射为车体坐标位移，并对粗定位前向位移加入40 cm补偿与最大位移约束；目标进入±60像素范围后切换到精定位多项式。
ΔX=f3(ex,ey),　ΔY=g3(ex,ey)	(公式5)
其中f3、g3为由实测样本拟合得到的二维多项式映射，包含ex、ey、ex²、exey、ey²以及三次交叉项。计算得到的位移由里程计轴向控制器执行，精定位结束条件为前向剩余量不大于5.8 cm、横向剩余量不大于1.8 cm，并连续满足5个控制周期。由于模型来自实车数据，其价值在于把透视和非线性安装误差直接吸收到经验映射中，而不要求建立理想针孔模型。
4.6　主车任务状态机
主车任务按照PHASE_BALL、PHASE_BEAR、PHASE_SANDBAG、PHASE_FINAL四个阶段组织。发车后先前进20 cm，再按“前向65 cm、右向135 cm”的比例斜向离开发车区；随后进入网球搜索。若500 ms内未发现网球，车辆每次向前移动25 cm后再次停止观察。识别目标后直接进入视觉定位。
完成网球定位后车辆向前推送，程序以黄色边界作为网球阶段完成判据。随后车辆转向泰迪熊搜索方向，经过预定位、视觉定位和环绕调整后推送泰迪熊；之后转向沙包搜索与搬运阶段。所有搬运完成后车辆将目标航向设置为180°，按里程计前进160 cm后停止。

4.7　目标丢失与恢复策略
视觉状态下，程序以250 ms判断目标是否新鲜，并统计400 ms时间窗内连续丢失帧。当连续丢失达到3帧或等待超时后停止常规定位。对于网球，恢复状态继续沿原航向分段前进搜索；对于其他目标，则依据最后一次有效目标中心位于画面左侧或右侧决定横向搜索方向。第二次精定位阶段若短时丢失超过400 ms，则直接退出该视觉阶段，避免长期卡死。
4.8　从车视觉跟随算法
从车接收摄像头输出后先用系数0.65的一阶滤波得到相对中心位置。期望中心为(168,204)，X、Y方向分别设置6像素和8像素死区。X方向按误差绝对值分成近、中、远三个区间，比例增益为2.0、7.0、10.5，并加入误差变化率阻尼0.5，输出最大前向视觉修正为320。
Y方向根据误差符号区分“接近”和“退离”两种模式。接近阶段分段增益为3.5、10.5、14.0，最大横向修正1400；退离阶段采用更大的16、28、36分段增益，同时使用“80+44×像素误差”的速度上限函数将负向速度限制在700以内。视觉目标速度还经过加减速度限制和一阶平滑，避免误差符号改变时出现机械冲击。
4.9　双车普通跟随与刚性编队
从车控制器根据主车角速度采用迟滞方式切换两种跟随状态：|wz|超过20进入刚性编队，低于10退出刚性编队。普通平移状态下，从车基本速度直接取主车vx、vy，并叠加自身视觉补偿；刚性编队状态下，根据主车与从车之间的期望偏置计算旋转时的切向附加速度，再转换到从车车体坐标系。
当前程序的期望偏置为前向1 cm；顺时针旋转时从车位于主车右侧约20 cm，逆时针及最终返航旋转时右侧偏置约35 cm。刚性编队退出后设置120 ms保持时间，并清除视觉补偿和PID历史量，以减小模式切换的瞬态。
v′x = vx + wz·yoff/R,　v′y = vy − wz·xoff/R	(公式6)
式中R由底盘外接圆和软件有效轮径估计；随后根据主、从车航向差把(v′x,v′y)从主车体坐标系旋转到从车体坐标系。

4.10　通信与静止安全逻辑
从车只有在CRC8校验通过时才更新主车速度和航向；无线帧超过200 ms未更新时清空接收速度、跟随状态、PID和视觉补偿并停止电机。主车发送的是由编码器反解得到的实测底盘速度，因此当三轴实测速度均接近零时，从车立即进入静止锁止，不再因为视觉噪声反复微调。该逻辑可以保证主车停车后从车同步停车。
核心通信帧结构为：0xAA、0x55、vx(int16)、vy(int16)、wz(int16)、yaw(int16)、CRC8。CRC8采用多项式0x07，并对前10字节逐位计算；从车仅在CRC校验成功后更新运动指令。

第五章　开发、制作与调试过程
5.1　开发环境与程序组织
底盘程序运行于支持machine、smartcar和seekfree库的MicroPython环境；视觉程序运行于OpenART Plus环境，使用sensor、image、tf、UART等接口。为降低程序耦合，主车摄像头只负责目标检测和坐标发送，主车底盘负责目标选择、里程计、状态机及双车无线发送；从车摄像头只提供相对几何观测，从车底盘负责跟随控制。
5.2　机械与电气集成
机械装配首先保证三只全向轮的轴线方向和底盘中心关系一致，再固定N20电机、编码器、IMU和摄像头。两车机械及主驱一体板完全相同，可显著降低主从车动力学参数差异。电气调试按“P1输入与VCCBAT保护—SCT2450 5 V—RT9013-33 3.3 V—SY6280 5V_EXT—单路DRV8874—三路电机方向—三路编码器正负—IMU姿态—UART摄像头—无线串口”顺序逐项验证；确认三组CN1～CN3的电机线、编码器线和电源地无误后，再进入三轮运动学与任务状态机联调，以避免把硬件接线问题误判为控制算法问题。
5.3　轮速与里程计标定
轮速环先在单轮悬空和落地状态分别检查目标值与反馈值方向，再整定增量PID。里程计标定通过直线和横向定距离运动记录编码器积分误差，并修正ODOM_X_GAIN、ODOM_Y_GAIN。现有程序分别取1.045和1.05，说明两个方向均做了独立比例补偿。轮径软件参数为35 mm，应与实际有效滚动直径共同参与最终标定。
5.4　主车视觉定位调试
主车视觉调试分为识别稳定性和位姿映射两部分。识别侧固定曝光、增益和白平衡，并使用0.60置信度阈值及跨帧低通降低检测框抖动；定位侧采集不同目标像素误差与车辆需要移动距离的对应数据，拟合二维三次多项式。粗定位负责大范围接近，精定位只在误差绝对值小于60像素时使用，并在每次里程计移动后重新观察目标。
5.5　从车编队调试
从车先在主车静止条件下标定光斑期望中心，再分别调节X/Y死区、分段增益、最大速度和滤波系数。普通平移稳定后再启用刚性编队模型，通过顺/逆时针旋转测试期望右侧偏置。程序对顺时针和逆时针采用不同的20 cm和35 cm偏置，说明实际车辆安装或比赛动作需要非对称调节。模式切换使用角速度迟滞，减少wz在阈值附近波动时频繁跳变。
5.6　异常工况调试
最后验证视觉丢失、无线断连、主车停车、目标突然跳变和长时间搜索等异常情况。程序已实现目标新鲜度、视觉超时、无线超时、搜索方向恢复、刚性退出保持和PID清零等机制。实际比赛前仍应通过遮挡摄像头、关闭发送端、人工移动目标等方法重复测试安全停车和恢复路径。

第七章　结论与改进方向
本系统以相同三轮全向底盘构成主、从双车，主车采用OpenART Plus完成搬运目标与黄色边界识别，底盘以编码器、IMU和里程计完成全向运动控制；从车通过无线接收主车实测速度与航向，并以双光斑视觉误差进行相对位置修正。软件采用球、泰迪熊、沙包和返航四阶段状态机，将目标搜索、粗精定位、推送、转向和异常恢复统一组织。
从程序结构看，系统的主要特点是把视觉和运动控制分层：主车通过二维多项式把像素误差转换为里程计短距离目标，从车则把主车速度前馈与视觉补偿叠加，并在旋转时采用刚性编队几何模型。固定周期编码器采样、增量PID、偏航角闭环、通信CRC8、视觉/无线超时以及静止锁止共同提高了双车协同的可控性。
后续改进重点包括：进一步统一机械标称轮径与软件有效轮径的定义并扩充里程计标定样本；增加视场边缘二维像素—位移数据，提高多项式映射的泛化能力；针对顺、逆时针旋转分别优化20 cm/35 cm编队偏置和视觉增益；在不改变现有总体架构的前提下减少视觉与里程计状态切换时间，从而进一步缩短完整任务用时。

def chassis(vx, vy, wz):
    m1=(sqrt(3) / 2) * vx + 0.5 * vy - wz
    m2=(sqrt(3) / 2) * vx - 0.5 * vy + wz
    m3=vy + wz
    return int(m1), int(m2), int(m3)

def inc_pid_calc(pid, target, actual):
    if target == 0 and abs(actual) < 20:
        clear_inc_pid(pid)
        return 0
    pid[4]=target - actual
    if abs(pid[4]) < 20:
        pid[4]=0
    delta=(pid[0] * (pid[4] - pid[5])
           + pid[1] * pid[4]
           + pid[2] * (pid[4] - 2 * pid[5] + pid[6]))
    pid[7] += delta
    pid[7]=clamp(pid[7], -pid[3], pid[3])
    pid[6]=pid[5]
    pid[5]=pid[4]
    return int(pid[7])

def update_odom_from_counts(c1, c2, c3):
    global pos_x, pos_y, yaw
    s1=c1 * MM_PER_COUNT
    s2=c2 * MM_PER_COUNT
    s3=c3 * MM_PER_COUNT
    dx_body=(s1 + s2) / 1.732
    dy_body=(s1 + 2.0 * s3 - s2) / 3.0
    yaw=imu.get_euler()[2]
    yaw_rad=radians(yaw)
    dx_world=dx_body*cos(yaw_rad)-dy_body*sin(yaw_rad)
    dy_world=dx_body*sin(yaw_rad)+dy_body*cos(yaw_rad)
    pos_x += dx_world / 10.0 * ODOM_X_GAIN
    pos_y += dy_world / 10.0 * ODOM_Y_GAIN

B.3　从车无线校验与刚性编队控制
# 从车：无线 CRC8 与刚性编队速度计算
def crc8(data, length=None):
    crc = 0
    if length is None:
        length = len(data)
    for i in range(length):
        crc ^= data[i]
        for _ in range(8):
            if crc & 0x80:
                crc = (crc << 1) ^ 0x07
            else:
                crc <<= 1
            crc &= 0xFF
    return crc

def rigid_formation_velocity(master_vx, master_vy, master_wz, heading_delta_deg):
    final_return_rotation=(master_vx == 0
        and master_vy == FINAL_RETURN_RIGID_MARKER_VY
        and master_wz != 0)
    if final_return_rotation:
        master_vy = 0
        offset_left_cm = FORMATION_OFFSET_LEFT_FINAL_CM
    else:
        offset_left_cm=(FORMATION_OFFSET_LEFT_CCW_CM
            if master_wz > 0 else FORMATION_OFFSET_LEFT_CM)
    rigid_vx_master=(master_vx + master_wz * offset_left_cm
                     / CHASSIS_WHEEL_CENTER_RADIUS_CM)
    rigid_vy_master=(master_vy - master_wz * FORMATION_OFFSET_FORWARD_CM
                     / CHASSIS_WHEEL_CENTER_RADIUS_CM)
    delta_rad = radians(heading_delta_deg)
    slave_vx = rigid_vx_master*cos(delta_rad)-rigid_vy_master*sin(delta_rad)
    slave_vy = rigid_vx_master*sin(delta_rad)+rigid_vy_master*cos(delta_rad)
    return signed_round_int(slave_vx), signed_round_int(slave_vy)

# 跟随模式迟滞切换（节选）
if follow_state == FOLLOW_RIGID:
    if abs(rx_wz) < RIGID_EXIT_WZ:
        next_state = FOLLOW_TRANSLATION
elif abs(rx_wz) > RIGID_ENTER_WZ:
    next_state = FOLLOW_RIGID

# 主车视觉：TFLite 目标框转为像素中心坐标
def append_model_objects(img):
    model_img = img.copy(0.75, 1)
    for obj in tf.detect(net, model_img):
        x1, y1, x2, y2, label, score = obj
        obj_id, label_name = label_to_id(label)
        if obj_id < 0 or score < SCORE_TH:
            continue
        x = clamp_int(x1 * img.width(), 0, img.width() - 1)
        y = clamp_int(y1 * img.height(), 0, img.height() - 1)
        w = clamp_int((x2-x1) * img.width(), 1, img.width())
        h = clamp_int((y2-y1) * img.height(), 1, img.height())
        cx = x + w // 2
        cy = y + h // 2
        append_detection(obj_id, cx, cy, w, score, x, y, w, h)

blobs = img.find_blobs([red_threshold], pixels_threshold=50,
                       area_threshold=50, merge=False, roi=SEARCH_AREA)
if len(blobs) >= 2:
    blobs.sort(key=lambda b: b.pixels(), reverse=True)
    blob1, blob2 = blobs[0], blobs[1]
    if blob1.cx() < blob2.cx():
        left_blob, right_blob = blob1, blob2
    else:
        left_blob, right_blob = blob2, blob1
    c_x=(right_blob.cx()+left_blob.cx())//2
    c_y=(right_blob.cy()+left_blob.cy())//2
    width=right_blob.cx()-left_blob.cx()
    comm.send_data(c_x,c_y,width)
