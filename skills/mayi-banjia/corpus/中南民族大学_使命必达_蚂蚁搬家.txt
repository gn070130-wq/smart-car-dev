第一章  引言
1.1  课题背景与研究意义
全国大学生智能汽车竞赛是以智能汽车为研究对象的创意性科技竞赛，是面向全国大学生的一种具有探索性的工程实践活动。竞赛以"立足培养、重在参与、鼓励探索、追求卓越"为宗旨，旨在促进高等学校素质教育，培养大学生的综合知识运用能力、基本工程实践能力和创新意识。
第二十一届竞赛增设"蚂蚁搬家"组别，该组别要求两辆模型车协同工作，在规定场地内将不同类型的物品（泰迪熊、沙包、网球）从场地中央推送至边界外，同时需要规避场地内设置的红砖障碍物。该赛题融合了机器视觉、运动控制、多机协同、路径规划等多个技术领域，对参赛队伍的系统集成能力和算法设计能力提出了较高要求。
本报告详细阐述了中南民族大学"使命必达"队在蚂蚁搬家组别中的技术方案，包括机械结构设计、电路系统设计、主车控制算法、视觉识别系统、从车跟随控制以及系统调试过程，总结了设计制作过程中的创新点与技术难点。
1.2  赛题任务分析
蚂蚁搬家赛题场地尺寸为2.4m×3.2m，场地中央放置若干待搬运物品，四周设有发车区。比赛分为预赛和决赛两个阶段：预赛要求搬运5个物品，决赛要求搬运7个物品。两辆模型车分别为主车（主动搬运车）和从车（跟随辅助车），主车负责识别物品并推送出界，从车跟随主车并行运动，在需要时辅助推送。
场地内随机放置红砖作为障碍物，模型车在推送物品过程中需要实时检测并规避障碍物。物品分为三类：泰迪熊（体积较大、易被推倒）、沙包（圆柱形、滚动阻力大）、网球（球形、易滚动），不同物品需要采用不同的推送策略和返回策略。
通过对赛题的分析，系统需要解决以下关键技术问题：（1）三轮全向移动平台的精确运动控制；（2）基于嵌入式视觉的多类别目标检测与障碍物识别；（3）基于编码器与IMU的里程计全局定位；（4）双车无线通信与协同跟随控制；（5）复杂任务状态机的设计与调试。
1.3  系统总体方案设计
本系统采用"主从双车协同"架构，两车硬件配置一致，均以逐飞RT1021-MicroPython核心板为主控制器，搭载Open Art Plus视觉模块、IMU660RX六轴姿态传感器、三路光电编码器、三路DRV8874电机驱动和N20减速电机，配合38mm全向轮实现全向移动。
主车视觉模块运行基于TensorFlow Lite的YOLO目标检测算法，实时识别泰迪熊、沙包、网球三类物品，并通过LAB颜色阈值和长宽比分析识别红砖障碍物，将目标坐标、物品种类和避障标志通过UART发送至主控制器。主控制器基于编码器里程计和IMU航向实现全局定位，采用双闭环PID控制（位置环+速度环）实现精确运动，通过任务状态机调度巡航、寻物、对齐、推送、返回等完整流程。
从车视觉模块采用灰度图识别主车尾部的两个红外发光信标，计算两灯中心点、连线角度和距离，实现对主车的实时定位。从车控制器结合无线串口接收的主车速度/角速度前馈信息和视觉反馈的位置误差，采用"前馈+反馈"复合控制策略实现与主车的平行跟随。系统总体架构如图1所示。

第二章  机械结构设计
2.1  整车机械布局
两车均采用三轮全向轮布局，三个全向轮呈120°均匀分布在车体圆周上，实现平面内三自由度（X、Y平移和绕Z轴旋转）的全向移动。车体采用3D打印一体化框架，上层安装主控板和视觉模块，中层安装电机驱动板和电源模块，下层安装电机和全向轮。主车因需要搭载更高的视觉摄像头（俯视角度识别地面物品），整车高度为50cm；从车视觉模块高度较低，整车高度为38cm。
整车长宽均为38cm，主车重量287.3g（含电池），从车重量263.5g（含电池）。电池采用逐飞3S锂电池，重量24.5g，安装在车体中心位置以保证重心居中。车体设计充分考虑了轻量化与结构刚度的平衡，在关键受力部位采用加强筋设计。整车机械结构俯视图如图2.1所示。

图2.1  整车机械结构俯视图（主车）
2.2  全向轮运动平台设计
全向轮直径为38mm，每个轮子由多个小辊子组成，辊子轴线与轮子轴线成45°角，使得轮子在滚动方向具有驱动力的同时，在垂直方向可以被动滑动。三个全向轮的运动学模型如图2.2所示。
设车体中心速度为(vx, vy)（vx为车体右侧方向，vy为车体前方方向），绕Z轴旋转角速度为ω，则三个电机的目标速度为：
v₁ = vx/3 + vy/√3 + ω
v₂ = -2vx/3 + ω
v₃ = vx/3 - vy/√3 + ω
其中v₁对应右前轮，v₂对应后轮，v₃对应左前轮。该运动学解算保证了三个电机速度之和等于3ω，从而实现纯旋转运动；当ω=0时，三个电机速度矢量和为零，实现纯平移运动。实际控制中，通过对速度和进行补偿校正（v₂ = v₂ - (v₁+v₂+v₃)），消除累积误差。


图2.2  三轮全向轮运动学模型与速度分解
2.3  传感器安装布局
主车传感器布局如下：（1）Open Art Plus摄像头安装在车体正上方约40cm处，垂直向下俯视，视野覆盖车体前方约30cm×40cm区域，用于识别地面物品和障碍物；（2）IMU660RX安装在车体中心板上，尽量靠近重心位置以减小振动影响；（3）三路光电编码器与电机同轴安装，实时检测电机转速；（4）两路光敏电阻安装在车体前部下方，用于检测物品是否被推出边界（当物品离开车体下方时，光敏电阻接收到的光强发生突变）。
从车传感器布局如下：（1）Open Art Plus摄像头安装在车体前部，水平向前，用于识别主车尾部的两个红外发光信标；（2）主车尾部安装两个红外发光二极管作为信标，间距约10cm，从车通过识别两灯的相对位置计算主车的方位和距离；（3）其余传感器（IMU、编码器、光敏电阻）布局与主车一致。
2.4  电路板固定与连接
系统采用双层电路板结构：上层为逐飞RT1021-MicroPython核心板，通过排针与下层母板连接；下层为自行设计的扩展板，集成电机驱动、电源管理、传感器接口和通信模块。扩展板尺寸为8cm×8cm，通过铜柱固定在车体框架上。
电机通过硅胶线与扩展板上的DRV8874驱动芯片连接，编码器通过6P SH1.0连接器接入扩展板。摄像头通过4P HX2.54连接器连接至UART5接口，无线串口模块通过8P排针连接至UART2接口。电源输入采用XT30接口，通过拨动开关控制整车电源通断。所有连接线均采用扎带固定，避免运动过程中松动脱落。

第三章  电路系统设计
3.1  系统总体电路架构
系统电路以逐飞RT1021-MicroPython核心板为控制核心，外围电路包括电源模块、三路电机驱动模块、传感器接口电路和通信模块。RT1021是NXP i.MX RT系列跨界处理器，基于Cortex-M7内核，主频500MHz，搭载MicroPython运行环境，具有丰富的外设接口（UART、SPI、ADC、PWM、GPIO等），满足本系统的实时控制需求。
核心板通过板对板连接器与扩展板连接，扩展板上集成了所有外围电路。两车扩展板设计完全相同，保证硬件的一致性和可互换性。
3.2  电源模块设计
电源系统采用3S锂电池（标称11.1V）供电，经过SS34肖特基二极管实现防反接保护，然后通过TPS5430同步降压DC-DC转换器将电压降至5V/3A，为电机驱动、摄像头和无线模块供电；5V再经过RT9193-33GB低压差线性稳压器（LDO）降至3.3V，为MCU、IMU和编码器等数字电路供电。电源系统架构如图3.1所示。


图3.1  电源系统架构图
TPS5430是TI公司出品的宽输入范围（5.5V~36V）同步降压转换器，内置高侧和低侧MOSFET，输出电流可达3A，开关频率固定为500kHz，配合1μH功率电感（APH0630T1R0M）和输出滤波电容，具有转换效率高、纹波小的特点。RT9193-33是Richtek出品的300mA LDO，具有低噪声、高PSRR的特点，为模拟传感器提供干净的电源。
输入端并联100μF电解电容和100nF陶瓷电容进行滤波，5V输出端并联10μF和100nF电容，3.3V输出端并联4.7μF和100nF电容。所有IC电源引脚就近放置0.1μF去耦电容，保证电源完整性。
3.3  电机驱动模块
三路电机驱动均采用TI DRV8874PWPR芯片，这是一款集成了NMOS H桥的有刷直流电机驱动器，单通道持续输出电流3.5A，峰值电流6A，支持PWM调速和方向控制。DRV8874内置过流保护、过热保护和欠压锁定，具有低功耗睡眠模式，适合电池供电的小型移动机器人应用。
每路DRV8874的PWM输入引脚连接至RT1021的PWM输出（电机1：PWM_D6/DIR_D7，电机2：PWM_C28/DIR_C29，电机3：PWM_D4/DIR_D5），PWM频率为13kHz，处于人耳听觉范围之外，避免电机啸叫。电机输出端并联1N5819肖特基二极管作为续流保护，同时串联0Ω电阻作为电流检测预留。
3.4  传感器接口电路
IMU660RX通过SPI接口与核心板连接，输出六轴原始数据（加速度计+陀螺仪），内置DMP支持四元数输出，采样率配置为120Hz。三路光电编码器通过正交编码脉冲（QEP）接口连接，每路使用两个GPIO引脚（编码器1：D13/D14，编码器2：C2/C3，编码器3：D15/D16），由smartcar库的encoder模块实现硬件计数。
两路光敏电阻分别连接至ADC输入（B17和B15），与10kΩ上拉电阻组成分压电路，ADC采样率为100Hz。当物品位于车体下方时，光敏电阻受遮挡阻值增大，ADC读数低于阈值27000；当物品被推出边界后，光敏电阻曝光阻值减小，ADC读数高于阈值。系统通过连续两帧确认机制避免误触发。
扩展板上还预留了DY-ITR9909红外对管接口，可用于起跑线检测或辅助物品检测，实际比赛中使用光敏电阻方案，红外对管作为备用。
3.5  通信模块设计
系统包含两路UART通信：UART5（115200bps）用于主控与视觉模块之间的数据传输，UART2（115200bps）用于主从车之间的无线通信。无线模块采用逐飞无线串口模块，工作在2.4GHz频段，通信距离可达50m，满足场地内双车通信需求。
通信协议采用自定义帧格式，帧头为"="，帧尾为"*"，数据字段之间用"a"分隔，支持负号和数字字符。主车视觉向主控发送格式为"=cx a cy a label a obs_flag a 0*"，包含目标中心坐标、物品种类（1=熊，2=沙包，3=网球）和障碍物标志（90/91/92/93）。主车向从车发送格式为"=0 a gyro a vx a vy a ff*"，包含主车陀螺仪Z轴数据、分解速度和避障标志。从车视觉向从车主控发送格式为"=angle a dist a cx a cy a ok*"，包含红外信标连线角度、距离、中心点和有效标志。通信协议帧格式如图3.2所示。

第四章  主车控制软件设计
4.1  软件总体架构
主车控制软件基于MicroPython开发，采用模块化设计，主要包含以下模块：main_qian.py（主程序入口，初始化和主循环）、user_run_qian.py（任务状态机，预赛/决赛流程）、user_run_qian_base.py（运动控制基类，里程计、PID、运动学解算）、user_pid.py（PID控制器类）、user_uart.py（串口数据解析）、user_param.py（参数管理与持久化）、user_menu.py（LCD脱机调参菜单）。
软件采用多定时器中断架构：PIT定时器1（20ms周期）负责编码器采样、里程计积分和电机速度环PID计算；PIT定时器2（10ms周期）负责光敏电阻采样、ADC阈值判断和时间计数；主循环（约40ms周期）负责视觉数据解析、任务状态机调度、无线通信和LCD菜单更新。这种分层定时架构保证了电机控制的实时性，同时兼顾了视觉处理和任务调度的灵活性。任务调度时序如图4.1所示。

图4.1  主车软件多任务调度时序图
4.2  运动控制与PID算法
系统采用双闭环PID控制结构，如图4.2所示。内环为电机速度环，采用增量式PID，以编码器反馈的电机转速为当前值，以运动学解算得到的目标转速为设定值，输出PWM占空比直接控制电机。外环为位置环/转向环/视觉环，采用直接式PID，根据位置误差或角度误差计算目标速度，作为内环的设定值。

图4.2  主车双闭环PID控制系统框图
增量式PID控制律为：Δu(k) = Kp[e(k)-e(k-1)] + Ki·e(k) + Kd[e(k)-2e(k-1)+e(k-2)]，u(k) = u(k-1) + Δu(k)。增量式PID仅输出控制量的增量，具有误动作影响小、易于手动/自动切换的优点，适合电机速度控制。速度环PID参数为Kp=2，Ki=1，Kd=0，输出限幅±6000，控制周期20ms（50Hz）。
为克服电机死区和静摩擦，速度环引入了前馈补偿机制：当目标速度方向发生改变时，根据方向叠加固定的死区补偿量（shiqu参数）；当目标速度从0变为非零时，叠加半量死区补偿。这一机制显著改善了小车低速启动和换向时的响应特性。
转向环采用直接式PID，以IMU解算的航向角yaw为反馈值，以目标航向yaw_target为设定值，输出叠加到三个电机的速度指令上实现车体旋转。转向PID参数为Kp=4，Kd=6，输出限幅±75。在直行过程中，转向环持续修正航向偏差，保证车体沿直线行驶；在定点旋转时，转向环独立控制车体朝向目标角度。
4.2.1  速度斜坡限制
为防止速度突变导致车轮打滑和机械冲击，系统对目标速度进行斜坡限制：每周期速度变化量不超过max_dv（默认75，推送状态下30）。即v(k) = clip[v(k-1) ± max_dv, v_target]。这一措施有效抑制了全向轮小车在急加减速时的打滑现象，提高了里程计的精度。
4.2.2  视觉模糊PID
在视觉对齐阶段（状态4/54/58），系统根据视觉误差大小动态切换PID参数，实现分段模糊控制：当误差大于60像素时，采用高增益参数（Kp=5, Kd=6, 限幅350）快速接近目标；当误差在25~60像素之间时，采用中增益参数（Kp=3.6, Kd=6.8, 限幅200）平稳过渡；当误差小于25像素时，采用低增益参数（Kp=2.9, Kd=6.2, 限幅80）精细对齐。这种分段策略兼顾了响应速度和稳态精度。PID控制系统的阶跃响应特性如图4.3所示。

图4.3  PID控制系统响应曲线（仿真示意）
4.3  里程计与全局导航
全局定位基于编码器里程计和IMU航向角的融合。每个控制周期（20ms），系统读取三个编码器的增量计数，通过运动学逆解算得到车体局部坐标系下的速度(vx, vy)，然后根据当前航向角yaw通过旋转矩阵将局部速度转换为全局速度，最后积分得到全局坐标(global_x, global_y)。
坐标更新公式为：
vx = enc₁×0.5 - enc₂ + enc₃×0.5
vy = enc₁×0.866 - enc₃×0.866
vx_global = vx·cos(θ) - vy·sin(θ)
vy_global = vx·sin(θ) + vy·cos(θ)
global_x += vx_global,  global_y += vy_global
其中θ = yaw - yaw_start为相对起始航向的角度。坐标单位为编码器脉冲，480脉冲约等于1cm位移。场地坐标范围约为X∈[0, 153600]，Y∈[0, 115200]，对应实际尺寸3.2m×2.4m。
全局导航函数run_to_global(x, y)计算当前位置与目标位置的误差，将全局误差通过旋转矩阵转换为局部坐标系误差，经PID计算得到局部速度指令，再分解为三个电机速度。导航过程中同时运行转向环保持车体朝向。到达阈值为2880脉冲（约6cm），到达后停车并返回完成标志。
4.3.1  坐标校准机制
由于编码器存在累积误差，系统在每次将物品推出边界时（光敏电阻检测到adc_flag下降沿），根据当前航向角对全局坐标进行校准重置：当朝向0°时global_y=115200（北边界），朝向90°时global_x=0（西边界），朝向180°时global_y=0（南边界），朝向270°时global_x=153600（东边界）。这种基于边界事件的绝对坐标校准有效消除了里程计累积漂移，保证了长赛程中的定位精度。场地全局坐标系统如图4.4所示。

图4.4  场地全局坐标系统与小车导航示意图
4.4  任务状态机设计
主车任务调度采用有限状态机（FSM）设计，预赛和决赛分别有独立的状态机（run_control_yu和run_control_jue）。决赛状态机包含20余个状态，覆盖从发车到停车的完整流程，核心状态流转如图4.5所示。

图4.5  主车决赛任务状态机流程图
决赛状态机的核心流程为：状态50（初始转向90°）→ 状态51（直行入场）→ 状态52/62（全局导航至巡航起点）→ 状态53/63/64（S形巡航寻物）→ 状态54（视觉对齐物品）→ 状态55-58（绕物品旋转至推送朝向并微调）→ 状态59（等待从车就位）→ 状态60（推送物品出界）→ 状态61（掉头180°）→ 循环寻物。当推送物品数达到7个后，根据最后推送的物品种类选择不同的返回策略：泰迪熊采用三段式返回（状态71-74），网球采用两段式返回（状态75-76-74），沙包采用一步直达返回（状态77-78-74），最终在状态74完成360°旋转后停车。
4.4.1  180度旋转歧义处理
在状态57绕物品旋转时，当目标朝向与当前朝向相差接近180°时，常规PID的最短路径选择存在方向歧义。系统通过设置rotate_err_range参数（150°）检测180°模糊场景，并使用l_o_r_f标志强制指定旋转方向（0=逆时针，1=顺时针），将误差扩展到[-360°, 360°范围使PID按指定方向旋转。同时将360°停车旋转分为四个90°阶段执行，彻底避开歧义区间。
4.5  视觉伺服控制
视觉伺服是主车精确对齐物品的关键环节。视觉模块通过UART5以约25fps的速率发送目标中心坐标(cx, cy)、物品种类label和障碍物标志obs_flag。主控对接收数据进行低通滤波（一阶RC滤波，系数0.8），抑制单帧噪声，然后计算相对于目标参考点的误差。
误差经过死区处理（X方向死区5像素，Y方向死区7像素）后送入视觉PID控制器，输出局部速度指令控制车体平移对齐。当X和Y方向误差均小于死区阈值并连续确认1帧后，判定对齐完成，清空PID积分并进入下一状态。
在近距离对齐阶段（误差小于阈值但未退出），系统启用最小速度地板（approach_min_speed=30），保证克服静摩擦持续移动，避免PID输出过小导致车体静止卡死。该机制仅在PID输出与误差同向时启用，防止目标点附近震荡。

第五章  视觉识别系统设计
5.1  主车视觉系统
主车视觉模块基于Open Art Plus（搭载K210处理器）开发，运行MicroPython+OpenMV环境，使用TensorFlow Lite推理引擎。摄像头配置为QVGA分辨率（320×240），RGB565格式，关闭自动增益和自动白平衡以保证图像稳定性。视觉算法流程如图5.1所示。

图5.1  主车视觉识别算法流程图
5.1.1  基于TFLite的目标检测
目标检测采用自行训练的YOLO风格TFLite模型（144all3_3fliter15.tflite），输入分辨率144×144，模型大小约77KB，可在K210上实时运行。模型可识别三类物品：泰迪熊（label=1）、沙包（label=2）、网球（label=3），置信度阈值设为0.45。检测结果经过坐标映射转换为320×240像素坐标，并进行黄线过滤（检测目标中心区域黄色像素占比，超过40%判定为场地黄线误检）。
模型训练采用自建数据集，包含不同光照、不同角度下的物品照片约2000张，使用LabelImg标注后转换为TFLite格式。训练过程中采用数据增强（随机裁剪、翻转、亮度扰动）提高模型泛化能力。
5.1.2  红砖障碍物识别
红砖障碍物识别采用双策略融合：（1）LAB颜色阈值分割，阈值为[(45,67,52,63,-12,48)]，通过find_blobs提取红色色块，最小像素阈值100；（2）长宽比辅助识别，对YOLO检测中label=3且长宽比大于1.5的目标判定为疑似红砖。两种策略的检测结果经过多源去重融合（欧氏距离<40像素判定为同一目标，保留面积较大者），得到最终红砖列表。
5.1.3  多源融合与状态保持
为防止同一物体在"红砖/普通物品"之间来回切换导致检测框闪烁，系统引入红砖状态迟滞保持机制：上一帧已判定为红砖的物体，本帧即使未被颜色阈值检测到，也保持红砖状态最多3帧，并从物体列表中拉回最近的匹配目标。同时对所有检测目标进行ID追踪（update_tracks），保持目标ID连续性，丢失后保留2帧（泰迪熊保留4帧）。
5.1.4  避障决策
避障决策基于障碍物与目标的相对位置关系，分为两种场景：场景A（砖头在目标下方或无目标），采用纯平移避让（标志92/93），根据砖头中心离检测区域左右边界的距离选择避让方向；场景B（砖头在目标上方或无砖头），采用斜向避让（标志90/91），根据左侧区域是否有障碍选择向右或向左避让。避障标志还经过防突变锁存处理，避免92/93之间频繁切换。
视觉模块支持双模式切换：模式0为完整识别模式（320×240），执行目标选取和障碍物判定；模式1为简化识别模式（320×180），仅识别最下方障碍物，用于推送阶段的近距离避障。模式由主控通过UART发送指令动态切换。主车视觉识别效果如图5.2所示。

5.2  从车视觉系统
从车视觉模块同样基于Open Art Plus，但采用完全不同的识别策略：灰度图下识别主车尾部的两个红外发光信标。摄像头配置为QVGA灰度图（320×240），灰度阈值为(180,255)，仅提取高亮像素。
识别流程为：（1）find_blobs提取所有高亮色块，经过ROI过滤（X∈[64,256], Y∈[48,192]）和面积过滤（25~500像素）；（2）近距离色块合并（欧氏距离<20像素合并为一点，面积加权中心），处理同一光源被拆分的情况；（3）按面积排序取top5，与上一帧的左右灯位置进行最近邻匹配，保证左右灯身份稳定；（4）防突变处理，当前帧同侧灯距上一帧超过50像素则丢弃；（5）短暂丢失容错，允许0帧丢失（严格要求双灯同时可见）。
当两个灯均成功识别时，计算两灯中心点(cx,cy)、连线角度angle（atan2(dy,dx)）和距离dist，通过UART发送至从车主控。角度用于计算主车航向偏差，中心坐标用于计算横向和纵向跟随误差，距离用于估计前后间距。从车视觉识别帧率约30fps，满足跟随控制实时性要求。从车红外信标识别效果如图5.3所示。

第六章  从车跟随控制设计
6.1  平行跟随策略
从车的核心任务是与主车保持平行跟随，即在主车左侧或右侧保持固定间距和相同航向，同步移动。系统采用"前馈+反馈"复合控制策略，如图6.1所示。前馈通道基于无线串口接收的主车运动状态（速度vx、vy和角速度ω），通过坐标旋转换算到从车局部坐标系并叠加旋转补偿，预测从车应有的运动速度；反馈通道基于从车视觉识别的主车红外信标位置，计算横向、纵向和航向误差，通过PD控制修正前馈偏差。


图6.1  从车平行跟随控制系统框图
6.2  前馈控制设计
前馈控制是保证从车同步性的关键。主车通过无线串口以约33Hz的速率发送陀螺仪Z轴数据、分解速度(vx,vy)和避障标志。从车接收后，首先根据主从车相对航向角θ进行坐标旋转：
vx_ff = vx主·cos(θ) - vy主·sin(θ)
vy_ff = vx主·sin(θ) + vy主·cos(θ)
然后叠加旋转前馈补偿：当主车转弯时，从车由于位于主车侧方（跟随距离D=12单位），需要额外的纵向速度补偿vy_rotate = -ω主×D，以保证从车沿圆弧轨迹同步转弯。旋转前馈在X方向叠加绝对值补偿（k_ff_rotate_x=0.3），Y方向叠加带符号补偿（k_ff_rotate_y=1.2）。
系统还引入了超前预测机制：根据前馈速度的变化率预测下一帧速度（predict_gain系数），补偿无线通信和视觉处理带来的延迟。前馈总输出为：total_ff = k_ff_v·v_ff + k_ff_rotate·v_rotate + k_ff_ω·ω。
6.3  反馈控制设计
反馈控制用于修正前馈的偏差和累积误差。从车视觉提供三个误差量：横向误差error_x = cy - 140（左右并排偏差）、纵向误差error_y = cx - 169（前后距离偏差）、航向误差error_yaw = angle（信标连线角度）。三个误差分别经过PD控制器（带死区）输出反馈修正量。
死区设置为X方向3像素、Y方向3像素、航向1.5°，死区内直接输出0并清除PID历史误差，防止微小抖动导致车体频繁微调。反馈增益为Kp_vx=3, Kd_vx=5, Kp_vy=3, Kd_vy=5, Kp_turn=2, Kd_turn=4。反馈输出乘以增益系数（平移2.6，转向2.0）后与前馈输出叠加，最终经运动学解算分配到三个电机。
当视觉丢失信标（ok=0）时，误差不直接清零，而是缓慢衰减（乘以0.0立即停车），同时保持前馈控制，使从车在短暂视觉丢失时仍能维持运动趋势。
6.4  从车独立任务状态机
从车除了跟随模式外，也具备独立的任务状态机（预赛和决赛），可在主车完成物品推送后独立执行辅助推送任务。从车状态机包含状态51（直行入场）、52（转向90°）、53（巡航寻物）、54（视觉对齐）、55-58（旋转微调）、59（等待主车）、60（推送物品）等，逻辑与主车类似但参数不同（速度上限更低，PID增益更保守）。
从车与主车的协同通过无线串口实现：主车在状态55/59时发送就绪标志，从车检测到主车就绪后才进入推送状态，保证两车同步动作。从车还通过get_l_or_r()函数根据全局坐标判断自身位于主车左侧还是右侧，用于决定旋转方向和避让策略。双车协同推送物品的工作场景如图6.1所示。

第七章  系统调试与参数整定
7.1  开发工具与调试环境
软件开发使用逐飞提供的RT1021-MicroPython开发环境，通过Thonny IDE进行代码编辑和在线调试。视觉模块开发使用OpenMV IDE，支持帧缓冲区实时预览和脚本调试。无线通信调试使用USB转串口模块监听通信数据。
调试过程中，主车通过UART无线串口实时输出编码器读数、PID目标值/当前值/输出值、全局坐标、状态标志等关键变量，在上位机用串口助手记录并分析。视觉模块通过IPS200 LCD屏幕实时显示检测结果（目标框、障碍物框、FPS、状态标志），便于现场调试。
7.2  PID参数整定
PID参数整定采用"先内环后外环、先比例后积分微分"的经典方法。首先整定电机速度环：固定Ki=Kd=0，逐步增大Kp直到电机出现小幅振荡，然后回退20%作为最终Kp（Kp=2），再加入少量Ki（Ki=1）消除稳态误差。速度环整定完成后，整定转向环：逐步增大Kp直到车体转向响应快速且无超调（Kp=4），加入Kd（Kd=6）抑制振荡。
视觉PID参数采用分段整定：大误差段追求响应速度，Kp=5；中误差段追求平稳过渡，Kp=3.6；小误差段追求稳态精度，Kp=2.9。整定过程中通过LCD菜单实时修改参数并观察对齐效果，最终确定各段参数。全局导航PID参数（Kp=0.05）根据导航距离动态调整输出比例，远距离时全比例输出，近距离（<15000脉冲）时按0.04/Kp比例减速。
7.3  视觉参数调试
主车视觉参数调试主要包括：（1）TFLite模型置信度阈值，最终设为0.45，在召回率和误检率之间取得平衡；（2）LAB颜色阈值，通过OpenMV IDE的阈值编辑器现场采集红砖颜色样本确定；（3）检测区域ROI，通过is_in_zone函数定义的梯形区域过滤远处误检；（4）去重距离阈值（40像素）和状态保持帧数（3帧），通过实验调整以平衡响应速度和稳定性。
从车视觉参数调试主要包括：灰度阈值（180~255）、ROI范围、面积过滤上下限（25~500像素）、合并距离（20像素）、防突变距离（50像素）。调试中发现红外信标在强光环境下容易过曝导致面积超限，因此设置了最大面积过滤；在弱光环境下信标面积偏小，设置了最小面积过滤。
7.4  脱机调参系统设计
为提高现场调试效率，主车设计了基于1.14寸SPI LCD和4个按键的脱机调参系统。菜单系统支持5级界面：主菜单（参数调节/文件管理/监视器）、参数组选择（电机PID/转向PID/视觉PID/全局导航PID/模糊PID/速度限制）、参数项选择、数值编辑、实时监视。
参数调节支持9组档位（Gear 1~9），可将当前参数保存为不同档位并快速切换，适用于不同场地条件。参数通过文件系统持久化存储在Flash中，掉电不丢失。监视器界面实时显示编码器读数、PID输出、全局坐标、状态标志等关键变量，无需连接电脑即可观察系统运行状态。该系统极大提高了赛场调试效率，减少了对电脑的依赖。

结论
本报告详细阐述了中南民族大学"使命必达"队在第二十一届全国大学生智能汽车竞赛蚂蚁搬家组别中的技术方案。系统采用主从双车协同架构，以逐飞RT1021-MicroPython核心板为主控制器，搭载Open Art Plus视觉模块，实现了物品识别、障碍物规避、全向运动控制、双车协同跟随等完整功能。
在机械设计方面，采用三轮全向轮布局实现三自由度全向移动，3D打印一体化框架保证了结构刚度和轻量化。在电路设计方面，自行设计了集成DRV8874电机驱动、TPS5430电源管理和多传感器接口的扩展板，硬件两车通用。在控制算法方面，设计了双闭环PID控制系统、基于编码器+IMU的里程计全局导航、分段模糊PID视觉伺服和复杂任务状态机，实现了精确稳定的运动控制。
在视觉识别方面，主车采用自行训练的TFLite目标检测模型结合LAB颜色阈值和长宽比分析，实现了三类物品和红砖障碍物的实时识别；从车采用红外信标灰度识别方案，实现了对主车的高精度实时定位。在双车协同方面，设计了"前馈+反馈"复合平行跟随控制策略，保证了从车与主车的同步性。
系统仍存在以下可改进之处：（1）里程计在长时间运行后仍有累积漂移，未来可引入视觉路标或UWB定位进行修正；（2）TFLite模型在极端光照下识别率有所下降，可增加更多光照场景的训练样本；（3）从车跟随控制在主车急转时仍有滞后，可进一步优化前馈预测算法。未来将围绕这些方向继续优化，提升系统的鲁棒性和完成效率。

A.1  PID控制器实现
class PIDclass:
    def __init__(self, target, kp, ki, kd, out_max, out_min, shiqu=0):
        self.target = target
        self.kp, self.ki, self.kd = kp, ki, kd
        self.out_max, self.out_min = out_max, out_min
        self.out = self.current = 0
        self.error = self.lerror = self.llerror = 0
        self.ierror = 0
        self.shiqu = shiqu  # 死区补偿量

    def PID_Increase(self):  # 增量式PID（电机速度环）
        self.error = self.target - self.current
        self.ierror += self.error
        self.out += (self.kp * (self.error - self.lerror)
                     + self.ki * self.error
                     + self.kd * (self.error - 2*self.lerror + self.llerror))
        # 死区/摩擦前馈补偿
        if self.target * self.target_last < 0:
            self.out += self.shiqu if self.target > 0 else -self.shiqu
        self.out = max(min(self.out, self.out_max), self.out_min)
        self.llerror, self.lerror = self.lerror, self.error
        self.target_last = self.target

    def PID_Direct(self):  # 直接式PID（位置环/转向环/视觉环）
        self.error = self.target - self.current
        self.ierror += self.error
        self.out = (self.kp * self.error
                    + self.ki * self.ierror
                    + self.kd * (self.error - self.lerror))
        self.out = max(min(self.out, self.out_max), self.out_min)
        self.lerror = self.error

def update_position(self):
    theta = math.radians(normalize_angle(self.yaw - self.yaw_start))
    # 编码器增量 -> 局部速度
    self.vx = self.global_one * 0.5 - self.global_two + self.global_three * 0.5
    self.vy = self.global_one * 0.866 - self.global_three * 0.866
    # 局部 -> 全局旋转矩阵
    vx_global = self.vx * math.cos(theta) - self.vy * math.sin(theta)
    vy_global = self.vx * math.sin(theta) + self.vy * math.cos(theta)
    # 积分累加（480脉冲 ≈ 1cm）
    self.global_x += int(vx_global)
    self.global_y += int(vy_global)
A.4  从车前馈+反馈复合跟随控制
def parallel_follow_with_feedforward(self, pid_vx, pid_vy, pid_turn):
    # ===== 前馈：主车速度旋转换算 + 旋转补偿 =====
    theta = math.radians(self.relative_yaw)
    ff_vx = self.ff_vx * cos(theta) - self.ff_vy * sin(theta)
    ff_vy = self.ff_vx * sin(theta) + self.ff_vy * cos(theta)
    ff_vy_rotate = -(self.ff_omega * pi/180) * 12  # D=12跟随距离
    total_ff_vx = ff_vx + abs(ff_vy_rotate * 0.3)
    total_ff_vy = ff_vy + ff_vy_rotate * 1.2
    total_ff_omega = self.ff_omega * 0.0185

    # ===== 反馈：视觉误差PD控制（带死区）=====
    fb_vx = 0 if abs(self.err_x) <= 3 else pid_vx.PID_Direct()
    fb_vy = 0 if abs(self.err_y) <= 3 else pid_vy.PID_Direct()
    fb_turn = 0 if abs(self.err_yaw) <= 1.5 else pid_turn.PID_Direct()

    # ===== 合成 =====
    total_vx = 2.6 * fb_vx + total_ff_vx
    total_vy = 2.6 * fb_vy + total_ff_vy
    total_turn = 2.0 * fb_turn + total_ff_omega
    # 运动学解算到三电机
    self.num_run = kinematics(total_vx, total_vy, total_turn)
