第一章、模型车设计制作的主要思路及技术方案概要
1.1 总体设计思路
本车面向 “蚂蚁搬家”组，采用“主副车协同、惯导结合视觉定位、全向搬运”的总体技术路线。搬运车由主车与副车两辆三轮全向车模组成：主车负责场地内的物品搜索、识别与搬运，副车作为伴随车通过“速度前馈 + 视觉修正”全程跟随主车，形成一主一副的协同搬运编队。
为实现轻量化、微缩化设计，车模平台选用三轮全向底盘，并采用主板、驱动板、车模平台一体化设计。三路直流有刷电机提供全向平移与原地旋转能力，三路增量式编码器提供轮速反馈；主控采用逐飞 RT1021 MicroPython btb核心板；主车摄像头采用 OpenART Plus 实现多目标检测，实时识别场地内的球、沙包、熊三类物品；副车使用OpenART Mini配合红外信标摄像头，追踪安装在主车上的红外灯板。姿态角采集自 IMU660RC 六轴惯性测量单元；主副车之间通过无线串口模块完成通信。
系统围绕三大核心任务展开：(1) 物品搜索识别——通过 OpenART Plus加载神经网络模型检测场地内的球、沙包、熊三类物品；(2) 物品搬运——通过视觉对齐与一系列动作将物品搬运至场地边界（黄胶带）外；(3) 安全避让——避让凸起与红砖障碍物。

1.2 技术方案概要
本节从运动控制、定位与视觉三个方面介绍系统的核心技术方案。
（1）三轮全向底盘速度分解
车模采用三轮全向底盘，三个全向轮呈 120° 对称布置。给定一个确定方向和大小的车体运动速度 (vx, vy, wz)（vx 为横向、vy 为纵向、wz 为旋转角速度），由逆运动学模型将其分解为三路电机目标转速：
w1 =  0.5 * vx - 0.866 * vy + 0.5 * wz
w2 = -1.0 * vx + 0.5 * wz
w3 =  0.5 * vx + 0.866 * vy + 0.5 * wz
其中 0.866 = √3/2 为 120° 布置的投影系数。三路转速合成即可实现平面内任意方向的平移与原地旋转；若某一路转速超过上限，则三路按同一比例缩放，保证运动方向不变。
（2）轮速闭环
速度分解得到的是三路目标转速，还需确保每个轮子实际追踪目标转速。系统为每个电机配置独立的 PID 速度闭环：在 10ms 定时器中断中读取编码器反馈的实际转速，与目标转速求误差，经 PID 运算（KP=18、KI=1.6）输出 PWM 占空比驱动电机。目标转速变化较大时重置积分，防止积分累积冲掉响应；目标为 0 且实际转速低于死区时自动停转。
（3）编码器里程计
由三路编码器读数经逆运动学反解出车体实际速度：
vx = (w1 + w3 - 2.0*w2) / 3.0
vy = (w3 - w1) / sqrt(3)
wz = 2.0*(w1 + w2 + w3) / 3.0
反解速度经比例系数 ODOM_SCALE 换算为实际毫米速度，再依据 IMU660RC 提供的偏航角旋转到世界坐标系，对时间积分即得到车在世界坐标系下的位移 (position_x, position_y)。该位置供平移控制的目标跟踪、凸起避让与出界判定使用，是本车惯导定位的基础。
（4）视觉伺服靠近物体
搜索发现物品后，主车需靠近并对准物品。系统采用视觉伺服：以摄像头输出的物品画面坐标 (cx, cy) 与设定的目标位置 (TARGET_CX, TARGET_CY) 的偏差为误差，PI 控制横移（cx 偏差 → 车身 vx）与前后（cy 偏差 → 车身 vy），驱动底盘持续逼近，直到物品进入目标位置附近。对齐过程带目标丢失处理（丢帧沿用、旋转搜索、后退搜索）与距离门，防止跳到其他同色物体。
（5）视觉信息获取与副车跟随
主车摄像头（OpenArt Plus）运行 YOLOv3 目标检测模型，实时检测球、沙包、熊三类物品；同时对画面中上区域做红色色块检测得到红色障碍标志，对画面上端左右两个 ROI 做黄色检测得到黄胶带边界标志，结果按定长帧 n,bd,red_flag,rx,ry,label,cx,cy... 经 UART 发送给主车。
副车摄像头（OpenMV Mini）采用灰度图，识别主车车身上两个亮色（红外）标记点，输出两点坐标 x1,y1,x2,y2。副车主控据此计算：两点中点与画面中心的偏差 → 横移/前后修正，两点连线角度 → 旋转修正；叠加主车广播的速度前馈，实现视觉反馈跟随。

第二章、机械部分安装及改造
车模结构：采用三轮全向底盘，车模平台、主板、驱动板一体化，实现极致轻量化和微缩化。三个全向轮呈 120° 对称布置，通过三路电机转速的合成即可实现平面内任意方向平移与原地旋转，无需转向机构即可完成全向运动，结构简单、运动灵活。
主副车结构：主车与副车采用相同的三轮全向底盘与传感器配置。主车安装OpenART Plus以识别物体，副车加装用于跟随的红外摄像头，通过识别安装于主车车身上的红外灯板，计算主车的相对位置与角度，实现视觉跟随。
第三章、电路设计说明
主控采用逐飞 RT1021 MicroPython 核心板，其电路由官方提供，不做说明。其余电路接线说明如下：
电机驱动：三路直流有刷电机由核心板 PWM 接口直接驱动（MOTOR_CONTROLLER），PWM 频率 13kHz，通过 DIR 引脚控制电机转向，duty 控制转速。

编码器：三路增量式编码器（encoder）与电机同轴安装，输出正交脉冲，由核心板定时器（ticker）采集，为 PID 速度闭环与里程计提供反馈。

传感器接口：IMU660RC 与核心板连接，配置为 RC 模式、120Hz 解算速率，INT2 硬件中断自动更新解算数据；OpenArt Plus 摄像头通过 UART（波特率 115200）输出多目标检测结果；逐飞无线串口模块（WIRELESS_UART，波特率 115200）实现主副车之间的速度前馈通信。

第四章、软件设计与任务实现
控制软件采用 MicroPython 编写，运行于逐飞 RT1021 核心板，由主车主程序 user_main_old.py、副车主程序 vice_main_old.py、传感器工具库 tool.py、参数集中管理 params.py、运动控制库 move.py、物品搬运状态机 fsm3.py 六个模块组成。其中 params.py 集中管理所有可调参数（观测点坐标、速度、PID 增益、各类阈值等），修改后烧录即可，无需改动主程序逻辑，极大提高了现场调试效率。
本节按一次完整搬运任务的时间顺序展开：从系统启动标定、出发列搜索、目标发现、靠近对准、搬运推出、途中避让障碍到归位回车库，依次介绍各环节的实现方法，再补充贯穿全程的副车协同，最后给出支撑整条任务链的底层运动与定位控制以及关键的工程决策。

4.1　轮速闭环：PID 速度环
三个全向轮各有一路独立的 PID 速度闭环，使每个轮子的实际转速精确跟随目标转速，这是所有运动控制的基础。速度环在 10ms 定时器中断（ticker）中执行（move.pid_tick），每 10ms 对三路电机各迭代一次。
每个控制周期：读取编码器得到实际轮速 actual，计算误差 error = target − actual，积分项 integral += error（限幅 ±3000 防止积分饱和），微分项 derivative = error − last_error，由 PID 公式输出占空比：
output = KP * error + KI * integral + KD * derivative
输出经限幅（±5000，对应 PWM 满占空比）后写入电机。目标转速为 0 且实际转速低于死区（DEAD_SPEED=3）时自动停转并清零积分，释放电机，避免带载发热。
设定目标转速（speed_ctrl）：上层只需调用 speed_ctrl(motor, target) 即可让某个轮子以目标速度转动；当目标变化较大（超过 50）时自动清零积分与上次误差，防止旧积分冲量造成过冲。编码器极性（ENC_POLARITY）统一为同向。
这样，运动控制层只需给出三个轮子的目标转速，速度环就能保证每个轮子快速、稳定地跟踪到位。
4.2　全向底盘速度分解

图4速度分解示意图

三轮全向底盘由三个呈 120° 对称布置的全向轮组成，通过三路轮速的合成，可实现平面内任意方向、任意大小的平移与原地自旋。要“以一定大小的速度朝一定角度运动”，只需把期望的车体速度分解到三个轮子上。
set_chassis(vx, vy, wz) 完成这一分解。其中 (vx, vy) 是车体系下的平移速度，其大小 |v| = √(vx²+vy²) 即运动速度大小，方向 θ = atan2(vy, vx) 即运动方向；wz 是车体自旋角速度。由正运动学模型解算三路目标轮速：
w1 =  0.5 * vx - 0.866 * vy + 0.5 * wz
w2 = - 1.0 * vx  + 0.5 * wz
w3 =  0.5 * vx + 0.866 * vy + 0.5 * wz
w1,w2,w3分别为车模三个电机的期望转速。
若三路轮速中有任一超过满幅（MAX_DUTY=5000），则按比例整体缩放，保证不饱和时合成速度的方向与比例不变。
解算出的三路目标轮速通过 speed_ctrl 交给速度环驱动，由速度环保证每个轮子实际跟踪到目标值，于是车模就按期望的大小与方向运动。例如令 vy=200、vx=0、wz=0，车沿车头前方以速度 200 直线前进；令 vx=0、vy=0、wz=60，则车原地自旋。
4.3　惯导定位：编码器与偏航角
要知道车在场地上每个点的坐标，需把三个编码器的读数结合偏航角反推出车的位移，即惯性导航/里程计。先由逆运动学把三路编码器读数反解为车体系速度：
vx = (w1 + w3 - 2.0 * w2) / 3.0
vy = (w3 - w1) / sqrt(3)
wz = 2.0 * (w1 + w2 + w3) / 3.0
此处w1,w2,w3为三个电机对应编码器的读数。
编码器读数乘以比例系数 ODOM_SCALE（3.2）换算成实际毫米/秒。此时得到的是车体系速度，还需依据当前偏航角 yaw 旋转到世界坐标系，得到世界系速度：
world_vx = vx_body * cos(yaw) - vy_body * sin(yaw)
world_vy = vx_body * sin(yaw) + vy_body * cos(yaw)
对世界系速度按时间积分，即得到车模在世界坐标系中的位置 (position_x, position_y)，从而确定场地上每个点的坐标，在此基础上，可以将整个赛道变成长3200mm，宽2400mm，车模开机朝向为正北(0°)的惯导定位地图。偏航角 yaw 由 IMU660RC 硬件解算得到。该位置为定点运动、凸起避让、出界判定提供依据。

4.4　基础运动动作的实现
在速度环、速度分解与里程计的基础上，封装三类基础运动动作——平移 move_to、原地旋转 rotate、绕物体旋转 orbit_rotate，上层任务（列搜索、搬运、避障、归位）均通过组合调用这三类动作完成。
平移（move_to）：让车前往世界坐标系中的目标点，是阻塞式位置控制。每帧计算目标点相对当前位置的方向向量 (dx/dist, dy/dist)，再旋转到车体系得到车体平移方向：
body_vx =  wx * cos(yaw) + wy * sin(yaw)
body_vy = -wx * sin(yaw) + wy * cos(yaw)
用 set_chassis(body_vx×speed, body_vy×speed, 0) 驱动底盘，配合速度环向目标推进；当与目标点的距离小于容差 POS_TOLERANCE（5mm）时判定到达并停车。
高速移动时启用软加速/减速（params.SOFT_ENABLE）：起步以 SOFT_START_SPEED（100）缓慢加速到目标速度，接近目标点一定距离后按 SOFT_ACCEL（300mm/s²）减速到 SOFT_MIN_SPEED（80），减少急起急停对车身与物品的冲击。
原地旋转（rotate）：采用 PI 旋转控制器，以偏航角误差为控制量。误差 error = 目标角 − 当前角（按最短角差折算到 ±180°），输出角速度 cmd = KP×error + KI×积分（KP=25、KI=0.1，积分限幅 ±100，最小输出 30），交给 set_chassis 实现原地旋转：
error = wrap_180(target_yaw - current_yaw)
cmd = ROT_KP * error + ROT_KI * integral
set_chassis(0, 0, cmd)   # 原地自旋
rotate 支持绝对旋转（自动走最短路径）与相对旋转（指定顺/逆时针方向）；连续 5 次误差小于 2° 判定稳定停车，超时 5s 保护。
绕物体旋转（orbit_rotate）：搬运时需要绕到物品的推出方向，即绕车外一点（K 点）为轴心做圆周运动。K 点位于车头正前方约 30° 方向，设旋转角速度 wz，由瞬时旋转中心 ICR 的几何关系（vx/vy 与 wz 的比值决定旋转半径与圆心方向）反推出同时叠加的平移速度：
vx = 0.866 * wz
vy = 0.5 * wz
set_chassis(vx, vy, wz)   # 车体自旋 wz，同时绕 K 点弧线平移
这样车体一边自旋、一边绕 K 点做弧线平移，实现绕车外固定点的圆周运动；控制器结构与 rotate 相同（PI + 稳定判定），超时 10s。
4.5　物品搬运思路
搬运是系统的核心任务，由状态机 fsm3.execute_item 统一处理球、沙包、熊三类物品，整体流程为：靠近 → 绕圈 → 二次靠近 → 盲推 → 边界判定。

表 2　物品搬运流程表
靠近（approach）：PI 视觉伺服，以物品画面坐标 (cx, cy) 与目标位置 (TARGET_CX, TARGET_CY) 的偏差为误差，分别控制车体横移 vx 与前后 vy，把车对准物品；对齐过程带目标丢失处理（丢帧沿用/±15° 旋转搜索/后退搜索/超时放弃），并用距离门防止锁定跳到其他同色物体。
绕圈（orbit_rotate）：对齐后绕物品旋转到推出方向。三类物品推出方向不同：球沿北向（0°）、沙包沿西向（90°）、熊沿东向（-90°）。
盲推（blind push）：旋转到推出方向后，保持 yaw 盲推前进，直至检测到黄胶带（frame_bd）或里程计出界，再按物品类型继续推进固定时长（BOUNDARY_PUSH_MS），确保物品完全推出边界。
4.6　红砖与雷区避让
红砖（红色障碍）避让：盲推过程中，若摄像头检测到红色障碍（frame_red_flag=1）即触发避障。根据物品种类与车当前 y 坐标决定绕行方向与绕行目标点：球（北向推出）逆时针绕到西侧（90°）并前推到西侧安全线 DODGE_XMIN；沙包/熊根据自身 y 大于或小于阈值，选择绕到北侧（前推到 DODGE_YMAX）或南侧（前推到 DODGE_YMIN）。
绕行流程：旋转 → 视觉对齐 → 前推到固定坐标 → 转回原推出方向 → 再次对齐，然后继续推出；避障时用 DODGE_FILTER 对对齐坐标做画面过滤，剔除红色障碍被误识别为目标物品的情况，且每件物品至多触发一次避障（DODGE_ONCE），防止反复绕行震荡。
雷区（凸起）避让：雷区以中心坐标 + 边长定义（可多个），采用纯几何检测而非视觉，可靠性高、不受光照影响。系统实现四类检测函数：mine_check_path（线段与雷区矩形相交检测）、mine_check_near（射线与雷区求交，返回沿当前航向直行到雷区边界的距离）、mine_check_inside（判断当前位置是否在雷区内）、mine_clearance（计算横向推出雷区投影范围所需的距离）。
盲推前用 mine_check_near 检测前方是否即将进入雷区（距离小于触发阈值），若进入则绕行：旋转到垂直于推出方向的方位 → 前推出雷区横向投影范围（由 mine_clearance 计算）→ 转回原推出方向继续盲推；若盲推起点已在雷区内，则先垂直推出雷区再继续。
4.7　搬运全流程
主车采用“列搜索搬运”策略，将场地划分为北→南三列，逐列搜索、逐列搬运：
1. 上电后完成 IMU 零位标定，前往 y=0 出发线；
2. 依次前往三列观测点（第 1 列 → 第 2 列 → 第 3 列）；
3. 每列：最短路径旋转到 -90°（朝东），边前进边搜索任意物品，越过搜索阈值（观测点 x + 搜索距离）即本列搜索完毕；
4. 搜索到物品后执行搬运（fsm3.execute_item），推完后按路径记录逆向返回，继续本列搜索；
5. 三列全部搜索完成后归位（退回第 3 列观测点 → (250,0) → (250,-500)）。
前行搜索（_forward_search）：朝东前进，保持航向，持续解析摄像头帧，按 cy 降序（近者优先）选取目标物品，检测到即停止前进进入搬运流程；越过搜索阈值仍未发现则本列搜索结束。
4.8　主副车协同跟随
主副车协同采用“速度前馈 + 视觉 PID 跟随”方案（纯 B 模式）。主车 20ms 定时器持续广播自身底盘速度 (vx, vy, wz)，以 11 字节定长帧发送：
FF | action | v1h v1l | v2h v2l | v3h v3l | v4h v4l | FE
action=0: v1=vx  v2=vy  v3=wz  v4=0   （速度前馈，跟随模式）
副车接收主车速度前馈，叠加视觉 PID 修正实现跟随，融合公式为：
vx = vx_ff * W_F  +  delta_vx * W_V
vy = vy_ff * W_F  +  delta_vy * W_V
uA = wz_ff * WZ_SCALE * W_F  +  delta_uA * W_V
其中 W_F=1.0 为前馈权重，W_V=0.3 为视觉权重。
副车视觉（hongwai.py）：副车摄像头采用灰度模式（GRAYSCALE、QVGA），开启垂直/水平镜像，用灰度阈值 [(155,255)] 在 ROI 区域内查找高亮色块（主车车身上两个高亮/红外标记点），按面积降序取前两个色块，输出 x1,y1,x2,y2,found。当同时检测到两个标记点（found=1）时，由两个标记点连线计算主车相对副车的横向位置误差与连线角度误差，作为视觉 PID 的输入。
视觉 PID 三路修正：横向（SIDE，图像 y 误差 → 横移修正）、前后（FORWARD，图像 x 误差 → 前后修正）、角度（ANGLE，主车连线角度误差 → A 轮旋转修正）。PID 参数随主车速度大小动态切换（低速/中速/高速三档），并在方向反转时清零积分，防止积分饱和。
副车底盘模型：平移采用前一后二全向分解，旋转采用绕 K 点旋转（由 A 轮转速推导 B/C 轮转速），与主车模型略有差异以适应副车摄像头安装方向（摄像头转了 90°：图像 x=车前后，图像 y=车横移）。
4.9　主副车视觉系统与通信
主车与副车各配一个 OpenMV 摄像头：主车摄像头负责目标物品识别、红砖识别与边界黄胶带识别，副车摄像头负责识别主车车身上的红外灯板实现视觉跟随修正。二者均通过 UART 与各自主控通信。
主车摄像头（model_uart6.py）：分辨率 QVGA（320×240）、RGB565 色彩格式，关闭自动白平衡并固定曝光 400us、固定增益，保证不同光照下检测的一致性；一帧内同时输出目标物品、红砖、黄胶带三类信息。
物体识别：加载 YOLOv3 目标检测模型 yolo3_iou_smartcar_final_with_post_processing.tflite，每帧检测球（0）、沙包（1）、熊（2）三类物品，仅保留置信度大于 0.55 的检测框，取检测框中心坐标 (cx, cy) 作为目标位置，供主控视觉伺服与列搜索使用。
红砖识别：在画面上部 ROI（RED_ROI）内用红色色块阈值 find_blobs 查找红色色块，取面积最大者；red_flag=1 表示检测到红砖，rx/ry 为红色色块中心坐标，用于盲推阶段的避障绕行。
边界黄胶带识别：在画面上端左右各取一个 100×100 的 ROI 子区域，分别查找黄色胶带色块，仅当左右两个 ROI 同时命中（roi_hits==2）时才置 boundary_flag=1，避免单侧误判，用于判断物品是否到达场地边界。
主车与主控通信：检测结果通过 UART（115200）以定长帧输出，协议格式为：
n, bd, red_flag, rx, ry, label1, cx1, cy1, label2, cx2, cy2, ... \r\n
其中 n 为物品数量，bd 为黄胶带边界标志（0/1），red_flag 为红砖标志（0/1），rx/ry 为红色色块中心坐标，label 为物品种类，cx/cy 为物品画面中心坐标。主控在 tool.parse_camera 中按行分割处理 UART 粘包，解析出 frame_objects（物品列表）、frame_bd（黄胶带）、frame_red_flag（红砖）、frame_rx/ry 等全局帧快照。
副车摄像头（hongwai.py）：采用灰度模式（GRAYSCALE、QVGA），开启垂直/水平镜像，用灰度阈值 [(155,255)] 在 ROI 区域内查找高亮色块（主车车身上的红外灯板标记点），按面积降序取前两个色块；当同时检测到两个标记点（found=1）时，由两个标记点连线计算主车相对副车的横向位置误差与连线角度误差，作为视觉 PID 的输入，实现红外灯板视觉修正。
副车与主控通信：副车摄像头输出 x1,y1,x2,y2,found（两个标记点的坐标与是否同时命中标志），副车主控据此计算三路视觉 PID 修正量，叠加到主车广播的速度前馈上完成跟随（详见 4.8）。
4.10　工程决策与调试历程
姿态方案选择：初期尝试软件 AHRS（四元数梯度下降）解算姿态，计算量大且调试复杂，最终改用 IMU660RC 硬件解算（INT2 中断自动更新），主控零计算负担，航向稳定。
主副车跟随方案演进：早期采用指令模式（主车发送 move_to 目标点，副车执行），存在握手延迟、跟随滞后的问题；最终改为纯速度前馈模式（action=0），主车直接广播底盘速度，副车以前馈为基础叠加视觉 PID 修正，跟随更连续、更实时。
物品搬运调参：视觉对齐、绕圈、盲推三个阶段相互耦合，将三类物品的推出方向、对齐目标点、绕圈半径、盲推速度等参数全部集中到 params.py 分类管理，逐项整定；对齐过程引入距离门防止跳到同色物体，显著提升搬运成功率。
避障策略：雷区采用几何检测（线段相交、射线求交）而非视觉，可靠性高、不受光照影响；红障采用视觉触发 + 固定坐标绕行，绕行后转回原方向继续推出。避障采用一次性触发（DODGE_ONCE）防止重复绕行震荡。
