# 提问 → 算法推荐 → 代码结构（强制处理流程）

用户用自然语言提问（例如「蚂蚁搬家怎么写软件」「弯道外切怎么改」「给我整套目录」）时，**必须按本流程输出**，不要只给空泛建议。

若用户要**根据比赛题目直接撰写代码**，改走 `FROM_PROBLEM_TO_CODE.md`（本流程仍用于算法与结构，并继续写出模块代码）。

## Step 0 · 从问题抽取槽位

| 槽位 | 如何推断 | 缺了怎么办 |
|------|----------|------------|
| 组别 | 关键词（疯狂电路/轮腿/智慧医疗…） | 先问 1 句确认，或给 2 个候选 |
| 目标 | 搭框架 / 推荐算法 / 改某模块 / 修现象 | 默认「推荐算法 + 整套结构」 |
| 主控/传感 | TC264、STC32、ROS2、摄像头… | 写「假设：…」，并给可替换接口 |
| 约束 | 实时、无NPU、已有工程… | 默认：控制 1–5ms 级，视觉可异步 |

## Step 1 · 推荐算法（必须带 ID）

1. 打开 `../smartcar-ml-optimize/refs/TRACK_ALGORITHM_MAP.md` 取该组默认链  
2. 打开 `../smartcar-ml-optimize/refs/INGESTED_ALGORITHMS.md` 展开每个 ID 的含义  
3. 按用户目标裁剪：必选 / 可选增强 / 不建议上（算力不够时）  
4. 输出表：

| 优先级 | 算法ID | 名称 | 为何选 | 关键参数 | 风险 |
|--------|--------|------|--------|----------|------|

创意组补充默认链：
- 智慧医疗：`V06/VLM→P06/导航→C05/底盘→S01/任务→S03`
- 智慧工厂：`V01/V05→S01(环岛/锥桶/灯)→C01/C02`
- 智慧救援/农场/城市：先感知目标 → 任务 FSM → 底盘；缺资料时用 SOFTWARE_SKELETON

飞檐走壁默认：`P02→C01/C03→S01` + 电磁/吸附安全 `S05`  
走马观碑默认：`V06/V10→P07→S01→C01` + `S03` 新鲜度

## Step 2 · 给出整套代码结构

必须输出三块：

### A. 目录树（可落地）

优先套用 `SOFTWARE_SKELETON.md`，再按组别改名（电磁组可把 `vision` 换成 `inductance` 等）。

### B. 数据流（一句话 + 箭头）

```text
传感器 → 感知(V..) → 规划/状态机(S01/P..) → 控制(C..) → 执行器
                ↘ 日志/遥测
推理(若有) 异步队列 → 只产出 err/目标 + stamp，不进 1ms 环
```

### C. 模块接口表

| 模块文件 | 输入 | 输出 | 周期 |
|----------|------|------|------|

对照仓：打开该组 `../<track>/code_opensource/RECOMMENDED.md` 点名 1 个目录对齐。

## Step 3 · 最小主循环 / 模板

- 从 `CODE_TEMPLATES.md` 选 T1–T8 填到对应模块  
- 主循环骨架用 `SOFTWARE_SKELETON.md`  
- 有用户工程：【原→改→说明→测试】  
- 无用户工程：给出可粘贴 `.h/.c` 或 `.py` 骨架 + 假设接口

## Step 4 · 验证清单

给出 5～8 条可执行测试（上电安全、传感器 raw、低速闭环、状态机空跑、超时停车…）。
