# 硬件与分模块联调

资料常见构成：龙芯板卡、UVC相机、双正交编码器、IMU、DRV8701类直流电机驱动，以及独立无刷风扇电调。出现相同型号不代表PCB、引脚映射、SDK或供电能力相同。焊接、上电和驱动命令以用户实物、原理图及当前授权为准。

## 硬件配置必须落到工程

按 `assets/car-profile.json` 记录来源：板卡丝印/原理图、设备树、SDK头文件、实际测量或报告参考。区分Linux用户态模拟“定时中断”、内核驱动和MCU硬件中断，不能把它们的时序保证混称。

| 模块 | 编码前确认 | 优先定位信号 |
|---|---|---|
| 电源 | 电池范围、各轨电压/峰值电流、共地/隔离、连接器和保险保护 | 主控输入与逻辑轨纹波、复位时刻 |
| H桥/电机 | 预驱型号、PWM频率/极性、DIR、使能、制动/滑行真值表 | PWM、EN、故障脚、母线电压 |
| 编码器 | 接口电平、上拉、A/B相序、轴位、倍频、回绕与清零 | 原始计数、方向、周期与目标轮速 |
| IMU | 精确型号、I2C/SPI、安装轴、量程、ODR、单位、零偏和温漂 | 原始角速度、时间戳与标定状态 |
| 相机 | 输出格式、真实曝光/帧间隔、USB带宽、镜头及安装姿态 | 捕获时间、解码时间、失败帧 |
| ToF | 型号、接口、状态码、视轴、测距范围和超时 | 原始值、状态、最近有效时刻 |
| 风扇/电调 | 电机/桨方向、额定电流、解锁信号和停机值 | 命令、母线电流、电压与轮速扰动 |

## 分模块验证方法

现有用户授权范围内，从只读测量和离线检查开始。实际接线、架空轮驱动或风扇测试需要合适的机械约束与既有实车授权，不把“写代码”解释成可直接启动电机。

1. 检查供电与静态设备枚举；先记录无负载基线，再定位负载启动时的变化。
2. 手动转轮或回放计数，验证方向、每轮有效计数、测速与里程一致性。齿比、倍频或轮径未确定前不标成准确m/s。
3. 静止记录IMU零偏，再按约定方向转动车体，核对轴、正负、单位与积分。低通滤波减少噪声也引入相位延迟。
4. 离线看相机原图与映射；支架松动、弹性变形、曝光过长等不能单靠PID修复。
5. 已授权驱动测试时，以项目定义的受控输出确认正反转、使能和停止真值表，再验证单轮闭环。关闭PWM未必等于驱动彻底禁用，应按驱动电路决定。
6. 最后加入风扇、目标识别和整车负载，检查供电压降、EMI、CPU耗时及振动耦合。

## 常见误读

- DRV8701、DRV8320等型号在报告中可能分别服务有刷行走或无刷电调，不根据名称近似互换。
- 有电流采样ADC不等于运行了电流闭环；仅有FOC称呼也不足以证明闭环FOC实现。
- 多路独立稳压不等于电气隔离，信号缓冲不等于隔离器。未确认拓扑不能宣称隔离性能。
- 总电容需考虑单位、串并联和耐压，不按报告的“法拉电容”名称推断等效容量、瞬态电流或安全电压。
- 全局快门避免行间扫描差异，不保证无运动模糊；高分辨率也不保证ROI可辨识。
- 重心后移、增大风扇功率都不是单调提高稳定性。负载、加减速、接地点和结构刚度要一起分析；不沿用报告中未经证明的重心/翘头因果结论。
- 多风扇不必然更快：增加重量、电流、气流与振动，应比较同一赛道下的轮胎打滑、速度和电源状态。

## 板卡故障排查入口

主控复位：先查电源与驱动/风扇启停对应，再看系统日志、退出原因、过温和看门狗；不要直接加电容掩盖未知原因。
编码器丢数：区分实际脉冲、接口电平、驱动采集、计数器溢出、软件读取与日志抽样。
IMU异常：区分总线失败、采样率不足、单位/轴映射、真实振动、漂移和时间戳停更。
ToF偶发零值：零、未就绪、无效、超量程可能各有语义。沿用旧值必须带年龄并设置失效条件，不能无限保留。
电机保持输出：查状态机之外的写PWM路径、失效快照、线程退出次序，以及驱动使能是否由独立保护切断。37有硬件看门狗/锁存关闭的案例，实施仍须结合用户电路。
