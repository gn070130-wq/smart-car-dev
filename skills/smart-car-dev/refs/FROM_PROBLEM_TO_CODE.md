# 根据比赛题目撰写代码（强制）

用户给出**赛题/任务描述**（官方规则摘要、任务点、场地元素、或「要完成 XXX」）时，必须写出**可落地的涉及代码**，不是只讲思路。

## 输入（有则用，无则假设并写明）

- 组别（竞速/创意）
- 赛题要点：任务顺序、得分点、禁止项、传感器/车模约束
- 主控与传感器（未知则按该组最常见栈假设）
- 是否已有工程（有则【原→改】；无则从零给模块文件）

## 撰写流程

1. **拆题** → 任务列表 / 状态机节点 / 安全约束  
2. **算法** → 走 `QUESTION_TO_ARCHITECTURE.md` + `INGESTED_ALGORITHMS` 选 ID  
3. **结构** → 目录树 + 数据流 + 接口（`SOFTWARE_SKELETON`）  
4. **写码** → 按任务点逐模块给出代码：  
   - 感知、规划/状态机、控制、执行器、通信、主循环  
   - 外设：TOF / 编码器 / 红外灯板 / IMU → `MODULES_BSP.md`、`IMU_INS_PLAYBOOK.md`  
   - 视觉循迹 / 元素 / 电磁 / Stanley·PP → 见 `ALGORITHMS_CODE_INDEX.md`  
   - 套用 `CODE_TEMPLATES.md`（T1–T16）并改成用户语言（C/C++/Python/ROS2）  
5. **对照** → 该组 `RECOMMENDED.md` 开源仓对齐目录命名  
6. **测试** → 与赛题任务点一一对应的检查项  

## 输出格式（必须）

```markdown
## 赛题理解
- 组别 / 任务点 / 假设硬件

## 算法与模块映射
| 赛题任务点 | 算法ID | 模块文件 | 说明 |

## 代码结构（目录树）

## 涉及代码
### 1. 主循环 app/main.c（或 main.py / ROS launch+node）
### 2. 感知 …
### 3. 状态机 …
### 4. 控制 …
### 5. 安全/超时 …
（每个文件：完整可粘贴或清晰接口+核心实现）

## 参数初值与调参顺序

## 按赛题任务的测试清单
```

## 硬约束

- 控制环非阻塞；视觉/推理异步；`stamp` 超时进安全态  
- PWM/速度/舵机限幅；上电默认安全  
- 状态机：进入 / 保持 / 退出条件写清  
- 赛题未写明的细节用「假设」标注，便于用户改  

## 用户可以这样发题

- 「组别：疯狂电路。赛题要点：…（贴规则/任务）。请撰写涉及的全部软件代码。」  
- 「雁过留痕：循迹 + 激光打靶，STC32，按赛题写状态机和控制代码。」  
- 「智慧医疗：根据下列任务点写 ROS2 节点代码：…」
