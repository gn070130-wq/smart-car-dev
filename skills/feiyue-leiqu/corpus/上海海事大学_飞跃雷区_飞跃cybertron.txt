摘  要
本项目面向第二十一届全国大学生智能汽车竞赛“飞跃雷区”任务，构建由空中飞行器和地面麦克纳姆轮小车组成的空地协同系统。飞行器采用飞控主板与后置视觉板双主控协同：飞控主板的 CM7_0 承担状态估计、位置与速度控制、姿态控制、高度控制、双摄仲裁及电机混控，CM7_1 承担前相机视觉、后置板链路接收、显示和调试遥测；后置视觉板的 CM7_1 独立完成后相机采集与识别，并通过 UART3 向飞控主板发送视觉结果和图像。地面小车使用独立 CYT4BB7 主控完成全向运动与任务控制。各板内部通过共享内存协调双核任务，板间通过 UART 链路完成视觉协同与空地协同。
飞行器感知链由 IMU、ToF测距、光流和前后双视觉组成。后置视觉板把后相机图像旋转到统一坐标后输出结构化目标结果；飞控主板依据序号和本地时间判断前后观测的新鲜度，在前、后摄像头之间进行目标所有权仲裁、丢失宽限和坐标锁存，再将统一的信标—小车方向提供给飞行控制与地面小车。小车采用 B 型麦克纳姆轮运动学、四路编码器反馈、轮速 PID、IMU航向估计和任务状态机。系统进一步补入整机实拍、机架与电机产品参数、打印件模型及四类自制PCB正面图。
关键词：飞跃雷区；空地协同；CYT4BB7；视觉跟踪；光流融合；麦克纳姆轮

引言
任务背景与设计目标
“飞跃雷区”系统需要在受限场地内完成空中感知、地面运动和空地协同。当前工程将任务拆分为飞行器自主稳定与目标观测、地面小车全向运动与信标任务、空地信息交换和调试观测四类功能。软件设计强调感知、估计、控制、执行和任务管理分层，便于分别调参并在观测失效时进入受控状态。 本报告的组成与编排按照第二十一届竞赛技术报告要求细则执行[1]。
系统组成与总体数据流
系统由空中飞行器、地面四轮麦克纳姆小车、板间视觉链路、空地数据链和调试观测端组成。飞行器内部包含飞控主板和后置视觉板：后置视觉板负责后相机采集与识别，飞控主板负责前相机处理、后板数据接收、双摄仲裁和飞行闭环。飞控主板通过 UART3 与后置视觉板双向交换视觉结果、图像请求和运行配置，再通过共享内存把视觉结果交给 CM7_0。飞行器与小车通过任务串口交换目标、姿态和动作指令，并分别输出调试遥测。

本系统的技术特点体现在双主控分工、空地协同、分层控制和视觉有效性门控等实现机制。
分层协同架构：飞控板内部将高频闭环与视觉/遥测分配到 CM7_0 和 CM7_1；后置视觉板独立处理后相机；两块飞行器主控通过 UART3 协同并由飞控板统一仲裁。
多源状态融合：将 IMU、ToF、光流和视觉信息分别用于姿态、高度、平面运动和目标相对位置估计。
分层控制与保护：飞行器采用位置—速度—姿态串级控制，小车采用运动学—轮速—航向分层控制，并设置有效性判断、限幅和丢失处理。
空地任务闭环：飞行器提供目标与姿态信息，小车依据任务状态机选择跟踪、转向、后退或安全停止等动作。

机械系统设计
飞行器机械结构

实物装配采用四旋翼布局，并在四个旋翼外侧设置环形防护结构。飞控与供电相关板卡沿机体中轴布置，线束集中连接。参数资料给出的机架外廓尺寸约为303 mm×303 mm，机架质量约195 g；整机起飞重量 740 g。

地面小车机械结构

实物采用 M 车模四轮麦克纳姆轮底盘，四个驱动轮分布于车体四角。电池、主控与通信模块集中布置于车体上层，前部 V 形灯带由独立支架固定，线束沿车体中部汇集。

硬件与电气系统
主控平台、双核与双主控协同
飞控主板、后置视觉板和地面小车工程均基于 CYT4BB7 逐飞开源库平台。飞控主板内部由 CM7_0 承担确定周期的控制与双摄仲裁，CM7_1承担前相机视觉、后置板UART3接收、显示和遥测；后置视觉板当前由 CM7_1 完成后相机采集、识别和链路发送。飞控板内部使用共享数据区交换视觉与控制状态，并另设独立64字节视觉时钟块，避免双核时钟差和缓存行共享造成新鲜度误判。双主控之间则使用带序号、时间戳和CRC32的UART3帧传输结果。

飞行器软件设计
软件总体流程
飞控主板 CM7_0 进入 flight_app_run 主流程，按周期完成传感器更新、状态估计、双摄仲裁、控制器计算和执行器输出；飞控主板 CM7_1 并行完成前相机视觉、后置视觉板 UART3 接收、共享结果发布、显示和WiFi SPI遥测。后置视觉板 CM7_1 独立采集后相机，完成同类目标识别，并向飞控主板发送结构化视觉结果或诊断图像。主链最终把统一后的目标观测转换为位置、速度、姿态和电机控制量。
飞行器软件主循环由 flight_app.c 的固定周期调度驱动。CONTROL_PERIOD_MS 为 5 ms 时，传感器读取、姿态更新、ToF 更新、视觉输入、串级控制和电机输出在同一周期内按“采样—估计—控制—执行”顺序完成；CM7_0 负责实时控制，CM7_1 负责图像/遥测并通过共享结构交换结果。
/* flight_app.c：固定周期控制入口（摘录） */
imu_process_update(CONTROL_DT_S);

flight_attitude_loop_update(&attitude_input, &attitude_output);

flight_altitude_loop_update(&altitude_input, &altitude_output);

惯性姿态估计
系统采用IMU660RB惯性传感器。IMU处理模块对加速度进行低通滤波，对陀螺仪进行零偏扣除、低通和死区处理；横滚角和俯仰角采用加速度倾角与陀螺积分的互补融合，偏航角主要由角速度积分获得。该结构计算量较低，适合高频姿态闭环。
姿态估计先读取 IMU660RB 的加速度和角速度，在机体系与世界坐标系之间完成旋转，再将加速度中的重力分量扣除，供速度/位置预测和姿态环使用。

ToF高度处理与高度控制
高度链对ToF原始测距进行跳变抑制和一阶低通，并结合当前姿态完成垂直方向投影。控制流程支持起飞爬升、目标高度保持和基础油门调整；在测距无效时，可利用垂向加速度进行短时预测并设置保护逻辑，以降低遮挡或异常值导致的突变。代码还保留基础油门自适应与诊断量。
DL1B 的原始距离以毫米输入 tof_update。程序先进行有效性判断和滤波，再按横滚/俯仰投影修正斜距，最后加入传感器相对机体的力臂补偿，形成 tof_control_mm 供高度环使用。
/* tof.c：斜距到垂直控制距离的核心关系 */
roll_projection = cosf(roll_angle_rad);
    // 横滚方向的垂直投影因子 cos(phi)
pitch_projection = cosf(pitch_angle_rad);
    // 俯仰方向的垂直投影因子 cos(theta)
tof_control_mm = (tof_filtered_mm * roll_projection * pitch_projection)
    // 横滚方向的垂直投影因子 cos(phi)
                 + pitch_lever_arm_mm;
    // 代码执行语句

光流解码与平面状态融合
系统采用优象UP-FLOW-LC-302-3C光流模块。该型号由系统采用，并与工程采用的逐飞光流接收接口相对应。模块接收平面光流量和质量信息，利用陀螺角速度补偿机体转动分量，并依据DL1B测得高度进行尺度换算；融合模块维护平面加速度、速度和位置状态，在数据有效时修正估计，在质量不足或数据失效时对相关状态进行衰减。
优象 UP-FLOW-LC-302-3C 的光流观测先换算为机体平面速度，再与 IMU 加速度积分预测进行有效性、时间间隔和质量门控融合；视觉或光流失效时由代码的 leak/guard 分支逐步释放而不是瞬时跳变。

串级控制与电机混控

    // 角速度环输出横滚修正量

控制频率方面，主循环固定为 5 ms（200 Hz）；各子环是否在每个周期执行由其 elapsed/period 条件决定。输出端还包含 motor saturation、slew 和失效保护，保护逻辑优先于正常控制输出。
平面位置环根据目标与估计位置生成期望速度，速度环根据速度误差生成期望加速度或姿态，姿态环再产生横滚和俯仰修正；偏航控制与高度控制分别形成偏航修正和基础油门修正。最终将基础油门与三轴修正量按电机布局混合输出。当前调度关系为主姿态链5 ms更新，速度环20 ms更新，位置环40 ms更新。

B型麦克纳姆轮运动学
运动学模块输入车体纵向速度、横向速度、角速度及方向误差，根据车体长度、宽度、轮半径和辊子布置计算四个车轮目标角速度。本文采用B型轮组方向。模块还对各轮目标进行统一限幅，防止运动合成后某一路超过执行能力。
运动指令首先由方向角和速度得到车体平面分量 vx、vy，再按 B 型麦克纳姆轮符号矩阵分解到四个编码器目标。方向角为 θ 时，vx=v cosθ，vy=v sinθ。
/* pid.c：方向—速度到四轮目标 */
float rad = direction_deg * 3.1415926f / 180.0f;
    // 代码执行语句
float vx = speed * cosf(rad);
    // 代码执行语句
float vy = speed * sinf(rad);
    // 代码执行语句
encoder_target_lf = target_limit(vx + vy);
    // 左前轮目标（转向时为正）
encoder_target_rf = target_limit(vx - vy);
    // 右前轮目标（转向时取反）
encoder_target_lb = target_limit(vx - vy);
    // 左后轮目标（转向时为正）
encoder_target_rb = target_limit(vx + vy);
    // 右后轮目标（转向时取反）
因此可写成 [ωLF,ωRF,ωLB,ωRB]ᵀ = [[1,1],[1,-1],[1,-1],[1,1]]·[vx,vy]ᵀ（当前函数还对每个目标做 ±2000 限幅）。旋转指令在 motion_control.c 中以左右轮相反符号叠加到四轮目标。
运动学计算采用实际装配几何参数：车轮半径为31.5 mm，轮距为120 mm，轴距为198 mm；底盘外廓尺寸为282 mm×210 mm×63 mm。
四轮轮速闭环与里程估计
四个车轮分别配置PID控制与编码器反馈。控制器根据目标轮速和测量轮速计算PWM输出，并包含输出饱和与积分约束思路；编码器增量还用于车轮里程和车体运动量估计。四轮独立闭环可补偿电机、负载和地面附着差异。
PIT 周期中先 Get_Encoder() 读取四轮增量，再依次调用四个轮 PID；计算完成后清零计数，保证下一周期只统计新的脉冲。
/* cm7_0_isr.c：四轮闭环介入点 */

left_B_motor_pid(encoder_target_lb);
    // 左后轮速度 PID，输出驱动占空比
right_B_motor_pid(encoder_target_rb);
    // 右后轮速度 PID，输出驱动占空比
left_F_motor_pid(encoder_target_lf);
    // 左前轮速度 PID，输出驱动占空比
right_F_motor_pid(encoder_target_rf);

encoder_clear_count(ENCODER_LB); /* 其余三轮同理 */

if(abs_err > w->deadband) w->error_sum += w->error;

IMU导航与航向控制
IMU导航模块完成陀螺仪/加速度计校准，维护偏航、横滚、俯仰以及水平速度、位置和累计距离。航向控制器支持静止和运动状态下不同的增益组合，并叠加积分补偿、陀螺阻尼和输出限幅；系统可记录初始航向作为基准，也可切换为仅显示而不介入控制的模式。
imu_nav_update() 更新航向角、角速度和零偏状态，motion_control.c 再用航向误差生成旋转修正，叠加到四轮目标；航向保持开启/关闭由状态机控制。

精确转向控制
转向模块支持绝对角度和相对角度目标，根据剩余角度规划转速与制动区，并通过容差、稳定计数和超时条件判定完成。该模块与航向估计配合，可用于任务状态切换前的姿态对准。
转向任务由目标角和当前 yaw 计算误差，先以固定速度生成方向目标，再由四轮编码器闭环执行；turn_control_is_done() 负责结束判定，完成后清零四轮目标。
/* main_cm7_0.c：精确转向目标 */
encoder_target_lf = rot_delta;
    // 左前轮目标（转向时为正）
encoder_target_lb = rot_delta;
    // 左后轮目标（转向时为正）
encoder_target_rf = -rot_delta;
    // 右前轮目标（转向时取反）
encoder_target_rb = -rot_delta;
    // 右后轮目标（转向时取反）
if(turn_control_is_done()) {
    // 判断目标角是否已达到
    encoder_target_lf = encoder_target_rf = 0;
    // 左前轮目标（转向时为正）
    encoder_target_lb = encoder_target_rb = 0;
    // 左后轮目标（转向时为正）

该路径与普通平移路径分开，避免在转向完成前被新的遥控平移量覆盖。
信标任务状态机与安全回退
任务层支持手动模拟和真实信标两种数据来源。在真实模式下，小车读取飞行器提供的信标、小车相对坐标和偏航信息，判断目标是否可见，并依据目标方向、距离特征和飞机/小车姿态选择前进、后退、平移或转向动作。代码还维护已观察、目标锁定、冷却计数和熄灭信标数量等状态。
信标任务状态机在“搜索—对准—接近—刹车/回退—完成”之间切换。对准阶段使用 beacon_err_x/beacon_err_y 和 beacon_angle，接近阶段调用 mecanum_typeb_set_encoder_target()，超时或信标失效则停止目标或进入回退。

当目标数据过期或丢失时，状态机不会无限沿用旧数据，而是结合最近观测、丢失计时和回退策略降低速度、搜索、后退或停止；运行显示模块对串口帧设置新鲜度判断，避免过期目标持续驱动。

系统联调与实验
联调环境与观测量
自制图像采集上位机与算法调试闭环
飞行器参数整定使用逐飞助手观察姿态、位置、速度和控制量；视觉算法调试采用自制图像采集上位机。上位机接收 CM7_1 发送的 CYIM v3 数据帧，按飞行器按键请求保存双摄灰度图，并同步保存高度、姿态、视觉阈值、曝光和增益等元数据。该方式使图像样本与飞行状态在同一采样时刻对应。

图 6.1 自制图像采集上位机界面与回传数据
图像回传服务在 CM7_1 上异步执行：前摄输出 188×120 灰度区域，后摄灰度区域经一次 180° 旋转后拼接为 188×240 图像；数据帧由 136 字节小端头、45120 字节 GRAY8 载荷和 CRC32 组成。服务端校验魔数、版本、长度和 CRC 后再保存 BMP，采集过程不阻塞 CM7_0 的 5 ms 飞行控制循环。
调试闭环为：飞行器按键请求采集→上位机接收图像及高度、姿态元数据→分析连通域、面积、包围盒、亮度密度和车体 V 字特征→调整阈值与目标评分参数→在 Image_Process_Frame、Image_Car_Score_V2 和 Image_Beacon_Score_V2 中回放验证。该流程支撑车体随动、信标识别及信标—小车相对位置计算。
空地通信与板间通信采用有线串口链路交换视觉结果、姿态和任务状态，能够支撑车辆跟随和信标任务闭环。
当前工程提供屏幕状态显示、UART运行数据和WiFi SPI遥测，可观察姿态、高度、目标误差、双摄当前所有者、目标代数、结果年龄、UART3 CRC错误/序号缺口、控制输出、编码器和电机占空比等变量。调试应按“单相机—后置板链路—双摄坐标统一—仲裁切换—单闭环—空地协同”的顺序逐级验证。

结论
工作总结
当前代码已形成飞控主板、后置视觉板和地面小车三块CYT4BB7控制板的协同工程。飞控板内部使用双核共享内存，飞控板与后置视觉板通过UART3交换带CRC和序号的前后视觉协同数据，飞行器与小车通过任务串口交换目标与动作状态。飞行器现已具备前后视觉独立处理、统一时基判龄、目标所有权仲裁、丢失宽限、坐标锁存与切换平滑，并将统一结果接入原有姿态、高度、光流与串级控制；小车保持麦克纳姆运动学、轮速闭环、航向控制和任务状态机。
系统已完成飞行器与地面小车的软硬件协同实现，形成了双主控视觉处理、姿态与高度控制、麦克纳姆轮全向运动、信标识别和车机协同任务链路。
存在问题与改进方向
优化飞行器与小车的结构布局，降低线束干扰和载荷变化对控制稳定性的影响。
完善飞控主板与后置视觉板的数据同步、超时处理和异常恢复，提高复杂环境下的视觉连续性。
继续优化定高、定点、视觉跟踪和小车全向运动控制参数，提升不同高度和速度下的动态响应。
增加不同信标位置、不同车速和不同光照条件下的任务测试，增强系统对场地变化的适应能力。
改进目标评分与多传感器融合策略，减少遮挡、反光和短时丢帧造成的误判。

static float distance_to_car(float target_x, float target_y)
{
    float dx = target_x - state.car_x_latched;
    float dy = target_y - state.car_y_latched;
    return sqrtf((dx * dx) + (dy * dy));
}
static uint8 beacon_materially_closer(float current_x,
                                      float current_y,
                                      float candidate_x,
                                      float candidate_y)
{
    float current_distance = distance_to_car(current_x, current_y);
    float candidate_distance = distance_to_car(candidate_x, candidate_y);
    return (uint8)(((current_distance - candidate_distance) >=
                    IMAGE_BEACON_SWITCH_MIN_GAIN_PX) &&
                   (candidate_distance <=
                    (current_distance * IMAGE_BEACON_SWITCH_MAX_DISTANCE_RATIO)));
}

void flight_position_loop_update_vision(const flight_position_vision_input_t *input,
                                        flight_position_vision_output_t *output)
{
    float vision_move_angle_deg;
    float dir_inv_norm;
    vision_move_angle_deg = pid_axis_update_pi(&vision_move_hold_pid,
                                               input->error_norm_px,
                                               CONTROL_DT_S);
    dir_inv_norm = 1.0f / input->error_norm_px;
    vision_move_angle_deg = func_limit_ab(vision_move_angle_deg, 0.0f, input->angle_limit_deg);
    vision_move_angle_deg *= input->brake_scale * input->track_scale;
    output->roll_deg = (-input->error_x_px * dir_inv_norm) * vision_move_angle_deg;
    output->pitch_deg = (input->error_y_px * dir_inv_norm) * vision_move_angle_deg;
    if(input->freeze_integrator)
    {
        vision_int_x *= VISION_HOLD_FLOW_I_DECAY;
        vision_int_y *= VISION_HOLD_FLOW_I_DECAY;
    }
    else
    {
        vision_int_x += (-input->error_x_px) * VISION_HOLD_VECTOR_KI * CONTROL_DT_S;
        vision_int_y += (input->error_y_px) * VISION_HOLD_VECTOR_KI * CONTROL_DT_S;
    }
    vision_int_x = func_limit_ab(vision_int_x, -VISION_HOLD_I_LIMIT_DEG, VISION_HOLD_I_LIMIT_DEG);
    vision_int_y = func_limit_ab(vision_int_y, -VISION_HOLD_I_LIMIT_DEG, VISION_HOLD_I_LIMIT_DEG);
    output->roll_deg += vision_int_x;
    output->pitch_deg += vision_int_y;
    output->integrator_roll_deg = vision_int_x;
    output->integrator_pitch_deg = vision_int_y;
}

    output->pitch_error_deg = input->pitch_target_deg - input->pitch_angle_deg;

                                                      output->roll_error_deg,

                                                       output->pitch_error_deg,

    output->roll_rate_target_dps = roll_rate_target_prev_dps + roll_rate_delta;
    roll_rate_target_prev_dps = output->roll_rate_target_dps;
    pitch_rate_delta = output->pitch_rate_target_dps - pitch_rate_target_prev_dps;
    pitch_rate_delta = func_limit_ab(pitch_rate_delta, -rate_target_slew_limit, rate_target_slew_limit);
    output->pitch_rate_target_dps = pitch_rate_target_prev_dps + pitch_rate_delta;
    pitch_rate_target_prev_dps = output->pitch_rate_target_dps;
    output->roll_rate_error_dps = output->roll_rate_target_dps - input->roll_rate_dps;
    output->pitch_rate_error_dps = output->pitch_rate_target_dps - input->pitch_rate_dps;

            if(beacon_x > 0.0f && beacon_y > 0.0f)  quadrant = 1;

            if(beacon_x < 0.0f && beacon_y < 0.0f)  quadrant = 3;
            if(beacon_x > 0.0f && beacon_y < 0.0f)  quadrant = 4;
            if(quadrant != 0)
            {
                char qd_buf[16];
                int qd_len = snprintf(qd_buf, sizeof(qd_buf), "QD:%d\r\n", quadrant);
