第一章  引言
1.1 任务背景
全国大学生智能汽车竞赛是以智能车辆为载体的科技创新性竞赛，参赛队伍需要在竞赛规则限定的时间内，围绕赛道环境感知、车辆运动控制与任务决策完成一套完整的车模系统[1]。本参赛队（华北电力大学 Samaritan 队）参加飞跃雷区组别，任务形态为空地协同：无人机在空中持续跟踪安装有 V 形指示灯（下称 V 灯）的小车，识别场地内按固定频率闪烁的信标灯，并将两者在图像中的相对几何关系下发给小车，引导小车自主运动并以车身压亮信标灯（下称压灯）。
该任务的核心难点在于：其一，感知与执行分布在两个运动平台上，视觉解算、链路传输与底盘执行之间存在固有时延与数据抖动；其二，无人机悬停跟踪与小车高速压灯分属两个动力学差异极大的被控对象，需要在同一套信息流内协同；其三，50 Hz 视觉帧率与像素级量化噪声叠加，近距离时方向噪声被显著放大，直接用于控制会造成压灯轨迹摆动。
1.2 系统设计目标
针对上述难点，本队确定如下设计目标：（1）无人机在 800 Hz 控制频率下实现稳定的姿态与高度控制，为下视视觉提供平稳的成像平台；（2）以像素坐标系的 VB 向量作为全系统统一中间表示，避免跨平台世界坐标标定；（3）主、副双摄像头协同，在主摄像头近距离丢失信标时由副摄像头恢复引导信息，提高任务连续性；（4）小车端以方向调理、视觉超前外推与平滑速度规划为核心，实现顺滑连续的压灯轨迹；（5）全链路失效保护，任何一环异常都能安全制动。
1.3 报告结构安排
第二章给出系统总体方案与信息流设计；第三章介绍机械结构、传感器选型安装与电路设计；第四章详细阐述双核软件架构与各控制、估计算法；第五章说明开发工具与分级调试过程，并给出典型问题的定位与解决；第六章汇总系统技术参数。报告正文之后附参考文献、附录 A（系统照片）与附录 B（程序源代码摘录）。

无人机主控板两核通过共享内存中的无锁双缓冲（seqlock）结构交换数据：CM7_1 将视觉结果（V/B 坐标、置信度、帧号）发布到固定地址，CM7_0 读取并回传高度、速度与航向反馈，配合数据缓存（DCache）维护与内存屏障保证一致性。该结构避免了跨核队列与锁开销，单次交换耗时为微秒级。
2.2 工作流程
系统完整任务流程如图 2.2 所示。上电后无人机完成传感器自检与陀螺零偏标定，起飞并定高至 1000 mm；主摄像头锁定 V 灯后进入空中跟踪模式，在图像参考点附近维持车体居中。信标灯由主摄像头通过闪烁相位自相关完成 B1/B2/B3 编号识别；当主摄像头丢失信标超过 120 ms 时，副摄像头按请求解算 V→B 相对向量并映射回主摄像素系，融合生成虚拟信标 B1。最终 B 与 V 坐标随视觉帧以 A4 帧下发，小车据此完成接近、压灯、滑行与制动。

2.4 方案论证
像素向量方案与世界坐标方案的对比：若在无人机端换算世界坐标，需要精确的相机外参、高度与姿态联合解算，误差链条长且标定工作量大；直接传输 V、B 像素坐标，小车端只需 B−V 即可获得方向与相对距离信息，带宽开销仅 8 字节。本队选择像素向量方案，并在小车端引入偏航角补偿旋转，消除无人机航向误差带来的坐标系偏差。
单摄与双摄方案的对比：主摄像头在接近信标过程中会因视场角与遮挡丢失信标，此时单摄方案只能制动停车；增加副摄像头板后，只要副摄能同时看到 V 灯与信标，即可恢复虚拟信标，任务连续性显著提高。副摄链路采用请求-应答而非连续上报，一是避免常态占用 UART6 带宽，二是天然形成主摄优先、副摄兜底的仲裁结构。

第四章  软件设计与控制算法
4.1 双核软件架构与跨核通信
三个工程均为裸机前后台结构：时间关键任务由定时器中断置标志，主循环消费标志执行，另设循环超载检测。无人机主控板上，CM7_0 以 800 Hz PIT 中断执行姿态与高度控制，CM7_1 主循环逐帧执行视觉识别与三条 UART 链路服务。两核间以 64 字节定长包通过共享内存无锁交换：写方以递增序号+两副本写入，读方校验序号一致性，读侧执行缓存失效（DCache invalidate）、写侧执行缓存清理（clean）并插入 DMB 屏障。该设计在读多写少场景下无需关中断，最坏情况读方重试一次。

4.5 视觉识别算法
视觉输入为 188×120 灰度图像，50 FPS。V 灯检测采用多级判决链（图 4.2）：候选区域先经严格几何形态判决（STRICT_V），失败后依次尝试短时记忆恢复（RECOVERY）与亮度兜底（BRIGHT_FALLBACK），全部失败则进入 PURE_HOLD 保持上一拍输出且不作为控制观测，避免闪烁边沿污染控制环。V 灯与信标均输出千分制置信度，控制侧仅采用置信度不低于 360 的观测[5]。

图4.2  视觉识别多级判决流程
信标灯以约 10 Hz 频率闪烁，算法对候选做闪烁自相关分析与稳定编号，区分 B1/B2/B3 并输出各自置信度；编号在遮挡恢复后保持连续，供任务层判断压灯目标。
4.6 主副摄像头协同与虚拟信标融合
副摄像头平时不主动上报。当主摄 V 灯可用而信标丢失时，飞控经 UART6 发送 B1 请求；副摄在自己视野内同时找到 V 灯与信标后，将 V→B 相对向量按两相机安装角度旋转 90° 映射回主摄像素系（mapped_dx=−raw_dy、mapped_dy=raw_dx），随 B2 帧返回。飞控侧融合逻辑为：主摄信标连续丢失超过 120 ms，且副摄链路在线、返回帧连续两次向量变化不超过 32 像素，则生成虚拟信标 B1 = V + mapped。主摄信标恢复后立即回到主摄优先。该链路以标志位自描述有效性，任何一环不满足即整体降级为无信标，不产生错误观测。
4.7 空中跟踪控制

4.9 安全机制与失效保护
全系统失效保护按就近原则分级：无人机侧，姿态量非有限值立即停桨锁存，光流失效或高度越界撤销水平估计并退出跟踪，视觉丢失按帧数计数制动；链路侧，C5 应答 200 ms 超时判定小车离线，A4 停发后小车 120 ms 判定链路失效；小车侧，模式仲裁优先级为 MISSION_STOP 锁存 > 调度超载 > A4 自动 > 手动遥控 > 航向保持，SAFE_STOP 输出硬零，IMU 未就绪或锁定状态下一切输出被禁能。遥控通道任何时刻可以接管并触发任务终止。

第五章  开发工具与调试过程
5.1 开发环境与工程管理
三个工程统一使用 IAR Embedded Workbench（9.2）开发，基于逐飞（SeekFree）CYT4BB7 库函数 V3.9.3，无操作系统。每个仓库提供 build_all_cores.bat 一键双核构建脚本，交付标准为 CM7_0、CM7_1 两目标均 0 错误 0 警告。三个仓库以 Git 独立管理，协议改动同步修改收发两端实现与文档，并以标签记录实机验证状态，构建通过与实机验收严格区分。

5.3 典型问题与解决过程
问题一：无人机引导下车走走停停。现象为小车在接近过程中周期性急停再起步。定位过程：抓取 A4 帧发现 V/B 标志位在 50 Hz 帧间频繁闪断，而小车原逻辑将标志无效立即映射为硬制动（1.8 m/s²），视觉单帧丢失即触发。解决：引入 COAST 状态与 300 ms V 丢失滑行宽限，链路新鲜时按最后方向惯性滑行等恢复，超时才制动；该宽限大于单帧闪断的典型时长、又远小于正常链路的失效判定窗口，既吸收抖动也不掩盖真实失联，实测轨迹连续性显著改善。
问题二：近距离压灯方向摆动。现象为距离小于约 15 像素时小车方向反复小幅摆动。分析：VB 向量的像素量化噪声固定约 1 像素，方位角噪声随距离减小被放大，与距离成反比。解决：方向冻结区（5 像素内完全冻结直线压灯）+ 距离加权低通（5～15 像素线性恢复信任）+ 每帧方位角 4° 硬限幅，三级措施叠加后近场轨迹为受控直线。
问题三：副摄数据显示但小车不动。现象为无人机屏幕出现主副摄融合的紫色连线（说明虚拟信标已生成，调试界面见图 A-1），小车仍无运动。定位：虚拟信标 B1 = V + 映射向量必须落在 188×120 图像坐标范围内，否则 A4 组帧侧按协议清掉信标有效标志；而屏幕连线使用裁剪到边界后的端点绘制，视觉上始终存在。该问题确认为协议边界与显示端语义不一致的结构性约束，改进方向（允许越界信标或直接传递相对向量）已列入后续工作。

赛道检测方面：图像分辨率 188×120、帧率 50 FPS，目标中心以整数像素输出，量化精度 ±1 像素；信标闪烁识别基于 10 Hz 自相关，编号在遮挡恢复后保持。控制方面：无人机姿态环 800 Hz，高度观测约 100 Hz，光流速度经 EKF 与 800 Hz 预测融合；小车导航与底盘环 200 Hz（5 ms 周期，含超载检测）；A4 帧随视觉帧 50 Hz 下发，C5 应答与在线判定窗口 200 ms。坐标传递全程为像素域，端到端附加时延主要为视觉曝光与传输（数十毫秒级），由小车端 60 ms 超前外推部分补偿。

结论
本报告给出了一套基于三块 CYT4BB7 双核核心板的空地协同压灯系统。系统以像素域 VB 向量为统一中间表示，无人机端实现 800 Hz 级联姿态控制、Mahony 姿态解算与三通道 EKF 状态估计，视觉端以多级判决链保证 50 Hz 观测的鲁棒性，并以主副摄融合扩展信标可见范围；小车端以五状态导航状态机为核心，配合方向调理、视觉超前外推与 smoothstep 速度规划实现顺滑压灯，底盘以轮速 PID+摩擦前馈与航向保持环保证跟踪精度。全链路按就近原则分级失效保护，并通过桌面联调、台架、系留与实机分级验收控制风险。
后续工作包括：其一，改进信标越界时的协议语义（允许图像外信标或直接传递相对向量），消除虚拟信标受限导致引导中断的结构性约束；其二，按分级验收流程逐步开放更高追车速度档，统一无人机跟踪限速与小车速度档的匹配；其三，完成 Stage B/C 实机验收并补充实测整机参数。

float PID_Calculate(PID_t *pid, float target, float measure) {
    if(!isfinite(target) || !isfinite(measure))
    {
        control_reset_pid(pid);
        return 0.0f;
    }
 
    // 1. 计算误差
    pid->error = target - measure;
    
    // 2. 计算积分项 (带限幅)
    pid->integral += pid->error;
    if (pid->integral > pid->max_integral) pid->integral = pid->max_integral;
    else if (pid->integral < -pid->max_integral) pid->integral = -pid->max_integral;
    
    // 3. 计算微分项
    float derivative = pid->error - pid->last_error;
    
    // 4. 计算总输出
    float output = (pid->kp * pid->error) + 
                   (pid->ki * pid->integral) + 
                   (pid->kd * derivative);
                   
    // 5. 更新上一次误差
    pid->last_error = pid->error;
    
    // 6. 输出限幅
    if (output > pid->max_output) output = pid->max_output;
    else if (output < -pid->max_output) output = -pid->max_output;
    
    return output;
}

static void chase_shape_target(void)
{
    float delta_x = s_chase.raw_target_x_mm_s - s_chase.shaped_target_x_mm_s;

    if(g_nav.prev_vb_valid && (frame_dt_s >= 0.010f) && (frame_dt_s <= 0.200f))
    {
        float lead_right = car_nav_clamp_abs(
            ((right_px - g_nav.prev_right_px) / frame_dt_s) * HW_DRONE_LEAD_S,
            HW_DRONE_LEAD_MAX_PX);
        float lead_forward = car_nav_clamp_abs(
            ((forward_px - g_nav.prev_forward_px) / frame_dt_s) * HW_DRONE_LEAD_S,
            HW_DRONE_LEAD_MAX_PX);
        /* 历史帧必须保存未外推的补偿向量，避免超前量逐帧叠加。 */
        car_nav_store_prev_vb(right_px, forward_px);
        right_px += lead_right;
        forward_px += lead_forward;
    }
    else
    {
        car_nav_store_prev_vb(right_px, forward_px);
    }
    g_nav.frame_gap_ms = 0U;
 
    norm = sqrtf((right_px * right_px) + (forward_px * forward_px));
    if(norm < 0.5f) return 0U;
    g_nav.last_distance_px = norm;
 
    right_px /= norm;
    forward_px /= norm;
    if(g_nav.dir_valid == 0U)
    {
        g_nav.dir_right = right_px;
        g_nav.dir_forward = forward_px;
        g_nav.dir_valid = 1U;
    }
    else if(norm >= HW_DRONE_DIR_FREEZE_PX)
    {
        /*
         * 近距方向调理：距离越近越不信任新方向（像素噪声引起的方位角摆动
         * 随距离减小被放大），FREEZE 内完全冻结方向直线压灯；
         * 每帧方位角变化量再受 STEP_MAX 硬限幅。
         */
        const float trust = car_nav_clamp(
            (norm - HW_DRONE_DIR_FREEZE_PX) /
            (HW_DRONE_DIR_TRUST_FULL_PX - HW_DRONE_DIR_FREEZE_PX), 0.0f, 1.0f);
        const float alpha = HW_DRONE_TRACK_FILTER_ALPHA * trust;
        const float step_max = HW_DRONE_DIR_STEP_MAX_DEG * (CAR_NAV_PI / 180.0f);
        float cand_right = g_nav.dir_right + alpha * (right_px - g_nav.dir_right);
        float cand_forward = g_nav.dir_forward + alpha * (forward_px - g_nav.dir_forward);
        float cand_norm = sqrtf((cand_right * cand_right) +
                                (cand_forward * cand_forward));
        if(cand_norm > 0.0001f)
        {
            const float az_cur = atan2f(g_nav.dir_right, g_nav.dir_forward);
            float az_delta;
 
            cand_right /= cand_norm;
            cand_forward /= cand_norm;
            az_delta = car_nav_wrap_pi(atan2f(cand_right, cand_forward) - az_cur);
            if(fabsf(az_delta) > step_max)
            {
                const float az_target = az_cur +
                    ((az_delta > 0.0f) ? step_max : -step_max);
                cand_forward = cosf(az_target);
                cand_right = sinf(az_target);
            }
            g_nav.dir_right = cand_right;
            g_nav.dir_forward = cand_forward;
        }
    }
    /* norm < FREEZE_PX：方向冻结，仅刷新距离。 */
    if(distance_px != 0) *distance_px = norm;
    return 1U;
}
