第一章 引言
1.1.课题背景
全国大学生智能汽车竞赛是一项融合自动控制、机器视觉、嵌入式系统、传感器、电机驱动和机械设计的综合性工程实践竞赛。参赛队伍需要自主完成机械结构、电路系统、控制软件和运动算法设计，并使作品在规定场地内稳定完成比赛任务。
第21届全国大学生智能汽车竞赛“飞跃雷区”组由一台可悬停飞行器和一辆自制地面车模组成。系统需要在室内平面光标赛道中识别亮起的信标灯，控制飞行器和车模协同运动，最终由车模到达信标位置并完成灭灯。
由于车模上不允许安装用于检测信标的环境感知传感器，信标检测主要由飞行器上的摄像头完成。因此，飞行器不仅负责稳定飞行，还承担场地观察、目标识别、视觉定位和信息传输等任务；地面车模则根据飞机端发送的位置误差完成全向移动。
本队采用双摄像头视觉方案。一路摄像头由CYT4BB7处理，另一路由CYT2BL3处理。双摄像头具有不同的有效观察范围，可提高信标距离发生变化时的识别连续性。CYT4BB7采用双核架构，其中CM7_1负责本地摄像头处理、第二路视觉数据接收、双摄来源选择以及信标灯和车模灯板识别；CM7_0负责飞行器姿态、高度、速度和位置控制，并向地面车模发送视觉误差。
视觉系统同时识别亮起的信标灯和车模上的灯板，并根据灯板方向计算信标相对于车模的纵向误差和横向误差。小车接收到误差后，通过位置外环、航向保持环、麦克纳姆轮运动学分解和四路电机速度内环，逐步移动到信标位置并完成灭灯。

1.2.赛题任务与规则约束
比赛开始后，飞行器起飞并利用机载双摄像头搜索亮起的信标灯，同时识别车模上的灯板。视觉系统根据目标位置生成飞行器控制所需的视觉信息，并计算车模灯板与信标灯之间的纵向误差和横向误差。
飞机端将车模误差和数据有效标志发送给小车。小车对通信数据进行解析和校验，再由纵向、横向位置控制器计算车体速度。随后，控制器根据麦克纳姆轮运动学关系得到四轮目标速度，并利用编码器反馈和四路速度闭环调节电机输出，使车模到达信标位置并通过机械接触完成灭灯。
根据飞跃雷区组相关规则，参赛作品还需满足以下要求：
飞行器应能放置在50×50cm范围内；
地面车模应能放置在30×30cm范围内；
飞行器保护网罩孔眼应小于4cm，乒乓球不能穿过；
飞行器与车模之间的线缆长度不得超过1.5m；
飞行器不安装独立电池，由车模通过线缆供电；
信标检测传感器应安装在飞行器上，车模不得直接检测信标。
作品的尺寸、质量、网罩孔径和线缆长度将在第三章中结合实物测量结果进行说明。
1.3.系统主要技术难点
1.3.1.双摄目标识别
信标与摄像头之间的距离变化较大，单摄像头难以同时兼顾远距离识别能力和近距离观察范围。本系统利用两台摄像头扩展有效识别范围，并通过连续帧判断和来源保持策略减少摄像头切换造成的误差跳变。
1.3.2.信标和车模灯板识别
信标灯和车模灯板均表现为图像中的高亮区域，容易受到背景反光和图像噪声影响。系统需要根据灰度、面积、形状和连续帧位置等特征区分两类目标，并利用主成分分析方法计算灯板方向。
1.3.3.双摄坐标统一
两台摄像头的安装方向和成像参数不同，其坐标不能直接混合使用。系统对第二路摄像头的数据进行方向转换，并且只在信标和灯板来自同一标定摄像头时计算车模误差，避免跨摄像头坐标直接相减。
1.3.4.双核实时协同
图像处理计算量较大，飞行控制又具有严格的实时性要求。本系统使用CM7_1处理视觉任务，使用CM7_0完成飞行控制，并通过共享内存和帧序号传递视觉结果，从而降低图像处理对控制周期的影响。
1.3.5.飞行器串级控制
飞行器需要同时完成高度、水平位置、速度、姿态角和角速度控制。本系统使用视觉、光流、TOF和IMU构成多级串级控制，使飞行器在目标识别过程中保持稳定运动。
1.3.6.通信与安全保护
视觉数据需要经过双摄通信、双核共享内存和飞机—车模通信链路。系统通过帧头、校验、有效标志和帧序号判断数据状态。小车超过150 ms未收到有效数据时，立即停止电机并清除PID历史状态，避免失联后继续运动。
1.3.7.车模全向控制
车模采用四轮麦克纳姆轮结构。控制器将视觉纵向、横向误差转换为车体速度，并结合航向修正量完成四轮速度分解，再利用编码器反馈控制四个电机，实现二维位置跟随
第二章 系统总体方案
2.1.系统设计目标
根据飞跃雷区组的比赛任务，本系统需要利用安装在飞行器上的摄像头检测亮起的信标灯和车模灯板，获得飞行器、车模与信标之间的相对位置信息。在此基础上，控制飞行器完成空中定位，并引导地面车模运动至信标位置，最终通过机械接触完成灭灯。
系统设计需要满足以下目标：
在不同目标距离下稳定识别信标灯和车模灯板；
保证图像处理和飞行控制任务互不干扰；
实现飞行器水平位置、姿态和高度的闭环控制；
准确计算车模相对于信标的纵向和横向误差；
实现飞机端与小车端之间的实时通信；
控制麦克纳姆轮车模完成前后、横向及斜向运动；
在视觉失效或通信中断时及时停止运动；
满足飞行器、车模、保护网罩和线缆等规则限制。
2.2.系统总体组成
本系统主要由飞行器平台、双摄视觉系统、飞行控制系统、地面车模和通信供电系统五部分组成，其功能如表2.1所示。

表2.1 系统总体组成表

2.2.1.飞行器平台
飞行器平台由四旋翼机架、保护网罩、四个无刷电机、双摄像头、CYT4BB7双核控制器、IMU、TOF、光流模块以及供电通信线缆组成。
飞行器承担以下任务：
搭载双摄像头观察比赛场地；
获取信标灯和车模灯板位置；
根据视觉信息进行水平位置调整；
根据TOF信息维持飞行高度；
根据IMU和光流信息完成姿态及速度闭环；
将车模相对信标的误差发送给地面车模。
2.2.2.双摄视觉系统
双摄视觉系统由两台安装在飞行器上的摄像头组成。一路摄像头直接连接飞机端CYT4BB7，由CM7_1完成图像处理；另一路摄像头由独立的CYT2BL3处理，识别结果通过UART发送给CYT4BB7。
采用双摄方案的主要目的是扩大有效识别范围。当信标距离较远时，系统选择远距离识别效果较好的摄像头；目标距离变化或当前摄像头识别失效时，系统根据连续帧有效性切换视觉来源，从而提高信标识别的连续性。
双摄系统不直接对两路坐标求平均，而是对信标灯和车模灯板分别选择有效来源。只有信标灯和车模灯板来自同一台经过标定的摄像头时，才计算车模相对信标的位置误差。
2.2.3.地面车模
地面车模采用四轮麦克纳姆轮结构，主要由车模控制器、车载灯板、四个驱动电机、四路编码器、IMU、电机驱动板和灭灯机械结构组成。
车载灯板为飞行器视觉系统提供车模位置和方向标志。车模控制器接收飞机端发送的纵向误差、横向误差和有效标志，通过位置外环、航向保持环和四轮速度内环控制车模移动。
麦克纳姆轮底盘能够在保持车头方向基本不变的情况下完成前后、横向和斜向运动，适合根据二维视觉误差直接修正车模位置。
2.2.4.通信与供电系统
系统包含两条主要通信链路：
CYT2BL3与飞机端CYT4BB7之间的双摄通信链路；
飞机端CYT4BB7与地面车模之间的控制通信链路。
CYT2BL3通过串口发送第二路摄像头的信标位置、灯板位置、灯板方向和有效标志。飞机端CM7_1完成双摄选择后，通过共享内存将最终视觉结果传递给CM7_0。CM7_0对车模误差进行处理后，通过串口发送给地面车模。
飞行器不使用独立电池，由车模通过长度不超过1.5 m的线缆供电。线缆同时需要满足供电电流、通信可靠性和运动柔性要求。

CM7_1每完成一帧图像处理后，将信标误差、灯板位置、车模误差、有效标志和摄像头来源写入共享内存，并更新视觉帧序号。CM7_0读取共享数据时，根据帧序号判断视觉结果是否更新。两个核心分别进行数据缓存清理和失效操作，保证共享数据的一致性。
该方案将图像处理与飞行控制分离，避免图像处理时间波动影响飞控周期。
2.4.系统工作流程
系统运行流程分为初始化、目标识别、飞行器定位、车模跟随和灭灯五个阶段。
2.4.1.系统初始化
系统上电后，分别初始化双摄像头、CYT2BL3、CYT4BB7双核、IMU、TOF、光流、串口、车模编码器和电机驱动。飞行器完成传感器零偏校准，车模清零位置环和速度环状态。
2.4.2.信标与车模识别
两路摄像头采集场地图像，分别提取亮起的信标灯和车模灯板。视觉算法对候选区域的亮度、面积、形状和连续帧位置进行判断，并使用PCA方法估计车模灯板方向。
CYT4BB7根据两路数据的有效性和连续性选择最终视觉来源。若视觉数据失效，则不向控制系统输出有效运动误差。
2.4.3.飞行器位置控制
视觉系统计算目标相对于摄像头参考位置的误差。飞机端将视觉误差输入水平位置环，并结合光流速度、IMU姿态和TOF高度信息，生成四个旋翼电机的控制量，使飞行器保持稳定并调整水平位置。
2.4.4.车模位置控制
视觉系统计算信标灯与车模灯板之间的坐标差，并根据灯板方向将其投影为车模坐标系下的纵向误差和横向误差：

2.6.安全与异常处理
双摄数据长时间未更新时，将对应摄像头标记为失效；
信标和灯板未同时有效时，不生成车模运动误差；
飞行控制核使用帧序号判断视觉数据是否为新数据；
飞行器未解锁或高度、姿态异常时限制相关控制输出；
飞机端通过有效标志控制车模是否采用当前误差；
小车超过150 ms未收到有效数据时立即停车；
停车后清零位置环、航向环和四轮速度环历史状态；
电机控制量设置输出限幅，避免异常指令产生过大驱动力。

第三章 机械结构设计
3.1.机械系统设计要求
飞跃雷区参赛系统由四旋翼飞行器和地面车模组成。机械结构既要满足比赛规则中的尺寸和安全限制，也要保证双摄视觉、飞行控制、车模运动和灭灯任务能够稳定完成。
本系统机械设计主要考虑以下要求：
飞行器最大外廓不超过50cm×50cm
地面车模最大外廓不超过30cm×30cm
飞行器保护网罩孔眼尺寸小于4cm
飞行器与车模之间的线缆长度不超过1.5m
飞行器不安装摄像头云台，摄像头采用固定安装方式；
双摄像头视场应满足远、近距离目标识别要求；
线缆不得与旋翼、车轮和灭灯机构发生干涉；
车模灯板应便于机载摄像头识别；
车模应能可靠接触并触发信标灯。
在满足上述要求的基础上，机械结构还应具有质量分布均匀、连接可靠、拆装方便和易于维护等特点。
3.2.飞行器总体结构
本系统采用四旋翼飞行器作为空中平台。飞行器主要由机架、四个电机、旋翼、保护网罩、双摄像头支架、主控板、IMU、TOF、光流模块以及供电通信线缆组成，其整体结构如图3.1所示。



图3.1 飞行器总体结构
飞行器机架采用碳纤维制作，主要承载电机、控制板、摄像头和传感器。各部件尽量沿机体中心对称布置，以减小重心偏移对姿态控制的影响。主控板和传感器通过螺钉、尼龙柱和减振垫固定，避免飞行过程中发生松动。
飞行器重心应尽量接近四个电机组成区域的几何中心。双摄像头、保护网罩和线缆固定件安装完成后，需要重新检查重心位置。若重心出现明显偏移，可通过调整控制板、传感器或线缆固定点的位置进行修正。

3.3.旋翼保护网罩
为避免高速旋转的桨叶与人员、线缆或场地设施发生接触，飞行器外部安装了旋翼保护网罩。保护网罩采用碳纤维制作。
保护网罩设计需要同时满足安全性、强度和轻量化要求。网罩孔眼尺寸应小于4cm，并保证乒乓球无法从孔眼中穿过。网罩外缘应覆盖旋翼运动范围，在发生轻微碰撞时能够先于桨叶接触障碍物。

3.4.双摄像头安装结构
本系统在飞行器上安装两台摄像头。其中，一台摄像头连接CYT4BB7视觉处理核心，另一台摄像头连接CYT2BL3视觉处理节点。双摄结构主要用于扩大系统的有效识别范围，提高信标距离变化时的视觉连续性。
根据比赛规则，飞行器上不允许增加摄像头云台，因此两台摄像头均采用固定支架安装。
两台摄像头的安装需要考虑以下因素：
镜头视场应覆盖飞行器下方主要比赛区域；
摄像头视场之间应具有一定重叠区域；
飞行器机架和保护网罩不得遮挡镜头；
两个摄像头的安装方向必须固定且便于标定；
支架应具有足够刚度，避免飞行振动造成视角变化；
摄像头位置变化后应重新进行坐标方向和识别参数校准。

3.5.飞行器传感器安装
飞行器上安装了IMU、TOF和光流等传感器。不同传感器对机械安装位置有不同要求。
IMU应安装在靠近飞行器重心的位置，并保证芯片坐标轴与飞行器坐标轴方向一致。为降低电机和机架振动对测量结果的影响，IMU控制板通过减振垫进行固定。

光流模块安装在飞行器底部，镜头朝向地面，用于测量飞行器的水平运动速度。光流镜头周围应保留足够视野，并避免线缆摆动进入其观察区域。

3.6.供电与通信线缆结构
根据比赛规则，飞行器不使用独立电池，而是由地面车模通过线缆供电。本系统的线缆同时包含供电线、通信线，从车模端固定点连接至飞行器端固定点。
线缆结构设计需要兼顾载流能力和柔韧性。线径过小会造成较大压降，影响飞行器电机输出；线缆过粗或过硬则会增加飞行器负载，并在运动过程中产生较大的牵引力。
本队使用线缆，实际长度为1.2m。
线缆走线应避开以下区域：
飞行器旋翼和保护网罩边缘；

车模麦克纳姆轮；
编码器和电机传动部分；

5.1.双摄视觉系统总体流程
本系统使用两台安装在飞行器上的摄像头获取场地图像。其中一路摄像头由飞机端CYT4BB7的CM7_1核心处理，另一路摄像头由CYT2BL3独立处理。CYT2BL3将识别结果通过UART发送至CM7_1，CM7_1对两路结果进行有效性判断和来源选择，并将最终视觉信息发布给CM7_0飞行控制核心。

5.3.信标灯与车模灯板识别

车模灯板由多个LED组成。程序提取灯板区域后，计算灯板中心，并采用主成分分析方法获得灯板主方向。灯板中心用于确定车模位置，主方向用于建立车模自身的前后和左右坐标轴。

双摄选择的基本原则如下：
当前摄像头识别有效时，优先保持原来源；
新来源需要连续有效一定帧数后才允许切换；
CYT2BL3数据长时间未更新时，将其判定为失效；
CYT2BL3坐标经过方向转换后统一到CYT4BB7坐标系；
信标和灯板必须来自同一摄像头才能计算车模误差。

5.6.3.异常保护
系统在视觉和通信链路中设置了多级保护：
第二路摄像头数据长时间未更新时，将其标记为失效；
双核共享数据帧序号不更新时，飞控停止使用旧视觉误差；
信标或灯板识别失效时，不输出有效车模误差；
通信帧校验失败时，车模不更新控制数据；
车模超过150 ms未收到有效数据时，清零目标速度和PID状态并停止电机。

6.10.启停与异常保护
为保证空地系统运行安全，控制程序设置了以下保护措施：
飞行器未解锁时清除飞行控制状态；
视觉帧连续未更新时复位飞行位置环；
TOF或光流数据无效时停止使用对应反馈；
信标或车模灯板识别无效时，不发送有效车模误差；

模式切换时清除旧目标速度，防止沿用上一次控制输出。

第八章 结论与展望
本文围绕第21届全国大学生智能汽车竞赛飞跃雷区组的任务要求，设计并实现了一套由四旋翼飞行器、双摄视觉系统和麦克纳姆轮车模组成的空地协同系统。系统利用安装在飞行器上的摄像头识别亮起的信标灯和车模LED灯板，计算目标位置信息，并控制飞行器和地面车模协同完成信标搜索、位置调整及灭灯任务。
针对单摄像头难以兼顾不同识别距离的问题，本系统采用CYT4BB7与CYT2BL3组成的双摄视觉方案。CYT2BL3独立处理一路摄像头图像，并通过UART将识别结果发送至飞机端CYT4BB7；CYT4BB7的CM7_1核心处理本地摄像头图像，完成信标灯、车模灯板及灯板方向识别，并根据两路结果的有效性和连续性选择最终视觉来源。
视觉系统根据车模灯板的主方向，将信标灯与灯板之间的图像坐标差转换为车模坐标系下的纵向误差和横向误差。最终视觉结果通过共享内存传递给CYT4BB7的CM7_0核心。CM7_0负责飞行器姿态、高度、光流速度和视觉位置控制，并通过串口将车模误差及有效标志发送给地面车模。
地面车模采用四轮麦克纳姆轮结构。车模端根据接收到的纵向误差和横向误差，通过位置外环计算车体平移速度，并利用IMU航向信息进行方向修正。随后，控制器通过麦克纳姆轮运动学分解得到四轮目标速度，再利用编码器反馈和四路增量式PI控制器调节电机输出，使车模移动至信标位置并通过机械接触完成灭灯。
系统软件采用分层、模块化设计。飞机端将视觉处理与飞行控制分配至两个核心，以减小图像处理对飞控实时性的影响；车模端将通信接收、位置外环和速度内环设置为不同周期任务。系统还通过连续帧确认、视觉有效标志、数据校验、共享数据帧序号和通信超时停车等措施，提高了视觉与通信链路的可靠性。
本系统仍存在一定不足。双摄视觉容易受到场地光照、背景反光、目标遮挡及飞行器姿态变化的影响，在远距离、图像边缘或摄像头切换过程中可能出现识别不稳定和误差跳变。两路摄像头尚未完成统一空间标定，目前只有信标与车模灯板来自同一摄像头时才能可靠计算相对误差。此外，保护网罩、供电线缆、气流和机体振动会影响飞行稳定性；麦克纳姆轮受地面摩擦、电机差异和低速死区影响，可能出现运动偏斜或末端灭灯定位不准。系统还包含双摄、核间及飞机—车模等多条通信链路，其时延和异常保护仍需进一步验证。
后续将对两台摄像头进行统一标定，并结合目标距离、识别置信度和环境光照优化摄像头选择、曝光及二值化参数，同时利用IMU姿态信息补偿飞行倾斜造成的视觉误差。控制方面将继续整定飞行器水平位置环及速度环，完善飞行器状态与车模启停的协调逻辑，并优化车模低速控制和末端接近策略。机械方面将改进灭灯机构和线缆固定结构，减小线缆牵引并提高灭灯成功率；同时建立视觉、飞控、通信和车模状态的同步记录机制，为后续参数调整与故障分析提供依据。
本文完成了飞跃雷区空地协同系统的总体方案、机械结构、硬件电路、双摄视觉、通信协议以及运动控制算法设计。系统利用双摄像头识别信标灯和车模灯板，通过CYT4BB7双核完成视觉处理和飞行控制，并由地面麦克纳姆轮车模根据视觉误差移动至信标位置完成灭灯。
测试结果表明，该方案具备完成比赛任务的基本能力。后续仍需围绕双摄标定、视觉抗干扰、飞行器二维定位、空地协调、车模低速控制和灭灯结构开展进一步优化，以提高系统在复杂比赛环境中的稳定性、准确性和任务成功率。

车模位置外环、航向环和麦克纳姆轮分解
void car_control_position_outer_loop_10ms(void)
{
float target_vx_cmd = 0.0f;
float target_vy_cmd = 0.0f;
float control_err_fwd = err_fwd;
float control_err_lat = err_lat;
float near_cross_dir_fwd = 0.0f;
float near_cross_dir_lat = 0.0f;
uint8 fwd_near_gain_active = 0;
uint8 lat_near_gain_active = 0;
uint8 near_cross_ready = 0;
// IMU 原始航向角先回绕，再加上安装零偏。
current_yaw_angle = wrap_angle_deg(imu660rc_yaw) - 2.5f;
if(!follow_enable || !car_comm_is_connected())
{
reset_all_motion_state();
return;
}
// yaw 闭环：以累计后的目标航向角为参考，输出转向速度指令。
vz_cmd = yaw_pid_calculate(&yaw_hold_pid, current_yaw_angle);

// 视觉模式下，近距离误差先乘 NEG 再进入位置 PID。
// err_fwd/err_lat 保留原始通信误差，control_err_fwd/control_err_lat 只作为控制输入。
if(g_error_source == ERROR_SOURCE_VISION && car_error_valid)
{
// 记录最近几帧有效误差，供后面的“低速穿越”判断稳定方向。
// 这里保留的是原始视觉误差，不改动 NEG 放大逻辑。
near_cross_history_push(err_fwd, err_lat);
control_err_fwd=apply_near_error_gain(err_fwd, NEAR_ERROR_GAIN_RANGE_FWD, &fwd_near_gain_active);
control_err_lat=apply_near_error_gain(err_lat, NEAR_ERROR_GAIN_RANGE_LAT, &lat_near_gain_active);
fwd_min_push_active = fwd_near_gain_active;
lat_min_push_active = lat_near_gain_active;
}
else
{
fwd_min_push_active = 0;
lat_min_push_active = 0;
}
fwd_min_push_cmd = fwd_min_push_active ? control_err_fwd : 0.0f;
lat_min_push_cmd = lat_min_push_active ? control_err_lat : 0.0f;
// 位置外环：误差 PID 输出作为车体前后/左右速度目标。
target_vx_cmd = OUTER_SPEED_SCALE * pos_pid_calculate(&fwd_error_pid, control_err_fwd);
target_vy_cmd = OUTER_SPEED_SCALE * pos_pid_calculate(&lat_error_pid, control_err_lat);
// 当视觉误差已经变成 0 或无效时，使用最近几帧有效误差的平均方向做低速穿越。
// 这样不会卡在“最后一帧抖动”上，仍然能带着很低的速度把信标灯压灭。
if(g_error_source == ERROR_SOURCE_VISION)
{
near_cross_ready = near_cross_history_get(&near_cross_dir_fwd, &near_cross_dir_lat);
if(!car_error_valid && near_cross_ready)
{
float near_cross_dir_sum = fabs(near_cross_dir_fwd) + fabs(near_cross_dir_lat);
if(near_cross_dir_sum <= VISION_ERROR_EPSILON)
{
near_cross_dir_fwd = 1.0f;
near_cross_dir_lat = 0.0f;
near_cross_dir_sum = 1.0f;
}

target_vx_cmd = NEAR_CROSS_MIN_SPEED * near_cross_dir_fwd / near_cross_dir_sum;
target_vy_cmd = NEAR_CROSS_MIN_SPEED * near_cross_dir_lat / near_cross_dir_sum;
fwd_min_push_active = 1;
lat_min_push_active = 1;
fwd_min_push_cmd = target_vx_cmd;
lat_min_push_cmd = target_vy_cmd;
}
}
vx_cmd = target_vx_cmd;
vy_cmd = target_vy_cmd;
// 麦克纳姆轮分解：vx / vy / vz 转成四轮目标速度。
left1_target_speed  = (int16)clamp_float_value(target_vx_cmd + target_vy_cmd + vz_cmd, -wheel_speed_max, wheel_speed_max);
left2_target_speed  = (int16)clamp_float_value(target_vx_cmd - target_vy_cmd + vz_cmd, -wheel_speed_max, wheel_speed_max);
right1_target_speed = (int16)clamp_float_value(target_vx_cmd - target_vy_cmd - vz_cmd, -wheel_speed_max, wheel_speed_max);
right2_target_speed = (int16)clamp_float_value(target_vx_cmd + target_vy_cmd - vz_cmd, -wheel_speed_max, wheel_speed_max);     
left1_speed_pid.target = left1_target_speed;
left2_speed_pid.target = left2_target_speed;
right1_speed_pid.target = right1_target_speed;
right2_speed_pid.target = right2_target_speed;
}

// 位置式PID计算（添加ki≠0判断，避免除零错误）
float pos_pid_calculate(pos_pid_controller_t *pid, float current_value) {
    float error = pid->target - current_value;
    
    // 积分项限幅，防止积分饱和
    if (fabs(error) < 50 && pid->ki != 0) {  // 误差小且ki≠0时累加积分
        pid->integral += error;
        // 积分限幅
        if (pid->integral > pid->output_max / pid->ki) {
            pid->integral = pid->output_max / pid->ki;
        } else if (pid->integral < pid->output_min / pid->ki) {
            pid->integral = pid->output_min / pid->ki;
        }
    }
    
    // 位置式PID计算
    pid->output = pid->kp * error + 
                 pid->ki * pid->integral + 
                 pid->kd * (error - pid->last_error);
    
    // 输出限幅
    if (pid->output > pid->output_max) {
        pid->output = pid->output_max;
    } else if (pid->output < pid->output_min) {
        pid->output = pid->output_min;
    }
    
    // 更新误差历史
    pid->prev_error = pid->last_error;
    pid->last_error = error;
    
    return pid->output;
}

// 增量式PID初始化
void inc_pid_init(inc_pid_controller_t *pid, float kp, float ki, float kd, 
                 float output_max, float output_min) {
    pid->kp = kp;
    pid->ki = ki;
    pid->kd = kd;
    pid->target = 0;
    pid->last_error = 0;
    pid->prev_error = 0;
    pid->output = 0;
    pid->output_max = output_max;
    pid->output_min = output_min;
}

// 增量式PID计算
float inc_pid_calculate(inc_pid_controller_t *pid, float current_value) {
    float error = pid->target - current_value;
    
    // 增量式PID计算
    float delta_output = pid->kp * (error - pid->last_error) + 
                        pid->ki * error + 
                        pid->kd * (error - 2 * pid->last_error + pid->prev_error);
    
    // 累加输出
    pid->output += delta_output;
    
    // 输出限幅
    if (pid->output > pid->output_max) {
        pid->output = pid->output_max;
    } else if (pid->output < pid->output_min) {
        pid->output = pid->output_min;
    }
    
    // 更新误差历史
    pid->prev_error = pid->last_error;
    pid->last_error = error;
    
    return pid->output;
}
