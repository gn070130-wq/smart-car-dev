第一章 引言
1.1 竞赛背景与课题意义
全国大学生智能汽车竞赛是一项面向大学生工程实践能力、系统设计能力和创新能力培养的综合性科技竞赛。参赛队伍需要围绕赛题要求完成机械结构、硬件电路、嵌入式软件、传感器信息处理以及控制算法等多个环节的设计与调试。飞跃雷区组别在传统智能车竞速与控制任务的基础上，引入了空中平台感知和地面平台执行的协同要求，对参赛系统的稳定性、实时性和模块协作能力提出了更高要求。
本组别的核心特点是环境感知传感器安装在悬停无人机上，地面车不能依靠自身视觉直接搜索信标目标。无人机需要在空中提供稳定俯视视野，识别信标灯与地面执行车的位置关系，并将目标误差分别传递给飞控系统和地面车控制系统。地面车则需要根据无人机端给出的误差信息完成快速接近、姿态修正和压灯动作。因此，该赛题本质上是一个由空中视觉、无人机飞控、地面全向移动平台和有线通信共同组成的空地协同控制系统。
1.2 系统设计目标
针对飞跃雷区组别任务要求，本系统以“空中稳定感知、地面快速执行、空地可靠协同”为总体设计目标。无人机端采用CYT4BB7核心板作为主控平台，完成飞控控制和图像处理任务；地面执行平台采用四轮麦克纳姆轮小车结构，通过CYT4BB7核心板实现串口指令接收、运动学解算和电机速度闭环控制。
在执行机构方面，地面车采用DRV8701E构成四路有刷直流电机驱动，通过编码器反馈实现四轮速度闭环；无人机采用基于STC32G12K128-48PIN的四合一无刷电调板，将四个单电调功能集成在一块电路板上，以减小线束复杂度并提高整机集成度。系统通过无人机端视觉识别信标和底车位置，生成飞控修正量和底车运动目标，从而完成无人机悬停、目标识别、底车接近和压灯执行的完整任务链路。
1.3 技术路线概述
本系统的软件结构采用双平台分工方式。无人机端CYT4BB7的CM7_0核心负责飞控闭环控制，包括IMU姿态更新、ToF定高、角度环与角速度环PID控制、电机混控以及四路电调PWM输出；CM7_1核心负责MT9V03X图像采集与识别处理，包括车灯高亮区域提取、信标阈值分割、连通域筛选、目标跟踪、时域平滑和坐标变换。视觉处理结果一方面通过共享内存传递给飞控核心，用于修正无人机水平位置；另一方面通过UART串口发送给地面车，用于指导底车运动。
地面车端CYT4BB7主要运行在CM7_0核心上。系统通过UART6接收无人机发送的[position,x,y]格式目标指令，解析后更新目标坐标。主循环根据目标坐标计算平移方向和速度，并通过四轮麦克纳姆轮运动学解算得到四个车轮的目标速度。2ms周期中断中，系统读取四路编码器反馈，执行四路增量式PID速度闭环，并通过方向引脚和PWM信号驱动DRV8701E电机驱动器，从而实现地面执行车的全向移动控制。
1.4 本报告内容安排
本报告围绕飞跃雷区组空地协同智能车系统的设计与实现展开。第二章介绍系统总体方案与任务分解；第三章说明无人机和地面车机械结构设计；第四章介绍主板、驱动板、电调板及供电通信电路；第五章阐述无人机飞控系统设计；第六章介绍空中视觉识别算法；第七章分析地面麦克纳姆轮小车控制系统；第八章说明空地协同通信和比赛任务流程；第九章总结系统调试方法和实验结果；第十章对整体方案进行总结，并提出后续改进方向。

第二章 系统总体方案设计
2.1 赛题约束与系统需求
飞跃雷区组别要求系统在雷区环境中完成空中识别、地面接近和压灯执行等任务。与传统单车视觉方案不同，本系统的主要感知视角来自无人机端，地面车不再承担大范围搜索信标的视觉任务，而是根据无人机给出的目标偏差进行运动控制。因此，系统设计的重点不只是单个模块的性能，而是无人机悬停稳定性、视觉识别实时性、串口通信可靠性和底车执行精度之间的协调。
根据比赛任务特点，本系统需要满足以下基本需求：无人机能够在任务区域上方稳定悬停并保持俯视视野；视觉程序能够识别信标灯和底车位置，给出可用于控制的坐标误差；底车能够接收无人机端发送的目标信息，并通过四轮麦克纳姆轮实现前后、左右及姿态修正；空地之间的通信链路需要在运动和振动条件下保持稳定，避免因线缆晃动、串口丢包或启动时序不一致导致任务中断。
2.2 系统总体任务分解
本系统采用空中平台和地面平台分工协作的总体方案。无人机端以CYT4BB7核心板为主控，利用双核心结构分别承担飞控闭环和图像处理任务。图像处理核心完成MT9V03X图像采集、信标灯识别、底车定位以及目标偏差计算；飞控核心完成IMU姿态解算、定高控制、姿态环与角速度环PID控制，并将混控结果输出给四合一无刷电调板。
地面执行平台采用四轮麦克纳姆轮小车结构，同样以CYT4BB7作为主控。底车接收无人机端发送的[position, x, y]格式目标指令后，将目标偏差转换为底盘坐标系下的期望平移速度和角速度，再通过麦克纳姆轮逆运动学分配到四个车轮。电机驱动部分采用DRV8701E方案，通过方向信号和PWM信号控制四路有刷直流电机，并结合编码器反馈完成速度闭环。
2.3 系统总体架构与数据流
系统总体架构如图2.1所示。无人机视觉核心从摄像头图像中提取信标与底车的相对位置，并将偏差信息提供给飞控核心和底车控制核心。飞控核心根据视觉偏差、IMU姿态和高度信息调整无人机悬停状态，使相机视野尽可能稳定；底车控制核心根据视觉端给出的目标坐标执行全向运动，从而完成接近目标和压灯动作。
图2.1 空地协同智能车系统总体架构图
在通信连接上，无人机端使用P4.0、P4.1串口引脚，底车端使用P3.0、P3.1串口引脚，二者通过约1.5m线缆连接。该长度能够满足无人机悬停高度和底车活动范围的基本要求，同时保持有线通信较低的延迟和较强的抗干扰能力。系统调试时需要重点固定线缆走向，避免线缆受螺旋桨气流、车体运动或压灯动作影响。
2.4 系统启动与任务流程
本系统采用无人机和底车同步启动的方式。比赛开始前，无人机与底车完成供电、串口连接和任务状态初始化；启动后，无人机进入悬停与视觉识别状态，底车等待有效目标指令。当视觉核心识别到信标灯和底车位置后，系统计算底车相对于目标的偏差，并通过串口发送给底车。底车收到有效坐标后执行运动控制，逐步减小位置误差，并在接近目标区域后完成姿态修正和压灯动作。
从控制逻辑上看，任务流程可划分为初始化、空中稳定、目标识别、底车接近、近距离校正和压灯执行六个阶段。初始化阶段主要保证各主控、传感器和电机驱动状态正常；空中稳定阶段保证无人机高度和姿态满足视觉识别要求；目标识别阶段输出信标与底车的相对坐标；底车接近阶段利用麦克纳姆轮全向移动优势快速减小偏差；近距离校正阶段降低速度并提高定位精度；压灯执行阶段完成最终动作并等待下一次任务状态更新。
2.5 本章小结
本章从赛题需求出发，确定了本系统的总体设计思路：以无人机作为空中视觉感知平台，以四轮麦克纳姆轮小车作为地面执行平台，通过CYT4BB7双平台控制、四合一无刷电调、DRV8701E电机驱动和有线串口通信构成空地协同系统。后续章节将分别从机械安装、硬件电路、飞控算法、视觉识别和底车控制等方面展开说明。

第三章 机械结构设计与安装
3.1 机械结构设计目标
飞跃雷区组别的机械结构同时服务于空中感知和地面执行两个平台。无人机部分需要在有限尺寸内完成螺旋桨保护、摄像头下视安装、飞控与电调固定以及线缆引出；底车部分需要在约30cm×30cm的面积范围内完成四轮麦克纳姆轮驱动、电池放置、主控与驱动板固定以及压灯接触。由于无人机与底车之间存在串口线和电源线连接，机械结构还需要兼顾线缆下垂、随动和防拉扯，避免线缆对无人机姿态和底车运动造成明显干扰。
本系统在结构设计上遵循三个原则：一是保证核心感知器件安装位置稳定，使摄像头能够获得连续可靠的俯视图像；二是使电路板、电池和驱动模块分层布置，便于散热、接线和检修；三是通过支柱、硅胶柱、减震胶带和线缆固定结构降低振动与拉扯对控制系统的影响。
3.2 无人机机械结构设计
无人机采用四旋翼保护罩式机架，整体尺寸约为30cm。该类机架在四个螺旋桨外侧设置保护圈，能够在调试和比赛过程中降低桨叶碰撞风险，同时保护罩结构也便于在有限空间内进行起飞、悬停和姿态调整。机架中心区域作为主要承载平台，用于安装电调板、主控板以及摄像头固定结构。

图3.1 无人机整体结构图
无人机端不单独搭载电池，整机电源由底车通过电源线提供。这样可以减轻无人机自重，降低悬停功率需求，并减少机体上方的质量集中。由于供电线缆会随无人机和底车相对运动而产生扰动，因此电源线与串口线统一从无人机中心区域引出，使线缆作用点尽量靠近机体质心，减小线缆拉力对横滚和俯仰姿态的附加力矩。
3.3 无人机板卡与摄像头安装
无人机的摄像头安装在机架前方正下方，用于获取赛场信标灯和底车位置的俯视图像。摄像头安装位置靠近机架前部，有利于避开中心板卡和线缆遮挡，同时保持较稳定的观测方向。安装时需要保证摄像头光轴基本朝向地面，减少图像倾斜造成的坐标误差；在后续视觉标定中，可根据实际安装偏差进行坐标补偿。
机架上方采用分层安装方式：电调板位于机架上层，主板安装在电调板上方。四合一电调板靠近四个电机输出端，能够缩短电机相线连接距离，降低线束复杂度；CYT4BB7主板位于更上层，便于连接调试接口、传感器接口和空地通信接口。两层板卡之间通过支柱固定，并在关键位置使用硅胶柱和减震胶带进行隔振处理，以减小电机振动传递到飞控主板和摄像头的幅度。

图3.2 无人机主控板与电调板安装位置图
3.4 地面麦克纳姆轮底车结构设计
地面执行平台采用四轮麦克纳姆轮底盘，整车面积约为30cm×30cm，车体周围安装挡板。挡板一方面能够保护内部主板、驱动板和电池，另一方面也使车身外轮廓更明确，便于无人机视觉识别底车位置。底车最终压灯动作采用车身直接接触信标灯的方式完成，因此车体外形需要兼顾保护和接触可靠性，避免局部结构过高或过窄导致压灯不稳定。
四个麦克纳姆轮采用X型安装方式。该安装方式能够通过四轮速度组合实现前后、左右和旋转运动，使底车在接近信标灯时无需大角度转向即可完成横向修正。相比普通差速底盘，麦克纳姆轮底盘更适合无人机视觉给出二维位置偏差后的快速校正任务，能够降低路径规划复杂度，提高近距离对准效率。
3.5 底车板卡、电池与驱动安装
底车主板安装在车体中间位置，并通过支柱架高固定。主板居中布置能够缩短与两侧驱动板、串口接口和调试接口之间的连接距离，同时有利于保持整车重心分布均衡。电池放置在主板下方，利用较低安装位置降低整车重心，减少快速平移、急停和压灯接触时的俯仰晃动。
电机驱动板同样采用支柱架起的方式安装，并分别布置在主板两侧。由于底车使用四个有刷直流电机，驱动板靠近左右两侧电机能够缩短大电流走线和电机线长度，降低线路压降和布线混乱程度。分层安装方式使主控、电池和驱动模块之间形成较清晰的空间关系，便于后期检查接口、替换板卡和排查电机驱动故障。
3.6 空地线缆连接与固定结构
无人机与底车之间通过串口线和电源线连接，线缆从无人机中心区域引出，经底车尾部支架和万向节后接入底车主板。支架用于抬高线缆连接点，避免线缆直接拖拽车体上表面；万向节用于释放线缆在不同方向上的转动约束，使底车平移和无人机轻微姿态调整时线缆能够自然随动。
线缆采用胶带进行固定，并在无人机与底车之间保持自然下垂状态。自然下垂可以为相对运动预留余量，降低瞬时拉力；固定处理则能够防止线缆进入螺旋桨区域或缠绕底车轮组。该部分结构虽然不直接参与控制算法，但会影响无人机悬停扰动和底车运动阻力，因此在整车调试中需要重点检查线缆长度、固定点位置和运动过程中的摆动范围。
3.7 本章小结
本章介绍了无人机和地面麦克纳姆轮小车的机械结构设计。无人机部分采用约30cm保护罩式四旋翼机架，通过分层安装、减震固定和中心引线方式保证飞控、视觉和供电连接的稳定性；底车部分采用约30cm×30cm四轮麦克纳姆轮结构，通过主板居中、电池下置、驱动板两侧布置和车身直接压灯的方式兼顾运动灵活性、重心稳定性和维护便利性；空地连接部分通过尾部支架、万向节和胶带固定降低线缆对系统运行的影响。

第四章 硬件电路设计
4.1 硬件系统总体设计
本系统硬件由底车控制电路、底车电机驱动电路、无人机控制电路、四合一无刷电调电路以及电源管理电路组成。底车和无人机均采用CYT4BB7核心板作为主要控制平台，便于统一软件开发环境和外设接口配置；底车电机驱动采用DRV8701E方案，实现四路有刷直流电机的方向控制和PWM调速；无人机电调采用STC32G12K128-48PIN作为控制芯片，将四个单电调集成在一块PCB上，以提高空中平台的集成度。
系统电源由底车端4S锂电池提供。电池输出首先进入电源管理部分，再分别转换为电机驱动、主控板和外设所需的电压。由于底车和无人机之间同时存在电源线和串口通信线，硬件设计中需要重点考虑供电稳定性、接口可靠性和大电流回路对控制信号的干扰。整体电路采用模块化设计，各功能板之间通过排针、端子和线束连接，便于比赛现场维护与故障排查。
4.2 电源管理电路设计
本系统采用4S锂电池作为整车能源来源。4S电池电压较高，能够满足底车电机和无人机无刷电机对功率的需求，但主控芯片、传感器和通信模块无法直接使用该电压，因此需要通过多级降压电路得到稳定的12V、5V和3.3V电源。
电源管理部分采用SCT2450QSTER降压芯片构成12V和5V降压模块。其中12V电源主要用于后级功率模块和部分外设供电，5V电源用于主控板外设、接口模块以及进一步降压。3.3V电源由RT9013稳压芯片从5V降压得到，主要供给CYT4BB7核心板相关低压外设和逻辑电路。通过“4S电池输入、开关降压到12V/5V、线性稳压到3.3V”的分级供电方式，可以兼顾功率输出能力和低压逻辑电源的稳定性。
4.3 底车主板设计
底车主板以CYT4BB7核心板为核心，主要承担串口指令接收、运动控制运算、编码器信号采集、PWM输出以及人机交互等功能。主板上引出了底车控制所需的电机驱动接口、通信接口、调试接口和电源接口，使底车控制系统能够集中接线，减少飞线和临时转接带来的不稳定因素。
底车主板需要同时连接两侧电机驱动板、编码器、电源模块和空地通信线。为了提高调试效率，主板上预留了串口、按键、显示或下载调试相关接口，便于在不同阶段观察运行状态和修改参数。PCB布局上，核心板区域与电源降压区域、外设接口区域相对分开，大电流供电走线尽量远离串口和编码器等弱信号线，以降低电机工作时的干扰。

4.4 底车电机驱动板设计
底车电机驱动板采用DRV8701E作为有刷直流电机预驱芯片，配合外部MOS管构成H桥驱动电路。DRV8701E负责接收主控板输出的PWM和方向控制信号，并完成栅极驱动、使能控制以及必要的保护控制。外部MOS管承担电机大电流通断，能够满足麦克纳姆轮底车在启动、横移、急停和压灯过程中的瞬时电流需求。

4.5 无人机主板设计
无人机主板同样采用CYT4BB7核心板作为控制核心，主要承担飞控控制、图像采集接口、传感器接口、电调PWM输出以及与底车通信等功能。根据无人机任务需求，主板预留了MT9V03X摄像头接口、IMU接口、ToF定高接口、屏幕接口、调试串口和输出电调接口，使飞控、视觉和调试功能能够集中在同一控制平台上完成。

4.6 四合一无刷电调板设计
无人机四合一电调板采用STC32G12K128-48PIN作为控制芯片，将四个单电调功能集成在一块PCB上。电调板接收无人机主板输出的四路PWM控制信号，根据油门指令完成无刷电机换相控制，并通过MOS驱动和三相桥式功率级驱动四个无刷电机。四合一设计减少了单独电调之间的电源线、信号线和固定结构，有利于降低无人机机体重量和线束复杂度。
电调板上包含电源输入、单片机控制、MOS驱动、功率MOSFET、指示灯以及电机输出接口等部分。由于无刷电机工作时电流变化快、开关频率高，PCB设计需要特别关注功率回路面积、地线回流路径和散热铜皮面积。四路电调在同一块板上工作时，还需要保证各路驱动布局尽量对称，减少某一路电机因线路阻抗差异导致的响应不一致。

4.7 空地通信与接口连接
空地通信采用有线串口方式完成。无人机端使用P4.0、P4.1作为通信引脚，底车端使用P3.0、P3.1作为通信引脚，两端通过约1.5m线缆连接。相较于无线通信，有线串口延迟低、协议简单、调试方便，适合在比赛任务中传输[position, x, y]等目标坐标信息。
在接口设计上，串口线和电源线都从无人机中心区域引出，并通过底车尾部支架与万向节接入底车主板。硬件连接时需要保证通信地线可靠共地，并尽量使串口信号线远离电机相线、电源输入线和驱动板大电流走线。对于实际比赛环境，接口处还需要进行机械固定，避免线缆晃动导致接触不良。
4.8 本章小结
本章介绍了系统硬件电路设计。底车主板和无人机主板均以CYT4BB7核心板为控制核心，分别面向地面执行和空中感知控制任务；底车驱动板采用DRV8701E配合外部MOS管完成四路有刷电机驱动；无人机四合一电调板采用STC32G12K128-48PIN实现四路无刷电机电调集成；电源部分以4S锂电池为输入，通过SCT2450QSTER和RT9013构成12V、5V和3.3V供电网络。模块化硬件结构提高了系统集成度，也为后续软件调试和比赛现场维护提供了便利。

第五章 无人机飞控系统设计
5.1 飞控系统总体结构
无人机飞控系统运行在无人机端CYT4BB7的CM7_0核心上，主要完成姿态解算、定高控制、目标指令接收、串级PID控制、电机混控和四路PWM输出等任务。系统启动后，主函数首先完成时钟、调试接口、蜂鸣器与板级外设初始化，随后关闭电机输出并进行IMU静态校准。校准完成后，程序加载PID默认参数，初始化飞控中断调度和调试通信链路，最后进入主循环执行调试数据轮询和状态指示。
飞控闭环的核心计算不放在主循环中，而是由PIT0_CH0周期中断触发。在中断服务函数中，系统清除PIT中断标志后调用fc_isr_work()。该函数按照固定节拍完成IMU姿态更新、视觉目标读取、ToF高度处理、角度环与角速度环控制、电机混控和PWM输出，从而保证飞控控制周期具有较好的实时性。

图5.1 无人机飞控程序总体流程图
5.2 姿态传感器与SO3姿态解算
姿态测量部分采用IMU963RA惯性传感器，通过SPI接口与CYT4BB7连接。由于传感器在PCB上的安装方向与无人机机体坐标系可能不完全一致，系统在board_cyt4bb7.h中定义了IMU轴映射关系，将传感器坐标统一转换到无人机标准机体系。当前机体系定义为X轴向前、Y轴向右、Z轴向下，后续控制算法均基于该坐标系进行计算。
IMU数据处理由fc_imu.c完成。系统在IMU_Init()中初始化姿态解算状态和二阶低通滤波器，在ReadIMUSensorHandle()中读取加速度、角速度和磁力计原始数据，并对加速度和角速度进行单位转换与滤波。启动阶段通过IMU_Calibrate()累积一定数量的静止采样，计算加速度零偏和陀螺仪零偏，校准完成后置位g_imu.ready，使姿态控制进入可运行状态。
姿态解算采用非线性SO3互补滤波方法。该方法以四元数表示无人机姿态，通过陀螺仪积分获得短时间姿态变化，并利用加速度方向对横滚角和俯仰角进行修正。程序中主要由IMUSO3Thread()调用NonlinearSO3AHRSupdate()完成四元数更新，随后将四元数转换为roll、pitch、yaw三个欧拉角，供姿态控制环使用。
5.3 目标输入与任务状态管理
飞跃雷区任务中，无人机不仅需要保持自身稳定，还需要根据视觉处理结果修正悬停位置。视觉核心CM7_1将目标偏差、偏航角和高度目标等信息写入共享内存，CM7_0端通过fc_m1_m0_input_poll()读取该共享目标。为避免双核心读写过程中出现半包数据，目标结构中包含magic、seq和checksum字段，CM7_0连续读取两次并进行序号和校验判断，确认数据有效后再提交给fc_remote_input_post()。
目标输入模块由fc_remote_input.c管理。该模块将外部视觉给出的X/Y偏差进行限幅、死区处理、低通滤波和斜率限制，再转换为横滚角和俯仰角修正量。这样可以避免视觉坐标瞬时跳变直接作用到飞控姿态目标，从而减小无人机悬停时的抖动。程序中还设置了起飞、定高、等待稳定、旋转和接收视觉控制等任务状态，使无人机在任务开始后按照预定流程逐步进入稳定工作状态。
5.4 串级PID姿态控制
无人机姿态控制采用角度环和角速度环串级PID结构。外环为角度环，以期望roll、pitch、yaw和IMU解算得到的实际姿态角作为输入，计算得到各轴期望角速度；内环为角速度环，以期望角速度和陀螺仪测得的实际角速度作为输入，输出横滚、俯仰和偏航三个控制量。串级结构能够将姿态误差和角速度阻尼分开调节，使无人机既能快速响应姿态目标，又能抑制高频振荡。
系统调度参数定义在fc_params.h中。PIT基础节拍为1000Hz，IMU更新和角速度环频率为500Hz，角度环频率为100Hz。角度环PID默认参数中，roll和pitch的比例系数均为3.60，积分系数均为1.0；yaw比例系数为1.60，积分系数为0.1。角速度环中，roll、pitch和yaw的比例系数均为1.05，其中roll和pitch设置了微分项0.01，用于增强角速度阻尼。
控制计算可概括为：角度环根据角度误差e_angle = angle_target - angle_feedback计算rate_target；角速度环根据e_rate = rate_target - rate_feedback计算控制量u。程序中还对积分项和输出量进行了限幅处理，当油门为零或电机输出接近饱和时，积分状态会被复位或限制，避免积分累积导致重新起飞或扰动恢复时出现过冲。

5.5 ToF定高控制
无人机高度控制采用DL1B ToF测距模块获取离地高度。系统在fc_isr_work()中周期调用hal_range_poll()更新测距数据，并在高度环节拍到来时调用fc_altitude_hold_update()计算油门修正量。高度环默认目标高度为1200mm，最大接受外部高度目标为1500mm，高度环更新周期为20ms，即50Hz。
定高控制采用带速度阻尼的PID思想。程序首先对ToF测量高度进行低通滤波，并由相邻高度差估计垂向速度；然后计算高度误差error = target - measured。误差进入死区后冻结积分，接近目标且垂向速度较大时降低比例作用并加入制动限制，最终得到油门偏移量。该油门偏移量叠加在基础油门上，用于补偿电池电压变化、机体重量和地面效应带来的悬停油门差异。
为保证高度控制平滑，定高模块对积分项、输出幅值和单次输出变化量均进行了限制。当前参数中，高度比例系数为0.60，积分系数为0.05，微分系数为0.15，高度死区为20mm，油门偏移输出限制为±80。通过这些限制，系统在保持高度响应速度的同时减少了因ToF噪声或线缆扰动导致的油门突变。
5.6 电机混控与PWM输出
角速度环输出的roll、pitch和yaw控制量需要与总油门一起转换为四个电机的油门命令。程序在fc_control_mix_motors()中完成四旋翼混控，当前电机布局中M1为右后电机、M2为左后电机、M3为左前电机、M4为右前电机。混控关系可表示为：M1 = T - R - P + Y，M2 = T + R - P - Y，M3 = T + R + P + Y，M4 = T - R + P - Y，其中T为总油门，R、P、Y分别为横滚、俯仰、偏航控制量。
混控结果经过限幅后写入fc_motor_output_t结构，再由hal_motor_write()转换为四路PWM输出。飞控内部电机命令范围为0~900，对应电调输入脉宽1000us~1900us；PWM频率默认设置为50Hz。该设计保留了2000us满油门之前的安全余量，适合比赛调试阶段控制电机最大输出，降低无人机突然大油门带来的风险。
PWM输出对应无人机四合一无刷电调板的四路输入信号。电调板接收1.0ms至1.9ms左右的高电平脉宽后，分别驱动四个无刷电机。由于四路电机的输出直接决定无人机姿态，调试时需要保证电机编号、旋转方向、桨叶方向和混控符号一致，否则会出现姿态环正反馈或偏航方向错误。
5.7 安全保护与调试数据
飞控系统设置了基本安全保护逻辑。当IMU尚未准备完成或目标油门为零时，姿态控制模块会复位PID状态并将四路电机输出清零；在fc_isr_work()中，如果检测到pitch或roll绝对值超过FC_MAX_ANGLE设定值，系统直接调用hal_motor_write(0,0,0,0)关闭电机输出，防止机体姿态过大时继续加油造成危险。
调试数据由fc_debug模块定时采集，默认每10ms记录一次姿态误差、角速度目标、PID输出、混控值、高度测量值、高度误差以及实际写入的电机命令。主循环中持续执行fc_debug_poll()，并通过状态指示灯显示调试链路状态。通过这些数据，可以在调参时区分姿态解算误差、PID参数不合适、混控符号错误、电调输出异常和高度测距异常等不同问题。
5.8 本章小结
本章介绍了无人机飞控系统的软件结构和控制方法。飞控核心以PIT周期中断为实时调度基础，通过IMU963RA和SO3姿态解算获得roll、pitch、yaw姿态角，通过DL1B ToF模块实现高度反馈，并利用角度环、角速度环和高度环完成无人机稳定控制。控制输出经四旋翼混控后转换为四路PWM信号，驱动基于STC32G12K128的四合一电调板。该飞控结构将姿态稳定、定高控制、视觉目标输入和调试数据采集统一到CM7_0控制流程中，为后续空中视觉识别和空地协同执行提供了稳定平台。

第六章 空中视觉识别算法设计
6.1 视觉系统总体流程
空中视觉识别系统运行在无人机端CYT4BB7的CM7_1核心上，主要任务是在无人机俯视视角下识别信标灯和底车位置，并将识别结果分别发送给地面麦克纳姆轮小车和无人机飞控核心。视觉主程序位于main_cm7_1.c中，系统初始化后进入循环等待MT9V03X摄像头采集完成标志。当mt9v03x_finish_flag置位后，程序清除标志位，依次调用vs_core_recognition()完成图像识别与目标计算，再调用vs_core_output()完成坐标转换和结果输出。
与将图像任务放入中断不同，本系统采用“摄像头完成标志触发、主循环处理整帧图像”的方式。这样可以避免复杂图像处理长时间占用中断，同时保证每一帧图像均按照固定流程完成车灯识别、信标识别、跟踪防抖、目标选择和输出。视觉算法整体流程如图6.1所示。

图6.1 空中视觉算法总体流程图
6.2 图像采集与初始化
视觉核心初始化函数为vs_core_init()。该函数首先完成惯性方向模块初始化、系统时钟与调试接口初始化，然后初始化CM7_1到CM7_0的共享内存输出接口，并配置UART2作为底车通信串口，波特率为115200。随后程序循环调用mt9v03x_init()完成摄像头初始化，若初始化失败则通过LED翻转提示状态，直到摄像头正常工作。
MT9V03X摄像头输出灰度图像，图像数据保存在mt9v03x_image数组中。由于比赛场景中信标灯和底车识别主要依赖亮度差异，灰度图像可以降低处理复杂度，便于在嵌入式平台上使用阈值分割和连通域分析完成实时识别。
6.3 底车识别算法
底车识别的核心依据是车体上高亮车灯区域。程序首先在threshold_car()中对原始灰度图进行阈值分割，当像素亮度大于Car_LOW时将其置为车灯候选区域。当前参数中Car_LOW设置为140，可滤除背景和较暗区域，只保留亮度较高的车灯光斑。
完成二值化后，find_vehicle()通过连通域分析寻找满足面积、形状和配对关系的车灯候选。由于底车上用于视觉定位的灯通常表现为两个分开的高亮连通域，算法会根据单个候选面积、细长度、两个候选之间的距离等条件筛选车灯对，并计算底车中心位置和朝向向量。当双灯识别失败但仍存在较大的高亮连通域时，程序还保留car_fallback_cx、car_fallback_cy作为降级位置，用于短时间维持无人机控制和底车定位。
为降低图像噪声和短暂遮挡带来的抖动，smooth_vehicle()对底车中心坐标和方向向量进行EMA指数移动平均。当前小车平滑系数VEHICLE_EMA_ALPHA为0.35，短暂丢失时可保持上一次有效结果最多10帧。该设计可以在底车灯被线缆、车体姿态或信标强光短暂影响时，提高视觉输出的连续性。
6.4 信标灯识别算法
信标灯识别采用阈值分割与连通域筛选相结合的方法。程序在threshold_beacon()中对原始图像进行亮度区间判断，当像素值大于TH_LOW且小于TL_HIGH时认为其可能属于信标区域。当前参数中TH_LOW为120，TL_HIGH为256，能够覆盖信标灯的高亮区域。
由于底车车灯同样属于高亮目标，若直接进行信标识别，车灯边缘和晕染区域可能被误判为信标。为此，程序先执行底车识别，再由mask_car_from_beacon()根据车灯连通域外扩后的包围框，将车灯附近过亮区域从信标二值图中剔除。这样可以减少车灯对信标候选的干扰，提高目标筛选的稳定性。
find_beacons()采用Two-Pass连通域标记方法统计每个候选区域的面积、边界框和中心位置。随后根据信标所在图像区域自适应设置面积、宽高比和填充率约束。图像中心区域约束较严格，用于排除噪声和大面积干扰；图像边缘区域适当放宽，以适应无人机姿态变化和镜头畸变造成的信标拉伸。通过面积排序和距离去重后，单帧最多保留6个信标候选。
6.5 帧间跟踪与防抖处理
单帧识别结果容易受到亮度波动、无人机微小晃动和遮挡影响，因此系统对信标目标进行了帧间跟踪。track_beacons()将当前帧beacon_list中的候选与上一帧tracked_beacons中的目标进行匹配，匹配依据为中心点距离，当前MATCH_DIST_THRESH为15像素。匹配成功则更新目标坐标和面积，匹配失败则增加丢失计数；新出现的候选会分配新的track_id。
信标平滑由smooth_beacons()完成，对每个跟踪目标的中心坐标进行EMA更新，当前BEACON_EMA_ALPHA为0.40。对于短暂丢失的信标，程序保留上一次平滑位置，不立即清零。若信标连续丢失且底车位置接近该信标，update_beacon_extinguish()会将其标记为已踩灭，从而避免系统反复选择已经完成的目标。
靠近信标时，车灯或信标可能因车身遮挡、压灯动作和画面边缘畸变出现短暂丢失。程序中还设计了惯性方向模块inertia_update()：当底车接近信标且方向出现丢失或跳变时，系统可在一定帧数内沿历史运动方向继续给出底车速度，避免小车在最后接近阶段因视觉瞬间失效而停在目标附近。
6.6 目标选择与坐标转换
跟踪防抖完成后，track_update()负责目标锁定和速度计算。若当前已有有效目标信标，系统优先根据track_id继续跟踪该信标；若目标失效或已经踩灭，则通过find_nearest_beacon()在未踩灭、未边缘丢失的信标中选择距离底车最近的信标作为新目标。这种策略使底车优先处理当前位置附近目标，减少不必要的大范围移动。
底车运动指令由calc_car_velocity()计算。当目标信标和底车位置均有效时，程序调用beacon_to_vehicle_coord()将信标相对底车的位置转换为底车坐标系下的速度向量。随后transform_car_coord()将内部坐标修正为底车接收格式，其中输出s_car_x表示左向分量，s_car_y表示前向分量。
无人机悬停修正量由calc_plane_velocity()和transform_plane_coord()计算。程序以图像中的飞机投影点PLANE_CX、PLANE_CY作为参考，结合底车和信标在图像中的位置得到无人机需要修正的偏差。图像坐标系中向右、向下的偏差经过转换后，得到无人机坐标系下的前向和左向误差drone_dx、drone_dy。

图6.2 视觉坐标转换示意图
6.7 视觉结果输出
视觉结果输出由vs_core_output()统一完成。对于地面底车，程序通过UART2发送字符串格式指令[position, x, y]，其中x和y分别为经过坐标转换后的底车运动目标分量。该格式与底车端串口解析程序对应，便于底车直接根据目标偏差进行麦克纳姆轮运动控制。
对于无人机飞控核心，视觉程序调用fc_m1_m1_output_send_xy_deviation_target()将drone_dx、drone_dy、高度目标和任务标志写入双核心共享内存。当前输出中高度目标设置为1300mm，偏航目标为0。CM7_0飞控核心在周期中断中读取该目标，用于修正无人机悬停位置，使摄像头视野尽量跟随底车和任务目标。
此外，程序还通过update_car_zero_stat()统计最近10帧底车输出速度接近零的帧数，并在显示调试界面中输出识别与控制状态。该信息可用于判断底车是否已经接近目标、视觉输出是否长时间无效，以及任务是否可能进入下一阶段。
6.8 本章小结
本章介绍了空中视觉识别算法的整体设计。系统以MT9V03X灰度图像为输入，在CM7_1核心上完成底车车灯识别、信标灯识别、连通域筛选、帧间跟踪、EMA防抖、目标选择和坐标转换。识别结果一方面通过UART2发送给底车，形成[position, x, y]运动指令；另一方面通过共享内存发送给CM7_0飞控核心，用于无人机悬停位置修正。该算法将空中感知和空地协同控制联系起来，是系统完成飞跃雷区任务的关键环节。

第七章 地面麦克纳姆轮小车控制系统设计
7.1 底车控制系统总体结构
地面底车承担飞跃雷区任务中的承载、跟随与目标触碰功能。底盘采用四轮麦克纳姆轮结构，车体边缘设置挡板，用于在靠近信标后直接完成压灯动作。控制核心板采用CYT4BB7，底车程序主要运行在CM7_0内核上，CM7_1内核当前仅完成基础初始化，不参与主要运动控制。
底车控制软件按照“串口接收、目标解析、运动解算、速度闭环、电机驱动”的链路组织。无人机视觉端将识别到的底车相对偏差封装为[position,x,y]格式，经空地串口线发送到底车；底车主循环完成协议拆包和目标更新，并在导航函数中计算四轮目标速度。2ms定时中断负责读取编码器、更新IMU姿态、执行方向控制和四路电机速度闭环，因此快速闭环控制与相对耗时的串口解析被分离在不同执行节拍中。

图7.1 底车控制程序总体流程图
7.2 空地串口指令接收与解析
底车与无人机之间通过UART6通信，底车端引脚配置为P3.1发送、P3.0接收，波特率设置为115200。串口中断函数uart6_isr()在接收中断到来时循环读取硬件FIFO中的所有字节，并写入软件FIFO uart6_rx_fifo。这样可以降低主循环临时阻塞对串口接收的影响，避免连续数据包到达时丢失字节。
主循环调用uart_protocol_process()从FIFO中读取数据，并采用以“[”为起始、“]”为结束的状态机拆包。当状态机得到完整数据包后，回调position_cmd_parse()进行命令解析。当前实际绑定的是不带CRC的解析函数，其有效数据格式为[position,x,y]。解析成功后，字符串中的x、y通过atof()转换为浮点数，并分别写入全局变量target_x和target_y，作为后续导航计算的目标偏差输入。
7.3 目标偏差与导航控制
底车导航函数navigation_update()在主循环中反复执行。程序中保留了current_x、current_y变量，但当前工程没有形成可靠的全局里程计更新链路，因此本设计将无人机下发的x、y作为视觉相对偏差使用，即根据target_x与target_y直接计算底车相对目标的平面距离和运动方向。其距离与方向角计算关系为：
dist = sqrt(dx^2 + dy^2),    angle = atan2(dy, dx)
其中dx、dy为目标相对底车的平面偏差，dist用于判断底车与目标之间的接近程度，angle用于确定麦克纳姆轮底盘的平移方向。速度映射函数fuzzy_control()当前选择USE_PIXEL_P_CONTROL=1的像素比例控制分支：当偏差大于15时，速度指令随距离线性增大；当偏差小于等于15但仍未归零时，输出固定冲击速度；当偏差为0时停止平移。该策略计算量小、响应直接，适合视觉偏差闭环中的短距离跟随与压灯动作。
7.4 四轮麦克纳姆轮运动学解算
麦克纳姆轮底盘能够在不改变车头朝向的情况下实现前后、左右及斜向平移。程序中的omni_control()先将平移速度speed_cmd按照目标方向angle分解为vx和vy，再根据四轮X型安装关系计算四个轮子的目标速度。代码采用k=0.35355作为速度分解系数，使对角轮具有相同速度设定，前右轮与后左轮具有相同速度设定。
FL = k(vy + vx),    FR = k(vy - vx),    BL = k(vy - vx),    BR = k(vy + vx)
式中FL、FR、BL、BR分别表示左前、右前、左后、右后轮目标速度。由于四个麦克纳姆轮呈X型安装，该分配关系能够把二维平移指令转换为四路电机转速设定。程序中还保留了基于IMU航向角的方向双环PID控制，PIT中断内会计算g_rot；但当前navigation_update()中将rot固定为0，因此正文将其作为预留的姿态补偿接口，不作为当前底车平移控制的主要执行量。

图7.2 麦克纳姆轮底盘运动学示意图
7.5 编码器测速与速度闭环
底车四个电机均配置正交编码器。Encoder_init()分别初始化左前、右前、左后、右后四路编码器通道；speed_get()在2ms周期中断内读取并清零各编码器计数，将本周期脉冲数作为电机实际速度反馈，同时累加q_encoder用于里程信息记录。为了统一四个电机的正方向，左前轮和左后轮编码器读数在软件中取负。
速度闭环由roll_wheels()完成。四个轮子分别配置独立的增量式PID控制器，目标值来自motor.speed_set_*，反馈值来自motor.speed_act_*。增量式PID按照当前误差、上一次误差和上上次误差计算PWM输出增量，再进行输出限幅和增量限幅。四路速度PID参数分别设置，便于补偿不同电机、减速箱和轮胎摩擦带来的差异。
Delta u = Kp(e(k)-e(k-1)) + Ki e(k) + Kd(e(k)-2e(k-1)+e(k-2))

图7.3 四轮速度闭环控制框图
7.6 DRV8701E电机驱动输出
底车电机驱动采用DRV8701E方案，CYT4BB7通过PWM信号与方向GPIO控制四路电机。程序中motor_init()初始化PWM_F_L、PWM_F_R、PWM_B_L、PWM_B_R四路PWM输出，同时初始化DIR_F_L、DIR_F_R、DIR_B_L、DIR_B_R四个方向控制引脚。PWM频率由MOTOR_FRE设置，当前参数为17000Hz。
roll_wheels()将PID输出转换为有符号PWM值：当PWM为正时设置对应正转方向并输出占空比，当PWM为负时切换方向并输出其绝对值，当PWM为0时关闭该路输出。为克服电机静摩擦，程序设置DEAD_ZONE_PWM=400；当目标速度绝对值大于5且PID输出尚不足以启动电机时，软件会把PWM提升到死区补偿值，使底车在低速跟随和末端压灯阶段仍能可靠起步。
7.7 安全停止与调试
底车程序预留了follow_enable控制标志和pwm_clean()停止函数。pwm_clean()可将四路PWM占空比全部置零，并在需要时配合清零motor.speed_set_*目标速度，使底车立即退出闭环驱动状态。虽然当前PIT中断中速度闭环分支固定执行，但该结构为后续加入启动按键、通信超时保护和任务完成停车提供了接口。
调试过程中主要观察target_x、target_y、speed_cmd、四轮speed_set、四轮speed_act以及PWM输出值。其中target_x和target_y反映无人机视觉识别结果，speed_set和speed_act用于判断运动学解算与速度闭环是否一致，PWM输出则用于判断死区补偿和DRV8701E驱动级是否工作正常。通过分层观察这些变量，可以将问题定位到通信、导航、速度闭环或功率驱动中的具体环节。
7.8 本章小结
本章介绍了地面麦克纳姆轮小车的控制系统设计。底车以CYT4BB7为核心，通过UART6接收无人机视觉端下发的相对位置偏差，利用目标距离和方向角生成平移速度指令，再通过麦克纳姆轮运动学解算得到四轮目标速度。四个电机采用编码器速度反馈和独立增量式PID闭环控制，最终由PWM与方向信号驱动DRV8701E电机驱动电路。该设计实现了空中视觉定位结果到底车全向运动的闭环转换，为飞跃雷区任务中的协同跟随和目标压灯提供了控制基础。

第八章 空地协同通信与任务流程设计
8.1 空地协同总体流程
飞跃雷区任务需要无人机与地面底车协同完成。系统启动后，无人机飞控、视觉识别程序和底车控制程序同步进入工作状态。无人机利用下视摄像头识别底车和信标位置，计算底车相对目标的平面偏差；底车接收该偏差后，通过麦克纳姆轮底盘完成全向跟随，最终靠近并压灭目标信标。
本系统采用“空中识别、地面执行”的分工方式。无人机侧负责环境感知和目标偏差计算，底车侧负责运动控制和电机闭环，两者之间仅传输必要的位置偏差信息。该方式减少了底车端图像处理负担，也使通信数据格式保持简单，便于调试和现场排错。

8.2 通信数据格式
无人机与底车之间通过有线串口连接，线缆长度约1.5m。无人机端使用P4.0、P4.1串口引脚，底车端使用P3.0、P3.1串口引脚，两端通信波特率均设置为115200。考虑到空地之间传输内容较少，系统采用ASCII字符串数据包，便于在调试串口中直接观察。
实际发送的数据包格式为[position,x,y]，其中position为命令类型，x和y为视觉坐标系下的相对偏差。数据包以左中括号作为起始标志，以右中括号作为结束标志，底车端状态机在接收到完整数据包后再更新目标变量。该格式具有较强的可读性，在联调过程中可以快速判断数据是否正常到达。
8.3 任务执行逻辑
任务开始后，无人机飞控维持自身姿态与高度稳定，视觉端持续采集图像并完成底车、信标的识别与跟踪。当视觉端获得有效目标后，将目标相对底车的偏差转换为底车可用的x、y指令，通过串口周期性发送给底车。底车端不断刷新target_x和target_y，并根据偏差大小决定运动速度。
在靠近目标过程中，底车先以较大偏差对应的速度快速接近；当偏差进入小范围后，程序输出较低的冲击速度，保证底车能够继续克服静摩擦并完成末端接触。信标被压灭后，无人机视觉端更新目标状态，进入下一个目标的识别与跟随过程。
8.4 同步启动与异常处理
本方案采用车和无人机同步启动方式。启动后，无人机飞控先完成传感器初始化与姿态稳定，底车完成电机、编码器、IMU和串口初始化。为避免刚上电时传感器数据不稳定，底车程序在初始化后设置了约3s延时，再开启2ms周期控制中断。
异常处理方面，底车程序保留了PWM清零函数和控制使能标志，可用于后续扩展通信超时停车、任务结束停车等保护逻辑。联调时重点检查串口是否持续收到[position,x,y]数据、视觉偏差是否随车体运动逐渐减小，以及四轮速度反馈是否与目标速度方向一致。
8.5 本章小结
本章说明了无人机与地面底车之间的协同方式。系统通过空中视觉获得目标偏差，并通过串口发送给底车，底车再完成全向运动控制和目标压灯。这种分层设计使感知、通信和执行环节边界清晰，既方便软件调试，也提高了整车系统在比赛任务中的可维护性。

第九章 系统调试与实验结果分析
9.1 调试总体思路
系统调试按照由单模块到整机联调的顺序进行。首先分别验证无人机飞控、视觉识别、底车电机驱动和串口通信等基础模块，确认各部分能够独立稳定工作；随后进行空地通信联调，使无人机视觉端输出的目标偏差能够被底车正确接收；最后在完整任务环境下进行跟随、接近和压灯测试。
调试过程中采用分层定位方法：当整车表现异常时，先观察视觉识别结果是否稳定，再检查串口数据格式是否正确，然后查看底车四轮目标速度和实际速度是否一致，最后检查电机驱动输出和机械安装状态。该方法能够避免直接修改控制参数造成新的问题。
9.2 无人机飞控与视觉调试
无人机部分首先进行飞控基础调试，包括IMU零偏校准、姿态角输出检查、电机旋向检查和油门响应测试。在确保飞控能够稳定输出电机控制量后，再进行摄像头图像采集和视觉算法调试。视觉调试重点观察底车识别框、信标识别结果、目标匹配状态以及输出给底车的偏差值。
在图像处理调试中，通过改变赛道光照、摄像头安装角度和底车位置，检查阈值分割、目标跟踪和坐标转换是否稳定。当识别结果出现跳变时，优先检查曝光、二值化阈值和目标遮挡情况；当识别结果稳定但底车运动方向异常时，重点检查视觉坐标系与底车运动坐标系之间的符号关系。
9.3 底车运动控制调试
底车调试从单电机开始，依次验证四路PWM输出、方向引脚、电机旋向和编码器反馈方向。在四个轮子均能正常闭环后，再进行麦克纳姆轮平移测试，分别检查前后、左右和斜向运动是否符合预期。如果底车出现偏航或斜行误差，则分别从轮子安装方向、电机旋向、编码器符号和四轮PID参数进行排查。
速度闭环调试时，重点观察四轮目标速度speed_set、实际速度speed_act和PWM输出值。当目标速度较小而电机不能启动时，需要考虑死区补偿；当目标速度和实际速度长期偏差较大时，需要检查PID参数、轮胎摩擦和驱动板输出能力。通过逐步提高速度指令，可以验证底车在低速跟随和末端压灯阶段的运动可靠性。
9.4 空地联调与任务测试
空地联调时，无人机与底车同步启动，无人机视觉端周期性发送[position,x,y]数据包，底车端实时解析并更新目标偏差。测试中先固定无人机和底车位置，确认串口数据与视觉偏差变化一致；随后让底车在小范围内跟随目标，检查偏差是否随运动逐渐减小。
完整任务测试主要验证三个指标：一是无人机视觉识别是否能够持续锁定底车和信标，二是底车能否按照偏差方向稳定接近目标，三是接近目标后能否依靠车体和挡板完成压灯动作。经过多次调试后，系统能够完成从视觉识别到串口下发、再到底车运动执行的闭环流程。
9.5 典型问题与改进方向
调试中可能出现的典型问题包括：视觉识别受光照影响产生跳变，串口线缆摆动影响无人机姿态，底车低速时受静摩擦影响起步不稳定，以及麦克纳姆轮安装方向或编码器符号错误导致运动方向异常。针对这些问题，分别通过调整阈值、固定线缆、设置PWM死区补偿、逐轮检查旋向和反馈方向等方法进行处理。
后续改进可从三个方面展开：一是增加串口通信超时保护和数据校验，提高异常情况下的安全性；二是继续优化视觉滤波和目标跟踪，降低误识别对底车运动的影响；三是结合实测数据细化底车速度映射，使远距离接近、近距离微调和末端压灯之间的速度衔接更加平滑。
9.6 本章小结
本章介绍了系统调试和实验测试过程。通过无人机飞控调试、视觉识别调试、底车运动控制调试和空地联调，验证了系统各模块之间的配合关系。实验结果表明，本方案能够实现无人机视觉引导下的底车全向跟随与信标压灯，满足飞跃雷区组别任务对空地协同和稳定执行的基本要求。

第十章 总结与展望
10.1 工作总结
本文围绕第二十一届全国大学生智能汽车竞赛飞跃雷区组别任务，完成了一套由无人机、地面麦克纳姆轮底车、空地通信链路和电源驱动系统组成的空地协同智能车系统设计。系统以CYT4BB7为主要控制核心，无人机侧完成飞控稳定与视觉识别，底车侧完成目标偏差接收、麦克纳姆轮运动学解算和四轮速度闭环控制。
在机械结构方面，无人机安装在底车上方，通过支架、万向节和线缆完成供电与通信连接；底车采用四轮麦克纳姆轮结构，具备全向移动能力，并通过车身挡板完成末端压灯动作。在硬件方面，系统完成了核心板、电机驱动板、四合一电调板和多路降压电源的设计，满足无人机和底车同时工作的供电与控制需求。
在软件方面，无人机飞控程序通过IMU姿态解算、角度环和角速度环控制实现基本稳定；视觉程序通过摄像头采集、阈值分割、目标识别、跟踪和坐标转换生成底车控制偏差；底车程序通过UART6接收[position,x,y]数据包，并将视觉偏差转换为四轮速度目标，最终由编码器速度闭环和DRV8701E驱动级完成运动执行。
10.2 系统特点
本系统的主要特点是任务分工清晰。无人机承担视野获取和目标定位，底车承担运动执行和信标触碰，两者之间只传输必要的相对位置偏差，降低了通信复杂度。麦克纳姆轮底车能够在狭小区域内完成横移、斜移和前后运动，适合飞跃雷区任务中目标位置变化较快、末端接近空间有限的场景。
系统软件结构采用分层设计，飞控、视觉、通信、导航、速度闭环和电机驱动模块相对独立，便于逐级调试。调试时可以从图像识别结果、串口数据、目标速度、实际速度和PWM输出等多个层面观察系统状态，从而快速定位问题来源。
10.3 不足与展望
目前系统仍存在进一步优化空间。首先，空地通信采用较简单的ASCII数据包格式，虽然便于调试，但抗干扰能力和异常保护仍可增强；后续可加入CRC校验、通信超时停车和任务状态反馈。其次，视觉算法受光照、反光和遮挡影响较大，后续可继续优化曝光控制、目标滤波和多目标匹配策略，提高复杂赛场环境下的稳定性。
在运动控制方面，底车速度映射和末端压灯策略还可以结合更多实测数据进行细化。例如根据偏差大小设置分段速度，在远距离阶段提高接近速度，在近距离阶段降低抖动，并在压灯阶段保持足够的冲击能力。同时，可以进一步完善IMU航向补偿，使麦克纳姆轮底车在长时间运行和线缆扰动情况下保持更稳定的车体方向。
总体来看，本系统完成了飞跃雷区任务所需的空地协同感知、通信和执行闭环，为后续参赛调试和性能提升提供了完整基础。随着硬件可靠性、视觉鲁棒性和控制参数的持续优化，系统仍有较大的稳定性和速度提升空间。

void position_cmd_parse(char *packet)
{
    if (packet[0] != '[') return;
    int len = strlen(packet);
    if (len < 2 || packet[len-1] != ']') return;
    if (strcmp(tokens[0], "position") == 0)
    {
        target_x = atof(tokens[1]);
        target_y = atof(tokens[2]);
    }
}

void navigation_update(void)
{
    float dx = target_x - current_x;
    float dy = target_y - current_y;
    float dist = sqrtf(dx*dx + dy*dy);
    float target_angle = atan2f(dy, dx) * 57.2958f;
    int16_t speed_cmd = fuzzy_control(dist);
    omni_control(speed_cmd, target_angle, &FL, &FR, &BL, &BR);
}

        fc_control_rate_update(&g_imu, s_roll_rate_target, s_pitch_rate_target,
