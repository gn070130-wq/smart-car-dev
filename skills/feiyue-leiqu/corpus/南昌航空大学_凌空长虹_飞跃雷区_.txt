摘   要
在本套空地协同系统中，团队以英飞凌Traveo II系列微控制器为核心构建了无人机、无人车与视觉识别板协同工作的完整控制架构。无人机与无人车均采用CYT4BB双核微控制器作为主控，分别实现飞行控制与底盘运动控制：无人机端集成IMU（ICM42688）、光流、TOF、气压计与摄像头等多源传感器，通过互补滤波完成高度与视觉目标融合，结合级联PID、LADRC与滑模控制实现姿态、高度、速度与位置的多环控制，具备自主悬停、定高及实时追踪信标与车灯的能力；无人车端采用四轮全向底盘，基于麦克纳姆轮运动学解算，通过XY位置PID、角度PID与增量式速度PID构成多闭环控制，实现自主追踪信标灯的全向移动与状态反馈。视觉识别板则以CYT2BL3微控制器为核心，搭载MT9V03X摄像头，采用固定阈值分块二值化与Otsu自适应二值化结合的方式提取目标区域，利用四邻域连通域标记与PCA主成分分析进行形状判别，并通过多特征加权评分实现信标灯与车灯的稳定识别与锁定，最终将位置误差经串口实时下发至无人机与无人车。在系统研制过程中，团队从机械结构、硬件布局到软件算法进行了全面优化——硬件上重点改进了传感器安装布局、供电走线与驱动电路，软件上融合多传感器数据并引入分层控制与保护机制，显著提升了系统在复杂环境下的稳定性、跟踪精度与识别鲁棒性。

关键词：空地协同；CYT4BB；级联PID；LADRC；麦克纳姆轮；图像识别；多传感器融合；自主追踪

1.2 智能汽车制作要求及任务
在本次比赛中，本组使用大赛组委会统一提供的竞赛车模，采用英飞凌Traveo II系列CYT4BB双核微控制器作为核心处理器，通过搭载于无人机的MT9V03X摄像头与多源传感器（光流、TOF、气压计、IMU）协同无人车底盘实现信标灯识别与自主追踪灭灯任务，以完成全部信标熄灭且系统稳定协同者胜。比赛要求无人机与无人车必须采用大赛组委会指定的主控芯片（CYT4BB/CYT2BL3），无人机机身（含桨叶防护罩）必须能放入50×50cm的限定方框内，且无人机不得搭载独立电池，须由无人车通过系留线缆统一供电。车模底盘须为四轮全向结构，整车高度不超过30cm，不允许对底盘机械结构进行破坏性改动，仅允许进行必要的打孔与安装固定操作。无人机端视觉识别板须自行设计制作，禁止直接使用成品飞控模块或成品视觉处理板。
系统制作过程中，主要任务分为机械结构、硬件电路、软件算法三大板块。机械方面需对无人机与无人车的整体结构进行调校与优化，新组装的无人机在高速旋翼振动与线缆拖拽下易出现姿态抖动，传感器安装角度偏差与减振不足将直接导致光流漂移与IMF数据异常，严重影响定点悬停精度；无人车底盘的麦轮安装垂直度、编码器联轴器同轴度以及线缆悬挂点的力学平衡同样需要在反复测试中校准，机械调校的质量直接决定系统高速协同运行时的稳定性。
硬件电路方面需要自行设计飞控板、视觉识别板与底盘驱动板，各电路板须包含独立的电源管理单元、处理单元、电机驱动单元及人机交互单元。电路板覆铜层上必须蚀刻学校名称与队伍名称，板上禁止使用任何成品功能模块（如成品电调、成品光流模块、成品降压模块等），所有功能电路须从器件级自主布线焊接。飞控板与视觉板之间、无人机与无人车之间通过串口及系留线缆实现双向通信与电力传输，通信链路的抗干扰设计与供电链路的稳压能力是硬件设计的核心难点。
软件方面需要自主设计多传感器融合算法与控制策略，飞控端需实现基于互补滤波的高度融合与视觉目标融合，采用级联PID结合LADRC实现姿态—速度—位置的多环控制；无人车端需完成麦克纳姆轮运动学解算，构建XY位置环、角度环与增量式速度环的分层PID控制架构；视觉端需编写图像采集、二值化分割、连通域标记与PCA形状判别算法，并将信标位置误差经串口实时下发至无人机与无人车。三大板块联调完成后，需对整个空地协同系统进行联合标定与实地测试，无人机摄像头与小车紫外标记的相对位姿、线缆长度与拖拽力对飞行姿态的耦合影响、复杂光照下视觉识别的鲁棒性等均需通过大量实飞实验迭代优化，任何单一环节的偏差都将导致协同追踪失败。









第二章 系统总体方案设计
系统采用"无人机—无人车（视觉识别板）"的空地协同方案。无人机与无人车均采用英飞凌公司CYT4BB 微控制器作为主控芯片，视觉识别板采用 CYT2BL3 作为核心控制单元。在任务执行过程中，视觉识别板与机载视觉核心通过摄像头采集场景图像，识别信标灯与车灯两类光源目标并解算位置误差，下发至相应主控；无人机主控结合惯性测量单元、激光测距、光流等传感器的融合状态与视觉误差，输出 PWM 对四台电机的转速进行控制，从而进一步控制无人机的姿态、高度与水平位置，实现稳定悬停与目标跟踪；无人车主控结合编码器、陀螺仪反馈与视觉误差，输出 PWM 对四轮转速进行控制，从而实现车体的全向移动与信标跟踪，最终完成空地协同跟踪与降落等任务。整个控制过程中采用串级 PID 的算法。

概况来说，系统主要包括 7 个模块：主控模块、传感器采集模块、视觉识别模块、驱动模块、通信模块、供电模块、显示及其他辅助调试模块。具体来说，传感器采集模块包括惯性测量单元、激光测距、光流、气压计、编码器与陀螺仪等；视觉识别模块选用了总钻风摄像头；通信模块通过串口实现视觉板与车、机之间的数据交互，并通过共享内存实现无人机双核间的数据交换；显示模块选择了 TFT 屏幕，辅助调试模块中包括按键、串口调试工具等。













第三章 机械结构设计
3.1无人机机械结构设计
3.1.1 机架与核心板布局 
无人机采用X对称机臂配合碳纤维板机架架构。核心控制板（CYT4BB飞控板与CYT2BL3视觉板）在碳板上下中心位置进行堆叠式安装，确保机械重心与机体几何中心重合，为后续姿态调参与LADRC、滑模等控制算法的整定提供良好的机械基础。整套结构能够完整放入赛事规定的50×50cm限定方框内，满足飞行器外形尺寸的硬性要求。
3.1.2上下分层布置 
碳板上层布置飞控MCU与陀螺仪（IMU42688），下层依次安装电调、图像识别板与分电板。上下分层且居中的布局策略，一方面有效抑制了旋翼高速旋转产生的振动向传感器传导，另一方面进一步锁定整机重心位置，提升了悬停稳定性与姿态抗扰能力。
3.1.3 摄像头与外设对称安装 
 搭载两颗MT9V03X（总钻风）摄像头，以45°斜角对称安装在机身前后两端。该布局兼顾了视野广度与图像清晰度，在系留线缆拖拽导致飞机偏航时可通过双摄互补减少视觉盲区。其余外设（光流模块、TOF传感器等）均遵循对称排布原则，从机械层面最大程度维持整机重心平衡，确保无人机在有线约束条件下依然保持姿态稳定。
3.1.4 重心优化
为优化整机重心分布，电线固定于机架几何中心的最低处，减小了机体转动惯量，使姿态响应更加灵活，同时避免了电线牵扯可能引发的姿态偏移与额外配平负担。核心板居中布置，惯性测量单元尽量靠近机体几何中心，保证所测姿态与机体实际姿态一致；光流传感器与激光测距模块对称布置于机身前后，电源线走线远离光流视场，避免了遮挡可能引发的光流数据突变。结合四电机对称布局，整机几何中心与重心尽可能重合，保证了悬停、跟踪与降落过程中的动态平衡。
3.2无人车机械结构设计
3.2.1整体架构与尺寸设计 
车模为自行改装设计，采用双层架构方案。整车长宽严格控制在赛事规定的30×30cm上限以内，高度不超过30cm。底板尺寸尽量延展至30cm以缩短任务路径时间，同时避免过大导致通过信标时卡滞。双层分离式设计将驱动功能与遮挡功能解耦，既保证了底盘通过性，又为无人机提供了最大化的俯视视野。
3.2.2驱动层设计 
第一层为驱动层，搭载两对无刷电机与两对编码器，轮胎采用麦克纳姆轮。麦克纳姆轮配合运动学解算可实现XY平面全向移动与任意角度转向，适应信标灯位置不确定的追踪场景。底盘整体进行了架高处理，使小车高速通过信标灯时避免底盘剐蹭或卡滞。编码器芯片对准电机内置磁铁并保持适当间隙安装，有效隔离电机高频振动，确保转速反馈准确，为底层速度环PID提供稳定数据支撑。
3.2.3挡板层设计 
第二层为挡板层，采用3D打印成型，兼具遮挡信标灯光与承载核心电路板双重功能。该层结构向四周延展至50×50cm上限，高度紧贴30cm赛事限制——一方面最大化无人机的俯视视野范围，另一方面为系留线缆预留充足的活动余量。核心板放置于此层中心位置。
3.2.4重心优化 
为优化整车重心分布，电池组置于车腹内部最低处，降低了整体重心并减小了转向惯量，使全向移动更加灵活，同时避免了电池外挂可能引发的卡信标风险。结合核心板居中布置，整车几何中心与重心尽可能重合，保证了急启急停和侧向滑移时的动态平衡。


第四章 系统硬件设计
我们主要从系统的稳定性、可靠性、高效性、实用性、简洁等方面来考虑硬件的整体设计。从最初方案设定到最终方案的敲定，我们经历各种讨论与大的改动才有了如下的硬件。
可靠性与稳定性是一个系统能够完成预设功能的最大前提。在原理图与 PCB的设计过程中，我们考虑到各个功能模块的电特性以及之间的耦合作用。对易受干扰的模块做了电磁屏蔽作用，而其他部分则做了相应的接地、滤波、模拟与数字电路的隔离等。
简洁是指在满足了可靠、高效的要求后，为了尽量减轻车模的负载，降低模型车的重心位置，应使电路设计尽量简洁，尽量减少元器件使用数量，缩小电路板面积，使电路部分使电路部分重量轻，易于安装。在设计完原理图后，注重 PCB 板的布局，优化电路的走线，整齐排列元器件，最终做到电路板的简洁。
4.1传感器的选择
4.1.1 IMU的选择
为了获取机体实时的姿态与加速度信息，我们选用了 TDK 公司生产的 ICM42688 六轴惯性测量单元。该传感器特点是噪声低、采样率高、温漂小，能够同时输出三轴角速度与三轴加速度，为姿态解算与加速度融合提供可靠的数据来源。IMU 通过 SPI 协议与单片机进行通信，以毫秒级周期读取数据并完成姿态解算，保证了姿态环控制的实时性。同时，车体航向解算选用了逐飞公司生产的 IMU660RC 陀螺仪模块，其内部集成姿态解算算法，可直接输出航向角，通过串口与单片机进行通信，简化了车端姿态解算的设计。
4.1.2 TOF的选择
为了准确测量无人机的对地高度，我们选用了逐飞公司生产的 DL1A 激光测距模块。该模块特点是测距精度高、响应速度快、光束发散角小，且不易受地面纹理与气流扰动的影响，克服了气压计易受气流与温漂影响、超声波传感器精度低且波束发散角大的缺点。模块通过 IIC 协议与单片机进行通信，测距周期能够满足高度融合算法的需求，为高度闭环控制提供了可靠的观测来源。
4.1.3光流的选择
为了获取无人机的水平位移与速度信息，我们选用了优象电子公司生产的 LC302 光流模块。该模块特点是输出稳定、灵敏度高、抗干扰能力强，能够实时输出像素位移与积分角速度，结合 TOF 测得的对地高度即可换算为水平线速度，为水平定点与跟踪提供速度反馈。模块通过 SPI 协议与单片机进行通信，采样周期短，满足速度融合算法的实时性需求。
4.1.4 摄像头的选择
为了实现对信标灯与车灯等光源目标的识别与定位，我们选用了总钻风全局曝光灰度摄像头。该摄像头特点是全局曝光、运动时无图像畸变，帧率高、感光能力强，适合动态条件与光照变化环境下的目标识别。摄像头通过 SCCB 协议配置参数，图像数据经并行接口送入视觉核心进行处理，识别结果再下发至飞控核心与车控核心，为目标跟踪与协同降落提供依据。
4.1.5 编码器的选择
为了使更加精准的反馈速度，我们选用了逐飞公司生产的磁编码器。该编码器特点是，输出性能稳定，器功耗低，重量轻，抗冲击抗震动，精度高，寿命长，非常实用，可5.0v供电。编码器通过SPI协议与单片机进行通信。

4.2电路模块设计
4.2.1 无人机电调模块设计
四旋翼无人机需独立驱动 4 个无刷电机，整机共采用 24 颗功率 MOS 管构成 4 组三相桥式电路（每相上下管各一颗）。考虑到电机高转速下换相频繁，功率管开关损耗直接影响系统效率与散热，本设计选用英飞凌 CYT2BL3 芯片作为主控，搭配 FD6288Q 栅极驱动芯片，生成精确的六步换相 PWM 时序。功率级选用 TMN3080NF，其具备极短的关断开始时间，可大幅压缩开关过渡区损耗，从而降低温升并延长续航。

第五章 智能车图像设计
5.1 图像采集
系统采用 MT9V03X 全局曝光灰度摄像头作为图像采集器件。全局曝光方式保证同一帧内所有像素在同一时刻感光，避免了卷帘曝光在机体运动或灯光闪烁条件下产生的图像畸变与亮带干扰，尤其适合无人机搭载条件下对发光目标的拍摄。摄像头通过 SCCB 协议完成寄存器配置，图像数据经并行接口以 DMA 方式直接写入帧缓冲区，不占用核心带宽；每帧采集完成后置位帧完成标志，主循环检测到标志后启动一次完整的图像处理流程，实现采集与处理的严格同步，避免处理半帧数据或重复处理同一帧的问题。
5.2 二值化
二值化是目标提取的第一步，其质量直接决定后续连通域分析的可靠性。系统提供两种二值化模式：固定阈值分块二值化与 Otsu 自适应二值化。固定阈值模式针对鱼眼镜头"中心偏暗、边缘过曝"的光学特性，将整幅图像划分为六行八列共四十八个区域，为每个区域单独设定阈值，使同一套参数在不同光照分布下均能正确分离灯光与背景；同时考虑到摄像头以一定俯仰角安装，画面上下区域对应的实际场景亮度分布不对称，程序对行坐标以 y=60 为基准做翻转映射后再查表取阈值，进一步贴合实际光照分布。Otsu 自适应模式则统计整幅图像的灰度直方图，遍历所有候选阈值并计算前景与背景之间的类间方差，取类间方差最大者作为分割阈值，能够在光照整体变化时自动调整分割点，无需人工干预。两种模式互为补充，兼顾了现场稳定性与环境适应性。
5.3. 连通域标记与特征提取
二值化后的图像通过四邻域区域生长法进行连通域标记：逐行扫描寻找未标记的白点作为种子，利用队列进行广度优先搜索，向上、下、左、右四个方向生长，将相互连通的亮像素归为同一区域并赋予统一标号。在生长过程中同步累积每个连通域的一阶矩与二阶矩、像素个数、边界框范围与灰度总和，单遍扫描即可同时获得面积、质心坐标、平均亮度、外接矩形等基础特征。在此基础上，由二阶矩构造协方差矩阵并求解特征值，以两特征值之比作为"圆度"得分，该值越接近 1 说明亮区形状越接近圆形，越接近 0 则越细长，为后续区分圆形信标灯与 V 形车灯提供了关键判据；同时以十字扫描法从质心出发向四个方向延伸，求得亮区的长宽比，作为形状判别的辅助特征。
5.4 信标灯判别
信标灯的判别采用多特征加权评分与多重排除条件相结合的方式。评分方面，以连通域质心到图像中心的距离计算中心度得分，距离越近得分越高，再叠加 PCA 圆度得分构成综合权重，使位于画面中央、形状圆润的亮区获得最高优先级。排除方面，面积过小的连通域视为噪声杂点直接剔除；长宽比过粗或过细的亮区不符合信标灯的圆形特征，予以剔除；填充率过低的连通域说明亮区空心或呈 V 形展开，判定为车灯而非信标；位于画面两侧车灯候选矩形区域内且面积较大的亮区，判定为车灯灯光溢出，予以剔除。此外还设计了眩光聚类检测：当某连通域周围近距离内聚集了多个其他连通域且平均距离小于阈值时，认为该区域是强光源眩光分裂出的多个亮斑，整体置零剔除，避免眩光干扰目标选择。
5.5 车灯判别
车灯为 V 形灯带，其形状特征与信标灯明显不同，因此采用与信标判别相反的判据。程序以 PCA 圆度的反向值作为车灯得分，圆度越低、形状越细长或越呈 V 形展开的连通域得分越高；同时结合质心相对外接矩形中心的偏移量描述 V 形结构的重心偏移特征。在空间约束上，车灯只允许出现在画面下方的两个候选矩形区域内，其余位置的连通域一律不计入车灯候选，避免将远处的信标灯或其他光源误判为车灯；再配合面积下限与圆度上限剔除过小或过圆的区域，最终在剩余候选中选出权重最大的连通域作为车灯目标，输出其质心坐标。
5.6 目标锁定与丢失保护
在多灯共存的场景下，若每帧都直接选择全局权重最大的连通域，目标可能在多个信标之间来回跳变，导致控制量剧烈波动。为此系统设计了"就近锁定"策略：记录上一帧目标位置，每帧优先在上一帧位置附近的匹配距离内寻找权重最高的连通域，只要匹配成功就延续锁定，保证目标连续性；当连续多帧匹配失败、丢失计数超过阈值后，才允许切换为全局最大权重的新目标，实现"短时丢失不跳变、长时丢失可换目标"。当画面中完全不存在有效候选目标时，信标误差置零并复位锁定状态，通知上位控制端执行保护策略；车灯一侧则采取保持策略，丢失时沿用上一有效坐标，避免车端控制量突变，二者策略根据各自控制回路的特点分别设计。
5.7 误差解算与下发
目标坐标确定后，系统进行误差解算：以图像几何中心为基准计算信标灯的横向与纵向像素偏差，作为无人机视觉跟踪的输入；以车灯质心为基准计算信标灯相对车灯的像素偏差，作为无人车跟踪的输入，使车、机各自获得与自身相关的误差量。解算结果按照帧头、数据段、标志位、帧尾的二进制协议帧打包，通过串口分别下发至无人机主控与无人车主控；接收端以状态机方式解析协议帧，并支持断帧重同步，保证通信的可靠性。
第六章 飞行控制系统架构
6.1总体系统设计
飞行控制系统基于双核微控制器构建，其中一个核心承担飞控主控任务，负责传感器采集、姿态解算、控制律计算与电机驱动，另一个核心专门负责视觉图像的采集与目标识别。两个核心之间通过共享内存区域进行数据交互，将视觉处理与飞控计算相互解耦，保证飞控回路的实时性不受图像处理负担的影响。软件整体上采用驱动层、算法层、应用层的分层结构，各层之间通过接口抽象进行解耦，传感器型号更换或算法迭代时只需替换对应模块，不影响整体框架，具有较好的可维护性与可扩展性。
6.2 传感器采集与姿态解算
飞控板集成了惯性测量单元、激光测距、光流、气压计等多种传感器。惯性测量单元提供高频的姿态角、角速度与加速度数据，是姿态解算的核心；激光测距模块提供精确的对地高度；光流传感器提供水平方向的位移信息；气压计作为高度的备用观测。姿态解算采用基于四元数更新的互补滤波方案，上电时先对陀螺仪进行静态零偏校准，并对原始数据做低通滤波以抑制机械振动噪声，再将加速度计观测到的重力向量与陀螺仪积分结果进行融合，输出稳定的横滚、俯仰与偏航角度，同时将机体系加速度转换到地球系，为后续的位置与速度解算提供数据基础。
6.3 多传感器融合设计
针对单一传感器难以同时满足实时性与精度的问题，系统分别针对高度、水平速度和视觉定位设计了三套融合模块。高度融合以加速度积分进行高频预测，以激光测距进行低频修正，并加入跳变检测与滑动窗口滤波，获得平滑可靠的垂直高度与速度。水平速度融合先对光流原始数据做旋转补偿，消除机体自身旋转带来的误读，再结合当前高度换算为线速度，并经过毛刺滤波、滑动平均与死区处理，提高数据质量。视觉定位融合则将地球系加速度映射到像素空间进行预测，以相机回传的目标坐标进行修正，使相机帧率较低或目标短暂丢失时仍能维持连续的位置与速度估计。三套模块的总体思路一致，即高频预测、低频修正、优势互补。
6.4 任务调度架构
系统采用定时中断加时间片轮询的裸机调度方式。惯性测量单元的采集、姿态解算与控制律计算以毫秒级周期执行，保证控制回路的实时性与确定性；激光测距、光流等传感器按照各自的数据速率分配更新周期，融合算法与采集周期同步触发。主循环则负责核间数据接收、视觉数据预处理、调试通信等非实时任务，使实时任务与非实时任务相互分离，避免非实时操作占用控制周期。
6.5 飞行状态机与安全保护
系统以有限状态机管理整个飞行流程，划分为地面待机、起飞、飞行、降落、停机等状态。上电后先在地面状态完成高度基准校准，随后进入起飞状态，目标高度线性抬升，离地稳定后转入飞行状态执行定点悬停与目标跟踪任务。降落过程分为两个阶段，先悬停对准，再线性降低高度，实现平稳着陆。同时系统设置多级安全保护：当姿态角过大或目标姿态与实际姿态偏差过大时触发保护性降落；当机体严重倾斜时立即切断电机输出，防止意外发生。视觉侧同样设有目标丢失保护逻辑，在长时间丢失目标时通知飞控侧执行相应策略。
6.6 核间通信与视觉数据预处理
视觉核与飞控核通过共享内存数组交换数据，双方以握手标志约定读写时序，并配合缓存维护操作保证数据一致性。飞控核接收到视觉数据后，进行零值保持、低通滤波、数据卡死检测、限幅与死区滤波等多级预处理，抑制毛刺与异常跳变后再送入控制回路。通过这一设计，视觉数据的质量波动被隔离在控制回路之外，降低了对飞行稳定性的影响。
6.7 电机驱动与混控输出
飞行器采用四旋翼布局，控制律输出的俯仰、横滚、偏航三个方向的力矩量与高度环输出的总升力按照混控矩阵分配到四个电机，得到各电机的油门指令。总升力中设置重力补偿项以维持悬停平衡，并预留倾角油门补偿接口，用于补偿机体倾斜时垂直方向升力的损失，保证大角度机动下的高度稳定。
6.8 总结
本飞控系统以多传感器融合与分层控制为核心设计思想，感知层提供多源异构数据，融合层兼顾实时性与精度，决策层以状态机管理飞行流程与安全保护，执行层完成姿态稳定与运动控制。整体架构模块化程度较高，各层通过接口解耦，便于传感器替换与算法迭代，为后续控制算法的优化与功能扩展奠定了基础。
第七章 车控系统架构
7.1 总体系统设计
车控系统基于双核微控制器构建，由主控核心承担全部控制任务。底盘采用四轮全向驱动构型，四个直流电机分别配备正交编码器，可实现前进、横移、自旋等全向运动。软件整体上采用驱动层、算法层、应用层的分层结构：驱动层封装电机、编码器、陀螺仪、串口与显示屏等外设；算法层完成运动学解算与闭环控制；应用层负责任务调度、通信解析与状态显示。各模块通过接口结构体解耦，便于替换与调试，具有较好的可维护性。
7.2 传感器采集与状态估计
在传感器配置上，四路编码器实时采集轮速，为速度闭环提供反馈；陀螺仪采集角速度并积分得到车体航向角，上电时进行零点检测与校准，为航向闭环提供反馈。系统按固定周期读取编码器数据，并依据四轮速度的组合关系反解车体当前的平移与旋转运动状态，用于上层控制与状态回传，使车体具备对自身运动的实时感知能力。
7.3 通信与数据预处理
车控核心与视觉板通过串口交换数据，采用帧头、数据段、标志位、帧尾的二进制协议帧格式，接收端以状态机方式解析字节流，支持断帧重同步与越界保护。接收的数据包含车体与信标的位置误差、无人机与信标的位置误差两类量。数据解析后经过多级预处理：零值保持，即数据短暂丢失时沿用上一次有效值；低通滤波，抑制误差量的抖动；卡死检测，即数据长时间不变时认为图像停滞，将误差清零以防车体误动作；以及限幅与最小接受处理，保证进入控制回路的数据平滑可靠。同时车体状态量经串口回传上位机，用于调试观测。
7.4 任务调度架构
系统采用基于定时中断的周期任务调度方式：控制回路以毫秒级周期运行，完成编码器读取、陀螺仪角度解算、控制律计算与电机输出；通信解析任务以稍长周期运行，完成串口帧的接收与预处理；主循环负责显示与调试输出等非实时任务。实时任务与非实时任务相互分离，保证了控制周期的确定性与实时性。
7.5 运动控制架构
车体控制采用分层闭环架构。外层为位置环，以车体与目标的横向、纵向位置误差为输入，输出两个方向的期望平移速度；航向环以目标航向角与当前航向角的偏差为输入，输出期望旋转角速度，保证车体在运动过程中保持设定姿态。中层为运动学解算，依据全向底盘的几何参数，将平移与旋转速度指令分解为四个车轮的目标转速。内层为轮速环，每个车轮独立设置速度控制器，以编码器反馈为输入输出电机驱动占空比，并对积分与输出进行限幅保护。通过这种位置、航向、运动学、速度逐层分解的结构，车体能够在保持自身姿态的同时稳定跟踪目标位置。
7.6 协同策略与安全保护
在空地协同任务中，车体需要与无人机的动作相互配合。系统设置了保持停车保护逻辑：当无人机与信标的误差较大、说明无人机尚未到位时，车体主动停车保持，等待无人机跟上；当误差缩小到阈值以内时自动恢复跟踪，避免车体独自跑远而失去协同。同时在误差预处理环节设置最小接受机制，使车体在接近信标时仍保持一定的运动量，保证能够稳定压过信标区域；误差过大时进行限幅，防止车体运动过快失控。此外系统预留了电机阶跃测试与位置环仿真测试等模式，便于调试阶段逐层验证各控制回路。
7.7 调试与人机交互设计
系统配备显示屏实时显示关键误差量，便于现场观察；同时通过调试串口向上位机输出误差、速度、电机输出等多路状态数据，支持波形观察与参数整定。参数配置集中在参数头文件中管理，控制参数与保护阈值可一处修改，无需改动逻辑代码，提高了调试效率。
7.8 总结
车控系统以分层闭环控制为核心：外层位置环负责目标跟踪，航向环负责姿态保持，运动学解算负责指令分解，内层速度环负责执行精度。配合通信数据的多级预处理与协同保护逻辑，实现了车体在空地协同任务下的稳定跟踪与状态实时输出。整体架构层次清晰，各模块通过接口解耦，便于维护与功能扩展。

第八章 PID控制算法

8.1 PID控制算法介绍 
PID 控制算法是一种基于比例（Proportional）、积分（Integral）、微分（Derivative）三个核心环节的经典控制策略，其核心思想是通过持续监测系统设定值与实际输出值的偏差，并利用偏差的瞬时值、累积值和变化趋势，动态调整控制量以实现被控对象的稳定运行。作为工业控制领域应用最广泛的算法之一，PID 控制以其结构简单、原理直观、鲁棒性强的特点，在温度调节、电机调速、液位控制等众多工业与民用场景中占据核心地位。尽管现代控制理论不断发展，但 PID 控制因其易于实现、适应性强的优势，至今仍是工程实践中解决闭环控制问题的首选方案之一，对提升自动化系统的稳定性与精度具有不可替代的作用。​
8.2 飞行姿态与运动控制
四旋翼飞行器作为一种典型的欠驱动、强耦合非线性系统，其稳定飞行一直是飞控领域的核心问题。为实现机体的姿态稳定与运动控制，采用串级控制架构，这是多旋翼工程实践中广泛应用的有效方案：通过外角度环（PD 控制）实时监测机体姿态角与目标姿态角的偏差，利用比例环节快速响应角度偏移，微分环节抑制角度变化率以增强系统阻尼；再通过内角速度环（PI 控制）对电机力矩进行调节，比例环节快速修正角速度偏差，积分环节消除由电压波动、重心偏移等引起的稳态力矩误差，形成从角度到角速度的闭环控制链路。在垂直方向上，高度环（PI）根据高度偏差输出期望垂直速度，速度环（PD）根据速度偏差输出总升力，实现平稳的爬升、悬停与降落；在水平方向上，位置环（P）将位置偏差转化为期望速度，速度环（PD）再将速度偏差转化为期望倾角，借助飞行器的欠驱动特性以姿态倾斜实现水平运动；视觉跟踪任务中则在像素空间内再设一层位置—速度串级环，将目标像素偏差逐级转化为姿态指令。
图8.2.1 PID示例

在串级控制的设计上，遵循"内环高带宽、外环低带宽"的带宽分离原则：内环作为直接执行环，以更高的频率运行并赋予较高的增益，能够快速抑制电机响应波动、机体振动等内部扰动，相当于为外环提供了一个响应迅速、特性近似理想的受控对象；外环作为指令生成环，以较低的频率运行并赋予较低的增益，输出平滑连续的速度或角度指令，避免指令变化过快激励内环动态、引起系统振荡。本系统中角速度内环的执行周期为角度外环的数分之一，高度速度内环与水平速度内环同样以高于各自外环数倍的频率运行，保证内外环之间具有足够的带宽间隔，使外环在设计指令时可将内环视为近似瞬时跟踪环节，从而获得充足的稳定裕度。同时，各控制回路中引入积分分离、死区处理与输出限幅等工程化保护手段，在大偏差工况下切除积分作用、抑制积分饱和与误输出，保证起飞、降落与跟踪过程中的安全。这种分层控制策略充分发挥了 PD 控制抑制超调、PI 控制消除稳态误差的优势，能在机体受到外部扰动或目标位置变化时快速调整电机输出，确保飞行器稳定飞行，为目标跟踪与空地协同降落等任务奠定了核心基础。

8.3车模速度控制
为了使速度控制精准，我们采用了 PID 控制车速。全向底盘车模的车速是通过运动学解算将车体的平移与旋转速度指令分解为四个车轮的目标转速，而在速度环的具体实现中，选用增量式 PID 作为核心控制算法，以适配系统对动态响应与稳态精度的双重需求，四个车轮各自独立设置增量式速度控制器，控制器输出在历史占空比上累加形成当前驱动量，并施加限幅保护。

控制量增量公式：​
Δu(k)=u(k)−u(k−1)
Δu(k)=Kp*[e(k)−e(k−1)]+Ki*e(k)+Kd* [e(k)−2e(k−1)+e(k−2)]

增量式 PID 在速度环中具有多方面突出优点，其输出为控制量的变化量而非绝对值，当电机转速因负载突变或编码器噪声出现异常偏差时，可通过限制 Δu(k) 的最大值，避免电机输出功率急剧波动，防止转速超调过大或机械结构承受瞬时冲击，尤其适合全向底盘车模这类对动态稳定性要求高的设备；在速度环调试过程中，常需手动干预电机转速，增量式 PID 的控制量基于历史值累加，切换至手动模式时只需记录当前控制量 u(k−1)，切换回自动模式后可无缝衔接，避免因控制量跳变导致的转速冲击，降低调试过程中的系统震荡风险；同时，速度环控制需高频采样，而增量式 PID 仅需存储最近 3 次的转速偏差和上一时刻控制量，相比位置式 PID 减少了积分项累积所需的存储空间，尤其适合算力有限的嵌入式控制器，可提升实时性；此外，其能增强抗积分饱和能力以改善稳态精度，速度环中积分环节可用于消除转速静差，但持续积分易导致"积分饱和"，增量式 PID 可通过限制 Δu(k) 间接限制积分分项的增长速度，结合积分分离策略能在保证稳态精度的同时避免因积分饱和导致的转速超调；最后，比例、微分、积分环节协同作用，实现了响应速度与稳定性的平衡，比例环节快速响应转速偏差，微分环节通过预判偏差变化趋势抑制转速波动，积分环节逐步消除长期存在的微小偏差，使速度环在动态调节和稳态运行中均能保持良好性能，为上层位置环与航向环提供稳定的速度基础。

结论
自报名参加全国大学生智能汽车竞赛以来，我们小组成员从查找资料、设计机构、组装车模、编写程序一步一步的进行，最后终于完成了最初目标，定下了现在这个设计方案。
在此份技术报告中，我们主要介绍了准备比赛时的基本思路，包括机械、电路以及最重要的控制算法的创新思想。
在传感器布局，我们分析了前几届中出现的摄像头安装方法，综合考虑到程序的稳定性、简便性，我们最后敲定了现在的摄像头安装，并通过反复实践决定了摄像头的位置。
在电路方面，我们以模块形式分类，在TC377主控模块、传感器模块、电源模块、电机驱动模块、速度检测模块、辅助调试模块这六个模块分别设计，在查找资料的基础上各准备了几套方案；然后我们分别实验，最后以报告中所提到的形式决定了我们最终的电路图。
在算法方面，我们使用C语言编程，利用比赛推荐的开发工具调试程序，经过小组成员不断讨论、改进，终于设计出一套比较通用的，稳定的程序。在这套算法中，我们结合路况调整车速，做到直线加速，弯道减速，保证在最短时间跑完全程。
在这几个月的备战过程中，场地和经费方面都得到了学校和学院的大力支持，在此特别感谢一直支持和关注智能车比赛的学校和学院领导以及各位指导老师、指导学长，同时也感谢比赛组委会能组织这样一项有意义的比赛。
现在，面对即将到来的大赛，在历时近十个月的充分准备之后，我们有信心在比赛中取得优异成绩。也许我们的知识还不够丰富，考虑问题也不够全面，但是这份技术报告作为我们十个月辛勤汗水来的结晶，凝聚着我们小组每个人的心血和智慧，随着它的诞生，这份经验将永伴我们一生，成为我们最珍贵的回忆。

//缓慢降落函数
static void app_start_protected_landing(void)
{
    landing_start_height = Userfly.height_target;

    if (landing_start_height < 0.0f)
    {
        landing_start_height = 0.0f;
    }

    /*
     * 记录进入降落阶段时的相机基准值，后续只按相对偏移计算
     *，避免每次都对已经处理过的 camera_pos 继续做减法。
     */
    landing_camera_ref_x = data.camera_pos[0];
    landing_camera_ref_y = data.camera_pos[1];

    landing_elapsed = 0;
    landing_stage = 1;

    fly_status = FLIGHT_STATUS_LANDING;
}



void error_check()
{
    // 倾斜过度
    if (ABS(data.angle[0]) > 40 || ABS(data.angle[1]) > 40)
    {
        fly_status = FLIGHT_STATUS_WAIT;
    }
}

void app_event_test(void)
{
    Userfly.height_target = HEIGHT_TARGET;
    error_check();
}

void app_event_wait(void)
{
  
    // 等待指令
}
void app_event_ground(void)
{
    static uint32_t count = 0;
    static float height_sum = 0;
    if (count < 2000)
    {
        height_sum += data.tof_height;
        count++;
    }
    else
    {
        Userfly.height_target = height_sum / 2000.0f + 0.3f;  
        fly_status = FLIGHT_STATUS_TAKEOFF;
        // fly_status = FLIGHT_STATUS_TEST;
        count = 0;
    }
    error_check();
}

void app_event_point(void)
{
    // 定点
}

void app_event_takeoff(void)
{
    Userfly.height_target += 0.0005f;
    Userfly.base_throttle += 10;
    Userfly.height_target = LIMIT(Userfly.height_target, 0, HEIGHT_TARGET);
    Userfly.base_throttle = LIMIT(Userfly.base_throttle, 0, F_MASS);
    if (data.tof_height > 0.8)
    {
        Userfly.height_target = HEIGHT_TARGET;
        Userfly.base_throttle = F_MASS;
        
        // fly_status = FLIGHT_STATUS_POINT;
        fly_status = FLIGHT_STATUS_FLYING;
    }
    error_check();
}

void app_event_flying(void)         //缓慢降落只在无人机飞行的过程才有效
{
    // 摄像头触发慢速降落
    if (data.camera_pos[4] == 1.0f)
    {
        app_start_protected_landing();
        return;
    }
}

void app_event_landing(void)
{
    if (landing_stage == 1)
    {
        // 第一阶段：定点悬停，使用相机传来的位置误差偏移，避免直接降落到车上
        // 这里基于进入降落阶段时的基准值计算相对误差，并加上固定悬停偏移
//        data.camera_pos[0] = (data.camera_pos[0] - landing_camera_ref_x) - 5.0f;        //x轴
//        data.camera_pos[1] = (data.camera_pos[1] - landing_camera_ref_y) - 5.0f;        //y轴
        
        // data.camera_pos[0] = data.camera_pos[0];        //x轴
        // data.camera_pos[1] = data.camera_pos[1];        //y轴
        
        Userfly.height_target = landing_start_height;

        if (landing_elapsed < LANDING_HOVER_TIME_MS)
        {
            landing_elapsed++;
        }
        else
        {
            landing_stage = 2;
            landing_elapsed = 0;
        }
    }
    else if (landing_stage == 2)
    {
        /*
         * 降落过程中始终保持水平姿态和零偏航目标
         */
        Userfly.angle_target[0] = 0.0f;
        Userfly.angle_target[1] = 0.0f;
        Userfly.angle_target[2] = 0.0f;

        /*
         * 按照4000个1ms周期，将目标高度线性降到0
         */
        if (landing_elapsed < LANDING_TIME_MS)
        {
            landing_elapsed++;

            Userfly.height_target =
                landing_start_height *
                (float)(LANDING_TIME_MS - landing_elapsed) /
                (float)LANDING_TIME_MS;
        }
        else
        {
            Userfly.height_target = 0.0f;
            fly_status = FLIGHT_STATUS_WAIT;
            landing_stage = 0;
        }
    }
    else
    {
        // 兜底安全降落
        Userfly.angle_target[0] = 0.0f;
        Userfly.angle_target[1] = 0.0f;
        Userfly.angle_target[2] = 0.0f;
        Userfly.height_target = 0.0f;
        fly_status = FLIGHT_STATUS_WAIT;
    }

    error_check();
}

/**
 * @brief 飞行状态分发（内联）
 *
 * 根据当前飞行状态调用对应的事件处理函数
 */
void fly_status_dispatch(void)
{

    if (fly_status == FLIGHT_STATUS_FLYING ||
    fly_status == FLIGHT_STATUS_TEST)
    {
        if (app_stop_protection_check())
        {
            app_start_protected_landing();
        }
    }


    switch (fly_status)
    {
    case FLIGHT_STATUS_TEST:
        app_event_test();
        break;
    case FLIGHT_STATUS_WAIT:
        app_event_wait();
        break;
    case FLIGHT_STATUS_GROUND:
        app_event_ground();
        break;
    case FLIGHT_STATUS_TAKEOFF: //
        app_event_takeoff();
        break;
    case FLIGHT_STATUS_POINT:
        app_event_point();
        break;
    case FLIGHT_STATUS_FLYING:
        app_event_flying();
        break;
    case FLIGHT_STATUS_LANDING:
        app_event_landing();
        break;

    default:
        break;
    }
}
