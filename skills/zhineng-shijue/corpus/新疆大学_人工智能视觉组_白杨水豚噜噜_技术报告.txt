第一章  引言
本项目参加第二十一届全国大学生智能汽车竞赛人工智能视觉组。该组采用虚实结合、硬件在环的比赛模式，车模在平面场地内自主运动，通过车载无线屏幕获取虚拟游戏的全局俯视图和车模第一视角图像，并完成推箱子闯关任务。参赛车辆采用逐飞科技 M 车模，以 RT1064Lite 核心板为主控制器，搭载两台 OpenART Plus 摄像头和四个 IMU660RC，并使用 DRV8701E 驱动板控制车辆执行机构。
1.1 竞赛任务与设计目标
正式比赛包含三个连续关卡，地图由比赛系统随机选择。车模从车库出发后开始计时，需要识别虚拟地图、可移动箱子、目的地及相关图像或数字信息，规划运动路线并将箱子推到对应目的地。每个关卡至少完成50%的箱子才计为有效完成；每少完成一个关卡罚时300秒，有效关卡中每遗漏一个箱子罚时30秒。设计目标是在满足规则约束的前提下，提高地图解析、目标识别、定位控制和推箱操作的准确性与稳定性。
1.2 主要工作与系统特点
系统采用双 OpenART Plus 摄像头分工处理视觉任务：地图摄像头输出12×16离散地图及车模视觉坐标，模型摄像头识别箱体卡通图案和目的地数字。RT1064Lite 主控以状态机组织三关流程，依据地图类型调用普通推箱、带类别约束推箱或炸弹开墙算法，并将网格路径转换为四轮麦克纳姆底盘的直线、转向和观察动作。底盘控制采用编码器轮速闭环、IMU航向反馈、六状态EKF定位和停车视觉校正。
1.3 技术报告结构
第二章介绍规则约束和总体方案；第三章说明车模、屏幕、标识牌及传感器安装；第四章介绍主控、视觉、姿态和驱动硬件；第五章说明地图识别、目标分类、推箱规划、定位融合、运动控制及异常恢复；第六章记录调试与测试；第七章汇总技术参数；第八章给出结论。
第二章  系统总体方案
2.1 车模设计制作思路
我们参加的是人工智能视觉赛道，采用了比赛方指定的车模即M车模，利用麦轮车的全局移动性能够在不依赖舵机的情况下轻松完成各个方向的行驶。既然车模是指定的，那我们只需要在已有的基础上进行添砖加瓦，我们讲究对称美和空间合理利用，决定在车头和车尾装上DRV8701E驱动板，在小车中心放置主板和陀螺仪，最后利用两根塑料管来支撑识别的tag码。

2.2 实现的技术方案概要
通过网络购买和3D打印实现了整个车的设计。


第三章  机械系统与安装
参赛车辆采用逐飞科技 M 车模。在竞赛规则允许范围内，完成两台 OpenART Plus 摄像头、四个 IMU660RC、RT1064Lite 核心板、DRV8701E 驱动板、无线屏幕和方向标识牌支架的安装与布置。
3.1模型车机械安装及改造
M 车模属于规则允许的成品车模。整车及附属物的地面投影必须控制在35 cm×35 cm以内。车顶需设置磁吸安装结构，两铁片中心间距20 cm（±0.2 cm），现场标识牌安装后高度为15 cm（±0.5 cm），且标识牌与车模之间不得相对移动或转动。待补充整车实测尺寸、支架结构和重心调整。
3.2 传感器设计安装
车辆配置两台 OpenART Plus 摄像头和一个 IMU660RC。地图摄像头应稳定观察约4英寸车载无线屏幕上的俯视图与第一视角；模型摄像头用于获取箱体图案和目的地数字。
3.3 电路板固定及连接
我们一共自制了三块电路板，包括一块主板和两块驱动板，主板通过尼龙柱和螺丝与车进行固定，驱动板则是用扎带进行捆绑固定在车头车尾，主板和驱动板之间通过两根电源线和一根pwm信号线进行连接。
第四章  硬件电路设计
。
4.1 电路设计说明
RT1064Lite 工程采用 Keil MDK 工程文件，启用Arm Compiler 6，目标器件为MIMXRT1064DVL6A。工程从外部NOR Flash启动并配置外部存储区，主程序调用 clock_init(SYSTEM_CLOCK_600M) 将系统时钟设为600 MHz。软件以2 ms基础时基组织轮速控制，以10 ms周期组织里程计、IMU、EKF、位置控制和视觉校正任务。
4.2 视觉传感器接口
地图摄像头连接主控UART1，主控引脚为TX-B12、RX-B13，波特率115200 bit/s；模型摄像头连接UART4，主控引脚为TX-C16、RX-C17，波特率同为115200 bit/s。地图链路使用“AA 55＋2字节长度＋类型/命令＋数据＋异或校验＋0D 0A”的可变长帧；模型链路使用“AA＋命令＋长度＋类别＋累加校验＋55”的短帧。UART1和UART4均使用接收中断，解析器分别采用逐字节状态机完成帧同步、长度与校验判断。
4.3 电机驱动与编码器接口
四路电机PWM均来自PWM2模块，频率17 kHz，方向控制引脚依次为C9、C7、D2和C10，软件输出范围限制在±9000。四路编码器使用QTIMER1/2正交解码：左前C0/C1、右前C2/C24、左后C3/C4、右后C5/C25。编码器参数设为256 PPR、4倍频，减速比按70/30计算，2 ms更新一次轮速。DRV8701E驱动板接收主控PWM与方向信号并驱动四个车轮电机。
4.4 姿态传感器接口
主程序以 IMU660RC_QUARTERNION_120HZ 模式初始化IMU660RC，GPIO中断中调用传感器回调，底盘模块读取航向角和Z轴角速度。启动阶段执行陀螺仪零偏校准；运行阶段将航向角送入EKF，并用于独立转向控制。四个IMU660RC的实物安装位置、是否全部接入主控以及其坐标方向仍需按实际车辆确认。
第五章  微处理控制软件
系统软件由两台 OpenART Plus 视觉程序、RT1064Lite任务状态机、推箱求解器、定位融合模块和底盘控制模块组成。主循环以10 ms节拍服务任务状态，长时间求解期间通过服务钩子维持调试与串口响应。
5.1 软件总体架构
主程序定义空闲、驶出车库、等待地图、航向对齐、目标识别、K1/K2/K3求解、路径执行、结果地图验证、回库和完成等状态。上电后初始化电机、编码器、底盘、IMU和双串口，驶出车库0.30 m后请求首张地图；首张有效地图固定按K1处理，后续地图若含两个炸弹则判为K3，否则判为K2。各关完成或放弃后均返回车库并请求下一张地图，坐标原点在整个连续比赛过程中保持一致。
5.2 地图透视校正与网格重建
地图摄像头在320×240图像中选取 ROI（7，15，296，217），利用四个目标点完成透视校正，再依据3.2 m×2.4 m场地尺寸划分为16列×12行网格，每格对应0.2 m×0.2 m。程序在每个格子内部取5×5个采样点并转换到 LAB 色彩空间，分别统计围墙、空地、黄色箱子、红色炸弹和粉紫色目的地的命中数；彩色目标至少命中8个采样点才被接收，否则在围墙与空地之间比较，无法确定时默认按围墙处理。
5.3 静态地图多帧融合
收到建图命令后，摄像头先等待80 ms，再连续采集3帧地图并要求同一格至少有2帧一致。小车位置不写入静态地图，其所在格按空地参与投票；地图最外圈强制设置为围墙。若三帧分类互不一致，则保守地将该格设置为围墙。主控收到地图后再次检查箱子数、目标数、炸弹数及数组溢出标志；普通地图要求箱子数与目标数相等且非零，K3地图要求炸弹数量符合程序约束，不合格帧最多进行6次有界重试。
5.4 车模检测、坐标系与视觉校正
车模由P2、P4两种颜色标记联合检测，通过候选色块尺寸、长宽比、颜色纯度、间距及几何关系筛选中心。首次建图请求触发视觉原点初始化，连续5帧中心波动不超过5像素后锁定；每次位置请求收集最多8个请求后的有效中心并求平均。主控将摄像头返回的“前进为X正、左侧为Y正”的厘米坐标换算为米，并在车辆停止、视觉数据不超过250 ms且坐标接近当前目标时才执行校正；一般EKF直接校正还要求位置跳变量不超过0.06 m、车速不高于0.13 m/s，炸弹动作期间暂时屏蔽视觉更新。
5.5 双模型目标分类与主控交互
模型摄像头加载 /sd/model1.tflite 和 /sd/model2.tflite，将画面缩放为128×128，分别识别10类卡通图案和数字0—9。单帧最高得分低于0.6返回0xFF，标签表外类别返回0xFE；请求后密集采集7帧，某一类别占全部采集帧比例超过50%才作为结果。主控对箱体发送0x01请求并期待0x81回复，对目标发送0x02请求并期待0x82回复；单次识别最多发送2次请求，间隔3 s，总超时6 s。错误类别、低置信度和不满足全局数量约束的结果会触发重试、保留对象替换或UNKNOWN通配处理。
5.6 地图解析与任务数据结构
主控将192个ASCII地图元素解析为12×16占据栅格，分别保存车模起点、最多14个箱子、14个目标和2个炸弹。围墙和炸弹在规划网格中视为不可通行，箱子与目标坐标另存，目标类别状态使用UNSEEN（0xFD）、NONE（0xFE）和UNKNOWN（0xFF）表示未观察、无类别和不确定。路径数组上限为400个网格节点，每个节点除行列坐标外还可标记推箱、炸弹、观察、转向或K2试探动作。
5.7 基础路径搜索与代价函数
空车移动和单箱推动均采用带航向状态的图搜索。搜索状态包含网格行列和行进方向，使用二叉堆维护最小代价；代价定义为“移动格数＋控制段数×2”，在路径长度接近时优先减少转向和分段次数。推箱搜索先规划车辆到箱后站位，再检查箱体下一格、其他箱子、围墙以及可能吸收箱子的目标格。程序同时设置死角、2×2冻结结构和目标兼容性检查，避免把箱子推入不可恢复状态。
5.8 K1与K2动态推箱求解
K1将所有箱子和目标视为无类别对象，综合采用快速贪心种子、依赖感知的可行解搜索以及固定内存加权动作搜索，在3 s预算内选择较短且控制段较少的完整方案。K2在几何可行性的基础上加入箱体图案与目标数字的匹配约束；程序先识别目标、再识别箱子，并通过类别多重集可行性、唯一匹配消元和forced_match约束减少不必要识别。K2求解预算默认8 s，搜索过程预留精确阶段和最后机会窗口，并在求解期间周期输出存活信息。
5.9 观察点与识别顺序优化
每个待识别对象最多生成4个相邻观察候选点，候选必须可达且能面向目标。程序以目标优先、箱子随后为基本流程，在同列对象及观察侧选择上进行优化：对象数不超过8时采用位掩码动态规划精确求解，更大任务集使用宽度48的束搜索和空间代价排序。代价同时考虑移动距离、方向变化、独立旋转和控制指令数；若规划路径本身经过可观察位置，则插入内联识别标记，减少额外绕行。每阶段保留一个可由类别计数消元的对象，降低模型请求次数。
5.10 K3炸弹开墙与后续规划
K3先对每个炸弹枚举候选围墙，候选评分综合炸弹到墙的推行距离、围墙与车模/箱子/目标的相关距离及爆炸可清除墙格数量。求解器在4 s总预算内组合炸弹顺序与目标墙，模拟炸弹推到墙后清除其3×3邻域内的墙体，并以剩余箱子是否仍可求解作为可行性条件。实体执行到炸弹动作末端后等待1.5 s让场景刷新，并在200 ms内屏蔽视觉校正；爆破路线中尽量选择能够顺带观察箱子或目标的自然停车点，之后进入带类别约束的箱体推送。
5.11 路径压缩与动作执行
求解器输出的相邻网格节点先转换为0.2 m坐标，再合并同方向连续节点，保留推箱末端、爆破、识别和转向边界。长度达到4格即0.8 m的直线段被视为长距离运动，控制器在车头和车尾两个朝向中选择转角较小者，先完成航向调整再平移；短距离仍发挥麦克纳姆底盘全向运动能力。每一运动段设置与距离相关的1.8—5.5 s超时，接近目标0.02 m时可提前结束；停车后请求视觉位置确认，失败时最多重试10次或重新获取结果地图。
5.12 四轮速度闭环与底盘运动学
底盘根据麦克纳姆轮逆运动学将车体速度vx、vy、wz分配到四轮。轮径按0.060 m、半轮距0.0925 m、半轴距0.110 m计算，线速度上限1.35 m/s，角速度上限4.6 rad/s。四轮转速以500 Hz更新并使用系数0.25的一阶低通滤波；每轮采用增量式PID（Kp=400、Ki=10000、Kd=0.5）叠加静摩擦和转速比例前馈，PWM限幅±9000，并设置输出滤波与斜坡限制。
5.13 EKF定位与位置控制
EKF状态量为[x，y，θ，vx，vy，wz]，由四轮速度经麦克纳姆正运动学预测位姿，并以IMU航向角进行带3σ门限的观测更新。位置控制在世界坐标与车体坐标之间转换误差，对vx、vy和航向分别采用位置式PID；根据目标距离选择长、中、近三类速度曲线，使用S形起步、制动距离限速、最低可动速度和横向误差限幅。到达条件为位置误差小于0.03 m、航向误差小于0.03 rad且速度稳定连续6个周期。独立转向采用PD、角速度前馈、变化率限制和静止判据。
5.14 闯关状态机与异常恢复
主状态机在地图接收后统一将航向校正到0 rad，再进入对应关卡。地图、位置和模型请求均带超时与重试；长时间求解仍定期服务通信。最后一次推箱后重新请求结果地图：若无箱子和目标则回库；若仍有可解任务则刷新车模位置、重新识别或重新规划；若多次地图异常、模型不一致、爆破或推箱求解失败，则停止当前任务，通过空地路径绕开墙体、箱子和炸弹返回两个候选车库入口中较近者，等待3 s后进入下一关，避免盲目穿墙。

第六章  开发工具、制作、安装、调试
工程具备分模块日志、串口计数器、求解计时和状态心跳，可按视觉、通信、规划、定位、底盘及整车流程逐级开展联调验证。
6.1 开发环境与工具
RT1064Lite端使用Keil MDK工程、Arm Compiler 6和逐飞/NXP SDK，目标器件MIMXRT1064DVL6A；OpenART Plus端使用sensor、image、tf和machine.UART等模块。主控日志可输出当前关卡、状态、识别阶段、执行步数、串口帧计数、错误计数和EKF坐标，求解器可报告用时、展开状态和回退情况。
6.2 视觉与通信调试
地图摄像头联调覆盖ROI、透视点、LAB阈值、格内采样、三帧投票、P2/P4配对和位置平均；模型摄像头联调覆盖两套模型、0.6阈值、7帧一致性及0xFE/0xFF状态。主控端通过UART1/UART4接收中断和状态机解析器完成双视觉数据接收，地图链路与模型链路分别运行，互不干扰。
6.3 规划算法验证
K1、K2、K3规划模块均设置了对应的地图边界与异常处理逻辑。K1检查箱子到达目标及死角规避；K2处理图案—数字类别约束、消元结果和UNKNOWN通配回退；K3处理炸弹目标墙、3×3墙体清除、后续箱体可解性和观察点覆盖。输出路径通过软件状态回放逐步检查，确保车辆和箱体不穿墙、不重叠，并保持目标覆盖完整。
6.4 底盘与定位调试
底盘联调依次覆盖四路电机方向、17 kHz PWM、编码器正负号、500 Hz轮速计算、直线行驶、原地转向、横移、纵移及推箱动作。定位模块结合四轮里程计、IMU航向和视觉停车校正运行，X/Y里程计比例表按运动距离分段配置。
6.5 整车联调与结果分析

B.1 地图数据解析函数
void parse_2d_map(char map_data[MAX_ROWS][MAP_COLS + 1], int car_r, int car_c, MapContext *ctx)
{
    memset(ctx, 0, sizeof(MapContext));
    for (int r = 0; r < MAX_ROWS; r++) {
        for (int c = 0; c < MAP_COLS; c++) {
            char ch = map_data[r][c];
            if (ch == 'W' || ch == '#') ctx->grid[r][c] = 1;
            else if (ch == 'B' || ch == '$') {
                ctx->grid[r][c] = 0;
                if (ctx->box_num < MAX_BOXES) {
                    ctx->boxes[ctx->box_num][0] = r;
                    ctx->boxes[ctx->box_num][1] = c;
                    ctx->box_ids[ctx->box_num] = SOKOBAN_ID_UNSEEN;
                    ctx->forced_match[ctx->box_num] = -1;
                    ctx->box_num++;
                } else ctx->box_overflow = 1;
            } else if (ch == 'G' || ch == '.') {
                ctx->grid[r][c] = 0;
                if (ctx->target_num < MAX_BOXES) {
                    ctx->targets[ctx->target_num][0] = r;
                    ctx->targets[ctx->target_num][1] = c;
                    ctx->target_ids[ctx->target_num] = SOKOBAN_ID_UNSEEN;
                    ctx->target_num++;
                } else ctx->target_overflow = 1;
            } else if (ch == '*') {
                ctx->grid[r][c] = 1;
                if (ctx->bomb_num < MAX_BOMBS) {
                    ctx->bombs[ctx->bomb_num][0] = r;
                    ctx->bombs[ctx->bomb_num][1] = c;
                    ctx->bomb_num++;
                } else ctx->bomb_overflow = 1;
            } else {
                ctx->grid[r][c] = 0;
            }
        }
    }
    seal_outer_boundary(ctx->grid);
    ctx->car_r = car_r;
    ctx->car_c = car_c;
    ctx->start_r = car_r;
    ctx->start_c = car_c;
}
B.2 麦克纳姆底盘速度解算函数
void Chassis_SetSpeed(float vx, float vy, float wz)
{
    float linear_mag = sqrtf(vx * vx + vy * vy);
    if (linear_mag > TRAJ_MAX_V) {
        float scale = TRAJ_MAX_V / linear_mag;
        vx *= scale;
        vy *= scale;
    }
 
    if (wz > TRAJ_MAX_W) wz = TRAJ_MAX_W;
    if (wz < -TRAJ_MAX_W) wz = -TRAJ_MAX_W;
 
    chassis.vx = vx;
    chassis.vy = vy;
    chassis.wz = wz;
 
    float l_plus_w = HALF_WIDTH + HALF_LENGTH;
    float v_lf = vx - vy - wz * l_plus_w;
    float v_rf = vx + vy + wz * l_plus_w;
    float v_lb = vx + vy - wz * l_plus_w;
    float v_rb = vx - vy + wz * l_plus_w;
    float k = 60.0f / (M_PI * WHEEL_DIAMETER);
 
    chassis.wheels[MOTOR_LF].target_rpm = v_lf * k;
    chassis.wheels[MOTOR_RF].target_rpm = v_rf * k;
    chassis.wheels[MOTOR_LB].target_rpm = v_lb * k;
    chassis.wheels[MOTOR_RB].target_rpm = v_rb * k;
}
