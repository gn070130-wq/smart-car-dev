第一章 引言
1.1 智能车大赛背景
全国大学生智能汽车竞赛以自动控制、嵌入式系统、传感检测和人工智能
等技术为基础，要求参赛队伍围绕指定车模完成机械结构、硬件电路、控制软
件和视觉算法的综合设计。第二十一届人工智能视觉组进一步引入虚实结合任
务，车模需要从车载显示屏获取虚拟环境信息，并在真实场地中完成与虚拟任
务相对应的运动控制。
1.2 智能车制作概述
本队以逐飞科技M1 麦克纳姆轮车模为机械平台，使用一块逐飞RT1064 核
心板及一块自制主控板完成状态融合、路径规划和运动控制；两块自制双路驱
动板分别驱动四个RC380 有刷电机；两套OpenART Plus 采集车载屏幕提供的两
路画面；IMU963RA 用于获取车体姿态信息。车载5 英寸IPS 显示屏采用磁吸
方式固定，动力系统使用3300 mAh 的3S 锂电池。
整车设计围绕屏幕画面采集、虚拟元素识别、地图状态构建、任务决策、
路径规划和麦克纳姆轮底盘控制展开。由于当前仍处于系统完善阶段，本报告
只写入已经由实物、BOM 和产品资料确认的内容，整车技术参数、算法性能和
比赛任务完成率将在定型测试后据实补充。
1.3 本文结构
本文沿用洛阳理工学院上一届智能视觉组技术报告的组织方式，并结合本
届任务变化增设路径规划与任务决策章节。第二章说明任务及总体方案；第三
章介绍机械结构；第四章说明硬件电路；第五章介绍控制软件；第六章重点介
绍路径规划；第七章介绍视觉软件；第八章记录制作和调试过程；最后给出结
语、参考文献及附录。

第二章 设计方案
2.1 人工智能视觉组任务
依据第二十一届人工智能视觉组比赛细则及修改补充，比赛采用虚实结合
方式。车模在实际平面场地内运动，通过车载屏幕显示的俯视图和第一视角画
面获取虚拟场景信息，并依据识别结果完成定位、规划和推箱子等任务。虚拟
场景中的围墙、箱子、目的地和其他任务元素由比赛软件给出，车模的真实运
动与虚拟场景状态共同构成任务闭环。
规则补充对车模方位标识牌、场地定位标识和车载显示设备提出了明确要
求。方位标识牌尺寸为30 cm×15 cm，采用磁吸结构安装，两铁片中心距为20 
cm±0.2 cm，安装高度为15 cm±0.5 cm，并保证标识牌不能相对车体转动。场地
角点AprilTag 定位码高度按补充规则设置。
2.2 实行方案
本队采用“视觉前端—中央主控—四轮执行”的总体方案。两套OpenART 
Plus 分别面向车载屏幕的两路画面，对显示区域进行采集和预处理；识别结果
经串行通信送入RT1064 核心板。主控根据任务状态建立场景信息，结合路径
规划结果和IMU963RA 姿态数据进行麦克纳姆轮运动学解算，再通过两块双路
驱动板控制四个RC380 电机。
机械部分以M1 麦克纳姆轮底盘为基础，将屏幕、双视觉模块、主控板、
两块驱动板和电池分区固定。屏幕采用磁吸安装并通过框架限位；方位标识牌
支架按照本届补充规则预留磁吸位置和安装高度。电源部分由3S 锂电池向电机
驱动和主控板供电，主控板再产生5 V 和3.3 V 电源。该方案便于分别调试视觉、
规划、控制和硬件模块，也便于比赛现场快速拆换。

3.1 机械安装
3.1.1 车模底盘
本车采用逐飞科技M 麦克纳姆轮裸车模。产品资料给出的裸车外廓尺寸为
282 mm×210 mm×63 mm，底板尺寸为282 mm×120 mm，裸车质量约930.8 g。

地转向等全向运动。单轮直径为63 mm、宽度为32.5 mm；电机端14 齿主动齿
轮与70 齿从动齿轮啮合，理论传动比约为5 1∶ 。

3.1.3 车载屏幕固定

3.2.2 IMU963RA 安装
IMU963RA 通过主控板预留的姿态传感器接口接入。模块采用刚性固定，

3.3 电路板安装

板。主控板承载核心板并连接视觉、IMU、编码器和驱动信号；两块驱动板分
别承担两个电机通道。电池和功率板尽量布置在较低位置，大电流电机线与视
觉通信排线分开走线，减少电磁干扰和结构晃动。各板卡通过安装孔、支柱和
支架固定，并在插接件附近预留拆装空间。

第四章 硬件电路
4.1 RT1064 核心板及主控板
整车中央控制器采用逐飞科技 RT1064 核心板，核心器件为NXP i.MX 
RT1064 系列微控制器，采用Arm Cortex-M7 内核，最高主频600 MHz。核心板
以排针方式安装在自制主控板上。主控板集成电源输入与开关、5 V 和3.3 V 稳
压、按键、编码器接口、电机控制信号接口、屏幕与串口接口、姿态传感器接
口及SPI 无线模块接口。
RT1064 接收两套OpenART Plus 的识别结果和IMU963RA 的惯性数据，统
一完成任务状态管理、路径决策、麦克纳姆轮运动学解算和四路电机闭环控制
OpenART Plus 作为独立视觉前端，可降低主控直接处理原始图像的负担。

4.2 电源电路
动力电源采用3300 mAh 的3S 锂电池，标称电压11.1 V、满充电压12.6 V。
电池电压分别送往两块电机驱动板和主控板电源变换电路。主控板 5 V 电源以
SCT2450 降压器件、4.7 μH 电感和SS54 肖特基二极管为核心，3.3 V 电源采用
RT9013-33GB 稳压器，并在输入、输出及关键器件附近配置储能与去耦电容。
车载屏幕使用自身内置电池供电。
根据现有BOM 统计，一块主控板电容总容量约513.2 μF，一块驱动板约
247.4 μF；车上实际使用一块主控板和两块驱动板，因此三块自制 PCB 的电容
总容量约为1008.0 μF。该数值不包含RT1064 核心板、两套OpenART Plus、
IMU963RA 和车载屏幕内部电容，最终技术检查值应按组委会口径复核。

4.3 电机驱动
整车使用两块相同的双路电机驱动板。每块板包含两颗DRV8701E 栅极驱
动器和八颗TPH1R403NL N 沟道功率MOS 管，可形成两组独立全桥通道；两
块板合计使用四颗DRV8701E 和十六颗功率MOS 管，对应四个RC380 有刷直
流电机。主控板向各驱动通道输出 PWM、方向和使能信号，SN74HC125PWR

mA、堵转电流小于14.4 A。14.4 A 为单个电机的堵转电流参数，不代表驱动板
可长期承受该电流。实际PWM 频率、连续电流、峰值电流及保护阈值应结合

4.5 PCB 设计

5.1 整体流程

主循环只处理非实时事务，包括视觉数据包分发、地图求解、重规划请求、

5.2 底盘运动学与闭环控制
底盘以车体坐标系横向速度vx、纵向速度vy 和航向控制量wz 为输入。四
轮目标速度按L1=vy+vx+wz、L2=vy-vx+wz、R1=vy-vx-wz、R2=vy+vx-wz 计算。
编码器反馈反算为vy=(L1+L2+R1+R2)/4、vx=(L1+R2-L2-R1)/4，再利用 IMU
航向角将车体速度转换到全局坐标系，并以5 ms 周期积分更新车辆位置。旋转
控制将A、B、C、D 四个方向分别映射到0°、-90°、90°和-180°，角度误差小
于1°时判定旋转完成。
Control_Task()依次完成编码器采样、全局里程更新、移动/旋转/视觉速度模
式调度、软启动、航向位置式PID、麦克纳姆轮解算和四轮增量式PID 输出。
电 机 PWM 频 率为 17  kHz ， 占空比 限幅为 10000 。 当前启 用
PID_MOTION_PROFILE_CURRENT：网格尺寸0.2 m，X/Y 最大速度分别为50
和40，X/Y 减速距离分别为12 cm 和18 cm，到达阈值为2 cm；编码器基础换
算系数为0.01565，X/Y 里程修正系数分别为0.9663 和1.0297。上述参数来自当
前工程宏定义，最终提交前仍应与实际参赛固件核对。
5.3 路径规划与任务决策

组上限为1024。通用A*模块支持不超过32×32 的搜索地图，采用四邻域扩展

void PIT_IRQHandler(void)
{
    if (pit_flag_get(PIT_CH0)) {
        pit_flag_clear(PIT_CH0);
        static int imu_t;
        get_imu_data();
        if (++imu_t % 5 == 0) {
            imu_t = 0;
            imu_task();
        }
    }
    if (pit_flag_get(PIT_CH1)) {
        pit_flag_clear(PIT_CH1);
        Control_Task();
    }
    if (pit_flag_get(PIT_CH2)) {
        pit_flag_clear(PIT_CH2);
        key_scanner();
    }
    __DSB();
}

uint16_t f_score(uint16_t idx)
{
    Node *n = &pool[idx];

    uint16_t dy = n->y > target.y ? n->y - target.y : target.y - n->y;

C.1 视觉数据包分发（code/Visual.c）
void handle_visual_packet(const char *packet)
{
    int len = visual_packet_length(packet);
    if (len == 0) return;
    if (packet[0] == 'M' && packet[1] == ':') {
        if (packet[2] != '\0') {
            if (!parse_car_pixel_packet(&packet[2]))
                parse_camera_packet(&packet[2]);
        }
    }
    else if (packet[0] == 'G' && packet[1] == ':') {
        solve_map_packet(&packet[2]);
    }
    else if (is_utf8_map_prefix(packet)) {
        solve_map_packet(&packet[7]);
    }
    else if (Visual_IsMapPacket(packet)) {
        solve_map_packet(packet);
    }
}
