第一章  引言
1.1  竞赛背景与研究意义
全国大学生智能汽车竞赛是由教育部高等学校自动化类专业教学指导委员会主办的面向全国大学生的创意性科技竞赛，是教育部"质量工程"重点资助的国家级大学生竞赛项目之一。竞赛要求参赛队伍在统一的模型车平台基础上，自主设计并制作能够自主识别赛道、自动循迹行驶的智能汽车模型，综合考察参赛学生在自动控制、嵌入式系统、传感器技术、计算机视觉、机械设计等多学科领域的知识运用能力与工程实践能力。
智能汽车技术融合了环境感知、决策规划、运动控制等核心技术，是当前人工智能与自动驾驶领域的重要研究方向。通过参与智能汽车竞赛，参赛学生能够将课堂所学的控制理论、信号处理、电路设计等理论知识应用于实际工程系统，培养系统思维与工程创新能力。本报告围绕第二十一届全国大学生智能汽车竞赛四轮组赛题，详细阐述基于 NXP i.MX RT1064 微控制器的四轮独立驱动智能车的设计方案、实现过程与调试经验。
1.2  国内外研究现状
在智能车竞赛领域，国内外高校与研究机构开展了大量研究工作。早期智能车多采用光电传感器阵列进行赛道检测，具有响应速度快、成本低的优势，但检测距离有限、信息量少。随着图像处理技术的发展，基于 CMOS 摄像头的视觉方案逐渐成为主流，能够获取更丰富的赛道信息，实现更优的路径规划与速度控制[1]。
在控制算法方面，经典 PID 控制因其结构简单、鲁棒性好而被广泛采用。近年来，模糊控制、神经网络、模型预测控制（MPC）等先进控制策略也被引入智能车控制中，在复杂赛道条件下展现出更好的适应性[2]。在硬件平台方面，从早期的 8 位单片机逐步发展到以 ARM Cortex-M 系列为代表的 32 位高性能微控制器，NXP i.MX RT 系列跨界处理器凭借其高达 600MHz 的主频与丰富的外设接口，为复杂视觉算法的实时运行提供了硬件保障[3]。
本设计在总结往届参赛经验的基础上，采用摄像头视觉方案与四轮独立驱动架构，结合经典 PID 与前馈控制策略，力求在稳定性与速度之间取得平衡。

本技术报告共分为八章，各章内容安排如下：

第二章  系统总体方案设计
2.1  设计思路与技术路线
本智能车系统的设计目标是在保证稳定运行的前提下，尽可能提高平均速度，实现对赛道的快速、准确循迹。整体设计遵循"模块化、分层化"的原则，将系统划分为机械结构、硬件电路和控制软件三个相对独立又紧密协作的子系统，便于分别设计、调试与优化。
技术路线如下：以 NXP i.MX RT1064 微控制器为核心，通过 CMOS 摄像头采集赛道图像，经图像处理算法提取赛道中线与弯道信息；根据路径偏差与曲率，采用 PID 算法控制舵机转向，同时采用速度闭环控制四个驱动电机；通过编码器反馈实现精确的速度控制与里程计功能。系统设计中注重电源稳定性、信号完整性与电磁兼容性，确保在高速运行条件下系统可靠工作。
2.2  系统总体架构
智能车系统总体架构如图 2.1 所示，主要由以下五个功能模块组成：
（1）主控模块：以 i.MX RT1064 为核心，负责图像采集、图像处理、决策规划与运动控制，是整个系统的"大脑"。
（2）传感器模块：包括 CMOS 摄像头（赛道检测）、光电编码器（速度反馈）、陀螺仪/加速度计（姿态检测，可选）等。
（3）执行器模块：包括四路直流驱动电机（四轮独立驱动）、舵机（转向控制）、蜂鸣器（状态提示）。
（4）电源管理模块：将 7.4V 锂电池电压转换为 5V、3.3V 等多路稳压输出，为各模块供电。
（5）人机交互与通信模块：包括按键、拨码开关、LED 指示、无线串口（参数调试与数据回传）。

第三章  机械结构设计与安装
3.1  车模选型与机械改造
本设计采用竞赛组委会指定的 B 型车模（四轮独立驱动模型）作为基础平台。原车模配备四个直流减速电机与一个舵机，具有结构紧凑、传动效率高的特点。为适应高速循迹需求，对车模进行了以下改造：
（1）底盘加固：在底盘关键受力部位加装碳纤维板，提高整车刚性，减少高速过弯时的底盘形变。
（2）轮胎处理：对轮胎进行打磨处理，增大接地面积并提高抓地力；根据赛道表面状况选择合适的轮胎硬度。
（3）悬挂调整：调整前后悬挂的弹簧刚度与阻尼，使车模在直道加速与弯道行驶时均具有良好的抓地性能与姿态稳定性。
（4）重心优化：通过合理布置电池、电路板与传感器的位置，将整车重心控制在几何中心附近且尽可能低，以减小过弯侧倾。
（5）舵机改装：更换金属齿轮舵机，提高转向响应速度与定位精度，确保在高速行驶时转向机构的可靠性。
3.2  传感器安装布局
传感器的安装位置与角度直接影响检测精度与系统响应。本设计的传感器布局遵循"视野最大化、重心最优化"的原则：
（1）摄像头安装：采用云台支架将 OpenArt Plus 摄像头模块固定于车模前部上方，镜头朝前下方倾斜约 15°~20°，使视野覆盖车前 30cm~120cm 范围的赛道。摄像头高度约 15cm，确保既能看到足够远的赛道以提前预判弯道，又能保证近处赛道的检测精度。OpenArt Plus 是逐飞科技推出的智能车专用视觉模块，集成图像传感器与处理电路，支持全局快门模式，有效消除高速运动中的图像模糊。
（2）编码器安装：在四个驱动电机的输出轴上分别安装逐飞科技 mini 增量式编码器（1024 线/转，带方向正交解码），通过联轴器与电机轴连接。编码器的 A/B 相输出信号直接接入 MCU 的正交编码器接口（ENC），实现四轮速度的独立检测与闭环控制。该编码器体积小巧，测速精度高，非常适合智能车模型的紧凑安装空间。
（3）姿态传感器（可选）：在电路板中心位置安装六轴 IMU（MPU6050），用于检测车模的横滚角与俯仰角，辅助姿态控制与异常检测。
3.3  电路板固定与系统连接
主控电路板采用 4 层 PCB 设计，尺寸为 80mm×60mm，通过铜柱固定在车模底盘中部。电路板与各模块的连接如下：
（1）电源连接：7.4V 锂电池通过 2.54mm 间距 2P 插座接入电路板电源输入端，经电源管理模块分配至各子系统。
（2）电机连接：四路电机通过 MCX 接口（2.54mm 4P 排针）连接至 DRV8870 驱动输出端，每路电机独立控制。
（3）摄像头连接：通过 8P 排针（SW184）连接 OpenArt Plus 摄像头模块，包含 SCCB 配置总线与像素数据总线。
（4）舵机连接：舵机信号线接入 MCU 的 PWM 输出引脚，舵机电源经 HY19P03D 开关控制后由独立稳压支路供电。
（5）无线模块连接：通过 PZ254V-11-08P 插座连接蓝牙/无线串口模块，用于参数调试与运行数据回传。
所有连接线均采用扎带固定，避免在车模高速运动过程中因晃动导致接触不良。

第四章  硬件电路设计
本章详细介绍智能车主控板的各功能电路模块设计。主控板基于 NXP i.MX RT1064 微控制器设计，集成了电源管理、电机驱动、传感器接口、人机交互与通信等功能，电路原理图详见附录 A。
4.1  电源管理电路
电源管理是智能车系统稳定运行的基础。本设计采用 7.4V 锂电池供电，电源管理电路分为三级稳压结构，如图 4.1 所示。
第一级为双路 TPS5430DDCR 同步降压转换器，将 7.4V 电池电压降至 5V，每路最大输出电流 3A。其中一路为电机驱动与舵机供电（+5V_PERIPHERAL），另一路为数字电路供电（+5V）。TPS5430 具有宽输入电压范围（5.5V~36V）、高效率（典型 90%以上）及过流、过热保护功能，适合电池供电的电机驱动应用。电路中输入端采用 100μF 电解电容与 10μF 陶瓷电容组合滤波，输出端采用 100μF 电解电容与 1μF 陶瓷电容滤波，电感选用 10μH 功率电感。
第二级为双路 RT9013-33GB 低压差线性稳压器（LDO），将 5V 降至 3.3V，每路最大输出电流 500mA。其中一路为 MCU 内核与外设供电（VCC_3V3），另一路为摄像头与传感器供电（VCC_A）。RT9013 具有低噪声（30μVrms）、高电源抑制比（PSRR 70dB@1kHz）的特点，能够为对电源噪声敏感的模拟电路与图像传感器提供干净的电源。每路 LDO 输入端与输出端均配置 10μF 与 0.1μF 去耦电容。
此外，舵机由 +5V_PERIPHERAL 直接供电，确保舵机大电流工作时不影响数字电路电源稳定性。电源输入端口采用 2.54mm 间距 2P 插座，连接 7.4V 锂电池，输入端配置 100μF 电解电容与 10μF 陶瓷电容进行滤波，抑制电池内阻引起的电压波动。
图 4.1  电源管理电路框图
4.2  MCU 最小系统
主控芯片采用 NXP i.MX RT1064（MIMXRT1064CVL5A），基于 ARM Cortex-M7 内核，主频高达 600MHz，内置 1MB 系统 SRAM 与 4MB QSPI Flash，具有丰富的外设接口（GPIO、UART、SPI、I²C、ADC、PWM、ENC 等），完全满足智能车控制的计算与接口需求。
MCU 最小系统包括电源去耦、复位电路、时钟电路与调试接口。电源引脚均配置 0.1μF 去耦电容，关键电源引脚额外配置 10μF 钽电容。复位电路采用 RC 复位与按键复位组合设计。时钟电路采用 24MHz 无源晶振作为外部时钟源，经内部 PLL 倍频至 600MHz 系统时钟。调试接口采用标准 10-pin Cortex Debug 接口（SWD），支持程序下载与在线调试。
MCU 的 I/O 引脚分配如下：摄像头接口使用 CSI 外设（8 位数据总线 + PCLK/VSYNC/HREF），四路电机驱动的 PWM 控制信号经 SN74HC245 缓冲后接入 DRV8870 的 IN1/IN2 引脚（共 8 路 PWM），四路编码器使用 4 组 ENC 正交编码器接口，舵机使用 1 路 PWM，按键与拨码开关使用 GPIO 输入，无线串口使用 LPUART 外设。
4.3  电机驱动电路
电机驱动电路采用四路 DRV8870DDAR H 桥驱动器，实现四轮独立驱动控制。DRV8870 是一款集成式有刷直流电机驱动器，单通道峰值输出电流 3.6A，工作电压 6.5V~45V，支持 PWM 调速与相位/使能两种控制模式。
本设计中每片 DRV8870 驱动一个电机，四路驱动芯片分别对应左前、右前、左后、右后四个车轮。MCU 输出的 8 路 PWM 控制信号（每路电机 2 路）经 SN74HC245PWR 八总线收发器缓冲后接入 DRV8870 的 IN1/IN2 引脚，通过调节 PWM 占空比控制电机转速与转向。SN74HC245 具有三态输出，DIR 引脚接高电平配置为 A→B 方向传输，OE 引脚接地使能输出，有效增强了 PWM 信号的驱动能力与抗干扰性。DRV8870 内置过流保护、过热保护与欠压锁定，PMODE 引脚配置为相位/使能模式以简化控制逻辑。每个驱动芯片的电源引脚配置 100μF 电解电容与 0.1μF 陶瓷电容去耦，输出端串联 0Ω 电阻便于调试与电流测量。
电机驱动电路的原理图如图 4.2 所示（以其中一路为例）。四路驱动电路布局对称，布线时注意功率回路与信号回路分离，大电流走线宽度不小于 2mm。
4.4  传感器接口电路
传感器接口电路包括摄像头接口与编码器接口两部分。此外，SN74HC245PWR 八总线收发器用于电机驱动控制信号的缓冲增强。
摄像头接口通过 8P 排针（SW184）连接 OpenArt Plus 摄像头模块，包含 8 位像素数据总线（D0~D7）、像素时钟（PCLK）、行同步（HREF）、场同步（VSYNC）、SCCB 时钟（SIO_C）与数据（SIO_D）信号线。摄像头由独立的 3.3V 模拟电源（VCC_A）供电，以减少数字电路噪声对图像质量的影响。
编码器接口直接连接逐飞科技 mini 增量式编码器的 A/B 相输出信号至 MCU 的正交编码器接口（ENC）。四路编码器共 8 路信号（每路 A/B 两相），分别接入 4 组 ENC 外设，实现四轮速度的独立测量。编码器输出为 3.3V 电平，与 MCU I/O 电平兼容，无需额外电平转换。为提高抗干扰能力，在编码器信号走线末端靠近 MCU 处串联 33Ω 匹配电阻，并在 PCB 布局中远离电机功率走线。
4.5  舵机控制与蜂鸣器电路
舵机控制信号由 MCU 的 PWM 输出引脚产生，PWM 频率 50Hz，脉宽范围 0.5ms~2.5ms 对应舵机转角 -90°~+90°。舵机电源由 +5V_PERIPHERAL 直接供给，确保舵机大电流工作时不影响数字电路电源稳定性。
蜂鸣器电路采用 MMBT5551LT1 NPN 三极管驱动有源蜂鸣器。MCU 的 GPIO 通过 4.7kΩ 限流电阻连接三极管基极，蜂鸣器正极接 +5V_PERIPHERAL，负极接三极管集电极，发射极接地。当 GPIO 输出高电平时三极管导通，蜂鸣器鸣响。该电路用于车模状态提示（如启动确认、故障报警、完赛提示等）。
4.6  人机交互与通信接口
人机交互电路包括一个 5 脚轻触按键（SW1）与一个 8 位拨码开关。按键通过 10kΩ 上拉电阻接 3.3V，按下时接地，用于模式切换与参数确认。8 位拨码开关每位均通过 10kΩ 上拉电阻接 3.3V，拨至 ON 时接地，用于选择运行模式（如调试模式/比赛模式、速度档位等）。此外还有 2 位拨码开关用于辅助功能选择。
通信接口包括异步串口（ART）与无线串口。ART 接口通过 4P 排针引出，支持 TX/RX/GND/VCC 信号，用于有线调试。无线串口通过 PZ254V-11-08P 插座连接逐飞科技恩智浦智能车无线串口透传模块（支持 USB 转串口），支持车模运行时的参数在线调整与数据实时回传，是调试过程中的重要工具。

第五章  控制软件与算法设计
5.1  软件总体架构
控制软件基于 NXP MCUXpresso SDK 开发，采用 C 语言编写，整体架构分为硬件抽象层（HAL）、驱动层、算法层与应用层四个层次，如图 5.1 所示。软件采用前后台系统架构：后台以主循环方式执行图像处理、路径识别、决策规划等耗时任务；前台通过中断服务程序处理摄像头帧同步、编码器计数、PWM 输出等实时任务。
主循环的执行周期由摄像头帧中断触发，典型帧率为 50FPS，即每 20ms 完成一次图像采集、处理、决策与控制输出的完整流程。编码器速度环以 5ms 周期执行（由 PIT 定时器中断触发），确保速度控制的实时性。

5.2  赛道图像采集与预处理
图像采集通过 MCU 的 CSI（CMOS Sensor Interface）外设实现，采用 DMA 方式将 OpenArt Plus 摄像头输出的像素数据直接传输至内存缓冲区，无需 CPU 干预。摄像头配置为 QVGA 分辨率（320×240），灰度输出，帧率 50FPS。每帧图像大小为 320×240=76800 字节，使用 RT1064 内置的 1MB SRAM 可容纳多帧图像缓冲区。OpenArt Plus 支持全局快门模式，在车模高速运动时可有效消除图像的运动模糊，提高赛道识别的准确性。
图像预处理包括以下步骤：
（1）灰度化：摄像头直接输出 8 位灰度数据，无需额外转换。
（2）二值化：采用大津法（Otsu）自动计算阈值，将灰度图像转换为二值图像。大津法通过最大化类间方差自动确定最优阈值，能够适应不同光照条件下的赛道图像。二值化后赛道线为白色（255），背景为黑色（0）。
（3）感兴趣区域（ROI）提取：仅对图像中包含赛道信息的有效区域进行处理，去除天空与车模自身等无关区域，减少计算量。
（4）滤波去噪：采用 3×3 中值滤波去除二值化后的孤立噪点，提高后续边缘检测的可靠性。
5.3  路径识别与中线提取算法
路径识别的目标是从二值化图像中提取赛道的左右边界，并计算赛道中线，为转向控制提供偏差量。本设计采用基于行扫描的边缘检测算法，具体步骤如下：
（1）逐行扫描：从图像底部（近处）到顶部（远处）逐行扫描，在每行中从中心向左右两侧搜索白色赛道边缘点。
（2）边缘点记录：记录每行检测到的左边缘点与右边缘点的横坐标。若某行未检测到边缘，则利用上一行的边缘点进行插值补全。
（3）中线计算：对每行的左右边缘点取平均值，得到该行车道中线的横坐标。
（4）偏差计算：将中线横坐标与图像中心横坐标的差值作为横向偏差 Δx，用于转向控制。
为提高弯道识别能力，在提取中线后，对中线点进行最小二乘线性拟合，得到赛道的斜率与截距。斜率反映赛道的弯曲方向与程度，用于弯道预判与速度规划。对于十字交叉、坡道等特殊赛道元素，通过检测左右边缘点的异常跳变进行识别与特殊处理。
Δx = (x_left + x_right) / 2 - x_center        公式 1
5.4  电机 PID 控制算法
电机速度控制采用增量式 PID 算法，每个电机独立闭环。PID 控制器以目标速度与编码器反馈速度的差值 e(t) 为输入，输出 PWM 占空比控制量 u(t)。增量式 PID 的离散化表达式如公式 2 所示。
Δu(k) = Kp·[e(k)-e(k-1)] + Ki·e(k) + Kd·[e(k)-2e(k-1)+e(k-2)]        公式 2
其中 Kp、Ki、Kd 分别为比例、积分、微分系数，e(k) 为第 k 次采样的速度偏差。增量式 PID 仅输出控制量的增量，具有计算量小、无积分饱和问题、切换平滑等优点。PID 参数通过实验整定：先调节 Kp 使系统响应快速且无明显振荡，再加入 Ki 消除稳态误差，最后加入 Kd 抑制超调。
四轮速度采用差速控制策略：直道行驶时四轮速度相同；弯道行驶时，内侧车轮减速、外侧车轮加速，实现差速转向，减小转向阻力与轮胎磨损。差动量根据舵机转角与弯道曲率计算。
5.5  舵机转向控制策略
舵机转向控制采用"位置式 PID + 前馈"的复合控制策略。以横向偏差 Δx 作为 PID 控制器的输入，输出舵机转角 θ。同时引入赛道斜率（弯道曲率）作为前馈量，在进入弯道时提前给出转向量，提高系统响应速度。
θ = Kp_steer·Δx + Ki_steer·ΣΔx + Kd_steer·(Δx-Δx_prev) + Kf·slope        公式 3
其中 Kf 为前馈系数，slope 为中线拟合斜率。为避免舵机抖动，对输出转角进行限幅与一阶低通滤波处理。舵机 PWM 频率为 50Hz，分辨率为 1μs，对应转角分辨率约 0.18°。
5.6  速度规划与决策系统
速度规划的目标是在保证车模不冲出赛道的前提下，使平均速度最大化。本设计采用基于赛道曲率的分段速度规划策略：
（1）直道加速：当检测到赛道斜率接近零（直道）时，逐步加速至最高目标速度。
（2）弯道减速：当检测到赛道斜率超过阈值（弯道）时，根据曲率大小提前减速，曲率越大减速越多。
（3）出弯加速：当检测到弯道结束（斜率回归零）时，逐步恢复加速。
目标速度与赛道曲率的关系如公式 4 所示，其中 v_max 为直道最高速度，k 为曲率，a、b 为经验常数。
v_target = v_max / (1 + a·|k| + b·|k|²)        公式 4
决策系统还包括起跑控制、障碍检测（如适用）、完赛判断等功能。起跑时采用渐进加速策略，避免车轮打滑；运行中通过编码器累计里程判断完赛圈数。

第六章  开发与调试过程
6.1  开发工具与环境搭建
软件开发环境采用 NXP MCUXpresso IDE v11.8，基于 Eclipse 与 GCC ARM 工具链，支持 C/C++ 开发、编译与调试。硬件调试器采用 NXP MCU-Link Pro，通过 SWD 接口连接主控板，支持程序下载、断点调试与实时变量查看。
上位机调试工具采用自行开发的 Python 串口调试助手，通过无线串口模块与车模通信，实现以下功能：（1）实时接收车模回传的运行数据（速度、偏差、PWM 输出等）并绘制曲线；（2）在线修改 PID 参数与速度规划参数，无需重新烧录程序；（3）接收图像数据并在 PC 端显示，便于调试图像处理算法。
PCB 设计采用嘉立创 EDA 软件，原理图与 PCB 布局均在该软件中完成。4 层板设计中，顶层与底层为信号层，中间两层分别为地层与电源层，确保良好的信号完整性与电源完整性。
6.2  硬件制作与焊接调试
电路板采用 SMT 贴片工艺制作，主要芯片（RT1064、DRV8870、TPS5430 等）均为 QFN/SOIC 封装。焊接过程如下：
（1）锡膏印刷：使用钢网将锡膏印刷至 PCB 焊盘。
（2）元件贴装：使用镊子与真空吸笔将贴片元件贴装至对应位置，注意芯片方向与极性元件的正负极。
（3）回流焊接：将 PCB 放入回流焊炉，按照锡膏温度曲线（预热 150℃/60s，回流 230℃/30s）完成焊接。
（4）手工补焊：对回流焊后存在虚焊、桥接的引脚进行手工补焊修复。
焊接完成后，首先进行电源调试：不安装 MCU 与驱动芯片，仅焊接电源部分，通电测量各档电压输出是否正常。确认电源无误后，再焊接其余元件并进行功能测试。
6.3  软件模块调试
软件调试采用模块化策略，逐个模块验证功能正确性：
（1）GPIO 与 LED 测试：验证基本 I/O 功能与系统时钟配置。
（2）PWM 输出测试：用示波器测量 PWM 频率与占空比，验证电机驱动与舵机控制信号。
（3）编码器测试：手动转动电机，观察 ENC 计数值变化，验证编码器方向与分辨率。
（4）摄像头采集测试：通过 CSI 接口采集 OpenArt Plus 输出的图像并通过无线串口回传至上位机显示，验证图像采集的正确性与帧率。
（5）图像处理算法测试：在 PC 端用 Python 原型验证算法后，移植至 MCU 并通过回传图像验证处理效果。
（6）PID 速度环测试：给定阶跃速度指令，通过编码器反馈观察速度响应曲线，整定 PID 参数。
6.4  系统联调与问题解决
系统联调阶段将各模块整合，在实际赛道上进行整车调试。调试过程中遇到的主要问题及解决方法如下：
问题一：高速过弯时车模冲出赛道。原因分析：转向响应滞后，速度规划减速不够。解决方法：增加前馈控制量，提前转向；增大弯道减速系数；优化 PID 参数提高转向响应速度。
问题二：图像采集偶发丢帧或花屏。原因分析：摄像头信号线过长导致信号完整性差，CSI 时钟频率过高。解决方法：缩短摄像头排线，降低 CSI 时钟频率，在信号线上串联 33Ω 匹配电阻。
问题三：电机运转时图像出现干扰条纹。原因分析：电机大电流工作导致电源噪声耦合至图像传感器电源。解决方法：将摄像头电源与电机电源完全分离，增加 LDO 输出滤波电容，在 PCB 布局中分隔功率地与信号地。
问题四：编码器计数偶发错误。原因分析：编码器信号未做硬件滤波，电机电刷产生的电磁干扰导致误触发。解决方法：在 SN74HC245 输入端增加 RC 低通滤波（1kΩ + 1000pF），软件中增加编码器信号有效性判断。

第八章  结论
8.1  工作总结
本报告详细阐述了基于 NXP i.MX RT1064 微控制器的四轮独立驱动智能车的设计与实现过程。在硬件方面，设计了集成电源管理、四路电机驱动（SN74HC245 信号缓冲）、编码器接口、OpenArt Plus 摄像头接口与人机交互的 4 层 PCB 主控板，电路结构紧凑、功能完整。在软件方面，实现了基于 OpenArt Plus 视觉的赛道图像采集与处理、路径识别与中线提取、PID 速度闭环控制、舵机转向控制及基于曲率的速度规划等功能模块。
经过反复调试与优化，智能车能够在标准竞赛赛道上稳定、快速地自主循迹行驶，单圈最快时间 8.2s，连续运行 20 圈无冲出赛道，达到了预期的设计目标。
8.2  存在问题与改进方向
尽管本设计取得了较好的运行效果，但仍存在以下不足与可改进之处：
（1）图像处理算法仍有优化空间。当前采用基于行扫描的边缘检测算法，在光照变化剧烈或赛道磨损严重的情况下鲁棒性不足。未来可引入深度学习方法（如轻量级语义分割网络）进行赛道识别，提高复杂条件下的检测精度。
（2）速度规划策略较为简单。当前采用基于曲率的分段减速策略，未考虑车模动力学约束与赛道全局优化。未来可引入模型预测控制（MPC）或强化学习方法，实现全局最优的速度规划。
（3）四轮独立驱动的优势尚未充分发挥。当前仅实现了简单的差速控制，未来可研究基于动力学的四轮扭矩分配策略，进一步提高过弯极限速度。
（4）机械结构的轻量化与刚性仍有提升空间。可采用更轻的材料与优化的结构设计，在保证刚性的前提下降低整车质量，提高加速性能与操控响应。

B.1  增量式 PID 控制子程序
typedef struct {
    float Kp;           // 比例系数
    float Ki;           // 积分系数
    float Kd;           // 微分系数
    float err[3];       // 偏差历史 e(k), e(k-1), e(k-2)
    float output;       // 输出量
    float out_max;      // 输出限幅
} PID_TypeDef;

float PID_Calc(PID_TypeDef *pid, float target, float feedback)
{
    float delta_u;
    pid->err[2] = pid->err[1];
    pid->err[1] = pid->err[0];
    pid->err[0] = target - feedback;

    // 增量式 PID 计算公式
    delta_u = pid->Kp * (pid->err[0] - pid->err[1])
            + pid->Ki * pid->err[0]
            + pid->Kd * (pid->err[0] - 2*pid->err[1] + pid->err[2]);

    pid->output += delta_u;

    // 输出限幅
    if (pid->output > pid->out_max)  pid->output = pid->out_max;
    if (pid->output < -pid->out_max) pid->output = -pid->out_max;

    return pid->output;
}
B.2  赛道中线提取子程序
#define IMG_WIDTH   320
#define IMG_HEIGHT  240
#define ROI_START   60      // 感兴趣区域起始行

uint8_t image[IMG_HEIGHT][IMG_WIDTH];  // 二值化图像
int16_t left_edge[IMG_HEIGHT];         // 左边缘
int16_t right_edge[IMG_HEIGHT];        // 右边缘
int16_t center_line[IMG_HEIGHT];       // 中线

void ExtractCenterLine(void)
{
    int16_t row, col;
    int16_t left = -1, right = -1;

    for (row = ROI_START; row < IMG_HEIGHT; row++) {
        left = -1; right = -1;
        // 从中心向左搜索左边缘
        for (col = IMG_WIDTH/2; col >= 0; col--) {
            if (image[row][col] == 255) { left = col; break; }
        }
        // 从中心向右搜索右边缘
        for (col = IMG_WIDTH/2; col < IMG_WIDTH; col++) {
            if (image[row][col] == 255) { right = col; break; }
        }
        // 边缘丢失时用上一行插值
        if (left == -1 && row > ROI_START) left = left_edge[row-1];
        if (right == -1 && row > ROI_START) right = right_edge[row-1];

        left_edge[row] = left;
        right_edge[row] = right;
        if (left != -1 && right != -1) {
            center_line[row] = (left + right) / 2;
        }
    }
}
B.3  舵机转向控制子程序
float steer_pid(float delta_x, float slope)
{
    static float err_prev = 0;
    static float err_sum = 0;
    float output;
    const float Kp = 0.35f, Ki = 0.01f, Kd = 0.15f, Kf = 0.8f;

    err_sum += delta_x;
    if (err_sum > 100)  err_sum = 100;   // 积分限幅
    if (err_sum < -100) err_sum = -100;

    // 位置式 PID + 前馈
    output = Kp * delta_x + Ki * err_sum
           + Kd * (delta_x - err_prev)
           + Kf * slope;

    err_prev = delta_x;

    // 舵机转角限幅 ±30°
    if (output > 30)  output = 30;
    if (output < -30) output = -30;

    return output;
}
B.4  速度规划子程序
float SpeedPlanning(float curvature, float v_max)
{
    float v_target;
    const float a = 5.0f, b = 20.0f;  // 经验常数

    // 基于曲率的速度规划
    v_target = v_max / (1.0f + a * fabsf(curvature)
                       + b * curvature * curvature);

    // 最低速度限制
    if (v_target < 0.5f) v_target = 0.5f;

    return v_target;
}

int main(void)
{
    // 板级初始化
    BOARD_InitHardware();
    Motor_Init();
    Servo_Init();
    Camera_Init();
    Encoder_Init();
    Debug_Init();

    // PID 初始化
    PID_TypeDef speed_pid[4];
    for (int i = 0; i < 4; i++)
        PID_Init(&speed_pid[i], 0.8f, 0.1f, 0.05f, 100.0f);

    // 等待起跑信号
    while (!start_flag) { WaitForStart(); }

    // 主循环
    while (1) {
        if (frame_ready) {          // 等待一帧图像采集完成
            frame_ready = 0;
            Image_Binarize();       // 二值化
            ExtractCenterLine();    // 提取中线
            float curvature = CalcCurvature();
            float delta_x = center_line[180] - IMG_WIDTH/2;

            // 速度规划与转向控制
            float v_target = SpeedPlanning(curvature, 2.5f);
            float angle = steer_pid(delta_x, curvature);
            Servo_SetAngle(angle);

            // 四轮速度闭环
            for (int i = 0; i < 4; i++) {
                float speed = Encoder_GetSpeed(i);
                float pwm = PID_Calc(&speed_pid[i], v_target, speed);
                Motor_SetSpeed(i, pwm);
            }
            Debug_SendData();       // 回传调试数据
        }
    }
