第一章  引言
1.1  竞赛背景与赛题概述
全国大学生智能汽车竞赛是以智能汽车为研究对象的创意性科技竞赛，是面向全国大学生的一种具有探索性的工程实践活动。第二十一届竞赛人工智能视觉组的比赛形式在往届基础上发生了较大变化：参赛车模不再直接感知真实赛道，而是在约3.2m×2.4m的平面场地内自由运动，由比赛系统的全局摄像头通过车模顶部15cm高度处的AprilTag方位标识牌（TAG16H5系列）确定车模的位置与方向，再由上位机虚拟现实仿真系统将车模在虚拟游戏世界中的画面通过无线投屏显示在车载屏幕上。车模需要“看懂”屏幕中的虚拟游戏画面，完成推箱子（Sokoban）类游戏任务：将散布在地图中的箱子推至指定目的地，并可利用炸弹元素炸开围墙以缩短行进路线[1][2]。
按照赛题细则，比赛按科目一至科目三顺序连续进行，难度梯度包含纯推箱子、按箱子上的图片分类推箱子等不同关卡；车模地面投影须在35cm×35cm范围内，主控限定使用NXP公司的MCU（推荐i.MX RT系列），图像处理平台限定使用基于NXP微控制器的OpenART、OpenART Plus等模块，车模须从组委会指定的成品车模（B、C、F、G、M、H、Y、Z型）中选择[1][3]。这一赛题形式将考察重点从传统的赛道循迹转向了“屏幕画面理解—全局地图构建—虚拟坐标定位—路径规划—精准运动控制”的完整链条，对车模的视觉感知能力、定位精度与运动控制精度提出了很高要求。
1.2  设计目标与总体思路
针对上述赛题特点，本队确定了如下的设计目标与技术路线：
（1）底盘选型：推箱子任务要求车模能够在不转向的情况下横向对正箱子与目的地，因此选用逐飞科技M1麦克纳姆轮全向底盘（四轮麦克纳姆轮结构），配合四个RC380电机与自行安装的逐飞科技1024线带方向正交解码MINI增量式编码器，实现前后、左右、旋转三自由度解耦控制；
（2）主控选型：选用逐飞科技i.MX RT1064[4]核心板（ARM Cortex-M7内核，600MHz主频），承担运动控制、姿态解算、里程计推算、推箱子路径规划与比赛状态机等全部实时计算任务；
（3）视觉方案：采用双OPEN ART PLUS摄像头的分工协作方案——一块摄像头专用于观测车载屏幕，完成赛道（地图）元素识别并向主控回传车模在地图中的坐标，结合主控控制算法实现视觉辅助定位；另一块摄像头专用于前视识别，完成箱子图案与目的地数字的神经网络分类；
（4）硬件自主设计：自行设计主控板（含多级电源、保护与时序控制电路）与四路DRV8701电机驱动板[5]，保证系统在3S锂电池供电下的可靠运行。
1.3  报告内容安排
本报告共分为七章。第一章为引言，概述赛题背景与总体思路；第二章介绍系统总体方案设计；第三章介绍机械结构设计与安装；第四章详细论述主控板与驱动板的硬件电路设计；第五章论述软件系统架构、通信协议、运动控制、姿态解算、视觉感知策略与推箱子规划算法；第六章介绍开发工具与调试过程；第七章给出车模主要技术参数；最后为结论、参考文献与附录（电路原理图与核心算法源程序）。本报告的结构与格式参照竞赛秘书处发布的技术报告内容与格式要求[10]编排。

第二章  系统总体方案设计
2.1  需求分析
人工智能视觉组的比赛任务可分解为四个关键技术环节：其一，屏幕画面理解——车载屏幕以无线投屏方式显示虚拟游戏画面，车模须从画面中提取完整的14×10（16×12含外围墙）网格地图，识别墙体、箱子、目的地、炸弹与自身图标等元素；其二，自身定位——车模在场地中的真实运动与虚拟世界中的位置并不同步测量，须将屏幕中车模图标的坐标作为观测值，与车载里程计、惯性航向融合，实现高精度的地图坐标估计；其三，目标识别——科目二、科目三要求识别箱子表面的图案与目的地处的数字并建立对应关系；其四，运动执行——推箱子要求车模以厘米级精度停靠在箱子侧面并以恒定方向推动，任何航向漂移都会导致推箱失败。围绕这四个环节，本章给出系统的总体方案。
2.2  系统组成
整车系统由五部分组成：以RT1064核心板为核心的主控系统、以双OPEN ART PLUS为核心的视觉感知系统、以ICM42688[6]与四路正交编码器为核心的姿态与测速系统、以DRV8701四路全桥驱动为核心的动力执行系统，以及以3S锂电池与多级稳压为核心的电源系统。系统组成与信号流程如图2.1所示。

图2.1  系统组成与信号流程图
主控RT1064通过两路2Mbps高速串口（UART4/UART5）分别连接两块OPEN ART PLUS：UART5连接观测屏幕的“地图/位姿板”，请求完整地图与车模视觉坐标；UART4连接前视的“识别板”，请求箱子图案与目的地数字的分类结果。主控通过SPI4总线读取ICM42688六轴IMU进行姿态解算，通过四路QTIMER正交解码接口采集四个车轮的编码器脉冲实现测速与里程计推算。运动控制输出为四路17kHz PWM与方向信号，经SN74ALVC244缓冲后送至驱动板的四片DRV8701栅极驱动器，驱动四个RC380电机。按键、拨码开关、蜂鸣器与TFT180显示屏构成人机交互界面，无线串口模块用于调试数据的远程观测。
整车外观如图2.2、图2.3所示。主控板与驱动板叠放于底盘中部，3S锂电池经固定架安置于屏幕支架后方，两块OPEN ART PLUS并装于车前上方的3D打印支架上，车载无线屏幕以一体化支架固定于车头，屏幕四周设有遮光帘以抑制环境光干扰。

2.3  比赛工作流程
车模的一次完整比赛流程如下：发车后主控驱动车模移出发车区，比赛系统随即在屏幕上加载虚拟地图；主控通过UART5向地图板发出地图请求（0x30），地图板对屏幕画面逐格分类后回传整张地图；主控据此规划观察路径，依次行驶至各观察点，通过UART4向识别板发出图案/数字识别请求（0x10/0x11），获得箱子图案编号与目的地数字；完成箱—目标匹配后，主控在16×12格地图上进行推箱子路径规划，依次执行推箱与炸墙动作；行进过程中，主控周期性地通过UART5请求车模视觉坐标（0x40），对编码器里程计进行闭环校正；全部任务完成后车模自动返回发车区。上述过程由主控内一个19状态的比赛状态机统一调度，详见第五章。整车比赛工作流程如图2.4所示。

第三章  机械结构设计与安装
3.1  底盘选型与整车布局
本队选用逐飞科技M1车模作为底盘。M1车模采用四轮麦克纳姆轮结构，四个车轮分别由RC380电机独立驱动，配合运动学逆解即可实现平面三自由度（前后、左右、原地旋转）的全向运动，非常契合推箱子任务中“横移对正—直线推箱—原地转向”的动作需求。为实现车轮测速与里程计推算，本队在四个车轮轴上自行安装了逐飞科技1024线带方向正交解码MINI增量式编码器（实物如图3.1所示），编码器A/B相输出直接接入主控板的正交解码接口。实测左右轮中心距D_x=180mm、前后轮中心距D_y=200mm，车轮直径60mm，上述尺寸作为运动学解算与里程计推算的基本参数写入控制程序。整车重心布置遵循“低、中、对称”原则：电池与驱动板等重部件贴近底盘平面，主控板居于车体中部，摄像头支架前伸，屏幕支架位于车头上方，使整车质心基本落于四轮几何中心附近，减小了加减速时的俯仰与横摆扰动。


图3.1  逐飞科技1024线带方向正交解码MINI增量式编码器实物图
3.2  双OPEN ART PLUS安装结构
两块OPEN ART PLUS分别承担屏幕观测与前视识别任务，须以确定的空间位姿刚性固定。为此设计了3D打印的双摄支架：支架通过立柱抬高至屏幕上沿高度，使两块摄像头的视场分别覆盖屏幕画面与车前识别区域；支架与车体、摄像头与支架之间均采用螺栓紧固并辅以胶封，保证车辆加减速时摄像头位姿不发生变化——这对依赖固定标定参数的地图解算至关重要。支架的3D打印结构与装配实体分别如图3.2、图3.3所示。

3.3  屏幕与电池固定结构及遮光设计

3.4  电路板固定与方位标识牌
主控板与驱动板均通过铜柱架空固定于底盘上方，层间保留足够走线与散热空间；板间控制信号经XH2.54排线连接，动力线经KF301螺钉端子连接，均具有防呆与抗震能力。按照赛题要求，车模顶部须水平安装30cm×15cm的磁吸式方位标识牌（最高处15cm±0.5cm），两吸附磁铁中心间距20cm。本队自制了标识牌固定横杆与磁铁预装结构，标识牌经磁铁吸附后与车模无相对位移、不可转动，满足全局摄像头对车模位置与方向解算的要求[1]。

第四章  硬件电路设计
4.1  电源系统总体方案
整车由3S锂聚合物电池（标称11.1V，满电12.6V）统一供电。用电负载分为三类：一是四路驱动电机，工作电流大、瞬态冲击强；二是RT1064核心板、OPEN ART PLUS摄像头、TFT屏幕等数字负载，对电压稳定性敏感；三是编码器、ICM42688等传感器，要求低噪声供电。为此采用“动力直通、数字稳压、传感隔离”的多级电源方案：电池电压经保护电路后直接作为12V动力母线送往驱动板；同时经DCDC降压至5V，再由LDO降至3.3V供给传感器与外设；摄像头供电经限流开关与磁珠滤波单独分配。电源分配与上电时序如图4.1所示。


图4.1  电源分配与上电时序流程图
4.2  主控板电路设计
主控板采用逐飞科技RT1064核心板作为全车的控制核心。该核心板搭载NXP i.MX RT1064跨界处理器（ARM Cortex-M7内核，600MHz主频，片内4MB Flash，配合芯片内部1MB SRAM），其在整车系统中的关键作用体现在三个方面：其一，系统控制——运行比赛状态机与200Hz运动控制环，输出四路17kHzPWM与方向信号，经缓冲后驱动四路DRV8701全桥，控制四个RC380电机完成麦克纳姆轮全向运动；其二，数据采集——通过四路QTIMER正交解码通道硬件采集四个编码器的脉冲计数，经SPI4总线以24MHz时钟读取ICM42688六轴IMU，并经UART4/UART5两路2Mbps高速串口接收双OPEN ART PLUS回传的地图、位姿与目标分类结果；其三，数据处理——在片内实时完成Madgwick[7]姿态解算、编码器里程计推算、视觉/惯性多源定位融合以及推箱子路径搜索等全部运算，无需任何片外协处理器。
主控板为100mm×64mm的四层板（顶层—内层1完整GND平面—内层2—底层），承载RT1064核心板及其全部外围电路。主控板顶层与底层PCB如图4.2、图4.3所示，下文按功能模块逐一说明，并给出对应的原理图截图；完整原理图见附录A。

4.2.1  输入保护与防反接电路
电源引入电路如图4.4所示。电池输入经总电源开关U12后，首先由P沟道MOSFET IRFR5305（Q2）构成防反接开关：电池极性正确时体二极管先导通、栅源形成负偏使MOS管完全导通，导通压降仅数十毫伏，远小于串联二极管方案；电池反接时MOS管截止，后级电路得到保护，栅极经R30（100kΩ）下拉确定关断态。随后经F2自恢复保险丝（SMD1812封装，3A/24V）实现过流保护：过流或短路时保险丝呈高阻态切断回路，故障消失后自动恢复。母线上并联双向TVS二极管SMBJ15CA（钳位电压15V），吸收热插拔与电机回馈引起的浪涌尖峰，输入端并布置10µF与100nF滤波电容。该“P-MOS＋PTC＋TVS”链路实现了防反接、过流与过压的全方位防护。经保护后的+12V母线由电源引出电路分配（图4.5）：一路经开关U13与插座U4/U16送往驱动板作为动力电源，另设U14/U15两路5V调试取电口，便于外接调试设备。

4.2.2  多级稳压电路（DCDC＋LDO）

4.2.3  上电时序控制电路

第五章  软件系统设计与算法实现
5.1  软件总体架构与任务调度
主控软件基于逐飞SeekFree RT1064DVL6A开源库[8]开发，采用裸机前后台结构，主频配置为600MHz。后台主循环负责菜单交互与比赛总状态机调度；前台由两路周期中断构成确定性实时调度：PIT0周期5ms（200Hz），依次执行编码器采样与M法测速、车体系速度合成、里程计积分、路径跟踪/goto输出、麦克纳姆轮运动学逆解与四轮速度环PID；PIT1周期2ms（500Hz），执行IMU数据读取与Fusion AHRS姿态解算。串口接收采用“UART＋eDMA环形缓冲＋空闲线中断”的零拷贝方案，中断内仅完成DMA搬运事件登记，协议解析统一放在前台执行，保证了高波特率下控制环的实时性不受干扰。
5.2  与双OPEN ART PLUS的串口通信协议
主控与两块OPEN ART PLUS之间设计了统一的请求—响应式串口协议，两路均工作于2Mbps波特率。帧结构为：帧头0xA5 0x5A｜包类型PKT｜序号SEQ｜长度LEN｜负载PAYLOAD｜CRC16（CCITT，多项式0x1021，初值0xFFFF，覆盖PKT/SEQ/LEN/PAYLOAD，低字节在前）｜帧尾0xA6。请求与响应通过非零递增的SEQ匹配，接收侧逐字节重同步并校验帧尾与CRC，可抵抗任意字节级的错位与干扰。UART4（识别板，eDMA通道7、256B环形缓冲）承载图案/数字识别业务：请求0x10（箱型图案）/0x11（目标数字）/0x12/0x13（自动观察变体），响应0x20/0x21（分类编号0~9）、0x22（跳过）与0x2F（远端错误码：模型未就绪、置信度不足、无多数票等）；UART5（地图板，eDMA通道9、1024B环形缓冲）承载地图与位姿业务：请求0x30获取完整地图，响应0x31的负载为元素条目流，每条2字节（高4位类型：墙1/目标2/箱3/玩家4/炸弹5，低4位x坐标，第2字节y坐标），主控解析后自动补加外围一圈墙体构建16×12地图；请求0x40获取车模位姿，响应0x42为int16小端的x×100、y×100（单位0.01格）。该协议将命令字按功能分区（0x1x/0x2x归识别板，0x3x/0x4x归地图板），链路层完全一致，便于两块摄像头的软件复用与维护。

5.3  运动控制：麦轮运动学与速度环
底盘四个麦轮由四路17kHz PWM独立驱动（占空比上限6000），控制周期5ms。编码器采用QTIMER硬件正交解码（四倍频），每5ms读数清零作M法测速；比例系数按轮径60mm、编码器每电机转1024计数、传动比70/30标定为0.0789mm/count，速度以mm/s为单位进入闭环。
麦克纳姆轮运动学逆解按车体速度(vx, vy, ω)合成四轮目标速度：记k=(D_x+D_y)/2=190mm，则v_LF=vx−vy−kω，v_RF=vx+vy+kω，v_LR=vx+vy−kω，v_RR=vx−vy+kω（车体前为+vx、左为+vy、逆时针为+ω，ω由deg/s换算为rad/s后参与运算）。针对麦轮横移时普遍存在的前向耦合偏移，软件按横移方向与行程档位（短≤4格/中≤6格/长段）叠加前馈补偿系数；针对快速转向时的轮速饱和问题，在逆解后叠加“陀螺轮速阻尼”——按实测角速度对各轮目标速度施加抑制（增益K=3.20，上限2060，死区0.8dps），原地转向或|ω|>40deg/s时自动让出，显著改善了转向过程中的轨迹保持能力。
速度环采用增量式PID：Δu=Kp·(e0−e1)+Ki·e0+Kd·(e0−2e1+e2)，四轮同参Kp=3.9、Ki=0.35、Kd=0，输出限幅±6000，单周期积分增量限幅6000以防积分风暴。航向控制采用位置式PID（Kp=6.5、Ki=0.035、Kd=0，输出上限1400deg/s，误差死区0.45°），配合0.12°的转向完成死区，实现了原地转向亚度级的停车精度。
5.4  ICM42688姿态解算与零漂抑制
IMU选用TDK ICM42688六轴传感器（SPI4，24MHz，突发读取14字节），配置陀螺量程±2000dps、加速度量程±8g、输出数据率1000Hz并启用二阶低通滤波。姿态解算采用xio Fusion AHRS算法（无磁力计模式），以2ms周期更新四元数，增益0.5、加速度拒绝角10°、拒绝超时5s；上电时以加速度计解算初始姿态。由于偏航角缺乏绝对观测，零漂抑制成为关键：上电静态标定采集1000个样本（约2s）估计陀螺与加速度零偏；运行期进行静止检测（陀螺变化<0.35dps且绝对值<1.5dps、加速度变化<0.08g且模长在1g±0.12内、持续0.35s），判静止后以α=0.004的低通系数在线更新零偏；陀螺z轴设0.25dps死区，并引入运动漂移前馈（实测约0.1875°/150s，上限0.10dps，1s缓启）。此外软件预留外部航向注入接口，可将视觉解算的航向写入AHRS，进一步压制长时间漂移。经上述处理，连续运行数分钟的偏航漂移可控制在比赛容许范围内。
5.5  双OPEN ART PLUS视觉感知策略
视觉系统是整车感知能力的核心。本队没有采用“单摄像头分时复用”的常规做法，而是设计了双OPEN ART PLUS分工协作方案：一块摄像头专用于赛道（地图）元素识别并向主控回传目标（车模）坐标，结合主控控制算法进行视觉辅助定位；另一块摄像头专用于箱子图案与目的地数字的分类识别。两板并行工作、互不阻塞，主控经两路独立2Mbps串口按需索取结果。视觉感知与定位流程如图5.1所示。

5.5.1  屏幕观测板（FullMap）：地图识别与位姿解算
该板以固定机位观测车载屏幕，采集VGA（640×480）RGB565图像、锁定60fps帧率，关闭自动增益与自动白平衡以保证颜色阈值稳定，并施加0.65强度的镜头畸变校正。地图识别的基本坐标系由屏幕四角点定义：四角点初值经OpenMV IDE[9]手动标定，每次识别时再沿画面四边按“蓝色场地/灰墙”颜色交界自动精修（跨5帧取候选四边形中位数），据此解析求解8参数单应性矩阵，实现像素平面到地图平面的双向映射（等价于AprilTag四角方案的标签平面坐标，但无需在屏幕上附加任何标记）。
地图元素识别不依赖色块连通域搜索，而是采用逐格多点采样投票策略：将画面映射为14×10网格，每格按3×3采样点取5×5邻域的LAB均值，依据标定的LAB阈值（黄箱、紫目标、灰墙、炸弹、蓝色场地）逐点分类后多数投票——一般格最少2票、墙格最少4票方可确认，有效抑制了屏幕摩尔纹、反光与投屏抖动造成的误判；连续2帧地图内容一致才认为识别稳定，随即按0x31协议回传整张地图。
车模位姿解算用于向主控回传车模在地图中的坐标：程序以两组LAB阈值分别锁定屏幕上代表车模的蓝/青与绿色标记块，find_blobs粗定位后在外接矩形内逐像素重算质心，并以双色块几何成对约束（间距7~24像素、面积比不超过3）剔除误检；取两色块连线中点为车心、连线方向为车头朝向。像素坐标经单应性逆变换映射为地图坐标（原点取地图左下角，1格=100单位，坐标范围x∈[0,1400]、y∈[0,1000]，y轴翻转），再经单帧跳变限幅与7帧稳定观测后按0x42协议回传，分辨率0.01格（合2mm）。
5.5.2  前视识别板（Realize）：图案与数字分类
该板随车移动，到观察位后对准箱子或目的地采集QVGA（320×240）图像。分类采用TensorFlow Lite轻量级神经网络：程序按主控请求动态加载图案模型（10类卡通图案，映射编号0~9）或数字模型（0~9），以滑窗方式执行tf.classify推理，top-1置信度高于0.9方可采信；为消除单帧误分类，进一步执行3帧多数投票（连续3帧中至少2帧一致），12次尝试仍无置信结果则向主控返回置信度不足错误码。在自动观察模式下，程序还会以find_blobs预检视野中的大块黄色/粉色区域（面积阈值20000像素），一旦确认无有效目标立即回传“跳过”应答，使主控免于空等超时。模型切换后执行垃圾回收释放显存，保证长时间运行的内存稳定。
5.5.3  分工协作的优越性分析
双摄像头方案带来三方面收益：其一，并行性——地图板在行进途中可持续输出位姿，识别板在观察位独立推理，两块MCU的算力与两路UART的带宽互不争用，主控无需等待“切换视角”的机械或软件开销；其二，专用性——两板的镜头焦距、安装角度、图像参数与算法流水线均可针对各自任务独立优化（地图板VGA+畸变校正+单应性解算，识别板QVGA+TFLite推理），不存在参数折中；其三，冗余性——任一板返回错误码时主控可降级运行（如位姿短时失效时纯里程计续跑、识别失败时重试或跳过），系统的任务鲁棒性显著提高。
5.6  全局定位与视觉辅助定位融合
地图坐标系定义为16×12格、每格200mm。车模自定位采用“编码器里程计为主、AHRS航向为向、视觉位姿为校”的融合方案：PIT0每5ms将四轮编码器位移合成车体系速度，经方向标定系数（前向0.985、后向0.980、横移0.823）修正后按当前yaw旋转至地图系积分，得到连续位姿估计；地图板回传的视觉坐标按误差窗口进行择信融合——偏差小于0.01格认为一致、保持原值；0.01~0.5格写入修正；大于1格判定为误观测直接拒绝，防止屏幕反光或图标遮挡造成的野值污染里程计。在路径拐点等误差敏感位置，主控还会主动降速至350mm/s以下并发起0x40位姿请求进行定点修正。该方案将视觉观测的绝对性与里程计的连续性互补结合，实测全程定位误差稳定在一个格边长的5%以内，满足推箱子的对正精度要求。
5.7  推箱子路径规划与比赛状态机
推箱子规划分为自由移动与推动求解两层。自由移动层采用带动作代价的BFS（直行代价8、转向6、推动2，同代价偏好直道），输出平滑的格点路径；推动求解层采用单箱推动型A*搜索，状态压缩为“箱格＋玩家相对方向”共768状态，多箱任务再外包分支限界——以已有可行解代价减1为上界、anytime节点预算控制搜索规模，配合推动距离、下界与可达对等多级缓存及返程锚点估价，另设箱—目标动态规划指派以确定最优匹配关系。该求解器在主控600MHz平台上对比赛规模地图（不超过6箱/目标/炸弹）可在秒级内给出近优解。
比赛流程由19个状态的总状态机驱动：IDLE→离库→等待地图→（位姿修正）→观察选点→移动/转向对正→识别请求→恢复航向→匹配→推箱/炸弹→解锁→回库→DONE/ERROR。状态机支持最多9关配置，每关可独立设置识别模式（直接/匹配/自动）、视觉修正档位与阈值；关键动作均设有超时与重试（如观察结果超时200/300个tick、地图请求1000个tick超时重发2次、炸弹爆炸等待20个tick，1 tick=5ms），保证异常情况下流程不死锁。

#include "Pid.h"
 
#include <math.h>
 
/* 四轮增量式速度 PID 默认值。Kp 调大响应更快但易振荡；Ki 调大可更快消除静差但易累积；
 * Kd 调大可增强阻尼但会放大速度噪声。IntegralMax 限制单周期积分增量，OutMax 限制 PWM 输出；
 * 两者调大可增强极限纠偏但冲击/饱和风险上升，调小更保守但大误差收敛变慢。 */
PID_Speed Motor1_PID = {
	.Kp = 3.9f,
	.Ki = 0.35f,
	.Kd = 0.00f,
	.OutMax = PWM_MAX,
	.IntegralMax = 6000.0f,
};
 
/* Motor2/3/4_PID 与 Motor1_PID 参数完全相同，此处从略 */
void PID_Speed_Calc(PID_Speed* pid, float target, float actual){
    float delta_p;
    float delta_i;
    float delta_d;
    float delta_out;
 
	pid->Err2 = pid->Err1;
	pid->Err1 = pid->Err0;
	pid->Err0 = target - actual;
 
    delta_p = pid->Kp * (pid->Err0 - pid->Err1);
    delta_i = pid->Ki * pid->Err0;
    delta_d = pid->Kd * (pid->Err0 - 2 * pid->Err1 + pid->Err2);
 
    if (delta_i > pid->IntegralMax){
		delta_i = pid->IntegralMax;
    }else if(delta_i < -pid->IntegralMax){
		delta_i = -pid->IntegralMax;
	}
 
    delta_out = delta_p + delta_i + delta_d;
	pid->Out += delta_out;
 
	if(pid->Out > pid->OutMax){
		pid->Out = pid->OutMax;
	}else if(pid->Out < -pid->OutMax){
		pid->Out = -pid->OutMax;
	}
 
}
 
void PID_Speed_Reset(PID_Speed* pid){
    pid->Err0 = 0.0f;
    pid->Err1 = 0.0f;
    pid->Err2 = 0.0f;
    pid->Out  = 0.0f;
    pid->Integral = 0.0f;
}

void Mecanum_ClearLateralForwardCompSegmentLength(void)
{

void Mecanum_Cal(Param_t *param)
{
    float vx;
    float vy;
    float w;
    float lateral_forward_comp_k;
    float w_rad_s;
    float v1_mm_s;
    float v2_mm_s;
    float v3_mm_s;
    float v4_mm_s;
    const float k_mm = (param->D_x + param->D_y) * 0.5f;  // mm
 
    vx = param->vx;
    vy = param->vy;
    w = param->w;
    lateral_forward_comp_k = Mecanum_SelectLateralForwardCompK(
        g_lateral_forward_comp_segment_length_cell, vy);
 
    if ((lateral_forward_comp_k != 0.0f) &&
        (fabsf(vx) <= MECANUM_LATERAL_COMP_CMD_DEADBAND) &&
        (fabsf(vy) > MECANUM_LATERAL_COMP_CMD_DEADBAND) &&
        (fabsf(w) <= MECANUM_LATERAL_COMP_CMD_DEADBAND))
    {
        vx -= lateral_forward_comp_k * vy;
    }
 
    // 角速度从 deg/s 转为 rad/s。
    w_rad_s = w * (PI / 180.0f);
 
    // 轮周方向等效线速度，轮序为左前、右前、左后、右后。
    v1_mm_s = vx - vy - k_mm * w_rad_s;
    v2_mm_s = vx + vy + k_mm * w_rad_s;
    v3_mm_s = vx + vy - k_mm * w_rad_s;
    v4_mm_s = vx - vy + k_mm * w_rad_s;
 
    // 编码器反馈已经按轮径和齿比换算为轮地 mm/s，目标速度保持同一单位。
    param->wheel_vel[0] = v1_mm_s;
    param->wheel_vel[1] = v2_mm_s;
    param->wheel_vel[2] = v3_mm_s;
    param->wheel_vel[3] = v4_mm_s;
}
 
void Mecanum_LimitWheelVel(Param_t *param, float max_abs_mmps)
{
    /* 上限调大可保留更高合成速度但更易超过电机能力；调小可防饱和，但会按比例压低全部轮速。 */
    float max_abs = 0.0f;
 
    if ((!param) || (max_abs_mmps <= 0.0f))
    {
        return;
    }
 
    for (int i = 0; i < 4; i++)
    {
        float abs_vel = fabsf(param->wheel_vel[i]);
        if (abs_vel > max_abs)
        {
            max_abs = abs_vel;
        }
    }
 
    if (max_abs > max_abs_mmps)
    {
        float scale = max_abs_mmps / max_abs;
        for (int i = 0; i < 4; i++)
        {
            param->wheel_vel[i] *= scale;
        }
    }
}

    return None

        center_x, center_y = get_cell_center(col, row)
        lab_avg = get_avg_lab(img, center_x, center_y, LAB_SAMPLE_RADIUS)
        return classify_lab_for_map(lab_avg)
 
    label_counts = {}
    spread = GRID_CELL_SAMPLE_SPREAD
    if GRID_CELL_SAMPLE_GRID <= 1:
        offsets = (0,)
    else:
        offsets = []
        step = (spread * 2) / (GRID_CELL_SAMPLE_GRID - 1)
        start = -spread
        for i in range(GRID_CELL_SAMPLE_GRID):
            offsets.append(start + i * step)
 
    for offset_u in offsets:
        for offset_v in offsets:
            sample_x, sample_y = get_grid_sample_point(col, row, offset_u, offset_v)
            lab_avg = get_avg_lab(img, sample_x, sample_y, LAB_SAMPLE_RADIUS)
            label = classify_lab_for_map(lab_avg)
            if label is None:
                continue
 
            if label not in label_counts:
                label_counts[label] = 0
            label_counts[label] += 1
 
    best_label = None
    best_count = 0
    for label, label_count in label_counts.items():
        if label_count > best_count:
            best_label = label
            best_count = label_count
 
    min_hits = GRID_CELL_SAMPLE_MIN_HITS
    if best_label == '#':
        min_hits = WALL_CELL_SAMPLE_MIN_HITS
 
    if best_count < min_hits:
        return None
 
    return best_label
B.6  视觉端CRC16校验与帧解析（节选）
def crc16_ccitt(data):
    crc = 0xFFFF
    for b in data:
        crc ^= b << 8
        for _ in range(8):
            if crc & 0x8000:
                crc = ((crc << 1) ^ 0x1021) & 0xFFFF
            else:
                crc = (crc << 1) & 0xFFFF
    return crc
 
def make_frame(cmd, seq, payload=b""):
    ln = len(payload)
    body = bytearray([cmd, seq, ln & 0xFF])
    body.extend(payload)
    crc = crc16_ccitt(body)
    out = bytearray([SYNC0, SYNC1])
    out.extend(body)
    out.append(crc & 0xFF)
    out.append((crc >> 8) & 0xFF)
    out.append(EOF)
    return out
 
def send_frame(cmd, seq, payload=b""):
    uart.write(make_frame(cmd, seq, payload))
 
def drop_rx(count):
    global rx_buf
    if count <= 0:
        return
    if count >= len(rx_buf):
        rx_buf = bytearray()
    else:
        rx_buf = bytearray(rx_buf[count:])
 
def poll_frames():
    data = uart.read()
    if data:
        rx_buf.extend(data)
 
    frames = []
    while len(rx_buf) >= 8:
        if rx_buf[0] != SYNC0 or rx_buf[1] != SYNC1:
            drop_rx(1)
            continue
 
        ln = rx_buf[4]
        total = 8 + ln
        if ln > 16:
            drop_rx(1)
            continue
        if len(rx_buf) < total:
            break
        if rx_buf[7 + ln] != EOF:
            drop_rx(1)
            continue
 
        body = rx_buf[2:5 + ln]
        recv_crc = rx_buf[5 + ln] | (rx_buf[6 + ln] << 8)
        if recv_crc == crc16_ccitt(body):
            frames.append((rx_buf[2], rx_buf[3], bytes(rx_buf[5:5 + ln])))
        drop_rx(total)
 
    return frames
