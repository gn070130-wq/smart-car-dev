摘    要
本作品针对智能视觉组比赛中基于屏幕视觉感知的虚实融合硬件在环环境，设计了一套集视觉解析、自主决策与运动控制于一体的智能车系统。由于车模无法直接获取虚拟环境数据，仅能通过车载视觉模块对显示屏信息进行采集与分析，因此系统面临视觉反馈延迟、地图信息实时解析以及复杂任务规划等问题。
本系统采用多视觉处理模块协同架构，其中视觉处理单元负责屏幕图像采集、目标识别及地图信息解析，主控单元完成地图建模、任务决策、路径规划以及运动控制。针对推箱子任务中状态空间复杂、规划实时性要求高的问题，设计了面向嵌入式平台的自主任务规划方法，在保证系统实时性的同时实现复杂场景下的路径决策。
在运动控制方面，采用博思M车模，结合麦克纳姆轮全向运动特性，建立车体运动模型，并利用视觉反馈与编码器信息实现闭环控制，提高车模在动态环境下的定位精度与运行稳定性。同时，针对屏幕显示环境存在反光、亮度变化以及视觉采集稳定性问题，设计了封闭式视觉结构，提高图像获取可靠性。
最终系统实现了从屏幕环境感知、地图解析、任务规划到运动执行的完整自主闭环流程，为复杂虚拟环境下嵌入式智能车系统设计提供了一种有效方案。
关键词：智能视觉、屏幕视觉感知、地图解析、路径规划、推箱子任务、麦克纳姆轮、闭环运动控制、视觉反馈。




















第一章 引言
1.1 大赛背景与赛题介绍
全国大学生智能汽车竞赛是由教育部高等学校自动化类专业教学指导委员会主办的面向全国大学生的探索性工程实践活动。竞赛以“立足培养、重在参与、鼓励探索、追求卓越”为宗旨，旨在促进高等学校素质教育，培养大学生的综合知识运用能力、基本工程实践能力和创新意识。
第二十一届全国大学生智能汽车竞赛智能视觉组采用“虚实融合推箱子”赛题，该赛题基于硬件在环（Hardware-in-the-Loop）架构构建虚拟与现实结合的智能车运行环境。与传统智能车任务相比，参赛车模无法直接获取虚拟环境中的数字化地图信息，而需要通过车载视觉模块采集显示屏中的虚拟场景，并完成地图解析、任务决策以及运动控制。
该模式将传统智能车中的环境感知问题扩展为视觉理解与自主决策问题。车模需要在有限计算资源条件下完成从图像信息获取、环境建模、路径规划到运动执行的完整闭环过程，对视觉识别实时性、任务规划能力以及运动控制稳定性提出了更高要求。
根据任务复杂程度，比赛设置了基础推箱、分类推箱以及策略推箱三个阶段。基础模式要求车模完成基本箱体移动任务；分类模式进一步增加视觉识别需求，需要根据箱体特征与目标信息完成对应规划；策略模式引入特殊元素，使任务由单纯路径搜索扩展为包含环境变化和策略决策的综合规划问题。
随着任务复杂程度逐步提升，系统不仅需要具备稳定可靠的视觉识别能力，还需要在嵌入式计算平台上完成实时地图分析、任务规划以及运动控制，实现复杂虚拟环境下的自主运行。
1.2 系统设计目标
针对第二十一届全国大学生智能汽车竞赛智能视觉组虚实融合推箱子任务中视觉信息获取困难、任务状态复杂以及运动控制精度要求高等问题，本系统设计了一套集视觉感知、自主决策与运动控制于一体的嵌入式智能车系统。
系统以NXP i.MX RT1064作为核心控制平台，通过车载视觉模块对显示屏中的虚拟环境进行实时解析，获取地图元素、目标信息以及任务状态，并在主控平台上完成地图建模、路径规划和任务调度。
针对推箱子任务中状态空间复杂、规划实时性要求高的问题，系统设计了适用于嵌入式平台的自主任务规划方法，在有限计算资源条件下实现复杂场景下的路径搜索与任务决策。同时，结合四轮麦克纳姆轮全向运动特性，建立车体运动模型，通过编码器反馈与姿态信息融合实现精确运动控制。
此外，针对屏幕视觉采集中存在的环境光干扰、显示反光以及视觉反馈延迟等问题，系统设计了封闭式视觉采集结构，并结合视觉校正与运动反馈方法，提高环境感知可靠性和车模运行稳定性。
1.3 智能视觉组比赛规则
比赛使用博思M车模等指定型号底盘，地面投影面积不超过35cm×35cm。车顶需水平固定官方提供的方位标识牌（30cm×15cm，安装高度15±0.5cm），标识牌包含AprilTag码（TAG16H5系列）用于全局定位。主控MCU限定使用NXP公司产品（推荐i.MX RT系列），图像处理平台限定基于NXP MCU的指定模块（如OpenART Plus、MCXVision等）。
物理场地尺寸约3.2m×2.4m，为蓝色平面，黄色胶带标示边界。场地四角固定AprilTag码（#15-#18）用于全局摄像头自动标定与逆透视校正。车载屏幕通过无线投屏接收组委会VR软件渲染的二分屏画面（左侧全局俯视图720×540，右侧第一人称视角720×540），该屏幕是车模感知虚拟环境的唯一窗口。
比赛过程中，车模需要根据视觉解析结果完成虚拟环境中的推箱任务。成绩以完成所有箱子推动或陷入死局为结束，最终成绩由运行时间和未完成箱子罚时共同决定。车模虚拟角色不可穿越围墙，否则导致比赛结束。详细规则参见官方比赛细则文件。
1.4 本文主要工作与章节安排
本文围绕第二十一届全国大学生智能汽车竞赛智能视觉组虚实融合推箱子任务，系统介绍了黑龙江科技大学速墨七队参赛车模的设计与实现。
全文主要围绕机械结构设计、硬件电路设计、软件控制算法、视觉识别方案以及系统调试过程展开。第一章介绍大赛背景、赛题特点以及系统设计目标；第二章介绍车模总体方案设计，包括系统架构、硬件在环数据链路以及关键技术选型；第三章详细介绍机械结构设计，包括车模底盘、视觉暗室以及安装结构设计；第四章介绍硬件电路设计，包括主控系统、电源模块、电机驱动以及传感器接口设计；第五章介绍软件控制设计，包括运动控制、路径规划以及任务调度方法；第六章介绍视觉识别方案，包括屏幕地图解析、图案数字分类以及车模定位方法；第七章介绍系统开发流程和调试过程中遇到的问题及解决方案；第八章总结车模主要技术参数；第九章对整体设计工作进行总结，并提出后续改进方向。




第二章 总体方案设计
2.1 系统总体架构
图2.1 系统总体架构框图
本届智能视觉组赛题采用基于硬件在环的虚实结合运行环境，车模无法直接获取虚拟场景中的结构化数据，需要通过车载视觉模块采集显示屏图像，并完成环境理解、任务决策以及运动控制。因此，系统需要解决视觉信息实时解析、复杂任务规划以及运动状态反馈等问题。
针对上述需求，本系统设计了“视觉感知—决策规划—运动控制”的三级架构。视觉感知层负责从屏幕图像中提取环境信息，包括地图元素识别、目标信息获取以及自身状态估计；决策规划层基于视觉解析结果完成地图建模、任务规划以及运动路径生成；运动控制层结合麦克纳姆轮运动特性，实现车体运动执行与状态反馈。
在视觉处理部分，系统采用双OpenART Plus协同架构，根据任务需求分别承担地图解析和目标特征识别任务，以降低单一视觉模块计算压力，提高信息处理实时性。主控单元采用RT1064完成地图规划、运动决策以及控制指令生成，并通过闭环控制实现车模稳定运行。
2.2 硬件在环架构与数据链路
系统整体运行流程如下：场地环境信息经过虚拟仿真系统生成，并通过显示屏呈现；车载视觉模块采集屏幕图像，对其中包含的地图、目标以及任务信息进行解析，并将结构化结果传输至RT1064主控。
RT1064根据视觉解析结果完成地图建模、任务规划以及运动控制计算，随后输出控制信号驱动麦克纳姆轮底盘运动。同时，系统通过编码器及姿态反馈信息对运动状态进行修正，实现视觉感知、决策规划和运动执行之间的闭环。
需要说明的是，车模不直接获取虚拟环境中的结构化数据，而是通过自身视觉系统完成环境信息获取，使整个系统具备类似真实机器人视觉感知的工作流程。
2.3 关键技术选型
主控单元选用NXP i.MX RT1064作为系统核心处理器。由于推箱子任务涉及地图解析、状态搜索以及运动控制等计算过程，需要主控具备较高计算性能和较大的片上存储资源，因此选择具备Cortex-M7内核的RT1064作为决策与控制核心。
图像处理部分采用两块OpenART Plus模块完成视觉任务处理。考虑到屏幕图像解析和目标特征识别具有不同处理需求，通过任务分配方式降低单模块负载，提高视觉处理实时性。
摄像模块选用SCC8660广角摄像头，用于近距离采集车载显示屏画面，满足较大视野范围和稳定图像获取需求。
底盘驱动采用DRV8701E结合MOSFET构成电机驱动模块。由于麦克纳姆轮运动过程中存在频繁正反转和速度变化，需要驱动模块具备较好的响应能力以及足够的输出能力。
姿态检测采用ICM-42688六轴惯性传感器，用于辅助获取车体运动状态，提高运动控制过程中的稳定性。
2.4 系统设计特点
针对虚实融合推箱子任务特点，本系统主要围绕视觉信息获取、嵌入式自主规划以及高精度运动控制三个方面进行设计。
（1）采用双视觉处理架构，将地图解析与分类识别任务分离，提高系统任务处理效率；
（2）针对嵌入式平台计算资源限制，实现面向RT1064平台的推箱任务规划与状态管理；
（3）结合视觉位置校正与编码器里程计，实现运动过程中的连续定位，提高复杂任务环境下的执行稳定性。








第三章 机械结构设计
3.1 车模底盘选型
本系统选用逐飞科技博思M车模作为运动平台，采用四轮麦克纳姆轮全向移动结构。相比传统差速底盘，麦克纳姆轮能够实现平移、旋转以及复合运动，使车模在执行推箱任务过程中无需频繁调整车身姿态即可完成横向调整和位置修正。
推箱子任务对车模与箱体之间的相对位置精度要求较高，尤其是在箱体推动前需要完成精确对位。因此，全向运动底盘能够降低路径调整复杂度，提高任务执行过程中的灵活性。
改装后整车尺寸为28cm×21cm×15cm（含标识牌支架），满足比赛规则对于车模尺寸限制要求。
图3.1 车模整体侧面图
3.2 3D打印暗室结构设计
由于本届智能视觉组采用屏幕视觉感知方式，车载摄像头需要直接采集显示屏中的虚拟环境信息。与传统环境视觉识别不同，屏幕拍摄过程中容易受到环境光反射、屏幕亮度变化以及镜面反射等因素影响，导致图像颜色偏移和特征识别稳定性下降。
针对上述问题，本系统设计了一套封闭式3D打印视觉暗室，通过主动隔绝外部环境光，建立稳定的屏幕采集环境。暗室结构将OpenART Plus视觉模块与赛用屏幕进行整体封装，使摄像头采集图像主要受到屏幕自身显示特性的影响，从而提高视觉信息的一致性。
暗室主体采用黑色PLA材料，通过六片模块化结构拼接组成，包括前面板、后面板、左右侧板、顶部结构以及底部连接结构。黑色PLA材料具有较好的吸光特性，可以减少外部光线反射对摄像区域的影响。所有结构件均基于SolidWorks完成自主建模，并通过3D打印加工制作。
图3.2 暗室3D建模渲染图
3.3 摄像头与屏幕安装
两个OpenART Plus视觉模块安装于暗室内部，分别承担不同区域图像采集任务。其中一个模块负责获取全局地图信息，另一个模块负责获取任务相关视觉信息，实现视觉任务的分工处理。
摄像头安装位置经过多次实际测试确定，在兼顾视野范围、图像清晰度以及屏幕覆盖区域的基础上，设计对应固定支架。不同于传统可调节安装方式，本系统采用固定化结构设计，将摄像头最佳安装姿态直接集成至机械模型中，避免比赛运输以及运行振动导致视觉参数变化，提高系统重复性。
赛用屏幕通过定制化3D打印支架固定于暗室前侧，并通过偏振片降低屏幕镜面反射，提高视觉采集稳定性。
                                                                                      图3.4 屏幕与摄像头支架渲染
3.4 标识牌支架
标识牌支架根据组委会尺寸规范进行设计，通过三维建模完成结构优化，并采用3D打印加工。支架尺寸满足官方标识牌安装要求，同时结合整车高度约束进行设计，使安装标识牌后的车模整体尺寸满足比赛规范。
3.5 控制面板与电路板固定
控制面板及主控电路板采用模块化安装方式固定于车模底盘。考虑到比赛过程中调试频繁以及维护需求，机械结构设计阶段充分利用底盘预留安装孔位，在PCB设计阶段同步规划固定孔位，实现机械结构与电气系统的一体化设计。
主控电路板安装于车体中心区域，以降低质量分布不均对运动控制产生的影响；控制面板布置于车尾区域，便于比赛过程中的参数调整与状态观察。\



第四章 硬件电路设计
4.1 系统硬件框图
本车模硬件系统围绕“视觉感知—自主决策—运动执行”的整体架构进行设计，以NXP RT1064作为核心控制单元，完成地图处理、任务规划以及运动控制。
系统硬件主要由视觉处理模块、主控计算模块、运动驱动模块、电源模块以及人机交互模块组成。其中，视觉处理模块由两块OpenART Plus构成，负责屏幕图像采集与环境信息解析；主控模块基于RT1064完成数据处理和控制决策；运动执行模块采用多路电机驱动电路控制四轮麦克纳姆底盘运动。
为提高系统集成度与可靠性，整车设计了主控电路板和控制面板两块PCB。其中主控电路板集成核心控制、电源管理、电机驱动以及传感器接口，控制面板负责调试交互功能。
图4.1 系统硬件框图
4.2 主控电路板设计
主控电路板采用四层PCB结构设计，安装于车模中心区域，用于实现控制核心、电源管理、电机驱动以及外围接口的一体化集成。
主控部分采用核心板与底板分离设计，将计算核心与外围电路进行模块化划分，在保证系统稳定性的同时提高调试和维护效率。
电路板主要集成以下功能模块：
（1）RT1064核心控制模块：负责地图信息处理、任务规划以及运动控制算法执行；
（2）电源转换模块：根据不同功能模块需求提供稳定电压；
（3）电机驱动模块：集成四路电机驱动电路，实现麦克纳姆轮运动控制；
（4）传感器及通信接口：提供编码器、惯性传感器以及OpenART视觉模块的数据接口。
PCB布局过程中，将主要器件和调试接口集中于板面同侧，方便装配、测试以及后期维护。
4.3 电源模块
车模采用3S锂电池作为主供电源，根据不同模块的工作需求设计多路电源转换系统。由于视觉模块、主控芯片、电机驱动以及显示设备对供电电压需求不同，系统通过降压电路分别产生对应电压轨，为各功能模块提供独立稳定供电。
在电源设计过程中，针对电机运动过程中产生的电流变化以及数字电路高速工作产生的噪声问题，各电源轨均配置去耦电容以及滤波网络，提高系统供电稳定性，降低电源波动对视觉识别和控制系统的影响。
4.4 电机驱动电路
为满足麦克纳姆轮底盘高速响应以及频繁正反转控制需求，系统采用分立MOSFET结合栅极驱动芯片的电机驱动方案。
驱动部分由4片DRV8701E构成四路H桥驱动电路，每路驱动对应一个直流电机。相比集成式电机驱动模块，分立MOSFET方案能够根据实际电流需求选择功率器件，在散热能力以及大电流工作可靠性方面具有更好的适应性。
同时，将电机驱动电路直接集成于主控PCB中，减少了驱动板与主控板之间的连接线，提高了系统整体可靠性和结构紧凑性。
4.5 传感器选型
系统采用ICM-42688六轴惯性传感器用于车体姿态检测，通过SPI接口与RT1064通信，为运动控制提供航向状态反馈。
同时，四个车轮分别配置1024线正交编码器，用于获取轮速信息。编码器输出AB相正交信号，可实现速度测量以及运动方向判断，为底盘闭环控制提供实时反馈。
4.6 控制面板与车载屏幕
为实现比赛运行与调试操作的功能分离，系统设计独立控制面板作为人机交互模块。
控制面板通过排线与主控电路连接，集成运行模式切换、参数调整以及状态显示功能，便于比赛过程中快速调试。
赛用5英寸IPS显示屏安装于视觉暗室内部，作为车载视觉系统的信息来源，由OpenART模块采集屏幕图像完成环境解析；2英寸IPS调试屏则面向参赛人员，用于显示系统状态和调试信息。
两块显示屏分别承担“环境感知”和“人机交互”功能，避免调试信息对视觉采集造成干扰。

第五章 软件控制设计
5.1 软件总体架构
针对智能车系统中视觉解析、任务规划以及运动控制具有不同实时性需求的问题，本系统采用“双循环+状态机”的软件架构，将实时控制任务与任务流程管理任务进行分离。
快循环运行于定时中断中，主要负责传感器数据采集、运动状态更新以及底盘闭环控制，保证车模运动过程中的实时响应；慢循环运行于主循环中，负责地图信息处理、任务规划、模式切换以及状态管理等非实时任务。
系统通过状态机方式组织不同比赛模式的任务流程，使基础推箱、分类推箱以及策略模式具有独立的软件逻辑，同时提高程序结构的可维护性。

5.2 运动控制算法
为实现车模在推箱任务中的精准移动，系统采用基于反馈控制的运动控制方案。控制系统根据目标位置与实际运动状态之间的偏差进行实时调节，使车模能够完成直线移动、横向调整以及旋转等动作。
由于采用四轮麦克纳姆轮底盘，系统根据车体运动需求进行速度分解，将期望运动速度转换为四个车轮的目标速度，并结合编码器反馈获取实际运动状态，实现底盘闭环控制。
在定位方面，系统融合轮速信息与姿态信息进行运动状态估计。考虑到编码器积分过程中存在累计误差，系统利用视觉识别结果对运动状态进行阶段性校正，提高长距离运动过程中的定位可靠性。
通过上述控制方式，系统能够在复杂推箱任务中实现较高精度的位置调整，为后续任务执行提供稳定运动基础。
5.3 路径规划算法
推箱子任务区别于传统移动机器人路径规划问题，其不仅需要规划车模自身运动路径，还需要考虑箱子移动顺序、目标匹配以及环境状态变化。因此，系统将推箱任务规划划分为任务层规划和运动层规划两个部分。
在任务层规划中，系统基于地图信息建立离散化环境模型，并采用搜索算法完成箱子推动方案分析。其中，利用BFS（广度优先搜索）对推箱状态空间进行遍历分析，寻找满足任务要求的可行状态转移过程；针对多箱子、多目标情况下组合数量快速增长的问题，引入DFS（深度优先搜索）及剪枝策略降低搜索规模，提高规划效率。
在运动层规划中，采用A*启发式搜索算法完成车模当前位置到目标位置之间的路径规划。算法综合考虑当前位置代价与目标距离估计，通过启发函数引导搜索方向，在保证路径有效性的同时提高搜索效率。针对麦克纳姆轮底盘运动特点，在路径评价过程中加入运动平滑性因素，减少不必要的转向动作。
最终生成的任务规划结果由运动控制模块逐段执行，并结合编码器反馈与姿态信息完成闭环定位。在执行过程中，系统通过视觉信息进行阶段性校准，以降低累计误差对任务完成效果的影响。
5.4 任务调度状态机
为保证不同任务模式之间逻辑清晰，系统采用“全局状态管理+任务子状态机”的调度方式。
全局状态机负责控制比赛整体流程，包括启动、地图获取、任务选择、执行以及结束状态切换；不同比赛模式分别对应独立任务状态机，用于管理各自的执行流程。
模块化状态机设计使不同任务之间相互隔离，便于功能调试和算法优化，同时提高程序结构的可扩展性。
5.5 模块间通信协议
系统采用串口通信方式实现RT1064主控与视觉处理模块之间的数据交互。根据不同视觉任务需求，两个视觉模块分别负责地图信息解析和目标特征识别，并将处理结果发送至主控。
通信协议采用结构化数据传输方式，通过数据帧封装、状态校验等机制提高通信可靠性，避免视觉数据异常对任务执行造成影响。
主控接收到视觉信息后完成数据解析，并结合当前任务状态进行路径规划和运动控制。
5.6 视觉延迟补偿与定位修正
由于视觉信息需要经过采集、识别以及通信传输过程，高速运动状态下视觉反馈存在一定时间滞后。系统结合运动状态预测与视觉校正方式，对视觉反馈结果进行修正，提高高速运行过程中的定位可靠性。




第六章 视觉识别方案
6.1 屏幕地图识别
图6.1 地图识别流程示意图
地图识别由OpenART Plus #1负责，主要完成屏幕全局地图区域的信息解析。考虑到比赛地图元素具有固定尺寸、固定颜色以及规则化分布特点，本系统采用基于颜色特征分析的轻量级视觉方案，实现对地图信息的快速提取。
具体流程包括地图区域定位、网格划分以及元素分类三个步骤。首先确定有效地图区域，然后按照地图结构进行离散化划分，对各网格区域进行颜色特征分析，识别墙体、箱子、目标点、炸弹等元素，并生成结构化地图数据发送至主控。
在颜色空间选择方面，系统采用LAB色彩空间进行特征提取。相比RGB空间，LAB空间能够将亮度信息与颜色信息分离，在屏幕亮度变化情况下具有更好的颜色稳定性。结合封闭式暗室结构以及偏振处理，有效降低环境光变化对识别结果的影响。
该方案计算量较低，能够满足嵌入式平台实时处理需求，为后续地图规划提供稳定输入。
6.2 图案与数字分类识别
图案与数字分类任务由OpenART Plus #2负责，主要应用于分类推箱模式以及策略模式。由于箱体图案和数字信息具有较强的语义特征，仅依靠颜色阈值难以完成稳定识别，因此采用轻量级神经网络模型进行分类。
在任务执行过程中，主控根据当前任务状态发送识别请求，视觉模块采集对应区域图像并完成分类推理，将识别结果反馈至主控，用于建立箱体与目标之间的对应关系。
分类模型采用轻量化卷积神经网络结构，并针对嵌入式运行环境进行优化，在保证识别准确性的同时降低计算资源需求。模型设置无效类别用于处理图像质量不足或分类置信度较低的情况，提高实际运行过程中的鲁棒性。
根据任务需求，系统分别完成数字信息和图案信息识别，并将结果转换为结构化数据参与后续任务规划。
6.3 车模自定位
针对屏幕视觉反馈存在一定处理延迟，而编码器定位存在累计误差的问题，系统采用视觉校正与里程计推算相结合的定位方式。
在每段运动开始前，视觉模块通过检测屏幕中的车模标识信息，获取当前虚拟环境中的位置状态，并转换为实际坐标信息，作为运动控制的初始参考。
在运动过程中，系统主要依靠编码器反馈进行连续位置估计，通过麦克纳姆轮运动模型计算车体运动状态，并结合惯性传感器获取姿态变化，提高短距离移动过程中的定位稳定性。
由于推箱任务中单次移动距离有限，采用阶段性视觉校正能够有效限制里程计累计误差，同时避免连续视觉定位带来的计算压力以及反馈延迟问题。




















第七章 开发与调试
7.1 开发工具链
本系统开发过程涉及嵌入式控制、视觉算法以及任务规划三个方向，采用多平台协同开发方式。
主控程序基于RT1064平台开发，主要完成运动控制、任务调度以及路径规划算法部署；视觉模块基于OpenART Plus平台完成图像采集与识别算法开发；推箱子规划算法通过虚拟环境进行离线验证，用于测试不同地图条件下的任务规划效果。
在调试过程中，系统配备无线调试接口以及车载人机交互模块，实现脱离电脑环境下的实时状态监测。通过调试屏幕可查看当前位置、运动状态、任务流程等关键参数，提高现场调试效率。
7.2 关键问题与解决方案
7.2.1 屏幕反光与环境光干扰
由于车载摄像头需要直接采集显示屏画面，外部环境光容易在屏幕表面产生反射，使图像出现亮度变化和颜色偏移，影响视觉识别稳定性。
针对此问题，系统从机械结构、光学处理以及安装一致性三个方面进行优化。首先设计封闭式3D打印暗室，将摄像头与屏幕置于相对独立的视觉环境中，减少外部光源干扰；其次在屏幕表面增加偏振处理，降低镜面反射影响；最后通过实验确定摄像头安装位置，并设计固定支架保证装配一致性。
通过上述措施，提高了屏幕图像采集的稳定性，为后续颜色识别和地图解析提供可靠输入。
7.2.2 串口通信丢帧与数据错误
在系统联调过程中发现，视觉模块与主控之间的数据传输在高频数据交互情况下存在偶发异常，导致地图信息解析错误。
经分析，问题主要来源于串口通信过程中数据边界识别以及异常数据干扰。针对该问题，系统对通信流程进行优化，通过增加数据有效性检测机制，提高接收端对异常数据的识别能力，同时优化发送和接收流程，降低通信异常对任务执行的影响。
优化后，视觉信息传输稳定性得到提升，保证了地图解析和任务规划过程的可靠运行。
7.2.3 推箱子搜索耗时控制
在多箱子、多目标任务场景下，推箱子规划面临状态空间快速增长的问题。如果直接搜索全部可能状态，将导致计算时间增加，无法满足嵌入式平台实时运行需求。
针对该问题，系统在规划过程中引入搜索优化方法，通过降低无效状态扩展数量，提高搜索效率，使任务规划时间满足比赛运行要求。
优化后的规划算法能够在RT1064有限计算资源条件下完成复杂地图任务分析，为自主推箱提供实时决策支持。
7.2.4 编码器里程计定位漂移
麦克纳姆轮底盘在运动过程中，由于滚轮结构特点以及地面接触状态变化，容易产生一定程度的滑移误差。若仅依靠编码器进行长时间积分，累计误差会逐渐影响定位精度。
针对此问题，系统采用视觉校正与里程计估计相结合的定位方式。在每段运动开始前，通过视觉信息获取当前位置作为校准参考；运动过程中利用编码器和姿态传感器进行连续状态估计，将误差控制在较短运动区间内。
该方法充分利用视觉定位的绝对参考能力和里程计连续运动估计能力，提高了复杂推箱任务中的定位稳定性。

第九章 结论
9.1 工作总结
本文针对第二十一届全国大学生智能汽车竞赛智能视觉组赛题需求，设计了一套基于嵌入式视觉感知与自主决策的智能车系统。
系统以RT1064作为核心控制平台，结合双OpenART Plus视觉处理模块，实现了从屏幕环境感知、地图解析、任务规划到运动执行的完整闭环流程。
在机械结构方面，针对屏幕视觉采集过程中存在的环境光干扰问题，设计了封闭式视觉采集结构，提高了图像获取稳定性；在硬件方面，自主设计集成控制、电源以及驱动模块的一体化电路系统，提高了整车集成度；在软件方面，实现了视觉信息解析、推箱任务规划以及底盘闭环控制等功能。
通过多阶段仿真验证与现场调试，系统完成了不同任务模式下的自主运行，验证了方案在嵌入式平台上的可行性。
9.2 存在的问题与改进方向
虽然当前系统已经完成比赛任务要求，但仍存在进一步优化空间。
在视觉识别方面，可以进一步优化轻量化模型结构，提高复杂分类任务下的响应速度；在路径规划方面，可以结合更加高效的启发式搜索方法，提高复杂地图情况下的规划效率；在定位方面，可以进一步融合多源传感信息，提高高速运动状态下的位置估计精度。
后续工作将围绕算法优化、系统集成以及可靠性提升展开，进一步提高智能车系统在复杂任务环境中的自主运行能力。

B.1 麦克纳姆轮运动解算子程序
该程序根据四个车轮的编码器反馈计算车体在平面内的运动增量，并结合姿态角完成坐标系转换，为里程计定位提供基础数据。
void mecanum_odometry_update(void)
{
    float wheel_delta[4];
    float body_vx, body_vy;
    float field_dx, field_dy;
    float yaw_angle;
    float cos_yaw, sin_yaw;
    /* 读取四个车轮在当前周期内的运动增量 */
    for (int i = 0; i < 4; i++)
    {wheel_delta[i] = read_wheel_delta(i); }
    /* 根据麦克纳姆轮运动学关系解算车体坐标系位移 */
    body_vx = ( wheel_delta[0] - wheel_delta[1]
              - wheel_delta[2] + wheel_delta[3]) / 4.0f;
    body_vy = ( wheel_delta[0] + wheel_delta[1]
              + wheel_delta[2] + wheel_delta[3]) / 4.0f;
    /* 读取当前航向角 */
    yaw_angle = get_vehicle_yaw();
    cos_yaw = cosf(yaw_angle);
    sin_yaw = sinf(yaw_angle);
    /* 将车体坐标系位移转换到场地坐标系 */
    field_dx = body_vx * cos_yaw + body_vy * sin_yaw;
    field_dy = -body_vx * sin_yaw + body_vy * cos_yaw;
    /* 更新当前位置估计 */
    vehicle_position.x += field_dx;
    vehicle_position.y += field_dy;
    /* 清除本周期累计量 */
    reset_wheel_delta();}
B.2屏幕地图网格识别子程序
该程序用于对屏幕中的全局地图区域进行网格化识别。系统先确定有效地图区域，再对各网格单元进行颜色特征分析，并将识别结果转换为结构化地图数据，供后续路径规划使用。
def recognize_map_grid(image):
    map_result = []
    # 获取屏幕中的有效地图区域
    map_area = locate_map_area(image)
    # 按照地图结构划分网格
    grid_list = split_to_grid(map_area)
    for grid in grid_list:
        # 提取当前网格区域图像
        block_image = crop_region(image, grid)
        # 分析该网格的主要颜色特征
        color_feature = extract_color_feature(block_image)
        # 根据颜色特征判断地图元素类型
        element_type = classify_map_element(color_feature)
        # 写入结构化地图结果
        map_result.append(element_type)
return map_result
B.3地图元素分类函数
该函数根据颜色特征判断当前网格对应的地图元素类别。实际工程中会结合屏幕亮度、色彩稳定性和识别置信度进行综合判断。
def classify_map_element(color_feature):
    if match_wall_feature(color_feature):
        return MAP_WALL
    elif match_box_feature(color_feature):
        return MAP_BOX
    elif match_target_feature(color_feature):
        return MAP_TARGET
    elif match_special_feature(color_feature):
        return MAP_SPECIAL
    else:
        return MAP_EMPTY
B. 4 控制任务执行流程
主控程序根据视觉模块发送的地图信息完成任务规划，并将规划结果转换为底盘运动指令。执行过程中，系统结合编码器和姿态传感器反馈进行闭环控制。
void task_execute_loop(void)
{
    MapData current_map;
    PathData path;
    MotionCommand command;
    /* 获取视觉模块解析后的地图信息 */
    current_map = receive_map_data();
    /* 根据当前地图和任务要求生成路径 */
    path = plan_task_path(current_map);
    while (!path_finished(path))
    {
        /* 根据路径生成运动指令 */
        command = get_next_motion_command(path);
        /* 执行底盘运动控制 */
        motion_control(command);
        /* 更新运动状态 */
        mecanum_odometry_update();
        /* 根据反馈信息修正执行过程 */
        update_motion_state();
    }
}
