摘　　要

本文详细介绍了安徽理工大学“路径规划对不队”在第二十一届全国大学生智能汽车竞赛人工智能视觉组中的系统方案。作为今年的智能视觉组，我们选用大赛组委会提供的M车模完成比赛任务。系统以NXP i.MX RT1064为核心控制器，搭载逐飞科技OpenART视觉模块进行识别虚拟地图感知；通过四路正交编码器检测各轮实时速度，使用ICM42688六轴陀螺仪获取车模偏航角；采用麦克纳姆轮实现全向移动，结合增量式与位置式PID控制算法实现速度与角度的闭环控制。在软件层面，设计了基于搜索状态机的推箱子决策系统，通过双层BFS路径搜索、DFS、贪心、奖罚机制进行动作序列规划与TNT爆炸机制求解最优推箱序列，并通过VOFA+无线调参上位机、IPS200显示屏及按键等人机交互工具进行参数整定与调试。实验结果表明，该系统设计方案可行，能够在比赛规则下稳定、高效地完成多关卡推箱子任务。
关键词：人工智能视觉；惯性导航；路径规划；图像处理；PID控制

第一章　引言
1.1　竞赛任务与设计要求
第二十一届全国大学生智能汽车竞赛人工智能视觉组采用“虚实融合”的全新比赛模式，突破了传统智能车竞赛单纯比拼速度与图像处理精度的框架，引入了虚拟游戏系统与推箱子任务。比赛场地为矩形平面区域，场地四周使用5cm宽的黄色布基胶带作为边界标识，四角贴有AprilTag码，供系统进行全局自动定位。车模本体上方需水平安装30cm×15cm的方位标识牌，标识牌包含AprilTag码与红绿色矩形区域，安装高度固定为15cm，采用磁吸方式固定，便于快速拆装。
比赛内容以虚拟推箱子游戏为核心。比赛共设三个关卡，系统在官方地图库中随机抽取每关的具体地图配置。车模从车库出发时计时开始，需连续完成三个关卡的推箱子任务。在每个关卡中，场地内随机分布若干箱子，车模需要自主导航至箱子位置，并将箱子沿可行路径推至对应的目标位置。一个关卡有效完成的判定标准为：被推到目标位置的箱子数量达到该关卡箱子总数的50%及以上。若某关卡未达到此标准，则该关卡视为未完成，每少完成一个关卡罚时300秒；在已有效完成的关卡中，每遗漏一个箱子（即该箱子未被推至目标位置），罚时30秒。最终成绩以完成全部三个关卡的总用时（含罚时）进行排名。
上述任务对车模系统的综合性能提出了极高要求：车模不仅需要具备准确的视觉感知与定位能力，还需要具备高效的路径规划与决策能力、平稳的全向运动控制能力以及鲁棒的姿态保持能力。如何在一个紧凑的嵌入式平台上实现视觉感知、任务决策、运动规划与实时控制的高效协同，是本赛题的核心技术挑战。
1.2　智能汽车制作情况概述
本参赛队伍自确定选题以来，围绕人工智能视觉组的赛题要求，进行了从需求分析、系统架构设计、硬件选型、机械改装到软件算法开发的全流程设计与实现。整个制作周期历时约六个月，经历了方案论证、分模块调试、整车集成、赛道测试与参数优化等多个阶段。
在硬件架构方面，本系统以逐飞科技生产的i.MX RT1064高性能核心板作为主控制器，该芯片基于Arm Cortex-M7内核，主频高达600MHz，具备丰富的外设接口和较强的运算能力，能够满足实时控制与中等复杂度算法运算的需求。视觉感知模块选用OpenART视觉模块，负责虚拟地图信息获取，通过UART串行通信将识别结果传输至主控MCU。运动控制方面，车模采用四个独立的直流减速电机驱动麦克纳姆轮，每个电机均配备增量式正交编码器，实现对转速的精确闭环控制；同时搭载ICM42688六轴陀螺仪用于实时获取车模偏航角与姿态信息，为惯性导航与角度闭环控制提供数据支撑。
在机械结构方面，我们在符合竞赛规则的前提下对车模进行了合理改造：通过3D打印制作了暗箱以及必要的外部结构件；合理布置主控板、驱动板、电池及各传感器模块，力求降低车模重心、提高整车稳定性；对麦克纳姆轮的安装精度进行了反复校准，确保四个轮子与地面接触良好且传动效率一致。
在软件开发方面，我们采用模块化分层设计思想，将系统划分为视觉感知层、状态估计层、任务决策层、路径规划层和运动控制层。视觉感知层基于OpenART完成地图信息解析；状态估计层融合编码器里程计与陀螺仪数据，采用惯性导航算法获得车模在场地中的实时坐标与航向角；任务决策层根据虚拟游戏系统的地图信息，通过搜索状态机求解推箱子的最优行动序列，包括TNT爆炸位置决策、箱子与目标点的匹配识别以及推箱顺序规划；路径规划层通过贪心算法与基于BFS的平滑路径生成方法，规划车模在箱子和目标位置之间的可行走路径；运动控制层采用增量式PID速度环与位置式PID角度环相结合的控制策略，实现车模在麦克纳姆轮底盘下的全向移动与精确停靠。
通过各模块的反复联调与优化，本系统在稳定性、实时性和任务完成率方面均达到了预期设计目标。在实验室多轮模拟赛道测试中，车模能够稳定完成三个连续关卡的推箱子任务，具备较好的环境适应性和鲁棒性。
1.3　相关技术研究综述
推箱子问题是一类经典的组合优化与路径规划问题，其本质属于NP难问题，在人工智能与计算智能领域具有长期的研究历史。针对小规模地图（如本赛题中不超过20×20的网格地图），当前主流求解方法包括基于逆向搜索的推箱子求解器（如Sokoban Solver系列）、基于强化学习的策略网络方法以及基于启发式搜索的规划方法。本赛题面临的推箱子任务相较于传统推箱子求解问题，存在两个显著区别：其一，车模作为物理实体在真实场地中运动，必须同时考虑运动学约束和控制精度；其二，地图信息由虚拟游戏系统通过视觉感知动态获取，存在感知噪声和定位误差，决策系统需要具有一定的容错能力。因此，本系统无法直接套用离线推箱子求解器，而需要在实时感知数据的基础上进行在线决策，这对算法的计算效率和鲁棒性提出了更高要求。
在麦克纳姆轮移动平台的运动控制方面，国内外已有大量研究工作。麦轮平台的全向移动能力使得车模可以在不改变朝向的情况下向任意方向平移，这一特性对推箱子任务中的精确对准非常有利。然而，麦轮平台也存在地面适应性较差、易打滑以及对安装精度敏感等固有问题。针对这些问题，本系统在设计中对轮系进行了反复标定，并在控制算法中加入了缓启动、积分分离以及微分先行等工程优化措施，在确保控制响应速度的同时有效抑制了超调与振荡。
在嵌入式实时系统的软件架构设计上，本系统借鉴了分层状态机和事件驱动架构的思想，将任务决策过程与底层执行过程解耦。任务决策层在关键状态切换时向控制层下发目标坐标与航向指令，控制层则独立执行路径跟踪与闭环调节，避免了决策算法阻塞控制循环的问题。同时，本系统借鉴了前几届智能视觉组参赛队伍的调试与开发经验，在VOFA+无线调参、按键与IPS200显示屏的人机交互等方面进行了系统化的工程实现，显著提升了调试效率和参数整定的便捷性。

第二章　系统总体设计方案
2.1　总体设计思路
针对第二十一届全国大学生智能汽车竞赛人工智能视觉组的虚实融合推箱子任务，本系统的总体设计遵循“实时感知—精准定位—最优决策—稳健控制”的设计主线，将整车上层智能决策与底层运动控制进行清晰分离，既保证了任务规划算法的计算完整性，又确保了运动控制的实时性与鲁棒性。
系统总体设计围绕以下几个核心原则展开：
（1）模块化分层架构原则。 将系统软件划分为视觉感知层、状态估计层、任务决策层、路径规划层和运动控制层五个层级。各层级之间通过定义良好的数据结构与接口函数进行数据交互，层级内部的具体实现细节对外部模块透明。这种设计使得各模块可独立开发、测试和优化，显著提升了系统的可维护性和调试效率。
（2）感知—决策—执行闭环原则。 车模在物理场地中的状态（位置、航向）通过编码器导航和视觉导航实时推算，经延迟补偿后融合生成当前车模的可靠位姿估计。任务决策层基于当前感知到的地图状态（箱子位置、目标位置、TNT位置）在线求解最优推箱序列，生成的行动指令经由路径规划模块转化为一系列期望航点，最终由运动控制层驱动车模逐点跟踪。整个系统构成一个闭环反馈控制回路，确保车模能够自适应地应对场地环境变化与执行过程中的累积误差。
（3）计算资源合理分配原则。主控MCU i.MX RT1064虽然具备600MHz的主频和较强的算力，但考虑到推箱子问题的搜索空间可能随着箱子数量的增加而迅速膨胀，本设计在决策层采用了带启发式剪枝的深度优先搜索（DFS）与状态哈希缓存机制，有效控制了单次决策的计算耗时。同时，将视觉感知中的图像采集与神经网络推理任务交由OpenART模块独立完成，主控MCU仅通过串口接收结构化的识别结果，避免了图像处理对实时控制循环的阻塞。
（4）工程实用性与可调参性原则。 考虑到比赛场地的光线条件、地面摩擦系数以及虚拟游戏系统的随机性，系统在多个关键环节设计了可在线调节的参数接口，包括PID控制参数（速度环Kp/Ki、位置环Kp/Kd）、缓启动步长、惯性导航死区阈值以及视觉定位延迟帧数等。上述参数可通过VOFA+无线调参上位机、按键及IPS200显示屏进行实时修改，极大地方便了现场调试与参数整定。
2.2　系统结构与组成
本系统由硬件平台与软件架构两大部分组成，整体结构如下。
硬件系统组成：硬件系统以逐飞科技i.MX RT1064核心板为控制核心，搭载以下功能模块：
主控单元：i.MX RT1064微控制器，负责系统总体调度、传感器数据采集与融合、任务决策与路径规划、运动控制解算以及人机交互等全部核心功能。
视觉感知单元：彩钻风全局快门摄像头，独立完成场地内AprilTag码的检测；OpenART视觉模块，独立完成虚拟地图信息的提取，将识别到的箱子位置、目标位置、TNT位置及玩家起始位置等信息通过UART串行总线发送至主控MCU。
运动执行单元：四个独立直流减速电机分别驱动四个麦克纳姆轮，每个电机由基于DRV8701方案的H桥驱动电路驱动，采用PWM+方向信号的控制方式。
状态反馈单元：四个增量式正交编码器分别安装于四个电机尾部，用于实时测量各轮转速与转角，为速度闭环与里程计推算提供数据来源；ICM42688六轴陀螺仪用于测量车模的偏航角度与角速度，为姿态控制与航向保持提供依据。
人机交互单元：按键用于菜单选择与参数调节；IPS200显示屏用于实时显示系统运行状态、关键变量与调试信息；无线转串口模块用于与VOFA+上位机进行无线通信，实现数据波形实时观测与参数在线整定。
软件系统组成：软件系统基于逐飞科技提供的底层驱动库进行开发，采用C语言编写，整体架构分为以下五个层次：
（1）底层驱动层：包括GPIO、UART、SPI、I2C、PWM、GPT定时器、ADC、正交编码器等外设的初始化与驱动程序，由逐飞底层库封装提供。
（2）传感器数据处理层：包括编码器速度与距离解算模块（Encoder.c）、陀螺仪姿态解算模块（angle.c）以及惯性导航模块（Inertial_Navigation.c）。该层将原始传感器数据转换为具有物理意义的车模状态量（X/Y坐标、航向角、各轮速度、线速度等），并对视觉定位数据进行延迟补偿与融合。
（3）运动控制层：包含增量式PID与位置式PID控制器（PID.c）、麦克纳姆轮运动学解算模块以及缓启动模块（Control.c）。该层根据期望速度向量（Vx, Vy, Vz）解算四个轮子的目标转速，再通过速度闭环PID驱动电机，实现车模的全向移动与精确定位。
（4）任务决策与规划层：这是本系统的核心算法层，包含推箱子决策状态机（Sokoban_sys.c）、行动序列搜索器（DFS搜索带哈希剪枝）、箱子与目标点匹配算法（match_id）、TNT爆炸位置决策算法（decision_DetonatePosition）、路径平滑生成器（solve_innerA_smoothedPath，expand_path_to_player_moves）等模块。该层根据当前地图状态与车模位姿，生成最优行动序列（包括TNT推炸、箱子识别、箱子推送等原子动作），并进一步将每个动作展开为车模可执行的航点序列。
（5）应用与调试层：包含主循环任务调度（UserMain.c）、菜单交互界面（Menu.c）、VOFA+无线调参任务（vofa_tune.c）以及调试打印任务（DEBUG.c）。该层负责协调各模块的执行时机，提供人机交互接口，并输出关键状态信息用于调试与验证。
整个系统的数据流方向为：OpenART视觉模块识别地图信息 → 主控MCU接收并解析 → 状态估计模块更新车模位姿 → 决策模块生成行动指令 → 路径规划模块生成航点序列 → 运动控制模块解算轮速并驱动电机 → 编码器与陀螺仪反馈形成闭环。同时，调试信息与参数交互通过VOFA+实现双向传输。


2.3　主控平台选型与说明
本系统主控平台选用逐飞科技生产的i.MX RT1064核心板，该核心板基于NXP公司的i.MX RT1064跨界处理器设计，芯片型号为MIMXRT1064DVL6A。i.MX RT1064处理器采用Arm Cortex-M7内核，主频最高可达600MHz，拥有高达1MB的片上SRAM和4MB的集成Flash，同时支持外部QSPI Flash扩展。该芯片具备丰富的外设接口，包括多个UART、I2C、SPI、PWM、ADC、正交编码器接口以及硬件浮点运算单元（FPU），能够在不增加额外协处理器的情况下完成中等复杂度的浮点矩阵运算与搜索算法计算。
选择i.MX RT1064作为主控平台主要基于以下考虑：
（1）性能优势。 600MHz的主频在Cortex-M7系列中处于领先水平，兼具DSP指令扩展与FPU，足以在实时控制循环（5ms周期）之外，承载推箱子搜索算法（DFS、BFS）和路径规划（贪心、BFS）等计算密集型任务。在实际测试中，对于8个箱子以内的推箱子搜索，单次决策耗时控制在500ms左右，不会对控制循环造成明显影响。
（2）比赛规则兼容性。 人工智能视觉组要求主控MCU必须采用NXP公司产品，i.MX RT1064属于官方推荐型号，且逐飞科技提供了完善的底层驱动库和开发例程，降低了开发门槛，缩短了开发周期。
（3）存储资源充足。 1MB SRAM足以容纳搜索过程中的状态备份、路径节点、哈希表等数据结构；4MB片上Flash配合外部Flash足以存储完整的程序固件和掉电参数。
（4）外设接口匹配。 芯片内置的4路正交编码器接口可直连增量式编码器，无需外部计数芯片；多路PWM输出可直接驱动电机驱动芯片；多路UART分别连接OpenART视觉模块、蓝牙调参模块以及无线串口，满足全部通信需求。
在视觉协处理器方面，本系统选用OpenART视觉模块。OpenART同样基于NXP i.MX RT系列处理器（RT1062），运行MicroPython固件，支持TensorFlow Lite Micro推理，能够独立完成虚拟地图信息的图像识别任务。OpenART与主控MCU之间通过UART串口通信，通信协议定义明确，包含地图提取指令（START_EXRACTION）、目标识别指令（START_TF_CHARACTERS与START_TF_NUM）以及位姿请求指令（SRTATE_RECEIVE_CARPOS）等，数据交互稳定可靠。
2.4　传感器方案
本系统根据不同功能需求，配置了四种类型的传感器，分别为视觉传感器、惯性测量单元、正交编码器以及辅助人机交互输入设备。各传感器的选型与配置方案如下：
（1）视觉传感器——OpenART视觉模块和彩钻风全局快门摄像头。 OpenART是逐飞科技基于NXP i.MX RT1062开发的嵌入式AI视觉模块，内置OV7725或MT9V034图像传感器，支持灰度与彩色图像采集，分辨率最高可达640×480。本系统中，彩钻风全局快门摄像头的核心任务是是检测场地四角的AprilTag码，为系统提供全局定位参考；OpenART的核心视觉任务是解析虚拟游戏系统投影在场地中的地图信息，包括箱子的位置、目标点位置、TNT炸药位置以及玩家（车模）的起始位置。OpenART通过串口以结构化数据包的形式将识别结果发送至主控MCU，主控接收到STATE_RECEIVE_FLAG标志后，通过发送请求指令（如START_EXRACTION、START_TF_CHARACTERS）触发相应的视觉识别流程。
（2）惯性测量单元——ICM42688六轴陀螺仪。本系统选用ICM42688（六轴MEMS惯性测量单元，集成三轴陀螺仪和三轴加速度计。陀螺仪用于测量车模绕Z轴（竖直轴）的偏航角速度，经积分可获取航向角；加速度计用于辅助姿态解算，通过互补滤波算法与陀螺仪数据融合，抑制陀螺仪的积分漂移，提高航向角的长期稳定性。在推箱子任务中，车模需要频繁调整航向以对准箱子和目标位置，准确的偏航角信息对于提高推送精度至关重要。本系统在angle.c中实现了基于四元数的互补滤波姿态解算算法（IMUupdate函数），并在初始化时自动进行陀螺仪零点偏移校准（gyroOffset_init）。
（3）正交编码器——增量式编码器。 四个电机尾部各安装一个增量式正交编码器，输出A/B两路正交脉冲信号，通过MCU内置的正交编码器接口进行计数。编码器原始计数值经标定系数换算为各轮的实际转速（cm/s）与累计转角，进而通过麦克纳姆轮运动学正解推算出车模在场地坐标系中的X轴、Y轴位移以及航向角变化量，形成里程计信息。编码器还作为速度闭环控制的反馈量，Control.c中的增量式PID控制器根据编码器测量转速与目标转速的偏差输出PWM占空比调整量，实现精确的电机转速控制。在惯性导航过程中（Navigation_Distance.Start_Flag == true），编码器累计位移被用作车模的相对位移基准，与视觉定位信息进行融合。
（4）传感器融合与延迟补偿策略。 由于OpenART视觉模块的图像采集、传输与处理存在一定的固有延迟（约3～6帧，对应15～30个5ms控制周期），直接将视觉定位坐标用于实时控制会导致系统振荡甚至失控。为解决这一问题，本系统在Encoder.c中实现了环形缓冲区视觉延迟补偿机制（Odometry_Process与On_Vision_Received函数）。具体做法为：在惯性导航使能后，系统在环形缓冲区中持续存储每一控制周期的编码器里程计坐标；当收到OpenART发送的视觉定位坐标时，读取缓冲区内与视觉数据时间戳对应的历史里程计坐标，计算两者之差作为延迟段内的编码器增量，再将该增量叠加到当前视觉坐标上，从而得到经过延迟补偿后的实时位姿估计（true_now_x与true_now_y）。这一机制有效消除了视觉延迟对闭环控制的不利影响，提高了车模在动态运动中的定位精度与稳定性。

4.1.2 第一级降压：DC-DC 5V 稳压 
使用 SCT2450STER 降压型 DC-DC 转换器（U3）将电池的高电压 VCCBAT 降压并稳压输出系统的主供电VCC_5V。
输入滤波：在 VIN 输入端并联了三种不同容值的电容：220uF 的大容量电解电容（C5）、4.7uF（C6）与 100nF（C7）的陶瓷电容。大电容负责吸收电池端的低频波动并提供瞬态大电流；小容值的陶瓷电容则利用其极低的等效串联电阻（ESR）和等效串联电感（ESL），有效滤除芯片开关时产生的高频噪声，防止高频干扰。
BOOT（引脚 1）与 SW（引脚 8）之间连接了一颗 100nF 的自举电容（C1）。由于 SCT2450STER 内部采用 N 沟道 MOSFET 作为高侧开关，当开关管导通时，其源极（SW 节点）电压会升至输入电压。此时需要电荷泵原理通过该自举电容提供高于 VIN 的栅极驱动电压，以确保内部开关管能够完全导通，降低导通损耗。
降压核心拓扑：功率电感 (L1)：选用 4.7uH 功率电感。当内部开关管导通时，电感储能并平滑电流；当开关管关断时，电感释放能量维持输出。4.7uH 的感值在保证输出电流响应速度的同时，有效控制了电流纹波。续流二极管选用 SS54 肖特基二极管。由于采用非同步 Buck 拓扑，在内部开关管关断的死区时间内，电感电流需要回路。SS54 具有极低的正向压降和极短的反向恢复时间，能够高效地承担续流任务，减少热损耗。

4.2　电机驱动电路设计
基于德州仪器（TI）DRV8701E 栅极驱动器的双路直流电机驱动板设计。电路使用了分立的 N 沟道 MOSFET 组成全桥（H桥），具备驱动大电流负载的能力。
4.2.1 电源输入及滤波电路
电源输入 (P3 端子)：驱动板的 VCC 来自主板上的XT30接口，主板由12v电池供电，经过开关及保护电路后直接接给驱动板。
储能与滤波 (C11)：在电源入口处并联了一颗 220uF 的大容量电解电容。由于电机在频繁启停、正反转切换时会产生巨大的瞬态电流抽取和反电动势，该电容能有效平滑母线电压（VCC），防止电压剧烈抖动导致驱动芯片触发欠压保护（UVLO）而频繁复位。  




        







4.2.2 驱动电路
工作原理：芯片的PH 引脚负责控制电机的运转方向（正转或反转），EN 引脚则负责控制输出的开启与关闭。PWM 占空比决定有效电压：主控 MCU 并不会输出一个真实的模拟电压，而是通过 EN 引脚输入一个高频的方波（PWM）信号。当 PWM 信号处于高电平时，H 桥完全导通，电机两端承受全部的母线供电电压。当 PWM 信号处于低电平时，H 桥进入“制动/慢速衰减”模式，此时电机两端被短接接地，电压降为 0V。宏观等效计算：由于 PWM 信号的切换频率极快，电机的线圈电感和机械惯性会将这些快速跳变的脉冲“平滑”掉。最终电机感受到的等效有效电压，就等于总线电压乘以 PWM 信号的占空比。电池供电 VCC 是 12V。如果主控给 EN 输入 50% 占空比的 PWM 信号，电机感受到的有效电压就是 6V；如果输入 80% 占空比，有效电压就是 9.6V。














4.2.3 信号输入
单片机（RT1064）的 GPIO 引脚驱动能力弱且对干扰敏感，信号在通过排线传输到大功率驱动板时，必须经过严密的调理。
接口对应：驱动板的 2x3 Pin 信号输入接口（P4）与主板上的“电机接口”（带有 100Ω 串联限流电阻）通过排线直连，接收两路 PH（方向）和两路 EN（PWM速度）信号。

4.2.4缓冲电路
使用这颗四路总线缓冲门对输入信号进行隔离与增强。其使能端全接地，处于常开状态。DVDD 是 DRV8701 芯片内部自带 LDO 产生的 3.3V 逻辑电源，给SN74HC125PWR直接供电。

第五章　控制软件设计
5.1　软件总体架构与开发流程
本系统软件采用分层模块化设计思想，将复杂的推箱子决策、路径规划与运动控制任务分解为若干相对独立的功能层次，各层之间通过定义良好的数据结构与函数接口进行交互，有效降低了系统的耦合度，提高了代码的可读性、可维护性与可调试性。软件总体架构自上而下划分为以下五个层次：
（1）应用与调试层（Application & Debug Layer）。 该层位于架构最顶层，负责系统主循环调度、任务状态管理、人机交互与调试信息输出。主要实现文件为UserMain.c、Menu.c、DEBUG.c和vofa_tune.c。其中User_Loop()函数作为系统主循环，按照固定周期轮询调用各功能模块；Menu.c实现基于IPS200显示屏与五向按键的菜单交互界面，支持参数浏览与在线修改；vofa_tune.c实现基于无线转串口模块的VOFA+无线调参协议，解析上位机下发的字符串命令并动态更新PID参数与运动控制变量；DEBUG.c管理各调试模式的切换与调试数据的格式化打印输出。
（2）任务决策与规划层（Decision & Planning Layer）。 该层是本系统软件的核心算法层，负责根据当前感知到的地图状态与车模位姿，求解最优推箱子行动序列并生成平滑的路径航点。主要实现文件为Sokoban_sys.c。decision_running()函数实现了基于状态机的任务调度逻辑，将完整的比赛过程划分为离开出发区、地图提取、炸弹爆炸位置决策与箱子标识识别（Phase 1）、箱子与目标匹配推送（Phase 2）、行动解析与执行、返回与完成等多个阶段。该层包含DFS搜索器（带哈希剪枝与启发式代价评估）、TNT爆炸位置规划器、箱子与目标点匹配算法（match_id）以及双层BFS路径平滑生成器（solve_innerA_smoothedPath、solve_pushbox_smoothedPath等）。
（3）运动控制层（Motion Control Layer）。 该层负责将规划层下发的速度指令（X轴速度、Y轴速度、偏航角速度）通过麦克纳姆轮逆运动学解算为四个轮子的目标转速，并通过增量式PID速度闭环驱动电机，实现车模的全向移动与精确停靠。主要实现文件为Control.c与PID.c。Set_Car_Speed()函数实现运动学解算与电机驱动输出；ApplySoftStart()实现缓启动功能，对速度指令进行斜率限制，避免电机启动时产生过大冲击电流；Angle_Control()与Turn_Angle()实现偏航角的闭环控制，用于车模在推箱过程中的精确方向对准。
（4）状态估计与传感器数据处理层（State Estimation & Sensor Layer）。 该层负责采集各类传感器的原始数据，并将它们转换为具有物理意义的车模状态量（位置坐标、航向角、轮速、线速度等）。主要实现文件为Encoder.c、Inertial_Navigation.c与angle.c。Encoder_Process()函数在每个控制周期读取四路编码器计数值，经标定与滤波后得到各轮转速与累计位移；Odometry_Process()与On_Vision_Received()函数实现了编码器里程计与视觉定位数据的延迟补偿融合算法，输出经校正的实时坐标（true_now_x、true_now_y）；IMUupdate()函数基于四元数互补滤波算法解算陀螺仪与加速度计数据，输出稳定的偏航角（Gyro_YawAngle_Get()）。
（5）底层硬件驱动层（Hardware Driver Layer）。 该层基于逐飞科技提供的底层驱动库（zf_common_headfile.h）实现，包含GPIO、UART、SPI、I2C、PWM、GPT定时器、ADC、正交编码器接口（encoder_quad_init）等外设的初始化与底层操作函数。该层为上层模块提供了统一的硬件访问接口，屏蔽了底层寄存器操作的复杂性。
在开发流程方面，本团队采用“分模块开发—逐级联调—整车集成”的迭代开发模式。首先在逐飞底层库的基础上完成各传感器模块的独立驱动测试（编码器测速、陀螺仪数据读取、OpenART串口通信、IPS200显示驱动等）；随后将各模块按照数据流关系逐步集成，依次完成“编码器+陀螺仪→惯性导航定位”、“视觉定位→延迟补偿融合”、“决策搜索→路径平滑”等子系统的联调测试；最后进行整车系统集成，在主循环中完成全部模块的协同工作。开发环境采用Keil MDK uVision5，调试工具为逐飞双模DAP-Link仿真器与VOFA+无线调参上位机。
5.2　视觉感知算法
本系统的视觉感知任务全部交由OpenART视觉模块独立完成，主控MCU通过UART串口与OpenART进行指令交互与数据接收。视觉感知算法主要包含两类任务：虚拟地图提取、目标字符识别。
（1）虚拟地图提取。比赛开始后，OpenART通过识别由虚拟游戏系统投影在场地中的推箱子地图信息。当主控MCU需要获取地图时，通过UART4_SendByte(START_EXRACTION)指令触发OpenART执行地图提取流程。OpenART完成识别后，将地图数据以extracted_map二维数组的形式通过串口发送至主控MCU。extracted_map采用与Sokoban_Map.c中预定义地图相同的编码规则（0为空地、1为墙壁、3为箱子、4为目标点、5为TNT炸药），主控接收到STATE_RECEIVE_FLAG标志后即认为地图数据接收完成，并置finish_extracted_map标志为1，通知决策模块地图已就绪。
（2）目标图片识别。 在“炸弹与标识识别”阶段（Phase 1），车模需要走到特定的观察位置，识别箱子和目标点上的图片，以建立箱子和目标之间的一一对应关系。该过程分为两个子任务：识别箱子标签（START_TF_CHARACTERS）和识别目标标签（START_TF_NUM）。OpenART在接收到相应指令后，执行图片分类神经网络推理（基于EfficientNet或轻量级CNN模型），将识别到的标签编号（0～9）通过串口返回。主控MCU将识别结果存入Box_Label或Target_Label全局变量，决策模块在applyPath()函数中检测到标签返回后，通过INFO_WITH_KNOWN宏将标签信息写入对应箱子或目标点的信息字段（s.box_info[id]与s.goal_info[id]），完成标识绑定。
通过上述两类视觉任务的协同工作，系统能够获得完整的场地地图信息、箱子与目标的标识对应关系以及车模的全局定位坐标，为后续的路径规划与决策提供了可靠的感知基础。


5.3　路径规划与决策
路径规划与决策是本系统软件的核心与难点所在，其目标是在给定的推箱子地图上，求解出一组从当前状态到目标状态的可行行动序列，并将每个行动进一步展开为车模可执行的平滑运动路径。该模块的实现集中在Sokoban_sys.c中，核心数据结构为SearchState（搜索状态）与decision_maker_t（决策管理器）。
（1）任务决策状态机。 系统通过decision_running()函数管理完整的比赛决策流程，其状态转换如下所述：
PHASE_LEAVE_DEPARTURAREA（离开出发区）：车模从车库出发，沿指定方向行驶固定距离（如30cm），进入场地中央区域，随后转入地图提取阶段。
PHASE_EXTRACT_MAP（地图提取）：若为仿真模式（decision.simulateRun == 1），直接加载预定义地图（如simulateRun_Map）；否则通过视觉感知模块请求OpenART提取实际场地地图，并将地图数据加载到决策管理器中。
PHASE1_BOMB_AND_IDENTIFY（炸弹与标识识别）：调用decision_DetonatePosition(&s)决策TNT炸药的爆炸位置，随后通过DFS搜索（DFS_search_ActionSequence）生成包含“移动至观察点→识别箱子标签→识别目标标签→推送TNT至爆炸位置”等动作的行动序列，依次执行以完成所有TNT的引爆与所有箱子/目标的标识绑定。
PHASE2_MATCHING_PUSH（匹配推送）：在完成标识识别后，调用match_id(&s)函数，根据已绑定的标签信息建立箱子与目标点之间的最优匹配关系，随后通过DFS搜索（DFS_Search_PushboxSequence）生成将所有箱子推送至对应目标点的行动序列。
PAHASE_ANALYSIS_ACTION（行动解析）：对于决策阶段生成的每个抽象动作（如ACT_PUSH_BOX、ACT_IDENTIFY_BOX、ACT_PUSH_TNT），调用solveAction()函数将其解析为具体的平滑路径（pos_path_t），并切换至执行阶段。
PAHASE_ACTION（行动执行）：通过applyPath()函数逐点跟踪解析出的路径航点，调用运动控制模块驱动车模实际运动。路径跟踪完成后，根据当前阶段决定是否进入下一轮决策或切换至下一阶段。
PHASE_RETURN与PHASE_SUCCESS：在所有箱子推送完成后，车模返回场地指定位置（return_pos），随后标记比赛完成。
（2）推箱子搜索算法。本系统采用深度优先搜索（DFS）作为核心搜索框架，并融合了启发式代价评估、状态哈希剪枝以及行动优先级排序等优化策略。以DFS_search_ActionSequence函数为例，其搜索流程如下：
状态表示：SearchState结构体记录了当前地图矩阵（map）、玩家位置（player_pack）、所有箱子位置（box_pack）、所有目标位置（goal_pack）、所有TNT位置（tnt_pack）以及各箱子与目标的标识信息（box_info与goal_info）。
行动生成：generation_action()函数根据当前状态枚举所有可能的候选行动，包括：移动到箱子或目标相邻位置执行标识识别（ACT_IDENTIFY_BOX/ACT_IDENTIFY_GOAL）、将可用的TNT推送至预计算的爆炸位置（ACT_PUSH_TNT）。每个候选行动附带一个基于玩家距离与转角代价的优先级评分，通过action_rank()计算并排序。	
状态扩展与剪枝：对于每个候选行动，apply_action_incremental()函数在状态备份的基础上执行状态转移，并更新代价估计（s->cost_step）。若当前代价加上启发式下界（heuristic_lower_bound）不低于当前最优解，则剪枝返回。同时，系统维护一个全局状态哈希表（g_state_hash），对已访问的状态进行记录，若当前状态已存在且代价不低于历史记录，则剪枝，避免重复搜索。
终止判定：当所有箱子与目标的标识均已识别（check_phase_end返回true）或所有箱子均已推送至目标位置时，记录当前行动序列为候选最优解。
（3）TNT爆炸位置决策。 在含有TNT的地图上，部分墙壁需要通过TNT爆炸来移除，从而打开新的可行通道。decision_DetonatePosition函数采用递归DFS与地图连通性分析相结合的方法，枚举每个TNT可能被推送到的爆炸位置，评估爆炸后的地图状态是否仍能保证所有箱子可达目标点。通过generate_sorted_wall_list和BFS可达性检查，该算法能够筛选出最优的TNT爆炸组合与推送顺序，并将结果存储在boom_pack数组中供后续执行使用。

（4）路径平滑生成。 对于每个原子动作（如将玩家从A点移动到B点、将箱子从位置P推送到位置Q），系统需要生成一条平滑且可执行的路径航点序列。基于双层BFS搜索和贪心、奖励机制，在网格地图上规划玩家从起点到终点的最短路径，并通过转角压缩算法（Pos_t turning[100]）提取路径中的关键转向点，去除冗余的直线中间点，形成精简的航点序列，确保生成的路径在物理上可执行。随后，expand_path_to_player_moves函数将箱子轨迹进一步转换为玩家需要依次经过的航点序列，实现推箱动作的完整执行。
5.4　运动控制算法
运动控制层负责将规划层下发的期望速度指令转换为四个麦克纳姆轮的实际驱动信号，并实现车模的精确定位与姿态保持。该模块实现在Control.c与PID.c中，包含运动学解算、PID闭环控制、缓启动以及惯性导航等多个子模块。
（1）麦克纳姆轮运动学解算。 Set_Car_Speed(float Speed_X, float Speed_Y, float Speed_Z)函数实现了从车体坐标系速度（X轴横向速度、Y轴纵向速度、Z轴偏航角速度）到四个麦克纳姆轮目标转速的映射。根据麦克纳姆轮的运动学模型，四个轮子的转速计算公式为：
左后轮（LB）：Target_Speed[0] = Speed_Y - Speed_X + Speed_Z
右后轮（RB）：Target_Speed[1] = Speed_Y + Speed_X - Speed_Z
右前轮（RF）：Target_Speed[2] = Speed_Y - Speed_X - Speed_Z
左前轮（LF）：Target_Speed[3] = Speed_Y + Speed_X + Speed_Z
上述速度量纲为cm/s，直接作为速度环PID控制器的目标值。运动学解算完成后，各轮目标速度与编码器实测速度的偏差被送入增量式PID控制器，计算PWM占空比调整量，经限幅后写入电机驱动寄存器，实现速度闭环控制。
（2）PID控制器设计。 本系统同时使用了增量式PID与位置式PID两种控制结构。速度环采用增量式PID（Incremental_PID_TypeDef），输出量为PWM占空比的增量，具有响应快、积分饱和风险低的优点，适用于电机转速的实时调节。位置环与角度环采用位置式PID（Pid_TypeDef），用于位置定位（CorrectPosX_PID/CorrectPosY_PID）与航向保持（Yaw_Control_PID），输出量为期望速度值，作为速度环的前级输入。各PID参数均通过VOFA+上位机进行了充分整定，并在All_PID_Init函数中完成初始化。
（3）缓启动与平滑控制。 为避免车模在启动或加减速过程中因力矩突变导致电机堵转或车轮打滑，系统在ApplySoftStart函数中实现了缓启动机制。该函数对速度环的输入指令（Car.Speed_X与Car.Speed_Y）施加斜率限制，每控制周期按照固定步长（RAMP_STEP，典型值1.0～5.0 cm/s/周期）将实际下发速度逐步逼近目标速度，使车模的加加速度（jerk）保持在可控范围内，显著改善了启动与制动过程的平稳性。
（4）惯性导航与定位控制。 定位控制通过Inertial_Navigation.c中的两个核心函数实现：基于编码器里程计的Navigation_Process_Encoder与基于视觉融合定位的Navigation_Process_Visual。
Navigation_Process_Encoder函数用于执行精确的距离定位。在Move_State阶段，函数根据当前编码器累计位移（Get_X_Distance与Get_Y_Distance）与目标位置之间的偏差，通过位置式PID（DistanceX_PID与DistanceY_PID）计算期望速度，经航向角旋转变换（compute_heading_offset_Encoder）后下发至运动控制层。当位置偏差小于预设阈值（min_err = 1.2cm）时，判定定位完成，速度归零，状态转移至Move_Finish。

Navigation_Process_Visual函数用于执行基于视觉全局坐标的精确对准。该函数接收视觉融合后的当前坐标（true_now_x与true_now_y），计算与目标坐标之间的偏差，通过CorrectPosX_PID与CorrectPosY_PID计算期望速度，并经航向角旋转变换（apply_heading_velocity）后驱动车模运动。由于视觉坐标存在噪声，该函数在接近目标点时采用了更小的死区阈值（min_pos_err = 0.12cm）和更严格的超时判定，确保车模在推箱前能够达到足够高的定位精度。
（5）航向角闭环控制。 偏航角控制由Angle_Control函数实现，该函数采用位置式PID（Yaw_Control_PID）根据目标航向角与当前陀螺仪偏航角之间的偏差（经±180°归一化处理）计算偏航角速度指令（Car.Speed_Z），并叠加至运动学解算中。偏航角闭环与位置闭环并行工作，使得车模在平移过程中能够始终保持指定的朝向，这对于推箱子任务中箱子的推送方向控制至关重要。
5.5　核心代码设计说明
在本小节选取系统软件中的几项关键代码设计进行说明，以体现本系统的工程实现质量与编程规范性。
（1）关键数据结构定义。 系统定义了多个核心数据结构用于状态管理与数据传递。Car_Handle结构体（Control.c）集中管理车模的运行时状态，包括三轴期望速度（Speed_X/Y/Z）、当前航向角（Angle）、视觉与编码器定位坐标（rx_Grid_X/Y、Grid_X/Y）、移动标志位（Move_flag）以及定位状态标志（Visual_location_flag、Encoder_location_flag）等。SearchState结构体（Sokoban_sys.c）用于推箱子搜索过程中的状态表示，包含地图矩阵、所有箱子/目标/TNT的位置与标识信息、已使用的TNT掩码以及累计代价等字段。decision_maker_t结构体用于管理完整的比赛决策过程，包含当前阶段（phase）、行动计划（plan数组）与执行进度（plan_idx）等。
（2）状态机设计模式。 在decision_running与Navigation_Process_Encoder等核心函数中，广泛使用了有限状态机（FSM）设计模式。以惯性导航为例，Navigation_Distance.Navigation_State从Start_State（起始等待）切换至Move_State（运动定位），再切换至Move_Finish（定位完成），每个状态下执行的逻辑清晰分离，状态转换条件明确定义。这种设计避免了复杂的条件嵌套，提高了代码的可读性，也便于针对每个状态进行独立的调试与优化。
（3）中断与定时器任务调度。 系统采用GPT定时器实现分时任务调度。timer_init(GPT_TIM_1, TIMER_US)初始化微秒级定时器，并通过硬件中断触发周期性任务。DeBug_Handler_5ms函数以5ms为周期执行高频任务，包括编码器数据采集（Encoder_Process）、运动控制解算（Control_Loop）以及无线调参接收（VOFA_Receive_Task）等。DeBug_Handler_15ms函数以15ms为周期执行中频任务包括惯性导航进程（Navigation_Process_Visual/Navigation_Process_Encoder）、航向角闭环控制（Angle_Control）以及推箱子任务进程（move_task_process）等。主循环User_Loop中则执行低频任务，包括地图提取、推箱子决策搜索、菜单显示以及调试信息打印。通过合理划分任务周期，系统确保了实时控制任务的优先响应，同时为非实时计算任务保留了充足的CPU时间。
（4）参数在线调参。 系统在vofa_tune.c中实现了完整的VOFA+无线调参协议解析器（Parse_VOFA_String函数），支持上位机下发Kp=xxx、Ki=xxx、Speed_X=xxx等字符串命令，动态更新PID参数、目标速度、目标位置以及缓启动斜率等关键运行参数。
（5）代码分层与命名规范。 整个工程遵循统一的命名规范与文件组织方式。硬件驱动函数以gpio_、uart_、encoder_等前缀标识模块归属；上层算法函数采用驼峰命名法（如Navigation_Process_Visual、DFS_search_ActionSequence）；全局变量以大写字母开头（如Car、decision、s）；宏定义与枚举常量全部使用大写字母（如MAXBOX、PHASE_EXTRACT_MAP）。各功能模块按文件独立组织，头文件（.h）声明外部接口，源文件（.c）隐藏内部实现细节，符合信息隐藏原则，便于团队协作开发与代码复用。

6.1　开发工具与环境

调试工具方面，选用逐飞科技双模DAP调试器作为程序烧录接口。代码版本管理使用Git进行协作开发，有效避免了多成员修改时的代码冲突。
在视觉模块开发方面，OpenART模块使用逐飞官方提供的MicroPython固件，通过OpenMV IDE进行图像处理算法的原型验证与调试。OpenART的固件支持Python脚本的即时运行，便于快速迭代视觉识别参数。在实际集成中，将经过验证的视觉识别逻辑固化至OpenART固件中，通过串口与主控MCU进行结构化数据通信。
在机械设计与安装辅助工具方面，使用SolidWorks 2024进行3D打印结构件的建模与装配仿真，包括摄像头支架、方位标识牌支架、电池固定座以及电路板安装柱等非标准件的设计。电路板原理图与PCB设计使用嘉立创EDA完成，采用四层或双层板布局，兼顾信号完整性与装配密度。
人机交互与参数调试方面，主要依赖VOFA+无线调参上位机、IPS200显示屏以及按键。VOFA+是一款开源上位机软件，支持浮点数据波形显示与字符串命令下发，通过无线转串口模块与车模进行无线通信，可在车模运行过程中实时观测关键变量变化趋势并在线修改控制参数，极大提高了调试效率。
6.2　制作与安装过程
车模制作与安装过程分为机械加工与装配、电路板焊接与测试、传感器安装与标定以及整车总装四个阶段。
（1）机械加工与装配。本系统采用大赛指定的M型车模底盘，在此基础上进行了必要的机械改造。使用SolidWorks设计了以下3D打印结构件：①暗箱，将OpenART模块固定于上方较高位置，以获得较开阔的视野，将显示屏固定在暗箱下方，便于OpenART识别并处理图像信息；②电池固定座，将电池稳固于底盘中央偏后位置，降低整车重心；③电路板安装柱，将主控板、驱动板分层固定在底盘预留孔位上。所有3D打印件采用PLA或PETG材料打印，填充率不低于40%以保证结构强度。在机械装配过程中，重点确保四个麦克纳姆轮的安装高度一致、轴线平行，各轮与地面接触均匀，避免因安装误差导致车模行走偏航或打滑。
（2）电路板焊接与测试。主板与驱动板均采用手工焊接方式，使用电烙铁与加热台完成主板和驱动板的焊接。焊接完成后，使用万用表进行电源短路检测，确保各电压轨（5V、3.3V、6V供电）无短路现象。随后进行上电测试：先空载测试电源芯片输出电压是否正常，再依次连接陀螺仪、编码器、电机驱动等外设，通过串口打印或LED指示灯确认各模块的供电与初始化状态正常。驱动板在连接电机之前，先使用示波器测量PWM输出波形与方向信号电平，确保驱动芯片的输入逻辑符合预期。
（3）传感器安装与标定。编码器安装于四个电机的上方，安装时需仔细调节编码器齿轮与电机齿轮的啮合间隙，确保阻尼适中——啮合过紧会增加电机负载并加速齿轮磨损，啮合过松则会导致丢步或测量噪声。安装完成后，通过手动转动车轮并观察编码器读数变化，确认四路编码器方向与计数一致性，在软件中对方向相反的通道通过Encoder_dir数组进行修正。陀螺仪（ICM42688）紧贴底盘中央安装，通过铜柱固定，确保其敏感轴与车体坐标系对齐。在首次上电时，系统自动执行陀螺仪零点偏移校准（gyroOffset_init函数），连续采集100组静止状态下的陀螺仪数据并计算平均值作为零偏补偿值。
（4）整车总装与线束管理。 将所有已安装的模块通过线束进行电气连接，包括：电池至驱动板的电源线、驱动板至电机的动力线、各传感器与主控板间的信号排线。线束采用扎带和螺旋管进行整理，避免在车模运动过程中线束松动或干扰运动部件。总装完成后，整车重量控制在合理范围内，重心位于底盘几何中心附近，确保车模在加减速和转向过程中具有良好的稳定性。
6.3　软硬件调试过程
软硬件调试采用“分模块验证—逐步集成—系统联调”的递进策略，确保每个子系统的功能正确后再进行整车联调。
（1）硬件模块独立调试。 首先对各硬件模块进行单独测试：电机驱动板通过直接给定固定占空比的PWM信号，观察四个电机是否正常旋转以及旋转方向是否与预期一致，利用示波器测量电机两端的电压波形，确认驱动芯片的死区时间与输出幅度正常。编码器通过手动旋转车轮，读取串口打印的计数值，验证计数方向与分辨率正确。陀螺仪通过读取原始加速度与角速度数据，在静止状态下观察数据稳定性，并在人为旋转车模时查看角速度响应的线性度。OpenART模块通过独立供电并运行测试脚本，验证摄像头图像采集与串口数据收发功能正常。
（2）传感器数据融合调试。 在编码器与陀螺仪均可正常读取数据后，进行惯性导航模块的联调。将车模放置在平整地面上，沿X轴或Y轴推动车模一定距离，比较编码器推算的位移（Get_X_Distance/Get_Y_Distance）与实际测量值之间的误差，并根据标定系数（CM_PER_PULSE）进行校准。检查陀螺仪偏航角积分是否准确：将车模旋转90°或180°，观察角度输出与实际转角是否一致，若存在漂移则调整互补滤波系数或重新校准零偏。视觉定位与编码器融合的调试中，通过人为将车模移动至场地已知坐标点，读取OpenART返回的视觉坐标（Car.rx_Grid_X/Y）并与实际坐标比对，调整延迟补偿参数（DELAY_FRAMES）直至融合后的实时坐标（true_now_x/y）与真实位置吻合良好。
（3）运动控制闭环调试。 在进行PID参数整定之前，先进行开环测试：给定固定速度指令（如Car.Speed_Y = 10），观察车模是否沿Y轴直线行驶，若存在明显偏航，则检查四个轮子的速度是否一致以及麦克纳姆轮安装方向是否正确。随后进行速度闭环调试，从低增益开始逐渐增大速度环的Kp值，观察电机响应速度与稳态误差，根据编码器反馈波形的振荡情况调整Kp、Ki、Kd参数，使速度响应既快速又平稳。位置闭环调试在速度环调好的基础上进行，将车模置于目标点附近，下发位置指令，观察车模是否能够准确停靠在目标位置且无超调振荡，通过调整位置环Kp与Kd参数获得最佳定位性能。角度闭环调试则通过下发固定航向角指令，观察车模是否能够在规定时间内完成转向并稳定保持，调整Yaw_Control_PID参数使转向响应快速且无过冲。
（4）决策与规划模块的离线仿真调试。 由于推箱子决策算法涉及较复杂的搜索逻辑，直接在实际车模上调试效率低下且容易造成碰撞。因此，本系统在PC端搭建了离线仿真环境，在仿真环境下验证搜索算法的正确性与执行效率。通过仿真，测试了不同地图规模和箱子数量下的搜索耗时，优化了哈希剪枝与启发式函数的参数，确保决策算法在实际运行中能够实时响应。仿真验证通过后，再将决策模块集成到嵌入式工程中，通过串口打印方式验证实际地图数据加载与决策结果的一致性。
（5）整车系统联调。 在各子系统均调试通过后，进行整车系统联调。首先进行“空跑”测试：在无虚拟地图的条件下，通过菜单下发简单的移动指令（前进、后退、左移、右移、原地旋转），观察车模的实际运动方向与指令是否一致，检查运动控制层与状态估计层的数据流是否正确。随后进行“模拟推箱”测试：运行完整的推箱子决策流程，观察车模是否能够依次完成地图提取、TNT爆炸、标识识别、箱子推送等全流程动作，记录各个环节的执行时间与成功率。在模拟测试中，利用VOFA+上位机实时观测车模的坐标轨迹、速度曲线与PID输出，快速定位控制异常环节并进行参数修正。



6.4　赛道测试与参数整定
赛道测试与参数整定是整个调试过程中最为关键的一环，直接决定了比赛成绩。测试场地为3.2m×2.4m的室内平面场地，地面材质为比赛用蓝色PVC膜，场地四周按规则粘贴黄色布基胶带，四角布置AprilTag码。测试环境的光照条件尽量模拟比赛现场。
（1）视觉参数整定。OpenART的视觉识别受光照影响较大，因此首先在不同的光照条件下（晴天、阴天、灯光直射、灯光侧射）测试地图提取的稳定性。通过调整OpenART的曝光时间、增益、对比度以及LAB色域分割阈值，使地图中的箱子（黄色）、目标点（紫色）、TNT（红色）以及墙壁能够被准确分割识别。在字符标签识别方面，采集不同光照下箱子和目标点标签的图像样本，扩充训练数据集，重新训练分类模型，使识别准确率达到95%以上。
（2）运动控制参数整定。速度环PID参数按照“先I后P”的整定顺序进行：首先将Kp和Kd置零，逐渐增大Ki直至电机出现轻微振荡，然后将Ki减小至临界值的60%左右；随后缓慢增大Kp以消除稳态误差，但注意避免积分饱和导致的超调；位置环PID参数采用类似方法整定，同时加入较大的Kd以抑制位置超调。角度环PID参数根据转向响应特性进行调整，在Turn_Angle函数中实现了分段PID参数切换，对于不同转角范围使用不同的Kp/Kd组合，既保证小角度转动的精度，又保证大角度转动的速度。	
（3）惯性导航参数校准。 在赛道测试中，通过多次跑圈或定点往返运动，测量编码器里程计的累计误差。若X轴或Y轴方向存在系统性偏差（例如每次移动20cm实际只走了19cm），则微调标定系数Cm_Per_X与Cm_Per_Y，直至定位误差在允许范围内。视觉延迟补偿参数DELAY_FRAMES通过在已知坐标点处快速移动车模并观察视觉融合坐标的跟踪情况来调整，若融合坐标超前或滞后于实际位置，则相应增减延迟帧数。
（4）推箱子决策参数优化。 在决策算法中，行动搜索的剪枝阈值（min_cost）、分支因子限制（branch_limit_max）以及启发式代价系数等参数会直接影响搜索耗时与解的质量。在实际场地中，针对典型地图进行多次决策测试，记录搜索耗时与生成路径的总步数，在搜索速度与路径最优性之间寻找平衡。通过调整branch_limit_max（通常设为2～4）和heuristic_lower_bound的计算权重，使单次决策耗时控制在100ms以内，同时路径总步数接近理论最优解。
（5）综合性能测试与比赛模拟。在所有参数整定完成后，进行完整的比赛流程模拟测试：从车库出发，依次完成三个关卡的推箱子任务，记录每个关卡的完成时间与箱子推送成功率。测试过程中重点关注车模在不同关卡地图下的适应能力、TNT爆炸后地图变化对后续路径的影响以及多箱子推送顺序的合理性。对于测试中暴露的问题（如某一关卡箱子推送失败、路径规划出现死循环、定位累计误差导致撞墙等），针对性地调整决策策略或控制参数，并反复验证直至系统在所有测试地图上均能稳定完成任务。
通过上述系统化的调试与参数整定流程，本车模在实验室模拟赛道上取得了较好的稳定性和任务完成率，为正式比赛打下了坚实的基础。

        car_cx, car_cy = (largest.cx()+cx)//2, cy
    else:
        car_cx, car_cy = cx, (largest.cy()+cy)//2
    img.draw_cross(car_cx,car_cy,(255,0,0),3,1)
    if min_threshold > largest.area():
        min_threshold = largest.area()
    #print(min_threshold)
    return (car_cx,car_cy)

void Set_Car_Speed(float Speed_X,float Speed_Y,float Speed_Z)
{
    if(disable_motor) 
	{
		Motor_Disable();
		return;
	}
	float Speed_n[4]={0};
	
    if (isnan(Speed_X) || isnan(Speed_Y) || isnan(Speed_Z)) {
        return;
    }
	//运动解算
	Target_Speed[3] = LF_Speed = Speed_Y + Speed_X + Speed_Z;
	Target_Speed[0] = LB_Speed = Speed_Y - Speed_X + Speed_Z;
	Target_Speed[2] = RF_Speed = Speed_Y - Speed_X - Speed_Z;
	Target_Speed[1] = RB_Speed = Speed_Y + Speed_X - Speed_Z;
	

	Speed_n[0] = LB_Speed - Encoder_Speed[0];
	Speed_n[1] = RB_Speed - Encoder_Speed[1];
	Speed_n[2] = RF_Speed - Encoder_Speed[2];
	Speed_n[3] = LF_Speed - Encoder_Speed[3];
		
	for(uint8 x=0;x<4;x++)
	{
		OutPut_n[x]=Get_Incremental_PID_Value(&Motor_Speed[x],Speed_n[x]);
	}
	
	
	for(uint8 x=0;x<4;x++){
		set_single_motor_speed(x,OutPut_n[x]);
	}	

}
