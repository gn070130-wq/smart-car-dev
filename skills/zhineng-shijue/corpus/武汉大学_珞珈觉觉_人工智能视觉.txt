第一章 引言
全国大学生智能汽车竞赛以“立足培养，重在参与，鼓励探索，追求卓越”为指导思想，旨在促进高等学校素质教育，培养大学生的综合知识运用能力、基本工程实践能力和创新意识，激发大学生从事科学研究与探索的兴趣和潜能,倡导理论联系实际、求真务实的学风和团队协作的人文精神，为优秀人才的脱颖而出创造条件，是一项鼓励创新的科技竞赛活动。竞赛要求设计并制作一辆可以在平面比赛场地内自由运动的车模，以完成比赛要求智能车在虚拟现实系统中推箱子的要求。
人工智能视觉组的基本比赛任务为：
（1）比赛场地：场地大约为3.2×2.4米（与320×240图片比例一致），使用宽度为5厘米的黄色布基胶带贴在场地边缘，示意车模可活动范围。需要确保黄色胶带内的区域有3.2×2.4米。四个角落会贴上数字为15、16、17、18的Apriltag码，用于系统自动定位场地位置并对全局进行逆透视校正。比赛场地部署在室内无阳光直射的场地，地面保持基本平整。比赛场地外50cm左右距离设置围挡，以防止竞赛车模冲出赛场；
（2）制作一辆小车从发车区出发，成功发车后，系统自动开始计时；
（3）虚拟赛道中分布有箱子、目的地；
（4）小车上安装无线屏幕，小车通过摄像头看屏幕显示的内容来获取虚拟游戏画面，包括虚拟环境的俯视图以及小车的第一视角图像；
（5）场地中设定有多个需要推动箱子抵达的目的地，且有与目的地同等数量的可移动箱子，需要将可移动箱子按照要求推到目的地箱子所在位置，完成后可移动箱子和目的地会同时消失（避免重复推动和游戏逻辑的难以实现）；
（6）小车的虚拟位置不可以越过黑灰色的围墙，在场地内如果小车真实的坐标已经穿过围墙，虚拟图像会一直保持未穿过的位置，最终会导致小车无法获取到正确的自身坐标。小车只能从上次离开围墙的附近回到游戏中系统才再次认可并继续刷新小车的实时位置到虚拟图像中，如果小车直接穿过外围的围墙，则比赛自动结束；
（7）场地内可能出现炸弹元素，炸弹可以将场地中间的围墙炸掉，使得小车的运动路线可以更短，但最外围一圈围墙无法炸掉。

3.2 传感器的选择与安装
为了对小车进行控制，选择与安装传感器是必不可少的，测量变速元件是控制系统的基础。
(1)姿态采集部分：六轴加速度陀螺仪IMU660RA,自带LDO稳压芯片，供电电源为3.3V-5V。该陀螺仪的零漂和温漂小于ICM20602，测量的精度要比MPU 好，噪声要比MPU小，IMU660RA使用硬件SPI可达到10M波特率。陀螺仪侦测的是角速度。其工作原理基于科里奥利力的原理：当一个物体在坐标系中直线移动时，假设坐标系做一个旋转，那么在旋转的过程中，物体会感受到一个垂直的力和垂直方向的加速度。可测量不同方向的加速度信息和角速度信息，由静态加速度即重力加速度的各分量值，解算后便可得到车体倾角信息，姿态的获取对于控制是十分重要的。将此模块直接利用白乳胶固定在车模底盘除，高度足够低，且水平安装，以保证测量的准确与受到的干扰小。

第四章 硬件电路
4.1整车预览
整车的系统组成为传感器、控制单元和执行器。
其中传感器包括编码器，六轴陀螺仪，OPENART mini摄像头等模块，分别用来测量速度，角度，采集图像。
控制单元采用基于RT1064设计的最小系统板，这款核心板芯片主频高达600MHZ，芯片资源充足，其丰富的端口资源以及超高的主频，是现阶段运算性能最为强劲的微控制器之一。丰富的端口资源确保了可以驱动更多的外设资源。举个简单的例子，车模在执行任务的过程中需要通过陀螺仪获取角度信息，此时陀螺仪可以通过 IIC、软件 SPI 和硬件 SPI 等多种方式与控制器进行通信，在这三者之中，硬件 SPI 把控制器用于模拟 IO 的时间省了下来，因此硬件 SPI 的通信速率是最快的。要想以最快的速度获取到陀螺仪产生的数据，可以在控制器内嵌 SPI 通信端口。这也是为什么控制器端口资源的丰富性为什么是评价其好坏标准的原因。主频越高，控制器的性能越强，超高的主频缩短了程序的运行周期，越高的主频可以大大缩短算法的运算时间。
执行器是四个电机，控制四个麦轮的运动，通过驱动板输出不同的电压进行控制。
其余还有液晶显示屏、无线串口等，用来进行人机交互，方便调参的进行。

4.2.2 驱动板的设计和制作
驱动单元是控制系统的重要组成部分，驱动的设计尤为重要。
我们人工智能视觉组M车模使用的电机型号是RS380。为了准确的控制电机的转速，需要准确的向电机提供电压，在这采用了H桥进行控制，经过仿真设计及制作，最终使用半桥驱动器DRV8701作为驱动电路，配合低导通内阻MOSFET，构成了一个使用了由分立元件制作的直流电机可逆双极型桥式驱动器。
H桥是一种常用于电机驱动电路的拓扑结构，它能够实现电机的正反转和制动操作。H桥由四个开关元件（通常是MOSFET或IGBT，在这里采用了MOSFET）组成，排列成一个字母"H"的形状。这四个开关元件分别称为上半桥和下半桥。
其中，假设开关元件 IN1、IN2、IN3 和 IN4 。Vcc是电源供电，GND是地线。
当 IN1 和 IN4 为高电平（即元件开通时），IN2 和 IN3 为低电平（即元件关断时）时，电机正转。当 IN2 和 IN3 为高电平（即元件开通时），IN1 和 IN4 为低电平（即元件关断时）时，电机反转。当 IN1、IN2、IN3 和 IN4 都为低电平（即元件关断时）时，电机制动或停止。
H桥电路需要控制输入信号的脉宽调制（PWM）来控制电机的速度。通过调整PWM的占空比，可以改变电机的平均电压和电流，从而改变电机的转速。
设计的H桥驱动电路如下图所示：

图 4.5  H桥驱动电路
电机驱动信号经过芯片SN74HC125PWR进行输入。SN74HC125PWR是一款5A同步降压转换器，具有3.8V至36V宽输入电压范围，内部集成45mΩ上管MOSFET和20mΩ下管MOSFET。该器件采用峰值电流模式控制，支持脉冲跳跃调制（PSM）技术，典型静态电流仅25μA，可在轻载或待机状态下实现高效转换。
驱动部分使用DRV8701 驱动芯片和N沟道MOSFET组成完整的直流电机 H 桥式驱动电路，分立的N沟道MOSFET具有极低的导通电阻，大大减小了电枢回路总电阻。
MOSFET的选择主要需要考虑耐压、导通内阻和封装。而导通内阻则越小越好。封装越大功率越大，即同样导通电阻下通过电流更大，但封装越大栅极电荷越大，会影响导通速度。我们最终选择了DRV8701ERGER,为避免电机反向电动势的影响，在 MOSFET 两端接二极管，避免在电路开闭瞬间产生的反向电动势对电路造成影响甚至烧毁元件。

5.3 小车的运动控制
5.3.1 四轮全向控制原理
与传统组别不同，智能视觉组的车模使用四轮全向实现全向移动，在转弯与旋转时不需要舵机打角，只需要将速度（X方向，Y方向，角速度）分解到四个轮子输出。
以车体纵向速度 Y、横向速度 X 和绕竖直轴角速度 W 为输入，将速度分解为四轮目标：v_LF=Y+X−W，v_LB=Y−X−W，v_RF=Y−X+W，v_RB=Y+X+W。该符号关系与轮子安装方向和正向定义耦合。 
5.3.2 电机控制
电机的转速是用PWM控制的，所谓PWM就是脉宽调制器，通过调制器给电机提供一个具有一定频率的脉冲宽度可调的脉冲电。脉冲宽度越大即占空比越大，提供给电机的平均电压越大，电机转速就高。反之脉冲宽度越小，则占空比越越小。提供给电机的平均电压越小，电机转速就低。
我们使用的电机有两路PWM输出通道，可以实现电机的正转和反转。当我们将小车的实际目标速度分解到四个轮子上后，就可以通过控制PWM的输出占空比来控制电机转速即各轮子的转速，从而控制小车行走的速度与方向。
5.3.3 编码器测速
为了实现对电机速度的闭环控制，我们需要用编码器进行测速。在全场定位中也需要通过编码器测速积分来计算走过的路程。本次比赛中我们使用的是正交编码器。

图5.2 正交编码器输出信号
正交编码器主要有两个信号，分别是脉冲A和脉冲B，转速越高脉冲的频率越高，顺时针旋转时脉冲信号A超前脉冲信号B 90°，逆时针旋转时脉冲信号A滞后脉冲信号B 90°，这就是我们所说的正交信号。单片机有正交解码功能，片内的正交解码模块实际上判断的是当脉冲A的上升沿时脉冲时B信号如果是高电平，则当前的旋转方向为顺时针，如果为低电平时则当前的旋转方向为逆时针。通过这样的判断来实现旋转速度和旋转方向的测量。
为了不受高频信号的干扰，我们对编码器采集的数据进行了低通滤波。
5.3.4 PID控制
为了保证车模在比赛过程中能够实现各种任务，且在各阶段的运行过程中不受外界扰动影响，在各个环节都需要采用闭环控制，其中闭环控制主要涉及到：
电机转速的控制(编码器输入，PWM输出)
行驶路径的控制(里程计输入，电机速度输出)
对准目标的控制(目标板偏差输入，行驶距离输出)
等多个闭环同时控制整个车模，各个闭环拥有不同的控制周期。

图5.3 PID算法

我们对角度环采用位置式PD控制。
位置式PD能够抑制震荡、提供快速响应，通过引入微分项来反馈角度变化率，以减少系统的震荡，并提高系统的稳定性。其响应速度更快，能够快速调整输出，减少响应延迟。在小车旋转和转向时，需要迅速反应，且不希望有超调震荡。因此，角度环采用位置式PD控制能够有效地满足控制要求，提供稳定且精确的角度控制。
我们对速度环采用增量式PI控制。
增量式PI控制具有快速响应、抗积分饱和、良好的抗干扰性能和简单的实现方式。其通过计算误差的增量，可以立即对系统进行调整，以快速响应速度变化。此外，增量式控制器避免了传统位置式PI控制器中可能出现的积分饱和问题，从而减少系统超调和不稳定的风险。该控制方法对于外部干扰的影响较小，提高了系统的稳定性和鲁棒性。增量式PI控制器相对于位置式控制器具有更简单的实现方式，仅需存储上一时刻的误差和控制信号，并通过计算增量来获得当前的控制信号。因此，增量式PI控制适用于速度环控制系统。


第六章 视觉处理
视觉系统是智能车完成环境感知、目标定位和图像分类的核心。系统采用两块 OpenART 摄像头协同工作：ART1 面向场地全局视角，负责恢复地图栅格、识别地图元素并计算车辆与目标的相对位置；ART2 面向车体前方视角，负责在指定区域内完成目标图像分类。两块摄像头通过 UART 交换请求、坐标和识别结果，主控据此完成后续路径规划与运动控制。
	当前工程部署中ART1 采用颜色分割、灰墙多数投票和栅格编码实现地图识别；ART2 采用基于车体相对坐标的识别范围框拟合，并根据目标类型选择动画标识模型或数字标识模型。
6.1 ART1 地图识别思路与实现
ART1 的输入为 OpenART Plus 在 QVGA 分辨率下采集的全局场地图像，输出为 12 行、16 列的地图矩阵、车辆像素坐标以及目标所在栅格的像素中心。地图识别结果通过串口提供给主控和 ART2，作为目标查询、路径规划和图像识别范围预测的统一坐标基础。
	为降低光照变化带来的影响，摄像头运行时关闭自动白平衡和自动增益，采用固定曝光参数并保持 60 帧每秒采集。程序在限定搜索区域内提取蓝色空地、绿色车尾、青色车头、黄色箱子、红色障碍物和紫色目标点等颜色区域，再将有效色块合并为地图内部矩形。

图6.1 ART1 地图识别与数据输出流程

第七章 路径规划算法设计
	本章介绍推箱子（Sokoban）任务路径规划核心算法的设计与实现，内容包括任务建模、扫描绑定决策算法、推箱规划算法、路径平滑优化、炸弹清障与被困格检测算法，以及支撑上述算法在嵌入式平台落地的程序架构与数据结构。
7.1问题建模
	推箱子任务要求无人车在 12×16 的离散网格地图上，通过推箱动作将箱子搬运至指定的目标位置。地图由空地和墙壁构成，并包含箱子、目标、炸弹等任务对象；感知系统采集的地图信息经解析后生成统一的内部地图表示，作为规划器的输入。本系统任务规模支持最多 4 个箱子和 3 颗炸弹。
7.1.1任务描述与地图模型
	推箱子问题的基本操作是推箱动作。每一步合法的推箱动作分为两个阶段：机器人先步行移动到箱子的一侧，形成推箱站位（robot stance），随后推动箱子沿推力方向移动一格。地图以 12×16 网格进行离散化，箱子坐标、机器人坐标以及地图障碍布局共同构成规划所需的状态信息。
7.1.2状态空间与搜索可行性
	推箱子问题的理论核心是状态空间搜索。单个箱子在 12×16 地图上的可达位置约有 192 个，当存在 4 个箱子时，组合状态的规模近似 192⁴，约为 1.36×10⁹，全状态空间 BFS 在嵌入式平台上不可行。
为此，本系统采用组合分解策略，将多箱整体求解问题分解为单箱 BFS 子问题与组合调度两层，避免状态空间爆炸，在可接受的时间与存储开销内获得高质量解。
7.1.3三阶段任务分解
	依据竞赛赛题要求，推箱子任务划分为三个递进阶段：
（1）Stage 1 纯推箱阶段：地图中无炸弹、无需 CNN 分类。规划器穷举箱子到目标的所有排列组合，利用距离场（Build_Distance_Fields）计算每种绑定方案下全部箱子的推箱总代价，通过最优分配（Find_Best_Assignment）选出代价最小的绑定方案，再规划最短推箱路径。
（2）Stage 2 CNN 分类扫描阶段：地图中无炸弹，但箱子与目标带有颜色或 ID 标签，需通过 CNN 分类确定绑定关系。规划器先执行扫描阶段，逐个导航到未观测目标附近，借助视觉模块采集图像并执行分类以获取目标标签 ID，逐步建立箱子到目标的绑定映射；采用覆盖度启发式（N-1 规则）判定扫描是否充分，绑定确认后进入推箱阶段。
（3）Stage 3 炸弹清障阶段：地图中存在炸弹且需要 CNN 分类，为最复杂阶段。地图中可能存在被困格（trapped cell），即被墙壁包围、无法通过推箱动作到达的目标或箱子，必须使用炸弹炸墙清障。炸弹引爆后清除以爆炸点为中心的 3×3 区域墙壁，且炸弹不可恢复，错误使用可能封死关键路径导致无法完赛。因此规划器需在扫描阶段综合决策可炸墙与所用炸弹，并为后续推箱阶段保留足够炸弹。
7.2扫描规划：绑定决策算法
	规划器整体分为扫描规划（Phase 1 Bind）与推箱规划（Phase 2 Push）两个核心模块，分别对应 soko_algo 与 soko_planner 两个实现模块。本节介绍扫描规划，即绑定决策算法。
	扫描规划的核心是任务驱动的贪心扫描循环（Bind_ScanLoop）。每一轮扫描中，系统构建当前所有待执行的分类任务（CLS）与炸墙任务（BMB），并通过两阶段任务选择策略（Bind_PickTask）决定本轮执行的任务：
	第一阶段在各类任务内部排序：CLS 任务按覆盖率优先排序；BMB 任务中标记为强制（forced）的任务获得代价加成而优先选择。
	第二阶段在 CLS 冠军与 BMB 冠军之间按自然代价进行比较，选出本轮最终执行的任务。任务选定后，通过导航搜索（Car_Only_BFS）计算机器人到达任务点的路径并执行，完成一次地图状态的增量观测。
	扫描充分性采用覆盖度启发式判定：当已确认的绑定数量满足 N-1 规则（有效覆盖数不小于 n-1）时，判定绑定映射就绪，规划器切换至推箱阶段。
7.3推箱规划算法
7.3.1组合调度：排列枚举与代价评估
	当箱子到目标的绑定关系尚未由感知确定时，规划器通过排列枚举与代价评估直接求取最优绑定：利用距离场（Build_Distance_Fields）为每一种排列计算总推箱代价，再通过最优分配（Find_Best_Assignment）从全部排列中选出代价最小的组合作为求解依据。该机制在 Stage 1 中作为绑定求解的核心，同时也是推箱路径代价评估的基础。
7.3.2双层推箱策略：DFS 调度器与单箱 BFS 回退
	推箱规划采用双层策略保证求解的完整性与效率。组合层使用 DFS 调度器（DFS_Scheduler_Search）对当前所有未解箱子进行整体推箱规划，统筹考虑箱子之间的相互阻挡关系；在构建子地图时，将已解箱子及其占用的目标格标记为不可穿越，避免后续箱子的规划路径穿越已占用目标，保证求解正确性。若组合规划无法获得可行解，则回退到单箱 BFS（Single_Box_BFS）方式逐箱推送，降低求解规模，保证任意情形下都有可执行的解。
7.3.3扩展层搜索与评分函数
	Single_Box_BFS 在推箱约束下对单个箱子进行 BFS 搜索，找到首个可达目标层后，在同层内按拐点最少选择目标节点，在保证推箱步数最优的同时兼顾路径平顺。
	为突破首层限制，规划器提供扩展层搜索框架（BFS_EXTRA_LAYERS），允许继续向更深层搜索，并通过综合评分函数在步数与拐点之间取得平衡：评分 = 推箱步数 N + λ × 拐点数 T。扩展层搜索可找到步数略有增加但拐点显著减少的路径，从而降低物理机器人转弯带来的时间开销。
7.4路径平滑优化
	规划器输出的路径为离散网格步点。为减少物理机器人转弯耗时，路径平滑采用三级递进策略，从不同粒度消除路径拐点：
	第一级，同向优先（SMOOTH_PATH）：在 BFS 扩展时，将扩展方向与来向相同的节点排在队列最前，使直行路径在同层内优先入队并优先被发现，锯齿形路径被自然淘汰。
	第二级，锯齿消除（SMOOTH_ZIGZAG）：使用四节点滑动窗口检测上-右-上型锯齿走法，并将其优化为更平顺的走法，消除局部来回偏移。
	第三级，射线平滑（SMOOTH_RAY）：通过射线探测与末位索引查表，将同行或同列上的长程来回偏移直接拉直。
	三级策略相互配合，在测试地图上使路径总拐点减少约 6%~8%，在不增加 BFS 空间开销的前提下有效改善路径的物理可执行性。
7.5炸弹清障与被困格检测算法
7.5.1被困格三层检测
	Stage 3 引入炸弹机制后，规划的核心挑战从如何推箱转变为何时何地使用炸弹。被困格检测是炸弹决策的基础。系统采用三层递进检测架构：
	Tier 1 静态墙壁检查：对每个目标格或箱子的四个推方向进行快速预判，检查箱子被推前位置（box_start）与机器人推箱站位（robot_stance）是否均为可通行格，排除明显可推的情形。
	Tier 2 箱子可达性 BFS：从所有初始箱子位置出发，按照推箱规则进行 BFS 泛洪，计算箱子的可达集合，检测窄口、死胡同型被困格。此类被困格仅依靠静态检查容易漏判，典型情形为目标格三面环墙。
	Tier 3 中间态机器人可达性：模拟箱子被推至 box_start 后的中间状态，通过 BFS 验证机器人能否绕行到达推箱站位，检测中间态隔离型被困。当 Tier 3 判定失败时，自动收集分隔墙（frontier walls），存入被困格数据结构（SokoTrappedCell.frontier），供后续炸弹决策使用。
7.5.2炸弹到墙的分配
	炸弹到墙的分配采用多层优化策略，由简到繁逐级兜底：
	贪心基准：通过可推性（pushability）检查与覆盖计数，为各被困格选出初始炸弹绑定（Pass 1 与 Pass 2 两级处理）。
	回溯搜索（Bind_BacktrackAssign）：穷举炸弹到墙的全部单射映射（规模不超过 4 时最多 24 种排列），以综合代价选出全局最优绑定。
	可解性搜索（Bind_SolvSearch）作为最终兜底：不再将炸弹固定绑定到单个被困格，而是收集所有候选墙，构建炸弹到墙的可达性矩阵，回溯枚举所有组合，模拟炸墙后的地图并验证其可解性，最终选出总代价最低的可解方案。
7.5.3BMB 墙候选过滤与 GBU 推箱安全网
	炸墙任务的墙候选过滤（Bind_IsWallUseful）采用双层策略：
	Layer 1 硬保留箱子或目标四邻域的贴脸墙，此类墙直接造成物理阻塞，必须清除。
	Layer 2 对非贴脸墙应用三角不等式 MD(W,B) + MD(W,G) ≤ MD(B,G) + K 进行过滤，式中 K 取 3，用于保留位于通道上的墙、剔除孤立远墙，避免无效炸墙造成的炸弹浪费。
	推箱阶段提供 GBU 机制（GreedyBombPush_UnlockBox）作为最后的炸弹安全网：当某个箱子在推箱搜索中无路可达时，自动搜索仍存活的炸弹为其推墙清障，并拼接推弹与推箱命令，保障极端情形下任务仍可继续。
7.6程序架构与数据结构
	规划器在整体软件中位于功能模块层，由 soko_planner 与 soko_algo 两个模块构成。整体软件遵循分层模块化架构，自底向上依次为驱动层、设备层、功能模块层与任务调度层；规划器通过任务调度层管理扫描-推箱的状态机流转，各模块间通过全局 BSS 结构体传递状态，全程不依赖堆分配。
	算法的关键设计决策如下：
（1）全静态分配：所有 BFS 搜索队列（bfs_q、bfs_parent、bfs_act，合计约 180 KB）、距离缓存表（dist_table，576 B）与地图状态（g_map，192 B）均在编译期分配于 .bss 或 .data 段，运行期不调用动态内存分配，保证在主控仅有 4~8 KB 栈空间的条件下安全运行。
（2）双平台兼容：通过编译宏 SOKO_NO_STATE_ARG 控制全局状态的传递方式，并以定时器桩（phase3_pit_stub.c）在 PC 端模拟定时器行为，使算法核心代码零平台差异，可直接在 PC 端完成仿真验证后再移植到板端。
（3）算法层与测试框架分离：真值表、CNN 分类替代实现等测试支撑仅存在于测试目录，算法模块与板端代码不携带任何测试残留，保证实际运行行为的唯一性。

static float Speed_PI_AntiWindup(float current_output,
                                 double p_delta,
                                 double i_delta,
                                 double d_delta)
{
    double output_without_i = current_output + p_delta + d_delta;
    double next_output = output_without_i + i_delta;

    if ((next_output > MAX_MOTOR_PWM && i_delta > 0.0) ||
        (next_output < -MAX_MOTOR_PWM && i_delta < 0.0))
    {
        next_output = output_without_i;
    }


    if (next_output > MAX_MOTOR_PWM)
    {
        next_output = MAX_MOTOR_PWM;
    }
    else if (next_output < -MAX_MOTOR_PWM)
    {
        next_output = -MAX_MOTOR_PWM;
    }

    return (float)next_output;
}

void LF_Speed_Control(void)
{
    double fP, fI, fD, SPEED_P_LF, SPEED_I_LF;

    LF_Speed_Error_t2 = LF_Speed_Error_t1;
    LF_Speed_Error_t1 = LF_Speed_Error;
    LF_Speed_Error = LF_Set_Speed - LF_Speed;

    SPEED_P_LF = P_LF;
    SPEED_I_LF = I_LF;

    fP = (LF_Speed_Error - LF_Speed_Error_t1) * SPEED_P_LF;
    fI = LF_Speed_Error * SPEED_I_LF / 100.0;
    fD = (LF_Speed_Error - 2 * LF_Speed_Error_t1 + LF_Speed_Error_t2) * SPEED_D;

    LFSpeedControlOut = Speed_PI_AntiWindup(LFSpeedControlOut, fP, fI, fD);
}
