摘 要
本文详细介绍了大连交通大学智能视觉组参赛队伍在第二十一届全国大学生智能汽车竞赛中的系统设计方案。本届智能视觉组采用“虚实结合”的全新比赛模式，车模通过车载无线屏幕读取虚拟游戏画面，完成推箱子任务。
本队基于大赛组委会统一指定的M型全向车模构建车体，使用NXP i.MX RT1064作为主控芯片，搭载两个OpenART Plus视觉模块分别识别屏幕中的全局俯视图与第一视角画面，配合架设于场地上方的彩钻风全局摄像头完成车模定位。
比赛任务分为三个连续关卡：第一关通过颜色阈值分割区分箱子与目的地完成传统推箱子；第二关利用基于MobileNetV2的图像分类模型识别箱子侧面的卡通角色图案（共10类），将其推送至对应数字的目的地；第三关在第二关基础上增加炸弹元素。
路径规划方面，在RT1064主控上运行BFS与A*算法完成栅格地图中的路径搜索。运动控制采用麦克纳姆轮全向运动学解算与PID闭环控制算法，结合编码器速度反馈与IMU姿态感知，实现车模的精确速度与方向控制。电路部分自主设计主板与驱动板，集成电源管理电路与基于DRV8701的电机驱动电路。在调试阶段，利用VOFA+上位机软件观测控制响应曲线，通过按键与屏幕完成参数整定。实验结果表明，该系统方案能够有效完成虚实融合环境下的推箱子比赛任务。

第一章
1.1 智能汽车制作概况
　　全国大学生智能汽车竞赛是由教育部高等学校自动化类专业教学指导委员会主办的一项面向全国大学生的创意性科技竞赛，自2006年创办以来已成功举办二十届。竞赛以迅猛发展的汽车电子为背景，涵盖控制、模式识别、传感技术、电子、电气、计算机、机械等多个学科交叉，旨在培养大学生的综合知识运用能力、基本工程实践能力和创新意识。竞赛要求参赛队伍在规定车模平台上，自主设计控制方案，完成传感器信号采集、决策算法开发、运动控制实现等全流程工程实践，最终完成指定的赛道任务。
第二十一届全国大学生智能汽车竞赛智能视觉组采用了“虚实结合”的全新比赛模式。与传统竞速组别依赖物理赛道不同，智能视觉组通过在车模上放置一块车载无线屏幕，实时显示由比赛系统生成的虚拟仿真画面。画面中包含场地的全局俯视图以及车模的第一视角图像。车模通过自身的视觉模块读取屏幕内容，识别虚拟环境中的目标元素，并自主规划路径完成推箱子任务。车模在物理场地中的真实位置由架设于场地上方的全局摄像头通过识别车模顶部的AprilTag标识牌来实时定位，从而实现物理空间与虚拟空间的坐标映射。场地四角贴有编号15-18的AprilTag码，用于系统自动定位场地位置并对全局进行逆透视校正。

图 1 -4 AprilTag码（ID 15-18）
围绕本赛事要求，本队选用竞赛组委会指定的M型全向车模作为移动平台。M车模采用麦克纳姆轮底盘，具备全向移动能力，能够实现前进、后退、横向平移及原地旋转等运动，为在狭窄场地内完成推箱子任务提供了灵活的机动性。车模搭载一块约4英寸的车载无线屏幕，分辨率不低于720×1080，屏幕画面分为左右两半：左侧显示车模第一视角画面，右侧显示场地全局俯视图。车模前方安装有两个OpenART Plus视觉模块，分别对准屏幕的左右两侧区域，实时读取屏幕中的虚拟场景信息。其中一个OpenART Plus负责解析全局俯视图中的元素（箱子、目的地、围墙、炸弹等），另一个负责识别第一视角画面中目标箱体上的卡通角色图案。在场地正上方约2米高处，架设有一台彩钻风全局摄像头，用于识别车模顶部的标识牌，实时获取车模在场地中的位置与方向信息，并将其反馈至比赛系统，完成虚实坐标同步。

图 2 车模设计从简到精
比赛任务分为三个难度关卡。第一关为传统推箱子，车模通过颜色识别区分可移动箱子（黄色）、目的地箱子（紫色）、围墙（灰色）、炸弹（红色）等元素，将所有黄色箱子推到紫色目的地即可完成。第二关为按图片分类推箱子，可移动箱子侧面贴有卡通角色图案（共10种：米老鼠、皮卡丘、海绵宝宝、喜羊羊、唐老鸭、哪吒、大头儿子、猪猪侠、葫芦娃、灰太狼），目的地箱子侧面贴有数字0-9，车模需识别箱子上的图案并将其推到对应数字的目的地。第三关在第二关基础上增加炸弹元素，炸弹可以炸掉场地中间的围墙，使运动路线更短。三个关卡连续进行，车模完成一关后需自动返回发车区以触发下一关。

图 3 比赛系统
　　车模的主控芯片选用NXP公司的RT1064微控制器，该芯片基于Arm Cortex-M7内核，主频高达600MHz，具备充足的计算性能和丰富的外设接口，能够满足多路传感器数据采集、运动学解算、PID闭环控制以及与视觉模块间高速通信的实时性要求。三个驱动电机均配备编码器用于速度反馈，同时搭载IMU（惯性测量单元）用于姿态感知，两者结合形成速度闭环与角度闭环控制系统。车模的驱动电路采用基于DRV8701芯片的自制驱动板，电源管理采用自主设计的主板完成多级稳压供电。路径规划方面，系统在RT1064主控上运行，获取全局地图信息后，采用广度优先搜索（BFS）与A*算法相结合的路径搜索策略，在保证路径最优性的同时兼顾计算效率。运动控制则采用经典PID控制算法，分别对车速和航向进行闭环调节。
整体而言，本系统围绕“感知—决策—执行”的技术链路进行设计：两个OpenART Plus构成视觉感知前端，RT1064主控完成信息融合与决策计算，麦克纳姆轮底盘配合PID控制实现运动执行。系统的核心竞争力主要体现在路径规划算法的效率优化与控制参数的精细整定两方面。
1.2 相关技术与文献综述
　　智能车自主导航技术涉及环境感知、路径规划与运动控制三大核心环节，近年来随着嵌入式平台算力的提升与深度学习算法的发展，该领域的研究取得了显著进展。
　　在视觉感知方面，传统的图像处理方法如颜色阈值分割、边缘检测等，凭借其计算开销小、实时性高的优点，在资源受限的嵌入式平台上仍有广泛应用。本赛题第一关要求车模仅凭颜色区分箱子与目的地，这一任务通过简单的颜色阈值分割即可高效完成。随着赛题难度提升至第二关和第三关，车模需要识别箱体上的卡通角色图案或数字类别，此时需要引入基于深度学习的方法。卷积神经网络（CNN）在图像分类任务中表现出色，MobileNet等轻量化网络模型通过深度可分离卷积在保持较高准确率的同时大幅降低计算量，适合部署于OpenART Plus等嵌入式视觉模块。各参赛队伍通常采用NXP eIQ工具链完成模型的训练、量化与部署。本队同样采用此技术路线，在eIQ平台上完成分类模型的训练与INT8量化部署。
　　在路径规划方面，智能车竞赛中常用算法包括A、Dijkstra、BFS等经典搜索算法。A算法通过引入启发式函数在保证最优性的同时提高搜索效率，是全局路径规划的常用选择。BFS则在无权图中能够保证找到最短路径，适用于网格化的环境建模。本赛题中虚拟场地被建模为16×12的栅格地图，地图规模有限，BFS与A*算法能够在RT1064上实时运行，满足比赛对决策频率的要求。此外，部分队伍尝试采用深度强化学习方法（如PPO、DQN）进行路径规划策略的学习，但训练过程复杂且对算力要求较高。
　　在运动控制方面，PID控制因其结构简单、参数物理意义明确、易于工程实现，仍然是智能车竞赛中最广泛使用的控制算法。对于麦克纳姆轮全向底盘，需要将车体坐标系下的期望速度（纵向、横向、旋转角速度）通过逆运动学模型解算为四个轮子的独立目标转速，再通过PID闭环控制实现精确的速度跟踪。参赛队伍普遍借助上位机软件可视化观察响应曲线，辅助参数调整。
　　综合而言，本系统在视觉感知、路径规划与运动控制三个方面均采用了业界成熟、经过竞赛验证的技术方案，将精力集中于算法实现的可靠性与参数优化的精细度上，确保车模在比赛中的稳定表现。

第二章 模型车总体设计方案
2.1 整体设计思路
系统整体架构自上而下分为感知层、决策层与执行层三个层级。感知层由两个车载OpenART Plus视觉模块与一个场外彩钻风全局摄像头构成。其中，右侧OpenART Plus负责采集车载屏幕中的全局俯视图画面，通过颜色阈值分割识别可移动箱子、目的地箱子、围墙及炸弹等元素的位置信息；左侧OpenART Plus负责采集屏幕中的第一视角画面，通过部署于其上的MobileNetV2图像分类模型识别目标箱子侧面的卡通角色图案（共10类）。彩钻风全局摄像头架设于场地上方约2米处，通过识别车模顶部的AprilTag标识牌，实时获取车模在场地中的全局坐标与航向角，并将该信息反馈至比赛系统，完成物理车模与虚拟场景的坐标同步。

图 4 比赛系统与比赛场地
　　决策层以NXP RT1064微控制器为核心，接收来自感知层的结构化信息。对于来自右侧OpenART的全局地图信息，RT1064构建16×12的栅格地图，运行BFS与A*路径规划算法，在考虑围墙障碍与当前车模位姿的前提下，搜索从当前位置到目标箱子的最优路径，以及从箱子到对应目的地的最优推箱路径。对于来自左侧OpenART的图案识别结果，RT1064根据第二关的匹配规则（卡通角色对应数字0-9），确定当前箱子应被推送至哪个目的地。对于来自彩钻风全局摄像头的车模位姿信息，RT1064将其与车载编码器里程计和IMU姿态数据进行融合，修正车模在栅格地图中的精确位置与方向。
　　执行层同样以RT1064为核心，将决策层输出的期望速度指令（纵向速度、横向速度、旋转角速度）通过麦克纳姆轮逆运动学模型解算为四个驱动电机的独立目标转速，再经由增量式PID速度闭环控制算法，结合编码器实时反馈的实际转速，驱动电机精确执行。IMU提供的姿态角信息则用于角度闭环控制，确保车模在转向和推箱过程中的方向精度。
系统工作流程如下：彩钻风全局摄像头识别车模位姿并同步至比赛系统；比赛系统将虚拟场景渲染至车载屏幕。我们的两个OpenART Plus分别读取屏幕左右半区的画面并解析为结构化信息；RT1064融合多源信息完成决策与运动解算；执行层驱动底盘运动；编码器与IMU将实际运动状态反馈至RT1064，形成速度与角度的闭环调节。
   
图 5 AprilTag识别逆透视前后对比图

与竞速组别（如摄像头竞速、电磁竞速等）相比，智能视觉组的差异化特征主要体现在以下三个方面。其一，感知对象不同。竞速组别通常依赖摄像头或电磁传感器感知物理赛道上的边界线与元素（如环岛、十字路口等），而智能视觉组感知的是屏幕中的虚拟画面，感知对象是软件渲染生成的虚拟元素，其颜色、形状、位置均由比赛系统动态决定，且存在屏幕反光、画面畸变等干扰因素。其二，决策任务不同。竞速组别的决策主要体现为循迹控制与速度规划，而智能视觉组除路径跟踪外，还需要完成推箱子任务中的目标选择、路径搜索、推箱顺序规划等更高层次的决策。其三，定位方式不同。竞速组别通常依赖赛道上的标志物或编码器里程计进行相对定位，而智能视觉组依赖全局摄像头与AprilTag标识牌实现绝对定位，定位精度直接影响虚拟场景中车模坐标的准确性，进而影响整个任务执行的成败。

2.2 硬件平台选型
2.2.1 主控MCU
　　本系统主控芯片选用NXP公司的i.MX RT1064跨界微控制器。该芯片基于Arm Cortex-M7内核，主频高达600MHz，配备1MB片内SRAM与4MB片内Flash，并外扩32MB SDRAM，在微控制器架构下实现了接近应用处理器级别的计算性能，同时保持了中断响应延迟确定性的优势，适合承担多传感器数据融合、路径规划算法运行与实时运动控制等对算力和实时性均有较高要求的任务。
在接口资源方面，RT1064提供了丰富的外设接口，包括多个UART、SPI、I2C、PWM及正交解码器接口等，能够满足与两个OpenART Plus视觉模块（UART通信）、彩钻风全局摄像头（连接系统）、编码器（正交解码）、IMU（I2C/SPI）以及电机驱动（PWM）等多路外设的同时连接需求。NXP官方提供的MCUXpresso SDK与eIQ机器学习工具链为模型部署与嵌入式开发提供了完善的软件生态支持，显著缩短了系统开发周期。

图 7 RT1064核心板
2.2.2 视觉传感器
　　本系统共使用三个视觉传感器，根据各自功能定位分别选型。
车载屏幕读取采用两个OpenART Plus视觉模块。OpenART Plus是基于NXP i.MX RT系列MCU的嵌入式视觉处理平台，内置TensorFlow Lite Micro推理引擎，支持在边缘端直接运行轻量化深度学习模型，无需将图像数据上传至上位机处理，有效降低了系统整体延迟。两个OpenART Plus分别对准车载无线屏幕的左右半区：左侧模块负责第一视角画面中卡通角色图案的分类识别，运行MobileNetV2图像分类模型；右侧模块负责全局俯视图画面中元素的位置检测，运行基于颜色阈值的传统视觉算法。两个模块均通过UART串口（115200bps）与主控RT1064通信，将识别结果以结构化数据包的形式实时上报。

图 8 OpenART Plus
全局定位采用彩钻风摄像头，架设于场地正上方约2米处，俯视覆盖整个3.2m×2.4m的比赛场地。该摄像头具备较高的分辨率和帧率，能够稳定识别车模顶部的AprilTag标识牌以及场地四角的编号15-18定位码，为比赛系统提供车模的全局坐标与航向角信息。彩钻风摄像头通过USB接口连接至比赛系统上位机，由上位机软件完成AprilTag检测与逆透视变换处理，车模本身无需直接处理该摄像头的图像数据，仅需通过无线通信接收比赛系统下发的车模定位结果。

2.2.3 辅助计算单元
　　两个OpenART Plus模块已承担全部车载视觉计算任务，RT1064承担全部决策与运动控制计算任务。当前算力分配方案能够满足比赛任务对实时性的要求（路径规划周期与运动控制周期均在毫秒级），无需额外增加协处理器以控制硬件成本与系统复杂度。
2.3 软件架构设计
2.3.1 操作系统
　　本系统软件采用裸机中断驱动架构，未引入实时操作系统（RTOS）。选择裸机方案主要基于以下考虑：系统外设数量有限且任务类型相对固定，主要包括UART数据接收（来自两个OpenART Plus）、编码器脉冲计数（三个电机）、IMU数据读取、路径规划计算、PID控制计算与PWM输出等。上述任务可通过定时器中断与串口接收中断的优先级调度机制实现有序执行，裸机方案足以满足实时性要求，且代码结构简洁、中断响应延迟确定、资源占用低。
　　系统的主控制周期由PIT定时器产生20ms周期中断驱动。在每个控制周期内，主控依次完成以下操作：读取最新到达的OpenART识别结果与车模定位信息、执行路径规划与决策更新、计算期望运动速度、进行麦克纳姆轮逆运动学解算、执行增量式PID速度闭环控制、更新PWM输出。编码器计数在中断服务程序中实时累计，IMU数据以独立定时器中断采集，与主控制周期异步进行。
2.3.2 视觉处理流水线设计
　　两个OpenART Plus视觉模块各自运行独立的视觉处理流水线，分别完成全局感知与目标识别任务。
　　右侧OpenART Plus的视觉处理流水线（全局感知）按以下步骤执行：图像采集（从车载屏幕右半区获取720×540分辨率的全局俯视图）→颜色空间转换（RGB转HSV）→颜色阈值分割（根据预设的黄色、紫色、红色、黑灰色的HSV阈值范围生成二值化掩膜）→形态学处理（开运算去除噪声、闭运算填充空洞）→连通域分析与轮廓提取（识别各目标的中心坐标与边界框）→数据打包与发送（通过UART将目标类型与坐标以自定义帧格式发送至RT1064）。该流水线完全基于传统图像处理算法，无需神经网络推理，单帧处理时间可控制在30ms以内。
左侧OpenART Plus的视觉处理流水线（目标识别）按以下步骤执行：图像采集（从车载屏幕左半区获取第一视角画面）→感兴趣区域（ROI）提取（定位屏幕中目标箱体所在的区域）→图像预处理（尺寸归一化至128×128）→MobileNetV2模型推理（运行INT8量化的图像分类模型，输出10类卡通角色的概率分布）→置信度判决（选取最高置信度类别，若置信度阈值高于0.7则作为有效识别结果）→数据打包与发送（通过UART将图案类别ID以自定义帧格式发送至RT1064）。该流水线的核心是MobileNetV2轻量化卷积神经网络，经INT8量化后模型体积小于1MB，单次推理时间满足实时识别要求。

3.1.1 底盘重心调整与配重方案
本系统选用竞赛组委会指定的M型全向车模作为移动平台。M车模采用四轮麦克纳姆轮底盘，配备四个380有刷直流减速电机，麦克纳姆轮直径约6.3cm。麦克纳姆轮对重心位置较为敏感，重心偏移会直接影响全向运动时各轮与地面的接触压力分布，进而导致平移运动时的偏航和旋转运动时的抖动。因此，重心调整是机械改造的首要任务。

3.1.2 转向机构优化
　　M车模采用麦克纳姆轮实现全向运动，无需传统的转向舵机机构。车模的转向通过四个麦克纳姆轮的速度差合成实现：当车体需要旋转时，对角方向的轮组以相反方向转动，产生绕车体垂直轴（Z轴）的力矩，从而实现原地旋转或行进间转向。因此，转向机构的优化主要体现在车轮与地面的接触性能以及电机响应的一致性上。
本队对转向性能的优化主要包括以下方面：其一，确保四个麦克纳姆轮的辊子转动灵活，定期清理辊子与轮毂之间可能夹入的异物，避免因个别辊子卡滞导致的转向力矩不对称。其二在软件层面通过编码器实时监测四个电机的转速，若检测到某一轮速偏离目标值超过设定阈值，则通过PID控制器动态补偿，确保四轮转速能保证转向动作的精确性与平滑性。

3.2 视觉传感器安装设计
3.2.1 摄像头安装高度、俯仰角与前视距离
　　本系统的车载视觉传感器为两个OpenART Plus模块，分别对准车载无线屏幕的左右半区进行图像采集。两个OpenART Plus以并排方式安装于车模前部的一个3D打印支架上，镜头平面垂直于水平面，与车载屏幕平面保持平行。支架高度根据屏幕安装位置确定——车载无线屏幕竖直固定于车模前部，屏幕下沿距离地面约12cm，屏幕中心距离地面约18cm。两个OpenART Plus的镜头中心与屏幕中心大致处于同一水平高度（约18cm），以确保采集到的画面在垂直方向上居中，避免因镜头与屏幕不在同一高度而产生的梯形畸变。
　　在水平方向上，两个OpenART Plus的镜头光轴与屏幕平面垂直，镜头距离屏幕表面约10-12cm。这一距离的确定基于以下因素的综合考量：若距离过近，单个OpenART Plus的视场角无法覆盖屏幕的半区画面（每半区分辨率为720×540）；若距离过远，则画面中目标元素的像素尺寸过小，影响颜色阈值分割的精度与分类模型的识别准确率。经实测，10-12cm的物距能够在OpenART Plus的视场范围内完整覆盖屏幕半区，且目标元素（边长为45像素的虚拟方块）在画面中占据足够的像素数量，满足后续图像处理与模型推理的要求。
　　两个OpenART Plus的水平间距由屏幕的左右半区分割线决定。屏幕中线位置对应的物理坐标即为两个模块采集区域的分界，左侧OpenART Plus采集屏幕左半区（第一视角画面），右侧OpenART Plus采集屏幕右半区（全局俯视图）。两模块之间通过3D打印支架上的隔板进行物理隔离，避免侧面杂光干扰。

3.2.3 机械减震与防抖结构设计
车模在运动过程中，电机振动与路面不平会通过底盘传递至上部结构，引起OpenART Plus摄像头与车载屏幕的抖动，进而影响图像采集的稳定性。为此，本队在视觉传感器与屏幕的安装结构中设计了减震与防抖措施。
安装板上的模块用螺丝钉固定好，所有线束（包括OpenART Plus的供电线与UART通信线、屏幕的电源线与视频信号线）均使用扎带固定于主支架的走线槽内，避免线束在运动过程中晃动拉扯模块，引入额外的振动源。
3.2.4 防反光方案
　　车载无线屏幕为自发光显示设备，其亮度与对比度受环境光影响较大。在室内比赛场地中，若环境光过强或存在定向光源直射屏幕表面，会导致屏幕画面出现反光或局部过曝，影响OpenART Plus的图像采集质量。为此，本队设计了防反光方案。
防反光即使用安装版同时作为遮光罩，是3D打印的黑色PLA材质，内壁采用哑光处理，长度为3cm，前端开口略大于镜头视场角。遮光罩能够有效遮挡来自侧上方和侧方的环境光，防止光线直接照射到镜头前端的屏幕区域，同时不影响镜头对屏幕画面的正常采集。

3.3 其他传感器布局
3.3.1 编码器、IMU的安装位置
　　本系统除视觉传感器外，还配置了编码器与IMU（惯性测量单元）两类辅助传感器。
编码器用于测量四个驱动电机的实时转速，构成速度闭环控制的关键反馈环节。四个编码器分别安装于四个电机的尾部，通过齿轮与电机输出轴啮合。安装时需确保编码器齿轮与电机齿轮的啮合间隙适中——啮合过紧会增加电机负载并加速齿轮磨损，啮合过松则会导致编码器计数丢步，影响速度测量的准确性。经多次调整，齿轮啮合间隙控制在0.1-0.2mm范围内，编码器输出信号稳定，未出现明显的计数跳变。

图 20 编码器
　　IMU（六轴惯性测量单元，包含三轴加速度计与三轴陀螺仪）用于测量车模的角速度与加速度，为姿态感知与角度闭环控制提供数据基础。将IMU布置于车体中心位置，能够最大限度地减小车模旋转时向心加速度对加速度计测量的影响，同时使陀螺仪测量的角速度更准确地反映车体绕垂直轴的转动。
3.3.2 各传感器坐标系与视觉坐标系的统一对齐
　　系统中涉及多个坐标系：彩钻风全局摄像头的场地坐标系（以场地一角为原点，X轴沿场地长边，Y轴沿场地短边）、车载屏幕的像素坐标系（以屏幕左上角为原点，U轴向右，V轴向下）、车模本体的机体坐标系（以车体几何中心为原点，X轴指向车头方向，Y轴指向车身左侧）以及IMU的传感器坐标系（与机体坐标系对齐）。
上述坐标系之间的对齐关系如下：彩钻风全局摄像头的场地坐标系与比赛系统的虚拟地图坐标系重合，由比赛系统通过AprilTag标定统一维护。车模在场地坐标系中的位置与航向角由比赛系统解算后，通过无线方式下发给RT1064主控，作为路径规划的全局参考。车载屏幕的像素坐标系与两个OpenART Plus的图像坐标系通过镜头视场角与物距的几何关系建立映射——OpenART Plus采集到的画面中每个像素的位置均可通过预先标定的转换关系映射到屏幕像素坐标系中的对应位置，进而映射到虚拟地图中的坐标。机体坐标系与IMU传感器坐标系通过IMU的安装方向保持一致（IMU的X轴指向车头方向），编码器测量的轮速在机体坐标系下进行运动学合成。整体而言，所有传感器数据最终均统一转换至虚拟地图坐标系中，由RT1064进行融合处理。

第四章 电路系统设计
4.1 电源管理电路
　　稳定的电源供给是保障智能车各模块正常工作的基础。本系统采用3S锂聚合物电池（额定电压11.1V，满电电压12.6V）作为总电源，经多级电压转换后为各功能模块提供所需的供电电压。
4.1.1 电池电压监测与欠压保护电路
　　3S锂电池在放电过程中电压逐渐下降，当单节电芯电压低于3.0V时继续放电将导致电池不可逆损坏。因此，系统设计了电池电压监测与欠压保护电路。
4.1.2 多路稳压拓扑设计
　　系统各模块所需电压等级不同，需要将12.6V电池电压转换为多路稳定的低压电源。本系统采用“一级降压+二级稳压”的两级电源架构，具体拓扑如下。
　　12V→5V降压电路：采用芯洲科技SCT2450STER同步降压DC-DC转换器。该芯片输入电压范围为3.8V至36V，输出电流高达5A，完全满足3S锂电池的输入条件与系统总电流需求。电路采用典型应用拓扑，输入侧并联100μF电解电容与0.1μF陶瓷电容进行滤波，输出侧配置22μH功率电感与100μF电解电容，输出电压通过反馈电阻网络设置为5.0V。该5V电源作为系统的主干电源，为后续各级LDO以及部分5V供电模块提供输入。
5V→3.3V稳压电路：采用331MR-G低压差线性稳压器（LDO）。该芯片输入电压范围为2.5V至16V，固定输出3.3V，最大输出电流500mA，采用SOT-23封装，外围电路简单，仅需输入输出各并联1μF陶瓷电容即可稳定工作。该3.3V电源为主控RT1064的I/O电源、OpenART Plus的I/O接口以及IMU的数字接口供电。
5V直接供电：部分模块直接使用5V主干电源，包括两个OpenART Plus视觉模块、车载无线屏幕以及编码器。OpenART Plus支持通过5V引脚直接供电，车载屏幕与编码器同样为5V工作电压。

4.3.1 驱动芯片选型
　　本系统需驱动四个直流减速电机，选用德州仪器（TI）的DRV8701E栅极驱动器芯片配合外部N沟道MOSFET构成H桥驱动电路。DRV8701E是一款单路H桥栅极驱动器，采用4个外部N沟道MOSFET驱动直流电机，其主要特性如下：
　　宽电压输入：支持6.5V至45V的电机供电电压，可直接由3S锂电池（12.6V）供电，无需额外升压。
　　接口简单：通过PH/EN接口与主控连接，PH引脚控制电机方向（高电平正转、低电平反转），EN引脚接收PWM信号控制电机转速。相比传统的双PWM控制方案，PH/EN方式仅需两路信号即可完成方向与速度控制，节省了主控的PWM资源。
　　集成电流检测：内部集成高精度电流检测放大器，通过外部采样电阻可实时监测电机相电流，为主控提供过流保护与力矩感知的硬件基础。
　　完善保护功能：集成过流保护、欠压保护、过温保护等多重保护机制，有效保障驱动电路在异常工况下的安全性。
每个电机使用一片DRV8701E，共需四片。每片DRV8701E搭配四颗N沟道MOSFET（型号TPH1R403NL，耐压40V，导通电阻1.4mΩ）构成全桥拓扑。MOSFET选型依据为低导通电阻以降低功率损耗、高开关速度以支持较高频率的PWM调制（本系统PWM频率为17kHz）。

4.3.2 驱动电路外围设计
　　DRV8701E的外围电路主要包括以下部分：
　　供电与去耦：DRV8701E的VM引脚连接至电池正极（12.6V），在VM与地之间并联100μF电解电容与0.1μF陶瓷电容，为驱动电路提供稳定的电源并抑制电机换相时产生的电压尖峰。VCC引脚需提供3.3V或5V逻辑电源，本系统由5V主干电源供电。

自举电容：DRV8701E的CB引脚与VM引脚之间连接0.1μF自举电容，为上桥臂MOSFET的栅极驱动提供自举升压电源。

5.1.1 畸变校正与自动白平衡

5.1.2 感兴趣区域（ROI）动态提取
　　两个OpenART Plus分别对准车载无线屏幕的左右半区，各模块的采集画面中仅屏幕区域为有效信息，屏幕周围的车体结构件与背景为无效区域。为减少后续图像处理的计算量并提高识别准确性，系统对每个模块的采集画面实施感兴趣区域（ROI）动态提取。
　　右侧OpenART Plus（全局俯视图识别）的ROI提取策略如下：基于屏幕在画面中的固定物理位置，设定固定矩形ROI区域（宽度160像素，高度120像素），裁剪出屏幕右半区的俯视图画面。该ROI覆盖了虚拟场地16×12栅格地图的全部区域，排除了屏幕边框与背景干扰。
　　左侧OpenART Plus（第一视角识别）的ROI提取策略如下：由于第一视角画面中目标箱体出现的区域随车模运动而变化，采用动态ROI提取方法——先通过颜色阈值快速定位画面中紫色目的地或黄色箱体的位置，再以该位置为中心扩展适当边距构成动态ROI，将目标区域裁剪后送入分类模型进行推理。动态ROI将分类模型的输入从整幅画面缩小至目标周围区域，减少了无效背景对分类结果的干扰。
5.2 目标元素识别算法
5.2.1 左侧OpenART Plus：图像分类模型
　　第二关与第三关需要识别可移动箱子侧面的卡通角色图案，共10个类别，对应关系如下表所示。
　　数据集构建：本队从比赛系统软件中提取官方数据集图片，保存为128×128分辨率的RGB图像，按10个类别分类存放。为提高模型泛化能力，对原始数据集进行了数据增强操作，包括：±15°随机旋转、±10%亮度调整、±5%对比度调整、高斯模糊（核大小3×3）以及水平翻转（仅针对非对称图案）。数据增强后每类图片扩充至约200张，构建了总计约2000张的训练集与验证集。
　　模型结构：选用MobileNetV2作为分类骨干网络。MobileNetV2采用深度可分离卷积（Depthwise Separable Convolution）代替标准卷积，将标准卷积分解为深度卷积与逐点卷积两个步骤，参数量减少约一个数量级。其倒残差结构（Inverted Residual）在扩展维度后进行深度卷积，再压缩至低维空间，在保持特征表达能力的同时进一步降低了计算量。针对10分类任务，将MobileNetV2的全连接输出层修改为10维Softmax层，其余层结构与ImageNet预训练权重保持一致。
　　训练与量化：模型训练在NXP eIQ Portal平台上完成。训练参数设置如下：Epoch数100，Batch Size 32，初始学习率0.001，优化器采用Adam，损失函数为稀疏分类交叉熵（Sparse Categorical Crossentropy）。训练过程中使用早停策略（Early Stopping，Patience=10）防止过拟合。训练完成后，模型在验证集上的准确率达到99%以上。
　　模型量化采用eIQ Portal的后训练INT8量化工具，将FP32浮点权重转换为INT8定点格式。量化后模型体积由约9.4MB压缩至约3.5MB，推理速度提升约40%。量化后的模型文件（.tflite格式）与标签映射文件（labels.txt）存入OpenART Plus的SD卡中，由推理程序加载执行。
5.3 路径规划与决策
5.3.1 栅格地图建模
　　虚拟场地被建模为16×12的栅格地图，每个栅格对应物理场地中约20cm×20cm的区域。系统在RT1064主控中维护一个16×12的二维数组作为地图数据结构，每个元素存储该栅格的类型信息：空地（可通行）、围墙（不可通行）、可移动箱子（黄色）、目的地箱子（紫色）、炸弹（红色）以及车模当前位置。
　　右侧OpenART Plus通过颜色识别获取各元素在屏幕画面中的像素坐标，经坐标系转换后映射至栅格地图中对应的行列索引。RT1064接收这些结构化的地图信息后，实时更新维护的栅格地图数据。
5.3.2 路径搜索算法
　　本系统采用BFS（广度优先搜索）与A*算法相结合的路径搜索策略，两种算法根据任务需求自适应切换。
　　BFS算法用于无权重的空地连通性搜索。BFS从起点栅格开始，逐层向外扩展，直至搜索到目标栅格，保证找到的路径在步数上最短（即栅格数量最少）。BFS的时间复杂度为O(V+E)，其中V为栅格总数（192），E为相邻栅格边数（约360），在RT1064上单次搜索时间小于1ms。BFS适用于以下场景：状态0（搜索目标）中从车模当前位置搜索最近的可移动箱子，以及状态4（推送）中搜索箱子到目的地的最短路径。
　　A算法用于带启发式信息的优先搜索。A在BFS的基础上引入了启发式函数f(n)=g(n)+h(n)，其中g(n)为从起点到当前节点的实际代价，h(n)为当前节点到目标节点的估计代价（本系统采用曼哈顿距离）。A能够引导搜索方向优先朝向目标区域，在保证最优性的前提下搜索效率高于BFS。A适用于以下场景：当场地中存在多个目标箱子时，需要评估推箱顺序以最小化总路径长度。

5.3.3 推箱路径规划
　　推箱子任务的核心在于规划从目标箱子到对应目的地的推箱路径，同时避免将箱子推入死角（如墙角或贴边位置）。推箱路径规划遵循以下约束条件：
　　箱子只能被车模从某一方向推动，推动方向为车模前进方向。当车模位于箱子后方（相对于目的地方向），向前行驶时箱子被推动一格。推箱路径规划分为两个阶段：第一阶段，规划车模从当前位置到箱子后方的路径（空载路径）；第二阶段，规划箱子被逐格推至目的地的路径（负载路径），其中每一步推动后车模均位于箱子后方，下一步推动前需绕行至新的后方位置。
　　系统采用BFS算法在栅格地图上搜索推箱路径。每次搜索时，箱子的位置被视为可通行但不可跨越的障碍，车模可以在箱子周围的空地上绕行。搜索空间定义为（车模位置，箱子位置）的二元组，状态转移包括两种情况：车模移动到相邻空地（箱子位置不变），以及车模推动箱子到相邻空地（车模和箱子同时移动，且推动方向前方为可通行空地）。
5.4 运动控制算法
5.4.1 麦克纳姆轮运动学模型
　　M车模采用三轮麦克纳姆轮底盘（因车模为三轮布局，三个电机分别驱动三个麦克纳姆轮），需要将车体坐标系下的期望速度（纵向速度v_y、横向速度v_x、旋转角速度ω）通过逆运动学模型解算为三个轮子的独立目标转速。
　　三轮麦克纳姆轮底盘的运动学模型如下。设三个轮子呈120°对称分布，轮子半径为r，车体质心到轮子的距离为R，三个轮子的转速分别为ω1、ω2、ω3。根据麦克纳姆轮的运动学原理，车体速度与轮速的转换关系为：
　　逆运动学方程（由期望车体速度求轮速）：
　　将三轮角度（120°对称分布）代入后可得到具体解算公式。三个轮子的目标转速由以下方程组计算：
　　轮1目标转速 ← -sin(270°) × v_x + cos(270°) × v_y + ω × N
　　轮2目标转速 ← -sin(150°) × v_x + cos(150°) × v_y + ω × N
　　轮3目标转速 ← -sin(30°) × v_x + cos(30°) × v_y + ω × N
　　其中N为与轮子半径和轮距相关的比例系数，v_x为横向速度（正值为右移），v_y为纵向速度（正值为前进），ω为旋转角速度（正值为顺时针旋转）。
5.4.2 PID速度闭环控制
　　系统对三个驱动电机分别实施增量式PID速度闭环控制。增量式PID的输出为控制量的增量Δu(k)，而非绝对控制量，适用于电机转速控制场景。
　　增量式PID控制律为：
　　Δu(k) = Kp × [e(k) - e(k-1)] + Ki × e(k) + Kd × [e(k) - 2×e(k-1) + e(k-2)]
　　其中e(k) = 目标转速 - 实际转速为第k次采样的速度偏差，Kp、Ki、Kd分别为比例、积分、微分系数。实际控制量u(k) = u(k-1) + Δu(k)，经限幅后输出为PWM占空比。
　　每个电机的PID参数独立整定，以补偿机械装配差异导致的各轮性能不一致。参数整定采用Ziegler-Nichols临界比例度法：先令Ki=0、Kd=0，逐渐增大Kp直至系统出现等幅振荡，记录临界增益Ku与振荡周期Tu，再按以下公式计算最终参数：
　　Kp = 0.6 × Ku
　　Ki = 2 × Kp / Tu
　　Kd = Kp × Tu / 8
　　经实际调试，最终参数为Kp=35、Ki=4.5、Kd=0.8，三个电机在此参数基础上进行±10%的微调以匹配各自特性。PID控制周期为5ms，与主控制周期保持一致。
5.4.3 角度闭环控制
　　车模的航向角控制通过IMU反馈实现。系统采用位置式PD控制器，以目标航向角与实际航向角的偏差为输入，输出为旋转角速度指令ω。
　　角度PD控制律为：
　　ω = Kp_angle × θ_err + Kd_angle × (θ_err - θ_err_last)
　　其中θ_err = 目标航向角 - 实际航向角，Kp_angle为角度比例系数，Kd_angle为角度微分系数。该控制器的输出ω作为运动学模型的旋转角速度输入，最终解算为三个轮子的差速指令，驱动车模向目标航向角旋转。
　　角度闭环主要用于以下场景：状态1（靠近目标）中调整车头指向目标方向、状态3（绕行对准）中精确对准推箱方向、状态4（推送）中保持直线行驶方向不偏移。

    encoder_data_4=0.3*first_encoder_data_4+0.7*last_encoder_data_4;

int16_t speed_pid_set_1(int16_t target_speed, int16_t speed, speed_pid k)
{
    static float speed_error[3] = {0};
    static float pwm_out1 = 0;

    speed_error[0] = speed - target_speed;
    pwm_out1 += k.P * (speed_error[0] - speed_error[1]) + k.I * speed_error[0] + k.D * (speed_error[0] - 2 * speed_error[1] + speed_error[2]);
    speed_error[2] = speed_error[1];
    speed_error[1] = speed_error[0];
    pwm_out1 = func_limit(pwm_out1, pwm_pid_max);
    return pwm_out1;
}

#include "kaerman.h"

//卡尔曼只负责输出平滑曲线，滤波作用

 Kalman_TypeDef kf1,kf2,kf3,kf4,kf5;


// 卡尔曼初始化，dt则是多久调用一次
// 曲线更平滑（噪声更小）增加R减小Q；想要跟得上变化减小R增大Q
void Kalman_Init( float dt,Kalman_TypeDef * kf)
{
    kf->X = 0;
    kf->P = 1;
    kf->Q = 0.1;
    kf->R = 3;
		kf->dt=dt;
}

//------------------------------------------------------------------------------------------
// 函数简介
// 参数说明
// 返回参数
// 使用示例
// 备注信息
//------------------------------------------------------------------------------------------
void Kalman_Update(Kalman_TypeDef *kf,float measurement)
{
		kf->P = kf->P + kf->Q;
      // 卡尔曼增益
    float K = kf->P / (kf->P + kf->R);
    // 状态更新
    kf->X = kf->X+ K * (measurement - kf->X);
    // 协方差更新
    kf->P = (1.0f - K) * kf->P;
}
//获得滤波
float  Kalman_Get(Kalman_TypeDef *kf,float data)
{
	Kalman_Update(kf,data);
	
	return kf->X;
}
