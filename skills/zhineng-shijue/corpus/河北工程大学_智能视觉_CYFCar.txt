摘    要
本文以第二十一届全国大学生智能汽车竞赛为背景，以大赛组委会指定的车模为平台，介绍CYFCar队人工智能视觉组智能车系统的设计与实现。本设计采用虚实融合的“小车盯着屏幕玩游戏”赛制，以 NXP i.MX RT1064 高性能处理器为系统控制核心，通过视觉模块实时采集游戏屏幕图像，利用基于 MobileNetV2 的轻量化卷积神经网络识别屏幕上的动漫角色图形与数字，从而实现自主导航、目标识别与推箱子等比赛任务。系统主要由主控模块、视觉识别模块、电机驱动模块、电源模块与无线收发模块组成。动力系统采用四轮独立驱动的麦克纳姆轮底盘，无转向舵机，通过麦克纳姆轮运动学解算实现直行、横移与旋转等全向运动控制。视觉部分针对嵌入式平台算力受限的特点，通过宽度缩放（Alpha=0.75）、输入分辨率压缩（128×128）与 INT8 全整数量化等手段对模型进行深度裁剪与优化，在保证识别精度的前提下实现高速低耗的端侧推理；控制部分基于麦克纳姆轮运动学解算得到各轮目标转速，采用增量式 PID 对四个驱动电机分别进行速度闭环控制。经反复调试与测试，小车能够稳定、快速地完成目标识别与循迹行驶任务。

1.1 智能车大赛简介
教育部为了加强大学生实践、创新能力和团队精神的培养，在已经举办全国大学生数学建模、电子设计、机械设计、结构设计等四大竞赛的基础上，委托教育部高等学校自动化专业教学指导委员会举办每年一度的全国大学生智能汽车竞赛。
该赛事与教育部已经举办的四大竞赛一样，都是为了提高大学生的动手能力和创新能力而举办的，全国大学生智能汽车竞赛秉承“立足培养、强调参与、倡导探索、追求卓越”的理念，致力于为全国各高校学子提供一个开展探索性工程实践的开放平台。与其他大赛不同的是，这个大赛的综合性很强，是以迅猛发展的汽车电子为背景，涵盖了控制、模式识别、传感、电子、电气、计算机和机械等多个学科交叉的科技创意性比赛，这对进一步培养本科生获取知识、应用知识的能力及创新意识，具有重要意义。
第二十一届全国大学生智能汽车竞赛共设置多个赛题组别，人工智能视觉组为其中之一。本届人工智能视觉组采用虚实融合的“小车盯着屏幕玩游戏”赛制，结合真实车模与虚拟地图，通过视觉模块识别屏幕上动态出现的动漫角色图形与数字元素，并完成推箱子等比赛关卡任务，比赛过程既考验车模的控制稳定性，也对端侧视觉识别的实时性与鲁棒性提出了较高要求。
1.2 本组智能车制作情况概述
根据竞赛规则及功能要求，我们参加了第二十一届全国大学生智能汽车竞赛人工智能视觉组。本组以大赛组委会指定的车模为平台，以 NXP i.MX RT1064 高性能交叉处理器作为主控制单元，运用 MCUXpresso 等开发工具进行智能控制策略研究。道路信息检测模块由摄像头、显示屏等视觉模块构成，用于采集游戏屏幕图像并进行目标识别。智能车通过摄像头采集图像送入处理器，在处理器中运行基于 MobileNetV2 的轻量化神经网络模型，实时识别屏幕上的动漫角色图形与数字，据此规划运动路径并完成相应比赛任务；同时采用四个独立驱动电机带动麦克纳姆轮，配合编码器测速，基于麦克纳姆轮运动学解算实现全向运动控制，并通过 PID 算法对各轮速度进行闭环控制。
整个系统设计包括车体机械结构设计和软/硬件系统设计。车体机械结构设计主要包括 PCB 板的布局、车身底盘的改装、图像传感器、麦克纳姆轮以及编码器的安装等。
硬件电路设计部分主要包括：1）电源模块采用 SCT2450STER、RT9013 等芯片完成多级稳压，为系统各功能模块提供稳定、可靠的工作电源；2）视觉模块负责屏幕图像的采集与显示；3）速度传感器采用编码器构成测速部分，完成对速度的实时测量和反馈控制；4）采用 DRV8701E 搭建电机驱动电路，驱动电机稳定、快速地运行。软件系统设计完成了各功能模块的算法及程序设计，包括神经网络模型的训练、量化与部署，图像采集及预处理算法设计，目标识别算法设计、麦克纳姆轮运动学解算以及各驱动电机的 PID 算法设计。所设计的系统经过测试，赛车能够稳定快速地完成比赛任务。

第二章 系统总体方案设计
根据大赛的统一要求，须在组委会统一提供的车模平台上，自主选择传感器类型，设计系统硬件电路，开发软件算法。本系统主要包括三个大部分，分别为车模的机械结构、硬件电路系统、软件算法。每一个部分又由各个小模块构成。所以要构建一个完整的智能车系统，必须先对各个模块进行论证和设计，再将整个系统组合成一个完整系统，进行系统整体的调试。
2.1 系统总体结构
智能车主要由三个部分组成：检测系统，控制决策系统，动力系统。其中检测系统由摄像头、显示屏等视觉模块构成，控制决策系统用 NXP i.MX RT1064 作为主控芯片，动力系统由四个独立驱动的直流电机与麦克纳姆轮构成，通过各轮转速的差速组合实现全向运动控制。整体的流程为：通过视觉传感器检测游戏屏幕上的目标信息，并将图像信息发送给主控处理器。同时，通过编码器构成的反馈渠道将车体各轮的行驶速度信息传送给主控处理器。根据所取得的目标信息和车体当前的速度信息，由主控处理器做出决策，通过麦克纳姆轮运动学解算得到四个车轮的目标转速，并以 PWM 信号控制四个直流电机进行相应动作，从而实现车体的直行、横移与旋转等全向运动控制。
赛车的硬件电路主要由以下几个部分组成：i.MX RT1064 芯片及其外围电路（单片机最小系统），电源管理模块，视觉识别模块（摄像头、显示屏），速度检测电路，电机驱动电路，无线收发模块及调试模块。
（1）i.MX RT1064 芯片及其外围电路是系统的核心部分，负责接收屏幕图像数据、赛车速度等反馈信息，并对这些信息进行恰当的处理，形成合适的控制量对各驱动电机模块进行控制。
（2）电源管理模块给整个系统供电，保障系统安全稳定运行。
（3）图像采样处理模块采用视觉模块采集游戏屏幕图像，是智能车的“视觉系统”。
（4）速度检测电路采用编码器实时测量车速。
（5）电机驱动电路采用 DRV8701E 全桥驱动，可以实现四个驱动电机的正反转与调速。
（6）无线收发模块、按键模块、拨码开关、LED 指示及串口通讯等辅助电路。

2.2 视觉识别系统方案
针对本届人工智能视觉组“小车盯着屏幕玩游戏”的赛制，本车视觉识别系统主要负责对游戏屏幕上显示的动漫角色图形与数字进行实时识别与定位。视觉处理流程为：摄像头采集屏幕图像，经灰度化、缩放等轻量化预处理后，送入轻量化神经网络进行推理，输出各类别置信度与目标位置信息，控制决策系统据此规划运动路径并输出相应控制指令。
为提高推理速度、满足车模高速运行的实时性要求，模型经过 INT8 全整数量化后部署于 i.MX RT1176 处理器上。量化后的模型以 uint8 格式接收输入，摄像头采集的原始图像（0-255）可直接送入模型，无需执行耗时的浮点归一化操作，大幅降低了主控负担。视觉识别算法的具体设计与部署将在第五章详细论述。

第三章  智能车的机械结构设计
根据组委会的相关规定，本届人工智能视觉组采用组委会指定的车模平台。针对不同的车模，必然会有不同的机械调整方式。在比赛备战之初，我们就对车模的结构特点和比赛规则进行了分析，在规则允许范围内对车模进行合理改装，如底盘的固定与麦克纳姆轮的安装，以提高车模的整体精度。
要使智能车能够稳定、高速地运行，正是在于机械结构与软硬件系统地融洽结合。通过不断地实验和测试，我们发现以下三个方面的机械结构对智能车的运行影响很大：麦克纳姆轮的安装，传感器的固定，重心的调整。四个麦克纳姆轮的安装精度与各轮转动的一致性直接决定了全向运动的控制效果。摄像头是采集最原始图像信息的最前端的传感器，良好的固定方案才能使其最大限度地采集到良好的图像信息。而整车的重心越低，才能在控制时更加灵活稳定。
3.1 车模机械模型
本次比赛采用组委会指定的车模，有较好的调零装置，可以自由组装。在严格遵守比赛规则对车模要求的前提下，我们对车模进行了重新组装和改装，将底盘改装为四轮独立驱动的麦克纳姆轮结构，并针对视觉模块的安装位置进行了专门设计。
本车经改装后长30cm 宽20.5cm 高15cm 重量为2170g
3.2 视觉模块的安装
视觉模块的安装主要考虑三个方面：一是图像的失真要小，二是整车重心要低，三是视野要满足比赛需求。由于本届赛制要求小车识别游戏屏幕上的目标，视觉模块需要保证屏幕图像采集的完整性，同时安装必须相当牢固，避免高速运行时的图像抖动。在安装高度与角度的选择上，我们通过大量实验确定了一套既能保证识别区域完整覆盖、又不致整车重心过高的方案。

3.3 编码器的安装
编码器是测速用的核心模块，四个车轮各安装一个，必须将其和对应电机牢牢咬合才能准确测量实际转速，而且必须保证高速和低速情况都能咬合紧。我们选取的编码器性能稳定且返回的速度值稳定，安装时通过自带的安装板与车身固定在一起，使编码器能非常牢固地与电机齿轮咬合。

第四章  智能车的硬件电路设计
4.1 硬件设计方案
从最初进行硬件电路设计时我们就既定了系统的设计目标：可靠、高效、简洁，排版合理合适，在整个系统设计过程中严格按照规范进行。
可靠性是系统设计的第一要求，我们对电路设计的所有环节都进行了电磁兼容性设计，做好各部分的接地、屏蔽、滤波等工作，将数字电路与模拟电路分开，使本系统工作的可靠性达到了设计要求。另外对使用的便捷性进行了合理的排版，还考虑了美观性、对称性。
我们使用了 DRV8701E 作为电机驱动，该驱动的额定工作电流可以轻易达到 20A 以上，保证了电动机的工作转矩和转速。
简洁是指在满足了可靠、高效的要求后，为了尽量减轻整车重量，降低智能车的重心位置，应使电路设计尽量简洁，尽量减少元器件使用数量，缩小电路板面积，使电路部分重量轻，易于安装。我们在对电路进行了详细分析后，对电路进行了简化，合理设计元件排列、电路走线，使本系统硬件电路部分轻量化指标都达到了设计要求。
4.2 硬件电路整体架构

第五章 智能车视觉识别与路径规划算法设计
本届人工智能视觉组比赛要求小车在游戏屏幕区域内识别动漫角色图形与数字并完成相应任务，识别算法直接决定了比赛成绩。本章从算法架构、数据处理、训练策略与模型量化部署四个方面介绍本车视觉识别算法的设计与实现。
5.1 算法架构设计
由于在使用 eIQ 进行模型训练时遇到了很多软件 bug，所以我们直接使用 TensorFlow 编写算法进行模型训练。针对智能车竞赛嵌入式平台算力受限的特点，本方案采用 MobileNetV2 作为骨干网络，并进行了深度裁剪：
（1）宽度缩放：设置 Alpha=0.75，将网络通道数压缩至标准的 3/4，在保留特征提取能力的同时大幅降低计算量。
（2）分辨率适配：输入尺寸设定为 128×128。相较于常用的 224×224，该设置有效减少了内存占用，提升了图像预处理和推理速度，满足车模高速运行时的实时性要求。
（3）结构调整：移除了标准分类任务中的 Dropout 层。由于比赛样本相对封闭且有限，我们采用“全拟合”策略，迫使模型在训练集上达到最高精度，避免正则化带来的欠拟合风险。
5.2 数据处理策略
数据质量直接决定模型上限，本方案在数据处理上采取了两项关键措施：
（1）全量数据训练：代码中 train_generator 与 val_generator 均加载全部数据。鉴于比赛数据集规模较小，划分独立验证集会减少模型见过的样本。使用全量数据训练能最大化利用数据价值，确保模型“见过”所有可能的场景。
（2）场景化数据增强：针对车模运行环境，定制了增强参数。
① brightness_range=[0.8, 1.2]：模拟赛道光照不均及阴影干扰。
② rotation_range=5 & shear_range=0.05：模拟车体姿态变化引起的视角偏差。
③ 类别权重平衡：通过计算 class_weight 解决个别类别样本极少的问题，防止模型对大类过拟合。
5.3 训练策略：两阶段迁移学习
采用“冻结-微调”两阶段训练法，解决小样本下的模型收敛问题：
阶段一（特征迁移）：冻结 MobileNetV2 骨干网络，仅训练顶层分类器。利用 ImageNet 预训练权重快速适应新任务，学习率设为 0.001，快速收敛。
阶段二（精细微调）：解冻骨干网络最后 20 层，学习率降至 0.0001。通过极低学习率微调高层特征，使模型能够识别比赛特定的图形细节（如特定颜色的卡通图标），显著提升识别精度。
5.4 模型量化与部署优化
本方案的核心竞争力在于高效的模型部署流程：
（1）INT8 全整数量化：使用 TFLite Converter 将模型从 Float32 转换为 INT8 格式。
① 体积优势：模型体积压缩约 75%，占用 Flash 空间极小。
② 速度优势：嵌入式 CPU 处理整型运算效率远高于浮点运算，推理帧率显著提升。
（2）输入输出优化：配置量化参数为 uint8 输入/输出。
① 零预处理开销：在单片机端，摄像头采集的原始图像（0-255）可直接送入模型，无需执行耗时的浮点归一化操作（/255.0），大幅降低主控负担。
（3）量化精度校准：通过 representative_dataset 提供 500 张校准图片，确保 INT8 模型精度损失控制在 5% 以内。代码内置了对比验证环节，若掉点严重则自动切换至 Float16 备份方案。
5.5 路径规划算法——经典A星算法
在完成目标识别与定位之后，小车需要规划出一条从当前位置到达目标位置的最优路径。针对场地栅格化地图下的路径搜索问题，我们采用经典 A* 算法进行全局路径规划，并在实际行驶过程中结合局部避障进行实时修正。
A* 算法是 Dijkstra 算法在启发式搜索方面的扩展，其核心思想是利用估价函数对搜索方向进行引导，从而在保证最优性的前提下显著减少搜索的节点数。A* 算法的估价函数表示为：
f(n) = g(n) + h(n)
其中，f(n) 为从起点经过节点 n 到达终点的总代价估计；g(n) 为从起点到节点 n 的实际代价；h(n) 为从节点 n 到终点的启发式估计代价。当 h(n)=0 时，A* 算法退化为 Dijkstra 算法；当 h(n) 始终不大于从节点 n 到终点的真实代价时，A* 算法保证能够找到最优路径。
算法维护两个列表：OPEN 表存放待考察的节点，CLOSED 表存放已经考察过的节点。算法的基本步骤如下：
（1）将起点放入 OPEN 表，并设置其 g 值为 0。
（2）若 OPEN 表为空，则搜索失败；否则取出 OPEN 表中 f 值最小的节点 n 作为当前考察节点。
（3）若节点 n 为目标点，则沿父节点指针回溯即可得到最优路径，算法结束。
（4）将节点 n 移入 CLOSED 表，遍历其相邻节点 m：若 m 在 CLOSED 表中则忽略；若 m 不在 OPEN 表中，则将其加入 OPEN 表并记录父节点与 f 值；若 m 已在 OPEN 表中且经由节点 n 的新路径 g 值更小，则更新其 g 值、f 值与父节点。
（5）转至第（2）步继续循环。
在栅格代价地图中，我们采用曼哈顿距离作为启发式函数，即 h(n) 取当前节点与目标节点在行列方向上的距离之和，保证启发式估计不大于真实代价。由于本车采用可全向运动的麦克纳姆轮底盘，纵向、横向与斜向运动均可直接执行，因此我们以 8 邻域作为节点扩展方向，并将靠近障碍物的栅格赋予较高的代价值，使规划出的路径既平滑又远离障碍。A* 算法的路径规划示意图如图 5.1 所示。

6.3 麦克纳姆轮运动学解算
本车采用四轮独立驱动的麦克纳姆轮底盘，四个车轮均由独立直流电机直接驱动，无转向舵机，通过各轮转速的差速组合即可实现前后直行、左右横移、斜向行驶与原地旋转等全向运动。麦克纳姆轮的外圆周上均匀分布着一圈可自由转动的辊子，辊子轴线与车轮轴线呈 45° 夹角，且左右两侧车轮的辊子朝向相反。由于辊子可沿其轴线方向自由滑动，轮子对地面的驱动力可分解为沿辊子方向的滑动分量与垂直于辊子方向的推进分量，因此每个车轮都能独立地对车体产生两个方向上的推进力，四个车轮的推进力合成后即可驱动车体沿任意方向运动。
为便于分析，建立车体坐标系：以车体几何中心为原点，车头方向为 x 轴正方向，车体左侧为 y 轴正方向，逆时针旋转为角速度正方向。四个车轮编号为 1-前左轮、2-前右轮、3-后左轮、4-后右轮，各轮角速度分别记为 ω1、ω2、ω3、ω4；车体运动速度记为 (vx，vy，ωz)，其中 vx、vy 分别为沿 x、y 方向的线速度，ωz 为绕车体中心的旋转角速度。设车轮半径为 r，车体中心到前、后轮轴线的距离（半轴距）为 a，到左、右车轮中心线的距离（半轮距）为 b。
（1）逆运动学解算：由规划出的期望车体速度反解出四个车轮的目标转速，用于驱动控制，其表达式为：
ω1 = (vx − vy − (a + b)·ωz) / r
ω2 = (vx + vy + (a + b)·ωz) / r
ω3 = (vx − vy + (a + b)·ωz) / r
ω4 = (vx + vy − (a + b)·ωz) / r
（2）正运动学解算：由四个编码器测得的车轮转速反推车体的实际速度，用于里程计推算与速度反馈，其表达式为：
vx = (ω1 + ω2 + ω3 + ω4) · r / 4
vy = (−ω1 + ω2 − ω3 + ω4) · r / 4
ωz = (−ω1 + ω2 + ω3 − ω4) · r / (4(a + b))
式中各轮转速的正负号取决于辊子的安装朝向，实际使用时应根据本车辊子的具体方向确定各式的符号组合。
在控制流程中，上层规划根据识别与定位结果给出期望的车体速度 (vx，vy，ωz)，经逆运动学解算得到四个车轮的目标转速，再由四路独立的速度闭环分别驱动四个电机，从而实现直行、横移、旋转等运动模式的平滑切换。由于四个车轮的转速完全解耦，车体在纵向、横向与旋转三个自由度上的运动可以同时独立执行，这正是麦克纳姆轮底盘实现全向运动的核心优势。麦克纳姆轮运动学解算示意如图 6.2 所示。

6.4 PID 控制算法介绍
在工程实际中，应用最为广泛的调节器控制规律为比例、积分、微分控制，简称 PID 控制，又称 PID 调节。PID 控制器问世至今已有近 70 年历史，它以其结构简单、稳定性好、工作可靠、调整方便而成为工业控制的主要技术之一。当被控对象的结构和参数不能完全掌握，或得不到精确的数学模型时，控制理论的其它技术难以采用时，系统控制器的结构和参数必须依靠经验和现场调试来确定，这时应用 PID 控制技术最为方便。即当我们不完全了解一个系统和被控对象，或不能通过有效的测量手段来获得系统参数时，最适合用 PID 控制技术。PID 控制，实际中也有 PI 和 PD 控制。
PID 控制器是一种线性控制器，它根据给定值与实际输出值构成控制偏差。将偏差的比例（P）、积分（I）和微分（D）通过线性组合构成控制量，对被控对象进行控制，故称 PID 控制器。
6.5 驱动电机的 PID 控制算法
本车四个驱动电机分别采用独立的增量式 PID 速度闭环控制，由逆运动学解算得到的各轮目标转速作为给定值，编码器实测转速作为反馈值。速度控制对于智能车的平稳行驶以及必要时候的减速起到了至关重要的作用，我们在尝试使用传统 PID 方法之后，发现并不能达到理想的速度控制需求，于是在其基础上加入了前馈补偿与死区补偿等修正项，取得了不错的效果。

本章详细介绍了系统软件控制思想和算法，包括视觉识别与图像处理算法、麦克纳姆轮运动学解算以及各驱动电机的 PID 速度控制算法。经试验调试，收获了很好的控制效果。
第七章 智能车调试
调试工具的正确使用以及如何运用都能给整个系统的建立和优化带来好处，它是单片机和用户之间的桥梁。
我们的软件程序编写任务主要在 NXP MCUXpresso / Keil 等平台下进行，该平台是非常有效的集成开发环境（IDE），能够使用户充分有效地开发并管理嵌入式应用工程。在视觉识别调试方面，我们借助串口调试助手与上位机工具，实时观测模型的分类输出、置信度与目标坐标，直观地评估模型在真实场景下的识别效果；在控制调试方面，通过上位机曲线实时整定 PID 参数，使整车响应达到理想状态。
7.1 在线调试
在线调试是整个系统开发过程中最核心的调试手段，它允许我们在程序运行过程中实时观察变量状态、修改参数、监控算法输出，从而快速定位问题并优化系统性能。本系统在调试过程中主要采用了以下在线调试工具与方法：

7.1.1 MCUXpresso/Keil 集成开发环境调试
本系统的主控程序基于 NXP MCUXpresso IDE 与 Keil MDK 平台进行开发。这两个平台均提供了强大的在线调试功能，具体包括：
（1）断点调试：在关键代码处设置断点，程序运行至断点时暂停，可观察当前各变量值、寄存器状态与函数调用栈，用于排查逻辑错误与异常跳转。
（2）单步执行与步过执行：通过单步（Step Into）与步过（Step Over）功能，逐条跟踪指令执行流程，验证算法分支是否正确，特别适用于 PID 参数计算、运动学解算等数值运算模块的精度校验。
（3）变量实时监视：通过 Watch 窗口添加关键变量（如期望速度、实际转速、PID 输出值、图像识别置信度等），在程序全速运行时实时刷新变量值，直观评估控制效果。
（4）数据波形输出：利用 Keil 的逻辑分析仪（Logic Analyzer）或 MCUXpresso 的变量图形化工具，将 PID 的给定值、反馈值与输出值以波形形式呈现，便于判断系统的收敛速度与超调量。

7.1.2 串口调试助手与上位机通信调试
除了 IDE 自带的调试功能外，本系统还大量使用了串口（UART）通信方式进行在线调试，具体方案如下：
（1）调试信息打印：在程序的关键节点（如图像采集完成、模型推理结束、PID 运算完成等）通过串口打印带有时间戳的调试信息，借助 SecureCRT 或 SSCOM 等串口调试助手实时显示，用于跟踪程序的运行状态与执行时序。
（2）上位机参数整定：开发了配套的 Python 上位机工具，通过串口与主控进行双向通信。上位机可实时接收下位机上传的转速曲线、识别结果与车体姿态数据，并以图形化界面动态显示；同时，上位机可向下位机发送 PID 参数（Kp、Ki、Kd）及运动控制指令，实现“在线调参”，无需反复烧录程序，大幅提升了调试效率。
（3）视觉识别结果可视化：摄像头采集到的图像经模型推理后，上位机同步接收推理结果（类别标签、置信度、目标坐标），并叠加显示在原始图像上，便于直观评估模型在真实场景下的识别效果。通过该手段，我们快速发现了光照不均匀导致的误识别问题，并针对性地调整了数据增强策略。

7.2 本章小结
本章主要介绍了本系统主要的调试方法以及使用的调试工具。在视觉识别调试上，通过上位机实时观测推理结果，不断优化模型参数与图像预处理流程；在控制调试上，通过串口与上位机对 PID 参数进行了细致整定。无论怎样，如果没有调试工具，很难让智能车跑得好、跑得快，如果没有良好的辅助调试的方法，就不能更加高效地调试智能车。本小组的水平有限，所用的调试方案仍然不是很好，希望借此抛砖引玉，发现更优的调试方案。
第八章 结论
8.1 智能车整体制作情况及技术参数
该智能车以 NXP i.MX RT1064 作为核心控制单元，通过视觉模块采集游戏屏幕图像，运行基于 MobileNetV2 的 INT8 量化模型识别动漫角色图形与数字，以编码器对各轮速度进行实时采集，自动驱动动力系统完成比赛任务。整个设计主要分为车体机械结构设计和软/硬件系统设计。车体机械结构设计主要包括视觉模块、编码器以及麦克纳姆轮的安装等；硬件系统设计完成了电源管理模块、电机驱动模块、速度测量模块、无线收发模块、辅助调试模块、视觉采集处理模块等；软件系统设计完成了各功能模块的算法及程序设计，包括图像采集与预处理算法、目标识别模型部署、麦克纳姆轮运动学解算以及各驱动电机的 PID 算法设计。所设计的系统经过测试，能够稳定快速地完成识别与循迹任务。
8.2 存在的问题及解决方案
硬件方面：智能车硬件设计的核心集中在电源部分与驱动模块。在电源模块的制作中，我们通过采用 SCT2450STER、RT9013 等多级稳压方案解决了芯片发热与供电不稳的问题；在驱动板的制作过程中，也遇到了单侧电机不转、MOS 管引脚虚焊等问题，通过逐级排查信号链路并改进焊接工艺逐一解决。
软件方面：在硬件条件稳定的情况下，算法的改进最能够提高智能车的能力。视觉识别模型在保证精度的前提下仍需兼顾推理速度，INT8 量化虽然显著提升了帧率，但在复杂光照下个别类别的识别精度仍有波动，我们通过补充数据增强与量化校准图片加以改善；速度与方向控制的策略优劣将直接影响智能车的运行情况，控制算法的好坏并不是完全与算法的复杂度成正相关的，我们对控制策略进行了持续简化和优化。
机械方面：对于智能车稳定性的问题，前期我们对不同轮胎与赛道的摩擦力不同问题较为头疼，通过将车重心移到中点后车速有了极大提升。机械结构与软件是相辅相成的，智能车的速度提到一定值时，算法的优化不能使小车的速度有明显的提高，只能从机械结构入手，考虑将整车的重心放低，使小车更平衡，机械结构的改进对小车速度的提高效果较为明显。
一个良好的系统仍然需要不断完善和更新，为了保证车子能够稳定高速地行驶，智能车系统的设计需要不断地改进。但是限于时间和水平，我们的智能车仍然有很多需要改进的地方。

/* 逆运动学：期望速度→四轮转速 */
void kinematics_inverse(float vx, float vy, float wz, float omega[4])
{
    float factor = (HALF_WHEELBASE + HALF_TRACK) * wz;

    omega[0] = (vx - vy - factor) / WHEEL_RADIUS;
    omega[1] = (vx + vy + factor) / WHEEL_RADIUS;
    omega[2] = (vx - vy + factor) / WHEEL_RADIUS;
    omega[3] = (vx + vy - factor) / WHEEL_RADIUS;

    /* 限幅保护 */
    for (int i = 0; i < 4; i++) {
        if (omega[i] > MAX_SPEED) omega[i] = MAX_SPEED;
        if (omega[i] < -MAX_SPEED) omega[i] = -MAX_SPEED;
    }
}

/* 正运动学：四轮转速→实际速度 */
void kinematics_forward(const float omega[4], float* vx, float* vy, float* wz)
{
    *vx = (omega[0] + omega[1] + omega[2] + omega[3]) * WHEEL_RADIUS / 4.0f;
    *vy = (-omega[0] + omega[1] - omega[2] + omega[3]) * WHEEL_RADIUS / 4.0f;
    *wz = (-omega[0] + omega[1] + omega[2] - omega[3]) * WHEEL_RADIUS
          / (4.0f * (HALF_WHEELBASE + HALF_TRACK));
}

/* 速度平滑处理 */
void kinematics_smooth(float* vx, float* vy, float* wz,
                       float prev_vx, float prev_vy, float prev_wz,
                       float max_accel)
{
    float dt = 0.01f;  /* 10ms控制周期 */
    
    if (*vx - prev_vx > max_accel * dt) *vx = prev_vx + max_accel * dt;
    if (prev_vx - *vx > max_accel * dt) *vx = prev_vx - max_accel * dt;
    if (*vy - prev_vy > max_accel * dt) *vy = prev_vy + max_accel * dt;
    if (prev_vy - *vy > max_accel * dt) *vy = prev_vy - max_accel * dt;
    if (*wz - prev_wz > max_accel * dt) *wz = prev_wz + max_accel * dt;
    if (prev_wz - *wz > max_accel * dt) *wz = prev_wz - max_accel * dt;
}
/* PID结构体 */
typedef struct {
    float Kp, Ki, Kd;
    float integral;
    float last_error;
    float prev_error;
    float output;
    float out_max;
    float out_min;
} PID_t;

/* PID初始化 */
void pid_init(PID_t* pid, float Kp, float Ki, float Kd,
              float out_max, float out_min)
{
    pid->Kp = Kp;
    pid->Ki = Ki;
    pid->Kd = Kd;
    pid->integral = 0.0f;
    pid->last_error = 0.0f;
    pid->prev_error = 0.0f;
    pid->output = 0.0f;
    pid->out_max = out_max;
    pid->out_min = out_min;
}

/* 增量式PID计算 */
float pid_calculate(PID_t* pid, float target, float feedback)
{
    float error = target - feedback;
    float delta_u;

    /* 增量式PID: Δu = Kp*Δe + Ki*e + Kd*(Δe - Δe_prev) */
    delta_u = pid->Kp * (error - pid->last_error)
            + pid->Ki * error
            + pid->Kd * (error - 2.0f * pid->last_error + pid->prev_error);

    pid->output += delta_u;

    /* 输出限幅 */
    if (pid->output > pid->out_max) pid->output = pid->out_max;
    if (pid->output < pid->out_min) pid->output = pid->out_min;

    /* 积分分离：误差过大时停止积分累加 */
    if (fabs(error) > 1.0f) {
        pid->integral = 0.0f;
    }

    /* 更新误差历史 */
    pid->prev_error = pid->last_error;
    pid->last_error = error;

    return pid->output;
}

/* PID参数重置 */
void pid_reset(PID_t* pid)
{
    pid->integral = 0.0f;
    pid->last_error = 0.0f;
    pid->prev_error = 0.0f;
    pid->output = 0.0f;
}
/* 路径跟踪：根据当前位置与路径点计算期望速度 */
typedef struct {
    float vx_des;
    float vy_des;
    float wz_des;
} SpeedCmd_t;

SpeedCmd_t path_follow(int current_x, int current_y, int path[][2],
                       int path_len, int target_idx)
{
    SpeedCmd_t cmd = {0, 0, 0};
    
    if (target_idx >= path_len - 1) {
        cmd.vx_des = 0.0f;
        cmd.vy_des = 0.0f;
        return cmd;
    }

    int next_x = path[target_idx + 1][0];
    int next_y = path[target_idx + 1][1];
    int next2_x = path[target_idx + 2][0];
    int next2_y = path[target_idx + 2][1];

    /* 计算当前到下一个点的方向 */
    float dx = (float)(next_x - current_x);
    float dy = (float)(next_y - current_y);
    float dist = sqrtf(dx*dx + dy*dy);

    if (dist < 0.01f) {
        cmd.vx_des = 0.0f;
        cmd.vy_des = 0.0f;
        return cmd;
    }

    /* 归一化速度方向 */
    cmd.vx_des = (dx / dist) * 0.5f;  /* 速度幅值0.5m/s */
    cmd.vy_des = (dy / dist) * 0.5f;

    /* 路径平滑：预判第二个点，适当减小转弯速度 */
    if (target_idx < path_len - 2) {
        float dx2 = (float)(next2_x - next_x);
        float dy2 = (float)(next2_y - next_y);
        float angle = atan2f(dy, dx) - atan2f(dy2, dx2);
        if (fabs(angle) > 0.5f) {
            cmd.vx_des *= 0.7f;  /* 转弯减速 */
            cmd.vy_des *= 0.7f;
        }
    }

    return cmd;
}
