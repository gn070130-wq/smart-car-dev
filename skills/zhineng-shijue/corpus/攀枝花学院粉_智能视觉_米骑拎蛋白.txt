第一章 引言
1.1 智能汽车制作情况概述
在第二十一届全国大学生智能汽车竞赛中，本车模系统针对“人工智能视觉组”的比赛任务进行了完整的设计与制作。该组采用虚实结合、硬件在环的竞赛模式，要求车模通过车载摄像头识别无线投屏屏幕上的虚拟游戏画面，在物理场地内完成推箱子等游戏任务。系统以追求高可靠性运动控制与精准的“车看屏”视觉导航为核心目标。在硬件层面，底层控制采用主频高达600MHz的NXP i.MX RT1064跨界微控制器（Cortex-M7内核），搭配全桥栅极驱动芯片DRV8701，构建了具备强大算力与高响应速度的底层驱动平台；在视觉感知层面，系统搭载双OpenART Plus摄像头模组，分别负责车载屏幕画面解析与场地实体目标识别，配合逐飞科技5英寸IPS磁吸车载彩屏进行高帧率图像采集；在机械层面，系统选用M型麦克纳姆轮全向底盘，具备全向平移与零半径转向能力。通过双摄协同工作与主控的深度软硬件联调，本车模能够实时、精准地解析屏幕上不断变换的赛道与目标元素，在推箱子路径规划、视觉伺服导航及运动控制等任务中展现出优异的综合性能与鲁棒性。在系统级优化方面，本系统从视觉感知、导航决策到底层运动控制进行了跨层协同设计：视觉端以中心微采样和多帧投票实现极低分辨率下的高帧率识别，决策层面向RT1064片上存储实施静态内存分区与确定性搜索，控制层提出边走边转与提前转向机制，将平移与姿态准备在时间轴上重叠。实测表明，提前转向使含3次转向的连续任务总耗时由18.4s降至14.1s（缩短约23%），驱动峰值电流由4.8A降至2.9A（降低约40%），到达航向偏差由±3.2°收窄至±1.5°，段间停车与原地转向次数均降为零。正式比赛中三个关卡连续计时，每遗漏一个箱子罚时30秒、每少完成一个关卡罚时300秒，因此单段动作的耗时优化与执行可靠性对总成绩具有直接影响。
1.2 竞赛任务与规则简介 
本届人工智能视觉组采用虚实结合、硬件在环的竞赛模式：车模在3.2m×2.4m的物理场地内运动，顶部固定AprilTag方位标识牌供全局摄像头定位；车载无线投屏屏幕同时显示虚拟场景的俯视图与第一视角画面，车模通过自带摄像头拍摄屏幕获取游戏信息（即“车看屏”），控制自身运动以驱动虚拟角色完成推箱子任务。比赛要求将可移动箱子推至对应目的地，场地内设有围墙、炸弹等元素，并设置颜色识别、图案分类、随机摆放等多种难度模式与多关卡闯关。成绩以完成时间加罚时计算，未完成箱每个加罚30秒。规则限定使用NXP i.MX RT系列MCU及OpenART Plus等视觉模块，本系统据此选用M型麦克纳姆轮车模、RT1064主控与双OpenART Plus摄像头。

第二章 机械结构设计与改造
2.1 整体设计思路与技术方案概要
本届智能视觉组的核心任务是“车看屏”与“推箱子”。根据竞赛规则要求，本系统统一选用 M型车模（麦克纳姆轮底盘）。该型车模具备平稳的全向平移与零半径转向能力，完美契合了无物理赛道边界下推箱子任务对高机动性的需求。在整体机械改造上，我们秉持“低重心、高刚性、模块化”的原则。系统以 RT1064为核心控制单元，通过碳纤维支架实现了双OpenART Plus摄像头的高位合理布局，既保证了“看屏幕”与“找箱子”的视觉盲区最小化，又为底层的麦轮运动学精确解算及推箱子决策提供了坚实的物理基础。
2.2 麦克纳姆轮底盘的组装与重心优化
车轮“X型”排布：麦克纳姆轮采用“X型”排布（辊子受力指向车体几何中心），确保底盘全向平移及自转时受力均匀，构成了第六章运动学矩阵解算的物理基石。
底盘共面性保证：严格控制底盘组装刚性及四轮共面性，有效防止了车辆在执行推箱子任务或“提前转向”时发生轮胎打滑及位置漂移。

3.3.1  栅极驱动芯片的选择
本次视觉组电机驱动电路采用分立  沟道  结合专用栅极驱动芯片  搭建  桥，用于驱动四路有刷直流电机。该驱动方案的主要特点如下：
高集成度与极简控制接口： 是一款专为  至  双向有刷直流电机设计的高集成度单路  桥栅极驱动器，可直接驱动 4 个外置 N 通道 ，极大简化了  布局与走线结构。控制器仅需通过 （方向）和 （使能/PWM）两个逻辑引脚，即可轻松完成电机的正反转逻辑控制与 PWM 高频调速。
高性能栅极驱动与参数可调：片内集成了高效电荷泵，能提供  的  栅极驱动电压，确保高侧与低侧外部  均能充分导通以降低导通损耗。芯片允许通过  引脚上的单个外接电阻灵活调节栅极驱动电流，从而精准控制  的开关速度，在优化响应效率的同时降低电磁辐射。此外，内置的固定关断时间  电流斩波电路能对绕组电流进行高效稳幅调节。
超低功耗休眠管理：具备硬件级的低功耗模式，只需将  引脚拉低即可切断内部绝大部分主电路的工作，使整机迅速进入静态电流极低的睡眠状态，非常适合对电池续航有要求的供电系统。
全方位硬件级安全防护：芯片内部集成了多重工业级故障保护机制，包括输入欠压锁定、电荷泵故障检测、过流关断、输出短路保护、前置驱动器故障诊断以及过热关断等，可以在电机堵转、大负载冲击或电源波动等恶劣工况下迅速切断输出，最大程度保障驱动电路与主控系统的安全。

3.3.2  MOSFET的选择
我们选用的MOSFET型号为TPH1R403NL，其主要技术特点如下：
充裕的耐压余量：漏源极耐压值（）为 30V，能够轻松应对 3S 锂电池（标称 11.1V，最高 12.6V）供电以及电机高速运转时产生的高压反电动势尖峰。

小型化高密度封装：具备微型贴片封装优势，在提供高功率密度的同时显著节省板载空间，使电机驱动电路的 PCB 布局更加紧凑。

3.3.3  控制信号缓冲与隔离电路的选择
采用了 SN74HC125PWR 四路三态总线缓冲器，其主要技术特点如下：
信号隔离与驱动增强：对主控芯片输入的电机使能（EN）与方向（PH）信号进行隔离和驱动增强，大幅提高长距离或复杂走线下的传输抗干扰能力。
硬件下拉防误动作：控制输入端均配置了 10kΩ 下拉电阻，有效防止主控系统在复位或未完全初始化等浮空状态下引起电机误动作。

3.3.4  电源稳压与滤波保护电路的选择
在辅助电源与保护设计方面，系统选用了 LR8341A-T33 线性稳压芯片、XT30 高流接口及 220μF 大容量电解电容，其主要技术特点如下：
稳定可靠的逻辑稳压：采用 LR8341A-T33 低压差线性稳压芯片将高压动力电源（VM）稳定转换为 3.3V（DVDD），专为驱动芯片逻辑控制端与 SN74HC125PWR 总线缓冲器供电，确保控制链路不受动力端电压波动干扰。
大电流输入与能量吸收：主电源经 XT30 高流接口接入，并并联 220μF 大容量电解电容，可高效吸收电机正反转切换及快速刹车时产生的反电动势尖峰与电源纹波，保障大功耗运行时的电压稳态。
便捷的休眠控制与状态指示：通过硬件拨动开关直接控制 nSLEEP 引脚电平实现整板一键休眠，并配套电源指示灯（LED1）与工作状态指示灯（LED2），便于直观进行上电与使能调试。

第五章 导航决策与路径规划算法
5.1 任务建模与导航边界
导航规划层负责离散决策：根据当前地图状态，通过搜索算法（如 ）确定机器人应到达的操作位置，以及箱子 / 炸弹的推动方向；运动控制层只负责将已确定的离散动作稳定执行到位。两层之间以 "动作 — 状态" 接口交互，使地图搜索与电机、串口、显示等具体硬件解耦，同一套箱子推动与碰撞判定规则可在 PC 演示端与单片机固件间直接复用。
规划层内部维护地图状态、搜索工作区、观察暂停点与路径，但不关心相机采集、执行等待和界面显示的具体实现。系统采用 "规划 — 执行 — 观测 — 重规划" 的闭环方式：每段路径执行完成后，依据最新视觉观测或执行确认更新真实状态，再进行下一步规划，而非将预测的运动结果直接作为下一帧输入，从而避免单次执行误差沿路径累积。

5.2 地图与状态表示
地图尺寸固定为 16×12。系统采用按行存储的位棋盘表示墙、目标、炸弹和箱子，每行使用一个 16 位掩码，因此碰撞判断、爆炸清墙和实体计数都可以用紧凑的整数操作完成。静态墙层描述当前拓扑，目标层描述仍需填充的目的地，箱子和炸弹层描述动态障碍；箱子到达允许吸收的目标后从动态箱子层消失，目标层同时被清除。
除位棋盘外，求解器还保存玩家的精确栅格位置、箱子和目标的 Entity 数组、炸弹数量及其位置、已炸毁墙体掩码、动态隧道标记和静态死锁标记。Entity 同时携带位置、ID 和激活状态，因而同一个几何格在自由匹配、实体识别和严格 ID 求解中可以有不同的约束语义。搜索状态不能只用“玩家可达区域”代替玩家位置，否则相同箱子布局下不同的导航前缀会被错误合并。
每次爆炸都会改变墙体拓扑，因而爆炸前后的状态必须分开保存。状态键至少要能够区分玩家位置、箱子集合、目标集合、剩余炸弹和已炸墙层；在炸弹状态束中还保留完整位棋盘与实体数组，用于严格重放和去重。
5.3 规划目标与代价函数
导航决策采用分层目标。第一层是物理可执行性：不越界、不撞墙、不把箱子推入阻塞格，不违反炸弹的推动和爆炸规则。第二层是任务语义：在识别求解中箱子只能被对应 ID 的目标吸收，炸弹必须真正到达候选墙体并完成爆破，所有剩余箱子和目标必须在严格重放后清空。只有前两层成立后，才比较移动步数、推箱次数、炸弹数量和路线形状等代价。
局部 A* 使用可解释的整数代价。基础移动步代价为 10，方向改变增加 2 的拐弯惩罚，启发式以目标距离乘以 10 加入  值；单箱单目标时还可以预先计算目标距离场，炸弹攻击时使用面向目标墙的距离场。实体识别路径使用另一套更贴近观察耗时的评分，基本形式为 =2×移动数+7×拐弯数，并在相同评分下优先选择直线连续性更好的路径。

5.4 导航决策总体流程
一次完整求解从地图加载开始。加载器解析 16 行、每行 12 格的地图字符串，建立位棋盘和实体状态，并检查玩家、箱子、目标、炸弹数量及字符合法性。随后计算静态死锁和动态隧道，初始化哈希表、搜索边界以及本次求解的路径工作区；连续求解或重新载入地图时，旧的实体识别记录、转置表和缓存状态都会在新的生命周期边界清空。
求解流程首先按输入条件选择两种模式。直接求解模式适用于地图已经给出箱子、目标及其物理位置的情况：不进行实体识别，不建立编号账本，也不存在 ID 绑定，直接依据箱子与目标的几何关系完成推箱和炸弹分层规划。实体识别求解模式适用于箱子或目标匿名的情况：先生成实体识别路径，在首次合法观察位置暂停并完成实体编号绑定，再进行严格编号匹配求解。两种模式随后都执行局部 A*、全局推箱搜索、炸弹分层规划、严格物理重放和必要的残局恢复。

导航层在每一个决策节点都保留玩家实际所在格，而不是假设小车已经到达计划中的终点。实体识别路径的末端、炸墙后的玩家位置、箱子吸收后的目标层和剩余炸弹都会由 replay 结果写回，正式求解从这个真实交接状态开始。这一规则避免了“规划路径在纸面上闭合，但执行后从错误位置继续”的累积偏差。

5.5 局部导航 A* 算法
局部 A* 模块使用固定容量最小堆和闭表，状态以紧凑的玩家索引、被推动箱子索引、父节点和方向步数编码。碰撞掩码可以按调用场景组合墙、箱子、炸弹等障碍，从而让同一 A* 核心服务于不同的局部任务。纯玩家导航只改变玩家位置；常规推箱同时推进玩家和一个被跟踪箱子；炸弹到墙将炸弹看作可推动实体并把目标墙作为终止条件。
在纯导航模式中，邻接格通过静态障碍掩码判断，启发式使用玩家到目标的曼哈顿距离。检测到由墙体形成的水平或垂直隧道时，A* 将连续同向格压缩成一次带步数的扩展，回溯时再展开为方向序列。这样既减少了堆节点，也使直线运动在代价上保持连续；遇到目标、障碍或边界时会立即停止滑行。
常规推箱模式的节点包含玩家和箱子两个位置。玩家走到箱子相邻侧后，扩展动作才可能成为推箱；目标格是否允许吸收由当前严格模式和 Entity ID 共同决定。箱子进入预处理得到的静态死锁格会被直接剪枝，动态隧道和目标距离场则用于估计后续可达性。多目标局部 A* 返回实际到达的目标索引，供上层继续安排剩余任务。
炸弹攻击模式的碰撞掩码通常同时屏蔽墙、箱子和其他炸弹，并允许最后一步把炸弹推入指定墙体。对于较远的墙体，模块可先从目标墙反向建立距离场；若候选墙不可达、最终站位不存在或固定容量耗尽，调用方会淘汰该候选，而不是把一条不完整路线交给执行层。
5.6 全局推箱搜索与匹配下界
局部 A* 只处理一次箱子或一次导航，多个箱子的先后关系由全局推箱搜索决定。通用求解器以 DFS/递归推进搜索树，每个节点记录当前玩家位置、所有存活箱子、已填充目标、剩余炸弹和已发生的路径前缀。一次扩展先调用局部导航把玩家送到合法推箱站位，再用统一物理规则执行推箱，并将新的玩家和箱子位置写入下一层。
表5.2 导航决策与路径规划的核心模块
搜索使用 Zobrist 哈希分别混合玩家、箱子、炸弹和墙体位置，并以转置表记录已经证明无效或已找到更优前缀的状态。DFS 域和全局 universe 域使用不同的表和比较方向，避免把不同搜索语义下的度量混用。哈希只负责快速筛选，发生碰撞或状态约束不同仍会回到原始搜索和严格验证，不会因为命中近似键而直接返回无解。
下界计算先排除已经在合法目标上的箱子，再对剩余箱子和目标做有限规模的最小匹配。自由匹配时配对代价可使用曼哈顿距离；严格 ID 模式会把不相容的箱—目标对设为无穷大，并可使用目标距离场替代几何距离。该匹配下界不代替真实推箱搜索，只用于判断当前路径前缀不可能优于已知解时的剪枝。

对于满足条件的场景，求解器还会先运行固定宽度的 assignment beam。当前宽度宏为 16，状态按已发生路径长度、剩余匹配下界和稳定顺序保留有限候选；束搜索完成、资源耗尽或场景不符合资格时，自动回退到通用 DFS。束宽是静态资源约束下的确定性上限，不是根据运行时间动态截断搜索的计时器。
静态死锁剪枝只能说明某些格子从拓扑上不适合作为箱子终点，动态剪枝还要考虑剩余目标、其他箱子和炸弹拓扑。候选排序会优先处理可达且不会产生死锁的推步，但不强行固定“最近箱子先完成”。这使搜索能够表达先移动一个箱子为另一个箱子让路的交错关系，同时仍受固定容量和路径长度上限保护。
5.7 炸弹地图的分层规划
含炸弹地图不能把爆破当作普通移动。规划器先生成候选墙体和炸弹到墙的局部路线，再对路线进行严格 ；只有确认炸弹数量减少一枚、目标墙确实被清除、玩家位置和箱子目标层均合法，才把爆破后的局面作为下一层搜索的根。爆炸范围按项目规则处理为以爆破中心为中心的 3×3 区域，爆炸可能同时改变墙体、可达区域和后续箱子路线。
为控制多炸弹组合的状态数量，规划器使用有限宽度的 。每个束状态完整保存位棋盘、玩家、箱子、目标、剩余炸弹、已炸墙掩码、路径前缀和剩余解下界；宽度由剩余箱子和剩余炸弹计算后再限制在最大 16。相同的精确物理状态只保留排序更优的候选，同时优先保留不同爆破拓扑的代表，避免某一种墙体布局占满整层。
每层候选的处理顺序是“候选墙筛选—炸弹 reach A*—严格物理重放—更新爆破拓扑—求剩余尾部”。尾部求解仍使用通用推箱搜索；若束搜索不完整或候选全部失败，则回到完整通用路径。规划器只记录最终路径上的爆破延时事件，例如爆破所在路径索引和爆破中心，等待时长、通信通知和执行状态机由具体执行环境解释。
5.8 未知实体识别与观察覆盖
当地图只有匿名箱子和目标时，系统不能预先假定箱子与目标的对应关系。实体识别阶段的任务是让玩家到达实体的合法观察端口，并在第一次到达该端口时暂停，等待视觉模块或人工测试输入编号。合法观察通常要求玩家位于实体正交相邻且可停留的格子；实体被箱子、炸弹或墙体遮挡时，经过几何附近并不等于完成识别。
无炸弹匿名地图采用观察覆盖路径规划。普通分支使用 观察配额并保留清障回退；当箱子数和目标数相等且目标连通时使用 N/N 配额，实体识别阶段禁止改变箱子和墙体状态，确保观察路线不会影响待识别实体。两种分支都使用固定容量前沿搜索，覆盖不完整、路径重放失败或候选不优时回退到已验证路线。
实体识别路径候选的主要评分为 =2×移动数+7×拐弯数，观察暂停不增加移动代价，也不切断连续直线段。评分相同时比较直线连续性、移动长度和稳定生成顺序。路径接受前还要执行首次观察校验：每一个计入配额的实体必须在第一次到达合法观察端口时立即产生观察暂停，不能先经过实体、随后绕回识别。
实体识别路径用表示观察暂停点。一个车位如果同时邻接多个待识别实体，可以连续产生多个零移动暂停，但每个实体仍要单独进入编号账本；含炸弹地图还要沿既定炸弹主链完成有状态动作。满足观察配额后可在最后一个合法暂停处结束，实体识别阶段结束时，正式求解从严格得到的真实玩家、墙、箱子、目标和剩余炸弹状态交接。
5.9 实体编号绑定与严格求解交接
实体识别接口按当前观察点顺序接收 0～9 的实体编号；输入 -2 表示当前观察信息不足，需要从当前位置扩展识别路径，-1 表示结束实体识别阶段。系统不在外层保存一个“看起来已经完成”的终点，而是在每次提交后恢复到对应观察暂停状态、更新编号账本和识别索引，再决定下一段路径。
控制分流与验收门禁的核心实现片段见附录A。所有观察点完成后，规划器执行箱子和目标编号的自动补全与冲突检查。计数不平衡或编号关系矛盾时返回错误，不能静默退化为任意匹配；确认账本完整后关闭实体识别状态，打开严格目标模式。正式求解因此使用与实体识别阶段结束时相同的物理状态，但箱子只能被相同编号的目标吸收。
严格模式并不要求路径文字逐字复现某条基准路线。允许不同候选使用等价的移动顺序，但每一步都必须满足同一物理规则，最终箱子、目标、炸弹和墙体状态一致，编号账本和爆破事件一致，并通过完整路径重放。直接求解模式不经过本节的编号绑定步骤。
5.10 路径重放、后处理与缓存
统一的只解释调用方已经给定的序列，不调用，也不重新选择炸弹或替代路线。严格模式遇到非法方向、越界、撞墙、推箱目标被阻挡、炸弹无法推进等情况立即报错；遇到推箱、推炸弹、炸墙、目标吸收和暂停则返回相应事件，供上层审计路径含义。

公式3 路径合法性与终态判定
路径后处理可以合并连续导航段、重接合法的导航桥或缩短不改变状态的直线段，但不能跳过推箱、炸墙、炸弹等待标记、观察暂停点或改变最终物理状态。每一次候选重排后都重新并核对消费长度、终态和状态事件；如果后处理资源耗尽，保留已经验证的原路径。
缓存按求解来源隔离为实体识别缓存和直接求解缓存。缓存键包含地图层、起始玩家、箱子/目标/炸弹数量、实体编号、求解模式和策略版本；缓存命中后仍必须严格重放，确认路径没有撞墙、没有错误吸收且最终目标清空。实体识别求解的正式路径不直接写入直接求解缓存，因为编号账本来自本次观察，不能跨会话盲目复用。
5.11 残局恢复决策
主路径执行完毕不等于任务已经完成。恢复模块要求外层提交包含唯一玩家位置的完整残局观测，并重新解析墙、箱子、目标、炸弹和已炸墙状态。只有新观测实测箱子数和目标数同时为零时才返回 COMPLETE；预测路径已经到达目标、但现场仍有残留时，必须继续进入下一轮观测。

5.14 本章小结
本章建立了从地图位棋盘到执行路径的完整决策链：直接求解模式不经过实体识别和编号绑定，直接依据箱子与目标的物理关系规划；实体识别求解模式先完成首次合法观察、实体编号绑定和冲突检查，再进入严格匹配求解。两种模式共同使用 A*、全局推箱搜索、死锁剪枝、匹配下界、炸弹分层规划和严格路径重放，并通过观测驱动的残局恢复守住状态一致性。
本章的核心取舍是先保证可执行性和任务语义正确，再在固定内存与确定性顺序下比较路径代价。位棋盘编码、Zobrist哈希去重、死锁剪枝与固定宽度束搜索共同构成了面向嵌入式资源的系统级性能优化：碰撞检测以16位整数位运算完成，转置表与死锁位图大幅削减重复状态展开，炸弹状态束将多炸弹组合爆炸控制在可预测的宽度上限内。每一条交给执行层的路径都必须能够从当前真实状态重放，并在状态变化、识别失败或残局残留时回到可恢复的决策边界，从而在有限算力下兼顾求解质量与执行时效。




















第六章 导航决策与运动控制算法
6.1 系统任务与本章范围
推箱子小车的运动控制并不是将一串方向指令简单转换为电机正反转，而是一个由任务决策、模式切换、误差反馈、姿态约束和底盘解算共同构成的多层闭环系统。系统需要将上层给出的离散动作序列，转换为可连续执行的纵向速度、横向速度和航向修正量，最终生成四个麦克纳姆轮的独立速度目标。
为保护项目的核心决策细节，本章不展开地图状态搜索、箱子与目标匹配、路径代价评估以及具体路径生成方法。对控制层而言，上层结果被抽象为“已确定的动作段、目标位置与任务事件”。本章仅分析控制层如何安全、平滑且准确地执行这些已知结果。
6.2 整体控制架构
系统采用 "任务状态机 + 多源反馈 + 串级运动控制" 的分层架构，如图6.1所示，从上到下分为五个层次。
（1）执行决策层。读取已给定的动作段，由执行状态机判断当前应采用编码器定距、视觉闭环、定时停车、回库引导或安全终止等执行模式。
（2）动作管理层。将连续同向动作组织为可执行运动段，管理段开始、行驶中、到达、停稳与下一段交接；该层只消费已有动作，不参与路径搜索。
（3）位移与姿态目标层。根据执行模式生成纵向速度、横向速度和目标航向：编码器模式以行驶距离为反馈量，视觉模式以目标像素误差为反馈量，姿态通道则在两种模式下持续工作。
（4）底盘运动学与轮速闭环层。将车体速度向量与旋转修正量分解到四个麦克纳姆轮，再由四路独立的增量式 PID 跟踪各轮速目标。
（5）硬件执行层。对 PID 输出进行方向判断、死区处理与 PWM 限幅，驱动四路电机；同时由编码器和 IMU 采集新的运动状态反馈给控制器，形成多源闭环。
6.3 面向执行的状态机决策
状态机是上层离散动作与底层连续控制之间的接口，其状态转移如图 6.2 所示。它不重新规划路径，核心原则是位移模式互斥 —— 任意时刻仅编码器定距或视觉伺服中的一种接管底盘，避免两路速度同时写入电机目标。
各状态职责如下：
（1）动作派发。取得下一个已知动作段，完成方向与车体坐标对齐后，选择编码器定距或视觉伺服闭环。
（2）编码器执行与到达等待。针对边界明确的短距离运动段生成轮系脉冲目标，在定距完成前不切换动作。
（3）视觉伺服与到达等待。针对需连续纠偏的运动段，循环请求目标误差并更新底盘速度，直至收到与当前段匹配的到达确认。
（4）安全停稳。在段间交接、设备等待或异常恢复时强制速度为零并清除速度整形器历史，防止上一段惯性目标泄漏到下一段。
（5）回库与任务收尾。采用独立的视觉引导与到达确认，完成后经安全等待释放控制状态。
执行状态到达或异常后统一进入安全停稳，再由其判断派发下一段或转入回库；到达信号按运动段编号校验，防止延迟消息被下一状态误消费。该设计将 "往哪里走" 与 "怎么走准" 解耦，使位置控制、姿态控制与通信容错可独立调整

6.4 编码器定距控制
编码器定距模式主要用于动作距离清晰、不需要持续视觉修正的运动段。控制器在每段运动开始时记录四轮脉冲起点，再按前进、后退、左平移或右平移的轮系符号关系生成四路目标脉冲。
定时中断周期性读取四路编码器增量，一方面作为当前轮速反馈，另一方面累加为局部行驶位置。位置环根据剩余脉冲误差计算当前允许的基础速度：距离目标较远时保持较高速度，接近目标时逐步减速。同时设置起步补偿以克服静摩擦死区，并通过速度上限抑制加速过快。
到达判断同时参考剩余误差和实际行驶量，既能在正常情况下精准停车，也能避免个别轮打滑或少量计数不一致导致状态机无限等待。动作完成后，局部脉冲坐标被重新对齐，将累计误差限制在当前动作段内。

（5）异常跳变拒绝。当新的视觉误差与上一次差异明显过大时，暂停当前速度并重置平滑状态，避免单帧误检直接转化为底盘猛动。
6.6 IMU 姿态解算与航向保持
 为底盘提供连续航向基准。系统上电后首先在静止状态下统计陀螺仪零偏，运行时对三轴角速度扣除零偏，再经过死区和低通滤波抑制静止噪声。加速度数据用于观测重力方向，陀螺仪数据用于捕获快速姿态变化。
姿态解算使用四元数表示车体方向，根据预测重力与实测重力之间的误差对陀螺仪进行反馈修正，积分更新四元数并持续归一化，最后提取偏航角。与直接累加 轴角速度相比，该方式对车身轻微倾斜和传感器噪声更稳定。偏航角始终被归一化到连续的角度区间，便于对跨越正负半周边界的航向误差进行正确处理。
航向环以  实时偏航角为反馈，对目标航向和当前航向的最短角度误差进行  修正。比例项提供回正能力，微分项抑制转向过冲；在角度跨越边界时，误差及其变化量均采用最短方向归一化，避免将小角度修正误判为大幅旋转。
航向环增益会随底盘合成速度调整：低速时保持足够的转向力，高速时适当降低修正强度。这样可以避免高速平移时因航向环过强而摆动，同时保证低速对准时仍具有足够的姿态精度。

6.9 边走边转与提前转向控制
传统方式要求小车 "先完全到点，再原地转向"，存在三个问题：一是每次转向都伴随停车与重新起步，累计耗时随动作段数增加；二是原地转向时四轮横向摩擦大，易引起轮胎滑动和位置漂移；三是频繁起停造成电流尖峰。本系统利用麦轮底盘的全向运动能力，引入受限的提前转向机制：在当前平移段尚未结束时，将车头以受控速率朝后续作业需要的方向调整，使 "移动" 与 "转向" 在时间上部分重叠，如图 6.3 所示。该机制不改变上层给定的位置目标，仅调整航向目标的施加时机。
该功能的控制链分为五步：
（1）航向预告。任务执行接口提供后续需要的车头指向，控制层只使用该方向结果，不介入其产生过程。
（2）授权与锁存。仅在当前动作模式、行驶状态和航向差符合要求时，状态机才授权提前转向；进入有效区域后使用锁存状态，避免测量在边界附近抖动而频繁启停。
（3）连续目标航向过渡。目标角度不一次性跳变到新方向，而是根据当前运动速度逐步推进：车速较高时变化更柔和，低速接近终点时更积极地完成对准。
（4）平移与旋转叠加。当前位移速度仍由编码器环或视觉伺服给出，航向 PD 只产生旋转修正量；二者经 6.7 节运动学矩阵合成为四轮目标，因此提前转不改变当前位置目标，只在行驶过程中完成姿态准备。
（5）到达后撤销。当前运动段确认到达、切换至不允许边走边转的定距动作、视觉通信异常或任务终止时，授权立即收回，防止旧目标航向影响下一段运动。
该机制不改变导航路线，而是将原本串行的 "移动" 与 "转向" 在安全条件下部分重叠。实测表明，对同一含 3 次转向的连续任务，提前转向使总耗时由 18.4 s 降至 14.1 s（缩短约 23%），驱动峰值电流由 4.8 A 降至 2.9 A（降低约 40%），到达航向偏差由 ±3.2° 降至 ±1.5°，段间停车与原地转向次数均降为 0，见表 6.1。该机制是系统级优化的典型体现：它并非单一参数调优，而是将麦轮全向运动学、执行状态机授权锁存、航向PD连续过渡、速度斜率限制与输出限幅协同设计，在不改变导航路线和位置目标的前提下挖掘了平移与旋转并行的时间余量，同时降低了电流尖峰和机械磨损。
6.10 控制系统的时序与坐标协同
底层反馈控制在固定周期中断中运行。每个周期依次更新 、读取四路编码器、计算位置环基础速度、处理提前转航向目标，再执行航向环和四路轮速 。固定周期使微分、积分和速度估计拥有稳定的时间基准。
主循环则负责较低频的任务状态转移、串口消息解析与运动段交接。这种“中断保证控制实时性，主循环管理任务语义”的分工，避免路径任务、通信或显示处理阻塞电机闭环。
系统同时维护世界/地图方向、视觉像素方向、车体前后左右方向以及四轮旋转方向。 航向是这些坐标系之间的桥梁：它既用于旋转视觉误差，也用于将离散移动方向解释为当前车身姿态下的前进、后退或横移动作。

6.12 控制流程示例
以一个需要连续运动并在终点调整车头姿态的动作段为例，控制过程如下：
（1）执行状态机接收已知的目标动作，创建新的运动段并清理上一段视觉与到达标志。
（2）系统根据运动段的执行属性选择编码器定距或视觉伺服。
（3）若使用视觉伺服，对新的二维误差进行坐标旋转、跳变检查、主次轴判断、近目标限速和斜率限制，生成平滑的纵横向速度。
（4）若提前转向已被授权，航向目标开始向后续作业方向柔和过渡。
（5）固定周期中断获取编码器和 反馈，航向  生成旋转修正，麦轮解算生成四路轮速目标，四路增量式  更新 。
（6）到达确认有效后，系统停车、撤销提前转授权、重置速度整形状态，再进入下一个已知动作段。
6.13 本章小结
本系统的控制核心可概括为：以状态机保证动作执行的顺序与互斥，以编码器定距和视觉伺服适应不同类型的位移任务，以IMU四元数姿态解算提供稳定航向，以航向PD和四路增量式PID完成姿态与轮速闭环，再通过麦克纳姆轮运动学将位移与旋转统一转换为电机输出。
提前转向机制在不改变已知移动目标的前提下，将平移与姿态准备部分重叠，实测将含3次转向的连续任务总耗时缩短约23%，驱动峰值电流降低约40%，段间停车与原地转向均降为零，显著提高了连续任务的流畅性与能效表现。同时，通过模式互斥、到达信号分段验证、视觉跳变拒绝、通信超时刹车、输出限幅与急停清理，保证了复杂环境下的稳定性与可恢复性。
本章仅公开控制系统的功能结构与通用闭环原理，具体标定参数、模式切换边界、提前转完整触发条件以及上层动作序列的产生方法均不在本章展开。






第七章 系统开发与调试过程
7.1 开发环境与软件协作
主控软件主要在 Keil MDK 环境中完成编写、编译和下载。RT1064 作为整车控制核心，承担视觉通信、路径执行、姿态控制和电机驱动等任务，因此开发过程采用“修改代码—编译检查—下载运行—现场观察—记录问题”的循环方式推进。每次下载前先确认工程配置、编译告警和目标文件均正常，避免将构建错误与实车故障混在一起。
在软件协作方面，VS Code 中的 Codex 主要用于代码阅读、模块关系梳理、边界条件分析、日志解释和重构建议。对于状态机分支、通信协议解析、视觉与编码器控制切换等容易遗漏的逻辑，先让 Codex 根据现有代码提出可能的风险点，再由本人结合硬件连接、时序要求和比赛规则进行核对，最后将确认后的修改放回 Keil 工程编译并下载验证。AI 只作为分析和辅助工具，最终结论以编译结果、仪器信号和实车表现为准。
7.2 Keil 下载与迭代开发流程
系统开发初期先对时钟、GPIO、PWM、ADC、UART、DMA、编码器和 IMU 等基础功能逐项验证，再逐步加入视觉数据接收、地图生成、路径重放和推箱动作。这样可以把问题限制在较小范围内：若电机没有响应，先检查底层输出和驱动状态；若动作方向错误，再检查坐标映射与麦克纳姆轮分配；若路径执行异常，则进一步检查上层动作序列和状态机条件。
每轮功能调整都通过 Keil 重新构建并下载到 RT1064，在固定测试场景中重复运行。测试时保留必要的状态标志、目标坐标、到达确认和异常分支信息，并将串口输出与实际动作逐项对照。对于视觉阈值、编码器定距脉冲、转向误差容差、通信超时和停车等待等参数，不一次性大幅修改，而是记录修改前后的现象，采用小步调整和回归测试，避免局部优化破坏已经稳定的动作。
7.3 嵌入式系统联调与问题定位
联调按照“底层驱动—单模块—功能链路—完整任务”的顺序进行。电机和编码器首先在单方向、单格距离下测试，确认正反转、脉冲计数和停止条件；随后加入 IMU 航向保持和麦克纳姆轮合成运动，检查前后、左右平移与转向叠加时的方向一致性；最后接入视觉伺服，验证位置误差、速度输出和到达确认能够在同一运动段内闭合。
视觉问题主要通过“采集结果—坐标换算—通信帧—控制响应”逐层排查。先确认画面中的网格和实体目标是否被正确识别，再检查像素坐标到地图行列、车体坐标的换算，随后观察 RT1064 是否收到完整且属于当前目标的消息。对于识别抖动、坐标偏移或过期消息，分别从采样区域、阈值、多帧确认、帧头帧尾和状态机接收条件入手处理，而不是直接用运动参数掩盖感知错误。
运动控制调试中较典型的问题是单格距离偏差、连续编码器动作后的航向漂移、视觉到达后停车时序不稳定，以及转向方向与当前车头姿态不一致。定位这些问题时，将编码器计数、目标航向、当前航向、视觉误差和状态机状态放在同一时间线上比较，并结合逻辑分析仪观察 UART、PWM 和到达信号的先后关系。确认原因后，再分别调整方向映射、脉冲参数、控制周期、超时和状态切换条件，并通过同一地图重复验证。
当完整任务出现中途停顿、重复动作或推箱结果与预期不符时，先保留现场日志和地图，复现最短失败路径，再将故障拆分为识别、规划、通信和执行四类。通过这种方式可以判断是路径本身错误、动作序列传输不完整、视觉确认延迟，还是车辆已经偏离了规划位置，从而避免在多个模块上同时修改造成新的不确定性。
7.4 路径规划上位机与主控验证
路径规划部分由队友使用 Python 开发推箱子游戏上位机和调试界面，主要在 PyCharm 中完成。上位机能够显示关卡地图、箱子与目标位置以及规划出的推箱路径，用于在车辆实际执行前检查搜索结果、推箱顺序和关键转移。对于复杂关卡，先在上位机中完成路径规划和回放，再将动作序列交给 RT1064 执行，可以显著降低直接在实车上试错的成本。
上位机与主控联调时重点核对地图行列、世界方向、车体方向和动作编码之间的对应关系。将 Python 界面中的每一步动作与 RT1064 的状态机、视觉目标和编码器动作逐项对照；若仿真路径正确而实车走偏，则优先检查坐标系转换、当前航向下的方向分流、视觉定位时机和动作完成确认。这样既能验证队友的规划结果，也能反向暴露底层执行过程中的时序问题。
在上位机界面和主控代码的协作过程中，同样使用 VS Code 中的 Codex 辅助分析 Python 路径数据、通信字段和 C 端解析逻辑，帮助快速定位字段含义不一致、路径长度异常和状态编号错位等问题。修改后仍需经过上位机回放、Keil 编译下载和实车复测三个环节，确保仿真结果与物理执行保持一致。
7.5 阶段性测试与结果复盘
完成单模块验证后，测试进一步分为视觉识别、单段移动、连续推箱、回库和异常恢复等阶段。每一阶段固定测试地图和起始姿态，记录识别是否稳定、停车是否准确、动作是否重复、箱子是否进入目标以及失败后能否回到可恢复状态。对同一问题至少进行一次修改后的回归测试，确认改动没有影响其他阶段。
调试过程表明，系统性能并不只取决于某一个算法或参数，而取决于视觉、路径规划、通信、状态机和运动控制之间的时序配合。通过 Keil 的持续下载验证、Python 上位机的路径回放、VS Code/Codex 的代码分析以及现场仪器观测，逐步建立了从仿真到实车、从现象到原因、从修改到验收的闭环开发流程。
7.6 本章小结
本章总结了系统从软件编写到实车验收的开发与调试方法。Keil MDK 负责 RT1064 工程的编译和下载，VS Code 中的 Codex 辅助代码分析、重构和问题定位，队友开发的 Python 推箱子上位机用于路径规划验证与执行对照。通过分层测试、日志记录、信号抓取和重复回归，系统逐步解决了视觉定位、坐标换算、通信时序、编码器定距、航向保持和路径执行中的问题，为最终完成完整推箱任务提供了可靠的软件调试基础。

8.1 全文总结
本报告围绕第二十一届全国大学生智能汽车竞赛人工智能视觉组的比赛任务，完整阐述了一辆基于M型麦克纳姆轮底盘的智能车模系统的设计与实现过程。系统以NXP i.MX RT1064跨界微控制器为主控，搭载双OpenART Plus摄像头模组，通过"车看屏"模式识别车载无线投屏屏幕上的虚拟推箱子游戏画面，在物理场地内自主完成路径规划与运动控制。本系统的硬件电路原理图与PCB设计文件均采用嘉立创EDA绘制，并将开源至立创开源硬件平台，供同类竞赛队伍参考。
在机械结构方面，系统采用麦克纳姆轮X型排布底盘，通过碳纤维支架与3D打印件实现双摄像头高位布局与IMU中心化安装，有效降低了重心并减小了运动干扰。在硬件电路方面，设计了基于RT1064的主控电路、DRV8701全桥电机驱动电路及电源管理模块。在视觉识别方面，系统实现了屏幕画面采集、透视畸变校正、12×16栅格地图动态构建，以及基于颜色识别与AI分类的实体目标检测与编号绑定；通过中心微采样（每栅格仅取4×4像素）、优先级互斥判定与三帧多数投票，在极低分辨率下实现了高帧率、高鲁棒性的多元素分类与定位，以极低算力开销保障了感知实时性。
在导航决策方面，系统构建了从A*局部导航、DFS全局搜索到Zobrist哈希去重、死锁剪枝、炸弹分层规划的完整推箱子求解框架，并设计了严格路径重放与残局恢复机制以保证执行可靠性；同时针对RT1064的片上存储结构实施了DTCM/OCRAM/SDRAM静态内存分区优化，全程零动态堆内存分配，搜索队列、闭表与路径缓冲区均采用编译期定长数组，消除了内存分配延迟与堆碎片风险，保证了决策与控制的确定性实时执行。在运动控制方面，系统采用“任务状态机+多源反馈+串级运动控制”的分层架构，实现了编码器定距、视觉伺服、IMU四元数姿态解算、麦克纳姆轮运动学解算与四路增量式PID轮速闭环；提出的边走边转与提前转向机制将平移与转向在时间轴上部分重叠，实测将含3次转向的连续任务总耗时由18.4s降至14.1s（缩短23%），驱动峰值电流由4.8A降至2.9A（降低40%），到达航向偏差由±3.2°收窄至±1.5°。

8.3 存在问题与展望
在系统开发过程中，仍存在以下不足：硬件电路的EMC/信号完整性仿真与散热设计仍有优化空间；部分标定参数（如PID增益、视觉容差、速度整形斜率等）依赖实车调试经验，缺乏系统化的参数整定方法；实体识别阶段在极端光照条件下仍可能出现误检，需要进一步增强视觉算法的鲁棒性。
未来可从以下方向改进：一是引入更高效的目标检测模型（如轻量化神经网络）以提升复杂图案分类的准确率与帧率；二是优化推箱子搜索算法的启发式函数与剪枝策略，进一步缩短高阶关卡的求解时间；三是增加无线调试与数据回传功能，便于现场快速诊断与参数调整；四是完善硬件电路的保护设计与PCB集成度，提高系统的电气可靠性；五是建立系统化的性能基准测试框架，对求解耗时、识别帧率、控制周期抖动等关键指标进行自动化测量与回归对比，为进一步优化提供量化依据。
