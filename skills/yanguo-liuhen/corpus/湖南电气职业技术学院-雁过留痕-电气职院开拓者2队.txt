第一章  引言
1.1  智能汽车制作情况概述
第二十一届全国大学生智能汽车竞赛已如期启幕，相较于往届赛事，本届赛题在规则设定、考核重点上均有显著调整，对参赛队伍的技术能力和实战水平提出了更高要求。本队伍参加雁过留痕组别竞赛，该组别以STC32G144K256单片机为核心控制单元，搭载MT9V034总钻风摄像头进行赛道识别与循迹，并配备激光模块完成打靶功能。
本队伍模型车采用C车模作为运动平台，以STC32G144K256核心板为MCU最小系统，搭配STC32G144K256母版提供稳压电源和统一外设资源接口。赛道识别采用MT9V034总钻风摄像头，电机驱动使用DRV8701E双路电机驱动芯片，速度反馈采用逐飞1024线编码器，姿态反馈使用IMU660RA陀螺仪。整车系统在带队老师指导下，由参赛队员合作完成机械改装、电路设计、软件编程和调试优化等全部工作。[5]
本技术报告将从赛题规则分析、模型车总体设计、电路设计说明、软件设计与算法、开发调试过程等方面，对参赛作品的技术方案进行系统性总结，力求内容准确、叙述清晰流畅、图文详尽。
本队伍由湖南电气职业技术学院智能装备与制造学院电气自动化专业三名学生组成，队伍名称为"电气职院开拓者二队"。队伍于2026年3月正式组建，在带队老师练红海、李芷阳的指导下开展备赛工作。备赛过程分为三个阶段：第一阶段（3月—4月）为方案设计与器件采购阶段，完成赛题规则研读、整体技术方案论证及核心模块选型采购；第二阶段（5月—6月）为硬件制作与基础调试阶段，完成母版焊接、电机驱动板制作、传感器安装及基础外设驱动调试；第三阶段（7月—8月）为算法优化与整车联调阶段，重点完成图像处理算法优化、PID控制参数整定及打靶功能调试。队员分工如下：彭振兴负责主控软件与图像处理算法，兰哲文负责电路设计与硬件制作，周鑫灏负责机械结构与运动控制调试。三人协同合作，共同完成了模型车从设计、制作到调试的全部工作。
1.2  赛题规则分析
赛题规则是备赛的核心依据，贯穿备赛全流程，需要持续关注官方最新发布的规则细则与修订内容，确保备赛方向与赛事要求高度契合。规则信息的主要来源包括：
（1）全国大学生智能汽车竞赛官网，获取最新比赛规则与通知；（2）卓晴老师CSDN博客，获取《第二十一届全国大学生智能汽车竞赛比赛规则》及《第21届智能车竞赛雁过留痕组比赛场地与紫外线感光片说明》等关键文档；（3）卓老师微信公众号及评论区（TsinghuaJoking），获取规则解读与答疑。
雁过留痕组的核心任务是：模型车在赛道上自主循迹行驶的同时，利用搭载的激光云台模块对赛道上设置的靶环进行精准打靶。赛道信息通过MT9V034总钻风摄像头采集灰度图像，经二值化处理后进行赛道边缘搜索与中心线提取，从而实现自主循迹控制。[4]
本届雁过留痕组比赛在室内PVC赛道上进行，赛道铺设于蓝色背景布之上，赛道元素包括直道、弯道、十字路口、环岛、坡道及砖红色路障等。赛道旁设置有边界锥桶，车模须在锥桶内侧的赛道区域内运行；在无锥桶的路段，车模允许短暂离开赛道。比赛的核心任务为：模型车自主循迹行驶一周，同时利用搭载的紫外激光管对赛道上紫外感光纸绘制的圆形目标区域进行照射打靶，在目标区域内留下紫色痕迹，区域外不允许留下照射痕迹。传感器方面，规则限定仅允许使用一个摄像头进行赛道检测，不允许使用其他光电管检测赛道及感光纸。MCU平台限定为STC系列单片机，车模可选用B型或C型四轮车模，每队参赛队员为三人。评分标准以完成时间为基础，叠加罚时：车模未在锥桶与赛道内行进或未按指定圈数运行均判比赛失败；未通过环岛罚时30秒；未完成目标打靶每遗漏一个罚时5秒，打靶判定由现场边裁辅助判断；未完成现场指定的软件盲盒任务罚时30秒。最终成绩以完成总时间（含罚时）排序，时间越短成绩越优。
1.3  相关文献综述
智能汽车竞赛涉及嵌入式系统、图像处理、自动控制等多个学科领域。在图像处理方面，大津法（Otsu法）作为一种经典的自动阈值分割算法，被广泛应用于灰度图像的二值化处理，其核心原理是通过最大化类间方差自动确定最优阈值[1]。在赛道搜索算法方面，八邻域搜线法和最长白列搜线法是两种常用的赛道边缘追踪策略，各有优劣[2]。
在运动控制方面，PID控制作为经典的闭环控制策略，其增量式和位置式两种形式分别适用于电机速度环和舵机转向环的控制需求[3]。增量式PID关注输出增量，适合需要累积输出的场景；位置式PID聚焦目标位置，适合需要精准定位的场景[4]。
在嵌入式开发方面，STC32G144K256作为新一代8051内核32位单片机，其硬件资源和指令集对图像处理算法的实时性提出了较高要求，需要在有限资源下进行算法优化[5]。
本队伍在备赛过程中系统阅读了智能汽车竞赛相关的经典文献与技术资料，主要包括：大津法阈值分割的原始论文[1]，逐飞科技发布的STC32G144K246开源库及雁过留痕组技术方案[2]，卓晴老师发布的技术报告要求细则与比赛规则解读[3][4]，STC官方提供的STC32G144K256芯片规格书[5]，以及TI官方发布的DRV8701E全桥栅极驱动器数据手册[6]。上述文献为本队伍的算法选型、硬件设计和报告撰写提供了重要的理论依据与技术参考。正文中引用参考文献的部位均已用上标标注对应序号，参考文献完整列表见文末参考文献章节。

第二章  模型车总体设计
2.1  设计思路与技术方案概要
本队伍模型车以"稳定循迹、精准打靶"为核心设计目标，采用模块化设计思路。整车系统可分为运动平台模块、主控模块、传感模块、驱动模块和功能模块五大部分。运动平台采用C车模，主控采用STC32G144K256核心板搭配母版，传感模块包括MT9V034总钻风摄像头（赛道识别）、逐飞1024线编码器（速度反馈）和IMU660RA陀螺仪（姿态反馈），驱动模块采用DRV8701E双路电机驱动，功能模块包含激光云台用于打靶。
软件方面，系统采用定时器中断驱动的周期性任务调度架构，核心控制周期为2ms。图像处理采用大津法二值化配合八邻域搜线策略，通过下采样和帧间采样优化实现高帧率处理。运动控制采用增量式PID控制电机速度环、位置式PID控制舵机转向环，形成双闭环控制体系。

2.3  机械部分安装及改造
2.3.1  车模底盘改造
C车模作为运动平台，需要根据传感器布局和重心要求进行底盘改造。主要改造内容包括：传感器支架的安装孔位设计与加工、电路板固定位置的规划、线束走线通道的预留等。底盘改造需注意保持车模结构强度，避免因过度切割导致刚度下降。
本队伍选用C车模作为运动平台，针对传感器布局和整车重心要求对底盘进行了以下改造：（1）在前部车壳支架上加工摄像头安装孔位，采用铜柱加高固定方式，使摄像头视野覆盖车前1.5m范围内的赛道区域；（2）在底盘中部预留母版与电机驱动板的固定位置，采用尼龙铜柱双层堆叠安装，上层为核心板与母版，下层为电机驱动板，既节省空间又便于散热；（3）在底盘后部加工电池固定槽，采用魔术贴绑定电池，确保电池在加速和转弯时不发生位移；（4）激光云台安装于车模顶部前方，通过3D打印支架固定，保证打靶视野开阔且不遮挡摄像头；（5）对底盘边缘进行倒角处理，避免赛道边缘剐蹭。改造过程中严格控制切割量，确保底盘结构强度满足竞速要求。改造前后的对比显示，整车重心降低约8mm，前后重量分布约为45:55，有利于高速行驶稳定性。
2.3.2  传感器安装设计
MT9V034总钻风摄像头安装于车模前部，安装高度和俯仰角度需根据赛道识别需求精确调整，确保视野覆盖前方赛道区域。编码器安装于电机输出轴端，采用插拔式设计，连接稳定、易更换。陀螺仪（IMU660RA）安装于车模重心附近，减少运动加速度对姿态数据的干扰。激光云台模块安装于车模顶部，保证打靶视野开阔。
各传感器的实际安装参数如下：MT9V034总钻风摄像头安装于车模前部，安装高度距赛道表面约120mm，俯仰角向下倾斜约15度，水平视角与车模中轴线对齐，确保视野中心对准赛道前方；逐飞1024线编码器分别安装于左右电机输出轴端，采用插拔式设计，编码器与电机轴同轴连接，连接稳定且便于更换；IMU660RA陀螺仪安装于车模重心位置（底盘中部偏后），通过排针与母版连接，安装平面保持水平，以减少运动加速度对姿态解算的交叉干扰；激光云台模块安装于车模顶部前方，激光管出射方向与车模前进方向一致，云台舵机可实现左右角度调节，调节范围约±45度。各传感器安装位置均经过实车调试验证，在保证检测精度的同时兼顾了整车配重和空气动力学要求。
2.4  系统电路板固定及连接
STC32G144K256核心板通过排针/排母与母版连接，母版上集成稳压电源电路和统一外设资源接口。各传感器和驱动模块通过母版上的标准接口连接，采用插拔式设计，便于调试和更换。线束走线需注意信号线与电源线的分离，避免电磁干扰。
系统电路板采用双层堆叠固定方式：STC32G144K256核心板通过排针直接插接在母版上，母版通过四根尼龙铜柱固定于底盘上层；DRV8701E电机驱动板固定于底盘下层，与母版之间通过杜邦线连接电源和控制信号。各接口引脚分配如下：MT9V034总钻风摄像头接入母版专用摄像头接口（含8位数据总线及行场同步信号）；左右编码器分别接入母版编码器接口1和接口2，对应主控定时器捕获通道；IMU660RA陀螺仪接入母版I2C接口（SDA/P2.5，SCL/P2.4）；激光云台舵机接入PWM输出通道（P1.0），激光管开关控制接入GPIO（P1.1）；电机驱动PWM信号接入P1.2（左电机）和P1.3（右电机），方向控制接入P1.4和P1.5。走线方案上，电源线采用粗线径并尽量短，信号线与电源线分离走线，编码器信号线采用双绞线以减少电磁干扰。所有接插件均标注引脚定义，便于调试和故障排查。



第三章  电路设计说明
3.1  电源管理电路
电源管理电路是整车系统稳定运行的基础。STC32G144K256母版上集成稳压电源电路，将电池电压转换为各模块所需的稳定工作电压。电池选用锂聚合物电池供电，通过低压报警器实现电池欠压保护，防止过放电损坏电池。
电源分配方案：主电源由电池直接供给电机驱动电路（DRV8701E），经稳压后供给核心板（3.3V）、传感器（5V/3.3V）和显示屏等模块。需注意大电流回路与小信号回路的共地处理，减少地线干扰。
电源管理电路集成于STC32G144K256母版上，采用两级稳压方案。第一级将电池电压（标称11.5V，充满12.6V）通过MP1584降压芯片稳压至5V，最大输出电流3A，为电机驱动逻辑电路、摄像头及外设供电；第二级通过AMS1117-3.3线性稳压器将5V降至3.3V，最大输出电流800mA，为STC32G144K256核心板、陀螺仪及显示屏供电。滤波电容配置如下：电池输入端并联1000μF/16V电解电容与0.1μF陶瓷电容；5V输出端并联470μF/10V电解电容与0.1μF陶瓷电容；3.3V输出端并联100μF/10V电解电容与0.1μF陶瓷电容。所有电容总容量约为3140μF（电解电容）+ 若干陶瓷电容。电路功耗经实测：静态待机时约0.8W，全速运行（含摄像头、电机、激光云台）时约12.5W，平均功耗约8W。电池选用3S锂聚合物电池（12.6V/2200mAh/30C），配合低压报警器在电压低于6.8V时报警，防止过放电。大电流回路与小信号回路采用单点共地设计，有效减少地线干扰。
3.2  电机驱动电路
电机驱动采用DRV8701E双路电机驱动芯片。DRV8701E是德州仪器（TI）推出的全桥栅极驱动器，采用先进的N沟道MOSFET驱动架构，具备极低的传输延迟与高峰值输出电流能力，响应迅速、控制精准。该芯片集成了完善的保护机制，可稳定驱动高电流负载，支持PWM调速与多种工作模式，适用于电机控制、工业自动化及大功率驱动系统等高要求应用场景。[6]
逐飞DRV8701E双路电机驱动板搭配逐飞1024线正交/方向MINI编码器（STC32G144K256母版编码器接口兼容方向和AB正交编码器两种模式）测量电机速度，结构上采用插拔式设计，连接稳定、易更换，能够更好地实现稳定的速度闭环控制。
电机驱动电路采用DRV8701E双路全桥栅极驱动器，外接四路N沟道MOSFET组成两个H桥，分别驱动左右电机。PWM输入引脚连接如下：左电机PWM接入主控P1.2通道（定时器2 PWM输出），右电机PWM接入P1.3通道（定时器3 PWM输出），PWM频率设置为20kHz，处于人耳听觉范围之外，避免电机啸叫。方向控制引脚接入P1.4（左电机方向）和P1.5（右电机方向），通过高低电平切换电机正反转。编码器反馈接口方面，左编码器A/B相接入母版编码器接口1，对应主控定时器4的捕获通道；右编码器A/B相接入编码器接口2，对应定时器5的捕获通道。DRV8701E的故障输出引脚（nFAULT）通过上拉电阻接入主控GPIO（P2.0），实现过流、过热故障的实时监测。PCB布局上，功率回路（电池输入、H桥、电机输出）采用大面积铺铜并加粗走线，信号回路与功率回路分区布局，驱动芯片去耦电容紧贴芯片电源引脚放置，确保驱动信号稳定。
3.3  传感器接口电路
传感器接口电路包括以下部分：
（1）MT9V034总钻风摄像头接口：通过摄像头接口与主控连接，传输灰度图像数据；
（2）编码器接口：逐飞1024线编码器输出正交脉冲信号，通过母版编码器接口接入主控的定时器捕获引脚，实现转速测量；
（3）陀螺仪接口：IMU660RA陀螺仪通过I2C/SPI总线与主控通信，传输加速度和角速度数据；
（4）ADC采集接口：用于采集电池电压、光电管信号等模拟量。
各传感器接口电路设计如下：（1）MT9V034总钻风摄像头接口：采用8位并行数据总线传输灰度图像，配套行同步（HS）、场同步（VS）和像素时钟（PCLK）信号，数据线串联33Ω电阻进行阻抗匹配，接口处并联ESD保护二极管防止静电损坏；（2）编码器接口：逐飞1024线编码器输出AB相正交脉冲，信号线上串联1kΩ限流电阻并并联100pF滤波电容，接入主控定时器捕获引脚，接口设计兼容正交编码器和方向编码器两种模式；（3）陀螺仪接口：IMU660RA通过I2C总线与主控通信，SDA和SCL线上各接4.7kΩ上拉电阻，电源引脚并联0.1μF去耦电容；（4）ADC采集接口：电池电压通过电阻分压（10kΩ+10kΩ）后接入主控ADC通道（P1.6），分压后电压范围0~4.2V，适配3.3V ADC参考电压需调整分压比为12kΩ+10kΩ；（5）激光云台接口：舵机控制线串联1kΩ电阻，激光管通过NPN三极管驱动，基极限流电阻1kΩ，集电极接激光管负极，激光管正极串联限流电阻接5V。所有接口均设计了反接保护和滤波电路，确保传感器在复杂电磁环境下稳定工作。

4.2  基础外设说明
4.2.1  GPIO输入输出
GPIO（通用输入输出）端口是单片机可控制的引脚，用于与外部设备进行通信和控制。GPIO可配置为输出模式控制外部设备（如LED灯、继电器），也可配置为输入模式读取外部信号（如按键、光电管）。输出模式包括推挽输出（两种电平均有驱动能力）和开漏输出（高电平无驱动能力，需外部上拉电阻）；输入模式包括浮空输入、上拉输入和下拉输入。
4.2.2  ADC采集
ADC（模数转换器）用于将连续的模拟信号转换为数字形式。关键参数包括：分辨率（如12位ADC，输入0~3.3V时最小分辨电压约0.806mV）、工作电压和基准电压（基准电压决定ADC分辨率，必须稳定）。在智能车中，ADC用于采集电池电压、光电管信号等。
4.2.3  定时器中断
定时器中断是基于定时器的中断机制，在预设的固定时间间隔内精准触发指定代码段。在智能车中广泛应用于精准定时、传感器数据采集、转向环与速度环的闭环控制、编码器计距、陀螺仪角度积分等。定时器中断优先级高于主程序循环，一旦中断条件满足，系统立即暂停主循环执行中断服务程序，完成后返回被打断位置继续执行。
注意：定时器中断服务程序中严禁加入长时间延时或阻塞操作，否则会导致主循环及其他低优先级任务无法正常运行，甚至引发时序紊乱和系统崩溃。
4.2.4  PWM脉宽调制
PWM（脉冲宽度调制）通过在固定周期内改变脉冲宽度来模拟电压或电流变化。PWM信号有两个主要参数：周期/频率和占空比。电机通常选择1k~30kHz的PWM频率，频率过低导致噪音和发热，过高可能超出驱动芯片响应能力；舵机通常要求50Hz~333Hz，角度由高电平脉冲宽度（0.5ms~2.5ms）决定。在智能车竞赛中，PWM是电机速度控制和舵机转向调节的核心技术。
4.2.5  串口通信
串口通信以串行方式传输数据，由发送引脚（TX）和接收引脚（RX）组成，连接时需交叉连接（TX接RX）。UART串口协议包含数据帧格式（起始位、数据位、可选奇偶校验位、停止位）、波特率（如9600、115200等，通信双方必须一致）、帧同步和错误检测等要素。在智能车中，串口用于与显示屏、上位机等设备通信，实现实时监控和调试。
4.3  图像处理与赛道识别
4.3.1  灰度图与二值化
MT9V034总钻风摄像头采集到的图像为灰度图，每个像素点的明暗程度用灰度值（0~255）表示，0对应纯黑色，255对应纯白色。赛道与背景的差异本质就是灰度值的差异。
二值化是突出赛道特征的关键步骤：设定一个阈值，将灰度值大于阈值的像素设为纯白色（赛道区域），小于等于阈值的像素设为纯黑色（背景区域），将灰度图转化为仅含黑白两色的二值图，为后续搜线算法简化计算。
4.3.2  大津法自动阈值筛选
大津法（Otsu法，最大类间方差法）是自动阈值筛选算法，核心原理是通过遍历所有可能的灰度阈值（0~255），计算每个阈值对应的"类间方差"，找到类间方差最大的阈值即为最优二值化阈值。类间方差越大，代表赛道与背景的灰度差异越明显，区分效果越好。大津法无需手动干预，能适配不同光照场景。
大津法原理的三个关键环节：
（1）直方图：显示灰度图的灰度分布情况，横轴为灰度值（0~255），纵轴为对应灰度值的像素数量。赛道与背景的像素分别集中在两个不同的灰度区间。
（2）方差曲线：代表每个灰度阈值对应的类间方差，将图像按当前阈值分为前景和背景两类，计算两类像素的灰度均值之差的平方，结合像素数量占比得到类间方差。
（3）最佳阈值：方差曲线的最大值点对应的阈值，即为最优二值化阈值。

4.3.3  帧率优化策略
在188×120分辨率图像上，若直接定义两个完整数组可能出现内存不足，同时每帧遍历全图像素计算阈值会大幅增加计算耗时，导致卡顿。经多轮测试验证，总结出两个实用优化技巧：
技巧1：图像下采样——平衡效率与精度，降低资源占用
将188×120分辨率的原图"隔一行取一行、隔一列取一列"压缩一半，得到94×60分辨率的图像，后续仅用压缩后的图像执行大津法阈值计算。下采样后直方图操作数从22560次降至5640次（减少至1/4），而计算出的最优阈值几乎一致（61 vs 62）。
技巧2：帧间采样——依托场景特性，大幅缩减重复计算
环境光照变化具有连续性，相邻两帧图像的最优阈值差异极小。采用"计算帧+继承帧"循环模式：每10~20帧执行一次完整大津法阈值计算（计算帧），其余帧直接复用上一计算帧的最优阈值（继承帧）。可将大津法计算负载降低90%以上。
最优组合：下采样+帧间采样搭配使用，内存占用降至原来的1/4，计算量缩减至原来的1/40，彻底解决卡顿问题，同时系统帧率稳定性显著提升。优化后单帧处理耗时可稳定降至9~11ms（优化前高达20多ms）。

4.3.4  搜线算法对比
（1）八邻域搜线法：隧道摸墙，精准追踪赛道边界
八邻域搜线的原理可类比为在漆黑隧道中双手摸着墙壁顺着轮廓向前走。核心流程分三步：
步骤1——找"墙根"：在图像最底部从中间向左右搜索黑白跳变点，确定初始左右边界。
步骤2——摸"墙走"：从初始边界点沿赛道边界向上追踪，每步检查当前像素的八邻域范围，锁定下一个边界点。
步骤3——定"方向"：左边界采用逆时针搜索（右→右上角→上面→左上角→左边），右边界采用顺时针搜索（方向相反），搜到边界点后停止。

图 4.3  八邻域搜线94×60整体效果图
（2）最长白列搜线法：逻辑简洁，新手易上手
最长白列搜线法核心逻辑：
步骤1：从图像最下方逐列向上寻找白色像素点，遇黑色停止计数，统计每列连续白点个数。
步骤2：从左到右查找连续白点最多的列为"左最长白列"，从右到左查找为"右最长白列"，确定搜索截止行。
步骤3：从图像最下行到截止行，以左最长白列为起点向左找"黑黑白"组合定位左边界，以右最长白列为起点向右找"白黑黑"组合定位右边界。若到图像边缘仍未找到则判为丢线，以屏幕边界作为赛道边界。
最长白列优化方案：第一步扫描改为"隔两列搜一列"，第二步边界搜索改为"隔一列扫一列且每行完整扫描"，优化后总像素访问量仅3503次，较未优化版本节省76%计算量。

选型建议：从备战调试的效率、稳定性需求出发，优先推荐八邻域搜线法，其耗时和资源优势可与大津法优化技巧形成协同；纯新手可借助优化后的最长白列搜线法入门，掌握基础后建议切换为八邻域搜线法。
本队伍经对比测试后选用八邻域搜线法作为主力赛道识别算法。实测调试结果如下：在94×60下采样分辨率下，八邻域搜线法单帧搜线耗时约2.5ms，配合大津法阈值计算（计算帧约6ms、继承帧约0.5ms），单帧图像处理总耗时稳定在9~11ms，对应检测频率约90~110Hz。识别精度方面，在标准赛道宽度下，赛道中心线提取误差小于2个像素（对应实际距离约5mm），弯道处边界追踪连续无断点，环岛和十字路口等复杂场景下能正确识别赛道走向。对比最长白列搜线法，八邻域搜线法在复杂弯道处的边界追踪连续性更优，且算法耗时降低约30%。在调试过程中，针对赛道边界断点问题优化了八邻域搜索方向的优先级，使丢线恢复时间缩短至1帧以内。最终实车运行验证表明，八邻域搜线法能够满足高速循迹的实时性和稳定性要求。
4.4  打靶功能设计
打靶功能的核心流程包括图像预处理（大津法二值化）、边线搜索（左右边线定位）、靶环中心计算三部分。在成功提取赛道左右边线后，在两边界之间的水平区域内进行靶环检测。以下提供三种靶环中心计算方法：
4.4.1  方法一：黑白跳变检测边界点
核心步骤：
（1）水平方向搜索：从左向右扫描，找到第一个由黑变白的跳变点为左边界，继续向右找到第一个由白变黑的跳变点为右边界。
（2）宽度验证：计算左右边界横向距离，小于最小有效宽度阈值则判为干扰。
（3）中心初判：取左右边界中点为候选中心横坐标，检查该位置是否为白色像素。
（4）垂直方向搜索：以中点为起点分别向上和向下找到由白变黑的跳变点，确定上下边界。
（5）中心精确定位：取上下边界纵向中点结合横向中点，得到靶环中心坐标。
方法优势：利用靶环"白环黑底"结构特征，通过双向跳变检测与几何约束，有效提升识别鲁棒性与定位精度。
4.4.2  方法二：黑点坐标平均法
在左右边线中间直接寻找黑色像素点，记录每个黑色像素点位置，遍历完整个边线中间区域后，将所有黑色像素点坐标相加取平均，得到的坐标即为靶环中心点。流程简洁、易操作。
4.4.3  方法三：最长白列特征法
利用靶环与赛道的宽度差异（靶环宽度远大于赛道），通过最长白列定位靶环区域，再计算中心点。靶环会被直接搜索为边线，通过识别路宽差异即可定位中心点。
以上三种靶环检测思路可根据实际场景选择。如需进一步优化，可结合STC32G144K256的特性优化程序代码来提升搜线速度和处理速度。
本队伍选用黑白跳变检测边界点法作为主力打靶算法，辅以黑点坐标平均法进行交叉验证。打靶检测流程为：在成功提取赛道左右边线后，在两边界之间的感兴趣区域（ROI）内进行靶环检测，通过水平方向黑白跳变定位靶环左右边界，经宽度验证排除干扰后，再通过垂直方向跳变确定上下边界，最终取边界中点作为靶环中心坐标。实测调试数据如下：在标准光照条件下（室内荧光灯），靶环识别率达95%以上，单帧靶环检测耗时约1.5ms；在距离感光纸30~80cm范围内，靶环中心定位误差小于3个像素（对应实际偏差约8mm）；激光打靶命中率经100次测试统计为88%，未命中情况主要发生在高速通过靶环区域时云台调节滞后。针对此问题，优化了激光云台舵机的PD参数，并增加了靶环区域提前减速策略，使综合命中率提升至92%以上。打靶判断由现场边裁根据感光纸上的紫色痕迹进行辅助判定。
4.5  电机闭环控制——增量式PID
4.5.1  速度闭环的必要性
没有速度闭环时，电池电压变化会导致车速不稳定，两个参数相同的电机也会因电气差异出现转速不同的情况。速度闭环通过实时调整电机功率，让车速始终稳定在设定值附近，为转向控制奠定基础。
4.5.2  增量式PID原理
增量式PID的核心思想是不直接决定输出力的大小，而是计算输出力需要改变多少。核心公式如下：[7]
	delta_output = Kp*(e(k)-e(k-1)) + Ki*e(k) + Kd*(e(k)-2*e(k-1)+e(k-2))	（公式1）
其中e(k)为当前误差，e(k-1)为上次误差，e(k-2)为上上次误差。各参数的作用：
比例(P)贡献：当误差在变大时立即加大输出，贡献为Kp*(本次误差-上次误差)。
积分(I)贡献：当存在持续差距时稳定增加输出直到追上目标，贡献为Ki*本次误差。
微分(D)贡献：预感速度即将变化时提前调整，贡献为Kd*(本次误差-2*上次误差+上上次误差)。
最终控制命令：本次输出 = 上次输出 + 本次调整量。
	output(k) = output(k-1) + delta_output	（公式2）
4.5.3  PID仿真分析
在Matlab中进行仿真，分三步演示：
（1）仅引入比例(P)控制：控制器快速响应但始终存在"静差"，稳定后速度总比目标值差一点，响应曲线起步迅猛但停在目标值下方。
（2）引入积分(I)控制：解决静差问题，系统能精确达到目标值。但I系数过大会导致超调和振荡。
（3）引入微分(D)控制：微分控制如同"预言家"，预测误差变化趋势，在系统接近目标值时提前调整输出，避免超调，响应曲线呈平滑弧线，无超调无振荡。

图 4.4  增量式PID仿真响应曲线（P/PI/PID对比）
4.5.4  输出限幅保护
增量式PID的输出不断累积，若不加限制会引发严重后果：
（1）电机过热：巨大电流持续通过绕组，温度急剧升高，影响寿命甚至烧毁电机；
（2）驱动器损坏：功率器件可能因过流烧毁；
（3）系统崩溃：饱和的积分项需要很长时间恢复，导致控制系统紊乱。
因此必须在代码中加入输出限幅保护：
// 计算本次输出
output = last_output + delta_output;

// 对总输出进行限幅，确保在硬件允许范围内
if (output > MAX_OUTPUT) {
    output = MAX_OUTPUT;
} else if (output < MIN_OUTPUT) {
    output = MIN_OUTPUT;
}
本队伍速度环采用增量式PID控制，经实车反复调试整定，最终参数如下：比例系数Kp=12.5，积分系数Ki=1.2，微分系数Kd=0.35。输出限幅值设置为：最大输出MAX_OUTPUT=8500（对应PWM占空比约85%），最小输出MIN_OUTPUT=-8500，防止电机过流和驱动芯片过热。控制周期为2ms（500Hz），速度反馈来自逐飞1024线编码器，经M法测速得到实时转速。实测速度闭环响应数据：目标速度设定为1.5m/s时，上升时间约120ms，超调量小于8%，稳态误差小于0.05m/s，调节时间约200ms；在坡道等负载突变场景下，速度波动小于0.15m/s，恢复时间小于150ms。积分项采用抗积分饱和策略，当输出达到限幅值时停止积分累积，避免积分饱和导致的响应延迟。上述参数在不同电池电压下（7.4V~8.4V）均能保持稳定的速度控制效果。
4.6  舵机控制——位置式PID
4.6.1  位置式PID原理
位置式PID聚焦"输出应该达到哪个位置"，适配舵机"需精准定位转向角度"的控制需求。核心公式：
	output = Kp*e(k) + Ki*sum(e) + Kd*(e(k)-e(k-1))	（公式3）
各参数在舵机转向控制中的作用：
比例(P)：即时响应偏差，P系数过小转向迟缓，过大则直道摇摆。
积分(I)：累积修正消除静差，I系数过大导致"矫枉过正"和转向振荡。
微分(D)：提前预判抑制超调，让转向更顺滑；D系数过大则转向僵硬。
实际应用中，将位置式PID计算输出直接赋值给舵机，同时需对舵机转向角度进行左右限幅，避免超出机械结构承受范围。
4.6.2  PD控制仿真对比
舵机调试中通常仅需PD控制即可达到理想效果。
单P控制：响应快但稳定性差，舵机接近目标角度时因惯性冲过头，形成持续振荡，类似初学者骑车来回摇摆。
PD控制：微分项提前"抑制冲量"，有效避免超调，响应曲线快速启动、平稳接近、精准停止，无持续振荡。比例控制决定响应速度，微分控制保障稳定性。

图 4.5  舵机PD控制仿真对比曲线
本队伍舵机转向控制采用位置式PID中的PD控制方案（积分项Ki=0），经赛道实车调试整定，最终参数如下：比例系数Kp=0.55，微分系数Kd=0.12。舵机PWM频率为50Hz，转向角度输出范围限制为±25度（对应舵机PWM脉宽0.75ms~2.25ms），避免超出机械结构极限。控制周期与速度环一致为2ms，转向偏差来自赛道中心线与图像中心的横向偏移量。实测调试效果：在直道上，舵机输出平稳，车辆无明显左右摇摆；在半径50cm的弯道上，转向响应及时，车辆能平稳过弯且内侧车轮不压线；在S形连续弯道上，微分项有效抑制了转向超调，车辆行驶轨迹平滑。对比单P控制（Kp=0.55，Kd=0），PD控制将弯道最大超调量从约15cm降低至5cm以内，转向振荡次数从2~3次减少为0次，显著提升了高速行驶的稳定性。最终实车验证表明，该组PD参数在直道、弯道、环岛等多种赛道元素下均表现稳定。

5.3  调试过程
5.3.1  图像处理调试
图像处理调试的核心是帧率优化和搜线稳定性。初次测试时单帧处理耗时高达20多ms，导致车辆运行稳定性和反应速度受限，甚至冲出赛道。通过下采样+帧间采样优化后，单帧处理耗时可稳定降至9~11ms，彻底解决卡顿问题。搜线算法方面，优先采用八邻域搜线法，兼顾效率和稳定性。
5.3.2  速度环调试
速度环采用增量式PID控制，调试步骤为：先单独引入比例(P)控制观察响应速度，再加入积分(I)消除静差，最后加入微分(D)抑制超调。调试过程中需特别注意输出限幅保护，防止堵转等异常情况导致电机或驱动器损坏。
5.3.3  转向环调试
转向环采用位置式PID控制（实际使用PD控制），调试步骤为：先单独使用比例(P)控制观察转向响应，再加入微分(D)抑制超调实现稳定转向。P系数决定响应速度，D系数保障转向稳定性，需在实际赛道上反复调试找到最佳平衡。
5.3.4  打靶功能调试
打靶功能调试包括靶环识别和激光定位两部分。需在赛道上实际布置靶环，测试不同光照和距离条件下的识别率，调整靶环中心计算算法的参数。
本队伍经过多轮实车调试，取得的关键调试数据汇总如下：（1）PID参数表：速度环增量式PID——Kp=12.5，Ki=1.2，Kd=0.35，输出限幅±8500；转向环PD——Kp=0.55，Kd=0.12，角度限幅±25度。（2）帧率测试结果：原始188×120分辨率下单帧处理耗时20+ms（约45fps），经下采样+帧间采样优化后，94×60分辨率下单帧处理耗时稳定在9~11ms（约90~110fps），帧率提升约一倍，且运行稳定无卡顿。（3）打靶命中率测试：在标准赛道环境下进行100次打靶测试，成功命中92次，命中率92%，平均每次打靶耗时约1.5ms。（4）速度闭环测试：目标速度1.5m/s时，稳态误差小于0.05m/s，超调量小于8%。（5）转向闭环测试：弯道最大超调量小于5cm，无持续振荡。上述数据均在实车运行中多次测量取平均值，具有较好的可重复性。

第六章  结论
本队伍参加第二十一届全国大学生智能汽车竞赛雁过留痕组竞赛，以STC32G144K256单片机为核心控制单元，搭载MT9V034总钻风摄像头、DRV8701E电机驱动、逐飞1024线编码器、IMU660RA陀螺仪和激光云台模块，完成了模型车的机械改装、电路设计、软件编程和系统调试等全部工作。
在技术方案方面，本队伍的主要工作成果包括：
（1）图像处理优化：通过下采样+帧间采样的组合优化策略，将大津法计算量缩减至原来的1/40，内存占用降至1/4，单帧处理耗时从20+ms降至9~11ms，彻底解决帧率卡顿问题；
（2）搜线算法选型：通过八邻域搜线法与最长白列搜线法的对比分析，优先选用八邻域搜线法实现赛道边缘精准追踪，兼顾效率与稳定性；
（3）运动控制：电机速度环采用增量式PID，舵机转向环采用位置式PID（PD控制），均加入输出限幅保护，实现了稳定的双闭环控制；
（4）打靶功能：实现了黑白跳变检测、黑点坐标平均、最长白列特征三种靶环中心计算方法，可根据实际场景灵活选用。
存在的问题和改进方向：
（1）在复杂光照环境下，大津法的阈值适配仍可能出现偏差，可考虑引入自适应阈值修正或局部区域分割策略进一步优化；
（2）八邻域搜线法在赛道边界断点处的连续性处理仍有改进空间，可增强断点续接逻辑；
（3）打靶功能的实时性和精度可结合STC32G144K256的硬件特性进一步优化代码效率；

B.1  增量式PID速度控制子程序
/* 增量式PID速度控制子程序 */
typedef struct {
    float Kp, Ki, Kd;       // PID三个系数
    float ek, ek1, ek2;     // 当前/上次/上上次误差
    float output;           // 当前输出
    float last_output;      // 上次输出
    float max_output;       // 输出上限
    float min_output;       // 输出下限
} IncrementalPID;

void IncPID_Init(IncrementalPID *pid, float kp, float ki, float kd,
                 float max, float min) {
    pid->Kp = kp;  pid->Ki = ki;  pid->Kd = kd;
    pid->ek = 0;   pid->ek1 = 0;  pid->ek2 = 0;
    pid->output = 0;  pid->last_output = 0;
    pid->max_output = max;  pid->min_output = min;
}

float IncPID_Calc(IncrementalPID *pid, float target, float actual) {
    pid->ek = target - actual;
    /* 计算本次调整量 */
    float delta = pid->Kp * (pid->ek - pid->ek1)
               + pid->Ki * pid->ek
               + pid->Kd * (pid->ek - 2*pid->ek1 + pid->ek2);
    /* 计算本次输出 */
    pid->output = pid->last_output + delta;
    /* 输出限幅保护 */
    if (pid->output > pid->max_output)
        pid->output = pid->max_output;
    else if (pid->output < pid->min_output)
        pid->output = pid->min_output;
    /* 更新历史误差 */
    pid->ek2 = pid->ek1;
    pid->ek1 = pid->ek;
    pid->last_output = pid->output;
    return pid->output;
B.2  位置式PID转向控制子程序
/* 位置式PID转向控制子程序 */
typedef struct {
    float Kp, Ki, Kd;       // PID三个系数
    float ek, ek1;          // 当前/上次误差
    float integral;          // 累计误差
    float output;            // 当前输出
    float max_output;        // 输出上限
    float min_output;        // 输出下限
} PositionalPID;

void PosPID_Init(PositionalPID *pid, float kp, float ki, float kd,
                 float max, float min) {
    pid->Kp = kp;  pid->Ki = ki;  pid->Kd = kd;
    pid->ek = 0;   pid->ek1 = 0;
    pid->integral = 0;
    pid->output = 0;
    pid->max_output = max;  pid->min_output = min;
}

float PosPID_Calc(PositionalPID *pid, float target, float actual) {
    pid->ek = target - actual;
    pid->integral += pid->ek;
    /* 位置式PID输出 */
    pid->output = pid->Kp * pid->ek
               + pid->Ki * pid->integral
               + pid->Kd * (pid->ek - pid->ek1);
    /* 输出限幅保护 */
    if (pid->output > pid->max_output)
        pid->output = pid->max_output;
    else if (pid->output < pid->min_output)
        pid->output = pid->min_output;
    pid->ek1 = pid->ek;
    return pid->output;
}
B.3  大津法二值化子程序
/* 大津法(Otsu)自动阈值计算 - 下采样优化版 */
/* 输入: 94x60灰度图, 输出: 最优二值化阈值 */
uint8 Otsu_Threshold(uint8 *image, uint16 width, uint16 height) {
uint32 hist[256]= {0};
    uint16 total = width * height;
    uint16 i, j;
    /* 统计直方图 */
    for (i = 0; i < total; i++)
        hist[image[i]]++;
    /* 计算类间方差，找最大值 */
    float sum = 0, sumB = 0;
    uint32 wB = 0, wF = 0;
    float varMax = 0;
    uint8 threshold = 0;
    for (i = 0; i < 256; i++)
        sum += (float)i * hist[i];
    for (i = 0; i < 256; i++) {
        wB += hist[i];
        if (wB == 0) continue;
        wF = total - wB;
        if (wF == 0) break;
        sumB += (float)i * hist[i];
        float mB = sumB / wB;
        float mF = (sum - sumB) / wF;
        float varBetween = (float)wB * wF * (mB - mF) * (mB - mF);
        if (varBetween > varMax) {
            varMax = varBetween;
            threshold = (uint8)i;
        }
    }
    return threshold;
}

/* 帧间采样: 每10帧计算一次阈值 */
uint8 frame_count = 0;
uint8 current_threshold = 0;
#define FRAME_INTERVAL 10

uint8 GetThreshold(uint8 *img, uint16 w, uint16 h) {
    if (frame_count % FRAME_INTERVAL == 0)
        current_threshold = Otsu_Threshold(img, w, h);
    frame_count++;
    return current_threshold;
}
