摘要
本文介绍了临沂大学的队员们在准备此次比赛中的成果。 本次比赛采用C车模，硬件平台采用STC32G144K246，软件平台使用Keil5。
文中介绍了本次我们的智能车控制系统软硬件结构和开发流程，整个智能车涉及车模机械调整，传感器选择，控制算法优化等许多方面。整辆车的工作原理是先将小车的控制周期中提取出相应的时间片，相应的时间片作为一次控制周期， 用来控制速度和转向，由总钻风摄像头采集赛道信息至主板， 由STC32G144K246读取信号进行分析处理，运用我们自己的软件程序对赛道信息进行提取并以此为根据控制舵机和电机。
在进行大量的实践之后，表明我们的系统设计方案完全是可行的。

第一章 系统整体设计
1.1系统概述
雁过留痕组智能车系统的总体工作模式为：总钻风摄像头采集赛道信息，输入到STC32G144K246，经过软件对比度后的得到巡线；通过编码器来检测车速，通过imu660ra陀螺仪采集车身姿态，转向舵机和驱动电机采用PID控制，通过PWM控制驱动电路调整电机的功率；而车速的目标值由默认值和基于图像处理的优化策略进行综合控制。
该系统总共包括 7个子系统： 主控制器模块、 赛道采集模块、伺服器（舵机）控制模块、 电机控制模块、调试模块、姿态传感器模块、激光打靶模块。
1、 主控制器模块
使用 STC32G144K246 作为智能车底层实时控制主控，该芯片采用国产增强型 32 位 8051 内核，兼容 32 位 / 8 位 8051 指令集，最高主频 120 MHz（极限可达 140 MHz），内置独立 TFPU 浮点三角函数运算单元，片上搭载 246 KB Flash 程序存储器与 144 KB SRAM，无需外接内存颗粒，可裸机运行或搭载 FreeRTOS 实时操作系统，集成大量模拟外设与电机控制接口，响应速度快、实时性强，非常适合智能车电机驱动、传感器信号采集、底层运动控制与中小型视觉算法处理。
芯片集成丰富硬件资源：配备 2 组独立 12 位 ADC、2 组 12 位 DAC、4 组运算放大器与比较器；多路高速 PWM、8 路 USART、SPI、I2C、CAN-FD、USB2.0、DMA 控制器，支持 DVP 摄像头接口，原生适配智能车摄像头数据采集；具备 AEC-Q100 Grade1 车规等级，工作温度区间 - 40℃~+125℃，抗干扰性能优异。
2、赛道采集模块
使用逐飞科技提供的总钻风摄像头作为光电传感器进行赛道图像采集， 通过使用场中断触发主控制器开始图像采集、 像素中断控制采集速度。
3、姿态传感器模块
姿态传感器模块主要为速度传感器，使用逐飞科技提供的带方向编码器读取实时速度， 用于对于电机进行闭环控制。
4、伺服器（舵机）控制模块
使用S-U400舵机进行车模转向控制。此款舵机工作电压为7.5V，空载电流约为0.2A ，控制频率是300HZ。
5、电机控制模块
使用380电机进行车模的速度控制。该电机额定电压7.4V
6、调试模块
调试模块由IPS屏幕、 组合按键、tape-C串口组成。
7、激光打靶模块
使用七个405nm大功率紫外激光头完成激光打靶任务，每路由主控GPIO经三极管驱动，主板设七路激光接口，软件控制点亮时序和组合模式。
机械系统设计与实现
智能车车模的机械结构设计是智能车制作过程中极具关键性的一环，它极大程度地影响着小车的行驶平稳性和精度。合理且合适的机械结构设计加上软件的算法控制能够使小车的运行状态得到最大的优化和提高。因此在实际设计中，学习和了解机械结构设计的基本知识同时，也要通过不断测试已做的机械设计的实际结果来不断调整优化机械结构来实现高效完美的小车机械结构。本章内容也将对车模类型、车模机械部分安装及改造、传感器的设计安装、系统电路板的固定及连接等进行介绍。

2.1 车模类型介绍
车模选择的指定C车模，采用3D打印的方式，打印出车的激光支架等小零件进行组装，车轮胎皮采用橡胶胎皮。
2.2 机械结构设计方案
车模选择的指定C车模，采用差速车原理，进行图像采集处理循迹。增加激光支架使得车模在运行过程中可以更加准确迅速发射激光击中靶纸。为了增加车模高速运行的稳定性，增加了无刷电机产生向下负压增强抓地。
2.3 摄像头安装
对于前瞻的我们选用更细的8毫米碳素杆进行搭建，在安装传感器时就考虑到碳素杆如何又方便又稳固的搭建，最终我们将碳素杆固定至车中间进行固定，再从车底板支出一根碳素杆进行稳定前瞻，结合螺丝、结构件、胶枪进行牢固，这样我们就能够很好的控制摄像头的高度与角度。
2.4 舵机安装
   采用经典的舵机安装立式方法，立式安装的舵机在响应速度方面远胜于卧式舵机，这对于车模在弯道处的转弯性能有着很大的提升。其次，对于比赛选手而言，立式舵机的伺服中值很好确定，也利于车模发生故障后快速的恢复和调节。车模转向时最大程度符合阿克曼转角是车模轮胎前束的最优解。
2.5 编码器安装
编码器是用来对车速进行测算的仪器，目前很多学校使用的是通过光电编码的编码器，其精度较高、安装较为方便，但体积有点大。光电编码器的安装精度较高， 要求编码器轴与赛车后轴同轴， 且编码盘必须与赛车的中心线共线。 我们是直接装在车上，利用齿轮与差速器上的大齿轮相咬合。这种安装方法方便快捷，更能较准确的测出电机的转速。
2.6 负压的实现
负压风扇的加入，大大提高了C车模的上限，采用EMAX银燕 RSIII 2307竞速无刷电机，利用吊扇来产生负压力。
第三章 硬件系统设计及实现
智能车电路部分主要的模块包括主驱一体板、电调。在硬件设计中，我们需要考虑到系统的稳定性、可靠性、高效性、简洁性和美观性等，以此实现硬件电路的最优化。其中，稳定性和可靠性是电路设计的最优先原则。简洁性和美观性主要考虑到元器件的使用数量、电路板面积、PCB板布局和电路走线等。
3.1.硬件电路整体架构
本智能车硬件系统包含基于STC32G144K246核心板、电源管理模块、摄像头、电机模块、调试交互模块等，其中STC32G144K246核心板通过排针排母直插在主驱一体板上。
3.2.电源电路设计

3.6.	硬件部分的总结
对于硬件部分，能够满足调车的需求是最基本的。对于我们注重的是稳定性和实用性。在我们的一年的锻炼和学习中，从一开始使用最稳定、常用的电源方案，分模块根据经典应用设计制作电路到逐渐有自己的想法。在创新的基础上，都要保证稳定性，足够稳定既包含电路板本身的性能稳定、也包含电路板的安装稳定。我们发现如果电路板在行驶的过程中固定不牢有松动，复位这种情况就很容易发生。复位很大一部分原因是电路板的元器件比如大的电容松动。硬件部分作为整个车的基础，通过原理图绘制 PCB，制板后上车验证，根据实际情况，调整方案，最后定型。

第四章 软件系统设计及实现
4.1 软件控制程序的整体思路 
软件编写的目的，是控制车模在既定规则前提下，以最快的速度，最多的超车次数，跑完整个赛道。不论上哪种方案，软件的总体框架总是相似的，我们追求的就是稳定至上，兼顾速度。软件上大类分为图像采集、图像处理识别黑线、会车控制，速度控制以及速度反馈。 
4.2 主程序流程
采用初始化+主循环+中断架构。上电初始化时钟、GPIO、定时器、中断、外设和变量，就绪后进入主循环。主循环按时间片执行图像处理、姿态解算、速度计算、转向与速度控制、按键处理、IPS显示、激光逻辑和状态监测。中断处理摄像头帧同步、PWM更新、编码器脉冲、控制周期时基和串口通信。
4.3 摄像头图像处理算法
4.3.1 中心扫线
中心扫线是指每行图像的起始扫线都是从上一行图像的中线位置开始的，从白点向左向右扫到黑点及寻找到所需要的边界线，进而拟合出赛道中心线。
优点：对于环境光线依赖比较小，如由于光线不均匀造成的反光仅仅会影响反光存在的几行，而不会对整幅图像之后的边界线提取造成干扰；
缺点：比较消耗时序，需要遍历图像中大多数像素点才能够找到赛道的边界线，同时由于环岛等特殊元素的存在，使我们寻找的边界线与环岛的特征点有一定的差距，不利于元素的识别。

4.3.2 根据不同的赛道元素类型，指定每行的扫线起始点
“根据不同的赛道元素类型，指定每行的扫线起始点”是指在每行扫线的过程中，同时对元素类型进行区分，根据先前确定下来的赛道元素类型明确扫线的方向及起始点。
如在正常扫线可以将下一行的扫线起点指定为本行的左右边线，在十字的判断中可以将扫线的起点通过十字前拐点下的直线斜率确定，方便寻找十字远处的跳变点，而环岛扫线可以通过环岛阶段确定需要扫到的特征点进而确定扫线方向与扫线起始。
由此看来，这种方式的扫线可以最大限度的简化程序执行流程，同时我们可以在扫线的应用“搜索”中“剪枝”的思想。
如在扫线的过程中判断是否已经扫到了赛道外，如果已经扫出赛道即停止扫线，体现了“可行性剪枝思想”；在对十字和环岛的判断中，可以根据之前图像找到的特征点具体位置寻找这场图像的特征点，体现了“记忆化搜索思想”。
4.4 电机PID控制算法
PID控制器以其原理简单、适应性强、工作可靠、调整方便等优点而在实际工程中得到广泛的应用。其主要由比例单元（P）、积分单元（I）和微分单元（D）组成。当我们不完全了解一个系统和被控对象，或不能通过有效的测量手段来获得系统参数时，最适合用PID控制技术，实际中也有PI和PD控制。
PID 控制器是一种线性控制器，它根据给定值与实际输出值构成控制偏差，将偏差的比例(P)、积分(I)和微分(D)通过线性组合构成控制量，对被控对象进行控制。采用PID实现电机速度闭环：


比例环节：及时成比例地反映控制系统的偏差信号,偏差一旦产生,控制器立即产生控制作用,以减少偏差.
积分环节：主要用于消除静差,提高系统的无差度.积分作用的强弱取决于积分时间常数,越大,积分作用越弱,反之则越强.
微分环节：能反映偏差信号的变化趋势(变化速率),并能在该偏差信号变得太大之前,在系统中引入一个有效的早期修正信号,从而加快系统的动作速度,减小调节时间.

4.5 控制思路
4.5.1 舵机整体控制思路
在各种参数的对比之后，我们确定使用300Hz的PWM波能够使舵机响应最快的同时使舵机工作稳定。
在每个控制周期中，每当图像处理完成，我们根据不同的赛道类型和速度传感器返回的实际转速综合分析得出最佳的舵机打角行，计算这一行的中线偏离差值，带入到舵机位置式PD的计算中，在舵机中值的基础上经过舵机上下限的限幅计算得到实际的舵机值。如图4.10所示：

4.5.2 舵机PD计算式
舵机控制采用位置是PID，经过尝试我们认为I项（积分项）不适用与舵机的控制中，便将PID简化为舵机的PD控制，控制公式如下：
AngleChange = servoP * error + servoD * dError;

4.5.3 动态打角行的选取
由于车模不是处于匀速的运动中，不能够通过固定的打角行来计算偏差。我们采用根据编码器的速度返回值计算出来当前打角行的高度，其策略是速度越快打角行越高，目的是使不同的速度下小车的路径相近，达到小车整体的闭环控制。

4.5.4 不同元素的舵机PD选取
当车模行进到不同赛道元素的时候，如果同样的舵机PD会造成在直道上抖动和弯道上的转向不连续的问题，由此我们根据不同的赛道类型选取了不同的舵机控制PD，使得能够在直道跑的直，在弯道流畅，同时在S型弯道能够基本沿着中线行进。
其中不同元素的PD选取有以下的规律：直道PD小，弯道PD大，S型弯道P小D略大。
4.5.5 不同元素的速度控制策略
通过对智能车的调试我们发现，在直道使用较高的转速，在弯道使用稍慢一些的转速能够很流畅的跑完整个赛道，其中在直道（长直道、短直道）的加速能够非常关键的决定车模的整体速度，而弯道的速度能够提升车模的稳定性。
针对直道入弯的过程我们采取了特定的减速策略，即先根据车模当前速度给出减速场数，当减速场数较高的时候设定速度较低，当减速场数较少的时候设定速度较高，并随着减速场数的减少设定速度逐渐接近弯道速度使车模能够流畅的进入弯道，避免出现“猛加猛减”的情况。

4.5.6 车模的电机PI控制
电机使用增量式PID控制，其中I项能够加快电机响应，P项能够减少稳态误差，控制公式如下:
MotorL_Out += MotorL_Ki * MotorL_Error[2];
MotorL_Out += MotorL_Kp * (MotorL_Error[2] - MotorL_Error[1]);
其中MotorL_Out作为加在电机输出占空比上的增量，针对不同元素，我们给出不同的PI，规律大概是“直道PI大，弯道PI小”，能够使车模长直道加速更快，弯道更顺畅。

5.1 上位机调试软件的介绍
上位机在工业控制当中又被称为HMI,就是一台计算机，它的作用是监控现场设备的运行状态，当现场设备出现问题在上位机上就能显示出各设备之间的状态（如正常、报警、故障等）。 
上位机的概念属于计算机集散控制系统的概念。在计算机集散控制系统中， 计算机分为各个级别，与现场设备发生直接关系的计算机属于下位机，用来控制下位机，或给下位机下达新任务的计算机是下位机的“上位机”。若集散控制系统较大，计算机的级别可能不止两级，此时上位机还可能有级别更高的上位机对其进行控制或指派任务。
使用 VOFA + 作为智能车系统调试上位工具，该软件是面向嵌入式开发的轻量化可视化调试平台，原生支持 Windows、Linux、macOS 多操作系统，搭载 FireWater、JustFloat、RawData 三类数据解析引擎，兼顾文本收发与高速浮点数据流解析，无需开发定制上位机程序，可高效接收主控通过串口、TCP/UDP 网口上传的实时数据，实现多通道波形绘制、状态观测与在线参数调节，充分满足智能车 PID 参数整定、传感器信号观测、运动状态监控、多节点数据遥测的调试需求。
软件集成丰富可视化组件资源，支持多路实时波形图、数据仪表盘、3D 姿态显示、滑动调参控件、指令发送模块；内置大容量波形缓存与 FFT 频谱分析功能，可长时间记录、回放运行数据；通信链路兼容有线串口、无线蓝牙、WiFi 透传等常见方案，适配龙芯 2K0300、TC387、STC32G 等各类智能车主控制器，能够直观展示循迹误差、电机 PWM 输出、陀螺仪姿态、速度反馈等关键信息，大幅降低智能车控制算法调试难度，提升参数优化效率。

5.2 上位机软件的使用和调试
VOFA + 搭建波形观测平台完成智能车电机 PID 参数整定，该上位工具支持串口、网络等多种通信方式接收主控实时输出的目标值、实际反馈值、误差、P/I/D 输出量等浮点数据，通过可视化波形直观呈现控制动态响应过程，能够清晰观测超调量、调节时间、稳态误差、震荡现象，快速完成 PID 参数迭代优化，充分满足智能车电机闭环调速、位置闭环控制的调参需求。
工作流程：主控采集电机编码器速度 / 位置反馈，运行 PID 算法，周期性按照 VOFA + 约定协议打包目标值、反馈值、PID 输出等数据并上传；VOFA + 解析数据流并实时绘制多路波形。调试人员对照波形特征修改参数：波形出现持续震荡则减小比例系数 Kp；响应缓慢、上升时间过长可适度增大 Kp；存在明显稳态静差时增大积分系数 Ki；系统达到设定值后波动较大可引入微分系数 Kd 抑制震荡。同时 VOFA + 支持在线下发指令，可直接修改目标转速、在线更新 PID 参数，无需反复重新编译下载程序，大幅缩短电机闭环算法调试周期。

uint16_t adc_raw[SENSOR_NUM];

uint16_t filter_buf[SENSOR_NUM][FILTER_BUF_LEN];
uint8_t filter_index[SENSOR_NUM]={0};
const int8_t weight[SENSOR_NUM]={-3,-2,-1,0,1,2,3};
float error,integral,last_error,pid_out;

int32_t sum_temp;

void Gray_Data_Filter(void)
{
    Get_Gray_Raw(adc_raw);
    for(i=0;i<SENSOR_NUM;i++)
    {
        filter_buf[i][filter_index[i]]=adc_raw[i];
        filter_index[i]++;
        if(filter_index[i]>=FILTER_BUF_LEN)
        {
            filter_index[i]=0;
        }
        sum_temp=0;
        for(j=0;j<FILTER_BUF_LEN;j++)
        {
            sum_temp+=filter_buf[i][j];
        }
        adc_filter[i]=sum_temp/FILTER_BUF_LEN;
    }
}
float Contrast_Line_Track(void)
{
    Gray_Data_Filter();
    float sum_weight=0;
    uint8_t detect_cnt=0;
    uint8_t line_lost=1;
    for(i=0;i<SENSOR_NUM;i++)
    {
        if(adc_filter[i]<BLACK_THRESH)
        {
            sum_weight+=weight[i];
            detect_cnt++;
            line_lost=0;
        }
    }
    if(line_lost||detect_cnt==0)
    {
        return error*1.2f;
    }
    return sum_weight/detect_cnt;
}
void Line_PID_Calc(void)
{
    error=Contrast_Line_Track();
    integral+=error;
    if(integral>INTEGRAL_MAX)
    {
        integral=INTEGRAL_MAX;
    }
    if(integral<INTEGRAL_MIN)
    {
        integral=INTEGRAL_MIN;
    }
    pid_out=KP*error+KI*integral+KD*(error-last_error);
    last_error=error;
}
void Line_Running(void)
{
    Line_PID_Calc();
    int16_t left_speed=BASE_SPEED-pid_out;
    int16_t right_speed=BASE_SPEED+pid_out;
    if(left_speed>SPEED_MAX)
    {
        left_speed=SPEED_MAX;
    }
    if(left_speed<SPEED_MIN)
    {
        left_speed=SPEED_MIN;
    }
    if(right_speed>SPEED_MAX)
    {
        right_speed=SPEED_MAX;
    }
    if(right_speed<SPEED_MIN)
    {
        right_speed=SPEED_MIN;
    }
    Motor_Control(left_speed,right_speed);
}
void Line_Stop(void)
{
    Motor_Control(0,0);
    integral=0;
    last_error=0;
}
