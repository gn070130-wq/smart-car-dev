第一章 引言
在引言部分，对智能汽车制作情况进行概述，对相关联的文献进行综述，并阐明本报告的内容框架安排。
一、智能车大赛背景
为了加强学生实践、创新能力，培养学生团队精神，从2006年开始，由教育部高等教育司委托高等学校自动化类专业教学指导委员会举办全国大学生智能汽车竞赛。竞赛以"立足培养、重在参与、鼓励探索、追求卓越"为指导思想，在继承和总结前二十届比赛实践的基础上，竞赛组委会不断拓展竞赛内涵、设计新的竞赛内容、创造新的比赛模式。第二十一届比赛设立了"雁过留痕"组别，将传统的竞速任务与目标识别、定点标记相结合，进一步激发大学生的想象力和创造力。
二、雁过留痕组比赛规则
雁过留痕组要求参赛队伍制作一辆四轮竞速车模，在室内PVC赛道上运行一周。赛道为白色PVC材料，包含直道、弯道、十字交叉路口、环岛、坡道、砖红色路障等赛道元素，车模需从发车区斑马线出发，绕行赛道一周后返回起跑线。
在竞速之外，本组别还设有"雁过留痕"辅助任务：赛道某些路段铺设有紫外感光纸，感光纸上用激光打印机绘制有圆形目标区域（线径宽度10毫米，中心线半径5厘米）。车模在运行过程中需要识别感光纸上的圆形目标，并通过车载紫外光源在圆形区域内部照射、留下变色痕迹，圆形区域外不允许留下照射痕迹。若遗漏M个留痕任务，比赛成绩将在原有竞速成绩上增加5×M秒。
比赛规则只允许使用一个摄像头用于赛道检测，不允许使用其他光电管检测赛道及其上面的感光纸；赛道旁设置有边界锥桶，车模需要在锥桶内侧赛道内运行，没有锥桶的部分允许短暂离开赛道。微控制器方面，要求使用STC系列单片机进行信息处理与控制。
三、本文结构
本文将从机械结构、硬件电路、控制软件三个维度，介绍本队"雁过留痕"组车模的设计与实现过程。第二章介绍系统总体方案设计；第三章介绍车模机械结构的安装与改造；第四章介绍以STC32G144K246为核心的电路设计，包括电源管理、主控接口与电机驱动电路；第五章介绍控制软件设计，涵盖图像处理、目标识别与运动控制算法；第六章介绍系统开发与调试过程；第七章给出模型车的主要技术参数；第八章对全文进行总结。
第二章 系统总体方案设计
2.1 模型车设计制作的主要思路
我们的智能车本着速度快，打靶准的理念，主打原创和培养新生力量，对车模进行了多次迭代，利用云台电机提高反应打靶速度，使用风扇负压加大车辆摩擦力加快速度，根据摄像头的图像信息完成跑赛道的任务。
电路设计使用嘉立创EDA，电路板由嘉立创工厂生产和贴片，塑料的机械结构零件由拓竹的3D打印机打印，材料为PLA+。摄像头通过碳纤维杆支撑，固定在车身上。
控制算法采用基础的基于二元化图像的像素差值的算法，使用PID对小车在赛道上的偏移进行纠正。
2.2 实现的技术方案概要
本车系统采用"主板＋功能驱动板"的分布式架构，以STC32G144K246单片机为主控核心，围绕赛道检测、留痕任务、运动控制三条主线构建

赛道检测由摄像头完成：摄像头采集的图像先经AL422B帧缓冲器缓存整场画面，再由主控分时读出；主控对图像进行二值化处理，采用基于像素差值的扫线算法提取赛道边界，得到车模相对赛道中心的横向偏移量。姿态传感器IMU660RA用于感知车模的俯仰与横滚姿态，辅助识别坡道等赛道元素；ToF测距模块用于检测赛道前方的砖红色路障；左右两个正交编码器实时测量驱动轮转速，为速度闭环控制提供反馈。
运动控制方面，主控根据赛道偏差经PID运算输出转向与速度指令：转向舵机BDS300控制前轮转角，双驱板驱动左右直流电机实现差速驱动，使车模沿赛道中心稳定行驶。执行"雁过留痕"任务时，主控从图像中识别紫外感光纸上的圆形目标区域，控制云台电机带动紫外激光头对准目标并点亮照射，在感光纸圆形内部留下变色痕迹，完成留痕。
电源部分将3S锂电池电压变换为5V、3.3V及舵机可调电源等多路电源轨，为主控、传感器、摄像头与执行机构独立供电，并在输入端设有防反接保护。按键、拨码开关与显示屏构成人机交互接口，用于模式选择与参数设定；无线模块用于调试阶段与上位机交换数据，实现控制参数的在线整定与运行状态的实时回传。

第四章 电路设计说明
本车电路系统以自制主板为核心，主板承担整车电源分配以及各传感器、执行机构与主控之间的信号连接；电机驱动、云台驱动等功率电路分别布置在独立的驱动板上。主板电源部分将电池电压变换为5V、3.3V及舵机专用电源等多路电源轨，并为摄像头、姿态传感器、编码器、ToF测距模块、显示屏与无线调试模块预留了标准接口。下面分别从电源管理、主控与接口、电机与云台驱动三个方面介绍本车的电路设计。
4.1 电源管理电路
1. 电源输入与防反接。整车电源由12V 3S锂电池供给。电源输入接口处采用P沟道MOSFET（HY19P03D）构成防反接电路：电池正极经拨动开关S1和MOSFET向整车供电，栅极经10kΩ电阻下拉使管子常态导通，16V稳压二极管BZT52C16对栅源电压进行钳位保护；当电池接反时MOSFET截止，后端电路无电流通过，从而保护整机安全。电机动力电源经XT30U-M接插件直接取自电池，大电流回路不经过控制板电源网络，减小了电机启停对逻辑电源的干扰。电源输入电路如图4-1所示。

图4-1 电源输入与防反接电路
2. 5V电源。5V电源轨（VCC5V）由降压型DC-DC变换器SCT2450STER产生，为各5V外设及后级LDO供电。芯片开关频率由RT/CLK引脚外接的200kΩ电阻设定，输入端并联100μF电解电容与4.7μF、100nF陶瓷电容滤波，自举电容为100nF，功率电感4.7μH，输出端并联47μF与220μF电容以进一步降低输出纹波；输出电压由FB引脚外接的分压网络设定为5V，肖特基二极管SS54用于吸收开关尖峰，LED6为5V电源指示灯。5V电源电路如图4-2所示。

图4-2 5V DC-DC降压电源电路
3. 舵机电源。舵机电源（VCCSERVO）同样采用SCT2450STER降压方案，与5V电源相互独立，避免舵机动作时的大电流冲击影响逻辑与外设供电。其反馈网络由27kΩ电阻、50kΩ电位器与8.2kΩ电阻组成，输出电压可在一定范围内连续调节，以适应不同舵机的工作电压需求，提高舵机的输出力矩与响应速度；LED3为舵机电源指示灯。舵机电源电路如图4-3所示。

图4-3 舵机电源电路
4. 3.3V电源。3.3V电源采用三路独立的低压差线性稳压器RT9013-33GB，分别产生主控及传感器电源VCC3V3、摄像头电源VCCCAM与运放电源VCCOP，输入输出端均并联10μF与100nF电容。将摄像头与运放的模拟电源同数字3.3V电源分开供电，可有效抑制数字噪声对模拟小信号的干扰；各路输出均设有LED指示灯（串联2.7kΩ限流电阻），便于调试时快速判断各路电源的工作状态。LDO电源电路如图4-4所示。

图4-4 3.3V LDO电源电路

4.2 主控与接口电路
本车微处理器为STC32G144K246一片、STC32F12K54一片、STC32G12K128两片。其中主板主控STC32G144K246负责摄像头图像处理、姿态解算与整车控制，其余单片机分布于各驱动板上，分别承担电机驱动、云台控制与负压驱动等任务。主板为主控提供3.3V电源与复位信号，并将各外设接口信号引至主控对应IO口，本节介绍主板上的各接口电路。
1. 按键与拨码开关。主板上设有旋钮，配合复位信号经P00接口接入主控IO，用于比赛现场的模式选择、参数设定与系统复位，无需重新下载程序即可调整车辆运行状态。电路如图4-7所示。

图4-7 旋钮开关电路
2. 摄像头接口。摄像头经P26插座接入。受单片机IO读取速度限制，图像数据先写入AL422B帧缓冲器（FIFO）缓存整场画面，再由主控分时读出处理：AL422B的写时钟WCK由摄像头像素时钟PCLK经单与非门SN74LVC1G00与行同步信号HREF门控产生，仅在行有效期间写入像素数据；读时钟RCK、写复位WRST、读复位RRST及输出使能OE均由主控IO控制，8位数据总线DO0～DO7直接接至主控端口。该硬件缓存方案大大降低了图像采集对单片机实时性的要求。摄像头接口电路如图4-8所示。

电机与云台部分的功率电路布置在独立驱动板上，主板仅引出控制信号，实现了功率回路与信号回路的分离，提高了系统的抗干扰能力与可维护性。
1. 动力电机驱动。动力电机驱动采用"主板＋双驱板"分离方案：电池经XT30U-M接口向双驱板直接供电，主控的电机控制信号经主板P20电机信号接口引出至双驱板，由双驱板上的功率级驱动直流电机；信号线串联的10kΩ电阻用于抑制干扰、防止功率级误触发。电机信号接口见图4-9。

第五章 控制软件设计
5.1 软件总体框架
本车软件基于STC32单片机开发，主频96MHz，采用前后台程序加多定时器中断的分层调度框架，整体分为驱动层、算法层和应用层三层。驱动层负责摄像头、陀螺仪、编码器、电机、舵机、负压风扇、云台串口、激光头、电池电压采集以及屏幕按键等外设的初始化和读写。算法层由六个功能模块组成，分别是图像处理与赛道元素识别模块、转向控制模块、电机速度闭环模块、打靶控制模块、里程计融合模块和屏幕调参菜单模块，各模块之间通过全局变量和少量接口函数解耦。应用层负责任务调度和运行状态管理。整个软件运行在三个异步时间轴上：1毫秒定时中断读取陀螺仪并去除零偏、采集编码器、执行1千赫兹的速度环运算、维护云台和激光的毫秒级定时状态机以及按键扫描和电池采样；300赫兹定时中断执行与图像帧率解耦的舵机输出级，完成陀螺阻尼微分、舵机限位输出和差速计算；主循环等待摄像头一场图像完成后，逐帧执行图像处理、靶环识别、云台决策和串口发送，菜单激活时则切换为菜单预览和调参流程。整车运行状态分为待机、发车运行和刹车停车三种，发车后自动关闭屏幕刷新以消除显示对控制周期的干扰，并带有32秒定时自动刹车保护。整体数据流为：摄像头图像经过图像处理得到边线和赛道元素，进而得到转向误差，在300赫兹中断中输出舵机打角和左右轮差速目标，再由1千赫兹速度环闭环到电机；同时图像识别出的靶环经测距换算后得到云台角度和开火时机，通过串口和IO口执行。
5.2 主要控制理论与算法说明
图像预处理采用行列动态阈值二值化方法。针对光照不均和赛道远暗近亮的特点，不使用全局阈值，而是每隔四行或四列采样一次，分别计算亮像素均值和暗像素均值，按比例插入得到该行或该列的目标阈值，再经过上下限限幅和与上次有效阈值取均值的时间滤波，未采样的行用加权插值补齐。判决时每个像素的最终阈值取该点行阈值和列阈值的平均，实现逐点自适应二值化，在逆光和阴影下仍能稳定提取边线。
边线搜索采用中心射线扫线与爬虫跟踪相结合的方法。射线法从图像底部上一帧中线记忆位置出发，逐行向两侧搜索黑白跳变，快速得到左右边线和有效前瞻行；爬虫法以八邻域方式沿赛道边界轮廓爬行，在弯道和圆环处仍能获得连续的轮廓边线，弥补射线法内侧丢线的问题。由左右边线求出中线后进行单帧平滑和记忆补线，再对多行误差加权求和得到转向误差，加强了前瞻行的权重。
转向控制采用视觉比例微分与陀螺阻尼分频融合的方案。舵机偏移量由四项叠加：线性比例项保证小偏差灵敏度，二次比例项在大偏差时迅速增大打角，视觉微分项由图像帧间误差差分得到，陀螺微分项以300赫兹直接读取陀螺仪z轴角速度。前两项在图像帧中计算，后一项在300赫兹中断中计算，两者异步运行，陀螺项弥补了摄像头帧间隔内的响应滞后，有效抑制蛇形振荡。入环瞬间按缺口高度对打角做自适应放大，保证入环切角。
差速采用基于转向量的几何方法。以舵机打角归一化后的值作为输入，内轮减速比按二次曲线计算，即打角越大内轮减速越多，遵循内减外不加的原则，过死区后不差速，使弯道内外轮速度符合阿克曼几何关系，减少差速打滑。
速度环为1千赫兹位置式PID，输出等于速度前馈、比例项、积分项和微分项之和。前馈直接给出稳态占空比减小调节滞后；比例增益随误差自适应变化，误差大时增强抗扰能力，误差收敛到目标的百分之二十以内时切换为小增益并投入积分以消除稳态误差，体现积分分离思想；目标值突变时按加速或减速方向自适应调整微分增益抑制超调；输出级还包含左右轮死区补偿和左右电机平衡系数，消除机械不对称。

圆环识别采用左右各自独立的四态状态机，即正常循迹、识别入环缺口、环内循迹和出环保持。入环依据边线缺口特征结合直道判定，环内和出环判断利用1毫秒中断对去零偏后陀螺仪z轴角速度的积分，累计角度接近一整圈时判定出环，避免了纯视觉在环内遮挡时的误判，出环后限时保持原打角方向完成切出。
负压风扇支持恒定和变负压两种模式。变负压模式下按舵机打角偏差分低中高三档，偏差越大吸附力越强，降档需连续十个图像帧确认以防抖动，升档立即执行。另用陀螺仪y轴上坡尖峰检测触发坡道保底负压并保持四百毫秒，防止坡道吸附不足侧滑。
赛道元素方面，斑马线在底部感兴趣区内以差比和跳变逐行细扫判定黑白相间特征，首次识别后挂起防重触发，跑满两圈后延时自动刹车。砖块避让对砖块出现在左右侧的行做多数投票防止误判抖动，再对中线施加固定偏移绕行。整幅图像大面积异常时触发出界保护自动回中限速，等待重新捕获赛道。
打靶子系统由靶环识别、逆透视测距、云台控制和开火决策四部分组成。靶环识别在爬虫边线约束下用相对动态白点的差比和判据沿环壁扫描黑色靶环轮廓，抗光照干扰，取极值得到环心和轮廓远近边。测距采用逆透视查表方法，离线标定生成图像行到前方纵向距离的查找表以及每行每像素对应横向毫米数的查找表，将靶心像素实时换算为以激光头为原点的物理坐标，并按距离随 tan 角视差修正激光与相机光轴不重合带来的横向偏差。云台控制由靶心横向距离经512点反正切查表得到偏角，换算为执行器位置，以位置加CRC8校验的三字节协议经串口DMA非阻塞下发，连续丢靶两百毫秒后云台自动回中。开火决策中，激光落点纵向距离为标定固定值，当靶轮廓远近边按可调内缩量构成的区间覆盖落点时判定进窗，对视觉一帧延迟用编码器实时速度做纵向补偿，支持限时单脉冲和窗内跟随连续出光两种模式，前者脉宽为毫秒级墙钟时间与帧率无关，并对已击靶计数，计数后挂起两百毫秒防止重复计数。
里程计融合采用航位推算方法，编码器左右均值位移与陀螺仪z轴角速度的1毫秒积分得到航向，按中点航向分解为纵横向位移递推车体相对位姿，三角函数用1024点查表加16倍线性插值实现，角度量化约百分之二度，并换算到激光头前方二百三十毫米处的坐标，为跨帧目标位置外推提供位姿基准。
5.3 代码设计介绍
工程按驱动、算法、应用三层组织源文件。主函数文件负责系统初始化、三任务调度框架、运行状态机、电池采样和云台串口协议；中断文件提供摄像头场中断等中断入口；图像模块实现行列动态阈值、射线扫线、爬虫边线、中线提取平滑、圆环状态机、斑马线检测、砖块投票避让、出界检测和边线显示变换；转向模块实现误差计算、视觉比例微分、300赫兹舵机与差速输出以及负压风扇分档与坡道保底；电机模块实现电机初始化、含死区与平衡补偿的占空比输出和左右轮1千赫兹速度环；打靶模块实现爬虫边线、双环壁扫靶、逆透视测距与角视差补偿、云台角度查表、开火窗口与激光脉冲状态机以及丢靶回中；里程计模块实现编码器与陀螺的航位推算和三角函数查表插值；菜单模块实现电池、发车、图像、打靶四个主页的多级菜单、编码器导航、参数掉电保存加载和各预览模式；另有一个上位机标定脚本由像素样本生成逆透视查找表和反正切表。
代码设计上有七个要点。一是时序隔离，1毫秒速度环、300赫兹舵机输出和100赫兹视觉决策三级任务各司其职，速度环与视觉帧率彻底解耦，图像帧处理耗时波动不影响底层闭环。二是并发安全，中断与主循环共享变量一律加volatile修饰，跨变量快照场景按先停更后读取的顺序保证一致性。三是定点化运算，全工程基本避免浮点，比例系数用定点数表示，除法以移位和整数除法实现，满足无浮点单元平台的实时性要求。四是查表优化，逆透视距离表、每像素横向表、反正切表和三角函数表都放在扩展数据空间，把实时三角与几何运算降为一次查表加一次插值。五是参数表驱动的菜单，所有可调参数注册进统一参数表，由菜单统一完成显示、修改、限幅和掉电保存，调试时无需重新编译。六是可观测性设计，圆环入口、扫靶、差比阈值等关键算法都带屏幕诊断页，配合上位机串口协议在线调参，缩短现场调试周期。七是防御性设计，串口协议带CRC8校验且发送忙则丢帧，激光开火使用与帧率无关的墙钟脉宽状态机，发车限时自动刹车、出界自动回中、丢靶云台回中等失效保护贯穿全流程。

6.2 制作与安装过程
整车的制作分为机械装配、电路连接和软件环境搭建三个阶段。机械装配首先按照车模说明书完成底盘组装，安装差速齿轮和四轮，调整前轮前束使直行方向不跑偏。驱动电机固定在后桥两侧，通过三十六比六十八的齿轮副带动一千零二十四线编码器，安装时反复调整齿轮啮合间隙，既不能过紧增加阻力也不能过松产生空程，保证里程反馈准确。转向舵机安装在前桥中央，舵机臂通过拉杆连接左右转向节，装配后先给舵机上电打出中位，再机械微调拉杆长度使前轮在舵机中位时严格平行。摄像头通过铝合金支架固定在车头，高度和俯仰角经过多次试验确定，使视野既覆盖足够的前瞻距离又不损失近处赛道信息，支架加装减振垫抑制车体振动引起的图像抖动。云台和激光头安装在车头最前端，安装时以车体纵轴线为基准对正云台零位，保证云台回中时激光指向正前方。电池放置在车体重心位置，兼顾配重和前后轴荷平衡。
电路部分以主控板为核心，主控、陀螺仪、摄像头和屏幕之间的信号线全部采用排线并使用接插件连接，方便拆装更换。电机动力线与信号线分开两侧走线并尽量缩短，减少电机干扰窜入图像和陀螺仪信号。电池电压经电阻分压后接入单片机模数转换通道，用于低电压监测。装配完成后逐路检查电源电压和各模块供电，确认无短路和虚焊后再插入主控芯片。
软件环境方面，在电脑上安装Keil建立工程并配置好编译选项，配合VS Code进行代码编辑，通过烧录器连接主控板的调试口，实现程序下载和在线调试。6.3 调试过程
整车调试遵循先模块后系统、先低速后高速、先直道后元素的原则分阶段进行。第一阶段为分模块调试。上电后利用屏幕菜单和旋转编码器进行人机交互，先用校准页面确认电池电压采样准确。陀螺仪在每次上电静止时自动采集零偏，消除温漂影响。速度环调试时先给固定的目标转速，观察屏幕显示的编码器反馈，逐步整定死区补偿量和速度前馈，再调比例和积分增益，使左右轮实际转速快速跟随目标且无明显静差，针对左右电机特性不一致的问题分别设置了平衡系数。舵机调试先确认中位和左右限位，保证打角在安全范围内。
第二阶段为图像与循迹调试。在屏幕的阈值标定页面实时观察动态阈值的上下限、噪声基准和比例参数在不同光照下的表现，将赛道边线的二值化效果调到直道和阴影处都稳定。然后在图像预览页面观察扫线和爬虫边线，配合上位机观察赛道中线提取效果。循迹调试从低速开始，先调线性比例和二次比例系数保证弯道不冲出赛道，再逐步加入视觉微分和陀螺微分抑制蛇形振荡，提高直线稳定性。速度提升后引入几何差速，调整内轮减速曲线系数消除弯道甩尾打滑。
第三阶段为赛道元素调试。圆环调试借助屏幕上专门设计的入口诊断页面，实时显示缺口位置、长度和识别失败原因，据此调整缺口判定的宽度和直道条件，环内依靠陀螺积分判断跑满一圈后出环，反复测试保证左右环都能准确进出。斑马线通过差比细扫识别黑白跳变，调整识别阈值和防重触发挂起时间，实现跑满两圈后自动停车。砖块避障通过投票机制确认砖块方向后施加中线偏移绕行。
第四阶段为打靶子系统调试。先进入校准模式让激光常亮，通过菜单调节云台位置使激光精确指向车体正前方，确定云台零位。再用附带的标定脚本对图像像素和实际距离的对应关系采样，生成逆透视查找表和反正切表写入程序，使像素到毫米的换算准确。然后在打靶预览页面观察靶环识别和云台跟随，调整开火窗口的轮廓内缩量和视觉延迟的速度补偿量，使激光落点在靶环纵向范围内时可靠触发，最后整定每靶的出光脉宽，保证既有足够的能量触发记分又不误击相邻靶。
第五阶段为整车联调与场地测试。综合调整基础车速、负压档位和各元素参数，在坡道处验证陀螺触发的保底负压是否有效。发车测试中确认三十二秒自动刹车、丢靶云台回中和出界保护等失效保护逻辑都能正常工作。所有调好的参数通过菜单保存到存储器中，换场地时只需微调光照相关参数，缩短了赛前适应时间。经过多轮完整跑圈测试和参数迭代，整车在速度、稳定性和打靶命中率上都达到了设计预期。

第八章 结论 
本次模型车的制作经历了方案论证、机械装配、电路搭建、软件开发和场地调试五个阶段，历时数月完成。团队以STC32单片机为主控，构建了图像处理、转向控制、速度闭环、赛道元素识别、激光打靶和负压管理六个软件模块，采用一毫秒速度环、三百赫兹舵机输出和一百帧视觉决策三级异步调度的控制架构，通过屏幕菜单加旋转编码器的调参体系和多个专用诊断页面，显著提高了现场调试效率。整车实现了对直道、弯道、圆环、斑马线、砖块等全部赛道元素的稳定识别与通过，并能在行进中自动识别靶环、控制云台跟踪并择机出击靶，完成了从起点到自动停车的全自动无人运行。
整车达到的主要技术指标为：主控工作在九十六兆赫兹主频下全定点运算；摄像头以每秒一百帧的帧率采集一百八十八乘一百二十的灰度图像，单帧图像处理和靶环识别在一次帧间隔内完成；速度环控制频率一千赫兹，舵机与差速输出频率三百赫兹；云台指令以五百赫兹经串口下发并带循环冗余校验；正常巡航车速约为每秒二点五到三米，打靶识别时可自动降速保证命中率；系统具备三十二秒定时自动刹车、出界自动回中、丢靶云台回中、低电压监测等多重失效保护，连续跑圈测试中完赛率稳定。
制作过程中也暴露出一些问题。一是视觉帧率带来的延迟限制，当前对靶环位置的一帧滞后采用固定比例的速度补偿，精度有限，工程中已经实现了编码器与陀螺仪的航位推算模块，但受限于定位误差累积，跨帧目标外推功能尚未在正式方案中启用，靶环在两帧之间的运动只能靠开环估计。二是强逆光和地面反光条件下动态阈值仍有少量误判，圆环入口在特定光照角度下偶发漏识别，需要进一步利用多帧确认和更多轮廓特征来增强鲁棒性。三是电池电压随放电下降导致电机出力特性变化，目前依靠速度环积分弥补，响应不够及时。四是负压风扇的分档控制是开环的，上下坡和不同车速下的吸附需求只能靠保守加大档位来覆盖，浪费了电池能量。五是打靶降速与整圈用时之间存在权衡，降速过多影响成绩，目前的降速量仍是经验值。
针对上述问题的改进方向包括：完善里程计融合的误差抑制后启用跨帧目标外推，把开环速度补偿升级为基于位姿的预测，进一步提高高速下的命中率；在电机输出中引入电池电压前馈，使占空比随电源电压自适应修正；将负压风扇改为以打滑程度或车速为反馈的闭环调节，兼顾抓地力与能耗；为圆环等元素建立多帧投票与时序约束的识别机制，降低误判率；并探索按车速和赛道元素自动切换参数组的调度策略，减少人工调参工作量。
通过本次制作，团队形成了几点认识。其一，底层高频率闭环与上层低频率视觉决策相解耦的架构是整车稳定性的基础，图像处理耗时的波动被完全隔离在速度环之外，这一设计思路比单纯提高某个算法的复杂度更有价值。其二，调试手段的投入回报极高，参数表驱动的屏幕菜单和圆环入口诊断页面使绝大多数问题能在现场几分钟内定位，工程初期在可观测性上的设计投入远比后期补偿更有意义。其三，失效保护不是可选项，限时自动刹车、丢靶回中等逻辑在测试中多次避免了车损和跑飞，完整的系统必须在性能指标之外保证任何单点失效都不导致失控。其四，机械、电控与算法必须协同设计，云台零位标定和相机安装角度等机械因素对软件上限的影响，不亚于控制参数本身，只有软硬件一体迭代才能持续提高整车成绩。

static uint8 crc8_2(uint8 b0, uint8 b1)
{
    uint8 crc = 0;
    uint8 i;
    crc ^= b0;
    for (i = 0; i < 8; i++)
        crc = (crc & 0x80) ? ((crc << 1) ^ 0x07) : (crc << 1);
    crc ^= b1;
    for (i = 0; i < 8; i++)
        crc = (crc & 0x80) ? ((crc << 1) ^ 0x07) : (crc << 1);
    return crc;
}

volatile uint16 ptz_target_pos = PTZ_MOTOR_CENTER;

/* 一次起 3 字节 DMA，不等发送完成；忙则丢本帧（500Hz 下极少发生） */
void uart_send_pit_handler(void)
{
    uint16 pos;
    uint8 pkt[3];

    pos = ptz_target_pos;
    pkt[0] = 0x80 | (uint8)(pos >> 7);
    pkt[1] = (uint8)(pos & 0x7F);
    pkt[2] = crc8_2(pkt[0], pkt[1]);
    (void)uart_write_buffer_noblock(UART_3, pkt, 3);
}

static uint16 bat_raw_to_cv(uint16 raw)
{
    return (uint16)((uint32)raw * 3630 / 4096);
}

static void bat_voltage_startup_calibrate(void)
{
    uint8 i;
    uint32 sum = 0;

    for (i = 0; i < 8; i++)
        sum += adc_mean_filter_convert(BAT_ADC_CH, 16);

    bat_voltage_cv = bat_raw_to_cv((uint16)(sum / 8));
}

static void bat_voltage_sample(void)
{
    bat_voltage_cv = bat_raw_to_cv(adc_mean_filter_convert(BAT_ADC_CH, 16));
}

/* 1ms：陀螺仪 / 圆环 / 风扇 */
void imu_pit_handler(void)
{
    imu660ra_get_gyro();
    imu660ra_gyro_y = imu660ra_gyro_y - gyro_y_offset;
    imu660ra_gyro_z = imu660ra_gyro_z - gyro_z_offset;
    if (imu660ra_gyro_y > -3 && imu660ra_gyro_y < 3)
        imu660ra_gyro_y = 0;
    if (imu660ra_gyro_z > -3 && imu660ra_gyro_z < 3)
        imu660ra_gyro_z = 0;

    if (Right_Ring_State == 2 || Left_Ring_State == 2)
        total_raw_z += imu660ra_gyro_z;
    else
        total_raw_z = 0;

    if (Right_Ring_State == 3 || Left_Ring_State == 3)
        ring_state3_timer++;
    else
        ring_state3_timer = 0;

    /* ===== 速度环（1000Hz，位置式 PID，直接喂 l_target/r_target）===== */
    l_encoder_data = encoder_get_count(ENCODER_QUAD_1);
    r_encoder_data = -encoder_get_count(ENCODER_QUAD_2);
    encoder_clear_count(ENCODER_QUAD_1);
    encoder_clear_count(ENCODER_QUAD_2);

    /* 帧间隔惯导外推暂关，仅保留丢靶回中计时 */
    /* Odom_Fusion_Step(l_encoder_data, r_encoder_data, imu660ra_gyro_z); */
    /* Target_Odom_Propagate_1ms(); */
    Target_Ptz_Tick_1ms();
    Menu_Input_1ms();

    if (car_run_state == 0)
    {
        l_duty_set(0);
        r_duty_set(0);
        Fan_Vac_Reset();
        pwm_set_duty(PWM_3, 3000);
        pwm_set_duty(PWM_4, 3000);
        fan_startup_timer = 0;
        run_auto_stop_ms = 0;
    }
    else if (car_run_state == 1)
    {
        Fan_Vac_Update();
        pwm_set_duty(PWM_3, fan_duty);
        pwm_set_duty(PWM_4, fan_duty);

        if (fan_startup_timer < FAN_STARTUP_MS)
        {
            fan_startup_timer++;
            l_motor_pid(0);
            r_motor_pid(0);
            l_duty_set(0);
            r_duty_set(0);
        }
        else
        {
            l_duty = l_motor_pid(l_target);
            r_duty = r_motor_pid(r_target);
            l_duty_set(l_duty);
            r_duty_set(r_duty);
        }

        /* GO 后满 32s → 刹车 */
        if (run_auto_stop_ms > 0)
        {
            run_auto_stop_ms--;
            if (run_auto_stop_ms == 0)
                car_run_state = 2;
        }
    }
    else if (car_run_state == 2)
    {
        l_duty = l_motor_pid(0);
        r_duty = r_motor_pid(0);
        l_duty_set(l_duty);
        r_duty_set(r_duty);
        Fan_Vac_Reset();
        pwm_set_duty(PWM_3, 3000);
        pwm_set_duty(PWM_4, 3000);
        fan_startup_timer = 0;
        run_auto_stop_ms = 0;
    }

    {
        static uint16 bat_sample_ms = 0;

        bat_sample_ms++;
        if (bat_sample_ms >= BAT_SAMPLE_INTERVAL_MS)
        {
            bat_sample_ms = 0;
            bat_sample_flag = 1;
        }
    }

    Zebra_Stop_Tick_1ms();  /* 斑马线：挂起倒计时 + 第2条延时后刹车 */
}
