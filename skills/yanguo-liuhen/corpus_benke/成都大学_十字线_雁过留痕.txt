摘 要
本文设计的智能车系统以 STC32G144K246核心控制单元，使用 Keil 5软件开发平台进行设计。通过车体前方的总钻风灰度摄像头传感器采集二值化后提取赛道信息；通过正交编码器检测模型车的实时速度，使用了PID控制算法来实现转速控制，使用阿克曼模型控制后轮差速，实现了对车运动速度和运动方向的闭环控制。并且为了提高模型车的速度和稳定性，使用Matlab、图像上位机、无线图传模块、IPS屏以及按钮等调试工具，进行了大量硬件与软件测试。实验结果表明，该系统设计方案稳定可行。

关键字：智能车，STC32G144K246，总钻风灰度摄像头，图像处理算法，电机PID控制

第一章 系统总体设计
	在本章中简要介绍智能车系统的整体设计内容，在后面的章节会分别对于机械结构与控制部分以及图像算法部分对于智能车系统进行分析。
1.1系统总体方案的选定
	根据二十一届智能车竞赛的规则，雁过留痕组使用C车模，车模微控制器使用STC32G144K246。允许使用摄像头，激光测距传感器件等进行赛道和环境检测。
固定使用STC32G144K246主控芯片，其性能强大，芯片主频可以实现100MHz，合理利用可以运行复杂算法，达到较高效率。并且选用了总钻风灰度摄像头，二者之间使用了一颗FIFO场存储器，作为摄像头和MCU之间的图像数据缓冲芯片，弥补了STC32G144K246内存的不足。编码器选用1024线正交编码器，对于车的速度获取精确性更高，使用其来对速度闭环反馈。相对于C车模而言，使用差速进行方向的控制，后轮是靠电子差速来实现转弯差速。 
1.2系统总体方案的设计
	遵循本届竞赛规则规定，智能汽车系统采用STC32G144K246作为核心控制单元用于智能车系统的控制。总钻风灰度摄像头采集赛道信息，返回到STC32G144K246作为差速实时转向和速度控制的依据。编码器模块采集速度信息，用于速度的闭环控制。根据以上的系统方案设计，可以将智能车系统分为七个子系统：电源模块；主控模块；赛道提取传感器模块；激光打靶模块；电机驱动模块；测距模块；人机交互调试模块。
1.电源模块：电源模块采用不同的稳压芯片为单片机、舵机、摄像头等硬件提供合适且稳定的电源。
2.单片机主控模块：主控是整个智能车的处理中心，其完成赛道数据的输入和处理，并且通过各种控制算法来实现对智能车的舵机以及电机实现控制，实现整个智能车的闭环稳定运行。
3.赛道提取传感器模块：通过摄像头获取整个赛道的信息，使智能车能在赛道中稳定运行。
4.激光打靶模块：通过摄像头获取靶子的信息，使智能车能在运行状态下快速打靶。
5.电机驱动模块：包含对于电机驱动和速度采样，使智能车能拥有稳定快速的速度输出。
6.测距模块：实现对障碍物距离的测量。
7.人机交互模块：通过拨码开关、按键、IPS高分辨率屏以及无线图传模块的发送，可以检测并观察智能车运行状态中所处的状态，也可以通过其自主设计的菜单完成对于智能车的功能调试，提高其鲁棒性。

2.4电机齿轮与车轮齿轮盘啮合调整
良好的齿轮啮合可以让车模运行时的噪音降到很低，过大的噪音会影响对车模运行状态的判断。在调节啮合度时，先将编码器齿轮卸下，将电机固定螺栓稍稍拧松，同时手捏电机微调两齿轮见的啮合度，当齿轮间隙约一A4纸厚较为合适，微调一次拧紧后程序控制电机开环旋转，通过听来判断啮合是否良好。两电机齿轮啮合度应尽量保持一致，对后期电子差速调节有帮助。
在调节过程中发现，不同的电机黄铜齿轮对整体噪音有较大影响，通过挑选黄铜齿轮能够尽快调整好整体噪音。

4.2图像识别算法
4.2.1灰度图像处理思路
受限今年使用的STC芯片性能，我们决定不对原始灰度图做任何预处理操作。图像处理流程中，每一帧的缩放、滤波或增强等常规操作，都会显著消耗本就紧张的运算资源和存储空间，进而拖累整体系统的响应速度。因此，为了最大限度节省图像处理时间、保证控制指令的实时性，我们直接采用原始灰度图像数据（分辨率为188×120像素），以最精简的方式完成后续识别与决策任务。这一选择虽牺牲了一定的图像质量与鲁棒性，但在当前硬件条件下，是平衡性能与效率的最优折中方案。
4.2.2基本循迹扫线思路
1．赛道边界判断
由于我们直接采用未经处理的原始灰度图像，像素值在空间上呈现出连续的渐变过渡，而非二值化图像中常见的剧烈黑白跳变。这种连续的灰度分布虽然保留了更丰富的细节信息，但也意味着传统的固定阈值二值化方法难以有效提取赛道边界。因此，我们摒弃了依赖边缘跳变特性的简单阈值分割方式，转而采用差比和算法来寻找赛道边缘。该算法通过对局部窗口内的灰度差值进行归一化比率计算，能够有效抑制光照不均和整体亮度变化带来的干扰，在灰度渐变的原始图像中稳定地定位出赛道边界的过渡带，从而为后续的方向控制和决策提供可靠的特征输入。
4.2.3图像中线获取
当赛道的左右边线均被成功提取后，我们便得到了两条描述赛道边界的像素级坐标序列。为获取用于车辆循迹控制的核心引导线，我们采用最直接的中心线计算策略：对每一行中左、右边线的列坐标进行对应相加，再取其算术平均值，即得到该行赛道中心的像素列坐标。遍历所有有效行后，所有中心点便连缀成一条完整的中线轨迹。这种对称平均的方式实现简单、计算开销极低，在左右边线对称性良好的情况下，能够快速生成精确的控制参考路径，为后续的方向偏差计算和转向控制提供直接依据。
4.2.4特殊元素处理思路
为了在赛道中准确识别各类特殊元素（如环岛、十字交叉、急弯、坡道等），此方案并非仅依赖单一的中线轨迹，而是对提取到的左右边线进行多维度的综合分析。具体而言，主要从以下三个维度对边线质量进行评估：
1、边线丢线数目：统计每一帧图像中左右边线各自缺失的行数。若某一边线在连续多行内无法被有效提取，则可能预示着赛道存在大角度弯道、十字交叉口或环岛入口等特殊结构；若两侧边线同时大量丢失，则可能表明车辆正处于赛道交汇区域或面临剧烈的视角变化。
2、边线连续性：检测每条边线在纵向空间上是否保持连续的像素连接。若边线在某一位置出现非预期的断裂，则可能是由于赛道元素突变（如环岛出口的错位衔接）或图像噪声导致，结合连续性特征可有效区分正常弯道与异常跳变。
3、边线跳变点：计算相邻行之间边线列坐标的差分值，若某处差分超过预设阈值，则判定为跳变点。跳变点的分布规律是识别赛道突变区域的关键指标——例如，十字交叉路口通常会在四个方向产生对称的跳变点，而环岛区域则会呈现独特的渐进式跳变模式。
通过对上述三个维度的特征进行综合阈值判定与模式匹配，我们能够将当前帧的赛道状态归类为特定的特殊元素类型，进而触发相应的决策策略（如降速入环、转向补偿或路径规划切换），从而保证智能车在复杂赛道场景下的稳定通过能力。
4.3转向控制方案
4.3.1整体控制思路
考虑到摄像头的帧率为100帧，为了实现摄像头一帧最少保证一次控制，且转向环使用100HZ的PWM波可以实现控制转向的稳定快速的响应，我们确定使用100HZ的PWM为转向环实行控制。
在每个控制周期中，每当图像处理完成，我们根据图像的状况，分析获得最佳的打角行，计算该行的赛道中值偏差值与偏差变化率，将其代入转向模糊控制代码中进行计算限幅后实现指定占空比的PWM输出。

4.3.3角速度环模糊控制
在调试得当的情况下较于传统PD控制，模糊控制的优点是鲁棒性强，适用于解决过程控制中的非线性、强耦合时变、滞后等问题；有较强的容错能力，具有适应受控对象动力学特征变化、环境特征变化和行动条件变化的能力，并且省去单独调节不同元素下的PD参数，是一个两全其美的控制策略。
模糊 PD 控制的基本原理[1]：模糊PD控制,即利用模糊逻辑并根据一定的模糊规则对PD的参数进行实时的优化,以克服传统PD参数无法实时调整PD参数的缺点。模糊PD控制包括模糊化,确定模糊规则，解模糊等组成部分。小车通过传感器采集赛道信息,确定当前距赛道中线的偏差E以及当前偏差和上次偏差的变化EC，根据给定的模糊规则进行模糊推理,最后对模糊参数进行解模糊,输出控制参数。

4.4.3 动态速度策略
在完成中线提取与特殊元素识别后，我们进入最终的速度决策环节。该环节的核心思想是：根据当前时刻的路径偏差与前瞻预瞄距离，动态调整车辆的期望速度，以实现“直道快跑、弯道减速”的智能控速策略。具体而言，速度决策的逻辑包含以下两个关键维度：
1、基于偏差的速度调节：计算当前帧下车辆中心线与赛道中线之间的横向偏差值。当偏差较小时，表明车辆正处于直线或大曲率弯道，此时赋予较高的期望速度以追求圈速；当偏差急剧增大时，意味着前方存在急弯或特殊元素，系统立即触发降速机制，确保车辆在转向极限内能够稳定过弯，避免因速度过快而冲出赛道。
2、基于前瞻的速度预判：考虑到单纯依赖当前偏差属于“事后调节”，容易在高速行驶时反应滞后，我们引入前瞻预瞄机制——选取前方一定行数处的中线点作为预瞄目标，计算该点与当前车辆朝向之间的预瞄偏差。这一偏差能够提前感知赛道曲率的变化趋势：若前瞻偏差较小，说明前方路径平直，可适度加速；若前瞻偏差迅速增大，则预示着弯道逼近，系统据此提前执行减速操作，从而实现“预判性”的速度调控。
最终，将上述两项策略输出的速度指令进行加权融合，并结合当前特殊元素的类型（如环岛内强制限速、十字路口缓行通过）进行速度修正，形成当前帧的目标速度值。该值随后送入底层PID控制器，驱动电机实现平滑、稳定的加减速响应，确保车辆在追求速度极限的同时，始终保持对赛道路径的有效跟踪能力。

/****************************PID计算核心函数************************************/

/*
 功能：位置式PID
 参数：pid - PID结构体指针 | expect - 目标值 | feedback - 反馈值 
 返回值：计算得到的PID输出
*/
float Speed_PID_Calculate(Speed_PID *pid, float expect, float feedback)
{ 
	pid->Error = expect - feedback;

    pid->Pout = pid->Kp*(pid->Error - pid->Last_Error);
    pid->Iout = pid->Ki*pid->Error;
    pid->Dout = pid->Kd*(pid->Error - 2*pid->Last_Error + pid->Prev_Error);

    pid->OutPut += pid->Pout + pid->Iout + pid->Dout;
    pid->OutPut = LIMIT(pid->OutPut, -pid->MAX_OutPut, pid->MAX_OutPut);    //限幅

    pid->Prev_Error = pid->Last_Error;
    pid->Last_Error = pid->Error;

    return pid->OutPut;
}

float Image_PID_Calculate(Pos_PID *pid, float err)
{	
    pid->Error = err;
	
	pid->Differential = pid->Error - pid->Last_Error;
	
//	My_LPF_1(0.2, (pid->Error - pid->Last_Error), &pid->Differential);
		
	pid->OutPut = pid->Kp*pid->Error + pid->Kd*pid->Differential;

    pid->Last_Error = pid->Error;
	
	return pid->OutPut;
}
