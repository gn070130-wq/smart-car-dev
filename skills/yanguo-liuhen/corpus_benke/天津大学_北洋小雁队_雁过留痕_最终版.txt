第一章  引言
1.1  赛题任务与设计目标
第二十一届全国大学生智能汽车竞赛“雁过留痕”组属于室内PVC赛道竞速组。参赛车模采用四轮竞速车模，以STC系列微控制器作为主要控制平台，在白色PVC赛道上自主完成一周运行。赛道铺设于蓝色背景布上，包含直道、弯道、十字交叉路口、环岛、坡道以及砖红色路障等典型元素；赛道部分区域外侧设置蓝色锥桶，用于界定车辆的有效运行范围。车模需要在保证稳定、连续行驶的基础上，以尽可能短的时间完成全程竞速任务。
与传统单纯循迹竞速不同，本组别在赛道中加入了“留痕”任务。赛道若干位置会铺设紫外感光纸，感光纸上打印有圆形目标区域，车模在运行过程中需要通过视觉系统识别目标圆环，并控制紫外光源在圆形目标区域内部完成照射，使感光纸产生肉眼可辨识的变色痕迹。根据比赛细则，赛道上的感光纸数量为1～5个，圆环线宽为1 cm、中心线半径为5 cm，圆环中心距离赛道边界不小于10 cm；有效留痕长度应不小于1 cm，且圆形目标区域外不得出现紫外照射形成的变色痕迹。
图1  紫外感光纸及靶环示意图
“雁过留痕”任务属于竞速过程中的附加任务，其完成情况直接影响最终成绩。若比赛过程中遗漏M个留痕目标，则在原有竞速时间基础上增加5M s的罚时；若紫外光照射到圆形目标区域外，则对应留痕任务判定失败。因此，参赛车模不仅需要追求较高的行驶速度，还必须兼顾目标检测、目标定位、照射控制和运动稳定性，避免因漏检、定位误差或车体振动造成任务失败。
在传感器使用方面，规则明确规定本组别只允许使用一个摄像头用于赛道检测，不允许再使用其他光电管对赛道及感光纸进行检测。这一限制要求视觉系统同时承担赛道信息提取和留痕目标识别任务，并在有限计算资源下兼顾图像处理实时性与识别可靠性。
基于上述赛题要求，本车模系统的总体设计目标是在满足竞赛规则和器材约束的前提下，实现“稳定循迹、快速通行、准确识别、可靠留痕”的统一：一是保证车模能够稳定通过直道、弯道、十字路口、环岛、坡道及路障等赛道元素；二是利用单摄像头实时获取赛道与目标信息，准确识别紫外感光纸上的圆形区域；三是完成车体运动、目标位置与紫外照射机构之间的协同控制，使变色痕迹可靠落在目标区域内部；四是在保证留痕成功率的基础上提高整体运行速度，尽可能降低单圈时间及漏靶罚时，从而获得更优的综合比赛成绩。
1.2  系统设计思路与技术路线
本车模采用“单摄像头感知—主控实时处理—运动闭环控制—留痕执行”的总体技术路线。硬件上，以STC32G144K246为核心控制器，MT9V03X灰度摄像头负责获取赛道图像，图像数据经外置FIFO缓存后送入主控；陀螺仪通过SPI提供车体角速度信息，主控根据视觉中线误差和姿态信息输出PWM控制驱动电机、转向舵机及两台无刷下压力电机，并通过IO口驱动七路留痕激光头完成打靶任务。
感知算法以“降低整帧数组运算量”为主要优化方向。早期方案采用大津法二值化、扫线和边界绘制的传统流程，完整运行时帧率仅约17～18帧/s，即使通过跳行、跳列降低扫线精度，整体也仅提高至约23帧/s。针对STC平台运算资源有限的特点，本车模改用直接处理灰度图像的对比度搜线方法，通过参考点灰度、最长白列以及左右边界搜索获得赛道边线，避免对188×120整幅图像进行重复二值化赋值，从而显著提高实时性。
软件上将视觉处理划分为图像获取、图像预处理和图像后处理三个相对独立的阶段。图像获取阶段采用双缓冲与指针交换方式锁定完整图像帧，预处理阶段完成快速搜线并写入lineinfo结构体，后处理阶段完成十字、圆环、斑马线、路障、坡道等赛道元素判断以及补线处理。最终由控制层根据赛道边界、元素状态和留痕目标位置生成转向、速度及激光控制指令，实现竞速与留痕任务的协同。
1.3  相关方案与资料综述
在视觉循迹方案调研中，传统智能车摄像头算法通常采用“大津法求阈值—整帧二值化—逐行搜线—边界补线”的处理流程。该方法结构清晰、元素识别资料较成熟，但在STC平台上需要频繁访问并改写大尺寸图像数组，运算时间较长。队内测试表明，完整传统流程仅能达到约17～18帧/s，降低扫线密度后仍只有约23帧/s，因此继续在二值化框架内优化的收益有限。
为提高实时性，本车模参考逐飞开源方案中的灰度对比度搜线思想，不再生成完整二值化图，而是直接在灰度图上寻找参考灰度、最长白列并向两侧搜索赛道边界。该方法与原有lineinfo数据结构兼容，可在保留已有十字、圆环等后处理逻辑的同时显著降低前处理开销。摄像头采集速率设置为100帧/s时，O7优化后的整体处理帧率可基本跟随摄像头采集速率。
针对高速运动下图像采集和处理不同步的问题，队内进一步采用双缓冲/指针交换方案，将图像写入区与算法读取区分离，避免DMA/FIFO更新图像时造成混帧和撕裂。与整帧复制到临时数组相比，该方案几乎不增加大规模数据搬运，仅带来约1～3 ms的指针交换及缓冲切换延迟。对于斑马线等特殊元素，方案参考历届开源资料，根据参考白列的纵向跳变特征进行识别；逆透视方法也已在STC平台完成初步移植，单次运算约1～2 ms。
1.4  主要工作与报告结构
本队围绕“有限算力下的高速视觉循迹与留痕目标识别”开展了针对性设计。主要工作包括：完成传统二值化方案的分模块耗时测试并定位性能瓶颈；构建直接面向灰度图像的对比度搜线方法；采用双缓冲与指针交换保证高速采集时的帧一致性；在快速搜线结果上复用并移植十字、圆环、斑马线、路障和坡道等元素处理逻辑；完成逆透视算法的初步移植，并针对留痕圆形靶提出双向扫描极值点的中心定位方案。
本报告第一章介绍赛题任务、总体设计思路及视觉方案选型；第二章说明系统总体组成、硬件与软件架构以及任务流程；第三章介绍机械结构与安装；第四章介绍主控、电源、驱动和接口电路；第五章重点说明单摄像头感知方案、图像处理流程及实时性测试；第六章介绍运动控制、任务状态机和执行机构控制；第七章给出制作调试和实验验证过程；第八章汇总模型车主要技术参数；第九章总结系统性能并提出进一步改进方向。

第二章  系统总体方案
2.1  系统总体组成
模型车系统由机械车体、主控制器、视觉感知模块、姿态测量模块、运动执行模块、留痕执行模块和电源模块组成。主控采用STC32G144K246，负责图像处理、赛道元素判断、运动控制以及留痕任务调度。视觉部分采用单个MT9V03X灰度摄像头，并通过外置FIFO完成图像缓存，满足本组别只使用一个摄像头进行赛道及目标检测的规则要求。
运动执行部分包括车模原有驱动电机与转向舵机，以及两台T-MOTOR无刷电机。驱动电机完成车速控制，舵机完成转向控制，无刷电机用于提供下压力，提高高速通过弯道时的附着能力。留痕部分采用七路高功率激光头，主控IO经多路达林顿管进行驱动，根据目标识别结果选择相应光路完成照射。
电源由鹰牌3S 2200 mAh电池提供，实际使用电压通常为12.2～12.6 V。系统通过多路DC-DC和LDO产生不同电压等级，其中7.1 V支路独立供给SU400舵机，3.3 V LDO独立供给摄像头，其他逻辑与执行模块由相应5 V及3.3 V电源供电。各模块围绕主控形成“感知输入—计算决策—执行输出”的闭环系统。
2.2  硬件系统总体架构
摄像头输出的灰度图像首先进入外置FIFO缓存，主控读取完整图像后进行赛道边界和目标处理；陀螺仪通过SPI总线向主控提供角速度信息。主控将视觉处理得到的赛道中线误差与姿态信息结合，生成驱动电机和转向舵机的PWM控制量，同时输出PWM控制两台无刷电机提供下压力。留痕任务触发后，主控通过普通IO控制达林顿管阵列，驱动相应激光头完成目标区域照射。
电源系统采用分级、分路供电方式，舵机7.1 V支路与逻辑电源相对独立，减小舵机大电流变化对主控和摄像头的干扰；摄像头采用3.3 V LDO供电，以获得较稳定的模拟/数字供电条件。硬件架构在满足功能的同时尽量减少额外传感器和通信链路，降低系统复杂度。

2.3  软件系统总体架构
软件采用分层、模块化结构。底层驱动负责摄像头/FIFO、SPI、PWM、GPIO以及定时器等外设；图像采集层负责接收摄像头数据并维护双缓冲；视觉预处理层完成灰度对比度搜线并将左右边界写入lineinfo结构体；视觉后处理层根据边界形态识别十字、圆环、斑马线、路障和坡道等元素，并根据需要进行补线。
控制决策层读取赛道边界、中线误差、元素状态和陀螺仪角速度，根据当前任务状态选择相应速度与转向策略；执行层统一输出驱动电机、舵机、无刷电机和激光头控制信号。调试阶段通过串口/GUI输出FPS、预处理耗时、元素处理耗时以及关键状态变量，以便快速定位算法瓶颈并调整参数。
考虑STC平台RAM和访问效率限制，大数组及低频调用的大结构体可按需要放置在far区域，高频访问的边界结构尽量保留在访问开销较小的存储区。同时工程采用NOOVERLAY设置，避免复杂调用关系下局部变量复用造成异常。

2.4  任务执行流程
系统上电后依次完成主控、摄像头/FIFO、陀螺仪、电机与舵机、无刷电机以及激光驱动模块初始化。摄像头开始连续采集灰度图像，当一帧采集完成后通过双缓冲指针交换锁定当前完整图像，并立即将另一缓冲区交给后续采集。
对锁定图像先执行对比度搜线，获得左右边界和丢线信息，再进行赛道元素判断与补线；根据左右边界计算赛道中线及车辆横向偏差，并结合陀螺仪角速度生成转向与速度控制量。车辆运行过程中持续判断十字、圆环、斑马线、路障、坡道以及留痕目标等状态，并根据不同元素切换相应处理策略。
当检测到留痕目标后，视觉模块估计目标在图像中的位置，任务状态机根据目标位置和车体运动状态确定照射时机，并控制对应激光头工作；完成照射后退出留痕状态并继续循迹。车辆完成赛道一周后进入结束状态，停止或按比赛要求完成终点处理。
2.5  关键技术指标与设计取舍
本系统的核心取舍是优先保证视觉链路的实时性和帧一致性。在传统大津法二值化框架下，完整处理只有约17～18帧/s；通过跳行、跳列减少遍历虽然可提高到约23帧/s，但会直接损失边界精度且总体收益有限，因此最终采用直接灰度对比度搜线。摄像头通常设置为100帧/s，在O7优化后整体处理可基本跟随采集速度；研究中也将摄像头最高设置到约130帧/s。
为避免高速采集时出现撕裂帧，系统采用双缓冲而不是整帧复制。指针交换约增加1～3 ms开销，但可以保证每次算法处理的都是完整单帧图像，即使处理速度低于采集速度，也只会发生跳帧而不会混帧。实际使用时两个缓冲区首地址需保持一致的奇偶/对齐特性，避免DMA/FIFO按16位访问时出现交替帧位置抖动。
在功能完整性与算力之间，赛道基础边界提取采用轻量算法，复杂元素识别放在后处理阶段按需执行。逆透视虽然可在STC平台运行且单次耗时约1～2 ms，但需要额外标定且会增加计算量，因此作为进一步提升循迹几何一致性的可选模块，而非所有状态下的强制处理。

第三章  机械结构与总体装配
3.1  车模总体机械结构
本车采用博思威龙C车模作为基础机械平台，并针对“雁过留痕”组的高速循迹与激光留痕任务进行结构改造。整车保留原有四轮阿克曼转向机构，在车头、激光执行机构及负压系统位置进行重新布局，以降低重心、减轻附加质量并保证激光照射路径畅通。
为避免原车舵机前方的底盘伸出结构遮挡激光光路，对该部分底盘进行了切除处理，使位于车头低位的激光能够直接照射赛道目标区域。该改造同时减少了车头冗余质量，为激光固定件留出了安装空间。
3.2  特殊执行机构结构
针对留痕任务，自行设计激光头固定件并安装于SU400舵机正前方，使七路高功率激光头尽可能靠近底盘布置，从而降低新增执行机构的重心。原激光头钢制外壳质量较大，因此另行设计轻量化改造外壳，在保证固定可靠的前提下降低车头质量。
两台T-MOTOR无刷电机构成负压下压力系统，并采用自制负压风扇固定件与车体连接。固定结构兼顾安装强度、风道空间和维护便利性，使负压系统在高速行驶和过弯时能够稳定工作。
3.3  传感器安装与布局
总钻风摄像头安装在车模前方碳素杆上，通过调整碳素杆位置确定摄像头高度与俯角，使单摄像头同时获得赛道边界和留痕目标所需视场。
IMU660RA安装在有刷电机上方的龙邱双车组别蓝色摄像头支架安装板上。该位置与车体连接可靠，可减小线束摆动和安装松动对角速度测量的影响，同时避开舵机、激光机构与负压风扇的运动空间。
3.4  电路板与线束安装
整车PCB主要使用铜柱固定在车模中部偏后区域。主控制板与有刷电机驱动板采用短铜柱上下叠放，在充分利用底盘面积的同时降低电路板安装高度，有利于降低整车重心。
两台T-MOTOR分别使用两块独立电调进行驱动，电调安装于负压电机驱动板紧上方，使MOS管能够利用负压风扇工作时形成的气流辅助散热。实际调试过程中未出现MOS管过热击穿现象，表明该布局具有较好的散热与运行可靠性。
动力电池安装于主控制板前方，并使用专用电池扎带固定。在摄像头支架安装板上另布置功能副板，用于按键、旋转编码器以及无线串口和WiFi模块的连接，减少主板周围线束堆叠并方便现场调试。整车线束按照传感器信号、控制信号和动力供电分类布置，避免与舵机、激光机构和负压风扇发生干涉。
3.5  重量、尺寸与规则符合性

4.2  电源系统设计
整车采用鹰牌3S 2200 mAh电池供电，实际使用电压通常为12.2～12.6 V。由于主控、摄像头、舵机、通信模块及各驱动单元的工作电压和对电源纹波的敏感程度不同，系统采用多路DC-DC与LDO相结合的分立供电方案，形成7.1 V、5 V和3.3 V等电源轨。

4.3  电机 / 舵机 / 执行器驱动电路

SU400舵机由PA.0输出PWM控制，7.1 V独立电源为其提供动力。两台T-MOTOR负压电机由两块独立电调驱动，主控分别通过PA.1和PA.3输出PWM调节其转速。

4.4  传感器接口电路
总钻风摄像头通过外置FIFO与主控连接。图像数据D0～D7采用P2.0～P2.7八位并行总线读取，同时使用WEN、WRST、RCK、RRST和OE等信号完成FIFO读写控制。该方式将摄像头连续采集与主控图像处理相对解耦，为双缓冲和完整帧处理提供硬件基础。
IMU660RA采用SPI接口，SCK、MOSI、MISO和CS分别连接P8.7、P8.5、P8.6和P3.4，用于获取车辆角速度等运动状态。左右轮编码器使用P4.0、P4.2、P6.0和P6.2四路输入，为速度闭环和差速控制提供反馈。
4.5  通信接口设计
系统设置普通串口、无线串口模块、无线SPI/WiFi模块和显示屏接口，用于程序下载、参数调试和状态监测。普通串口使用P0.5/P0.4作为Tx/Rx；无线串口模块使用P9.3、P9.2、P9.4和P5.4；无线SPI模块与显示屏复用P8.2、P8.3和P8.1等总线信号，并通过独立片选及控制信号区分不同外设。
按键、旋转编码器、无线串口及WiFi连接集中布置于功能副板，蜂鸣器控制端使用P5.1。通过将高频操作和调试接口从主板中独立出来，降低主板周围接线复杂度并提高现场维护便利性。
4.6  自制PCB设计

第五章  感知与传感系统
5.1  赛道环境信息检测方案
受组别规则限制，本车模仅使用一个摄像头承担赛道检测和留痕目标识别任务。视觉传感器采用MT9V03X灰度摄像头，图像在当前配置下以188×120数组形式进入处理链路。系统不依赖额外光电管进行赛道判断，而是从灰度图像中直接提取左右边界、赛道中线及元素特征。
赛道检测采用“快速边界提取+元素后处理”的结构。首先利用灰度对比度搜线获得基础左右边界，再由后处理模块根据边界丢失、跳变、形状及补线结果识别十字、圆环、斑马线、路障和坡道等赛道元素。相比对整帧图像先二值化再搜线的方法，该结构减少了大规模数组赋值和遍历，更适合STC平台实时运行。
5.2  姿态、位置与距离测量
车辆相对赛道的位置主要由视觉边界计算得到。根据每一行左右边界位置计算赛道中心，并在选定前瞻区域内形成中线误差，作为转向控制的主要输入。采用逆透视时，可将图像边界转换到鸟瞰坐标系，并结合车轮位置标定计算边界相对车轮的几何斜率，为转向量计算提供更接近地面坐标的几何信息。
车体姿态变化由陀螺仪/IMU提供角速度信息，主控通过SPI读取后用于辅助判断车辆转向动态及控制稳定性。对于坡道等与姿态变化相关的元素，现阶段代码已预留相应判据。
5.3  视觉感知方案
传统方案首先利用大津法计算阈值，再对整幅188×120图像执行二值化，随后调用scan_line完成搜线并绘制边界。分模块测试表明，只要涉及整幅图像数组的赋值和计算，运行时间就明显增加。由于二值化本身几乎没有进一步减少运算量的空间，而跳行、跳列搜线又会牺牲边界精度，因此最终放弃将完整二值图作为后续算法的基础。
本车模采用的对比度搜线直接在灰度图上工作：先获取参考点灰度值，再搜索最长白列作为稳定参考，从该参考列向左右寻找灰度变化明显的边界位置，最后将结果整理并写入原有lineinfo结构体。这样既保留了成熟的元素后处理接口，又避免了整帧二值化。直道且无明显边界跳变时，研究记录中的预处理耗时约为0～4 ms；在不同元素和测试条件下，预处理耗时一般仍处于毫秒级。
图像后处理在lineinfo基础上完成元素识别。十字处理沿用成熟边界判断与补线逻辑，元素部分典型耗时约0～3 ms；赛道圆环识别加入补线后整体增加约1～2 ms；斑马线识别根据参考白列的纵向灰度/白列跳变次数判断，目前仍需加入zebra_confirm等附加判据进一步验证；路障识别代码已完成移植，但需防止与圆环特征混淆。
对于留痕圆形靶，研究阶段提出两类轻量化中心定位方法：其一从上、下两个方向扫描圆形靶顶点并对坐标取平均，其二从左、右两个方向搜索边缘极值点并求中心。两种方法均只需两次方向性遍历，并可通过隔行或隔列扫描降低运算量。

5.4  数据滤波与融合
视觉数据处理首先解决“同一帧一致性”问题。若摄像头在算法处理上一帧时继续向同一图像数组写入下一帧，会出现撕裂或混帧，影响边界和元素判断。为此系统设置两个图像缓冲区，将采集写入区和算法读取区完全分开；一帧采集完成后仅交换读写指针，不进行整幅图像复制。这样在处理速度暂时低于采集速度时，系统可能跳过部分帧，但不会把两帧内容混合在一次处理过程中。
双缓冲切换的实测额外延迟约1～3 ms。实际调试中还发现，若两个缓冲区首地址的奇偶/对齐关系不一致，在DMA/FIFO按16位方式访问时可能出现相邻帧左右跳动，因此初始化时对两个缓冲区采用一致的地址对齐约束。边界层面则利用lineinfo中的丢线统计、边界连续性及元素状态进行后处理，减少局部异常点对控制量的直接影响。
本系统的多源信息融合主要发生在控制输入层：视觉模块提供赛道中线误差、元素状态和目标位置，陀螺仪提供角速度信息，两者在控制决策层共同参与转向与状态切换。
5.5  检测精度与更新频率
视觉实时性通过串口输出FPS、预处理耗时（PROC_MS）和元素处理耗时（ELEM_MS）进行测试。传统“大津法二值化+搜线+画边界”完整流程约为17～18帧/s；通过降低扫线密度只能提高到约23帧/s。改用灰度对比度搜线并进行O7优化后，在摄像头采集速率设置为100帧/s时，记录中的总帧率基本保持在99～101帧/s附近，说明基础视觉链路能够基本跑满摄像头采集速率。
在更高采集设置下，直道状态的预处理记录可达到约0～4 ms；十字元素处理约0～3 ms，圆环补线增加约1～2 ms，双缓冲指针交换约1～3 ms，逆透视单次运算约1～2 ms。由于不同元素会叠加不同后处理模块，实际更新率随赛道状态变化，因此最终以控制周期内获得有效lineinfo和元素状态的频率作为视觉有效更新频率。 留痕目标检测在实际任务链路中的有效更新频率约为80 Hz，与100帧/s的摄像头采集频率区分统计。

第六章  控制算法与软件设计
6.1  软件工程结构
整车软件围绕“图像采集—视觉处理—状态判断—运动控制—任务执行”的数据链路进行模块化设计。底层驱动负责摄像头/FIFO、SPI、PWM、GPIO、编码器及定时器等外设；图像采集模块维护双缓冲；视觉预处理模块完成灰度对比度搜线并将边界写入lineinfo结构体；视觉后处理模块完成十字、圆环、斑马线、路障、坡道及留痕目标等元素判断。
控制层读取赛道中线误差、边界状态、元素状态、编码器轮速及IMU660RA角速度，计算舵机、左右驱动轮和负压电机控制量。任务层依据当前元素与留痕目标状态决定运行模式和激光执行时机。图像处理在完整帧准备后执行，运动控制使用最新有效感知结果持续更新，以减少大规模图像运算对控制实时性的影响。
6.2  运动控制算法
车辆方向控制以视觉系统得到的横向误差为主要输入。程序计算当前误差及相邻周期误差变化量，通过方向控制器得到舵机PWM，并叠加舵机中值与安装修正量输出至SU400舵机。普通循迹状态下可根据误差及赛道变化程度进行模糊参数调整；进入圆环等特殊元素后暂停常规模糊参数更新，避免元素补线与普通循迹参数相互干扰。
车辆采用四轮阿克曼结构。转弯时内外侧驱动轮的运动半径不同，程序根据舵机转角计算差速比例，分别生成左右轮目标速度。左右轮编码器反馈进入增量式PID速度环，基本形式为：Δu(k)=Kp[e(k)-e(k-1)]+Ki·e(k)+Kd[e(k)-2e(k-1)+e(k-2)]。其中e(k)为目标速度与实际速度之差。
在高速弯道中，系统还根据赛道弯曲程度和当前转向方向加入转向补偿量，使大曲率状态下获得更快的方向响应；离开弯道后补偿逐渐恢复为零。
6.3  特殊执行机构控制
两台T-MOTOR无刷电机通过独立电调驱动，主控输出两路PWM控制其转速。车辆启动后负压电机按照基础设定运行，并根据当前转向方向和赛道弯曲程度对左右下压力进行补偿，以改善高速弯道中的附着与转向一致性。
留痕系统使用7个固定激光头。视觉模块确认目标后，根据目标在图像中的横向位置选择激光通道，主控通过ULN2803ADWRG4驱动对应激光头。任务状态机同时结合目标位置和车辆运动状态确定照射时机，完成照射后退出留痕状态并恢复正常循迹。固定多路激光方案避免了额外机械扫描机构带来的动作延时和重心增加。
6.4  任务状态机与决策逻辑
整车任务控制采用基于赛道元素状态的状态机结构。系统初始化后进入普通循迹，视觉模块持续输出左右边界、中线误差和元素检测结果。识别到十字、圆环、路障或坡道等特殊元素后，程序切换至对应补线和控制策略；满足退出条件后恢复普通循迹。
留痕目标作为独立任务状态处理。目标经过确认后，程序记录其位置并进入留痕执行状态，选择对应激光通道完成照射后清除状态。斑马线用于终点或特定任务阶段判断，并通过跳变计数和连续帧确认降低单帧误判。系统总体状态流程如图6.1所示。

6.5  核心算法实现
核心算法处理链为：摄像头完成一帧采集后交换双缓冲指针；获取参考区域灰度并搜索稳定参考列；直接在灰度图中提取左右边界并写入lineinfo；统计丢线、宽度和边界连续性；判断十字、圆环、路障、坡道、斑马线及留痕目标；根据元素状态进行补线并计算中线误差；方向控制器生成舵机PWM，阿克曼差速模块生成左右轮目标速度，编码器速度环输出有刷电机控制量；最后根据赛道状态调整负压电机，并在留痕条件成立时触发相应激光通道。完整核心程序见附录B。
6.6  安全保护机制
软件设置运行超时和速度堵转保护。车辆进入运行状态后持续累计运行时间，超过设定上限时主动停车并报警。堵转保护联合编码器速度与电机PWM判断：当实际速度长期接近零而驱动输出持续较大时，仅在异常持续多个控制周期后触发保护，以避免瞬态波动造成误判。
保护触发后立即停止有刷电机输出并清除左右速度环积分，防止解除故障后历史积分导致电机突然大幅输出。视觉链路采用双缓冲和统一地址对齐方式，减少混帧、撕裂和相邻帧位置跳变，从数据源头降低异常控制量产生概率。

第七章  制作、调试与实验验证
7.1  开发工具与制作环境
整车开发包括机械结构设计、电路设计、嵌入式程序开发和实车赛道调试。软件在STC32G144K246平台完成编译、下载和运行，通过串口及GUI输出FPS、视觉处理耗时、元素处理耗时、方向误差、轮速及状态变量用于调参。硬件采用嘉立创EDA完成主板、副板及驱动板设计，并结合车模结构制作激光固定件、负压风扇固定件及轻量化激光外壳。
7.2  系统安装与联调过程
系统联调按照“电源检查—传感器测试—执行机构测试—视觉算法测试—闭环控制—完整赛道运行”的顺序进行。首先检查3.3 V、5 V和舵机7.1 V电源，再验证摄像头/FIFO图像读取、IMU660RA SPI通信和编码器反馈；随后分别测试SU400舵机中值与方向、RS380有刷电机、两路无刷电调以及七路激光通断。
基础模块正常后，先在静态赛道验证左右边界提取，再逐步加入十字、圆环、斑马线、路障和坡道等元素识别。之后进行低速闭环循迹，依次整定方向控制、左右轮速度环和阿克曼差速比例，最后逐步提高目标速度与负压输出，对高速直道和连续弯道进行联合调试。
7.3  关键问题与解决过程
早期视觉算法采用大津法阈值、整帧二值化和搜线，完整流程仅约17～18帧/s，降低扫描密度后也只能提高到约23帧/s。最终改为直接灰度对比度搜线，避免对188×120图像重复进行整帧赋值和遍历；开启O7优化后，在100帧/s摄像头配置下整体处理速度可基本跟随采集速度。
高速采集时曾出现算法处理上一帧、摄像头同时改写下一帧造成的撕裂与混帧。系统采用双缓冲和指针交换，将采集区与处理区分离，只在帧完成时交换指针；实测额外开销约1～3 ms。调试中还发现双缓冲首地址对齐不一致会造成相邻帧位置交替偏移，最终通过统一地址对齐方式消除。
两台负压无刷电机工作电流较大，对电调MOS管散热要求较高。两块分立电调安装在负压风扇附近，使风扇工作气流同时经过电调区域辅助散热；实际调试过程中未出现MOS管过热击穿现象。
7.4  实验设计与测试结果
系统主要对视觉实时性、图像帧一致性、留痕目标更新频率和高速运行能力进行验证，阶段性测试结果见表7.1。

7.5  系统性能总结
现阶段系统已形成从单摄像头图像采集、赛道边界提取和元素识别，到方向控制、左右轮速度闭环、负压下压力调节和七路激光执行的完整链路。灰度对比度搜线与双缓冲优化显著提高了视觉实时性和帧一致性，阿克曼差速、编码器速度闭环及负压系统提高了高速运行条件下的稳定性，实车阶段性最高速度达到约3.5 m/s。系统的主要限制仍在于复杂元素及留痕任务缺少足够的标准化重复统计。

第九章  结论与展望
9.1  工作总结
本项目围绕第二十一届全国大学生智能汽车竞赛“雁过留痕”组任务，完成了一套集高速循迹、赛道元素识别、负压下压力控制和激光留痕于一体的四轮阿克曼智能车系统。硬件以STC32G144K246为核心，单总钻风灰度摄像头承担赛道与留痕目标检测，IMU660RA和左右轮编码器提供运动状态信息；SU400舵机与RS380有刷电机构成基础运动系统，两台T-MOTOR无刷电机提供下压力，七路100 mW激光头执行留痕任务。
针对STC平台算力限制，视觉算法由传统整帧二值化改为直接灰度对比度搜线，并采用双缓冲与指针交换保证帧一致性。优化后基础视觉链路可基本跟随100帧/s摄像头采集速度，留痕目标有效检测频率约80 Hz。控制系统实现方向控制、阿克曼差速、左右轮增量式PID速度闭环、转向与负压补偿以及激光任务状态机，阶段性最高实车速度达到约3.5 m/s。
9.2  存在问题
系统仍存在进一步提升空间。单摄像头同时承担赛道和留痕目标识别，高速运动及复杂元素并存时对实时性和鲁棒性要求较高；圆环、路障等局部特征在特定视角下可能出现相似性，需要依靠元素互斥、边界连续性和多帧确认进一步降低误判。
高速运行时摄像头振动、车体姿态变化和目标快速位移会影响留痕定位及激光触发时机。两台负压电机工作电流较大，也是整车主要功耗与热负荷来源。此外，部分速度、方向和负压参数仍主要依靠实车经验整定，轮胎状态、场地摩擦系数及电池电压变化时需要重新调整。
9.3  改进方向
后续可继续从机械、电气、视觉与控制四方面优化。机械上进一步减轻激光固定件和负压风道质量、降低重心并抑制高速振动；电气上增加大电流支路电压/电流在线监测，根据电池状态动态限制负压输出，提高供电安全性和续航。
视觉上可在灰度对比度搜线基础上完善特殊元素互斥与连续帧跟踪，并对留痕目标引入运动预测，提高高速条件下的定位稳定性；控制上进一步结合IMU角速度、视觉曲率和车速动态调整方向增益、目标速度及左右负压输出。后续还应建立统一实车测试流程，对各元素识别和留痕任务进行重复统计，使优化建立在可量化、可复现的数据基础之上。

B.1.2  阿克曼差速与双电机速度闭环
车辆运行时根据舵机转角计算左右轮差速比例，并分别以增量式 PID 对两侧编码器速度进行闭环控制，最终输出至电机驱动。
void common_running()
{
    if(mycar.car_running == 1)
    {
        fan_begin(setpara.fan_start);
    }

    if(mycar.car_running == 2)
    {
        mycar.speed_differ =
            (float)tan_value((double)((float)mycar.steer_pwm
            * 3.1415926535 / 1800.0f / 2.0f))
            * (float)setpara.differ_ratio / 100.0f;

        if(mycar.speed_differ > 0.95f)  mycar.speed_differ = 0.95f;
        if(mycar.speed_differ < -0.95f) mycar.speed_differ = -0.95f;

        mycar.speed_left_differ  = mycar.speed_differ;
        mycar.speed_right_differ = mycar.speed_differ;

        mycar.target_left_speed = mycar.target_speed *
            (1 - 2 * mycar.speed_left_differ /
            (1 + mycar.speed_left_differ));
        mycar.target_right_speed = mycar.target_speed *
            (1 + 2 * mycar.speed_right_differ /
            (1 - mycar.speed_right_differ));

        mycar.left_pwm_set = -PID_Incremental(
            &Speed_left, mycar.left_speed, mycar.target_left_speed);
        mycar.right_pwm_set = -PID_Incremental(
            &Speed_right, mycar.right_speed, mycar.target_right_speed);

        set_pwm((int)mycar.left_pwm_set, (int)mycar.right_pwm_set);
        fan_begin(setpara.fan_start);
    }
}

void steer_buchang_cal()
{
    if(mycar.corner_flag == 2 && watch.track_count >= 70)
        mycar.steer_buchang =
            setpara.steer_buchang * (watch.track_count - 70) / 15;
    else if(mycar.corner_flag == 1 && watch.track_count >= 70)
        mycar.steer_buchang =
            -setpara.steer_buchang * (watch.track_count - 70) / 15;
    else
        mycar.steer_buchang = 0;
}

void fan_buchang_cal()
{
    if(Element == None || Element == Left_ring || Element == Right_ring)
    {
        if(mycar.corner_flag == 2 && watch.track_count >= 55)
        {
            mycar.fan_buchang = (float)setpara.fan_differ_ratio *
                                (85 - watch.track_count) / 3000;
            if(watch.track_count < 55)
                mycar.fan_buchang =
                    (float)setpara.fan_differ_ratio / 100;
        }
        else if(mycar.corner_flag == 1 && watch.track_count >= 55)
        {
            mycar.fan_buchang = (float)-setpara.fan_differ_ratio *
                                (85 - watch.track_count) / 3000;
            if(watch.track_count < 55)
                mycar.fan_buchang =
                    (float)-setpara.fan_differ_ratio / 100;
        }
        else if(mycar.corner_flag == 0)
        {
            mycar.fan_buchang = 0;
        }

B.1.4  运行保护核心判据
运行保护模块对持续堵转、超时以及赛道元素相关异常进行计数判断。以下列出工程中速度堵转保护的核心逻辑；保护触发后停止车辆并清除速度环积分，避免电机持续大电流输出。
void running_protect()
{
    static int danger_time_speed;

    if(mycar.car_running == 2)
    {
        mycar.RUNTIME++;

        if(mycar.RUNTIME > 30000)
        {
            mycar.RUNTIME = 0;
            car_stop();
            if(mycar.stop_mode == 0) stop_warning();
            mycar.stop_mode = 1;
        }

        if(mycar.RUNTIME > 1000 && Element != zebra)
        {
            if((mycar.left_speed < 1 && abs(mycar.left_pwm_set) > 1000) ||
               (mycar.right_speed < 1 && abs(mycar.right_pwm_set) > 1000))
            {
                danger_time_speed++;
                if(danger_time_speed > 200)
                {
                    danger_time_speed = 0;
                    mycar.car_running = 0;
                    car_stop();
                    stop_warning();
                    clear_integral(&Speed_left);
                    clear_integral(&Speed_right);
                    if(mycar.stop_mode == 0) mycar.stop_mode = 2;
                }
            }
            else if(danger_time_speed > 0)
            {
                danger_time_speed--;
            }
        }
    }
}

    (lineinfo[y].persp_rx - 97) /
    (lineinfo[y].persp_ry + 31);
除上述程序外，十字、圆环、路障、坡道和留痕靶定位等模块均以 lineinfo 与元素状态变量为统一接口进入图像后处理层。完整工程中相关源文件与本附录代码共同构成“图像采集—快速搜线—元素识别—控制决策”的处理链路。
