 摘要
本技术报告介绍中国计量大学赛博-1队为第二十一届全国大学生智能汽车竞赛“雁过留痕”组别设计的智能车系统。该组别要求车模在室内PVC赛道上自主循迹行驶的同时，利用紫外激光在紫外感光纸上精准留痕，对高速循迹能力与精准定位能力提出了双重挑战。
系统采用四轮C车模，以STC32G144K246为主控核心，总钻风摄像头采集赛道图像，1024线编码器实现速度闭环，IMU963RA陀螺仪辅助姿态控制。硬件方面采用两级电源架构，由DRV8701E驱动有刷电机实现差速转向，增设无刷电调驱动涵道风扇产生主动下压力以提升高速过弯抓地力。软件方面采用优化大津法进行图像二值化，八邻域搜线提取赛道边界，通过状态机识别环岛等特殊元素；转向采用位置式PD结合陀螺仪阻尼控制，速度采用增量式PI结合分层速度策略。激光打靶通过摄像头识别靶标位置实现精准留痕。经赛道验证，系统实现了稳定循迹行驶与高成功率留痕功能，达到预期目标。

关键词：智能车；摄像头循迹；图像处理；PID控制；主动下压力；激光打靶。

第一章  绪 论
1.1智能车概述
智能车是一种集环境感知、自主决策与运动控制于一体的综合性系统，是人工智能与机器人技术的重要应用方向之一。它综合运用了自动控制、模式识别、传感技术、计算机科学、机械工程等多学科知识，通过传感器获取环境信息，由处理器进行数据分析和路径规划，最终由执行机构完成转向和速度的控制。随着传感器成本降低、处理器算力提升以及图像处理算法的持续进步，智能车技术正从实验室研究加速走向自动驾驶、无人物流等实际应用场景，具有广阔的发展前景。
全国大学生智能汽车竞赛是由教育部高等学校自动化专业教学指导委员会创办的一项面向全国大学生的工程实践活动，自2006年以来已成功举办二十届，是国内最具影响力的大学生科技竞赛之一。该竞赛以统一硬件平台为基础，要求参赛队伍自主设计算法与控制策略，使模型车在指定赛道中自主循迹并快速完赛，全面锻炼了学生的理论分析能力、工程实践能力和团队协作能力。
1.2 方案总体介绍
本参赛队伍参加的是第二十一届全国大学生智能汽车竞赛“雁过留痕”组别。该组别属于室内赛道竞赛项目，要求制作一辆四轮竞速车模，在室内PVC赛道上完成自主循迹行驶，同时完成激光打靶任务。车模需要通过紫外LED照射紫外感光纸使其变色并留下痕迹，对车辆的识别精度、停车定位和精准控制能力提出了较高要求。
针对上述竞赛规则，本系统方案如下：主控采用STC系列单片机，使用总钻风摄像头采集赛道图像，经图像处理提取赛道中心线实现循迹；编码器实时检测车速，实现速度闭环控制；舵机与电机分别采用PD与PI控制算法，确保车模稳定通过直道、弯道、十字、环岛、坡道、路障等赛道元素。激光打靶方面，通过摄像头识别紫外感光纸靶标位置，使紫外激光在合适的时机开关，实现精准留痕。系统配备显示屏与按键用于参数调试，便于赛场快速整定。本系统围绕“高速循迹”与“精准留痕”两大任务，从机械、硬件、软件三个层面进行设计，力求在保证竞速性能的同时稳定完成打靶任务。




机械系统设计与实现
2.1 整车布局
本系统采用竞赛组委会指定的四轮C车模。整车布局以重心合理分布为原则，电池放置于车模中部涵道内，有效降低整车重心并集中在车体中心位置；主控电路板固定于车模后部，通过铜柱支撑，与底盘保持一定间距，避免震动干扰；紫外激光模块安装于车模前部，一排激光管水平排列，朝向正前方；摄像头安装于车头合适位置，与激光模块保持合理间距；编码器分别固定于左右后轮电机输出轴一侧，通过齿轮啮合采集速度信息。整车布局力求紧凑，重心较低，各模块间连线整齐，便于安装与维护。

2.2 前轮定位
前轮定位对赛车的行驶性能有着重要影响。虽然车模尺寸较小，但前轮定位参数直接关系到直线稳定性、转向响应特性以及轮胎磨损程度。前轮定位主要包含主销后倾、主销内倾和前轮前束三项内容。合理的前轮定位应使车模在直道行驶时阻力较小，同时在转向过程中不产生过大的垂向分力，否则会限制车模的速度上限和弯道性能。

2.2.1 主销后倾
主销是转向轮围绕其旋转的虚拟轴线，前轴载荷通过主销传递至转向轮。主销在纵向平面内向后倾斜，其轴线与地面垂直线之间的夹角称为主销后倾角。
主销后倾使得前轮重心相对主销轴线产生偏移，当车轮偏离直线行驶方向时，地面侧向反作用力对主销形成回正力矩，推动车轮自动恢复至直线行驶位置。该回正力矩随车速升高而增大，因此主销后倾对车模高速行驶时的方向稳定性起着关键作用。

2.2.2 主销内倾
主销在横向平面内向内侧倾斜，其轴线与地面垂直线在赛车横向断面内的夹角称为主销内倾角。
主销内倾同样具有使转向轮自动回正的功能。当车轮偏转时，前部车体被轻微抬升，外力消失后，车身重力促使车轮恢复至中间位置。但主销内倾角不宜过大，否则转弯时轮胎与赛道之间的侧向滑动加剧，转向阻力增加，同时加速轮胎磨损。

2.2.3 前轮前束
前轮外倾角是指通过车轮中心的横向平面与车轮平面的交线与地面垂线之间的夹角。当车轮上端向外倾斜时为正倾角（呈“V”字形），向内倾斜时为负倾角（呈“八”字形）。前轮外倾可抵消车辆重力导致的车轮向内倾斜趋势，减轻转向机构负荷。
由于前轮外倾使车轮在滚动时具有向外滚开的趋势，但因转向拉杆的约束无法实现，车轮会出现边滚动边向内滑移的现象。为补偿这一趋势，需设置前轮前束，即两前轮前端略向内收，前端距离小于后端距离（内八字）。适当的前束角有助于车模在直道行驶时更好地贴合赛道中线，提升直线跟踪精度。

           
2.3 传感器与执行器安装
传感器与执行器的安装位置直接影响车模的信息采集精度和控制响应速度。本系统主要涉及摄像头、编码器与紫外激光发射器的安装。

2.3.1 摄像头安装：摄像头固定于车模前部专用支架上，高度经调试后确定，兼顾直道前瞻与弯道预判的需求。

2.3.2编码器安装：编码器通过安装支架固定于左右后轮电机一侧，编码器齿轮与电机输出轴齿轮相互啮合。安装时需保证两齿轮轴平行、啮合间隙合适，避免过紧增加传动阻力或过松导致打齿及计数丢失。

2.3.3紫外激光模块安装：紫外激光发射管排列安装于车模前部专用支架上，一排激光管水平布置，照射方向朝向前方。安装后需进行光轴标定，确保各激光管照射区域与摄像头视野中心区域一致，以保证瞄准精度。

2.4 电路板固定与线材整理

系统电路板通过尼龙柱或铜柱支撑固定于车模底盘上，采用四点固定方式，确保电路板在高速行驶和震动条件下保持稳定。各模块间连接线使用扎带统一整理，避免线材松散干扰运动部件，同时便于检修时快速拆卸。






















硬件系统设计及实现
3.1 硬件部分概述
本系统硬件电路采用STC32G144K246作为主控核心,负责总钻风摄像头图像采集、赛道识别、传感器数据融合及整车控制算法等任务，实现整车运行。不同于主流的核心板加主板的方案，本车采用裸片直接焊接在主板上的方案，以实现电路板轻量化、缩小化的目的。两路STC32G12K128电调模块分别驱动左右无刷电机。

3.2 电源电路设计
本系统采用3S锂电池供电（额定电压12.8V）。由于各模块工作电压差异较大，采用两级电源架构——第一级由两路TPS54531 DC-DC降压芯片将12.8V转换为5V电源轨以及7.4V舵机供电电压，第二级由RT9013 LDO将5V进一步降压至3.3V，为不同模块提供稳定供电。

3.2.1 第一级降压：TPS54531（5V/7V DC-DC）

TPS54531是德州仪器推出的一款 SWIFT™ 架构降压 DC/DC 转换器，其主要特性如下：
宽输入电压范围：3.5V ~ 28V，可从容应对 12V/24V 电压总线，并支持可编程欠压锁定（UVLO）。
最大输出电流：5A，满足中等功率负载需求。
输出电压：可调输出，最低可至 0.8V，通过外部电阻灵活配置 5V 及其它电压轨。
高效率：12V 输入转 5V 输出时峰值效率约 90%，内置 80mΩ 低导通电阻高边 MOSFET 减小损耗。
轻载管理：轻载时自动进入脉冲跳频模式，显著提升待机效率，关断电流低至 1μA。
固定开关频率：570kHz 定频设计，支持陶瓷输出电容，简化外部补偿。
封装：8 引脚 SO PowerPAD™（HSOIC）热增强封装，配合外露散热焊盘，2A 负载下仍可稳定散热。
本系统采用两路TPS54531，分别用于：
1. 5V：为TFT屏幕、编码器、TOF模块和蜂鸣器供电，以及作为所有3.3V降压的供电源。
2. 7.4V：为舵机提供充足的供电，保证舵机快速响应。

本系统采用两片DRV8701E栅极驱动器 + 外部N沟道MOSFET构成双路独立H桥驱动方案，分别控制C车模的左右驱动电机。通过PWM信号控制电机转速、通过PH引脚控制转向，实现左右轮独立调速与差速转向。

3.5 本章小结

本系统硬件电路采用主控与驱动主板一体化设计，以STC32G144K246为主控核心负责赛道识别、传感器融合及控制算法等任务。车模前进动力由两路独立DRV8701E栅极驱动器驱动直流有刷电机提供，通过外部N沟道MOSFET构成H桥实现左右轮差速转向；同时增设两路STC32G12K128无刷电调，分别控制双风扇，在高速过弯时增强抓地力。电源系统基于3S锂电池构建两级架构——两路TPS54531将12.8V降压为独立5V电源轨和7V供电，分别为主控和外设供电；后级经RT9013降压至3.3V，为IMU及按键等外设提供稳定电源，确保各模块供电独立。DRV8701E动力驱动与STC32G12K128电调在电源分配、控制信号上各自独立，确保高速运动中动力与下压力的协同配合。整体硬件设计遵循功能分区、功率与信号隔离、单点接地等原则，兼顾轻量化与结构紧凑性，为控制算法的稳定运行提供了可靠的硬件平台。


第四章 软件系统设计及实现
4.1 灰度图像处理思路
图像采集是整个软件流程的起点，其质量直接影响后续所有处理环节的效果。本系统使用总钻风数字摄像头采集赛道图像，通过主控MCU的DMA通道直接读取图像数据，减少CPU干预，提高采集效率。
摄像头输出的原始图像分辨率为188×120像素，灰度范围为0~255。该分辨率在保证赛道细节完整的前提下，有效控制了单帧图像的数据量。考虑到实际赛道识别对细节的要求以及MCU的运算能力，原始图像尺寸适中，既可满足远瞻距离需求，又不会造成过大的存储与计算开销。
原始图像中不可避免地包含各类噪声，如摄像头感光元件热噪声、赛道表面反光、光照不均匀等。若直接对原始图像进行处理，这些噪声会干扰赛道边界的准确提取。因此，在进入核心处理流程之前，需要对图像进行预处理。
为降低后续图像处理算法的计算量，同时保留足够的赛道信息，将188×120的原始灰度图像压缩至60×60像素。压缩采用邻近插值或双线性插值方法，在缩小图像尺寸的同时尽量保持赛道边界的清晰度。压缩比的选择兼顾了处理速度和识别精度两个方面的需求。

压缩后的灰度图像需转换为二值图像，将赛道（白色）与背景（蓝色）区分开来。本系统采用大津法（OTSU算法）进行自适应阈值二值化。
大津法是一种基于类间方差最大化的自动阈值选择算法。其基本原理如下：设图像的灰度级为0~255，对于某一阈值T，将像素分为前景（灰度大于T）和背景（灰度小于T）两类。计算两类像素的灰度均值μ0、μ1以及整体均值μ，并根据公式（4.1）计算类间方差σ²(T)：
σ2(T)=ω0​⋅(μ0​−μ)2+ω1​⋅(μ1​−μ)2     （公式4.1）
其中ω0和ω1分别为前景和背景像素所占比例。遍历所有可能的灰度值（0~255），选取使类间方差最大的阈值T*作为最优二值化阈值。

大津法的优势在于能够根据每帧图像的灰度分布自动计算阈值，对不同光照条件具有良好的适应性，避免了固定阈值法在光照变化时出现大范围误判的问题。二值化处理后，图像中的赛道区域表现为白色（灰度值为1），背景区域表现为黑色（灰度值为0），为后续的边界提取和赛道识别奠定了基础。
针对STC32G主控的运算资源特性，我们对大津法进行了以下优化：限定ROI区域为图像底部60%，剔除顶部无效背景像素，降低计算负荷；在遍历灰度级时仅统计实际有效灰度范围，避免对0~255全范围无效扫描。此外，引入帧间阈值平滑机制，将当前帧与上一帧计算结果按9:1加权，有效抑制阈值跳变导致的图像抖动。经实测，单帧大津法计算耗时由约40ms降8ms以内，完整图像处理周期控制在10ms内，为舵机和电机的实时控制留出充足余量，同时保证了在不同光照条件下二值化分割的稳定性。


4.2 基本循迹扫线思路
二值化处理完成后，图像中的赛道区域与背景区域已实现分离，接下来需要从二值化图像中提取赛道的左右边界信息，为中线计算和舵机控制提供依据。本系统采用八邻域搜线算法进行赛道边界提取。

八邻域搜线算法的核心思想是：从图像底部找到一个可靠的边界起始点后，沿着赛道边界逐点向上追踪，通过检查当前像素点周围8个相邻像素（上、下、左、右、左上、右上、左下、右下）的颜色分布，判断边界延伸的方向。相比逐行扫描等传统方法，八邻域算法能够更好地处理弯道、十字路口等复杂赛道场景下的边界连续性问题，在环岛等复杂元素中表现尤为突出。
算法的具体实现分为以下几个步骤：
起点查找：从二值化图像底部向上搜索，在图像下方区域（距底部若干行范围内）从左向右扫描，寻找符合条件的左右边界起始点。左边界起点的判定条件为当前像素为黑色（赛道）而右侧相邻像素为白色（背景），右边界起点则相反。为保证起点可靠性，通常会连续检查多个像素点以排除噪声干扰。
边界追踪： 确定起点后，从该点出发沿边界向上逐点追踪。追踪过程中，算法检查当前点八邻域内满足边界条件的像素点，选择其中最可能是下一个边界点的位置进行移动。为提高追踪效率，采用方向记忆机制——记录上一次的移动方向，在下一轮搜索中优先检查与该方向相近的邻域位置，避免无效搜索。
方向管理与终止条件：在追踪过程中，算法会根据当前边界走势动态调整搜索策略。左右边界的搜索逻辑呈镜像对称。同时设置最大追踪行数，防止因边界中断而陷入无限循环。若某侧边界在追踪过程中丢失，则将该侧边界标记为丢线状态，交由后续补线逻辑处理。
八邻域搜线完成后，即可得到赛道左右边界的连续点集，为后续中线拟合和舵机控制提供基础数据。相比逐行遍历法，八邻域法在边界连续性和抗干扰能力方面更具优势，适合本系统所采用的60×60压缩图像尺寸下的赛道识别需求。

4.3 特殊元素识别及处理
 特殊元素处理——环岛
环岛是赛道元素中较为复杂的场景之一，其特点是赛道呈环形闭合结构，车模需从直道驶入环岛绕行一周后从出口驶出。相比普通弯道，环岛对车模的路径规划和状态管理提出了更高的要求。若将环岛简单视作普通弯道处理，容易导致车模在环岛内出现路径偏差甚至冲出赛道。因此，本系统采用状态机对环岛进行分阶段处理，将环岛过程划分为六个状态，各状态之间依据图像特征进行切换。
状态一：看见环岛
车模在直道或弯道正常行驶过程中，当图像中出现环岛特征时进入本状态。环岛的典型图像特征为一侧边线连续、另一侧边线出现拐点且边线存在不连续或消失区域。具体判断条件包括：检测到一侧赛道边线存在明显拐点，另一侧边线保持相对连续；赛道宽度在拐点附近发生突变；拐点处的曲率大于普通弯道的阈值。当上述条件满足时，系统判定前方存在环岛元素，进入状态二。
状态二：判断环岛方向
进入本状态后，系统需确定环岛为左环岛还是右环岛。环岛方向的判断依据是拐点出现的位置以及边线丢失的方向。若拐点出现在右侧边线且右侧边线存在连续性丢失，则判定为右环岛；反之，若拐点出现在左侧边线且左侧边线存在连续性丢失，则判定为左环岛。方向判断的准确性直接影响后续补线策略的选择，因此本状态在环岛处理流程中起到承上启下的关键作用。方向判定完成后，系统根据环岛方向选择对应的补线策略，进入状态三。
状态三：进环岛
确认环岛方向后，车模开始执行入环动作。本阶段的核心任务是在环岛入口处进行补线，引导车模顺利进入环岛内部。以右环岛为例，当识别到右下拐点后，将该拐点与左边界上合适位置的点进行连线，封锁前方直行路径，迫使车模向右转向进入环岛。补线的基本原则是：利用拐点与对侧边线构建一条平滑的过渡路径，使车模沿该路径切入环岛。入环过程中需适当降低车速，确保转向响应及时。
状态四：环岛内巡航
车模已进入环岛内部，沿环形赛道行驶。本阶段赛道呈现连续弯道特征，左右边线均呈弧形延伸。环岛内的控制策略与普通弯道类似，但由于环岛曲率较大且持续，常规中线算法计算出的路径可能不够平滑。因此，本系统在环岛内采用专门的路径规划策略：在环岛内选取若干行进行中线计算，通过这些点拟合出一条平滑的弧形路径作为跟踪目标。车模沿拟合路径稳定行驶，直至检测到环岛出口特征。
状态五：出环岛
当车模在环岛内行驶接近一周时，图像中再次出现边线拐点特征，表明环岛出口即将到来。本阶段需要在出口处进行补线，引导车模顺利驶出环岛。以右环岛为例，当检测到左下拐点和右上出口特征时，将两点连线，引导车模向右转向驶出环岛。出环补线的关键在于准确识别出口拐点位置，拐点识别过早或过晚都会影响出环路径的平滑性。出环过程中同样需要适当控制车速，避免因速度过快导致转向不及。
状态六：环岛离开
车模已驶出环岛，进入环岛出口后的直道或弯道区域。本阶段系统判断环岛处理是否完成，具体依据为：左右边线均已恢复正常且连续；赛道宽度恢复至正常范围；环岛相关的拐点特征消失。当上述条件均满足时，系统退出环岛状态机，恢复正常循迹模式。
4.4 控制思路
4.4.1 舵机整体控制思路
舵机是车模转向控制的执行机构，其响应速度和控制精度直接影响车模的路径跟踪能力。经过对比测试，本系统确定使用330Hz的PWM波控制舵机，在该频率下舵机响应速度较快且工作稳定，无明显抖动。
在每个控制周期中，图像处理完成后，系统综合当前识别的赛道类型和编码器反馈的速度值，确定最佳的打角行，计算该行中线偏离赛道中心位置的偏差值，将该偏差及其变化率代入舵机位置式PD控制器进行计算，输出结果经舵机中值偏置和上下限限幅后，转换为最终的PWM占空比输出至舵机。

4.4.2 舵机PD计算式

舵机控制采用位置式PD控制。在调试过程中发现，积分项（I项）会累积历史偏差，容易导致舵机响应滞后和超调，尤其在弯道中表现明显。因此本系统将积分项置零，简化为PD控制，控制公式如下：
// 舵机PD控制
float dError = error - last_error;      // 偏差变化率
int angle_change = (int)(kp * error + kd * dError);

// 舵机PWM输出 
int servo_pwm = servo_mid + angle_change;
if (servo_pwm > servo_max) servo_pwm = servo_max;
if (servo_pwm < servo_min) servo_pwm = servo_min;
pwm_set_duty(SERVO_CHANNEL, servo_pwm);

4.4.3 陀螺仪阻尼控制
为提高车模在高速行驶和急弯工况下的转向稳定性，本系统引入了陀螺仪进行阻尼控制。陀螺仪安装在车模主控板上，用于检测车模的偏航角速度（Z轴角速度）。当车模转向时，若偏航角速度过大，表明车模转向过急，存在侧滑或甩尾风险；若偏航角速度过小，则表明转向响应不足。
陀螺仪阻尼的控制原理是将偏航角速度作为负反馈项叠加至舵机PD控制器的输出中，其控制表达式如下：
// 陀螺仪阻尼控制
float gyro_z = imu_get_gyro_z();  // 获取Z轴角速度
float gyro_feedback = k_gyro * gyro_z;
int angle_change = (int)(kp * error + kd * dError - gyro_feedback);

其中k_gyro为陀螺仪阻尼系数。当车模偏航角速度增大时，阻尼项随之增大，舵机输出反向减小，起到抑制转向过急的作用，使车模姿态更加平稳。该阻尼控制类似于在转向系统中引入了“粘性阻尼”效果，有效抑制了车模在高速弯道中的振荡现象。需要说明的是，该阻尼项仅在偏差较小时起主导作用，当偏差较大时（急弯、环岛等场景），PD主控项仍占主导，确保车模具备足够的转向响应。

4.4.4 不同元素的速度控制策略
通过大量调试发现，车模在直道上使用较高转速、在弯道上适当降低转速能够取得较好的综合成绩。直道（尤其是长直道）的加速能力是决定总用时的关键因素，而弯道的速度控制则直接影响车模的稳定性和路径质量。
针对直道入弯过程，本系统采用分级减速策略：根据车模当前速度计算出所需的减速场数（即提前减速的行数），减速场数较高时目标速度设定较低，随着车模接近弯道，减速场数逐步减少，目标速度逐级提升至弯道设定速度，实现平滑过渡，避免速度突变导致失稳。
4.4.5 不同元素的速度控制策略
通过对智能车的调试我们发现，在直道使用较高的转速，在弯道使用稍慢一些的转速能够很流畅的跑完整个赛道，其中在直道（长直道、短直道）的加速能够非常关键的决定车模的整体速度，而弯道的速度能够提升车模的稳定性。
针对直道入弯的过程我们采取了特定的减速策略，即先根据车模当前速度给出减速场数，当减速场数较高的时候设定速度较低，当减速场数较少的时候设定速度较高，并随着减速场数的减少设定速度逐渐接近弯道速度使车模能够流畅的进入弯道，避免出现“猛加猛减”的情况。

4.4.6 车模的电机PI控制
电机速度控制采用增量式PI控制算法。比例项（P项）作用于当前速度偏差，减小稳态误差；积分项（I项）作用于偏差的累积，加快电机响应速度，缩短加速时间。控制公式如下：
// 增量式PI控制
int error = target_speed - current_speed;
motor_out += kp * (error - last_error) + ki * error;
motor_out = limit(motor_out, -MAX_OUT, MAX_OUT);
针对不同赛道类型，系统配置多组PI参数。直道采用较大的P值和I值，使电机加速响应迅速，充分发挥车模的直线速度潜力；弯道采用较小的P值和I值，避免速度突变导致车模失稳。参数切换与舵机PD参数切换同步进行，确保速度和转向控制协调一致

{//        NB      NM      NS      ZO      PS      PM      PB

    {-0.6, -0.4,  0.0,  0.4,  0.8,  1.0,  1.0},
};

static float FuzzyTable2D(const float table[7][7], float e_norm, float ec_norm)
{
    int ie, jec;
    float fe, fec;
    float v00, v01, v10, v11, v0, v1;

    e_norm += 3.0f;
    ec_norm += 3.0f;
    if (e_norm < 0.0f) e_norm = 0.0f;
    if (e_norm > 6.0f) e_norm = 6.0f;
    if (ec_norm < 0.0f) ec_norm = 0.0f;
    if (ec_norm > 6.0f) ec_norm = 6.0f;

    ie  = (int)e_norm;
    jec = (int)ec_norm;
    fe  = e_norm - (float)ie;
    fec = ec_norm - (float)jec;

    if (ie  >= 6) { ie  = 6; fe  = 0.0f; }
    if (jec >= 6) { jec = 6; fec = 0.0f; }

    v00 = table[ie][jec];
    v01 = table[ie][jec + 1];
    v10 = table[ie + 1][jec];
    v11 = table[ie + 1][jec + 1];

    v0 = v00 + (v10 - v00) * fe;
    v1 = v01 + (v11 - v01) * fe;

    return v0 + (v1 - v0) * fec;
}

/* 每帧调用一次: 根据偏差e和变化率ec动态调整kp */
void Pid_Param_Map(float e, float kp_base, float kp_range,
                   float e_div, float ec_div, float *kp_out)
{
    static float last_err = 0;
    float ec = e - last_err;
    float factor_kp;

    last_err = e;

    /* e/e_div → [-3,3], ec/ec_div → [-3,3] */
    factor_kp = FuzzyTable2D(ruleKp, e / e_div, ec / ec_div);

    /* kp = base + factor * range, 例: 62 + 1.0*2 = 64 */
    *kp_out = kp_base + factor_kp * kp_range;
}
