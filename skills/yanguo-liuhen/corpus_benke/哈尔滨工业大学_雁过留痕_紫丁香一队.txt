摘要
本报告介绍紫丁香一队四轮智能车模的制作与调试过程。车模以 STC32G144K246 微控制器为核心，采用灰度摄像头获取赛道信息，结合左右编码器、惯性测量单元和 TOF 测距模块完成运动状态感知。软件通过图像处理得到循迹误差和赛道元素状态，利用转向闭环与左右轮速度闭环完成车辆控制，并设置菜单、显示和停车调试等辅助功能。报告重点说明系统组成、机械与硬件安装、图像信息处理、PID 控制原理、软件组织和调试流程；未公开关键识别阈值、赛道策略和完整源代码。
关键词：智能车；灰度视觉；编码器反馈；PID 控制；嵌入式系统



第一章 引言
全国大学生智能汽车竞赛面向嵌入式控制、传感测量、机械安装和系统调试等综合工程能力。本队围绕四轮车模的自主循迹需求，完成了车体装配、视觉采集、运动控制与调试界面的集成。本文以制作过程为主线，介绍系统组成、硬件安装、软件运行流程、调试方法和主要技术参数；涉及核心识别与控制策略的部分仅作模块级说明。
1.1 任务目标
本车面向室内赛道自主运行任务。系统需在有限车体空间内完成图像采集、赛道循迹、速度与转向控制、特殊赛道区域处理、运行状态显示以及必要的停车保护。设计目标是在保证基本稳定性的前提下，提高信息获取和控制响应的可靠性，并为现场调试提供清晰的观察手段。
1.2 报告范围
本文以车模制作和工程实现为主，不对关键阈值、赛道记忆序列、激光策略和完整源代码做展开。机械尺寸、主要模块、原理图、车模照片与开发界面均以已核对资料为准；运行成绩和图像采集频率等现场测量数据在最终检录后填写。
第二章 车模总体方案
2.1 系统总体架构
车模采用以 STC32G144K246 为核心的控制系统。前端灰度摄像头采集赛道图像，图像处理模块输出循迹误差和当前运行状态；编码器提供车轮速度信息，惯性测量单元和 TOF 模块用于辅助姿态与距离判断。控制器根据各模块信息产生舵机转向和电机驱动输出，同时通过屏幕菜单完成参数观察与调节。
2.2 主要技术路线
本车采用“采集—处理—控制—反馈”的运行路线。摄像头持续采集灰度图像，软件从图像中获得赛道边界及循迹误差；控制模块结合编码器反馈完成速度闭环，并以误差驱动转向舵机。系统保留菜单调参、状态显示、停车报告和上位机数据观察等辅助功能，便于不同场地条件下进行快速检查。
2.3 信息流与控制流
系统的信息流为：摄像头灰度帧进入图像缓冲区，经图像模块输出循迹误差和状态量；编码器计数在控制周期内转化为左右轮速度；IMU 与 TOF 提供辅助测量量。控制流为：控制模块根据图像误差、速度反馈与当前状态计算舵机和电机 PWM 输出，执行机构驱动车模运动，新的图像和编码器数据再形成闭环。

第三章 机械结构与硬件系统
3.1 机械安装与结构改造
3.2 传感器与执行器配置
车体使用四轮底盘作为机械基础，前部安装转向机构，后部布置驱动与供电部分。摄像头支架固定在车体前上方，使其视场覆盖车模前方赛道；主控板、电机驱动和传感器模块采用可靠固定方式安装，并对线束进行分组整理，以减少振动和运动时的拉扯。电池布置尽量兼顾重心与维护便利性。
车模前端采用 MT9V03X 灰度摄像头获取赛道亮暗分布；左右驱动轮编码器用于获得轮速反馈；惯性测量单元用于读取车体角速度和加速度；TOF 测距模块提供距离信息，用于辅助特定赛道区域的状态判断。执行部分由转向舵机、左右驱动电机及其驱动模块构成，显示屏和按键模块用于运行前检查、参数设置和停车后的状态查看。各类传感器均通过主控统一管理，避免在不同模块间重复读取同一硬件资源。
3.3 传感器接口与信号使用
摄像头通过 DMA 方式将灰度图像写入图像缓冲区，软件在完整帧到达后进行处理；编码器在固定控制周期内读取计数增量并换算为速度反馈；IMU 与 TOF 采用底层驱动提供的读取接口获取数据。图像信息主要用于赛道边线、中心参考和元素状态判断，编码器信息主要用于速度闭环，IMU 与 TOF 作为辅助传感信息参与状态确认。该分工使各传感器分别承担适合的测量任务，提高了系统调试的可观察性。
3.4 执行与供电设计
转向舵机由主控输出周期性 PWM 信号控制，驱动电机由电机驱动模块输出相应的调速信号。控制板、摄像头、传感器和执行机构按功能分区供电，并通过可靠连接和线束整理降低振动、接触不良及电机干扰对信号采集的影响。实际制作中重点检查电源极性、公共地连接、插接件牢靠程度和摄像头连接状态。
3.5 电路板与实物安装说明
主控板和扩展电路承担传感器接口、PWM 输出、编码器输入、显示接口及供电分配等功能。整车制作中按照功能对线束和接口进行分区布置，重点检查供电极性、公共地连接、插接件牢靠程度和摄像头连接状态。本节采用文字说明安装关系，不展示实物照片；具体电路连接关系见下一节原理图。

第四章 软件功能与运行流程
4.1 软件功能概述
上电后，程序依次完成主控、显示、传感器、摄像头和执行机构的初始化。运行阶段由主循环负责图像帧处理与菜单交互，由定时中断完成编码器读取、速度控制和转向输出。图像模块向控制模块提供循迹误差及运行状态；控制模块根据当前模式生成电机和舵机控制量。该组织方式使图像处理与控制执行保持相对独立，便于定位问题和开展调试。
4.2 图像处理与循迹误差计算
高效的软件处理流程是智能车高速、平稳自动循迹的基础。本车以 STC32G144K246 单片机为控制核心，采用 MT9V03X 总钻风灰度摄像头采集赛道图像。软件在获得完整灰度帧后，依次完成图像预处理、二值化、边线搜索、参考线构造和赛道元素状态判断，并将循迹误差、状态量及必要的目标位置信息提供给控制模块。转向和速度控制分别以图像误差与编码器反馈为主要输入，通过闭环调节保证车辆能够稳定地沿赛道运行。本节仅说明模块功能和数据流，不公开具体阈值、判据和赛道策略。
4.2.1 图像采集与帧同步
MT9V03X 总钻风灰度摄像头输出赛道亮暗分布，每个像素以 0~255 的灰度值表示明暗程度。由于镜头成像和近大远小的透视关系，赛道边界在图像中呈现由近及远收敛的形态；同时，光照不均、地面反光、局部阴影和远处细节衰减都会影响边界质量。底层采集模块通过 DMA 将一帧图像写入缓冲区，并在完整帧到达后置位完成标志。主循环仅处理已完成采集的图像帧，避免读写同一图像缓冲区时出现不完整数据。
4.2.2 灰度预处理与二值化
原始灰度图会受到环境照度、地面反光、镜头曝光和局部阴影影响。程序在有效图像区域内提取亮暗特征，并结合不同区域的灰度差异完成二值化处理，将连续灰度信息转换为可供快速逻辑判断的黑白信息。二值化结果用于区分赛道、背景与局部黑色目标；调试阶段可通过屏幕显示原始灰度图和二值化结果，据此检查曝光、增益和图像阈值设置是否适应当前场地。
4.2.3 参考点、边线与参考线构造
基础循迹以图像中的参考列和参考点为起点，在有效区域内逐行搜索左右原始边线。对搜索到的边界进行连续性和有效性检查后，程序由左右边线计算中间参考线；一侧边线暂时缺失时，结合另一侧边线、近期搜索结果和当前运行状态维持连续输出。参考线相对图像中心的横向偏移被转换为循迹误差，作为舵机转向控制的输入。该过程同时保留边线宽度、边界有效性等基础信息，为后续元素判断提供支撑。
4.2.4 特殊元素识别与状态机处理
在普通赛道之外，十字、环岛、坡道、避障和斑马线会使边线形态出现明显变化。软件将这些场景组织为独立状态，并在状态切换期间选择与当前画面相适应的边线补偿和误差生成方式。状态机的作用不是替代基础寻线，而是在特殊区域中限制不合适的普通规则，从而保证车辆在进入、通过和退出元素时仍能获得连续的控制信息。对黑色目标区域，视觉模块同步输出位置和有效性信息，供后续执行模块作高层处理。
4.2.5 鲁棒性处理与调试观察
为提高实际赛道中的稳定性，图像处理过程对边线有效性、局部异常和短时缺失进行保护，并在元素状态变化时对参考线结果进行平滑衔接。程序保留灰度图、二值化图、左右边线、中线和状态量等调试观察接口，便于在不同光照条件下检查图像质量和状态切换是否合理。上述保护仅用于提高信息输出连续性，不改变控制模块的基本闭环结构。
4.2.6 坡道状态联合判断
坡道处理采用图像特征与 TOF 测距信息的联合确认方式。图像模块先依据边线、参考线和局部形态变化形成坡道候选状态；控制侧在相应状态下读取 TOF 距离，为坡道进入、保持与退出提供辅助依据。状态机将坡道过程与普通循迹过程分开管理，避免在短时图像扰动或单次距离异常时频繁切换。该策略仅使用已经接入的图像与测距信息进行状态确认，不以额外的编码器里程作为坡道识别依据。
4.3 PID 控制算法介绍
4.3.1 PID 控制原理与数字化实现
比例、积分、微分控制简称 PID 控制，是工程控制中应用广泛的闭环调节方法。其结构清晰、实现简单，并可通过现场试验完成参数整定，适合智能车这类机械结构、轮胎附着和供电状态均可能变化的机电耦合对象。当难以建立精确的车辆运动模型时，PID 能利用实时反馈持续修正控制偏差。
数字控制系统以离散采样时刻的期望值与实际值之差 e(k) 作为输入，分别形成比例、积分和微分校正量。比例项对当前偏差立即响应，决定基本的校正强度；积分项补偿长期存在的稳态偏差；微分项根据偏差变化趋势提前抑制过冲和振荡。实际应用中可根据执行机构与传感器特性选用完整 PID、PI 或 PD 结构。
u(k) = Kp * e(k) + Ki * T * sum[e(i)] + Kd * [e(k) - e(k-1)] / T
式中，k 为采样序号，T 为采样周期，e(k) 为当前偏差，u(k) 为控制输出；Kp、Ki、Kd 分别为比例、积分和微分相关系数。数字实现时还应考虑量化误差、传感器噪声以及输出边界，因此控制量需配合限幅与有效性判断使用。
4.3.2 转向舵机的位置式 PD 控制
转向控制以视觉模块输出的赛道中心误差作为主要输入。舵机 PWM 占空比对应实际舵机位置，因而采用以当前位置误差为核心的位置式控制形式：比例项使车辆及时向赛道中心回归，误差差分项用于抑制转向过快造成的摆动。考虑到图像误差受采集噪声和特殊赛道状态影响，转向环以 PD 为主，避免不必要的积分累积放大短时误判。
为提高高速工况下的稳定性，转向控制还结合车体角速度信息。视觉误差负责确定回正方向，误差变化和角速度用于描述车辆转动趋势；三者共同形成舵机 PWM 偏移量，再叠加至舵机中值并进行上下限约束。该处理可减小由连续弯道、直道回正或图像瞬时波动带来的振荡。
舵机输出 = 舵机中值 + 比例校正 + 误差变化校正 + 角速度抑制项
调试时先在低速直线条件下确认舵机中值与比例响应，再逐步加入差分和角速度抑制。若比例系数过大，车辆易在直线或出弯阶段左右摆动；若比例系数过小，则入弯响应迟缓。差分与角速度相关项过大也会放大高频噪声，因此应以车辆不出现明显振荡为边界逐步整定。
4.3.3 驱动电机的增量式 PI 控制
速度控制采用左右轮独立闭环。固定控制周期内，程序读取左右编码器计数增量并计算实际轮速，将其与目标轮速比较后，分别更新左右电机 PWM。与固定 PWM 驱动相比，闭环 PI 可以补偿电池电压下降、左右传动差异及负载变化，使实际速度更接近设定值。
电机控制采用增量式 PI 形式，即每个周期计算 PWM 的修正增量，而不是重新给出不连续的绝对输出。其主要优点是输出变化平缓，适合电机速度控制；同时计算只依赖当前及相邻周期误差，便于在单片机实时控制周期内执行。
Delta u(k) = Kp * [e(k) - e(k-1)] + Ki * e(k)
车辆转弯时，软件依据转向需求设置左右不同的速度目标，形成差速控制。直道可保持较高的速度目标，进入弯道或特殊元素时再由状态机选择更合适的速度与前瞻策略。这样，横向转向控制与纵向速度控制相互配合，可改善入弯、出弯和连续弯道中的车身姿态。
4.3.4 PID 参数整定与控制保护
智能车系统由图像采集、转向机构、轮胎、传动和电源共同构成，参数会随机械安装和赛道条件变化而变化，因此采用工程整定方法。整定遵循由低速到高速、由直线到弯道、由单环到多环的顺序：先保证转向基本稳定，再整定左右轮速度闭环，最后在典型元素中检查状态切换前后的连续性。每次仅调整少量相关参数，并通过图像、编码器和运行状态进行对比观察。
控制程序对舵机和电机输出均设置限幅；停车、起跑延时和特殊状态下统一切换速度目标并管理执行输出。当图像或传感器数据短时异常时，控制量仍需经过状态保护和边界约束后才作用于执行机构。上述措施既降低了异常误差导致的冲击风险，也为现场调试提供了明确、可回退的控制边界。
4.4 状态管理与调试设计
软件对运行状态、传感器有效性、菜单参数和停车信息进行统一管理。屏幕菜单支持在静止状态下保存和加载参数；运行过程中可通过显示界面或数据通道查看循迹误差、状态量、速度与传感器读数。停车后保留必要的运行统计信息，以便复核整车运行现象。调试代码与正常运行路径保持分离，避免调试显示影响核心控制周期。

static void Show_Init_Result(uint8 row, char *name, uint8 ok)
{
    char buf[32];
    uint16 y_pos = (uint16)row * 20;

    ips200_set_color(ok ? RGB565_GREEN : RGB565_RED, RGB565_BLACK);
    sprintf(buf, "%-5s : %s      ", name, ok ? "OK" : "FAIL");
    ips200_show_string(0, y_pos, buf);
}

static void Show_Camera_Start_Preview(void)
{
    uint8 frame_count;
    uint8 wait_count;

    for(frame_count = 0u; frame_count < 10u; frame_count++)
    {
        wait_count = 0u;
        while(mt9v03x_finish_flag == 0u && wait_count < 20u)
        {
            system_delay_ms(5);
            wait_count++;
        }

        if(mt9v03x_finish_flag == 0u)
        {
            break;
        }

        ips200_show_gray_image(0, 0, mt9v03x_image[0],
            MT9V03X_W, MT9V03X_H,
            MT9V03X_W, MT9V03X_H, 0);
        mt9v03x_finish_flag = 0u;
        system_delay_ms(50);
    }
}
C.2 停车信息显示
static void Show_Park_Debug_Info(void)
{
    char buf[40];
    float zhenlv;
    float lap_distance;
    float lap_time;
    uint8 lap_index;
    uint8 target_index;
    uint16 y;
    uint8 shown_laps;

    if(Run_count > 0)
    {
        zhenlv = (float)image_count * 200.0f / (float)Run_count;
    }
    else
    {
        zhenlv = 0.0f;
    }

    ips200_clear(RGB565_BLACK);
    ips200_set_color(RGB565_WHITE, RGB565_BLACK);
    ips200_show_string(0, 0, "---- Park Debug Info ----");

    sprintf(buf, "C:%d I:%d", Run_count, image_count);
    ips200_show_string(0, 16, buf);
    sprintf(buf, "FPS:%4.1f ST:%d Z:%d", zhenlv, state, zebra_count);
    ips200_show_string(0, 32, buf);

    shown_laps = lap_report_count;
    if(shown_laps > 6u)
        shown_laps = 6u;

    for(lap_index = 0u; lap_index < shown_laps; lap_index++)
    {
        lap_distance = (float)lap_encoder_sum[lap_index] / 3000.0f / 3.65f;
        lap_time = (float)lap_run_ticks[lap_index] * 0.005f;
        y = (uint16)(48u + (uint16)lap_index * 16u);
        sprintf(buf, "L%u M:%6.2f T:%6.2fs",
            (uint16)(lap_index + 1u), lap_distance, lap_time);
        ips200_show_string(0, y, buf);
    }

    if(lap_report_count != 0u)
    {
        lap_index = (uint8)(lap_report_count - 1u);
        for(target_index = 0u; target_index < 6u; target_index++)
        {
            y = (uint16)(144u + (uint16)target_index * 16u);
            if(target_index < lap_target_count[lap_index])
            {
                lap_distance = (float)lap_target_distance[lap_index][target_index]
                    / 3000.0f / 3.65f;
                sprintf(buf, "T%u:%5.2f", (uint16)(target_index + 1u), lap_distance);
            }
            else
            {
                sprintf(buf, "T%u: --", (uint16)(target_index + 1u));
            }
            ips200_show_string(0, y, buf);
        }
    }
}

void main(void)
{
    uint8 dl1b_ok;
    uint8 imu_ok;
    uint8 camera_ok;

    clock_init(SYSTEM_CLOCK_96M);
    debug_init();
    InitMenu();

    ips200_clear(RGB565_BLACK);

    Control_init();

    dl1b_ok = (0 == dl1b_init());
    Show_Init_Result(0, "DL1B", dl1b_ok);
    imu_ok = (0 == imu963ra_init());
    Show_Init_Result(1, "IMU", imu_ok);

    camera_ok = (0 == mt9v03x_init());
    if(camera_ok)
    {
        mt9v03x_set_exposure_time(
            (uint16)menu_image[MENU_IMAGE_CAM_EXP].para);
    }
    Show_Init_Result(2, "CAM", camera_ok);

    if(camera_ok)
    {
        Show_Camera_Start_Preview();
    }

    system_delay_ms(100);
    pit_ms_init(TIM0_PIT, 5, Control_main);
    pit_ms_init(TIM1_PIT, 1, Target_Laser_Timer_Handler);
    system_delay_ms(100);
    DisplayMenu1_Full();

    while(1)
    {
        if(Park_Debug_Hold_Process())
        {
            continue;
        }

        if(Run_flag == 0)
        {
            Menu_main();
            continue;
        }

        /* Manual targeting test path is omitted from this report. */
        if(target_manual_mode != 0u)
        {
            continue;
        }

        if(mt9v03x_finish_flag != 0u)
        {
            image_main();
            mt9v03x_finish_flag = 0u;
            image_control_ready = 1u;
            image_count++;
            Vofa_Send_Car_Data();

            if(park_flag == 1u)
            {
                go_test_display = 0u;
                Lap_Report_Finalize();
                Show_Park_Debug_Info();
                park_debug_hold = 1u;
            }
            else if(go_test_display != 0u)
            {
                Show_Go_Test_Info();
            }
        }
    }
}
