摘要
本文详细介绍了我们为了二十一届全国大学生智能车大赛雁过留痕组准备的硬件和软件方案。车模采用四轮 C 车模平台，以 STC32G144K 单片机作为主控核心，结合总钻风摄像头完成赛道图像采集与循迹识别，并通过编码器构建速度闭环控制，提高车辆加减速响应和运行稳定性。硬件方面，系统采用 3S 锂电池统一供电，设计了主控与驱动一体板及无刷电调板，实现对舵机、有刷电机、负压风扇、激光模块和各类传感器的稳定控制。机械结构方面，通过优化摄像头、负压风扇和激光支架布局，并增加碳素底板加强结构刚性，提升车辆高速行驶时的稳定性。软件方面，系统基于图像处理算法提取赛道边界和中线误差，结合 PID 控制、陀螺仪辅助、主动差速及特殊赛道元素识别，实现车辆在环岛、十字、坡道等复杂场景下的稳定运行。同时，针对“雁过留痕”任务，设计了靶标识别和多路紫外激光分区发射方案，提高激光留痕的准确性。通过软硬件协同设计与反复调试，车模实现了较好的循迹性能、运行稳定性和任务执行能力。
关键词：智能车，STC32G144K，图像处理，PID控制，激光留痕，速度闭环

第二章 车模整体设计
2.1车模机械模型
在本次的比赛过程中我们采用的是C车。
车模的简介：C车模采用经典的四轮结构，前轮由高精度舵机控制转向，后轮由直流电机驱动，搭配减速齿轮组提升扭矩。底盘采用轻量化铝合金材质，同时我们增加了碳素底板以适应不同赛道工况。轮胎采用高抓地力橡胶胎，通过更换不超过原来直径的光头胎以应对不同摩擦系数赛道。
2.2车模电路板安装位置
我们采用主控和驱动电机集成板还有两块无刷电调板。两块无刷电调板根据支撑负压电机的支撑架来设计板子的PCB布局，通过相应的固定孔，能完整地固定在支撑架上方且确保电机运行过程中风扇不会打到板子上面对应的器件；主控和驱动电机集成板的PCB布局是由车模后面部分编码器的安装位置而设计的，正好嵌套在电机上面，极大地降低了车模的重心，同时，我们将3S电池放置于主控和驱动电机集成板下方。
2.3支架的设计
车模主要涉及摄像头支架的位置，负压风扇的位置和激光支架安装的位置，摄像头的位置涉及循迹时候的前瞻，安装在车模的前面部分；负压风扇，我们采取设计安装在车模的中间位置。接着，考虑到行进过程中，负压风扇的开启会使底板下压，于是我们采取了在不改变原有的底板增加碳素板来加固底板。
2.3.1摄像头支架的设计
为了考虑车可以更好的响应，我们将前车的摄像头安装到舵机位置后一点，这样可以更清晰地获取到赛道的图像，可以使得四轮车模响应更加的迅速。底座采用和碳素杆刚好契合的孔洞设计，在摄像头的安装位置，我们采用三通可调节的形式来进行摄像头视角的调整。
2.3.2风扇支架的设计
车模由于转向时舵机加差速导致负压最好的位置是车的中心，于是我们将支撑无刷电机的碳素支架放置在车模中心位置，即摄像头后方位置。但是还有一个非常重要的点就是风扇的开启会使车模的底板下压，于是我们采取了在不改变原有的底板增加碳素板来加固底板，使摄像头前瞻在行进过程中变化更小。
2.3.3激光支架的设计
为了更快地响应激光留痕的效果，我们前期将激光支架的安装位置选择在了和摄像头安装位置的同一个碳素杆上面，在调试过程中，我们发现高速行进过程中，激光支架会使摄像头的碳素杆摇晃，导致摄像头在行进过程中前瞻发生微小变化，于是我们后期将激光支架的安装位置选择在前轮舵机的正上方位置，如图2.3.1。
为了增加激光留痕的准确性，我们采用三通设计来固定整体激光支架进而整体调整碳素板的位置，进而控制紫外激光管的角度。同时我们还在激光的底座设计上面巧妙地增设了TOF测距模块的固定孔。

第三章 系统方案设计及实现
3.1比赛要求
车模正常按PVC道循迹，实现赛道自主循迹，并且在行进过程中，识别到目标靶纸，在目标区域内，通过紫外激光管照射留下紫色痕迹。
3.2传感器选择
为了适应这次比赛我们主要应用了陀螺仪，总钻风摄像头，TOF测距，紫外激光管，正交Ａ／Ｂ编码器。
为了更好的循迹我们采用逐飞官方STC专用的总钻风摄像头进行对赛道的循迹，同时为了达到激光留痕的准确性，我们采用多路激光发射方案。为了更好地适应坡道，我们采用TOF测距检测，方便行进过程中，遇到坡道提前减速。为了更好地矫正行进姿态和辅助检测坡道，我们增加了陀螺仪模块。
3.3舵机选择
舵机的选择过程中限制了只能使用车模分布里面限定的舵机，所以我们选择了SU400舵机，扭矩适中，速度较快，使用电压6.0V-7.4V，信号频率50-330Hz，采用立式安装于车模前部。在前期，我们也尝试过BDS300舵机，虽然速度反应较SU400快，但是在调试过程中，我们能明显感受到它的扭矩力弱于SU400舵机。
3.4电机选择
电机的选择过程中由于规则限制车模，所以我们采用了车模原装380电机。该电机与车模底盘匹配度较高，传动结构稳定，在调试过程中能够保持车辆机械性能的一致性。为了进一步提升速度控制效果，我们采用龙邱推出的正交A/B编码器，能够实时采集车轮的转速信息，为闭环速度控制提供准确反馈，使车辆在加速、减速和入弯出弯过程中响应更加及时，提高了车辆运行稳定性和控制精度，从而提升整车的循迹性能和赛道适应能力。
3.5硬件设计方案
系统采用3S锂电池作为统一电源输入，通过主控和驱动集成板给各个功能模块和无刷电调板提供稳定电源。控制核心采用STC32G144K单片机，并围绕其完成主控、驱动及相关接口电路设计。图3.5.1和图3.5.2展示了系统方案设计阶段所规划的主要外设模块及其连接关系。

第五章 系统软件设计及算法实现
高效稳定的控制程序和高适应性的算法是智能车快速平稳运行的基础。我们的智能车采用STC32G144K芯片作为控制器，通过摄像头采集PVC赛道边线，为使小车快速平稳运行，我们使用了编码器测速对小车进行速度闭环。速度和方向控制算法方面，我们采用经典PID算法，配合理论计算与实际参数调试过程使程序和小车充分契合，使智能车达到快速平稳运行的目的。
5.1软件系统总体设计
本系统采用“图像识别——轨迹生成——舵机控制——电机控制——特殊任务处理”的软件架构。主循环在 go.c 中完成，先更新赛道元素识别，再进行寻线、误差计算和控制输出。
软件模块之间的关系相对清晰，初始化阶段由 init.c 完成传感器、舵机、电机、按键、激光和测距模块配置；控制阶段由 types.c、PID.c 和 motor.c 构成闭环；打靶任务由 shot.c 独立完成。
从任务角度看，软件系统需要同时满足两类要求：一类是车辆行进要求，即在白色 PVC 赛道中可靠提取赛道中心并稳定通过环岛、十字、坡道等元素；另一类是任务执行要求，即在车辆行进过程中识别白色感光纸上的黑色圆环靶，并把激光准确打在圆环内部的感光区域。因此，软件设计不只追求单帧识别准确率，还要考虑车速、舵机角度、圆环状态和发射冷却对打靶时机的影响。
5.2软件初始化与主流程
系统上电后，init.c 依次完成屏幕、陀螺仪、摄像头、舵机 PWM、编码器、左右电机方向、拨码开关、激光、蜂鸣器、测距模块和负压风扇的初始化。该流程保证了传感器和执行器在进入主循环前均处于可用状态。
主循环在 go.c 中执行。每一帧图像到达后，系统先更新参考线和赛道边界，再进行赛道元素判断，随后调用打靶识别与误差计算。最终由 Direction_Control() 和 Velocity_Control() 将图像误差转换成舵机角度和左右轮速度。
go.c 的调度顺序体现了“先感知、再判断、后控制”的原则。程序先调用 扫线函数更新赛道信息，再依次调用元素识别函数。这样做的好处是，打靶识别可以直接使用最新的边界信息等图像结果，并且能够避开环岛、坡道等复杂状态对普通巡线带来的干扰。
5.3图像处理与寻线算法
图像处理部分以 image.c 为核心，采用加权寻线和局部灰度阈值的方法。程序先根据左右边线和赛道宽度生成中线，再由 error() 按不同赛道状态选择权重表以及环岛权重表，得到加权误差。
从代码实现看，error() 不是简单地取单行偏差，而是遍历多个有效行，将每行的中线偏差乘以行权重后累加。靠近车体前方或更关键的区域权重更高，这样可提升高速行驶时的稳定性。
赛道补线和特殊元素判断由 Cross_Boundary_Compensate()、Ramp_Detect() 等函数协同完成。若赛道发生丢线，系统会根据边界起点和最长白列对左右边界进行补偿，确保中线连续。
5.3.1 赛道边界提取
赛道边界提取以左右边界数组为基础。search_line() 根据图像灰度变化搜索赛道内外边界，并将每一行的左右边界结果保存下来。后续所有元素判断，包括十字补线、坡道检测、环岛状态机和打靶扫描，都直接依赖这两个边界数组。
为了减少误识别，打靶扫描和坡道宽度计算都只在左右边界之间进行。这样可以保证算法关注“车实际所在赛道内部”的信息，而不是整幅图像中的背景噪声。
5.3.2 中线误差计算
error() 函数采用多行加权平均方式计算 error_2。程序将左右边界数组相加得到当前行的中心信息，再与基准值 base 比较，乘以权重表后累加。最后通过 归一化得到最终误差。
系统为不同速度模式和环岛状态设置了多套权重表。普通赛道时，权重集中在中远距离行；环岛或复杂区域中，权重表会改变有效关注区域，使车辆能够根据更可靠的图像行进行转向。
5.3.3 视觉截止行与最长白列
Search_Stop_Line 表示图像中可见白色赛道截止行。它既用于判断直道和坡道，也用于限定打靶扫描范围。若截止行较大，说明车前方可见赛道较远；若突然变短，可能是坡道、十字、靶纸或其他特殊元素造成的远端截断。

速度控制由 Positional_type_Ackermann_differential()、PID_L() 和 PID_R() 共同完成。程序先根据舵机打角计算阿克曼主动差速，再由左右轮速度 PID 进行闭环修正。mode.c 中根据“很快、快、中、慢”四档模式设置不同的 Base_Speed、Ramp_Speed、Ack_K 和电机 PID 参数。
5.4.1 舵机控制
Direction_Control() 首先判断停车标志 Stop_Flag。若车辆已进入停车过程，则直接回正舵机；否则调用 output(error_2) 计算舵机输出。output() 内部保留上一帧误差 error_last，通过 e2 = error_current - error_last 得到误差变化量，用 D 项抑制直道晃动和弯道过冲。
舵机最终由 Steer(angle) 输出 PWM。代码中 SET_MID 为舵机中值，SET_LEFT 和 SET_RIGHT 为左右极限，LEFT_MAX 和 RIGHT_MAX 用于限制打角范围。限幅可以避免误识别时舵机瞬间打死，提高车辆运行安全性。
5.4.2 陀螺仪辅助
在舵机控制公式中，imu660ra_gyro_z 作为转向阻尼项参与输出。普通赛道使用 GKD，环岛状态使用 GKD_island。该项的作用是抑制车身快速旋转造成的摆动，使舵机响应更稳定。陀螺仪还被应用于坡道和环岛的辅助判断。
5.4.3 速度闭环和主动差速
速度控制函数按速度模式设定基础速度：中速、快速、慢速和很快模式分别对应不同 Base_Speed 和 Ramp_Speed。进入环岛时，程序会主动降低 Base_Speed，并使用 Ack_K_yh 计算圆环差速；进入坡道时，左右轮目标速度统一设置为 Ramp_Speed，降低通过坡道时的冲击。
左右轮电机采用增量式 PID。PID_L() 和 PID_R() 根据 set_speed 与编码器实际速度的误差计算 PWM 增量，再通过 Motor_Left()、Motor_Right() 输出到电机驱动通道。PWM 输出设置了 SPEED_MAX 和 SPEED_MIN 限幅，防止电机过流或速度闭环发散。
5.5 特殊赛道元素处理
系统针对环岛、十字、坡道、斑马线等特殊元素采用分状态处理。每类元素都对应独立的标志位或状态变量，主循环根据当前标志位切换补线策略、速度策略和打靶策略。这样可以避免把所有情况都交给普通中线算法处理，从而提高复杂赛道通过率。
5.5.1 环岛元素
检测依据：Island_Detect() 根据左右边界丢线、拐点和赛道宽度判断车辆是否接近环岛。
状态划分：代码中通过 Island_State 区分准备入环、入环、环内、出环和恢复普通巡线等阶段。
补线策略：island.c 中提供 Left_Add_Line()、Right_Add_Line()等函数，用直线补偿缺失边界。
控制策略：进入环岛后切换 KP1_island、KD1_island、GKD_island 和 Ack_K_yh，同时降低基础速度，使车辆绕环时更稳定。
打靶影响：在 Island_State 不为 0 时，shot.c 使用 shot_i_* 参数单独修正打靶窗口，避免环岛转向时目标横纵坐标偏移。
5.5.2 十字元素
检测依据：Cross_Boundary_Compensate() 使用双边固定范围内的丢线判断左右边界同时丢失程度。当 Both_Lost 大于阈值且不处于普通环岛状态时，置位 cross_flag。
补线策略：进入十字后，程序寻找左右上拐点和下拐点。若有效端点存在，则用 Left_Add_Line()、Right_Add_Line() 将底部边界与远端边界连接；若端点不足，则向上延长原有边界。
退出条件：当 Both_Lost 小于设定值，说明左右边界恢复，cross_flag 清零，车辆回到普通巡线。
设计目的：十字区域中线容易断裂，补线后可以维持左右边界连续，避免车辆进入十字时左右摆动。
5.5.3 坡道元素
检测依据：Ramp_Detect() 结合测距、中线误差、截止行、左右丢线时间和 imu660ra_gyro_y 判断坡道或前方高差。
宽度计算：程序统计 35 到 55 行之间的左右边界宽度平均值 width，用于辅助判断前方赛道形态。
速度策略：Ramp_Flag 置位后，Velocity_Control() 将左右轮目标速度设置为 Ramp_Speed，避免高速冲坡导致车身跳动。
互斥策略：坡道检测要求 cross_flag 为 0 且 Island_State 为 0，避免十字和环岛内误触发坡道模式。
5.5.4 直道、保护和停车元素
直道检测：Straight_Detect() 通过 Search_Stop_Line、边界起始点和 error_2 判断车辆是否处于稳定直道。
保护逻辑：protect() 利用底部最长连续白列判断车辆是否仍在赛道内，若未检测到足够长的白色区域，则触发保护停车。
停车逻辑：Stop_Flag 控制停车阶段，Velocity_Control() 根据 Stop_Flag 分别执行短距离前进、减速停车和电机关闭。
与打靶互斥：直道检测中包含 shoot_state 判断，避免车辆正在打靶时误判为直道加速。
5.6 激光打靶设计
打靶模块单独实现于 shot.c，目标是识别白色感光纸上的黑色圆环靶，并输出靶心中心坐标供后续激光发射使用。为了适应小车在赛道上行进，识别过程只在当前有效赛道内部扫描，并结合左右边线限定搜索范围，避免把边线、阴影或赛道外背景误判为目标。
首先在 target_detect_black_average() 中遍历左、右边界之间的有效区域，统计灰度值低于 110 的黑点。
再计算黑点总数 black_count，以及黑点分布的最小/最大坐标，得到靶区包围盒。
通过黑点平均值和包围盒中心融合，确定靶心 center_x、center_y。
利用中心像素必须为白色的条件，排除普通黑块或赛道边缘。
根据 y 方向范围和 mode、Island_State 的组合，计算 y_low、y_high 以及横向偏移 offset1、offset2。
最终在 fire() 中按照 center_x 所在区间选择对应激光点亮。
打靶代码的一个特点是会进行车身运动补偿。由于小车在打靶时仍在移动且舵机可能处于转向状态，因此 shot.c 使用 angle、mode[] 和 Island_State 动态修正靶区上下边界和左右边界，使激光能够尽量落在圆环内部。
5.6.1 靶标识别区域
靶标识别不是在整幅图像中盲目搜索，而是限定在 Left_Line[row] 和 Right_Line[row] 之间的赛道内部区域。扫描上界由 Search_Stop_Line 计算得到，最低不小于 30 行。该设计符合小车在赛道内行进的实际情况，可以减少赛道外背景和边缘杂点对识别的干扰。
5.6.2 黑色圆环中心计算
target_detect_black_average() 当前采用黑点平均法。程序以 pixel <= 110 作为黑色判据，累计黑色像素数量 black_count 及其坐标和，同时记录最小、最大黑点坐标。black_count 小于 BLACK_COUNT_MIN 或大于 BLACK_COUNT_MAX 时直接判为无效目标。
靶心中心由黑点平均坐标得到。由于本任务中的目标是黑色圆环，内部是白色感光纸，因此代码还读取 center_pixel，并要求中心像素亮度大于 white_min_point。这个条件用于排除普通黑块，保证激光目标更接近“白心黑环”的结构。
5.6.3 打靶窗口补偿
select() 根据速度模式和环岛状态选择不同的打靶窗口参数。普通赛道使用 shot_low、shot_high；圆环中使用 shot_i_low、shot_i_high。angle 为正或为负时，分别使用右转和左转的补偿参数 shot_R6h、shot_R6w、shot_L6h、shot_L6w。
offset1 主要修正纵向打靶窗口，即目标在图像中应该进入的行范围；offset2 主要修正横向激光分区，使车辆转向时仍能选择正确的激光通道。该设计将打靶时机与车辆动态状态绑定，适合边行驶边打靶的任务。
5.6.4 激光分区发射
fire() 先判断目标中心是否位于 y_low 和 y_high 之间，再按 center_x 所在区间选择激光 GPIO。当前代码将横向范围分为五段，分别对应IO口。每次触发后置位 calm_down，由 calm() 在后续周期中关闭激光并完成冷却。
这种“多路激光分区”方案不需要实时旋转激光头，而是通过识别靶心横坐标选择固定激光通道。优点是响应快、结构简单；缺点是需要通过实车标定保证每个横向区间与实际激光落点对应。

    }
    else

        abs_angle = -steer_angle;
    }
		if(Island_State !=0&& Island_State !=9 && type != 0)//小环
		{
				diff_speed = (int32)Base_Speed * abs_angle * Ack_K_yh/ 32200;

				{
						Speed_Left_Set  = Base_Speed + (int)diff_speed;
						Speed_Right_Set = Base_Speed - (int)diff_speed*125/100;
				}
				else if(steer_angle < 0)            // 左转：左轮减速，右轮加速

						Speed_Left_Set  = Base_Speed - (int)diff_speed*12/10;

				}
				else                                // 直行
				{
						Speed_Left_Set  = Base_Speed;
						Speed_Right_Set = Base_Speed;
				}
		}
		else if(Island_State !=0&& Island_State !=9 && type == 0)//大环
		{
				diff_speed = (int32)Base_Speed * abs_angle * Ack_K_yh/ 32200;
				if(steer_angle > 0)                 // 右转：右轮减速，左轮加速
				{
						Speed_Left_Set  = Base_Speed + (int)diff_speed;
						Speed_Right_Set = Base_Speed - (int)diff_speed*105/100;
				}
				else if(steer_angle < 0)            // 左转：左轮减速，右轮加速
				{
						Speed_Left_Set  = Base_Speed - (int)diff_speed;
						Speed_Right_Set = Base_Speed + (int)diff_speed;
				}
				else                                // 直行
				{
						Speed_Left_Set  = Base_Speed;
						Speed_Right_Set = Base_Speed;
				}
		}
		else
		{
				diff_speed = (int32)Base_Speed * abs_angle * Ack_K/ 32200;
				if(steer_angle > 0)                 // 右转：右轮减速，左轮加速
				{
						Speed_Left_Set  = Base_Speed + (int)diff_speed/10;
						Speed_Right_Set = Base_Speed - (int)diff_speed*14/10;
				}
				else if(steer_angle < 0)            // 左转：左轮减速，右轮加速
				{
						Speed_Left_Set  = Base_Speed - (int)diff_speed*135/100;

				}
				else                                // 直行

				}
		}

 volatile int PID_L(int set_speed ,int speed)//pid控制电机转速
{
    volatile static int out;
    volatile static int out_increment;
    volatile static int ek,ek1,ek2;


		ek2 = ek1;
    ek1 = ek;
    ek = set_speed - speed;
	  
    out_increment= (int)(Lkp*(ek-ek1) + Lki*ek + Lkd*(ek-2*ek1+ek2));
    out+= out_increment;
    
		
		
    if(out>=SPEED_MAX)//限幅处理
        out=SPEED_MAX;
    else if(out<=SPEED_MIN)
        out=SPEED_MIN;
    return (int) out;
}

volatile int PID_R(int set_speed ,int speed)//pid控制电机转速
{
    volatile static int  out;
    volatile static int  out_increment;
    volatile static int  ek,ek1,ek2;

	
		ek2 = ek1;
    ek1 = ek;
    ek = set_speed - speed;

	
    out_increment= (int)(Rkp*(ek-ek1) + Rki*ek + Rkd*(ek-2*ek1+ek2));	   
    out+= out_increment;

    if(out>=SPEED_MAX)//限幅处理
        out=SPEED_MAX;
    else if(out<=SPEED_MIN)
        out=SPEED_MIN;
    return (int) out;
}
