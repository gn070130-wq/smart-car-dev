摘  要
本报告面向第二十一届全国大学生智能汽车竞赛雁过留痕（本科）组，说明“啊对对队”智能车的总体方案、机械与器件安装、硬件电路、图像识别与控制算法、制作调试、安全策略以及技术参数。系统采用 STC32G144K 作为控制核心，MT9V03X 灰度摄像头以 188×120 分辨率获取赛道与靶标信息，IMU963RA 和双编码器提供姿态与轮速反馈；执行端由转向舵机、双后轮电机、双负压装置以及七路100 mW、5 V蓝紫光源构成。
软件采用图像帧事件与固定周期任务相结合的结构。图像链路完成动态白点估计、最长白列搜索、左右边界提取、中线重建、十字与环岛状态判断、斑马线识别和靶标定位；车辆控制链路以 5 ms 为周期完成编码器读取、惯性量更新、车辆安全、速度闭环和阿克曼差速；紫外光源由独立 1 ms 关断定时任务管理。最新版工程中，摄像头曝光参数为 260，1—6 路照射脉冲为 15 ms，第 7 路为 20 ms。
报告以当前可核验源码、整车实测结果、电池铭牌参数和最终版BOM为依据，不填写未经实测的数据。整车质量、外形尺寸、电池参数、有效图像处理频率及按BOM统计的总电容已补录至第六章；目标检测和完整任务均完成10次重复测试，其中成功9次，实测成功率均为90%。相关原理图、PCB资料和主要自主编写源文件收录于附录，便于复核、维护和答辩。

第一章  引言
1.1 竞赛背景与研究目标
第二十一届全国大学生智能汽车竞赛“雁过留痕（本科）组”要求车辆在赛道环境中稳定运动，利用车载视觉识别道路结构和任务目标，并在满足触发条件时驱动对应位置的紫外光源完成照射。技术报告需完整呈现总体方案、关键技术、技术指标、存在问题和改进方向[1]。因此，本系统除循迹和特殊元素通过能力外，还必须协调负压、驱动、转向、目标识别和七路输出；任何环节的时序漂移都可能造成偏航、错位照射或保护动作。
本车采用“前轮舵机转向、双后轮独立驱动、双负压辅助、单目灰度视觉主感知”的总体结构。控制器负责图像处理与执行器协调，编码器用于闭环轮速，IMU 用于获取角速度信息，七路紫外照射装置沿前端横梁布置。设计重点不是堆叠算法，而是保持感知、控制和执行链路的确定性：图像处理随新帧触发，车辆控制以 5 ms 周期运行，光源关断以 1 ms 周期独立运行。
相关资料中，STC32G 系列数据手册与逐飞开源库为主控外设配置、定时器和工程接口提供依据[2-3]；MT9V03X 与 IMU963RA 使用资料分别支撑灰度图像采集和惯性量获取[4-5]；车辆动力学与控制文献为转向误差、速度闭环和差速分配的分析提供参考[6]。本文在上述资料基础上结合现有源码与实车结构开展一致性梳理，所有定量结论均以可核验配置或最终封车实测记录为准。

第二章  机械结构与器件安装
2.1 整车结构布局
整车采用前轮转向、双后轮驱动布局。车体后部为驱动轮与编码器区域，中部集中布置主控板、电源连接和执行器接口，摄像头通过竖直支架置于车体中轴附近，前端横梁安装七个紫外光源模块。双负压执行单元位于车体左右，尽量保持横向质量和吸附能力对称。

图2.1  整车正视、侧视与俯视结构
图2.1 反映了当前实车的相对布置关系。摄像头立杆位于车辆前中部，保证视场中心与车辆纵向中心线接近；七路照射单元在前端横梁上展开，以覆盖不同横向位置；左右负压单元相对分布，减少单侧负载对转向和轮胎附着的影响。最终封车时应再次检查紧固件、线束摆动范围和前轮全转角干涉。
2.2 摄像头与惯性传感器安装
MT9V03X 的安装高度和俯仰角决定有效前瞻范围、近端盲区与目标成像尺度。安装时以车辆中轴为横向基准，先保证镜头无明显侧倾，再通过赛道图像检查左右边界在直道中的对称性。软件使用固定 188×120 图像尺寸和曝光参数 260，因此机械调整完成后不应随意改变镜头位置或曝光，否则边缘阈值、最长白列和目标行标定需要重新验证。[4]
IMU963RA 应固定在振动相对较小且方向明确的位置，避免软质胶层过厚造成低频晃动。程序启动阶段连续采样 1000 次，每次间隔 5 ms，计算 Z 轴角速度零偏；因此车辆上电后的约 5 s 内应保持静止。编码器与左右驱动轮一一对应，右侧计数在软件中进行符号修正，使两侧前进方向反馈保持同号。[5]
2.3 紫外照射装置与负压单元
七路100 mW蓝紫光源沿横梁从左至右布置，软件逻辑位置为1—7，各模块采用5 V供电。安装时应保证各通道朝向、机械零位和导线编号一致，防止图像横向位置与实际输出通道颠倒。各模块需要具备可靠固定、绝缘和遮光措施，避免振动导致照射方向漂移或引线疲劳。
双负压装置使用两路 300 Hz PWM 同步渐增，5 s 内由 0 提升到最大占空参数 5600。左右吸附结构的密封和间隙应尽量一致；若一侧泄漏明显，会引起横向附着差异并放大高速转向时的姿态变化。负压风机周围需留出进排气空间，线束不得进入叶轮区域。
2.4 机械可靠性检查要点
摄像头支架在轻微碰撞和负压振动下不应产生可见松动，镜头表面保持清洁。
舵机连杆在 ±510 控制限幅对应的全行程内无卡滞，左右转向余量基本一致。
编码器连接、轮胎紧固和齿轮啮合可靠，空转时两侧反馈符号与幅值符合预期。
七路光源的通道标签同时标注在横梁、插头和主控接口处，便于赛前快速排查。
负压单元、车轮和地面之间无干涉，风机防护圈和导线固定点能够承受连续运行振动。

第三章  硬件电路设计
3.1 硬件总体拓扑

图3.1  电气连接与能量流向
硬件设计围绕“逻辑控制与功率执行分区、周期信号与大电流回路分离”展开。主控板接收摄像头、IMU、编码器和按键输入，输出舵机 PWM、两路电机 PWM、两路负压 PWM 以及七路紫外光源控制。动力电机和负压装置属于快速变化的大电流负载，应与摄像头和惯性传感器的供电、地回流及信号线保持合理间隔。
3.2 主控与传感器接口
STC32G144K 以 96 MHz 运行。摄像头初始化后设置曝光参数 260，帧完成标志用于通知主循环处理新图像；IMU963RA 在初始化和零偏计算后由 5 ms 任务读取；左右编码器使用带方向增量编码器接口，每周期读取并清零计数器。该结构把高速图像采集、周期反馈和低频按键输入分开处理，便于定位接口故障。[2-3]

3.3 电机、舵机与负压驱动
左右驱动电机使用 17 kHz PWM，以减少可闻噪声并获得较平滑的占空调节。方向引脚和 PWM 引脚分别控制转向与幅值，软件将速度闭环输出限制在 ±6000，并在停止函数中同步清零目标速度、占空累积量、阿克曼差速状态和 PID 历史量。这样可避免车辆再次启动时继承旧控制状态。
舵机使用 300 Hz PWM，中值为 3900。方向控制器输出 `server_out` 后先限制在 ±510，再写入 PWM，并把取整后的控制量提供给 5 ms 阿克曼差速计算。双负压也使用 300 Hz PWM；渐增算法通过整数步长和余数累加，在 1000 个 5 ms 周期内准确到达 5600，而不是一次性跳变。
3.4 七路紫外光源输出
七路输出均由 GPIO 控制，初始化时保持关闭。目标状态机根据预测中心列选择逻辑通道，输出后设置剩余时间计数；TIM10 每 1 ms 递减计数并在到期时关闭所有通道。第 1—6 路脉冲宽度为 15 ms，第 7 路为 20 ms。独立关断任务避免主循环图像处理、通信或显示调试造成脉冲拖长。
3.5 电源完整性与布线原则
负压风机与驱动电机启动会产生较大的电流变化。硬件布线应使动力回路尽量短而粗，逻辑电源在主控附近完成去耦，摄像头与 IMU 信号线避开电机 PWM 和风机线路。各模块地线最终应形成低阻公共参考，避免把电机回流路径串入传感器地。主控、电机驱动、负压驱动和七路输出连接器应有防反插或清晰标识。

第四章  图像识别、人工智能说明与控制算法
4.1 软件总体结构
人工智能说明：本车没有使用神经网络、深度学习或其他需要训练数据的模型。报告中所称的智能识别，实际由传统图像处理、几何判断、规则状态机和闭环控制实现，不虚构训练数据、模型精度或人工智能性能指标。

图4.1  图像识别与控制信息流
主循环中保留 `uart_control_process()` 与 `target_report_process()`，用于命令处理和照射结果上报；摄像头图像发送初始化与发送调用当前处于注释状态，因此不能表述为整套通信功能已关闭。新帧到达时，程序先清除帧完成标志，再调用 `image_process()`，把 `Image_Error` 写入方向误差，最后执行 `servo_Control()`。这种次序使处理期间到达的新帧仍可在下一次循环中被识别。
4.2 图像采集与灰度基准
MT9V03X 输出 188×120 灰度图像。当前初始化代码在摄像头启动后调用 `mt9v03x_set_exposure_time(260)`，因此本报告统一采用曝光参数 260。赛道识别并非直接使用固定二值化阈值，而是统计图像底部搜索区的灰度直方图，从亮端向暗端寻找白色区间，再取偏向亮端的参考值并进行限速平滑，得到当前白点 `current_white`。[4]
边缘判别使用亮暗像素差与灰度和的比例关系，并通过交叉相乘避免逐像素除法。该方法先排除亮暗关系错误、对比度过低和整体过暗的像素，再判断相对差异是否超过阈值。与单一固定灰度阈值相比，它对整体亮度变化具有更好的适应性，但摄像头位置、曝光和补光条件发生明显变化时仍需重新验证。
4.3 最长白列、边界提取与中线重建
程序在限定列范围内自图像底部向上搜索亮暗跳变，记录各采样列的最远可见行和列坐标，并选择整体最长白列作为边界搜索参考。若某列与锚点偏差过大，会进行全列重扫以抑制局部噪声。以最长白列为参考后，算法分别向左右寻找满足相对灰度差条件的边缘，形成 `l_border[]` 与 `r_border[]`。
当左右边界均有效时，中线取两者平均；单边缺失时根据预先标定的赛道半宽表估算另一侧或直接恢复中线。特殊元素补线完成后，方向误差计算在设定前瞻行附近使用多行加权，中心行权重最大，邻近行权重递减。若窗口内无有效中线，程序先向车身方向、再向远端搜索最近有效行；全图丢线时先保持上次误差 3 帧，随后按 3/4 比例逐帧衰减。

4.4 十字、环岛与斑马线处理
十字和环岛使用状态机而非单帧阈值判定。程序先检查左右边界有效性、连续性和拐点，再根据进入方向和阶段执行分段补线。环岛状态锁存后，十字候选会被清除；处于十字阶段时暂停环岛检测，从而避免相似缺边特征相互抢占。左右环岛分别维护镜像状态，补线过程根据可见侧边界、拐点和半宽表恢复中线。
系统通过状态机记录当前赛道元素与目标识别阶段，识别逻辑在全图范围运行。当满足连续帧、位置和形态判据时，程序进入对应状态，并在规定阶段完成速度调整、转向控制和目标执行。在固定测试条件下进行了10次目标检测测试，其中9次正确识别并给出有效目标位置，目标检测成功率为90%。
4.5 靶标识别、预测与通道选择
靶标流程包含等待远端识别、远端跟踪、近端精跟踪和紫外照射四个状态。算法在指定行列步长内搜索候选点，远端状态获得中心后，近端状态围绕上一中心列建立较窄窗口，必要时扩大窗口重新搜索。目标中心的横向变化在两帧间进行趋势检查，过大的跳变被视为不可靠；有效趋势用于把当前中心预测到标定命中行。
当前工程设置短距离触发行 75、标定命中行 95，横向最终补偿限制为 ±5 列，前向预测不超过 20 行。达到触发条件后，预测中心列映射到七个逻辑位置，选择对应紫外光源。若车辆进入十字或环岛，或斑马线仍在画面内，程序调用取消函数并立即关闭全部通道，防止识别状态与赛道元素状态冲突。
4.6 转向控制
舵机控制以图像方向误差为输入。控制器计算 `server_out` 后限制在 ±510，并以 `server_mid - server_out` 写入 300 Hz PWM，其中舵机中值为 3900。限幅后的浮点控制量按符号四舍五入为整数 `servo_steer_command`，供 5 ms 电机差速任务读取，避免中断读取主循环正在更新的浮点量。
工程中保留了模糊调整比例、微分参数的相关结构，但正式描述以当前实际调用路径为准：主循环直接调用 `servo_Control()`，电机任务读取限幅后的舵机指令进行阿克曼差速。调试时应分别确认图像误差符号、舵机偏转方向和差速方向，三者必须形成负反馈。
4.7 双电机速度闭环
左右编码器每 5 ms 读取一次，得到当前周期轮速增量。电机使用增量式 PID 结构，左侧参数为 Kp=13、Ki=1.6、Kd=0，右侧参数为 Kp=19、Ki=2、Kd=0。两侧参数不同是针对实际电机、传动和负载差异进行的独立补偿，不能在没有复测的情况下强行设为一致。
PID 输出累加到浮点占空量并限制在 ±6000，最终取整后设置 PWM 和方向。停车函数同时清除左右占空、目标速度、误差历史和差速状态，保证再次启动时从确定状态开始。基础目标速度当前为 170，实际物理速度需要结合编码器线数、轮径和 5 ms 周期换算后测量，本报告不作无依据换算。
4.8 阿克曼几何差速

图4.2  阿克曼几何差速参数示意
车辆转弯时，左右后轮路径半径不同。程序把舵机控制量按最大前轮角40°线性换算为前轮偏转角δ，并根据轴距L=0.200 m、后轮距T=0.155 m计算单侧差速量：
	Δv = V·k·T/(2L)·tan(δ)	公式1
其中基础速度V=170、差速增益k=0.7，计算结果限制在±30。
为避免方向变化时轮速指令突变，差速应用值每个 5 ms 周期最多变化 5。正负方向由 `ACKERMANN_STEER_DIRECTION` 统一定义，当前实现的目标是左转时左后轮减速、右后轮加速。三角函数使用适用于 40° 范围的多项式近似，减少对数学库的依赖。
4.9 紫外光源定时与结果上报
通道选定后，1—6 路设置 15 ms 剩余时间，第 7 路设置 20 ms。`laser_off_handler()` 在 TIM10 中每 1 ms 调用，剩余时间归零时关闭所有输出。目标结果先写入单条待发送记录，再由主循环 `target_report_process()` 调用串口发送，使目标处理不依赖传输耗时。工程中 Wi-Fi 图像调试初始化和发送调用目前被注释，必要时可在调试版本中恢复，但不应进入正式竞赛版本的硬实时路径。
4.10 算法协同与异常恢复
图像处理按照“基础赛道几何—特殊元素状态—靶标任务—方向误差”的顺序协同运行。十字、环岛或斑马线状态有效时，程序优先维护赛道边界和补线结果；若当前道路状态不适合继续照射，则取消靶标任务并关闭全部紫外输出，避免任务状态与循迹状态相互竞争。
对于边界短时缺失和目标中心跳变，系统采用受限恢复而不是立即接受异常结果。恢复策略只在有限时间和可信条件内保持，停车、急停、堵转或任务取消时同步清除相关历史状态与执行输出。
仅单侧边界可信时，利用已知赛道宽度和另一侧趋势恢复中线，双侧同时失效时不无限外推。
允许在有限帧数内保留上一帧有效几何，超过持续时间后转入降级或停车策略。
目标中心出现大幅跳变时先检查运动趋势和赛道位置关系，不直接据此选择照射通道。
任何保护状态触发后，方向、速度、负压和七路紫外输出按联锁逻辑处理，恢复运行前重新确认状态。

5.1 开发工具、制作与安装顺序
软件开发与编译在Windows 11 64位环境下完成，工程使用Keil μVision 5.43.1.0组织，采用C251编译器5.04b，主工程文件为project/mdk/seekfree.uvproj，编译目标为stc32g144k246；STC-ISP v6.89C用于程序下载。原理图与PCB使用嘉立创EDA（专业版）3.2.121设计，示波器用于紫外输出脉宽和image_process()测试引脚频率测量。工程按zf_common、zf_driver、zf_device、user和code等目录管理启动文件、逐飞库及自主编写的C源文件。
整车调试遵循“单模块验证—静态联合—低速赛道—任务联调—连续运行”的顺序。先确认电源极性和各路默认关闭，再分别验证摄像头图像、IMU 静态零偏、左右编码器方向、舵机中位、双电机方向、双负压渐增和七路输出编号。单模块通过后，才允许安装负载并进入闭环行驶。
上电静止约 5 s，完成 IMU 1000 次零偏采样；确认车辆没有被移动或振动。
架空驱动轮，低目标速度验证左右编码器符号、PWM 方向和停止清零。
在直道上固定曝光 260，校准摄像头中心、前瞻区和左右边界对称性。
依次调节舵机方向、速度 PID 和阿克曼差速，先保证稳定，再提高响应。
逐路触发七个逻辑位置，核对 PA7 至 P44 的实际横向顺序和脉冲宽度。
最后验证十字、左右环岛、斑马线与目标状态的优先关系以及取消动作。
5.2 图像与控制参数调试
图像调试首先观察原始灰度、动态白点、最长白列、左右边界和中线，确认问题属于成像、阈值还是几何补线。曝光参数已经在最新工程中固定为 260，若现场照明导致整体过暗或过曝，应先从遮光、镜头、补光和安装角度排查，再决定是否修改曝光；任何修改都需同步复测赛道元素和靶标行标定。
控制调试采用逐层闭环。舵机中值应先在静止状态校正，再以低速确认误差方向；速度 PID 在架空和落地两种条件下比较左右响应，避免积分过强造成启动冲击；阿克曼差速在基础循迹稳定后开启，依次确认方向、增益 0.7、限幅 30 和 5/5 ms 变化率是否适合当前轮胎附着。[6]
5.3 启动、急停与负压联锁
车辆启动请求不会立即使能驱动电机，而是先置位负压使能和启动等待状态。双负压输出在 1000 个 5 ms 周期内渐增，达到 5600 后才置位电机使能。该联锁避免车辆在附着尚未建立时突然运动。急停函数先清除电机、负压和等待标志，再关闭负压输出并停止电机，使同一 5 ms 周期内不会被旧状态重新开启。
5.4 堵转保护
堵转判据同时检查目标速度和编码器反馈：当目标速度绝对值不小于 60、编码器速度绝对值不大于 3，并连续满足 100 个 5 ms 周期，即持续 500 ms 时，判定对应驱动轮堵转。任一侧确认堵转后，系统锁存故障并关闭双电机与双负压。电机刚使能后的前 100 个周期同样为 500 ms 忽略窗口，用于避免启动阶段误判。
堵转故障锁存后，单纯再次启动不会恢复输出，必须先执行停止/复位流程清除故障，再重新建立负压并启动车辆。该策略防止机械卡死、赛道边缘阻挡或车轮无法转动时持续施加功率。实际比赛前还应验证编码器插头松脱是否会触发相同保护，并确认操作人员能够快速识别故障提示。

后续改进应首先对目标检测和完整任务各1次失败过程进行录像、日志与控制状态复盘；随后针对不同曝光、车速、电池状态和场地条件增加异常样本，优化视觉阈值、目标定位和元素切换参数。最终应对照冻结的原理图、PCB、BOM、照片、源码与报告版本，形成可复现的提交前检查流程。

B.5  阿克曼差速目标计算
文件：project\code\PID.c
static float Ackermann_Differential_Target(int speed, float gain, int limit)
{
    float servo_command;
    float steer_angle_rad;
    float tan_steer;
    float differential;
    float differential_limit;
 
    servo_command = Limit_float222(-ACKERMANN_SERVO_COMMAND_MAX,
                                   (float)servo_steer_command,
                                   ACKERMANN_SERVO_COMMAND_MAX);
 
    motor_ackermann_steer_angle_deg = servo_command
                                    * motor_ackermann_max_angle_deg
                                    / ACKERMANN_SERVO_COMMAND_MAX;
    steer_angle_rad = motor_ackermann_steer_angle_deg * ACKERMANN_DEG_TO_RAD;
    tan_steer = Ackermann_Tan(steer_angle_rad);
 
    differential = (float)speed * gain
                 * (ACKERMANN_REAR_TRACK_M / (2.0f * ACKERMANN_WHEEL_BASE_M))
                 * tan_steer * ACKERMANN_STEER_DIRECTION;
 
    differential_limit = (float)limit;
    if(differential_limit < 0.0f)
    {
        differential_limit = -differential_limit;
    }
 
    return Limit_float222(-differential_limit, differential, differential_limit);
}
