摘 要
本文设计的智能车系统以TC264与TC4D7作为控制单元，采用摄像头读取赛道信息；采用陀螺仪检测车模的角速度；通过光电编码器检测车模的打角与车速，使用PID控制算法调节电机的转速，实现对车模运动速度和运动方向的闭环控制。为了提高车模的速度和稳定性，使用键盘显示模块、上位机等调试工具，对硬件与软件进行反复调试和改进。

该竞赛融创新性、科学性、趣味性和观赏性为一体。在创新性和科学性方面，竞赛以前景广阔的智能汽车为背景，包含了自动控制、模式识别、传感技术、电子、电气、计算机、机械等多学科专业。竞赛要求各参赛队在使用竞赛秘书处规定范围内的标准硬软件技术平台，保证了竞赛的一致性和公平性。竞赛要求学生以小组或团队的形式报名参加，激励学生体会一个工程实践活动从理论设计到最后实现的全部过程。趣味性方面，竞赛过程包括理论设计、实际制作、整车调试、现场比赛等多个环节。观赏性方面，学生可以在观众席、线上直播平台等多角度观看比赛的同时还有现场解说。该竞赛规则透明，评价标准客观，坚持公开、公平、公正的原则，保证竞赛向健康、普及，持续的方向发展，深受广大师生的欢迎。

第二章  方案设计
本章对智能车系统的总体设计思路进行简要介绍，为后续深入分析奠定基础。在之后的章节中，将按照系统的构成逻辑，分别从机械结构、硬件电路和控制算法三个关键组成部分，对智能车控制系统展开全面且深入的阐述与剖析，详细呈现各部分的设计原理、实现方式及性能特点。​
本届全国大学生智能车竞赛竞速比赛卡丁赛跑组别的规则明确规定，比赛分为三个科目，从易到难，分别考察制作车模作品不同的运动特性。这一规则对车模的综合性能提出了严苛要求，包括车模转向特性，传感器检测精度，车模稳定性，识别能力等。
在机械结构设计层面，以稳定为核心目标。为了达成这一目标，我们对转向连杆，减速箱，车轮进行了重点改装与优化。转向连杆决定了转向虚位；减速箱内部改装了光栅编码器进行速度闭环，它的安装也决定了转向虚位；车轮决定车辆的抓地力，行驶阻力。​
在硬件电路设计方面，我们始终秉持简洁、可靠的设计理念。围绕这一理念，重点对电源模块、驱动模块进行了设计。
车模的微控制器选用Infineon AURIX™系列单片机中的 TC264与TC4D7，TC系列单片机具备较强的运算处理能力和丰富的外设接口，能够满足车模图像识别以及控制系统的需求。软件开发工作在 ADS与ACS开发环境中完成，确保了程序开发的高效性与可靠性。在系统的感知与控制环节，通过摄像头获取图像信息并由TC4D7结算处理；陀螺仪实时获取车模当前状态的角速度，从而精准掌握车模的姿态信息；减速箱内的编码器负责记录车模运动，将采集到的信号准确传送至控制核心；编码器测速模块则用于实时检测车模的转向角度与行驶速度。基于这些采集到的信息，利用 PID 控制算法实现对车模的闭环控制，使车模能够根据实际工况及时调整运动状态，保证行驶的稳定性与精准性。同时，借助蓝牙、串口、上位机等多种调试工具，对车模的控制参数进行持续优化与完善，确保车模能够稳定、高效地完成卡丁快跑的比赛任务。

第四章  电路设计说明
智能车电路部分的主要模块包括：单片机最小系统、电源模块、传感器模块、驱动模块。各模块的总体设计原则是：紧凑、易于拆换、稳定可靠。但根据各模块的不同，又有不同的设计要求，本章对各个模块的设计进行详细描述。
4.1 电源模块设计
电源设计的核心指标在于可靠性，整个硬件系统的稳定运行取决于电源供电的稳定性。电源供电不稳定可能导致电池损耗加剧、单片机复位、传感器损毁等严重问题，因此电源设计是硬件电路设计中至关重要的环节之一。
本车使用电源额定24V、14Ah、0.5C铅酸电瓶与额定37V、8Ah、5C锂电池，选择其一为整车供电；在分区赛结束后，车辆速度受限于电机极限转速，我们采用超过电机额定电压供电的方式进一步提升车辆性能，但由于缺乏大量测试，额定37V锂电池场上作为备选方案。
电源模块我们选择了两种DCDC稳压芯片，分别是TPS5450与TPS54561；两种LDO稳压芯片，分别是AMS1117-3.3V与A33B5。
TPS5450电压输入范围为5.5V-36V，输出电压通过分压电阻可调，其开关式架构让降压过程能量损耗低，输入输出电压差较大时，仍能高效输出稳定电压，保证像大功率负载在复杂电源环境下正常工作，同时，它输出电流峰值可达6A，足够供应多组外设电路的用电需求，设计原理图如图4-1-1。

第五章  智能车控制软件设计
控制程序是人的智慧在车模中的体现，程序要体系化，模块化，稳定化，目标是使硬件电路和机械性能得到最大发挥，在考虑耗能的前提下让车模用最快的速度完成比赛。 
5.1 使用到的外设
0核初始化函数负责实时性要求较高的控制任务，涉及以下外设：
GPIO：配置为输入与输出模式。输入引脚用于读取拨码开关或按键的使能信号，输出引脚用于向电机驱动板发送使能信号，确保驱动电路在安全条件下工作；
PWM：用于控制扬声器和舵机，驱动两个后轮和一个转向电机；
编码器：采用正交解码方式，通过两个后轮电机及转向电机自带的光电编码器获取实时转速反馈。编码器计数周期设为1ms，通过M法测速计算实际转速；
陀螺仪：使用ICM20602六轴传感器，通过SPI接口与0核通信。初始化完成后，以1kHz采样率读取角速度与加速度原始数据，用于姿态解算与惯性导航；

1核初始化函数负责非实时的人机交互任务：
键显初始化：配置OLED显示屏与独立按键，用于显示当前速度、方向偏差、PID输出等关键参数，并支持在线调节PID系数，便于调试；

5.2 传感器信号处理
在转向与速度控制中，本系统采用鲁棒性良好的经典PID控制算法，并结合理论计算与实际参数补偿，确保智能车行驶平稳。

速度控制的精度要求低于方向控制，仅需在较短时间内逼近目标速度，允许一定误差范围。考虑到智能车作为大惯性系统，其速度在控制周期内不会剧烈突变，因此选用PID结构。经反复调试，选定合适的比例系数（P）以防止加速超调；引入积分项（I）以抑制行驶阻力等因素造成的稳态偏差；同时加入微分项（D）以补偿车模惯性对动态响应的影响，提升控制的快速性与稳定性。

5.3 惯性导航算法
本系统采用的惯性导航算法以Stanley算法为理论核心，并针对四轮卡丁车的实际行驶工况进行了适配性改进。具体措施包括：适当延长惯导姿态解算周期，以防止微小角速度读数在积分运算中因精度截断而被舍去，从而提升数值稳定性；同时在姿态解算链路中引入一阶低通滤波，有效抑制车体高频振动及传感器噪声对导航精度的干扰。

5.4 视觉跟随部分
图像采集采用逐飞公司出品的高帧率凌曈摄像头，通过排线连接至TC4D7处理器。TC4D7对接收到的彩色图像进行预处理，先将RGB格式转换为HSL色彩空间，再通过色块检测算法提取目标色块的大小与位置坐标。最终，将处理得到的视觉信息通过串口通信传送至负责整车控制的TC264主控芯片，作为路径跟随与决策的依据。

int core0_main(void)
{

    clock_init();                   // 获取时钟频率<务必保留>
    // 此处编写用户代码 例如外设初始化代码等
    interrupt_global_disable();     // 关闭全局中断

//    // 初始化默认调试串口
//    debug_init();


    // 初始化
    Init_All();

    Uart_Communication_init();

    // 初始化sbus遥控器串口
    remote_control_init();

    // 点阵屏初始化
    dot_matrix_screen_init();

    // 初始化在线监测
    Device_MonitoringInit(DeviceID_NULL, DeviceID_RC);

    // 此处编写用户代码 例如外设初始化代码等
    pit_ms_init(CCU60_CH0, 2);       //定时中断初始化并配置中断时间
    pit_ms_init(CCU60_CH1, 1);

    // 此处编写用户代码 例如外设初始化代码等
    cpu_wait_event_ready();         // 等待所有核心初始化完毕
    interrupt_global_enable(0);     // 打开全局中断

    if (Sub.Sub_Sel == Subject_2)
    {
        Sub2_GetAllPath();
    }

    while (TRUE)
    {
        if (gpio_get_level(ASR_BUTTON) == 1)
        {
            Close_Task();                 // 关灯/鸣笛/雨刷残留
            dot_matrix_screen_set_brightness(0); // 关闭点阵屏
            Path_Flag = 0;                // 下次门洞任务重新从 Flash 装路径
            Task_Count = 0;
            Sub.Sub2_Act = None_2;        // 停掉当前动作
            Sub.SubState = Stop;          // 路径侧停车
            Sub.Sub2_State = Sub2_Listen; // 重新等待语音
            asr_result_ready = 0;         // 清掉可能残留的识别结果
            offline_asr_result = 0;
        }

        if (Device_GetState(DeviceID_RC) == DeviceState_Online)
        {
            if (rc_ctrl.ch.sw_c == RC_SW_UP)
            {
                gpio_set_level(Light_Low, 0);
                gpio_set_level(Light_High, 0);
            }
            else if (rc_ctrl.ch.sw_c == RC_SW_MID)
            {
                gpio_set_level(Light_Low, 1);
                gpio_set_level(Light_High, 0);
            }
            else if (rc_ctrl.ch.sw_c == RC_SW_DOWN)
            {
                gpio_set_level(Light_Low, 0);
                gpio_set_level(Light_High, 1);
            }
        }
        else
        {
            gpio_set_level(Light_Low, 0);
            gpio_set_level(Light_High, 0);
        }

        dbg[0] = gpio_get_level(Acc);
        dbg[1] = gpio_get_level(Brake);
        // vofa发送
        vofa_send_data();
    }
}

float Stanley_Run(Stanley_TypeDef* stanley, PathPoint_TypeDef* pathpoint, CarState_TypeDef* carstate)
{
    // 处理倒车
    if (Sub.SubState == Back)
    {
        // 取两点之间的连线作为目标直线，倒车时，方向由下一个点指向上一个点，对末尾点单独处理
        if (Stanley.BackNowPoint == Stanley.BackSumPoint)
        {
            theta = atan2((PathPointBack[Stanley.BackNowPoint-1].y - PathPointBack[Stanley.BackNowPoint].y),(PathPointBack[Stanley.BackNowPoint-1].x - PathPointBack[Stanley.BackNowPoint].x));
        }
        else
        {
            theta = atan2((PathPointBack[Stanley.BackNowPoint].y - PathPointBack[Stanley.BackNowPoint+1].y),(PathPointBack[Stanley.BackNowPoint].x - PathPointBack[Stanley.BackNowPoint+1].x));
        }

        // 绝对角度统一为0-2PI
        if (theta < 0)
        {
            theta += 2*PI;
        }
    }
    else
    {
        // 取两点之间的连线作为目标直线，前进时，方向由上一个一个点指向下一个点，对末尾点单独处理
        if (Stanley.NowPoint == Stanley.SumPoint)
        {
            theta = atan2((PathPoint[Stanley.NowPoint].y - PathPoint[Stanley.NowPoint-1].y),(PathPoint[Stanley.NowPoint].x - PathPoint[Stanley.NowPoint-1].x));
        }
        else
        {
            theta = atan2((PathPoint[Stanley.NowPoint + 1].y - PathPoint[Stanley.NowPoint].y),(PathPoint[Stanley.NowPoint + 1].x - PathPoint[Stanley.NowPoint].x));

            // 绝对角度统一为0-2PI
            if (theta < 0)
            {
                theta += 2*PI;
            }
        }

    }

    // 计算横向误差
    stanley->lat = (carstate->now_x - pathpoint->x) * sin(theta) - (carstate->now_y - pathpoint->y) * cos(theta);

    // 计算左半部分角度
    stanley->delta_e = theta - carstate->now_yaw;

    // 归一化到 [-PI, PI]
    if (stanley->delta_e >= PI)
    {
        stanley->delta_e -= 2 * PI;
    }
    if (stanley->delta_e < -PI)
    {
        stanley->delta_e += 2 * PI;
    }

//    // 计算右半部分角度
//    stanley->delta_lat = (float)atan(0.001*stanley->k_gain * stanley->lat);

    // 计算最终航向角
    if (Sub.SubState == Back)
    {
        stanley->delta_lat = (float)atan(0.001* k_Back * stanley->lat);

        stanley->delta = -stanley->delta_e + stanley->delta_lat;
    }
    else
    {
        stanley->delta_lat = (float)atan(0.001*stanley->k_gain * stanley->lat);

        stanley->delta = stanley->delta_e + stanley->delta_lat;
    }

    if (Sub.Sub_Sel == Subject_2)
    {
        if (Sub.Sub2_Act == Gate1_Right_Return
                ||Sub.Sub2_Act == Gate1_Return
                ||Sub.Sub2_Act == Gate2_Return
                ||Sub.Sub2_Act == Gate3_Return
                ||Sub.Sub2_Act == Gate3_Left_Return)
        {
            stanley->delta_lat = (float)atan(0.001* k_Back * stanley->lat);

            stanley->delta = -stanley->delta_e + stanley->delta_lat;

        }
    }

    stanley->delta = Amplitude_Limit(stanley->delta, -PI/6.0, PI/6.0);

    return stanley->delta;
}
