引    言
全国大学生智能汽车竞赛是由教育部高等学校自动化类专业教学指导委员会创办、现由中国自动化学会主办的一项面向全国大学生的具有探索性质的工程实践活动。竞赛以“立足培养、重在参与、鼓励探索、追求卓越”为指导思想，以设计制作在特定赛道上能够自主行驶且具有优越性能的智能模型汽车这类复杂工程问题为任务，鼓励大学生综合运用自动控制、机械设计、传感器技术、电子电气、计算机与人工智能等多学科知识，培养大学生的工程实践能力、创新意识与团队协作精神。
本报告面向第二十一届全国大学生智能汽车竞赛卡丁快跑组，介绍厦门大学嘉庚学院“南鸿离线也能跑”队卡丁车模型的设计与制作过程。报告围绕本组比赛任务——识别并跟随人身上的标志板完成第一圈路径、第二圈车模自动原路返回——展开，重点阐述系统总体方案、机械结构改装、硬件电路设计、车辆控制与视觉识别算法，并在最后对整体工作情况、技术指标以及有待改进之处进行总结。
在引言之后，报告首先在概论中概述智能汽车与本竞赛背景；随后依次介绍系统总体设计、硬件系统设计与车辆算法设计；最后给出结论、参考文献与附录。附录中包含车模技术检查表与核心算法子程序。

第一章 概论
1.1    智能汽车系统概述
智能汽车是集环境感知、规划决策与运动控制等功能于一体的综合系统，它融合运用了传感器、信息处理、通信、人工智能与自动控制等技术，是典型的高新技术综合体。近年来，随着感知硬件与嵌入式计算平台的快速发展，智能驾驶相关技术在提高行驶安全性、提升通行效率以及改善驾乘体验等方面展现出越来越重要的价值，成为车辆工程领域的研究热点之一。
一个典型的智能车系统通常包含感知层、决策层与执行层三个层次：感知层通过摄像头、编码器、惯性测量单元等传感器获取自身状态与环境信息；决策层在此基础上完成定位、路径规划与控制量计算；执行层则通过电机与舵机等执行机构，将控制量转化为车辆的实际运动。本组卡丁车模型的设计正是围绕这三个层次展开。
1.2    全国大学生智能汽车竞赛简介
全国大学生智能汽车竞赛自 2006 年首届举办以来，已成功举办二十届，参赛高校与学生规模持续扩大，是国内自动化、电子信息、机械等相关专业极具影响力的学科竞赛之一。竞赛设置竞速赛、创意赛与技术方案赛等多种类别，并根据传感器方案与车模形式划分为若干组别，为不同基础的参赛队伍提供了展示与交流的平台。
本届卡丁快跑组以卡丁车车模为载体，要求车模在无人驾驶模式下，先识别并跟随目标完成第一圈行驶，再自主原路返回。该任务对感知的稳定性、定位的连续性以及运动控制的平顺性都提出了较高要求，需要参赛队伍在有限的车载算力下完成感知、定位与控制的协同设计。

第二章    系统总体设计
2.1    设计方案概述
本组车模采用“一主板、双 TC264D”的双微控制器异构方案：其中一块 TC264D 作为视觉处理单元，负责摄像头图像采集与标志板识别，输出目标的横向偏移与偏航角等信息；另一块 TC264D 作为运动控制单元，负责融合定位、路径跟踪与电机、舵机的闭环控制。两块微控制器之间通过串口直接通信，视觉单元将识别结果实时传给运动控制单元。
整车工作流程可概括为：第一圈由视觉单元识别人身上的标志板，运动控制单元根据识别结果控制车模跟随目标行驶，并同步记录行驶路径；第二圈车模不再依赖视觉，而是按照第一圈记录的路径反向重放，实现自主原路返回。
2.2    车模总体布局
卡丁车模自带驱动电机与减速箱，动力电池由原厂的铅酸蓄电池更换为 24V、15Ah 的锂电池，以降低整车重量并提高续航。由于电池与驱动电机位于车身后部，整车重心偏后，车身后部空间较大，便于集中安装控制电路与电源模块。
主控板、按键板、后电机驱动板、分电板以及驱动点阵屏的 TLD7002 灯光控制板等电路模块集中布置在电池上方；各电路板与电池之间通过 3D 打印件隔离固定，板卡四周加装亚克力板进行防护，兼顾防水与防尘。摄像头支架布置在车身后部、靠近主控板的位置，便于走线与调试。整车总体布局如图 2.2 所示。

2.3    机械结构改装
2.3.1    转向角度传感器安装
为实现前轮转向角的闭环控制，需要在转向机构上加装角度传感器实时读取转角。本组选用普地 16 位 SPI 角度传感器，采用内齿轮与角度传感器小齿轮相啮合的方式进行安装：内齿轮随转向立柱同步转动，带动与传感器同轴的小齿轮转动，从而将前轮转角映射为传感器读数。齿轮啮合方式安装紧凑、传动可靠，配合 16 位分辨率可获得较高的角度测量精度。角度传感器安装位置与齿轮啮合情况如图 2.2所示。

2.3.2    后轮编码器安装
为获取车速与里程信息，在左右后轮各加装一枚普地迷你正交 1024 线编码器。为便于安装，利用 3D 打印件制作了一个套装在电机减速箱外侧的大齿轮，并通过 3D 打印支架将编码器固定在减速箱附近，使编码器上的小齿轮与大齿轮相啮合，从而随车轮转动读取编码器数据。左右轮独立测速为后续的双轮速度闭环与后轮主动差速控制提供了反馈来源。

2.3.3    电路板安装与防护
如前所述，主控板、按键板、后电机驱动板、分电板与 TLD7002 灯光控制板等模块集中布置在电池上方，通过 3D 打印件与电池隔离，避免电池与电路板直接接触带来的挤压与散热问题。板卡四周加装亚克力围板进行防护，一方面在户外场地行驶时起到一定的防水、防尘作用，另一方面也保护电路板免受外部碰撞。摄像头支架同样采用 3D 打印件制作，固定在车身后部靠近主控板处，保证视野稳定。

第三章    硬件系统设计
3.1    系统硬件结构
系统硬件主要由视觉处理单元、运动控制单元、电源系统、感知传感器与执行机构五部分组成。视觉处理单元（TC264D）驱动摄像头完成图像采集与标志板识别，并将识别结果通过串口发送给运动控制单元；运动控制单元（TC264D）融合编码器与惯性测量单元的数据完成定位，运行路径跟踪与闭环控制算法，输出 PWM 信号驱动转向电机与后轮驱动电机。系统硬件总体结构如图 3.1 所示。
图 3.1    系统硬件结构框图
3.2    电源系统设计
整车动力电池采用 24V、15Ah 锂电池。为满足不同模块的供电需求，电源系统采用多级降压方案：由 24V 经 TPS5450 稳压至 12V，为转向电机驱动等模块供电；12V 再经 MP2315 降压至 5V，为大部分外设供电；5V 最后经 RT9013-GB 线性稳压器降至 3.3V，为微控制器及 3.3V 外设供电。各级电源通过自制分电板分送到相应模块，供电层级如图 3.2 所示。
图 3.2    电源系统供电层级与分电板原理图
其中，TPS5450 为高输出电流的降压转换器，负责 24V 到 12V 的转换；MP2315 是一款宽输入范围的同步降压转换器，外围元件少、效率高，负责 12V 到 5V 的转换；RT9013-GB 为低压差线性稳压器，具有较高的电源抑制比与较低的压降，用于为微控制器提供稳定的 3.3V 供电，减小数字电源噪声对控制系统的影响。
3.3    主控与驱动电路
3.3.1    双 TC264D 主控方案
本组以两片英飞凌 SAK-TC264D 微控制器作为核心。TC264D 基于双核 32 位 TriCore 架构，主频 200MHz，具有较大的片上 Flash 与 RAM，并集成了丰富的定时器、ADC、SPI、UART 等外设，性能强、外围简单、成本适中，适合作为本系统的主控。两片 TC264D 分别承担视觉识别与运动控制任务，通过串口直连协同工作。
采用双微控制器而非“上位机 + 下位机”方案，一方面避免了额外的高算力平台带来的功耗与成本，另一方面将图像处理与运动控制在硬件上解耦，各自独立运行，提高了系统的实时性与稳定性。
3.3.2    电机驱动电路
前轮转向电机与后轮驱动电机均采用相同的驱动方案：以德州仪器 DRV8701ERGER 全桥栅极驱动芯片配合英飞凌 BSC0702LS 功率 MOS 管构成 H 桥驱动。DRV8701E 支持满占空比输入且无需外部升压电路，可降低设计复杂度并节省 PCB 空间；BSC0702LS 具有较低的导通内阻，在大电流工况下发热更小，有利于提升驱动效率与可靠性。后轮驱动沿用车模原厂电机，通过该驱动电路控制其转速与方向。电机驱动部分原理图如图 3.4 所示。
图 3.4    电机驱动电路原理图
3.3.3    灯光控制电路
为模拟真实车辆的灯光效果并提升车模的整体表现，本组采用英飞凌 TLD7002 灯光驱动芯片驱动车灯与点阵屏。TLD7002 是一款多通道 LED 驱动芯片，可对多路 LED 进行独立的亮度控制，配合运动控制单元的状态输出，实现转向灯、示廓灯等灯光效果。灯光控制电路原理图如图 3.5 所示。
图 3.5    TLD7002 灯光控制电路原理图
3.3.4    感知传感器
本系统的主要感知传感器包括：逐飞凌瞳（高帧率版，SCC8660）摄像头，用于标志板的图像识别；普地 16 位 SPI 角度传感器，用于前轮转角测量；普地迷你正交 1024 线编码器（左右后轮各一枚），用于车速与里程测量；以及 ICM42688 惯性测量单元，用于姿态与航向角解算。上述传感器共同为定位与控制提供输入。
3.3.5    双机通信
视觉处理单元与运动控制单元之间通过 UART 串口直接连接，即在主板上将一方的 RX 与另一方的 TX 直连，无需额外的 USB 转串口芯片。通信采用带帧头与校验的自定义协议，视觉单元将识别到的目标横向偏移、距离与偏航角等信息按帧发送给运动控制单元，供其进行跟随控制。

第四章    车辆算法设计
本组算法整体上分为运动控制单元与视觉处理单元两部分。运动控制单元负责融合定位、路径跟踪与电机、舵机的闭环控制，视觉处理单元负责标志板识别并输出跟随所需的目标信息。下面分别对两部分的核心思路作概要介绍，具体实现以随附源代码为准。
4.1    融合定位
本组未使用 GPS 等外部定位设备（代码中虽保留了相关命名，实际未调用），而是采用惯性导航方式实现定位。运动控制单元以左右后轮编码器进行航位推算得到位移，以 ICM42688 惯性测量单元解算航向角，并通过卡尔曼滤波将两者融合，得到车模在平面内的连续坐标与航向估计，为路径记录与路径跟踪提供位置基准。
/* encoder + IMU fusion update (excerpt) */
void localization_update(void)
{
    Encoder_get_XY();                 // odometry increment
    IMU_GetValues();                  // yaw / angular rate
    yaw = MahonyAHRSupdate(imu_data);
    Kalman_Update(odo_dx, odo_dy, yaw,
                  &GPS.Ins_X, &GPS.Ins_Y);
}
/* bias calibration and abnormal-data rejection are omitted */
4.2    路径跟踪与运动控制
在路径跟踪层，本组采用纯追踪（Pure Pursuit）算法：根据当前估计位置在记录路径上搜索最近点，并按设定的前视距离确定目标点，进而计算出期望的前轮转角。相比简单的航向角比例控制，纯追踪能够利用路径的几何信息实现更平顺的循迹效果。
在底层执行上，转向与速度均采用 PID 闭环：前轮转向采用位置式 PID，以普地角度传感器读数为反馈，将纯追踪输出的期望转角闭环到舵机；左右后轮速度各采用一路增量式 PID，以编码器测速为反馈进行调节。控制内环周期约为 10ms，以保证响应的实时性。
为改善卡丁车在转弯时的循迹表现，本组还引入了后轮主动差速控制：根据当前前轮转角查表并线性插值，得到左右后轮的目标速度比例，使内外侧车轮速度随转角自动分配，减小转弯时的滑移与拖拽，提高转向的顺畅度。
/* path tracking + closed-loop actuator control (excerpt) */
target_angle = pure_pursuit_control(
    GPS.Ins_X, GPS.Ins_Y, YAW, Aim_X, Aim_Y,
    Aim_S, Aim_Num, vehicle_speed, WHEEL_BASE_M, &near_idx);
Positional_PID_Calc(&motor_PID_F, target_angle, steer_angle);
Incremental_PID_Calc(&motor_PID_L, target_speed_l, speed_l);
Incremental_PID_Calc(&motor_PID_R, target_speed_r, speed_r);
Steer_Control(limit(motor_PID_F.output));
Motor_Control(motor_PID_L.output, motor_PID_R.output);

4.3    标志板识别与跟随
视觉处理单元使用逐飞凌瞳（SCC8660）摄像头采集图像，通过基于 HSV 颜色空间的色块识别方案完成对人身上四色标志板的识别与位姿解算。标志板由四个共面色块构成矩形，其中一个为唯一定位色块、其余三个为紫色色块。程序先将采集到的 RGB565 图像转换到 HSV 空间，通过颜色阈值与连通域扫描得到候选色块，再在候选中挑选最符合平面矩形几何关系的组合，最后结合相机内参对四点求解，得到标志板中心的前向距离、横向偏移与偏航角等位姿信息。
为提高识别在遮挡与光照变化下的鲁棒性，本组在识别流程中加入了若干工程处理：一是动态 ROI 跟踪，在获得稳定位姿后仅在上一帧色块附近区域搜索，兼顾速度与稳定性，必要时回退全图搜索；二是单点遮挡容错，当仅缺失一个色块时，利用 alpha-beta 预测器以预测位置补齐缺失点，短时维持位姿输出；三是自动曝光，根据识别到的色块区域亮度自动调节摄像头曝光，适应室内外不同光照。识别结果经串口发送给运动控制单元用于跟随控制。
/* vision recognition and communication (excerpt) */
camera_get_frame(image);
marker = marker_pose_detect(image);

4.4    任务流程：跟随与自动返回
本组比赛任务分为两圈完成。第一圈为跟随圈：视觉处理单元实时识别人身上的标志板，将目标的横向偏移与偏航角等信息发送给运动控制单元，运动控制单元据此进行转向与速度控制，使车模平稳跟随目标行驶；与此同时，运动控制单元利用融合定位持续记录行驶路径。
第二圈为返回圈：车模不再依赖视觉跟随，而是将第一圈记录的路径反向重放，通过纯追踪算法沿反向路径行驶，实现自主原路返回。两圈之间通过运动控制单元的模式切换实现衔接，从而完成“识别跟随—原路返回”的完整任务。

第五章    总结
本报告介绍了“南鸿离线也能跑”队面向第二十一届全国大学生智能汽车竞赛卡丁快跑组设计制作的卡丁车模型。系统采用“一主板、双 TC264D”的异构方案，将视觉识别与运动控制在硬件上解耦：一片 TC264D 负责基于 HSV 色块的四色标志板识别与位姿解算，另一片 TC264D 负责编码器与惯性测量单元的融合定位、纯追踪路径跟踪以及电机与舵机的闭环控制，两者通过串口协同，完成了第一圈识别跟随、第二圈自主原路返回的比赛任务。
在硬件方面，本组以 24V 锂电池为动力源，构建了 24V→12V→5V→3.3V 的多级供电体系，采用 DRV8701ERGER 配合英飞凌 BSC0702LS MOS 管的电机驱动方案，并通过 TLD7002 实现灯光效果；机械上通过齿轮啮合方式安装转向角度传感器与后轮编码器，并对电路板进行了集中布置与亚克力防护。在算法方面，采用惯性导航实现连续定位，以纯追踪结合位置式与增量式 PID 完成循迹与速度控制，并引入后轮主动差速改善转向表现；视觉上通过动态 ROI、单点遮挡容错与自动曝光等手段提升了识别的稳定性。
经实际测试，标志板识别帧率约为 25FPS，有效识别距离约 1～2.5m，偏航角解算精度约 0.01°；跟随效果与目标的运动状态相关，在目标运动较平稳时能够实现稳定跟随。
在调试过程中，我们也遇到并解决了一些问题，例如识别在强逆光与低照度下的稳定性、双机通信的可靠性以及转弯时的循迹平顺性等。后续可进一步优化标志板识别在复杂光照下的鲁棒性、提升融合定位的长时精度，并对路径记录与返回策略作进一步完善，以获得更稳定的整体表现。

B.2    纯追踪路径跟踪
float pure_pursuit_control(float x, float y, float yaw_deg,
                            const float *px, const float *py,
                            const float *s, int n, float speed,
                            float wheelbase, int *nearest_idx)
{
    *nearest_idx = find_nearest_by_arclen_window(
        px, py, n, x, y, *nearest_idx, SEARCH_WINDOW, 0);

    float ld = clampf(fabsf(speed) * SPEED_GAIN + LD_MIN,
                      LD_MIN, LD_MAX);
    float tx, ty;
    find_target_by_arclen(px, py, s, n,
                          s[*nearest_idx] + ld, &tx, &ty);

    float bx, by;
    world_to_body(x, y, yaw_deg, tx, ty, &bx, &by);
    float ld2 = maxf(bx * bx + by * by, EPSILON);
    float curvature = 2.0f * by / ld2;
    return rad_to_deg(atanf(wheelbase * curvature));
}
/* reverse-path boundary, CTE compensation and angle limits are omitted */
B.3    标志板识别与位姿解算
marker_pose_result_t marker_pose_detect(const uint16 image[H][W])
{
    marker_pose_result_t result = marker_pose_empty_result();
    const color_block_roi_t *roi = marker_prediction_get_roi();

    /* symbolic thresholds hide the calibrated color parameters */
    marker_pose_extract_candidates(image, roi, &candidates);
    if (candidates.color_count < 4U)
        return marker_pose_detect_in_roi(image, FULL_IMAGE);

    marker_pose_sort_quad(candidates.blocks, selected,
                           ordered_points, ordered_index);
    if (marker_pose_solve_corners(ordered_points, &result))
    {
        result.forward_mm = pose_from_camera_model(result);
        result.lateral_mm = result.translation.x;
        result.yaw_deg = result.heading_deg;
        marker_prediction_update_measurement(&result);
    }
    else
        marker_prediction_note_failed_frame(&result);
    return result;
}
