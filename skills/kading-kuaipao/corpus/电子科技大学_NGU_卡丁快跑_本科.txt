1 基础信息

1.1 团队介绍
NGU 队来自电子科技大学，由颜忠、石林、张讯、张富涵、乔易新五名队员组成，指导教师为马文建、王伊凡。团队围绕卡丁快跑综合科目的自主跟随、轨迹复现和语音人车交互任务开展软硬件协同设计，以可靠的底层硬件、稳定的惯导与视觉感知以及清晰的任务状态管理为主要技术路线。

1.2 题目要求
本组别采用“卡丁快跑综合科目”。车辆从起始区出发，在第一阶段自主跟随参赛队员穿越由锥桶构成的迷宫并到达停车区；第二阶段车辆自动驶出停车区，沿第一阶段形成的路线反向复现并返回起始区；返回后进入人车交互环节，根据随机语音指令完成灯光或鸣笛任务。综合科目不执行科目一。

图1 卡丁快跑综合科目赛道与任务流程（来源：国赛比赛规则截图）
国赛跟随阶段不得由电子设备引导，参赛人员可穿戴规定图案供车辆识别。轨迹复现计时包含中场衔接时间，因此停车区状态判断、控制模式切换和回放启动必须连续可靠。综合科目的语音环节只在返回起始区后执行灯光与喇叭任务；“过闸门”和“动作区运动”属于科目二通用规则背景，不纳入本综合科目实现边界。

2 设计概述
2.1 项目介绍
本车以科宇科技 TC264 核心板为控制核心，采用双核分工：CPU1 负责 160×120 视觉流水线，CPU0 负责惯导、轮速、运动闭环、轨迹记录与反向复现。车辆抵达终点后通过跨核握手停止视觉并切换到 8 kHz 语音采集，借助 WiFi 完成云端听写，再驱动 TLD7002 三联 5×7 灯阵和功放扬声器执行灯光、鸣笛指令。整车主板、BTN3 驱动板、灯驱动板与硅麦板均采用模块化接口，兼顾大电流可靠性与快速检修。
2.2 设计目标与原则
• 闭环优先：视觉只给出目标方位和尺度，最终速度、转向由周期控制任务约束，避免识别抖动直接作用于执行器。
• 状态可追溯：每个阶段都有独立使能、完成标志和资源归属，任务切换采用请求—应答握手。
• 硬件分域：动力、执行机构、数字逻辑、摄像头/模拟前端分别滤波供电，并通过统一地参考连接。
• 开源可复现：原理图工程、固件源码、依赖库、报告及演示资料按附件清单组织；联网密钥不进入公开仓库。
2.3 系统工作过程
上电后完成传感器、视觉、PWM 与通信初始化。阶段A中，CPU1持续输出目标中心、面积和方向，CPU0按5 ms/10 ms节拍更新姿态、遥控安全状态、速度斜坡和跟随控制，并按约0.3 m累计里程写入轨迹点。进入停车区后冻结轨迹；阶段B从倒数第二点开始索引递减，用惯导与轮速位置估计追踪历史折线。回到起点后停止视觉DMA及相关中断，初始化音频、灯阵和语音网络，等待随机口令并执行。
3 核心设计
3.1 总体设计框图

图3 整车硬件总体设计框图（电源与接口关系）
TC264 核心板位于系统中心。图中左侧集中表示凌瞳摄像头、惯性单元、编码器、硅麦与安全输入，右侧表示无线通信、屏幕、BTN3 动力板及其左轮、右轮、转向三路执行机构、TLD7002 灯阵和音频功放。橙色为 VBAT、5 V、3.3 V 与灯板独立 7 V 电源母线，蓝色为并口或 PWM，青色为 SPI/UART 串行通信，绿色为 ADC、QTIMER 与 GPIO。BTN3 接收主控的 3 路 PWM，不设置备用 H 桥；TLD7002 灯板由另一路 DCDC 将 24 V 降至 7 V 供电，主控通过另外 3 路 PWM 与灯板连接。
3.2 硬件电路组成
3.2.1 TC264 核心控制模块
系统采用科宇科技成品 TC264 核心板模块，主板仅通过排针引出摄像头、SPI、UART、编码器、PWM、ADC 与 GPIO。TC264 系列具备双 TriCore 内核，适合把确定性控制与计算量较大的视觉任务隔离。固件中 CPU0 负责控制、定位、轨迹和语音，CPU1 负责图像采集后的识别流水线；共享变量配合内存屏障和停止握手，避免切换阶段时访问已复用缓存。核心板的晶振、复位、下载和片上电源细节以科宇成品模块资料为准，本报告不把模块内部电路误列为自研。
3.2.2 主板 V1.2：电源、接口与保护

图4 主板 V1.2 原理图总览（嘉立创 EDA 工程）
电池由 XT30 接入，SMBJ36A 负责浪涌/瞬态抑制，NCE40P70K 高边器件与 SS54 肖特基二极管构成输入保护和电源路径。两路 TPS5450 降压分别服务 5 V/执行机构电源，ME6211 系列 LDO 再生成 3.3 V 及摄像头、运放等低噪声支路。板上集成核心板座、摄像头、屏幕、无线 UART/SPI、陀螺仪、编码器、TLD 灯、硅麦运放、踏板、按键及有刷电机等接口。音频由 TC8002D/AD8002B 功放链路驱动扬声器。

图5 主板 V1.2 PCB 预览
布局上将电源转换区置于板边并靠近输入连接器，核心板位于中部，摄像头/屏幕等高速或敏感接口分散在周边，便于线束维护。最终制板前应再次检查 TPS5450 开关节点面积、功率地回流、TVS 到输入端的走线长度以及大电流铜宽和过孔阵列。
3.2.3 BTN3 动力驱动板

图6 BTN3 驱动板原理图
BTN3 板由输入保护、逻辑缓冲和六路 BTN7971B 受保护半桥组成。六个半桥两两组合为三组双向 H 桥，分别驱动左轮、右轮和转向执行机构。TC264 向 BTN3 提供总计 3 路 10 kHz PWM 控制信号，板上不设置备用 H 桥；SN74LVC2G241、SN74HC125 对相关控制信号进行整形与隔离。三路 PWM 的通道对应、极性和使能逻辑均以最终线束与实车标定结果为准。

图7 BTN3 驱动板 PCB 预览
功率器件并排布置、输出采用 XT30 等大电流连接器。实车必须保证散热铜面、导线截面积和接插件额定电流；第一次带载应限流并悬空车轮，逐通道验证使能、方向与制动逻辑，防止上下桥臂控制错误。
3.2.4 TLD7002 灯驱动与 Board3 三联点阵

图8 TLD7002 灯驱动板原理图
灯驱动板采用独立电源路径：另一路 DCDC 将 24 V 降至 7 V 后为 TLD7002-16ES 与三联点阵供电，避免灯板负载直接叠加在主控 5 V/3.3 V 支路。TLD7002 提供 16 路受保护恒流输出，工程中使用其中 15 路作为三块 5×7 点阵的列线；七路 S8050 与 AO3401 组成高边行开关，配合点阵扫描。整车线束中，TC264 主板与灯板之间使用 3 路 PWM 控制连接。

图9 Board3 三联 5×7 LED 点阵原理图

图10 Board3 点阵 PCB 预览
三块 1357BS 点阵在一块窄长板上横向排列，合计形成 15×7 像素显示面，可显示左转、右转、远光、近光、雾灯、双闪、车内灯和雨刷等符号。三路 PWM 分别承担灯板控制/使能功能，TLD7002 在板端完成恒流驱动与点阵显示配合；亮度、扫描占空比和 PWM 极性需结合 7 V 实际供电、LED 正向压降与实物线束标定。
3.2.5 Board2 硅麦模拟前端

图11 Board2 硅麦模拟前端原理图
硅麦板使用 3.3 V 供电，LMV321 构成单电源放大/偏置级；249 kΩ反馈电阻与 2.49 kΩ输入网络设定较高交流增益，1.5 MΩ、100 nF 与 1 μF 元件参与偏置、隔直和低频稳定，BZT52C3V6 对输出进行钳位保护。OUT 接入 TC264 的 ADC0_CH0_A0，固件以 8 kHz、12 bit 采样。

图12 Board2 硅麦板 PCB 预览
模拟板应远离 BTN7971 开关节点、扬声器大电流回路和 DC/DC 电感；麦克风开孔不能被外壳遮挡。OUT 线宜短并配置地参考，必要时使用屏蔽线。调试时同时观察静音均值、峰峰值和削顶比例，再决定软件门限，不能只依靠主观听感。

3.4 程序设计流程图

图13 程序设计与任务状态流
3.4.1 双核调度
CPU0 初始化系统并运行控制主循环。CCU60 周期中断产生 5 ms 和 10 ms 软件标志：5 ms 任务更新 ICM 与惯导，10 ms 任务更新 PWM 斜坡并在“跟随/回放”间择一运行。CPU1 在摄像头帧完成标志到来后执行 vision_pipeline_tick()，只发布识别结果，不直接写电机 PWM。该分工使视觉卡顿不会破坏控制周期。
// CPU0：周期任务骨架（节选并简化）
if (flag_5ms) { ICM_update(); INS_update(); }
if (flag_10ms) {
    motor_pwm_slew_update();
    if (INS_flag) path_replay_update();
    else if (record_flag) { cam_follow_path(); record_points(); }
}

// CPU1：有新帧才运行视觉流水线
if (camera_finish_flag) vision_pipeline_tick();
3.4.2 人员跟随与曝光控制
视觉模块识别人员穿戴的四色标志，通过目标中心偏差估算方位、通过区域面积估算远近，并结合锥桶信息约束路径。启动阶段对曝光进行分段扫掠，依据有效目标质量和滞回规则锁定曝光，避免环境亮度变化造成频繁来回调整。控制层对目标角度和距离误差做限幅、滤波和速度规划；目标短暂丢失时保持安全低速或停车，而不是沿最后一次方向持续加速。
3.4.3 轨迹记录与反向复现
记录点结构包含平面坐标、点间距离、当前航向和原始航向。车辆累计行驶约0.3 m才写入下一点，从而在存储量与弯道分辨率间折中。回放从 point_index-2 开始，逐点向零递减，通过位置误差计算前视目标和转向量，并叠加速度闭环。停车区与起始区附近应使用较低速度和更严格的完成窗口，避免过冲。
// 关键思路（伪代码）
record: if (accumulated_distance >= 0.3 m) save(x, y, yaw);
replay: target = points[replay_index--];
        steering = path_policy(pose, target);
        speed = speed_policy(distance_to_target, curvature);
        if (replay_index <= 0 && speed_is_low) replay_done = true;
3.4.4 视觉到语音的资源切换
回放完成后，CPU0先发出视觉停止请求，CPU1在帧边界确认退出并置应答标志；随后关闭摄像头 VSYNC、DMA 和相关周期任务，再初始化 ADC、灯阵、WiFi 与语音状态机。该顺序用于避免音频复用缓冲区时仍有 DMA 写入。超时情况下进入安全停车并提示故障，不强行覆盖资源。
3.4.5 语音识别与动作执行
ADC 以8 kHz采集模拟麦克风。前64个样本估计直流偏置，端点检测根据幅度和静音持续时间切分语句，PCM以最多4000样本为块进行Base64编码，通过WiFi SPI连接讯飞听写 WebSocket。返回的UTF-8文本进入关键词匹配；灯类写入1~8，喇叭类写入17~25。执行器采用非阻塞计时状态机，以免长达数秒的鸣笛阻塞网络和安全输入。

5 补充说明
5.1 注意事项
• 赛前必须把源码快照中 car_finished_replay 的启动初值核对为 0；若保持完成态，任务切换器可能在车辆尚未回放时提前进入语音阶段。
• 视觉停止与音频初始化必须保留跨核请求—应答握手；禁止在 DMA 或 CPU1 仍可能访问时复用图像缓存。
• asr_ctrl.h 等配置文件可能含 WiFi SSID、密码、AppID、APIKey/Secret；公开前必须删除真实凭据，改用不入库的本地私有配置。
• TLD7002 灯板必须使用独立 DCDC 将 24 V 降至 7 V；赛前复核 7 V 输出、三路 PWM 极性、LED 正向压降、扫描占空比和亮度参数。
• 动力地、数字地、模拟地在规划位置汇接；硅麦和摄像头支路远离 PWM、DC/DC 开关节点与扬声器电流回路。
• 逐台标定轮径、编码器比例、转向零位、IMU 安装角、摄像头俯仰/曝光、人员标志尺寸、0.3 m 记录阈值和停车窗口。
• 设置机械急停、遥控接管、失目标停车、通信超时停车和上电 PWM 锁止。初次测试需架空驱动轮并使用限流电源。
• 云端识别依赖赛场网络。赛前验证断网、弱网和服务器超时路径；超时应提示重说并保持静止，不能误执行残留命令。
