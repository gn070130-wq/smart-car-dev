第一章　引言
1.1　竞赛背景与任务分析
全国大学生智能汽车竞赛是面向全国大学生的综合性工程实践竞赛。第二十一届竞赛（2025—2026 赛季）设立"卡丁快跑"赛题组，要求参赛队基于指定车模平台完成无人驾驶相关的自主行驶任务。根据《第 21 届智能车竞赛卡丁快跑组比赛科目细则》【4】，分赛区卡丁快跑组共设三个比赛科目：
（1）科目 1（自动驾驶）：场地为室外操场，包含发车区、倒车入库区与锥桶绕行区。车模从发车区自动出发，按给定方向依次绕行全部锥桶后，在倒车入库区完成倒车入库。
（2）科目 2（战场救护·人车交互）：通过自然语言控制车模完成云端人机交互任务，包含灯光任务（八种语音指令）、停车区鸣笛任务、门洞通过任务与运动任务（前行/后退 10 m、蛇形前进/后退、顺/逆时针转圈等）；语音经硅麦采集后通过 WiFi 联网调用云端语音转文字模型，解析为动作指令。
（3）科目 3（如影随形·穿越迷宫）：比赛前重新摆放锥桶，不允许提前进行位置定位。第一阶段车模从发车区出发，按规定的迷宫路径绕行至停车区（分赛区允许队员驾驶车模完成迷宫绕行，国赛要求车模跟随队员）；第二阶段车模根据第一阶段路径从停车区自动出发、绕行回到发车区；比赛成绩为两个阶段时间之和。引导阶段禁止携带电子设备，要求使用机器视觉跟随引导员。
另据全国总决赛通知《总决赛的新变化》【3】，总决赛将科目二与科目三融合为"带语音任务的综合科目"。
本队方案以科目 3 为主线，提出"视觉追踪录制路径—MPC 自动倒车循迹返回"的完整方案：第一阶段由车模通过摄像头识别非对称四圆点标记物（或引导员身上标记），自动视觉跟随行驶并录制路径；第二阶段车模从终点自动倒车，采用模型预测控制（MPC）沿录制的路径循迹返回起点。同时系统保留灯语、蜂鸣器、点阵 LED 显示等任务执行能力，可与国赛综合科目的灯光/鸣笛任务衔接。本队基于英飞凌 AURIX TC377 三核微控制器，自主设计并实现了这套控制系统，重点解决高速倒车工况下的路径跟踪稳定性与视觉目标跟随问题。
1.2　技术报告撰写依据
本报告根据《第二十一届全国大学生智能汽车竞赛技术报告要求细则》【1】撰写，内容覆盖细则要求的基本内容（总体方案、机械与安装、电路设计、软件算法、开发调试、主要技术参数、原理图与核心算法子程序），并以正文第六章调试记录作为算法验证内容；本报告不附研究论文，程序源码以独立 PDF 文档作为附录提交。
1.3　相关技术与文献综述
（1）模型预测控制（MPC）：MPC 通过在线求解有限时域最优控制问题，在每一采样时刻根据当前状态和预测模型，在满足状态/控制约束的前提下最小化代价函数，并只施加第一个控制量【7】。对于车辆路径跟踪，MPC 在 Frenet 坐标系下可自然地融合横向偏差、航向偏差、速度约束、加速度限制等多维约束，相比纯追踪（Pure Pursuit）和 Stanley 控制器在处理系统约束方面具有显著优势。
（2）视觉目标检测与位姿估计：基于已知几何模型的非对称点标记（如不对称四点标记）可实现单目摄像机的 PnP（Perspective-n-Point）问题求解，获得目标相对于摄像机的位置和姿态。本队采用 SCC8660 彩色数字摄像头，通过 HSL 颜色空间阈值分割、BFS 连通域提取、排列匹配等方法，实现了非对称四圆点标记物的实时检测、识别与六自由度姿态解算。
（3）姿态解算：采用 Mahony 互补滤波算法，以加速度计修正陀螺仪积分漂移，适用于低成本六轴 IMU【8】。针对车辆转弯时向心加速度会污染加速度计姿态修正的问题，本车实现了"转弯自动减弱加速度修正"与"运行时 Z 轴零偏跟踪"等改进。
（4）多核处理：TC377（AURIX 2G）集成三颗独立 TriCore CPU，可将视觉处理、高频传感器解算与应用逻辑分离，降低单核负载与任务之间相互干扰。
1.4　本队主要工作与创新点
1. 基于 TC377 三核实现"CPU0 视觉追踪 / CPU1 IMU 姿态解算与电机控制 / CPU2 应用逻辑（视觉跟随 + MPC 倒车循迹）"的分工架构，通过共享内存（g_shared）进行高效数据交换；
2. 自主设计并实现基于 SCC8660 摄像头和非对称四圆点标记物的视觉追踪系统，包含颜色标定、HSL 颜色识别、连通域提取、24 排列匹配、位姿解算（距离/偏航/俯仰/滚转）等完整流水线；
3. 自主设计视觉跟随控制器（vision_motion），基于距离 PD 控制与角度 P 控制，实现弯道/直道自适应速度调节，并包含丢失保持、安全刹车、帧间平滑等抗干扰机制；
4. 自主移植并实现 LTV-MPC 控制器（my_mpc_solver），基于 TinyMPC 风格的 ADMM 算法与每步 Riccati 递推，在 Frenet 坐标系下实现带约束的倒车循迹优化；
5. 实现基于曲率与车辆物理限制的理论最快速度规划（v = √(a_lat/κ)），并支持干/湿路面工况一键切换；
6. 基于 bicycles 模型将 MPC 输出的横摆角速度分解为前轮转向角与差速分配，实现双执行器协同控制；
7. 编写 Python 车辆动力学仿真对控制器进行离线验证（stimulate_纯追踪），缩短实车调参周期。

第二章　总体方案设计
2.1　设计思路
系统工作流程为：
1. 录制阶段（视觉跟随）：车模通过 SCC8660 摄像头识别非对称四圆点标记物（或引导员身上标记），视觉跟随控制器（vision_motion）根据实时检测的距离和偏航角自动输出速度与转向指令，引导车模跟随标记物沿目标路径行驶；同时按"移动距离阈值（0.2 m）"自动打点，记录路径点（坐标、航向、速度）；
2. 预处理阶段：循迹开始前对路径点计算累计弧长、三点曲率、端点延拓与平滑，并基于曲率与车辆物理限制生成理论最快速度曲线（v_opt）；
3. 循迹阶段（MPC 倒车）：车辆从终点位置自动倒车，采用 LTV-MPC 算法沿路径反向（弧长递减）回到起点，利用 Frenet 坐标系下的横向偏差、航向偏差和速度作为状态，在线优化加速度与横摆角速度，全程无需遥控干预；
4. 安全逻辑：遥控器断开、超时、异常时立即停车。

2.5　工作模式状态机
路径管理采用清晰的状态机（project3_INS.h 的 P3INS_MODE）：IDLE → RECORD → READY → TRACK_BACK → FINISH：
- IDLE：空闲，等待按键/遥控指令；
- RECORD：视觉跟随行驶，摄像头识别标记物并自动跟随，同时按位移阈值自动打点录制路径；
- READY：录制完成，等待人工将车放置到终点后按 KEY4 触发；
- TRACK_BACK：MPC 倒车循迹，从终点向起点逐点推进；
- FINISH：到达起点，抱闸停车，蜂鸣提示。

3.2　视觉系统安装
SCC8660 凌瞳彩色数字摄像头安装于车头前上方，俯视视角约 30°，视场角 90°（水平）× 67.5°（垂直）。在车头固定安装 IPS200 2.0 寸 SPI 彩屏，用于实时显示摄像头画面与标记物姿态信息叠加，便于调试。
非对称四圆点标记物制作：在白纸上打印 4 个黑色实心圆，圆心坐标（单位 mm）为 A(0,0)、B(30,0)、C(0,20)、D(30,50)，圆点直径建议 5~10 mm，4 个圆形成不对称四边形（非正方形/矩形），确保 24 种排列中有且仅有一种匹配正确。录制阶段将标记物粘贴于引导员背部或手持引导板上。

3.4　驱动系统
后桥左右轮由两路直流有刷电机独立驱动，PWM 频率 17 kHz。每轮安装带方向输出的编码器（1024 PPR/转），实现 10 ms 周期的速度闭环与里程累计。轮子周长按实测标定为 0.828 m（见 imu_odom.h，换算每脉冲约 0.81 mm，含 2:1 齿轮减速比）。

- GPS 模块：安装于车顶开阔处（备用），天线面朝上；

- 点阵屏与车灯：按赛题要求安装于车头醒目位置，由 TLD7002 驱动。
3.6　电路板固定与线束
所有电路板通过铜柱/尼龙柱固定，动力线与信号线分区走线，避免大电流对 IMU、编码器等信号造成干扰；遥控接收天线、GPS 天线均远离电机线束。摄像头 DVP 并口排线、SCC8660 配置串口、IPS200 SPI 接口、IMU 硬件 SPI 接口及编码器接口均通过主板对应接口连接【待补充：线束整理照片】。

5.1　软件总体框架与共享内存
软件分为三层：
1. 驱动层：逐飞 TC377 开源库外设驱动（PWM、编码器、SPI、UART、PIT、外部中断、DMA 等）；
2. 中间层：driver_imu.c（姿态）、imu_odom.c（里程计）、motor_pid.c（速度环）、servo.c（舵机闭环）、remote.c（遥控）、color_tracer.c（视觉标记检测）、vision_motion.c（视觉跟随控制）、my_mpc_solver.c（MPC 求解器）；
3. 应用层：project3_INS.c（MPC 倒车循迹主控）、diff_speed.c（差速分配）。
三核通过 system_data.h 中的全局共享结构体 g_shared 通信，关键字段包括：
typedef struct {
    volatile uint32_t shared_counter;
    volatile float odom_x, odom_y, odom_yaw;   // CPU1 航向 + 里程计
    volatile float target_speed_l, target_speed_r;  // 目标速度

CPU0 视觉检测结果通过全局变量 dist_int（距离 mm）、yaw_int（偏航角 deg）、detected（有效标志）直接传递给 CPU2 的视觉跟随控制器。采用 volatile 保证跨核可见性；关键控制量由 CPU2 计算写入，CPU1 在 10 ms 中断中读取执行，实现"计算与执行分离"。
5.2　视觉追踪——标记物检测与位姿解算（CPU0）
5.2.1　摄像头与标记物
本系统采用逐飞 SCC8660 凌瞳彩色数字摄像头（DVP 并口），视场角 90°（水平）× 67.5°（垂直），通过 DMA 采集 RGB565 格式图像。非对称四圆点标记物由 4 个黑色实心圆点组成，圆心模型坐标 A(0,0)、B(30,0)、C(0,20)、D(30,50) mm（可整体缩放），圆点直径 5~10 mm。
5.2.2　颜色标定与阈值分割
为适应不同光照条件，系统支持自动颜色标定：将标记物黑色圆点对准摄像头画面中心，按下 REFRESH_TARGET 按键（P11_3），程序自动以画面中心像素的 HSL 值为基准，按 H±20、S±65、L±80 的容差设置目标颜色阈值（target_color_condi）。RGB565→RGB→HSL 转换直接在逐像素扫描中完成，无需额外图像缓冲。
5.2.3　连通域提取（BFS）
对匹配颜色阈值的像素在位图（vision_blob_mask）中标记，通过 BFS 8 连通域算法提取所有连通区域（blob），计算每个 blob 的质心（cx, cy）和面积（像素数）。为节省内存，BFS 队列直接复用摄像头图像缓冲区（scc8660_image）。
5.2.4　24 排列匹配与识别
从所有候选 blob 中过滤面积在 4~650 像素范围内的区域，选取面积最大的 4 个 blob（或遍历所有 4 组合，最多 8 选 4），对每种 4 点排列计算 6 条边长的比例关系，与模型 6 条边长的比例进行误差匹配（24 种排列，取匹配误差最小者）。匹配误差阈值为 0.12（MATCH_ERROR_THRESH）。
5.2.5　位姿解算
利用匹配成功的 4 个圆心坐标，计算：
距离：由标记物 B-D 两点像素距离（bd_pixel）经畸变修正（空间角相关的畸变系数查表）和距离标定表（分段线性插值，6 个标定点：20 px→1435 mm…80 px→365 mm）换算为实际距离，标定参考 D_REF=500 mm、BD_PIXEL_REF=20.8 px、标记物实际 BD 距离=350 mm。距离范围 50~3000 mm。
$\theta_{yaw} = \frac{x_{center} - W/2}{W} \cdot FOV_H,\qquad
\theta_{pitch} = \frac{y_{center} - H/2}{H} \cdot FOV_V,\qquad
\theta_{space} = \sqrt{\theta_{yaw}^2 + \theta_{pitch}^2}$
	θroll = arctan2(Δ xBD, -Δ yBD)	公式2
5.2.6　帧间平滑与 ROI 加速
为抑制检测抖动，对 4 个圆心坐标进行帧间一阶低通平滑（SMOOTH_ALPHA=0.35）。目标丢失后在 LOST_HOLD_FRAMES=6 帧内继续显示历史结果，减少闪烁。利用上一帧圆心包围盒向外扩展 ROI_MARGIN=25 px 作为下一帧的搜索区域（ROI），显著减少逐像素扫描量；若 ROI 内未检出则回退全图扫描重新捕获。
5.3　视觉跟随控制器（vision_motion，CPU2 录制阶段）
录制阶段（P3INS_MODE_RECORD）由视觉跟随控制器驱动车模自动跟随标记物。控制器每 10 ms 调用一次，以视觉检测的距离（distance_m）和偏航角（angle_deg）为输入，输出速度指令（speed_cmd）和转向角（steer_deg）。
5.3.1　距离 PD 控制
距离误差：e_dist = distance_m − VISION_STOP_DIST_M（0.60 m），距离超过 VISION_FULL_SPEED_DIST_M（1.43 m）时饱和处理。控制律：
	uspeed = Kp · edist + Kd · ėdist + Ki ∫ edist dt	公式3
其中 Kp=60、Kd=20、Ki=0（默认关闭积分），输出限幅 0~VISION_MAX_SPEED_CMD（70，约 2.2 m/s）。
5.3.2　安全刹车限速
接近目标时，采用平方根刹车速度上限防止撞击：
	vcap = Gbrake · √distance - d_stop - d_margin	公式4
其中 G_brake=70、d_stop=0.60 m、d_margin=0.05 m。实际速度指令取 PD 输出与刹车上限的较小值。
5.3.3　角度 P 控制与弯道模式
转向角 = 滤波后偏航角 × VISION_STEER_KP（1.0）× VISION_STEER_SIGN（−1），限幅 ±28°。当偏航角绝对值超过 VISION_CURVE_ENTER_ANGLE_DEG（12°）时进入弯道模式，速度下限提升至 VISION_CURVE_MIN_SPEED_CMD（27）~VISION_CURVE_MAX_SPEED_CMD（50）线性插值，防止弯道中速度过低；偏航角回落到 VISION_CURVE_EXIT_ANGLE_DEG（8°）时退出弯道模式（角度滞回）。
5.3.4　抗干扰机制
- 有效确认：连续 VISION_VALID_CONFIRM_CYCLES（2）帧检测到目标才确认有效，防止误检；
- 丢失保持：目标丢失后 VISION_LOST_HOLD_CYCLES（3）帧内保持上一帧转向角，速度渐变至丢失目标速度（VISION_LOST_SPEED_CMD=15），弯道中丢失使用弯道丢失速度（VISION_LOST_TURN_SPEED_CMD=25）；
- 安全停止：丢失超过 VISION_LOST_STOP_CYCLES（10）帧（弯道 150 帧）后强制停车，转向归零；
- 停止确认：距离 ≤ 停止距离且连续 VISION_STOP_CONFIRM_CYCLES（4）帧确认后，确认停车，转向保持；距离 > VISION_STOP_RELEASE_DIST_M（0.68 m）时释放停车；
- 帧间滤波：距离一阶低通（α=0.35），角度一阶低通（α=0.45），距离跳变限幅（0.35 m），角度跳变限幅（25°）；
- 速度/转向斜坡：速度指令变化率限幅（默认 1/周期，弯道加速 4/周期），转向角变化率限幅。
5.4　IMU 姿态解算（CPU1，250 Hz）
初始化流程（driver_imu.c）：
1. 上电后增加静止等待（默认 2.5 s），期间检测车辆静止（陀螺阈值 6°/s、加速度模长与变化量阈值）；
2. 采集 5000 组静止样本（1 ms 间隔）求陀螺零偏均值，有效样本不足 2500 组则标记校准失败但不死锁；
3. 由加速度计初始化横滚/俯仰四元数；
4. 进入 4 ms 周期解算循环。
解算采用 Mahony 互补滤波：
- 陀螺积分更新四元数：q̇ = ½ q ⊗ ω；
- 加速度计与陀螺预测姿态之间的误差经 PI 项修正：ω_corr = ω + Kp·e + Ki·∫e dt；
- 加速度数据先经一阶标量卡尔曼滤波（IMU_ACC_KF_Q=0.005、IMU_ACC_KF_R=0.30）平滑；
- 转向时（|ωz| 达 8°/s 起、25°/s 全关）逐渐减弱加速度计修正权值，避免向心加速度污染姿态；
- 积分项做限幅与指数泄漏（0.998），防止长时间转向时积分饱和；
- 输出 roll/pitch/yaw，并维护连续累计航向 yaw_accumulated（不截断到 ±180°），供里程计与 MPC 循迹使用；
- 运行时若检测到车辆连续静止约 1 s，允许锁零并慢速更新 Z 轴零偏（学习系数 0.001），抑制长时间运行漂移。
	q̇ = ½ q ⊗ ωcorr,   ωcorr = ω + Kp e + Ki ∫ e dt	公式5
5.5　航向里程计（CPU1，100 Hz）
里程计基于差速模型（imu_odom.c）。设每周期左右轮里程为 dL、dR，编码器 1024 PPR，轮周长 0.828 m，电机到车轮 2:1 齿轮减速比，轮距 0.50 m。每周期里程 = (dL+dR)/2/2（除以 2 为齿轮减速比）。
	ds = (d_L + d_R)/(2 · G_ratio)	公式6
	xk+1 = xk + ds·sinψk,   yk+1 = yk + ds·cosψk,   ψk+1 = ψk + ΔψIMU	公式7
其中 Δψ_IMU 由 CPU1 的连续累计航向差分得到（g_shared.odom_yaw）。里程计除提供 x/y/yaw 外，还用于路径录制打点与 MPC 到达判定。
5.6　路径录制与预处理
录制阶段自动打点以"位移超过 0.2 m"触发（并设有 200 ms 最小间隔），路径点记录 x、y、yaw、录制时速度；最大点数 800（project3_INS.h 的 P3INS_POINT_MAX）。开始循迹（track_back_start）前完成：
1. 累计弧长 s：arc[i] = arc[i-1] + |P_i − P_{i-1}|，得到 total_arc；
2. 三点曲率：利用相邻三点外接圆半径的倒数计算有符号曲率 κ；
3. 端点延拓 + 5 点加权平滑（权重 0.1/0.2/0.4/0.2/0.1），配合极大值保留滤波（3 点窗口取绝对值最大）防止峰值被磨平；
4. 曲率限速 v_opt 曲线（见 5.8）。
	κ = (sign(a×b)· √|a|²|b|² |P_0P_2|)/(2|a×b|)	公式8
其中 a=P0−P1，b=P2−P1。
5.7　LTV-MPC 倒车循迹控制器（核心）
5.7.1　MPC 问题建模
控制器将倒车循迹建模为 Frenet 坐标系下的离散时间 LTV-MPC 问题（my_mpc_solver.c）。预测时域 N=50，采样周期 dt=10 ms（前瞻 0.5 s）。
状态向量：x = [e_y, θ_e, v]^T
- e_y：车辆在 Frenet 坐标系中的横向偏差（右侧为正），m
- θ_e：车辆航向与参考路径点航向之间的偏差，rad
- v：车辆速度幅值，m/s
控制向量：u = [a, ω]^T
- a：纵向加速度，m/s²
- ω：横摆角速度，rad/s
线性化运动学模型（以当前速度 v0 为线性化点）：
$\begin{aligned}
e_y(k+1) &= e_y(k) + v_0\cdot dt \cdot \theta_e(k) \\
\theta_e(k+1) &= \theta_e(k) + dt \cdot \omega(k) - \kappa_k \cdot dt \cdot v(k) \\
v(k+1) &= v(k) + dt \cdot a(k)
\end{aligned}$
其中 κ_k 为第 k 步的路径有效曲率（倒车时取负值：κ_eff = −κ_recorded）。
代价函数（包含状态跟踪、控制代价与控制增量代价）：
	J = Σk=0N-1 [(xk - rk)T Q (xk - rk) + (uk - uref,k)T R (uk - uref,k) + (uk - uk-1)T Rd (uk - uk-1)] + (xN - rN)T QN (xN - rN)	公式10
权重矩阵：Q = diag(50, 5, 3)、QN = diag(50, 5, 15)、R = diag(1, 2)、Rd = diag(3, 3)。
控制约束：每步独立可调：
	-abrake ≤ ak ≤ aaccel,   -ωmax ≤ ωk ≤ ωmax	公式11
约束参数通过 P3INS_TRACK_MODE 宏一键切换（干地/湿地），当前默认为湿地模式：v_max=4.0 m/s、a_brake=1.75 m/s²、a_accel=2.5 m/s²、ω_max=4.0 rad/s。
5.7.2　求解算法：ADMM + Riccati 递推
采用 TinyMPC 风格的 ADMM（Alternating Direction Method of Multipliers）算法，将"增广状态（[x; u_prev]）"引入"虚拟约束"（v = clamp(u+w, lb, ub), w += u−v），然后对每个 LTV 系统进行 Riccati 递推求解无约束子问题【7】。
每步求解流程：
1. Riccati 反向递推：P[N] = QcN，对 k=N−1,…,0 计算 At_k（含 v0 和 κ_k）、Hinv_k（2×2 解析求逆）、K_k = Hinv_k·G_k、P[k] = Qc + At'PAt − G2·K；
2. ADMM 迭代（最多 120 次，收敛阈值 ε=0.0001）：反向递推计算 p 和 q_k，前向递推计算 xi 和 uu_k，v 更新与投影，检查原始/对偶残差；
3. 输出：返回第一步的投影控制量 u = [a, ω]。
ρ=1.0，增广矩阵 Qc=2·blkdiag(Q,Rd)、Rc=2·(R+Rd)、Sc=−2·[0;Rd]。所有矩阵静态分配，无动态内存申请，适合 TC377 嵌入式平台。
5.7.3　参考轨迹生成
每控制周期（10 ms），根据当前 odometry 位姿计算最近路径点投影（mpc_proj_idx，搜索范围 ±40/+5 点），然后沿路径弧长递减方向（倒车）生成 N 步参考序列：
- 参考弧长：s_k = s_now − k·v_ref·dt（k=0,…,N−1）
- 参考状态：r_k = [0, 0, v_opt(s_k)]^T（期望横向偏差与航向偏差为 0）
- 参考控制：u_ref,k = [0, κ_eff(s_k)·v_opt(s_k)]^T（前馈横摆角速度）
- 有效曲率：κ_eff = −κ(s_k)（倒车时符号反转）
5.7.4　指令转换与执行
MPC 输出加速度 a_cmd 和横摆角速度 ω_cmd，经以下步骤转换为执行器指令：
1. 速度积分：v_cmd += a_cmd·dt，限幅 0 ~ v_max；
2. 摩擦圆约束：若当前曲率 × 速度² 接近侧向加速度极限，则限制加速度（a_cmd = a_allow·√(1−(ay/ay_max)²)）；
3. 曲率前瞻减速：前瞻 0.80 m（5 个采样点）取最大曲率绝对值，按 v_lim = √(a_lat/κ) 限制速度；
4. 前轮转向角（自行车模型）：
	δ = sign · arctan(ω_cmd · L)/(v_safe),   vsafe = max(vcmd, 0.1)	公式12
其中 sign=−1（舵机方向标定），L=0.62 m（轴距），δ 限幅 ±30°；
5. 差速分配：前轮转向承担大部分横摆，剩余横摆角速度（ω_residual = ω_cmd − ω_front）通过差速补充：
$\omega_{eff} = \text{sign}_{diff} \cdot \omega_{residual},\qquad
\Delta v = G_{diff} \cdot \omega_{eff} \cdot \frac{B}{2},\qquad
v_L = -v_{cmd} + \Delta v,\quad v_R = -v_{cmd} - \Delta v$
其中 G_diff=1.0、B=0.50 m（轮距）、差速限幅为当前速度的 35%；
6. 速度斜坡：每周期速度变化限幅 P3INS_SPEED_RAMP_ENC（30 脉冲/10 ms ≈ 1.2 m/s²），最终输出 p3ins_wheel_l/r 给 CPU2 写入 g_shared 供 CPU1 执行。
5.7.5　到达判定与超时跳点
- 到达距离：dist_to_target < 0.35 m 时切换到上一个路径点（索引 −1），蜂鸣提示；

5.8　速度规划
循迹基础速度为编码器脉冲指令（10 ms 周期），P3INS_BASE_SPEED_CMD=90（约 3.6 m/s），最大 100（约 4.0 m/s），最小 15（约 0.6 m/s），速度斜坡每周期 ≤30 脉冲（约 1.2 m/s² 量级）。倒车输出为负。
- 航向误差减速：|θ_e| > 15° 乘 0.70，|θ_e| > 30° 乘 0.50（保留在 p3ins_heading_error 中用于差速分配）；
- 理论最快速度曲线（P3INS_USE_OPT_SPEED=1 时启用）：以曲率限速为基础（公式 14），再做前向加速平滑与后向减速平滑，得到 v_opt(s)：
	v(κ) = min(√a_lat/|κ|, vmax)	公式14
$v_{i+1} = \min\left(v_{opt,i+1},\ \sqrt{v_i^2 + 2a_{max}\Delta s}\right),\qquad
v_i = \min\left(v_{opt,i},\ \sqrt{v_{i+1}^2 + 2b_{max}\Delta s}\right)$
相关常量：a_lat=1.9（湿）/2.5（干）m/s²、a_max=2.5 m/s²、b_max=1.75（湿）/3.5（干）m/s²、v_max=4.0（湿）/4.5（干）m/s。
5.9　差速转向（speed_diff，手动模式备用）
CPU2 的 speed_diff() 将"航向误差角"与"基础速度"转换为左右轮目标速度（cpu2_main.c），用于手动遥控模式和非 MPC 模式：
1. 误差 < 5° 死区：左右轮同速；
2. 外轮（远离转向中心一侧）：大角度时最多减速 10%（20° 起线性过渡到 55°）；
3. 内轮：误差 5°~32° 区间按幂函数减速（γ=1.2）；误差超过 32° 时内轮反转，最大反转比例为基础速度的 8%（γ=2.5）；
4. 内轮最小速度保护（≥8），防止极端情况完全停转；
5. 倒车时基础速度为负，分配结果整体取负方向。

5.10　电机速度闭环（CPU1，10 ms）
左右轮分别采用增量式 PID（motor_pid.c），在 10 ms 中断中读取编码器计数、一阶低通滤波（α=0.3）后与目标速度求差：
	u = Kp e + Ki∫ e dt + Kdde/dt	公式16
实现要点：抗积分饱和（积分仅在输出未饱和时累加）、积分限幅、输出限幅（±9500）、死区补偿（≤1000 清零），最后写入 17 kHz PWM。实车整定参数：左右轮相同，Kp=30、Ki=2、Kd=8（即代码当前配置值，见 cpu1_main.c 中 MotorPID_Init 调用）。
5.11　舵机转角闭环与航向保持
舵机控制（servo.c）采用"位置环"结构：
1. 绝对编码器读取实际转角，映射到 ±20° 机械角度（中心 1180，左右分别标定比例）；
2. 目标角与转向角误差经 PID（直行 Kp=0.72 / 弯道 Kp=2.0）输出 PWM 占空比；
3. 机械虚位补偿：按误差方向保持预紧（0.45°），误差换向阈值 1.10°；
4. 0° 附近滞回锁中（退出 0.8°、进入 0.35°），中心角滤波（α=0.6）抑制抖动；
5. 编码器异常保护：读数超出安全范围立即断开 PWM；
6. IMU 直行航向保持：当遥控转向输入接近 0° 时，以 IMU 航向为反馈做 PID（Kp=0.45、Ki=0.22、Kd=0.01，20 ms 周期），并自学习中值补偿（≤4.5°），修正机械中心偏差；
7. 局部 XY 直线保持：直行时以当前位置建立局部坐标系，横向位置环（前视距离 0.8~1.8 m，最大横向修正 8°）生成目标航向，再交由 IMU 航向环执行。
以上设计使倒车循迹中"MPC 输出舵角"与"直行航向保持"能平滑切换，兼顾了弯道响应与直道稳定。
5.12　遥控与安全逻辑
遥控通过无线转串口模块接收（uart_receiver，6 通道），主要通道定义为：CH1 油门、CH2 转向、CH5 退出自动任务、CH6 开始/结束录制或触发循迹。安全策略：
- 遥控连接状态实时检测，异常断开时 CPU1 立即将左右目标速度清零并停车；
- 刚连上遥控后稳定等待 1.5 s 再响应油门，防止误动作；
- 手动模式下转速/转向均做限幅与死区处理；强差速（CH6 开关）用于人工调试。

- 陀螺零偏须在每次上电静止校准，运行中长时间漂移通过静止锁零与零偏跟踪抑制；

第八章　结论
本报告围绕"卡丁快跑"赛题，设计并实现了一套基于英飞凌 AURIX TC377 三核微控制器的无人卡丁车"视觉追踪录制—MPC 倒车循迹"系统。系统采用三核分工架构，将视觉处理（30 fps）、姿态解算（250 Hz）与电机速度闭环（100 Hz）、MPC 应用逻辑（10 ms）解耦；以 SCC8660 摄像头识别非对称四圆点标记物实现视觉跟随录制，以 IMU+编码器航位推算为定位基准，采用"LTV-MPC（ADMM+Riccati）+ 速度规划 + 摩擦圆约束 + 自行车模型转向 + 差速补充"的控制方案，并配套路径录制、舵机角度闭环与航向保持等模块。系统在方案演进中分阶段完成从 GPS/纯追踪到视觉/MPC 的技术路线升级【待补充：实测结论、成绩与数据】。
当前方案仍存在以下问题与改进方向：
1. 视觉标记检测对光照变化敏感，后续可引入自适应曝光控制或迁移至基于深度学习的检测方法；
2. 里程计在打滑、颠簸工况下存在累计误差，后续可引入 GPS/RTK 位置修正或视觉里程计辅助；
3. MPC 计算量较大（ADMM 每步 O(N) 矩阵运算），当前 N=50 在 TC377 上运行良好，但若需增加时域或增加状态维度，需进一步优化矩阵运算或降低时域；
4. 舵机与电机的功率/死区参数目前依赖人工整定，可开发上位机自动标定流程；
5. 建议补做系统可靠性测试（长时间运行、遥控失控、电量不足、视觉目标丢失等安全场景）。

A.3　MPC 求解器（my_mpc_solver.c 简化流程）
// 初始化：Qc = 2*blkdiag(Q,Rd), Rc = 2*(R+Rd), Sc = -2*[0;Rd]
// Riccati 反向递推（每步因 v0 和 kappa 变化需重新计算）
P[N] = QcN
for k = N-1..0:
    At = [[1 v0*dt 0], [0 1 -kappa_k*dt], [0 0 1]]
    H = Rc + rho*I + Bt'*P[k+1]*Bt
    Hinv = inv2x2(H)
    G = Bt'*P[k+1]*At + Sc'
    K[k] = Hinv * G
    G2[k] = At'*P[k+1]*Bt + Sc
    P[k] = Qc + At'*P[k+1]*At - G2[k]*K[k]
 
// ADMM 迭代
xi[0] = [x0; u_prev]
v = clamp(u_prev, lb, ub), w = 0
for iter = 1..120:
    // 反向递推
    p = 0
    for k = N-1..0:
        q[k] = Hinv[k] * (Bt'*p + l_u - rho*(v[k]-w[k]))
        p = l_xi[k] + At'*p - G2[k]*q[k]
    // 前向递推
    for k = 0..N-1:
        u[k] = -K[k]*xi[k] - q[k]
        xi[k+1] = At[k]*xi[k] + Bt*u[k]
    // v 更新 + 残差
    for k in 0..N-1:
        v_new = clamp(u[k] + w[k], lb[k], ub[k])
        w[k] += u[k] - v_new
        prim = max(|u[k]-v[k]|), dual = max(rho*|v_new-v_old|)
    if prim < eps && dual < eps: break
 
return clamp(v[0][0], lb[0], ub[0]), clamp(v[0][1], lb[0], ub[0])
