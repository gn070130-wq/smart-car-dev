第一章 引言
全国大学生智能汽车竞赛秉持“立足培养、重在参与、鼓励探索、追求卓越”的宗旨，是一项以激励创新为核心的科技竞赛活动。该竞赛要求参与者在指定的汽车模型平台上，以英飞凌公司的TC264微控制器作为核心控制模块设计主板，通过增设摄像头、陀螺仪、编码器等传感器，增加电机驱动模块、舵机驱动模块，并编写配套控制程序，最终完成具备自主道路识别能力的模型汽车制作。针对本次总决赛的具体要求与场景，我们构建了赛车、赛道及自主控制系统的基础模型，提出了涵盖理论分析与在线调试的完整开发方法。通过对各类算法的性能特点进行对比分析，我们确定了车随人及自动返回起点的最终实施方案，并已完成智能车的制作与调试工作。此技术报告包含方案总体设计、机械结构设计、硬件设计、程序设计、调试过程、结论等内容，详实记录了参与本次竞赛的智能汽车制作情况。
第二章 方案总体设计
在此次比赛中，本组使用北京科宇有限公司提供的卡丁车车模，采用英飞凌公司推出的一款高性能汽车微控制器TC264作为核心的控制单元，自主设计系统的控制方案。
在这份报告中，我们将阐述整车系统的整体方案、机械结构、硬件设计、以及软件算法等方面，详细说明我们设计过程。硬件设计：选用逐飞科技TC264核心板，自主设计电源板、主板及电机驱动板。主要程序包括：显示程序、按键程序、定时中断程序、正交编码器采集程序、陀螺仪采集程序、摄像头采集程序、电机驱动程序、与语音模块通信程序及点阵模块控制程序。

第三章 机械结构设计及调整
本车采用型卡丁车车模，整体机械结构未作改动，拆除了原车的控制线路，仅保留原车的后面两个电机和前面的转向电机，并在车辆后部加装了第五轮正交编码器，舵机电机处也安装了编码器支架和联轴接，安装正交编码器，前部安装了摄像头和陀螺仪，主板、电源板、语音模块、点阵屏安装在车前部，驱动板安装在车辆后部。以下是科宇官方给出的车模规格：
车模尺寸：130*67cm
驱动电机：定制KY4845电机(额定电压DC24V)*2
转向电机：定制加长轴RS380电机(电压DC24V)*1
车轮：高强度耐磨EVA材料，后轮直径10时、前轮直径8吋简介:本定制车辆载重不低于80公斤，可坐人用方向盘手动操控，可遥控，因国赛要求采用车跟随人打点，然后自动原路返回，可以拆除遥控器。整车重量约22公斤(含电池)，整车底盘车架采用高强度钢管钢架结构，可伸缩，最长可达130cm，宽约70cm；车身外壳采用超强ABS材料，坚固耐撞:前端安装金属保险杠，保险杠缠绕了一层海绵，以免撞伤引导员，也避免高速时损坏车身。后轮驱动配置2个定制工业级24V150W直流马达，转向驱动配置1个24V15W定制直流电机控制转向，转向传动采用阿克曼机构，转向电机后轴已加长，加装了正交编码器。  
车辆最高时速不低于25公里/小时。

第四章 硬件设计
4.1电源板设计
由于我们是第一年进军大车组别，考虑车的电池和原来的小车组别电池规格和型号大不相同，故把电源模块独立出来:
采用固定12V输出的LM2596开关电源芯片把24V降到12V，转换效率可达90%以上, 注意固定12V电压输出LM2596输入电容的耐压要40V以上，容量大于470微法，输出电容也要大于100微法。










图4.1 电源板设计图
原始设计方案是采用mos管驱动，几番调试后均效果不佳。且距离比赛时间较近，打板时间不够充足，故舍去驱动部分，只保留电源部分。
采用可变电压输出LM2596把12V降7V，通过分压电阻网络（R10=51kΩ, R12=10kΩ）精确设定输出电压为7V，注意固定此LM2596输入电容的耐压要20V以上，容量大于470微法，输出电容也要大于100微法。
利用LM1117-5.0LDO把7V为降5.0V。
利用LM1117-3.3LDO再把电压降到3.3V。

4.2 驱动设计
电机驱动电路(H桥驱动模块)。采用左电机、右电机、转向电机各用一块驱动板，共需三块驱动板。每块驱动板需要两片BTN8982组成一个完整的H桥，用于驱动一路电机。BTN8982内部集成了P沟道高边MOSFET和N沟道低边MOSFET，以及相关的驱动控制和保护电路（如过温、过流、欠压保护）。
IN引脚接收来自控制器的PWM信号，决定半桥输出高电平还是低电平。
INH(Inhibit)引脚为使能端，通常置高电平以激活芯片，使能电源来源于前面的5伏特电源。
外围配置：每个芯片的电源引脚附近都配置了10uF和100nF的去耦电容，用于滤除电源线上的高频噪声，保证大电流切换时芯片电源的稳定。
每个驱动板有单独的电源开关，这在物理调试时提供了一个安全的电机硬件断电手段。
每个驱动板的接口如下：24v电源输入端子、接电机端子、PWM信号2根排线、5v电源、信号GND排针。

4.3主板
采用7v电源引到主板，用于给点阵屏驱动供电。
5v电源引到主板，给核心板、语音模块等需要5v的模块或芯片供电。
3.3v电源也引到主板，给陀螺仪、摄像头等需要3.3v的模块或芯片供电，注意为了使电源可靠，我们采用多针脚方案。
我们的主板采用模块化设计，主板上不走电源，只留插口，核心板插到主板上。主板上设置有传感器和电机信号接口。这样对于室外组别来说，更容易更换易损PCB，而且降低了主板损坏的机率。

5.3 IMU963RA解算
采用四元数方法解算航向角。打点时存储一定里程的航向角存储的不再是遥控器的舵机输入角度或转向角度，而是当前时刻车辆的航向角。我们也试图记录绝对磁力计航向（0~360°），但效果不好。
在回放时，系统将插值得到的期望航向与当前实测的绝对航向进行比较，并通过PD控制器直接生成给定的方向板转动角度，与实际的角度比较，输出转向电机的动作。
除了基础的回放控制，系统还集成了多个纠偏模块，以应对轮胎打滑、侧滑及传感器漂移带来的累积误差。
打滑检测(IMU Slip)：对比加速度计积分出的速度与编码器推算的速度，若编码器速度异常偏大，则按比例缩减计入里程的脉冲数。
转向侧滑补偿(Steer Odom Scrub):根据经验模型，转角越大，侧滑导致的里程多记越严重。系统通过 INS_STEER_ODOM_SCRUB_K 计算补偿系数动态缩小脉冲增量。
弯道里程补偿(Gyro Curve)：在弯道时，通过陀螺仪角速度和轴距推算理论行驶距离，将其与编码器读数加权融合。

第六章 开发工具及调试过程
AURIX™ Development Studio（以下简称ADS）是英飞凌公司于2019年底推出的免费的集成开发环境，支持英飞凌TriCore™内核AURIX™ 系列MCU；ADS是一个完整的开发环境，包含了Eclipse IDE、C编译器、Multi-core调试器、英飞凌底层驱动库（low-level driver,iLLD),同时对于编辑、编译及调试应用代码没有时间及代码大小的限制。
同时在程序的编译和运行过程中，遇到的大部分问题都能够通过ADCS的Debug模式解决。在这个模式下，用户可以单步运行程序,在设置断点处停止或复位程序，还可以将变量添加到“Variables”列表中，方便跟踪其变化。

   在调试流程上，我们采取了“分步实施、由简入繁、先静后动”的策略，以降低系统复杂度带来的风险，确保每个环节都稳定可靠。
1、静态硬件与基础通信调试
在整车通电但电机不启动的状态下，首先使用万用表和示波器检查各电源模块（24V、12V、7V、5V、3.3V）的输出是否正常且稳定。随后，通过串口或SPI接口，逐一验证核心板与各外设（陀螺仪、摄像头、编码器、语音模块、点阵屏）的通信是否成功，确保底层驱动能够正确读取传感器ID或初始化数据。这一阶段的目标是保证“电气通路”和“数据链路”的畅通。
2、开环执行机构测试
在硬件基础确认无误后，将车辆驱动轮垫起（使其悬空，避免带载损坏），进行电机和舵机的开环测试。编写简单的测试程序，分别给左驱动电机、右驱动电机和转向电机施加固定的PWM占空比，检查电机旋转方向是否一致、响应是否灵敏、是否有异响或异常发热。同时，验证正交编码器的读数是否正确反映了电机转速和转向，为后续的闭环控制打下基础。
核心传感器算法调试（桌面联调）
此阶段主要针对摄像头寻迹和IMU姿态解算进行算法验证。将车辆固定，引导员在车辆前方移动，利用显示屏实时查看摄像头捕捉到的图像和二值化处理后的效果，调试“列最小法”的阈值参数，确保能准确提取引导员的位置。同时，将IMU数据通过串口打印到上位机，观察四元数解算出的航向角是否平滑、准确，并验证磁力计校准和滤波算法的有效性。
整车动态闭环调试
在确保所有传感器信号可靠、执行机构动作正确后，进行整车带载动态调试。首先在低速条件下，测试“车随人”模式（即追踪引导员），调整摄像头的PD控制器参数，使车辆跟随平稳、不振荡。然后，测试“返回解算”模式：让引导员带领车辆走出一段包含直线和弯道的路径，存储航向和里程数据，随后让车辆自动返航。返航过程中，重点调试航向PD控制器和里程融合算法（包括打滑检测和弯道补偿），通过观察实际行驶轨迹与预期路径的偏差，反复调整各纠偏模块的系数。
系统联调与抗干扰测试
将语音识别功能与整车控制逻辑整合，测试“语音指令切换模式”的可靠性。最后，对整车进行抗干扰和极限性能测试，包括急加速、急刹车、急转弯等工况，检查电源电压是否稳定、通信是否中断、机械结构是否有松动。整个调试过程是一个不断迭代、逐层递进的过程，每一步验证都为下一步的顺利进行提供了坚实的保障。

第七章 结论
本技术报告详细阐述了辽宁理工职业大学“辽理工卡丁快跑二队”基于英飞凌TC264微控制器设计并制作的一款具备自主跟随与返航功能的智能卡丁车的全过程。报告从方案总体设计、机械结构改制、硬件电路搭建到软件算法实现，进行了系统性的总结。
在硬件方面，我们针对24V工业级车模的特点，设计了独立、可靠的级联降压电源系统（24V→12V→7V→5V→3.3V），为各模块提供了稳定的能量供应。采用模块化的主板设计，将核心控制、传感器接口和执行器驱动分离，极大提高了系统的可维护性和可靠性。三路独立的BTN8982电机驱动板，分别驱动左右驱动电机和转向电机，确保了动力充沛和控制灵活。
在软件算法方面，本项目成功攻克了大型车模在室外环境下的自主导航难题。我们不仅实现了基于摄像头视觉的“车随人”跟随模式，更重要的是，创新性地融合了里程计（编码器）、惯性导航（IMU四元数解算）和磁力计数据，设计并实现了一套完整的路径记录与返航算法。针对大型车模在运行中不可避免的打滑和侧滑问题，我们引入了打滑检测、转向侧滑补偿和弯道里程补偿等纠偏模块，显著提高了返航路径的复现精度。
然而，在实际测试中，我们也发现了一些待改进之处。首先，磁力计在室外复杂磁场环境下（如靠近金属物体或地下管线）容易受到干扰，导致航向基准偏移，未来可考虑引入GPS或UWB定位系统进行辅助融合。其次，车辆转向机构存在一定的机械间隙，在高速行驶或急转弯时会引起转向响应的非线性，影响了控制精度，后续可通过优化转向拉杆结构或采用更先进的模型预测控制算法来改善。最后，语音模块在嘈杂环境下的识别率有待提升，需增加更有效的降噪算法。
总体而言，本项目不仅成功实现了竞赛要求的所有功能，更在大车控制、多传感器融合及路径规划方面积累了宝贵的实战经验。从机械改装、硬件设计到复杂算法落地，整个开发过程全面锻炼了团队的理论分析能力、工程实践能力和解决复杂工程问题的能力，充分践行了全国大学生智能汽车竞赛“立足培养、重在参与、鼓励探索、追求卓越”的宗旨。

#define M_PI 3.14159265358979323846f
typedef struct {
    float q0;   // 四元数分量
    float q1;
    float q2;
    float q3;
    float roll;     // 滚转角（度）
    float pitch;    // 俯仰角（度）
    float yaw;      // 偏航角（度）
    float sample_time; // 采样时间（秒）
} quaternion_t;
quaternion_t attitude = {1.0f, 0.0f, 0.0f, 0.0f}; // 初始化四元数
void quaternion_init(void)
{
    attitude.q0 = 1.0f;
    attitude.q1 = 0.0f;
    attitude.q2 = 0.0f;
    attitude.q3 = 0.0f;
    attitude.sample_time = 0.001f; // 1ms采样时间
}
void quaternion_update(void)
{
    static float gyro[3];     // 存储角速度（弧度/秒）
    static float q0, q1, q2, q3;
    static float k1_q0, k1_q1, k1_q2, k1_q3;
    gyro[0] = imu963ra_gyro_transition(imu963ra_gyro_x/3*3) * (M_PI / 180.0f);
    gyro[1] = imu963ra_gyro_transition(imu963ra_gyro_y/3*3) * (M_PI / 180.0f);
    gyro[2] = imu963ra_gyro_transition(imu963ra_gyro_z/3*3) * (M_PI / 180.0f);
    // 一阶龙格库塔法
    q0 = attitude.q0;
    q1 = attitude.q1;
    q2 = attitude.q2;
    q3 = attitude.q3;
    // 计算k1
    k1_q0 = (-q1*gyro[0] - q2*gyro[1] - q3*gyro[2]) * 0.5f;
    k1_q1 = ( q0*gyro[0] + q2*gyro[2] - q3*gyro[1]) * 0.5f;
    k1_q2 = ( q0*gyro[1] - q1*gyro[2] + q3*gyro[0]) * 0.5f;
    k1_q3 = ( q0*gyro[2] + q1*gyro[1] - q2*gyro[0]) * 0.5f;
    // 计算四元数更新
    q0 += k1_q0 * attitude.sample_time;
    q1 += k1_q1 * attitude.sample_time;
    q2 += k1_q2 * attitude.sample_time;
    q3 += k1_q3 * attitude.sample_time;
    // 四元数归一化
    float norm = sqrtf(q0*q0 + q1*q1 + q2*q2 + q3*q3);
    if(norm > 0.0f)
    {
        q0 /= norm;
        q1 /= norm;
        q2 /= norm;
        q3 /= norm;
    }
    // 更新四元数
    attitude.q0 = q0;
    attitude.q1 = q1;
    attitude.q2 = q2;
    attitude.q3 = q3;
    // 计算欧拉角
    attitude.roll  = atan2f(2.0f*(q0*q1 + q2*q3), 1.0f - 2.0f*(q1*q1 + q2*q2)) * (180.0f/M_PI);
    attitude.pitch = asinf(2.0f*(q0*q2 - q3*q1)) * (180.0f/M_PI);
    attitude.yaw   = atan2f(2.0f*(q0*q3 + q1*q2), 1.0f - 2.0f*(q2*q2 + q3*q3)) * (180.0f/M_PI);
}
