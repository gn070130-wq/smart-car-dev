摘要
本文档对智能车的软件系统进行专项说明。系统以 TC264 微控制器为计算核心，采用主控与驱动分离的双处理器架构：主控端完成惯性导航、卫星定位融合、路径点巡航、转向控制与人机交互；驱动端完成霍尔信号采集、无刷电机换相、速度闭环及保护。通过卡尔曼滤波融合 IMU、编码器与 GPS 信息，系统在高频航位推算的基础上利用低频绝对定位修正累计误差，获得连续、平滑的车辆位姿。上层导航模块依据路径点与预瞄策略输出期望航向，底层 PD 控制器形成舵机闭环，同时结合转向强度实施动态调速。文档进一步给出驱动通信、参数整定、软件调试与安全降级方案，为竞赛现场部署和后续迭代提供依据。
关键词：TC264；组合导航；卡尔曼滤波；路径点巡航；PD 控制；GTM 驱动




















第一章 引言
1.1 智能车大赛介绍
全国大学生智能汽车竞赛由教育部高等教育司委托，自动化专业教学指导分委员会主办，旨在通过智能汽车的研究与实践，推动大学生科技竞赛的发展。该竞赛以探索性工程实践为核心，强调实践、创新和团队合作，致力于高等教育教学改革与素质教育的推进。竞赛秉持“立足培养，重在参与，鼓励探索，追求卓越”的理念，旨在提升大学生综合知识的应用能力、基本工程实践能力和创新意识，激发科研兴趣及潜能。
竞赛提供标准化软硬件平台，流程涵盖理论设计、实际制作、整车调试到现场比赛等环节，要求学生团队协作完成项目，体验从设计到实现的全过程。活动结合科学性、趣味性和观赏性，依托快速发展的汽车电子领域，覆盖自动控制、模式识别、传感技术等多个学科。透明的规则、客观的评价标准确保了竞赛的公开、公平、公正，促进了竞赛健康、普及、持续的发展。
1.2 第二十一届卡丁快跑组规则介绍
1.2.1 比赛环境
比赛可在多种室外场地举行，包括但不限于：标准运动场跑道、草坪区域、篮球场、羽毛球场地、城市广场或开放道路等。场地应具备足够的平整度与安全性，确保车模在高速运行下的稳定性与可控性。
室外比赛可能面临多变的自然条件，包括：光照变化（如强光、阴影、反光）；声音干扰（如人群、车辆鸣笛）；天气影响（如微雨、高温、风沙）。
参赛队伍需在设计阶段充分考虑上述因素，确保车模具备良好的环境适应能力。
防护与安全要求车模应具备基本的防水、防尘、耐高温能力，以应对非极端天气（如小雨、日晒）下的运行。
由于比赛场地可能存在固定障碍物（如树木、路灯、围栏）或其他动态对象（如其他车模、行人），车模需具备防碰撞机制，避免因意外碰撞造成设备损坏
或人身伤害。
1.2.2 比赛科目设置
比赛共设四个科目，按技术难度递进，分别考察车模在速度性能、转向控制、复杂路况通过能力及人机交互任务执行等方面的综合表现。
科目1：自动驾驶
比赛场地实在室外操场上。 包括有发车区，倒车入库区，锥桶绕行区。 车模自动从发车区出发，按照给定的方向依次绕行所有的锥桶之后，在倒车入库区完成倒车入库。
科目2：战场救护（人车交互）
科目2要求通过自然语言控制车模完成云端的人机交互任务。交互任务有四个区域任务。选手随机抽取一组语音口令，分别包括有四个区域八条任务。 通过安装在车模上的硅麦传感器，小车通过单片机AD通道完成硅麦的声音信号采集，并将语音数据转换成文字信息，进行识别之后完成相应的车模动作。 将语音信号成文字信息可以采用以下两种方式：
（1）将声音数据通过WiFI 联网之运动，调用云端语音转文字AI模型，根据语音转换的结果传递至本地；
（2）通过离线语音芯片+英飞凌硅麦；
  执行人机交互任务时，参赛队员坐在驾驶座位上，正对车模上的硅麦说出抽取的任务。
这个科目是通过检验交互任务完成来记录比赛成绩。
1、发车区灯光任务
  卡丁车在发车区完成灯光任务。灯光任务包括有以下八种语音命令：打开左转向灯、打开右转向灯、打开远光灯、打开近光灯、打开雾灯、打开双闪灯、打开车内照明灯、打开雨刷器。
注1：雨刷器可以使用一个灯来标识，也可以使用一个舵机移动一个模拟雨刷器。
注2：关于灯光任务，可以直接在卡丁车上前后位置安装上产出的灯光显示。 也可以在独立的一个 LED 屏幕上，显示不同的图案表示执行相应的灯光任务。如果使用LED屏幕显示需要使用Infineon免费赠送的LED驱动芯片 TLD4020（或者其它Infineon的TLD系列的芯片，但其它的Infineon驱动芯片没有免费赠送）组成LED屏幕。
2、停车区鸣笛任务
  卡丁车在停车区完成鸣笛任务。 鸣笛任务包括有一下八种语音命令：鸣笛1秒钟、鸣笛两秒钟、鸣笛三秒钟、鸣笛两声、鸣笛三声、鸣笛四声、长短鸣笛、急促鸣笛、警报鸣笛。 喇叭必须使用2W以上的无源扬声器，便于录制视频中能够清晰听到喇叭声响。
其中，
（1）鸣笛1,2,3秒：只需要一次；
（2）鸣笛2,3,4声：时长一秒，间隔一秒；
（3）长短鸣笛：鸣笛1秒钟，三秒钟，中间间隔一秒；
（4）急促鸣笛：鸣笛0.5秒，间隔0.5名，次数5以上次；
（5）警报鸣笛：使用双频声音（500Hz，1000Hz）交替发送，每个声音持续1秒，交替5以上次。
3、行进区通过门洞任务
  从发车区行进到动作区有五个语音命令：通过门洞1左侧，通过门洞1，通过门洞2，通过门洞3，通过门洞3右侧。
从动作区返回到停车区有五个语音命令：门洞1右侧返回，门洞1返回，门洞2返回，门洞3返回，门洞3左侧返回。
4、动作区车模运动任务
  车模行进到动作区有一下八条语音命令任务：前行10米、后退10米、蛇形前进10米、蛇形后退10米、逆时针转一圈、顺时针转一圈、左转、右转。
其中：
（1）前行10米，后退10米，蛇形前进，蛇形后退：根据现场场地大小，只需要超过现场规定的距离即可，比如大于5米。
（2）蛇形前进，蛇形后退，车模在行进过程中左右摆动，行进路线轨迹左右摆动超过2米。
（3）转一圈对应的转动半径可以在3米到10米均可。
（4）左转、右转，车模在行进超过2米之后，完成左转或者右转，而且只要方向转正之后即可停止。
科目3：如影随形（穿越迷宫）
在比赛前，所有的标识路上的锥桶重新摆放，不再允许进行位置定位。比赛分为两个阶段：
（1）第一阶段，车模从发车区出发，跟随参赛队员按照规定迷宫路径完成绕行之后到达停车区。 在分赛区比赛的时候，允许队员驾驶车模或者遥控车模完成迷宫绕行，在国赛的时候，则要求车模跟随队员完成迷宫绕行。
（2）第二阶段，车模根据第一阶段的路径，从停车区自动出发，绕行回到发车区。
比赛成绩等于第一阶段与第二阶段时间之和，包括两个阶段中间的时间，也就是车模从出发直到最后返回之间的时间。
  在参赛队员引导车模运行的时候，禁止携带电子设备进行引导和控制车模。 要求使用机器视觉进行跟随引导员。 允许在引导员衣服上张贴适当的图案便于车模识别跟踪。

1.2.3 评比标准
为提高效率、减少天气等外部因素影响，比赛采用分科目并行组织模式。所有参赛队伍按抽签顺序依次完成各科目的比赛。
调试阶段（并行调试）：各队在赛前按分配时间段进入各科目场地进行适应性调试；调试期间可进行参数优化、传感器校准等操作，正式比赛时不再提供现场调试时间。
正式比赛（并行比赛）：每轮比赛，车模按抽签顺序依次发车；前一辆车模完全返回起点后，下一辆车模立即出发；每辆参赛车模配备独立计时系统，确保计时准确、公正。
评判标准：在完成所有任务的前提下，用时越短，成绩越高；未完成任一科目或发生严重违规（如碰撞、脱轨、人工干预），该科目成绩无效；若车模存在安全隐患（如高速失控、部件脱落），裁判有权终止比赛

  本届智能车竞赛中，我们使用北京科宇第21届智能车比赛室外卡丁快跑车组专用F1方程式赛车，本定制车辆最大承重量不低于60公斤，可坐人，可用方向盘手动操控，可手柄遙控，可编程自动驾驶完成多方向连续运行及停车。整车重量约22公斤(含电池)，车身外壳采用红色/黄色ABS材料，坚固耐撞，前端安装金属保险枉，避免高速时损坏车身。整车底盘车架采用高强度钢管钢架结构，可以伸缩，最长可达13Ocm,宽约7Ocm;标准版车轮采用高强度耐磨EVA材料制作，摩擦力大，寿命长。车模带测试驱动板，购买车模配24V14Ah铅酸电瓶，配送原装专用充电器；车辆操控方便，反应迅速，前转向齿轮箱转动无虚位，转向电机和方向盘完美同步。车辆行驶采用2个工业级24V150W直流马达同时驱动后轮、采用1个24V15W直流电机控制转向，最高时速满足智能车比赛的要求。

第三章 软件方案
3.1 软件系统总体设计
软件采用“感知与状态估计—导航决策—运动控制—执行与保护”的分层架构。分层的目的在于将高频、确定性的底层任务与计算量较大的导航任务解耦，使定位、控制和驱动模块能够独立调试、独立优化，并在故障发生时实现快速降级。
表 1-1 软件分层及模块职责
主控端与驱动端通过 UART 传递目标速度、制动等高层指令，并通过心跳包确认双方工作状态。主控不直接承担高频电机换相，避免底层中断对定位融合、路径计算和控制周期造成扰动。
3.1.1 任务调度与数据流
系统以定时中断作为高频任务节拍。每个控制周期先读取 IMU 姿态和编码器速度，进行航位推算与状态预测；当 GPS 新数据到达时，再执行一次测量更新。随后由导航模块查找当前路径点或预瞄点，计算目标航向与期望速度，最后由 PD 控制器和速度规划模块输出舵机与电机指令。

3.2多传感器融合定位
3.2.1 卡尔曼滤波建模
卡尔曼滤波以“预测—更新”的递归方式估计动态系统状态。预测阶段依据上一时刻状态和运动模型得到当前先验估计；更新阶段将 GPS 观测与先验结果比较，并按不确定度加权修正。其线性形式可写为：
x(k) = F(k)x(k-1) + B(k)u(k) + w(k)
z(k) = H(k)x(k) + v(k)
其中 x 为状态向量，z 为观测向量；w 和 v 分别表示过程噪声与观测噪声。滤波器通过过程噪声协方差 Q 描述对运动模型的信任程度，通过观测噪声协方差 R 描述对 GPS 数据的信任程度。R 较大时输出更加平滑、更多依赖 IMU 与编码器；Q 较大时对 GPS 校正响应更快，但可能带入更多定位抖动。
3.2.2 状态量与预测过程
本系统采用五维状态描述车辆平面运动：x=[p_x, p_y, v, theta, b]^T，其中 p_x、p_y 为局部坐标系位置，v 为车速，theta 为航向角，b 为预留偏置项。预测过程使用编码器速度和 IMU 航向角进行航位推算：
p_x(k)=p_x(k-1)+v(k-1)dt cos(theta(k-1))
p_y(k)=p_y(k-1)+v(k-1)dt sin(theta(k-1))
高频预测可保证 GPS 暂时失锁或更新间隔较长时，车辆仍具有连续的位姿输出；其不足是积分误差会随时间积累。GPS 到达后，系统将经纬度转换为局部直角坐标，以位置量作为观测值更新状态，从而消除长期漂移。
3.2.3 多速率融合与异常处理
1.高频预测：以 2 ms 周期使用 IMU 与编码器更新位置、速度和航向，保证控制量连续。
2.低频校正：仅在接收到新的 GPS 数据包时触发测量更新，避免重复使用陈旧观测。
3.观测筛选：对突变、无效或质量不足的 GPS 数据不进行强制更新，防止异常观测拉偏轨迹。
4.参数整定：先保证预测轨迹短时间内平稳，再调整 Q、R 的相对量级，使车辆在动态响应和长期精度之间取得平衡。
3.3  路径点巡航与转向控制
3.3.1 路径点管理与预瞄
赛道路径以局部坐标系中的二维点序列表示。控制器依据当前融合位置计算到目标点的距离；当距离小于设定阈值时，自动切换至下一路径点。直接追逐相邻点容易使车辆在弯道内频繁修正，因此系统引入预瞄点：根据当前速度从路径序列中选择前方一定距离处的点，以更平滑的轨迹切入弯道。
设车辆当前位置为 (x,y)，预瞄点为 (x_t,y_t)，则目标航向可由 atan2(y_t-y, x_t-x) 得到。该航向与车辆当前航向的差值构成转向控制误差。预瞄距离随速度增大而适当增大，既降低高速摆动，又保留在急弯中的转向能力。
3.3.2 PD 舵机控制
舵机采用以航向误差为对象的闭环 PD 控制。比例项根据当前误差直接生成转向修正；微分项反映误差变化趋势，用于提前抑制过冲。主循迹任务不采用积分项，以避免目标航向快速变化时发生积分累积和舵机来回摆动。
u(k) = Kp·e(k) + Kd·[e(k)-e(k-1)]
为抑制 IMU 噪声和路径点切换引起的微分尖峰，微分量采用一阶低通滤波。滤波系数越小，输出越平滑但响应越慢；系数越大，则转向更敏捷但更容易振荡。最终控制量经 PWM 映射和舵机行程限幅后输出，防止机械极限附近的堵转。
3.3.3 动态速度规划
速度规划与转向强度相耦合。直道或小转向工况可逐步提高目标速度；当 PD 输出或期望转角增大时，系统降低速度上限，使横向加速度保持在可控范围。接近路径点、定位质量下降或短时失去目标时，系统采用阶梯减速；若失效持续超过阈值，则输出零速度并等待状态恢复。

3.4  驱动软件与双芯片协同
3.4.1 GTM 硬件自动换相
驱动端基于 AURIX MCU 的 GTM 模块构建 TIM→SPE→TOM 的硬件链路。TIM 模块采集三路霍尔位置并完成硬件滤波；SPE 模块根据预设换相表自动决定下一时刻 PWM 模式；TOM 模块输出六路互补 PWM 驱动无刷电机。该链路减少了 CPU 参与换相的频率，提高了执行确定性，并将算力留给速度闭环、电流电压采样和故障处理。
3.4.2 主控与驱动的接口
主控端通过 UART 向驱动端发送目标转速、制动及使能控制等指令；驱动端反馈转速、电流电压、故障码和心跳状态。通信协议采用固定帧头、长度、数据区和校验字段，接收端仅在帧完整、校验正确时更新控制量。对于超时、校验失败或驱动故障，主控端进入受控减速或停车状态。

3.6  鲁棒性与安全策略
竞赛场地存在光照变化、卫星信号遮挡、路面起伏、轮胎打滑和通信干扰等不确定因素。软件设计需把“保持可控”置于“维持高速”之前：任何单一传感器数据都不应直接决定全部控制输出；重要状态应通过时间连续性、范围限制和多源交叉验证进行筛选。
1.对定位、速度、航向和通信状态设置合理范围及变化率约束，异常数据不直接进入控制闭环。
2.对舵机角度、PWM 占空比和目标速度执行限幅，避免计算异常转化为机械损伤。
3.定位质量下降或路径目标暂时不可用时优先降速；故障持续时停车并保留调试状态。
4.保留关键运行信息，便于赛后复盘定位来源、控制输出和故障时间点。







第四章 硬件电路设计
4.1 硬件设计方案
从最初进行硬件电路设计时我们就既定了系统的设计目标：可靠、高效、简洁，在整个系统设计过程中严格按照规范进行。 可靠性是系统设计的第一要求，本队对电路设计所有环节都进行了电磁兼容性设计，做好各部分的接地、屏蔽、滤波等工作，将高速数字电路与模拟电路分开，使系统工作的可靠性达到了设计要求。
4.2 电路设计方案
本车的电路系统由六部分组成：以TC264为核心的主控电路及外设、单双驱动板、离线语音模块、音频放大器、灯板驱动和硅麦信号放大滤波电路，为了使电路板易于安装，希望将板子设计得更小巧，因此我们的板子大多数使用四层板的设计。四层板的优越性还在于其减小了布局布线的压力，且极大程度得减少了信号之间的串扰。
板上集成了本系统的主要电路，它包括如下部件：MCU 系统、硅麦模块接口、电机驱动板接口、陀螺仪接口、按键等。硅麦选用的是英飞凌的模拟硅麦IM68A130A。
在实际设计中，为了保证电路的可替换性，我们将各电路模块进行分立式的模块化设计。设计工具采用立创eda，对于智能车竞赛而言，立创eda的功能完善，设计界面简单，大部分操作通俗易懂，有免费的打板次数，且为国产软件，非常推荐。 电源模块为系统其他各个模块提供所需要的电源。电源模块可以说是智能车的命脉，电源模块的可靠性决定了车模的其他部分能否正常发挥作用。电源的不稳定将导致单片机复位、传感器不能正常工作等严重问题，因此稳定优秀的电源模块对车模尤为重要。
4.2.1 主板电源电路
主板系统承担整车的电源变换、电源保护与外围信号汇集功能。5V电源采用SP1N28STER同步降压转换器，该芯片输入电压范围宽、转换效率高，能够将电池电压稳定降压为5V，为单片机、传感器以及蜂鸣器等5V负载供电。考虑到单片机等数字电路需要3.3V供电，且5V与3.3V之间压差较小，选用RT9013-33GB低压差线性稳压器将5V转换为3.3V，该芯片输出波纹小、静态功耗低，保证了数字电路的供电质量。蜂鸣器驱动电路选用S8050 NPN三极管，通过基极串联限流电阻将单片机I/O口的高电平转换为蜂鸣器的驱动电流，并在蜂鸣器两端并联续流二极管，防止感性负载产生的反电动势损坏驱动管。电源保护方面，选用HY19P03D P沟道MOSFET作为整体电源保护开关，串联在电源输入端，利用其导通压降低、开关速度快的特性实现电源的通断控制，并配合过流与防反接保护电路，防止电池反接或负载短路时损坏整车电路。

4.2.2 电机驱动电路
电机驱动系统负责将主控输出的PWM信号转换为驱动电机的大电流功率信号。电机驱动模块采用了DRV双驱的方案，选用两片DRV8701E芯片（DRV8701ERGET），分别驱动左右电机的H桥，该芯片工作电压范围宽、栅极驱动能力强，内部集成了电流检测放大电路，能够根据PWM占空比精确控制电机的转速与方向。功率级采用TPH1R403NL组成H桥，与电调功率级选用同型号功率管，便于物料统一管理。由于主控板输出的PWM信号需要经过排线传输，信号波形在长线传输过程中容易发生畸变，我们在驱动板输入端使用SN74HC125W四路三态缓冲器对PWM控制信号进行整形与缓冲，增强信号驱动能力，避免主控与功率级之间的信号串扰，保证两路电机PWM信号的相位一致性。综合考虑到整车充电功率与驱动能力的匹配，驱动级采用12V电池直接供电。

static void k3v_gimbal_set_angle(float angle_deg)
{
    float servo_angle_deg;
    float duty;

    k3v_gimbal_angle_deg = k3v_clampf(angle_deg,
                                       -K3V_GIMBAL_WORK_LIMIT_DEG,
                                       K3V_GIMBAL_WORK_LIMIT_DEG);
    servo_angle_deg = K3V_GIMBAL_CENTER_DEG +
                      K3V_GIMBAL_SERVO_DIRECTION * k3v_gimbal_angle_deg;
    servo_angle_deg = k3v_clampf(servo_angle_deg, 0.0f, 180.0f);
    duty = (float)K3V_GIMBAL_SERVO_MIN_DUTY +
           servo_angle_deg * ((float)(K3V_GIMBAL_SERVO_MAX_DUTY - K3V_GIMBAL_SERVO_MIN_DUTY) / 180.0f);
    if(k3v_gimbal_ready)
    {
        pwm_set_duty(K3V_GIMBAL_PWM_CH, (uint32)(duty + 0.5f));
    }
}

static void k3v_gimbal_track_target(float lateral_m, float forward_m)
{
    float camera_bearing_deg;
    float angle_step_deg;

    if(forward_m <= 0.01f)
    {
        return;
    }

    camera_bearing_deg = atan2f(lateral_m, forward_m) * 57.29578f;
    if(fabsf(camera_bearing_deg) <= K3V_GIMBAL_TRACK_DEADBAND_DEG)
    {
        return;
    }

    angle_step_deg = k3v_clampf(-camera_bearing_deg * K3V_GIMBAL_TRACK_GAIN,
                                 -K3V_GIMBAL_TRACK_STEP_MAX_DEG,
                                 K3V_GIMBAL_TRACK_STEP_MAX_DEG);
    k3v_gimbal_set_angle(k3v_gimbal_angle_deg + angle_step_deg);
}

static float k3v_wrap_angle(float angle)
{
    while(angle > K3V_PI_F)
    {
        angle -= 2.0f * K3V_PI_F;
    }
    while(angle < -K3V_PI_F)
    {
        angle += 2.0f * K3V_PI_F;
    }
    return angle;
}

static uint16 k3v_rgb565_pixel(uint16 pixel)
{
#if KEMU3_VISION_RGB565_SWAP_BYTES
    return (uint16)((pixel << 8u) | (pixel >> 8u));
#else
    return pixel;
#endif
