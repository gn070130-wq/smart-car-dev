摘要
本文针对第二十一届全国大学生智能汽车竞赛“卡丁快跑”组别需求，设计了一款基于英飞凌TC364芯片的卡丁车车模结构与软硬件设计方案。核心控制器选用英飞凌TC364芯片，作为整车控制核心，支持高速运算与多外设协同。传感器系统整合陀螺仪实现惯导实时定位、正交编码器测量车模速度以构建速度闭环控制、角度编码器测量前轮准确打角、硅麦采集语音信号与凌瞳摄像头识别颜色；同时配备TLD7002 LED驱动芯片，通过HSLI接口实现灯板特定图案显示。控制算法采用PID控制策略，对电机输出扭矩与舵机转向角度进行精细化调节，确保车模在高速行驶中保持稳定性与操控性。机械优化通过减轻车壳重量、优化车模结构及轮胎抓地力设计，提升加速性能与弯道通过能力。调试则借助WIFI模块与上位机通信，结合IPS200屏幕实时监控车模状态，实现控制参数远程调整与算法优化。
该方案全面覆盖卡丁快跑组对车体机械设计、感知控制与系统集成的要求，为参赛队伍提供了从硬件选型到软件调试的完整参考。

车模整体设计
系统概述
车模主要分三个部分：控制器、传感器和执行器。控制器采用英飞凌TC364单片机，负责处理多源传感器数据并输出精准控制信号，满足大型卡丁车实车尺寸下的高速运算与多任务协同需求；传感器包括惯性导航系统（陀螺仪+加速度计）、角度与正交编码器、摄像头及TLD7002芯片，从而实现高精度定位与姿态感知、灯光秀效果及车态反馈；执行器采用强化型电机驱动电路，适配大型车模的高扭矩输出需求，搭配增量式PI控制算法调节电机PWM占空比实现速度闭环，转向则通过高精度PD控制算法优化弯道响应速度。
车模运行的整体流程围绕卡丁快跑组“室外大型载人卡丁车”的赛事需求设计，融合多传感器协同与科目任务适配：首先，传感器实时采集数据——IMU惯性测量单元实时获取车模相对位置、摄像头识别视觉目标（如科目三“如影随形”中的引导人员/标签）、正交编码器反馈电机转速、麦克风接收战场救护科目的语音指令，所有数据通过滤波等操作修正后传入单片机；其次，控制层基于数据计算期望状态：单片机结合惯导轨迹规划与视觉目标信息，通过PD控制算法调整转向舵机角度以修正轨迹偏差；最后，执行反馈层形成闭环控制：电机采用增量式PI控制调节PWM占空比，精准输出扭矩以匹配期望速度，编码器实时反馈的实际转速与目标速度对比后持续优化PI参数，确保巡航稳定性。
我们队伍参与的项目对车模的选型有明确限制，仅允许使用T车模。虽然可选方案单一，但T车模本身具备均衡的性能优势：其底盘采用一体化金属结构，刚性好且抗扭性强，在高速过弯时能保持稳定的姿态；同时，T车模的轮距设计适中，配合低重心布局，既保证了直线行驶的循迹性，又能满足赛道中急转工况下的灵敏响应。尽管缺乏其他车模的横向比较，但通过针对性改装与参数标定，我们充分挖掘了T车模的潜力，最终将其确定为唯一适配方案，以确保机械结构与控制算法的协同高效。

系统机械系统设计及实现
传动结构
T车模的转向结构，是靠转向电机带动转向轴转动，转向轴下部是横向连杆，其两端固定两前轮，带动前轮转向。 
动力结构部分，电机通过减速箱齿轮和后轮齿轮啮合，驱动后轮转动，实现前进后退。

电池选型
我们选择科宇原装24V 卡丁车电池作为电源方案。科宇原装电池的核心优势在于其出色的稳定性与可靠性，具体表现为：它采用高品质电芯与成熟封装工艺，能够提供持续平缓的电流输出，有效保障设备在全速运行中的动力连贯性，避免因输出波动导致的操控迟滞；同时，其在长期高负荷使用下仍能保持较低的发热量，显著降低热衰减风险，从而延长单次续航时间与整体循环寿命。
电机和转向电机的选型
我们选择科宇原装KW068有刷电机作为动力核心。有刷电机的核心优势在于其成熟可靠、控制简便与低速大扭矩特性：它通过碳刷与换向器的机械接触实现换向，结构简单且技术成熟，在复杂多变的越野赛道中展现出极强的耐冲击性和故障容错率。此外，有刷电机在堵转或重载工况下具备良好的过载能力，搭配科宇原装电池的稳定放电平台，能够持续输出充沛的牵引力，且维护成本低廉、配件供应广泛，便于我们在高强度测试中快速更换耗材，是兼顾经济性与场地适应性的务实选择。
转向电机选用科宇原装转向电机，24V供电，通过检测转动角度，可实现转向闭环控制。
同时，我们在符合规则的情况下，对车壳阻碍转向的部分进行了小规模切除，以减小转弯半径。
传感器及电路板安装
本车安装的传感器有逐飞后轮编码器*2，逐飞转向编码器*1，imu660rc六轴imu*1，凌瞳高帧率摄像头*1，逐飞硅麦模块*1。后轮编码器仿照逐飞设计安装板安在电机减速箱上，通过齿轮连接电机。转向编码器仿照逐飞设计安装板安装在转向轴旁，通过齿轮连接转向电机。六轴imu通过螺丝固定在车模尾部电池盖上。摄像头通过碳杆安装在车头打印件，硅麦模块焊在主控板上。
本车主控板，后轮电机驱动板，转向电机驱动板，均通过铜柱安装在车头打印件支架上。电池连接主控供电接口，主控输出24v电压给两个驱动板供电，主控通过fc线给驱动板提供信号。



 系统硬件设计及实现
	本车硬件设计主要分为以下几个模块：主控板模块，led灯板及其驱动模块，后轮电机驱动模块，转向电机驱动模块。稳定性是硬件的基本要求。
驱动板
驱动电路为智能车驱动电机提供控制和驱动，这部分电路的设计要求以能够通过大电流为主要指标。驱动电路的基本原理是 H 桥驱动原理，目前流行的H 桥驱动电路有： H 桥集成电路，如 MC33886；集成半桥电路，如 BTN7971 等；MOS 管搭建的 H 桥电路。
对于卡丁快跑组别，为了选出一个可以持续通过大电流的驱动方案，我们对比几种电路，MC33886 的优点是电路简单，外围元件少，但缺点是内阻较大，通过电流有限，可以通过两片 MC33886 并联方式进行改善；BTN7971是集成半桥电路，电路简单，只需要简单的几个外围电阻，缺点是输入电压要高于5V才能正常工作，需要升压电路给予其足够工作的电压，但是很难找到效率极高的升压芯片且升压电路设计也较为复杂。相比之下，使用DRV8701E电机控制芯片驱动由HD504N060SG这种mos管组成的H桥，既控制简单（只需输入方向及pwm值），又运行大电流通过，所以采取这种方案。
同时后轮电机及转向电机的驱动板均大面积开窗堆锡，加强散热能力。

LED灯板模块
对于卡丁快跑组别的科目二，需要在规定的范围内完成灯语的显示，我们选用了英飞凌的TLD7002芯片作为控制芯片。英飞凌的 TLD7002 是一款专为汽车和工业应用设计的 16 通道 LED 驱动芯片，采用线性电流驱动器架构（LCS），单通道最大输出电流可达 76.5mA 且支持通道并联扩展以驱动更大电流的LED负载。其每个通道均可通过 6 位 OTP 寄存器独立配置 5.625mA 至 76.5mA 的输出电流，并内置 14 位 PWM 引擎，支持 100Hz 至 2kHz 的频率调节，能实现动态灯光效果和精确的亮度控制。芯片集成了全面的保护与诊断功能，包括开路、短路检测及热降额机制，可配置故障阈值和去抖动时间，还支持 VS、VLED 电压监测及 NTC/PTC 温度反馈，符合 ISO 26262 ASIL-B 功能安全标准以保障高可靠性。芯片内置 HSLI（高速照明接口） 收发器，兼容 CAN-FD 物理层，通过UART协议可实现最高 2Mbit/s 的数据通信速率，用于远程配置与实时诊断；配置方式灵活，支持一次性 OTP 编程固化参数或通过仿真模式动态调试，开发阶段可借助 Arduino 兼容的 TLD7002-16SHIELD 快速验证方案。该芯片典型应用于汽车尾灯动态转向指示、内饰 RGB 氛围灯、工业 LED 面板等场景，尤其适合需要多通道精密控制和高安全性的照明系统。实际应用中需特别注意： OTP 编程时 VS 引脚电压必须严格保持在 15.5V至20V之间；正常工作时建议 VS电压不低于6V 以确保芯片性能。灯板驱动电路原理图如下图所示：

系统软件设计及算法实现
高效稳定的控制程序和高适应性的算法是智能车快速平稳运行的基础。卡丁车系统采用英飞凌TC2/TC3/TC4系列芯片作为核心控制器，通过摄像头、IMU（惯性测量单元）和硅麦等多传感器融合实现三项科目竞赛任务。为实现精准控制，系统采用正交编码器测速进行速度闭环，并结合经典PID控制算法与现代智能算法，确保卡丁车在各种工况下的稳定运行。

控制算法
PID算法介绍
PID控制器是过程控制中应用最广泛的算法之一，特别适用于被控对象模型不确定或难以建立精确数学模型的场景[1]。PID控制器通过计算给定值与实际输出值的偏差，将偏差的比例（P）、积分（I）和微分（D）通过线性组合构成控制量，对被控对象进行调节。
由于单片机控制是采样控制，只能根据采样时刻的偏差控制输出量，不能计算连续输出量，所以要采用离散化的PID算法。离散化PID公式如下：
		
离散PID分为位置式和增量式两种。位置式的输出量直接就是控制量，由于全量输出，所以每次输出均与过去的状态有关，计算时要对过去偏差进行累加，计算机工作量大；而且因为计算机输出量对应的是执行机构的实际输出，如计算机出现故障，输出大幅度变化会引起执行机构位置的大幅度变化，这种情况往往是生产实践中不允许的，在某些场合，还可能造成严重的生产事故。因而产生了增量式 PID 控制的控制算法，所谓增量式PID是指数字控制器的输出只是控制量的增量。由于计算机输出增量，所以误动作时影响小算式中不需要累加。控制增量的确定仅与最近k次的采样值有关，所以较容易通过加权处理而获得比较好的控制效果。
PD方向控制
方向控制采用PD控制，结合IMU数据与编码器实现精准航向控制：
xy点位信息获取：通过IMU计算的航向角与编码器数据融合建立相对坐标系，从而获取小车及路径xy坐标。
偏差航向角计算：根据所打点位，与自身坐标的夹角与陀螺仪计算的航向角计算航向角偏差

PI速度控制

自适应调整：根据速度变化自动调整PI参数，提升控制相应速度。
语音识别
基于讯飞（XF）ASR云服务的端云协同语音识别系统，支持实时音频采集、WebSocket传输、语音指令解析及车机交互控制，整体架构包含三部分：
前端音频处理：ADC采样+FIFO缓存+预处理
网络传输：WebSocket客户端+加密通信
指令解析：JSON格式结果转换+语义执行
关键技术优化：在原有方案基础上，我们预定义instruction[16]数组存储标准控制指令，支持16类语音命令（-1表示无效指令，-2表示紧急指令），同时设置全局标志位实现语音优先级控制，支持语音直接触发发车。
惯导方案设计
融合IMU（惯性测量单元）与 编码器 的紧耦合导航系统，通过四元数姿态解算和路径跟踪算法实现高精度定位与路径跟随，支持各个速度等级的动态自适应控制。关键算法与优化如下：
IMU姿态解算
该方案基于加速度计 + 陀螺仪数据，采用PI 互补滤波 + 四元数姿态解算算法，输出车体横滚、俯仰、偏航欧拉角，为路径跟踪提供车体航向姿态基准，同时在系统初始化期间通过1000次采样平均去除陀螺仪零偏，提升静态姿态稳定性，具体流程如下：
传感器数据实时预处理：加速度计采用一阶加权低通滤波抑制赛道颠簸高频噪声；陀螺仪原始角速度统一转换为弧度制，适配四元数微分迭代运算。
姿态观测误差计算：利用当前四元数解算出机体坐标系下理论重力向量，将理论重力与归一化加速度计实测重力做叉乘，得到三轴姿态误差。该误差表征陀螺仪长时间积分产生的姿态漂移量。
PI 互补滤波：采用比例积分校正机制补偿陀螺漂移。
梯形积分更新并归一化四元数：采用当前帧与上一帧角速度平均值实现梯形积分，相比普通矩形积分提升迭代精度。
四元数转换欧拉角并修正航向：将四元数转换为 ZYX 顺序欧拉角，最终输出横滚、俯仰、偏航角度。
路径跟踪算法
基于预存储赛道离散xy坐标点集，采用改进纯跟踪（Pure Pursuit）预瞄算法，结合 IMU 输出车体航向，实现全局坐标系下自主循迹，分为 KM1 正向巡线、KM3 倒车巡迹两套逻辑，支持直道、弯道、终点、倒车等赛场分段工况。
其流程如下：
匹配当前最近路径参考点：调用gd_find_nearest_point函数，以车辆当前坐标为中心，限定前后局部路径点区间，遍历搜索距离车身最近的赛道参考点；增设点位回退限制，避免颠簸、打滑时匹配路径点来回跳变，锁定当前所处赛道位置。
自适应预瞄距离：根据实时车速动态计算预瞄距离，车速越高预瞄距离越长，同时设置最大、最小预瞄距离阈值限幅。
带符号横向误差 CTE 计算与平滑：通过向量叉乘计算车身相对赛道中心线的横向偏差 CTE，区分车身左偏、右偏；采用一阶加权低通滤波平滑 CTE 数值，消除点位跳变带来的误差突变，保证转向控制连续平稳。 
求解期望目标航向：结合预瞄点路径航向、横向 CTE 偏差与预瞄距离，换算出补偿横向偏移后的期望目标航向；倒车工况下对 IMU 航向做 180° 修正，适配倒车朝向逻辑，最终供给上层转向 PID 控制器。
摄像头识别模块
为实现卡丁快跑组科目三“如影随形”任务中车辆对目标的实时跟随，w我们设计了一套基于颜色特征识别的视觉跟踪系统。系统采用凌瞳摄像头采集前方目标图像，通过图像处理算法获取目标中心位置，并将视觉信息传递至车辆控制模块，实现车辆方向调整和速度控制。
视觉处理流程
视觉处理流程主要包括图像采集、颜色特征提取、目标区域搜索、目标位置计算以及运动状态判断五个部分。具体流程如下：
图像采集与预处理：摄像头输出图像采用RGB565格式存储，首先通过颜色空间转换将图像转换至HSV空间。相比RGB颜色空间，HSV空间能够降低环境亮度变化对颜色识别造成的影响，因此更加适用于室外复杂光照环境下的目标检测。
颜色特征提取：在目标识别过程中，系统通过自动取色方式获取目标初始颜色信息，并建立对应HSV阈值范围。
目标区域搜索：通过遍历图像像素，对满足颜色条件的区域进行筛选，获得目标候选区域。
目标位置计算：利用颜色区域质心计算目标中心坐标，并通过边界搜索获取目标宽度和高度信息，为后续距离判断和控制提供数据基础。
运动状态判断：考虑到比赛过程中车辆高速运动导致目标位置变化较快，若采用全图搜索会增加计算量并降低响应速度，因此系统设计了基于目标运动趋势预测的ROI区域搜索方法。当当前帧成功检测目标后，根据连续帧目标中心位置变化计算目标运动方向，并预测下一帧目标可能出现的位置，在预测区域内进行重点搜索。当目标短暂丢失时，系统利用历史运动方向保持搜索趋势，并逐步扩大搜索范围，提高目标恢复能力。
基础视觉算法的优化处理
以上完成了视觉目标检测完整流程的设计。在实际室外竞赛场景中，光照条件复杂多变，仅依靠基础检测流程，难以应对强光、阴影、反光带来的识别扰动，同时高速运动场景下还存在检测结果抖动、距离估计等现实问题。为此，系统进一步引入颜色自适应、动态滤波、距离分级估算等优化策略，提升视觉算法在真实赛场环境下的鲁棒性与跟随控制效果。
颜色自适应：由于室外比赛环境存在阳光直射、背光、阴影以及反光等情况，目标颜色可能发生变化，导致固定阈值识别稳定性下降。针对该问题，系统加入颜色自适应调整机制，根据当前检测目标区域颜色特征动态调整HSV阈值范围。同时，在检测到异常高亮区域时冻结颜色更新，避免环境干扰导致颜色模型发生偏移，提高复杂光照条件下的识别可靠性。
动态滤波：为了提高车辆高速跟随稳定性，系统对视觉检测结果进行滤波处理。目标中心横向位置采用动态滤波方式，根据目标运动状态调整滤波强度：在车辆快速转弯或目标位置变化明显时降低滤波作用，提高响应速度；在目标稳定状态下增强滤波效果，减少由于像素变化造成的方向抖动。
距离分级估算：系统利用目标检测框尺寸变化估计车辆与目标之间的相对距离。通过目标宽度、高度以及面积信息建立距离判断模型，将目标状态划分为远距离、中距离和近距离三个等级，并根据距离状态调整车辆速度控制参数。当目标距离较近时，通过稳定控制策略降低视觉角度输出波动，避免停车阶段因目标中心像素变化导致车辆方向频繁调整。
最终，视觉模块将目标横向偏差、距离状态以及运动趋势信息传递至车辆控制系统，实现视觉感知与运动控制的闭环结合，使车辆能够在不同环境条件下保持稳定跟随。

总结
本文从机械、硬件、软件三方面系统阐述了卡丁快跑组车模的设计方案，核心围绕“大型载人卡丁车+室外视觉跟随+科目任务适配”三大挑战展开：
技术优化
结构优化：我们对车壳阻碍转向的部分进行了小规模切除，以减小转弯半径。同时在车头安装自己设计的3D支架，以支撑摄像头、主板及驱动板。
硬件设计：电机驱动采用MOS管搭建H桥方案，搭配堆锡散热工艺，提升大电流承载与散热能力。电源系统采用分层降压设计，依托SCT2450STER与RT9013芯片，实现高效、低噪、稳定供电且具备多重保护。主控板完善外设接口并增设运放放大微弱信号，同时采用TLD7002芯片实现高精度、高可靠的灯语控制，有效提升了整车硬件稳定性与实用性。
软件算法：针对卡丁快跑卡丁车模型，软件算法集成了三套核心方案：视觉循迹模块通过实时图像分析实现对目标 / 路径的精准跟踪，从而实现如影随形效果；惯性导航方案借助惯性传感器输出高精度定位与姿态信息，从而实现准确的导航结果；语音识别方案通过声学模型解析语音指令，实现便捷的人车交互。三套方案协同工作，有效提升卡丁车的自主控制能力与赛场环境适应能力。
备赛经验与启示
个人能力锻炼：在整个卡丁快跑赛车的开发调试周期中，组员的嵌入式编程、硬件电路设计、机器视觉算法调试、机械结构改装等多方面能力得到充分锻炼。从驱动代码编写，到赛道图像预处理、路径识别算法调参，再到电机 PID 参数整定，面对硬件故障、算法跑飞、赛车高速失控等各类实际问题，逐步建立起从现象定位故障根源的工程思维，提升了独立排查问题、迭代优化方案的实操能力。
安全意识深化：卡丁车高速行驶的安全隐患促使我们新增“遥控器刹车”功能，在出现危险之前操纵遥控器使电机PWM占空比立即降至0，有效避免了调试中因视觉失效或者其他情况导致的碰撞。
团队协作价值：团队采用分工协作模式，分别负责硬件电路、视觉算法、控制逻辑、机械改装。备赛过程中频繁开展方案讨论，互相验证代码逻辑、排查硬件 bug，遇到赛车性能瓶颈时集体头脑风暴，多角度分析问题。同时做好版本管理与沟通对接，高效推进项目进度。

//增量式（用于电机）
void ZPID(PID_parameter *Pidparameter,float intemax,float intemin)
{
    
    //保存上次偏差
    (*Pidparameter).PrOut=(*Pidparameter).Out;
    (*Pidparameter).Bias_2=(*Pidparameter).Bias_1; //换位置
    (*Pidparameter).Bias_1=(*Pidparameter).Bias_0;
    
    //计算当前偏差
    Pidparameter->Bias_0=Pidparameter->Target-Pidparameter->Current;
    
    //计算PID
    Pidparameter->P=Pidparameter->Kp*(Pidparameter->Bias_0-Pidparameter->Bias_1);
    Pidparameter->I=Pidparameter->Ki*(Pidparameter->Bias_0);
    //    //积分限幅
    if (Pidparameter->I>=intemax&&Pidparameter->I>=0) Pidparameter->I=intemax;
    else if (Pidparameter->I<=intemin&&Pidparameter->I<0) Pidparameter->I=intemin;
    Pidparameter->D=Pidparameter->Kd*(Pidparameter->Bias_0-2*(Pidparameter->Bias_1)+Pidparameter->Bias_2);
    Pidparameter->Out+=Pidparameter->P+Pidparameter->I+Pidparameter->D;
}

{
    
    (*Pidparameter).PrOut=(*Pidparameter).Out;
    (*Pidparameter).Bias_1=(*Pidparameter).Bias_0;
    
    Pidparameter->Bias_0=Pidparameter->Target-Pidparameter->Current;
    if (mode==1)
    {
        
        //对误差进行限制
        if (Pidparameter->Bias_0>180.0f) Pidparameter->Bias_0-=360.0f;
        if (Pidparameter->Bias_0<-180.0f) Pidparameter->Bias_0+=360.0f;
    }
    Pidparameter->Bias_I+=Pidparameter->Bias_0;
    //积分限幅
//    if (Pidparameter->Bias_I>=intemax) Pidparameter->Bias_I=intemax;
//    if (Pidparameter->Bias_I<=intemin) Pidparameter->Bias_I=intemin;
    Pidparameter->P=Pidparameter->Kp*Pidparameter->Bias_0;
    Pidparameter->I=Pidparameter->Ki*Pidparameter->Bias_I;
    
    //积分限幅
    if (Pidparameter->I>=intemax) Pidparameter->I=intemax;
    if (Pidparameter->I<=intemin) Pidparameter->I=intemin;
    Pidparameter->D=Pidparameter->Kd*(Pidparameter->Bias_0-Pidparameter->Bias_1);
    Pidparameter->Out=Pidparameter->P+Pidparameter->I+Pidparameter->D;
}

    gy=gy_g*PI/180;
    gz=gz_g*PI/180;
    // ★ 梯形积分：使用当前帧和上一帧角速度的平均值 ★
    float avg_gx = (gx + last_gx) * 0.5f;
    float avg_gy = (gy + last_gy) * 0.5f;
    float avg_gz = (gz + last_gz) * 0.5f;
    //加速度计：归一化。
    float ax_g=sensor.acc[0];
    float ay_g=sensor.acc[1];
    float az_g=sensor.acc[2];
    if (ax_g*ay_g*az_g==0) return;
    float acc_norm=invSqrt(ax_g*ax_g+ay_g*ay_g+az_g*az_g);
    ax=ax_g*acc_norm;
    ay=ay_g*acc_norm;
    az=az_g*acc_norm;
    //赋值给SENSOR
    sensor.acc[0]=ax;
    sensor.acc[1]=ay;
    sensor.acc[2]=az;
    //更新上一帧加速度
    last_ax=ax;
    last_ay=ay;
    last_az=az;
    //2.由四元数预测重力方向
    vx=2.0f*(q1q3-q0q2);
    vy=2.0f*(q0q1+q2q3);
    vz=1.0f-2*q1q1-2*q2q2;
    //3.计算四元数预测重力方向与加速度计预测重力方向的观测误差
    //（ax,ay,az）*(vx,vy,vz)
    ex=ay*vz-az*vy;
    ey=az*vx-ax*vz;
    ez=ax*vy-ay*vx;
    //误差进行积分
    if(abs(error.ex_int)<0.5f||abs(error.ey_int)<0.5f||abs(error.ez_int)<0.5f)
    {
        error.ex_int+=ex*0.001*sys_para.quarterion.ki;
        error.ey_int+=ey*0.001*sys_para.quarterion.ki;
        error.ez_int+=ez*0.001*sys_para.quarterion.ki;
    }
    //互补滤波
    gx+=sys_para.quarterion.kp*ex+error.ex_int;
    gy+=sys_para.quarterion.kp*ey+error.ey_int;
    gz+=sys_para.quarterion.kp*ez+error.ez_int;
    //5.四元数更新
    // 用平均值更新四元数
    float dq0 = 0.5f * (-q1*avg_gx - q2*avg_gy - q3*avg_gz);
    float dq1 = 0.5f * ( q0*avg_gx - q3*avg_gy + q2*avg_gz);
    float dq2 = 0.5f * ( q3*avg_gx + q0*avg_gy - q1*avg_gz);
    float dq3 = 0.5f * (-q2*avg_gx + q1*avg_gy + q0*avg_gz);
    q0+=dq0*0.001;
    q1+=dq1*0.001;
    q2+=dq2*0.001;
    q3+=dq3*0.001;
    // 保存当前角速度作为下一帧的"上一帧"
    last_gx = gx;
    last_gy = gy;
    last_gz = gz;
    //6.四元数归一化(防数值漂移）
    float norm=invSqrt(q0*q0+q1*q1+q2*q2+q3*q3);
    Q_info.q0=q0*norm;
    Q_info.q1=q1*norm;
    Q_info.q2=q2*norm;
    Q_info.q3=q3*norm;
    //7.转为欧拉角(ZYX顺序)(角度值)
    IMU_quaterToEulerianAngles();
}
惯导方案
    void gd_xunji_km3_pro(void)
    {
        int16 nearest;
        static int16 last_nearest = 0;
        static float last_cte = 0.0f;
        float preview_dist = gdpara_adjust.look_ahead
		+0.05f*fabsf(sys_para.Speed_car);//动态前瞻
        /*******************************模式判断***********************************/
        mode=1;//x+y(强制xy)
        /*******************************误差选择**********************************/
        trace_para.dis_error = gdpara_adjust.error_of_distance;
        /*******************************不同模式不同方式***************************/
        if (mode==1)//xy
        {
            // ====================== 1 清空（为mode==2)与赋值 ==================//
            gd_para.gddistance=0;
            trace_para.gdmode=1;//xy模式
            // ====================== 6 终点判断（全局生效）======================//
            float dx = gd_para.gdx[gd_para.targetpoint_gd] - gd_para.gd_x;
            float dy = gd_para.gdy[gd_para.targetpoint_gd] - gd_para.gd_y;
            float dx_end=gd_para.gdx[gd_para.gdindex-1] - gd_para.gd_x;
            float dy_end=gd_para.gdy[gd_para.gdindex-1] - gd_para.gd_y;
            float dis = sqrtf(dx * dx + dy * dy);
            float dis_end = sqrtf(dx_end * dx_end + dy_end * dy_end);
            //第一:直接结束
            if (trace_para.carstatus == end_car) return;
            //第二：标准结束（其实没啥用）
            if (gd_para.targetpoint_gd == gd_para.gdindex - 1 )
            {
                if (dis < trace_para.dis_error)
                {
                    trace_para.carstatus = end_car;
                    return;
                }
            }
            //第三：动态结束(要求打的点足够多)
            else if (gd_para.gdindex -gd_para.targetpoint_gd <= 28
			 &&dis_end < trace_para.dis_error)
            {
                if (gd_para.gdindex >gd_para.targetpoint_gd) 
			trace_para.carstatus = end_car;
                return;
            }
            //第四：越界防护
            if (gd_para.targetpoint_gd >= gd_para.gdindex )
            {
                trace_para.carstatus = end_car;
                return;
            }
            //优化的惯导
            nearest = gd_find_nearest_point();
            //增添限制
            if (nearest < last_nearest - KM3_NEAREST_BACKTRACK_MAX)
                nearest = last_nearest - KM3_NEAREST_BACKTRACK_MAX;
            nearest = CLAMP(nearest, 0, gd_para.gdindex - 1);
            last_nearest = nearest;
            gd_para.nowpoint_gd = nearest;
            gd_para.targetpoint_gd =
		gd_find_lookahead_point(gd_para.nowpoint_gd, preview_dist);
            float cte = gd_signed_cross_track_error(gd_para.nowpoint_gd);
            cte = 0.75f * cte + 0.25f * last_cte;
            last_cte = cte;
            float path_heading = gd_path_heading(gd_para.targetpoint_gd,1);//倒车模式
            float cte_heading = atan2f(gdpara_adjust.gd_cet_gain * cte, 
				preview_dist)* 180.0f / PI;
            float yaw_deg = sys_para.eulerAngle.yaw;
            //如果倒着走，需要取消注释
           yaw_deg+=180.0f;
           if (yaw_deg>360) yaw_deg-=360;
		//小车位于右侧，cte_heading为正
            trace_para.target_yaw =angle_normalize(path_heading - cte_heading);
            trace_para.current_yaw = yaw_deg;
        }
        //强制为6（发车时）
        trace_para.yuansu_flag=backup;
    }
