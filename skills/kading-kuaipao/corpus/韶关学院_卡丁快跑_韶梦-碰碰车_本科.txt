摘要
本作品以英飞凌 TC387 车规级多核微控制器为核心控制单元，基于赛事官方指定 T 型载人卡丁车平台，构建了适配室外操场场景的 "视觉跟随 + 纯惯导航迹复现" 智能驾驶系统。系统围绕卡丁快跑组三大竞赛科目 —— 自动驾驶绕桩泊车、语音人机交互、如影随形穿越迷宫 —— 开展全系统设计。
核心技术方案采用 "视觉人跟随 + 纯惯导里程计" 双模式架构：在 "如影随形" 科目第一阶段，通过 MT9V034 全局快门摄像头实时识别前方引导员，提取目标横向偏差（final_mid_line）控制转向，配合按键设定的目标速度与缓加速策略，完成载人卡丁车对人员的自主跟随；同时利用 IMU660RC 六轴陀螺仪解算航向角、双绝对编码器累计里程，以固定距离间隔记录轨迹点数组，构建纯惯导航迹地图。第二阶段切换至自主返回模式，采用纯追踪（Pure Pursuit）算法按记录轨迹反向循迹，自动从停车区返回发车区。
系统同时集成硅麦语音采集与 WiFi 云端识别模块，支持灯光、鸣笛、行进、转向等多类语音指令执行；保留 SBUS 遥控手动模式，实现自动 / 手动无缝切换。控制层采用阿克曼运动学模型，配合大转角自动降速与斜坡加减速策略，保证载人行驶的平顺性与安全性。
本设计通过机械结构低重心优化、硬件电路抗干扰设计与分层软件控制架构，在载人卡丁车平台上实现了高精度视觉跟随、稳定惯导航迹复现与自然语音交互的有机结合，全面适配卡丁快跑组全部竞赛科目要求。



关键词：智能卡丁车；英飞凌 TC387；纯惯导航迹复现；视觉人跟随；纯追踪算法；语音交互；阿克曼控制

引言
全国大学生智能汽车竞赛是融合控制科学、电子工程、计算机技术与机械工程的综合性科技赛事。第二十一届赛事首次增设卡丁快跑组别，以载人卡丁车为载体，聚焦室外开放场景下的自主导航、人机交互与路径记忆能力，对系统的环境适应性、控制稳定性与功能集成度提出了全新挑战。
卡丁快跑组设置三大核心科目：科目一 "自动驾驶" 要求车模自动完成绕桩与倒车入库；科目二 "战场救护" 要求通过自然语言语音指令控制车辆完成灯光、鸣笛、通行与运动任务；科目三 "如影随形" 要求车模先跟随引导员穿越迷宫，再依据记忆路径自主返回发车区。其中科目三对实时目标跟踪与路径记忆能力提出了较高要求，是本设计的技术重点。
本团队基于赛事指定 T 型载人卡丁车平台开展全系统改装设计，围绕三大科目任务，重点攻克室外光照下的视觉人跟随鲁棒性、纯惯导航迹累积误差抑制、载人工况下的动力控制平顺性三大技术难点。系统设计遵循 "感知 - 决策 - 执行" 三层架构：感知层融合摄像头、IMU、编码器等多源传感器数据构建环境与车身状态模型；决策层通过视觉跟踪算法、惯导航迹记录与纯追踪路径规划输出运动指令；执行层通过电机驱动与转向舵机完成车辆运动控制。
研发过程中，团队完成了从机械结构改装、硬件电路设计到软件算法调试的全流程开发，经过多轮室外场地测试迭代优化，最终形成了功能完整、运行稳定、适配竞赛规则的完整技术方案。

第一章 车模设计及其技术方案
1.1 车模设计
针对卡丁快跑组室外开放场地、载人行驶、多科目任务的核心特点，本设计以官方指定 T 型载人卡丁车为机械基础。
覆盖全部竞赛科目需求，同时保留原车手动驾驶与遥控能力，支持自动 / 手动模式快速切换；
载人场景下设置多重安全保护机制，包括硬件过流保护、软件急停逻辑、大转角自动降速与遥控紧急制动；
采用模块化设计与按键菜单化参数配置，支持现场快速校准传感器、调整控制参数，适配不同比赛场地。
硬件架构采用 TC387 多核主控方案（CPU0 运行主控制逻辑，CPU1 处理图像采集与视觉算法），配合自制功能底板实现外设扩展。感知系统配置全局快门摄像头、六轴 IMU、双正交编码器、绝对编码器、硅麦语音模块与 WiFi 模块，形成 "视觉目标跟踪 + 惯导航位推算 + 语音人机交互" 的完整感知体系。

1.2 技术方案
本系统采用 "视觉人跟随 + 纯惯导航迹复现" 的核心技术方案，整体技术架构如下：

感知层方案：
视觉目标跟踪：MT9V034 全局快门摄像头采集前方图像，通过图像分割与特征提取识别引导员（或引导员身上的标识图案），计算目标在图像中的横向偏移量，作为转向控制的直接输入。
惯导姿态解算：IMU660RC 六轴传感器实时采集角速度与加速度，通过四元数姿态解算算法输出车身航向角，为轨迹记录与路径跟踪提供航向基准。
里程计测距：左右轮各装一个绝对编码器，实时采集车轮转角，经阿克曼运动学模型换算为车辆行驶距离，作为轨迹记录的距离触发条件与速度反馈。
语音人机交互：硅麦采集语音信号，经放大后通过 WiFi 模块上传至云端语音识别 API，解析指令后触发对应车辆动作与灯光 / 鸣笛输出。

决策与控制层方案：
视觉跟随模式：以摄像头目标横向偏差为转向控制输入，按键设定目标速度，配合缓加速策略实现对引导员的实时跟随行驶。
惯导记录模式：在跟随行驶过程中，以固定距离间隔（≥2 个编码器单位）触发轨迹点记录，将当前位置坐标（xr, yr）与航向角存入轨迹数组，最多支持数十个轨迹点。
纯追踪返回模式：记录完成后切换至自主返回模式，采用纯追踪（Pure Pursuit）算法，以轨迹数组反向序列为目标路径，计算期望转向角，控制车辆沿原路径自动返回。
阿克曼运动控制：基于阿克曼转向几何模型，将期望速度与转向角换算为左右轮转速与舵机角度，实现差速驱动与转向协同控制。
语音指令执行：解析语音指令后，匹配预定义动作集，控制车辆完成灯光显示、鸣笛、前进 / 后退 / 转向 / 绕圈等指定任务。
科目适配方案
科目一（自动驾驶）：采用惯导记录 + 纯追踪复现方案，预先录制绕桩与泊车路径，比赛时自动执行；配合视觉识别锥桶修正局部偏差。
科目二（语音交互）：硅麦采集语音→WiFi 云端识别→指令匹配→执行灯光 / 鸣笛 / 运动任务。
科目三（如影随形）：第一阶段视觉跟随引导员走迷宫，同时惯导记录轨迹；第二阶段纯追踪算法按记录轨迹自主返回。

第二章 机械系统设计与实现
车辆的运行上限由其机械结构决定，若想实现极为流畅稳定的运行，离不开优良的机械结构支撑。此外，机械结构与软件算法的有效协同，是保障系统正常运转的核心前提。因此，在机械设计阶段，必须审慎考量各部件的功能定位，着力优化机械参数，从而实现与软件控制算法的高效适配。
2.1 机械结构设计
在第二十一届全国大学生智能汽车竞赛中，我们采用赛事官方指定的 T 型载人卡丁车车模，其硬件配置完全达到专业级载人竞赛水准。从结构强度来看，该车模底盘选用高强度钢管焊接而成的空间桁架结构，搭配加厚型转向节与金属下摆臂连接件，能从核心结构层面全方位强化车身整体刚性，确保 100kg 载人载重下的结构安全与形变量控制；全车传动系统搭载金属减速齿轮与链条传动机构，不仅耐磨性优异，还可大幅降低传动损耗，使车辆行驶更平顺、过弯稳定性更突出；其连接端的固定板采用加厚金属板材加工，进一步提升了车身抗撞性与结构坚固度。
在行驶稳定性方面，轮胎配置上，胎皮选用优质防滑越野橡胶材质，既扩大轮胎与地面的摩擦接触面积，显著增强抓地力，又能有效缓冲行驶中的颠簸震动，适应室外操场草地与塑胶跑道的复合路面；出厂时胎皮与轮毂已通过专用工艺紧密结合，可彻底规避高速行驶时胎皮脱落的风险。此外，车模的动力与操控适配性同样出色，电机兼容性强，可搭载大扭矩直流无刷驱动电机，该电机转速快、动力强，能充分满足载人竞赛场景下的动力需求；转向机构采用齿轮齿条式阿克曼转向设计，响应灵敏，操控手感精准顺滑；整车零部件加工精度高、装配配合精细，兼具长期使用的耐用性与赛车的性能质感

3.3 电路设计
1.主板电路设计
本主板整体采用电池供电（VCCBAT）、多级电源轨分配、模块化接口扩展的设计思路。在电源输入与保护层面，板子通过 XT60 接口接入电池，输入端配备 BZT52C30V 稳压管与 SMAJ33A TVS 瞬态抑制二极管构成防反接与浪涌保护电路，经电源开关后由四颗 BSC030P03NS3G P 沟道 MOS 管组成电源分配与电机驱动开关网络，同时引出两路有刷电机接口；为满足不同模块的电压需求，板上设计了三路基于 SP1N28STER 同步降压芯片的 DC-DC 开关电源，分别输出 VCC5V（系统 5V 主电源）、VCC7V（灯光秀模块专用电源）以及 （VCCSTEER 舵机电源），此外还通过两片 TPRT9013-33GB 低压差线性稳压器分别生成 VCC3V3 主控逻辑电源与摄像头专用 3.3V 电源，每路 LDO 均配输入输出滤波电容与独立 LED 指示灯，形成 "BAT→DC-DC→LDO" 的三级供电架构。在核心控制与人机交互层面，板载7路轻触按键加 1 路拨码开关构成按键阵列，每路按键通过 4.7K 上拉电阻接 VCC3V3 后引出至主控 IO，同时设有 S8550 PNP 三极管驱动的 2.75kHz 无源蜂鸣器报警电路。在传感器与通信接口层面，板子集成了丰富的外设接口：包括SPI 显示屏接口、摄像头接口、感知模块接口、两路踏板输入接口、三路编码器接口、陀螺仪接口、定位模块接口、无线串口模块接口、WiFi 转接串口。在执行器驱动层面，除前述两路有刷电机输出外，还设有独立舵机接口和灯光秀驱动接口（H14，由 VCC7V 供电，支持多路 LED/PWM 输出），并通过 MOS 管切换电路实现 VCC5V 与 VCCBAT 之间的电源域切换。整体来看，这块主板将电源管理、电机驱动、舵机控制、多传感器接入、人机交互和无线通信高度集成于一体，供电上注重分级与隔离保护，接口上兼顾工业级连接器与标准排针。

2.电机驱动电路设计

第四章 软件系统设计及实现
4.1 软件总体架构与任务调度
本车软件以英飞凌 AURIX TC387QP 为核心，采用“感知—决策—执行”分层结构，并利用多核资源拆分图像处理、控制管理与人机显示任务。CPU0 完成系统初始化、运行模式管理、航向与里程更新、语音交互以及控制量组织；CPU1 等待 CPU0 外设初始化完成后启动 MT9V034，并在每个 DMA 完整帧到达后执行目标识别；CPU2显示灰度图像、目标叠加框、航向角、横向误差和测距结果。
初始化函数统一配置 IPS200、IMU660RC、绝对式转向编码器、转向电机、超声波舵机、ADC、按键、左右轮电机与编码器、蜂鸣器、拨码开关、SBUS 接收机及三个 5 ms 周期 PIT。CPU1 对相机 DMA 所在共享内存段采用非缓存访问，规避 DMA 已更新而 CPU 仍读取旧缓存的风险；语音模式启动时暂停摄像头 VSYNC/DMA 与 IMU 外部中断，退出后再恢复，避免高优先级数据源与 WiFi 音频链路争用资源。

图4-1 软件分层与多核任务划分
实时控制集中在 5 ms 周期中断中执行。中断先接收 CPU1 输出的视觉横向误差，再依据当前运行状态选择距离控制、正向行驶或反向返回，随后调用阿克曼差速和转向位置闭环。编码器在另一个 5 ms 周期中断中采样并清零计数器；串口中断分别服务GNSS 与 WiFi；相机通过 VSYNC 触发 DMA，DMA 完成后置位完整帧标志。各任务之间只交换必要的全局状态和控制量，减少长耗时图像、网络处理进入电机控制中断的概率。
4.2 运行模式与安全互锁
CPU0 主循环以按键、接收机通道和状态标志构成模式管理器。默认状态下由 SBUS 遥控器提供速度和转向命令；KEY2 进入图像循迹与航迹记录，首次进入时清零左右轮累计编码器、局部坐标和路径数组，并保存起始航向偏置；车辆每行驶约 2 cm 记录一个局部坐标点。KEY8 触发制动等待，定时完成后进入反向路径跟踪，从最后一个记录点沿索引递减方向返回起点。KEY6 进入语音交互，KEY2 具有更高优先级，可强制退出语音独占模式并恢复摄像头。


图4-2 主控运行模式与安全切换
安全设计采用“命令清零优先、状态复位随后”的原则：接收机安全通道越过阈值时立即将前进/反向目标速度置零；停止键会关闭图像模式、清除距离控制启动锁存并复位相关按键；反向返回开始前先停止电机并将转角归零；到达起点后同时清零正、反向速度及转向目标。图像模式、语音模式与高优先级中断之间均有显式启停和标志清理，防止模式切换时继承旧帧、旧速度或旧积分状态。
4.3 视觉目标识别与稳定跟踪
视觉模块处理 MT9V034 灰度图像，目标为带外框的中心十字标志。算法先在全图或历史预测 ROI 内统计平均亮度与平均绝对偏差，据此自适应调整对比度阈值和锁定/保持得分阈值；随后使用 6、8、10、12、16、20 像素多尺度十字臂长进行步进粗搜索，并在最佳候选点附近逐像素精细搜索。为排除背景长直线和锥桶纹理，候选中心还需通过上下左右四条外框的边缘响应、对称性、宽高比和距离约束。
稳定跟踪使用“锁定—保持—丢失”状态机。未锁定时要求候选得分连续满足阈值；锁定后采用较低的保持阈值并允许短时丢失。相邻帧位置生成速度估计，速度经过限幅和低通后用于自适应前视预测；当候选跳变超过物理上限时拒绝该帧，在信任半径之外则要求多帧一致确认。最终位置由预测值和测量值按置信度动态融合，置信度同时考虑识别得分裕量与预测残差。
横向误差由目标中心相对图像中线的位置得到。原始误差先经“中心低增益、边缘高增益”的 S 形映射和死区处理，再通过历史中值滤波抑制脉冲噪声，最后与上一帧输出进行动态权重融合。目标短期丢失时沿估计速度预测并逐帧衰减，长期丢失时将控制误差平滑回零。CPU0 的控制中断取反 final_mid_line 作为目标转角，从而将视觉像素偏差转换为转向命令。

4.4 航迹记录、局部定位与纯追踪控制
4.4.1 编码器—航向航迹推算
当前实际运行路径使用 IMU660RC 模块输出的航向角 imu660rc_yaw，并在录迹开始时减去 yaw_offset 建立局部零航向。左右轮编码器每 5 ms 读取一次，累计脉冲的平均值换算为总里程；相邻周期的里程增量与航向角共同更新车辆在“右为 x 正、前为 y 正”的局部平面坐标。该实现无需依赖卫星信号，适用于桥洞、建筑遮挡和短距离往返场景。

录迹模式下，当累计里程相对上次记录点变化不小于 2 cm 时，将当前 x、y 写入 coordinate_x/coordinate_y 数组并增加 finish_count。返回阶段从 finish_count−1 开始搜索目标点，索引随车辆行驶逐步减小，因此可以沿原始路径反向重放。源码同时包含 GNSS 经纬度打点、地图显示、Flash 保存以及 ESKF 模块，但当前 cpu0_main.c 未调用这些模块；本报告将其列为预留能力，不作为现行闭环定位方案。
4.4.2 自适应纯追踪与速度规划
纯追踪控制先从当前 goal_num 向路径起点方向搜索距离车辆达到前视距离的目标点。返回算法的速度前视距离由车辆速度确定，并在 90～140 cm 范围限幅；同时计算目标区间的平均曲率，以曲率前视和速度前视按 0.7∶0.3 融合，再执行第二次目标点搜索。这样可在直线段提前观察更远点、减小舵机频繁修正，在弯道缩短有效前视以提高跟随精度。
路径曲率以相邻路径段方向角的绝对变化量除以弧长估计。目标速度按照“直线高速、弯道低速”原则由曲率线性衰减，并使用一阶低通抑制跳变；当前返回参数将目标速度限制在 50～55 的控制量范围内。车辆接近起点且 goal_num 足够小时，将正向速度、反向速度和转向角全部清零，并置位完成标志。

4.5 底盘运动控制
4.5.1 阿克曼差速
运动学层根据基础速度与转向误差计算左右轮目标速度。转向误差先从角度转换为弧度，在 ±0.08 rad 内设为零以抑制直行抖动，并限制在 ±1.42 rad。随后以轮距 B 与轴距 L 的比值构造左右轮速度差：左转时降低内侧轮、提高外侧轮，右转时关系相反。中断还会在目标转角绝对值超过 30°且基础速度较高时逐步扣减速度，形成额外弯道保护。
k = B/(2L)
v_L = v(1-k·e_δ),   v_R = v(1+k·e_δ)
4.5.2 左右轮增量式 PID
左右轮采用独立增量式 PID。编码器速度与目标速度做差后，比例项使用相邻误差差值，积分项使用当前误差，微分项使用二阶差分，并对微分分量施加 0.3/0.7 一阶低通。输出增量累加到 PWM 占空比后限幅；前进和后退分别设置不同的输出区间。六个左右轮 PID 参数由 Flash 读入，便于不重新编译即可保留实车整定结果，同时方便调试。

4.5.3 转向位置闭环
转向机构由直流电机与绝对式编码器构成位置闭环。目标角首先限制在机械安全范围内，实际角度由编码器计数减去中位值后按每圈计数换算。控制器使用线性位置误差、误差变化以及预留的非线性/速率反馈项生成 PWM，输出再限幅并根据符号切换方向引脚。相较开环舵机脉宽控制，该结构能直接补偿机械载荷和地面冲击造成的位置偏差。
4.6 语音交互与通信
语音模式通过 ADC 以 8 kHz、16 bit 单声道采集硅麦数据，125 μs PIT 回调将采样写入 FIFO。音频按照首帧、连续帧和结束帧组织为 JSON，PCM 数据经 Base64 编码后通过 WiFi 串口模块和 WebSocket 发送至在线语音识别服务。连接前先获取网络时间，使用 HMAC-SHA256、Base64 与 URL 编码生成鉴权参数；WebSocket 握手还校验 Sec-WebSocket-Accept，接收端解析文本帧并汇总识别内容。
语音任务设有三次 WiFi 与时间获取重试、发送失败复位、最终结果超时和无语音判断。识别到有效文本后，Process_Short_Sentence 根据关键词触发双闪、左右转向灯、近远光、雾灯、雨刮和车内灯等动作。由于语音处理与摄像头/IMU 中断具有资源竞争，系统进入语音模式时暂停相机和 IMU 数据源，退出时清理 FIFO、网络连接与会话标志，再恢复视觉模式。
4.7 参数存储、调试与软件版本边界
Flash 层提供两类接口。专用 double 数组接口通过联合体获取 IEEE 754 的 64 位位模式，并将其拆为四个 16 位片段，分别放入四个 uint32 缓冲单元；读取时按 48、32、16 和 0 位移重新组合。通用接口则按照元素个数与字节宽度直接 memcpy 到页缓冲区，并用 zf_assert 检查所需 32 位单元数不超过 EEPROM_PAGE_LENGTH。该层用于保存电机 PID 参数，并可支持 GNSS 点列、轨迹点及菜单参数。
调试主要依赖 IPS200 实时显示、蜂鸣器反馈、串口日志和源码中的运行时调试开关。CPU2 显示相机灰度图、识别十字和四边外框，可同时观察 yaw_yaw、final_mid_line 与 current_distance；图像模块可输出候选得分、对比度、预测残差和拒绝原因；控制模块在关键模式切换时清屏并用蜂鸣器确认，便于赛场快速判断状态。

第五章 智能车调试说明
5.1 调试环境与工具

智能车的调试是将机械结构、硬件电路与软件算法有机融合的关键环节，也是决定最终竞赛成绩的核心因素。本车调试遵循 "从模块到系统、从室内到室外、从低速到高速" 的渐进式原则，分为模块级调试、系统联调与场地实车调试三个阶段，逐步验证各子系统功能并优化控制参数，最终实现稳定可靠的自动驾驶性能。
5.1.1 调试场地
调试工作在室外操场进行，场地包含塑胶跑道与草地两种路面，与竞赛环境一致。调试区域划分为直线测试区（长约 30m）、转弯测试区（半径 3~5m 圆弧）、迷宫模拟区（用锥桶搭建 S 形与 U 形路径）和语音测试区（安静环境），分别对应不同功能模块的调试需求。
5.1.2 调试工具
软件调试：英飞凌 AURIX Development Studio（ADS）配合 vofa上位机，实时性问题排查与算法调优。
串口调试：USB 转 TTL 模块连接主控 UART0 调试串口，使用串口助手实时输出航向角、编码器里程、视觉横向偏差、纯追踪目标点索引等关键变量，便于数据分析。
显示调试：车头 IPS200 显示屏实时显示当前运行模式、yaw_yaw 航向角、final_mid_line 视觉偏差、motor_speed 目标速度、goal_num 当前目标点索引等状态信息；CPU2 副屏显示摄像头灰度图与目标识别叠加框，可直观观察视觉算法效果。
参数存储：电机 PID 参数、转向闭环参数等通过 Flash 存储接口保存，支持不重新编译即可修改并保留实车整定结果，大幅提升调试效率。
辅助工具：卷尺（标定行驶距离与轨迹精度）、万用表（电路电压检测）、示波器（电源纹波与 PWM 波形测试）、秒表（计时测速）。

5.2 机械结构调试
机械调试是整车调试的基础，重点验证转向机构、传动系统与编码器安装的可靠性。
5.2.1 转向机构标定：
手动转动方向盘，测量左右最大转角，确认转向行程对称且无卡滞；
安装转向舵机（或转向电机 + 绝对编码器）后，标定中位 PWM 值与左右极限位置，记录转向角度与编码器计数的对应关系；
调整转向连杆长度，使左右最大转角基本对称，偏差控制在 2° 以内；
5.2.2 编码器安装校验：
缓慢推动车辆直线行驶 5m，记录左右轮编码器脉冲变化，计算脉冲当量（每脉冲对应行驶距离）；
左右轮分别标定，消除轮胎直径差异与安装误差，确保两轮里程计读数偏差≤3%；
检查齿轮啮合间隙（0.1mm 以内）与联轴器同轴度，确认行驶中无丢步或异响。
5.2.3传动与制动检查：
通电测试电机正反转，确认左右轮转向正确、转速匹配；
测试制动系统响应，确认急停按钮可在 0.5s 内使车辆完全停止；
检查所有紧固件防松处理，确保连续行驶后无松动。

5.3 IMU 姿态校准
车辆静止放置于水平地面，采集陀螺仪零偏数据，计算并写入零偏补偿值；
缓慢旋转车辆 360°，验证航向角输出连续无跳变，±180° 边界处理正确；
测试航向角静态漂移，确认≤3°/ 分钟，

5.4 视觉目标识别调试
视觉识别是科目三第一阶段跟随行驶的核心，调试重点在于提升不同光照与背景下的识别鲁棒性。
5.4.1 摄像头参数调整：
调整摄像头曝光时间与增益，适应室外不同光照条件（晴天、阴天、逆光）；
标定图像中心与车辆中轴线的对应关系，确保视觉偏差零点准确；
调整摄像头俯仰角，使目标标识在 2~10m 距离内均能完整成像。
5.4.2 转向闭环标定：
给定不同目标转角，测量实际前轮转角，绘制目标 - 实际曲线；
整定转向位置闭环 PID 参数，使阶跃响应超调≤10%、稳态误差≤1°、调节时间≤0.3s。
5.4.3 识别阈值调试：
在 CPU2 副屏上实时显示灰度图与识别叠加框，观察目标（引导员身上的十字标识）的成像效果；
调整自适应对比度阈值与锁定 / 保持得分阈值，使目标在晴天强光、阴天漫射光、逆光等不同条件下均能稳定识别；
测试背景干扰（锥桶、草地纹理、远处行人），通过外框边缘响应、对称性、宽高比约束排除误识别。
5.4.4跟踪稳定性调试：
调试 "锁定 — 保持 — 丢失" 状态机的切换条件，平衡响应速度与抗干扰能力；
调整自适应前视预测的速度估计限幅与低通系数，使目标快速横向移动时跟踪不丢失；
设置候选跳变物理上限与信任半径，拒绝异常帧，避免转向突然抖动。
5.4.5 横向偏差处理调试：
调试 S 形映射的中心低增益 / 边缘高增益参数，使小偏差时转向平稳、大偏差时响应迅速；
调整中值滤波窗口与动态融合权重，抑制脉冲噪声同时保证响应速度；
5.5 航迹记录与纯追踪调试
5.5.1航迹推算精度调试：
车辆直线行驶已知距离（如 10m），对比推算坐标与实际距离，校准编码器脉冲当量；
车辆沿矩形路径行驶一圈回到起点，检查推算坐标的闭合误差，评估航向漂移与里程计精度；
调整轨迹点记录距离阈值（约 2cm / 点），平衡轨迹精度与存储容量。
 5.5.2纯追踪参数调试：
调试前视距离：直线段采用较大前视（120~140cm）减小舵机频繁修正，弯道采用较小前视（90~100cm）提高跟随精度；
调试曲率估计窗口与速度衰减系数，实现 "直线高速、弯道低速" 的自适应速度规划；
测试不同速度下的路径跟随效果，逐步提升返回速度，确认无冲出路径或振荡现象。
5.5.3反向返回逻辑调试：
验证记录结束→刹车延时（约 400ms）→反向启动的时序，确保车辆停稳后再换向；
调试倒车软启动参数（前 150ms 限制加速度），避免倒车冲击；
验证到达起点后的停车逻辑，确认终点精度≤15cm。

5.6 系统联调
各模块单独验证通过后，进行系统级联调，重点验证多模块协同工作的稳定性。
视觉跟随 + 惯导记录联调：

KEY2 进入视觉跟随模式，同时启动惯导记录，车辆跟随引导员直线行驶，验证转向跟随与轨迹记录同步正常；
测试 S 形路径跟随，确认视觉转向响应及时，轨迹点记录连续无遗漏；
通过 IPS 屏实时观察 final_mid_line 与坐标更新，确认两系统数据一致。

记录→返回全流程联调：

完整执行 "KEY2 开始记录→跟随行驶→KEY8 结束记录→刹车延时→纯追踪反向返回→到达起点停车" 全流程；
对比返回轨迹与原始轨迹的重合度，逐步优化纯追踪参数；
测试中途急停遥控安全通道（SBUS 通道 1强制停车）的中断恢复逻辑。

5.7 调试总结
经过为期数月的分阶段调试，本车各子系统功能均达到设计指标：视觉跟随可在室外复杂光照下稳定识别并跟踪引导员，横向偏差控制在 ±5cm 以内；惯导航迹记录与纯追踪返回在 30m 迷宫路径下终点精度≤15cm；语音交互识别准确率≥90%，可正确执行灯光、鸣笛与运动指令；底盘控制平顺稳定。
调试过程中，模块化设计与 Flash 参数存储机制大幅提升了调试效率，使团队能够快速迭代优化控制参数；多模式安全互锁设计保证了载人调试过程的安全性。最终整车在竞赛速度下可稳定完成全部科目任务，达到预期设计目标。

第七章 总结
本技术报告完整阐述了第二十一届全国大学生智能汽车竞赛卡丁快跑组参赛作品的全系统设计方案。团队基于载人卡丁车平台，通过机械结构合理改装、硬件电路模块化设计与 "视觉跟随 + 纯惯导航迹复现" 核心算法开发，实现了室外场景下的人员自主跟随、路径记忆与自动返回、语音人机交互等核心功能，全面覆盖竞赛科目要求。
本次设计的核心创新与技术特点包括：
视觉人跟随算法：基于全局快门摄像头的目标识别与横向偏差直接控制，实现了对引导员的实时、鲁棒跟踪，适配室外复杂光照环境；

安全冗余设计：遥控通道紧急停车、硬件过流保护、软件急停等多重保护机制，确保行驶安全。
本次设计在工程实践中验证了纯惯导方案在室外路径复现场景下的可行性，视觉跟随方案在载人低速车辆上的实用性。系统在调试便捷性与环境适应性方面做了充分优化，具备较强的工程实用价值。
后续可进一步优化的方向包括：引入 ESKF（误差状态卡尔曼滤波）融合 IMU 与编码器数据，进一步抑制惯导累积误差；优化视觉识别算法，引入轻量级深度学习目标检测，提升复杂背景下的人员识别准确率；增加多传感器融合定位，提升长距离路径复现的精度。

float PID_Increase(PID *pid, float kp_value, float ki_value, float kd_value,
                   float now_data, float target)
{    pid->Error = target - now_data;
    pid->Out_P = pid->Error - pid->LastError;
    pid->Out_I = pid->Error;
    pid->D_new = pid->Error - 2.0f * pid->LastError + pid->PrevError;
    pid->Out_D = 0.3f * pid->D_new + 0.7f * pid->D_last;
    pid->D_last = pid->Out_D;      // 保存滤波后的微分值
    pid->PrevError = pid->LastError;// 更新前一次误差
    pid->LastError = pid->Error;    // 更新上一次误差
    return kp_value * pid->Out_P + ki_value * pid->Out_I + kd_value * pid->Out_D;
}
float PID_Normal(PID *pid, float now_data, float target)
{
    pid->Error = target - now_data;
    pid->Out_P = pid->Error;
    pid->Out_I += pid->Error;
    pid->Out_D = pid->Error - pid->LastError;
    pid->LastError = pid->Error;
    return (pid->Kp * pid->Out_P +
            pid->Ki * pid->Out_I +
            pid->Kd * pid->Out_D);
}

void Motor_Init(void)
{
    gpio_init(MotorL_turn, GPO, 0, GPO_PUSH_PULL);
    gpio_init(MotorR_turn, GPO, 0, GPO_PUSH_PULL);
    pwm_init(MotorL_pwm,5000,0);
    pwm_init(MotorR_pwm,5000,0);
}
void MotorR_SetSpeed(int pwm)
{
    if(pwm >= 0)
    {
        gpio_set_level(MotorR_turn,1);
        pwm_set_duty(MotorR_pwm,pwm);
    }
    else
    {
        gpio_set_level(MotorR_turn,0);
        pwm_set_duty(MotorR_pwm,abs(pwm));
    }
}

void Motor_Control(int Speed_L, int Speed_R)
{
    motor_l.target_speed = (wheel_peri / encoder_wheel_peri) * (Speed_L * 200);
    motor_r.target_speed = (wheel_peri / encoder_wheel_peri) * (Speed_R * 200);

    if(Speed_L > 0 && Speed_R > 0)
    {
        motor_l.duty = Limit_int(0, motor_l.duty + PID_Increase(&motor_pid_l,motor_l_KP,motor_l_KI,motor_l_KD,(float)motor_l.encoder_speed_cm, (float)motor_l.target_speed),10000);
        motor_r.duty = Limit_int(0, motor_r.duty + PID_Increase(&motor_pid_r,motor_r_KP,motor_r_KI,motor_r_KD, (float)motor_r.encoder_speed_cm, (float)motor_r.target_speed),10000);
    }
    else if(Speed_L <= 0 && Speed_R <= 0)
    {
        motor_l.duty = Limit_int(-10000, motor_l.duty + PID_Increase(&motor_pid_l,motor_l_KP,motor_l_KI,motor_l_KD,(float)motor_l.encoder_speed_cm, (float)motor_l.target_speed),3000);
        motor_r.duty = Limit_int(-10000, motor_r.duty + PID_Increase(&motor_pid_r,motor_r_KP,motor_r_KI,motor_r_KD, (float)motor_r.encoder_speed_cm, (float)motor_r.target_speed),3000);
    }
    MotorL_SetSpeed(motor_l.duty);
    MotorR_SetSpeed(motor_r.duty);
}

            audio_frame_status = 1;
        }
        while(websocket_client_receive(websocket_receive_buffer,
                                       sizeof(websocket_receive_buffer), 50))
        {
            audio_process_response(websocket_receive_buffer);
        }
        if(fifo_used(&adc_data_fifo) >= ASR_AUDIO_CHUNK_SAMPLES)
        {
            audio_send_data_flag = 1;
        }
    }

    if(audio_need_net_flag)
    {
        audio_send_data_flag = 0;
        pit_disable(ASR_PIT);
        do
        {
            uint8 status = (audio_frame_status == 0) ? 0 : 1;
            if(!audio_data_prepare(status)) break;
            if(!websocket_client_send((uint8_t*)json_data, strlen(json_data)))
            {
                pit_enable(ASR_PIT);
                audio_fail("FINAL AUDIO FAILED");
                return;
            }
            audio_frame_status = 1;
        }while(fifo_used(&adc_data_fifo) > 0);
        if(audio_frame_status == 0)
        {
            audio_data_prepare(0);
            if(!websocket_client_send((uint8_t*)json_data, strlen(json_data)))
            {
                pit_enable(ASR_PIT);
                audio_fail("FIRST FRAME FAILED");
                return;
            }
            audio_frame_status = 1;
        }
        audio_data_prepare(2);
        if(!websocket_client_send((uint8_t*)json_data, strlen(json_data)))
        {
            pit_enable(ASR_PIT);
            audio_fail("END FRAME FAILED");
            return;
        }
        bool final_received = false;
        for(uint8 i = 0; i < 8 && !final_received; i++)
        {
            if(websocket_client_receive(websocket_receive_buffer,
                                        sizeof(websocket_receive_buffer), 500))
            {
                audio_process_response(websocket_receive_buffer);
                final_received = audio_response_is_final(websocket_receive_buffer);
            }
        }
        printf("ASR result: %s\r\n", history_buffer);
        websocket_client_close();
        audio_reset_session(false);
        if(audio_result_has_words(history_buffer))
        {
            audio_subject_four = 1;
            ips200_show_string(0,16 * 8,"ASR OK          ");
        }
        else
        {
            /* A lone full stop is the server's no-speech result, not a task. */
            audio_subject_four = 0;
            ips200_show_string(0,16 * 8,
                               final_received ? "NO SPEECH-RETRY " : "ASR TIMEOUT     ");
        }	
        run_flag = 1;
    }
}
void Process_Short_Sentence(const char* sentence)
{
    int found_tasks[SPEECH_TASK_MAX_FOUND] = {0};
    int task_positions[SPEECH_TASK_MAX_FOUND] = {0};
    int found_count = 0;
    is_processing = true;
    task_flag = 0;
    if(sentence == NULL || sentence[0] == '\0')
    {
        printf("未收到有效语音文本，请重说\r\n");
        return;
    }
    for(int i = 0; i < SPEECH_TASK_KEYWORD_COUNT; i++)
    {
        const char *search_start = sentence;
        const char *pos;
        while((pos = strstr(search_start, speech_task_keywords[i].keyword)) != NULL)
        {
            int is_duplicate = 0;
            for(int j = 0; j < found_count; j++)
            {
                if(found_tasks[j] == speech_task_keywords[i].task_num)
                {
                    is_duplicate = 1;
                    if((int)(pos - sentence) < task_positions[j])
                        task_positions[j] = (int)(pos - sentence);
                    break;
                }
            }
            if(!is_duplicate && found_count < SPEECH_TASK_MAX_FOUND)
            {
                found_tasks[found_count] = speech_task_keywords[i].task_num;
                task_positions[found_count] = (int)(pos - sentence);
                found_count++;
            }
            /* Original code advances one byte so repeated commands are found. */
            search_start = pos + 1;
        }
    }
    /* Execute multiple commands in the same order as the spoken sentence. */
    for(int i = 0; i < found_count - 1; i++)
    {
        for(int j = i + 1; j < found_count; j++)
        {
            if(task_positions[i] > task_positions[j])
            {
                int temp_task = found_tasks[i];
                int temp_pos = task_positions[i];
                found_tasks[i] = found_tasks[j];
                task_positions[i] = task_positions[j];
                found_tasks[j] = temp_task;
                task_positions[j] = temp_pos;
            }
        }
    }
    if(found_count > 0)
    {
        printf("检测到%d个任务:\r\n", found_count);
        for(int i = 0; i < found_count; i++)
        {
            task_num = found_tasks[i];
            Process_Short_Sentence_Init(task_num);
        }
        memset(history_buffer, 0, sizeof(history_buffer));
        current_len = 0;
    }
    else
    {
        /* Never guess an action from meaningless text such as "嗯嗯嗯". */
        printf("未匹配到任务，请重说: %s\r\n", sentence);
        ips200_show_string(0, 16 * 9, "PLEASE RETRY    ");
    }
}
// 移除字符串中的中文逗号（全角）和英文逗号（半角）
void remove_commas(char* str) {
    char* src = str;
    char* dst = str;
    while (*src) {
        // 处理英文逗号（半角，ASCII码 0x2C）
        if (*src == ',') {
            src++;
            continue;
        }
        // 处理中文逗号（全角，UTF-8编码 0xE3 0x80 0x82）
        else if (*src == 0xE3 && *(src+1) == 0x80 && *(src+2) == 0x82) {
            src += 3;
            continue;
        }
        // 复制非逗号字符
        *dst++ = *src++;
    }
    *dst = '\0';  // 确保字符串终止
}
void append_history(const char* new_content) {
    char temp_content[256] = {0};
    strncpy(temp_content, new_content, sizeof(temp_content) - 1);  // 防止缓冲区溢出
    remove_commas(temp_content);  // 先移除新内容中的逗号

    int content_len = strlen(temp_content);
    if (current_len + content_len > MAX_TOTAL_LEN) {
        // 截断历史缓冲区（从头部移除溢出部分）
        int overflow = current_len + content_len - MAX_TOTAL_LEN;
        memmove(history_buffer, history_buffer + overflow, current_len - overflow);
        current_len = MAX_TOTAL_LEN;
    }
    // 追加处理后的内容
    strncat(history_buffer, temp_content, MAX_TOTAL_LEN - current_len);
    current_len = strlen(history_buffer);  // 更新当前长度（不含终止符）
    // 再次确保历史缓冲区中没有逗号（处理可能的截断残留）
    remove_commas(history_buffer);
}
