第二十一届全国大学生智能汽车竞赛

技 术 报 告

卡丁快跑组






摘 要
本文介绍了第二十一届全国大学生智能汽车竞赛卡丁快跑组智能车的设计与实现。车模基于卡丁车模平台，以英飞凌TC264为核心，采用imu660rc、总钻风进行环境感知，通过纯追踪、odom、PID等算法实现路径规划与自主导航。系统实现了赛道循迹、自动跟随、灯光展示等功能。在机械结构上，对转向系统和驱动系统进行了优化设计；在硬件上，自主设计了主控板、驱动板和LED灯光驱动板；在软件上，采用分层架构，实现了传感器数据融合、运动控制和任务调度。经场地测试，车模运行稳定，效果良好。
关键词：卡丁快跑；AURIX™；路径规划；自动跟随；TLD7002

第一章 引言
1.1 卡丁快跑赛题介绍
卡丁快跑是第二十一届全国大学生智能汽车竞赛首次引入的大型车模组别，打破了前二十届均使用小型模型车的传统。参赛车模采用科宇厂商提供的卡丁车模，国赛任务将原本的科目三和科目二（灯光和鸣笛部分）合并为赛题。
1.2 技术方案概述
本系统以TC264微控制器为核心，通过正交编码器和imu660rc传感器采集赛道信息，采用纯追踪控制算法实现车模的自主行驶。系统主要由机械结构、硬件电路和软件算法三部分组成。
1.3 章节安排
本文结构安排如下：第二章介绍机械结构设计；第三章介绍硬件电路设计；第四章介绍软件算法设计；第五章介绍系统调试与测试；第六章进行总结与展望。

第四章 软件算法设计
4.1 系统软件架构
系统软件采用分层架构设计，自上而下分为应用层、算法层、驱动层和底层硬件抽象层。系统由视觉处理控制器和车辆运动控制器组成：视觉处理控制器负责摄像头采集、目标识别及结果发送，车辆运动控制器负责融合定位、路径跟踪、速度控制、转向控制和任务调度，两者通过串口交换目标位置与尺寸信息。
应用层负责比赛科目选择、运行状态管理、遥控与自动模式切换、轨迹录制和比赛策略执行；算法层负责里程计解算、路径生成、Pure Pursuit路径跟踪、左右轮差速、速度PID、转向PD及视觉目标跟随；驱动层负责摄像头、IMU、编码器、电机、显示屏、按键、串口和Flash等外设；底层硬件抽象层负责TC264D双核初始化、时钟配置、PIT周期中断、DMA及通信中断管理。
系统采用"主循环＋周期中断"的裸机软件结构。主循环执行状态机、路径规划和任务逻辑，20 ms周期中断完成编码器采样、里程计更新、速度PID计算及电机PWM输出，以保证控制周期的稳定性和实时性。
4.2 视觉目标信息采集与处理
4.2.1 图像采集
视觉处理控制器采用总钻风黑白摄像头，分辨率为188×120像素，设置帧率为60 fps。图像通过DMA传输至控制器内存，以降低采集过程中的CPU负担。摄像头主要用于跟随标记识别，不直接用于提取赛道中线。
4.2.2 图像处理
图像处理首先获取灰度值，再采用大津法（Otsu）计算自适应二值化阈值。系统对二值图像进行连通域搜索，筛选满足面积和尺寸要求的候选区域，并通过四边形轮廓、透视采样、编码校验和静区检查识别目标标记。
识别成功后，算法计算目标区域的中心坐标、宽度、高度和面积，并通过串口向车辆运动控制器发送识别状态及目标信息。车辆控制器根据目标横向偏差计算转向量，并根据目标面积估算距离、调整行驶速度。

          ↓

4.3 路径规划与导航算法
4.3.1 编码器与IMU融合定位
车辆采用左右轮增量式编码器和IMU进行融合定位。编码器测量一个控制周期内的左右轮位移，IMU提供车辆航向角，系统根据左右轮平均位移和航向变化，通过里程计模型实时计算车辆在全局坐标系中的二维位置。
设左右轮位移分别为ΔsL和ΔsR，则车辆中心位移为：
Δs＝（ΔsL＋ΔsR）/2
融合得到的车辆位置和航向角用于轨迹记录、路径进度判断、前瞻点搜索和自动循迹。
4.3.2 轨迹录制与路径生成
轨迹录制模式下，系统依据里程计位置按照设定距离间隔保存路径点，并将有效路径写入Flash。自动运行时，程序从Flash读取路径数据；对于固定比赛科目，则根据起点位置、航向角和赛题几何参数生成参考路径。
4.3.3 前瞻点搜索
系统首先根据车辆当前位置确定路径进度，再沿参考路径搜索满足动态前瞻距离的目标点。动态前瞻距离随速度变化，并限制在1.5～3.0 m范围内，从而兼顾低速跟踪精度和高速行驶稳定性。
4.4 速度控制策略
系统采用增量式PID算法对左右驱动轮转速进行独立闭环控制。编码器每20 ms反馈左右轮脉冲数，控制器计算目标速度与实际速度之间的偏差，并根据误差变化调整电机PWM占空比。
上层根据车辆中心目标速度和前轮目标转角，通过车辆运动学模型计算左右后轮目标速度。转弯时内外侧车轮采用不同目标速度以实现主动差速，随后左右轮分别进入速度PID闭环。本系统驱动电机采用单速度环控制，未设置电流内环。
增量式PID的计算公式为：
Δu(k)＝Kp[e(k)－e(k－1)]＋Ki·e(k)＋Kd[e(k)－2e(k－1)＋e(k－2)]
u(k)＝u(k－1)＋Δu(k)
左右轮PID参数分别设置为：左轮Kp＝1.3、Ki＝3.3、Kd＝0.1；右轮Kp＝1.1、Ki＝3.4、Kd＝0.1。为提高弯道稳定性，系统还根据目标转角进行平滑降速，最大转角时速度最多降低25%。
4.5 转向控制算法
系统采用Pure Pursuit（纯追踪）算法计算目标前轮转角。算法根据车辆速度确定动态前瞻距离，在参考路径上搜索前瞻点，并将前瞻点转换到车辆运动坐标系中。
设前瞻点在车辆运动坐标系中的坐标为（x，y），前瞻距离为Ld，车辆轴距为L，则路径曲率和目标前轮转角分别为：
κ＝2y/Ld²
δ＝arctan（Lκ）
本车轴距设置为0.60 m，目标前轮转角限制在±20°以内。由于转向机构存在机械非线性和左右不对称，系统通过实测标定表进行分段线性插值，将目标前轮转角转换为转向电机偏移角。
转向电机使用绝对值编码器反馈实际角度，并采用PD算法进行位置闭环控制。位置环参数设置为Kp＝180、Kd＝22，同时设置1.5°死区，以减少机械抖动和电机发热。

4.6.2 灯板控制实现原理
（1）硬件结构
点阵屏采用动态扫描方案：TLD7002芯片通过15路恒流LED输出控制点阵列数据；7个GPIO引脚（SR0~SR6）控制当前点亮哪一行；P20_9 (SYNC引脚) 接收EXTI中断触发扫描。
（2）软件分层架构
灯板控制软件采用三层架构：
应用层 (cpu0_main.c)：switch(voice_id) 根据语音ID选择显示图案；display_example1~4() 灯动画效果函数；dot_matrix_tld7002_show_int(a,b,c) 设置显示。
点阵屏驱动层 (zf_device_dot_matrix_screen.c)：dot_matrix_screen_scan() / dot_matrix_tld7002() 扫描函数；tld7002_ascii_font_5x7[][] 字库数据(5x7点阵)；字库索引 → 16路PWM占空比映射。
TLD7002芯片驱动层 (zf_device_tld7002.c)：tld7002_init() 芯片初始化+OTP配置；tld7002_set_duty() 写入16路占空比(UART发送)；tld7002_duty[16] 占空比缓存(0~10000)。
（3）动态扫描核心流程
扫描函数 dot_matrix_tld7002() 采用两阶段逐行扫描，通过 entry_num 计数器（0~13，共7行×2阶段）控制：
偶数阶段（entry_num%2 == 0）：准备数据阶段。关闭上一行GPIO → gpio_low(上一行SR引脚)；查表取出当前行的3个字符的5位列数据；映射到 tld7002_duty[0~14]（亮=亮度值，灭=0）；调用 tld7002_set_duty(1) 通过UART下发到芯片。
奇数阶段（entry_num%2 == 1）：点亮行阶段。打开当前行GPIO → gpio_high(当前行SR引脚)。等待TLD7002的PWM输出稳定后再点亮，避免鬼影。
（4）字库映射原理
字库 tld7002_ascii_font_5x7[索引][行号] 存储每个字符的7行×5列点阵。每个字符占用5列，3个字符拼接为15列，对应 tld7002_duty[0~14]。字库索引16~25对应数字 '0'~'9'（+16偏移）。

4.6.3 声音输出实现原理
（1）硬件方案
PWM输出引脚：P33_10 (GTM ATOM2_CH0) → 连接音频功放（如8002A）
PWM频率：64kHz（避开音频范围，减少噪声）
采样定时器：CCU61_CH1 PIT，周期 10μs（100kHz采样率）
功放SD脚：任意GPIO拉高使能
（2）两种声音模式
声音模块支持PCM语音播放和DDS鸣笛合成两种模式，鸣笛优先级更高。
DDS鸣笛合成（Voice_Horn）：Voice_Horn(duration_ms, freq_hz) 使用直接数字频率合成(DDS)产生方波。32位相位累加器，每ISR节拍累加 horn_phase_inc，相位最高位(bit31)作为方波输出开关。
频率计算：
isr_freq = 1,000,000 / VOICE_PLAY_PERIOD_US;  // 10μs → 100kHz
horn_phase_inc = (freq_hz * 2^32) / isr_freq; // 每拍相位增量
ISR中的鸣笛逻辑：
horn_phase += horn_phase_inc;
if (horn_phase & 0x80000000) 
    输出 HORN_DUTY_HIGH;  // 8000，响亮
else 
    输出 HORN_DUTY_LOW;   // 2000
horn_ticks_left--;        // 倒计时结束则停止
音频频率对照如表5所示：
PCM语音播放（Voice_Play）：Voice_Play(idx) 播放字库中的PCM采样数据，采用定点数上采样实现低采样率音频在高ISR频率下的平滑播放。
play_step = (DATA_SAMPLE_HZ × PERIOD_US × 2^FRAC_BITS) / 1,000,000
// 例：500Hz采样率，10μs周期 → step = 500×10×256/1e6 = 1.28
// play_ptr_frac 每次累加 step，整数部分作为样本索引
ISR播放逻辑：
idx = play_ptr_frac >> 8;                    // 取定点数整数部分
sample = voice_pool[play_base + idx];         // 取8bit PCM样本(0~255)
duty = sample × PWM_DUTY_MAX / 256;           // 映射到PWM占空比(0~10000)
pwm_set_duty(P33_10, duty);
play_ptr_frac += play_step;
注：当前 voice_pool 中仅有占位数据（16字节），实际使用时需要替换为完整的PCM音频数组。

4.7 自动跟随功能实现
自动跟随模式下，视觉处理控制器将目标状态、中心坐标、宽度和高度通过串口发送至车辆运动控制器。车辆控制器对目标中心位置和面积进行滤波，并根据标记面积与距离之间的标定关系估算目标距离。
系统根据目标中心相对图像中心的横向偏差计算目标转角，根据目标面积误差计算倒车速度。当目标偏差较大或接近图像边缘时自动降低速度；当目标进入停止距离后停车，并通过启停回差避免车辆在临界距离附近频繁启停。目标丢失或通信超时后，系统停止驱动输出并使转向逐步回中。

5.3 软件调试方法
系统软件采用"模块测试、分系统联调、整车调试"相结合的方法进行调试。首先对摄像头、IMU、编码器、电机、显示屏和串口等硬件驱动模块进行单独测试，确认各传感器数据读取正常，电机转向正确，串口通信稳定。
在算法调试阶段，利用IPS200显示屏实时显示编码器脉冲数、车辆航向角、电机PWM、目标速度、实际速度和转向角等关键参数。同时，通过串口将运行数据发送至上位机，利用VOFA+观察速度误差、PID输出、车辆位置和航向角变化曲线，为参数调整和故障定位提供依据。
速度控制调试时，先将车辆驱动轮架空，在较低目标速度下分别测试左右轮的转动方向和编码器反馈方向。确认反馈方向正确后，逐步调整比例、积分和微分系数，使电机转速能够快速跟随目标速度，同时避免出现明显的超调和持续振荡。完成单轮调试后，再进行左右轮同步和差速转向测试。
转向控制调试时，首先标定转向机构机械中位，并通过绝对值编码器测量不同转向电机角度对应的实际前轮转角。根据测量结果建立分段线性标定表，然后在低速条件下调整转向位置环的PD参数，减小转向超调、机械抖动和稳态误差。
路径跟踪算法调试采用由低速到高速、由简单路径到复杂路径的方式进行。首先在直线和缓弯路径上验证Pure Pursuit算法的转向方向、前瞻点搜索和车辆坐标变换是否正确，再逐步增加路径曲率和车辆速度。调试过程中重点观察车辆横向偏差、转向角变化和弯道稳定性，并根据实际效果调整动态前瞻距离、弯道降速比例和最大转向角。
图像处理模块通过显示原始图像、目标识别框、目标中心坐标和识别状态进行调试。分别在不同距离、角度和光照条件下采集图像，检查Otsu二值化、连通域搜索和目标编码校验结果。当目标短暂丢失时，系统进入保持或停止状态，以验证视觉通信超时和异常保护功能。
完成各模块测试后进行整车联调，依次验证遥控模式、轨迹录制模式、自动循迹模式和目标跟随模式。整车调试始终采用低速起步，并逐步提高目标速度。若出现异常，立即停止电机输出，根据显示屏和上位机记录的数据判断故障来源，修改参数或程序后重新进行测试。通过多轮重复试验，最终确定速度PID、转向PD、Pure Pursuit前瞻距离和弯道降速等控制参数。
5.4 场地测试数据
为验证视觉识别模块在不同环境下的稳定性，分别在不同目标距离、偏转角度和光照条件下进行测试。测试过程中记录目标识别是否成功、识别结果是否稳定、车辆是否能够根据目标横向偏差完成转向修正，以及目标丢失后是否能够安全停车。 
测试结果表明，在正常室内光照及有效跟随距离内，视觉模块能够稳定输出目标中心坐标和面积信息；车辆可根据目标偏差完成转向调整，并根据目标远近进行速度控制。当目标离开摄像头视场或识别结果连续丢失时，系统能够进入降速停车状态。
5.5 灯光与声音模块调试
灯光与声音模块的调试遵循"先硬件后软件、先单功能后联调"的原则。
（1）TLD7002硬件调试
首先验证TLD7002供电电压（6~10V）和UART2通信（2Mbps波特率）。通过示波器检测P02_0发送的PWM配置帧，确认TLD7002返回的响应帧格式正确。OTP配置阶段需确保校准参数正确写入，否则会导致LED电流异常。
常见问题排查：
点阵全不亮：检查VCC电压、UART2接线、OTP参数是否正确配置
显示乱码/鬼影：检查行选GPIO关断是否先于占空比设置，确保扫描时序正确
只有一列亮：检查 show_int(a,b,c) 中字库索引是否包含+16偏移
（2）动态扫描调试
在IPS200显示屏上实时显示当前扫描行号、entry_num 计数器和TLD7002占空比数组，验证14阶段扫描（7行×2阶段）顺序正确。通过逐行点亮测试确认7个行选GPIO和15列驱动对应关系无误。
（3）语音识别联调
使用串口助手监视语音模块TX输出，确认UART1（115200bps）正确接收voice_id。依次测试各语音指令对应的灯光图标和声音输出，验证switch分支映射正确。
（4）声音输出调试
用示波器检测P33_10引脚，确认64kHz PWM基波正常。播放不同频率的DDS鸣笛，验证相位累加器输出方波频率准确。PCM播放时需确认 play_step 计算正确，避免采样率转换导致的变调或失真。
常见问题排查：
声音无声：检查功放SD脚是否使能，用万用表测P33_10是否有64kHz PWM波形
鸣笛变调：检查 VOICE_PLAY_PERIOD_US 与采样率宏是否匹配，防止 play_step 溢出
语音ID不响应：检查UART1波特率是否匹配、接线是否反接

B.3 Pure Pursuit转向算法
float control_pure_pursuit_steering_rad(
    float target_x_motion_m, float target_y_motion_m,
    float drive_direction)
{
    float lookahead_sq = target_x_motion_m * target_x_motion_m +
                         target_y_motion_m * target_y_motion_m;
    float direction = (drive_direction < 0.0f) ? -1.0f : 1.0f;
    float curvature;
    if(lookahead_sq < 0.000001f) return 0.0f;
    curvature = 2.0f * target_y_motion_m / lookahead_sq;
    return control_clampf(
        atanf(direction * CONTROL_WHEELBASE_M * curvature),
        -CONTROL_MAX_STEER_RAD, CONTROL_MAX_STEER_RAD);
}
