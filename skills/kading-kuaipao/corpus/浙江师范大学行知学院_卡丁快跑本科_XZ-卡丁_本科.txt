 引言
1.1 引言
全国大学生智能汽车竞赛以“立足培养，重在参与，鼓励探索，追求卓越”为指导思想，涵盖了机械、模式识别、电子、电气、传感技术、计算机、自动化控制、人工智能等多方面知识，从一定程度上反映了当代大学生综合运用所学知识和探索创新的精神。该赛事由教育部高等教育司委托，教育部高等学校自动化专业教学指导分委员会主办的全国性、多学科交叉、趣味性、创新性赛事，旨在加强大学生实践与团队合作精神，促进高等教育改革。竞赛规则透明，评价客观标准，坚持公开、公平、公正的原则，从而保持了竞赛的健康、普及、持续的发展。
学校积极响应教育部关于加强大学生的实践、合作精神和创新能力的培养的号召，成立智能车队伍参加比赛。我们组队参加第二十一届全国大学生智能车竞赛卡丁快跑组别的比赛，并进行了积极认真的准备。卡丁快跑组别是本届竞赛极具挑战性的室外综合赛题组别，其比赛科目融合了自动驾驶、人机交互与智能跟随等多项技术任务。根据本届竞赛规则相关规定，卡丁快跑组别指定使用特定车模厂商提供的卡丁1车模，主控芯片限定为英飞凌TC2/3/4系列微控制器。我们在符合竞赛规则的范围内，对小车的机械结构进行了针对性改良，以适应室外复杂路况和多科目比赛需求。
技术方面，选用英飞凌TC264D微控制器作为核心控制单元，并从零开始设计了一套覆盖自动驾驶、语音交互与跟随控制三大核心模块的综合控制方案。
在人机交互科目中，车模需通过语音指令完成相应任务。我们选用英飞凌指定型号IM68A130A硅麦采集语音信号，通过单片机AD通道完成声音信号采集，并采用云端语音转文字AI模型或离线语音识别方案完成指令解析与动作响应。
在跟随穿越科目中，车模需在无固定引导线条件下跟随引导员完成迷宫，并自动记忆路径完成返程。我们利用机器视觉算法实现引导员识别与跟踪，通过在引导员衣物上张贴特定图案提升识别鲁棒性。
本技术报告详细记录了第二十一届杭电卡丁快跑一队智能车的开发历程，内容涉及机械硬件设计、TC264D单片机的应用学习、多传感器融合算法研究、机器视觉跟随与路径规划、语音信号采集与识别，以及车模机械结构参数的调整与优化。
1.2 整车结构设计
1.2.1 车辆布局
本车在结构设计上以高可靠性、易维护性为核心目标，针对卡丁快跑组别室外场地多变、高速冲击风险大的特点，采用快拆式结构与防撞式结构相结合的整体布局方案。
整车按功能划分为六大区域：
底盘及动力部分：位于车架底层，包括24V铅酸电池、后轮驱动电机（原装）、转向舵机（原装）及轮轴编码器安装座；
核心控制部分：位于车辆后部，包括母板（背板）与子板（TC264DA主板+DRV8701驱动+板+运放板）构成的快拆组合，通过铜柱抬高约15mm以避让底盘走线；
姿态传感部分：IMU963rb安装于底盘几何中心处，通过刚性支架固定，保证与车体坐标系的严格对齐；
测速与反馈部分：左右后轮各安装一枚1024线正交编码器，转向管柱安装360度角度位置编码器一枚；
人机交互与通讯部分：硅麦IM68A130A模块与TLD7002 LED灯板安装于车后部；WiFi16B21无线模块及无线遥控模块同样布置于车架后部；
显示与调试部分：IPS屏安装于车架的后部上方，用于实时显示惯导位姿、车速、电池电量等关键状态参数。
视觉部分：总钻风MT9V034摄像头支架的安装在车辆尾部，方便跟随。
1.2.2 控制简述
针对卡丁快跑组别三个科目任务特征差异显著的特点，本系统完全依靠纯惯性导航作为定位与路径规划的核心手段。霍尔传感器获取实时轮速，陀螺仪获取当前航向角，两者结合构成航位推算系统，连续记录行驶路径并实时推算车模位姿。在此基础上，通过上位机UI界面与软件状态机实现三科目策略调度，针对长直道、锥桶绕行、掉头等不同区域运用差异化的分区开环控速与变参数PID控制——特定区域采用开环前馈快速降速以提升响应，方向环PID参数则根据区域特征分别整定，确保小车在直道高速平稳、锥桶区精确贴绕、掉头区灵活转向，实现全赛道丝滑通过。
在科目三跟随穿越中，国赛要求使用机械视觉跟随，因此引入视觉模块进行引导员识别与跟踪。通过摄像头采集前方图像，利用颜色特征或特定图案检测算法锁定引导员方位，输出相对车体的偏移角度与距离信息，与惯导位姿进行融合，引导车辆跟随引导员穿越迷宫路径，同时惯导系统全程记录行驶轨迹，用于返程时的路径复刻。视觉与惯导的协同，既保证了跟随过程中的实时响应能力，又为返程无引导自动归位提供了可靠的位置基准，实现全科目的闭环控制。
第二章 机械设计与修改
2.1 机械设计与修改

本车机械结构设计以高可靠性、易维护性、动态稳定性为核心目标，充分考虑卡丁快跑组别车模自重大、速度快、室外工况复杂的特点。T型卡丁车车模作为本届竞赛指定平台，整车轴距、轮距及原装驱动电机、转向舵机均保持原厂配置不变，仅针对传感器加装、板卡固定与防护需求进行功能性改造。整体布局遵循快拆式结构与防水防护相结合的设计原则，确保赛场突发故障时可快速维修，同时有效抵御室外雨天环境对电子设备的侵害。
2.2 车架主体与底盘布局
车模底盘采用原厂T型钢架结构，保持原有刚度与承重能力。在底盘布局上，遵循重心下移原则：24V铅酸电池固定于底盘几何中心偏后位置（最底层），降低整车质心高度，减小过弯侧倾力矩，提升高速弯道稳定性。驱动电机与转向舵机保持原装位置，后轮驱动电机防伪标签完整，传动链条未经改装。
2.3 3D打印防水箱设计
考虑到卡丁快跑比赛环境相对恶劣，可能经历雨天或积水路面，而常规防水措施难以完全保障板卡安全，本车在车辆尾部设计了一体化防水箱体，用于安置核心电子设备。该箱体采用3D打印技术制作，选用防水性能优异且耐温性好的PETG耗材，箱体设计特点如下：
全密封结构：箱体采用上下分体式设计，上盖与箱体之间通过嵌入式卡槽配合过盈挤压实现密封，无需额外涂抹防水胶，依靠3D打印的高精度尺寸控制保证卡槽配合面的贴合度，雨水无法从接缝处渗入；
散热设计：箱体顶部开设散热格栅并覆盖防水透气膜，兼顾散热与防水需求；
模块化布局：TC264DA主板、DRV8701驱动板等核心板卡集中安装于防水箱内部，与外界水汽和泥沙完全隔离；
快拆兼容：箱体上盖采用抽拉式结构，便于开盖检修，同时保留快拆子板结构的操作空间，核心板故障时无需拆卸整个箱体即可更换子板。
相较于涂覆三防漆或简单包裹的方式，3D打印一体化防水箱体通过结构自密封实现可靠防水，不依赖胶水等易老化失效的附加材料，维护便捷且防护寿命长，显著提升了整车在恶劣天气下的完赛率。
2.4 传感器安装设计
2.4.1 编码器改装支架
为获取车轮实时轮速作为惯导速度积分的主输入源，本车在左右后轮轴端各安装一枚1024线正交编码器。由于T型卡丁车车模原厂未预留编码器安装位置，本队设计了一体式编码器改装支架。支架中央设有与车体电机架同轴配合的紧固孔位，利用原电机架固定螺丝完成刚性连接，无需对原车进行破坏性改装。

2.4.2 摄像头改装支架

为满足科目三跟随穿越中引导员识别的视觉需求，本车将摄像头安装于车辆最后部中间位置。该位置视野开阔且远离前部转向振动源，有利于图像采集稳定。摄像头通过热熔胶与车体直接粘接固定，安装简便且不损伤车体结构，热熔胶固化后具备一定弹性，可缓冲行驶振动，保证摄像头与车体坐标系相对固定。安装后摄像头光轴与车体纵向中心线平行，为视觉引导算法提供准确的目标方位输入。
2.5 电路板硬件电路设计
全车共布置6块电路板，核心板卡集中安装于尾部3D打印防水箱内，所有自制电路板均在覆铜层标记“浙江师范大学行知学院”“XZ-卡丁”“2026参赛”等队伍信息。各板间通过排线与XT60或XT30电源接头连接，线束沿底盘走线并使用扎带分段约束，避免运动干涉或与转向机构摩擦。

3.2 单片机
微控制器是系统的核心组成部件，相当于系统的“大脑”，负责传感器数据采集、惯导解算、控制决策与驱动指令输出。本系统采用Infineon公司研发的TC264DA作为核心处理单元（实物图如图3-2所示）。该芯片在汽车电子与工业控制领域应用广泛，具有强大的运算能力与丰富的外设资源，完全满足卡丁快跑组别多传感器同步采集与实时控制的需求。
TC264DA采用双TriCore内核架构，主频200MHz，内部集成2.5MB Flash与752KB SRAM，为纯惯性导航解算中的高频姿态更新、四元数积分运算及路径规划算法提供了充足的算力裕度。芯片内部集成多通道12位SAR ADC，无需外部扩展即可满足硅麦语音信号、电池电压监测等多路模拟信号的同步采集需求；集成GTM（通用定时器模块） 与CCU6等丰富定时器资源，可独立生成多路高精度PWM波，用于电机调速与转向舵机控制；同时片内集成多通道DMA，可实现传感器数据在内存与外设间的高速传输，大幅减轻CPU的数据搬运负担，确保控制算法的实时性。
在环境适应性方面，TC264DA支持-40℃~125℃的宽温工作范围，足以应对卡丁快跑组别室外比赛可能面临的高温暴晒或低温等极端条件，保障系统长期稳定运行。TC264DA凭借其丰富的外设资源与计算能力，为纯惯性导航解算、变参数PID控制及多科目状态机调度提供了坚实的硬件基础，并留有充足裕度便于后续算法迭代升级。芯片硬件原理图如图3-3所示。

3.4 传感器模块
3.4.1 姿态传感器模块
姿态传感器是纯惯性导航方案的核心传感元件，负责实时测量车模的三轴角速度与三轴加速度，为航位推算提供基础数据。本系统选用IMU963ra六轴惯性测量单元（接口原理图如图3-8所示），安装于车模底盘几何中心位置，通过刚性支架与车体固定，确保传感器坐标系与车体坐标系严格对齐，减小角运动与线运动耦合带来的测量误差。
IMU963ra与主控芯片TC264DA之间通过SPI总线连接，采用高速数据传输模式，采样率设定为500Hz，以满足卡丁快跑组别高速行驶状态下对姿态更新的实时性要求。在电源设计方面，IMU963ra由独立的低纹波LDO供电，以减小电机驱动电路和开关电源引入的高频噪声干扰，保证加速度计和陀螺仪输出信号的纯净度。电路设计中，SPI总线的时钟线（SCK）、数据输入输出线（MOSI/MISO）及片选线（CS）均串联小阻值电阻进行阻抗匹配，减小信号反射与过冲，提升高速通信的可靠性。

3.4.2 视觉模块
为实现科目三跟随穿越中引导员识别与跟踪的图像信息采集，本系统选用凌瞳彩色摄像头作为视觉传感器（实物如图3-9所示）。该摄像头内置ISP（图像信号处理器）单元，可直接输出RGB565格式全彩图像，分辨率最高可达VGA（480×640），在标准模式下色彩还原准确，且支持切换到鲜艳模式以增强色彩饱和度，便于颜色识别与目标特征检测。凌瞳传感器在低光照条件下表现同样出色，即便在缺乏补光的昏暗环境中也能捕捉清晰、细节丰富的图像，噪点控制水平在同类产品中处于领先地位。
凌瞳摄像头通过DVP接口与TC264DA微控制器通信，传输图像数据及行/场同步信号。在设计过程中，为防止出现图像数据丢帧、噪点增多甚至通信失败等问题，需对PCB布线进行严格控制以保证信号完整性：DVP接口的高速信号线（如PCLK、HSYNC、VSYNC等）控制单端阻抗在50Ω±10%范围内，各组信号线长度偏差不超过50mil，以减小信号传输延迟差异；电源走线采用20mil以上线宽，确保供电充足。摄像头与单片机连接原理图如图3-10所示。
在电源设计上，凌瞳摄像头对供电稳定性极为敏感，与其他电路共用电源易导致初始化异常或图像出现噪点白斑等故障。因此，本系统为摄像头采用独立3.3V LDO电源供电，与主控芯片及其他外设的电源隔离，确保供电纹波满足传感器要求。安装时，摄像头固定于车辆最后部中间位置（通过热熔胶与车体粘接固定），光轴与车体纵向中心线平行，保证图像坐标与车体坐标系一致，为视觉引导算法提供准确的目标方位输入。

3.4.4 角度编码器
为实现转向舵机的闭环控制与方向盘转角的精确测量，本系统在转向管柱处安装一枚逐飞科技360度角度位置编码器（实物如图3-13所示）。该角度编码器基于磁感应原理，可提供360度全范围绝对角度输出，与增量式编码器不同，其输出为绝对角度值而非脉冲计数，无需上电归零即可获取当前方向盘绝对转角，为转向闭环控制提供了稳定可靠的位置反馈。

3.7 DRV8701驱动电路设计
3.7.1 DRV8701双驱电路设计
为驱动后轮原车电机实现差速转向控制，本系统设计了两路独立的DRV8701栅极驱动电路，分别控制左右后轮电机（原理图如图3-23所示）。每路DRV8701驱动一颗原车电机，通过PWM+DIR控制方式实现转速与方向的独立调节。双驱电路板集成两路完整的驱动通道，采用24V铅酸电池直接供电。
左/右电机驱动电路
DRV8701是一款单路H桥栅极驱动器，通过驱动4个外部N沟道MOSFET实现大电流电机控制，适用于12V至24V有刷直流电机驱动场景。芯片支持5.9V至45V宽电压输入，栅极驱动电流可通过IDRIVE引脚上的单个外部电阻配置，提供更高的驱动灵活性。DRV8701集成硬件死区时间，可有效防止同桥臂上下管同时导通导致短路。在控制接口方面，本系统采用PWM+DIR控制方式：一路PWM信号控制电机转速，一路DIR电平控制转向方向，接口简洁易于软件实现。
电源接口与缓冲电路
驱动板通过XT30电源接口接入24V铅酸电池。VM与GND之间并联缓冲电路——由大容量电解电容（≥100μF）与高频陶瓷电容（0.1μF）组成，用于吸收电机启停和换向时产生的反电动势尖峰，平抑母线电压波动，防止电压尖峰击穿MOSFET或干扰芯片工作。VCP引脚通过1μF/16V陶瓷电容连接VM，CPH与CPL之间连接0.1μF X7R电容构成电荷泵，为高侧MOSFET提供高于VM的栅极驱动电压。
使能开关与信号接口
每路驱动电路均设有使能开关接口，通过EN引脚控制驱动芯片的使能与关断。当EN引脚拉低时，芯片进入低功耗待机模式，输出级全部关断，便于系统调试与故障隔离。信号接口为6Pin排针，包括PWM输入、DIR方向控制、nFAULT故障输出、SO电流检测输出、EN使能及GND。PWM信号由TC264DA的GTM/CCU6模块生成，经隔离电路接入DRV8701。nFAULT为开漏输出，通过10kΩ上拉电阻接3.3V，正常工作时为高电平，发生欠压、过流或过热故障时输出低电平至MCU。SO引脚输出与负载电流成正比的模拟电压，可接入MCU的ADC实现电流实时监测。
电流检测与保护
DRV8701内置低侧分流放大器，SP与SN引脚跨接检流电阻（典型值10mΩ），放大器增益AV固定为20V/V，SO引脚输出与负载电流成正比的模拟电压。VREF引脚外接电阻分压网络设定斩波电流阈值，当检流电阻两端电压达到阈值时触发固定关断时间的电流斩波，实现逐周期限流，有效保护MOSFET和电机免受过流损坏。芯片集成欠压锁定、过流保护、过热保护等多重保护机制，保障系统长期运行可靠性。

3.8 运放电路设计
为满足科目二鸣笛任务的音频信号放大需求，本系统设计了一路运放放大电路（原理图如图3-25所示）。鸣笛信号源为车载喇叭或蜂鸣器输出的音频信号，经运放电路放大后由MCU的ADC采集，用于检测鸣笛动作是否执行到位，或驱动喇叭发声以完成比赛要求的鸣笛响应。
电路采用单电源供电方案，VCC与VEE分别为正负供电轨，经电源接口P1和P2接入。输入耦合电容C1（22μF）与C2（22μF）分别用于隔离输入信号中的直流偏置分量，仅允许交流音频信号通过。R1与R2（1MΩ）为输入下拉电阻，用于为运放输入端提供直流偏置通路，防止输入悬空导致输出漂移。输出端配置了由R13和R14（3.6Ω）、C13/C14（220nF）、C15/C8（220μF）及C10/C11/C12/C16（100nF）组成的外部滤波与阻抗匹配网络，用于滤除高频噪声并匹配后级负载阻抗，确保音频信号传输质量。电源引脚旁放置100nF陶瓷电容进行高频去耦，滤除电源纹波对音频信号的干扰。
放大后的音频信号接入TC264DA的ADC通道，实现鸣笛音量检测与频谱分析。软件通过对ADC采样值进行幅值判断，可识别鸣笛动作是否完成，配合状态机调度确保科目二鸣笛任务的可靠执行。

系统软件设计
4.1 软件控制总体思路
科目一（自动驾驶） ：以纯惯性导航为核心定位手段。系统上电后首先完成IMU静态零偏校准，建立导航初始坐标系。行驶过程中，TC264DA以500Hz采样率读取IMU963ra的三轴角速度与加速度数据，经四元数姿态更新算法实时推算车模航向角，并结合1024增量式编码器测得的轮速进行航位推算，连续计算车模相对于起点的实时位姿。路径规划层面，根据锥桶绕行与倒车入库的预设路径点序列，结合惯导实时位姿生成期望轨迹。控制执行层面，采用分区变参数PID控制策略——通过惯导位姿判断当前所处区域（长直道/锥桶区/掉头区），动态切换PID参数组，确保直道高速稳定、弯道精确绕行、掉头灵活转向，三者协同完成自动驾驶科目。
科目二（人机交互） ：以语音识别为核心任务，包含鸣笛与语音指令响应两个环节。鸣笛任务由运放电路采集车载喇叭音频信号，经ADC送入MCU进行幅值检测与频谱分析，通过判断鸣笛信号的频率特征与持续时间，确认鸣笛动作是否执行到位。语音指令环节则采用“本地采集+云端识别”的流程：硅麦IM68A130A拾取参赛队员发出的语音指令，经运放板放大滤波后由ADC采集，音频数据通过WiFi16B21无线模块经SPI总线上传至云端AI语音识别模型，识别结果返回后由状态机解析并执行对应的灯光或车模动作（如前进、后退、停止等）。整个语音交互过程通过按键触发启动与结束，避免比赛过程中的误触发。
科目三（跟随穿越） ：采用机器视觉跟随+惯性导航返程的协同方案。去程跟随阶段，凌瞳彩色摄像头实时采集前方图像，通过颜色特征或特定图案检测算法锁定引导员目标，输出目标相对车体的偏移角度与距离信息。视觉信息与惯导位姿进行融合，引导车辆跟随引导员穿越迷宫路径；与此同时，惯导系统全程记录行驶轨迹（位置序列与航向角序列）。抵达终点后，系统切换至返程复刻模式——将去程记录的路径点序列反向执行，完全依靠惯导位姿推算沿原路返回起点，无需视觉引导。视觉负责跟随阶段的实时目标追踪，惯导既负责跟随阶段的位姿基准又承担返程阶段的自主导航，二者协同配合实现完整闭环。

4.3 机器视觉跟随算法
科目三去程跟随阶段，本系统采用凌瞳彩色摄像头采集前方图像，通过识别与跟踪黄色引导目标实现车模对引导员的实时跟随。黄色目标为引导员衣物上张贴的特定颜色标识，在室外环境中具有良好的色彩区分度。算法流程分为RGB565转HSV、HSV颜色距离计算、种子点搜索、十字扩张与腐蚀迭代四个步骤。
摄像头输出RGB565格式的彩色图像，首先将其转换为HSV颜色空间。转换时，将RGB565的5-6-5位分布还原为8位RGB分量，再通过标准变换公式计算色调H、饱和度S与明度V分量，其中色调H分量与光照强度无关，能够有效降低室外光照变化对颜色识别的影响。转换完成后，预先标定引导目标在HSV空间的标准值 ，逐像素计算与目标色的加权欧氏距离：

其中为各通道的权重系数，色调H赋予最高权重。计算得到的距离值 D(u,v)越小，表示该像素颜色与目标黄色越接近；将距离值映射为0~255范围的灰度图，距离越近灰度越低（越亮），形成反映颜色相似度的灰度数据。
在生成的灰度图上进行亮点搜索，选取灰度值最低（即与目标色最接近）的若干像素点作为种子点，代表目标区域的候选中心，去除孤立噪点导致的伪种子。以每个种子点为起始，采用十字扩张算法进行区域生长：从种子点出发，沿水平与垂直两个方向分别向外扩展，逐像素判断扩展点是否满足灰度阈值条件，将符合条件的相邻像素纳入目标区域。扩张后的区域通过形态学腐蚀处理，去除孤立的毛刺和噪声点，保留连通性良好的主体区域；腐蚀后的结果作为下一次扩张的起始区域，重复上述步骤进行迭代。当相邻两次迭代中区域质心位移小于设定阈值时判定收敛，输出最终的目标区域质心坐标 ，即为黄色引导目标在图像平面中的中心位置。得到中心坐标后，计算相对于图像中心 的水平偏差 与垂直偏差 ，水平偏差直接作为转向PID控制器的输入，引导车模朝目标方向行驶。通过上述算法流程，视觉跟随系统可在室外环境下稳定锁定黄色引导目标，实现平稳跟随。
4.4 PID控制算法
在工程实际中，应用最为广泛的调节器控制规律为比例、积分、微分控制，简称PID控制。PID控制器以其结构简单、稳定性好、工作可靠、调整方便而成为工业控制的主要技术之一。当被控对象的结构和参数不能完全掌握，或得不到精确的数学模型时，系统控制器的结构和参数必须依靠经验和现场调试来确定，此时应用PID控制技术最为方便。本系统在方向环与速度环控制中均采用数字PID控制器，根据卡丁快跑组别三个科目的不同任务特征，动态调用差异化的PID控制策略。

PID控制器各校正环节的作用如下：比例环节及时成比例地反映控制系统的偏差信号，偏差一旦产生，控制器立即产生控制作用以减少偏差；积分环节主要用于消除静差，提高系统的无差度；微分环节能反映偏差信号的变化趋势（变化速率），并在偏差信号变得太大之前在系统中引入有效的早期修正信号，从而加快系统的动作速度，减小调节时间。
在卡丁快跑组别的实际应用中，PID控制器的输入偏差因科目而异。科目一自动驾驶阶段，方向环PID以惯导推算的航向角与期望航向角之间的偏差为输入；科目三跟随阶段，方向环PID则以视觉算法输出的目标水平偏差 Δu 为输入（即图像平面中引导目标偏离图像中心的像素距离）。速度环PID在三个科目中均以期望速度与编码器实测速度的偏差为输入，但目标速度值根据科目不同分别设定——科目一依据赛道区域（直道/弯道/掉头）动态调整，科目二保持在极低速待命状态，科目三跟随阶段根据目标垂直偏差 Δv 自适应调节。
针对赛道不同区域的控制需求，方向环PID采用分区变参数策略。在自动驾驶科目中，通过惯导位姿判断当前所处区域并动态切换PID参数组：长直道区域使用较小的比例系数（KP​=0.6）与微分系数（KD​=0.1），保证高速行驶时的航向稳定性；锥桶绕行区域增大比例系数（KP​=1.5）与微分系数（KD​=0.6），提高转向响应灵敏度；掉头区域进一步增大幅度项（KP​=2.5），强制航向快速跟随以实现小半径转弯。参数切换时通过线性插值进行平滑过渡，避免突变引起的方向抖动。此外，系统在特定区域配合开环速度前馈实现快速降速，使PID控制器始终工作在其最佳调节范围内，确保全赛道“直道稳、弯道灵、掉头快”的运动特性。
4.4.1 位置式PID控制算法
位置式PID是数字PID控制中最基本的形式，控制器的输出直接对应于执行机构的位置（如舵机角度或电机占空比）。其控制规律表达式如下：

在本系统中，位置式PID分别应用于方向环与速度环。方向环偏差 e(k) 在科目一中为期望航向角与实际航向角之差，在科目三中为视觉目标水平偏差 Δu，控制量直接输出转向舵机PWM占空比；速度环偏差 ，控制量输出驱动电机PWM占空比。各校正环节中，比例项及时响应当前偏差，积分项消除静差，微分项预测偏差变化趋势进行超前修正。
工程实现上，对积分项进行限幅以防止积分饱和，同时对输出进行限幅确保执行器安全。方向环与速度环的PID参数针对三个科目分别整定，并结合分区策略动态切换，保证不同工况下的最优控制效果。
4.4.2 增量式PID控制算法
增量式PID的输出为控制量的增量Δu(k)，而非绝对值，通过累加得到实际控制量 u(k)=u(k−1)+Δu(k)。其控制规律表达式如下：

其中 Δu(k) 为第 k 次输出的控制增量，e(k)、e(k−1)、e(k−2) 分别为当前、前一次和前两次的偏差值。比例项根据偏差变化量产生控制增量，积分项根据当前偏差消除静差，微分项根据偏差二阶差分进行超前预测。
在本系统中，增量式PID优先用于方向环控制，尤其在锥桶绕行和视觉跟随等需要连续平滑转向的场景。其输出直接作为舵机PWM增量，通过累加得到当前控制量。增量式PID在系统状态切换时控制量过渡平缓，能有效避免转向突变导致的车身晃动。工程实现上需对增量值进行限幅，防止单次增量过大导致动作剧烈，同时对累加输出进行绝对限幅确保执行器安全。方向环PID参数配合分区策略动态切换，通过增量式输出的平滑特性实现不同区域间的无缝过渡。
增量式PID具有以下优点：
(1)  由于计算机输出增量，所以误动作时影响小，必要时可用逻辑判断的方法关掉。
(2)  手动/自动切换时冲击小，便于实现无扰动切换。此外，当计算机发生故障时，由于输出通道或执行装置具有信号的锁存作用，故能保持原值。
(3)  算式中不需要累加。控制增量△u(k)的确定仅与最近k次的采样值有关，所以较容易通过加权处理而获得比较好的控制效果。
但增量式PID也有其不足之处：积分截断效应大，有静态误差；溢出的影响大。使用时，常选择带死区、积分分离等改进PID控制算法。
4.5 速度环控制
速度环是卡丁快跑控制系统的底层执行环节，直接决定了车模加减速的平顺性与路径跟踪的动态响应能力。本系统速度环以霍尔编码器实测轮速为反馈量，以期望速度为目标值，采用数字PID控制器实现闭环速度调节，配合分区开环前馈策略满足不同科目与路段的差异化速度需求。速度偏差为 e(k)=vtarget​−vactual​，其中 vtarget​ 由上层策略根据当前科目与路段动态设定，vactual​ 由左右后轮编码器轮速取平均获得。速度环与方向环构成串级控制结构——外环位置/航向环输出期望速度作为速度环给定值，内环速度环据此计算PWM占空比控制驱动电机，使速度环能够快速响应负载变化，将速度波动对上层路径跟踪的影响降至最低。速度环的PID参数 KP​、KI​、KD​ 在三个科目间差异化配置，以适应不同的速度控制需求。
速度目标值的设定策略因科目而异。科目一自动驾驶中，目标速度由惯导位姿判定的当前区域决定：长直道区域设置为最高速（如4m/s）以保证竞赛用时；锥桶绕行区域降速至3m/s以确保路径跟踪精度；掉头区域进一步降至2m/s以减小转弯半径。除分区定速外，系统还引入了开环速度前馈机制——当惯导检测到车辆即将进入特殊区域时，提前0.3~0.5秒向前馈通道输出预设的减速量，使电机在PID闭环调节之前先行响应，有效抑制纯闭环控制下入弯减速滞后的现象。科目二语音交互中，车模仅在识别到特定指令后执行短距离动作，速度目标设定为2m/s极低速，确保语音任务执行安全。科目三跟随穿越中，速度目标值采用视觉引导的自适应策略——根据引导目标在图像平面中的垂直偏差 Δv 动态调节：目标靠近图像上边缘（距离较远）时适当提速，靠近下边缘（距离过近）时减速保持安全间距，直至抵达终点停车。速度环输出经加速度限幅处理，避免急加急减影响车身稳定性，确保全赛道运行流畅。

5.2 调试过程说明
整个系统的完善主要依赖于现场软硬件联合调试。本系统针对卡丁快跑三个科目的不同任务特征，分别制定了差异化的调试流程与测试方案。
科目一调试：首先在静态条件下完成IMU零偏校准与初始对准测试，确认静态航向漂移率在可接受范围内。随后在校内模拟场地布设锥桶，以遥控方式采集路径点生成预设轨迹，逐步增加车速测试惯导自主绕行与倒车入库的路径跟踪精度。通过上位机无线监控软件实时观察惯导位姿、横向偏差与控制量输出，迭代整定各分区PID参数，确保直道段稳定、锥桶区贴绕、掉头区灵活。重点调试惯导漂移抑制策略的有效性——通过ZUPT与直航向约束测试验证单次运行周期内定位误差是否满足比赛要求。
科目二调试：首先测试运放板与硅麦的信号链路完整性，通过示波器观察放大后的音频信号波形，确认ADC采样幅值在合理范围内。随后针对鸣笛任务测试音频信号的幅值检测与频谱分析算法的可靠性，确保系统能准确识别鸣笛动作是否执行到位。语音识别环节则重点调试WiFi模块的联网稳定性与SPI通信可靠性，测试不同信噪比下的识别成功率与响应延迟，调整音频数据分段打包与重传策略以适应室外场地WiFi网络环境的变化。
科目三调试：首先标定摄像头安装位置与视角参数，在校内场地采集不同光照条件下的黄色目标图像，标定HSV阈值参数并验证颜色距离算法的鲁棒性。随后进行跟随测试，通过上位机观察目标偏差输出与舵机响应的延迟与超调，整定视觉跟随PID参数。最后进行路径记忆与复刻测试——引导员沿迷宫路径行走，车模视觉跟随的同时惯导记录轨迹，抵达终点后切换返程模式，验证惯导复刻路径与去程轨迹的重合度，针对复刻偏差调整路径点记录密度与插值策略。三科目分别调试完成后进行全流程联合测试，验证状态机在各科目间的切换逻辑与过渡衔接流畅性。

int core0_main(void)
{
    uint8 i;

    clock_init();
    debug_init();


    // ==================== IPS200初始化 ====================

    ips200_init(IPS200_TYPE_SPI);
    ips200_clear();
    ips200_full(RGB565_66CCFF);
    ips200_set_font(IPS200_8X16_FONT);
    ips200_set_color(RGB565_WHITE,RGB565_66CCFF);
    ips200_show_rgb565_image(0,169,(const uint16 *)gImage_1,240,151,240,151,0);


    // ==================== 基础外设初始化 ====================

    uart_receiver_init();

    LED_init();

    key_init_custom();

    throttle_brake_init();

    adc_init(
        ADC0_CH11_A11,
        ADC_12BIT);

    // GPS_init();

    motor_Init();

    steering_Init();

    steering_SetAngle(0.0f);

    motor_set_speed(0, 0);

    PidInit(&PID_Init);


    // ==================== IMU初始化 ====================

    if(imu963ra_init() != 0)
    {
        printf("IMU963RA init error!\r\n");

        motor_set_speed(0, 0);
        motor_set(0, 0);

        while(TRUE)
        {
        }
    }

    // 校准陀螺仪零漂
    gyroOffset_init();

    // 校准加速度计
    accOffset_init();

    // ==================== 导航初始化 ====================

    nav_init();

    // ==================== 语音本地模块初始化 ====================

    /*
     * 这里只初始化硅麦ADC、FIFO、按键和采样定时器。
     * 不会在开机时连接WiFi。
     *
     * WiFi仍然是在进入科目二语音页面时连接。
     */
    audio_init();

    // ==================== 点阵屏初始化 ====================

    dot_matrix_screen_init();


    // ==================== 周期中断初始化 ====================

    /*
     * 5ms：
     * IMU、导航、电机和转向控制。
     */
    pit_ms_init(CCU60_CH0,5);

    /*
     * 10ms：
     * 按键扫描、喇叭、麦克风预处理等。
     */
    pit_ms_init(CCU61_CH1,10);

    /*
     * 500ms：
     * 灯板闪烁控制。
     */
    pit_ms_init(CCU61_CH0,500);

    // 开机时关闭语音采样中断
    pit_disable(ASR_PIT);

    // 开机时关闭灯板闪烁中断
    pit_disable(CCU61_CH0);

    // 开机时关闭点阵屏同步中断
    exti_disable(
        DOT_MATRIX_SCREEN_SYNC_PIN);


    // ==================== 读取原有GPS Flash数据 ====================

    read_gps_data_from_flash(
        0,
        GPS_Flash_Dat);

    for(i = 0; i < GL_NUM_max; i++)
    {
        GPS_GET_LAT[i] =
            GPS_Flash_Dat[i].latitude;

        GPS_GET_LOT[i] =
            GPS_Flash_Dat[i].longitude;
    }


    // ==================== 菜单初始化 ====================

    ips200_clear();

    menu_init();


    // 开机提示音
    buzzer_once(1000);


    // ==================== 开启全局中断 ====================

    interrupt_global_enable(0);

    cpu_wait_event_ready();


    // ==================== 主循环 ====================

    while(TRUE)
    {
        int current_task;

        // ---------- 按键和菜单 ----------

        key_process();
        subject3_camera_poll();
        menu_refresh();

        // ---------- 科目二语音网络处理 ----------

        if(subject2_voice_irq_enabled)
        {
            audio_loop();
        }

        // ---------- 执行新的科目二任务 ----------

        if(subject2_voice_irq_enabled &&
           subject2_batch_collecting == 0 &&
           task_4_flag == 1 &&
           task_4_num_flag_ok == 0 &&
           task_4_num_flag < task_num)
        {
            current_task =
                task_4[task_4_num_flag];

            // 门洞导航任务
            // 门洞导航任务
            if(gate_task_is_code(current_task))
            {
                if(gate_task_start(current_task))
                {
                    task_4_num_flag_ok = 1;

                    ips200_set_font(IPS200_8X16_FONT);
                    ips200_set_color(
                        RGB565_BLACK,
                        RGB565_66CCFF);

                    ips200_show_string(
                        10,
                        96,
                        "GATE ROUTE RUNNING         ");

                    printf(
                        "GATE TASK RUN: index=%d code=%d total=%d\r\n",
                        task_4_num_flag,
                        current_task,
                        task_num);
                }
                else
                {
                    ips200_set_font(IPS200_8X16_FONT);
                    ips200_set_color(
                        RGB565_BLACK,
                        RGB565_66CCFF);

                    ips200_show_string(
                        10,
                        96,
                        "GATE START FAIL            ");

                    printf(
                        "GATE TASK FAIL: index=%d code=%d\r\n",
                        task_4_num_flag,
                        current_task);

                    task_4_num_flag++;
                    task_4_num_flag_ok = 0;
                }
            }
            // 动作区车辆任务
            else if(subject2_motion_is_code(current_task))
            {
                if(subject2_motion_start(current_task))
                {
                    task_4_num_flag_ok = 1;

                    ips200_set_font(IPS200_8X16_FONT);
                    ips200_set_color(
                        RGB565_BLACK,
                        RGB565_66CCFF);

                    ips200_show_string(
                        10,
                        96,
                        "MOTION RUNNING             ");

                    printf(
                        "MOTION START: index=%d code=%d total=%d\r\n",
                        task_4_num_flag,
                        current_task,
                        task_num);
                }
                else
                {
                    ips200_set_font(IPS200_8X16_FONT);
                    ips200_set_color(
                        RGB565_BLACK,
                        RGB565_66CCFF);

                    ips200_show_string(
                        10,
                        96,
                        "MOTION START FAIL          ");

                    task_4_num_flag++;
                    task_4_num_flag_ok = 0;
                }
            }
            // 灯板、照明灯、雨刮器和鸣笛任务
            else
            {
                tld7002_show();

                printf(
                    "TASK SHOW: index=%d code=%d total=%d\r\n",
                    task_4_num_flag,
                    current_task,
                    task_num);
            }
        }


        // ---------- 检查门洞导航是否结束 ----------

        /*
         * 放在subject2_voice_irq_enabled判断外面。
         *
         * 即使语音页面状态发生变化，
         * 也能检测导航结束并释放当前门洞任务。
         */
        if(gate_task_poll_finished())
        {
            if(task_4_flag == 1 &&
               task_4_num_flag < task_num)
            {
                task_4_num_flag++;
                task_4_num_flag_ok = 0;
            }

            ips200_set_font(IPS200_8X16_FONT);
            ips200_set_color(RGB565_BLACK,RGB565_66CCFF);
            ips200_show_string(10,96,"GATE ROUTE FINISH          ");


            printf("GATE ROUTE FINISHED\r\n");
        }

        // ---------- 检查动作区车辆任务是否完成 ----------

        if(subject2_motion_poll_finished())
        {
            if(task_4_flag == 1 &&
               task_4_num_flag < task_num &&
               subject2_motion_is_code(
                   task_4[task_4_num_flag]))
            {
                task_4_num_flag++;
                task_4_num_flag_ok = 0;
            }

            ips200_set_font(IPS200_8X16_FONT);
            ips200_set_color(
                RGB565_BLACK,
                RGB565_66CCFF);

            ips200_show_string(
                10,
                96,
                "MOTION FINISH              ");

            printf("MOTION FINISHED\r\n");
        }
        // ---------- 全部任务完成后的清理 ----------

        /*
         * 同样放在语音开关判断外面。
         * 防止门洞结束后task_4_flag未被清理。
         */
        if(task_4_flag == 1 &&
           task_4_num_flag >= task_num)
        {
            task_4_flag = 0;
            task_4_num_flag = 0;
            task_4_num_flag_ok = 0;
            // 停止灯板闪烁
            tld7002_blink_enable = 0;
            // 停止雨刮器
            wiper_enable = 0;
            // 停止喇叭
            buzzer_stop();
            // 恢复点阵屏显示
            dot_matrix_screen_set_brightness(5000);
            dot_matrix_screen_show_string("   ");
            printf("ALL TASKS FINISHED\r\n");
        }


        system_delay_ms(50);
    }
}
