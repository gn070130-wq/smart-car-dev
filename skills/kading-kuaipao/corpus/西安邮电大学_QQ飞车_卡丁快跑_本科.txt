第一章 引言
全国大学生智能汽车竞赛是由教育部高等学校自动化类专业教学指导委员会主办[1]、面向全国大学生的科技竞赛活动，以"立足培养，重在参与，鼓励探索，追求卓越"为指导思想，旨在培养大学生的综合知识运用能力、工程实践能力和创新精神。第二十一届全国大学生智能汽车竞赛于2026年举办，其中越野组比赛要求参赛车模在室外场地中自主完成规定的行进任务，对车模的传感器信息融合、路径规划与运动控制能力提出了较高要求。
本队"QQ飞车"采用"视觉识别＋惯导航位推算"的双处理器总体方案：车模尾部安装智能视觉模块，通过识别场地中的紫色圆形色块获得目标相对车模的横向偏移角与距离，实现第一阶段的倒车视觉跟随，并在跟随过程中利用编码器里程、前轮转向角与车身航向角完成路径的实时记录；当视觉目标丢失后，车模停车，经遥控/按键确认后进入第二阶段，由主控依据第一阶段记录的路径进行惯导原路返程，回到出发区域。该方案将视觉信息与里程/姿态信息有机结合，兼顾了室外环境的适应性与返程的自主性。
本报告按照《第二十一届全国大学生智能汽车竞赛技术报告细则》的要求撰写[2]，全文共分八章：第一章为引言，介绍竞赛背景与报告内容安排；第二章给出系统总体设计；第三章说明机械结构设计；第四章介绍硬件电路设计；第五章为重点，详细阐述系统软件设计，包括视觉识别、自动曝光、通信协议、视觉跟随控制、惯导航位推算与返程控制等；第六章介绍系统调试与参数整定过程；第七章列出模型车主要技术参数；第八章对工作进行总结与展望。报告附录附有核心算法源代码与电路设计说明。
1.1 竞赛背景
智能汽车竞赛自举办以来，已逐渐成为国内最具影响力的工科大学生竞赛之一。竞赛以车模为平台，将控制理论、传感器技术、嵌入式系统、数字图像处理、机械设计等多学科知识融为一体，强调"软硬结合、系统集成"。第二十一届全国大学生智能汽车竞赛越野组在室外场地举行，场地开阔、光照变化剧烈，且任务包含出发、行进、识别、返回等多个环节，与传统室内组别相比，对车模的环境适应能力、传感器鲁棒性以及控制算法的稳定性提出了更高要求。
针对越野组任务特点，本队将系统设计目标确定为：以视觉色块识别实现行进过程中的目标跟踪，以惯导航位推算实现不依赖外部信标的原路返程，保证车模在无GPS或GPS信号不佳的情况下仍能完成"去－回"全过程；同时通过自动曝光算法与颜色分割策略提高视觉系统在强光、阴影等复杂光照条件下的可靠性。
1.2 设计目标与技术指标
本车模的设计目标与主要技术指标如下：
（1）能够自动识别场地中的紫色圆形色块，并输出其相对车模的横向偏移角与距离，识别与跟踪全程实时进行；
（2）第一阶段能够依据视觉信息实现倒车跟随，跟随过程中以约每18个编码器脉冲一个采样点的密度记录路径信息（局部坐标、累计里程、航向角、前轮转向角），最大记录点数4096个；
（3）第二阶段能够依据记录的路径信息进行惯导原路返程，返程转向采用"记录转向角前馈＋惯导航向误差反馈＋横向位置修正"的复合控制策略，返程速度随遥控挡位变化，转弯与终点自动减速，全程最低速度保护；
（4）具有完善的手动/自动切换与安全保护机制：遥控断连自动保持、超时停车，视觉丢帧停车但不丢失路径，确保比赛过程安全可控；
（5）系统具备上电自检与前轮中位自动标定、串口调试输出、TFT路径显示等人机交互与调试手段。
1.3 报告内容安排
本报告按"总体设计—机械—硬件—软件—调试—参数—结论"的顺序组织：第二章介绍系统总体方案与器件选型；第三章介绍车模机械结构与传感器安装；第四章介绍电路设计；第五章详细说明软件架构、视觉算法与运动控制算法；第六章总结调试过程与参数整定经验；第七章给出模型车技术参数；第八章总结创新点并展望改进方向。

第二章 系统总体设计
2.1 系统总体方案
针对越野组"视觉识别＋自主返程"的任务需求，本队设计了"双处理器＋前后两级闭环"的总体方案。系统由智能视觉模块与主控模块两部分组成，二者之间通过串口（UART3，波特率115200bps）进行通信。
智能视觉模块采用逐飞SCC8660摄像头与TC264D微控制器，完成图像采集、自动曝光、色块识别、卡尔曼滤波等全部视觉处理，并以自定义帧协议向主控发送目标中心横向偏移角（int16，单位0.01°）与目标距离（uint32，单位mm）。将视觉处理放在独立的视觉模块上，可以避免图像处理占用主控计算资源，保证运动控制回路的实时性。
主控模块采用英飞凌AURIX TC264D双核微控制器，负责遥控信号解析、视觉数据接收、转向与速度闭环控制、路径记录、惯导航位推算与返程控制。主控内部按功能划分为三个工作模式：手动模式、视觉跟随模式与惯导返程模式，由遥控器挡位与视觉状态共同驱动状态机切换。
系统总体信息流为：视觉模块实时输出色块偏差与距离→主控据此计算前轮目标转角与后轮目标速度（倒车）→同时记录编码器里程、前轮转角与航向角→色块丢失后停车等待→确认后进入惯导返程→主控依据记录的路径与惯导航向完成转向与速度控制，原路返回。
2.2 系统硬件架构
系统硬件架构如图2.1所示（框图），主要包括：
（1）主控单元：TC264D核心板（逐飞E7开发平台），双核TriCore架构，最高主频200MHz，集成丰富的定时器、ADC、串口、SPI等外设；
（2）感知单元：SCC8660摄像头（RGB565彩色图像）、IMU660RA六轴惯性测量单元（陀螺仪2000dps）、增量式编码器（左右后轮各一，512脉冲/圈）、前轮转向角度传感器（电位器式，12位ADC采集）、BK-450i GPS模块（辅助定位与校准，当前版本不参与主任务闭环）；
（3）执行单元：后轮双直流电机（PWM调速，15kHz）与电机驱动、前轮转向电机（PWM控制）与角度反馈闭环；
（4）人机交互单元：TFT180彩色显示屏、遥控接收机（SBUS协议）、模式按键、拨码开关、蜂鸣器；
（5）无线调试单元：无线转串口模块与逐飞上位机（用于视觉模块图像回传与调试）。

2.3 系统软件流程
系统软件总体流程为：上电初始化（时钟、外设、传感器自检）→前轮中位自动标定→等待遥控指令→遥控挡位切换至自动后，等待视觉目标就绪→视觉倒车跟随（同时记录路径）→视觉目标丢失，车模停车（路径保留）→遥控/按键确认后进入惯导返程（等待1s后启动）→按记录路径原路返回→到达终点停车，任务结束。

第三章 机械结构设计
3.1 车模总体结构
本车模选用竞赛用越野车模，采用四轮底盘结构：前轮为转向轮，后轮为驱动轮。驱动方式为后轮双电机独立驱动，两后轮各配置一台直流电机并经减速齿轮驱动，通过左右电机差速实现转向辅助；前轮由转向电机经连杆机构驱动转向，转向角度通过电位器式角度传感器实时反馈。车模总体布局将视觉模块、主控板、电池等质量较大的部件置于底盘中部偏后位置，降低整车重心，提高越野路面行驶稳定性。
车模实测总重量约20 kg，车身长度约110 cm、宽度约70 cm；轴距约68 cm，轮距约65 cm。整车高度约70 cm，详细参数见第七章。
3.2 视觉模块安装
视觉模块安装在车模尾部，摄像头镜头朝向后下方，以保证第一阶段的倒车跟随能够持续观察到场地中的紫色圆形色块。安装时通过调节俯仰角与高度，使色块在常见距离（约0.5m～2.5m）内处于图像中心区域，避免出现遮挡与反光干扰。视觉模块与主控之间通过串口线连接，供电与信号线采用屏蔽线并尽量短距离走线，减少电机电磁干扰对图像质量的影响。
3.3 传感器安装
IMU660RA惯性测量单元安装在车模底盘几何中心附近，安装面保持水平，陀螺Z轴垂直于底盘平面，用于测量车模航向角速度并积分得到航向角。左右后轮轮轴处各安装一个增量式编码器，编码器与车轮同步旋转，用于测量左右轮转速与累计里程。前轮转向机构上安装电位器式角度传感器，传感器输出经12位ADC采集，用于前轮转角的实时检测与闭环控制。各传感器均采用减震与固定措施，防止越野路面颠簸造成松动。
3.4 转向机构与前轮角度检测
前轮转向采用"转向电机＋连杆机构"方案，转向电机经减速机构驱动前轮左右偏转，最大机械转角约为±30°。前轮实际转角由电位器式角度传感器检测，传感器输出电压经主控ADC（12位）采集，标定系数约为11.2个ADC计数对应1°。系统上电后自动执行前轮中位标定：以2ms间隔连续采样32次并取平均，得到转向中心对应的ADC值，据此将左右两侧转角统一换算为有符号角度（左负右正），并限制在±30°以内。该角度同时用于转向PID闭环反馈与后轮差速控制，保证三种工作模式（手动、视觉、返程）下转向控制的一致性。

第四章 硬件电路设计
4.1 主控电路
主控采用逐飞TC264D开发平台，核心为英飞凌AURIX TC264D微控制器。TC264D基于TriCore架构[3]，集成双核CPU（各200MHz）、1.5MB程序Flash、96KB数据RAM，并带有GTM/CCU6定时器单元、12位ADC、多路串口（UART/SPI/ASC）、DMA控制器等丰富外设，满足本车模"多传感器采集＋实时运动控制"的资源需求。主控板集成稳压电路、USB转串口调试电路与调试指示灯，外围电路设计集中于传感器接口、电机驱动接口与电源接口。主控板及外围接口原理图见附录B图B-1。
主控外设资源分配如下：UART0用于调试串口输出；UART2用于SBUS遥控信号接收；UART3用于与视觉模块通信；SPI0用于IMU660RA；SPI2用于TFT显示屏；SPI3用于磁力计LQ_9AGM；CCU6/GTM定时器输出多路PWM驱动后轮电机与前轮转向电机；编码器接口使用定时器输入捕获；前轮角度传感器接入12位ADC通道。
4.2 电源电路
整车采用锂电池供电，经主控板稳压电路转换为各模块所需电压：5V为电机驱动逻辑、遥控接收机、TFT显示屏供电；3.3V为TC264D、IMU、磁力计、编码器及视觉模块供电。电源入口设置防反接与滤波电容，电机驱动与数字电路分区供电、共地处理，动力地与信号地单点连接，降低电机启停造成的电压跌落与地弹噪声对传感器的影响。电路功耗等参数见第七章。
4.3 电机驱动电路
后轮双电机采用专用双路直流电机驱动器，输入PWM频率15kHz，PWM占空比对应电机电压，方向由方向控制引脚决定。左右后轮PWM与方向信号由主控GTM定时器输出与控制，形成左右独立的速度控制通道。前轮转向电机由主控PWM输出驱动，转向方向与角度由转向闭环控制器计算得到的PWM占空比决定。所有PWM输出在软件中均设有输出限幅与斜坡变化限制，防止突变电流冲击。双路电机驱动及降压供电原理图见附录B图B-2。
4.4 编码器测速电路
左右后轮编码器输出两路正交信号，经上拉与整形电路接入主控定时器输入捕获通道。主控在5ms定时中断中对左右编码器计数进行累加，得到左右轮累计脉冲，进而计算行驶里程与左右轮速度。编码器每圈512个脉冲，后轮实测直径为27.5 cm，按圆周率计算周长约0.864 m，换算系数为每脉冲约1.69 mm。
4.5 遥控接收电路
遥控接收机输出SBUS数字信号，经反相电路接入主控UART2串口。主控在串口接收中断中解析SBUS帧，得到8通道摇杆/开关数据。其中CH1通道用于转向控制（中位约800，灵敏度32计数/°），CH2通道用于油门/倒车控制（中位800，前进端200，倒车端1800），CH4通道用于模式选择（400～1000为手动挡，1500以上为自动挡），拨码开关提供8挡速度选择（对应PWM基值5500，每挡递增500）。
4.6 视觉模块电路
视觉模块为独立的"摄像头＋TC264D"处理板：SCC8660摄像头通过8位并行数据口（P00_0～P00_7）、VSYNC（P02_0）、PCLK（P02_1）与处理板连接，图像数据由DMA搬运，摄像头配置通过UART1完成；模块自带TFT180显示调试界面与无线转串口模块（UART2），可将原始图像与识别结果回传逐飞上位机辅助调参。视觉模块与主控之间通过UART3（115200bps）连接，发送自定义帧协议（详见5.3.5节）。
4.7 显示与调试电路
主控板配置TFT180彩色显示屏（160×128像素，SPI接口），运行中实时显示当前挡位、任务状态；进入返程阶段后切换为绿色路径绘制模式，仅显示记录路径，避免多余信息干扰。调试接口包括：调试串口（115200bps，输出[BOOT]上电自检、[G]惯性数据、[R]返程快照等诊断信息）、模式按键与拨码开关、SWD调试口（连接AURIX Development Studio进行在线调试）。

第五章 软件设计
5.1 软件总体架构
主控软件基于逐飞TC264开源库开发[4]，采用"双核分工＋定时中断＋10ms主循环"的软件架构。CPU0负责全部控制逻辑：主循环以10ms为周期依次执行遥控数据轮询解析、视觉串口帧解析、任务状态机处理、后台任务与调试输出；CPU1负责存放路径等大数据数组（路径数组置于CPU1数据RAM），当前版本未承担计算任务，为后续算法升级预留算力。
中断资源分配：CCU6定时器CH0以5ms周期触发，完成陀螺仪采样与航向积分、编码器脉冲累计；UART2接收中断完成SBUS遥控帧解析；UART3接收中断将视觉数据写入环形缓冲区；UART1用于摄像头配置；DMA完成摄像头图像搬运。5ms中断内仅执行轻量计算（积分与累加），重负载的路径记录、PID计算与控制输出在主循环中按周期完成，保证实时性与代码可维护性。
5.2 遥控输入与状态管理
为避免控制逻辑多处读取遥控全局变量造成的数据不一致，软件在每个控制周期开始时统一捕获一次遥控快照（在线标志、接收状态、全部通道值），后续"遥控守护"判断与手动执行共用同一份快照，保证同一周期内判断与执行的一致性。
遥控守护机制包括以下安全策略：
（1）接收机状态异常（failsafe）时立即停车并暂停任务；
（2）仅"在线标志"短暂丢失（非failsafe）时，手动模式保持最后指令不超过250ms，返程自动模式通过无符号tick差值保持约250ms，超时后停车并暂停返程；
（3）手动指令短保持增加CH4手动区间约束，避免CH4已切换至停止挡时沿用旧的手动油门；
（4）返程过程中速度计算加入最低1000的PWM保护，防止任何情况下出现无下限减速。
任务状态机（task_mode）共五个状态，转换关系为：空闲态等待CH4自动挡上升沿→进入视觉等待态（等待视觉目标就绪，视觉状态帧由停止切换为测量）→进入视觉跟随态（倒车跟随并记录路径）→收到视觉停止帧后进入返程等待态（停车1s，前轮回中）→进入返程态（按记录路径惯导返程）→到达终点停车，任务完成。视觉丢帧（超时500ms）仅停车不退出任务、不清除路径，只有收到明确的停止帧或遥控指令才结束跟随进入返程。

5.3 视觉模块软件设计
5.3.1 图像采集
视觉模块图像采集采用"VSYNC中断触发＋DMA搬运"方式：SCC8660摄像头输出RGB565格式图像（字节交换，低字节在前），VSYNC信号触发采集开始，PCLK信号驱动DMA通道将图像数据搬入内存，DMA完成中断置帧就绪标志；CPU0主循环检测到帧就绪标志后取帧处理。图像分辨率受TFT显示约束，原始图像可直接显示于TFT180用于调试。
5.3.2 自动曝光算法
越野场地光照变化剧烈（强光、阴影、逆光），固定曝光参数难以保证色块颜色分割的稳定性。为此设计了一种基于感兴趣区域（ROI）灰度统计的多档自动曝光算法：在图像ROI区域（水平40～120、垂直30～90像素）内隔行隔列采样，按(77R+150G+29B)/256的加权公式计算平均灰度；曝光值共分9档（3、5、10、18、30、43、58、74、96），每5帧评估一次，根据ROI平均灰度与各档边界阈值判断应切换到的档位。
为防止光照在档位边界附近来回切换造成画面闪烁，算法引入滞回比较与连续确认机制：各档位切换使用独立的进入/退出阈值（如正常档30在灰度低于110时进入暗档43，而暗档需灰度高于150才返回正常档）；同时目标档位需连续3帧确认后才实际执行切换，每帧只移动一档。实验表明该算法在太阳直射、云层遮挡、场地阴影等场景下均能将ROI灰度稳定维持在设定区间，色块分割阈值无需随光照调整。
5.3.3 色块识别算法
色块识别采用"颜色分割＋连通域分析＋特征筛选＋打分”的流程[5]。颜色分割阶段，依据RGB565颜色阈值将紫色色块像素从背景中分割出来，生成二值掩膜。紫色判据为：红色分量≥4、蓝色分量≥5、绿色分量≤45，且红、蓝分量分别大于绿色分量的一半并保留一定余量；同时针对强光下颜色发白的情况，设计了蓝色"亮色"分支阈值，抑制白色高光区域的误检。
连通域分析阶段，采用基于扫描线的区域填充算法（栈式搜索）对掩膜像素进行标记，统计每个连通域的面积、质心、外接框、四角位置等特征；特征筛选阶段剔除触边框、面积过小（<20像素）、宽高过小、填充率异常（450‰～950‰）与长宽比过小的候选区域；打分阶段对候选区域按"填充率接近圆形的程度×2＋长宽比×3＋面积/10"加权评分，取最高分区域为最终目标。
目标定位输出包括：中心横向偏移（目标质心横坐标与图像中心之差，用于转向控制，单位为像素，协议中记为"角度"）、目标距离（由小孔成像模型估算：距离＝色块真实直径150mm×焦距标定值70像素/图像竖直直径像素）。识别结果叠加显示于TFT（绿色外框＋中心十字）便于现场调试。需要说明的是，黄色事件圆盘识别模块（50mm直径，可测水平旋转角0°～90°）亦已完成开发，作为备用功能保留于工程中，当前版本主流程未调用。

5.3.4 卡尔曼滤波
为抑制单帧识别噪声，对发送给主控的目标偏差与距离进行标量卡尔曼滤波。滤波器状态为偏差与距离两个独立标量，过程噪声Q（偏差4.0、距离400）、量测噪声R（偏差5.0、距离900），协方差初值（25、2500）。每帧识别成功时执行预测－更新一步滤波；连续多帧未识别时重置滤波器，避免旧目标位置残留影响后续重新捕获。滤波器同时设置跳变拒绝：偏差变化超过160或距离变化超过1200mm时，视为无效测量，保持原状态输出。
5.3.5 通信协议
视觉模块与主控之间的通信帧格式为"帧头＋类型＋数据＋校验"：帧头AA 55，类型字节0x01为停止状态帧（帧长5字节），0x02为测量帧（帧长10字节）。测量帧数据段依次为：目标中心横向偏移（int16，大端，单位0.01°）与目标距离（uint32，大端，单位mm）；校验和为类型字节至倒数第二字节的累加和。主控在UART3接收中断中缓存数据，主循环解析帧结构并校验，校验通过后更新视觉状态与测量值；500ms内无有效帧判定视觉离线。视觉模块通过按键在"连续发送停止帧"与"发送测量帧"两种模式间切换，配合主控完成"就绪→跟随→结束"的状态传递。
5.4 视觉倒车跟随控制
视觉跟随阶段车模倒车行驶（摄像头朝后），主控根据视觉模块发送的目标横向偏移角计算前轮目标转角：偏移角小于死区（±5°）时前轮回中；偏移角在10°～30°范围内按比例线性映射至前轮最大转角（±30°），并根据"摄像头朝后、目标在图像右侧则车模应向右转"的几何关系取反，最终输出经统一转角限幅后送入前轮转向闭环。
跟随速度由遥控手动挡位换算得到（倒车速度为手动挡PWM的0.65倍），保证操作手可通过遥控挡位随时调整跟随速度。跟随过程中若视觉帧超时（500ms）或连续丢帧，主控立即停车但不退出任务、不清除路径，等待视觉恢复或收到停止指令。
差速控制：为提高转弯灵活性并减小转向电机负荷，后轮加入差速控制。当前轮转角绝对值超过4°时开始差速，至20°时达到最大差速比例0.40，即内侧轮速度最低降为基本速度的60%；差速只作用于内侧轮（减速），外侧轮保持目标速度。三种工作模式（手动、视觉、返程）共用同一差速函数，保证转向手感一致。
5.5 惯导航位推算
惯导航位推算（INS）以车模初始位置为原点建立局部坐标系（x为横向、y为纵向），利用陀螺航向角与编码器里程递推车模位置：
航向角由IMU660RA陀螺仪Z轴角速度在5ms定时中断中积分得到，积分前进行零漂校正（上电采集500次求平均作为零偏）并设置0.004rad/s的死区，抑制静止时陀螺噪声引起的航向漂移。
里程由左右编码器累计脉冲计算：脉冲增量为左右轮脉冲增量的平均值，行驶距离＝脉冲增量/512×后轮实测周长0.864 m。位置递推公式为x坐标累加距离×sin(航向角)，y坐标累加距离×cos(航向角)。左右轮脉冲按行驶方向取符号（倒车为负），保证倒车跟随阶段记录的里程方向正确。
5.6 路径记录与返程控制
5.6.1 路径记录
视觉跟随阶段同时进行路径记录：每累计18个编码器脉冲记录一个路径点，路径点数据包括局部坐标x、y、累计脉冲、航向角与前轮转向角（int8量化，分辨率约0.24°），最多记录4096个点，存储于CPU1数据RAM的路径数组中。
5.6.2 返程状态机
收到视觉停止帧或遥控确认后，系统进入返程等待态（停车1s，前轮回中），随后进入返程态执行原路返回。返程路径为记录路径的反序：路径点顺序反转，累计脉冲按"总脉冲－原值"换算为返程里程，航向角换算到返程坐标系，前轮转向角仅交换顺序、保持原符号（视觉阶段为倒车、返程阶段为掉头后正向行驶，物理转向方向一致）。
5.6.3 返程转向控制
返程转向采用"记录转向角前馈＋航向误差反馈＋横向位置修正"的复合控制策略：目标转角＝当前路径点记录的前轮转角（前馈系数1.0）＋当前INS航向与路径航向的误差反馈＋横向位置修正项。横向修正通过前视2.5m处的路径点计算横向偏差，经滤波（系数0.12）并限制在±6°以内、设置0.02m死区，用于抑制里程误差累积造成的路径漂移。
针对返程起步转向偏慢的问题，加入起步预转向：返程启动时前视0.9m范围内的路径转角，若前方存在明显转向，则后轮保持停止、前轮先转向120～500ms（或实际转角达到目标的60%以上）后再启动行驶；后续弯道不再停车等待前轮，依靠前馈与反馈连续控制。返程转向输出每周期步进限制1.5°，防止转向突变。


图5.3 返程复合转向控制框图
5.6.4 返程速度控制
返程速度跟随遥控挡位（与手动挡速度一致），并加入三处自动减速：前视1.85m范围内记录转角超过8°时开始减速，45°以上全速减速至最低PWM 1000；距终点1.00m时按平方关系减速至1000；返程起步0.90m内限速1500。全程速度输出不低于1000（最低保护），确保返程过程平稳可控。
5.7 转向与速度闭环控制
5.7.1 前轮转向闭环
前轮转向采用位置式PID闭环[6]：目标转角（来自遥控、视觉或返程控制）经统一限幅（±30°）后，与ADC换算得到的实际转角比较，偏差经PID运算（比例系数10，积分与微分项关闭，积分限800，输出限3200，死区0.15°）输出PWM驱动转向电机。接近机械限位时输出按距离按0.65/0.45/0.25软衰减，防止转向电机长时间堵转。
5.7.2 后轮速度闭环
左右后轮分别采用增量式PID速度闭环（比例系数36，积分系数0.6，输出限±10000）：目标速度由挡位、视觉跟随或返程速度策略计算，反馈速度由5ms中断内的编码器计数经5周期滑动窗滤波得到，目标变化每周期限制±20脉冲，PWM与速度换算系数600 PWM/脉冲。PID输出经方向保护后驱动电机，PWM变化按升50/降160的斜坡限制，兼顾响应速度与电流冲击。转向差速作用于速度目标层，与速度闭环级联。
5.8 GPS与辅助导航
本车模配置了BK-450i GPS模块（25Hz输出，RMC/GGA语句，经u-center配置并保存至Flash），用于场地定位参考与路径校准。当前比赛任务（色块跟随＋惯导返程）不依赖GPS实时闭环，GPS数据作为调试与扩展手段保留；后续可基于GPS绝对坐标与惯导局部坐标的融合实现场地级路径规划。磁力计LQ_9AGM已集成并完成椭圆校正，可在GPS信号不佳时提供绝对航向参考，当前版本航向以陀螺积分为主。
5.9 显示与调试
主控TFT在空闲状态显示当前挡位百分比；进入任务后切换为路径显示模式，以绿色绘制记录路径（显示区域坐标(4,38)～(124,134)，最多抽稀160点），任务过程中不刷新屏幕以免占用控制时间，仅返程暂停时低频刷新。调试串口输出三类诊断信息：上电自检[BOOT]（IMU初始化状态）、惯性数据[G]（500ms周期，含陀螺原始值、零偏、角速度、航向角）、返程快照[R]（200ms周期，含路径索引、累计脉冲、航向误差、转向指令、前轮角度、左右轮目标与反馈速度、PWM等40余项），为现场调参提供完整数据支撑。

第六章 系统调试与参数整定
6.1 调试工具与方法
系统调试基于AURIX Development Studio（ADS 1.9.4）集成开发环境与Tasking编译器，通过SWD接口在线仿真调试；辅助调试手段包括：调试串口（115200bps）实时打印[BOOT]上电自检、[G]惯性数据（500ms周期）与[R]返程快照（200ms周期）等诊断信息；TFT显示屏现场显示状态与路径；逐飞上位机配合无线转串口模块回传视觉模块图像与识别结果；GPS模块使用u-center工具进行配置与观测[7]。
调试流程遵循"先标定、后闭环、再任务"的原则：先完成前轮中位与传感器标定，再整定转向与速度闭环，随后联调视觉跟随，最后调试惯导返程。

6.2 传感器标定
前轮转向角度标定包括中位标定与增益标定。中位采用上电自动标定：以2ms间隔连续采样32次ADC取平均，作为转向中心；增益按"11.2个ADC计数/°"线性换算，左右两侧分别以"上电中心±最大角×增益"计算限位。调试中曾实测左右限位ADC（左2560、右3300，对应约±28°），为兼顾左右不对称性与标定简洁性，最终版本恢复为对称标定并统一限制±30°。
陀螺仪零漂标定在每次上电时自动完成：连续采集500次Z轴角速度（5ms周期）取平均作为零偏，并设置0.004rad/s死区抑制静止噪声。视觉模块距离标定采用已知直径色块的实测标定：紫色色块直径150mm，焦距标定值70像素（距离＝150×70/图像直径）。
6.3 视觉参数整定
视觉参数整定重点解决光照适应性与误检率两个问题。自动曝光方面，通过反复试验确定9档曝光与各档切换阈值，并引入滞回与连续3帧确认，消除档位边界处的画面闪烁；在太阳直射、阴天、树荫等场景下实测ROI灰度均能稳定收敛到设定区间。颜色分割阈值方面，针对场地光照偏强导致色块颜色发白的问题，增加蓝色"亮色"分支阈值并抑制白色高光误检；针对场地中其他蓝色物体干扰，通过面积、填充率、长宽比等特征过滤。卡尔曼滤波的噪声参数（Q、R）根据实际帧率与目标运动速度整定，跳变拒绝阈值用于滤除偶发误识别。
6.4 运动控制参数整定
运动控制参数整定以场地实测为准，主要过程如下：
（1）转向闭环：前轮转角PID采用纯比例控制（kp=10），配合输出限幅3200、积分限800与近限位软衰减，确保转向响应快且不抖动；
（2）速度闭环：后轮速度PID（kp=36、ki=0.6）经5周期滑动窗滤波反馈，目标变化限幅±20脉冲，兼顾加减速平顺性；
（3）差速参数：后轮差速最大比例由0.30逐步试验至0.40（当前轮转角20°时内侧轮最低保持60%基础速度），转弯灵敏性与直线稳定性折中；
（4）返程转向参数：返程入弯偏晚问题通过"记录转角前馈"解决，前馈比例经0.35→0.60→0.75→1.00的迭代试验最终定为1.00，并配合0.30m同向预瞄（增量20%）与起步预转向（120～500ms）；返程转向每周期步进限制1.5°，抑制转向突变；
（5）返程速度参数：转弯预瞄减速（1.85m内转角超8°减速，45°全减）、终点1.00m平方刹车、起步0.90m限速1500，全程最低速度保护1000，均经多轮场地试验确定。

第八章 结论与展望
8.1 工作总结
本队围绕第二十一届全国大学生智能汽车竞赛越野组任务，设计并实现了一套"视觉识别＋惯导航位推算"的智能车系统。系统以TC264D双核微控制器为主控，以"摄像头＋TC264D"独立视觉模块完成图像采集、自动曝光、色块识别与滤波，通过自定义串口协议与主控交互；主控完成遥控管理、视觉倒车跟随、路径记录、惯导航位推算与原路返程控制。
经过多轮场地调试，系统实现了以下功能：自动曝光算法在剧烈变化光照下保持色块识别稳定；视觉跟随与差速控制保证了行进过程的平稳；基于编码器里程、陀螺航向与前轮转角的路径记录与原路返程控制，实现了不依赖外部信标的"去－回"全过程；完善的安全保护机制（遥控快照、断连保持、丢帧停车、最低速度保护）保证了比赛过程的安全性。
8.2 创新点
本系统的创新点主要体现在：
（1）双处理器架构：视觉处理与运动控制分离，视觉模块独立完成图像处理并以轻量帧协议输出结果，避免图像处理占用主控算力，保证10ms控制周期稳定；
（2）基于ROI灰度统计的多档滞回自动曝光：以9档曝光＋滞回阈值＋连续确认，兼顾响应速度与稳定性，显著提升室外强光/阴影环境下的识别鲁棒性；
（3）"记录转角前馈＋航向误差反馈＋横向位置修正"的返程复合转向控制：利用第一阶段记录的路径信息，实现接近原路的返程轨迹，并通过起步预转向、步进限制与速度自动减速保证返程平稳；
（4）统一的转角限幅与差速控制框架：三种工作模式共用同一转向闭环与差速函数，参数一致、调试高效；
（5）完善的调试体系：串口诊断（[G]/[R]）、TFT路径显示、上位机图像回传与上电自动标定，支撑快速迭代。
8.3 不足与展望
系统仍存在以下不足与改进空间：
（1）当前返程完全依赖陀螺积分航向与编码器里程，长时间运行存在累积漂移，后续可融合磁力计绝对航向与GPS绝对坐标进行校正；
（2）视觉识别仅输出目标中心偏差与距离，尚未利用目标尺寸/姿态等更多信息，后续可扩展识别多种色块与标志物，支持更复杂的任务；
（3）路径记录为等脉冲间隔采样，弯道处点数相对稀疏，可研究按曲率自适应采样以提高返程精度；
（4）自动曝光与颜色阈值目前依赖经验整定，可进一步研究基于图像统计的自适应阈值算法。
总体而言，本车模已实现了竞赛任务要求的核心功能，系统架构清晰、算法可扩展，为后续优化与升级奠定了基础。

/* ROI 平均灰度：对感兴趣区域隔行隔列采样，按加权公式计算灰度 */
static uint16 roi_gray_average(const uint16 *image, uint16 width)
{
	uint16 x, y;
	uint32 sum = 0u;
	uint16 count = 0u;
	for(y = ROI_Y0; y < ROI_Y0 + ROI_H; y += 2u)
		for(x = ROI_X0; x < ROI_X0 + ROI_W; x += 2u)
		{
			uint16 pixel = image[(uint32)y * width + x];
			uint16 rgb = (uint16)((pixel << 8) | (pixel >> 8));
			uint16 r = (uint16)(((rgb >> 11) & 0x1Fu) * 255u / 31u);
			uint16 g = (uint16)(((rgb >> 5) & 0x3Fu) * 255u / 63u);
			uint16 b = (uint16)((rgb & 0x1Fu) * 255u / 31u);
			sum += (77u * r + 150u * g + 29u * b) >> 8;
			count++;
		}
	return count ? (uint16)(sum / count) : 0u;
}
/* 自动曝光：滞回比较 + 连续确认，每帧只移动一档，防止画面闪烁 */
if(selected == current) { pending_count = 0u; return current; }
if(selected != pending) { pending = selected; pending_count = 1u; return current; }
if(++pending_count >= ROI_EXPOSURE_CONFIRM)   /* 连续3帧确认 */
{
	pending_count = 0u;
	return selected;                          /* 执行档位切换 */
}
return current;

#define PURPLE_PIXEL_MIN_R       (4u)
#define PURPLE_PIXEL_MIN_B       (5u)
#define PURPLE_PIXEL_R_OVER_G_HALF (1u)

/* 标量卡尔曼滤波：预测 + 更新一步完成，带跳变拒绝 */
void square_kalman_update(square_kalman_filter_t *f, int16 raw_angle,
						uint32 raw_dist, int16 *f_angle, uint32 *f_dist)
{
	if(!f->initialized)                       /* 首帧直接采用 */
	{
		f->angle = raw_angle;
		f->distance = raw_dist;
		f->initialized = 1u;
	}
	else
	{
		/* 跳变拒绝：偏差超160或距离超1200mm 视为无效测量 */
		angle_jump = fabsf(raw_angle - f->angle);
		distance_jump = (raw_dist > f->distance) ?
			(raw_dist - f->distance) : (f->distance - raw_dist);
		f->angle_covariance += 4.0f;          /* 过程噪声 */
		angle_gain = f->angle_covariance /
					(f->angle_covariance + 5.0f);   /* 量测噪声 */
		if(angle_jump <= 160.0f)
			f->angle += angle_gain * (raw_angle - f->angle);
		f->angle_covariance *= (1.0f - angle_gain);
		/* 距离通道同理，噪声按比例放大 */
		f->distance_covariance += 400.0f;
		distance_gain = f->distance_covariance /
						(f->distance_covariance + 900.0f);
		if(distance_jump <= 1200u)
			f->distance += distance_gain * (raw_dist - f->distance);
		f->distance_covariance *= (1.0f - distance_gain);
	}
	*f_angle = (int16)(f->angle + 0.5f);
	*f_dist = (uint32)(f->distance + 0.5f);
}

A.4 主控：视觉角度到前轮转角映射（节选）
static float task_vision_angle_to_steering(int16 angle_deg)
{
	float limited_angle = (float)angle_deg;
	float steering_angle;

	if(limited_angle > TASK_VISION_INPUT_ANGLE_MAX)        /* ±30° 限幅 */
		limited_angle = TASK_VISION_INPUT_ANGLE_MAX;
	else if(limited_angle < -TASK_VISION_INPUT_ANGLE_MAX)
		limited_angle = -TASK_VISION_INPUT_ANGLE_MAX;

	if(limited_angle >= -TASK_VISION_INPUT_DEADBAND &&     /* ±5° 死区 */
	limited_angle <= TASK_VISION_INPUT_DEADBAND)
		return 0.0f;

	/* 10°~30° 区间线性映射至前轮全量程（±30°） */
	if(limited_angle > TASK_VISION_INPUT_DEADBAND)
		steering_angle = (limited_angle - TASK_VISION_INPUT_DEADBAND) *
			(TASK_VISION_STEER_ANGLE_MAX /
			(TASK_VISION_INPUT_ANGLE_MAX - TASK_VISION_INPUT_DEADBAND));
	else
		steering_angle = (limited_angle + TASK_VISION_INPUT_DEADBAND) *
			(TASK_VISION_STEER_ANGLE_MAX /
			(TASK_VISION_INPUT_ANGLE_MAX - TASK_VISION_INPUT_DEADBAND));

	return -steering_angle;   /* 摄像头朝后，方向取反 */
}
A.5 主控：惯导航位推算（节选）
void INS_UpdateByEncoder(void)
{
	int16 delta_l = Encoder_L - ins_last_encoder_l;
	int16 delta_r = Encoder_R - ins_last_encoder_r;
	float pulse_delta, distance_m, yaw_rad;

	ins_last_encoder_l = Encoder_L;
	ins_last_encoder_r = Encoder_R;
	if(!ins_state.ready) return;

	pulse_delta = (float)(abs(delta_l) + abs(delta_r)) * 0.5f;
	if(g_target < 0) pulse_delta = -pulse_delta;   /* 倒车方向取负 */

	/* 里程 = 脉冲 / 512(每圈) × 后轮实测周长0.864m */
	distance_m = pulse_delta / INS_ENCODER_PULSE_PER_TURN *
				INS_WHEEL_CIRCUMFERENCE_M;
	ins_state.yaw_deg = normalize_180(Dir_z_180);  /* 陀螺积分航向 */
	yaw_rad = ins_state.yaw_deg * (PI / 180.0f);
	ins_state.x_m += distance_m * sinf(yaw_rad);   /* 局部坐标递推 */
	ins_state.y_m += distance_m * cosf(yaw_rad);
	ins_state.speed_mps = distance_m / INS_DT_S;
}

A.7 主控：后轮差速控制（节选）
static void task_rear_apply_differential(float base_l, float base_r,
										float *target_l, float *target_r)
{
	float angle_abs = fabsf(task_front_mech_deg);
	float ratio = 0.0f;
	float left_factor = 1.0f, right_factor = 1.0f;

	/* 前轮转角4°起差速，20°达最大差速比例0.40 */
	if(angle_abs > TASK_REAR_DIFF_START_ANGLE)
	{
		ratio = (angle_abs - TASK_REAR_DIFF_START_ANGLE) /
				(TASK_REAR_DIFF_FULL_ANGLE - TASK_REAR_DIFF_START_ANGLE) *
				TASK_REAR_DIFF_MAX_RATIO;
		if(ratio > TASK_REAR_DIFF_MAX_RATIO) ratio = TASK_REAR_DIFF_MAX_RATIO;
	}
	if(task_front_mech_deg > 0.0f)  right_factor -= ratio;  /* 只减内侧轮 */
	else if(task_front_mech_deg < 0.0f) left_factor -= ratio;

	left_factor  = clamp(left_factor,  0.0f, 1.0f);
	right_factor = clamp(right_factor, 0.0f, 1.0f);
	*target_l = base_l * left_factor;
	*target_r = base_r * right_factor;
}
