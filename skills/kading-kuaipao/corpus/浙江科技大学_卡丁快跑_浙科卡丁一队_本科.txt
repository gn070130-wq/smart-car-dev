第一章 引言
1.1 赛题背景
全国大学生智能汽车竞赛是以智能汽车为研究对象的创意性科技竞赛。第二十一届竞赛卡丁车组采用指定卡丁车平台，要求参赛队在保留原车底盘与动力总成的条件下，加装传感器与计算单元，完成人工驾驶、辅助驾驶与自主行驶相结合的系列考核科目：包括基础的遥控与踏板驾驶，灯光、鸣笛与语音交互等安全辅助科目，基于机器视觉的目标跟随科目，以及记录行驶轨迹并自主循迹返回的科目。
与竞速组别不同，卡丁车组车模质量大、惯量大、行驶速度高，且考核科目同时涉及人机共驾与全自主控制，对控制系统的实时性、安全性和鲁棒性提出了更高要求。本队选用英飞凌 AURIX TC387QP 作为主控，利用其四个 TriCore 内核进行任务级并行调度，完成了全部规定科目的软硬件设计、制作与调试。
1.2 技术方案概述
整车控制系统以 TC387QP 为核心：感知层包括总钻风 MT9V03X 灰度摄像头（配单轴偏航云台）、ICM42688 六轴惯性测量单元、左右后轮 1000 线正交编码器、转向机构增量编码器与模拟量油门踏板；执行层包括左右后轮 DRV8701E 直流电机驱动、转向直流电机位置闭环、云台舵机、TLD7002 十六通道车灯驱动与 PWM 喇叭；交互层包括 ELRS 遥控接收机（CRSF 协议）、IPS200 液晶屏菜单系统与讯飞语音识别人机交互。
软件上采用"多核分工 + 周期中断"架构：CPU0 运行 2 ms 转向环与 50 ms 速度环；CPU1 专职图像采集与目标检测；CPU2 负责运行日志记录与低优先级通信；CPU3 负责人机交互与音频采样（ADC 32 kHz 过采样、4 倍抽取为 8 kHz 音频流）。自主行驶的核心算法包括基于行程编码连通域标记的黑圆目标检测与测距跟随、Mahony 姿态解算、航迹记录与"航向反馈 + 横向偏差修正 + 转向前馈"的循迹返回控制，以及基于曲率窗口与加速度约束的返程速度剖面规划。
1.3 报告结构安排
本报告共分八章。第二章介绍系统总体方案；第三章介绍机械结构与传感器安装；第四章介绍电路设计；第五章介绍控制软件的主要理论与算法；第六章介绍开发工具与调试过程；第七章给出模型车的主要技术参数；第八章为结论。附录 A 给出核心算法子程序，附录 B 为电路原理图。

第二章 系统总体方案
2.1 系统总体架构
整车电子系统按照"感知—决策—执行—交互"四个层次组织，如图 2.1 所示。感知层将赛道目标图像、车体姿态、轮速与驾驶人操作量数字化；决策层在 TC387QP 上运行状态机与控制算法，按"视觉 > 自动 > 遥控 > 踏板"的优先级仲裁出转向与速度指令；执行层完成电机与车灯驱动；交互层提供菜单、遥控与语音三种人机接口。

图2.1 系统总体结构框图
2.2 主控芯片与多核任务分工
主控采用英飞凌 AURIX 系列 TC387QP，片内集成四个 300 MHz TriCore 内核。四个内核全部投入使用，按数据流向就近分配任务：图像缓冲区位于 CPU1 本地 DSPR，图像检测由 CPU1 完成，避免跨核搬运图像；控制环对实时性要求最高，集中在 CPU0 并以最高中断优先级运行；日志与通信、人机交互分别安排在负载较轻的 CPU2、CPU3。各核之间通过位于线性地址段的全局变量交换数据，发布方写入带序号的一致性快照，订阅方按序号读取，避免读到写了一半的状态。多核任务分工如表 2.1 所示。
表2.1 四核任务分工
2.3 调度与中断优先级设计
TC387 中断优先级数值越大级别越高，且所有中断优先级不得重复。本系统按"采样时刻精度优先"原则排布：摄像头 DMA 完成中断（70）与 VSYNC 中断（62）最高，保证图像时序；CPU0 的 2 ms 控制中断（58）高于 50 ms 速度环中断（57）；CPU3 内 32 kHz 音频采样中断（55）高于菜单刷新（51）——菜单屏幕刷新单次可达毫秒级，若允许其抢占音频采样，采样时钟抖动将直接等效为注入语音链路的宽带噪声且无法在数字域补救，而菜单晚几十微秒人眼完全无感。主要中断分配如表 2.2 所示。

本队采用组委会指定的科宇 T 型卡丁车平台，原车为后轮双直流有刷电机独立驱动、前置转向机构。实测原车转向机构为平行转向（内外轮转角近似相等，阿克曼率为 0），存在先天转向不足，这一机械特性对后续电子差速与循迹控制的参数整定有直接影响，详见第五章。改装后的整车布局如图 3.1 所示。

3.2 摄像头与云台安装

3.3 编码器与惯性测量单元安装

第四章 电路设计
4.1 电源分配
整车以 24 V 车载动力电池为总电源，三只驱动电机由电池直接供电，控制与传感器系统经降压后供电。电源入口经拨动开关与 470 μF×2 电解电容滤波后分为两路同步降压：一路以 SCT2450（36 V/5 A 同步降压转换器）降至 5 V，为逻辑与外设供电；另一路以同型号降至 6 V，供云台舵机等执行机构，两路均配 10 μH 功率电感与 47 μF+100 μF 输出储能电容，抑制电机启停引起的母线电压跌落。5 V 母线再经两路 RT9013-33 低压差线性稳压器分别产生主 3.3 V 逻辑电源与摄像头独立 3.3 V 电源（+3.3C），摄像头由独立 LDO 供电以避免数字噪声串入图像链路。电源分配如图 4.1 所示，电源部分原理图如图 4.2 所示。

4.2 电机驱动电路
左右后轮驱动电机与转向电机均采用 TI DRV8701E 栅极驱动器构成 H 桥驱动，主控以 PWM + DIR 方式控制：PWM 频率取 20 kHz，超出人耳听阈以消除啸叫；DIR 引脚高电平为正转。左后轮 PWM 接 P33.5、DIR 接 P33.11；右后轮 PWM 接 P33.12、DIR 接 P33.13；转向电机 PWM 接 P15.2、DIR 接 P15.0。硬件接线阶段曾出现左右电机 PWM 接反的情况，表现为左轮命令驱动右电机，后将左右两组引脚定义整体对调修正，并在代码注释中固化判据"正输出→车轮物理前进"，防止后续维护再次接反。
4.3 车灯与指示电路
车灯系统采用英飞凌 TLD7002 十六通道 LED 驱动器，经 UART（2 Mbaud）与主控通信，实现转向灯、近光灯、远光灯、雾灯与双闪等科目二要求的全部灯语；另配有 8×8 点阵屏，用于显示转向箭头与状态表情，提高车外可读性。PWM 喇叭用于鸣笛科目。
4.4 人机交互与通信接口
人机交互包括 2 寸 IPS200 液晶屏（SPI 接口）、3 只轻触按键与 1 只旋转编码器（TIM6正交解码），构成完整的车载菜单系统；麦克风经 ADC 以 32 kHz 采样、4 倍过采样抽取为8 kHz 音频流，供语音识别使用。通信接口包括：ELRS 遥控接收机（UART9，CRSF 协议，420000 波特）、逐飞 WiFi-SPI 无线模块（图传与虚拟示波器）以及 UART0 调试串口（115200 波特）。主要 I/O 资源分配如表 4.1 所示。

第五章 控制软件与算法设计
5.1 软件总体结构
软件在逐飞科技 TC387 开源库（V3.4.3）基础上开发，底层使用英飞凌 iLLD 驱动。全部业务代码按子系统组织为 Motor、Turn、Pedal、MyEncoder、IMU、Camera_follow、Remote、PID、menu、xf_asr、led_driver、FollowLog 等模块。控制软件主体由三级周期任务构成：2 ms 任务完成转向仲裁、转向位置环与姿态更新；50 ms 任务完成测速、踏板采样与双轮速度闭环；帧事件任务完成图像检测。转向驱动源按"视觉 > 自动（回放/动作）> 遥控 > 踏板"优先级仲裁，任何时刻只有一个源接管执行器，从机制上杜绝混合控制。软件总体流程如图 5.1 所示。

图5.1 软件总体流程图
5.2 视觉目标检测与跟随
5.2.1 基于行程编码的黑圆检测
视觉科目要求跟随带有黑色圆形靶标的目标。检测算法以灰度图单遍行程编码（RLE）完成二值化、连通域标记（CCL）与统计量累加：逐行切出暗色行程段，仅对与上一行重叠的段做并查集合并，面积、包围框与周长在合并过程中增量累加到根节点，运算量为 O(行程段数) 而非 O(暗像素数)，暗区面积大时也不会塌帧。随后对每个候选连通域依次施加面积、长宽比、圆形度（C=4πA/P²，数字图像下理想圆约为 0.62）与相邻帧圆心横向跳变四重筛选；已锁定目标时优先选择圆心跳变最小的候选，首次捕获时选择圆形度最高的候选，兼顾抗干扰与首抓灵敏度。二值化阈值支持手动设定与按已命中圆边缘灰度自适应更新两种模式。
取候选包围框中心作为圆心（与质心近似相等而省去逐像素累加）；圆心相对画面中心列的横向偏差作为转向控制量；取包围框长边作为目标直径估计——透视只会压短某一方向，长边最接近真实直径，对仰视与侧视均鲁棒，按 Z=K/diameter 换算目标距离（K 由已知距离标定）。
5.2.2 云台—车体两级跟随与距离保持
跟随控制分两级：云台舵机先按像素偏差粗对准目标，车体转向再按"像素偏差 + 云台角等效像素"合成转向编码器目标，减小大偏差下车体频繁转向；纵向按直径测距误差经速度增益生成目标速度，并经独立的加速/减速斜坡限制，防止距离突变时车速跳变。视觉给出的左右轮附加速度在最终消费端强制零均值化处理（只保留差速分量、剔除共模分量），且当任一轮将因叠加而反向过零时成对缩放，保证视觉差速不会把车轮拉反转。目标丢失帧数超过门限则安全退出跟随。
5.3 姿态解算
ICM42688 以 500 Hz 更新，采用 Mahony 互补滤波融合陀螺仪与加速度计解算姿态；航向角由四元数解算后经 ±180° 解缠绕得到连续 yaw。上电进行 2000 样本陀螺仪零偏标定，运行中检测到整车静止（轮速 < 30 mm/s 且 |陀螺 z| < 0.8°/s）时以极小学习率（α=0.001）在线缓慢更新零偏，抑制长时间运行的航向漂移。
5.4 航迹记录与自主循迹返回
循迹返回科目分"记录"与"回放"两阶段。记录阶段以 2 ms 周期进行航位推算：由左右轮编码器差分得到里程增量，由滤波后 yaw 积分平面坐标，按 0.03 m 步距存点（转向编码器变化超过 100 计数时加密采样），形成 (s, yaw, x, y) 航迹序列，最多 5000 点，并可存入 Flash 的三个槽位供断电后调用。
回放阶段将当前位置投影到记录轨迹得到进度 s_track（搜索窗向前 0.45 m、向后 0.12 m，单帧前进量限幅防跳变），随后由三项合成转向目标：转向编码器前馈（记录轨迹上同一点的实际转向量）、航向误差 PID 反馈（限幅 ±7° 等效编码器量）与横向偏差修正（增益 30000 计数/m，限幅 ±15000 计数）。前馈承担轨迹复现的主要成分，两项反馈只纠正误差，保证了循迹精度与抗扰能力的平衡。倒车返回时由于同一舵角产生的横摆率方向翻转，航向反馈项须整体取反，否则闭环变为正反馈——这是倒放模式中最关键的一处符号处理。
5.5 返程速度剖面规划
返程速度不是恒定值，而是离线对记录轨迹预计算的速度剖面：以 0.3 m 曲率窗口对每点估计曲率 κ，按横向加速度上限 a_lat 求弯道速度上限 v=√(a_lat/|κ|)，再以最高速度封顶；随后自终点向起点按最大减速度反向传播制动可行性约束，自起点向终点按最大加速度正向传播加速约束，得到全程满足纵横向动力学约束的速度剖面。运行时按 s_track 插值取目标速度。规划参数（最高速度、纵/横向加速度上限、曲率窗口）全部可在菜单中调节并存入 Flash。
5.6 运动控制
5.6.1 电子差速
车体目标速度按自行车模型拆分为左右轮目标：diff = gain·tan(δ)，外轮 v(1+diff)、内轮 v(1−diff)，δ 为车头实际转角，限幅 ±0.6 防止内轮反向。差速系数理论值为 B/(2L)=0.60/(2×0.64)≈0.469，但实车为平行转向（阿克曼率 0）导致先天转向不足，叠加轮胎侧滑，有效差速需求低于理论值，经实车标定取 0.30 左右。记录、回放与手动驾驶三条路径共用同一差速系数。
5.6.2 双轮速度闭环
左右轮各用一路带积分限幅的位置式 PID，周期 50 ms；前馈通道使用台架标定的占空比—速度分段线性表（10 个标定点）直接给出占空比粗值，PID 只补偿残差，显著加快响应并减小积分压力。前馈与反馈叠加后经统一限幅下发 DRV8701E。
5.6.3 转向位置环
转向电机以编码器位置式 PID 闭环，周期 2 ms，含积分限幅与输出死区；转向量程标定为编码器 ±35000 计数对应车头 ±30°，全工程（差速换算、菜单显示、yaw 修正限幅、目标限位）共用这一套标定，避免多套比例并存引起的不一致。转向目标在设定处统一夹到量程以内作为唯一的限位保护。主要控制参数如表 5.1 所示。

5.7 安全机制
针对大质量车模，软件设计了多层安全闭锁：①遥控链路 150 ms 失联即进入闭锁，要求油门回中才重新解锁；②油门踏板带回零闭锁——电机使能上升沿强制上锁，踏板须回零一次才允许输出，防止上电自标定虚高或带油门使能导致车辆冲出；③遥控器独立急停通道触发时同时关闭驱动、转向、视觉、遥控与自动任务，且释放沿不恢复任何开关；④视觉退出后方向与油门分别等待摇杆回中，交权踏板时也要求踏板回零；⑤目标丢失、航向未就绪、转向编码器故障等条件下自动任务拒绝启动。
5.8 人机交互
车载菜单系统由 IPS200 屏幕、3 按键与旋转编码器构成，支持全部控制参数的在线编辑与三组参数（P1~P3）的 Flash 持久化；ELRS 遥控器承担驾驶、调速、一键录制/返回与急停；语音交互链路为"麦克风 ADC 采样（32 kHz 过采样、抽取至 8 kHz）→ WiFi TCP → PC 代理 → 讯飞云端识别 → 命令回传"，以白名单命令控制科目二的灯光与鸣笛，兼顾识别率与行车安全。

第六章 开发工具与调试过程
6.1 开发环境
固件开发使用 AURIX Development Studio v1.10.2（TASKING 编译器），工程在 IDE 内完成编译与烧录；PC 端辅助工具使用 Python 3 编写，单元测试基于 unittest。车端与 PC 间通过WiFi-SPI 无线模块与调试串口交换数据。
6.2 在线观测与日志回放
调试观测手段分两级：在线级使用逐飞助手上位机，经 WiFi 图传查看摄像头二值图与识别框、用虚拟示波器实时观察控制量（图传时针对 188 列非字节对齐做了 192 对齐处理）；离线级使用自研 FollowLog 日志系统，运行中以 0.1 m 步距记录里程、坐标、航向、横向偏差、双轮目标/实际速度与占空比、转向控制量等 25 列数据，赛后经串口以 CSV 文本回传，由 PC 端脚本生成 HTML 交互曲线进行逐段复盘。循迹调参即依靠该日志完成闭环：跑出→回传→曲线定位问题段→改参→复跑。
6.3 调试过程中的典型问题与解决
调试过程中解决的典型问题包括：①左右电机 PWM 接反导致闭环正反馈车轮反转，通过引脚定义整体对调并固化"正输出→物理前进"判据解决；②平行转向机构导致转向不足，表现为高速入弯外侧轮打滑、循迹横向偏差偏大，通过下调电子差速系数至理论值的 70%~90% 并配合横向修正增益整定解决；③无线模块通信中断原在控制核 CPU0 运行，对 500 Hz 控制环造成抖动，迁移至空闲核 CPU2 并降低优先级后消除；④菜单屏幕刷新抢占 32 kHz 音频采样引入宽带噪声，通过中断优先级重排（采样 55 > 菜单 51）解决。

第八章 结论
本队完成了第二十一届竞赛卡丁车组模型车的设计、制作与调试。整车以 TC387QP 四核并行架构为基础，实现了遥控与踏板驾驶、灯光/鸣笛/语音交互、视觉目标跟随以及航迹记录自主循迹返回等全部科目功能。工程上的主要特色包括：按数据流向就近分配的多核任务划分与"采样时刻精度优先"的中断优先级设计；单遍行程编码连通域标记的高效黑圆检测；"前馈为主、反馈纠偏"的循迹返回控制与满足动力学约束的返程速度剖面规划；以及覆盖失联、误操作与交权过程的多层安全闭锁机制。
目前系统仍存在一些不足：原车平行转向机构先天转向不足，电子差速只能在一定程度上补偿，高速过弯性能受机械结构制约；航位推算航向在长时间运行下仍有缓慢漂移，回程终点精度依赖起点对中与零偏标定质量；整车尚无电压/电流在线监测。后续可考虑加装轮速—航向—视觉的多源融合定位、引入电池状态监测，并研究转向机构的阿克曼化改造，以进一步提升性能。

A.1 位置式 PID（带积分限幅）
float Positional_PID(PID_IncTypeDef *PID, float SetValue, float ActualValue, float Max_I)
{
    float PIDInc;
    PID->Ek = SetValue - ActualValue;      // 当前偏差
    PID->Ek_sum += PID->Ek;                // 偏差积分
    if (PID->Ek_sum >  Max_I) PID->Ek_sum =  Max_I;   // 积分限幅, 防饱和
    if (PID->Ek_sum < -Max_I) PID->Ek_sum = -Max_I;
    PIDInc = (PID->Kp * PID->Ek)
           + (PID->Ki * PID->Ek_sum)
           + (PID->Kd * (PID->Ek - PID->last_Ek));
    PID->last_Ek = PID->Ek;
    return PIDInc;
}
A.2 电子差速与双轮速度闭环
/* 电子差速量: diff = gain * tan(delta), delta 为车头实际转角。
 * 自行车模型: 外轮 v*(1+diff), 内轮 v*(1-diff), 限幅 ±0.6 防内轮反向。
 * 记录 / 回放 / 手动三条路径共用, 入参为当前转向编码器原始值。 */
static float imu_follow_compute_diff(float turn_enc)
{
    float delta_rad = Transform_Angle(turn_enc) * (3.14159265f / 180.0f);
    float diff = imu_follow_diff_gain * tanf(delta_rad);
    if (diff >  0.6f) diff =  0.6f;
    if (diff < -0.6f) diff = -0.6f;
    return diff;
}
