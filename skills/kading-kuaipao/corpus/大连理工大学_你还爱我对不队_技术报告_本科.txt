摘要
本文介绍我们面向第二十一届全国大学生智能汽车竞赛卡丁快跑组设计的载人卡丁车控制系统。整车以英飞凌 AURIX TC377 核心板为实时控制器，采用 IMU963RA 三轴陀螺仪与三路增量编码器构建短程惯性导航，其中左右后轮各配置一路编码器，两后轮之间设置一只贴地的中央从动测距轮及独立编码器。左右后轮编码器提供轮速差和航向约束，中央从动测距轮提供车辆相对于地面的实际行驶位移，并用于识别后轮打滑；融合算法通过陀螺零偏估计、位移残差检验和自适应权重抑制轮胎滑移与积分漂移。
针对“如影随形”科目，系统利用彩色摄像头识别引导员衣物上的高对比图案，生成横向偏差与目标距离，结合目标短时预测实现转向和速度闭环；当目标丢失时按分级策略减速、搜索和停车。针对人车交互科目，IM68A130A 硅麦完成语音采集，CI1302离线语言模块进行识别，TC377 将指令解析为灯光、鸣笛、门洞选择和运动动作。硬件包括主控板、后轮双路牵引电机驱动板、前轮转向电机驱动板、功率放大板和灯板接口。

第一章  赛题分析与总体目标
1.1  赛题任务与约束
第二十一届竞赛将卡丁快跑设置为室外赛道组别，使用可载人的指定卡丁车平台。公开科目包括自动驾驶、人车交互和“如影随形”三类任务；本车以编码器与陀螺仪的短程惯导作为主要定位源。
科目1 自动驾驶。任务要点：从发车区出发，按方向依次绕行锥桶，最后倒车进入 1.5 m × 2 m 停车区；本车主要实现：惯导位姿估计、锥桶路点状态机、倒车轨迹与停车判定。
科目2 战场救护。公开任务要点：依据自然语言任务完成灯光、鸣笛、门洞选择和动作区运动；本车主要实现：硅麦采集、离线识别、命令校验、声光和运动执行。
科目3 如影随形。公开任务要点：第一阶段人工驾驶穿越迷宫；第二阶段车辆按记录路径或视觉引导自动返回；本车主要实现：视觉跟随引导员、路径记录/回放、丢失目标安全停车。
1.2  系统设计指标
控制周期。设计目标：1 ms 快速环 / 10 ms 规划环；说明：编码器、IMU 和电机控制放在快速环；视觉和任务状态机放在慢速环。
定位方式。设计目标：IMU963RA 陀螺仪 + 三路增量编码器（左右后轮各一路、中央从动测距轮一路）；说明：中央从动测距轮提供实际地面位移基准，系统完成短程相对定位，并在停车和直行阶段在线校正陀螺零偏。
动作距离误差。设计目标：≤ 0.20 m（目标）；说明：需按实车轮径、脉冲数和载荷重新标定。
转圈角度误差。设计目标：≤ 5°（目标）；说明：以陀螺航向为主、轮速差为约束。
视觉处理帧率。设计目标：≥ 40 frame/s（目标）；说明：160×120 或 188×120 ROI，避免全帧冗余运算。
失效保护。设计目标：目标丢失 1 s 内制动；说明：通信、传感器、驱动器故障均进入安全态。
1.3  方案特点
以“短时间高动态准确、长时间可校正”为原则融合陀螺仪和编码器，适合室外卡丁车在几十米范围内的动作任务。
采用三路增量编码器：左右后轮各一路，另在两后轮之间布置一只贴地的中央从动测距轮及一路编码器。左右后轮编码器用于获取驱动轮速度和轮速差，中央从动测距轮不参与驱动，仅测量车辆相对于地面的实际行驶位移，可用于识别后轮打滑并修正里程估计。
视觉跟随与路径回放共享同一位姿和安全层；视觉短时失效时仍能依靠惯导保持低速，不会立即失控。
主控、驱动、灯光、功放采用分板模块化设计，便于大电流走线、故障更换和规则器件升级。
第二章  整车系统设计
2.1  系统组成
执行层由后轮牵引系统和前轮转向执行机构组成。后轮驱动板控制左右后轮牵引通道，实现车辆前进、后退和制动；前轮转向机构采用有刷直流电机，以目标转角为给定、实际转角为反馈进行位置闭环控制，从而实现模拟舵机功能。前轮转向电机不参与纵向驱动。

2.2  信号与供电分区
载人卡丁车驱动电流大、线束长，电机换向和 PWM 边沿会在地线和电源线上产生明显干扰。系统将动力地和逻辑地在电源入口单点汇接，电机线与编码器/摄像头线分束布置；编码器输入采用上拉、施密特整形和软件去毛刺，IMU 使用独立 3.3 V 低噪声电源。24 V 动力输入经防反接与浪涌抑制后分别供给驱动板和灯板，逻辑侧由 5 V、3.3 V 两级电源供电。
VCCBAT / 24 V。负载：牵引电机、灯板电源；设计措施：防反接、TVS、保险与大容量母线电容。
7.7 V / 6~8 V。负载：灯板驱动芯片；设计措施：独立降压、峰值电流裕量、欠压保护。
5 V。负载：IMU、摄像头、WiFi、功放、语音模块；设计措施：低噪声LDO，敏感模拟部分磁珠隔离。
3.3 V。负载：TC377 I/O、编码器接口；设计措施：低噪声 LDO、就近去耦、完整参考地。
2.3  软件分层与调度
软件采用底层驱动、设备服务、状态估计、运动控制、任务逻辑和安全监控六层结构。所有传感器数据附带时间戳；快速控制中断只执行定长计算，图像和语音解析使用缓冲区在后台运行，避免阻塞电机控制。
1 ms。主要任务：编码器锁存、PWM 更新、故障引脚采样；超时处理：连续超时立即关闭驱动使能。
5 ms。主要任务：IMU 读取、零偏补偿、位姿融合；超时处理：保留上一帧并降低目标速度。
10 ms。主要任务：速度 PI、转向 PD、轨迹跟踪；超时处理：输出限幅并记录故障码。
20~25 ms。主要任务：摄像头处理、目标跟踪；超时处理：丢帧计数触发视觉降级。
100 ms。主要任务：语音、屏幕、参数存储；超时处理：采用非阻塞状态机，不占用控制中断。
第三章  机械与执行系统
3.1  载人卡丁车平台布局
本组使用指定载人卡丁车平台，保留原车车架、转向和制动结构，在不改变承载安全边界的前提下增加控制板、传感器和线束。电池与驱动板布置在电池存储箱正上方，整体重心偏后；摄像头安装在车体后端中轴线上，视线朝向车体后方，跟随时倒车跟随；IMU 固定在车座平缓位置，其 X 轴指向车头、Y 轴指向车体左侧、Z 轴向上。
3.2  转向与驱动
车辆采用后轮二驱结构，左右后轮为动力轮，分别由一台 KY4845-24V 有刷直流电机驱动；单台标称转速为 5000 r/min、功率为 150 W。后轮双路驱动板分别控制左右牵引通道，实现直线同步、差速辅助和故障隔离。前轮转向机构使用 RS380-24V 有刷直流电机，标称转速为 6000 r/min、功率为 15 W；该电机不提供车辆牵引力，仅通过机械转向机构改变前轮转角。控制器以目标转角为给定、实际转角为反馈，通过位置闭环输出 PWM 和方向信号，使普通有刷直流电机以模拟舵机方式工作。
3.3  安全设计
硬件急停串入驱动使能链路，软件失效不能阻止急停断开动力。
启动前检查油门/驱动指令为零、转向处于允许区间、IMU 静止、编码器无跳变。
设置驾驶员在位、通信心跳、驱动故障、母线欠压、视觉丢失和超速等独立故障位。
任何关键故障进入 SAFE_STOP：先将目标扭矩按斜坡降为零，再实施制动并保持声光提示。

第五章  惯性导航与运动控制算法
5.1  传感器标定与同步
系统上电后保持车辆静止 2 s，采集陀螺仪横摆角速度均值作为初始零偏 bg，并以中位数绝对偏差剔除启动抖动。左右后轮编码器与中央从动测距轮编码器同时清零。所有数据换算到统一车体坐标系，三路编码器累计值在 1 ms 中断中锁存，IMU 在 5 ms 任务中读取；融合器通过时间戳将两类增量对齐到同一时刻。
陀螺零偏 bg。方法：静置均值 + 在线微调；更新条件：编码器近零且加速度接近重力；或稳定直行。
轮径比例 kL/kR/kA。方法：分别标定左右后轮与中央从动测距轮的每脉冲位移；更新条件：轮胎、胎压、从动轮压紧程度或载荷改变后重标。
等效轮距 B。方法：多次左右转圈最小二乘；更新条件：机械转向或轮胎规格改变后重标。
安装角 Rb←i。方法：水平静态 + 正前方对准；更新条件：IMU 拆装后重标。
5.2  轮式里程计
设一个周期内左右后轮编码器行程为 ΔsL、ΔsR，中央从动测距轮行程为 ΔsA，左右后轮编码器的等效轮距为 B。先计算后轮平均行程 Δsd 和编码器航向增量 Δψe：
Δsd = (ΔsL + ΔsR) / 2，    Δψe = (ΔsR - ΔsL) / B，    Δs = β·ΔsA + (1-β)·Δsd
中央从动测距轮位于两后轮之间并保持贴地，不参与车辆驱动，因此其行程 ΔsA 作为实际地面位移基准。系统比较后轮平均行程 Δsd 与 ΔsA 的残差 es=|Δsd-ΔsA|：残差正常时综合三路数据，残差超过阈值时判定后轮可能打滑，并提高中央从动测距轮权重 β；若从动轮悬空或脉冲异常，则令 β=0，暂时使用左右后轮平均行程。
5.3  陀螺仪与编码器融合
陀螺航向增量 Δψg=(ωz-bg)Δt 对快速转向响应准确，但零偏会随时间积累；编码器航向在低动态时稳定，但载人加速、急转或地面湿滑时会受轮胎滑移影响。本系统采用带残差检验的自适应互补融合：
Δψ = α·Δψg + (1-α)·Δψe，    α = clamp(α0 + kv|v| + kr|Δψg-Δψe|, 0.65, 0.98)
车速越高或两路航向残差越大，越倾向信任陀螺仪；低速平稳转向时适当引入编码器航向以抑制零偏。更新后的位姿为 xk=xk-1+Δs·cos(ψk-1+Δψ/2)，yk=yk-1+Δs·sin(ψk-1+Δψ/2)，ψk=wrap(ψk-1+Δψ)。

5.4  漂移抑制与故障降级
零速更新：左右后轮与中央从动测距轮三路速度均小于阈值时冻结位置积分，并将陀螺输出缓慢收敛到零偏。
直行偏置估计：转向指令接近中位且左右轮速差很小时，将低频航向变化用于微调 bg。
轮滑检测：比较左右后轮平均位移与中央从动测距轮位移残差，并结合纵向加速度及陀螺/编码器航向残差判断后轮打滑；打滑时降低后轮位移权重，提高中央从动测距轮权重。
IMU 异常：数据超量程、校验错误或时间戳停滞时仅用编码器低速运行；编码器异常时仅允许短时陀螺维持并立即降速。
5.5  速度与转向控制
速度环采用带积分限幅和前馈的增量式 PI。目标速度由任务状态机、曲率限速、视觉距离和安全层共同取最小值；转向采用前视点轨迹误差与航向误差的 PD 控制，并叠加曲率前馈。载人时降低加速度和舵量变化率，避免指令突变。
uδ = Kp·ey + Kψ·eψ + Kd·d(ey)/dt + Kff·κ，    vref = min(vtask, vcurve, vvision, vsafe)
第六章  科目实现策略
6.1  科目1：自动绕桩与倒车入库
科目1在赛前将锥桶中心和停车区角点录入为相对坐标，或由人工低速示教生成路点。发车后，状态机按给定方向依次切换锥桶绕行侧，路径由圆弧—直线—圆弧段拼接。每通过一个锥桶，利用惯导位姿和累计里程双条件确认，防止定位抖动造成重复计数。最后车辆在停车区入口前减速、对正，切换倒车速度和反向转向控制，以车体包络进入 1.5 m × 2 m 区域为完成条件。
1.  发车自检并将当前位姿设为 (0,0,0)，缓慢前进建立编码器方向。
2.  按锥桶序列生成下一目标点，前视距离随车速在 1.5~4.0 m 之间调整。
3.  进入锥桶邻域后降低速度，依靠航向增量完成绕行并切换下一锥桶。
4.  到达停车区入口线后停车 0.3 s，重新估计陀螺零偏并切换倒车控制。
5.  倒车进入后利用累计后退距离、航向角与四角安全边界联合判定，制动并锁止。
6.2  科目2：自然语言人车交互
语音任务按“采集—识别—校验—排队—执行—确认”处理。TC377 通过 ADC 采集硅麦数据，能量门限检测到讲话后保存语音帧并经 WiFi 上传；识别文本通过关键词表映射为结构化命令。只有命令类别、参数和所在区域同时合法时才入队，避免相似发音直接触发车辆动作。
发车区。命令类别：左/右转向灯、远/近光、雾灯、双闪、车内照明、雨刷；执行要点：TLD7002 或合规点阵子板显示；每次动作保留足够观察时间。
停车区。命令类别：鸣笛 1/2/3 s、2/3/4 声、长短鸣笛、急促鸣笛、警报鸣笛；执行要点：PAM8302A 驱动 ≥2 W 扬声器；采用非阻塞定时序列。
行进区。命令类别：通过门洞1左侧、门洞1/2/3、门洞3右侧及相应返回；执行要点：将门洞选项转换为路径模板，惯导执行并限速。
动作区。命令类别：前进/后退、蛇形、顺/逆时针转圈、左/右转；执行要点：距离与角度由融合位姿闭环，完成后自动停车。
安全门：语音识别结果不会直接写 PWM；车辆动作必须经过区域合法性检查、二次确认、速度上限和急停状态检查。
6.3  科目3：如影随形
第一阶段由参赛队员人工驾驶穿越重新布置的锥桶迷宫，TC377 同时记录时间戳、融合位姿、车速和转向角，按距离自适应抽稀形成回放轨迹。第二阶段车辆从停车区自动出发，沿逆序轨迹返回发车区。规则要求第一阶段使用机器视觉跟随引导员，系统在摄像头图像中识别引导员衣物上的高对比图案，并用图案中心控制横向偏差、图案面积估计跟随距离。

图6.1  视觉跟随处理链
图像首先裁剪地平线以下 ROI，再进行亮度归一化和 HSV 阈值分割；对连通域按面积、长宽比和与上一帧预测位置的距离打分，选择得分最高者作为引导目标。α-β 滤波器预测目标短时运动，横向误差 ex=(ucx-u0)/W 进入转向 PD，目标面积或包围框高度构成距离误差进入速度 PI。惯导轨迹用于目标短时遮挡时的低速保持，并在第二阶段直接参与路径回放。
TRACK。判据：连续检测且置信度高；车辆行为：视觉横向控制 + 惯导限速，正常跟随。
PREDICT。判据：丢失 < 0.3 s；车辆行为：使用滤波预测，目标速度降至 60%。
SEARCH。判据：丢失 0.3~1.0 s；车辆行为：低速沿最后方向小角度搜索，禁止加速。
STOP。判据：丢失 > 1.0 s 或置信度突降；车辆行为：制动停车，双闪和蜂鸣提示，等待重新捕获。
6.4  任务状态机与统一安全层
三个科目共用驱动、定位与安全接口。任务状态机仅产生目标位姿、速度和声光动作，不直接控制硬件；安全层逐周期检查急停、超速、目标丢失、传感器超时、驱动故障和母线电压，并可覆盖上层目标。更换科目逻辑或国赛 AI 模块时，底层行为仍保持一致。
IDLE。进入条件：上电或任务结束；输出与转移：驱动禁用；按键与驾驶员确认后进入 SELF_CHECK。
SELF_CHECK。进入条件：急停释放，IMU 静置，编码器/驱动在线；输出与转移：清零位姿并装载科目参数；检查通过进入 RUN。
RUN。进入条件：科目开始且安全层允许；输出与转移：输出目标位姿、速度和声光序列；到达终点进入 BRAKE。
BRAKE。进入条件：科目完成、目标丢失或软限速触发；输出与转移：斜坡降速并制动；车速归零后进入 FINISH。
FINISH。进入条件：车辆已停稳；输出与转移：关闭驱动使能，给出完成提示，等待复位。
FAULT。进入条件：急停、驱动故障、传感器超时或母线异常；输出与转移：立即撤销动力并保持制动；仅人工排障后复位。
第七章  调试、测试与风险控制
7.1  分阶段调试流程
1.  台架调试：断开电机负载，检查各电源轨、驱动使能默认态、编码器方向和 IMU 数据。
2.  空载低速：验证左右后轮编码器方向、中央从动测距轮贴地状态及三路位移一致性，同时检查转向中位、急停链路和安全状态机。
3.  载人直线标定：测量轮径比例、制动距离和加速度上限，禁止直接进入高速。
4.  单动作调试：分别完成前进、后退、转圈、蛇形、门洞和灯光/鸣笛序列。
5.  科目联调：按比赛状态机串联任务，增加重复试验和传感器故障注入。
6.  场地复核：按最终锥桶位置、光照、载荷和网络条件重新确认参数。
第八章  总结
本文完成了卡丁快跑载人卡丁车的机械布置、主控与驱动硬件、陀螺仪—编码器融合惯导、视觉跟随、语音交互和安全状态机设计。定位系统采用左右后轮编码器和中央贴地从动测距轮编码器共三路数据：左右后轮提供轮速差与航向约束，中央从动测距轮提供实际地面位移基准，IMU963RA 提供高动态航向。系统根据位移残差和运行工况自适应调整权重，实现绕桩、门洞、蛇形、转圈与倒车入库所需的相对位姿闭环。
摄像头跟随采用轻量化传统视觉与滤波预测，避免将关键安全控制完全交给不可解释模型；第一阶段视觉跟随与惯导轨迹记录同步，第二阶段可直接回放反向轨迹。后续工作重点是完成载人实测参数、TLD4020 点阵子板合规核对、复杂光照下视觉阈值自适应和最终国赛人工智能任务的接口适配。

A.1  陀螺仪—编码器融合位姿更新

typedef struct {
    float x, y, yaw, v;
    float gyro_bias;
    float encoder_scale[3];   // left rear, right rear, center auxiliary
    uint32_t stamp_us;
    uint8_t valid;
} NavState;

static float wrap_pi(float a)
{
    while (a >  PI) a -= 2.0f * PI;
    while (a < -PI) a += 2.0f * PI;
    return a;
}

void nav_update(NavState *s, const ImuFrame *imu,
                const EncoderFrame *enc, float dt)
{
    float ds_l = enc->delta[0] * s->encoder_scale[0];
    float ds_r = enc->delta[1] * s->encoder_scale[1];
    float ds_a = enc->delta[2] * s->encoder_scale[2];

    float ds_drive = 0.5f * (ds_l + ds_r);
    float dpsi_enc = (ds_r - ds_l) / g_param.track_width;
    float dpsi_gyro = (imu->gyro_z - s->gyro_bias) * dt;

    bool aux_valid = (enc->valid_mask & 0x04u) != 0u;
    float slip_residual = fabsf(ds_drive - ds_a);
    bool rear_slip = aux_valid &&
                     slip_residual > g_param.slip_threshold;

    float beta_aux = aux_valid ? (rear_slip ? 0.90f : 0.65f) : 0.0f;
    float ds = beta_aux * ds_a + (1.0f - beta_aux) * ds_drive;

    float yaw_residual = fabsf(wrap_pi(dpsi_gyro - dpsi_enc));
    float alpha = g_param.alpha0
                + g_param.alpha_speed * fabsf(s->v)
                + g_param.alpha_residual * yaw_residual;
    alpha = clampf(alpha, 0.65f, 0.98f);
    if (rear_slip)   alpha = 0.98f;
    if (!imu->valid) alpha = 0.00f;

    float dpsi = alpha * dpsi_gyro + (1.0f - alpha) * dpsi_enc;
    float yaw_mid = s->yaw + 0.5f * dpsi;
    s->x   += ds * cosf(yaw_mid);
    s->y   += ds * sinf(yaw_mid);
    s->yaw  = wrap_pi(s->yaw + dpsi);
    s->v    = lowpass(ds / dt, s->v, g_param.v_lpf);

    bool stopped = fabsf(ds_l) < g_param.stop_ds &&
                   fabsf(ds_r) < g_param.stop_ds &&
                   fabsf(ds_a) < g_param.stop_ds;
    if (stopped && imu_is_static(imu)) {
        s->gyro_bias += g_param.bias_gain *
                        (imu->gyro_z - s->gyro_bias);
    }
    s->valid = imu->valid || ((enc->valid_mask & 0x07u) != 0u);
    s->stamp_us = imu->stamp_us;
}
A.2  速度 PI 与轨迹转向控制

typedef struct {
    float kp, ki, integral, out_limit, i_limit;
} PIController;

float speed_pi_step(PIController *c, float target, float measured,
                    float feedforward, float dt, bool enable)
{
    if (!enable) {
        c->integral = 0.0f;
        return 0.0f;
    }
    float error = target - measured;
    float unsat = feedforward + c->kp * error + c->integral;
    float output = clampf(unsat, -c->out_limit, c->out_limit);

    // Conditional integration: do not integrate deeper into saturation.
    bool release = (output == unsat) || (output > 0.0f && error < 0.0f)
                                  || (output < 0.0f && error > 0.0f);
    if (release) {
        c->integral += c->ki * error * dt;
        c->integral = clampf(c->integral, -c->i_limit, c->i_limit);
    }
    return output;
}

float steering_step(const NavState *nav, const PathRef *ref, float dt)
{
    static float last_ey = 0.0f;
    float ey   = ref->cross_track_error;
    float epsi = wrap_pi(ref->heading - nav->yaw);
    float dey  = (ey - last_ey) / dt;
    last_ey = ey;

    float cmd = g_steer.kp_yaw * epsi
              + g_steer.kp_y   * ey
              + g_steer.kd_y   * dey
              + g_steer.kff    * ref->curvature;
    cmd = rate_limit(cmd, g_steer.last_cmd, g_steer.max_rate * dt);
    return clampf(cmd, -g_steer.max_cmd, g_steer.max_cmd);
}
A.3  摄像头目标提取与丢失降级

bool vision_extract_target(const Image *img, Target *target)
{
    Blob best = {0};
    float best_score = -1.0f;
    normalize_roi(img, &g_work.roi);
    hsv_threshold(&g_work.roi, &g_work.mask, g_vision.hsv_min, g_vision.hsv_max);
    morph_open_close(&g_work.mask, 2);

    BlobList blobs = connected_components(&g_work.mask);
    for (int i = 0; i < blobs.count; ++i) {
        Blob b = blobs.item[i];
        if (b.area < g_vision.min_area || b.area > g_vision.max_area) continue;
        if (!ratio_in_range(b.width, b.height, g_vision.ratio_min,
                            g_vision.ratio_max)) continue;
        float motion_cost = distance2(b.cx, b.cy, g_tracker.pred_x, g_tracker.pred_y);
        float score = 2.0f * b.fill_ratio + 0.002f * b.area
                    - g_vision.motion_weight * motion_cost;
        if (score > best_score) { best = b; best_score = score; }
    }
    if (best_score < g_vision.accept_score) return false;
    target->x = best.cx;
    target->y = best.cy;
    target->area = best.area;
    target->confidence = clampf(best_score, 0.0f, 1.0f);
    return true;
}

void follower_step(const Target *t, bool detected, float dt)
{
    tracker_predict(&g_tracker, dt);
    if (detected) {
        tracker_correct(&g_tracker, t->x, t->y, t->area);
        g_tracker.lost_time = 0.0f;
        g_follow.state = FOLLOW_TRACK;
    } else {
        g_tracker.lost_time += dt;
        if (g_tracker.lost_time < 0.30f)      g_follow.state = FOLLOW_PREDICT;
        else if (g_tracker.lost_time < 1.00f) g_follow.state = FOLLOW_SEARCH;
        else                                  g_follow.state = FOLLOW_STOP;
    }

    float ex = (g_tracker.x - CAMERA_CX) / CAMERA_WIDTH;
    float ed = g_vision.target_area - g_tracker.area;
    MotionSetpoint sp = follow_policy(g_follow.state, ex, ed);
    motion_submit(SRC_VISION, &sp); // safety layer arbitrates the final command
}
A.4  科目状态机与安全仲裁

typedef enum {
    TASK_IDLE, TASK_SELF_CHECK, TASK_RUN, TASK_BRAKE,
    TASK_FINISH, TASK_FAULT
} TaskState;

void task_10ms(void)
{
    SensorSnapshot ss = sensor_snapshot();
    safety_update(&ss);
    nav_update_if_ready(&g_nav, &ss);

    switch (g_task.state) {
    case TASK_IDLE:
        if (start_key_pressed()) g_task.state = TASK_SELF_CHECK;
        break;
    case TASK_SELF_CHECK:
        if (safety_ready() && imu_static_ok() && driver_confirmed()) {
            nav_reset(&g_nav);
            g_task.state = TASK_RUN;
        }
        break;
    case TASK_RUN:
        course_dispatch(g_task.course, &g_nav, &ss, &g_setpoint);
        if (course_finished()) g_task.state = TASK_BRAKE;
        break;
    case TASK_BRAKE:
        safe_brake_ramp(&g_setpoint);
        if (fabsf(g_nav.v) < 0.05f) g_task.state = TASK_FINISH;
        break;
    case TASK_FINISH:
        drive_disable();
        signal_finish();
        break;
    default:
        drive_disable();
        signal_fault(safety_fault_code());
        break;
    }

    if (safety_critical_fault()) g_task.state = TASK_FAULT;
    motion_control_step(&g_nav, &g_setpoint, &ss);
}
