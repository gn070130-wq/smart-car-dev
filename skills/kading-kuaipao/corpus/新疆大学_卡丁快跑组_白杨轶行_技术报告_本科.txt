第一章　引言
1.1　竞赛背景与赛题简介
第二十一届全国大学生智能汽车竞赛是由教育部倡导、面向全国大学生开展的智能汽车创新实践竞赛活动。竞赛以智能汽车为对象，鼓励参赛队员综合运用控制、传感器、信号处理、模式识别、嵌入式系统、车辆工程等多学科知识，独立完成模型车的设计、制作与调试，培养大学生的创新意识、工程实践能力与团队协作精神。
本参赛队参加的卡丁快跑（本科）组别，比赛科目依据赛程分为省赛与国赛两个阶段。
省赛（分赛区）阶段共设三个科目。科目1自动驾驶：比赛场地在室外操场，包含发车区、锥桶绕行区与倒车入库区，车模需从发车区自动出发，按照给定方向依次绕行所有锥桶之后，在倒车入库区完成倒车入库（停车区门口宽1.5m、车库长2m，门口与库底四角以锥桶标识）。科目2战场救护（人机交互）：通过自然语言控制车模完成发车区灯光（左/右转向灯、远/近光灯、雾灯、双闪、车内照明、雨刷共8种）、停车区鸣笛（鸣笛1/2/3秒、2/3/4声、长短鸣笛、急促鸣笛、警报鸣笛共9种，采用2W以上无源扬声器）、行进区通过门洞与动作区车模运动等任务，语音由安装在车模上的英飞凌IM68A130A硅麦采集，经"离线语音识别芯片+硅麦"完成语音转文字与识别。科目3如影随形（穿越迷宫）：赛前重新摆放锥桶，不允许进行位置定位；第一阶段车模从发车区出发沿规定迷宫路径绕行至停车区，第二阶段根据第一阶段路径自动绕行返回发车区，成绩为两阶段用时之和。省赛阶段允许队员驾驶或遥控车模完成科目3迷宫绕行。
国赛（全国总决赛）阶段，为适应室外天气变化对比赛进程的影响，组委会将室外各赛题组别的三个比赛科目合并为统一的综合比赛科目。卡丁快跑组别将科目二与科目三融合，形成带语音任务的科目三：车模从发车区出发，跟随参赛队员沿规定迷宫路径绕行至停车区（国赛要求车模跟随队员完成迷宫绕行，禁止遥控引导），随后根据第一阶段记录的路径自动绕行返回发车区；回到科目三发车区后，通过语音指令完成灯光任务与鸣笛任务即可，不再比赛科目1。比赛成绩为跟随、自动返回与语音任务对应用时之和。
依据上述赛制，本队以国赛综合科目为主要目标设计并实现了整套系统：以摄像头色块识别实现科目3第一阶段的跟随队员，以基于"陀螺仪航向角"的惯性导航（录迹-回放）实现第二阶段的自动返回，以离线语音识别芯片+IM68A130A硅麦实现回到发车区后的灯光与鸣笛语音任务。开发初期曾尝试GPS航点导航方案，由于室外定位精度不足、更新率低且易受场地与天气干扰，最终弃用，系统全部导航功能均由惯性导航实现，具体技术方案见1.2节，软件实现见第五章。
1.2　系统总体设计思路与技术方案概要
本系统以英飞凌TC264D双核微控制器为核心，在遥控车模平台上集成了环境感知、运动控制、任务调度三大子系统。环境感知与定位子系统由SCC8660彩色摄像头、IMU963R九轴惯性测量单元、带方向编码器与AS5047P磁编码器组成，分别承担目标识别、航向姿态解算、轮速与转向角度测量等任务，其中定位采用基于陀螺仪航向的惯性导航方式；运动控制子系统由后轮双路驱动电机与前轮转向电机及其驱动电路构成，通过增量式PID速度闭环与位置式PID转向闭环实现精确运动控制；任务调度子系统则根据不同的驾驶场景，在"语音指令驱动"与"摄像头目标跟随/惯性航迹复现"两种工作模式之间灵活切换。
系统总体技术方案可概括为：以双核分工与中断任务调度保证控制的实时性；以"陀螺仪航向角"的惯性导航（录迹-回放）实现科目3第二阶段的自动返回；以HSL颜色空间色块识别实现科目3第一阶段对队员的目标跟随；以串口帧协议解析实现离线语音指令的接收与执行（灯光、鸣笛）；以PID控制与阿克曼转向几何模型保证行驶的平稳性与路径跟踪精度。开发期曾尝试GPS航点导航，因室外定位精度不足而弃用。硬件部分与机械部分的详细设计见第三章、第四章，软件部分的核心算法与实现见第五章。

2.3　系统软件总体架构与任务划分
软件系统基于逐飞科技TC264开源库编写，采用"主循环+多级中断"的架构。TC264D双核处理器中，核心0负责系统初始化与主业务循环，核心1保留空闲。实时性要求高的任务分别放入不同优先级的PIT周期中断中执行，周期性较强的传感器采集与控制输出在中断内完成，逻辑相对复杂、实时性要求较低的任务（按键扫描、屏幕刷新、语音解析）在主循环或低频中断中完成。

2.4　系统工作流程
系统上电后首先完成系统时钟、串口、PIT中断、摄像头、屏幕、车灯、蜂鸣器、按键、IMU、PWM、编码器等外设的初始化，随后进入主循环。系统软件围绕国赛综合科目（带语音任务的科目3）组织工作流程，共分为三个阶段。
阶段一（跟随队员）：车模从发车区出发，系统通过摄像头识别队员佩戴的黄色色标，实时计算目标方位角与距离并控制车模跟随行驶，同时按里程间隔记录航向角，将行进轨迹存入航迹数组。该阶段对应科目3第一阶段。
阶段二（自动返回）：车模到达停车区后，系统切换至惯性导航回放模式，依据阶段一记录的航迹，以倒车方式沿原路径自动行驶返回发车区。该阶段对应科目3第二阶段，全程无需GPS等外部定位。
阶段三（语音任务）：车模回到发车区停车后，系统进入语音指令模式。离线语音识别芯片（配合IM68A130A硅麦）将灯光、鸣笛类语音口令转换为帧协议指令，通过串口发送给主控，主控解析后按规定的时序依次执行发车区灯光任务与停车区鸣笛任务。
在省赛阶段，上述模式分别对应科目2（语音指令驱动）与科目3（摄像头跟随/航迹复现）两个独立科目，其中科目3迷宫绕行允许队员驾驶或遥控车模完成，工作流程与国赛综合科目一致。

第五章　软件系统设计
本章是技术报告的核心部分，详细阐述模型车软件系统的总体架构以及图像识别、姿态解算、运动控制、惯性导航（录迹-回放）、语音指令解析与灯光鸣笛控制等关键模块的设计思想与实现方法。
5.1　软件总体架构
软件系统基于逐飞科技TC264开源库与官方SDK编写，全部代码采用C语言实现，存放于工程code目录下的各功能模块文件中，主要包括：init（系统初始化）、Motor（电机与编码器驱动）、PID（闭环控制）、IMU（姿态解算）、navigation（惯性导航/录迹回放）、mike（语音指令解析）、color_tracer（色块识别）、Beep（鸣笛）、filter（滤波算法）以及Function（主流程控制）等模块。开发阶段编写的GPS航点导航模块因室外定位精度不足，未在正式比赛中启用。
按比赛科目划分，系统功能模块与科目的对应关系为：科目3（如影随形）由图像采集与色块识别模块（5.2节）实现第一阶段对队员的目标跟随，由惯性导航（录迹-回放）模块（5.5节）实现第二阶段自动返回发车区；国赛综合科目的灯光与鸣笛语音任务由语音指令解析执行模块（5.7节）与灯光鸣笛控制模块（5.8节）实现。省赛阶段的科目2（战场救护）同样由语音与灯光鸣笛模块完成，科目1（自动驾驶）在国赛阶段不再比赛。
系统采用"双核+多中断"的运行框架：核心0运行主循环，负责初始化、按键检测与模式切换；各PIT中断按不同周期分别执行IMU解算、电机闭环、编码器采集、鸣笛与指令调度等实时任务。系统级状态由全局结构体N（Nag）中的Nag_SystemRun_Index表征，取值含义为：0为停机、1为录制航迹、3为回放航迹。驾驶模式由kemu2_flag标志区分，0为科目3（摄像头跟随/航迹回放）模式，1为科目2（语音指令）模式。
系统的控制回路为串级结构：外环为导航/感知环，依据摄像头色块位置或录迹航向偏差计算期望转向角与期望差速；内环为电机闭环，转向电机采用位置式PID闭环跟踪期望转向角，驱动电机采用增量式PID闭环跟踪期望轮速。整个控制链路在10ms周期中断内完成。
5.2　图像采集与色块识别算法
5.2.1　SCC8660图像采集
摄像头采用逐飞SCC8660彩色摄像头，输出分辨率为160×120，像素格式为RGB565。图像数据通过并行数据线D0~D7传输，PCLK作为像素时钟触发DMA搬运，VSYNC作为场同步信号通过外部中断触发一帧图像的DMA采集。一帧图像由DMA写入scc8660_image[120][160]二维数组，采集完成后置位scc8660_finish_flag标志，主循环检测到该标志后调用图像处理函数。
由于图像采集由DMA在后台完成，不占用CPU时间，主循环在图像处理的同时可并行执行按键扫描、屏幕刷新等任务，保证了图像帧率与系统其他任务的实时性。
5.2.2　RGB565到HSL颜色空间转换
为降低光照变化对色块识别的影响，算法首先将RGB565像素转换为HSL颜色空间。颜色空间转换函数rgbtohsl依据RGB三通道的最大值与最小值计算色调H、饱和度S与亮度L，取值范围均为0～240。其中色调的计算对RGB分量差值作分段线性映射，避免了因硬件响应差异造成的色偏影响。
识别前可通过短按KEY_4，以图像中心像素为基准调用set_color_target_condi函数自动标定目标颜色的HSL阈值范围（色调±20、饱和度±40、亮度±40），从而适应不同光照与不同目标颜色的标定需求。
5.2.3　色块搜索与腐蚀迭代算法
色块识别算法由"搜索中心点"与"腐蚀迭代"两步组成。searchcentre函数在图像中按目标最小宽高的1/3为步长进行粗搜索，对每个候选窗口沿十字方向采样并逐一进行颜色匹配，采用容错机制（每1<<ALLOW_FAIL_PER个采样点允许一个错误点）增强对噪点的鲁棒性，命中后返回色块中心坐标。
得到初始中心点后，corrode函数以该点为中心分别向上、下、左、右四个方向扫描，统计连续满足颜色阈值条件的像素长度，从而确定色块的上下左右边界，进而计算色块的中心坐标(x,y)与宽高(w,h)。为逼近真实色块边界，算法对腐蚀过程迭代执行ITERATE_NUM=5次。若腐蚀得到的宽高满足设定的最小/最大尺寸约束，则判定识别成功，否则返回失败。
为提高连续帧的处理效率，算法将上一帧识别到的色块中心及尺寸作为本帧的搜索区域，在目标运动连续的前提下可大幅缩小搜索范围，减少计算量。
5.2.4　目标方位角计算
识别到目标色块后，根据目标中心横坐标相对图像中心的偏移量，按下式计算目标的方位角：
camera_target_angle = (target_pos_out.x - SCC8660_W/2) × camera_max_angle / (SCC8660_W/2)
式中camera_max_angle取25°，即当目标出现在图像最左/最右侧时对应±25°的转向角。该方位角直接驱动转向电机与左右轮差速，实现科目3第一阶段对佩戴黄色色标的参赛队员的实时跟随；同时依据色块高度判断目标距离，控制跟随车模的停驶与行进，保证与队员保持合适的安全间距。
5.3　姿态解算与航向角获取
5.3.1　IMU963RA初始化与零漂校正
航向测量采用IMU963RA九轴惯性测量单元，通过SPI接口读取加速度与角速度数据。系统上电初始化时执行gyroOffsetInit函数，连续采集200次陀螺仪原始数据并求平均，得到陀螺仪的三轴零点偏移值，供后续数据采集时扣除，消除陀螺仪静态零漂。
5.3.2　加速度与角速度预处理
在3ms周期中断中读取IMU原始数据后，icmGetValues函数对加速度数据进行一阶低通滤波（滤波系数alpha=0.3），平滑掉加速度计的高频振动噪声；对角速度数据扣除零漂并转换为国际单位，保证后续积分解算的数值一致性。
5.3.3　航向角积分解算
车模行驶在近似水平路面，航向变化主要体现在绕竖直轴的转动。系统采用yawhan函数对Z轴角速度进行积分得到航向角yaw1，并通过yaw2 = -yaw1将方向统一为"顺时针为正、取值范围0～360°"，与常用的地理方位角定义保持一致，便于后续惯性导航中作航向偏差比较。积分前对原始角速度进行滤波取整，降低量化噪声。
为防止长时间积分导致的航向漂移，系统同时实现了基于四元数与互补滤波的姿态解算函数icmAHRSupdate：利用加速度计估计的重力矢量与四元数预测重力矢量之间的叉积误差，通过PI控制器对陀螺仪角速度进行反馈校正，再以四元数微分方程更新姿态。该解算可作为Z轴积分方案在动态场景下的交叉校验与备用方案。
5.4　电机控制算法
5.4.1　驱动电机速度闭环
左右后轮各由一路独立电机驱动，分别配置一路正交增量式编码器（1024线，减速比1:2）测速。编码器在1ms周期中断中采集，每100ms执行一次测速更新：以当前采样周期的脉冲数除以采样时间换算为转速（MotorRpm）。原始脉冲序列经一维卡尔曼滤波器平滑后参与计算，有效抑制了编码器量化噪声。
速度环采用增量式PID控制器，控制量输出为PWM占空比增量，左右轮分别整定参数（左轮Kp=4.0、Ki=0.6、Kd=0.2；右轮Kp=3.5、Ki=0.6、Kd=0.2）。为防止起步猛冲，对单次输出增量限幅为±800；对累计占空比整体限幅为±6000。PWM频率10kHz，通过H桥驱动电路控制电机正反转与调速。
5.4.2　转向电机位置闭环
前轮转向由直流电机经减速机构驱动，转向角度通过AS5047P磁编码器反馈。AS5047P为14位绝对值编码器，输出0～16384计数值。程序通过过零处理与多圈累加获得多圈绝对角度total_encoder：相邻两次读数的差值超过半圈量程（±8192）时判定发生越零并更新圈数，从而实现超越单圈范围的连续角度测量。上电后自动采集前10帧求平均完成标零，并将角度值按0.00006的系数规范到±25°量纲。
转向环采用位置式PID控制器（Kp=390、Ki=0.9、Kd=1），以目标转向角与当前转角之差计算PWM占空比，带死区处理（占空比小于600时输出0）以避免转向电机在目标位置附近的抖动。
5.4.3　阿克曼转向差速模型
为保证弯道行驶时内外后轮无滑动、转向平稳，系统采用阿克曼转向几何模型计算左右后轮的差速。已知轴距L=0.65m，后轮轮距约0.60m，当期望转向角为angle时，转向半径R由下式近似计算：
R = L / tan(|angle|)
左、右后轮的目标速度按内外侧半径比例分配：
Speed_L = V·(R + d/2)/R，　Speed_R = V·(R − d/2)/R（右转）
Speed_L = V·(R − d/2)/R，　Speed_R = V·(R + d/2)/R（左转）
式中d为后轮轮距（取0.60m），V为期望车速。该模型同时应用于摄像头目标跟随（isr_fun模块）与惯性导航回放（navigation模块）两种场景，实现转向角到差速的平滑映射。
5.5　惯性导航（录迹-回放）
系统定位导航采用基于陀螺仪航向角与编码器里程计的惯性导航方案，以"录迹-回放"方式实现科目3第二阶段沿原路径自动返回发车区。该方法属于纯自主导航，无需依赖GPS等外部信标，仅凭自身航向与里程即可记录并复现行驶轨迹，抗干扰能力强、实现简单。
5.5.1　航迹记录（Nag_Read）
录迹模式下（Nag_SystemRun_Index=1），系统以编码器脉冲为里程依据，由左右轮平均里程累计行进距离。每累计达到设定里程间隔Nag_Set_mileage=500个脉冲，即将当前航向角yaw2放大100倍取整后写入航迹数组Nav_read[]，并扣除该间隔里程，如此往复形成等间距航迹点序列。录迹状态由N.Save_index管理，记录结束时的残余里程保留在N.Mileage_All中。
5.5.2　航迹复现与预瞄控制（Nag_Run / Nag_Run_Control）
回放模式下（Nag_SystemRun_Index=3），系统按记录序列的逆向依次读取航迹点（read_idx = Save_index-1-Run_index），即沿原轨迹反向行驶。行驶过程中同样以里程驱动换点，逐点推进。
为改善路径跟踪的动态性能，Nag_Run_Control采用预瞄控制：以当前已消耗的航迹点数为基准，向前预瞄11个点，通过线性插值求取目标航向，再与当前航向角yaw2作差得到航向偏差error。偏差经360°归一化处理并限幅在±25°，避免大角度跳变。将偏差输入阿克曼转向模型得到转向角与左右轮差速，从而实现沿原轨迹的回放行驶。当回放点接近轨迹终点（剩余点数小于80）时置位停车标志N.Nag_Stop_f，车辆减速停车。
5.6　导航方案选型与惯性导航误差处理
5.6.1　导航方案选型
开发初期曾选用GPS航点导航方案，期望通过室外绝对定位实现定点行驶。经场地试验发现，室外GPS定位精度不足（静态漂移与路径偏差明显）、更新率低，且易受场地遮挡与天气影响，无法满足迷宫路径精确记录与复现的要求，故最终弃用GPS方案，改用完全自主的惯性导航方案。
惯性导航不依赖任何外部信标：航向由IMU963RA陀螺仪积分获得，里程由后轮编码器脉冲累计获得，两者结合即可描述车模在地面上的相对运动轨迹，适用于迷宫等无标识环境下的路径记录与复现。
5.6.2　惯性导航误差来源与处理
惯性导航的主要误差来自陀螺仪零漂、量化噪声与长时间积分漂移。系统通过以下措施抑制误差：上电时连续采集陀螺仪200次求平均得到零漂值并扣除；3ms周期内对角速度进行一阶低通滤波与取整处理；航向角作360°归一化处理。由于科目3的跟随与返回任务路程短、时长小，航向角积分漂移在比赛尺度内可控制在允许范围内。
5.7　语音指令解析与执行系统
语音指令解析与执行系统用于实现科目2（战场救护/人机交互）。系统采用规则所允许的"离线语音识别芯片+英飞凌IM68A130A硅麦"方案：IM68A130A硅麦采集语音，离线语音识别芯片完成语音转文字与命令识别，识别结果以自定义帧协议通过串口发送给主控。
5.7.1　串口接收与FIFO缓存
离线语音识别模块识别到语音后，以自定义帧协议通过UART2（115200bps）发送指令。串口接收中断将每个字节写入环形FIFO缓冲区（容量128字节），主循环通过fifo_read_buffer逐字节取出解析。采用FIFO能够有效解耦串口中断与解析处理，防止高数据率下丢帧。
5.7.2　滑动窗口协议解析
指令帧格式为帧头0xFA、类别、命令、帧尾0xFB共4字节。解析采用4字节滑动窗口（parse_window），每读入一个字节便整体左移一次，当窗口首位为帧头、末位为帧尾时，即校验出一帧完整指令，取出中间的类别与命令字段。
协议共定义5类指令：发车区灯光（0x10）、停车区鸣笛（0x20）、前往动作区门洞（0x30）、前往停车区门洞（0x40）、动作区运动（0x50），以及开始/结束类指令（0x60），构成覆盖省赛阶段各科目的通用协议。每类指令下细分具体命令，如左/右转向灯、远近光灯、雾灯、双闪、车内照明、雨刷，以及鸣笛1/2/3秒、两声/三声/四声、长短鸣笛、急促鸣笛、警报鸣笛等。国赛综合科目中仅需使用灯光（0x10）与鸣笛（0x20）两类指令。
5.7.3　指令存储与调度执行
解析出的指令存入指令仓库cmd_storage[]（最大20条）。系统采用两阶段执行机制：接收阶段持续解析并存储指令，当收到"结束"指令（START_OVER类别）后进入执行阶段（j=2）；执行阶段按仓库顺序，由isr61_ch0_kemu2定时器任务根据每条指令预设的执行时间间隔（time[]）自动逐条调度执行，防止指令执行过快。
指令执行函数execute_stored_command按类别分发：灯光类指令通过TLD7002车灯驱动与点阵屏显示对应图标；鸣笛类指令设置display_mode后由Beep_Task鸣笛任务完成各种鸣笛模式。国赛综合科目所要求的灯光与鸣笛指令均已完成实测联调。门洞穿越与动作区运动指令为省赛科目2的扩展任务，通过指令仓库预留接口继续完善。
5.8　灯光与鸣笛控制系统
车灯控制以TLD7002芯片为核心，通过UART0接收指令，实现左/右转向灯、近光/远光灯、雾灯、双闪、车内照明、雨刷等多种灯光动作；同时通过点阵屏幕显示相应的灯光图标，便于调试观察。TLD7002与调试串口复用，初始化时通过外设配置避免冲突。
鸣笛控制采用PWM驱动蜂鸣器，由Beep_Task任务按display_mode对应的时序产生不同的鸣笛模式：1/2/3秒长鸣、两声/三声/四声短鸣（响1秒停1秒）、长短鸣笛、急促鸣笛（0.5秒周期交替）、警报鸣笛（500Hz/1000Hz交替，重设PWM频率实现），并限制单次鸣笛总时长。
5.9　人机交互与显示
系统配置4个按键：KEY_1开始录迹，KEY_2进入科目2（人机交互）语音模式，KEY_3开始航迹回放，KEY_4标定色块颜色阈值。IPS200Pro液晶屏幕实时显示系统工作状态（SystemRun_Index）、航向角yaw2、航向偏差error、转向电机角度、左右轮速、指令条数、色块识别结果等调试信息；屏幕同时可叠加显示摄像头图像，便于图像算法调试。屏幕显示在系统初始化时创建多个文本标签与图像控件，主循环中按需刷新。
5.10　中断资源与实时性分析
系统共使用3路PIT周期中断与若干外部中断。3ms中断承担IMU采集与解算；10ms中断承担电机闭环控制，运算量小；1ms中断承担编码器、鸣笛与指令调度，其中编码器与录迹导航仅在计数值达100时才执行，降低中断负载。


第六章　系统调试与测试
6.1　开发工具与调试环境
软件开发环境采用英飞凌官方AURIX Development Studio（ADS），配合逐飞科技TC264开源库进行开发，编译器为Tasking。程序烧录与调试使用。调试过程中充分利用串口上位机（VOFA+）与IPS200Pro屏幕实时观察变量波形与图像，显著提高了算法调参效率。
6.2　传感器调试
6.2.1　图像调试
通过屏幕图像窗口实时显示摄像头采集图像与色块识别结果（识别框），验证色块阈值标定是否准确、识别框是否贴合目标。针对不同光照环境，通过KEY_4现场重新标定阈值。经测试，黄色目标色块在室内外光照下的识别稳定，识别帧率与摄像头帧率一致，满足目标跟随需求。
6.2.2　IMU与航向调试
通过屏幕实时显示航向角yaw2，检查陀螺仪积分是否随车模转动正确变化，验证零漂校正效果。在车模原地旋转360°的测试中，航向角在0～360°范围内平滑变化，无明显跳变。
6.2.3　编码器调试
通过屏幕观察左右轮转速与转向电机角度反馈，确认编码器接线与量程换算正确；对开发期使用的GPS模块，通过上位机确认其定位稳定后即作为备用传感器保留。
6.3　控制参数整定
电机参数整定遵循"先转向环、后速度环"的顺序。转向环先整定比例系数Kp使转角快速响应且无振荡，再加入微分项改善动态特性，最后加入小积分项消除稳态误差。速度环采用工程整定法：先单独增大Kp至临界振荡，再按经验加入Ki消除静差、Kd抑制超调，最终确定左右轮参数。
6.4　导航算法调试
惯性导航（录迹-回放）调试分三步进行：首先低速直线录迹与回放，验证里程换点与航向记录正确；其次进行直线+转弯组合路径测试，调节预瞄点数与误差限幅，消除弯道处的转向滞后与振荡；最后进行自动返回等实景测试，验证停车标志触发时机。
导航方案对比试验中，将GPS航点导航与惯性导航方案在同一条迷宫路径上对比测试：GPS方案在室外漂移较大、路径复现偏差明显，惯性导航方案路径一致性好，最终确定采用惯性导航方案。
6.5　语音指令联调
语音联调针对国赛综合科目的灯光与鸣笛语音任务进行。通过屏幕实时显示指令条数与当前执行指令序号，验证帧协议解析的正确性与指令执行时序。测试了发车区灯光类与停车区鸣笛类指令的自动调度执行，确认各指令间的时间间隔设置合理、无串扰。
6.6　整车场地测试
在比赛场地完成整车综合测试。省赛阶段验证科目2（灯光、鸣笛等语音任务）与科目3（跟随与航迹自动返回）的独立流程；国赛阶段重点验证带语音任务的综合科目完整流程：跟随队员穿越迷宫、自动返回发车区、语音完成灯光与鸣笛任务。记录每轮测试中各项任务的完成情况、耗时与失败原因，并据此迭代改进。

第八章　结论与展望
8.1　工作总结
本报告从系统总体方案、机械结构、电路设计与软件算法四个方面对参赛智能汽车的设计与制作进行了系统总结。软件系统实现了摄像头色块识别与目标跟随、IMU航向解算、PID电机闭环控制、阿克曼差速转向、惯性导航（录迹-回放）、语音指令解析执行以及灯光鸣笛控制等功能，并通过双核多中断架构保证了控制系统的实时性与稳定性。经过反复调试与整车测试，模型车能够在国赛综合科目（带语音任务的科目3）中稳定完成跟随队员、自动返回与语音灯光鸣笛等任务。
8.2　存在的问题与改进方向
在系统调试与场地复现过程中，针对摄像头识别、惯性导航与电机转速控制三个环节进行了反复测试，发现若干影响系统稳定性与一致性的问题，现总结如下并提出相应改进方向。
（1）摄像头在晴天强光环境下识别不稳定。色块识别采用HSL颜色空间，通过按键对图像中心单像素进行自动标定获得阈值（色相±20、饱和度/亮度±40）。晴天时阳光直射造成大面积高光与阴影，同一色块亮度与饱和度分布剧烈变化，单点标定易落在反光点上，导致色块漏检、误检或目标中心抖动，进而引起转向指令抖动。改进方向：为摄像头开启自动曝光与自动增益，或依据画面整体亮度动态调整曝光；将单点标定改为对目标区域多点采样的均值/中值统计，并适当放宽色相阈值、在线更新阈值以自适应光照变化；增加目标尺寸与位置连续性约束，滤除单帧误检。
（2）陀螺仪与磁编码器偶发卡顿、丢值，疑似受温度影响。陀螺仪零偏仅在开机时采样200次一次性标定，未做温度补偿，长时间运行温升后零偏漂移，航向角出现缓慢漂移，或在低速转向时因角速度量化为10 LSB整数倍而“卡住”；AS5047P磁编码器通过软件SPI读取，读失败时返回0xFFFF错误帧，若未及时剔除会污染转向圈数计数、造成转向角突跳，磁钢与霍尔元件随温度漂移是诱因之一。改进方向：引入磁航向或GPS航向对陀螺航向做周期性校正与积分复位；对陀螺零偏做温度补偿或运行中周期性重标定；软件中剔除0xFFFF错误帧并增加多次读数一致性校验；硬件上加强传感器供电滤波，使传感器远离电机与驱动等热源。

8.3　创新点
本队的核心创新点在于提出一种仅使用陀螺仪与预瞄点的轻量级惯导录迹回放导航方案。该方案摒弃磁力计、GPS等外部航向参考，仅利用IMU陀螺仪对角速度积分得到车辆航向，并结合轮式编码器里程作为行程度量；路径录制阶段将航向按固定里程间隔离散存储，回放阶段通过预瞄点算法对未来若干采样点的航向进行插值预测，得到目标航向并与当前陀螺航向作差构成航向偏差，再经阿克曼差速与转向角闭环实现低速轨迹的精确跟踪。该方案结构简洁、传感器依赖少、算力开销低，在磁干扰较强的场地仍能保持航向基准稳定，兼顾了导航精度与系统鲁棒性，具有一定的工程推广价值。

A.1　PID控制算法（PID）
速度环与转向环均采用PID控制。速度环使用增量式PID，输出为占空比增量并做限幅，避免积分饱和；转向环使用位置式PID，对转向角偏差进行比例、积分、微分运算后直接输出PWM。控制器参数经实车整定。
#define pid_increment_limit 800//后轮驱动电机积分限幅
#define Integral_Limit 800//前轮转向电机积分限幅
//电机增量式PID参数
PID motor_pid_l = PID_CREATE(4.0,0.6,0.2,1);
PID motor_pid_r = PID_CREATE(3.5,0.6,0.2,1);
PID steering_motor_pid = PID_CREATE(390,0.9,1,1);
float PID_Normal(PID *PID,int NowData,int Point)
{
    PID->Error = (float)(Point - NowData);// Point是由自己决定的，范围最好在-20 ~ +20 之间  若加上GPS那么就由GPS的航向角决定
                                 // NowData 是 6050(mpu_yaw2)(范围0-360) 减去 963ra(yaw2)(范围0-360)

    PID->Out_P = PID->Error;

    PID->Out_I += PID->Error;

    //积分限幅  2000
    if(PID->Out_I > Integral_Limit) PID->Out_I = Integral_Limit;
    else if(PID->Out_I < -Integral_Limit) PID->Out_I = -Integral_Limit;

    PID->Out_D = PID->Error - PID->LastError;


    hulin = PID->Kp * PID->Out_P + PID->Ki * PID->Out_I + PID->Kd * PID->Out_D;

    //整体PWM占空比限幅
    if(hulin > 6000)     hulin = 6000;
    if(hulin < -6000)    hulin = -6000;

    PID->LastError = PID->Error;

    return hulin;
}
float PID_Increase(PID *PID,float NowData,float Point)
{
    PID->Error = Point - NowData;
    PID->Out_P = (PID->Error - PID->LastError);
    PID->Out_I = PID->Error;
    PID->Out_D = (PID->Error - 2 * PID->LastError + PID->PrevError);


    PWM = PID->Kp * PID->Out_P + PID->Ki * PID->Out_I + PID->Kd * PID->Out_D;

    // 积分限幅限制单次输出的增量
    if(PWM > pid_increment_limit)
        PWM = pid_increment_limit;
    else if(PWM < -pid_increment_limit)
        PWM = -pid_increment_limit;

    PID->PrevError = PID->LastError;
    PID->LastError = PID->Error;

    return PWM;
}
A.2　电机驱动与编码器测速（Motor）
本模块完成车轮速度测量与电机闭环控制。左右轮编码器计数按固定周期采样，经一维卡尔曼滤波平滑后折算为转速；速度环以增量式PID驱动BTN791B电机驱动电路；转向电机以AS5047P磁编码器为反馈构成多圈角度闭环，并自动完成机械零点标定。
void Steering_Encoder_Data_Get(void)
{
    static bool first_run = true;
    steering_motor.encoder_raw = (float)AS5047P_ReadAngle();//0-16384

    if(first_run)
    {
        steering_motor.last_encoder_raw = steering_motor.encoder_raw;
        full_turns = 0;
        first_run = false;
        return;   // 第一次只同步，不计算！
    }

    //计算真实差值
    int32_t delta = (int32_t)steering_motor.encoder_raw - (int32_t)steering_motor.last_encoder_raw;
    // 正确过零处理
    if (delta >  RAW_HALF)  full_turns--;
    if (delta < -RAW_HALF)  full_turns++;

    //累加多圈角度（正确！）
    steering_motor.total_encoder = (int32_t)full_turns * RAW_MAX + (int32_t)steering_motor.encoder_raw;


    /// ============ 自动标零（前10帧取平均后锁定） ============
    if (!zero_calibrated)
    {
        if (zero_calibration_cnt < 10)
        {
            encoder_zero_offset += steering_motor.total_encoder;  // 累加
            zero_calibration_cnt++;
        }
        else
        {
            encoder_zero_offset /= 10;   // 取平均
            zero_calibrated = true;
        }
    }

    steering_motor.total_encoder -= encoder_zero_offset;
    steering_motor.total_encoder = (float)steering_motor.total_encoder * 0.00006;//规范到-25~25
    //更新上次原始值
    steering_motor.last_encoder_raw = steering_motor.encoder_raw;
}

void Motor_Speed(void)
{
    motor_l.target_speed = Speed_L;
    motor_r.target_speed = Speed_R;

    motor_l.duty += PID_Increase(&motor_pid_l,(float)motor_l.MotorRpm,(float)motor_l.target_speed);//左轮PID增量式闭环
    motor_r.duty += PID_Increase(&motor_pid_r,(float)motor_r.MotorRpm,(float)motor_r.target_speed);//右轮PID增量式闭环


    //整体PWM占空比限幅
    if(motor_l.duty > 6000)  motor_l.duty = 6000;
    if(motor_l.duty < -6000) motor_l.duty = -6000;

    if(motor_r.duty > 6000)  motor_r.duty = 6000;
    if(motor_r.duty < -6000) motor_r.duty = -6000;


    if (motor_l.duty > 0)//左轮正转
    {
       pwm_set_duty(L1, 0);
       pwm_set_duty(L2, (uint32)motor_l.duty);

    }
    else
    {
       pwm_set_duty(L2, 0);
       pwm_set_duty(L1, (uint32)(-motor_l.duty));
    }


    if (motor_r.duty > 0)//右轮正转
    {
        pwm_set_duty(R1, 0);
        pwm_set_duty(R2, (uint32)motor_r.duty);
    }
    else
    {
        pwm_set_duty(R1, (uint32)(-motor_r.duty));
        pwm_set_duty(R2, 0);
    }


}

{
    motor_l.encoder_raw = encoder_get_count(TIM2_ENCODER);//让左轮encoder_raw这个变量等于编码器数据采集通道2的脉冲值
    motor_l.encoder_speed = kalman1_filter(&g_kalman1MotorL,motor_l.encoder_raw);//卡尔曼一阶滤波

    motor_r.encoder_speed = kalman1_filter(&g_kalman1MotorR,motor_r.encoder_raw);//卡尔曼一阶滤波

    //转速 = 当前脉冲数/采样周期  * 60 / 轮子转一圈会产生的脉冲数（1024）* 减速比1：2
    motor_r.MotorRpm =  motor_r.encoder_speed * 60 / (1024 * 0.1 * 2);
    motor_r.total_encoder += motor_r.encoder_speed; //累加，为了知道后续车走了多少距离

    encoder_clear_count(TIM4_ENCODER);//清空


}
A.3　录迹回放导航（navigation）
录迹回放导航是本队的核心创新。录制阶段按固定里程间隔离散存储陀螺航向；回放阶段以当前里程为基准向前预瞄若干采样点，对目标航向做线性插值并消除360°跳变，得到航向偏差后结合阿克曼差速模型分配左右轮速并驱动转向闭环，实现路径的精确复现。
void Nag_Read()
{
    N.Mileage_All += (R_Mileage+L_Mileage)/2.0;

    if(N.Mileage_All >= Nag_Set_mileage)
    {
        Nav_read[N.Save_index++] = (int32)(Nag_Yaw*100);//从Nav_read[0]开始记录

        if(N.Save_index >= Read_MaxSize) N.Save_index = Read_MaxSize;
        if(N.Mileage_All > 0) N.Mileage_All -= Nag_Set_mileage;
        else N.Mileage_All += Nag_Set_mileage;
    }
}
void Nag_Run()
{

    if(N.Run_index >= N.Save_index - 99)
    {
       N.Nag_Stop_f = 1;
       return;
    }

    N.Mileage_All += fabs((R_Mileage + L_Mileage) / 2.0);

    if(N.Mileage_All >= Nag_Set_mileage)
    {
        uint32 read_idx = N.Save_index - 1 - N.Run_index;
        N.Angle_Run = Nav_read[read_idx] / 100.0f;

        N.Run_index++;
        N.Mileage_All -= Nag_Set_mileage;
    }
}
void Nag_System()  // 100ms
{

    if(!N.Nag_SystemRun_Index || N.Nag_Stop_f )  return;

    switch(N.Nag_SystemRun_Index)
    {
       case 1 :
           Nag_Read();
       break;
       case 3:
           Nag_Run();
       break;
    }
}
void NagFlashRead()
{
    if(N.Save_state) return;
    N.Save_state = 1;
    if(N.Save_index == 0) return;
    N.Run_index = 1;

    float residual = N.Mileage_All;                        // 保存录制结束时的残差
    if(residual > 0.0f && residual < (float)Nag_Set_mileage)
    {
        N.Mileage_All = (float)Nag_Set_mileage - residual; // 让第一段走 residual 就触发切换
    }
    else
    {
        N.Mileage_All = 0.0f;
    }

    N.Nag_Stop_f = 0;
    N.Angle_Run = Nav_read[N.Save_index - 1] / 100.0f;
    N.Nag_SystemRun_Index++;
}
void Nag_Run_Control()
{
    float base_speed = -200.0f;

    // ── 预瞄计算 error ──
   error = 0.0f;
   if(N.Save_index > 0 && N.Run_index > 0)
   {
       float total_consumed = (float)(N.Run_index - 1) + (N.Mileage_All / (float)Nag_Set_mileage);
       if(total_consumed >= (float)(N.Save_index - 1)) total_consumed = (float)(N.Save_index - 1);

       float target_f = (float)(N.Save_index - 1) - total_consumed - 11.0f;
       if(target_f < 0.0f) target_f = 0.0f;

       uint16 idx1 = (uint16)target_f;
       uint16 idx2 = idx1 + 1;
       if(idx1 >= N.Save_index) idx1 = (uint16)(N.Save_index - 1);
       if(idx2 >= N.Save_index) idx2 = (uint16)(N.Save_index - 1);

       float frac = target_f - (float)idx1;
       float yaw1 = Nav_read[idx1] / 100.0f;
       float yaw2_val = Nav_read[idx2] / 100.0f;

       float yaw_diff = yaw2_val - yaw1;
       if(yaw_diff > 180.0f) yaw_diff -= 360.0f;
       if(yaw_diff < -180.0f) yaw_diff += 360.0f;

       float target_heading = yaw1 + frac * yaw_diff;
       if(target_heading < 0.0f) target_heading += 360.0f;
       if(target_heading >= 360.0f) target_heading -= 360.0f;

       error = yaw2 - target_heading;
       if(error > 180.0f) error -= 360.0f;
       if(error < -180.0f) error += 360.0f;
   }

//    error = yaw2 - N.Angle_Run;
//
//    if(error > 180.0f)  error -= 360.0f;
//    if(error < -180.0f) error += 360.0f;

    if(error > 25)  error = 25;
    if(error < -25) error = -25;

    if(error > 0)
    {
        float rad = 3.1415f/180.0f;
        float R = 0.65f/tanf(abs(error) * rad);

        Motor_Angle(error);
        Speed_L = base_speed * ((R+0.30)/R);
        Speed_R = base_speed * ((R-0.30)/R);
    }
    else if(error < 0)
    {
        float rad = 3.1415f/180.0f;
        float R = 0.65f/tanf(abs(error) * rad);

        Motor_Angle(error);
        Speed_L = base_speed * ((R-0.30)/R);
        Speed_R = base_speed * ((R+0.30)/R);
    }
    else
    {
        Motor_Angle(0);
        Speed_L = base_speed;
        Speed_R = base_speed;
    }
}
A.4　磁编码器读取（AS5047P）
AS5047P为14位磁编码器，通过软件SPI（Mode1）读取角度。程序实现16bit命令帧的偶校验计算与发送，读取返回帧并校验偶校验位与错误标志（EF位），读失败时返回0xFFFF以便上层剔除，提高转向角度反馈的可靠性。
uint8_t AS5047P_CalcParity(uint16_t data)
{
    uint8_t cnt = 0;
    for(uint8_t i=0; i<15; i++)
    {
        if(data & (1<<i)) cnt++;//判断当前是否是1，如果是1 cnt就+1 最后就算如果cnt是奇数，那么根据数据手册要求偶校验位，就返回1
                                                                     //反之如果cnt是偶数，就返回0
    }
    return cnt % 2; // 偶校验
}
uint16_t AS5047P_SoftSPI_Send16bit(uint16_t tx_data)
{
    uint16_t rx_data = 0;

    CSN_L();   // CS拉低，低电平有效，开始通信
    system_delay_us(1);

    for(uint8_t i=0; i<16; i++)//循环16次
    {
        // 放MSB到MOSI(也就是高位先发送)
        MOSI_WRITE((tx_data >> 15) & 0x01 );//把你要发的16位数据的最高位筛选出来发到MOSI里面(0/1)
                                            //对应内部函数MOSI_WRITE(val)：gpio_set_level(AS5047P_MOSI_PIN , val)拉低拉高
        tx_data <<= 1;//替换掉原本的最高位按序发送

        //从机采样 因为CPOL=0(即CLK空闲时是低电平) CPHA=1(第二个跳变才采样也就是下降沿采样)
        SCLK_H();
        system_delay_us(1); // 可根据MCU调整，保证时序

        //读MISO
        rx_data <<= 1;//把最先收到的数据放在右侧
        if(MISO_READ()) rx_data |= 0x01;//MISO_READ():gpio_get_level(AS5047P_MISO_PIN)如果电平获取的是1，就强制将0变为1

        //继续下一位
        SCLK_L();
        system_delay_us(1);
    }

    CSN_H(); // 片选拉高
    system_delay_us(1);
    return rx_data;
}
uint16_t AS5047P_BuildReadCmd(uint16_t addr)
{
    uint16_t cmd = (1<<14) | (addr & 0x3FFF); // R=1 W=0 (1<<14)是为了将写(Read)推到前面，剩余0~13位由地址决定，& 0x3FFF是为了将地址规整在14位里面
    uint8_t parity = AS5047P_CalcParity(cmd);//调用偶校验位函数
    cmd |= (parity << 15); //将偶校验位推到最前面再加上后15位
    return cmd;
}
uint16_t AS5047P_ReadAngle(void)
{
    uint16_t cmd = AS5047P_BuildReadCmd(AS5047P_READ_ANGLE);//AS5047P_READ_ANGLE  0x3fff(就是数据手册里面对应的地址)
    uint16_t data_frame = AS5047P_SoftSPI_Send16bit(cmd);//将返回的所有完整的16位数据打包好发送


    // ============== 关键校验 bit14 叫 EF 错误标志位 ==============
    //这个位 = 1 → 传感器说：我这个数据是错的，别用！
    //这个位 = 0 → 数据正常
    uint8_t parity_ok = (AS5047P_CalcParity(data_frame) == ((data_frame >> 15) & 0x01));
    uint8_t no_error  = (((data_frame >> 14) & 0x01) == 0); // EF=0 才有效


///*******************************方法一****************************************/
//    // 错的数据直接扔掉！用上一次正确的值
//    static uint16_t last_angle = 0;
//    if(parity_ok && no_error)
//    {
//        last_angle = data_frame & 0x3FFF;//更新新的数据 只返回低14位是角度
//    }
//
//    return last_angle;


/*******************************方法二(较好)****************************************/

    if(parity_ok && no_error)
    {
        return data_frame & 0x3FFF;   // 直接返回有效值
    }
    return 0xFFFF;  //错误时返回无效标志，让调用方处理

}
A.5　中断控制主循环（isr）
系统采用定时器中断驱动控制：CCU60_CH1每10ms执行速度/转向闭环与录迹回放控制；CCU61_CH0每1ms执行编码器采样、里程累积与转向编码器更新；CCU61_CH1每3ms读取IMU并更新航向。各控制环均在中断中实时执行。
IFX_INTERRUPT(cc60_pit_ch1_isr, 0, CCU6_0_CH1_ISR_PRIORITY)
{
    interrupt_global_enable(0);                     // 开启中断嵌套
    pit_clear_flag(CCU60_CH1);

    key_scanner();  //按键扫描函数


    if (N.Nag_SystemRun_Index == 1)
    {
        if (!yellow_check || target_pos_out.h >= 103)      // 无目标 或 太远 → 停
        {
            Speed_L = 0; Speed_R = 0;
        }
        else if (target_pos_out.h < 103 && target_pos_out.h > 9)  // 有目标且距离合适 → 前进
        {
            Set_target_Speed();
        }
        Motor_Angle(camera_target_angle);
        Motor_Speed();
    }

    if(N.Nag_SystemRun_Index == 3)  // 开始复现路径
    {
        if(N.Nag_Stop_f)
        {
            Speed_L = 0;
            Speed_R = 0;
            Motor_Angle(0);
            Motor_Speed();
        }
        if(!N.Nag_Stop_f)
        {
            Nag_Run_Control();
            Motor_Speed();
        }
    }

}
IFX_INTERRUPT(cc61_pit_ch0_isr, 0, CCU6_1_CH0_ISR_PRIORITY)
{
    static uint32_t pit0_cnt = 0;
    static uint32_t pit1_cnt = 0;

//    interrupt_global_enable(0);                     // 开启中断嵌套
    pit_clear_flag(CCU61_CH0);


    if(pit0_cnt++ > 100)
    {
        pit0_cnt = 0;
        Encoder_Data_Get();

        Nag_System();  // 惯性导航执行函数

    }

    /***科目二中断内容***/
    Beep_Task();//扬声器

    isr61_ch0_kemu2();//不同任务指令自动调度

    if(pit1_cnt++ > 2)
    {
        pit1_cnt = 0;
        Steering_Encoder_Data_Get();
    }



}
