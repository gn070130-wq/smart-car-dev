摘要
本文详细介绍了沈阳理工大学 “远征” 在第二十一届全国大学生智能汽车竞赛中卡丁快跑的系统方案。本次比赛采用统一车模，以英飞凌公司生产的 32 位单片机 TC264 为核心控制器，要求卡丁车依次完成自动驾驶泊车、语音人车交互、迷宫路径记忆复现多项竞赛科目，依托惯性导航获取车体位姿信息，以最快的速度完成各个科目。整套小车依靠惯性导航单元为主感知模块获取赛道环境与车体状态；通过编码器、陀螺仪检测卡丁车的实时速度，角度与坐标信息，使用 PID 控制算法调节电机的转速与差速，实现车模在运动过程中速度和方向的闭环控制；为了提高模型车的速度和稳定性，使用上位机、按键、屏幕模块等调试工具，进行了大量硬件与软件测试。实验结果表明，该系统设计方案确实可行。

第一章 绪论
1.1智能车研究背景
智能小车属于多学科交叉融合的高新智能载体，以汽车电子技术作为底层基础，横跨自动控制、模式识别、传感检测、电子电路、机械结构、嵌入式计算机等诸多专业领域，是综合性较强的工程创新设计。设备一般由环境路径感知、车速信息采集、航向角度调控、运动速度闭环控制等功能模块搭建而成，可以实现自主循迹行驶、车速动态调节、道路环境识别等智能化功能，同样也是当下智能车载电子领域十分重要的研究方向。
国内为培育高校学生的工程实操、科研创新以及团队协作综合能力，由教育部牵头，自动化专业教学指导委员会主办一年一度的全国大学生智能汽车竞赛。赛事依托官方提供的标准化模型车硬件平台，参赛队伍选用主流 32 位嵌入式单片机作为主控核心，自主搭建道路传感检测模块、电机驱动硬件电路，编写嵌入式控制程序、完成整车装配调试，打造一台具备自主感知能力的智能模型车。车辆需要在赛前未知的赛道环境当中自主行进，赛事以赛道全程完成耗时作为主要评判标准，以此锻炼学生对于车载智能控制系统的开发能力
1.2方案总体介绍
本次卡丁快跑竞赛场地为开阔的室外场地，赛场内设置多处锥桶用来划分行驶路线、泊车区域、语音交互区以及迷宫跟随通道，各行驶通道间距充足，赛道沿途包含自动驾驶泊车、语音指令执行、迷宫路径记忆复现等多项竞技科目。场地内锥桶作为道路标识，小车行驶途中需要依照任务规则绕开锥桶完成指定动作，不同功能分区之间留有充足的通行空间，场地不存在硬性的物理围墙边界。赛场内还设有门洞通道、动作执行区、倒车停车库等特殊任务点位，需要小车依靠惯性导航完成无引导标识路段的位姿推算与自主行驶。
根据竞赛规则相关规定，本卡丁车系统采用赛事官方统一标准车模，自主选配高性能32位微控制器TC264作为核心控制器，在ADS(AURIX™ Development Studio)开发环境中完成全套软件开发与算法调试。系统搭载IMU963RA惯性导航传感器采集车体航向、加速度等运动数据，通过编码器测量速度并记录里程，将实时位姿信息传输至主控芯片，经过融合解算获取卡丁车当前坐标、偏航角度及运动姿态等关键行驶信息；车辆加装后轮编码器与转向电机编码器，通过单片机对编码器脉冲信号进行解码，精准解算车辆实时行驶速度、行进路程及转向角度信息。车体整车速度与转向姿态均采用PID闭环控制算法，通过PWM信号调节驱动电路输出功率，动态调整电机运行状态。车辆目标车速结合基础默认参数、行车安全约束策略以及惯性导航位姿数据优化算法进行动态自适应调节，保障卡丁车在自动驾驶、人车交互、迷宫跟随等多个竞赛科目中稳定、精准、高效运行

机械结构设计
2.1整车布局
本组采用赛事官方统一卡丁快跑标准车模，整车保留原厂底盘、动力电机与电池结构，保证原车稳定的传动性能与行驶基础特性。为优化整车布局、规整硬件安装空间，本车在原装电池保护罩上方、驾驶座后方位置加装固定平板，将主控PCB板、IMU惯性传感器等核心传感与电路模块统一固定至后置平板区域。后轮编码器固定于原装电机减速器内部，不该改变传动比，该改装方式不改动原车动力结构和传动比，最大程度保证了编码器所获得数据的精确性，同时集中整合车载硬件，降低线路杂乱带来的干扰，并对各个核心传感器起到了保护作用，提升整车结构稳定性与传感器采样精度，满足卡丁快跑多科目稳定运行的需求。

2.2编码器的固定
为精准采集卡丁车车速与转向角度信息，本车在保留原装驱动电机与减速箱传动结构的基础上，将编码器内置安装于电机减速箱内部。为保证编码器安装牢固、并且可避免运动干涉，在不改变原车减速箱传动比、不改动核心传动结构的前提下，依据原厂减速箱外形尺寸重新设计了减速箱外壳与编码器专用固定支架。全新结构能够将编码器稳定限位在减速箱内部，有效降低测速抖动与安装间隙带来的数据误差。该改装方案结构紧凑、兼容性强，在完全保留原车动力特性的基础上，实现了速度采集，为后续PID速度闭环控制与惯性导航位姿解算提供了可靠的数据支撑。固定方式如图二-1与图二-2所示

3.4传感器的选择
3.4.1编码器
后轮测速采用1024线带方向编码器将输出轴上的机械几何位移量转换成脉冲，其获取信息准确、精度高、应用简单。
转向电机编码器采用单圈绝对值编码器，使用spi通信，可以将当前的绝对角度返回，避免了增量式编码器积分计角度无法掉电保存。
3.4.2姿态传感器
本车搭载IMU963RA九轴惯性测量单元，可高频稳定输出加速度、角速度、航向姿态等车体运动数据，采样频率可调且全程数据平稳、抖动量小。该传感器具备动态滤波与噪声抑制能力，能够自动滤除车体震动、电机干扰带来的高频噪声，适配赛场复杂环境。同时可通过程序配置采样参数与滤波系数，实时校准姿态数据，无需断电复位，能够持续稳定输出精准位姿信息，满足卡丁快跑惯性导航、路径复现、姿态闭环控制的使用需求。
3.4.3摄像头
采用scc8660，在户外色块识别中的优势主要体现在灵活的光照控制与高效的色彩处理上。它支持手动曝光与白平衡锁定，避免自动调节引起的亮度、色温波动，配合可调PCLK分频和多种分辨率/帧率选项，能适应阳光直射、阴影等复杂户外环境；同时，RGB565输出结合HSV色彩空间转换，使色调在光照变化中保持相对稳定，而硬件DMA采集和中断机制则保障了低延迟、高可靠的实时跟踪，非常适合嵌入式户外视觉任务。



第四章软件控制设计
4.1惯性导航姿态解算及数据优化处理
4.1.1 原始惯性数据特点
主控芯片通过外设接口实时采集IMU963RA惯性测量单元的原始运动数据，为车辆姿态解算与位姿推算提供基础数据源。卡丁车在行驶过程中存在车体颠簸、电机振动、路面抖动以及外界电磁干扰等影响，导致传感器输出的原始加速度与角速度数据存在高频噪声与微小漂移，直接使用原始数据会造成姿态角度偏移、位姿计算不准等问题。因此软件端需要对惯性数据进行滤波校正与姿态解算处理，精准解算车体运动状态，为自动驾驶、迷宫路径复现、断路惯性行驶等科目提供稳定可靠的姿态与位置信息。
本系统采集的惯性导航核心数据主要包括：三轴角速度数据、三轴加速度数据、车体方位偏航角、俯仰角及横滚旋转角等姿态信息。IMU963RA传感器输出的原始数据为高频实时采样数据，数据更新速率快、动态响应灵敏，但受机械震动影响存在瞬时波动，无法直接用于闭环控制。为消除误差影响，系统通过软件滤波算法对原始数据进行平滑处理，剔除异常抖动数据，保证姿态解算的稳定性与连续性。

4.1.2 四元数姿态解算算法
为实现高精度、低延迟的车体姿态求解，本系统采用四元数姿态解算算法对IMU963RA采集的原始惯性数据进行融合解算，替代传统欧拉角解算方式，有效避免了姿态解算过程中的万向锁问题，提升动态行驶下的姿态求解精度。
基于四元数姿态融合算法，核心采用改进型Mahony互补滤波，通过加速度计与陀螺仪数据融合实时估计载体姿态。其关键设计在于动态比例增益和泄漏积分机制：程序实时计算加速度模长与角速度幅值，动态评估加速度计的可信度，在剧烈运动或离心干扰（如高速转弯）时自动降低加速度修正权重，同时利用泄漏积分防止静态误差累积，兼顾了静态稳定性与动态响应性。此外，陀螺仪零漂自动补偿、一阶低通滤波和死区处理进一步抑制了传感器噪声，确保了姿态解算的平滑性和长期漂移抑制能力，非常适合户外高速运动场景下的姿态跟踪。

4.1.3 车体姿态与航向计算
通过四元数解算得到稳定的车体姿态信息后，系统可精准获取卡丁车实时航向角度与姿态状态，并将姿态偏移量作为核心控制量引入PID闭环控制。系统根据解算得到的车辆偏航角偏差，结合后轮编码器速度数据完成位姿融合，动态计算车体航向偏移误差。控制程序根据姿态偏差量实时调节左右电机转速差，完成车体转向纠偏与姿态稳定控制，实现车辆姿态自稳、定向直行、轨迹复刻以及断路惯性行驶等功能，满足卡丁快跑多科目稳定运行的控制需求。
在卡丁快跑赛事的特殊工况中，场地无固定引导线、迷宫路径随机可变、断路区域无视觉参照，传统视觉识别方案完全失效，惯性导航系统成为车辆自主行驶的核心保障。本系统依托IMU963RA持续输出的姿态与运动数据，结合积分运算实时推算车辆行驶位移与全局坐标，精准记录车辆行驶轨迹，为迷宫科目路径记忆、复现功能提供完整的数据支撑。同时，针对车辆启停、转向、颠簸带来的瞬时姿态突变问题，软件端增设动态权重融合策略，优化加速度计与陀螺仪数据配比，低速状态下侧重加速度计姿态校准，高速状态下依托陀螺仪稳定航向数据，有效抑制姿态抖动与角度漂移。该套惯性导航控制方案，完美适配自动驾驶泊车、语音交互精准对位、迷宫轨迹复现、等全部竞赛科目，大幅提升了卡丁车复杂场地环境下的行驶稳定性与任务完成精度。

4.2语音识别
4.2.1 原始语音信号特点
在卡丁快跑战场救护人车交互科目中，小车需要通过硅麦传感器实时采集赛场环境语音指令。赛场环境存在环境风噪、场地回声、人员走动杂音以及电机运行噪音等干扰，导致原始语音信号掺杂大量无效噪声，直接识别极易出现指令误判、漏判、识别不准等问题。同时参赛人员发音语速、音量差异较大，进一步增加了语音指令的识别难度。因此软件端需要对原始语音信号进行降噪处理、语义拆分与精准匹配，有效过滤环境干扰，保证小车对灯光控制、鸣笛控制、门洞通行、车体运动等语音指令的准确识别与执行。
本系统语音识别核心采集与处理内容主要包括：环境语音信号采集、噪声过滤、云端语音文本转换、指令语义分割、关键词得分匹配、对应车体动作指令输出。为提升复杂赛场环境下的识别鲁棒性，本车采用WiFi联网通信方案，将采集到的原始语音数据上传至云端AI语音模型进行解析，相比本地识别，具备抗干扰能力强、识别精度高、适配指令种类多等优势，能够适配比赛全部人机交互口令任务。

4.2.2 语音语义分割算法
参考低二十届南京信息工程大学极速越野语音识别的开源方案进行改进。
本系统通过WiFi联网完成语音转文字后，针对返回的文本语句采用语义分割算法进行解析处理，拆解完整语句中的有效指令信息，剔除语气词、杂音转化无效字符、多余修饰词汇等干扰内容。语义分割算法核心流程如下：
（1）将云端转换得到的文本数据进行预处理，清洗无效字符、过滤乱码与冗余信息，得到纯净指令文本；
（2）根据比赛既定语音指令库的词汇特征，对文本内容进行分词拆分，精准提取动作关键词、时长关键词、模式关键词等核心语义信息；
（3）区分灯光控制、鸣笛控制、门洞通行、车体运动四大类任务语义特征，完成指令初步分类，为后续得分匹配提供数据基础。

4.2.3 语句得分匹配算法
参考低二十届南京信息工程大学极速越野语音识别的开源方案进行改进。系统提前建立完整比赛语音指令特征库，将分割后的语义关键词与标准指令库进行逐一比对，通过字符相似度、关键词匹配度、语序特征权重进行综合打分。程序设定固定匹配阈值，当语句综合得分高于阈值时，判定指令匹配成功并输出对应控制指令；若得分低于阈值则判定为干扰语音，不执行任何动作，有效规避赛场噪音、误发音带来的误操作问题。
通过WiFi云端解析、语义分割与得分匹配的组合方案，本系统能够精准识别赛场全部语音交互指令，稳定完成灯光切换、不同时长与模式鸣笛、多方位门洞通行、车体姿态运动等复杂任务，极大提升了卡丁快跑人车交互科目的执行准确率与稳定性
4.3PID控制算法介绍
在工程实际中，应用最为广泛的调节器控制规律为比例、积分、微分控制，简称PID控制，又称PID调节。PID控制器问世至今已有近70年历史，它以其结构简单、稳定性好、工作可靠、调整方便而成为工业控制的主要技术之一。当被控对象的结构和参数不能完全掌握，或得不到精确的数学模型时，控制理论的其它技术难以采用时，系统控制器的结构和参数必须依靠经验和现场调试来确定，这时应用PID控制技术最为方便。即当我们不完全了解一个系统和被控对象，或不能通过有效的测量手段来获得系统参数时，最适合用PID控制技术。PID控制，实际中也有PI和PD控制。
PID控制器是一种线性控制器，它根据给定值与实际输出值构成控制偏差。将偏差的比例(P)、积分(I)和微分(D)通过线性组合构成控制量，对被控对象进行控制，故称PID控制器，原理框图如图      所示。

简单说来，PID控制器各校正环节的作用如下：
比例环节：及时成比例地反映控制系统的偏差信号，偏差一旦产生，控制器立即产生控制作用，以减少偏差。
积分环节：主要用于消除静差，提高系统的无差度。积分作用的强弱取决于积分时间常数，越大，积分作用越弱，反之则越强。
微分环节：能反映偏差信号的变化趋势(变化速率)，并能在该偏差信号变得太大之前，在系统中引入一个有效的早期修正信号，从而加快系统的动作速度，减小调节时间。
数字PID控制算法通常分为位置式PID控制算法和增量式PID控制算法。

4.3.1位置式
位置式PID中，由于计算机输出的u (k) 直接去控制执行机构(如阀门)，u(k)的值和执行机构的位置(如阀门开度)是一一对应的，所以通常称公式(4.2)为位置式PID控制算法。
位置式PID控制算法的缺点是：由于全量输出，所以每次输出均与过去的状态有关，计算时要对过去e(k)进行累加，计算机工作量大；而且因为计算机输出的u(k)对应的是执行机构的实际位置，如计算机出现故障，u(k)的大幅度变化，会引起执行机构位置的大幅度变化，这种情况往往是生产实践中不允许的，在某些场合，还可能造成严重的生产事故。因而产生了增量式PID 控制的控制算法，所谓增量式PID 是指数字控制器的输出只是控制量的增量△u(k)。

增量式PID具有以下优点：
(1) 由于计算机输出增量，所以误动作时影响小，必要时可用逻辑判断的方法关掉。
(2) 手动/自动切换时冲击小，便于实现无扰动切换。此外，当计算机发生故障时，由于输出通道或执行装置具有信号的锁存作用，故能保持原值。
(3) 算式中不需要累加。控制增量△u(k)的确定仅与最近k次的采样值有关，所以较容易通过加权处理而获得比较好的控制效果。
但增量式PID也有其不足之处：积分截断效应大，有静态误差；溢出的影响大。使用时，常选择带死区、积分分离等改进PID控制算法。
4.3.3 后轮驱动增量式PID参数整定
本车左右驱动电机相互独立，分别搭建增量式PID速度闭环控制，依靠后轮编码器实时采集两轮转速脉冲，独立计算左右轮实际车速并完成闭环调速。相较于位置式PID，增量式PID仅输出本次控制增量，累积误差小、输出变化平缓，非常适合电机持续调速、动态加减速的行驶场景。通过左右两轮独立调速，可根据航向偏差实时生成合理速度差，实现柔性差速转向，大幅减小转弯半径，提升车辆机动性能。
参数整定遵循先比例、后积分、再微分的调试逻辑。比例系数P主要决定车速响应快慢，P值偏小时左右轮提速滞后、跟随性差，弯道动力不足；P值过大则容易出现速度超调、车轮打滑、车身抖动。积分系数I用于消除稳态速度误差，修正左右轮动力输出不一致带来的直行跑偏问题，但积分作用过强易造成速度累积饱和，导致启停抖动。微分系数D用于抑制路面颠簸、电机负载波动带来的速度震荡，有效平滑车速突变。
在实车调试中，针对卡丁快跑直行巡航、低速泊车、迷宫轨迹复现等不同工况，对左右轮PID参数进行微差适配，保证直行时两轮转速一致、车身端正；转向时左右轮合理速差，实现小半径平稳过弯，兼顾车辆行驶速度与姿态稳定性。
4.3.3 前轮转向增量式PID参数整定
前轮转向电机采用增量式PID控制方式，以转向编码器采集的实际转角与IMU解算的航向偏差作为输入，直接输出对应角度控制量，实现转向角度精准定位。位置式PID具备控制精度高、定点稳态性好的特点，适合转向角度定点纠偏、姿态保持的控制场景，能够稳定维持车辆航向姿态。
转向PID整定以纠偏精准度和姿态平稳性为核心指标。比例系数P决定转向响应灵敏度，P值过小会导致航向修正滞后、轨迹偏移量大，无法精准复刻迷宫路径；P值过大会造成转向过冲、车身左右晃动，姿态稳定性下降。积分环节主要用于消除转向机械虚位带来的静态角度偏差，避免长时间行驶出现航向累积偏移，因此积分参数取值偏小，仅做微量误差修正。微分环节用于抑制快速纠偏过程中的角度震荡，缓冲转向动作，使车头姿态过渡平滑，避免急转抖动。
结合卡丁快跑赛事需求，最终整定的增量式转向PID可实现小偏差精细纠偏、大偏差快速修正的效果，配合后轮增量式差速PID调速策略，车辆能够在断路惯性行驶、迷宫轨迹复现、精准泊车等科目中保持优异的轨迹跟随能力与行驶稳定性。

4.4 摄像头色块识别算法介绍
为减少光照、阴影和相近背景色（如红色跑道、木地板）的干扰，本算法采用HSV颜色空间与连通域生长策略，稳定提取色块中心位置，为后轮差速和转向PID提供可靠视觉反馈。
4.4.1 颜色距离变换与种子选取
将RGB565图像转为HSV，根据标定的目标色H/S/V区间生成灰度距离图（0~255）：色调不符置0，相符但饱和度或亮度超限适度惩罚，完全匹配置255。在灰度图上按步长搜索，通过十字校验筛选高灰度点，取最高灰度候选的平均位置作为种子点，确保种子落于目标中心。
4.4.2 区域生长与边框平滑
从种子出发，利用自适应强阈值（依据全图最高灰度动态调整）进行连通域生长，并补入边缘弱灰度像素，完整提取色块。对包围框进行少量腐蚀去除毛刺；对框位置做加权平滑，并设置跳变确认（连续多帧大幅位移才更新），保证输出平稳抗闪烁。
4.4.3 质量门禁、曝光辅助与系统联动
输出前检查框内平均饱和度和色调偏差，防止误识别；短时丢失时允许沿用上一帧结果（最多5帧）。同时，根据跟踪框内亮度自动调节摄像头曝光（无框时回退全图统计），使目标始终处于适宜亮度。本算法在5ms定时中断中输出色块坐标，与编码器速度、IMU航向角结合，驱动后轮增量式PID差速和前轮转向PID，已在卡丁快跑等任务中验证了实时性与鲁棒性。

void SbusParseTask(void)
{
    if(sbus_rx_sta == 1)                          // 接收完一帧
    {
        sbus.head = sbus_rx_buf[0];               // 首部
        sbus.flag = sbus_rx_buf[23];              // 标志符
        sbus.end  = sbus_rx_buf[24];              // 结尾

        if(sbus.head != 0x0F || sbus.end != 0x00)
        {
            sbus_rx_sta = 0;
            sbus_rx_head = 0;
            sbus_rx_index = 0;
            return;
        }

        sbus.ch[1]  = ((sbus_rx_buf[2] << 8)  + (sbus_rx_buf[1])) & 0x07ff;
//        sbus.ch[2]  = ((sbus_rx_buf[3] << 5)  + (sbus_rx_buf[2] >> 3)) & 0x07ff;
        sbus.ch[3]  = ((sbus_rx_buf[5] << 10) + (sbus_rx_buf[4] << 2) + (sbus_rx_buf[3] >> 6)) & 0x07ff;
//        sbus.ch[4]  = ((sbus_rx_buf[6] << 7)  + (sbus_rx_buf[5] >> 1)) & 0x07ff;
//        sbus.ch[5]  = ((sbus_rx_buf[7] << 4)  + (sbus_rx_buf[6] >> 4)) & 0x07ff;
        sbus.ch[6]  = ((sbus_rx_buf[9] << 9)  + (sbus_rx_buf[8] << 1) + (sbus_rx_buf[7] >> 7)) & 0x07ff;
//        sbus.ch[7]  = ((sbus_rx_buf[10] << 6) + (sbus_rx_buf[9] >> 2)) & 0x07ff;
        sbus.ch[8]  = ((sbus_rx_buf[11] << 3) + (sbus_rx_buf[10] >> 5)) & 0x07ff;
        sbus.ch[9]  = ((sbus_rx_buf[13] << 8)  + sbus_rx_buf[12]) & 0x07ff;
        sbus.ch[10] = ((sbus_rx_buf[14] << 5)  + (sbus_rx_buf[13] >> 3)) & 0x07ff;
//        sbus.ch[11] = ((sbus_rx_buf[16] << 10) + (sbus_rx_buf[15] << 2) + (sbus_rx_buf[14] >> 6)) & 0x07ff;
//        sbus.ch[12] = ((sbus_rx_buf[17] << 7)  + (sbus_rx_buf[16] >> 1)) & 0x07ff;

//        sbus.ch[14] = ((sbus_rx_buf[20] << 9)  + (sbus_rx_buf[19] << 1) + (sbus_rx_buf[18] >> 7)) & 0x07ff;
//        sbus.ch[15] = ((sbus_rx_buf[21] << 6)  + (sbus_rx_buf[20] >> 2)) & 0x07ff;
//        sbus.ch[16] = ((sbus_rx_buf[22] << 3)  + (sbus_rx_buf[21] >> 5)) & 0x07ff;

        sbus.state = (0x04 == (sbus.flag & 0x04)) ? 0 : 1;

        sbus_rx_sta = 0;
    }
}
void SBUS_callback(uart_index_enum uartn)
{
    uint8_t chr;

    chr = uart_read_byte(uartn);

    if (sbus_rx_sta == 0)                                           // 接收未完成
    {
        if ((chr == 0x0F) || sbus_rx_head)                          // 找到首字节或已经找到首字节
        {
            sbus_rx_head = 1;                                       // 标明已经找到首字母
            if (sbus_rx_index < SBUS_DATA_SIZE)                     // 未接收到25个字符
            {
                sbus_rx_buf[sbus_rx_index] = chr;                   // 不断接收
                sbus_rx_index ++;
            }
            else                                                    // 接收到25个字符了
            {
                sbus_rx_sta = 1;                                    // 接收完成
                SbusParseTask();
                sbus_rx_head = 0;                                   // 清零，准备下一次接收
                sbus_rx_index = 0;
            }
        }
    }
}

void set_diff_speed(int16 avg_speed, float steer_angle_deg)//目标速度，转向角度
{
    float kp = 1.8f;
//    if(back_flag == 1)  kp = 1.8f;
//    else kp = 1.0f;
    float deg = kp*steer_angle_deg;

    if (fabs(deg) < 0.5f)
    {
        target1_speed = avg_speed;
        target2_speed = avg_speed;
        return;
    }

    float steer_rad = deg * (PI / 180.0f);

    float R = WHEELBASE / tanf(steer_rad);

    float left_speed  = avg_speed * (1.0f - (TRACK_WIDTH / (2.0f * R)));
    float right_speed = avg_speed * (1.0f + (TRACK_WIDTH / (2.0f * R)));

    const int16 max_speed = 270;
    const int16 min_speed = 1;

    if (left_speed > max_speed)     left_speed  = max_speed;
    else if (left_speed < -max_speed)    left_speed  = -max_speed;
    if (left_speed > 0 && left_speed < min_speed)     left_speed  = min_speed;
    else if (left_speed < 0 && left_speed > -min_speed)    left_speed  = -min_speed;
    if (right_speed > max_speed)    right_speed = max_speed;
    else if (right_speed < -max_speed)   right_speed = -max_speed;
    if (right_speed > 0 && right_speed < min_speed)     right_speed  = min_speed;
    else if (right_speed < 0 && right_speed > -min_speed)    right_speed  = -min_speed;

    target1_speed = (int16)left_speed;   // 左轮
    target2_speed = (int16)right_speed;  // 右轮
}

    }
    else

        pwm_set_duty(ATOM1_CH1_P21_3, 0);
        pwm_set_duty(ATOM1_CH0_P21_2, 0);
    }
}

    }
    else if(lr_flag == 2 && arrow_position_flag == 12)

    else if(lr_flag == 2 && arrow_position_flag == 15)   slip_k += 0.0001;

结论
自参与全国大学生智能汽车竞赛以来，团队依次完成资料调研、结构设计、车模装配与程序开发等工作，逐步完成系统迭代优化，最终达成设计目标，确定了本文智能卡丁车的整体设计方案。
本文完整介绍了本次备赛的整体设计方案，主要包含机械结构、硬件电路与控制算法三部分核心内容。机械方面，团队优化车辆转向机构，有效提升了车辆转向精度与稳定性。电路方面采用模块化设计，对主控最小系统、电机驱动、电源等关键模块进行反复调试，确定了稳定可靠的硬件方案。软件基于C语言开发，经过多次研讨迭代，形成了稳定通用的控制程序；算法结合赛场工况实现自适应调速，通过直道加速、弯道减速的控制逻辑，兼顾车辆行驶稳定性与竞速效率。
备赛期间，团队攻克多项技术难题，通过多次实战测试完成系统优化升级，积累了丰富的工程实践经验。在此，衷心感谢学校与学院提供的场地、经费等资源支持，感谢各位领导、指导老师与学长的悉心指导，同时感谢竞赛组委会搭建的科创实践平台，有效锻炼了团队的创新能力与协作能力。
