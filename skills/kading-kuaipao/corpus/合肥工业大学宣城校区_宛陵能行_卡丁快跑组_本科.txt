## 第一章 引言

### 1.1 任务概述

本车的控制目标不是预存固定地图，而是记录车辆本次跟随过程中的一条随机路线，并在人员离开后沿原路线倒车返回。因此，系统需要同时解决以下问题：

- 在低分辨率灰度图像中稳定识别目标标志；
- 将视觉横向偏差转换为连续转向目标；
- 使用双后轮编码器获得可用于停车和路径查询的里程；
- 在没有 GPS 和绝对航向基准的情况下，利用短时 IMU 航向保持路线相位；
- 解决整圈路线中入口、出口物理朝向相同而路径阶段不同的问题。

### 1.2 报告范围

本文覆盖技术报告所需的总体方案、机械和传感器接口、电路、软件算法、开发调试过程及主要技术参数。研究论文部分不单独展开。

## 第二章 总体设计方案

### 2.1 系统架构

```text
MT9V03X 灰度相机
        │  CPU0：配置、DMA、帧缓冲
        ▼
CPU1：标志检测、距离估计、横向偏差、结果发布、IPS200
        │  跨核共享快照
        ▼
CPU3：视觉跟随 / 路线记录 / 倒车回放 / 10 ms 底盘控制
        │
        ├── 后轮编码器 -> 里程和速度
        ├── IMU963RA -> 角速度和连续航向
        ├── 前轮绝对角度传感器 -> 转向位置闭环
        └── 后轮电机、转向电机 -> PWM 和方向控制

CPU2：UART3 语音模块、蜂鸣器、LED 动作
```

### 2.2 工作流程

<div align="center">表2.1 系统状态与功能</div>

| 状态 | 功能 |
|---|---|
| `READY` | 上电完成 IMU 零偏标定，等待 KEY1 |
| `REC` | 跟随目标，同时记录路线 |
| `READY` | KEY1 结束记录，停车并将前轮回到中位附近 |
| `BACK` | KEY2 启动倒车，按记录路线返回 |
| `DONE` | 剩余里程达到停车阈值，停止车辆 |
| `ERR` / `FULL` | 传感器、航向、路线过短或记录空间异常时停车 |

## 第三章 机械结构与传感器安装

### 3.1 机械执行机构

车辆采用双后轮独立驱动、前轮转向结构：

- 左、右后轮分别由独立电机和 PWM 通道驱动；
- 前轮由转向电机驱动，并通过绝对角度传感器构成位置闭环；
- 满舵时采用后轮差速，内侧轮 PWM 约为基础值的 0.60 倍，外侧轮约为 1.40 倍；

### 3.2 传感器安装与接口

<div align="center">表3.1 传感器配置</div>

| 传感器 | 数量 | 用途 |
|---|---:|---|
| MT9V03X 灰度相机 | 1 | 识别 AprilTag，输出横向偏差和距离代理量 |
| 后轮编码器 | 2 | 速度、前进/倒车里程 |
| 前轮绝对角度传感器 | 1 | 转向角位置反馈 |
| IMU963RA | 1 | Z 轴角速度和连续航向 |
| GPS / WiFi 接口 | - | 预留功能 |

本车车模为北京科宇科技卡丁车模，外形尺寸为 130 cm × 50 cm × 70 cm。传感器及相关线路主要使用电工胶布和热熔胶固定，实车布置见图 3.1～图 3.3 及图 4.1。相机、控制板和传感器均布置在车体内部或刚性支撑区域，线束沿车体进行整理固定。

## 第五章 控制软件与核心算法

### 5.1 多核软件分工

<div align="center">表5.1 多核软件分工</div>

| 核心 | 当前职责 | 主要文件 |
|---|---|---|
| CPU0 | 相机初始化、DMA、曝光请求、视觉校准协议 | `user/cpu0_main.c` |
| CPU1 | 目标识别、结果发布、IPS200 参数显示 | `user/cpu1_main.c`、`code/vision_tag_tracker.c` |
| CPU2 | UART3 语音协议、蜂鸣器、LED | `user/cpu2_main.c`、`user/car_voice.c` |
| CPU3 | 10 ms 底盘控制、编码器、IMU、状态机、记录和回放 | `user/cpu3_main.c`、`user/car_nav.c` |

视觉帧采用“获取 - 处理 - 发布 - 释放”生命周期，CPU3 不直接访问相机缓冲区，而是读取 CPU1 发布的结果快照，避免多核同时读写帧缓冲。

### 5.2 视觉识别与跟随

相机当前配置为 188 x 120 灰度图，默认帧率 50 fps。识别器针对 `tag36h11 ID 0` 的固定标志。主要处理链路为：

1. 采用 Otsu 方法获得灰度阈值；
2. 建立黑像素积分图，快速计算候选区域；
3. 搜索白色静区、黑色方框和内部 6 x 6 码字；
4. 对四边形候选进行透视采样和 ID 校验；
5. 锁定后优先搜索预测 ROI，丢失时进行短时预测；
6. 使用位置、速度和尺寸滤波输出目标中心、框尺寸、置信度和距离估计。

当前视觉参数包括：最小识别置信度 600，控制端接受置信度不低于 260；距离比例系数为 `13200 mm*pixel`；跟随阈值为近距离 300 mm、减速区 400 mm、远距离恢复区 450 mm。

视觉控制关系可概括为：

```text
steer_deg = error_x_px / 50 * 60 * (-1)
```

目标速度通常为 0.23 m/s，远距离时为 0.28 m/s，近距离时降低到 0.06 m/s。目标短时丢失时最多保持约 350 ms 的降速结果；视觉命令超过 450 ms 未更新则停车。丢标后转向 PWM 归零，但前轮保持当前位置，不自动回中。

### 5.3 编码器里程与 IMU 航向

后轮编码器采用 DIR 模式，左右轮分别进行符号修正。当前每轮约 1024 count/rev，轮径约 0.25 m，单计数理论距离约为：

```text
ds_count = pi * 0.25 / 1024 = 0.000767 m
```

控制周期为 10 ms，车辆里程使用两后轮增量的平均值：

```text
ds = (ds_left + ds_right) / 2
speed = lowpass(ds / 0.01 s)
```

IMU 使用 IMU963RA 的 Z 轴陀螺仪积分获得连续航向。上电后等待 300 ms，采集 1000 个零偏样本，至少 850 个样本有效才通过标定；运行时使用 0.6 deg/s 死区和两级 0.18 系数低通。只有在首次录制前、车辆静止且满足角速度残差条件时才缓慢跟踪零偏；进入 `REC` 后冻结零偏，避免把真实转动车体误当成零偏。

### 5.4 路线记录

路线点结构为：

```text
path point = { s_m, yaw_deg, steer_deg, time_10ms }
```

其中 `s_m` 为前进累计里程，`yaw_deg` 为不折叠的连续航向，`steer_deg` 为相对固定中位 `SA=2006` 的实测前轮角。直线路段约每 0.08 m 保存一点；当航向变化达到约 5 deg 且移动距离不小于 0.025 m 时提前记录转弯点。路线最多保存 900 点，至少 0.80 m 且至少 3 点才允许回放。

### 5.5 倒车回放

回放每 10 ms 执行一次：

1. 根据后轮倒车增量累计已回放里程；
2. 计算 `remaining = total - replayed`；
3. 以剩余里程查询记录路线，并沿倒车方向前视 0.15 m；
4. 以记录的实际前轮角作为主要转向前馈；
5. 只有记录前轮角接近中位时，才使用路径曲率作为补充前馈；
6. 使用 IMU 航向误差、航向积分和角速度反馈修正转向；
7. 在 0.12 m 短窗口和 0.30 m 长窗口上拟合航向变化，分别处理紧弯/S 弯和大半径弯；
8. 在弯道内于当前位置前后 0.40 m 搜索航向最匹配的路径相位，参考索引只允许向起点方向移动；
9. 剩余 0.65 m 开始减速，剩余 0.06 m 停车。

回放转向控制可简化表示为：

```text
steer = feedforward
      - Kp * heading_error
      - Ki * heading_integral
      - Kd * (desired_yaw_rate - measured_yaw_rate)
```

路线航向保持不折叠，因而绕桶一周产生的约 360 deg 航向变化不会被错误地当作 0 deg，入口和出口可以区分。

### 5.6 转向位置闭环与安全策略

前轮绝对角度传感器输出 0~4095 原始值。实测标定值为：右机械极限 925，中位 2006，左机械极限 2960。左右两侧采用不同量程映射，输出经过原始位置误差和角速度反馈后驱动转向电机。软件限位只禁止继续向当前极限外推，反方向命令仍然允许，避免到达限位后无法回转。

## 第六章 开发、制作与调试过程

### 6.1 开发环境

工程为 AURIX/TC387 多核工程，使用逐飞 TC387 库及Infineon iLLD 模块

### 6.2 主要调试问题及处理

<div align="center">表6.1 主要调试问题及处理</div>

| 问题 | 原因 | 当前处理 |
|---|---|---|
| 相机只有第一帧或画面异常 | DMA 所属核、帧生命周期和跨核访问不一致 | CPU0 统一生产帧，CPU1 获取和释放，CPU3 只读结果快照 |
| 屏幕雪花、黑屏或残影 | 多核同时写屏、刷新过快或图像与文字区域冲突 | IPS200 由 CPU1 单点初始化和刷新，当前只显示参数 |
| 编码器方向不一致 | 左右安装方向不同 | 保留左右独立符号，确认前进同为正、倒车同为负 |
| 转向一给目标就打死 | 位置环极性错误 | 保持正确电机接线，视觉方向单独用 `CAR_VISION_STEER_SIGN` 修正 |
| 丢标后车辆自动回正 | 旧逻辑在无效结果时将目标写为 0 | 丢标停车并保持当前位置 |
| 宽弯曲率接近 0 | 单点或相邻点差分不足以表达大半径弯 | 增加 0.12/0.30 m 双窗口航向拟合，并融合记录前轮角 |

## 第八章 结论与改进方向

本车完成了以 TC387 多核控制器为核心的视觉跟随和路线回放架构。视觉链路采用低分辨率灰度相机和固定标志识别，底盘链路采用双后轮编码器、IMU 航向和前轮绝对角度传感器，回放链路则将记录前轮角、路径曲率和 IMU 反馈结合起来，能够覆盖直线、一般弯道和随机路线的基本控制需求。

系统的控制边界主要来自轮胎侧滑、IMU 长时间积分漂移以及光照、姿态和遮挡对视觉距离估计的影响。针对这些因素，软件采用编码器里程、IMU 航向和视觉结果融合的方式提高路线跟随稳定性，并通过记录前轮角与航向闭环完成倒车回放。

### 附录 A 核心算法摘要

#### A.1 视觉跟随

```c
usable = result->valid && result->confidence >= 260;
speed = distance_to_speed(result->distance_mm, result->size_px);
steer = result->error_x_px / 50.0f * 60.0f * (-1.0f);
```

#### A.2 路径点记录

```c
point.s_m = car_record_s_m;
point.yaw_deg = filtered_yaw_deg;       // 连续航向，不折叠
point.steer_deg = filtered_steer_deg;   // 实测前轮角
point.time_10ms = elapsed_ms / 10;
```

#### A.3 倒车回放

```c
remaining = total_length - replayed_distance;
reference = phase_align_by_encoder_and_yaw(remaining, yaw);
sample = path_sample(reference - 0.15f);
feedforward = recorded_steer_or_curvature(sample);
steer = feedforward - kp * heading_error
                     - ki * heading_integral
                     - kd * yaw_rate_error;
```
